> 安装不只在成功时是按钮——进度、失败、断网、多窗一致都是第一站体验。

## 一、下载进度（E6#30.9a）
- 详情页 🟢安装按钮内显示进度（下载中 → 百分比/动画 → 完成）。
- 依赖 E6#13 IPC handler 进度事件 + E6#31 下载（`fetch(downloadUrl)` → ArrayBuffer → 进度）。
- **安装中动作置灰**（M6，mockup 帧 2）：下载进行中，版本下拉 + 自动更新勾选**置灰**——安装完成才可改（自动更新勾选只在已装态出现，05 §五 G2）。
- **侧栏瞬时徽标**（M4 二，三通道反馈状态型）：该行「安装中 62%」即时反馈，进度事件订阅同 E6#13。

## 二、失败 / 重试（E6#30.9b）

**失败态全览（缝隙 G2/B2/D1/D2/D3——每种失败明确归因 + toast 文案，不留「转圈装死」）：**

| 失败原因 | 归因 | toast 文案（11-API §三 key） | 动作 |
|:--|:--|:--|:--|
| 下载中断 / 源不可达 | 网络 | 安装失败：网络连接不可用 | [重试] |
| **下载超时（fetch 30s 无响应）** | 网络 | 安装失败：网络连接不可用 | [重试] |
| 校验失败（`checksum` 不符） | 完整性 | 安装失败：文件校验未通过 | [重试] |
| 实际字节 vs `size` 声明显著不符 | 完整性 | 安装失败：文件大小异常 | [重试] |
| **磁盘空间不足** | 环境 | 安装失败：磁盘空间不足 | [重试] |
| 解压 / plugin.json 校验失败 | 包损坏 | 安装失败：插件包损坏 | [重试] |
| 未知 | 兜底 | 安装失败：未知错误，请重试 | [重试] |

**重试策略（D3）**：[重试] = 手动触发才重发，**无自动重连循环、无风暴**——失败即停在失败态，等用户决定。
**断网/超时归因**（G2/B2）：源不可达 + fetch 30s 超时统一归「网络」；GitHub 慢/不稳 Gitee 源可缓解（01 §六 多源）。
**大小/校验**（D1/D2）：`checksum` 是 01 §三 新增字段，旧条目无字段 → 跳过校验（纯增量）；`size` 显著不符 → 警告 + 可重试（不拒装）。

### 二·一、断网离线态（缝隙 G3——「离线」≠「失败」）

- `navigator.onLine === false` → 归**「离线」**非「失败」：安装/更新按钮**置灰 + 提示「联网后重试」**，**无 [重试] 动作**（重试对断网无意义）。
- 与失败态（上表七种）区分：失败 = 有网但装不上（可重试）；离线 = 没网（重试前提不成立）。视觉 = mockup 帧注「断网时不是失败而是离线」。
- 恢复联网（`onLine` 事件）→ 按钮自动恢复可用，不打扰。

## 三、装完体验
- 装完 toast + 状态自动切换「禁用/卸载」（E6#30.5c 已有）。

## 三·五、卸载 / 禁用使用中的插件（缝隙 G4——用户拍板：不提示，静默）

插件有打开的标签页时卸载/禁用 → **静默关闭其标签页 + 执行动作 + toast 反馈照常**（不弹窗打扰——用户拍板）。用户发现标签页关闭 = 动作已完成的自然反馈。
- **卸载二次确认（M7，mockup 帧 4）**：点卸载先走 `window.linkdesk.ui.confirm`（复用既有确认流程，30.5b）——确认后执行；「使用中静默关闭不弹窗」只豁免**关标签页的打扰**（G4），卸载本身的确认不豁免。
**挂起中卸载**（B4）：依赖缺失挂起的插件可卸载；卸载连带清除依赖引用，**无孤儿挂起残留**。

## 五、toast 反馈——插件自调（E3j#76 基础 + E6#13.5 主动作按钮）
> 顶部横幅禁用（用户拍板：把整个 UI 往下推 + 影响性能）——一切事件反馈走右下角 toast。视觉 = mockups/02 帧 2/3/7。

- 进度 / 失败 / 缺依赖 / 装完成功 toast **全由市场插件自调** `window.linkdesk.notifications.show(msg, { type, progress, actions })`（四方法 show/update/finish/cancel，IpcBridgeHandler/ui.ts，E3j#76 已实现）——插件自己决定显示什么，壳零改动。
- **进度**：`show(msg, { progress: true })` → `handle.update("正在安装… 62%")` 循环改文字 → `finish(msg)` 收尾（图形进度条 UI 留未来，API 面已现成）。
- **主动作按钮（E6#13.5，2026-08-29 缝隙 K1 新增）**：`show(msg, { type, actions: [{ id, label, isPrimary?, command?, args? }] })`——toast 内可带 [重试]/[查看依赖] 按钮，点击 → 壳执行 `command`（走既有命令系统）；无 `command` → 现状 onClick。契约四齐全 + 03-插件制造 文档说明（13.5a/e）。
- **市场消费先例（13.5f）**：失败 toast [重试]（§二，落 30.9b）· 缺依赖 toast [查看依赖]（04 §二·六，落 30.5e）。
- **失败**：`show("安装失败：…", { type: "error", actions: [{ id: "retry", label: "重试", isPrimary: true, command: "plugin.retryInstall" }] })`；**缺依赖**：`show("无法安装：缺少依赖 …", { type: "warning", actions: [{ id: "view-deps", label: "查看依赖", command: "plugin.showDependencies" }] })`；**装完**：`show("已安装：X", { type: "info" })`（lifecycle onDidInstall 先例同款）。

## 六、付费插件扩展点（2026-08-29 原则定案，未来实现，不碰现状）

> **约束（用户原话）：未来付费是更新内容，不能影响前面已经制作的插件；已制作插件可借助升级升级为付费。** 三个正交扩展点，现在定原则，不写代码：

| 扩展点 | 原则 | 现有支撑 |
|:--|:--|:--|
| catalog 纯增量 | 加 `price` / `entitlement` 字段，旧条目不填 = 免费，解析不崩；**已制作插件升级付费 = 作者更新自己目录条目加 price**，零壳改动 | 01 §三 schema 版本化（03 §四 纯增量先例） |
| 安装流前置步骤 | 付费 = 在「下载→校验→复制」步骤链**前插「先验权」步骤**（先付费再装），不重写下载/校验/进度——免费插件路径完全不变 | 本档 §一 正交步骤链 |
| 授权 | 按 `pluginId` + 版本区间；已装旧版升级付费后的语义（保留 / 升级解锁 / 限流）未来拍板，key 落点现在可定 | — |

**打破约束的点（未来独立决策）：** 支付 / 抽成天然要服务器（支付服务商 / 授权服务）——「无自有服务器、靠 GitHub/Gitee」的约束在支付上撑不住。现在只记「支付 = 加法层」，不碰既有安装 / 更新流。
