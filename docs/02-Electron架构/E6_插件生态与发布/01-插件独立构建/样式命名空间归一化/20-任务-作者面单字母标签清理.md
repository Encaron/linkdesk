## 二、为什么不机械化（🔴 这一节是「不许加判据」的理由，别绕过）

1. **合法形态与它同形**：`F2`（按键）、`CM6`（库）、`T1`/`T2`（篇内标签）、`E5.8`/`P1至P5.5`（**真实路径**）——**112 处里只有 37 处该清**。任何一条抓 `D1` 的正则都会连它们一起抓进来（1.19 已实测：裸 `NNx` 撞计量单位、裸 `NN.NN` 撞节号与数值，同样不可判）。
2. **本系列禁区「不引白名单／基线／棘轮」** ⇒ 不能用豁免表把误报压下去；那条路正是 1.13 评估里被严格支配、被否掉的那条。
3. **机械解的代价大于收益**：本仓对同名问题的既有结论（[11-任务-保留名清单单一真相源](11-任务-保留名清单单一真相源.md) §二）是——**当机器判据会造出比它挡住的更多麻烦时，改判「人判一遍 ＋ 把容忍理由写进尺子文件头」**。1.19 已经把这条容忍理由写进 `scripts/check-author-docs-symbols.mjs` 的文件头（「仍然**没加**的判据」一节）。
4. **它不再增长**：7.8 起新写的作者面文档已不带这族 ⇒ **收益恒定、成本恒定、不随时间上涨**（与件 1 的裸类名相反——那个是分母在涨才必须早做）。

## 三、要做（三条改写原则，逐处套）

| 形态 | 改法 | 例 |
|:--|:--|:--|
| **装饰性 provenance**（句子本身已自足，标签只是「我们吃过这个亏」的出处） | **删标签**，句子一字不动 | `子元素用 position: fixed 也看不见（B54 教训）。` → `…也看不见。` |
| **指路性**（标签是唯一内容，句意靠它） | **把标签要指的东西直接写出来**，或整段改成自足句 | `（N1 超集注记）` → 把「这些面池侧真的有注入」直接写进该行说明 |
| **句内枚举标签** | **删标签留内容** | `D1 x 转发、D2 y 壳补、D3 z 壳补` → `x 转发、y 壳补、z 壳补` |

**逐处要求**：① **两棵树同笔**（`check-author-docs-bilingual` 只管篇目，**内容等价靠人**）；② 只动**措辞**，不动规则含义与数值；③ 改完**读一遍上下文**（判据里有一条就是这个）。

**灰色那 ~10 处**另判（不进 37 的账）：`theme (P6)` 这类若去掉后句子仍清楚（`theme` 一行本来就说明了自己是什么），就去掉括号；`E3 时代的历史记录` 若去掉后读者不知道「为什么这段是历史」就保留（它给了「这是早期形态」的信息）。

## 四、判据

- **读数**：三类 token（`D*` / `N*` / `G*` / `B*`）在两棵树**散文中 0 处**；**正控**（合法那族仍在：`F2`/`CM6`/`T1`/`E5.8_归一化基建/` 路径）**不为 0**——防止「一刀切删光」把合法形态也误伤。复跑命令：
  ```bash
  grep -rnoE '\b(D[0-9]|N[0-9]|G[0-9]|B[0-9]+)\b' docs/03-插件制造 docs/03-plugin-authoring | grep -vE 'F2|CM6|T1|T2|E5\.8|P1至P5\.5|V3-'
  ```
- **四道作者面门禁绿**（`check-author-docs-symbols` / `-links` / `-bilingual` ＋ `docs:check`）· **`npm run check` EXIT=0**。
- **人工读**：改动处上下文通顺（这条是**主判据**，不是形式）。
- **发版**：`npm run docs:build` 重生成文档包 ⇒ `@linkdesk/plugin-docs` **同批发一位 PATCH**（先例：1.19 的 `0.1.4 → 0.1.5`；步骤照 [作者轴 npm 发版 runbook](../../../../06-发布管理/作者轴npm发版.md) 五步，**`git add` 后先真跑 pre-commit 再 publish**）。
- **机器侧不加判据**（理由见 §二）——本格**一行脚本都不改**。
