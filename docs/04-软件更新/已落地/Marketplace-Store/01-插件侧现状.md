## 一、表面结构（plugin.json，全部声明式）

这只插件有 **8 个渲染面**，分布在两个容器 ＋ entry：

| 面 | 容器/位置 | 内容 |
|---|---|---|
| `entry`（`src/index.tsx` MarketplaceView） | 主区标签页（点侧栏 🧩 手动开） | **落地页**：现只有一段 hero（🧩 图标 ＋「已装 N 个插件」＋「在左侧侧栏中浏览」提示）——**这就是未来大屏商店最自然的改造位** |
| `search`（SearchView） | 侧栏 toolbar（order -1） | 搜索框 ＋「检查更新」钮 ＋ 添加源 |
| `installed`（InstalledListView） | 侧栏（order 0） | 已装列表 |
| `explore`（ExploreView，默认折叠） | 侧栏（order 1） | **市场目录浏览**（marketplace.json 驱动） |
| `disabled`（DisabledListView） | 侧栏（order 2，折叠） | 已禁用 |
| `builtin`（BuiltinListView） | 侧栏（order 3，折叠） | 内置 |
| `plugin-detail`（DetailView） | **主区**（`location:"main"`，全仓唯一用 main 的插件） | 插件详情页：header＋动作列＋元数据侧栏（sticky）＋三 tab（概览=截图画廊+README／功能=contributes 四组／更改日志） |
| `marketplace-install-confirm`（ConfirmInstall） | 主区（弹确认卡用） | 安装确认 |

要点：**侧栏与主区是各自独立的 bundle**（SDK 每表面一次独立打包），共享状态不能靠模块级变量——全部住 `realmSlot` 全局槽（v1.1.6 修过一次「侧栏翻新详情不翻新」的多表面塌缩，案档在本仓 `docs/01-多表面共享状态塌缩/`）。

## 二、数据面（`src/services/`）

- **目录（可装的）**：`marketSources/*` → 拉 `marketplace.marketplaceSources` 配置的各源（官方源 = `E:\linkdesk-marketplace` 目录仓发布的 `marketplace.json`，内置默认一条；作者可加源）→ **5min 缓存** → 多源合并 → `catalogStore`（realmSlot 槽）投影。离线用缓存兜底并在列表顶注记。
- **本地（已装/禁用/内置）**：`pluginsStore`（`useMarketplacePlugins`）→ 壳 `list()/getDisabled()` 实时读。**已装判定 = list() ∪ getDisabled() 两源合并**（list() 不含禁用件，漏合并会把禁用瞬间显示成未装）。
- **安装流水**：`installJobs`（job 表广播，行徽标「安装中 62%」/失败归因+重试）＋ `installGate`（装前门）＋ `minAppVersionGate`（版本门槛，四入口统一过门）。
- **更新发现**：`updateDiscovery/*`——启动 ~10s 延迟自动一趟（拉目录比版本→铃铛通知+徽标+自动更新数据源）；侧栏「检查更新」钮 = 手动绕缓存强刷＋当场补跑。
- **分类/下载数**：`marketCategories.ts`、`downloadCounts.ts` 已存在。
- 🔴 **你构想 3 的现状确认**：市场列表 = 目录条目 ⊕ 本地已装实时合并——插件装/卸/更新后列表自然跟着变（动作后本地不翻状态，等 lifecycle 事件驱动 store 刷新收敛到真值）。**不需要任何插件向市场登记。**

## 三、关键交互现实（改造时最要紧的三条）

1. **跨标签跳转 API 现成**——侧栏目录行点开详情就是这一句（`ExploreView.tsx:64`）：
   ```ts
   window.linkdesk.tabs.create("plugin-detail", { pluginId: id, pinned: false, label: name });
   ```
   **你构想 2（点卡片 → 跳该插件详情标签页）的壳接触点已查实：`linkdesk.tabs.create` 就是现成通道**，目录行今天就在用，只是 UI 形态是行不是卡片。大屏商店卡片点击复用同一条即可，零新增壳 API。
2. **详情页已接手数据展示**——DetailView 数据源 = list()（已装实时）⊕ catalog（未装可显示），作者缺失回退目录条目；壳侧 PluginDetailPoolView 只剩保底宿主。
3. **动作全走 `window.linkdesk.pluginManager.*`**（enable/disable/uninstall），卸载二次确认走 `linkdesk.dialog.confirm`；`core:true` 只藏卸载钮。

## 四、样式与文案地基

- 样式按面分节：`styles/sidebar/` 3 件、`styles/detail/` 6 件、根 2 件——**每个视图文件头部全量 import 本面整套**（类分散在子件里，逐件 import 收益为零，判据见 `detail-shell.css` 头注）。
- 铁律：颜色一律 `var(--xxx)`（切主题跟随）、文案一律 `t()`（`i18n/zh.json` + `en.json` 两份，官方插件里只有它双语）、弹窗 portal 到 `document.body`、持久化走 `linkdesk.configuration`（禁 localStorage）。

## 五、发版纪律（本仓自带，改码前必读 `docs/00-README.md` 发布路径）

- `distribution: builtin` + `core: true` + **出厂种子**（`seed: true`）⇒ 新用户装到的就是本仓最新发布件，**发版不可省**。
- 四件事同笔：① bump `plugin.json` version（`package.json` 同值）＋ CHANGELOG 一段 → ② `verify`+`test`+**`build`**（publish 不 build，改码不 build 会发 stale 资产）→ ③ `publish` 发本仓 Release → **官方目录收录**（`E:\linkdesk-marketplace`，这才是默认用户的更新通道，两步才算上架）→ ④ `sync:bundled --latest` 刷壳仓种子。
- ⚠️ 装新版界面没变 = 先重启（壳池按 URL import，同 URL 模块图不随磁盘替换重载）。
- 壳仓 `npm run check` 够不着本仓，本仓绿灯只看 `verify`+`test`。

## 六、对「大屏商店」构想的地基结论

| 构想 | 地基现状 | 结论 |
|---|---|---|
| 主区承担 Store 页 | entry 落地页（index.tsx）现成、几乎是空的，`tabBehavior.singleton: true` | 大屏商店最自然的落点 = 改造 entry 页（走它既有 `tab type`，零壳改动）；或新增第二个 main view（需动 `contributes.views.main`，纯插件侧声明） |
| Store 独立标签页 + 点卡片跳详情 | `linkdesk.tabs.create("plugin-detail", {pluginId})` 现成（§三·1） | **零新增壳 API**；卡片点击照抄目录行这句 |
| 清单自动同步 | catalog ⊕ pluginsStore 实时合并（§二末） | 现状已满足，重设计沿用同一数据面 |
| 分类/搜索/下载数 | `marketCategories` / `downloadCounts` / searchState（realmSlot 槽，跨表面同步）已存在 | 数据齐了，缺的只是大屏 UI 形态 |
