## 二、定稿（用户 4 点拍板，2026-08-27）

1. **砍「不越弧」**——zone 圆弧大小可设，精确不越弧 = 实时量测 + 订阅变化 = 算法债；越弧只在 hover 瞬时出现，接受。
2. **常态三点 → hover 成线**——常态三点居中（缝正中心，离四角圆弧最远，直角/圆角都自然）；hover 变整条线，越弧就让它越。横缝三点横排、竖缝三点竖排。
3. **线端圆角 = zone 圆角镜像**——`border-radius: var(--surface-radius)`：zone 直角（`--surface-radius=0px`）→ 线端直角；zone 圆角（scale≠0 → 绝对 px）→ 线端圆角（2px 线端帽自动成胶囊）。**零新配置键、零实时监视**——线端与 zone 同键。
4. **这是 zone 分界线的定义（结构元素），不是可配组件**——点/线写死固定值，不随 app.surfaceRadius 联动；只有线端圆角镜像 zone 圆角（读同一真相源）。

### 真实键核对（方案架在实键上，非假设）

- `app.zoneRadius` = 圆角开关（布尔）——关时 `--surface-radius = 0px`（直角短路值）。
- `app.zoneRadiusScale` = 圆角绝对值 px（clamp 0-32）——开时写 `--surface-radius`。
- `--surface-radius` = **唯一真相源**——缝系统 `--surface-inset` 已从它派生（tokens.ts:310 ③ 缝法则：>0 → 留缝 2px，=0 → 贴死）。线端读它 = 与缝系统同一血缘，零新耦合。

### 改法

1. **`.zone-resize-handle` 加视觉结构**（CSS 伪元素或子元素二选一，实现时择一）：
   - 常态 = 三点（2px 圆点 ×3，间距 3px，居中缝中心；竖缝 flex-column / 横缝 flex-row）。
   - hover = 整条线淡入 + 三点淡出（150-200ms opacity transition，`transform`/`opacity` 不触发重排）。
   - 线 `border-radius: var(--surface-radius, 0px)`——镜像 zone 圆角。
   - 命中区仍 4px（或维持现状 14px 热区？实现时按现有宽度，**不改命中区语义**）。
2. **MainZone split handles 同步同一套**（inline-style → 抽共用类或同款 inline 结构），行为（onDividerMouseDown / onDoubleClick 复位 50/50 / useResizeDrag）零改动。
3. **零新增配置项、零新增 API、零新增贡献点**——读 `--surface-radius`（已存在），不触 schema/contracts。
