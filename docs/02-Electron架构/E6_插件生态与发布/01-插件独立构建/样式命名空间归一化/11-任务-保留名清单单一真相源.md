# 任务 `#109i`：保留名清单**单一真相源**（件 3）——第 1.15 轮

> **一句话**：作者面 §12 里那张保留名表是**手抄的第二份**——把它改成**从 JSON 生成**（或给它配一条**对账门禁**），让「机器读的那份」与「人读的那份」不可能漂移。
> **前置**：第 1.10 轮已 ✅（§12 已按 ui 0.2.0 的现实翻面）。
> **规模**：1 个生成器/门禁脚本 + §12 两棵树的一处标记 + `docs:check` 链路。
> **提交轴**：文档 + scripts。

🔴 **两份之间没有任何对账**——逐脚本核过：`check-author-docs-symbols` 只查内部任务号；`generate-plugin-docs` 不做登记表替换；`check-css-namespace` 只对「登记 ↔ 源码实况」，**不看文档**。

**为什么必须修**：这正是本仓自己命名过的**第 ① 类 bug——手维护清单缺对账门禁**。先例：`check-namespace-matrix.mjs` 当初就是因为一张手维护的表**静默漂移了一个月**（自称「契约 40 命名空间」，实为 45，还多一条死行）才诞生的。而作者面是规则的唯一入口——**表烂 = 作者照不存在的面写代码**。

> 💡 **为什么现在做最便宜**：件 1 之后 `classes.shared` 已成空组、件 4（`#109j-a`）之后 `classes.host` 只剩 `.input` 一项——**表现在是史上最短**，生成逻辑最好写；而它**将来只会变长**（成本单调上涨，与件 1 同一个道理）。

## 二、两条路线（二选一，倾向 a）

### (a) 生成（推荐）
- 在 `npm run docs:build` 的链路里，把 §12 那段表**从 JSON 渲染出来**：源文档里留一个**标记块**（例如注释形式的首尾锚），生成器只替换锚之间的内容。
- 好处：**物理上不可能漂移**（人读的就是机器读的那份的投影）。
- 代价：`docs:check` 的「逐字节比对真源」语义要容纳「生成段」（生成器同时管 `--check`，逻辑与现有 `generate-plugin-docs.mjs` 同款）。

### (b) 对账门禁
- 保留手写表，新增一条脚本：把 §12 表里解析出的名字集合与 JSON 的 `classes.*` 名字集合**双向比对**（多一个/少一个都红）。
- 好处：改动小、不动生成链路。
- 代价：解析 markdown 表格脆弱（格式一改就假红/假绿）；且**表还是两份**。

**倾向 (a)**，理由：本仓已有同款先例（`docs/` 是生成真源、`packages/plugin-docs` 是产物、`--check` 比对），顺着走比新造一条解析更稳。

## 三、步骤

1. 量清 §12 段在**两棵树**里的确切形态（首尾锚怎么放才不会被下次编辑弄丢）。
2. 实现（生成器分支或新脚本），**带 `--self-test`**（照本仓惯例：正控 + 负控）。
3. 两棵树同笔 + `npm run docs:build` + 接进 `npm run check`（若走 (b)）。
4. 写清「下次有人要改这张表时该改哪里」——**加在 §12 表下的注里**（作者不需要知道，但维护者必须知道）。
