# 侧栏容器形态门禁化（待抉择池）

> **来源**：2026-09-28 修 [已落地/侧栏toolbar与section吸顶丢失.md](../已落地/侧栏toolbar与section吸顶丢失.md) 时用户拍板的第四件——「**先一次性实证，门禁化另登记**」。
> **要防的**：同类「搬运时丢的不是清单、是**让行为生效的前提**」再发生（容器 flex 形态／定位祖先／滚动容器归属／`min-height:0` 这类前提）。
> **这次的实情**：三件门禁全绿而缺陷照旧——判据物覆盖的是**结构与写法**，不是**计算后布局**。

## 为什么静态门禁拦不住（本次逐条原话）

| 门禁 | 为什么这次是假绿 |
|:--|:--|
| `check-pool-css-imports` | 只校「类名**有没有** CSS 定义」——类名**有**定义，只是定义里少一行 `display:flex` |
| `tsc` × 3 | 内联样式少一条属性，类型永远合法 |
| ESLint | 同上 |
| `vitest`（jsdom） | 不跑布局；**sticky 的包含块在 jsdom 里根本不存在** |
| `check-spacing-grid` | 只看间距档位，不看容器形态 |

（同族先例：2026-09-27「悬浮面板提示条没进收编」补的腿 3——账清到 0、腿全绿，面板那套提示面仍漏了一整套；教训同为**判据物必须覆盖到机制**。）

## 候选判据（三案，成本递增）

| 案 | 判据 | 成本／风险 |
|:--|:--|:--|
| **A**｜dev ＋ CDP 冒烟 | 起实例 → 量 `.ldk-side-panel-content`：① `computed display === 'flex'` 且 `flex-direction === 'column'` ②「谁是真滚动容器」＝ section 内层（`overflow-y:auto` 且可滚）③ 滚前滚后 toolbar 的 `getBoundingClientRect().top` 不变 | **能真拦**；缺 GUI 就跑不了（CI 盲区）；秒级起实例、每次冒烟约 10s；与既有 `cdp-ui-automation` 手段同源 |
| **B**｜静态断言（推荐作为钉子） | 新脚本 `check-sidebar-container-shape.mjs`：解析 CSS，断言 `.ldk-side-panel-content` 规则块**同时**含 `display:flex` ＋ `flex-direction:column`；左右两个 zone 文件都判 | 便宜、可进 `npm run check`；**判据脆**（换类名/写法即失效）——但它的目标只是「防这一处再退化」，够用 |
| **C**｜只上文档纪律 | 搬运类任务的验收清单加一行「容器形态对照」（`E5.7` 那份清单**本来就有**第 ④ 项，仍假绿） | 零成本、零机械保障——**本次的教训正是这条不够** |

> 若做 B：按规矩「新增门禁要写判据」——判据写进本档，并进 `check-gate-health.mjs` 自测清单与门禁矩阵文档。

## 现状

- ✅ **B 案已落地（2026-10-07）**——`scripts/check-sidebar-container-shape.mjs`，已接 `npm run check` 链（排在 CSS 同族 `check-pool-css-imports` 之后）；`check-gate-health` 自动认账（域内 scan，无需手工登记）。
- **判据（B 案钉子）**：剥注释后，左右两个 zone 文件（`SidebarZone.css` / `RightSidebarZone.css`）的 `.ldk-side-panel-content` 规则块 ① 必须存在（选择器整个丢失也算退化）② 块内必须同时含 `display: flex` ＋ `flex-direction: column`。自测 8 例（正控红 5 ／ 负控绿 3，含「声明只活在注释里」与「更长类名不算命中」）。

- **不引入 A 案**（A 的价值在验收期，已有 `cdp-ui-automation` 的人工流程覆盖）；若将来有 GUI CI 再上 A。
