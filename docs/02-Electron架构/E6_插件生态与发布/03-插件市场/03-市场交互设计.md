## 〇、定位：为什么市场是第一站

「万物皆插件」对用户的第一眼，就是打开软件看到什么。市场不是「管理插件的工具页」，是**「这个世界有什么可玩」的橱窗**。三条设计原则：

1. **探索优先**——未装插件也能看详情、看截图、看 README，看完再决定装不装。
2. **状态一眼即知**——安装/更新/禁用，按钮随状态自动切换，不让用户猜。
3. **作者就是门面**——图标/README/截图全由作者提供，壳只做容器，提供什么显示什么。

## 一、信息架构（IA）

侧栏（🧩）= 市场。主区 = 详情页。

```
侧栏（marketplace 插件 4 组）:
  ├── 探索插件   ← 目录浏览（marketplace.json 全量）——第一站
  │               · 未装 → 绿色「安装」按钮
  │               · 已装 → 状态徽标（已安装 / 可更新）
  │               · 有更新 → 升级入口
  ├── 已安装     ← 管理（禁用/卸载/更新/版本/自动更新勾选）
  ├── 内置       ← 核心插件（不可卸载）
  └── 已禁用     ← 管理（启用/卸载）

主区:
  ├── 市场欢迎页（现状——「已安装 N 个插件」引导）
  └── 插件详情页（三态 action + README + 截图 + 元数据侧栏）

搜索 → vscode式单一结果列表（E6#32a——四组合并平铺）
```

**语义变化：「待安装」→「探索插件」。** 旧「待安装」= `getUninstalled()`（E5.8 卸载缓存，残留概念）。新「探索插件」= market catalog 目录浏览——市场时代真正的橱窗。

## 二、插件状态机（三态 + 更新第三维）

```
                     ┌────────────────────┐
                     │   未安装（catalog）  │
                     └─────────┬──────────┘
                   安装(绿)     │  卸载
                     ┌─────────▼──────────┐
                     │  已安装 · 启用       │◄── 更新可用 → 升级入口 + 版本下拉
                     │  [禁用] [卸载]       │
                     └─────────┬──────────┘
                       禁用    │   启用
                     ┌─────────▼──────────┐
                     │  已安装 · 禁用       │
                     │  [启用] [卸载]       │
                     └────────────────────┘
```

- 按钮随状态**自动切换**（订阅 `plugin-lifecycle:changed`，安装完成自动变「禁用/卸载」，卸载完成变「安装」）。
- 更新可用 = **第三维**（不改变三态，在「禁用/卸载」旁叠加升级入口）。

## 三、marketplace.json 格式扩展

> **纯增量**——旧插件不填新字段不崩（对标 VS Code contributes 从 1.0 加几十个扩展点，旧扩展不升级不崩）。权威字段定义 → [01-GitHub-Releases方案.md](01-GitHub-Releases方案.md) §三，本档只列新增。

| 新字段 | 用途 | 需求点 |
|:--|:--|:--|
| `versions[]` `{ version, downloadUrl, publishedAt, changelog? }` | 版本历史（最新在前）——版本下拉数据源 | 点 4 |
| `readmeUrl` | 作者仓库 raw README——未装插件详情页数据源 | 点 6 |
| `screenshots[]` | 截图画廊 | 点 6 |
| `license` | 许可证标识（详情页侧栏） | 点 6 |
| `categories[]` | 多分类（E6#32b 分类源，替代单 `category`） | 点 6 |
| `icon` 的 url 形态 | 作者自制彩色图标（SVG/PNG 直接 `<img>`） | 点 5 |

**配套打包**：`.linkdesk-plugin` 包内带 `README.md`（E6#4a 打包结构补「原样复制」）——已装插件的详情页 README 数据源。

## 四、详情页设计（三态 + 富展示）

### 4.1 数据流（壳侧零新 API）

```
市场视图 ──tabs.create("plugin-detail", { pluginId, marketEntry, pinned })──► 壳 PluginDetailPoolView
                                                                              ├─ marketEntry（catalog 目录信息）
                                                                              └─ 实时状态（pluginManager.list / isDisabled）
```

- `marketEntry` = catalog 完整条目（icon/desc/readmeUrl/screenshots/versions/license…），作 tab 参数传入——**壳详情页保持哑，数据由市场插件带进来**（插件独立铁律）。
- 动作 API 全走已有 `pluginManager.install/disable/enable/uninstall`——壳零新 API。
- `marketEntry` 缺失（旧调用方）→ 走现有 installed 逻辑兜底；未装显示空态 + 提示「去市场探索」。

### 4.2 三态 action bar

| 状态 | 按钮 | 动作 API |
|:--|:--|:--|
| 未安装 | 🟢 安装（带进度） | `pluginManager.install(marketEntry.downloadUrl)` |
| 已装 · 启用 | 禁用 + 卸载 | `disable` / `uninstall` |
| 已装 · 禁用 | 启用 + 卸载 | `enable` / `uninstall` |

### 4.3 富展示（VS Code 对标）

**VS Code 怎么做：客户端 Extensions 详情页 = 渲染插件包内 `README.md`（markdown）+ 元数据侧栏；web 市场再加 longDescription(markdown) + screenshots + 评分。就是 md 文档。** manifest 有 `readme` 字段指 README.md。

LinkDesk 详情页目标形态：

```
┌────────────────────────────────────────────┐
│ [icon] 插件名          v1.2.0  🔒内置       │   ← 作者图标 + 名称 + 版本
│        作者名 · 来源仓库                     │
│        一句话描述                            │
│   🟢 安装  ⏷版本↓   [✓]自动更新             │   ← 三态 action（版本下拉/自动更新勾选）
├────────────────────────────────────────────┤
│ [截图1] [截图2] [截图3]      ← 画廊（横向滚动）│
│                                            │
│ # 标题                                      │
│ README markdown 渲染（代码块/图片/列表正常）  │
│                                            │
├────────────────────────────────────────────┤
│ 标识符 / 版本 / 大小 / 分类 / 许可证 / 来源   │   ← 元数据侧栏（未装也有）
└────────────────────────────────────────────┘
```

- **README 来源**：已装 = 包内 `README.md`（IPC 读取）；未装 = fetch `readmeUrl`；都没有 → 降级显示 description（现状）。
- **markdown 渲染 = 壳共享 MarkdownView 组件**——README 渲染是通用能力，走 E6#54 分发（`@linkdesk/ui` 可复用），不塞进市场插件。

## 五、更新（徽标 + 版本下拉 + 自动更新）

### 5.1 更新徽标（点 4 第一段）
- 已装插件有新版 → 「禁用/卸载」旁升级入口（图标 + 更新按钮）。
- 检测时机沿用 E6#33a：启动 10s + 手动刷新 → 状态栏铃铛 + 市场内按钮。

### 5.2 版本下拉（点 4 第二段）
- `versions.length > 1` → 升级/安装按钮旁下拉列出历史版本（最新默认）。
- 作者保留旧版本 → 用户可装任意旧版（下载到 `user/` 目录）。
- 无版本历史 → 不显示下拉（纯增量兼容）。

### 5.3 自动更新勾选（点 4 第三段）
- 插件级 **Opt-IN，默认关**——用户不勾，壳绝不自动动。
- `installed-plugins.json` 条目加 `autoUpdate: boolean`（PluginInstallService 唯一 owner）。
- 开启后：更新检查发现新版 → 自动下载替换 + toast 通知。
- 位置：详情页 action 区 + 已安装行。

## 六、图标（作者自制 · 全态 · 即时）

| 场景 | 图标源 |
|:--|:--|
| 探索插件 · 未装 | catalog `icon`（lucide / codicon / **url**——作者自制彩色图直接 `<img>`） |
| 已安装列表 / 详情页 | 本地 manifest（包内 icon.svg） |
| 已装插件作者换图标 | 随版本更新获得 |

- **未装插件图标 = 作者提供什么显示什么**——PluginIcon 支持显式 icon descriptor 入参（不走 viewRegistry——未装插件无 registry 条目）。
- **「即时改」** = 重新 fetch catalog（5min 缓存）→ 列表/详情刷新即新图标；已装插件随版本更新（诚实边界）。

## 七、标签页标题（市场图标 + 插件名）

**根因（已实锤）：** `getDefaultLabel`（[tabIdentity.ts:280](../../../src/core/utils/tabIdentity.ts#L280)）只读 `opts?.detailPluginId`，4 个 list view 全传 `opts.pluginId` → 永远兜底「插件详情」。`findTabByIdentity` / `isSameTabIdentity` 都有 pluginId 兜底（[:187](../../../src/core/utils/tabIdentity.ts#L187) / [:255](../../../src/core/utils/tabIdentity.ts#L255)），唯独 getDefaultLabel 漏。

**目标形态：** 标签 = **[🧩 市场图标] + 插件名**
- 修复：`opts?.detailPluginId ?? opts?.pluginId`。
- 图标：市场视图开详情时传自己的图标（`tabs.create` 加 `icon` 参数 → `Tab.icon`，GroupTabBar 已支持渲染 [:305-308](../../../src/pool/shared/group-tab-bar/GroupTabBar.tsx#L305-L308)）。
- 文本：插件名（manifest.name / marketEntry.name），不带「介绍」后缀。
