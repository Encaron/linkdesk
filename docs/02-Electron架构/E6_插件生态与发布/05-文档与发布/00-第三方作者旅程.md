# 第三方插件作者旅程——从 0 到市场可见（端到端总览）

> 对应任务：**E6#24/#25/#26/#28**（开发工具链 + 发布入口定案）+ **E6#40a**（插件开发指南——本章 = 总览稿，未来搬入 `docs/03-插件制造/11-插件开发指南.md`）。
> **2026-08-30 用户定案：发布入口主路 = 命令行 `npm run publish`**（市场 UI「发布插件」按钮 = 备路）。本档 = 第三方作者视角的端到端图 + 命令分层 + 能力分层 + 多源心智模型。
> 验收锚点：第三方作者 **10 分钟**写出第一个插件（[[e6-10min-first-plugin]]）。

---

## 〇、一句话

第三方作者 = 三步：`npm create linkdesk-plugin` **做**插件 → `npm run dev` **本地看** → `npm run publish` **一键发布**。
市场 = **目录**（`marketplace.json`）+ **多源**（加一个仓库 URL 即发现）。全程不碰壳源码、不碰壳构建链。

---

## 一、端到端旅程（三阶段图）

```
插件作者电脑                         GitHub（作者自己的仓库）            用户电脑
────────────                         ───────────────────────         ────────
① 做：npm create linkdesk-plugin my-cool-plugin
      npm install && npm run dev          ← 浏览器宿主页热刷新，零打包
      （需要真机能力 → 装进已装的 LinkDesk 验证）
② 发：npm run build                     → my-cool-plugin.linkdesk-plugin
      npm run publish ──────────────→ GitHub Releases（存安装包）
                                      根目录 marketplace.json（目录条目）
                                                                   ③ 用：打开 LinkDesk → 插件市场
                                                                         → 看到 my-cool-plugin
                                                                         → 点安装（无需作者任何操作）
```

三个阶段：**① 做（开发期）→ ② 发（发布期）→ ③ 显示（消费期）**。作者只管 ①②，③ 是目录机制自动发生的。

## 二、命令分层——作者 vs 壳作者（两个不同世界）

| 谁 | 命令 | 上下文 |
|:--|:--|:--|
| **第三方插件作者** | 脚手架生成的**独立项目**：`npm run dev`（= `linkdesk-plugin-sdk dev` 浏览器预览）· `npm run build`（产出 `.linkdesk-plugin`）· `npm run publish`（自动发布）· `npm run validate`（schema 校验） | 作者自己的插件目录 |
| **壳作者（LinkDesk 团队）** | `npm run dev`（纯前端预览壳）· `npm run electron:dev`（完整 Electron 桌面应用 + 真实主进程） | LinkDesk 仓库 |

**关键点：**
- 同名 `npm run dev` 是两个不同东西——作者的 dev 是 **SDK 预览宿主**（E6#24），壳的 dev 是**壳预览**。
- **插件作者永远不碰 `electron:dev`**——那是编译/启动整个壳的（壳作者主场）。第三方碰壳构建链 = 违反插件独立铁律（[[plugin-independence-iron-law]]）。
- 作者要**真机验证**（真实 IPC/串口/系统能力）→ 把插件 **build 后装进已安装的 LinkDesk** 看效果（E6#28 第 2.3 轮定案——「壳侧 dev 限壳团队/出厂插件作者；第三方走装进 LinkDesk」，不造「第三方独立启动壳」机制）。

---

## 三、能力分层——浏览器 dev 能测什么

浏览器是轻量渲染环境，但浏览器沙箱不能碰桌面能力。**两层互补**：

| 插件类型 | 浏览器 dev（E6#24） | 真机验证 |
|:--|:--|:--|
| Web/UI 类（数据可视化、工具面板、主题、语言） | ✅ 全覆盖，热刷新，浏览器 DevTools 断点 | E6#28 壳侧 dev（壳团队） / 装进 LinkDesk（第三方） |
| 数据源类（**串口助手**） | ✅ UI/逻辑全覆盖——`window.linkdesk.serial.*` 走 **Mock**（E6#27 自动生成假数据流） | 装进 LinkDesk，API 变真（真串口） |
| 系统集成类（**WPS**——碰桌面 Office 进程/OLE/文件系统） | ⚠️ 浏览器沙箱不能碰桌面软件 | **必须装进 LinkDesk 验证**（主场） |

**心智模型**：浏览器 dev 覆盖「**逻辑正确**」，装进 LinkDesk 覆盖「**硬件真实**」；Mock（E6#27）是两个世界的桥。

---

## 四、作者 debug 流程——破除「打包→上传→看→删」循环

**不存在「每次打包→上传→看效果→发现 bug→删包→debug→再封包」循环**。那是没有 dev 环境时代的痛苦，E6#24 建 dev 宿主就是为了消灭它：

```
VS Code 写代码 → git bash 敲 npm run dev → 浏览器热刷新看效果 + DevTools 断点
              → 需要真机能力 → 装进 LinkDesk 看 → 满意后 npm run build
              → npm run publish（一次性动作，不是循环）
```

打包/发布是**收尾动作**，不是每次调试的必经步骤。

## 五、发布入口定案（2026-08-30）——CLI 主路 + 市场 UI 备路

> 原 [03-插件发布流水线.md §三](03-插件发布流水线.md) 只有「市场 UI 发布按钮」一种入口；[01-GitHub-Releases方案.md §六.4](01-GitHub-Releases方案.md) 写 `npm run publish`——两说法并存。**2026-08-30 拍板：主路 = 命令行**。

- **主路（作者日常，命令行）**：`npm run publish`（= `linkdesk-plugin-sdk publish`）→ 第一次填一次 GitHub PAT（存 `app.*` 配置，audit-config-baseline 保底）→ 自动：**创建 Release + 上传 `.linkdesk-plugin` + 更新作者自己仓库根目录的 `marketplace.json`**。全在终端里完成，不打开 LinkDesk。
- **备路（可选图形入口，软件内）**：LinkDesk 市场插件里「发布插件」按钮（PAT 登录后可见）→ 文件选择框选 `.linkdesk-plugin` → 走**同一套**自动发布链路。给「不想碰命令行的人」或「想在软件内看一眼再发」。
- **自动发布链路（CLI 与 UI 共用底座，E6#26b/#26c）**：GitHub REST API——创建 Release + 上传 asset + 更新 marketplace.json；PAT 存配置。否决手动网页上传（[[no-deferral-future-excuse]]）。

## 六、市场心智模型——目录 + 多源

```
marketplace.json = 货架目录（一个 GitHub 仓库根目录的 JSON）
添加市场源       = 告诉商店「除了官方货架，再看作者这个仓库的货架」
两个货架合并     = fetch 全部源 → 去重（同 id 取版本高者）→ 统一展示，卡片标来源
```

- **提交到哪里**：作者**自己的 GitHub 仓库**——不需要官方审核、不进中心目录（对标 npm 多 registry / VS Code 多 marketplace）。仓库放两样：
  - **GitHub Releases** → 存 `.linkdesk-plugin` 安装包（免费 CDN，不限流量）
  - **根目录 `marketplace.json`** → 目录条目（`id / name / version / downloadUrl / icon / readmeUrl / screenshots / versions[]`……**纯增量**，加字段不破坏旧插件）
- **软件拉一次目录**：fetch 各市场源的 `marketplace.json`（raw URL）。官方默认源 + 作者自定义源。
- **「添加市场源」**：**本质是配置项**（marketplace 插件命名空间 `marketplace.marketplaceSources = [{id, url}, ...]`，E6#30c 定案——壳零改动）；**UI 是表单**（市场页/设置里「添加市场源」，填仓库 URL）。
- **发布即可见，无需中间人**：作者发版 = 往自己货架补新条目 → 几秒后所有加了该源的人都能看到。AI 一站式也成立：agentA 制作上传 → agentB 加源 URL 即装。
- **想让「所有用户」默认看到 → 申请收录官方目录**（2026-08-30 混合模型定案，[01-GitHub-Releases方案.md §6.7](../03-插件市场/01-GitHub-Releases方案.md)）：作者把条目提交到官方仓库（`encaron/linkdesk-marketplace`）→ 进官方 `marketplace.json` → 所有用户默认可见（官方源内置、零操作）。**早期形态 = 给官方仓库发 PR 加条目**；未来可自动化。**两路不冲突**：先自仓库发（立即用）→ 想扩大影响再收录官方；官方源与多源合并去重（同 id 取版本高者），来源标注区分。
