## 三、四特例（动手前单独回报；以下为我的建议，待拍）

### D2 · token 收口
- `plugins.requestInstall / requestUpdateBatch` 是**唯一远程安装入口**；壳内「画卡 → 确认 → 签 token → 立刻执行」同一事务。
- token：内存 Map，一次性 nonce，60s TTL，绑定 `pluginId + version + sourceUrl + sha256`；核销即删。
- 原 `plugins:install` / `plugins:update` IPC：**无 token 即拒**（`no-token` ＋ 日志）。
- **建议白名单（如实登记，不是漏洞）**：本地文件安装两条腿 `installFromDirectory` / `.linkdesk-plugin` 包安装（`installWithProgress` 来自文件关联/拖拽的**用户手势**、无远程 source）**不过 token 门**，但仍记来源账本。理由：给本地文件发 token 只是自己给自己盖章，且会让文件关联安装链路多一跳失败点。
- **风险**：dev 里现装 marketplace 1.4.25 会在壳切换后立刻报 `no-token` ⇒ 批 4 市场回落必须先就位，**壳与 marketplace 同一轮 dev 改完再重启**。

### D4 · 批量并发
- `INSTALL_CONCURRENCY = 3` **不动**——它是下载/解压并发槽，不是条数上限；批量 = 一次确认后 N 项全部入队，队列按 3 槽流水。
- batchId→jobIds 映射**只存在 confirm-service 内存**（通知汇总用），⛔ 不进 job 表（`InstallJob` 是池可达公共 DTO，加字段＝改契约面，收益不抵风险）。
- 20+ 条靠原型已有的滚动区 ＋ 分组计数 ＋ sticky 表头/底栏；>50 条才谈虚拟化。

### D8 · 渲染槽
- 现状：壳里**没有** `dialogChrome` / renderer slot 机制（全仓 grep 零命中）⇒ 要新建贡献点 `contributes.renderers`。
- 建议形态：`contributes.renderers: { installConfirm?: string, updateBatch?: string }` 指向插件自己的视图 id；壳注册表解析不到/崩溃 ⇒ 默认渲染器（`plugin-install-confirm`）⇒ 纯文字 confirm（三级兜底）。
- 工作量提示：这是本轮唯一「新增贡献点」，连带 sdk schema ＋ 校验 ＋ 文档 ＋ R1/R4/R8 门禁对账。**建议照此做，但不把它塞进批 2 的第一版**——批 2 先落「槽接口 ＋ 默认渲染器 ＋ 注册表」，第三方替换的 schema 在批 3 补（同一轮交付，不跨轮）。

### settings 1.0.50 是否真需要发
- **建议：本轮不发。** 两条 Toggle 是纯配置（通用渲染器直接出）；信任清单用「只读列表 ＋ 命令面（`trustSource`/`untrustSource`）」——设置页显示状态，操作走命令（AI 也可操作，符合硬约束 26）。
- `HostSettingSlot` 是「一次换长期零发版」的好东西，但它要 settings 仓改一次（线 2 唯一提交者），**建议单独立项**，不阻塞 P1。
- 若用户坚持本轮要逐源开关 ⇒ 我带标识给线 2 发需求（`renderHint: "hostSlot"` ＋ `slotId: "pluginSourceTrust"` ＋ 1.0.50）。

### 6.5 逻辑说明

- **确认策略矩阵**：见 6.1 `policy.ts` 行；两条开关**正交**（官方只认 `silentOfficial`，第三方只认 `silentTrustedSources ∧ 已信任`），官方 fixed 信任不参与免问判定（单测「正交铁律」一例守死）。
- **批量分组**：按来源分组；有 ask 的组在前、纯 silent 组在后；组内保持请求顺序；`totals` 只算 ask+silent（拒项单列）。
- **取消语义**：单卡取消 = 该次不执行（`cancelled:true`）；批量取消 = **整批 0 个入队**。
- **失败/回滚**：执行端口把 loader 回执原样透出；job 表负责进度/回滚（stage→unload→commit→回滚，未改动）；批量完成时成功→轻 toast、失败→铃铛面板 + [重试]（重试重走 `requestUpdateBatch`，会重新按策略判定）。
- **D2 门**：远程 `install/installWithProgress` 与 `update` 在 IPC 分发层一律拒；本地路径安装两条腿放行（拍板）。判断函数 = `policy.isRemoteSource`（单一实现）。
