# Python

![python 场景封面「补全的窗」（E6#69b 三图模型——整幅场景封面住 README，市场展示位走 Type-2 彩色图）](resources/cover.svg)

让 LinkDesk 编辑器「懂」Python——打开 `.py` 文件，语法高亮、智能补全、跨文件跳转、诊断，一次配齐。

> 它没有自己的窗口，也没有自己的面板。它的全部工作都在你编辑 Python 的那一刻发生——这正是语言支持插件该有的样子：**存在感越低，说明做得越好。**

## 这是什么

一个语言支持插件（零界面、纯声明）。它往 LinkDesk 的语言注册表里贡献了一格：

- 认出 `Python` 文件：扩展名 `.py` / `.pyi`
- 接上语言服务器：`pyright`（随插件自带，自动启动）

编辑器拿到 `.py` 文件后，自动把这套超能力点亮。

## 四件事，全自动

| 能力 | 谁干的 | 什么时候你感觉到 |
|---|---|---|
| 语法高亮 | Monaco 内置 TextMate 语法 | 一打开 `.py`，关键字/字符串/注释就分开配色 |
| 智能补全 | pyright LSP | 敲 `imp`，浮出 `import …` 候选 |
| 跨文件跳转 | pyright LSP | Ctrl+点击函数名 → 跳到它定义的那个文件 |
| 诊断 | pyright LSP | 写错类型，底下冒红色波浪线 |

你不需要配置任何东西——插件安装后，打开 `.py` 它就开始工作。

## 它到底是怎么工作的

插件本体几乎只做一件事：在 `plugin.json` 的 `langDefs` 里**声明**「Python 的语言服务器是 pyright、用 node 拉起、走标准输入输出通信」。剩下的智能，全部由 pyright 语言服务器完成，LinkDesk 负责把它和编辑器接起来。

所以它很小、很安静、很好卸载——卸掉它，`.py` 回到无高亮的纯文本，别的一切不受影响。

## 结构

```
plugin.json       语言声明（langDefs：扩展名 + pyright LSP 启动方式）
src/index.tsx     入口（纯声明——无 UI，返回空）
package.json      pyright 依赖（^1.1.413，随插件自带）
```
