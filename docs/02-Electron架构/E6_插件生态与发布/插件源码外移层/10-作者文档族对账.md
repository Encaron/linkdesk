## 〇、为什么单独立一条任务（不是顺手改改）

**两条机械耦合把「文档同步」从「最好做」变成「必须做」，且暴露了一个真空：**

| # | 事实（2026-09-14 回源） | 后果 |
|:--:|:--|:--|
| ① | `check-plugin-schema-sync.mjs` 管 **3 组 7 份** schema 的**字节相等**，其中**一组就是 `docs/03-插件制造/plugin.schema.json`**（`copies[0]=live` 权威） | 🔴 **`E6#98g` 往 live schema 加 `pluginId` 的那一笔，如果不同步这一份 ⇒ `npm run check` 当场红** |
| ② | `check-contributes.mjs` 的三条不变量**全部限定在 `contributes.*` 域**（schema→文档 / 拷贝漂移 / schema→消费面） | ⚠️ **顶层新字段（`pluginId` 就是这样）的文档覆盖「没有任何机械兜底」** ⇒ **本对账任务是它唯一的保险，必须人工过** |
| ③ | 其余机械兜底各有边界：`check-doc-links` 只管**链接存在性**（不管内容对不对）；`check-api-contracts` 管 `window.linkdesk.*` 引用；`check-namespace-matrix` 管命名空间矩阵 | 「链接没断」≠「内容还对」——**语义过期这类腐坏，机械门禁看不见** |

⇒ **结论：文档族的语义陈旧只能靠人工逐篇过，而这次要过的是十五篇。**
