# 双段快捷键注册被打乱（normalizeKey 对 chord 串不成立）

> **待抉择**——壳的 `normalizeKey()` 把**整串**键位按 `+` 切分再排序，**双段（chord）键位串会被打乱**：
> 注册进去的键位与按下时拼出的键位对不上 ⇒ **该快捷键静默失效**（不报错、不进冲突表、设置页还显示得好好的）。
> 2026-09-14 由 **E6 第 4 层收尾**（给 `my-cool-plugin` 加 `ctrl+k ctrl+q` 时）实测发现并登记。

---

## 定位

| | |
|---|---|
| 类型 | **壳侧真缺陷**（`src/core/utils/keybindingNormalization.ts` 的 `normalizeKey`） |
| 影响面 | **只有双段（chord）键位**——单键键位串里没有空格，行为正确 |
| 涉及架构改动 | **无**——`normalizeKey` 是纯函数，改成「先按空格拆段、每段各自归一化、再拼回」即可 |
| 谁来修 | 壳源码 ⇒ 需要**一次软件版本更新**（PATCH）；作者侧的插件不用动 |

---

## 实证（2026-09-14）

`normalizeKey(key) = key.toLowerCase().split("+").map(k => k.trim()).sort(compareModifiers).join("+")`
——`split("+")` 不认识空格，于是第二段的 `ctrl` 被并进第一段的字符里当普通 token 参与排序：

| 键位串 | 归一化结果 | 结果 |
|:--|:--|:--|
| `ctrl+k ctrl+t` | `ctrl+k ctrl+t` | ✅ 侥幸不变（既有 `theme.pick`） |
| `ctrl+k ctrl+l` | `ctrl+k ctrl+l` | ✅ 侥幸不变（既有 `workbench.action.selectLanguage`） |
| `ctrl+k ctrl+q` | `ctrl+k ctrl+q` | ✅ 侥幸不变（本轮新增，实测能触发） |
| `ctrl+k ctrl+h` | `ctrl+h+k ctrl` | ❌ **打乱 ⇒ 死键** |
| `ctrl+k ctrl+shift+p` | `ctrl+shift+k ctrl+p` | ❌ 打乱 |
| `ctrl+alt+k ctrl+alt+p` | `ctrl+alt+alt+k ctrl+p` | ❌ 打乱 |

**「侥幸不变」的条件**：第二段的字母要 ≥ `k`（`localeCompare("k ctrl", X) < 0`）。字母 a–j 一律被打乱。
——即：**能不能用完全取决于你挑的是哪个字母**，而这没有任何文档或门禁会告诉你。

**为什么没被发现**：注册路径只有 `registerKeybinding()` 一处调 `normalizeKey`，两条既有 chord 都是
`ctrl+k ctrl+t` / `ctrl+k ctrl+l`（正好都在「侥幸」那一侧）。直到本轮第一次去挑一个「偏门」的键位才撞上。

**静默性**：`isChordPrefix()` 用 `b.key.startsWith(normalizedKey + " ")` 判第一段——被打乱后前缀对不上，
所以第二段按下去后主进程/壳的 chord 状态机都匹配不到，**没有任何日志、没有冲突提示**。

## 建议修法（未拍板）

```ts
export function normalizeKey(key: string): string {
  // 双段（chord）：按空格分段，**每段各自归一化后原样拼回**——空格是段分隔符，不是可排序 token
  return key
    .trim()
    .split(/\s+/)
    .map((stroke) =>
      stroke.toLowerCase().split("+").map((k) => k.trim()).filter(Boolean).sort(compareModifiers).join("+"),
    )
    .join(" ");
}
```

⚠️ **改之前要看的两处**：
- `electron/windows/keyboard-router.ts` 与 `electron/preload-pool|preload-shell` 都 import 本模块的
  **`keyboardInputToKeyString`**（单段路径）——本改动不动它，但同文件共用一个 `<` 依赖面，改完要跑全量 check。
- 加了回归测试再改：至少覆盖 `ctrl+k ctrl+shift+p`（打乱侧）与 `ctrl+k ctrl+t`（不变侧）两个方向。
