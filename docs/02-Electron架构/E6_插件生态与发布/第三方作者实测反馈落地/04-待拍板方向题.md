## `E6#141` game 模板 ＋ canvas mock

- **前因**：第三方作者造游戏插件时无任何配方可循——keep-alive 下游戏该做什么（`isActive` 暂停 / dt 钳制防切页时间跳变 / 键盘只在活跃时收 / `visibilitychange` 处理）全靠自己设计；jsdom 里 `getContext("2d")` 不可用，测试只能逼他把引擎写成纯逻辑——**这个模式值得固化**，但没人告诉他，他是撞出来的。
- **核对结论**：文档树 00–20 无 canvas 专题；模板 `vitest.setup.ts` 无 canvas mock。真缺口。
- **范围草案**（拍板后细化）：① 模板 `vitest.setup.ts` 加 canvas 2D mock（⚠️ 该文件与壳仓**逐字同源**——动它 = 两处同笔改，这是本格最大的连带）；② 脚手架 `--template=game` 变体（或一篇《20-building-a-canvas-game.md》配方文档 ＋ 指针，二选一）；③ keep-alive 游戏四纪律写进配方。
- **你要说的那句**：做不做？做的话选「模板变体」还是「配方文档」（模板变体重，配方文档轻；第三方作者的建议是两者都要——`--template=game` ＋ 配方文档 ＋ canvas mock）。

## `E6#142` contentCanvas 一等声明

- **前因**：Canvas 游戏画面配色自含（美术不随主题走）是天然正当的，但现行豁免是文件头 `eslint-disable linkdesk/no-hardcoded-hex -- 内容画布` 注释——能用，像补丁；偏离标签跟着包走，且作者要读到 lint 输出尾部小字才知道出口存在。
- **核对结论**：plugin.schema.json 无 contentCanvas 字段。真缺口，但是**能力面扩展**（新 schema 字段 ＋ lint 消费 ＋ 市场显示联动——市场详情页的「偏离」展示要把这类豁免摘出去）。
- **你要说的那句**：做不做 ＋ 落点选 `plugin.json` 字段（作者声明，市场可读）还是 SDK 配置文件（纯构建期）——前者生态可见性好，后者改动面小。

## `E6#143` catalog:submit（收录工具化）

- **前因**：上架是两步走（publish 只写自己仓 → 官方目录收录才默认可见，memory `plugin-source-external-repos`），SDK 把第 1 步自动化到极致，第 2 步零工具且 marketplace.json 无 schema（schema 部分已由 **#135** 解决）。第三方作者是用脚本调 GitHub Contents API（读 sha → 合并 → PUT）手工完成的。
- **核对结论**：**半设计如此**——收录走人工环节是「混合模型定案」（官方目录 = 出厂 ＋ 已收录第三方，**收录即人工闸门**）；全自动直写目录 = 绕闸门，与「安装确认每次都要问」「官方目录收录才默认可见」的红线相顶。
- **你要说的那句**：做不做 ＋ 形态三选一——**A. 只生成 PR patch**（作者本地产出待合并条目，人工过目后收，不碰闸门）；**B. 收录请求队列**（SDK 提交请求 → 维护者审核 → 人工合并）；**C. 不做**（维持手工 + #135 的 schema 就够了）。工程建议 A——最低成本且不绕闸门。
