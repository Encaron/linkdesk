# 23-修复 · 改名迁移「补跑通道」（轮 1.46b · 编号 `#111n-5b`）

> 立档：2026-09-17（1.46 清账 · `settings` 收尾时实测发现）
> 位置：**插在 1.47（清账 · 主题族）之前**——它不是清账格，是**迁移机制的 bug 修复**。
> 类型：Bug 修复（照 `design-flow` §Bug 修复规范：**修前必答三件事**，先写再改）。
> 轴归属：本轴的「不改机制」讲的是**归属与判据**；本修复治的是**迁移编排的真缺陷**（会静默丢用户值），
> 经用户 2026-09-17 当次点头单开一小轮。

---

## 一、怎么发现的（现象）

1.46 收尾时被问「为什么这一轮没有版本号变更」，顺着去核用户自己的盘，实测到：

| 项 | 读数 |
|:--|:--|
| `%APPDATA%/linkdesk/settings.json` 的 `app.schemaVersion` | **11** |
| 同一份盘上的 `files.autoSave` | **`"afterDelay"`**（该键默认 `off` ⇒ 用户真设过，不是默认快照） |
| `editor.autoSave` | **不在盘上** |
| 实装 `editor` 插件 | **1.0.11**（仍声明旧名 `files.autoSave`；改名后的 1.0.12 已上架、未装到本机） |
| 对照 `file-tree` | 17 个键**全是新名**（`explorer.*` = 0）、`keybindings.json` 里 `explorer.` = 0 / `file-tree.` = 5 |

⇒ 同一套机制、同一批版本号：`file-tree` 的键**搬成功了**，`editor` 的那一条**被跳过且永不重跑**。

## 二、根因（三件事之①：`file:line` ＋ 机制）

- `src/core/services/configuration/schemaMigrations.ts:140`（`runNamespaceRenameMigration`）：

  ```ts
  const declared = Object.entries(maps.setting).filter(([, next]) => next in schema);
  ```

  **只有新名已被声明才搬**（`next in schema` 门禁；理由见同档 :98-108：插件还没声明新名就硬搬 =
  设置页当场把用户的值读成默认 —— 迁移自己制造它要消灭的那个病）。本机那一刻 schema 里没有
  `editor.autoSave`（实装 editor 1.0.11 只声明旧名）⇒ 这一条**整组跳过、零写**。
- `schemaMigrations.ts:294-295`（编排落盘段）：`batch.push({ key: SCHEMA_VERSION_KEY, value: pending[last].version })`
  —— **零产出也提升版本标志**（模块头 :19-20「成功语义含零产出」；那条语义是给**没有门禁**的 #85/#86/#90 步骤定的）。
- `schemaMigrations.ts:253`：`pending = migrations.filter(m => m.version > current)` ⇒ 版本一旦越过，该步**永不再选中**。

**机制一句话**：版本门禁是**单调自耗**的，而改名步骤要不要真干活取决于**那一刻插件在不在**；
两者绑在一起 ⇒ **插件晚到 = 这一步白烧 = 用户的旧键永远搬不过去、新名读默认**。

1.42 已踩过同一个坑（v7 被提前烧 ⇒ 补 v8），1.43–1.45 又连补 v9/v10/v11 —— 每轮的修法都是"再加一个版本号"，
而版本号本身仍依赖"插件比壳先到位"这个**时机**。本机今天证明这个时机在真实机器上会失手：
插件靠市场安装、壳靠重启，`「插件先发、壳后发」`只约束**发布顺序**，管不住**某台机器上的到达顺序**。

**影响面**：不是一台机器。任何先更壳、后装（或没装）改名插件的用户都会中，且**不可自愈**。

## 三、改法（三件事之②：哪个文件哪个函数）

1. `src/core/services/configuration/schemaMigrations.ts`
   - 把 `runPendingConfigMigrations` 的**落盘段**（写新值 → `takeLastFileWriteFailed()` 复核 → 再删旧键）
     抽成私有 `commitConfigWrites({ batch, deletes, advanceTo })`：`advanceTo` 为 `undefined` 时**不写版本标志**。
     批次收集闭包也抽成一份 `makeBatchCollector(batch, deletes)`（不抄第二份）。
   - 新增**模块内**函数 `repairRenamedKeys()`：跑**同一个改名体**（`runNamespaceRenameMigration`，纯数据复用），
     走**同一段落盘**，**不写 `app.schemaVersion`**。幂等靠既有两道自守：presence 门控（旧键没值不产出）
     ＋「命中即恒等」（已迁 ⇒ 再跑零命中）。失败**不抛**（补跑是收敛动作，不该拦启动）：记 `console.error`，下次启动再试。
     ⚠️ **不导出**（首版导出过 ⇒ knip 判「死导出」红）：判据一律走**生产入口** `runPendingConfigMigrations()`
     ——直接从测试里调补跑函数就不是在测接线了（memory `gate-selftest-must-be-wired` 的同一坑）。
   - `runPendingConfigMigrations()` **末尾**（版本记账跑完之后、早退之前）调一次 `repairRenamedKeys()`。
     **顺序是判据的一部分**（首版写反过，被既有判据当场判红）：补跑**在记账之后**——
     待执行迁移在场时先按 1.41 定下的原语义走完（「先写新值、再删旧键」与「任一失败即原子中止」
     一条不动，既有四条落盘顺序判据不受影响）；又**在早退之前**——`pending` 为空（版本记账已跑满 =
     门禁空烧的现场）时照样对一次账。放**开头**的话，补跑会先吞掉注入的写失败，
     版本记账那一步随即「成功」⇒「写失败必须原子中止」的判据被架空。
2. `src/App/startup.ts`：**一行不改**（有意）——生产接线点（:266）保持原样，补跑搭在**已被生产验证过**的同一条路径上，
   不新增"函数写好了没人调"的缺口（memory `gate-selftest-must-be-wired` 的同一坑）。

**效果**：顺序不再是判据 —— 先壳后插件、先插件后壳都收敛（每次启动对一次账，命中即零写）。

## 四、判据（三件事之③：验证路径）

单测全在 `src/core/services/configuration/schemaMigrations.v7rename.test.ts` 的**真持久化链**组里
（子组「1.46b 补跑通道 · 版本记账已跑满」）——它复用 1.41 那套内存盘 ＋ 假 `FileService`，
本组的种子版本从 6 换成 **11**（= 门禁空烧的现场）。

| # | 判据 | 形态 | 实测读数 |
|:--|:--|:--|:--|
| ① | **复现本机形态**：schema 声明新名 ＋ 旧键有值 ＋ `app.schemaVersion` 已是 11 ⇒ 走生产入口后值搬到新键、旧键被清、**版本标志不变** | 单测（驱动 `runPendingConfigMigrations()`，即生产入口） | ✅ 绿（新键 `false`、旧键消失、盘上版本仍 11） |
| ② | **幂等 ＋ 零写**：连跑两次，第二次**零写盘**（不是「写同值」——`writeFile` 一次都不发） | 单测 | ✅ 绿 |
| ③ | **门禁仍设防**：新名**没被声明**时**不搬**（否则＝把用户的值搬到没人读的新名上，正是 1.42 记录的病） | 单测 ＋ 负控 | ✅ 绿（且 `writeFile` 计数 = 0） |
| ④ | **补跑失败不拦启动**：写失败 ⇒ 不抛、值不丢、无版本可提升、下次启动重试 | 单测 | ✅ 绿 |
| ⑤ | **接线**：删掉 `runPendingConfigMigrations()` 里那次补跑调用 ⇒ ① 必须真红 | 变异负控（改源码、跑、**逐字节还原**） | ✅ 真红（`expected undefined to be false`） |
| ⑥ | **实机**：本机装 editor 1.0.12 → 启动 → `files.autoSave` 搬成 `editor.autoSave`、值仍 `afterDelay`、旧键消失 | 前后两份盘上读数（高风险必实机门禁） | 见下「实机读数」 |

**负控读数**（照 1.40 的规矩：判据必须在**打坏版上真跑**过才算数；改源码一律「备份 → 变异 →
跑 → 按 sha256 逐字节还原」，⛔ 不用 `git checkout` 还原）：

| 变异 | 期望 | 实测 |
|:--|:--|:--|
| M1 取掉 `await repairRenamedKeys();` | ① 红 | ✅ 1 failed（`expected undefined to be false`） |
| M2 `declared` 门禁打坏（`.filter(() => true)`） | ③ 红 | ✅ 1 failed（`expected 2 to be +0`，即门禁没了就真写盘） |
| M3' presence 门控打坏（`userValue === undefined` 不再跳过） | ② 红 | ✅ 1 failed（第二次启动写了第 3 次盘） |

**一条如实登记的发现**：`repairRenamedKeys` 里「零命中即返回」（`if (batch.length === 0 && deletes.length === 0) return false;`）
**不是判据面**——把它取掉（变异 M3）全部用例照样绿，因为**空批次本身就是零写**
（`setConfigurationValueBatch([])` 不落盘）。它留着只是省一次空调用；**真正守着「每次启动零写」的是
presence 门控**（M3' 才是那一格的负控）。⇒ 打坏要打**真正决定行为的那一格**。

### 实机读数（⑥ 的现场）

**方法**：本机实测时**用户自己的 LinkDesk 实例正在运行**（已装的 0.2.8）⇒ 单实例锁会挡掉开发态实例，
而**关掉用户的实例去跑真机盘**属于「动用户的盘」，本格**不做**（见 §五 不做第 6 条）。
⇒ 改用**复制盘**：把 `%APPDATA%/linkdesk` 的 `*.json` ＋ `plugins/`（77MB，23 只插件）复制进临时 userData，
用 `--user-data-dir` 起**真 Electron ＋ 真插件树 ＋ 真 `settings.json`**（脚本侧 `vite` 供 renderer）。
复制盘位置：`%LOCALAPPDATA%/Temp/linkdesk-liveproof`（含 `settings.json.before` 与两份 electron 日志）。

| 时刻 | `app.schemaVersion` | `files.autoSave` | `editor.autoSave` | `files.*` 键数 |
|:--|:--|:--|:--|:--|
| 启动前（= 本机形态逐字节复制） | 11 | `"afterDelay"` | —（不在） | 1 |
| 首次启动后（**补跑生效**） | **11**（不动） | **—（旧键已清）** | **`"afterDelay"`** | **0** |
| 第二次启动后 | 11 | — | `"afterDelay"` | 0 |

**第二次启动的写入判据**：`settings.json` 的 **sha256 `3b8058350dd2c591…` ＋ mtime 一字未动**
⇒ 「每次启动对一次账、命中即零写」这条承诺在真实运行时成立（不是只在单测的内存盘上成立）。

⚠️ **诚实边界**：跑的是**复制盘**而非用户正在用的那份盘——本格的实机证据覆盖「**同一形态的数据在真运行时会被搬**」，
**不覆盖**「本格已改动用户机器上的那份盘」（那份盘要等 **0.2.9 发布并装上**后的首次启动才会被搬）。
另：日志里有 `first-run-setup` 状态栏 bundle 的加载失败（`/@fs/` 路径在临时 userData 下不被 vite dev server 服务）
——与本修复**无关**（该插件的 manifest 照常注册；证据 = 迁移确实读到了 `editor.autoSave` 的声明），如实记在这里。

## 五、不做（边界，明写）

| # | 不做 | 理由 |
|:--:|:--|:--|
| 1 | **不加迁移版本号（v12）** | 补跑通道不依赖版本号；加 v12 只给"这一台机器/这一轮"续命，且同样有"插件必须先到位"的前置条件（先启动新壳 ⇒ v12 照样被空烧） |
| 2 | 不改「零产出也标记已迁」这条语义本身 | 它服务的是**没有门禁**的 #85/#86/#90 步骤，那条语义是对的；本修复只给**带门禁的改名步骤**另开一条不受版本门禁的通道 |
| 3 | 不动账 / 判据 / 命名 | 本轴归一件事：这是**迁移机制**的 bug，不是命名问题（名字仍归 1.47+） |
| 4 | 不改任何插件仓 | 插件侧无缺陷；本修复**纯壳侧** |
| 5 | 不重写迁移机制 / 不重构注册表 | 只加一条补救通道；既有步骤的语义、注册表结构、`app.schemaVersion` 的含义全部不动 |
