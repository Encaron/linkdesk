## 一、先把「缓存」这个词拆开（不拆清，第 4 点必然出错）

真机实测（2026-10-02，全新安装态，`%APPDATA%\linkdesk` 合计 **70.6 MB**）：

| 目录 | 体积 | 能不能删 | 是什么 |
|:--|--:|:--|:--|
| `Cache` | 12.0 MB | ✅ 可再生 | Chromium 网络/资源缓存 |
| `GPUCache` / `DawnGraphiteCache` / `DawnWebGPUCache` | 1.6 + 0.5 + 0.5 MB | ✅ 可再生 | 着色器/GPU 缓存，删了自动重建 |
| `Code Cache` / `Local Storage` / `Network` / `Session Storage` / `Shared Dictionary` | ≈0.2 MB | ✅ 可再生 | 渲染层缓存与会话存储 |
| **`plugins`** | **55.5 MB** | ❌ **删不得** | **已安装的插件本体 = 数据** |
| `appearance` / `update` / 若干 json | ≈0.1 MB | ❌ 删不得 | 您的配置与更新状态 |

**结论**：能安心清的只有 **≈14.6 MB**。`plugins` 占 79%，它是「用户装的东西」，不是缓存。
⇒ **「清除缓存」这颗按钮，绝不允许碰 `plugins`、`appearance`、各类设置 json。** 想清插件那是「重置」的另一件事，不塞进这颗按钮（决策点 **D3**）。

## 三、★ 落点契约（谁写谁读 —— 直答"安装器改了地址，软件内仍是旧地址"）

**这是整件事的核心，也是用户最怕的那句硬编码。**

```
【安装器】用户填了缓存目录                    【软件】启动
   │  仅当非空                                │
   │  写 HKCU\Software\LinkDesk\CacheDir  ────▶ 若「值存在」且
                                                「软件内 app.storage.cacheDir 为空」
   │                                                 │
   │                                                 ▼
   │                                        采用它作为 app.storage.cacheDir
   │                                        （= 写进设置，UI 上看得见）
   ▼                                                 │
（此时注册表只是"种子"）                              ▼
                                          此后【以软件内设置为准】
                                          注册表**不再被回读覆盖**
```

三条铁律：

1. **安装器只在"播种"时写注册表，且只在用户真填了值的时候写。** 留空 = 一个字都不写（⛔ 绝不把「默认路径」当值写进去——那会变成一个永远回弹的硬编码）。
2. **软件内设置是权威。** 启动时只在「软件内还没有值」时**采用**种子；一旦设立，之后用户在设置里改成什么就是什么，**注册表不会把它弹回去**（决策点 **D2**：采纳"播种制"，否决"注册表恒为准"）。
3. **任何地方都不再存第二份缓存路径。** 「打开缓存目录」永远在**主进程**解析**当前生效**的路径再去 `openPath`；卸载器、完成屏、关于页都不复制这个字符串。

⇒ 这套是**照抄壳里已有的先例**（`src/App/startup.ts:302-317`）：`app.osIntegration.fileMenu / .dirMenu / .fileAssoc` 这三个键就是「注册表状态 ↔ 配置项」的镜像——启动读注册表写进配置，`onApply` 写回注册表。缓存目录沿用同一手法，**同一套机制、同一处代码风格**，不是新发明。

## 五、为什么「清除缓存」不放进安装器（用户第 6 问我给否定）

| 维度 | 安装器 | 软件内 |
|:--|:--|:--|
| 时机 | 一辈子一次（装的时候） | **每天**（缓存是会长的） |
| 对象 | 还没装出来的东西 | 装好的东西 |
| 反悔 | 没法反悔（装完就走） | 随时可用、可再清 |

**安装器该管的是「装之前的决定」**（放哪、要不要右键菜单、PATH），**不是「装完之后的维护」**。把"清除缓存"塞进安装器 = 用户想清缓存时得重跑安装程序——这是反直觉的。
⇒ 安装器侧只做**一次性播种**（用户真填了才写），**清除永远归软件内**。
> 📌 「选择缓存目录」在安装器里**长什么样**不归本夹：🔀 [../安装器-更多配置/](../安装器-更多配置/00-README.md) 已拍板把它当**容器第 ① 组「安装位置」**里的**预留槽位**（该组现在住着"安装目录"；缓存目录那一行要等宿主 `PickCacheDir` 到位才画——**旧说"只加一行"作废**：容器是竖列多项不是一行，而且它得等宿主）。
