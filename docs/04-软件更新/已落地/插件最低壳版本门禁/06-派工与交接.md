# 06 · 派工与交接（**AI-1 ～ AI-3**）

> **一句话**：**AI-1 独占 SDK 轴（串行做完全部）→ AI-2 与 AI-3 并行 → 两者收口后由 AI-3 兼职验收 = 3 个 AI**。
> 🔴 **顺序是"先串后并"**（2026-10-06 用户拍的妥当版）：**AI-1 全部收口后**才起 AI-2/AI-3。宁可慢一点墙上时间，也不让消费者对着一个**还会动的契约**写代码（§一 有收益说明）。
> 本件只讲**谁先谁后、谁许动哪个文件**；每格具体做什么，看 [00 §四](00-README.md) 任务全景与各格正文。

## 一、为什么是 3 个、为什么"先串后并"

### 1.1 决定条数的是「出口单点」，不是格子数

| 出口 | 谁从它发 | 结论 |
|:--|:--|:--|
| **`@linkdesk/plugin-sdk` npm 包**（G1 账本 ＋ G2 lint ＋ G3 脚手架与 README 全从这里出去） | G1 / G2 / G3 | 🔴 **三条腿共用一个出口 ⇒ 必须同一个 AI 串着做**（并行改同一个包 = 版本号与 `release:mark` 互撞） |
| **壳仓运行期**（`src/core/` ＋ `electron/ipc/`） | G4 | 与上面**零文件重叠** ⇒ 可并行 |
| **壳仓发布链**（`scripts/`，dev 工具、**不占版本号**） | G5 | 与上面**零文件重叠** ⇒ 可并行 |

⇒ **三条线**：SDK 轴（AI-1）／壳运行期轴（AI-2）／壳发布链轴（AI-3）。**验收不再单独占人**，并进 AI-3（§三·阶段四）。

### 1.2 为什么等 AI-1 **全部**做完，而不是只等 G1

G1 只冻结**账本形状**。但 **G2 与 G3 落地时还会反推账本**：

- G2 的报错文案要给「地板值 ＋ 越界的导入名 ＋ 出处」⇒ 可能要求账本**多记一列**（比如子路径归属）；
- G3 的脚手架要**从模板自源码算出地板** ⇒ 可能要求账本暴露一个查询形状。

**若让 AI-2 在 G1 之后就开工，它就是在对着一个会变的契约写解析。** 而"等 AI-1 全收口"让 **S2（契约冻结）自动完成**——这个隐患直接消失。**这就是"先串后并"换来的真实收益，不是保守。**

**代价**：AI-3 的 G5 本可零依赖最早开工，等 AI-1 是白等墙上时间（**不是白花钱**——AI 按次计费，不是按日历）。想省时间见 §五 的「可选提速」。

### 为什么不设第 4 个 AI（验收者为什么是 AI-3）

- **AI-2 不能当验收者**：验收的正控 1 验的就是**读数腿（G4）**——那是 AI-2 亲手写的，**自己验自己**正是 [05 §一](05-验收判据.md) 最不能接受的那种。
- **AI-3 是天然的外部视角**：它做的是发布链（G5），与门禁（G2）、读数腿（G4）**文件零重叠**，没写过被测对象。
- **负载也合适**：G5 是三格里最小的一格，AI-3 有余量接验收。

⚠️ **诚实的残余**：G5 自己那条黄灯判据属于"自写自验"（AI-3 写的 G5、AI-3 验）。风险低（**纯提醒、不拦、不进 CI**，[04 §二](04-任务-读数腿与流程腿.md)），**登记备查**，不必另立第 4 人。

## 五、派工节奏（**三步 · ⛔ 别一次派齐**）

### 第一步（✅ 已完成 2026-10-06 · 交接见 §九）：**只派 AI-1**

> 交付 = **G1 → G2 → G3 全部收口 ＋ 账本 schema 冻结 ＋ 交接板**。
> ⛔ 这一步**不许**顺手去动 `src/core/compat`（那是 AI-2 的地）。

### 第二步（⏳ 现在 · 两张启动令已发）：**AI-1 收口后**，并行派 **AI-2 ＋ AI-3**

- **AI-2** 做 **G4**（契约已冻，可以放心写）；

- 两者各写各的 §六 交接板。

### 第三步：**两者都收口后** —— **先交话，再验收**

1. **AI-2 → AI-3 传话**（被验方先交，§六 三件套）；
2. **AI-3 转验收**：存量回归（扫官方全部插件仓、修声明）＋ [05](05-验收判据.md) 全表。

### 可选提速（不影响正确性）

AI-3 的 **G5 与 AI-1 零依赖**。若想把墙上时间压短，可**让 AI-3 从第一天就开工 G5**，做完先挂着，等 AI-2 交话再转验收。代价只是 AI-3 要等（**空等不花钱**）。⛔ **AI-2 没有这个选项**——它的契约必须等 AI-1。

## 六、交接板（每棒必须留什么）

每棒收口时在**本夹内**追加一节 `交接 · AI-x`（或更新自己那格正文），**只写三件**：

1. **现状**：做到哪、哪些是**真跑过**的（门禁 EXIT / 实测读数），哪些只是"写完没验"；
2. **冻结项**：我这棒定死的契约（AI-1 必写**账本 schema**；AI-2 必写**读数返回字段**）——下一棒照此实现，⛔ **不许改形状**；
3. **下一棒的第一件事**：一句话，可执行。

🔴 **方向纪律**：**被验方先交，验方后动**。阶段三里是 **AI-2 → AI-3**（AI-3 收到 AI-2 的"现状＋冻结项＋未验项"之后才开始验收）；AI-3 的**验收结论**回写本夹，供下一位维护者。

⚠️ **⛔ 不要复述本夹已有内容**（读 00–06 即可），交接板只写"变化量"。

### 9.2 冻结项（**账本 schema** —— 下一棒照此实现，⛔ 不许改形状）

```jsonc
{
  "generatedAt": "…",          // 信息栏（工作区那份独有；随包那份是 "$comment" ⇒ 字节稳定，⛔ 别往随包那份塞时间戳）
  "shellVersion": "0.2.49",    // 打戳基准（信息栏，非判据输入）
  "components": { "HintTip": { "since": "0.2.20" }, … },
  "hooks":      { "usePluginHost": { "since": "0.2.13" }, … },
  "helpers":    { … },
  "types":      { … }
}
```

- **四栏一个不少**：`components` / `hooks` / `helpers` / `types`；每栏是**纯对象**（`名 → { since }`），键 = **导出名原文**（含类型名）。裸名字数组是**旧形态**，只允许残留在历史 tag 快照里（`surfaceNames` 归一，⛔ 别要求基线也是新形态）。
- **`since` = 壳版本空间**（不是 `@linkdesk/ui` 包版本——ui 对货不对号，E6#166）：最老含该导出首次出现提交的发版 tag；尚未发版 ⇒ 该提交时的 dev 号。
- **地板公式（唯一算点，E6#117）**：`floor = max(baseline ∪ {since(x)})`，`baseline = min(since)` 全账本；只在 SDK 那条腿里实现，⛔ 别在 G4/文档里另写第二套。
- **三份投影，一个数据源**：`scripts/ui-surface.json`（工作区真源）→ `packages/plugin-sdk/schemas/ui-surface.json`（随包、离线可核）→ `19` 文档里的 since 表。三者由 `gen-ui-surface --check` 对账，⛔ 三处都不许手改。
- **消费方**：G2 地板（已落）· **G4 读数腿（AI-2，吃这份）** · `19` 生成表。
