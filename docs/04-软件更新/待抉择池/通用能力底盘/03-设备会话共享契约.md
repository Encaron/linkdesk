# 设备会话共享契约（设备/虚拟仪器类插件）

> **状态：待抉择**（2026-11-25 立案）· 归属：通用能力底盘（轴三「连接/端点登记」＋ 串口最小面）
> **一句话**：把「设备会话」从**串口插件里的正确实现**提升为**宿主/SDK 共享契约**，让 PLC / 探针 / 虚拟屏 / 烧录器**不读 serial-monitor 源码**也能把会话、状态、属主、幂等、拔插自愈做对。

## 一、证据（真实实测，不是推测）

serial-monitor 1.0.46 ＋ 壳 0.2.66 经三轮外部 AI 实机验收（拔插、reopen、错误码）暴露并修复了一组**设备类通用问题**：

| 症状 | 根因（已修） |
|:--|:--|
| 拔线后两个会话都报 `open:true`；`receiveStatus` 与 `listSessions` 互相矛盾 | 会话状态缓存 ≠ OS 句柄事实（缺「权威态」收口） |
| 插回后 `reopen` 回 `EDEVICE 已被打开`，只能重启软件 | 壳 `closePort` 在 `isOpen=false` 时提前 return，Map 条目永不删（僵尸句柄） |
| 失败的 `openPort` 污染绑定（把可用端口改绑到不存在的口） | 失败路径有副作用（未「先验证后提交」） |
| 非属主会话 `closePort` 作用到属主会话 | 缺「端口属主唯一 + 指名作用」判据 |
| `opened:false` 但实际已打开 | 回执不是从权威态派生 |

⇒ 这 5 条**不是串口的特殊知识**，而是任何"接外部设备"的插件都会遇到的结构问题；serial 只是第一个踩全的样本。

## 二、设计（分层，真相源唯一）

| 事实 | 真相源 | 说明 |
|:--|:--|:--|
| 句柄是否真在、设备是否在场 | **壳**（OS 层） | 设备类插件**不得**自己缓存 `open` 当事实 |
| 会话（谁在用、用哪些参数） | **插件** | 业务语义（波特率/协议/暂停）归插件 |
| 状态读面字段 | **共享契约**（本档定义） | 统一 `open / devicePresent / stale / ownerSessionId` 四字段语义 |

**宿主/SDK 提供（建议形状，待评审）**

- 会话生命周期骨架（主进程）：`acquire({deviceKey, ownerPluginId, params})` / `release(sessionId, {idempotent:true})` / `getState(deviceKey?)` / `recover(sessionId)`；
- 规则内置：**先验证后提交**（打开成功才建会话/写绑定）、**属主唯一**（一个 OS 句柄只归一个会话）、**关闭幂等**、**僵尸句柄自动摘账**、**error/拔线主动释放**；
- 事件面：`device.added` / `device.removed`（轴三「设备身份握手」的输入），供 `recover` 自愈；
- SDK 侧只暴露类型与薄封装（导出面归 C）；插件侧不得再自建第二套状态机。

## 三、判据（对 07 准入表）

- **归一化**：会话状态机只有一份（宿主/SDK）；插件只声明参数与业务语义。
- **无硬编码**：壳不认识任何设备类型/插件 id；`deviceKey` 由插件声明（端口名/VID-PID/serial）。
- **无死代码**：串口现有实现收敛后删除插件内的重复状态机（⛔ 留兼容分支）。
- **高内聚低耦合**：壳只提供「句柄事实 + 会话骨架」；编码/协议/暂停仍归插件。
- **AI 友好化**：状态四字段可判读；失败有码（`ENOPORT`/`EDEVICE`/`EBUSY`/`EBADARGS`）；`recover` 是显式自愈入口。

## 四、边界（⛔ 越界）

- ⛔ 不做业务协议（MODBUS/AT/STM32 命令）——归各插件仓。
- ⛔ 不做通用 `stream` 帧契约——归底盘轴二（另一条任务）。
- ⛔ 不把编码策略塞回壳——仍归插件（D2）。
- ⛔ 不为单个插件写特判分支。

## 五、验收

1. **第二个设备类插件**（探针/PLC 任一）在**不读 serial-monitor 源码**的前提下，会话/状态/属主/恢复全部做对；
2. `doctor` 设备类不变式对**两个插件**同样成立（拔线后无 `open:true`、失败零副作用、非属主关闭被拒、幂等关闭）；
3. 拔插用例：拔线 → 状态如实 → 插回 → `recover` 成功（有耗时读数）；
4. 全量 `npm run check` 绿。

## 六、不做的代价

- 每个新硬件插件重写一套会话状态机 → 重复踩 5 类 bug；
- 状态语义各写各的 → AI 读面不可跨插件复用，doctor 无法跨领域断言；
- 「第二个作者不看第一个源码也能做全」这条判据永远不成立。

## 七、依赖与排期

- 依赖：无（串口实现即参考）；与 [04-插件间事件契约](04-插件间事件契约.md) 共享 `device.added/removed`（本任务先定）。
- 建议顺序：**本任务 → 04**。


## 八、实施规格（Block 3a · 2026-11-25 · **B 可作为 serial 消费方照此实施**）

> 结论先写死：**生命周期的唯一真源 = 宿主 `DeviceSessionRegistry`**；serial-service 退化为
> 第一个 `transport`（只管开/关/读流），插件只管参数与业务。旧 `serial:*` 面保持兼容，串口插件
> 不必一次性改完。

### 8.1 分层与文件

| 层 | 位置 | 职责 |
|:--|:--|:--|
| 会话注册表（新） | `electron/services/deviceSession/registry.ts` | 会话表、属主唯一、幂等释放、僵尸摘账、`acquire/release/getState/recover/closeByOwner` |
| transport 接口（新） | 同目录 `transport.ts` | `open(deviceKey, params) → DeviceHandle`、`probe(deviceKey) → boolean\|null` |
| `serial` transport | `electron/services/serial-service.ts` | 现有 `SerialPort` 封装收编：读循环/数据推送不动，生命周期交注册表 |
| 插件侧 | 各插件仓 | 参数（波特率/地址等）、编码、会话业务、UI |

### 8.2 宿主 API（IPC / preload-pool `linkdesk.device`）

```ts
device.acquire({ deviceKey: string, transport: "serial" | "tcp", ownerPluginId: string, params: object })
  → { sessionId: string, state: DeviceState }
device.release(sessionId: string)
  → { released: true, already?: true }            // 幂等：已摘账 ⇒ already:true
device.getState({ deviceKey?: string })
  → { sessions: DeviceState[] }                   // 有 deviceKey ⇒ 只该设备（可为空）
device.recover(sessionId: string)
  → { recovered: boolean, sessionId?: string, ms: number }
```

`DeviceState`（四字段是契约，⛔ 插件自缓存）：

```ts
{ deviceKey: string; open: boolean; devicePresent: boolean | null;
  stale: boolean; ownerSessionId: string | null; sessionId?: string }
```

`devicePresent: null` = transport 探不了（不硬判，⛔ 当 false）。

### 8.3 不变式（每条都要有负控测试）

1. **先验证后提交**：`transport.open` 抛错 ⇒ 不建会话/不写绑定（零副作用）。
2. **属主唯一**：同一 `deviceKey` 已有活会话 ⇒ 他主 `EBUSY`；**同主幂等返回原 sessionId**（⛔ 自动关先开者）。
3. **幂等释放**：`release` 先摘账再 `close`（顺序即判据）；重复 release ⇒ `already:true`，不抛。
4. **僵尸摘账**：会话在但 `handle.isOpen()===false` ⇒ `stale:true`；`acquire/recover` 先摘再开。
5. **被动丢失**：transport 报错/拔线 ⇒ 会话保留为 stale（`open:false`），由 `recover` 自愈；⛔ 自动无限重连。
6. **非属主操作**：`release` 的调用会话与记录属主不符 ⇒ `EBADARGS`（⛔ 作用到别人会话）。

错误码（宿主语义码，与插件业务码分列）：`EDEVICE`（开失败/设备不在）、`EBUSY`（属主冲突）、`ENOSESSION`（未知 sessionId）、`EBADARGS`（坏参/非属主）。

### 8.4 serial 作为第一个 transport（B 的迁移口径）

1. **不动读流**：`serial:data/stats/system` 推送、编码、`sendData/sendText/setDtr/setRts` 全部保持原样。
2. **生命周期收编**：`serial:openPort` / `serial:closePort` 的实现改为调 `registry.acquire/release`（`transport:"serial"`，`params` = 现 `OpenPortConfig`）；旧 IPC 面保留 ⇒ **串口插件 1.0.46 不改也能跑**。
3. **插件后续可切新面**：会话服务改调 `device.acquire/release/getState/recover`；`receiveStatus/listSessions` 的状态四字段从 `device.getState` 派生（⛔ 插件自己缓存 `open`）。
4. **卸载连坐**：`closePortsByOwner` 改为 `registry.closeByOwner`（同一份属主表，⛔ 两套）。

### 8.5 第二个 transport（验收用）

- 新增 `tcp` transport（`node:net`）：`deviceKey = host:port`，`probe` = 尝试连接（超时 500ms，失败 false），`open` = 建连并保持。
- 夹具插件 `dev-fixtures/device-probe/`（⛔ 不随壳发货）只用 `device:*` ＋ 本页文档实现 acquire/release/getState/recover，**不 import serial 任何代码**；验收脚本起一个本地 TCP 回环服务当“设备”。

### 8.6 验收（Block 3a 完成判据）

1. 注册表单测：6 条不变式全有正控＋负控（fake transport，不起窗口）。
2. serial 行为不回归：现有 serial-service 单测全绿；实机拔插 → `getState` 如实（`open:false/stale:true/devicePresent:false`）→ `recover` 成功有耗时。
3. 第二插件：`device-probe` 仅凭本页 §8.2–8.4 实现，四字段语义正确；代码检索证明未引用 serial。
4. `doctor` 设备类断言对 **serial 与 device-probe 两个 profile** 都成立（拔线无 `open:true`、失败零副作用、非属主 release 被拒、幂等 release）。
5. 全量 `npm run check` 绿。

### 8.7 非目标（⛔ 越界）

- 不做协议/帧/编解码（归插件）；不做事件总线（Block 3b）；不做自动无限重连；不做跨机/远程设备发现。


### 8.8 复核口径（2026-11-25 调度台四点 · 实现现状）

| # | 口径 | 实现 |
|:--|:--|:--|
| 1 | 属主由宿主校验，⛔ 不信请求体 | **已落**：`recover` 也验属主（非属主 `EBADARGS`）；池侧 `release/recover/acquire` 运行时必须有 `ownerPluginId`；壳内 `scope=host` 例外。**已知限制**：池插件共用一个 JS 上下文，主进程无法从 IPC sender 推出「哪个插件在调」——`ownerPluginId` 仍是插件自声明（与 serial 既有口径一致）。真正的宿主注入需要「每插件身份令牌」或上下文隔离，属独立安全任务（另立项，⛔ 在本轮假装已解决）。 |
| 2 | 可见性：池侧只看自己 | **已落**：`device:getState` 池侧强制按 `ownerPluginId` 过滤（缺 owner ⇒ `EBADARGS`）；壳侧 `scope=host` 可看全量（doctor/诊断）。负控：`getState{ownerPluginId:p1}` 只回 p1 会话。 |
| 3 | 错误码单一来源 | **已落**：`electron/services/deviceSession/codes.ts`（`EDEVICE/EBUSY/ENOSESSION/EBADARGS/ECAPABILITY`）——registry/handlers 只引它，⛔ 字面量散落。未并进 contracts `SHELL_ERROR_CODES`（那组是壳命令面保留码；设备子系统码表先独立，后续由 B/C 决定是否升格）。 |
| 4 | transport 能力闸 | **已落**：插件根字段 `deviceTransports: ["serial"\|"tcp"]`（manifest 根允许扩展字段）；已装插件未声明 ⇒ 只给存量 `serial`；声明不含请求 transport ⇒ `ECAPABILITY`。未知属主 id（测试标签/未安装）放行（无法查清单，留宿主后续收紧）。 |
