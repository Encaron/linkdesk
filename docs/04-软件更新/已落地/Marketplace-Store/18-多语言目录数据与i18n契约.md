# 18 · 多语言目录数据与 i18n 契约（2026-11-23）

> **来源**：用户实机截图——英文界面混中文、作者卡「官方运营的插件与主题精选」不翻译、主题/合集标题中文、`Browse by category` 英文＋中文提示、rail「作者」竖排/黄点超格。
> **定位**：本档记**根因与契约**；实施账在 `10-纠正案/09-门禁实施记录.md`，作者面在 `docs/03-插件制造/05-插件UI写法规约.md §11.3`。

## 一、根因（四层，不是「翻译没做」）

| 层 | 现象 | 根因 |
|:--|:--|:--|
| UI 字典 | 英文界面出现「还没有添加作者源」 | 3 个 `t()` key 在 en/zh 字典都不存在；own-dict 腿是**黄灯不拦**，只数 key、不要求 en/zh 等长 |
| 硬编码 | 「官方目录 / 官方内置与精选插件 / 官方运营的插件与主题精选」中文 | `authors.ts` 合成官方域直接写死中文，没走 `t()`/locales |
| 目录数据 | 「主题专区 / 装机必备 / 官方精选」中文，卡片名英文 | 合集 title、插件 name/description、作者 storeTitle/intro 都是**单语言字符串**；marketplace-kit schema 无 locale 字段 |
| 布局 | 英文 Author 黄点超格 / 中文「作者」竖排 | compact rail 行没有 nowrap/省略，数字 `margin-left:auto` 把点顶到边界；点从 absolute 改 static 后没预留位置 |

## 二、契约（`locales`）

- **UI 字符串**仍走 `t()`（key=中文原文）；`contributes.i18n` 声明的每种语言键集必须相等。
- **目录数据**（插件 name/description、合集 title/hint、作者 storeTitle/intro、仓库 name/intro、板块 title/hint）走 `locales`：

```json
{
  "name": "官方主题",
  "locales": {
    "en": { "name": "Official Themes", "description": "Bundled dark/light themes" },
    "de": { "name": "Offizielle Themes" },
    "fr": { "name": "Thèmes officiels" }
  }
}
```

- 作用点：`plugin.json.locales`（publish 复制进目录条目）、`marketplace.json` 条目/合集、`authors/<id>.json` 块/仓/板块。
- 解析：**精确语言 → 主语言 → base**（`fr-CA` → `fr` → base）；base 必填兜底，缺语言不会空白。
- **政策**：官方默认 zh+en；只做中文的官方件必须在壳仓 `scripts/i18n-surface-exempt.json` 显式登记（reason/owner/until）；**第三方不强制**（不知道作者母语/擅长语言）。

## 三、门禁（`scripts/check-i18n-surface.mjs`）

| 判据 | 级别 |
|:--|:--|
| 官方插件字典齐平（声明语言键集相等） | error |
| 官方插件 `t()` key 在每种声明语言存在 | error |
| 官方插件 views/components 的 JSX 文本/UI 属性裸中文 | error（注释跳过） |
| 官方目录条目 name/description、合集 title/hint 有 zh+en（或在豁免账本） | error |
| marketplace compact rail 三不变量（nowrap/省略/点 flex:none） | error |
| 第三方条目缺 zh | warn（不判红） |

- `--self-test` 13 例；挂 `npm run check`。Marketplace 侧另有 `i18nText.test.ts`（含 de/fr/ja 解析）与 `railLayout.test.ts`。

## 五、验收：法国用户拉德国作者的源

- 德国作者在源里写 `locales: { de, en, fr }`。
- 法国用户把应用语言切到 `fr` ⇒ marketplace 渲染器按 `fr` 取 name/description/title/intro；没有 `fr` 时回退 `en` 或 base，**不会空白**。
- 该行为由 `localizedField`（精确→主语言→base）＋ `parseLocales`（任意 `[a-z]{2,3}(-region)?` 键）保证；`i18nText.test.ts` 已覆盖 de/fr/ja。

## 六、边界

- 第三方只引导不强卡；SDK lint 的 i18n 规则仍是后续 backlog（当前由壳门禁扫官方仓、作者文档与 kit schema 引导第三方）。
- 「官方目录」合成作者域不是数据，已用同一 `locales` 形状写在 `authors.ts`（en/zh），不是硬编码分支。
- 目录合并工具已改为 **API sha 钉读**（原来读 raw CDN，会有 5 分钟旧副本，导致 locales/版本漏读）；版本追新时**保留**官方目录已有 locales。

## 七、第二轮（2026-11-24）：翻译归宿主，市场只渲染

用户拍板：**插件市场只是 UI 渲染器**，第三方可以另写一个市场；翻译解析不能由市场接线。

- **宿主统一解析**：`@linkdesk/plugin-sdk/display-text` 提供唯一的显示字段表（`collectManifestDisplayText` / `resolveDisplayManifest` / `missingDisplayTranslations`）。宿主在加载期按**插件自己的 i18n 命名空间**解析 manifest 的 name/description、命令、菜单、视图、配置、状态栏、主题/语言 label；`pluginManager.list()` 给市场的已是解析后的显示视图。
- **市场零翻译**：详情页/功能页不再 `t()` 插件数据；未安装条目仍由目录 `locales` 解析（数据层），不是 UI 临时兜底。
- **作者侧硬门禁**：`linkdesk-plugin-sdk lint` / `publish` 用同一份 walker；声明了 `contributes.i18n` 的语言，`plugin.json` 每条显示文本都必须有译文，缺一条即红。**没声明语言 = 不检查**（单语言作者自由）；官方 13 个在仓插件已全部补齐。
- **README 多语言**：`plugin.json.readme.locales`（语言码 → 相对路径）；翻译文件住 `docs/readme/<lang>.md`，共享图仍住 `resources/`（从 docs/readme 引用 `../../resources/...`）；根 `README.md` 是 GitHub 首页 + 兜底。publish 写目录条目 `readmeLocales`（tag 下 raw URL），旧 `readmeUrl` 保留兼容。
- **门禁**：`check-i18n-surface` 继续守字典齐平；`own-dict-coverage` 的字段表补 `commands[].description` / `params[].description`（旧假设「零渲染消费方」已被市场功能页推翻），并改为**逐语言**检查。
