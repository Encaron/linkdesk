1. **2026-09-15 记账**（出处 = [`05-插件更新/00-README.md` §三](../../../05-插件更新/00-README.md)）：全软件评审（与 Serial Monitor V2 对照）发现——壳仓门禁很严（当时 153 个测试文件 / 2,063 用例 ＋ `npm run check`），**而插件层「测试这道关」是虚掩的**。当日记了三条：做什么（18 只逐只补，先纯逻辑、后视图交互）、怎么干（**不回壳仓做**，逐插件进独立仓）、起点建议（serial-monitor，最薄）。
2. **2026-09-19/20 接力位被两层先占**：L9（UI 集中供给）与 L10（第三方作者实测反馈落地）先后落地；本账一直挂着「未开工」。
3. **2026-09-25 用户立案本层**：要求「单独建文件夹」＋「任务档案在记忆和 skill 中有」＋「详到每一步（**SDK 介绍改不改、版本升不升、非视图插件怎么办、作者面文档改不改**）」＋「一个 AI 多个任务，接力完成」。**并特别点出**：「把 `vitest.setup.ts` 收到 SDK 里——**这件应该排第一**」。
4. **为什么值得立案（三条）**：
   - **它是「插件独立之后」最大的一块无保护面**：源码外移（L7）把 25 个测试文件的**运行环境**随行带出，但**只带了环境、没带判据**——插件仓的 `ci-verify.mjs` 五段（schema / 跨插件引用 / i18n 字典 / 声明自洽 / 结构）里**没有一段与测试有关**。
   - **纯逻辑零测试是「真金白银的返工源」**：`serial-monitor` 的 `RingBuffer`（44 行环形缓冲）、`autoFormatHex`、`portFilter`、`cm6/*` 五件（追加行 / 装饰 / 滚动 / 搜索 / 主题）都是**无替身纯函数**——最便宜可测，也最容易悄悄错。
   - **地基漂移是「未来某天必炸的账」**：8 份同体 `vitest.setup.ts` 里任何一份被改，另外七份不会跟；**而没有任何门禁看着这件事**（`check-scaffold` 只查模板里该文件**在不在**，不比内容；`sync-plugin-ci` 只在人工跑时铺）。
5. **为什么「收进 SDK」排第一**（用户点名的这条）：地基不先收敛 ⇒ 后面每一仓、每一轮补测试都要在自己的 `vitest.setup.ts` 上再抄一遍／再改一遍 mock，**本层的产出会立刻变成 8 份新的漂移源**。收成 SDK 一个 subpath 之后：**真源 1 份，其余 7 处各一行**（壳 ＋ 模板 ＋ 5 官方仓；第 6 份现存副本属第三方仓 `geme-tihu-bicycle`——⛔ 不代改、由作者自决）；mock 升级 = 一个 SDK PATCH。

**两条真缺口（本层要治的）：**

- **缺口 A：地基有 8 份同体拷贝。** 壳 `vitest.setup.ts`（90 行 / 3,568 B）与模板 ＋ 6 仓的那 7 份（96 行 / 4,028 B）**体完全相同**，只多 6 行头注；「同源」靠的是头注里的一句话——「本文件是壳仓 `vitest.setup.ts` 的逐字副本……**两处同源**」。**没有机械件在守这条**：`check-scaffold.mjs` 只查模板里该文件**在不在**（`EXPECTED_FILES`），`sync-plugin-ci.mjs` 只在人工跑时铺。头注自己写着收敛方向——「由 `@linkdesk/plugin-sdk` 提供共享版本、本文件改成一行 re-export 是可预见的收敛方向」——**本层就是把这句话做掉**。
- **缺口 B：没有判据，也没有尺子。** 插件仓 `ci-verify.mjs` 五段无测试段；壳仓 47 个 `check-*.mjs` 里没有一把量插件测试覆盖的尺子。「该不该有测试」「补到什么程度算够」**全靠自觉**——于是 serial-monitor 到 6,098 行生产代码只配 149 行测试。本层的尺子（`#153`）**排在最后**：先把地基与样本做出来，再让尺子照着既成事实写口径——**先有正例，才有资格定判据**。

## 〇e、本批软件制造理念对照

| 理念 | 本层怎么体现 |
