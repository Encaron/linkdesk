## 一、路径分隔符——同模式复现 7 处（已修复 #99a）

> **根因：** `listDir` 经 `path.join()` 在 Windows 返 `\`，前端工具函数用 `/`。VS Code 用 `URI` 类型做类型墙——LinkDesk 用 `normalizePath()` 做等效墙。
>
> **已修复：** #99a `FileTreeModel._toExplorerItem` + `setRoots` 入口归一化 `/`。
>
> **仍残余 4 处 `replace(/\\/g, "/")`——全部有正当理由（见 #99f 审计）。**

但以下 **外部输入** 路径仍未受保护：

| # | 位置 | 路径来源 | 风险 |
|:--:|------|------|------|
| #104 | `revealInExplorer(filePath)` | 调用方传参（设置/Git/AI） | 可能 `\` |
| #105 | `explorer.newFile` | `dirPath` 参数 + `/` + name | `dirPath` 可能是 `\` |
| #114 | 状态反序列化 | `PluginStateService` 读出旧 URI | F5 后 `\` 回来 |
| #117 | revealInOS | 外部 `filePath` 参数 | 调用方可能传 `\` |
| #113 | Multi-root startsWith | `root.uri`(`/`) vs 新 folder path(`\`) | 永不匹配 |
| #108 | 搜索显示路径 | `FileEntry.path` 来自 listDir | 显示 `\`，不统一 |
| #118 | Editor Tab filePath | Tab 创建时传入的路径 | 编辑器收到的路径格式 |

**预防：** 所有公开 API（`commands.ts` 的命令 handler、`createTab` 参数）在入口调 `normalizePath()`。见 §三 P0。

## 三、`findClosest` 的隐藏前置条件——路径链必须已加载

`FileTreeModel.findClosest(uri)` 沿 `root.children` → `child.children` 链走。**如果中间某个目录未展开（children === null），链断了→返回 null。**

| # | 场景 | 风险 |
|:--:|------|------|
| #104 | `revealInExplorer` | 要定位的文件在未展开的深层目录 → 需要新方法 `findAndExpandToBypassExclude` |
| #105 | `explorer.newFile` | 创建后调 `findClosest` 定位→自动进入重命名。但如果父目录未展开→找不到 |
| #107 | autoReveal | 编辑器切到深层文件→`findClosest` 未找到→定位失败 |

**设计文档 #104 提到了 `findAndExpandToBypassExclude` 但 `FileTreeModel` 没有这个方法。** 这是"设计先行但实现落后"——新 AI 不知道要做这个。

**预防：** 在 `FileTreeModel.ts` 加 `/** TODO #104 */` 占位注释。见 §三 P2。

## 九、AI 友好度检查清单（每新任务执行前）

新 AI 接手 E4 任务前，回答以下问题：

- [ ] **此任务涉及路径字符串吗？** → 入口调 `normalizePath()` + 拼接用 `joinPath()`
- [ ] **此任务需要获取文件扩展名吗？** → `import { extension } from "./pathUtils"`
- [ ] **此任务需要持久化状态吗？** → 走 `PluginStateService`，不写 localStorage/新文件
- [ ] **此任务 import 核心类型吗？** → `import type { ... } from "@src/core/..."`，不重定义
- [ ] **此任务消费现有命令/API 吗？** → 读 `FileTreeModel` 公开方法，看 JSDoc 警告
- [ ] **此任务涉及路径比较吗？** → 两端都 normalize 后再比（`findClosestRoot` 已带归一化）
- [ ] **此任务结束后需要更新文档数字吗？** → 执行清单打勾 + 设计文档行数同步
