# E6#161 补档 · i18n 归属——「谁的仓谁译文」

> **一句话**：插件**自己声明**的可渲染文案，译名**必须住本仓** `i18n/<lang>.json`——**声明在谁手里，译名就归谁**。
> 起因是一次真实漏翻（设置插件在设置页里的声明项英文界面下仍是中文），根子在**跨仓追不上**：声明在
> A 仓（settings）、译名在 B 仓（壳仓的 `lang-defaults`），A 仓加一条声明 B 仓没有人知道。
>
> **归层**：L1 插件独立构建层（门禁能力，非壳能力也非插件能力）。
> **状态**：判据 + 门禁 + 试点已落地（2026-09-30）；**其余 15 仓按「谁的仓」逐仓清扫中**。
> **落点**：SDK 子路径 `@linkdesk/plugin-sdk/own-dict-coverage` · 脚手架模板 `ci-verify` ⑧ 段 ·
> 壳 `scripts/audit-i18n.mjs` manifest 腿 + 中央债务账本 `scripts/i18n-manifest-debt.json`。
> **清单**：[E6-执行清单.md](../E6-执行清单.md) §E6#161。

## 一、缘起（用户实机两条，连起来才看出是同一件事）

| # | 用户的话 | 它暴露的东西 |
|:--:|:--|:--|
| 1 | 「设置插件自己的翻译没做全，比如自己在设置中的声明项」 | 设置页左栏「设置插件／打开方式」等在英文界面下仍是中文 |
| 2 | 「为什么设置插件自己的翻译最后让官方语言本承担？设置插件没有自己的 i18n 是历史遗留吗？」 | 官方 16 只里**只有 settings 一个键都没有**——它的 254 处 `t()` 全住 `lang-defaults` |
| 3 | 「我在主仓外的设置仓加了设置声明，但是官方语言包无法跟上，原因就是跨仓……我的考虑是搬出去，你怎么想？」 | 🔴 **根因**：**跨仓追不上**。声明在 settings 仓、译名在 lang-defaults 仓，两边没有任何机械联系 |

历史成因（不是拍脑袋）：`lang-defaults` 生于 2026-07-27，从壳的 `src/i18n/en.json` 起家；**每插件自带字典**是
2026-08-07 才给的通道——settings 早于那条通道，于是它的文案就留在了应用级字典里。**规则本身没错，缺的是归属。**

## 二、裁决（2026-09-30 用户拍板「同意你的方案」）

> 🔴 **谁的仓谁译文**——插件自己声明、会被渲染成界面文字的东西，译名必须住本仓 `i18n/<lang>.json`。
> 应用级字典（`lang-defaults`）是**合法提供方**，但**不是归属地**：它只负责**壳自身的文字**。

三条推论（都写进判据与门禁）：

1. **manifest 声明串 = 红**。声明与译名同住一仓才可能同步——跨仓只能靠人记，人一定记不住。
2. **`src` 里 `t("中文原文")` 的键 = 黄**。应用级字典是合法提供方（今天界面不错），但归属没落位；
   硬判会有一堆假红（宿主的键、别的插件的键在你仓里看不见）。
3. **第三方仓不判红**。别人的声明由**别人仓的 `ci-verify`** 拦——跨仓替人立账 = 拿别人的欠款卡自己的提交。

## 三、设计前置（8 维度 · `design-flow`）

① **能力边界** = 门禁能力（三层固化第 3 层）。**保底** = 「没声明字典的仓照判」——缺口照报，⛔ 不因未声明而跳过
（settings 正是零声明的形态，跳过它 = 把要抓的那只放走）。

② **API** = SDK 新 subpath `@linkdesk/plugin-sdk/own-dict-coverage`（单一实现 + `.d.ts`，照 `svg-wellformed` 先例；
**作者仓零新增 devDependency**）。导出 `OWN_DICT_CALIBER` / `RENDERABLE_MANIFEST_FIELDS` / `collectOwnDictDecls` /
`loadOwnDict` / `collectRenderableManifestStrings` / `collectSourceTKeys` / `checkOwnDictCoverage` /
`formatOwnDictIssue` / `ownDictHint`。**窗口 API 零新增**（插件运行面完全不碰）。

③ **通信** = 无运行时通信。数据流：插件仓 `plugin.json` ＋ `src/**` → 判据纯函数 → 作者侧 `ci-verify`（红/黄）
／壳侧 `audit-i18n`（含跨仓池对照）。零持久化。

④ **壳侧** = `scripts/audit-i18n.mjs` 的 manifest 腿：仓清单读 `scripts/lib/plugin-repos.mjs`（⛔ 不写死 id）；
**判据本体引 SDK 模块**（⛔ 不复制一份）；判域 = 官方 16 仓 ＋ 壳仓内夹具（第三方只报告）；未还清的缺口单立
中央账本（**新缺口 ⇒ 红；还清了没删行 ⇒ 也红**——账本不许自腐）。

⑤ **插件侧** = 各仓 `scripts/ci-verify.mjs` 消费同一判据（`npm run sync:plugin-ci` 铺开）；字典落点 = 仓内
`i18n/<lang>.json` ＋ `contributes.i18n` 声明。**作者仓零判据代码**（判据住 SDK）。

⑥ **显示** = 无 UI。可见后果 = 英文界面下**声明项**（设置页分组名/分节说明/枚举显示名、侧栏与视图标题、
命令标题、市场列表名与说明）显英文；判据读数打在 CI 日志。

⑦ **配置** = 零产品配置项。唯一「配置」＝ 中央债务账本 ＋ 各仓 `contributes.i18n` 声明。

⑧ **验收** = SDK 自测（正样本 ✓ ＋ 负样本必报 ＋ **反向对照**：拿旧字段表跑必漏 ⇒ 判据真的扩了域）＋
模板腿塞一条违规看它红 ＋ 壳 `npm run check` 全绿（含账本两向负控）＋ settings 试点实机。

## 四、判据（真源在 SDK，此处只摘要点——⛔ 别手抄第二份）

**可渲染** = 有渲染消费方。字段表与逐字段消费方的**唯一真源 = `packages/plugin-sdk/own-dict-coverage.mjs`
的 `RENDERABLE_MANIFEST_FIELDS`**（21 条规格，含 `children` 递归与 `enumDescriptions` 两种形态）。
`E6-执行清单` §E6#161 里那份人读表是它的摘要，改 schema 时**同笔改真源**。

**豁免（有据，非漏洞；每条带撤销条件）**：

| 豁免 | 依据 | 撤销条件 |
|:--|:--|:--|
| `commands[].description` / `params[].description` | 2026-09-28 裁决：**声明数据 → 契约 → AI**，零渲染消费方 | **进 UI 即撤销**（与补译同笔） |
| `contributes.themes[].label` / `languages[].label` / `langDefs[].aliases` | 品牌名／语言自称 = **专名**，不翻译 | 出现「可翻译的展示名」概念时重议 |
| `icons.*.description` | 作者面元数据，不进 UI | 图标选择器开始渲染说明时撤销 |
| 一切路径/ID/上下文键字段 | 不是文案（entry/icon/render/path/when/key/menu 槽位 `group`/cssVars…） | — |

**两轴严重度**：manifest 声明串 = **红**（上面 §二.1）；`src` t() 中文 key = **黄**（§二.2）。**只判含中文的串**
（纯 ASCII 串照旧走既有 G2 黄灯腿——那份判据问的是另一件事）。

**账本两铁律**（`scripts/i18n-manifest-debt.json`）：① 新缺口（不在账本里）当场红；② 已还清却没删行同样红。
⛔ **没有「一键重写账本」开关**——那等于把门拆了。
