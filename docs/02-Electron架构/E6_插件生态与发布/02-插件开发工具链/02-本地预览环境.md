## 一、当前状态（E5#110 初版）

```
npm run dev:plugin
→ Vite 启动
→ 打开 plugin-shell.html
→ ?pluginId=file-tree 指定插件
→ injectMockApi() 注入 mock linkdesk.*
→ import.meta.glob 匹配插件入口
→ 渲染为全屏最小壳
```

### 局限
- `import.meta.glob` 只能匹配 `plugins/<id>/` 平铺根下的插件（2026-09-05 塌平单根，无 builtin/user 层）
- 不支持外部目录（插件作者的项目在任意路径）
- dev 命令不在插件项目里——在壳的 package.json 里

## 二、目标

插件作者在自己的项目目录：

```bash
cd my-cool-plugin
npm run dev
→ 浏览器打开 → 只看到自己的插件 → HMR
```

## 三、实现方案

### 3.1 plugin-sdk CLI dev 命令

```bash
linkdesk-plugin-sdk dev
```

实际做的事：

```
1. 读当前目录 plugin.json → 获取 pluginId + entry
2. 启动 Vite dev server（端口 1421，不和壳的 1420 冲突）
3. 配置 Vite：
   - 入口：plugin.json 声明的 entry（如 src/index.tsx）
   - HTML：plugin-shell.html 的副本（临时生成或复用）
   - 插件本地路径通过环境变量或 query param 传入
4. open("http://localhost:1421/plugin-shell.html?pluginId=xxx&dev=true&path=<cwd>")
```

### 3.2 plugin-shell-main.tsx 扩展

```
?pluginId=xxx
  → 有 ?path= ：本地插件项目路径 → @fs/ 加载
  → 无 ?path= ：builtin/user → glob 匹配（现有逻辑）

?dev=true
  → 注入 mock API（现有逻辑）
```

### 3.3 与壳的关系

```
壳 Vite dev server（端口 1420）:     npm run electron:dev → 完整壳
插件 Vite dev server（端口 1421）:   npm run dev → 最小壳
```

两个 dev server 独立运行——插件作者不需要启动完整 Electron。

## 九、审视实锤（2026-08-30 第 2.2 轮——#23.5/#24 宿主形态拍板依据）

### 9.1 dev 宿主 = SDK 自带独立宿主页（不进壳）——否决 Pool zone / 独立窗口候选

- **#23.5a 原候选「Pool 内临时 zone / 独立轻量窗口」是 E5.6 双 Pool 时代残留**：#24 验证是「浏览器打开」（`npm run dev` → 浏览器 → 改代码 → 热更新）——dev 宿主是**纯浏览器 tab**，不是 Electron 窗口；「独立轻量窗口」与 #24 验证自相矛盾。
- **plugin-shell.html 是 E5.7#40 整删的独立 HTML**（`6eea96d5`：ShellPluginComponent / plugin-view.html / plugin-shell.html / plugin-shell-main.tsx 4 文件整删）——dev 宿主的正确重建 = **SDK 自带独立宿主页**（插件作者自己的 Vite dev server 下 `/@fs/` 加载插件源码 + mock 注入点），随包发布，与产品壳的极简 Pool 解耦。
- **「极简 Pool 架构（1 BW + 1 WCV）下重设计宿主」同步更正为「dev 宿主不进壳」**——极简 Pool 只约束产品壳；#28 Electron 模式（第 2.3 轮，`dev:plugin -- --electron`）才涉及壳。
- 设计稿 §四「涉及文件」原列 `src/plugin-shell-main.tsx` / `plugin-shell.html` 已删——宿主归属 SDK。

### 9.2 #26 发布 = GitHub REST API 自动链路（否决手动 deferral）

## 十、审视实锤（2026-08-30 第 2.3 轮——#27 Mock 生成源 / #28 Electron 范围与机制拍板依据）

> 2026-08-30 第 2.3 轮整轮审视（E6#27、#28）落笔的修正实锤。清单只留修正结论 + 本锚点。用户授权「选出最好的方案」——本 § 即决策记录。

### 10.1 #27a mock 生成源 = linkdesk-api.ts 标注源（非 preload）

- **#27a 原「读 preload-pool.ts / preload-shell.ts 的 exposeInMainWorld 面」是 E5.6 时代话术残留，与 #27 引言「同一标注源，第二输出目标」自相矛盾。** E5.8 契约生成器实测：`scripts/generate-contract.mjs:33` 输入源唯一 = `src/core/api/linkdesk-api.ts`（聚合器 + `linkdesk-api/` 13 域接口），输出 `contracts/linkdesk.d.ts` + `contracts/runtime-shapes.ts`；preload 只是消费方（组装命名空间），不是标注源。
- **定型：mock 与 linkdesk.d.ts 同源**——`generate-contract.mjs` 加第二输出目标 `injectMockApi()`，杜绝第三份漂移。连带 #27d「preload 改了 → 生成」→「**linkdesk-api.ts 标注源改了 → 生成**」；验证「mock 与 preload 方法列表一致」→「mock 与 **linkdesk-api.ts 标注源**一致」（preload 对齐已由 `check-api-contracts.mjs` 保证）。

### 10.2 默认值策略（#27a 颗粒度补齐）

- `linkdesk-api.ts` 是纯类型图（实测无 sync/async/fire 标注）——**sync/async 从返回类型推断**（返回 Promise = async、返回 void = fire-and-forget），机械可行。
- **类型驱动默认值**：Promise → `Promise.resolve(undefined)`、void → `() => {}`、其余 → `undefined`——够 UI 骨架开发（mock 本质 = 不崩 + 可感知调用，真数据走真实 IPC / 作者自 mock）。
- **个性化默认值 override 表按需追加**（如 `path.join` → `""`）——不承诺逐方法手写默认值（几十命名空间几百方法，纯手工 = 第二份维护，违背本任务初衷）。**纸面完美陷阱规避**：这是「按返回类型生成」的原意边界，先行定死避免开工才发现默认值怎么定。

### 10.3 #28 范围界定——Electron 模式 = 壳侧 dev；第三方走「装进 LinkDesk」（不 deferral）

- **完成路径断裂点**：原「`npm run dev:plugin -- --electron` 启动完整 Electron」隐含在**壳仓库**跑，消费方却是第三方插件作者——第三方没有壳源码/构建，机制未定义（overlay 分割线同型：开工才发现路线走不通）。
- **定型（消费方界定，非 deferral）**：
  - **壳侧 dev**（自研/出厂插件作者 + 壳开发者）：Electron 模式做全——机制见 10.4。
  - **第三方插件作者**：真实 IPC 验证 = **build → 装进 LinkDesk**（生产真环境，插件最终就在 LinkDesk 里跑——本身就是完整路径，不依赖 #28）。
  - **不造「第三方独立启动壳」巨额机制**（SDK 捆绑 Electron / 定位安装版 + 开发通道）——那会把 dev 工具链变成第二个壳。

### 10.4 #28b 机制——dev 门控并入发现集（`?path=` URL 路由废弃）

- **原 `?path=<cwd>&dev=true` 是 E5.6 多 WebView URL 路由话术——极简 Pool 无 URL 路由**（pool-main.tsx 零 `?zone=` 路由，第 1.2 轮实锤），且 #23.5 已定宿主 = SDK 页（无壳），`?path=` 无处消费。
- **定型（候选 A）**：壳 dev 模式 = 主进程把 cwd 插件**临时并入 `plugins:listAll` 发现集**（E6#9 动态加载 + PluginComponent `/@fs/` 兜底，均 E5.8 已建机制）→ 走**真实 preload-pool IPC**；dev 门控只加载 cwd 插件（对标「壳不加载其他插件」）。极小增量 = 复用已建加载路径，不新增宿主机制。
