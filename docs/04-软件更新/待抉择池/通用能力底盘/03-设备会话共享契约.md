# 设备会话共享契约（设备/虚拟仪器类插件）

> **状态：待抉择**（2026-11-25 立案）· 归属：通用能力底盘（轴三「连接/端点登记」＋ 串口最小面）
> **一句话**：把「设备会话」从**串口插件里的正确实现**提升为**宿主/SDK 共享契约**，让 PLC / 探针 / 虚拟屏 / 烧录器**不读 serial-monitor 源码**也能把会话、状态、属主、幂等、拔插自愈做对。

## 一、证据（真实实测，不是推测）

serial-monitor 1.0.46 ＋ 壳 0.2.66 经三轮外部 AI 实机验收（拔插、reopen、错误码）暴露并修复了一组**设备类通用问题**：

| 症状 | 根因（已修） |
|:--|:--|
| 拔线后两个会话都报 `open:true`；`receiveStatus` 与 `listSessions` 互相矛盾 | 会话状态缓存 ≠ OS 句柄事实（缺「权威态」收口） |
| 插回后 `reopen` 回 `EDEVICE 已被打开`，只能重启软件 | 壳 `closePort` 在 `isOpen=false` 时提前 return，Map 条目永不删（僵尸句柄） |
| 失败的 `openPort` 污染绑定（把可用端口改绑到不存在的口） | 失败路径有副作用（未「先验证后提交」） |
| 非属主会话 `closePort` 作用到属主会话 | 缺「端口属主唯一 + 指名作用」判据 |
| `opened:false` 但实际已打开 | 回执不是从权威态派生 |

⇒ 这 5 条**不是串口的特殊知识**，而是任何"接外部设备"的插件都会遇到的结构问题；serial 只是第一个踩全的样本。

## 二、设计（分层，真相源唯一）

| 事实 | 真相源 | 说明 |
|:--|:--|:--|
| 句柄是否真在、设备是否在场 | **壳**（OS 层） | 设备类插件**不得**自己缓存 `open` 当事实 |
| 会话（谁在用、用哪些参数） | **插件** | 业务语义（波特率/协议/暂停）归插件 |
| 状态读面字段 | **共享契约**（本档定义） | 统一 `open / devicePresent / stale / ownerSessionId` 四字段语义 |

**宿主/SDK 提供（建议形状，待评审）**

- 会话生命周期骨架（主进程）：`acquire({deviceKey, ownerPluginId, params})` / `release(sessionId, {idempotent:true})` / `getState(deviceKey?)` / `recover(sessionId)`；
- 规则内置：**先验证后提交**（打开成功才建会话/写绑定）、**属主唯一**（一个 OS 句柄只归一个会话）、**关闭幂等**、**僵尸句柄自动摘账**、**error/拔线主动释放**；
- 事件面：`device.added` / `device.removed`（轴三「设备身份握手」的输入），供 `recover` 自愈；
- SDK 侧只暴露类型与薄封装（导出面归 C）；插件侧不得再自建第二套状态机。

## 三、判据（对 07 准入表）

- **归一化**：会话状态机只有一份（宿主/SDK）；插件只声明参数与业务语义。
- **无硬编码**：壳不认识任何设备类型/插件 id；`deviceKey` 由插件声明（端口名/VID-PID/serial）。
- **无死代码**：串口现有实现收敛后删除插件内的重复状态机（⛔ 留兼容分支）。
- **高内聚低耦合**：壳只提供「句柄事实 + 会话骨架」；编码/协议/暂停仍归插件。
- **AI 友好化**：状态四字段可判读；失败有码（`ENOPORT`/`EDEVICE`/`EBUSY`/`EBADARGS`）；`recover` 是显式自愈入口。

## 四、边界（⛔ 越界）

- ⛔ 不做业务协议（MODBUS/AT/STM32 命令）——归各插件仓。
- ⛔ 不做通用 `stream` 帧契约——归底盘轴二（另一条任务）。
- ⛔ 不把编码策略塞回壳——仍归插件（D2）。
- ⛔ 不为单个插件写特判分支。

## 五、验收

1. **第二个设备类插件**（探针/PLC 任一）在**不读 serial-monitor 源码**的前提下，会话/状态/属主/恢复全部做对；
2. `doctor` 设备类不变式对**两个插件**同样成立（拔线后无 `open:true`、失败零副作用、非属主关闭被拒、幂等关闭）；
3. 拔插用例：拔线 → 状态如实 → 插回 → `recover` 成功（有耗时读数）；
4. 全量 `npm run check` 绿。

## 六、不做的代价

- 每个新硬件插件重写一套会话状态机 → 重复踩 5 类 bug；
- 状态语义各写各的 → AI 读面不可跨插件复用，doctor 无法跨领域断言；
- 「第二个作者不看第一个源码也能做全」这条判据永远不成立。

## 七、依赖与排期

- 依赖：无（串口实现即参考）；与 [04-插件间事件契约](04-插件间事件契约.md) 共享 `device.added/removed`（本任务先定）。
- 建议顺序：**本任务 → 04**。
