## 二、现实约束：壳 DialogService 真实能力（实锤）

对标前先摸壳现状——**壳 DialogService 只支持「标题 + 一段文字 + 确认/取消按钮」**：

- `DialogService.confirm(options: {title, message, confirmLabel?, cancelLabel?, type?}): Promise<boolean>`（[DialogService.ts:71](../../../../src/core/services/ui/DialogService.ts#L71)）
- `DialogService.alert(...)` / `showQuickPick(...)` / `showInputBox(...)`（[DialogService.ts:85-108](../../../../src/core/services/ui/DialogService.ts#L85-L108)）
- 渲染端 DialogHost：`title` + `message`（`<p>`）+ `confirmLabel`/`cancelLabel` 两个按钮（[DialogHost.tsx:129-140](../../../../src/pool/floating/dialog/DialogHost.tsx#L129-L140)）

**结论：现有 DialogService 画不出「字段逐行 + Logo + 复制按钮」的关于框。** 强行用 `alert()` = message 塞多行文本 + 只有「确定」——复制功能直接砍掉。**这是 06 的载体决策点，不是已定项。**

## 三、载体方案（已拍板：A 标签页——2026-08-30 用户拍板）

| 方案 | 形态 | 能力 | 代价 |
|:--|:--|:--|:--|
| **✅ A 壳内标签页**（已拍板） | 关于 = 标签页（同发行说明载体） | Logo/字段表格/复制按钮/**「检查更新」快捷按钮** 全可做，真实 React 视图 | 非模态（可接受：发行说明已是标签页先例） |
| B DialogService alert() 降级 | 弹窗，message 塞多行字段文本 + 「确定」 | 唯一按钮，**无复制**、无 Logo、无交互字段 | 砍复制功能，偏离 VS Code |
| C 扩展 DialogService 富内容 | 弹窗 + 自定义内容渲染器 | 全功能模态 | **新壳能力**——要走新能力设计前置 8 维度，本次不搭车 |

**拍板依据（A 胜出）**：
1. **标签页 = 通用表面容器**（memory `tab-universal-surface-container`）——「任何插件加新表达形式 = 加一个标签页，不设计新宿主」，发行说明已同款，两处一致。
2. **基于现实**：A 是唯一用现有壳能力（标签页引擎）就能承载全部字段 + 复制的方案；B 砍功能；C 新造能力。
3. 附赠：关于标签页可放「检查更新」按钮——关于 + 检查更新闭环同页（对标手机「设置→关于本机→软件更新」心智）。

> **2026-08-30 已拍板选 A**——本档 §四 布局即实现稿（对应 00-README 待拍板点②，已划勾）。

## 四、关于标签页布局（方案 A 实现稿）

### 4.1 打开

- 入口：帮助菜单「关于 LinkDesk」+ 齿轮菜单「关于 LinkDesk」+ 命令面板。
- 载体：壳内标签页（tabBehavior.singleton，同发行说明）。

### 4.2 布局

```
┌────────────────────────────────────────────┐
│  关于 LinkDesk                ─  □  ✕       │   ← 标签页标题
├────────────────────────────────────────────┤

│                 LinkDesk                    │
│                                            │
│  版本     0.1.0                             │
│  提交     91e6aa36…                         │

│  Electron 42.8.1                            │

│  Node.js  24.18.1                           │
│  V8       14.8.178.38-electron.0            │
│  OS       Windows 11 Home China …           │
```

字段逐条对照（与 02 产品身份同源）：

| 字段 | 值 | 来源 |
|:--|:--|:--|
| 版本 | `0.1.0` | `app.getVersion()`（= package.json，product.json 自证） |
| 提交 | `91e6aa36…` | product.json `commit` |
| 日期 | `2026-08-30T00:00:00Z` | product.json `date` |
| Electron | `42.8.1` | `process.versions.electron` |
| Chromium | `148.0.7778.280` | `process.versions.chrome` |
| Node.js | `24.18.1` | `process.versions.node` |
| V8 | `14.8.178.38-electron.0` | `process.versions.v8` |
| OS | `Windows 11 Home China (10.0.26200)` | `os.version()` / `os.release()`（win32 读注册表显示名） |

> **字段可扩展**：`Product`/`ProductRuntime`（02 §2.2）是开放结构——未来加字段 = 类型加一列 + 视图加一行，零架构改动。**纯增量。**

> **数据通道**：AboutView mount → `invoke(app:getProductInfo)` 一次拉 `{product, runtime}` 全量（07 §四 命令表）；「检查更新…」→ `invoke(update:checkForUpdates)`；「复制」→ 壳 ClipboardService。壳内部走 IPC 通道，**不走 `window.linkdesk.*` 契约**——那是给第三方插件的（第三方读版本号走 `app.getVersion()`，00 README §三②）。

### 4.3 两个动作按钮

- **复制**：全字段纯文本（`key: value` 每行一个，`\n` 连接，UTF-8）→ 剪贴板 → 通知面条目「已复制」（壳共享通知面，⚠️ 旧文写「toast」= 已删的右下小卡，见 [04 §〇](04-更新通知与交互.md)）。对标 VS Code，直接可贴进 issue。
- **检查更新…**：调 `update.checkForUpdates` 命令 → 结果落**通知面**（有更新 → 发现更新条目，[mockup 02](mockups/02-更新通知与关于.html) Frame 1；最新 → 「当前已是最新版本」Frame 4；**失败 → Frame 5，带归因文案 + `[重试]`**）。手机「设置→关于本机→软件更新」心智。

### 4.4 与产品三件套的关系

- 关于标签页 = 身份字段的**只读展示面**；唯一真相源 = product.json（02）。
- 没有 product.json（dev 裸跑）→ commit/date 降级显示 `—`（不崩，保底设计）。

### 4.5 页面视觉竞标（2026-08-30 拍板：A VS Code 对标）

布局结构定案（品牌区 + 字段表 + 两动作按钮），视觉语言 3 版并排竞标 → [mockups/05-关于-竞标.html](mockups/05-关于-竞标.html)：

| 版 | skill | 视觉语言 | 结果 |
|:--|:--|:--|:--|
| **✅ A** | ui-ux-pro-max | VS Code 对标：居中品牌区 + key:value 字段表 + 按钮行 | **拍板**——识别度最高 |
| B | high-end | 液态玻璃（双贝塞尔品牌卡） | 未选 |
| C | impeccable | 精修极简（行内复制 ⧉） | 未选 |

§四 布局即 A 版实现稿。**组件位置：** `src/pool/views/about/AboutView.tsx`（对标欢迎页/发行说明先例，`src/pool/views/` 下域夹）。
