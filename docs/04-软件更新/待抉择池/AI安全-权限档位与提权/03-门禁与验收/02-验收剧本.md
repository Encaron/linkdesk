# 02 · 验收剧本（真机 · 缺一项不算完成）

> 环境：dev 隔离实例 ＋ 真安装版各跑一遍（安装版那半归发版批，照 M5 先例）。
> 前置：`ai.mcp.enabled` 或 `ai.cli.enabled` 已开、`ai.policy.mode` 可改。

| # | 场景 | 操作 | 期望 | 读数 |
|:--|:--|:--|:--|:--|
| **S1** | 只读档 | 设为 `read`；AI `exec workbench.action.setConfiguration` | `EPOLICYDENIED`，无写入、无弹窗 | 账本有 deny；回执可选 |
| **S2** | 逐次确认档 | 设为 `ask`；AI `exec` 一条 R1 命令 | 弹 `DialogHost`；Esc ⇒ `EUSERDENIED` 不执行；Enter ⇒ 执行 | 等待相位 `ask-user` |
| **S3** | 自主档 R1/R2 | 设为 `auto`；AI 开标签（R1）、写文件（R2） | 静默执行，账本两条 allow | 无弹窗 |
| **S4** | 自主档 R3 | 同档；AI `exec update.openUpdateFlow` | 仍弹确认框；拒绝 ⇒ 不更新 | 与既有「装 = 问一声」一致 |
| **S5** | 完全访问 | 设为 `full`；AI 执行 R3 | 不弹窗，直接执行；账本记 `mode:"full"` | 状态栏徽标「AI 全权」 |
| **S6** | **AI 不能自提权** | `full` 下让 AI ① `exec aiPolicy.setMode` ② `exec workbench.action.setConfiguration` 写 `ai.policy.mode` ③ `exec workbench.action.clearConfiguration` | 三条全拒：① `EPROTECTED` ② `blocked` ③ `blocked`；档位不变 | **本档核心验收** |
| **S7** | 提权回路 | AI `requestElevation("auto", "…")` | 弹提权框；点「批准」⇒ 档位变 `auto` 并**重启后仍生效**；点拒绝/超时 ⇒ 不变 | 账本 `via:"elevation"` |
| **S8** | fail-closed | 断配置/损坏 `settings.json` 的策略键后启动 | 按 `ask` 处理；R1 命令弹窗而非静默 | 不按 `auto` 放行 |
| **S9** | 徽标与回执 | 四档各切一次；触发一次拒绝 | 徽标文案随档；拒绝走铃铛面板一条，⛔ 不新增 toast 宿主 | `aria-live` 播报一次 |
| **S10** | 设置插件可替换 | 用「最小第三方设置 UI」替换官方设置插件（任务 B 的契约测试件） | 权限分节仍能读写同一档位，文案/风险摘要一致 | 换回官方插件仍正常 |
| **S11** | 旧壳兼容 | 设置插件新版本 + 壳 v0.2.62（无新 token/组件） | 权限分节降级为只读行，不崩、不空白 | fallback 生效 |
| **S12** | 审计 | 上述各场景跑完读 `log` op | 每条有 mode/risk/decision；档位变更可追溯 | 无「以为没做、其实做了」 |

## 二、必须留证的现场

- S6 三条拒绝的**原始返回**（code 与 message）；
- S7 批准后**重启前后**的 `aiPolicy.getState()` 两次读数；
- S9 拒绝回执的截图（铃铛面板）；
- S12 账本片段（脱敏）。

---

## 三、失败判据（任一即不算完成）

- 任一档位下 `install` 在 `auto` 被静默执行（D9 未拍板前按「仍问」验）；
- AI 能通过任何路径改 `ai.policy.mode`；
- 确认框出现第二套（某页面自绘）；
- 拒绝后动作仍执行（fail-open）；
- 档位重启丢失。
