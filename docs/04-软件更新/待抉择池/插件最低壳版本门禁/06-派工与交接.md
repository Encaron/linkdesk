# 06 · 派工与交接（**AI-1 ～ AI-4**）

> **一句话**：**3 条并行线 ＋ 1 棒压尾验收 = 4 个 AI**；🔴 **⛔ 不许超过 4**。
> **并行度由「出口单点」决定，不由格子数决定**——本夹有 6 格任务，但其中 3 格挤在同一个出口上，实际并行度只有 3（见 §一）。
> 本件只讲**谁先谁后、谁许动哪个文件**；每格具体做什么，看 [00 §四](00-README.md) 的任务全景与各格正文。

---

## 一、为什么并行度只有 3（出口单点论据）

**决定因素是「谁从哪发出去」**，不是"有几件事要做"：

| 出口 | 谁从它发 | 结论 |
|:--|:--|:--|
| **`@linkdesk/plugin-sdk` npm 包**（G1 的账本 ＋ G2 的 lint ＋ G3 的脚手架与 README 全从这里出去） | G1 / G2 / G3 | 🔴 **三条腿共用一个出口 ⇒ 必须同一个 AI 串着做**。并行改同一个包，会在**版本号与 `release:mark`** 上互撞（本仓既有纪律：内容不许跑在版本号前面） |
| **壳仓运行期**（`src/core/` ＋ `electron/ipc/`） | G4 | 与上面零文件重叠 ⇒ **可并行** |
| **壳仓发布链**（`scripts/`，dev 工具、**不占版本号**） | G5 | 与上面零文件重叠 ⇒ **可并行**，且**无任何依赖**，最早可开工 |

⇒ 三条线：**SDK 轴（AI-1）／壳运行期轴（AI-2）／壳发布链轴（AI-3）**，再加 **验收棒（AI-4）**。

## 二、派工表

| AI | 棒名 | 负责格 | 落点 | 依赖 | 开工条件 |
|:--:|:--|:--|:--|:--|:--|
| **AI-1** | **SDK 轴**（主链） | **G1 → G2 → G3**（串行） | 壳 `scripts/`（账本生成器）→ SDK `schemas/`＋`src/eslint/checks/` → 脚手架模板＋SDK README＋`docs/03-插件制造/` 中英双语 | 自身串行 | **立刻**，但**只做 G1**（见 §五 第一步） |
| **AI-2** | **壳运行期轴** | **G4** 读数腿 | `src/core/compat/compatibility.ts`（＋ `electron/ipc/handlers/plugin-handlers.ts` 供数；复用 `dangling-scan-async`） | 只依赖 **G1 的账本形状**（schema 一冻即可开工，⛔ 不必等 G1 全部落地） | **S2 账本 schema 冻结后** |
| **AI-3** | **壳发布链轴** | **G5** 流程腿 | `scripts/check-publish-gate.mjs` 一族 | **无** | **立刻**（可与 AI-1 第一步同时开工） |
| **AI-4** | **验收棒**（压尾） | 验收 ＋ **存量回归** | 跑 G2 门禁扫官方全部插件仓、修声明、真机验收 | **必须等 AI-1 收口** | AI-1 交付后 |

**AI-1 为什么一个人扛三格**：G1 定账本、G2 吃账本、G3 把账本讲给作者听——是**同一个契约的三面**。拆给三个人就等于让他们各自猜格式，必然漂移（[02 §七](02-设计-账本与门禁.md)「归一化」那条红线的反面：**两份必然漂移**）。

**AI-4 能不能省**：能（并回 AI-1）。但代价是 AI-1 尾巴变长，而且**自己验自己**——[05 §一](05-验收判据.md) 的正控 1（读数必须由「正常」变「不适配」）正是**别人更容易挑出毛病**的那类判据。**建议留着。**

## 五、派工节奏（**三步走 · ⛔ 别一次派齐**）

### 第一步（现在）：**只派 AI-1**，任务只到 G1

> 交付 = **G1 可行性结论 ＋ 账本落地**：① 证 `since` 能回溯（翻 tag、逐版 diff ui 导出面）；② 账本落地为 `name → since`、四列全覆盖、随 SDK 携带；③ **把 schema 冻结并写进交接板**。
> ⛔ 这一步**不许**顺手做 G2/G3——先出结论。

**同时**可派 AI-3（G5 无依赖，两条线文件零重叠）。

### 第二步：**S1 出「可行」结论后**，一次派齐

- **AI-1** 续做 **G2 → G3**（同一棒，串行）；
- **AI-2** 开工 **G4**（S2 冻结后）；
- **AI-3** 自己那条线继续到收口。

### 第三步：**AI-1 收口后**，派 **AI-4** 压尾

存量回归（扫官方全部插件仓、修声明）＋ [05](05-验收判据.md) 全表验收。

## 六、交接板（每棒必须留什么）

每棒收口时在**本夹内**追加一节 `交接 · AI-x`（或更新自己那格正文），**只写三件**：

1. **现状**：做到哪、哪些是**真跑过**的（门禁 EXIT / 实测读数），哪些只是"写完没验"；
2. **冻结项**：我这棒定死的契约（AI-1 必写**账本 schema**；AI-2 必写**读数返回字段**）——下一棒**照此实现，⛔ 不许改形状**；
3. **下一棒的第一件事**：一句话，可执行。

⚠️ **⛔ 不要复述本夹已有的内容**（读 00–06 即可），交接板只写"变化量"。

## 七、成本纪律（本案专属）

- 🔴 **⛔ 不许超过 4 个 AI**；本案唯一的并行是 **P1 三条线**。**6 格 ≠ 6 个 AI**——五格里三格是同一条串行链。
- 每棒派工时**自带"读什么"**（AI-1/2/3 读 [00](00-README.md)＋[02](02-设计-账本与门禁.md)；AI-2 另读 [04 §一](04-任务-读数腿与流程腿.md)；AI-3 另读 [04 §二](04-任务-读数腿与流程腿.md)；AI-4 读 [01](01-事故复盘-真机实证.md)＋[05](05-验收判据.md)），⛔ **别让它把整夹通读一遍**（本夹 00 号档的表格行极长，整夹通读是纯浪费）。
- 🔁 前置教训（memory `subagent-fanout-cost`）：曾有一个任务被拆成 7–8 个子代理，当日 9,308 次调用 / ¥121.55（正常日 2,200–3,800 次 / ¥47–70）。**本案的并行度上限是 3，任何超过 4 的拆分都是白花钱。**
