### 2.1 🔴 补「每类文件的判断标准」表——加「上限」列

现表只有「放什么 / 不放什么」。**补一列「行数上限」**，与 12 档同一套数（**这样五只官方插件和 marketplace 用同一把尺**）：

| 目录 | 放什么 | 上限 |
|:--|:--|--:|
| `views/` | 页面级组件（有 ViewContainer 入口） | ≤150 |
| `components/` | 可复用 UI 组件 | ≤150 |
| `hooks/` | React hook（`use*`，一个文件一个 hook） | ≤150 |
| `services/` | 业务逻辑/数据/API 封装 | ≤200 |
| `utils/` | 纯函数工具（无状态、无副作用） | ≤150 |
| `styles/` | 独立 .css | ≤300 |
| `index.tsx` | entry（模块副作用 + re-export default 组件） | ≤120 |
| `__tests__/` | 测试 | 不限 |

🔴 **`.css` 一律 300，不看它放在哪个目录**（`.css` → 300 是全局规则）——这样 settings 那个 co-located 的 `views/SettingsView.css` 也管得住。

🔴 **本表与 [05 §二](05-门禁扩域与验收.md) 的 `ROLE_LIMITS` 必须逐字一致**——**同一把尺子不许写两份**。改一处必改另一处。

**并补一条超限处置句**（照抄 12 档 §一·〇 ⑤ + E6#0.4d）：

> **超限必拆——走 feature-folder（同名夹 = 聚合器 + 子模块），禁止拆同 domain 平铺多文件。**
> **例外档**：文件旁边**存在同名夹**时（= 它已是聚合器门面），按本档 ×2 计——见 [05 §2.3](05-门禁扩域与验收.md)。

### 2.2 🔴 补「`utils/` = 纯函数」的边界细则

现文写「`utils/` 纯函数工具——无副作用、与 UI/业务无关的通用函数」。**实测被违反**：`plugins/serial-monitor/src/utils/` 里放了 `RingBuffer.ts`（**有状态类**）和 `useSendData.ts`（**React hook**）。

**补两句判据**：
- **有实例状态 / 有副作用** → 不进 `utils/`，进 `services/`
- **React hook（`use*`）** → 不进 `utils/`，进 `hooks/`（**新增 `hooks/` 一档**）

### 2.3 🔴 补「`__tests__/` 与子目录的对应关系」——把现有那句写死

现文第 111 行：「插件测试用 Vitest，命名 `<被测文件名>.test.ts(x)`，与被测文件同目录（**`__tests__/` 内保持相同相对路径**）」——**这句话被两处违反**：

1. marketplace `__tests__/` 10 个测试**全平铺**（没有镜像 `services/` `views/` 的相对路径）
2. settings 插件**根本不用 `__tests__/`**，走壳的同夹做法

**改法**：
- 把「`__tests__/` 内保持相同相对路径」改为**明确的树形示例**（如 `src/services/a.ts` → `src/__tests__/services/a.test.ts`）
- **补一句强断言**：「**插件一律用 `__tests__/`；同夹紧邻是壳层做法，插件不采用。**」——把 settings 的做法明确判为不合规
- 补一条**测试文件行数不设上限**（fixture 天然长），但 **>1000 行的测试按 describe 组拆到同夹多文件**

### 2.4 补「`hooks/` 目录」一节

插件规范现在没有 `hooks/` 一档，但 serial-monitor 实际上有 `src/hooks/`（`useIpcEvent.ts` / `useSerialSessions.ts`），settings 有 `src/views/hooks/`，`editor` 等也可能有。**补一档**：`hooks/` = `use*` 前缀、一个文件一个 hook、不夹带组件/service。

同时补**归属判据**（照 壳目录规范 §4）：
- 插件内**只此一处用**的交互 hook → 插件本地 `hooks/`
- **跨插件共享**的图标/交互 hook → `@linkdesk/ui`（壳侧单一副本）
