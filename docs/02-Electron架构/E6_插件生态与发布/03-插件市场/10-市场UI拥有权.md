## 〇、一句话

**壳 = 宿主面 + 共享基础件 + 数据 API；市场插件 = 业务组合 + 皮肤。** 市场插件（`factoryRole: "marketplace"`）拥有的不只是侧栏——它拥有市场 UI 的渲染权。换市场插件 = 换全新样式，数据继承由壳 API + 版本化 catalog 保证。当前唯一违背此原则的部分 = 详情页（五层全在壳），本档就是它的归属决策。

## 一、分层原则——谁拥有什么

> 判定标准：**这个 UI 是「通用能力」（多插件共用）还是「市场业务」（市场自己决定）？** 通用 → 壳；业务 → 市场插件。

| 层 | 谁拥有 | 内容 | 理由 |
|:--|:--|:--|:--|
| **宿主面** | 壳 | tab 容器 / 侧栏容器 / 主区 tab 解析 / 打开关闭 / z-index / 拖拽区避让 | 容器能力，所有插件共用，统一性 + 可及性 |
| **基础件** | 壳 | Button / Badge / Dialog 容器 / SelectBox / MarkdownView / 主题 token | 通用组件，多插件复用，皮肤走主题系统（竞标定稿：皮肤一律走主题） |
| **数据 API** | 壳 | `pluginManager.*` / `notifications.*` / catalog（marketEntry）/ 下载数 / dependencies | 数据源，壳为单一权威，插件只消费不存储 |
| **业务组合** | 市场插件 | 侧栏 4 组 + 搜索 / 详情页布局 / 按钮组 / 胶囊组 / 状态组合 / 确认弹窗内容 | 市场业务决策——画几个胶囊、什么顺序、哪个状态怎么展示，全由市场插件定 |
| **皮肤** | 主题系统 | 颜色 / 圆角 / 字体 / 玻璃 / 尺寸 | 竞标定稿（2026-08-29）：皮肤一律走主题 token，插件不硬编码 |

**换市场插件 = 换「业务组合」这一层的渲染**——宿主面、基础件、数据 API、皮肤全不变，只有市场插件自己画的 UI 换了。这就是「换全新样式，继承过来旧的」。

## 三、决策：详情页渲染面 = 市场插件可贡献，壳保底宿主

### 三·一、机制设计（推荐：扩展 contributes.views 主区 location）

市场插件在 `contributes.views` 里声明**主区 tab 渲染视图**，壳解析 `plugin-detail` tab 时优先用活跃市场插件的贡献，缺则壳保底：

```jsonc
// marketplace/plugin.json（内置市场插件）
"contributes": {
  "views": {
    "marketplace": [ /* 侧栏 4 组 + 搜索（现状） */ ],
    "main": [
      { "id": "plugin-detail", "title": "插件详情", "render": "src/views/DetailView.tsx" }
    ]
  }
}
```

```text
tabs.create("plugin-detail", { pluginId, marketEntry, pinned })
   │
   ▼ 壳 ShellViewRenderer 渲染 plugin-detail tab
   ├─ factorySlots.getActive("marketplace")        ← E5.8#41.12 已有
   │   ├─ 该插件 contributes 主区视图含 id="plugin-detail"？
   │   │   ├─ 是 → 动态 import 插件视图，props = { pluginId, marketEntry, pinned }
   │   │   └─ 否 → 壳 PluginDetailPoolView 保底（现状兜底，对标「默认=内置」）
```

**为什么走 contributes.views 扩展而不是新字段**：复用现有视图声明/加载机制（schema + loader 已处理 contributes.views），只加一个 location 枚举值 + 一个 tab 解析分支——最小机制面达成「市场插件拥有详情渲染」。

**备选（记录在案，E6 不采用）**：
- **专用窄字段 `contributes.marketplaceDetail`**——更小但只服务一个槽，归一化差（市场细节会随第二个主区消费方出现而废弃）。
- **通用主区视图系统**（任何插件任意 tab）——最彻底但 E6 第一站只有一个消费方，改动面过大（tabBehavior/tab 身份联动），护健壮暂缓（见 §五 暂缓）。

### 三·二、交互边界

- 详情页**内容布局**（header/action bar/tab/README 区/元数据侧栏）→ 市场插件自绘（消费 E6#30.5/#30.6 的 UI 目标）。
- 详情页**宿主机制**（tab 打开/关闭/固定/标签标题/跨窗）→ 壳（E6#30.7 不变）。
- 壳 `PluginDetailPoolView` → **保底宿主**：无市场插件 / 无详情贡献时现状兜底（已装插件管理面不崩）。

## 四、按钮 / 胶囊 / 弹窗归属细则

### 四·一、按钮——壳 Button variant + 语义色 token（非全透明）

用户 2026-08-29 拍板方向：**「形状可被主题控制，但『安装是绿』不能被随手改，或干脆全部透明」**。

实机事实：壳已有语义 token `--error` / `--warning` / `--danger` / `--warning-text`（`src/index.css`），**grep 不到 `--success`——「安装绿」目前是 mockup 里画死的色，壳无对应 token**（缺口 → E6#30.12）。

**定案（推荐，非二选一）**：

| 维度 | 走法 |
|:--|:--|
| 形状（圆角/尺寸/padding/hover） | 壳共享 Button 基础件 + `var(--radius-*)` / `var(--surface-*)` → 主题可控 ✅ |
| 语义色（安装绿） | 壳补 `--success` 语义 token（E6#30.12），进主题配色域——主题能换整套语义色（有意换主题），市场插件代码不能随手写死绿 ✅ |
| 按钮类型 | 壳 Button variant 体系——安装=success 填充 / 卸载=danger / 禁用=ghost；市场插件只声明 variant 不碰色值 ✅ |

**不选「全部透明」**：全透明丢主操作可发现性（可及性——用户扫一眼该装哪个）。语义 token 是根治，透明是逃避硬编码。

### 四·二、胶囊——市场插件自己绘制（数据自 catalog）

`● 12.4k 下载 · MIT 许可证 · 更新于 2026-08-20 · 工具 · 协作`：

- **绘制 = 市场插件**——数据全部来自 catalog（marketEntry）：下载数=GitHub Releases API / 许可证=`license` / 更新=`versions[].publishedAt` / 分类=`categories[]`。市场插件自己决定「画几个胶囊、顺序、带不带图标」。
- **壳只给 Badge/Capsule 基础件**——统一圆角/内边距/文字走 token，不决定业务内容。
- **换市场插件 = 换胶囊呈现方式**（VS Code 式小字行 / 胶囊 / 图标+文字），同一份 catalog 数据。

### 四·三、弹窗——壳 Dialog 容器 + 市场自绘内容

用户 2026-08-29 点出「弹窗往往讲究统一性」。定案：

| 层 | 谁 | 内容 |
|:--|:--|:--|
| 机制 | 壳共享 Dialog（`#dialog-root`） | 打开/遮罩/Escape/焦点陷阱/z-index/拖拽区避让——统一，第三方插件不重复造轮子 |
| 内容 | 市场插件 | 安装确认框字段列表（来源/发布者/许可证/版本/大小）、排版、按钮——市场业务自由画 |

对标 VS Code：QuickPick 是壳机制+插件填 items；对话框是壳，内容插件定。**弹窗的样子统一，弹窗里的业务自由**（08-信任与安全 §四 已一致）。

## 五、数据继承契约——「换市场=继承旧的」的前提

> 换市场插件要保住已装标记、来源配置、下载数缓存——前提是**数据活在壳 API / catalog，不绑死在哪一个市场插件里**。

| 数据 | 单一权威 | 继承保证 |
|:--|:--|:--|
| catalog（marketplace.json 含扩展） | E6#29 + #30c 多源合并 | schema 版本化（E6#29c 纯增量）——新旧市场插件读同一份 |
| 安装状态 / 禁用列表 | `pluginManager.*`（壳） | 新市场插件走同一 API |
| factoryRole 激活套 | `FactorySlots`（E5.8#41.12，落盘） | 换市场插件 = `setActive("marketplace", newId)`，重启保持 |
| 下载数缓存 | 壳 / catalog 层 | 源级缓存，不存市场插件内 |

**验收（E6#30.13）**：第三方市场插件声明 `factoryRole: "marketplace"` + 主区详情贡献 → 实机「换市场=换样式 + 数据继承（已装标记/来源配置不丢）」。
