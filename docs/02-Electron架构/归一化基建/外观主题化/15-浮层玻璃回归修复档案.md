## 二、逐条根因（CDP 实锤，非猜测）

### #1 浮层无模糊——OverlayPortal 包装盒成 backdrop root 掐断表面采样（已修 #109）
- **根因**：隔离地板深度 2 规则 `#ld-float-layer > *:not(#ld-scrim-plane) > *` 打到了 OverlayPortal 的**包装盒**
  （`position:relative` 0×0 空盒，套在表面外一层）。包装盒带上 backdrop-filter → 在 Chromium 里成为 **backdrop root** →
  内部真实表面（`.ctx-menu`/`.toast-item` 等，深度 3）的 backdrop-filter 只能采样该 root 内、包装盒（0 尺寸）之下的
  内容 = 空 → **表面模糊从不渲染**。代码注释「wrapper backdrop-filter 命中无害」是错的（#109 纠正）。
- **证据**：CDP 注入关掉包装盒 blur 后，菜单自身 blur(16px) 立即剧烈渲染——diff mean 18.7 / max 131 / 60.6% 像素变化；
  原始状态下 blur-on vs blur-off diff = 0（完全无模糊）。

### #2 镜像清晰（拖 glassBlur 出背景图副本）——backdrop-filter 采样不到同元素伪元素（已修 #110）
- **根因**：panorama 镜像（#102）设计本意是玻璃层 `::before`（z:-1）的 backdrop-filter 把镜像 `::after`（z:-2）模糊成
  磨砂。但 **Chromium backdrop-filter 的采样集排除元素自身内容（含兄弟伪元素）**——`::before` 的 backdrop 只含
  「元素内容之外、元素之下」的绘制，`::after` 属于元素自身内容 → **镜像从不被模糊**。所以 blur>0 时镜像以**原图清晰度**
  直显 = 用户看到「zones 内生成一张背景图片」。
- **证据**：强制 blur32 vs blur0，主表面区域 **max=0 / changedPx=0**（像素完全相同，模糊从未作用到镜像）。

### #4 glassOpacity = 灰度/对比度（#112 已根治）
- **根因（双通道共用 `--glass-opacity` token）**：
  - ① 合成通道（玻璃面不透明度，正确语义）：`getGlassSurfaceSpec` 读用户 `app.glassOpacity` → `synthesizeGlassSurfaces`
    合成 SURFACE_COLOR_KEYS 8 键 `color-mix` = 玻璃面不透明度，写 `--glass-surface-alpha`。
  - ② tint 盖片灰度通道（污染）：`getAppearanceOverrides`（seeds.ts:190）把用户 `app.glassOpacity` **写进 `--glass-opacity` token**
    → `index.css:553` tint 盖片 `opacity: var(--glass-opacity)` 跟随用户值 = 灰度感。用户期望的「玻璃面不透明度」被 tint 抢占，滑杆拖大 = 表面变灰。
  - ③ 播种绕过拍板默认：`deriveAppearanceSeeds` 读 `tokens["glass-opacity"] ?? "1"` 反推 `app.glassOpacity`——无玻璃主题读哨兵 "1"（SURFACE_ZERO）播种 1 → 绕过拍板默认 0.5 → 合成全实、拖 blur 采不到背景无玻璃感。
- **修复（语义重接）**：用户 `app.glassOpacity` **只走合成层**（`--glass-surface-alpha`），不再写 tint 盖片 token（摘除 seeds.ts:190）；`--glass-opacity` token 归配方面 `surface.opacity`（tint 盖片消费，语义注释 #86 段同步）；播种反推 helper `resolveGlassSurfaceAlpha`——有玻璃（blur/saturate/tint/opacity 任一非哨兵）→ 反推配方面 opacity，无玻璃 → 系统默认 `GLASS_SURFACE_DEFAULT_ALPHA`(0.5)。
- **验证**：CDP 实机（Pool target）：初始 `app.glassOpacity=0` → `--glass-opacity` token=1（哨兵，用户值不写 token）、`--glass-surface-alpha=0`；`set 0.8` → alpha=0.8、token 恒 1；`set 0.15/0.275` 同 → **用户值只走合成 alpha、tint 盖片恒定**。播种反推单测覆盖（无玻璃 → 0.5 / 有玻璃 + opacity 0.275 → 0.275）。1295 绿。

### #5 glassSaturate 无作用（待做 #113）

  对背景图无任何可见作用。#110 已把 saturate 同挂到 `::after` 的 filter 上（理应随 #110 一并生效，待验证确认）。

### #7 backgroundOpacity = 亮度（#115 已根治）
- **根因（CDP 实锤，双 token 脱节）**：用户 `app.backgroundOpacity` 只写 `--bg-opacity` → 只淡出 `.background-layer`
  （清晰底图）露主题底 = **亮度感知**；而玻璃面镜像/纹理 `::after` 读 `--surface-bg-opacity`（配方面决定、用户值
  **不写它**）恒显 → **图与底脱节**（底图淡了但玻璃面上图还在）。CDP：`set backgroundOpacity=0.3` → `--bg-opacity=0.3`、
  `.background-layer` opacity=0.3，但 `--surface-bg-opacity` 空、main-zone ::after opacity=1。
- **修复（双 token 齐写 + 播种优先）**：用户值统一覆盖 `--bg-opacity` + `--surface-bg-opacity`——底图 + 镜像/纹理/切片
  **统一淡出**，图与底一致；播种反推 `deriveAppearanceSeeds` 改读 `surface-bg-opacity` 优先（用户统一覆盖后的当前背景不透明度），
  旧主题回退 `bg-opacity`。
- **验证**：CDP 实机 `set 0.3` → `--bg-opacity=0.3` + `--surface-bg-opacity=0.3` 双写（修复前 surface 版不动）+ `.background-layer` opacity=0.3；`set 1` 还原双 1。1296 绿。

## 六、复盘——为什么「浮层可读」一个需求演变成一打新/回归 bug（2026-08-27 用户质询）

> 用户：仅想要右键/toast/命令面板看清文字，却迟迟修不好，还引出无数新 bug + 回归 bug。系统性根因三条：

1. **窄需求被扩散到共享机制**：修「浮层可读」动了全局隔离地板规则（全浮层）+ ::after 镜像结构（全主表面 + zones 纹理）——
   爆炸半径 = 所有浮层 + 所有主表面，却按「小改动」对待，没有意识到每处都在改全局机制。
2. **回归 = 改共享结构只验局部**：#105 镜像门控 gate ::after opacity → zones 纹理回归（#6）；#107 归位 → ColorPicker 点退（#3）。
   每修一个都没做「其余消费方全量回归」——违反「结构重构必须逐表面 CDP 交互回归」铁律（memory `task-list-first-real-machine-gate`）。
3. **补丁叠加 = 新 bug 来源**：地板 depth-2/3 选择器 + wrapper 排除 + 镜像门控 + mirror 标记——每个补丁是新状态、新出错点。
   系统越「需要记例外」，新 bug 越必然。

**纪律改法（Phase 11.16 起，写进本档案强制）**：
- ① 每个 commit 前全浮层 + 全主表面 CDP 截图 A/B 回归——不只验被改的那个表面。
- ② 先做能恢复「浮层可读」的**最小改动**，不做多余重构（#109 优先验证 `display: contents` 让包装盒不成盒——地板规则零耦合；可行则替代 data-overlay-wrapper 标记）。
- ③ 验收以**用户视角像素 diff** 为准——computed backdrop-filter 有值 ≠ 画面有效（本次最致命教训：拿 computed 对冒充效果对）。
