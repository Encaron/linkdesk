# 插件目录结构规范

> 2026-08-05 E5#30。**官方插件模板——第三方开发者看任一官方插件，目录结构一致。**

---

## 标准目录结构

```
my-plugin/
├─ plugin.json           # 插件声明——唯一必选文件
├─ icon.svg              # 插件图标（可选，缺省用默认图标）
├─ README.md             # 插件说明（可选）
├─ i18n/                 # 翻译文件——每种语言一个 JSON（可选）
│  └─ en.json            # key=中文原文, value=译文
└─ src/
   ├─ index.tsx           # 入口——export default React 组件或空导出
   ├─ views/              # 页面级组件——每个对应一个 ViewContainer 视图
   │  ├─ MainView.tsx
   │  └─ SettingsView.tsx
   ├─ components/         # 可复用 UI 组件——被 views/ 或外部引用
   │  └─ Toolbar.tsx
   ├─ services/           # 业务逻辑——数据模型、状态管理、API 封装
   │  ├─ model.ts
   │  └─ api.ts
   ├─ styles/             # CSS 文件——每个视图/组件一个 .css，不内联
   │  ├─ MainView.css
   │  └─ Toolbar.css
   └─ __tests__/          # 测试文件——和被测文件同名 + .test 后缀
      ├─ model.test.ts
      └─ MainView.test.tsx
```

---

## 每类文件的判断标准

| 目录 | 放什么 | 不放什么 |
|:--|:--|:--|
| **views/** | 页面级 React 组件——有独立路由或 ViewContainer 入口 | 工具栏按钮、状态栏条目（→ components/） |
| **components/** | 可复用 UI 组件——被多处引用的无状态/弱状态组件 | 直接操作文件系统的逻辑（→ services/） |
| **services/** | 业务逻辑、数据模型、IPC 封装、纯函数工具 | JSX 渲染代码（→ views/ 或 components/） |
| **styles/** | 独立 .css 文件——每个视图/组件一个 | 内联 style（禁止手写——走 CSS 变量） |
| **__tests__/** | Vitest 测试——`<被测文件名>.test.ts(x)` | 测试辅助工具（→ `__tests__/helpers/`） |

### 判断流程

```
这个文件包含 JSX/React 渲染？
  ├─ 是 → 它是对应一个 ViewContainer 的页面吗？
  │        ├─ 是 → views/
  │        └─ 否 → components/
  └─ 否 → 它操作数据/状态/文件/网络吗？
           ├─ 是 → services/
           └─ 否 → 它是 CSS 吗？
                    ├─ 是 → styles/
                    └─ 否 → 它是测试吗？
                             ├─ 是 → __tests__/
                             └─ 否 → src/（根目录，特殊情况）
```

---

## 特殊情况——允许放 `src/` 根目录的

- **`index.tsx`**——插件入口，必须放在 `src/` 根
- **高度内聚的单文件插件**（总文件数 ≤ 3）——不强制建子目录
- **跨层共享的类型定义**（如 `types.ts`）——放 `src/` 根，被多个子目录 import

## `i18n/` 翻译目录

插件自带翻译文件，每种目标语言一个 JSON。key = 插件 UI 字符串原文（建议用作者母语），value = 译文。

```
i18n/
├─ en.json     ← { "在文件树中显示": "Reveal in File Tree" }
└─ ja.json     ← { "在文件树中显示": "ファイルツリーで表示" }
```

**声明：** `plugin.json` 的 `contributes.i18n` 字段声明各语言文件路径：
```json
"contributes": {
  "i18n": { "en": "i18n/en.json", "ja": "i18n/ja.json" }
}
```

**不需要为作者母语写回退文件**——缺译文的 key 由 `parseMissingKeyHandler` 返回原文：中文插件不必建 `zh.json`，纯英文/纯法文插件同样不必为英文/法文建回退文件——key 就是原文，缺译文时静默回退显示 key 本身。

**翻译对象：** `plugin.json` 中的 `title`/`description`（命令、配置项、视图容器名）+ `.tsx` 中 `t()` 调用的 UI 字符串。

**切语言行为：** 壳自动加载各插件的 `contributes.i18n` → 注册到 i18next → 切语言时即时生效，无需重启。渲染时调 `t()` 即可，不要求 `namespace` 参数——翻译注册在全局 `"translation"` 命名空间。

---

## 命名约定

- **文件名：** PascalCase（组件）、camelCase（非组件）、kebab-case.css（样式）
- **测试文件：** `<被测文件名>.test.ts(x)`——与被测文件同目录（`__tests__/` 内保持相同的相对路径）
- **CSS 文件：** 与被 styled 的组件同名——`MainView.tsx` → `MainView.css`

## 对标 VS Code

VS Code 扩展没有强制目录结构，但官方示例遵循类似约定：

| VS Code | LinkDesk |
|:--|:--|
| `src/extension.ts` | `src/index.tsx` |
| `src/commands/` | 无——命令在 `index.tsx` 中注册 |
| `src/views/` | `src/views/`——完全相同 |
| `src/test/` | `src/__tests__/`——Vitest 约定双下划线 |
| `media/` | `src/styles/`——LinkDesk 统一放在 src 下 |
| `package.nls.json` / `l10n/` | `i18n/`——LinkDesk key=中文原文，只提供目标语言 JSON |
