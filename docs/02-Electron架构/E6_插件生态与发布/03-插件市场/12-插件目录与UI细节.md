## 一、文件目录树规划（点5）

### 一·〇、目录规范总则——加新表达形式 = 五步仪式（订死）

> **为什么订死：** 市场插件的「表达形式」= 插件内的一个视图。加新表达形式（大屏商店 StoreView、未来更多浏览面）永远走同一仪式——**文件层零猜测**。这是用户 zone 类比（壳解耦 zone → 轻易加右栏/底栏/浮窗/拖出窗）在插件内的兑现（2026-08-29 拍板）。

| # | 动作 | 规则 |
|:--|:--|:--|
| ① | 建视图文件 `views/<域>/X.tsx` | 一个表达形式 = 一个视图文件，≤150 行。**视图按容器域建子夹**——`views/sidebar/`（`contributes.views.<侧栏容器>`）、`views/main/`（`contributes.views.main`）、`views/confirm/` 等。**分组轴 = `plugin.json` 的容器**（作者心里的分组本来就是这几块） |
| ② | 拆件 | **私有**子件（只被本视图 import）→ **同名字夹**（`views/main/DetailView/`）；**`components/` 只放跨视图复用件**；私有样式 → `styles/X.css`（token 化零 hex/px）；纯逻辑 → `services/`（共享逻辑进通用 domain service） |
| ③ | 声明 | `plugin.json` `contributes.views` 加一行（location: sidebar / main / floatingPanel）；要可浮出 = 再声明 `floatingPanel.viewId`，声明即出现（I8-3） |
| ④ | 容器免费 | 该视图 = 一个标签页 → 宽屏/浮出/独立窗全免费，容器层不再设计（标签页 = 通用表面容器） |
| ⑤ | 一票否决 | 行数超限必拆（见 一·二），拆子组件或拆服务，不堆行 |

> 🔴 **步骤 ② 是 2026-09-11 改的核心一条**（E6#84c）：旧文让**私有**子组件去 `components/`，结果 `DetailFeaturesTab` / `DetailChangelogTab` 这两个**只被 DetailView import** 的子件被放进了 `views/` 根（**放错两次**——房间错一次、角色也错一次）。**改成同名夹后，这类错位不会再发生**：私有件永远紧贴宿主，`components/` 的语义收窄为「跨视图复用」。
>
> 🔴 **步骤 ① 的连带铁律**：搬动 `views/` 下任何文件**必须同步改 `plugin.json` 的 `contributes.views[].render`**——详见 §一·五。

**命名与边界：**
- views/ components/ = PascalCase；services/ = camelCase；styles/ 与所属视图同名（`StoreView.css`）
- 依赖方向：视图只 import 自己的组件 + 壳基础件（Button/Badge 等）；services 只 import `window.linkdesk.*` + 兄弟 services；零 `@src/core`（插件独立铁律，`@linkdesk/ui` 经例外表）
- services = domain service 文件（marketEntry / installFlow / i18n）；**超限走 feature-folder**（domain 内聚合器 + 子模块，如 `services/installFlow/` = index.ts 聚合器 + steps/progress/revert 子模块），**禁止拆同 domain 平铺多文件**（拆法铁律 E6#0.4d/#0.6c——平铺拆分 = 「拆成更平铺」退路，违反 feature-folder）

**🔒 门面形态铁律（E6#86g，2026-09-11 立——判据是「有没有 basename 约束」，不是口味）：**

| 域 | 门面形态 | 为什么 |
|:--|:--|:--|
| `services/` `components/` `hooks/` `utils/` | **夹内 `index.ts`**（`services/foo/index.ts`） | 文件名**不是**任何声明字段 ⇒ 无 basename 约束 ⇒ 用夹内入口，该域根**不留多余散件** |
| `views/` | **夹旁散门面**（`views/foo/FooView.tsx` + `FooView/`） | 文件名 = `contributes.views[].render` = SDK bundle key（[vite-config.ts](../../../../packages/plugin-sdk/src/vite-config.ts) `collectSurfaces` 取 basename）⇒ **有** basename 约束，改名即改产物名 + 要同步 plugin.json |

> ⚠️ §二 末那句「门面文件绝不能改叫 `index.tsx`」**只在 `views/` 域成立**（`index` 与 entry 撞名）。**扩读到 `services/` 是误读**——E6#86c 当初就是这么把夹旁散门面误用到 services、导致 `services/` 根留 4 件散门面（E6#86g 订正为夹内 `index.ts`）。

**第一个示范位 = `StoreView.tsx`**（大屏商店，未来落地按此仪式）：`views/StoreView.tsx` + 私有 `PluginCard`/`StoreSidebar`/`StoreSearch` 拆 components、复用 `marketEntry`/`installFlow`、`contributes.views location:"main"` 声明（配合 location:"main" 多 id 原则）。

### 一·二、行数上限（一票否决）

| 文件类型 | 上限 | 超限处理 |
|:--|:--|:--|
| `views/*.tsx`（视图） | **≤150 行** | 拆子组件进**同名字夹**（私有）或拆纯逻辑进 `services/` |
| `services/*.ts`（服务/数据） | **≤200 行** | 拆 domain service（聚合器 + 同名夹子模块） |
| `components/*.tsx`（组件） | **≤150 行** | 拆子件进同名字夹；**`components/` 只放跨视图复用件** |
| `hooks/*.ts(x)`（React hook） | **≤150 行** | 按「纯函数层 / 状态层 / 聚合器」拆同名字夹 |
| `utils/*.ts`（纯函数） | **≤150 行** | 拆同名字夹（**纯函数才能进 `utils/`**） |
| `styles/*.css`（样式） | **≤300 行** | 按组件/视图拆独立 css（本地类前缀）——**⚠ 见下注** |
| `index.tsx`（入口） | **≤120 行** | 命令/菜单注册留入口，注册项超量提 `services/commands.ts` |
| **聚合器门面**（两种形态见 §一·〇 铁律） | **上表 ×2** | 上限放宽**不是目标值**——门面仍应尽量薄，**且不许含纯逻辑**。两种形态：<br>① **夹旁散门面**（`views/foo/FooView.tsx` + `FooView/`）——`views/` 支<br>② **夹内入口**（`services/foo/index.ts`）——`services`/`components`/`hooks`/`utils` 支（E6#86g） |
| `__tests__/**` | **不限** | fixture 天然长；**>1000 行**按 `describe` 组拆同夹多文件 |
| `i18n/*.json` | 不限（键随功能走） | — |

> 🔴 **`.css` 一律 300，不看它放在哪个目录**——`styles/*.css` 与组件自带样式（co-located，如 settings 的 `views/SettingsView.css`）**同一把尺**。「按目录定档」会让 co-located CSS 逃出门禁。

**`styles/` 分组（E6#86h 连带）**：11 件平铺 → `detail/`（6）+ `sidebar/`（3）+ 根保留 2 件（`MarketplaceView.css` / `MarketplaceConfirm.css`，各只 1 个消费者凑不成组）。改动 = 23 条 import + 5 条注释指针。

**测试：本轮不动。** 10 个测试平铺在 `__tests__/`（未镜像 `services/`/`views/` 相对路径），**规范上应镜像**但**不产生任何运行时/构建影响**——留待后续单独立案。

### 一·五、🔴 `plugin.json` 与目录的同步铁律（2026-09-11 新增）

> **本条是本层最贵的教训**——搬文件不改 `plugin.json` = 视图白屏，**且只在运行时才暴露，`npm run check` 抓不到**。

> **搬动 `views/` 下任何文件，必须同步改 `plugin.json` 的 `contributes.views[].render`。**

**为什么**：壳按 `_renderPath` **动态 import**（源码见 [contributions.ts](../../../../src/pluginLoader/contributions/contributions.ts)）——dev 走源码路径，打包由 `rewriteDistManifest` 改写为 `views/<Key>.bundle.js`。搬了文件不改声明 = **dev 白屏 + 打包版白屏**。

**同步核对法（机械，逐条过）**：

1. `grep -o '"render": "[^"]*"' plugin.json` 取全部声明值
2. **每个值都要能在盘上 `test -f` 通过**
3. 搬了文件 → **同步改源码里所有相对 import**（`../services/...` → `../../services/...`，层级加深一层全部 +1 级）
4. `npm run check`（tsc 抓漏）
5. **实机逐视图验**：dev 起 Electron → **逐个打开 7 个视图**（5 侧栏 + 详情 + 安装确认）→ 无白屏、无 console 报错

> ⚠️ **bundle key = basename，与子目录无关**（[vite-config.ts](../../../../packages/plugin-sdk/src/vite-config.ts)）——搬进子夹**产物名不变**。**但门面文件绝不能改叫 `index.tsx`**：`index` 已被 entry 占用，第二个会退化成 `index_`，语义混乱。**门面恒保留原名。**

## 三、UI 组件变量化（7.5）——哪些写为变量，谁控制

> **定案基准（10-市场UI拥有权 §四）：** 形状走主题（圆角/尺寸/颜色全 token），**「安装是绿」进语义 token 不能随手改**（30.12 补 `--success`），布局/业务组合归市场插件。用户 2026-08-29 拍板：不选「全部透明」（丢主操作可发现性），语义 token 是根治。

### 三·一、消费范围——哪些值必须走 token

| UI 值 | 用哪个 token | 谁控制 | 状态 |
|:--|:--|:--|:--|
| 胶囊文字颜色 | `var(--text-*)`（次级文本） | 主题 | ✅ 已有 |
| 胶囊文字大小 | `var(--font-size-sm)` / `var(--font-size-xs)` | 主题 | ✅ 已有 |
| 胶囊圆角 | `var(--radius-*)` | 主题 | ✅ 已有 |
| 胶囊内边距 | `var(--space-*)` | 主题 | ✅ 已有 |
| 胶囊底色 | `var(--surface-*)` 或语义 bg | 主题 | ✅ 已有 |
| **安装按钮绿** | `var(--success)` | 主题（语义 token，30.12 补） | 🔧 E6#30.12 |
| 安装按钮底色填充 | `var(--success)` + 文字 `var(--on-success, #fff)` | 主题 | 🔧 30.12 |
| 卸载按钮红 | `var(--danger)` | 主题 | ✅ 已有 |
| 禁用按钮透明 | ghost variant（`var(--surface-*)` hover） | 主题 | 🔧 30.14 |
| 等待依赖琥珀 | `var(--warning)` | 主题 | ✅ 已有 |
| 按钮圆角/尺寸 | `var(--radius-*)` / `var(--space-*)` / `var(--ui-scale)` | 主题 | 🔧 30.14 + 字号引擎 |
| 图标 | codicon（壳 `PluginIcon`） | 壳基础件 | ✅ |
| 本地类 CSS 布局（flex/grid/margin 相对量） | `var(--space-*)` | 主题 | ✅ 已有 |

### 三·二、边界——哪些**不**变量化

| 值 | 理由 |
|:--|:--|
| 布局顺序 / 胶囊数量 / 组合方式（画 4 个还是 5 个胶囊） | 市场业务组合，归市场插件（10 §一） |
| 三态 action bar 逻辑（未装/已装/更新互斥） | 业务逻辑，归市场插件 |
| toast 文案 / i18n key | 归市场插件 i18n（11-API§四） |
| 弹窗内容排版 | 归市场插件（10 §四·三：壳 Dialog 容器 + 市场自绘内容） |

| 步骤 | 落点任务 | 内容 |
