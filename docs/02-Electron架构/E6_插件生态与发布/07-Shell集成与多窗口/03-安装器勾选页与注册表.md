# 03 — 安装器勾选页与注册表（E6#45a-f）

> 目标：VS Code 同款「选择附加任务」勾选页（D2 拍板五项 + 默认状态），勾选结果驱动注册表写入；卸载对应清理；软件内开关（D5）可事后增减。
> 改动面：`build/installer.nsh`（追加，**不动 `customInit` 守卫**）+ `electron/main.ts` 新增注册表读写 handler（#45f）+ 设置插件设置项。**`electron-builder.yml` 不加 `fileAssociations`**（D3 拍板弃用）。

## 一、注册表键设计（勾选页挂在哪都写这些键）

per-user 安装（现状，D:\01link\LinkDesk）全部写 **HKCU**，不碰 HKLM、不需要管理员（VS Code User Setup 同口径）。

### 1.1 右键三键（#45b——D6 拍板：第二层传统菜单，带图标）

```
; ① 任意文件右键
HKCU\Software\Classes\*\shell\OpenWithLinkDesk
    (默认值) = "Open with LinkDesk"          ; 菜单文字（英文原语方向，memory english-first-direction）
    "Icon"   = "<安装目录>\LinkDesk.exe"      ; 菜单项图标
HKCU\Software\Classes\*\shell\OpenWithLinkDesk\command
    (默认值) = "<安装目录>\LinkDesk.exe" "%1"

; ② 文件夹右键（对文件夹本体）
HKCU\Software\Classes\Directory\shell\OpenWithLinkDesk        （同构）
HKCU\Software\Classes\Directory\shell\OpenWithLinkDesk\command  = ... "%1"

; ③ 空白处右键（文件夹背景）
HKCU\Software\Classes\Directory\Background\shell\OpenWithLinkDesk      （同构）
HKCU\Software\Classes\Directory\Background\shell\OpenWithLinkDesk\command = ... "%V"
```

- `*` 键 = 所有文件类型（清单 #45b 原文口径，VS Code 的 file context menu 同做法）；
- `%V` = Background 键专用占位（空白处无 `%1`）；
- 路径含空格 → command 里的 exe 路径**必须带引号**；
- 效果层：这三键出现在「显示更多选项」展开的传统菜单（用户拍板确认的同层；Win11 第一层见 00-README §五立案）。

### 1.2 文件类型编辑器注册（#45a——D3 拍板：手写，受勾选控制）

对标 VS Code 的「注册为受支持的文件类型**编辑器**」语义：**不抢默认程序**，只把自己登记进「打开方式」候选 + 系统「默认应用」设置页可选中：

```
; ProgId（每扩展名共用一个）
HKCU\Software\Classes\LinkDesk.Document
    (默认值) = "LinkDesk Document"
    \DefaultIcon\(默认值) = "<安装目录>\LinkDesk.exe"
    \shell\open\command\(默认值) = "<安装目录>\LinkDesk.exe" "%1"

; 13 个扩展名逐个登记（清单 #45a 原文列表）
HKCU\Software\Classes\.txt\OpenWithProgids
    "LinkDesk.Document" = ""        ；.py .js .json .md .html .css .ts .tsx .yaml .xml .csv .log 同构

; 系统级登记（「设置 > 默认应用」里出现 LinkDesk）
HKCU\Software\LinkDesk\Capabilities
    "ApplicationName" = "LinkDesk"
    "ApplicationDescription" = "..."
    \FileAssociations\.txt = "LinkDesk.Document"   ；13 项同构
HKCU\Software\RegisteredApplications
    "LinkDesk" = "Software\LinkDesk\Capabilities"
```

### 1.3 PATH（#45d 内的 PATH 勾选项——D4 拍板要，默认勾）

```
HKCU\Environment
    "Path" = 追加 "<安装目录>"（分号分隔；已有同段则跳过——幂等）
写完广播：SendMessageTimeout(HWND_BROADCAST, WM_SETTINGCHANGE, 0, STR: "Environment", ...)
```

- 只写用户 PATH，不动系统 PATH；
- **卸载/取消勾选时只删自己加的那段**：以 `;<安装目录>;` 形态做字符串定位替换，禁止整值重写（会吃掉其他程序加的路径）；
- NSIS 有现成宏可考：`PathFuncs`/`EnVar` 插件二选一（实施时确认 electron-builder 自带 NSIS 发行里有没有，没有就把 PathFuncs 的两个函数内联进 installer.nsh——不引外部 dll）。

## 二、勾选页（#45d）

### 2.1 ✅ 侦察结论与实现定案（2026-09-13 已落 `build/installer.nsh`）

**挂点 = `customPageAfterChangeDir`**（模板 `assistedInstaller.nsh:42-43`，`!ifmacrodef` 守护）——位置正在
「选完安装目录」与 `MUI_PAGE_INSTFILES` 之间，**就是 VS Code 附加任务页的同位**。原设计的 A/B/C
候选取 **A（插页）**，B/C 作废。页内 4 个勾选框（见下方 §2.2 的订正）。

三条实施期实证（都写进 `installer.nsh` 注释，改那里前先读）：
1. 🔴 **本文件里不许写顶层 `Page custom`**——本文件先于 `installer.nsi` 展开，页序=脚本序 ⇒ 页会跑到最前。
   必须把 Page 包进 `customPageAfterChangeDir` 宏（插入点由模板决定）。
2. 🔴 **StrFunc 的 `un.` 变体在 electron-builder 的两遍编译里都要不同前缀，实测两遍都炸**（installer 侧
   `${StrRep}` 要「声明」一次、卸载器侧要 `${un.StrRep}`，而卸载器那一遍又没有安装器函数）⇒ **PATH 操作
   定为「标记 + 备份」法，零字符串手术**：安装时首次追加前把原 PATH 存 `PathBackup`、加 `PathAdded` 标记；
   卸载时**精确匹配**（current == 备份;安装目录 或 current == 安装目录）才恢复备份，**用户改过就不动**
   （删错别家路径的代价 ≫ 留一段死路径）。
3. 页挂点/自定义函数必须包在 `!ifndef BUILD_UNINSTALLER` 里（Var 可见性老坑，同 `customInit` 守卫）。

### 2.1.1 页面挂点选型（历史候选，已作废）

electron-builder 的 NSIS 模板 `installer.nsi` 的 Page 序列写死在模板里，`installer.nsh` 被它 include（展开在前）。**我们写 `Page custom` 会排到模板页面之前**——页序错。所以挂点必须先侦察：

1. **侦察动作**：读本地 `node_modules\app-builder-lib\templates\nsis\installer.nsi`（及 include/*.nsh），grep 全部 `!macro custom*` 挂点 + 全部 `Page` 指令，列清单（像 #42d 守卫那样逐行确认挂点在模板的哪个位置）。
2. **候选路线**（按侦察结果择一，实施报告里写明选了哪条与为什么）：
   - **A** 模板支持在 Directory 页后插页（或有 `customPage` 类宏）→ 标准附加任务页（VS Code 同位）；
   - **B** 无法插页 → **Directory 页附加勾选区**：Directory 页 show 回调里 nsDialogs 加五个复选框（NSIS 支持在既有 MUI 页 show 函数补控件）；
   - **C** Finish 页勾选 + leave 回调补写注册表（customInstall 已跑完，注册表写入延迟到 finish leave——可行但写入点后移，卸载清理逻辑不变）。
3. 勾选状态保存：页面 leave 函数把五项结果写进 NSIS Var，`customInstall` 宏里按 Var 条件写 §一 的键。

### 2.2 五项与默认状态（D2 拍板，照抄 VS Code）

| # | 文案（对齐 VS Code 措辞） | 默认 |
|:--:|------|:--:|
| 1 | 将「通过 LinkDesk 打开」操作添加到资源管理器**文件**上下文菜单 | ☐ |
| 2 | 将「通过 LinkDesk 打开」操作添加到资源管理器**目录**上下文菜单 | ☐ |
| 3 | 将 LinkDesk 注册为受支持的文件类型的编辑器 | ☑ |
| 4 | 添加到 PATH（重启终端后生效） | ☑ |

> 🔴 **桌面快捷方式不做勾选项（对 D2「五项」的订正，2026-09-13 实施时定）**：electron-builder 的
> `createDesktopShortcut: true` 是无条件创建，勾选框**管不住它**——出一个管不住的勾选框就是骗用户。
> 改成自建快捷方式（`createDesktopShortcut: false` + `CreateShortcut` + 图标）属额外风险，本轮不做。
> 现状行为（装上即有桌面快捷方式）保持不变；要「可勾选」需单独立案。

### 2.3 静默安装口径（#45e）

- `/S`（自动更新与 CI 走这条）**不弹页**：按默认集执行（2/3 不写、1/4/5 写）——与 VS Code 的 `/mergetasks` 默认行为对齐；
- 重复安装/升级：§一 全部键**幂等写**（NSIS WriteRegStr 天然覆盖），无「已存在」分支；升级把用户当初没勾的项静默补上？**不**——静默升级按默认集写会把用户显式取消过的右键又加回来。处理：升级安装（`UNINSTALL_REGISTRY_KEY` 已存在，`customInit` 已在读）时静默路径**只补 PATH 与文件类型（默认勾的），右键两键按「已装版本是否写过」判断**——判据 = `Directory\shell\OpenWithLinkDesk` 键是否存在。此判据写进 #45e 验收。

## 三、卸载反向清理（#45e）

`customUnInstall` 宏（electron-builder 有此挂点，侦察同 §2.1 一起确认）：

1. §1.1 三键整树 `DeleteRegKey`（无条件——键不存在删除无害）；
2. §1.2：13 个扩展名的 `OpenWithProgids\LinkDesk.Document` 值删除 + `LinkDesk.Document` ProgId 整树删 + `Capabilities` 树删 + `RegisteredApplications\LinkDesk` 值删；**不删扩展名键本身**（`.txt` 等不是我们建的）；
3. §1.3 PATH 段移除（字符串定位替换，同 §1.3 规则）+ 广播；
4. 桌面快捷方式/卸载项由 electron-builder 自带卸载逻辑处理，不重复。

## 四、软件内开关（#45f——D5 拍板做）

- **设置项**：设置插件新增两项「资源管理器文件右键菜单 / 目录右键菜单」（文件关联是否也放开关：放——「注册为文件类型编辑器」同页第三项；UI 落地前**先调设计 skill**，硬约束 16）；
- **主进程 handler**：`electron/ipc/handlers/` 新增（或并入 env-handlers 同域，实施时按壳目录规范定）`registry-integration.ts`：`get`（三键存在性 → 三布尔）/ `set`（写/删 §一对应键，命令模板 = `"exe" "%1"`，exe 路径 = `process.execPath`，**打包后指向安装目录真 exe**）；
- **状态对齐**：设置开关读的是注册表现状（唯一真相），安装器勾选与软件内开关写的是同一批键——两边天然一致，无需同步逻辑；
- **边界**：软件内改动立即生效（资源管理器读注册表即时），无需重启；注册表写入失败（企业策略锁定等）→ pushToast 报错不静默；
- 🔴 这些键属**壳级系统注册**，数据面在主进程；设置插件只消费开关 UI——不违反「壳级功能不进插件」（B79），插件只是 UI 宿主。

## 五、验收（#45c 实机格 + 代码级预验）

| 判据 | 验法 |
|------|------|
| 打包通过 | `npm run electron:build` 出包——NSIS 编译零 warning（electron-builder `-WX`，installer.nsh 变量可见性教训见现有文件头 L48-54） |
| 勾选页 | 真装：五项出现、默认状态 = §2.2 表、勾/不勾逐项组合装 → 注册表只出现勾选的键（regedit 核） |
| 右键效果 | .txt 右键（显示更多选项层）见 "Open with LinkDesk" 带图标 → 点击启动并打开该文件（= #45c） |
| 文件夹/空白处 | 同上两键各自生效（= #45c） |
| 打开方式候选 | .txt 右键「打开方式」列表出现 LinkDesk；「设置 > 默认应用」能选到 LinkDesk |
| PATH | 新开 cmd 敲 `linkdesk --version`（或 `where linkdesk`）命中安装目录 |
| 卸载清理 | 装勾全套 → 卸载 → regedit 核三键/ProgId/Capabilities/PATH 段全清、`.txt` 键本身仍在、其他程序 PATH 段未损 |
