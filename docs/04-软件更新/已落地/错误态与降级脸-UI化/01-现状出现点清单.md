## 四、机制事实（设计要顺着走的）

- **术语澄清（AI 友好化轴，2026-11-21 用户点名）**：本档出现的「屏读」一律指**视障用户的读屏软件**（NVDA / VoiceOver，由 aria/role 承载，无障碍纪律）——**AI 取数不走视觉**：走命令面直取结构化数据（硬约束 26③「读结构化状态 → 调命令带参数 → 读结构化结果」；ai-bridge / linkdeskctl / MCP 已是现成火炮面）。两个「读」是两回事，不许混。
- **空态机制通用位**：`ViewContainerService/types.ts:84-95` `ViewEmptyContentDescriptor`（when 条件空态，`pluginId:viewId` 复合键归属）——`--empty` 变体的数据出口。
- **空态归属拍板在先**：E5.6#11g——空状态由插件内部自行判断，`PluginComponent` 始终挂载。⇒ `--empty` 变体是**可选统一件**，不强制收编（00-提案 §六-3）。
- **重试语义两处并存不合并**：发行说明页「刷新」（绕缓存）与「重试」（刚才那个再来一次）是有意区分（04 设计 §三）——新家族的动作区照此区分，不合并按钮。
- **「没有 ≠ 坏了」归一化已做**：E6#162 把「没有这只插件」（同步/异步判空）与「真加载失败」（import 抛错）分进两个出口（占位 vs ErrorBoundary）——新家族的 `--missing` / `--crash` 变体正是这两个出口的脸，语义对齐既有裁决。
- **四态互斥由 React 状态机保证（2026-11-21 用户问「加载与崩溃区分好了没」的答案）**：`PluginComponent` 管线上 import promise 的各终态各走各的脸——**pending → Suspense 显示 ViewSkeleton**（加载态）；**rejected → throw 被 ErrorBoundary catch → crash 脸**（且 rejected 不永久缓存，重试即重新 import，`PluginComponent.tsx:180-183`）；**null（不在盘上）→ missing 脸**（不 throw，`:172`）；**resolve → 真内容**（骨架整体卸载，ViewSkeleton「loaded 即整体卸载」）。**「加载中」与「崩了」不会错位互串**——骨架和崩溃脸不存在同时显示或串位显示的可能。
- **真实缺口（同问暴露）**：import **永久 pending 无超时兜底**——文件锁/网络挂起会让骨架无限呼吸，「慢」与「挂」用户不可辨。是否立第四变体 `--timeout`（超时转降级脸＋重试出路）→ 00-提案 §六开放问题 5 待拍板。
