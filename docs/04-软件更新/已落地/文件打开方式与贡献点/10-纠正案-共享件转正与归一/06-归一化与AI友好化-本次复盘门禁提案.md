## 一、两类问题的定义

### 1.1 非归一化（N）
同一语义或同一视觉元素在全软件出现**第二份实现**；或同一能力在新旧两处并存、旧路未删。

本次实例：三处头像各写一套（用户实机指出，待统一定位）；卡片/角标/媒体/轮播曾各有一套（媒体丰富度 A–F 收口）；价格角标多轮返工（F47 定「唯一状态出口」）。

### 1.2 非 AI 友好化（A）
UI 上可执行的动作**没有**对应的、可枚举、可调用的命令/API；只能通过鼠标坐标、拖拽、点击完成，AI 无法发现、无法复现、无法断言结果。

本次实例：作者排序/来源管理当初只能拖拽（作者身份实施已补 `swapAuthors`/`swapRepos`/`getOrder`，属正例）；其他「只能拖鼠标」的入口待盘点。

## 二、判据（制度层：评审时必须回答）

### N 判据（新增实现前五问）
- **N1** 这个元素/能力全软件是否已有实现？在哪？
- **N2** 为什么现成的不够？差额是否可参数化？
- **N3** 新实现是否会形成第二套数据/状态/样式？
- **N4** 旧实现是否**同笔删除**（无死代码）？
- **N5** 共享边界：能进 `@linkdesk/ui` 的进；插件私有长相不抽，但**插件内必须单实现**（CLAUDE 硬约束 28）。

### A 判据（任何 UI 动作合入前四问）
- **A1** 这个 UI 动作是否有命令 id？是否已注册、可在命令清单枚举？
- **A2** 是否能通过 `getState`/API 读到结果与当前状态？
- **A3** 不做鼠标操作时，能否用命令完成同一件事（AI 可复现）？
- **A4** 命令是否进契约/作者手册/命令清单（自动生成）？

> **判定**：A1/A2 任一否 ⇒ **不得合入（P0）**；A3/A4 否 ⇒ 合入前必须补。
> **原则**：拖拽只能是命令面的**一种呈现**；命令面是 canon，UI 是可替代表现（对齐「万物皆可插件」表现层可替换化）。

## 三、机械门禁规格（待实现，挂 `npm run check`）

| ID | 名称 | 检查方式 | 失败条件 | 可复用 |
|:--|:--|:--|:--|:--|
| **G-N1** | 同语义元素重复实现 | AST/组件引用白名单；对 Avatar / Card / Media / StatusTag / ActionBtn / MoreMenu 等原语做「单实现」断言 | 同一语义出现 ≥2 个本地实现且无登记豁免 | 新增 |
| **G-N2** | 视觉 token 越界 | 复用 `check-token-audit` / `check-css-hardcode`，扩展「磨砂/辉光/圆角」只认 `--surface-*` | 出现未走 token 的磨砂/辉光/圆角硬编码 | 扩展 |
| **G-N3** | 旧路残留 | `knip` ＋ 旧文件/旧导出白名单比对；**前置：先修 knip**（当前 HEAD 崩溃＋`ignoreWorkspaces: packages/*` 漏审 kit 包） | 旧实现仍被引用或文件未删 | 扩展 |
| **G-A1** | UI 动作→命令映射 | 枚举交互入口（`onClick` 动作、菜单项、快捷键、拖拽）与命令注册表，做差集 | UI 有动作、命令表无对应 id | 新增 |
| **G-A2** | 鼠标专属入口 | 检测「只有 drag / `onMouseDown` 而无命令」的排序/交换/删除动作 | 存在只能鼠标完成的实质操作 | 新增 |
| **G-A3** | 状态可读覆盖 | 每个页面/卡型至少一个可读状态断言（`getState` 契约） | 新页面/新卡型无状态读入口 | 扩展 `check-manual-surface` |
| **G-A4** | 命令面文档同步 | 复用 `build-ai-manual` / `check-manual-surface`，新命令必须进 AI 手册与命令清单 | 命令注册但手册/清单缺失 | 复用 |

### 实施顺序（按收益/成本）
1. **G-A1 + G-A2**（AI 友好化，收益最大、误报最低）；
2. **G-A3 + G-A4**（状态可读与文档同步，复用多）；
3. **G-N1**（归一化，需白名单与豁免机制，误报成本最高）；
4. **G-N2 + G-N3**（多数可复用既有脚本，做扩展）。

## 五、落位与执行顺序

1. **制度层**：本文件为判据源；如需进 `CLAUDE.md` 硬约束，走 `claude-md-maintenance`（一次只加一条、同笔压缩）。
2. **机械层**：新增 `scripts/check-ai-surface*.mjs`（G-A1/G-A2/G-A3/A4 可合并为一个脚本族）；G-N1 独立脚本带豁免表；全部带 `--self-test`，挂 `npm run check`。
3. **记忆层**：memory 新建条目 `normalization-and-ai-friendly-gates`（description 写触发条件：新增 UI 元素/新交互/新卡型/新命令）。
4. **执行**：派执行 AI 按 G 项逐条实现；**只加检查与豁免表，⛔ 顺手改业务代码**；每项单独一笔提交。

### 5.5 作者侧策略（2026-11-23 用户拍板）

- **官方范围强制**：软件本体、全部官方插件/主题、SDK/kit/脚手架——必须归一；门禁逮到不归一**立即修**。
- **第三方范围**：默认**警告 ＋ 可写理由豁免**，⛔ 硬阻断；⛔ 强制作者的卡片长相（CLAUDE 硬约束 28）。
- **官方归一化样板＝设置界面槽位化**：插件槽/详情槽只提供 UI，注册即显示——这是官方后续所有「面向插件的界面」的基准。
- **SDK/脚手架**：提供共享件（`statusTag`/`CardShell`/`cardMetrics`/`Avatar`）＋模板 lint＋schema 校验，让「用官方件」比「自己写」更省事；这是比门禁更有效的引导。
- **发现问题后的发版纪律**：软件本体**攒批不发版**；插件与 SDK **可随时发版**（用户 2026-11-23 授权），发前 `verify`/`test` 全绿、走现有 Release→目录→种子流程。
