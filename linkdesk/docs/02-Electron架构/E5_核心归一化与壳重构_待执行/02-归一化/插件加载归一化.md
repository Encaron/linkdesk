# 插件加载归一化——parseContributions 唯一入口

> 2026-08-02。**E5 第 2 层第 5 轮。** 三条加载路径归一化为一条。
> 执行清单任务：E5#12

---

## 一、前因——三条互不知道的路径

### 1.1 当前状态（loader.ts）

```
loadPlugin(pluginId)                    ← 总入口
  ├── loadViewPlugin(pluginId, manifest)    ← 有 entry → 加载 React 组件 (L875)
  ├── loadThemePlugin(pluginId, manifest)   ← 有 themes/file → 注册主题 (L933)
  ├── loadLanguagePlugin(pluginId, manifest)← 有 languages/file → 注册 i18n (L1096)
  └── parseContributions(pluginId, c)       ← 有 contributes → 分发到各 Registry (L344)

loadPluginRuntime(pluginId)            ← 运行时加载（非 glob 插件）(L725)
  └── 重复了大量 loadPlugin 的逻辑
```

**问题：**
1. `loadThemePlugin` 和 `loadLanguagePlugin` 逻辑和 `parseContributions` 的 `contributes.themes`/`contributes.languages` 分支重复——两条路径做同一件事
2. `loadViewPlugin` 内部还调了 `parseContributions` 中没有的 langDefs 解析——寄生在视图插件里
3. `loadPluginRuntime` 是 `loadPlugin` 的复制粘贴——E3b #36j1 提取了 `applyPostLoadSteps` 堵了一部分缝，但加载逻辑本身仍重复
4. Python 纯数据插件被迫声明 `entry` + 写空 `index.tsx`——因为 langDefs 解析寄生在 `loadViewPlugin` 里

### 1.2 目标

```
loadPlugin(pluginId)                    ← 唯一总入口
  ├── loadPluginLifecycle(pluginId, manifest)  ← 所有插件都走这个
  │     ├── parseContributions()  ← 公共步骤——主题/语言/命令/菜单/视图容器/文件关联/langDefs
  │     └── loadPluginComponent() ← 仅当 entry 存在——加载 React 组件
  └── 不再有 loadThemePlugin / loadLanguagePlugin
```

## 二、设计方案

### 2.1 核心——拆分公共步骤和视图步骤

```typescript
// loader.ts（改造后）

/**
 * 所有插件的公共加载步骤——解析 contributes。
 * 视图插件、主题插件、语言插件、数据插件——全部走这里。
 */
async function loadPluginLifecycle(
  pluginId: string,
  manifest: PluginManifest
): Promise<void> {
  // Step 1: 解析 contributes（所有插件共用）
  if (manifest.contributes) {
    await parseContributions(pluginId, manifest.contributes as Record<string, unknown>);
  }

  // Step 2: 加载视图组件（仅当有 entry）
  if (manifest.entry) {
    await loadPluginComponent(pluginId, manifest);
  }
}

/**
 * 仅加载 React 视图组件——不做任何数据解析。
 * 从 loadViewPlugin 改名，剥离 langDefs 解析（已移至 parseContributions）。
 */
async function loadPluginComponent(
  pluginId: string,
  manifest: PluginManifest
): Promise<void> {
  // 1. 从 glob 找到 entry 模块
  // 2. 动态 import
  // 3. 构造 ViewPluginEntry
  // 4. registerViewPlugin()
  // 5. 创建 WebContentsView
  // ← 不再解析 langDefs（parseContributions 已做）
}

/**
 * parseContributions 补全——加 langDefs 解析。
 */
function parseContributions(pluginId: string, c: Record<string, unknown>): void {
  // ... 现有分支 ...

  // 🆕 langDefs 解析（从 loadViewPlugin 迁移到这里）
  if (c.langDefs) {
    LangDefRegistry.registerLangDef(pluginId, c.langDefs as LangDefContribution[]);
```

### E5#12g 🛡️ 健壮性——分支出错不阻塞其他（~5 行）

**文件：** `src/pluginLoader/loader.ts`

**内容：** `loadPluginLifecycle` 内部 try/catch——任一步失败不阻塞其他：

```typescript
async function loadPluginLifecycle(pluginId: string, manifest: PluginManifest): Promise<void> {
  // Step 1: parseContributions——出错不阻塞视图加载
  try {
    if (manifest.contributes) {
      await parseContributions(pluginId, manifest.contributes as Record<string, unknown>);
    }
  } catch (e) {
    console.error(`[loader] ❌ parseContributions 失败: plugin=${pluginId}`, e);
  }

  // Step 2: loadPluginComponent——出错不阻塞其他插件
  if (manifest.entry) {
    try {
      await loadPluginComponent(pluginId, manifest);
    } catch (e) {
      console.error(`[loader] ❌ 加载视图组件失败: plugin=${pluginId}`, e);
    }
  }
}
```

**验证：** 故意写错一个插件的 contributes → Console 红色报错 → 其他插件正常加载。

## 🔴 预测 Bug

### Bug E5-12a 🔴🔴🔴 语言/主题静默失效——parseContributions 分支漏了

**历史：** E3c #38——`parseContributions` 忘加 `contributes.languages` 分支 → 合集语言插件静默失效。E3b #34——非视图插件踩进盲区。

**E5 触发条件：** 删除 `loadThemePlugin`/`loadLanguagePlugin` 后，如果 `parseContributions` 中 themes/languages 分支有 bug → 所有主题/i18n 静默失效——不报错、只是不生效。

**🔥 防线——vitest 覆盖所有插件类型：**
```typescript
// loader.test.ts
it("声明式语言插件 (contributes.languages) → parseContributions 正确注册");
it("声明式主题插件 (contributes.themes) → parseContributions 正确注册");
it("视图插件 (entry + viewsContainers) → 加载 React 组件");
it("数据插件 (纯 langDefs, 无 entry) → 不加载组件但 langDefs 生效");
it("旧格式 themes[] → 兼容层正确转换");
```

**🛡️ 手动验证：** E5#12 完成后立即执行全量回归——三图标切换、主题切换、语言切换。

### Bug E5-12b 🔴🔴 loadPluginRuntime 不同步——又漏了

**历史：** E3b Bug 2 `cea1476`——`loadPlugin` 加了主题数据加载，`loadPluginRuntime` 漏了 → 重装后主题空壳。修复后 E3b #36j1 提取 `applyPostLoadSteps`。但加载路径本身仍有重复。

**E5 触发条件：** `loadPlugin` 归一化为 `loadPluginLifecycle` → `loadPluginRuntime` 仍用旧的三路分发逻辑 → 市场安装的插件和源码插件走不同路径 → 行为不一致。

**🔥 防线——loadPluginRuntime 也走 loadPluginLifecycle：**
```typescript
async function loadPluginRuntime(pluginId: string): Promise<void> {
  // ... 读取 manifest ...
  // 🔥 和 loadPlugin 走同一个入口——不是复制粘贴
  await loadPluginLifecycle(pluginId, manifest);
  // ... applyPostLoadSteps（保留）...
}
```
