# 19 — 组件速查：壳提供了哪些 UI 零件

> **本页回答一个问题：** 界面上的按钮、下拉、开关、右键菜单……**哪些是壳已经给好的**？什么时候该用哪个？
>
> 🔴 **本页是"清单 + 选用判据"，不是 API 手册。** 组件的 props、签名、默认值的**唯一真相源**在包里：
> `node_modules/@linkdesk/ui/` 的 README 与 `dist/index.d.ts`（编辑器里 `import` 就有补全）。
> **本页不抄 props 表**——抄了就会漂移，那正是要避免的第二份真相源。

| | |
|---|---|
| 读者 | 要写界面、不想自己造轮子的作者 |
| 形态 | 速查（按"我要什么控件"查一行） |
| 不是 | 组件的 props 文档（→ `@linkdesk/ui` 包内 README / d.ts）· 写法规约（→ [05-插件UI写法规约](05-插件UI写法规约.md)） |

## 一、什么时候**必须**用共享件（不是建议）

| 你要做 | 必须走 | 为什么 |
|:--|:--|:--|
| 右键菜单 | `contributes.menus` 声明 ＋ `<ContextMenu>`（或 `window.linkdesk.menu.registerItems`） | 手写右键菜单 = 违反硬约束；且不会跟随主题/玻璃 |
| 弹窗 / 浮层 | `createPortal` 到 `document.body`（共享件 `OverlayPortal` 已封装位置约定） | 层级、焦点锁、窗口拖拽区冲突都在里面处理过 |
| 持久化"记住用户上次选的" | `window.linkdesk.configuration.get/set` | 禁止 `localStorage.setItem()` |
| 让用户选文件/目录 | `window.linkdesk.dialog.openFile` ＋ `FilePathInput` | 路径解析与资产路径约定在壳侧 |

**理由一句话：** 这些控件的"玻璃 / 主题 / 焦点 / 层级"是**壳统一管**的。你自己写一个，主题一换就不跟随，用户在两种外观之间来回切会明显看出来。

---

## 二、装与引

```bash
npm i @linkdesk/ui      # 可选——想让界面跟内置同款时装
```

```tsx
import { Button, Toggle, ContextMenu } from "@linkdesk/ui";
```

> 包是**单源码防漂移**的编译产物：壳改组件 → 包跟着变，所以"内置同款"是字面意义上的同一份实现。它也**不进**你的 `.linkdesk-plugin` bundle（构建时 external）——不用担心体积。

## 三、组件清单

| 组件 | 干什么 | 什么时候用它 |
|:--|:--|:--|
| `Button` | 按钮 | 任何"点一下就做"的动作；变体/尺寸跟着主题 |
| `Toggle` | 开关 | 二值设置项（开/关） |
| `Slider` | 滑杆 | 数值区间调节（配合 `inferSliderStep` 推步进） |
| `NumberInput` | 数字输入框 | 需要精确输入的数字（滑杆旁边常配一个） |
| `SelectBox` | 下拉选择（选项固定） | 枚举值，如单位 mm/cm/inch |
| `DynamicSelect` | 下拉选择（选项动态） | 选项来自运行时数据（串口列表、主题列表…） |
| `Combobox` | 可输入的下拉 | 选项多、允许用户自己填（如自定义路径） |
| `SegmentedRadio` | 分段单选 | 2–4 个互斥短选项，比下拉更直观（如 左/中/右） |
| `FormRow` | 表单一行（label ＋ 控件） | 要跟设置页一样的排版：标签在左、控件在右 |
| `StringListEditor` | 字符串列表编辑（一行一条，可增删） | 路径列表 / 扩展名列表 / 市场源列表 |
| `FilePathInput` | 文件或目录路径输入 | 选路径，带浏览按钮与校验 |
| `FontFamilySelect` | 字体族选择 | 让用户选 UI/编辑器字体 |
| `ColorPicker` | 取色器 | 让用户挑颜色（记得存成配置值，别写死进组件） |
| `ThemePicker` | 主题选择器 | 你要列出/预览可选主题时（一般直接用壳的设置页即可） |
| `MarkdownView` | Markdown 渲染（含安全清洗） | 展示 README / 说明 / 变更日志——**唯一指定组件**，别自己引 markdown 库 |
| `Badge` | 小标记 / 计数 | 未读数、已安装数量这类角标 |
| `PluginIcon` | 渲染插件图标 | 显示某个插件的图标（自动处理 codicon / 自定义 svg / 身份彩色图） |
| `ContextMenu` | 右键菜单组件 | 配合 `contributes.menus` —— 见 [05-插件UI写法规约](05-插件UI写法规约.md) |
| `InlineInput` | 行内输入（命令式句柄） | 树/列表里就地改名（拿 `ref` 调 `InlineInputHandle`） |
| `OverlayPortal` | 弹层 portal 宿主 | 自绘弹窗要 portal 到 body 时用它，别裸写 `createPortal` 到处飘 |
| `HintCard` | 贴锚的悬停说明卡（非交互） | 「停在某个小标上出一张说明卡」——给 `lines`（1–3 句）与锚元素，触发/定位/玻璃全归壳；⛔ 卡内不放链接按钮 |

> 清单以包的实际导出面为准（`packages/linkdesk-ui/src/index.ts` 是唯一真相源）——本页若与包不一致，**以包为准**。

## 四、Hooks 与工具函数

| 名字 | 干什么 | 什么时候用 |
|:--|:--|:--|
| `useDebouncedInput` | 输入防抖 | 边打字边算/边搜（避免每个字符都触发重活） |
| `useClipboardKeys` | 剪贴板快捷键（三轨道） | 你要在自己的控件里支持复制粘贴（文本键走容器 `onKeyDown`——见 05 号文档） |
| `useClickPreview` | 单击/双击区分预览 | 列表项"单击预览、双击打开"这类交互 |
| `inferSliderStep` | 按区间推滑杆步进 | 配 `Slider` 用（浮点区间自动给 0.01 这种步进） |
| `urlSourceKey` | URL 源去重键（owner/repo，分支无关） | 你自己做"加一个源"的列表时，键要跟壳同款 |
| `FileIconResolver` | 文件图标解析器 | 你要显示文件图标（按扩展名/文件名映射，跟壳同一个解析器） |
| `pickIdentityArt` / `DEFAULT_PLUGIN_IDENTITY_URI` | 插件身份图裁决与兜底 | 自己画插件身份图时用同一条裁决链 |
| `IconDescriptor` / `ContextMenuProps` / `ManifestIconShape` / `ResolvedIcon` / `InlineInputHandle` | 类型 | 需要显式标注类型时 `import type` |

## 五、常见错误

| 症状 | 病根 | 正确做法 |
|:--|:--|:--|
| 主题一换，我的下拉/菜单还是老样子 | 自己写了一套控件 | 换 `@linkdesk/ui` 的共享件 |
| 右键菜单点不出来 / 位置飘 | 手写 `contextmenu` 事件 | `contributes.menus` ＋ `<ContextMenu>` |
| 弹窗被标题栏吃掉一半点击 | 弹层放到 `top: 0`，撞上窗口拖拽区 | 用共享弹层组件（它已避开拖拽区） |
| 用户设置没保存住 | 用了 `localStorage` | `window.linkdesk.configuration.set` |
| 装了两个 UI 库，样式互相污染 | 自己引了第三方组件库 | 能用共享件就用；确需第三方时注意样式隔离 |
