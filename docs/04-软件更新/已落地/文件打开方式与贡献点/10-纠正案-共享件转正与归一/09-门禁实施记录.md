## 第 1 步 · 修 knip（G-N3 前置）

### 1.1 开工实测：与任务描述的出入（如实记）

| 说法 | 实测（2026-11-23 · Node 24.16 · knip 6.34.0） | 处置 |
|:--|:--|:--|
| HEAD 崩溃（oxc 解析/内存） | **本机未复现**：`npm run knip` 1.8s、exit 0、零输出；塞入死文件能准确报红 ⇒ 静态解析链是活的 | 未按「崩溃」修；把**真正失效的面**修掉（下两行）。若某台机器/某 Node 版本仍崩，先记读数再定，⛔ 不凭记忆改 |
| `ignoreWorkspaces: packages/*` 漏审 kit | **成立**。`packages/marketplace-kit` 整包不在审计域；单跑会报 6 个测试文件「未用」（kit 自己不声明 vitest，测试由根仓 vitest 统一跑） | 收窄为逐包列举；kit 进审计，测试文件列 entry |
| 豁免账本腐烂 | 成立但**不能照 knip 提示删**（见 §1.4） | 保持原 `ignore` 数组不动 |

### 1.2 改了什么

| 文件 | 改动 | 为什么 |
|:--|:--|:--|
| `knip.json` | `ignoreWorkspaces` 从 `["packages/*"]` 收窄为**逐包 4 条**（ui / sdk / docs / create-plugin，各带理由）；新增 `workspaces["packages/marketplace-kit"]` = `entry: src/*.test.ts` + `project: src/**/*.ts` | 通配豁免是「整类静默漏审」的温床；kit 是作者机器的正典工具链，死导出＝作者照文档调不到 |
| `scripts/check-dead-code.mjs` | **新增**：knip 的固定入口 ＋ 配置前置断言 ＋ `--self-test` 负控 | 让「审计腿活着」变成可自证的事；配置被改坏时给出「文件:期望 → 实际 → 示例修法」 |
| `package.json` | `check` 链的 `npm run knip` 换成 `node scripts/check-dead-code.mjs --self-test && node scripts/check-dead-code.mjs`；`knip` 脚本指向包装器，新增 `knip:raw` 保留原始诊断出口 | `check-gate-health` 要求每道 `check-*.mjs` 带自测并接线；`npm run knip` 的既有文档语义不变（仍 exit 0） |

### 1.3 验收读数

```
node scripts/check-dead-code.mjs --self-test
  [self-test] PASS：kit 在审计域内，塞入的死文件被 knip 报出（并已清理）。   exit 0

node scripts/check-dead-code.mjs      # = npm run knip
  （零输出）exit 0

node scripts/check-gate-health.mjs
  ✅ 63 道 check-*.mjs —— 有自测＋已接线 61 道 ／ 豁免 2 道   exit 0
```

- **正控**：`packages/marketplace-kit/src/__knip_selftest_probe.ts` ⇒ knip 报 `Unused files` 并 exit 1（自测自动跑、跑完删除）。
- **负控**：探针移除后同一命令零输出、exit 0；探针残留检查 = 无。
- **配置负控**：自测断言 `ignoreWorkspaces` 里不得再出现 `packages/*` / `packages/**` / `*`，且不得含 `marketplace-kit`；谁写回来当场红。

### 1.4 踩坑记录（给下一个 AI，别再踩）

1. **`knip --include files` 的 configuration hints 只对「files 这一种 issue」成立**。
   实测：按提示删除 30 条 `ignore` 后，默认审计从 0 条暴涨到 **123 条** unused exports/types（`src/core/index.ts`、`linkdesk-api.ts` 等**故意的公共 API 面**）。
   ⇒ 提示不等于许可证；**删豁免前必须用默认 issue 集复跑**。本步因此**一条 ignore 都没删**。
2. **knip 的配置必须逐包列举，⛔ 不再用 `packages/*`**：下一个新包若默认落进通配，就重演「kit 没人审」。
3. **kit 的 dist 不能当入口**：`package.json` 的 `exports`/`bin` 指向 `dist/`，审它等于审 tsc 产物；`project` 必须锚 `src/**/*.ts`，否则死导出永远看不见。
4. **kit 的测试是根仓在跑**（`vitest.config.ts` 的 `packages/**/*.test.ts`）：knip 按 workspace 分析时看不见这条边 ⇒ 不列 entry 就假红 6 个文件。

### 1.5 边界（本步没做的，别当成漏）

- `linkdesk-ui` / `plugin-sdk` / `plugin-docs` / `create-linkdesk-plugin` **仍不在 knip 域**，理由写在 `knip.json` 注释里（公共 API 面 / 产物包 / 模板素材）。要扩域＝另立拍板，⛔ 顺手放开。
- 本步**零业务代码改动**（`src/`、`electron/` 未动）。
- 软件本体不发版（攒批纪律）。

### 2.4 零视觉验收（真机环 · LinkDesk v0.2.60 · CDP 9333）

方法：`dev --real` 直写 `%APPDATA%\linkdesk\plugins\marketplace` → `linkdeskctl exec marketplace.openStore` → CDP 冻结动画/长定时器 + 全部图片 `decode()` → 截图 + 68 个卡/媒体/图标元素的 `getBoundingClientRect` 快照。同条件先截基线（回滚 CSS）再截改后。

| 视口 | 像素差 | 几何 |
|:--|:--|:--|
| **900×2800** | **0**（0/2,520,000 px） | 68/68 全等 |
| **1440×2800** | 15,342 px（0.37%），**每个通道差 ≤1（sum ≤3）**；差异全部落在「主题专区」图片区；**0 个像素 sum > 3** | 68/68 全等 |

- 自噪声底：同条件重复截图 1440 宽曾出现 572 px 抖动 ⇒ 上述 15k 属图片解码噪声量级，不构成尺寸/布局变化。
- ⚠️ 主题干扰已排除：首轮 A/B 因主题从暗切到「玫瑰窗」造成百万级假差；改为**固定静态 dark** 后复测。用户主题/外观已恢复（`app.theme = theme-rose-window.rose-window`），安装版插件已还原为发版版（`dev --real` 停止 + `git stash` 重建后 pop）。

### 2.5 老壳兼容（本步真踩到的坑）

运行中的安装版 v0.2.60 **没有**新 `--size-*`：插件直接引用会让尺寸解析为空、盒子塌。⇒ 独立发版的插件一律写 `var(--size-x, 原值)`；直到 `minAppVersion` 包含尺寸域 token 才可去 fallback。此条已写进作者文档（中英 §11.1）。

### 2.6 边界与后续

- 门禁当前 **0 error / 2 warn**：settings 导航图标 16 未迁（非 enforced 仓）⇒ step 5 全仓扫描时清并收紧。
- `declaredGeometry` 只对**已登记文件**生效；未登记插件走 warn，step 5 迁移后逐仓收紧。
- 第三方仓**不扫不判**（SDK lint 侧 WARN 是下一步的引导面）。
- 本步零视觉，按 memory `gate-idle-vs-zero-violation` 的先例（「零视觉声明变化 ⇒ 硬约束 16 未触发」）未调设计 skill；所有值原样搬迁，未做任何设计选择。
