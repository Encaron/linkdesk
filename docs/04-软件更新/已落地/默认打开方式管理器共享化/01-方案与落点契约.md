## 一、落地位置判据走查（§十 · 三问决策链）

```
Q1 它消费谁的数据？
   └ 宿主声明（四路全中）：
       ① contributes.fileAssociations（各插件声明）→ FileAssociationService
       ② 插件清单/图标/名称 → pluginManager.list()（卡头身份图）
       ③ 配置项 → workbench.fileAssociations / app.osAssociations.followPlugins（壳声明）
       ④ 动作 → 壳命令 workbench.action.openWith（母案纠正案 01 已归位）
   ⇒ 判据 A 定案：**壳或共享件，与消费者数量无关**（⛔ 不进 Q2）
```

**两个曾被用来挡的反论，先拆掉（都在判据里有名字）：**

| 反论 | 拆法 |
|:--|:--|
| 「设置插件是指定渲染方，它画宿主声明是本职」 | 渲染**通用配置行**是本职（判据 A 表「配置项」例＝设置页渲染器）；`fileAssociationsManager` 不是通用渲染，是一份**文件关联专属能力**的呈现。判据 A 的判词问的是「换一台插件谁来画」——设置插件这个**角色可整套替换**（CLAUDE.md 硬约束 11 明文），渲染体却只此一家 |
| 「现在只有官方一台设置插件渲染 ⇒ 等 D10」 | **D10 反向用法已废止**（2026-10-05，[纠正案 05 §2.3](../../已落地/文件打开方式与贡献点/10-纠正案-共享件转正与归一/05-防复发-机械准入原则.md)）：判据 A 管「住哪层」、D10 只管「进池时点」；「设置插件可整套替换」是架构自诺的场景，**不是假想消费者**。用户 8.6.1 同律：「第二个相同插件进场是必然的事情，等它＝白做工」 |

**定案（先例支撑）**：转正**共享层**（`@linkdesk/ui`）。同构先例＝**ThemePicker**——一只整页级选择器住共享池，渲染方可以整套用它（统一风格），也可以只拿数据自己画（自有风格）；**两层论在主题页已是现实，管理器没跟上**。

Q2/Q3 不必再走（Q1 已定案），照实登记：视图做成纯 props in／events out（`PluginCard` 模式）后天然满足「拎出来就能给第三方用」（R6）；动作面已在壳命令（Q3 ✅，母案纠正案 01 交付）。

## 二、8 维度设计前置

### ① 能力边界
- **壳能力的呈现件**（消费宿主声明的管理视图），渲染方可替换——与「终端是第一个视图插件」同理：能力归壳/共享，第一台渲染方只是第一个消费者。
- **保底设计**：C2 落地后——未知渲染器里 OS 跟随开关（boolean）按通用控件**可操作**、挂载键按拍板形态降级（隐藏或只读）；管理器完整呈现由共享件保证「谁渲染都取得到」。

### ② API 设计
- **零新 API**。数据装配**留在渲染方**：读面（`fileAssociation.listHandlersFor`／`pluginManager.list()`／覆盖表读）与写面（`setDefault`·`setDefaultBulk`）全是既有契约面——第三方渲染方自己也能拉同样的数据（这正是「只拿数据自画」那一路的可行性）。
- 契约不改：`SettingsUiHint` 仍 14 枚，语义不变——**改的只是渲染体的住址**。模型类型（`ManagerModel`/`CardModel`/`ContestedRowModel`/`ExtRowModel`）是渲染 props 契约，随件进 `@linkdesk/ui`，**不进 contracts**（同 `PluginCard` 先例）。

### ③ 通信方式设计
- **零新通道**。settings 插件照今天用 `lk().*` 读宿主面组装 model（`useFileAssociationsModel` 原样留在插件仓——它是「调用方」不是「能力」）；折叠块开关的读写经 `useConfigurationValueIpc` 留插件侧，共享件只收值＋回调。

### ④ 壳侧代码设计
- 落点 `src/components/shared/file-associations-manager/`（邻位照 `open-with-picker` 先例：视图＋类型＋CSS；**不需要 Host**——消费方是设置插件自己，不是壳命令弹层）。
- **CSS 迁移改前缀**：现族段 `settings-assoc-*` 是宿主保留名形状（settings 页宿主族段），进共享件必须改 `ldk-famgr-*`（硬约束 23：`ldk-` 命名空间属宿主、共享件类名全局唯一）。
- **R6 零壳依赖**：`osFollowBlock` 现调 `lk().set` ＋ `useConfigurationValueIpc`——不进共享件；折叠块的开关值／写入回调 props 化（照 `gearItems` 注入式）。
- 单一权威：键名常量仍「壳 owner ＋ 插件 managerHint 各一份字面量」——维持现状（跨仓对账同 R5 思路，本案不加新账）。

### ⑤ 插件侧代码设计
- settings 改**薄消费**：`FileAssociationsManagerView` 变「组装 model ＋ 喂共享件」的薄壳；私有视图件与私有 CSS **整删**（⛔ 无死代码）。
- **留**在插件仓：`managerHint.ts`（认组判据——「设置渲染方如何解释 hint」是渲染方职责）、`filterGroups` 恒保留豁免、`navCount` 计数、齿轮命令（`FILE_ASSOC_GEAR_COMMANDS` 是 settings 自己的命令，菜单项照 `PluginCard` 的 `gearItems` 注入）。
- 单测随件迁移：视图契约（六态胶囊／props）进壳仓；组装／认组／豁免回归留 settings 仓。

### ⑥ 显示设计
- **视觉变化仅限拍板范围（C3＋C5，2026-10-06）**：两区（**多候选类型**／按插件浏览）视觉照母案 `mockups/08/09` 零变化；**OS 折叠块升二级子节**「系统「打开方式」登记」（C3c，D6 翻案）＋文案四件改判（区标题/「N 个候选」/副标题泛称版）＋**C5 面**：卡内工具条（声明 ≥8 类才出）与**行序默认字母序**（可切回「按默认排序」＝作者声明序）——动工前照设计 skill 复核改判面（硬约束 16）；出图基线见下条。
- **出图基线＝真件实例 ＋ 尺寸逐值（2026-10-06 用户判据：html 展示基本就是实机效果——比例/大小/尺寸/显示文字）**：① 已有共享件/图标照**真件实例**画（先例＝滑杆搬迁）：SelectBox／InlineInput／Toggle／Badge／真 codicon 字形／PluginIcon 两形态（img 铺满 cover ｜ span 走 lg），⛔ 不许手绘近似；② 尺寸字号**引真 token 与真规则**——字号 `src/index.css:72-77`（2xs11/xs12/sm13/md14/lg16/xl18）、圆角 4/6/8、`--hover-overlay .06`；页面骨架与设置行逐条照 settings 插件 `SettingsView.css` ＋ `SettingsView-rows.css`；配色锚 `src/index.css` :root 兜底暗色；③ 产品区**零手填 px 字号**。机械门：`node mockups/校验-拟真度.cjs`。
- **C5（2026-10-06 已拍）卡内工具条**：声明 ≥8 类的卡展开后，卡头与卡体之间一行——① **过滤框**＝共享件 `InlineInput`（`normal` 32px，与设置页左上「搜索设置」**同一支**；图标前置照插件仓 `settings-search-bar`；防抖用既有 hook `useDebouncedInput`）② **排序**＝共享件 `SelectBox`（trigger 值照 `select-box.css`；面板经 `OverlayPortal`，不被卡 `overflow:hidden` 裁——E37）＝「按字母序」（默认）／「按默认排序」（＝插件**声明原始次序**）。两件都是**既有共享件** ⇒ ⛔ 零新造控件；皮随主题（token 全走 `var(--*)`，硬约束 1 ＋ check-css-hardcode／token 审计／命名空间／R6 罩着）。
- 工具条槽＝`PluginCard` 加 `toolbar?: ReactNode`（**通用槽、零业务语义**——卡片不认识槽里装的是过滤框；阈值/过滤/行序全属组装方策略）；加性 API，⛔ 不改既有调用方。
- ⛔ **工具条不同行、绝不塞进卡头**（2026-10-06 用户复问「为什么不同行」后**确认保持**现形态）：卡头＝**铺满整头的真按钮** `button.ldk-plugin-card-toggle`（`plugin-card.css:43` 自带注释「嵌套按钮禁令的正解：齿轮是它的兄弟，不是孩子」）——把 `<input>`（InlineInput）与 SelectBox（真件触发也是 `<button>`）塞进去＝**按钮嵌套交互控件**：HTML 不合法，且点击/打字会被卡头开合吞掉。要同行只能做**兄弟**（照齿轮先例），代价四条：卡头失去整行点击区（`width:100%` 退成 flex 子项）＋绝对定位的齿轮得改位＋工具条控件在折叠态也得占位（管一个看不见的列表）＋副行与摘要（真件 `nowrap`＋省略号）被挤断。收益＝省一行 ≈44px 高，而今天够阈值（声明 ≥8）的只有编辑器 1 张卡（45 类）⇒ 不值。
- **过滤分档口径（2026-10-06 定，用户复问「输 c 为什么先出 .bat」）**：命中仍**两源**——**扩展名**（可省前导点、忽略大小写、子串）与**显示名**（类型名，同口径）。显示名匹配**删不得**（`python` 只靠它命中 `.py`），但**排后**：扩展名命中在上、仅显示名命中沉底，**选定的排序在各自档内继续生效**（⛔ 分档不改排序语义）；且仅显示名命中的行**把命中理由标出来**（行内 muted 小字「类型名 TypeScript」）——理由是「命中理由必须可见」，否则单字母查询里 `.bat`(Batch) 排头看着像乱排。
- ⚠️ `PluginCard` 转正同款先例照用。

### ⑦ 配置设计
- 键名／默认值全不变。配置面改动＝**C3c（原 C2a 并入）**：`app.osAssociations.followPlugins` 摘掉 `uiHint`＋声明 `group: t("系统「打开方式」登记")` ⇒ 任何渲染器按**通用布尔行**渲染；组判据只看挂载键。`app.osAssociations.overrides` **维持 hint**：v1 无界面是刻意决定，摘了 hint 反而让它落进 ObjectEditor 可编辑兜底＝新开写入面。
- 挂载键（`workbench.fileAssociations`）在未知渲染器的形态＝**C2b 定案（2026-10-06）：隐藏**（只读一行 `{}` 是垃圾信息，已落选）。
- **C5 ⛔ 不新增配置项**：卡内行序选择＝视图本地状态（默认字母序、不持久化）；⛔ 不塞进覆盖表键（语义污染）——要变成持久偏好＝新增壳声明配置项，另案。
- **声明序是既有数据、不是新读**（C5 的关键前提）：`DeclaredPlugin.exts` 注释明写「**声明序（插件自己的声明序，不是字典序——卡内行的顺序照它）**」（settings `model.ts:112`）；`extractDeclaredExtensions` 按清单数组序收（重复只留首次，`model.ts:88-102`）；`buildCards` 直接 `p.exts.map(...)` 不经排序（`model.ts:294`）⇒ 转正时**必须保序透传**：聚合纯函数 ⛔ 不得在内部重排卡内行，否则「按默认排序」不可恢复（排序只在渲染层按 mode 施加）。

## 五、核心理念对照（§二 十条）

直接服务：①归一化（同一份管理器呈现不再只在一家渲染方手里）②利于插件生态 ③低耦合高内聚 ⑤易拓展（「整组自定义视图」这一级从此有正典住址）。⚠️ 本档为设计前置；10 条全量逐维对照在设计审查（design-flow skill）阶段做，不符合项届时说明理由并记录。
