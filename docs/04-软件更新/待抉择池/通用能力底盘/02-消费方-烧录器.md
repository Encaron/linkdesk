# 消费方 · 烧录器（flasher）

> **本档身份**：04 主档 [通用能力底盘](00-提案.md) 的**消费方章节**。
> **为什么在这里**：自己零壳改动，但**交付必须等壳的受控进程能力** ⇒ 按 04/05 分档判据整案归 04。
> **来源**：01 工程外部 AI（「为了重启板子看启动日志，我走了完整烧录，20+ 秒」）。

## 一、它要壳给什么

受控进程（同 [轴一](00-提案.md)）：调 Keil `UV4` / ESP-IDF / PlatformIO / CMake，拿退出码与错误行。

## 二、下载方式靠"声明"，不靠猜

工程根放一份配置（首次由 UI 选一次，之后自动读）：

```json
{
  "version": 1,
  "toolchain": "keil",              // keil | esp-idf | platformio | cmake | custom
  "chip": "stm32h750",
  "build": { "cmd": "UV4", "args": ["-b", "app.uvprojx"] },
  "download": { "probeSerial": "…JLink 序列号…", "speed": 4000 }
}
```

- **STM32 用 Keil、ESP32 用 ESP-IDF** —— 写在配置里，⛔ 不猜芯片/不嗅探工程；
- **哪个工程对应哪种下载** —— 配置绑在工程根；
- **两块板怎么分** —— 主键是**调试器序列号**；串口侧只有 `{name, description}`（**无 VID/PID**，现状缺口），不作可靠依据。

## 三、命令面

| 命令 | 回执 |
|:--|:--|
| `flash.build` | `{ok, exitCode, tookMs, errors[], logPath}` |
| `flash.download` | `{ok, exitCode, tookMs, bytes, logPath}` |
| `flash.reset` | `{ok, method, tookMs}` |

- `errors[]` 是**解析出来的**编译错误（文件:行:信息），不是原始日志；
- 原始日志落文件，回执只给路径（省上下文）。

## 四、边界

- ⛔ 不内置任何厂商工具链（用户机器提供，插件只调用）；
- ⛔ 不自动嗅探工程类型（宁可报错，也不烧错板）；
- ⛔ 不碰串口插件；烧录与读串口可同时进行；
- 卸载即消失，壳零改动。

## 五、验收

1. 两个不同工程（Keil / ESP-IDF）各绑一次配置，**命令不串**（烧错板 = 严重失败）；
2. 拔掉探针/板子 → 明确报错，⛔ 不挂起；
3. 编译失败 → `errors[]` 定位到文件与行；
4. 卸载 → 壳无残留。
