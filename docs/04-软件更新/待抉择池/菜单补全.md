## 任务详情

### 1. 顶栏菜单渲染（~80 行）

对标 VS Code 的顶栏：`File | Edit | Selection | View | Go | Run | Terminal | Help`。

LinkDesk 精简版（嵌入式场景，不需要 VS Code 那么多）：

```
LinkDesk | 文件 | 编辑 | 视图 | 插件 | 帮助
```

```typescript
// src/components/TitleBar.tsx —— 壳级组件

interface MenuBarItem {
  id: string;
  label: string;
  submenu: MenuItem[];  // 复用已有的 MenuItem 类型
}

// 从 MenuRegistry 动态聚合
// 插件注册了 contributes.menus["title-bar/file"] → 自动出现在"文件"菜单下
```

**渲染方式：** 壳自己的顶栏区域（不是 Electron 原生菜单——先做 HTML/CSS 版本，Electron 原生菜单是第二步）。

### 2. Electron 原生菜单（~50 行）

对标 VS Code 的 `Menu.setApplicationMenu()`。Windows/Linux 在窗口顶部渲染，macOS 在屏幕顶部。

```typescript
// electron/menu-bridge.ts

import { Menu } from "electron";

// 从 MenuRegistry 读取所有注册到 "title-bar/*" 的菜单项
// 构建 Electron Menu 模板
// 点击 → executeCommand(menuItem.command)
function buildNativeMenu(): Electron.Menu {
  const fileMenu = getMenuItems("title-bar/file");
  // → { label: "文件", submenu: [ ... ] }
  return Menu.buildFromTemplate([fileMenu, editMenu, viewMenu, pluginsMenu, helpMenu]);
}
```

**双轨策略：**
- 开发阶段 / 自定义标题栏模式 → HTML/CSS 顶栏菜单（任务 1）
- 原生标题栏模式 → Electron 原生菜单（任务 2）
- macOS 特殊处理：`app.applicationMenu` 在 `app.on('ready')` 中设置

### 3. 菜单贡献点标准化（~40 行）

当前 `MenuId` 定义了 12 个 menuId，但插件贡献的 `location` 字段没有规范——插件开发者不知道怎么把自己的菜单项挂到顶栏。

**标准化贡献点：**

| location | 出现位置 | 谁注册 |
|------|------|------|
| `title-bar/file` | 文件菜单 | 壳级命令 + 插件贡献 |
| `title-bar/edit` | 编辑菜单 | 同上 |
| `title-bar/view` | 视图菜单 | 同上 |
| `title-bar/plugins` | 插件菜单 | 仅插件贡献（动态聚合） |
| `title-bar/help` | 帮助菜单 | 壳级命令 |
| `icon-bar/gear` | 图标栏齿轮菜单 | 已有 |
| `tab/context` | 标签页右键 | 已有 |
| `sidebar/context` | 侧栏条目右键 | 已有 |
| `editor/context` | 编辑器右键 | 🆕 新增 |
| `explorer/context` | 文件树右键 | 🆕 新增 |

```json
// 插件 plugin.json 示例
{
  "contributes": {
    "menus": {
      "title-bar/file": [
        { "command": "my-plugin.export", "group": "1_save" }
      ],
      "explorer/context": [
        { "command": "my-plugin.analyze", "when": "explorerResourceExt == .json", "group": "3_analyze" }
      ]
    }
  }
}
```

对标 VS Code 的 `contributes.menus` 分组机制——`group` 字段控制排序（`1_xxx` / `2_xxx` / `navigation`）。

### 4. 右键菜单全覆盖（~30 行）

当前 LinkDesk 部分区域仍是浏览器默认右键菜单（审查元素/复制/粘贴），对标 VS Code 应该是全应用统一右键菜单。

| 主区空白处 | 浏览器默认 🔴 | `editor/context` 贡献点 |
| 状态栏 | 点击行为（无右键）🟡 | 右键→状态栏设置 |

## 为什么是壳级不是插件

和 CommandPalette 同理。菜单系统是壳的基础设施——卸载所有插件后，文件/编辑/视图/帮助仍需要存在。插件只是往里加东西。
