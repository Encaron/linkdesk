## 二、缺失的"治本化"改造

以下问题在 22 篇里是治标处理，但有治本方案——没写。

### 2.1 间距：从 grep 扫描 → `--space-*` token

**现方案：** `UI合规/间距与动画.md`——grep 扫描、逐处改 10/14px。

**治本方案：**

```css
:root {
  --space-xs: 4px;
  --space-sm: 8px;
  --space-md: 12px;
  --space-lg: 16px;
  --space-xl: 20px;
  --space-2xl: 24px;
  --space-3xl: 32px;
}
```

然后 ESLint 可以写一个 `no-raw-px-spacing` 规则——拦截不在 `{4,8,12,16,20,24,32}` 的 `padding`/`margin`/`gap` px 值（排除 `font-size`）。对标 `var(--z-*)` 的归一化。

### 2.2 未知文件类型：从两处 toast → FileAssociationService 返回状态

**现方案：** `功能补全/未知文件类型零反馈.md`——在 `FoldersView.tsx` 两处加 toast。

**治本方案：** `file-tree` 的 `getPluginFor()` 已经返回 `undefined` 表示未知类型。应该在 `linkdesk.tabs.create` 内部处理——如果创建标签页时发现没有注册编辑器，由壳统一弹 toast。插件不关心 toast——壳管。

```typescript
// 壳的 tabs.create handler（IpcBridgeHandler）
case "tabs:create": {
  const plugin = getViewPlugin(pluginId);
  if (!plugin) {
    // 🔥 壳统一处理——不论哪个插件调 tabs.create
    dialog.alert(`没有为 .${ext} 注册编辑器`);
    return;
  }
  // ...
}
```

这样 `FoldersView`、`SearchView`、未来任何调 `tabs.create` 的代码都自动受益——**和 E5#38 ErrorService 同类：改一处覆盖全调用方。**

### 2.3 PluginId 硬编码：从注释 → 声明式 IPC 通道

**现方案：** `架构债/壳硬编码PluginId清理.md`——加 `@deprecated` 注释。

**治本方案：** 多 WebView 恢复时，不在 `MainContent.tsx` 里 `if (pluginId === "editor")`。而是在 `plugin.json` 声明需要的 IPC 通道：

```json
// editor/plugin.json
{
  "ipcChannels": {
    "receive": ["openFile", "revealRequested"],
    "send": ["file:changed"]
  }
}
```

壳读声明而非 switch pluginId。对标 VS Code 的 `activationEvents`——"这个插件需要哪些 IPC 通道"由插件声明，壳不判断你是谁。
