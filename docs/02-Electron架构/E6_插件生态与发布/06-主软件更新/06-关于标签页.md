## 二、现实约束：壳 DialogService 真实能力（实锤）

对标前先摸壳现状——**壳 DialogService 只支持「标题 + 一段文字 + 确认/取消按钮」**：

- `DialogService.confirm(options: {title, message, confirmLabel?, cancelLabel?, type?}): Promise<boolean>`（[DialogService.ts:71](../../../../src/core/services/ui/DialogService.ts#L71)）
- `DialogService.alert(...)` / `showQuickPick(...)` / `showInputBox(...)`（[DialogService.ts:85-108](../../../../src/core/services/ui/DialogService.ts#L85-L108)）
- 渲染端 DialogHost：`title` + `message`（`<p>`）+ `confirmLabel`/`cancelLabel` 两个按钮（[DialogHost.tsx:129-140](../../../../src/pool/floating/dialog/DialogHost.tsx#L129-L140)）

**结论：现有 DialogService 画不出「字段逐行 + Logo + 复制按钮」的关于框。** 强行用 `alert()` = message 塞多行文本 + 只有「确定」——复制功能直接砍掉。**这是 06 的载体决策点，不是已定项。**

## 三、载体方案（已拍板：A 标签页——2026-08-30 用户拍板）

| 方案 | 形态 | 能力 | 代价 |
|:--|:--|:--|:--|
| **✅ A 壳内标签页**（已拍板） | 关于 = 标签页（同发行说明载体） | Logo/字段表格/复制按钮/**「检查更新」快捷按钮** 全可做，真实 React 视图 | 非模态（可接受：发行说明已是标签页先例） |
| B DialogService alert() 降级 | 弹窗，message 塞多行字段文本 + 「确定」 | 唯一按钮，**无复制**、无 Logo、无交互字段 | 砍复制功能，偏离 VS Code |
| C 扩展 DialogService 富内容 | 弹窗 + 自定义内容渲染器 | 全功能模态 | **新壳能力**——要走新能力设计前置 8 维度，本次不搭车 |

**拍板依据（A 胜出）**：
1. **标签页 = 通用表面容器**（memory `tab-universal-surface-container`）——「任何插件加新表达形式 = 加一个标签页，不设计新宿主」，发行说明已同款，两处一致。
2. **基于现实**：A 是唯一用现有壳能力（标签页引擎）就能承载全部字段 + 复制的方案；B 砍功能；C 新造能力。
3. 附赠：关于标签页可放「检查更新」按钮——关于 + 检查更新闭环同页（对标手机「设置→关于本机→软件更新」心智）。

> **2026-08-30 已拍板选 A**——本档 §四 布局即实现稿（对应 00-README 待拍板点②，已划勾）。

> **字段可扩展**：`Product`/`ProductRuntime`（02 §2.2）是开放结构——未来加字段 = **壳侧 `useAbout` 数组加一项 + `PoolAboutField` 无需改动**，池侧一个字都不改，零架构改动。**纯增量。**

> 🔴 **数据通道（E6#57.14 落地时订正）**：原文写「AboutView mount → `invoke(app:getProductInfo)`」——**那句作废**，它当初就是这么写的，但按下去会**当场撞墙**：`app:getProductInfo` 是**壳内私有扩展**，`electron/preload-pool/namespaces-data.ts` 明文**池侧不暴露**（E6#27：池侧与契约零漂移）⇒ 池**根本调不到**。正解是既有规矩（同 `#57.13` 发行说明，**壳想、池画**）：
>
> | 环节 | 谁做 | 走什么 |
> |:--|:--|:--|
> | 取数 | **壳** `useAbout` | `getShellExposed().app.getProductInfo()`（→ 主进程 `IPC.app.getProductInfo`） |
> | 组装 DTO | **壳** `buildAboutData` | 八行「`t()` 过的标签 + 值」→ 挂 `PoolTab.about` 推到池 |
> | 绘制 | **池** `AboutView` | 只 `data.fields.map(...)`，自己只 `t()` 两个按钮 |
> | 「检查更新…」 | 池 → 命令 | `executePoolCommand("update.checkForUpdates")`（**既有命令的第四个入口**，命令源唯一） |
> | 「复制」 | 池 → 命令 → 壳 | `executePoolCommand("app.aboutCopy")` → 壳 `ClipboardService` + 通知面「已复制」 |
>
> 壳内部走 IPC 通道，**不走 `window.linkdesk.*` 契约**——那是给第三方插件的（第三方读版本号走 `app.getVersion()`，00 README §三②）。壳侧消费私有面须经 `getShellExposed()` 转型（`surfaces.ts` 是唯一转型点），否则「运行时调得到、tsc 说没有」。

### 4.3 两个动作按钮

- **复制**：全字段纯文本（`key: value` 每行一个，`\n` 连接，UTF-8）→ 剪贴板 → 通知面条目「已复制」（壳共享通知面，⚠️ 旧文写「toast」= 已删的右下小卡，见 [04 §〇](04-更新通知与交互.md)）。对标 VS Code，直接可贴进 issue。
- **检查更新…**：调 `update.checkForUpdates` 命令 → 结果落**通知面**（有更新 → 发现更新条目，[mockup 02](mockups/02-更新通知与关于.html) Frame 1；最新 → 「当前已是最新版本」Frame 4；**失败 → Frame 5，带归因文案 + `[重试]`**）。手机「设置→关于本机→软件更新」心智。

### 4.4 与产品三件套的关系

- 关于标签页 = 身份字段的**只读展示面**；唯一真相源 = product.json（02）。
- 没有 product.json（dev 裸跑）→ commit/date 降级显示 `—`（不崩，保底设计）。

### 4.6 落地注记（E6#57.14 实现时记，逐条有据）

**① 品牌标 = 真资产，不是 mockup 里手画的方块。** mockup Frame 6 的 `.about-logo` 手画了一个「圆角蓝方块 + 白方块」（纯示意）。实现改用**真资产** `public/assets/logo.svg`：壳 `getAssetPath("assets/logo.svg")` 解析后经 `PoolAboutData.logoUrl` 推到池，池画 `<img>`。三个理由：**(a)** 那个文件自己的头注写着「替换此文件即可更换 logo，无需改代码」——手画一个方块会让那句话对本页变成假话；**(b)** 否则同一个软件里出现两个互相矛盾的「LinkDesk 标志」（标题栏一个、关于页一个）；**(c)** 硬约束 12：资产路径一律 `getAssetPath`，池不 import core。→ **品牌标全仓只有一个文件、一处规则。**

**② 版本号取纯 `app.getVersion()`，不带 mockup 的 `(user setup)` 后缀**（2026-09-13 用户拍板）。mockup 那串是安装器语境下的完整显示名，本页要的是版本号本身；`electron/product.ts` 的 `version` 字段本就恒取 `app.getVersion()`，无需改动。

**③ 取整全部是门禁逼的**（同 `ReleaseNotesPoolView.css` 的记账法）：间距网格把 `padding: 22px 32px`→`24px 32px`、`gap: 14px`→`16px`、`gap: 10px`→`12px`、`padding: 4px 14px`→`0 16px`；字号阶梯把 `16/12.5/11.5/12px` 落 `--font-size-lg/xs/2xs`；零硬编码色把 mockup 的 `#0078D4`→`var(--accent)`、`#fff`→`var(--text-on-accent)`。

**④ 两处内容层取舍**：hover 反馈用 `background: var(--hover-overlay)`（与兄弟视图 `.rn-btn:hover` 一致；mockup 那条 `border-color` 对主按钮也生效，会把 accent 描边变灰边）；正文外多包一层 `.about-inner` 承载 `max-width: 420px`，使栏宽确定、不随最长值浮动。

**⑤ 加载态无 mockup 帧**：`loading` 画与 Frame 6 同形的骨架（不跳位），一帧过渡；**不做 shimmer 动效**（本机 IPC 通常不足一帧）。
