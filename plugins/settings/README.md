# 设置

LinkDesk 自己的「设置」——外观、字体、语言、快捷键、插件管理都在这一个面板里调。

> 它自己也是一个插件。这不是巧合：如果连「设置」都是软件里可拆、可换、可贡献的一部分，那才是真的万物皆插件。

## 这是什么

LinkDesk 的控制面板（出厂自带，图标栏底部的齿轮 / 快捷键 `Ctrl+,`）。对标 VS Code 的设置体验：**你不需要记住每个配置项长在哪，搜索就好。**

- 插件 ID：`settings`
- 打开方式：图标栏最下齿轮 · `Ctrl+,` · 命令面板「打开设置」
- 标签页行为：单例（只有一个设置页）

## 界面三块

1. **搜索框**——输入即过滤，`主题` 打下去，所有含主题的设置项浮上来
2. **左侧分组导航**——把设置项按来源分节（外观、字体、快捷键…），点了直接跳到那组
3. **右侧设置行列表**——每行 **名字在左、控件在右**；顶部还能切到「键盘快捷键」页，搜到某条命令直接改它的快捷键

## 调设置 = 拨这些控件

开关、下拉、分段单选、滑杆、数字框、色板、字体下拉、文件路径、主题卡片——它们都来自 LinkDesk 的共享控件库，不是设置插件私造的。行尾偶尔有徽标：

- ✏️ **你手动改过**（和默认不一样了）
- 🎨 **跟随主题**（值来自当前主题，不是手设的）

## 一个有意思的设计

设置插件**自己不知道有哪些设置项**——所有条目从 LinkDesk 的配置注册表里「长」出来。任何插件都能在 `plugin.json` 里贡献自己的设置组，打开设置它就会自动出现，第三方配置一行行平铺进来、零侵入。

有些能力（比如「主题」）有好几家的候选实现，设置里会出现**切换条**——选哪家当默认，即时生效。

## 结构

```
src/index.tsx                        入口（直出 SettingsView）
src/views/SettingsView.tsx           设置主视图（搜索 + 分组 + 行）
src/views/SettingsView/renderControl.tsx  设置控件分发（→ 共享控件库）
src/views/keybinding-settings/       键盘快捷键设置视图
plugin.json                          声明（iconBar / tabBar / auxiliarybar 三处可驻）
```
