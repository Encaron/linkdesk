## 🔴 致命陷阱——每个 AI 进场必读

### 陷阱 1：E5#14 删除旧字段——顺序不可颠倒

```
正确顺序：
  1. E5#14e-g：先给 4 个官方插件 plugin.json 补 appearsIn 声明
  2. E5#14d：再删除 iconLocation/viewRole/keepSidebarOnFocus 字段

错误顺序 → 图标栏全白
```

### 陷阱 2：E5#12 删函数——checkpoint 不过不删

```
E5#27d loader.test.ts 5 条必须全绿后才删 loadThemePlugin + loadLanguagePlugin。
这 5 条验证：
  - 声明式语言插件 (contributes.languages) → parseContributions 正确注册
  - 声明式主题插件 (contributes.themes) → parseContributions 正确注册
  - 视图插件 (entry + viewsContainers) → 加载 React 组件
  - 数据插件 (纯 langDefs, 无 entry) → 不加载组件但 langDefs 生效
  - 混合插件 (entry + contributes.themes) → 视图+主题均生效
```

### 陷阱 3：E5#42 50 文件移动——Vite 缓存

```
移动文件后必须：rm -rf node_modules/.vite
不删 → Vite 缓存旧 import 路径 → 路径改对也白屏。tsc 抓不到这个。
```

### 陷阱 4：E5#40 keep-alive——验证 F12 跳转

```
display:none → opacity:0 后必须手动测试：
  - F12 跳转到同文件 → 光标正确
  - F12 跳转到跨文件 → 新标签页打开 → 光标正确
  - F12 跳转到已打开的隐藏 tab → 切过去 → 光标正确（之前这里必炸）
  - Ctrl+Click 跳转——同 F12
```

### 陷阱 5：E5#10 Fallback 退役——时序竞态

```
WebView ready 信号和 bounds 设置之间存在 gap。
必须等 plugin-view:ready → 设完 bounds → 再关 React fallback。
加 5s 超时兜底——WebView 5s 未 ready → 回退到 React fallback + console.warn。
```

### 陷阱 6：npm run check 每步必跑

```
tsc + ESLint + vitest。一个命令。
ESLint error 必须在提交前清零——warnings 可以留。
vitest ShellEvents.test.ts 10 条必须在 E5#2b 后全绿。
```
