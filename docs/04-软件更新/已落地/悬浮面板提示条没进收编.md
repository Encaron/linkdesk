# 已落地 · 悬浮面板的 □ ✕ 提示没进收编（第三套机制：CSS `content: attr()`）

> **已落地（2026-09-27 用户实机挑出 → 当日查清 → 当日收编 ＋ 补门禁腿 3；✅ **已发版 v0.2.21**〔2026-10-04 销账订正：`git tag --contains 16533bbf1`〕）。
> **用户原话**：「为什么 hint-tip，在悬浮面板中显示的'-▭×'的这几个 hint-tip，就是没有气泡，大小也是偏小一点的？难道是旧版的吗？难道是没有覆盖全吗？难道是有两套吗？这个可是在 dev 版呀」。
> **三问的答案：不是旧版 · 是没覆盖全 · 是有两套。**
> **归属**：软件本体（池层哑渲染器 ＋ 壳侧门禁）——不涉任何插件仓、不涉 SDK、不涉配置。

## 零、先把「不是旧版」钉死（免得后人往缓存方向查）

| 检查 | 结论 |
|:--|:--|
| dev 下主窗与悬浮面板是不是两套产物 | ❌ 不是——两者都是池窗，`electron/windows/window-manager.ts:220` 在 `!app.isPackaged` 时一律 `loadURL(\`${DEV_SERVER_URL}/pool.html\`)`，prod 才 `loadFile(dist/pool.html)`。**同一份代码、同一份 CSS、无 dist 分流** |
| 悬浮面板是不是另一套外壳（有自己的壳文档） | ❌ 不是——`FloatingPanelHost` 由 `src/pool/zones/floating-layer/FloatingLayerHost.tsx:82` 挂在**池文档**里，与主窗池 view 同一个文档类型（脱出/悬浮窗**没有自己的壳**，壳=唯一真相源） |
| 是不是提示条 CSS 没加载 | ❌ 不是——池文档里 `HintTipRenderer` 在（`PoolZoneShell.tsx:135`），委托监听在 document 上，**真出条**；只是那两颗按钮压根没走它 |

## 一、根因：判据只认**写法**，不认**机制**

现象来源就两处：

```tsx
// src/pool/floating/floating-panel/FloatingPanelHost.tsx（改前）
className={actionClass}          // toggledIcon → "… tip" / 其余 → "… tip close"
data-tip={currentLabel}
```

```css
/* src/pool/floating/floating-panel/FloatingPanel.css:164-183（改前） */
.ldk-floating-panel-act.tip::after {
  content: attr(data-tip);
  position: absolute; top: calc(100% + 6px); right: 0;
  font-size: var(--font-size-xs);   /* 12px */
  padding: 3px 8px;
  ...
}
```

这是一个**纯 CSS 伪元素方框**，于是用户看到的每一点都能对上：

| | 悬浮面板（改前） | HintTip |
|:--|:--|:--|
| 气泡尖角 | **无**（它就是方框） | 有（`[data-tip-placement]` 四条规则） |
| 字号 / 内边距 | `--font-size-xs` 12px / 3×8 | `--font-size-sm` 13px / 5×12（用户拍板的中号） |
| 底色 / 边 | `--bg-input` / `--separator` | `--bg-card` / `--border` ＋ `box-shadow` |
| 延时 / 翻面 / 夹紧 / 键帽 | 全无（`::after` 做不到） | 全有 |

**为什么收编时漏了它（本节是本档的重点）**：

- 腿 1 `check-native-title.mjs` 判的是 **JSX 小写标签上的 `title=` 新增**；
- 腿 2 `scripts/native-title-baseline.json` 记的是 **`title=` 的存量**（壳侧 43 处 ＋ 夹具 5 处）。

两条腿的判据物都是「**`title=` 这个写法**」。这一处**从来没用过 `title=`**——它用 CSS `content: attr(data-tip)`。于是：账清到 0、腿 1 全绿、收编看起来「全覆盖」，**提示面仍漏着整套**。

🔴 教训一句话：**判据物必须覆盖到「机制」，不能只覆盖到「写法」。** 清账 ≠ 清面。

⚠️ 同一句话的另一半：全仓 `content: attr(` 只有这一处（其余 `content` 全是 `""`/`''` 装饰，非空字符串实得 0 处）⇒ **这是一处真漏网，不是普遍塌方**；面板的另外两颗按钮里，`open-in`（«在主窗口中打开»）走的是 hover 就地展开全文（`.lbl`），那是**另一种交互**、不是提示条，本次**不动**。

## 二、改法（3 处）

| # | 改什么 | 位置 |
|:--:|:--|:--|
| 1 | `data-tip={currentLabel}` → `{...{ [HINT_ATTR]: currentLabel }}`——属性名走 `hintAttrs.ts` 单一真相源（⛔ 不写字面量） | `FloatingPanelHost.tsx` |
| 2 | 类名去掉只服务 CSS 提示的 `tip`（`… tip`→`…`、`… tip close`→`… close`——`close` 那条 hover 红底照旧保留） | 同文件 `actionClass` |
| 3 | 删 `.ldk-floating-panel-act.tip::after` 整段 ＋ `:hover::after`，并删 `.act` 上**只服务它**的 `position: relative`；原地留一段注释说明去向与不许回退 | `FloatingPanel.css` |

**为什么换得过来（层级核对，先说清）**：提示条 portal 到 `#overlay-root`（`Z_INDEX.overlayRoot` = 2000），悬浮面板本身是 `Z_INDEX.floatingPanel` = 1500，且 `#overlay-root` 在 `#ld-float-layer` 内**最后渲染** ⇒ 条在面板之上，不会被"面板盖掉自己的提示"。这也是这类 CSS 提示当初可能被采用的理由，**现在不成立**。

**为什么 `open-in` 不一起收**：它 hover 时是**就地展开文案**（宽度动画 ＋ `.lbl` 淡入），文案本来就是可见的，再叠一条提示反而是同一句话两处显示。留作另一种交互（设计原文 mockup 帧 1 即如此）。

## 三、门禁腿 3：`scripts/check-css-tooltip.mjs`

- **判据（一条）**：域内任何 `content: attr(<名>)` 判红。理由三条：① 长相不可控（不跟主题/字号缩放）；② 文案第二份（TSX 写一遍、CSS 再取一遍）；③ 无延时/翻面/夹紧/尖角/键帽。
- **正解写在报错里**：挂 `data-hint`（走 `HINT_ATTR`），要快捷键用 `data-hint-command`。
- **豁免口**：命中行上一行或同行写 `eslint-disable-next-line/-line linkdesk/no-css-tooltip -- 理由`，**理由必填**（CSS 里没有 eslint 在跑，这个形状只为全仓「豁免长什么样」只有一种）。
- 🔴 **⛔ 不设白名单账**（与腿 2 的有意差异）：腿 2 有账是因为落地当天存量 43 处；本腿**开盘即 0 处**，只判新增。别为「以后可能多」先建账——空账会腐烂成假门禁。
- **自测 13 例**（正控 5 / 负控 4 / 豁免 3 ＋ 选择器回填）：含「注释掉的不判」「非 `content` 属性上的 `attr()` 不判」「缺理由报红」「行号 1-based 按原文件对齐」。已按 `--self-test` ＋ 实跑两步挂进 `npm run check`（满足 `check-gate-health` 的 A①/A②）。
- **残余风险（诚实边界）**：① 文本级判据（不引 CSS 解析器，同其余腿）——`content` 与 `attr(` 之间塞注释/折行会漏；② 域 = 本仓 `src/` ＋ `plugins/` 的 `.css`（插件仓 `E:/linkdesk-plugins` 不在域内，那侧由 SDK 腿管）；③ CSS 里**写死的非空字符串**（`content: "关闭"`）同样不是 HintTip，但**不在域内**——本仓实得 0 处，出现时另立一件，⛔ 别顺手塞进本腿扩大射程。

dev 手测（悬浮面板 = 某视图右键「在悬浮面板中打开」）：

2. 最大化后同一颗按钮 → 提示文案跟着变（壳推的 `toggledLabel`「还原」，池只渲染 DTO，未变）。

4. 主窗标题栏 ─ ▭ ✕ 的提示**无变化**（本次没碰 `TitleBarZone`）。

## 五、边界与遗留

- `.tip` 类名全仓已无引用（唯一使用处即本处），已随之删除；`FloatingPanelHost.test.tsx` 未断言 `data-tip`，改动不破测试。
- 同一天同一面（**提示面**）的另一处漏网另档：[标签 tooltip 印内部 id](标签tooltip印内部id.md)——机制不同（那件是「功能键被当文案」，本件是「第二套渲染器」），但两件的教训同源：**收编要按机制清点，不按写法清点**。
- 若日后真出现必须用 CSS 造提示的形态：写**豁免注释＋理由**（逐条），不要开新账、不要在腿 3 里加白名单。
