### 7.1 (丁) 的做法（核心改动）

```
注册前：  const existing = i18n.getResourceBundle(langCode, "translation") ?? {};
          const incoming = Object.keys(data);
          const hits = incoming.filter(k => Object.hasOwn(existing, k));
命中即：  console.warn(`[i18n] 键 "${k}" 被 ${pluginId} 覆盖（已有同键，来源未知）`);
之后：    i18n.addResourceBundle(langCode, ns, data, true, true);   ← 两行保持原样
```

⚠️ **措辞纪律（1.39 裁决）**：**只说「X 覆盖了已存在的键 K」，不宣称「K 属于 Y」**。
理由：`_pluginI18nData` 是 `Map` 插入序，**本函数报不出「原本属于谁」**（详见 [09 §10.1](09-任务-i18n与黄灯族评估.md) 的边界登记）。**说做不到的事 = 假话。**

## 九、作者面两棵树（**1.39 已备草稿，落点 = §3.9 一带**）

**建议落点**：`03-contributes-spec.md` 的 **§3.9**（`contributes.languages` + `contributes.i18n`，该处已有「两条翻译管道」对照表）后追加一小段。

**草稿要点（中英各一份，双语对齐门禁守）**：

1. **建议**：给自己的键起**带归属**的名字，如 `<pluginId>.<原名>`（`serial-monitor.openPort`）——🔴 **但这不是强制**。
2. 🔴 **为什么不是强制（必须写明，否则建议会被读成规则）**：i18n 键**可以合法住在应用级字典**——官方 `settings` 插件的 **254** 个 `t()` 调用**一个键都不在自己仓**（全在 `lang-defaults` 的 525 键里）。⇒ **插件仓里判不出「你的键撞了别人」**，判了必出假红。
3. **今天真实存在的重合**（**如实告诉作者，不夸大**）：官方插件键与 `lang-defaults` 已有 **65** 条重合；其中 **3** 条译文已不一致（`命令` → `Command` / `Commands`）。
4. ⚠️ **运行时行为**（本格落地后）：键被覆盖时宿主会 `console.warn` **出声点名双方**——**它是提示，不是拦截**（值照常写入）。
5. 🔴 **不加前缀的合法情形**：`.py` / `.ts` 这类**扩展名** · `zh` / `en` 这类**语言码** —— **它们不是"没主"，是"本就不该有主"**，加前缀 = 语义错误。

⚠️ **改这两棵树必须同笔跑 `npm run docs:build`**（`docs:check` 与真源逐字节比对，挂 `check`）。
⚠️ **`docs/03-插件制造/` 与 `packages/plugin-docs/docs/zh/` 是同一份内容的两个落点**——1.38 的先例（见 `git show 4f0a6c49c --name-only`）是**四处同改**：`docs/03-插件制造/X` ＋ `packages/plugin-docs/docs/zh/X` ＋ `docs/03-plugin-authoring/X` ＋ `packages/plugin-docs/docs/X`。
