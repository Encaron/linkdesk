## 二、区域速查表

| 区域 | 你怎么进去（声明） | 放什么 | 用户怎么看到它 |
|:--|:--|:--|:--|
| **⑤ 图标栏** | `appearsIn.iconBar`（`"top"` / `"bottom"`）**＋** 要么有 `entry`，要么有一个 **sidebar** 容器 | 一个图标按钮 | 图标出现在最左 42px 竖条，点了切换侧栏容器 |
| **③ 侧栏** | `contributes.viewsContainers` 里 `location: "sidebar"`（默认值）＋ `contributes.views` 挂视图 | 可折叠的 section（每个视图一个） | 点图标栏切过来；多个插件可往同一个容器里加视图 |
| **⑥ 主区** | `entry` ＋ `appearsIn.tabBar: true` | 一个标签页的内容 | 图标栏点一下／`[＋]` 新建菜单里选；可多开、可分屏 |
| **底部面板** | `contributes.viewsContainers` 里 `location: "panel"` ＋ 视图 | 标签栏切换的多个面板视图 | `Ctrl+J` 展开；代码里 `window.linkdesk.panel.reveal(viewId)` 聚焦 |
| **⑦ 状态栏** | 顶层 `statusBar: [...]` 数组（**不是** `contributes.statusBar`） | 一行文字 / 图标 / 可点的条目 | 常在底部；`align` 决定左右 |
| **① 标题栏** | `contributes.titleBar.right[]` / `.left[]` | 图标按钮或纯文字按钮 | 窗口最上一行右侧 |
| **浮层** | `contributes.floatingPanel`（把某个已声明视图声明成"可在悬浮面板打开"） | 你已有的某个视图 | 标签页右键「在悬浮面板中打开」 |
| **视图动作区** | `contributes.views[].titleActions[]` | `icon` / `dropdown` / `split` 三种小控件 | 侧栏 section 折叠头右侧、面板标签栏右侧 |

### 两个"进不去"的地方

| 想放哪 | 实况 |
|:--|:--|
| **右侧栏**（`location: "auxiliarybar"`） | ⚠️ **壳当前未接线**——声明了也不渲染，是 dormant 区域。第三方要用侧栏请用 `"sidebar"` |
| **顶栏**（旧 TopBar） | 已在早期版本移除。`contributes.titleBar` 这个名字保留，但槽位落在**① 标题栏**，不是老"顶栏" |

## 三、最容易搞混的几件事

### ① 图标栏 ≠ 标签页：两种插件形态

一个插件想被看见，有**两条路**，别混：

| 形态 | 需要什么 | 结果 |
|:--|:--|:--|
| **有 `entry`** | `entry` ＋ `appearsIn.iconBar` | 图标＋可当标签页打开（经典形态） |
| **entryless**（侧栏专用） | **不写 `entry`**，只要有 sidebar 容器 ＋ `appearsIn.iconBar` | 只有图标＋侧栏，**永远不是标签页** |

> **entryless 是侧栏专用插件的推荐路径**——不用为了"凑一个图标"去写一个空的 `src/index.tsx`。
> 反过来：`appearsIn.tabBar: true` **必须**配合 `entry`（标签页靠 entry 组件渲染）。

**不同声明组合下，点图标栏图标实际会发生什么**（壳里有两个消费者各自独立响应同一次点击——一个管开标签页，一个管切侧栏）：

| 声明 | 点图标之后 |
|:--|:--|
| `entry` ＋ `appearsIn: { iconBar: "top", tabBar: true }` | **直接开（或聚焦）标签页**——经典形态，无需额外声明 |
| `entry` ＋ `appearsIn: { iconBar: "top" }`——无 `tabBar`、也无侧栏容器 | **什么都不发生**——图标纯展示。只声明 `iconBar` 图标不会开标签页，要开得加 `tabBar: true` |
| 无 `entry` ＋ 侧栏容器 ＋ `appearsIn: { iconBar: "top" }` | **切到你的侧栏容器**；再点同一个图标 = 折叠/展开侧栏——entryless 永不开标签页 |
| `entry` ＋ `tabBar: true` ＋ 侧栏容器 | 切侧栏总会发生；标签页**只在未声明 `appearsIn.sidePanel` 时才开**——声明 `sidePanel: true` 可让点击只切侧栏 |
| 顶层 `statusBar[]` | 根本不经过图标栏——条目直接渲染在状态栏，点击跑条目自己的 `onClick` 命令 |

**拿不到图标的三种情况**（都不是 bug，是设计）：
- 不声明 `appearsIn.iconBar`（**opt-in**——不写就没有图标）
- 数据插件（语言包 / 主题 / 图标主题这类没有侧栏容器的）
- 只有 panel / auxiliarybar 容器——图标栏的语义是"打开侧栏容器"，底部面板不算

### ② 侧栏容器 ≠ 标签页

侧栏里是**容器 → 视图**两层：容器是"频道"（点图标栏切换），视图是容器里一个个**可折叠 section**。
**别的插件可以往你的容器里加视图，你的插件也可以往别人的容器里加视图**——容器主人不知道也不关心。

```jsonc
// 往别人的容器里加一个 section：只写 contributes.views，不写 viewsContainers
{ "contributes": { "views": { "explorer": [ { "id": "timeline", "title": "TIMELINE", "render": "src/views/TimelineView.tsx", "order": 100 } ] } } }
```

### ③ 视图组件不要自己包 `SidebarSection`

壳用 `PoolSectionStack` 渲染时**自动**给你的组件包上折叠头。你返回**内容**就行，包了就是双层折叠头。

### ④ 三张图三种职责：`icon` / `marketIcon` / `cover`

| 图 | 出现在哪 | 最容易咬人的那条规则 |
|:--|:--|:--|
| `icon` | 图标栏 / 标签栏 / `[＋]` 菜单 / 欢迎页 | **图标栏会强制单色染色**——要画单色线稿剪影，放彩色图会糊成一团 |
| `marketIcon` | 市场列表行 ＋ 详情页头部 | 彩色身份图；不声明则市场回落用 `icon` |
| `cover` | 只住 README 说明区 | 不是 manifest 字段——文件放 `resources/`，从 `README.md` 里引用 |

完整规则 → [06-plugin.json规范 §marketIcon](06-plugin.json规范.md) · [12-README说明区媒体契约](12-README说明区媒体契约.md)。

## 四、每个区域的最小声明片段

### ⑤ 图标栏 ＋ ⑥ 主区（经典标签页插件）

```jsonc
{
  "pluginId": "my-plugin",
  "name": "我的插件",
  "icon": "resources/icon.svg",
  "entry": "src/index.tsx",
  "appearsIn": { "iconBar": "top", "tabBar": true }
}
```

```tsx
// src/index.tsx —— 入口组件：壳按 { isActive, tabId?, sourceId? } 注入 props
export default function MyView({ isActive }: { isActive: boolean }) {
  return <div>Hello LinkDesk</div>;
}
```

### ③ 侧栏

```jsonc
{
  "appearsIn": { "iconBar": "top" },
  "contributes": {
    "viewsContainers": { "my-sidebar": { "title": "我的工具", "location": "sidebar", "order": 100 } },
    "views": { "my-sidebar": [ { "id": "main", "title": "", "render": "src/views/MainView.tsx", "order": 0 } ] }
  }
}
```

### 底部面板

```jsonc
{
  "contributes": {
    "viewsContainers": { "my-panel": { "title": "我的面板", "location": "panel" } },
    "views": { "my-panel": [ { "id": "output", "title": "输出", "render": "src/views/OutputView.tsx", "order": 0 } ] }
  }
}
```

```ts
await window.linkdesk.panel.reveal("output");   // 聚焦底部面板的 output 视图（不在 panel 容器里 → no-op，不报错）
```

### ⑦ 状态栏

```jsonc
{
  "statusBar": [
    { "id": "units", "label": "mm", "align": "right" },
    { "id": "zoom",  "label": "100%", "align": "right", "onClick": "my-plugin.zoomFit" }
  ]
}
```

状态栏条目的 React 组件按三条路径自动找：`statusBar.tsx` / `src/statusBar.tsx` / `src/components/statusBar.tsx`。

### ① 标题栏按钮

```jsonc
{
  "contributes": {
    "titleBar": { "right": [ { "command": "my-plugin.refresh", "icon": "codicon-refresh", "when": "my-plugin.busy" } ] }
  }
}
```

### 视图动作区（侧栏 section / 面板标签栏右侧）

```jsonc
{
  "contributes": {
    "views": {
      "my-sidebar": [
        {
          "id": "main", "title": "我的工具", "render": "src/views/MainView.tsx",
          "titleActions": [ { "type": "icon", "id": "reload", "command": "my-plugin.reload", "icon": "codicon-refresh", "title": "重新加载" } ]
        }
      ]
    }
  }
}
```

`titleActions` 里的 `command` 由你的视图组件自己注册（`window.linkdesk.commands.registerCommand`）；**这类纯程序化命令建议 `when: "false"`**，免得在命令面板里刷屏。

## 五、组件的 props 契约

不管你落在哪个区域，**内容组件收到的都是同一套 props**：

```ts
type PluginViewProps = { isActive: boolean; tabId?: string; sourceId?: string };
```

| prop | 含义 | 用法 |
|:--|:--|:--|
| `isActive` | 所在标签页/视图当前是否聚焦 | **只用来 gate "聚焦才该跑的副作用"**（轮询、自动保存）——keep-alive 下所有标签页始终挂载，用 `isActive` 整块 blank 掉内容 = bug |
| `tabId` | 本标签页 id | 区分多开的同一个插件 |
| `sourceId` | 上下文数据（文件路径 / 会话 id 等） | 编辑器类插件靠它知道"用户打开了哪个文件" |

侧栏/面板的**视图**组件签名同款（可以只声明用得上的那几个 prop）。
