## 一、读法——三层各是什么，以及那条铁律

| 层 | 谁写 | 落在哪 | 例子 |
|:--|:--|:--|:--|
| **主题配方** | 主题插件作者（`ThemeRecipe`） | `appearance.{radius,glass,font,background}` ＋ `colorways[].colors` | `glass.opacity` · `radius.md` · `font.ui` |
| **用户设置** | 用户（设置页） | `app.*` 键（`getConfigurationValue`） | `app.glassOpacity` · `app.surfaceRadius` |
| **引擎默认** | 壳（常量／`:root` 兜底） | `ThemeEngine/constants.ts` ＋ `index.css` | `RADIUS_MAX_PX = 32` · `GLASS_SURFACE_DEFAULT_ALPHA = 0.5` |

**参考系铁律**（用户 2026-08-25 定性「参考系都选错了」→ [14-档案 §三 §四](../../../02-Electron架构/归一化基建/外观主题化/14-主题配置参考系根治档案.md)）：
> 每个可调属性定义**系统绝对标尺**；滑杆/色块以标尺为坐标；**主题值 = 标尺上的默认位置**；用户覆盖 = 标尺上另一位置。
> ⇒ **0 点与满刻度必须锚系统标尺，⛔ 不得锚「主题当前值」**。主题值入场时 render 侧 clamp 进标尺（圆角 `min(v,32)`；`radius-full` 相对几何值排除）。

## 三、参考系逐一过（8.2）

**判据**：0 点与满刻度是否锚在**系统标尺**上（而不是「主题当前值」）。

- ✅ **锚标尺，合格 7 项**：`surfaceRadius`(0→32) · `zoneRadiusScale`(0→32) · `glassBlur`(0→32) · `glassOpacity`(0→1) · `backgroundOpacity`(0→1) · `backgroundMask`(0→1) · `uiFontScale`(85→150)。**0 点都是「该属性的绝对无效果/最小」，满刻度都是「标尺上限」——没有一项锚主题当前值。**
- ⚠️ **中性点不在端点，4 项**（不是错，但**文案必须自证**，否则用户拿「中点」当「归零」）：
  - `glassSaturate`：1 = 原图在中段；两端（0 去饱和 / 2 加倍）**都是效果**。
  - `backgroundOpacity`：1 = 原图在**满刻度**；0 才是「全透见底色」。
  - `backgroundMask`：0 = 无遮罩在 **0 点**；1 = 全黑。
  - `uiFontScale`：100% 在中段；85/150 两端都是效果。
  - ⇒ **不透明度类 ≠ 遮罩类**：前者「大＝更实」，后者「大＝更黑」；两行相邻、同量纲 0..1，见 **C5**。
- ✅ **已消的历史参考系错**（[14-档案 §五 #85-#92](../../../02-Electron架构/归一化基建/外观主题化/14-主题配置参考系根治档案.md)）：滑杆 0 点不再锚主题当前值；`glassOpacity` 去掉 ×0.5 wash 隐藏乘数改绝对 0→1（#86）；`glassBlur` 去掉每表面隐式倍率改声明式系数（A5）。
- 🔴 **归属（归一 2：一个属性一个主人）** —— 见 C1／C2／C4。

## 四、撞车项清单（8.3 待拍板）

### C1 · 两个「玻璃不透明度」（E20）

| | 主题那只 | 用户那只 |
|:--|:--|:--|
| 入口 | 配方 `glass.opacity` | 设置页「玻璃面不透明度」= `app.glassOpacity` |
| 落地 | `--glass-opacity`（[`index.css:617`](../../../../src/index.css) tint 盖片强度） | `--glass-surface-alpha` → 合成 8 个 `--bg-*`（`getGlassSurfaceSpec`） |
| 主人 | 主题作者 | 用户 |
| 谁决定图标栏可读性下限 | ⛔ 管不到 | ✅ 就是它（E20/实测） |

**现状**：#112 已把用户键从 tint 盖片**摘除**（不再写 `--glass-opacity`，只走合成层）——功能上早已分开，**但名字几乎一样，设置页那条 label 也叫「玻璃不透明度」**。
**候选**：① **仅改文案**（设置页描述改说「玻璃面合成比例」＋主题文档已写清——零迁移、零类型改动）；② 用户键改名 `app.glassSurfaceAlpha`（要迁移 old key，波及 3 处引用 ＋ 配置迁移）；③ 不动，只在 tooltip 说。
**建议 ①**。

### C2 · 圆角两轴：`app.surfaceRadius` × `app.zoneRadiusScale`（#85）

同一把 0→32 标尺、两个滑杆（组件圆角 / 分区圆角），都是绝对 px，语义确有区别（组件 vs 分区），且分区侧还多一个 `app.zoneRadius` 开关。
**候选**：① **仅文案对齐**（现描述已分别写「组件圆角」「分区圆角」）；② 两轴合并成一把（会砍掉「分区独立圆角」的极限主题表达，gallery ①/⑦ 依赖它）；③ 加联动/偏置关系。
**建议 ①**（保留两轴，只补一句「谁管谁」）。

### C3 · 外观模式轴（原名「三枚举」）——**已消，待确认**

`app.mixMode` / `app.accentMode` 已随 #90 删（`app.mixColor`/`app.mixSurface`/`app.mixRadius`/`app.mixGlass` 随 #97/#132 删）。今天只剩两轴：`app.appearanceMode`（跟随/自定义）＋ `app.accentSource`（强调色来源）。
**候选**：① **不动（已消）**；② 文案再补一句「强调色是独立轴，主开关切回跟随主题不复位它」。
**建议 ②**（一句文案，防回潮误解）。

### C4 ·（新发现）`app.glassSaturate` 会动到主题侧的 `--glass-opacity`

`index.css:617`：tint 盖片 `opacity: max(var(--glass-opacity,1), calc(1 - var(--glass-saturate,1)))`——**用户拖饱和度到 0，会把主题写死的盖片强度顶成 1**（#150 端点语义：「0 = 任意主题整面全灰」）。
这是**有意设计**（有案可循），但与「一个属性一个主人」有张力：主题 author 写的 `glass.opacity` 被用户旋钮覆盖式抬升。
**候选**：① **不动**（端点是特性，有 #150 档案背书）；② 把 `1 - v` 项拆成独立 token（去掉跨层 `max()` 耦合，但改渲染表达式＝要重跑玻璃回归网）；③ **只在文档标注**这层关系。
**建议 ③**（本刀只正名；真要动另立小契约）。

### C5 ·（新发现）`backgroundOpacity` 与 `backgroundMask` 中性端点相反

相邻两行、同量纲 0..1：一个「越大越实」（1=原图），一个「越大越黑」（0=无遮罩）。**两者描述其实已各自写明端点**，风险在用户心智（拖错方向）。
**候选**：① **仅文案**（可选：给 mask 行加「数值越大越暗」的措辞）；② 给 mask 反向量纲（破坏既有语义与存量用户值）。
**建议 ①**。
