# 插件语义二分 · 随包（bundled）与重要（essential） —— 去 core:true

> **状态**：🟢 已落地并归档（2026-11-26 执行 · 2026-11-28 收口归档）——读数与遗留见 [06-执行回执.md](06-执行回执.md)；**软件轴未占版本号**（现场替换 `D:\01link`，版本号随下一批 CHANGELOG 回填）；插件轴已真发版（editor 1.0.33 / file-tree 1.0.43 / settings 1.0.58 / marketplace 1.4.41）
> **触发**：用户实机报障「库里 3 个可更新，点『全部更新』却弹『所有插件已是最新』」——根因是 `core:true` 被市场拿去判"能不能更新"。
> **用户拍板（2026-11-26 原话要点）**：
> ① 「内置」的本义只是**随安装包打包**（新用户不能面对空壳，至少要有市场、设置，将来还有 LPM）；与"属于壳/核心能力"无关。
> ② 「重要型」是打包型的**子集**：防止小白误删，所以 UI 不给卸载按钮；但允许从文件夹删、允许命令层卸、允许被第三方整套替换。
> ③ **`core` 从此不存在**；不再考虑兼容——「现在的兼容就是给未来埋坑」。
> ④ 表面行为不变：市场/设置等仍无卸载按钮。
> **一句话**：一个旗标只许表达一件事。随包＝构建/打包事实；重要＝UI 卸载入口可见性；可更新＝住所。三者正交、各归其位。

---

## 一、新模型（三件事实分家）

| 事实 | 唯一真相源 | 只影响什么 | ⛔ 不许影响 |
|:--|:--|:--|:--|
| **随包 bundled** | `bundled-plugins.lock.json` 的 `seed: true`（构建期事实；⛔ 插件不得自封） | 新用户开箱可用；「内置」分组/徽标的数据面 | 更新、卸载、权限 |
| **重要 essential** | `plugin.json` 的 `essential: true`（**仅随包件可声明**；本地/第三方自封 ⇒ 拒装） | **只**决定"卸不显示卸载按钮" | 更新判定、禁用、权限、默认槽位 |
| **可更新 updatable** | 壳住所（`{userData}/plugins` 才可为真） | **唯一**更新判据 | 卸载可见性 |

- `core` 字段**整删**：类型、契约、schema、投影、消费方、文档全部不再出现；不做读侧别名。
- 现状读数（与模型吻合）：随包 6 只 = editor / file-tree / settings / marketplace / lang-defaults / theme-defaults；其中声明重要 4 只 = editor / file-tree / settings / marketplace（语言包与默认主题随包但可卸）。
- 未来 LPM（LinkDesk Package Manager）按同一套：随包带进去；需要就声明 `essential`。

### 2.7 归一化要求（用户 2026-11-26 明确点名，最高优先级）

本项目把归一化视同正确性（历史实证：作者头像两处只更新一处、卡面不归一化）。本任务必须做到：

1. **一个事实一个 owner**：`bundled`（lock seed）／`essential`（manifest）／`updatable`（住所）三处，⛔ 任何消费方不得自行推导第二个副本。
2. **一个动作一个选择式**：批量更新/批量停用/批量卸载的目标集合各自由 `services`/`libraryData` 的具名函数产出；`views/**` ⛔ 不写 filter（E2 闸）。
3. **卸载可见性单点**：`essential` → 「卸不显示卸载按钮」的判定只许一处（详情页与列表共用同一 selector/predicate），⛔ 两处各判。
4. **无硬编码**：旗标名/文案键不写字面量散落；文案走 i18n；⛔ 死代码（删净 `core` 的残留分支、无用导出）。
5. **高内聚低耦合**：新语义只落在既有 feature folder（`pluginLoader/discovery`、`plugin-install` 等），⛔ 新建平行目录；⛔ 插件侧 import 壳内部。
6. **AI 友好**：类型注释/错误码/回执 reason 自解释（`essential-forbidden` 一眼可判），AI 不看源码也能从契约面答「为什么拒装」。

### 2.8 记忆库更新（仓库外，用户明确要求）

- 新建/更新记忆条目：**「`core` 退役：随包 / 重要 / 可更新 三事实分家」**——触发条件写「遇到 core / 内置 / 不可卸载 / 更新判定」；含根因（多义旗标被拿去判更新）与本次定论。

| 闸 | 落点 | 判据（红） | 负控 |

## 四、验收判据

1. `npm run check`（壳）全绿；插件仓 `validate` / `verify` / `test` / `build` 全绿。
2. 全仓 grep：`core` 不再作为插件旗标出现（类型/契约/schema/投影/消费方/文档/4 只 manifest）。
3. 表面行为零变化：市场/设置/编辑器/文件树**无卸载按钮**；语言包/默认主题/第三方插件**有卸载按钮**；「内置」徽标显示集合与今天一致。
4. 更新判定只读 `updatable`：`grep -n "essential" services/libraryData.ts` 不出现于 `updateTargetFor` 调用链。
5. 负控：E1/E2/E3 各自"塞回旧写法 ⇒ 红"取证。
6. 实机：装 1.4.40 后「全部更新」把 editor/file-tree/settings 一并带上；「卸载」钮依旧不出现。

## 五、边界与风险

- ⛔ 不做兼容别名——用户明确「兼容就是给未来埋坑」；这是 v1 前的窗口期，一次改干净。
- ⛔ 不改「随包件出厂装回/墓碑」语义（E6 四语义定稿 ①②③④ 原样有效，只把旗标名与含义拆清）。
- ⛔ 不让 `essential` 获得任何新特权（默认槽位、权限、更新都照旧）。
- 第三方作者成本：`core` 一删，旧清单校验会报未知字段——接受（无外部用户；作者文档同步改口）。
