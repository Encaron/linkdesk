## 一、#141 分屏移动的 tab 内容跨组 remount → 设置页分组跳回通用

### 现象

设置页在「主题」分组下 → 右键设置标签页 → 向右分屏 → 光标（左侧导航 active 高亮）和界面（右侧表单内容）自动跳到第一个「通用」组。

### ① 原因（根因 file:line + 机制）

**reduceSplitTab 语义 = 移动被右键的 tab**（[reducers-layout.ts:159-205](reducers-layout.ts) 目标 tab 进 `createGroup([tab])` 新面板，源组留 `sourceRemaining`）→ 右键设置 tab 分屏时设置 tab 物理移入新面板 → **tab 内容组件跨 GroupPane remount**，`SettingsView` `selectedGroup` 局部 state 丢失 → fallback 第一个「通用」组。

- **tab 内容渲染位置（旧）**：[GroupPane.tsx](GroupPane.tsx) `{group.tabs.map(tab => <div key={tab.id}>…ShellViewRenderer/PluginComponent…</div>)}`——tab 内容在 **GroupPane 内部**，而每个 group 一个 GroupPane。
- **跨组移动 = 换父节点 = React 必 remount**：React 的 key 只在「同一父节点」下才复用。tab 从 group-A 移入 group-B → 父节点 GroupPane-A → GroupPane-B → 必 unmount + remount。任何跨组移动（右键分屏 / 拖拽跨组 / 合屏迁移）都触发。
- **面板层去 Fragment 只覆盖「非移动 tab 留原面板」场景**：[MainZone.tsx:185-264](MainZone.tsx) 数组展开保证 1↔2 切换时**面板子树**按 key 复用零 remount——但当用户**右键设置 tab 本身分屏**时设置 tab 移入新面板（新 GroupPane），面板层复用救不了 tab 内容跨组 remount。
- **后果**：[SettingsView.tsx:40](SettingsView.tsx) `selectedGroup` useState 随 remount 重置 `null` → [SettingsView.tsx:210-213](SettingsView.tsx) `activeGroup = find(...) ?? filteredGroups[0] ?? null` fallback 第一个「通用」组。
- **连带影响（同一根因）**：任何 tab 本地状态（Monaco 编辑器、CM6、插件视图内部 state）在跨组移动时全部重置。

### ② 改法（A 方向——tab 视图保活，2026-08-27 用户拍板）

**tab 内容从 GroupPane 内提升到 `.main-zone` 根级 TabContentLayer（key=tab.id 永远同级），跨组移动只改「定位 rect + 显隐判定」，不改 DOM 位置 → 零 remount。**

- 结构：面板层（[GroupPane.tsx](GroupPane.tsx) 只剩 GroupTabBar）+ [TabContentLayer.tsx](MainZone/TabContentLayer.tsx)（每 tab 一个内容 div，absolute 定位所属面板 rect，内容区 top:TAB_BAR_HEIGHT 对齐标签栏）。
- rect 来源：多面板 = `computeLayout` 的 `layout.panels`（含 groupId+x/y/w/h）；单面板 fallback = `0,0,100,100` → 单↔多面板切换 tab 内容零迁移。
- 显隐：`visible = tab.id === 所属group.activeTabId`（keep-alive：非活跃 tab 仍在 DOM）；`isActive = 所属group.id === activeGroupId && visible`（[E5.8#30.15](E5.8-执行清单.md) 单聚焦语义不变）。
- 对标 B22：面板平级（[MainZone.tsx:11-14](MainZone.tsx) 已完成）→ tab 视图也平级（本次），同一思想推广到下一层。面板层去 Fragment 数组展开保留（两种场景都零 remount）。
- 风险规避：① 事件冒泡——tab 内容是面板 div 的兄弟，TabContentLayer 自身挂 focusGroup onMouseDown；② z-index——handle 在 DOM 后 + `Z_INDEX.splitHandle` 仍可拖，tab bar 不被盖（内容区 top:35px 避开）；③ 首次升级迁移——tab 内容「面板内」→「根级」一次性 remount，此后任何移动零 remount。

**不做**：SettingsView `selectedGroup` 持久化（band-aid）——只遮设置页症状，remount 空洞（Monaco/CM6 状态丢失）仍在，属治标。

### ③ 可执行性

- `npm run check` 全绿（tsc 双工程 / eslint --max-warnings 0 / vitest / jscpd / pool-css）。
- **CDP 实机复现 + 验收**：先读界面快照（不凭记忆）→ 打开设置 tab → 选「主题」组 → **右键设置 tab 分屏**（用户真实场景，tab 移动）→ 断言左侧 nav active 仍「主题」+ 表单内容仍主题组（非「通用」）；`data-tab-content-id` 探针确认分屏/合屏/tab 移动下 tab 内容 DOM 节点不变（零 remount）。
- **连带验证（根因修复额外收益）**：Monaco/CM6 tab 跨组移动后光标/内容/未保存状态保留；拖拽重排 / 拖出窗口 / 吸附插入零回归。

## 二、#142 浮层 z 分层缺口——overlay-root 内容 + toast 低于悬浮面板（下拉在面板后）

### 现象

设置页悬浮面板（ctrl+, 或右键标签栏 →「在悬浮面板中打开」）内点击下拉菜单 → 下拉出现在**悬浮面板后面**（玻璃主题半透明下一眼看出）。影响同类浮层次表面：面板内的下拉/取色器/dropdown-card/通知面板 + toast。

> ✅ **已修复（2026-08-27）**——用户实机确认「悬浮窗的下拉正常了」。实现 + 验证记录见 §四执行注。

### ① 原因（根因 file:line + 机制）

**浮层权威 #107/#119-#121 建了 `#overlay-root` + `#toast-root` 但未配 z 层**——Z_INDEX 表缺「通用 surface 根」层，overlay-root 内容（z600-650）与 toast（z-auto）低于悬浮面板（1500）。

- **层上下文**：[FloatingLayerHost.tsx:51-57](FloatingLayerHost.tsx) `#ld-float-layer` z2000（Z_INDEX.toast）建 stacking context；其内 sub-roots 自分层。
- **z 实况（全部相对 `#ld-float-layer` 内层）**：
  - `.floating-panel` = **1500**（[FloatingPanelHost.tsx:246](FloatingPanelHost.tsx) inline `Z_INDEX.floatingPanel`）+ backdrop 1499（:234）。
  - `#overlay-root` 无 zIndex（[FloatingLayerHost.tsx:90](FloatingLayerHost.tsx)）→ 内容落自身 z：`.selectbox-dropdown` 650（[SelectBox.css:86](SelectBox.css) `--z-dropdown`）、`.dropdown-card` 650（dropdown-card.css:18）、ColorPicker 600（[ColorPicker.css:13](ColorPicker.css) `--z-overlay`）、notif 600（status-bar CSS:124）——**全 < 1500**。
  - `#toast-root` 无 zIndex（[FloatingLayerHost.tsx:94-96](FloatingLayerHost.tsx)）→ toast z-auto（0）——**< 1500**。
  - context-menu 3000 / quick-pick 4000 / dialog 5000 / tooltip 6000（[constants.ts:17-19](constants.ts)）——**> 1500**，右键/命令面板/对话框在面板内开**正常**（用户猜测「有的面板需要右键…弹窗」实际这两类 OK，坏的是 overlay-root 内容 + toast）。
- **根因归属**：#107 浮层权威把 5 浮层 + 通用 surface 根归位时，`#overlay-root`/`#toast-root` 建根未配 z 层；遗留 `--z-dropdown 650`/`--z-overlay 600` 是 E5#98 时代的裸 z，未随层化迁到 Z_INDEX 常量——浮层权威「自分层」不完整。

### ② 改法

1. **constants.ts**：Z_INDEX 增 `overlayRoot: 2000`（注释：通用 surface 根层——下拉/取色器/dropdown-card/notif，盖悬浮面板 1500、被 context-menu 3000 盖）。
2. **FloatingLayerHost.tsx**：
   - `#overlay-root`（:90）加 `zIndex: Z_INDEX.overlayRoot` + **`position: relative`**（2026-08-27 实机确诊：overlay-root 原为 **static div，z-index 对 static 无效**——首步只加 zIndex 实测 dropdown 仍在面板后，补 `position: relative` 后 elementFromPoint 命中 dropdown。absolute 子元素零影响：全部 overlay surface 均 fixed、absolute 嵌于各自 fixed 容器内，containing block 不受本 root 影响）——root 建 stacking context，内容 z600/650 被收纳，整 root 以 2000 参与自分层，盖面板 1500。
   - `#toast-root`（:94）加 `zIndex: Z_INDEX.toast`（2000，`position:fixed` 可配 z）——toast 盖面板 + 盖 overlay（DOM 序 toast-root 在 overlay-root 后，同级 2000 → toast 胜）。
   - 结果层序：panel 1500 < overlay 2000 = toast 2000 < context 3000 < quick-pick 4000 < dialog 5000 < tooltip 6000。
3. **不碰** `--z-dropdown`/`--z-overlay` 遗留值（root 已收纳，语义仍是「root 内相对层」）；不碰结构隔离地板（[index.css](index.css) 结构选择器与 z 无关）。

### ③ 可执行性

- `npm run check` 全绿。
- **CDP 实机**：悬浮面板开设置 → 主题组点下拉 → `elementFromPoint`/像素采样确认下拉在面板之上（玻璃半透明可辨）；面板开启时触发 toast → toast 在面板之上；面板内取色器同样盖面板。
- **零回归**：普通窗口（非悬浮面板）下拉/右键/对话框行为不变——overlay-root 只提升层序不改结构，context 3000/dialog 5000 仍盖下拉；`#ld-float-layer` 层基准 2000 不变。
