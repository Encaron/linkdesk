## 一、你令的原话（2026-10-06）

**第一条（报 bug）：**

> 「关于 `app.accentSource`，为什么我如果选择 `{"app.theme": "theme-aurora-glass.aurora-glass"}` 这类主题，`app.accentSource` 的第一个按钮「跟随主题配方」的按钮的 UI 会有问题。本来是黑白双拼的，一般的 `{"app.theme": "light"}` 这种都是显示正常。但是我切换到 `theme-aurora-glass.aurora-glass`，那个黑色那边的最边上会出现白色，白色那边的一点会出现黑色，看起来像是最边上两个竖条像素交换位置了。」

**第二条（本夹的规格，四条，一字不改地钉在这里）：**

> 1. 「完善尾巴，确保万物皆可插件，当前设置插件内的不能留尾巴」
> 2. 「一方面这是归一化问题，你反正要修，你修 `@linkdesk/ui` 和插件仍在自画的都是修，为什么不按归一化修」
> 3. 「设置插件是外部插件引用 `@linkdesk/ui` 的一个官方示例插件，必须标准」
> 4. 「若有大量还没接上的，必须接上。简单一句话，我哪怕换了一个设置插件，接上线仍能够 gui 层面操作，而不是说 gui 退化」

⇒ 第 1 条判定：**你说得一个字不差**——就是最外两条竖列的像素互换了位置。⛔ 而且**与玻璃、blur 无关**，是这个色块**自己画渐变的方式**踩了一个 CSS 默认值（下 §三）。
⇒ 第 2 条裁定：**D1 走 B（归一化）**，不是原来建议的 A（只止血）——见 §五。
⇒ 第 3／4 条裁定：**验收判据 = 换掉设置插件后 GUI 不退化**（每条宿主声明的控件都能由任何渲染方经共享件画出来），逐条账在 [06](06-尾巴总账与验收.md)。

## 二、那枚色块是什么、在哪（只读审计）

| 项 | 值 |
|:--|:--|
| 是什么 | `app.accentSource` **第一个选项**「跟随主题配方」左侧的预览色块（黑白分半）；同一控件里 `自定义` 那枚是纯强调色块 |
| 谁声明 | 宿主 schema：`src/App/config/appearance.ts` 的 `app.accentSource`，带 `uiHint: "accentSource"` |
| 谁画的 | **设置插件**（外仓 `E:\linkdesk-plugins\official\settings`）的行渲染器：`renderControl/toneControls.tsx` 的 `AccentSourceControl`（选项壳用共享件 `SegmentedRadio`，色块本体吃共享件 `SegmentPreviewSwatch`） |
| CSS 住在哪 | ✅ **只有一处**：壳/共享件 `src/components/shared/segment-preview/SegmentPreview.css`（`.ldk-segment-preview--split`，随 `@linkdesk/ui` 发 npm）。⚠️ 插件私有那份 `.settings-segmented-swatch` **已随 1.0.40 整删**（旧版本本夹曾把它记成「两份拷贝」，那是修前的实况） |
| 几何 | `52×30` · `border: 1px solid var(--separator)` · `border-radius: var(--radius-sm)` · `overflow: hidden` · 渐变 `linear-gradient(90deg, var(--tone-surface-deep) 50%, var(--tone-surface-light) 50%)` |
| 同族另一处 | `app.fontTone` 的 `Aa` 分半预览——**不受影响**（它是两个子 `<span>` 各涂纯色，不走背景铺贴），这也是「只有第一个按钮出问题」的原因之一 |
| 为什么 `light` 正常 | 内置 light/dark 的 `separator` 是**不透明**色（`#E8E8E8` / `#474747`）⇒ 出问题的那两列**被边框盖死**；极光玻璃的 `separator` 是 `rgba(255,255,255,0.06)` ⇒ **94% 透明**，盖不住 |

## 三、病灶与根因（一条根因，四个症状）

| # | 症状 | 根因 | 证据 |
|:--:|:--|:--|:--|
| **①** | 极光玻璃下，色块**左右最外 1px 各显示对侧颜色**（黑侧最外＝白、白侧最外＝黑） | 渐变按**内边距盒 50×28** 铺，却被铺进**边框盒 52×30**，且默认 `background-repeat: repeat` ⇒ 左右各被补一条「平铺环绕列」：左＝图样**末列**（浅）、右＝图样**首列**（深） | 实测 修前 左列 `#F2F2F2` / 右列 `#272727`（[01 §五](01-根因与修法.md)）；全局 `box-sizing: border-box`（`src/index.css:197`） |
| **②** | 上/下边缘**看不出来** | 这是**水平**渐变 ⇒ 垂直方向补出来的列与本体同色 ⇒ 无视觉差 | 同 §五：只有左右两列异常 |
| **③** | 内置 light / dark **完全正常** | `separator` 不透明（alpha＝1）⇒ 边框把环绕列盖死，四边只剩一条均匀边框色 | `theme-defaults/themes/defaults.json` 的 light `#E8E8E8` / dark `#474747` |
| **④** | 🔴 **第一版「修了却看不出差别」**（2026-10-06 实测） | 只给基类 `.ldk-segment-preview` 加了 `background-origin: border-box`，而**变体用的是 `background` 简写**——简写会把 `background-origin` 一并重置回 `padding-box` ⇒ 那种写法**逐像素等于修前** | 实测：第一版下 左列 `#F2F2F2` / 右列 `#272727`，与修前**逐字节相同**；改长手后才是 `#272727` / `#F2F2F2`（[01 §六](01-根因与修法.md)） |

**一句话**：**渐变被平铺了，平铺会环绕；边框半透明时环绕就透出来了。** 而「修 `background-origin`」这件事**只有用长手写才作数**——简写会把那行声明抹掉。

## 四、改法（真修 / 无效的第一版 / 已否决的 B 案）

| 案 | 一句话 | 判定 |
|:--|:--|:--|
| 🔴 **无效的第一版** | 只在基类加 `background-origin: border-box`，变体仍用 `background: linear-gradient(...)` 简写 | ⛔ **等于没修**（简写重置回 `padding-box`，实测逐像素同修前）。⚠️ 这一版**已经发过 `@linkdesk/ui` 0.2.49** ⇒ 0.2.49 的 CHANGELOG 条已改写成「该版未生效」，真修复由 **0.2.50** 承接 |
| ✅ **真修（已落地）** | 基类保留 `background-origin: border-box`，**变体一律改长手**：`background-image: linear-gradient(…)` ／ `background-color: var(--accent)` ⇒ 基类那行活下来，铺贴块＝边框盒 52×30，没有多余环绕列 | 两处变体 ＋ 所有主题通吃；实测 左列 `#272727`（深＋6% 白）/ 右列 `#F2F2F2`（浅＋6% 白） |
| B（对照，⛔ 不推荐） | 加 `background-repeat: no-repeat` ⇒ 环绕没了，但边框那 1px **没东西可铺** ⇒ 露出底下的面板色（实测 `#1e252d`） | 脏边换个颜色继续存在（浅底上更明显） |

> 真修后的逐列读数、以及「无效的第一版为什么无效」的样式表顺序证据，见 [01 §五/§六](01-根因与修法.md) 与 [05 图](05-设计图-边缘串色.html) §⑤；真身对照现场可切（主题 × 修前/真修）。

## 五、决策点 D1（✅ 已拍板 ＝ B · 归一化）

| # | 问 | 裁定 | 依据 |
|:--:|:--|:--|:--|
| **D1** | 只修共享件那一行（A），还是**同笔**把插件那份私有拷贝接到共享件上（B）？ | ✅ **B** —— 而且更进一步：**凡「消费宿主声明的控件」由插件自画的，一律按归一化接上共享件**（不止色块这一处） | 你的原话「你修 `@linkdesk/ui` 和插件仍在自画的都是修，为什么不按归一化修」「设置插件是外部插件引用 `@linkdesk/ui` 的一个官方示例插件，必须标准」 |

**原来的 A 案建议已作废**（原档写「A（先止血）——B 值得单开一件」）：B 的性质当时被记成「受兼容面约束、须走 `pick()` 双轨或抬地板，⛔ 不能静态具名 import」，那两条前提**今天都已不成立**：

- 插件地板已抬到 **0.2.52**（`minAppVersion`），而所用共享件导入名的 `since` 最高 0.2.52 ⇒ **静态具名 import 天然安全**；
- `pick()` 双轨**已整层删除**（`sharedUi.ts` 删除，见 1.0.40 CHANGELOG）——而且它**本身就是错的**：变量键取值逃过「插件最低壳版本」地板账本（地板按静态具名导入算），官方示例插件不能是这个样子。

## 六、边界（⛔ 本轮明确不做）

- ⛔ **不动任何主题的 `separator` 值**——半透明 separator 是设计（玻璃面就是要透），不是错。
- ⛔ **不动 `--tone-surface-deep` / `--tone-surface-light` 标尺 token**（系统双字系，明暗主题同值）。
- ⛔ **不动 `app.accentSource` / `app.fontTone` 的选项值、文案、顺序**（本件是纯视觉修复）。
- ⛔ **不动 `52×30` 与 `--radius-sm` 几何**，不碰 `ui-scale` / `zoomLevel`。
- ⛔ **不改第三方仓**（第三方照抄过这段 CSS 的，只登记为作者面笔记，不代改）。
- ⛔ **不动契约字段、不加 IPC**（本件只动 CSS 属性与组件装箱）。
