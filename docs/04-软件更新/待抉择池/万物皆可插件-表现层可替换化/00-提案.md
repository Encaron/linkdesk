## 三、提案总模型

### 3.0 一条总线、两条铁律

**一条总线**：「壳想、池画」不动摇（memory `shell-thinks-pool-paints`）。所有替换都是同一件事——壳照常推 PoolLayout DTO 与数据命令，池把**某槽位的渲染体**换成插件贡献体。不引入第二渲染架构，不做 Shadow DOM / iframe / `@layer` 隔离（既有拍板），替换体照走 CSS 命名空间九件套。

**铁律 A（数据同源）**：被替换面的数据拉取一律先封装成壳只读命令（暂名 `app.getWelcomeData` / `app.getAboutData` / `update.getReleaseNotes`），任何渲染者（含壳内置页）只准走命令取数。GitHub 照旧拉版本历史、pluginState 照旧出最近文件——数据通路一根，皮随便换。命令自带 description＋params ⇒ AI/CLI 直接可读（用户第 8/9/11 点的固化）。

**铁律 B（双通道归一）**：每个槽位的「列出候选 / 切换 / 回退默认」全部命令化并进 AI 操作手册；设置 UI 面与命令面同源（`configuration.renderHint:"action"` 直连命令的现成模式）。「UI 方面和 AI 友好化方面两个都有、指向同一通路」＝硬约束 26 在槽位维度的重申。

### 3.1 L1 token 层（已有，补一口）

主题配方九分节已覆盖用户历数全部维度（颜色→玻璃→字体）。**残余口子**：OS 层窗底色 seed 只分亮/暗两档，自定义主题的精确底色到不了 OS 层（开屏第一帧可能闪错色）。补法：主题配方落一份 seed 值进 settings.json 供主进程 `theme-seed.ts` 同步读。

### 3.2 L2 部件槽位层（新贡献点 `contributes.renderers`，暂名）

插件贡献**同契约渲染体**，接管指定部件的「画」。槽位枚举（首批建议）：contextMenu / selectBox / dropdownCard / viewSkeleton / notificationPanel / dialogChrome / quickPick / emptyStage / bootMark / tabBar。设计要点：

- 渲染体走 `@linkdesk/ui` 导出契约＋R6/G1 纪律（渲染臂里只许共享件或自有组件，禁壳内部 import）——「第二个作者不看第一个人的源码也能做全」的既有判据直接适用。
- 槽位注册表对齐 MenuRegistry 形态；一槽多候选仲裁照抄 factoryRole（默认注册序＋用户切换持久化）。
- **窗控三键先走低成本版**：不换组件，先开 configuration 顺序/显隐配置（macOS 布局诉求一步到位，用户第 22 点），整套换皮留给 M2。

### 3.3 L3 页面层（factoryRole 推广，机制零新增）

welcome / about / releaseNotes（连同 EmptyStage）全部 factoryRole 化：`factoryRole: "welcome"` 等。这正是用户第 8 点的照抄——设置页怎么整套替换的，这三页就怎么整套替换：

- 官方内置三页先「吃自己狗粮」转成内置插件（`core:true` 只＝不显示卸载按钮，符合单等级插件制硬约束 11）；第三方替换＝装一只同角色插件，天然合法并存、用户可切。
- 欢迎页「壳兜底」（`tabBehavior.isFallback`）语义不变：无替换插件时内置页照旧兜底。
- 配套数据命令（铁律 A）；`menuItem` 补 icon 字段（用户第 12 点）同批做。
- 每个角色配逃生舱命令（照 `settingsCommands.ts:265-276` 先例）：第三方替换页崩掉时，命令直达官方默认。

### 3.4 L4 区域层（用户第 23/24 点）

两步走：

1. **整区去留**：PoolLayout DTO 的 visible 标志从内容级扩到整区级，区域显隐命令化。删减去留的**责任模型照录用户论证**：插件作者制作的是插件不是软件，只影响下载他的用户；官方原版该怎样就怎样；出了问题由插件作者与用户双方自担。但**回退链必须存在**（见 §五）。
2. **新建区**：新贡献点 `contributes.zones`（暂名）——受控槽位声明（位置枚举＋尺寸预算＋when 条件），壳侧把仅自用的 `LayoutEngine.addZone`（`LayoutEngine.ts:149`）开放为注册面，`computePoolGrid` 动态化。多插件抢位→factoryRole 同款仲裁。顺手项：auxiliarybar 声明了未接线（`plugin.schema.json:558`）的修复归入本层。

### 3.5 启动期协议（用户第 14/15 点，最深的一处）

现模型＝「启动全量注册元数据、零 JS import、按需懒加载」——这是性能底座，**不许整体打破**。开屏替换需要的是受控例外：

- 新增 `factoryRole: "splash"`（或 `contributes.splash`）：**唯一获准在 BootMark 阶段（首份 pushLayout 前）预热 entry 的白名单角色**。
- 协议四件：进度回调（splash 可上报加载进度，过场随之伸缩）／完成让位事件／**超时强制让位**（防恶意拖屏）／崩溃回退 BootMark。
- 如实列册：窗口创建→池首帧之间的 OS 底色段（亮/暗）够不着插件，硬约束 26①「OS 层够不着的如实列册」原文适用。

### 3.6 声音维度（用户第 19 点，全新品类）

新贡献点 `contributes.soundThemes`（暂名）：event→sound 映射（启动/通知/操作反馈/完成…），主题文件走独立 schema（对齐 theme.schema.json 先例），settings 配方加「声音」分节，壳统一 SoundService 播放。**与 UI 槽位完全解耦**——纯听觉主题是独立插件品类；通知音效是它的第一落点（通知事件源现成、且不碰「呈现面唯一」纪律）。音频文件随插件走 `getAssetPath`，无新增用户机落点。

### 3.7 L5 自由浮层（用户第 25 点）

现 `floatingPanel` 只能把「已注册视图」声明为悬浮面板。补第三形态 `contributes.widgets`（暂名）：**无视图依赖的独立浮层**——桌宠、Token 计时器、计费器都落这。落点 FloatingLayerHost（已存在）；z-index 走 OverlayPortal 层级契约（中央仲裁已有）；权限逐项声明（普通浮层/置顶/点击穿透/随启动），接 `permissions` 开放白名单。

### 3.8 AI 友好化配套（用户第 20/21 点）

§3.3–3.7 一切新面**同笔**出命令＋meta(description＋params)（硬约束 26②），AI 手册 02 章生成区随 `manual:build` 刷新。候选新门禁（起步只报不拦，照 `audit:plugin-commands` 先例）：**新增可替换槽位必须同时有切换命令＋数据命令**——机械防止「赛睿 Monitor V2 式藏在点击里」复发。

### 3.9 插件分类轴（只分贡献面，不动单等级制）

硬约束 11 单等级制不变——「类型」不是等级，是 **contributes 贡献面**的自然分野：

| 类 | 特征 | 现存成员 | 本提案新增成员 |
|------|------|------|------|
| **功能型** | 往软件里**加东西**（视图/命令/数据源） | 编辑器、文件树、串口监视器、PDF 阅读器等 | — |
| **角色呈现型** | 把系统已有的声明式数据**画出来**（factoryRole） | 设置页（`factoryRole:"settings"`）、市场 | 欢迎页/关于页/发行说明/开屏（§3.3/3.5） |
| **表现接管型** | 把已有部件的**画法换掉**（数据照旧同源） | 主题、图标主题（L1，已在仓） | `renderers`/`soundThemes`/`zones`/`widgets`（§3.2/3.4/3.6/3.7） |

「整体 UI 美化」插件＝**表现接管型的多槽打包形态**（§四-8），市场分类标签与覆盖面元数据（§四-6）即其登记处。一只插件可跨类（功能＋表现并存），互不妨碍。

## 四、AI 补充发散点（用户未明说、从代码长出来的）

1. **命令面板/QuickPick 换皮**——QuickPickHost 已是独立浮层宿主＋双数据源，是 L2 最顺的槽位之一。
2. **标签栏 GroupTabBar 换皮**——垂直标签、浏览器式分组；⚠️ keep-alive 与平铺方案（B22）不碰，只换视觉层。
3. **通知音效**＝soundThemes 第一落点（见 §3.6）。
4. **降级脸也换皮**——ErrorBoundary 崩溃页、PluginUnavailable 降级页也是一张脸，归 emptyStage 槽位族。
5. **HintTip / 滚动条 / 焦点环 token 化**——提示面三套机制归一顺带做，先 token 后槽位。
6. **市场覆盖面元数据**——manifest 声明占用槽位清单，市场页/安装确认显示「将接管：右键菜单·开屏·欢迎页」，用户知情（permissions 白名单已有骨架）。
7. **回退链机械化**——槽位渲染体崩溃→自动回退内置实现＋一条通知（PluginUnavailable 降级与 settings 逃生舱的推广，全槽位统一）。
8. **主题打包即槽位打包**——一只「美化包」插件可同时声明 token 配方＋图标＋声音＋渲染槽（用户第 7 点「做哪块换哪块」的 manifest 形态；市场元数据随之显示覆盖范围）。
9. **OS 级够不着清单**——drag-ghost（主进程自绘）、OS 底色 seed、原生 dialog——如实列册不假装可换，与 AI 手册「够不着清单」同册。
10. **深层行为 API 继续开**——布局快照读写、会话恢复策略等已是「命令化后 AI 可操作」的自然延伸，随各层顺手暴露。
11. **「形状」维度进配方**——窗体圆角、分层阴影、边框宽度，跟圆角标尺同一写法。

## 五、风险与边界

- **池＝哑渲染器不动摇**：替换体也是「被推着画」，禁直连 core。
- **CSS 命名空间九件套全覆盖**：替换渲染体就是插件渲染体——`ldk-` 禁借、`<pluginId>-` 前缀、判据先发 SDK 再铺插件仓（硬约束 23）。
- **通知面唯一纪律不废除**：「一个呈现面」可以换皮，不许并行第二面（`toast.ts:10-14` 铁律原文与本提案兼容）。
- **性能预算**：提前激活只开 splash 一个白名单口子＋超时强制让位；懒加载仍是默认。
- **安全/隐私分级**：欢迎页最近文件＝隐私数据→替换体须 permissions 声明＋安装确认（§四-6）。
- **版本化**：`@linkdesk/ui` 导出面只加不删＝渲染契约的版本底座；槽位契约变更走 SDK 发版节奏。
- **逃生舱常备**：每槽位一条「回官方默认」命令，AI 与用户都有路。
- **残余边界（如实登记，2026-11-05 自审）**：本提案对「新内容物硬编码」有四层机械锁（姊妹档 01 §五），但对「**新官方页面整体硬编码**」无专属新门禁——靠硬约束 9/10/28＋官方页吃狗粮先例兜底；是否加「官方新页面必须声明槽位」门禁腿 → 挂拍板。

## 七、开放问题（需用户拍板 · AI 建议值已录）

> 🔴 **交接说明（2026-11-05）**：用户指示**先不拍板**，AI 建议值录此备议；本对话可能关闭，后续会话（可能是新 AI）**从本节续谈**。标 ⭐ 者为 AI 建议值——**不是拍板**，讨论时逐条确认或改值；拍板后同笔把该条改写为「已拍板（日期）＋结论」并同步 §六 分期。方向与模型（§三/§八/§九）用户持续追问深化、未表异议；**七条决策全部未拍板**。

1. **区域删减去留的边界**（M4 最重一块）
   - 选项：a 只许隐藏既有区 / b 隐藏＋移动 / c 隐藏＋新建区
   - ⭐ 建议：**c 完整形态**——用户责任模型论证（插件只影响装了的用户）已成立；生效默认值挂第 2 条安装确认。拍方向即可，工程排 M4 末。
2. **隐私面替换是否强制授权确认**
   - 选项：a 安装时统一确认一次（弹窗列「将接管：右键菜单·开屏·欢迎页」）/ b 按数据敏感度分级二次确认 / c 不确认只靠市场元数据
   - ⭐ 建议：**a 一次知情**——不加第二道手续；敏感数据接口（最近文件等）另挂 permissions 白名单兜底。
3. **多插件抢同一槽位的默认仲裁**
   - 选项：a 维持注册序首个（factoryRole 现状） / b 后装提示（新装同槽插件弹一条通知问切不切） / c 后装自动接管
   - ⭐ 建议：**b**——a 被动（装了没生效，用户以为软件坏了）、c 霸道；b 只一条通知，正好落在唯一通知面上。
4. **splash 提前激活的性能红线**
   - ⭐ 建议：先立「必须有红线」原则，数字 M3 实测校准——起手值：**超时强制让位 3 秒**（到点回 BootMark）、entry 预热预算 ≤500ms。
5. **声音维度分期**
   - ⭐ 建议：**保 M3 不后撤**——用户原始诉求「开屏＋音效」成对出现，拆开则开屏插件没音效可配＝半个功能；且 soundThemes 与 UI 槽位完全解耦、工程独立不拖累别期。
6. **推进方式**（元决策，建议先议）

   - ⭐ 建议：**b**——M1 为纯移植（三页 factoryRole 化＋数据命令＋menuItem 补 icon＋窗控顺序配置），六条开放问题全部压在 M2–M4、无一阻塞 M1；M1 动工不等于代拍板。

## 九、终态自检：对照六条工程原则

> 结论先行：本提案不是在既有原则之外新增目标，而是这些原则的**必然推论**；同时给每条原则配机械护栏，防止「自由化」反噬原则本身。反向判据：若某个槽位化方案要违反下表任一格（例如靠双份实现才能换皮），方案错、原则不让步。

| 原则 | 现状已达标 | 缺口 | 提案如何让它更成立 |
|------|------|------|------|
| 高内聚低耦合 | 壳想池画（状态/渲染分离）· 命令双通道 · PoolLayout 单一推送面 | 下拉三族并行 · 壳三页取数散在 hooks · 加载态多套 | 每张脸收敛为「数据命令＋槽位渲染＋注册仲裁」三件套；插件与壳的耦合面收窄到契约 |
| AI 友好化 | 硬约束 26 · 命令带 meta · ai-bridge/linkdeskctl/MCP · AI 手册随包发货 | 槽位本身无命令（候选/切换/回退） | §3.8 新面同笔出命令＋候选门禁腿「有槽位必有切换命令＋数据命令」 |
| 归一化 | E5.8 基建 · L9 `@linkdesk/ui` 单实例 · 通知面唯一 · MenuRegistry 槽位表 | 一类多实现残余（下拉/骨架/取数） | 铁律 A 把取数归一到命令；槽位总线把「脸」归一成一种机制 |
| 万物皆可插件 | 核心空壳 · 单等级插件 · 设置/市场已是普通插件 · 核心无知原则 | §二 14 项写死面 | L2–L5 五贡献点逐项消化；官方件吃狗粮转内置插件（§3.3） |
| 无硬编码 | 硬约束 1/10/12 ＋ R1/R5 对账 | 窗控三键 JSX 写死 · BootMark 唯一资产与壳三页取数端点写死 · OS seed 两档 | 连壳自家的脸也走声明（factoryRole/configuration）——壳给自己开的例外口子全部关闭 |
| 无死代码 | jscpd 零克隆 · knip · dead-css 审计 · L9 导出只加不删 | 换皮后的风险：内置体与插件体双份并存＝克隆温床 | 官方内置页转内置插件走同一渲染通路（不保第二套实现）；R4「第二份实现」门禁盯槽位 |

**终态一句话判据**：改完之后，`src/core/` 里不再有任何一张「具体的脸」——只剩桌子（命令本/注册本/配置本）；B79「卸载所有插件还能用」与其反命题「任何一张脸都能被卸下换掉」同时成立。
