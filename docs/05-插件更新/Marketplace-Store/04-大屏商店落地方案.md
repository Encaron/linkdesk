## 〇、一句话

**把市场插件那张孤零零的 `entry` 页面，直接改造为大屏商店页**——换的是**内容**，不是**机制**（它本来就已经是一个主区标签页）⇒ **零壳改动**。

---

## 一、起点：那页是什么、为什么说它「孤零零」

| 事实 | 读数 / 出处 |
|:--|:--|
| 它是市场插件的 `entry` | `plugin.json` `"entry": "src/index.tsx"` → 产物 `index.bundle.js`，**483 字节** |
| 内容 = 一张指路牌 | `🧩` ＋「插件管理」＋「已安装 N 个插件」＋「在左侧侧栏中浏览和管理插件。点击插件可查看详情。」 |
| 它在主区标签页形态**能**渲染 | 2026-10-05 实测：`linkdeskctl open-tab marketplace` 开出一张全视口页面 |
| 但 GUI 里**零入口** | 顶栏图标走侧栏（`src/App/tabActions.ts:49`：仅在 `tabBar && !sidePanel` 时开标签页；本插件 `sidePanel: true` 且未声明 `tabBar`）；欢迎页 / `[+]` 菜单 / 命令面里都没有它 |
| 它连「可开为标签页」**名单**都进不去 | `getTabOpenableViews()` = `appearsIn.tabBar === true && !!entry`（`src/pluginLoader/contributions/viewRegistry.ts:152`）——未声明 `tabBar` ⇒ 不在名单 |
| 它唯一的门 = **软件外那条** | `tabs:create` 通道**不查** `appearsIn`（`src/core/services/plugins/IpcBridgeHandler/tabs.ts:27`：只要求 `type` 非空）⇒ 只剩 CLI / MCP / 别的插件直接 `tabs.create("marketplace")` |

**判据（可复用）**：一个插件**能不能开成标签页**，硬判据只有一条——**有没有可渲染的 `entry`**。`appearsIn.tabBar` / `standaloneOpenable` 只管 **GUI 的展示与创建菜单**，与「开不开得出来」无关。「名单门」与「创建通道」之间这道缝是**必要**的（file-tree 正是靠它才能以标签页形态打开），代价就是会出现**没有 GUI 入口的表面**——本页就是今天的那一个。

---

## 二、为什么「改造它」= 零壳改动

链已经全通，一个字节的壳代码都不用碰：

- **壳 → 池**：`tabs.create("marketplace")` → 池按插件 id 加载 `entry` → 全视口主区标签页（今天已如此）。
- **容器全免费**：标签页 = 通用表面容器 ⇒ 宽屏 ／ 右键「在悬浮面板中打开」／ 拖出独立窗（落位口径见 [00-README](00-README.md) §容器）。
- **props 契约不变**：`{ tabId, sourceId, isActive }`——**统一嵌入模型**，插件不知道自己被放进哪个 Zone ⇒ 大屏与侧栏视图可以共用同一批组件。
- **数据链已有**：市场插件的共享 chunk（`index-*.js`，全局一份）里已含 catalog 抓取 ＋ `ldk-market-catalog:v1:` 本地缓存 ＋ 已装/探索状态，侧栏 5 个视图共用它 ⇒ 大屏照同一写法消费即可，**不需要任何新壳 API**。
- **不新增表面**：大屏**不是**新构建表面，它就是把现有 `entry` 表面换内容——插件产物仍是 8 个表面（v1.1.7 读数），共享 chunk 仍是一份。
- **硬约束 10 不破**：壳只认 `factoryRole: "marketplace"` 角色牌，不认识插件 id。

## 三、要补的三样（全部落在插件仓）

| # | 补什么 | 怎么补 | 动谁 |
|:--:|:--|:--|:--|
| 1 | **GUI 的入口** | 侧栏某个视图里加一个「浏览商店」按钮 → `tabs.create("marketplace")`；**或**在 `plugin.json` 声明 `appearsIn.tabBar: true`（可选再加 `standaloneOpenable: true`）——后者会**自动**进欢迎页开始卡 ＋ 标签栏 `[+]` 菜单 | 纯插件（代码 / `plugin.json` 数据） |
| 2 | **命令面的入口** | `contributes.commands` 加一条（例：`marketplace.openStore`），handler 内 `tabs.create("marketplace")` | 纯插件 |
| 3 | **点卡片弹详情** | 卡片点击 → `tabs.create("plugin-detail", { pluginId, marketEntry, pinned })`——**现成先例**：侧栏 `UninstalledListView` 今天就这么写（[10 §二](../../02-Electron架构/插件生态与发布/03-插件市场/10-市场UI拥有权.md)） | 纯插件（零新机制） |

**声明 `tabBar: true` 的副作用（都是想要的）**：

- 它进入 `getTabOpenableViews()` ⇒ 悬浮面板的「open-in」这类**能力**消费方开始认它（正好对上 00-README 那句「右键在悬浮面板中打开」）；
- ⚠️ **顶栏图标点击仍然进侧栏**（`tabActions.ts:49` 的规则是 `sidePanel` 优先）⇒ 「一个竖向、一个大屏」的双形态天然成立，不需要任何「模式切换」代码。

## 四、非鼠标路径（本档补上旧档缺的那条）

**现状**：这页今天**只有**软件外一条门（`open-tab marketplace`）。改造时**必须同笔补上命令**，否则只是把一个「只有 AI 开得出来」的表面，换成内容更丰富的「只有 AI 开得出来」的表面。

| 门 | 入口 | 改造后 |
|:--|:--|:--|
| ① GUI | 侧栏按钮 ／ 欢迎页开始卡 ／ `[+]` 菜单 | §三·1 补齐 |
| ② 命令面 | `linkdesk.commands.executeCommand("marketplace.openStore", undefined)` | §三·2 补齐 |
| ③ CLI / MCP | `linkdeskctl exec marketplace.openStore` | **自动**——插件把动作注册成命令即进 CLI/MCP 工具清单（[07-如何接入 §八 边界 3](../../07-AI操作手册/07-如何接入.md)） |

**纪律依据**（硬约束 26，2026-09-29 立）：① 每个用户动作至少一条非鼠标路径；② 业务动作注册为命令，meta **必带 `description` ＋ `params`**；③ 达标 = 结构化操作（读状态 → 调命令带参 → 读结果）；④ 验收同样与物理指针无关。机械自查 = `npm run audit:plugin-commands`（**只报不拦**，⛔ 不进 `check`）。

**验收配方（读 → 调 → 读）**：

```bash
linkdeskctl tabs                                  # ① 读现状
linkdeskctl exec marketplace.openStore            # ② 调命令
linkdeskctl tabs                                  # ③ 回读——大屏标签页在，即生效证据
```

## 五、必须先拍的空白：图标与回落

- **图标来源** = catalog（`marketplace.json`，插件自己拉 ＋ `ldk-market-catalog:v1:` 本地缓存），侧栏各视图已按这条链取到图标与描述文字 ⇒ 大屏复用同一条链。
- 🔴 **空白**：**已安装但不在任何目录里的三方插件没有 catalog 条目** ⇒ 取不到图标。做「已装」网格前**必须先定一条回落规则**（读插件自带 `manifest.icon`？纯色块占位？），否则网格里会出现破图。
- ⚠️ 顺手清账：现有 `entry` 页里那个 `🧩` 是**写死在组件里的**（不是回落机制）——换网格时一并清掉，别把它当成「没有图标就显示 emoji」的先例。
