# 用户机落点规范

> **这份规范管「用户机上东西放哪」——与《[壳目录规范.md](壳目录规范.md)》对称**：那份管「源码仓里文件放哪」，这份管落点。
> **缘起**：2026-10-02 用户拍板（原话「linkdesk 在用户那里，哪些东西该放在哪里必须心里有数，**坚决禁止乱放**……**需要一个任务**」）。
> **立项与逐条执行规格**在 [发版后问题台账.md §六](../04-软件更新/已落地/安装界面自绘/发版后问题台账.md)；本文件是那节的**正式契约**（对外——第三方作者与换机器的人要看）。
> **机械腿**：`scripts/check-install-surface.mjs`（挂 `npm run check`）。**规范写在这里，判据跑在那里，两边不一致 = 门禁会红。**

## 〇、管什么 / 不管什么

**管**：本软件往用户机上**留下的东西**——目录、文件、注册表键、快捷方式、PATH 改动。
**不管**：① 源码仓内部布局（→ [壳目录规范.md](壳目录规范.md)）；② 用户在**软件里自选**的路径内容（装哪个目录、缓存放哪——选择权在用户，规范只管**默认落点**与**标准位**）；③ 第三方插件自己的落点（各插件仓自管）。

🔴 **一条判据先立稳**：`%APPDATA%\linkdesk`（＝ Electron `userData`）**是规范落点，不是「到处飞」**。规范要治的是**规范位之外的野落点**，不是把 userData 也搬走。

## 一、什么叫「落点」

任何**在用户机上留下痕迹**的动作，都产生一个落点：

| 形态 | 例子 |
|:--|:--|
| 写盘（目录 / 文件） | `userData` 下的设置、插件、缓存、热退备份、诊断日志 |
| 写注册表 | 卸载项（ARP）、`ProgId`、右键菜单、`RegisteredApplications`、PATH 尾巴 |
| 建快捷方式 | 开始菜单 · 桌面 |
| 改环境变量 | `HKCU\Environment\Path` 追加安装目录 |

## 二、现状总账（实机普查 · 2026-10-02）

> 普查方法（可复现）：`%APPDATA%` / `%LOCALAPPDATA%` / `%USERPROFILE%` / `Local\Programs` / `ProgramData` 逐层列 `*linkdesk*`；`Local\Temp` 列 `linkdesk*`；源码侧 grep `RegCreateKeyExW|RegSetValueExW|HKEY_CURRENT_USER|app.getPath|GetTempPath|KnownFolder` 全量对账。
> **合计 13 处**（数据与配置 4 · 注册表 7 · 临时 2）。🔴 用户初估「5 处」**偏少**——按目录数确实只有 5 处量级，但注册表键一处一个，加起来是 13。

### A．数据与配置——应留（4）

| # | 落点 | 内容 | 判定 |
|:--:|:--|:--|:--|
| 1 | `%APPDATA%\linkdesk\` | 设置 / 插件 / 布局 / Chromium 缓存 / 更新缓存 / `ai-bridge.json`·`.token` / `hot-exit\` / `appearance\` / `protocol-debug.log` / `tmp\` | ✅ 合规——Electron **userData** 规范落点 |
| 2 | `…\Start Menu\Programs\LinkDesk.lnk` | 开始菜单快捷方式 | ✅ 合规（修卸载项后**同目录再加一条卸载项**） |
| 3 | 桌面 `LinkDesk.lnk` | 桌面快捷方式 | ✅ 合规 |
| 4 | 安装目录（默认 `%LocalAppData%\Programs\linkdesk`，**用户可改**） | 程序本体 ＋ 卸载器副本 | ✅ 合规 |

### B．注册表——应留（7）

| # | 键 | 内容 | 判定 |
|:--:|:--|:--|:--|
| 5 | `HKCU\Software\LinkDesk\`（含 `\Capabilities`） | `PathAdded`/`PathBackup`、能力声明 | ✅ |
| 6 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\{…}` | ARP 卸载项（「设置→应用」里那条） | ✅ |
| 7 | `HKCU\Software\Classes\LinkDesk.Document\` | ProgId ＋ `DefaultIcon` ＋ `shell\open\command` | ✅ |
| 8 | `HKCU\Software\Classes\<各扩展名>\OpenWithProgids` | 「打开方式」候选 | ✅ |
| 9 | `HKCU\Software\Classes\*\shell\<键>` 与 `Directory\shell\<键>` | 右键菜单 | ✅ |
| 10 | `HKCU\Software\RegisteredApplications` | 注册应用（默认程序页） | ✅ |
| 11 | `HKCU\Environment\Path` | PATH 追加安装目录 | ✅（🔴 值类型曾是 `REG_SZ`，已按台账 §三 #1 修回 `REG_EXPAND_SZ`） |

> 🔴 **全部 HKCU**——per-user 安装、免提权，**永不写 HKLM**（`check-install-surface` 的 R4 守这条）。

### C．临时——必须清干净（2）

| # | 落点 | 判定 |
|:--:|:--|:--|
| 12 | `%TEMP%\linkdesk-bootstrapper-<pid>\`（含 `.wv2data`） | 🔴 历史 bug：每次装/卸留一个（台账 §五 H，已修） |
| 13 | `%TEMP%\linkdesk-7zl-<pid>.txt` / `linkdesk-7zx-<pid>.txt` | ✅ 已正确清理——**H 照它写** |

### D．不属于本软件 / 一次性残留（不计入 13）

`%APPDATA%\Temp`（空壳，本仓零处写此路径）· 清理时 AI 留的回滚备份目录。

### E．开发机专有（不进用户机，不计入）

`E:\linkdesk`（源码）· `E:\linkdesk-build` · `E:\linkdesk-build+scratch` · `E:\linkdesk-plugins`。

## 三、五条铁律（契约本体）

1. **一处用途只有一个落点**——同类数据 ⛔ 不许出现第二处。「这里也放一份」＝ 违规。
2. **每个落点必须有归属**：**谁写 / 谁删 / 卸载时怎么处置**，三者缺一不许上架。
3. **临时文件必须清干净**——退出时清；清不动的（进程占用）**下次启动兜底清**。
4. **新落点必须先登记**——任何新增「写盘 / 写注册表 / 建快捷方式」的代码，**先在本总账登记一行**再落代码；**未登记 = 机械门禁判红**。
5. **只许用标准位**——`%APPDATA%` / `%LOCALAPPDATA%` / `%TEMP%` / 已知文件夹 API；⛔ 禁止自造路径（反例：`%APPDATA%\Temp`）。

## 四、机械门禁：`scripts/check-install-surface.mjs`

```bash
node scripts/check-install-surface.mjs             # 真跑（挂 npm run check）
node scripts/check-install-surface.mjs --self-test # 尺子自测（正控绿 / 负控红）
```

| 判据 | 拦什么 |
|:--|:--|
| **R1** | **出厂件里的开发机绝对路径**——扫描域内出现盘符绝对路径字面量。注释不算；测试与 fixture 不算（硬约束 21：fixture 一律虚构值） |
| **R2** | **自造落点**——`%APPDATA%` / `%LOCALAPPDATA%` / `%TEMP%` 一类字面量必须整体命中 `SURFACE_ALLOW` 某条已登记落点 |
| **R3** | **`app.getPath(<键>)` 的键必须已登记**——今天只登记了 `userData`；多一个键 = 多一处落点 |
| **R4** | **注册表写调用不得碰 HKLM**（本行或前 5 行内出现 `HKEY_LOCAL_MACHINE` / `HKLM`） |
| **R5** | **登记表自洽**——每条必填 `path` / `who` / `uninstall` / `reason`（铁律 2 的机械形态） |
| **R6** | **豁免账本不得腐烂**——豁免挂的片段在文件里找不到 ⇒ 报「过期豁免」逼对账 |

**扫描域** = `src/` · `electron/` · `build/installer/`（用户 2026-10-02 拍板＝**只扫壳仓**）。
**域外（有意）**：`build/installer/bootstrapper/tools/`（CI/开发脚本，本就该指着本机仓库跑）· `__tests__/` `__fixtures__/` · `*.test.*` `*.spec.*` · `out/`。
⚠️ **R4 认不出「参数化的 hive」**——hive 存进变量再传给写函数时它看不到；那一路的强判据在 CI 侧（`tools/uninstall-test.ps1` 装前全量快照 ＋ 逐条对账）。

**豁免账本**（`ABSOLUTE_PATH_EXEMPT`）＝ 已复核过的「绝对值字面量，但它不是落点」。今天 4 条（git-bash 探测候选 / 系统目录黑名单 / `System32\reg.exe` 防劫持 / 安装器错误提示里的举例文案）。
🔴 **不许为了凑绿往里塞条目**——塞进去的每一条都是一个**没人再看着的绝对路径**。

## 五、新增一个落点，怎么走

1. **先问能不能不落**——能塞进已有的登记落点（`userData` / 安装目录 / 临时）就塞进去。
2. **真需要新落点** → 在本文件 §二 总账**加一行**，并在 `check-install-surface.mjs` 的 `SURFACE_ALLOW`（或 `APP_GETPATH_KEYS`）**同步登记**——四个字段都要：谁写 / 谁删 / 卸载怎么处置 / 为什么。
3. **再落代码**。门禁会替你守住：没登记的新落点当场红。
4. **写在 `%TEMP%` 的临时件**：文件名必须带 `linkdesk-` 前缀，且**退出时清、下次启动兜底清**。

## 六、卸载对称性（验收口径）

🟢 **判绿**：全新无缓存机器装一次 → 按 §二 总账**逐处核对**，**总账之外零新增**；卸载一次 → 除「保留用户数据」那一处（`%APPDATA%\linkdesk`，用户在卸载屏选「彻底删除」时才清）外，**目录 / 快捷方式 / 注册表键 / PATH 尾巴全部消失**。
🟢 装→卸→装三个来回后，`%TEMP%` 里 `linkdesk-bootstrapper-*` **数量为 0**。
