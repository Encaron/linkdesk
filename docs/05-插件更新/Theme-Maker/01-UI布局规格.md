# 01 — UI 布局规格

> **类型：市场插件** | **05-出厂制造 #07** | 2026-07-28。**主题制作器——遵循 LinkDesk 侧栏/主区架构。**
> 设计系统来源：`ui-ux-pro-max` → Vibrant & Block-based + 属性面板 UX 模式
> 原 `02-主题制作器.md` 是概念草图——此文档是完整 UI 重设计。
> **AI 是独立插件——不在本插件内。** AI 插件通过 `executeCommand` 操作本制作器的色键。
> 🎨 **交互预览：** [theme-maker-preview.html](theme-maker-preview.html) 在浏览器查看效果
> ⚠️ **多 WebView：** 浮层和标签页是独立渲染上下文。切换时当前编辑的主题数据（33 色键值）存在于共享 Store（`PluginStateService`）而非组件 local state——浮层改了色 → 点"在主窗口中打开"→ 浮层销毁 → 标签页打开 → 读同一份 Store → 数据无缝延续。不靠"转移"，靠"同一份数据两个视图"。

## 一、架构决策——重的放主区，轻的放侧栏

阅读 `src/components/SidePanel.tsx` 和 `src/components/MainContent.tsx` 后明确：

```
LinkDesk 布局模型：
  图标栏(42px) → 侧栏(220px, 贯穿上下, 侧栏内容跟着图标栏切换)
               → 主区(标签页, 持久存在)
```

**侧栏是临时的——** 点图标栏的不同图标，侧栏内容切换。如果 33 个色键的调色面板放在侧栏里，用户点别的图标回来——所有编辑状态丢失。这是灾难。

**主区标签页是持久的——** 主题制作器应该在这里。对标 VS Code：编辑器是重的，侧栏文件树是轻的。

| 位置 | 内容 | 重量 | 理由 |
|------|------|:--:|------|
| **主区标签页** `index.tsx` | 调色面板 + 实时预览 | 🔴 重 | 33 个色键是核心编辑区——必须在持久标签页内 |
| **侧栏** `sidebar.tsx` | 主题列表 + 导出 + 新建/导入 | 🟢 轻 | 只是一个列表——点图标栏切走不影响工作 |

**读代码确认的交互：**
- 用户点图标栏 🎨 → 侧栏出现主题列表（`sidebar.tsx`，由 `SidePanel` 渲染，`lastSidebar` 记住状态）
- 侧栏点某个主题 → `activateSidebarItem(tabActions, themeName, "theme-maker")` → 主区聚焦/创建主题制作器标签页
- 主区标签页内——左栏调色，右栏预览，顶栏保存/新建/导入
- 用户点别的图标栏图标 → 侧栏切走（比如切到文件树）→ 主区主题制作器标签页**不受影响**——色键编辑状态完全保留

## 五、33 个颜色键分 9 组（在标签页左栏内）

| 分组 | 可折叠 | 色键 |
|------|:--:|------|
| **主题信息** | ❌ 始终展开 | 名称（text input）、类型（dark/light 下拉） |
| **窗口/背景** | ✅ 默认展开 | `bg-window` `bg-card` `bg-input` `bg-icon-bar` `bg-side-panel` `bg-toolbar` `bg-status` (7) |
| **文字** | ✅ 默认展开 | `text-primary` `text-secondary` `text-muted` (3) |
| **强调/交互** | ✅ 默认展开 | `accent` `accent-hover` `icon-active` `icon-inactive` `toggle-knob` `dirty-dot` `hover-overlay` (7) |
| **边框/分隔** | ✅ 默认折叠 | `border` `separator` (2) |
| **状态** | ✅ 默认折叠 | `status-connected` `status-disconnected` (2) |
| **标签页/拖放** | ✅ 默认折叠 | `tab-hover-bg` `drop-indicator` (2) |
| **滚动条** | ✅ 默认折叠 | `scrollbar-thumb` `scrollbar-thumb-hover` (2) |
| **日志/数据** | ✅ 默认折叠 | `system-log` `sent-echo` `received` `cm-timestamp` (4) |
| **阴影** | ✅ 默认折叠 | `context-menu-shadow` `drag-preview-shadow` (2) |

**共 33 个色键。** 色键行格式：label(11px mono) + hex(11px mono 右对齐) + 色块(16×16px, 点击弹出 ColorPicker)。

## 六、与 AI 插件的关系

**AI 是独立插件——不在本制作器内。** 关系如下：

```
AI 插件（plugins/ai/）
  │
  │  executeCommand("theme-maker.setAllColors", { colors: {...} })
  │  executeCommand("theme-maker.setColor", { key: "accent", value: "#C8A42A" })
  │
  ▼
主题制作器（plugins/theme-maker/）
  │
  │  registerCommand("theme-maker.setColor", ...)
  │  registerCommand("theme-maker.setAllColors", ...)
  │
  ▼
标签页左栏色键更新 → 右栏预览即时显示
```

AI 生成主题 JSON → 调用 `theme-maker.setAllColors` → 色键自动填入 → 用户在制作器中微调。

## 七、状态矩阵

| 状态 | 触发条件 | 视觉表现 |
|------|------|------|
| 新建空白主题 | 侧栏/顶栏点"新建" | 新标签页 + 所有色键 = 默认灰值 + 名称 "未命名主题" |
| 编辑已有主题 | 侧栏点主题名 → 主区加载 | 标签页加载色值 + 预览区即时显示 |
| 改色值——即时预览 | 点色块 → ColorPicker → 选色 | 预览区即时更新——不弹确认 |
| 改色值——Esc | ColorPicker 中按 Esc | 色值恢复改之前——预览区同步恢复 |
| AI 填入色值 | `theme-maker.setAllColors` 被调 | 左栏色键全部更新 + 预览更新 |
| 保存 | 顶栏 [保存] / Ctrl+S | 写入 JSON → dirty 标记清除 |
| 导出 | 侧栏 [导出选中] | 生成 zip → 下载 |
| 名称冲突 | 保存时名称已存在 | 自动加 " - 2" 后缀 |
| 导入 JSON 格式错误 | JSON 解析失败 | toast "文件格式不正确" |
| 切图标栏 | 点别的图标 → 侧栏切走 | **主区标签页不受影响——色键状态保留** |

## 八、文件结构

```
plugins/theme-maker/
├── plugin.json              ← sidebar: "sidebar.tsx", entry: "index.tsx"
├── resources/icon.svg
└── src/
    ├── index.tsx            ← 主区标签页——双栏布局（调色面板 + 预览）
    ├── sidebar.tsx          ← 侧栏——主题列表 + 新建/导入/导出
    ├── ColorPanel.tsx       ← 标签页左栏——33 色键分组列表
    ├── ColorKeyRow.tsx      ← 单行色键组件
    ├── PreviewPane.tsx      ← 标签页右栏——壳窗口缩略图实时预览
    ├── commands.ts          ← 注册 theme-maker.* 命令（供 AI 插件调用）
    └── ThemeMaker.css
    └── themes/              ← 本地保存的主题 JSON
```
