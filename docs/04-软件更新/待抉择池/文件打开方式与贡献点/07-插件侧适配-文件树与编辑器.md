## 二、编辑器适配格（E1–E4 定稿）

> 一句话：编辑器从「什么文件都硬吃」变成**打开方式体系里的一个普通参与者**——文本类仍归它（它声明的），二进制不再硬解成乱码，兜底位从「写死的名字」变成「它声明的一个角色」。

**三重身份（先想清楚再动码）**：① 45 个文本扩展名的**持有者**——是**声明**不是特权，第三方可声明同名扩展名竞争（D7 仲裁）；② 兜底位的**当前承担者**——今天是因为壳 `DEFAULT_TAB_TYPE="editor"` 写死了它（证据⑧），T7 后这个身份来自它**声明 `role:"text-fallback"`**，第三方编辑器声明同角色即可整体接管；③ 兜底呈现的**参考实现者**——「这是二进制」**判定归壳**（`EncodingService.isBinary` 一处真相源），「警告怎么画」**归被兜底的插件**（编辑器也只是方式之一，警告归它自己弹）。

## 五、先后顺序与并行判断（回应「这两个该何时做、能不能并行、要不要和壳一起」）

**依赖阶梯**（下层等上层）：

```
第 0 层 · 壳面（住壳仓，⛔ 同一条提交线 ⇒ 只能串行）
  T1 isBinary＋files IPC ──▶ T7 role ──▶ T2 listHandlersFor／resolveOpenTarget／覆盖表键
                              T3 resourceExtname 账 · T5 菜单规范（与上面三格独立，可插）
第 1 层 · 两插件适配（各自仓，吃对应壳面）
  editor   E1（吃 T1）→ 第 1 波     E3（吃 T7 的 schema）→ 第 2 波
  file-tree F2/F4（吃 T3/T5）→ 第 2 波   F1/F3（吃 T2）→ 第 3 波
第 2 层 · 四只阅读器（05 蓝图）
  PDF／图片：零依赖 —— 任何时刻可立项（连壳案都不阻塞它们的 MVP）
  MD：吃 T3（when 条件）＋编辑器 E2（同屏契约）⇒ 等第 2 波 ＋ MD 立项时两仓对契约
```

**并行判断**：

- **两插件工程本身互不冲突**（两仓两套代码、不同壳面），但**都吃同一条壳仓提交线**，且各自依赖的壳面落在不同波 ⇒ **按六波串行走，不另开并行**（省钱默认＝串行，[交接 §二](交接.md)）。
- **⛔ 不建议把 file-tree 提前**：它的主战场（F1 选择器）吃 T2，T2 之前没有数据面可吃，提前只换来重写。
- **⛔ 不建议把 editor 推后与 file-tree 合波**：E1 吃 T1（第 1 波就有），且 E1 是**现存 bug 的正面修复**（pdf/exe 开成不报错乱码），越早越好。
- ⇒ 「**和壳一起完成**」的正确形态 = **波内成对**：每波 = 壳面 ＋ 插件消费 ＋ 插件发版走同一条链（细节见 [交接 §一](交接.md)），**不是**把两插件攒到最后统一做。

## 六、发布与验收口径（2026-10-05 用户拍板 · 修正 05 旧口径）

⛔ **壳与安装版不发版**（全程 dev 验收）；🟢 **npm 包与插件仓做完即发**（官方目录收录确认＝唯一验收，用户能点升级）。由此产生**两条硬规矩**：

1. **旧壳特性降级是发布前提**：插件侧凡消费新壳面的格，必须**先特性探测、旧壳上退回今日行为**，⛔ 不得出现「市场能升级、升完就报错/留死项」。
   - **E1**：`lk.files?.isBinary` 缺失 ⇒ 走今日的纯文本路径（乱码照旧，但不是新引入的 bug）；「打开方式…」钮 T2 未落地前隐藏。
   - **F1**：宿主无 `listHandlersFor` ⇒ 维持占位行为或不显示该项，⛔ 不留「点了就报错」的菜单项。
   - **取证依据**：壳运行时**不跑** `plugin.schema.json` 校验（`src/pluginLoader/contributions/contributions.ts:54` 原话「只喂**作者侧**校验器（SDK `validate.ts`）」；`src/pluginLoader/discovery/manifest.ts` 只校 `pluginId`/`version`/`name`）⇒ **旧壳忽略未知字段**（如 `role`），字段只是闲置、不致命。
2. **E3 的发布门槛在 SDK schema，不在壳发版**：editor 补上 `role` 后，其**自家 CI**（SDK `validate.ts` 读包内 schema 副本）会校验 `fileAssociations[].role`——故须等第 2 波的 schema 四拷贝落地、SDK 版本被插件仓收录后，editor 才能过 CI 发版；壳侧发不发版不影响该字段是否安全（旧壳忽略它）。
3. **CHANGELOG 注记**：每笔插件发版照 `settings 1.0.29` 先例记「**可见变化待壳发版**」——壳侧攒批未发期间，新壳能力**无人消费**，如实记，⛔ 不谎报「已可用」。
4. **验收**：dev 版目视（第 1 波＝pdf 单击见提示块＋toast 不再乱码；第 3 波＝右键选择器可点、三入口行为一致）＋ editor/file-tree 仓**市场可点升级＋官方目录收录确认**。
   ⚠️ 05 旧稿写的「壳侧攒批未发版期间 E1/E3 的**插件版先不发**」**已作废**——现行口径是**照发**（用户 2026-10-05 拍板），靠上述特性降级保安全。

## 七、勘误：`ext` → `extension`（在案文档的实键写错，同笔修正）

`schema` 与壳加载器读的都是 **`extension`**（不带点，如 `"pdf"`）：`packages/plugin-sdk/schemas/plugin.schema.json` 的 `fileAssociations.items.required = ["extension"]`；`electron/plugins/plugin-manifest-loader.ts` 也按 `fa.extension` 注册。**旧文档写的 `"ext"` 是错的**（已同笔修正 [01](01-方案与落点契约.md) 的结构图、[05 PDF 阅读器](../../../05-插件更新/PDF阅读器插件/00-README.md)、[05 图片阅读器](../../../05-插件更新/图片阅读器插件/00-README.md) 三处）——新写声明照 `extension`。
