> **为什么存在**：本面与多表面状态塌缩**是两个问题**（12-立案 §2026-09-30 补：⛔ 不并案）——插件升级后磁盘文件已换，但池按 URL `import()` 表面 bundle、**同 URL 不随磁盘替换重载** ⇒ 升级须重启才生效。归属 = 加载器优化域。

## 一、问题一句话

插件升级（官方目录收录 → 用户点更新 → 文件落盘）后，池对同一渲染 URL 的 module cache 不失效——用户看到的仍是**旧代码**，直到重启软件。

## 二、一条可达的缝

缓存键 = 表面 renderPath 的 **URL 字符串**（含 `?t=` 时间戳参数——版本变化的唯一信号源），而「升级完成后」没有任何人去 bump 这个键：没有「版本变了 ⇒ URL 变」的接线，也没有「模块缓存失效」的钩子。

## 三、两案候选（未拍板）

| 案 | 做法 | 代价 |
|---|---|---|
| **A：URL 带 version 查询参** | renderPath 追加 `?v=<plugin.json.version>`——升级 = 版本号变 = URL 变 = module cache 天然失效（browser 级机制，零缓存失效代码） | renderPath 构造点改造＋缓存/参照面全部过一遍（Vite dep cache 烤路径教训见 memory `vite-dep-cache-bakes-plugin-paths`） |
| **B：更新完成后主动失效** | 升级流水线终点对受影响 URL 调模块缓存清理 / 提示用户「重启生效」 | Electron renderer 的动态 import 无标准失效 API——大概率仍落到「提示重启」 |
