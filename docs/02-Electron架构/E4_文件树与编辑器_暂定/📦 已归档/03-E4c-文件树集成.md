# E4c — 文件树集成接口

> 2026-07-25。**5 任务，~260 行。** 🔥 文件树最重要的部分——跨插件命令 API + FileDecorationProvider + revealInExplorer。
> **这是"公共契约"。** 设置、Git、AI、智能体都调这些 API。设计错了 → 所有调用方跟着改 → V2.6 的根因。
> **性质：** 纯插件代码。不碰 `src/`。

---

## 一、定位

E4a 文件树能看了。E4b 能操作了。E4c 让它能被**其他插件调用**。

文件树不是孤立的功能——它是平台的"文件入口"服务。其他插件通过命令系统调用它。这 5 个任务定义的是文件树对外的**公共 API 契约**。

---

## 二、🔥 API 契约——为什么这是最重要的部分

```
设置 "在文件中显示" → executeCommand("revealInExplorer", { filePath })
Git checkout       → executeCommand("explorer.refresh")
                    → FileDecorationProvider.provideDecoration(uri) → 文件显示 M/A/D
AI "打开目录"       → executeCommand("revealInExplorer", { filePath, focus: true })
智能体 "新建配置"    → executeCommand("explorer.newFile", { dirPath, name: "config.json" })
```

**如果 revealInExplorer 的参数签名变了，设置插件和 AI 插件全部要改。** 如果 FileDecorationProvider 的接口变了，Git 插件要改。这些是跨插件的硬依赖——和壳的 `tabActions.createTab()` 同级。

```typescript
// FileTree.tsx 中的 handleOpenFile()
async function handleOpenFile(item: ExplorerItem, mode: 'preview' | 'pin'): Promise<void> {
  if (item.isDirectory) {
    model.toggleExpand(item);
    return; // 目录不打开编辑器
  }

  const ext = item.name.includes('.')
    ? item.name.substring(item.name.lastIndexOf('.'))
    : '';

  const pluginId = FileAssociationService.getPluginFor(ext);

  if (pluginId) {
    // 🔥 有注册的编辑器 → 直接打开

      filePath: item.uri,
      mode, // 'preview' = 斜体标签页（单击），'pin' = 正体（双击）
    });
  } else {
    // 无关联编辑器 → "打开方式…" 选择器
    showOpenWithPicker(item);
  }
}
```

### #104 revealInExplorer——🔥 公共 API 核心（~60 行）

```typescript
// 🔥 类型定义位置：plugins/builtin/file-tree/src/commands.ts（file-tree 插件内——文件树是唯一消费方）
// ⚠️ E4b #99i 勘误：原文档写 src/core/types.ts，但该文件在 E4 时代不存在。
//    圆形大厅原则——不为此 API 新建核心文件。类型放 file-tree 插件内，
//    调用方通过 executeCommand 的 args 参数传值——圆形大厅天然隔离，无需共享类型文件。
//    对标 VS Code：IExplorerService 是 Service 上暴露的方法，不是共享类型文件。

export interface RevealInExplorerArgs {
  /** 要定位的文件/目录路径（必填） */
  filePath: string;
  /** 是否聚焦文件树（默认 true） */
  focus?: boolean;
  /** 是否选中文件（默认 true）。false = 只展开不选中 */
  select?: boolean;
}

export interface RevealResult {
  /** 是否定位成功 */
  success: boolean;
  /** 找到的文件 URI */
  uri?: string;
  /** 失败原因——调用方 decide 要不要提示用户 */
  error?: 'not_found' | 'not_in_workspace' | 'excluded' | 'timeout';
}

// 🔥 RevealResult 不暴露 ExplorerItem——只暴露 uri 字符串。
// ExplorerItem 是文件树内部类型，不应泄漏到跨插件 API 契约中。
// 调用方只关心"文件在哪儿"，不关心文件树的内部节点结构。

// commands.ts（file-tree 插件内——仅命令实现，不定义类型）
// 🔥 这是文件树最重要的公共命令。
// 调用方：设置 (settings.json)、Git (文件跳转)、AI/智能体 (定位文件)

registerCommand('revealInExplorer', async (args: RevealInExplorerArgs): Promise<RevealResult> => {
  // 1. 确保文件树的侧栏可见
  await executeCommand('workbench.view.explorer');

  // 2. 🔥 绕过 FileExcludeFilter——对标 VS Code
  //    revealInExplorer 直接调 FileService.exists() + listDir() 定位，
  //    不经过 FileTreeModel。找到后文件树临时展开该目录（不改变永久排除设置）。
  //    对标 VS Code——revealInExplorer 能打开任何真实存在的文件，不管 files.exclude 怎么说。
  const exists = await FileService.exists(args.filePath);
  if (!exists) {
    return { success: false, error: 'not_found' };
  }

  // 3. 逐层展开目录链（绕过排除过滤器）
  const item = await model.findAndExpandToBypassExclude(args.filePath);
  if (!item) {
    // 文件不在当前工作区
    return { success: false, error: 'not_in_workspace' };
  }

  // 4. 选中 + 高亮（持续 2s 的动画高亮）
  if (args.select !== false) {
    treeView.selectItem(item);
    treeView.highlightItem(item, { duration: 2000 });
  }

  // 5. 滚动到可见区域
  treeView.scrollToItem(item);

  // 6. 可选：聚焦文件树
  if (args.focus !== false) {
    treeView.focus();
  }

  return { success: true, item };
});
```

**对调用方的承诺：**
- 文件在工作区内（即使被 files.exclude 排除）→ `{ success: true }`
- 路径不存在 → `{ success: false, error: 'not_found' }`——调用方 decide 要不要提示用户
- 文件在工作区外 → `{ success: false, error: 'not_in_workspace' }`
- AI 批量调用 5 个文件 → 逐个返回结果 → 调用方知道哪个成功哪个失败，不用猜

**不在 v1 暴露的字段：** `revealRange`——v1 不实现文件内行定位就不暴露。以后加字段不 breaking。

### #105 跨插件命令完整注册（~40 行）

```typescript
// commands.ts——除了 revealInExplorer 之外的全部对外命令

// 🔥 以下是文件树的"公共 API"——其他插件/快捷键/菜单通过 executeCommand 调用

registerCommand('explorer.newFile', async (args?: { dirPath?: string; name?: string }) => {
  const dir = normalizePath(args?.dirPath || model.getSelectedDirectory() || model.roots[0]?.uri);
  const name = args?.name || '新建文件';
  const path = joinPath(dir, name);  // 🔥 E4b #99i: 统一用 joinPath，不手写拼接
  await FileService.writeFile(path, '');
  await model.refresh(dir);
  // 自动进入行内重命名模式
  const item = model.findClosest(path);
  if (item) treeView.startRename(item);
});

registerCommand('explorer.newFolder', async (args?) => { /* 同上，调 mkdir */ });
registerCommand('explorer.refresh', async () => { await model.refresh(); });
registerCommand('explorer.collapseAll', () => { model.collapseAll(); });
registerCommand('explorer.openFolder', async () => {
  const result = await showOpenDialog({ properties: ['openDirectory'] });
  if (result) WorkspaceService.addFolder(result);
});
registerCommand('explorer.delete', async () => { /* 删除选中项 */ });
registerCommand('explorer.rename', async () => { /* 行内重命名 */ });
registerCommand('explorer.copy', async () => { /* 复制到剪贴板 */ });
registerCommand('explorer.cut', async () => { /* 剪切到剪贴板 */ });
registerCommand('explorer.paste', async () => { /* 从剪贴板粘贴 */ });
registerCommand('explorer.copyPath', async () => { /* 复制绝对路径 */ });
registerCommand('explorer.copyRelativePath', async () => { /* 复制相对路径 */ });
registerCommand('explorer.revealInOS', async () => { /* Electron shell.showItemInFolder */ });
registerCommand('explorer.openInTerminal', async () => { /* 在终端中打开目录——跨插件调 terminal */ });
```

**🔥 命令 ID 命名规范（对标 VS Code）：**
- `explorer.*`——文件树自己的操作（重命名/删除/新建）
- `revealInExplorer`——特殊：有固定语义，不放在 explorer 命名空间下（对标 VS Code `revealInExplorer`）
- 调用方用的是 `executeCommand("revealInExplorer", ...)`——这是"平台通知文件树去做某事"，不是"文件树的内部实现"

**🔥 接口在核心，不在文件树。** `FileDecorationProvider` 和 `FileDecoration` 类型在 `src/core/FileDecorationRegistry.ts`（E3f #59b 定义）。文件树 `import` 这些类型——不重新定义。如果类型变了，改一个地方（核心），所有消费者和提供方自动同步。

**Git 插件如何使用：**
```typescript
// plugins/git/src/fileDecoration.ts
const provider: FileDecorationProvider = {
  id: 'git',
  priority: 10,
  onDidChangeFileDecorations: gitStatusChangeEmitter.event,
  provideDecoration(uri: string) {
    const status = gitRepo.getStatus(uri);
    if (status === 'modified') return { badge: 'M', color: 'var(--git-modified)', tooltip: 'Modified' };
    if (status === 'added')    return { badge: 'A', color: 'var(--git-added)', tooltip: 'Added' };
    if (status === 'deleted')  return { badge: 'D', color: 'var(--git-deleted)', tooltip: 'Deleted' };
    return undefined;
  }
};
fileDecorationRegistry.register(provider);
```

**🔥 v2 扩展点——多装饰：** 返回值允许 `FileDecoration[]`（v2 行为），但 v1 实现只取第一个。不给未来封死路。如果 Git 说 "M"、ESLint 说 "Error"——v1 只显示优先级高的，v2 可横向合并显示多个标记。

### #107 tabActions 集成——文件树 ⇄ 编辑器双向联动（~40 行）

```typescript
// 🔥 文件树不应该知道"文件是否在编辑器中打开"——这是壳的职责。
// 但文件树可以订阅 CoreEvents 来响应编辑器状态变化。

// 1. 文件树 → 编辑器
//    双击文件 → tabActions.createTab(editorPluginId, { filePath })

// 2. 编辑器 → 文件树
//    autoReveal（对标 VS Code explorer.autoReveal）：
//    当编辑器的活跃标签页切换时，文件树自动定位到对应文件
CoreEvents.onDidChangeActiveTab((tab) => {
  if (tab.payload?.filePath && explorerConfig['explorer.autoReveal']) {
    executeCommand('revealInExplorer', {
      filePath: tab.payload.filePath,
      focus: false,       // 不抢焦点
      select: true,
    });
  }
});

// 3. 预览到固定
//    单击文件 = preview tab（斜体）
//    编辑文件内容 → preview tab 自动 pin（转为正体）
//    对标 VS Code editorGroupModel.ts preview → pin 自动转换
```

## 六、API 稳定承诺

一旦 #104 和 #106 的接口被其他插件调用，**不能 breaking change**。如果要改参数：
1. 旧参数继续支持（deprecated 但不删）
2. 新参数用可选字段追加
3. plugin.json 中声明 API 版本号

**这就是"V2.6 的根因"级别的设计失误区。宁可现在多花 3 小时设计 API 签名，不要未来花 3 天兼容旧调用方。**

## 七、FileDecorationRegistry 的跨消费者架构

`FileDecorationRegistry` 在核心（E3f #59b），不在文件树插件里。这意味着：

| 消费者 | 现状 | 接入方式 |
|---|---|---|
| 文件树 (E4c #106) | v1 实现——渲染时调 `getDecorations(uri)` | 直接注入 |
| 搜索结果 (E4d) | 🔥 v2——匹配文件旁显示 M/A/D | `getDecorations(match.filePath)`，~5 行 |
| 标签页标题 (E4f) | 🔥 v2——标签页标题旁显示 M/A/D | `getDecorations(tab.filePath)`，~5 行 |
| Ctrl+P 文件跳转 | 🔥 v2——文件列表项显示装饰 | `getDecorations(item.uri)`，~5 行 |

**所有消费者都只依赖核心，不依赖文件树插件。** 文件树只是"第一个消费装饰器的地方"，不是"装饰器的拥有者"。这就是 FileDecorationRegistry 放在核心而非文件树的原因。
