## 立案缘起（一句话账）

A1 实机批场景 6「设置标签页拖到主区右半边」自动化失败（事件全到、dragging 态有、但松手不分屏无玻璃预览），测试 AI 上报「纯自动化问题」，最终用户手动补拖 —— **用户质疑这是否就是 AI 不友好**。2026-09-14 四路调查（拖拽实现 / 全软件交互面 / API 面 / 安装包与安装版）结论 = **操作层整体健康、读取层半成品、知识沉淀空白**：标签页拖拽**有直通车**（`core.splitRight` 命令 / `pool.tabAction splitTab`），不友好在「没有时刻表告诉 AI 直通车在哪」；通知按钮剥掉 command/args、`notifications` 无读取面、`pool.onLayout` 状态快照未文档化、安装版更新重启丢 CDP 参数。用户拍板终局诉求：「**一个能够完全自动化的软件**」——本系列即其工程落点。

## 判据摘录（AI 友好四层定稿 · 层 1「运行时操作」，2026-09-14）

**可读**（界面每一处状态有契约级读取路径）· **可操作**（每个用户动作至少一条非鼠标路径；OS 够不着的列册）· **可查**（操作知识有单一真相源文档）。验收锚点 = 用户 toast 例：AI 应清楚通知「位置 / 因为什么 / 内容 / 几个按钮 / 按钮里有什么 / 该执行哪个 / 执行后做什么」。

**2026-09-28 补 · 验收面（§01-设计 §三 末 ＋ §七 第 7 条）**：「软件给不给门」之外补「**验收怎么跑**」——① 🔴 验收回路**必须与物理指针无关**（走命令/API/CLI；hover-only 面用 CDP 强制伪状态，不用真实坐标输入——否则人手一动就抢走 hover/焦点，验收不可复现）；② **dev 验收前置**（硬 reload ＋ 构建握手 ＋ CDP driver 库固化）——**属系列外、不占任务格**，记在 §01-设计 §六 末行。来源 = 04「侧栏 title 右键「视图」子菜单」实修（假阴性误判 ＋ 17 个一次性驱动脚本）。
