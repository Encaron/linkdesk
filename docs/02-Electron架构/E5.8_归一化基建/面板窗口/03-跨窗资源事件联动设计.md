# 03 — 跨窗资源事件联动设计（E5.8#46.2）

> 2026-08-28。**病根：资源身份（sourceId）变更只通知一个窗口。** 用户拍板走通用方案（10 条核心理念逐条对齐见 §七）。本档案 = 设计真相源——代码细节 → 边界 → bug 预案 → 可执行子任务。
> 清单指针：E5.8-执行清单 #46.2（细分子任务见 §八）。前身：#46.12 sourceId 族按来源窗路由（本设计将其 label/close 收缩，留 focus）。

## 一、现状与病根（代码实证）

跨窗资源联动现状 = **两套单发机制，同一疾病**：

| 入口 | 链路 | 只更新谁 | 幽灵场景 |
|---|---|---|---|
| **file: 事件**（文件树） | 文件树 emit `file:renamed/deleted` → 池广播 → [bridges.ts:59-69](linkdesk/src/App/bridges.ts#L59-L69) → shellEvents → [useTabManager.ts:415-437](linkdesk/src/hooks/useTabManager.ts#L415-L437) | **仅主窗** useTabManager | 文件 tab 在脱出窗 → 改名的 tab 标签不迁移 |
| **tabs API**（插件） | 串口等调 `tabs.updateLabelBySourceId/closeBySourceId` → IPC → [tabs.ts:47-56](linkdesk/src/core/services/plugins/IpcBridgeHandler/tabs.ts#L47-L56) → shellEvents → [tabActions.ts:75-77](linkdesk/src/App/tabActions.ts#L75-L77) → [tabCallbacks.ts:484-529](linkdesk/src/App/tabCallbacks.ts#L484-L529) `createSourceIdRouters` | **仅来源窗**（单发路由） | 串口会话在侧栏改名、tab 在脱出窗 → sourceWindowId=main → 主窗无此 tab → 静默 no-op |

**疾病本质**：`sourceId` 是全局唯一资源身份（文件路径 / 会话 id），"资源变更"是**全局事实**——却只广播到一个窗口。任何资源类型（文件/会话/未来设备/数据库连接…）都踩同一个坑。

**关键实证（编辑器插件的自救与缺口）**：[EditorTab.tsx:274](linkdesk/plugins/builtin/editor/src/components/EditorTab.tsx#L274) 在池内直接订阅 `file:renamed`（池广播同进程直达），自迁 EditorModel 内容 + 调 `tabs.updateLabelBySourceId(newPath, ●label)`——但该调用经 `findTabBySourceId` 按**新路径**查脱出窗注册表 tab，tab 的 sourceId 仍是旧路径 → **查无此 tab → no-op**。编辑器内容能更新、标签栏 label 不动 → 幽灵标签。这印证：#46.2 必须由**壳侧全窗广播迁移 sourceId**，插件自救补不上（顺序竞态 + 只改 label 不改 sourceId）。

**editor 的 ● 竞态（既有行为，非本次引入）**：壳迁移（label=basename 无 ●）与 editor 重挂 ●label 先后抵达——若 editor 调用先落（查新路径 no-op），● 暂失；editor 后落则补上。主窗现状同样如此，本次不改变（EditorTab.tsx:252 注释"幂等"即此容忍）。

## 二、方案——windowHost 唯一订阅点 + 纯 reducer 全窗广播

```
                     ┌──────────────────────────────────────────────────┐
  文件树 emit file:* ─┤  bridges.ts（池→壳转 shellEvents，桥不动）          │
                     │                  │                                 │
  插件调 tabs API   ─┤  IpcBridgeHandler → shellEvents                    │
                     │                  │                                 │
                     │                  ▼                                 │
                     │   ★ windowHost 资源广播 effect（唯一订阅点，deps []） │
                     │    每个事件 → 纯 reducer → mapResourceAcrossWindows   │
                     │      ├─ 主窗    → useTabManager 方法（真相源+副作用） │
                     │      └─ 脱出窗   → 注册表 reduce 应用 → updateTabState │
                     │              空窗 → closeWindow（I9-8 空窗自灭）        │
                     │                                                       │
                     │  → windows 变化 → usePoolSync 按窗重推布局（零新 API）  │
                     └──────────────────────────────────────────────────┘
```

**六类资源事件全窗广播**（一个订阅点、一个 mapper、共享 reducer）：

| shellEvents | 纯 reducer（reducers-tab.ts） | 主窗方法（useTabManager） |
|---|---|---|
| `file:renamed {oldPath,newPath}` | `reduceResourceRenamed(s, old, new, label)`（label=basename 壳派生） | `renameResourceBySourceId` |
| `file:deleted {filePath}` | `reduceResourceDeleted(s, sourceId)`（remove 语义强关） | `deleteResourceBySourceId` |
| `tab:updateLabelBySourceId {sourceId,label}` | `reduceUpdateTabLabelBySourceId`（已有） | `updateTabLabelBySourceId`（已有） |
| `tab:closeBySourceId {sourceId}` | `reduceCloseBySourceId`（dirty 阻断 + remove） | `closeTabBySourceId`（已有） |
| `plugin:removed {pluginId}` | `reduceRemoveTabsByPlugin`（remove 语义） | `removeTabsByPlugin` |
| `workspace:folderRemoved {folderUri}` | `reduceRemoveTabsUnderFolder`（remove 语义） | `removeTabsUnderFolder` |

**plugin:removed / workspace:folderRemoved 并入理由**：同一疾病类——插件卸载/文件夹移除时脱出窗同名 tab 也会幽灵。机制已备（mapper+reducer），并入成本每类一行，不并入 = 留 2 个同类 bug（违 #8 归一化）。若想收缩范围，只砍这两类即可，机制不变。

### 删除语义裁定（用户悬点 A）

**资源删除 = remove 语义（`reduceRemoveTab`），dirty 判定归壳窗口策略**——对齐 `reduceRemoveTab` 既有设计哲学（reducers-tab.ts:230 注释"窗口模式策略归壳决策"）：

- **主窗**：`ensureFallback(reduceResourceDeleted(...))`——末 tab 补欢迎页（main 恒非空，复用 [useTabManager.ts:369](linkdesk/src/hooks/useTabManager.ts#L369) removeTab 同款包装）。
- **脱出窗**：mapper 检空 → `closeWindow`（I9-8 空窗自灭）。
- **为什么不是 forceCloseTab**：forceCloseTab→reduceCloseTab 在"单面板末 tab"分支**自动注入欢迎页**（reducers-tab.ts:188-198）——对脱出窗是错的（脱出窗该空窗自灭而非补欢迎页）。remove 语义把 fallback 决策留在壳策略层 = 窗口模式正交。
- **file:deleted（资源已不存在）→ remove 不查 dirty**：无保存对象，脏标签保之无意义（对标现状 forceCloseTab 强关语义，仅换实现基元）。
- **tabs:closeBySourceId（资源可能仍存在）→ dirty 阻断**（`reduceCloseBySourceId` 内 `isTabDirty` 检查）：程序化关闭不弹窗（#46.12 既有决策），静默阻断防丢数据——主窗 `reduceCloseTab` 内建阻断（reducers-tab.ts:173-175）、脱出窗现状手动阻断（tabCallbacks.ts:527），两路本就一致，广播只是把"一致"扩大到全窗。

### label 来源（用户悬点 B 裁定）

**label 从事件负载来，壳不派生资源语义**——reducer 签名 `reduceResourceRenamed(s, old, new, label?)` 的 label 是参数：

- 文件 rename：壳桥派生 basename（文件是壳已认知领域，bridges 上下文自洽）。
- 串口/未来资源：插件经 `tabs.updateLabelBySourceId` 直传 name（已是正确先例）。
- 泛化不变量：**壳不认识新资源长什么样，但纯 reducer 只按 sourceId 操作，新资源零壳改动。**

### focus 不并入（用户悬点 C 裁定）

`tabs.focusBySourceId` **保持按来源窗路由**（#46.12 现状），不广播。理由：rename/delete/label/close 是**全局事实**（资源变了，凡持有者皆应知）；focus 是**视图动作**（聚焦哪一个，单目标）。语义不同源，混入广播会所有窗齐聚焦（错）。聚焦"按注册表查持有着"是独立改进，超出 #46.2 范围 → 沉档案留专项（§六 已知限制）。

## 三、代码改动清单（具体到文件行）

### 壳侧

**1. [reducers-tab.ts](linkdesk/src/hooks/useTabManager/reducers-tab.ts) 新增纯 reducer**（`findTabBySourceId` 同文件已有）：
- `reduceResourceRenamed(prev, oldSourceId, newSourceId, label?)`：匹配 `t.sourceId === oldSourceId || t.filePath === oldSourceId`；命中 → `sourceId: newSourceId` +（`filePath === oldSourceId` 时）`filePath: newSourceId` +（label 非 undefined）`label`。无命中 → 原引用（React bailout）。
- `reduceForceCloseAll(prev, matches: Tab[])` 共享 helper：逐 tab `reduceRemoveTab(...).state ?? next`，重查防组移除（前 tab 关闭致组消失，后 tab 引用失效）。无匹配 → 原引用。
- `reduceResourceDeleted(prev, sourceId)`：`reduceForceCloseAll(prev, 匹配 sourceId||filePath 的 tab)`。
- `reduceCloseBySourceId(prev, sourceId)`：`findTabBySourceId` + `isTabDirty` 阻断 + `reduceRemoveTab`；无命中/dirty → 原引用。
- `reduceRemoveTabsByPlugin(prev, pluginId)`：`reduceForceCloseAll(prev, 匹配 pluginId||type 的 tab)`。
- `reduceRemoveTabsUnderFolder(prev, folderUri)`：`reduceForceCloseAll(prev, normalizePath(sourceId||filePath).startsWith(normalizePath(folderUri)))`。

**2. [useTabManager.ts](linkdesk/src/hooks/useTabManager.ts)**：
- 新增 4 个 `useCallback([])` 稳定方法：`renameResourceBySourceId(old,new,label?)` / `deleteResourceBySourceId(sourceId)`（内套 `ensureFallback`）/ `removeTabsByPlugin` / `removeTabsUnderFolder`（内套 `ensureFallback`）——全部 `setTabState(prev => reduceXxx(prev, ...))`。
- **删 413-457 整个资源事件订阅 effect**（u1-u4 全搬 windowHost）。`forceCloseTab` 若实现时 grep 确认零外部消费 → 评估删除（防死代码）。
- re-export 新 reducer（聚合器模式同现状）。

**3. [windowHost.ts](linkdesk/src/App/windowHost.ts)**：
- options 增 `mainResourceActions`（6 稳定回调对象，ref 模式存——同 `onDriftWindowClosedRef` 先例）。
- 新增纯导出 `mapResourceAcrossWindows(windows, reduce): { windows, emptyWindows }`：
  - main 窗跳过（主窗归 useTabManager，副作用归其真相源——硬约束 6：updater 内不写副作用）。
  - 脱出窗 `reduce(w.tabState)`；无变化（原引用）→ 该窗对象不变；空 → 收 `emptyWindows`，不写回。
  - 全无变化 → 返回 `windows` 原引用（setWindows bailout）。
- 新增**广播 effect（deps []）**——🔥 **#46.12 死循环止血铁律**（见 §五 bug 1）：订阅 6 shellEvents，handler 内 `mainActionsRef.current(...)` 在 updater 外调用 + `setWindows(prev => mapResourceAcrossWindows(prev, reduce))` 函数式 + `emptyWindows` 各 `closeWindow(id)`。effect 恒等注册，**windows 变化绝不复订阅**。
- re-export `emptyTabState` 同层先例成立（纯函数放 hook 文件已有先例）。

**4. [tabCallbacks.ts](linkdesk/src/App/tabCallbacks.ts)**：
- `createSourceIdRouters`：**删 `updateTabLabelBySourceId` / `closeTabBySourceId` 两分支**（广播接管），只留 `focusTabBySourceId`（origin 路由）。
- `SourceIdRouterDeps` / `SourceIdRouters` 类型同步删两方法；`createStableSourceIdRoutersBridge` 同步删两转发。
- `applyDetachedTabAction` 保留（`createTabActionHandler` 仍用）。

**5. [tabActions.ts](linkdesk/src/App/tabActions.ts)**：删 u6/u7（`tab:updateLabelBySourceId` / `tab:closeBySourceId` 订阅）+ `TabActionsDeps` 两参数。u5 focus 保留。

**6. [ShellEvents.ts](linkdesk/src/core/react/events/ShellEvents.ts:91-93)**：`tab:updateLabelBySourceId` / `tab:closeBySourceId` payload **删 `sourceWindowId`**（广播不关心来源）；`tab:focusBySourceId` 保留（origin 路由仍用）。

**7. [IpcBridgeHandler/tabs.ts](linkdesk/src/core/services/plugins/IpcBridgeHandler/tabs.ts:47-56)**：两 channel emit 不再传 `sourceWindowId`；`handleTabsChannel` 签名保持（focus 仍用）。

**8. [App.tsx](linkdesk/src/App.tsx:111-151)**：`useWindowHost` 传 `mainResourceActions`（useMemo 稳定对象，组装 useTabManager 的 4 新 + 2 既有方法）；`createSourceIdRouters` / `useTabActions` 删两参数。

**9. [bridges.ts](linkdesk/src/App/bridges.ts:57-72)**：**代码零改**——桥保持转发 file:* 事件；仅注释更新"壳资源事件全窗广播"。

### 插件侧（规范性与独立性）

## 六、已知限制（沉档案留专项，不搭车）

1. **`tabs.focusBySourceId` 跨窗聚焦不保证**（origin 路由）——"按注册表查持有着聚焦"是独立改进，E6 专项。
2. **文件 rename 的 ● 重挂竞态**（§一）——editor 插件既有容忍，如需根治（壳迁移保留 ● 前缀）涉脏语义进 reducer，另立案。
3. **新资源类型身份迁移**：文件走 file:* 事件（壳桥一行）；非文件资源身份迁移目前无 API（`updateLabelBySourceId` 不改 sourceId）——若未来出现"资源 id 变更"需求，新 API `tabs.migrateSourceId` 按新能力流程另立（本次不引入，护 #10 健壮）。

## 九、CDP 实机验收清单（#46.2-8）

1. **回归**：主窗文件树 rename → 主窗 tab label/sourceId 迁移（对标现状）。
