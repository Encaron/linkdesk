## 一、结论：首选 **2 棒**；3 棒只在「抢墙上时间」时用

| 方案 | 棒次划分 | 理由（省钱视角） |
|:--|:--|:--|
| 🟢 **首选 2 棒** | **AI-1＝壳轴**：[阶段 1](04-任务清单.md)（共享层转正）＋ [阶段 3](04-任务清单.md)（降级语义与顺手账）→ 收口<br>**AI-2＝插件轴＋对外面**：[阶段 2](04-任务清单.md)（settings 薄消费）＋ [03 文档连锁](03-文档连锁与发版.md) ＋ 阶段 4 打包 ＋ 阶段 5 验收（自验） | **出口只有两个**：① 壳仓 `npm run check` ② settings 仓自己的 CI。两条线文件零重叠。每多一棒就多一次「重读全案＋重建上下文」——AI 按次计费，**棒数越少越省**，而本案总格子数（约 20 格）不足以摊掉第三棒的固定成本 |

## 四、每一棒的开工前必读（省「重读成本」用）

⛔ 别通读全案再动手——按下面顺序**按需**取，每次不超过必要：

1. [00-README.md](00-README.md)（案由／落点概览／边界）→ 2. [04-任务清单.md](04-任务清单.md) 自己那几阶段 → 3. [01-方案与落点契约.md](01-方案与落点契约.md) §三（落点一览：新增哪些文件、改哪些文件）＋ §②④⑤⑦（API／壳侧／插件侧／配置）→ 4. [02-边缘情况清单.md](02-边缘情况清单.md) 对应章 → 5. 需要对外面时读 [03](03-文档连锁与发版.md)，交接时读本档 §三。

- 大档按 `offset/limit` 取片段（[01 图](mockups/01-设计图-共享化落地态-整页拟真.html) 74KB，⛔ 别整份读）。
- 普查类活最多 1 个子代理；⛔ 别为「确认一下」重读同一文件或重跑同一命令。
- 收工一次跑齐：`node mockups/校验-拟真度.cjs`（动了图才跑）＋ `npm run check`，结果抄进 §三。
- 一格一 commit；**逐条点名路径**提交（⛔ 不用 `git add -A`——工作区常有别的工作流在途）。
