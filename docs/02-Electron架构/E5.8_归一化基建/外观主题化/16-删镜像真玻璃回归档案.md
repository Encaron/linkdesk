# 16-删镜像真玻璃回归档案（E5.8#117）

> 2026-08-27。**用户三连投诉（抖动/变图/假玻璃）+ glassTint 糊色块根治。** 用户拍板方向：删除镜像机制、回归真 backdrop-filter 玻璃。
> 清单指针：E5.8-执行清单 #117。

---

## 一、背景与用户投诉

Phase 11.14（#104/#105）为「右键显示更清楚」引入 panorama 镜像机制——把全景图镜像进每个 zone 表面 `::after`，用 `filter: blur()` 直接糊图片副本（绕开 backdrop-filter 采样限制）。用户实机三连投诉：

1. **抖动**：zone 内图片会动，尤其 blur 是否等于 0 的附近发生抖动（因为要往 zone 内加载图片）。
2. **变图**：有的主题 zone 和背景图不一样，拖动 glassBlur 甚至会变图片。
3. **假玻璃**：zone 内加入图片然后让图片模糊 = 假玻璃模糊，不是真 backdrop-filter 采样。

2026-08-27 用户再加一条：

4. **glassTint 糊色块**：「你知道你刚才的镜像机制最恶心的是什么吗？就是我设置了 app.glassTint，本意是改变玻璃材质，结果这直接在各个 zone 内糊了个巨大色块」。

**用户情绪**：极度沮丧。「这些所有东西本来在之前的 git 中都是完美的，结果一个让右键显示更清楚的需求，为什么会有这么多 bug」。「我甚至都不敢期望我要的东西了，这些 bug 都必须修好」。用户期望恢复对「液态玻璃漂浮」愿景（半透明面 + backdrop blur + 发丝光边 + 圆角留缝投影 + 顶部高光）的信心。

**诚实归因**：是 #102 第一步诊断就错了——误判「backdrop-filter 采不到兄弟 background-layer → 必须镜像」，建了镜像机制 → 用户三 bug。**不是右键需求的问题，是诊断方向的问题。**

## 二、决定性证据（cp114 实验）

**#102「合成边界」判断是误判。** zone `::before` 的 backdrop-filter **能**直接采到兄弟 `.background-layer`：

| 场景 | icon-bar | main-zone |
|---|---|---|
| glassBlur=24（真 blur） | 199% 像素 diff | 224.5% 像素 diff |
| glassBlur=0 | 基线 | 基线 |

→ backdrop-filter 直接采样兄弟背景层。镜像切片挂表面 = **整个多余**。

正确重构 = 删镜像，让 backdrop-filter 直接采样。

---

## 三、glassTint 糊色块根因

- 用户在配置区设 `app.glassTint`，本意 = 改玻璃材质色。
- panorama 主题**没有 surface 域** → `--glass-opacity` 落 SURFACE_ZERO 默认 **1**（完全不透明）。
- seeds.ts 只写 `glass-tint` 不写 opacity → 用户 hex 色被当完全不透明盖片糊满 zone。

**根子 = 壳侧系统默认值缺口，不是主题插件在作祟。** 主题没声明 surface 时，壳应提供玻璃系统默认材质（`GLASS_SURFACE_DEFAULT_ALPHA` = 0.5）。

**修复** = 用户设 glassTint 时，tint 盖片 opacity 跟随用户玻璃面不透明度（glassOpacity 或默认 0.5）；只拖 glassOpacity 不动 tint 时保持配方面材质（#112 语义不破）。

## 四、玻璃锚定系统标尺（回答「玻璃为什么取决于主题插件」）

用户 2026-08-27 质疑：「玻璃模糊等既然出现在配置区，就是可以被直接修改的，它为什么取决于主题插件，它是主题这个功能本身的东西，和插件有多大关系，是不是又是坐标系的问题」。

**结论：玻璃机制已经是系统级的，主题插件只是预设值。** 证据（CDP 实机）：

| 主题 | glassBlur | glassOpacity | glassTint | zone 磨砂 |
|---|---|---|---|---|
| panorama（无 surface 域） | 16px | 0.4 | #7AC7FF | — |
| 切 dark | **16px** | **0.4** | **#7AC7FF** | `blur(16px)` 真磨砂 |
| 切回 panorama | **16px** | **0.4** | **#7AC7FF** | — |

用户玻璃配置跨主题切换原样保留、继续生效。玻璃 4 键（`app.glassBlur/glassOpacity/glassTint/glassSaturate`）是壳配置区，走 presence 门控——显式写过就覆盖一切主题，主题插件声明了什么根本不看。这符合用户之前拍的「外观控件锚系统标尺，不锚主题基准」（见 [14-档案](../外观主题化/14-主题配置参考系根治档案.md)）。

**主题插件部分不需要大改。** 主题配方的 `surface.glass` 作为「预设值」机制是对的：主题作者给一套默认玻璃，用户随时覆盖，用户永远赢。改主题插件 schema 反而破坏插件独立。
