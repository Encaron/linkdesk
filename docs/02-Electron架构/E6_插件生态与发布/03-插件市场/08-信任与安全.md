# 信任与安全——第一站敢不敢装

> 对应任务：E6#30.8。用户 2026-08-29 拍板新增角（第一站体验的信任底座）。
> 文档归属：市场设计文档族（[03-市场交互设计.md](03-市场交互设计.md) = 总览索引）。
> 多源市场（E6#30c）= 谁都能发布——那「凭什么装」就是第一站必须回答的问题。

## 一、来源标注
- 列表/详情显示**来源仓库名**——用户装之前知道这是谁发的。
- 数据来自 E6#30c 多源（每个源 = 仓库 URL）；UI 落点 = 列表卡片 + 详情页元数据（E6#30.6c）。

## 二、下载数
- **来源不是我们统计**——GitHub Releases API 每个发布资产自带 `download_count`（GitHub 替所有下载者统计，我们只读）。
- 市场启动时拉一次 + 缓存；未认证 API 限 60 次/小时，5 分钟缓存后绰绰有余。
- 诚实边界：Gitee 源走 Gitee 自己的 API（实现时核字段）；连 API 都没有的自定义源 → **不显示下载数，不伪造**。

## 三、许可证
- **作者在 marketplace.json 里自己填**（MIT / Apache-2.0 / 闭源）——纯声明数据，不用扒。
- `license` 字段（E6#29c 格式扩展）+ 详情元数据侧栏展示（E6#30.6c）。

## 四、安装确认（E6#30.8a）
- 点 🟢安装前，轻量确认弹窗：来源仓库 + 发布者/作者 + 一句话描述 + 许可证 + 版本 + 大小（视觉 = mockups/02 帧 8）。
- 弹窗 = 壳共享 Dialog（#dialog-root 保底 UI，实机已具）；内容数据来自 catalog `marketEntry`（E6#30c 多源目录条目）。
- 装前一刻看见自己装的是什么（对标：浏览器装扩展前的确认）。
- v1 不做评分/评论——零服务器做不了真实评级，伪造没意义；下载数 + 来源 + 许可证已是零成本信任底座。

## 五、minAppVersion 校验（缝隙 G1 🔴——字段设计了零消费）

> 01 §三 定义了 `minAppVersion`（最低壳版本）但此前**无任何任务消费**——设计完字段忘实现。本档定行为。

- 安装/更新前校验：`marketEntry.minAppVersion` vs 当前壳版本（semver）。
- **不足 → 拒绝安装** + error toast「需升级 LinkDesk 至 x.x.x 才能安装」+ 详情页元数据区显示「需 LinkDesk x.x.x」。
- 已装插件版本高于本地壳 → 已装不崩（插件本身能跑则跑），只拦**新装/更新**。

## 六、恶意 id 抢占（缝隙 G11/A3——多源安全）

> 多源市场 = 任何人可发布。恶意源用合法插件 id 发布假插件，同 id 冲突取版本高者（01 §六.4）→ 可能顶掉真插件提示。

- **来源标注做显眼**：详情页「来源仓库」展示完整仓库 URL（可点击跳转），列表卡片来源名可见——用户一眼知道装的是谁的。
- 同 id 多源冲突维持「取版本高者」（不引入黑名单——零服务器做不了真实裁决）；**来源标注是防抢占的信任手段**。
- 安装确认弹窗（§四）已含来源仓库——抢占场景下用户装前看见「这个来源」。

## 七、更新后权限变化（缝隙 E3）

- 插件更新后**新增**权限请求 → 重新走审批（E6#49 审批审计），**不清已有 remember 授权，只补新授权的询问**。
- 已装插件更新不重置既有授权（用户信任不因更新被清零）。

## 八、官方发布徽标（缝隙 G1——派生判定，零新字段）

- mockup 详情页头部「官方发布」badge（帧 1-10）**不新增 catalog 字段**，由**默认源**派生：`source.id === 'official'`（01 §六 默认源约定）→ 显示「官方发布」徽标。
- 判定逻辑单一权威：**徽标 = `marketEntry.source.id === 'official'`**，随多源合并产物（E6#30c）走——壳/市场插件读同一条目，无第二份判断（归一化）。
- 自定义源 → 不显示官方徽标（不伪造认证）；来源仓库名照常展示（§一）。→ 落 E6#30.8f

## 九、审视实锤（2026-08-30 第 3.2.2 轮——#30.8c 壳版本 API 前置）

> 2026-08-30 第 3.2.2 轮整轮审视（E6#30.5-#30.9）落笔的修正实锤。清单只留修正结论 + 本锚点。

### 9.1 minAppVersion 比对完成路径断点——壳版本 API 全仓缺失

- **§五「minAppVersion vs 当前壳版本」缺完成路径**：src/ + electron/ 全仓 grep `getVersion`/`appVersion` **零命中**——壳侧无任何版本查询 API，设置「关于」页也拿不到版本号。「当前壳版本」从哪来 = 未定义（判据⑤ 完成路径前置——开工才发现做不了，overlay 分割线同型）。
- **定型：新增通用壳版本 API `app.getVersion()`**——新 API，走设计 8 维度 + 契约四齐全（contracts/linkdesk.d.ts 类型声明 + preload 实现 + 主进程 IpcBridgeHandler 分发 + 03-插件制造 文档说明）。主进程 `app.getVersion()`（Electron 内建）→ preload 暴露 → 插件 `window.linkdesk.app.getVersion()`。
- 连带受益：设置「关于」页未来显示版本号 = 消费同一 API（归一化——一个概念一处写，不另起来源）。
