# 如何造一个设置插件

> 2026-08-22（E5.8#41.15）· **E6 核 2026-09-06**（塌平单根 + 共享控件收 @linkdesk/ui）。**给第三方插件作者。** 你的插件想给用户一个"设置 UI"？不用改壳——声明一个 `factoryRole: "settings"` 插件即可。这是**整套设置 UI 的完整替代品**，不是往里加一个设置项。

## 这是什么

**设置插件 = 一整套设置界面。** 声名 `factoryRole: "settings"` 的插件，会与官方设置并存：

- 用户打开设置（`Ctrl+,` / 齿轮）→ 进**当前激活套**的 UI（没切过 = 官方套）
- 可装多套 → 每套设置 UI 顶部有个**通用区**，列出全部 N 套（含自身），点哪套切到哪套
- 激活套选择**持久化**，重启保持

关键心智：**设置插件的 UI 只是渲染器，数据永远在同一个地方。** 所有套 UI 都调同一个 `window.linkdesk.configuration` API、看到同一份数据——切套只是换渲染器，数据不动。这不是"数据私有/公开"之分，是**一致性**：人人看同一份。

## 最小声明——plugin.json 三步

照官方设置（repo `plugins/settings/plugin.json`）写：

```jsonc
{
  "$schema": "../../public/schemas/plugin.schema.json",
  "name": "漂亮设置",                       // 插件名——通用区按钮显示的就是它（走 t()）
  "version": "1.0.0",
  "icon": "resources/icon.png",
  // 不填 core —— 可卸载；core: true 则 UI 无卸载按钮（防误删旗标，非类别）
  "factoryRole": "settings",                // ① 关键——声明自己是"设置套"的一份子
  "entry": "src/index.tsx",                 // 标签页入口（appearsIn.tabBar 需要 entry）
  "appearsIn": { "iconBar": "bottom", "tabBar": true },
  "tabBehavior": { "singleton": true },     // 单例——切换时已开就不重复开
  "contributes": {
    "viewsContainers": {
      "settings": { "title": "设置", "location": "auxiliarybar" }   // ② 视图容器
    },
    "views": {
      "settings": [
        { "id": "settings", "title": "设置", "render": "src/views/SettingsView.tsx", "order": 0 }
      ]
    },
    "floatingPanel": { "viewId": "settings" }   // ③ 悬浮面板形态（可选）
  }
}
```

三个关键声明缺一不可：**`factoryRole: "settings"`**（进通用区候选列表）+ **`contributes.views`**（真实渲染组件）+ **`floatingPanel`**（`Ctrl+,` 兜底形态）。

## 数据 API 形状——全走 `window.linkdesk.*`

设置插件**禁止 `import @src/core/...`**（插件通信铁律 + ESLint `noCoreImportInPlugin`）。数据全在公开 API：

| 你要的 | 调用 | 返回形状 |
|------|------|------|
| 全部配置分组 | `window.linkdesk.configuration.getConfigurationContributions()` | `[pluginId, { title, properties }][]`（具名类型 `LinkDeskConfigurationContribution`） |
| 合并 schema | `window.linkdesk.configuration.getSchema()` | `LinkDeskConfigSchema`——含 `type/default/description/enum/enumDescriptions` + **`uiHint`/`minimum`/`maximum`/`renderHint`/`dependsOn`**（类型补全，官方控件切色的依据） |
| 读/写/订阅配置 | `configuration.get/set/onChange` | 通用 API，任何插件可用 |
| 设置页专用刷新 | `configuration.onDidChangeConfiguration(cb)` | 配置变 → cb(key, value)，UI 实时刷新 |
| 配置分组跳转 | `configuration.consumeSettingsGroup()` / `onRequestSettingsGroup(cb)` | 打开时切分组 |
| 滚动到某设置 | `configuration.consumeScrollToSetting()` / `onRequestScrollToSetting(cb)` | 打开时滚动定位 |
| 快捷键页数据 | `window.linkdesk.keybindings.getKeybindings()` | `Keybinding[]`（快捷键 UI 的数据源） |
| 主题选择器 | `window.linkdesk.commands.executeCommand("theme.pick")` | 唤起主题 QuickPick（两段式：配方→配色） |
| 语言选择器 | `window.linkdesk.commands.executeCommand("workbench.action.selectLanguage")` | 唤起语言 QuickPick |
| 插件装卸刷新 | `window.linkdesk.configuration.onPluginLifecycleChange(cb)` | 装卸插件 → cb，重拉候选/按钮消失 |

**`settings.json` 文件名常量 = 数据契约一部分。** 官方设置"以 JSON 打开"按钮这么定位落盘文件：

```ts
const dir = await window.linkdesk.path?.appDataDir?.();
const filePath = dir ? window.linkdesk.path.join(dir, "settings.json") : "";
```

文件名就叫 `settings.json`，没有壳侧 map——照抄即可。

## 共享控件——`@linkdesk/ui`

设置 UI 的共享控件在 **`@linkdesk/ui`** 包（E6#54c 收归——第三方 `npm i @linkdesk/ui` 后直接 import，**禁 `import @src/core/...` 也禁 `@src/components/...`**）：

`ContextMenu` · `InlineInput` · `SelectBox` · `Toggle` · `ColorPicker` · `FontFamilySelect` · `FilePathInput` · `NumberInput` · `Slider`（E5.8#50.9）· `Combobox` · `FormRow` · `SegmentedRadio` · `ThemePicker` · `PluginIcon` · 共享 hooks（`useDebouncedInput` / `useClipboardKeys` 等）

```tsx
import { InlineInput, SelectBox, FormRow } from "@linkdesk/ui";
```

> 官方 settings 实样（`plugins/settings/src/views/SettingsView.tsx`）就是从 `@linkdesk/ui` import——照抄 import 行即可，不用额外工程配置。

## 编排层自由组合——数据一样，想怎么排就怎么排

数据 API 只决定"有什么数据"；**布局是你的自由发挥**。现役参考：

- **官方设置**（repo `plugins/settings/`，core:true）= 左分组树 + 右表单 + 顶部平铺切换条——现役唯一设置套（旧 `settings-demo` 参考实样已下架，从零编排见下方造法一/二）
- 你做的设置套想怎么排就怎么排：banner 头 + 卡片分区（全部配置组 = 卡片，含角色胶囊行 + 快捷键键帽卡）+ 右下角胶囊切换套都行（形态二设计源 = 工厂角色并存 mockup `01-形态一形态二-复杂场景图.html`）

编排维度：分组导航 / 搜索框 / 控件渲染 / "以 JSON 打开" / 快捷键子页 / banner 头 / 卡片分区——每样都可以做、可以不做、可以换位置。

## 切换激活套——通用区按钮 + 全插件侧换套

每个设置插件的顶部通用区渲染**全部 N 套按钮（含自身）**，当前激活套高亮。点击切换 = **全插件侧换套**，零壳改动：

```ts
async function handleSettingsSwitch(targetId: string) {
  await window.linkdesk.factorySlots.setActive("settings", targetId); // ① 落盘持久化
  if (tabId) {
    // ② 标签页形态：关本套 tab → 开目标套（singleton 去重已存在则聚焦）
    await window.linkdesk.tabs.close(tabId).catch(() => {});
    await window.linkdesk.tabs.create(targetId).catch(() => {});
  } else {
    // ③ 悬浮面板形态（E5.8#41.18）：原地换套——候选 viewId 复合寻址，壳复合替换面板内容
    const target = settingsCandidates.find((c) => c.pluginId === targetId);
    if (target?.viewId) {
      await window.linkdesk.panel.revealFloating(target.viewId, target.pluginId).catch(() => {});
    } else {
      await window.linkdesk.tabs.create(targetId).catch(() => {}); // 无浮动面板声明 → 退回开 tab
    }
  }
}
```

组件在 `{ isActive, tabId }` props 里收 `tabId`（壳注入；浮动面板无标签页时为 `undefined` → 走悬浮面板原地换套分支）。`settingsCandidates` 来自 `factorySlots.list("settings")`——每条候选带 `viewId`（该套的 `contributes.floatingPanel.viewId`，供原地换套复合寻址）。`panel.revealFloating(viewId, pluginId?)` 的可选 pluginId 是 #41.18 新增——双套同名 viewId 并存时携带 pluginId 精确命中目标套。

通用区按钮数量 = **活集合运行时推导**——删任意一套 → `onPluginLifecycleChange` → 重拉 → 按钮自动消失。

## 造法一：复制官方（最快）

复制 repo `plugins/settings/` 目录到你的项目根（或 repo `plugins/<你的id>/`），只改：

1. `plugin.json`——`name`/`description`；**去掉 `core: true`**（否则 UI 无卸载入口），新增 UI 文案见下方 i18n 节
2. 追加你自己的风格到 `src/views/SettingsView.css`——**但覆盖规则必须挂你自己的根类**，见下方「🔥 CSS 作用域铁律」

官方设置**零 `@src/core` import**（历史两个 `@src/core` 依赖已随 E5.8#41.14 消除：`getFilePath` → `path.appDataDir()` 自推导；`useConfigurationIpc` → 直接调 `window.linkdesk.configuration.*`），复制即得自包含。

## 造法二：从零编排（画布全换）

不复制官方设置组件结构——**组件只依赖数据 API + `@linkdesk/ui` 共享控件，布局完全自己画**：banner 头、卡片网格、角色胶囊行、快捷键键帽卡、右下角悬浮胶囊，想怎么排怎么排（数据 API 形状见上表、控件见「共享控件」节）。

> 参考路径：官方 `plugins/settings/src/views/SettingsView.tsx` 是最小设置套骨架；要画布全换就从零写自己的 `SettingsView.tsx`，用 `contributes.views[].render` 指向它。

## 🔥 CSS 作用域铁律（E5.8#41.17）

**两个设置套的 CSS 注入同一个 Pool 文档。** 你的覆盖规则若写裸共享类（如 `.settings-form .settings-row`、`.settings-role-switch--gen`），会和官方套的同类规则打架——后注入者赢，官方套被你的样式污染（真机实测 bug 2：demo 的卡片气泡泄漏进官方套——教训仍成立）。

结构性解法 = **你自己的独有根类命名空间**（用自己的 pluginId，如 `.my-settings`）：

- 根元素挂一个独有类（`.my-settings`），你新增的覆盖/规则一律挂它：`.my-settings .settings-row { ... }`
- 规则只命中你自己子树 → 官方套零受影响；且自带"样式自包含"（官方套 CSS 加载与否都不影响你）
- 自己的新组件类也用独有前缀（`.ms-*`），别用裸名（`.keycap` 也要挂 `.my-settings .keycap`）

## i18n 新文案（i18n 审计门禁）

新增 UI 文案走 `t("中文原文")`；`npm run check` 的 i18n 审计要求**每个新 key 有英文翻译**，否则红灯。设置插件在 `contributes` 声明翻译文件即可：

```jsonc
"contributes": {
  "i18n": { "en": "i18n/en.json" },
  // ...
}
```

`i18n/en.json` = `{ "中文原文": "English" }`（zh 不需要——中文 key 自带兜底）。
