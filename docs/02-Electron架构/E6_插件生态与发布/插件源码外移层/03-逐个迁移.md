# 7.2 逐个迁移——搬一个、闭环一个

> **任务号：** E6#99 · **前置：** 7.1（出口打通——搬过去必须能构建） · **产物：** 每只发货插件一个独立 GitHub 仓；壳仓 `plugins/` 下只剩夹具
> **🔴 铁律：** **搬一只 → 构建验证一只 → 上架一只（7.3 轮）→ 壳仓那份删净一只。** 不许「全搬完再全上架」——中间态会长时间存在**双真相源**，而且**没有任何门禁能发现分叉**（内容指纹门禁只管 zip，不管源码）。

---

## 〇、本轮的物理动作只有三步

```
① 从壳仓历史里抽出该插件的子树 → 变成独立仓（保历史）
② 推到 GitHub + 在插件仓重建 zip（本轮手工，7.4 轮之后改由 sync:bundled 自动）
③ 壳仓同笔删源码 + 拆掉挂在它身上的壳侧绑定
```

难的不是 `mv`，是**第 ③ 步的「拆绑定」**（[总档案 §1.4](00-整理档案.md) 实测 17 处）。

## 一、批次切分（按「有没有构建管线」分两批，不按重要性）

| 批 | 对象 | 只数 | 前置 |
|:--|:--|:--:|:--|
| **批 A** | `file-tree` `marketplace` `settings` `editor` `python` `serial-monitor` | 6 | 7.1 全部完成 |
| **批 B** | 12 只纯 JSON（`lang-defaults` `lang-test-ja` + 10 只 `theme-*`） | 12 | 7.1 §四 的 pack 通道落地 |

> **为什么分两批**：批 A 有 SDK build 管线，搬过去立刻能出 zip；批 B 的产 zip 手段要先造（7.1 §四）。硬把它俩绑在一起，会让批 A 干等着批 B 的工具。

**批内顺序建议 = 由简到繁**，让「同一个故障模式」在前几只就暴露：

```
theme-* / lang-*（纯 JSON，最少绑定）
  → settings（1 只 @linkdesk/ui，无 contracts）
  → python（无 ui/contracts，但有 LSP 链）
  → serial-monitor（1 只 @linkdesk/ui，11 文件）
  → file-tree（ui + contracts，3 处 @src 测试，含 core:true）
  → marketplace（ui + contracts，最多文件，core:true）
  → editor（core:true，Monaco 依赖最重，壳侧 worker 基址有历史账）
```

## 二、抽子树保历史（照 L0.15 的先例做，**先试点**）

**先例：** [仓库结构上移/00-迁移档案.md](../仓库结构上移/00-迁移档案.md) 那次全仓上移用的就是 `filter-repo`，**3119 commit 全保、仅 hash 变**。本轮的形态更简单（只抽一个子树）。

### 2.1 红线与前置

- 🔴 **迁移期一律不许改任何插件的目录名**——插件身份今天靠**目录名兜底**，改目录名 = 改插件 id ⇒ **换了一个插件**（老用户安装目录并存两份、墓碑对不上、catalog 两个 id、更新链静默断、插件数据看似丢失；**五条后果全不报错**）。**展开与解法 = [09-命名规范.md §六](09-命名规范.md)**，前置动作 = 7.1 §七 身份显式化（`E6#98g`）。
- 🔴 **绝不在壳仓的工作副本上直接跑 `filter-repo`**——它是**破坏性改写**（会重写整份历史）。做法：**先 `git clone --mirror` 备份**，再在**临时克隆**上做抽取。
  ```
  git clone --mirror E:/linkdesk E:/linkdesk-l7-backup.git   # 备份（先做，且 fsck 校验）
  git clone E:/linkdesk <临时目录>                            # 在临时克隆上抽子树
  ```
- 🔴 **壳仓自身的历史不做 filter-repo**——即：壳仓的过去里**仍然留着** `plugins/<id>/` 的旧历史，这是**可接受且有意保留的**（重跑一次全仓 filter-repo 的风险远大于收益，而且会让所有已有 commit hash 再变一遍）。**本层只做「从今往后不再改它」**，见 §四。
- ⚠️ **实测教训可直接复用**（L0.15 记下的）：「**纯 `--path` 不移前缀**」⇒ 抽子树必须配 `--path-rename` 才能把 `plugins/<id>/` 变成仓库根：

  ```bash
  cd <临时克隆>
  git filter-repo --path plugins/<id> --path-rename plugins/<id>/:
  ```

  ⚠️ **本轮仍要在一个插件上先试点**（验证命令形态 + `git log --follow` 连续 + 文件树顶层正确），**试点通过再批量**——这是 L0.15 已经立过的规矩，别因为「看着简单」跳过。

### 2.2 试点验收（照 L0.15 的机械四验）

- `git log --oneline | wc -l` = 壳仓里该插件子树的 commit 数
- 顶层即插件工程（`plugin.json` / `src/` 直接可见，无 `plugins/<id>/` 套娃）
- `git log --follow src/index.tsx` 历史连续
- 抽出的工作树与壳仓现行 `plugins/<id>/` **逐字节一致**（`diff -r`，排除 `node_modules` / `dist`）

## 三、建仓与推送

### 3.1 建仓

> 🔴 **红线：`git push` 必须等用户本人点头**（memory `push-wait-for-user`）。本轮的「建仓」「推送」两步**都停在「命令已备好、等用户发话」**——AI **不许**自行推送。

- 仓库名（D5：**完全自由**）。建议惯例（**非强制**）：`linkdesk-plugin-<id>` 或裸 `<id>` 二选一，**全批统一**（`hello-linkdesk` / `first-run-setup` 是裸名先例，跟它们或另立新惯都可以，但**要在 7.0 轮落笔那一节里写死选了哪个**）。
- 本地落位：容器目录（D6）——`E:\linkdesk-plugins\official\<id>\`；**容器与容器内任何父级都不建仓**。

### 3.2 重建 zip（本轮手工；7.4 轮之后自动化）

```
cd <插件仓> && npm ci && npm run build      # 产出 <id>.linkdesk-plugin
copy <id>.linkdesk-plugin <壳仓>/bundled-plugins/
```

⚠️ **本轮是过渡态**：zip 手工复制进壳仓。7.4 轮落成 `sync:bundled` 后，**这段手工步骤被命令取代**（届时壳仓侧应只剩 lock 文件 + zip，不再需要人工搬运）。**过渡期不许把这一步写进常规流程文档**，否则会固化下来。

### 3.3 版本号处置

抽出来的插件仓 `plugin.json.version` **保持原值**（1.0.6 / 1.0.28 / …）——搬迁**不是内容变更**，不 bump。但**内容指纹门禁会在壳仓侧要求**：zip 换了 ⇒ `plugin.json.version` 要么不变而内容一致，要么 bump。**实测判断**：若插件仓重建出的 zip 与壳仓现存的**指纹相同**（同样的源码、同样的 SDK 版本、同样的 EOL 归一与固定时间戳）⇒ **`version-bumped`/`identical` 两者皆可过**；若指纹变了 ⇒ **必须 bump**（否则门禁红）。**这一步先跑再判，别猜。**

## 四、壳仓同笔删源码 + 拆 17 处绑定

**同笔 = 同一个 commit**（或同一批 commit，但**中间不许留过夜的双真相源**）。

### 4.1 拆除清单（顺序即依赖序）

| # | 落点 | 动作 |
|:--:|:--|:--|
| 1 | `tsconfig.json:28` | `include` 去掉四个 core:true 插件路径（`plugins/editor` `file-tree` `marketplace` `settings`） |
| 2 | `vitest.config.ts:12-13` | 去掉 `plugins/**/*.test.ts` / `.test.tsx` 两条 glob（**注意保留夹具的测试**——按实际 glob 形态调整，别一刀切） |
| 3 | `eslint.config.js:10/12/167/199` | 主 lint glob 去掉 `plugins/**/*.ts(x)`；**插件专属块（含 `linkdesk/no-cross-plugin-import`）随源码迁进插件仓的 CI preset**（7.5 轮）；局部规则（如 no-hardcoded-chinese 覆盖 `plugins/**`）复核是否仍需 |
| 4 | `knip.json:9` | `ignoreWorkspaces: ["plugins/*"]` 随 `workspaces` 处置 |
| 5 | `package.json` | `workspaces: ["plugins/*"]` 保留（**夹具仍在**）；`"@linkdesk/ui": "file:./packages/linkdesk-ui"` 复核是否仍被壳消费 |
| 6 | `package.json` scripts | `lint` / `fix` / `typecheck` 里的 `plugins/` 路径按 3 同步 |
| 7 | `scripts/audit-i18n.mjs:71` | **删写死的 `plugins/editor/i18n/en.json`**（改为随插件仓走，或从清单读） |
| 8 | `scripts/check-lsp-{deps,args-base,smoke}.mjs` + `lsp:smoke` | 基准参数化（7.1 §五） |
| 9 | `scripts/check-file-size.mjs` · `check-empty-dirs.mjs` · `check-css-hardcode.mjs` · `check-font-scale-audit.mjs` · `check-theme-audit.mjs` | 扫描域改造或显式声明「不再扫发货插件」——**逐条给结论，不许默默失效** |
| 10 | `scripts/pack-bundled-plugins.mjs` | JSON 插件搬走后**没有输入** ⇒ 按 7.1 §四 方案处置（甲：逻辑收进 SDK，本脚本退休；乙：保留） |
| 11 | `scripts/convert-material-icons.mjs` · `scripts/dev-plugin.mjs` · `scripts/build-plugins.mjs` | 逐个复核（`build-plugins.mjs` 已自陈「E6 前不运行，仅留作历史改造资产」⇒ 可入退休名单） |
| 12 | 物理目录 | `rm -rf plugins/<id>`（**保留 `plugins/panel-demo` `plugins/floating-panel-demo`**） |

> 🔴 **判据不是「改完了」，是「归零」**：
> ```
> grep -rn "plugins/\(editor\|file-tree\|marketplace\|settings\|python\|serial-monitor\)" \
>   tsconfig.json vitest.config.ts eslint.config.js knip.json package.json scripts/*.mjs
> ```
> ⇒ **逐条命中都要能说出为什么该留**（夹具例外、注释、文档指针），说不出的就是漏网。**批 B 的 12 只同理。**

### 4.2 「`plugins/` 降级为夹具目录」的语义要写进规范

`plugins/` **不会变空**：`panel-demo` / `floating-panel-demo` 是开发夹具、不发货、留仓内。所以 7.0 轮那条规范要写成 **「`plugins/` 降级为夹具目录，发货插件一律仓外」**，而不是「删掉 `plugins/`」——否则下一个 AI 会看着两个残留目录困惑，或更糟：把夹具也搬出去。

## 五、每只插件独立 commit + 独立验证

**逐插件独立 commit、独立跑验证**（照 L3.6 §3.6.4 的既有铁律：「四个一起改则出问题无法二分」）。

每只的完成判据（**逐只都要过**）：

- [ ] 插件仓：在**壳仓之外**的全新目录 `git clone && npm ci && npm run build` ⇒ 出 `<id>.linkdesk-plugin`
- [ ] 插件仓：`npm run lint` + `npm run validate` 绿灯
- [ ] 壳仓：`npm run check` 全绿
- [ ] 壳仓：`grep -rn "plugins/<id>"` 的每条命中都能解释（§4.1 判据）
- [ ] 壳仓：`git ls-files plugins/` 下该 id 归零
- [ ] **装机验证**：装到安装版 → 该插件加载正常、功能可用（批 A 的 editor 要验跳转、python 要验 LSP、serial-monitor 要验串口收发）
- [ ] `bundled-plugins/<id>.linkdesk-plugin` 仍在（**出厂种子不许丢**）
