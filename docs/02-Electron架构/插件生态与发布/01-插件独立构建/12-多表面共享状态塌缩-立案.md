# 12 · 多表面共享状态塌缩——立案（SDK 契约缺口）

> ⛔ **非新能力**：本档是**已发生缺陷**的立案与根因分析（不动 API 形状、不加控件、不改 `contributes` 语义）——§四两条候选解若实施，届时按实施件另过设计前置。

> **状态：✅ 两条路都已落地**。首个真实受害者 = 官方 marketplace 插件（用户实机报障 2026-09-30；插件侧立即解已随 **1.1.6** 发出，平台层正典解 = 本文档 ＋ **E6#158**）——**(a) 终局解已实施**（`E6#159` 实施轮 0/1/2 于 2026-09-30 全部落地：SDK 构建内核改单次多入口 build ＋ 产物判据 G1/G2 ＋ marketplace **1.1.7** 真安装对照（跨表面搜索过滤 ✅；另两条 ◐ 受样本／量具限制）；见 [13-跨表面共享chunk-设计前置.md](./13-跨表面共享chunk-设计前置.md)）。
> 定性一句话：**壳本体无辜、插件作者没写错——缺口在 SDK 多表面打包契约**：「各表面自包含打包」是文档化了的有意取舍，但**「模块级可变状态会随表面各复制一份」这一后果没有被写进契约、没有作者面成规、没有机械腿**。

---

## 一、缺陷形态（一句话版）

E6#15 起，一个插件 = 主入口 ＋ **每个 `contributes.views[].render` 一份独立的 vite lib build**（`packages/plugin-sdk/src/vite-config.ts`）。每份表面 bundle 单文件自包含。**ESM 模块身份 = URL** ⇒ 同一份 `services/` 模块在 N 份表面 bundle 里各内联一份 ⇒ **模块级可变状态（store / 守卫 / 去重表 / 订阅计数）在表面之间各长一个**。

于是「**模块级 = 跨视图唯一真相**」这条在单表面时代默认成立的设计前提，在多表面时代**静默失效**——不报错、不警告，表现为「同一个数据，A 面翻了、B 面没翻」这类面间不一致。

**既定取舍的原话**（[02-linkdesk-plugin格式规范.md](./02-linkdesk-plugin格式规范.md):40）：

> 各表面单文件自包含、入口 default 导出零失真。副作用代价 = 各表面共享模块重复打包（react 等壳 external 除外）

——取舍本身没问题；**缺的是「重复打包 ⇒ 模块级可变状态复制」这一条后果的成规与门禁**。插件作者照单表面时代的正典写模块单例（marketplace `searchState.ts` 头部至今写着 E3.6 定的「搜索状态必须是模块级的——`setSearch` 后所有 view 同步过滤」），**这是当时唯一正确写法，且今天无任何机制提示它已不成立**。

## 二、现场取证（首个受害者：marketplace，1.1.4↔1.1.5 实机）

- 症状：侧栏「检查更新」后行内徽标翻新、**主区详情页不翻新（版本下拉不动、更新钮不出现）**，须重启。
- CDP 探针（活应用内）：**同一 document 里并存 2 个目录 store 实例**（一个已翻新到 1.1.5、一个仍是 1.1.4 旧投影），分别被侧栏面与主区详情面持有：

  ```json
  {"distinctEntryObjects":2,"list":[{"id":1,"ver":"1.1.5","owners":"ht,pt"},{"id":2,"ver":"1.1.4","owners":"ei"}]}
  ```

- 同一 document 加载 3 份独立表面 bundle（SearchView / DetailView / ExploreView），**每份都内联一份共享模块副本**。
- 同族波及面（该插件体检结果）：跨表面搜索过滤**早已静默失效**、配置变更订阅每表面各注册一次、发现腿重入守卫每表面各一份、安装去重表跨表面失效、`events.on` 订阅每表面各一次。
- 详案 → marketplace 插件仓 [docs/01-多表面共享状态塌缩-立案与修复.md](https://github.com/Encaron/linkdesk-plugin-marketplace/blob/main/docs/01-%E5%A4%9A%E8%A1%A8%E9%9D%A2%E5%85%B1%E4%BA%AB%E7%8A%B6%E6%80%81%E5%A1%8C%E7%BC%A9-%E7%AB%8B%E6%A1%88%E4%B8%8E%E4%BF%AE%E5%A4%8D.md)。

## 三、影响面（为什么会再犯）

- **候选受害插件 = 一切多表面插件**（有 ≥2 条 `contributes.views` 或 statusBar ＋ 视图组合）。官方 5 仓里 marketplace（7 表面）、file-tree、serial-monitor、editor、settings 均可中；第三方作者仓**不可盘点**（正是最危险的部分——latent bug 无人报就不存在）。
- **受害形态清单**（作者无感知）：模块级 store / 模块级 `let` 缓存与 promise 盾 / 模块级订阅守卫（`started` 标志）/ 模块级去重 Map / 模块级计时器句柄 / 模块级命令注册守卫。
- ⚠️ **不犯的写法**（避免误伤）：纯函数与常量、`localStorage`/壳 KV 等外部真源、React 组件内状态、事件广播（池侧有 replay-on-subscribe）——这些天然跨表面。

## 四、正典解（两条路，建议并走）

| 方向 | 做法 | 代价 / 边界 |
|:--|:--|:--|
| **(a) 从根上：跨表面共享 chunk（首选）** | 多表面构建间去重——同一 shareable 模块只产出**一份 chunk**，各表面 bundle 以相对 import 引用它（`import "./chunk-x.js"`，`linkdesk://` 与 `/@fs` 两轨道都需验证相对解析）。保住「模块级 = 唯一真相」的前提，**作者零改动**、第三方仓存量缺陷自然消失 | 动 SDK 构建内核 + zip 布局规范（[02-linkdesk-plugin格式规范.md](./02-linkdesk-plugin格式规范.md) 需改写「单文件自包含」条）；「逐表面失败隔离」与「入口导出零失真」两条既定收益要逐条复核；chunk 命名要稳定（与缓存/升级语义联动）；CSS 同问 |
| **(b) 保底：SDK 原语 ＋ 成规 ＋ 机械腿** | SDK 导出 `realmSingleton(key, init)`（globalThis 命名空间槽，即 marketplace 1.1.6 `realmSlot.ts` 的收编版）；作者面文档（03-plugin-authoring / 03-插件制造）补一条**成规**：「跨表面共享的可变状态必须走原语」；可行的机械腿 = lint 腿扫「多表面插件 services 里的模块级 mutable」（启发式，需先定误报口径再决定拦/报） | 不动作业面；但依赖作者遵守，**存量第三方仓不自动受益**；(a) 落地后本原语仍保留（会话级/非同源复用场景） |

**两层的次序**：(b) 是**下一版 SDK 就能发的立即解**（marketplace 1.1.6 已作插件侧先例，SDK 版只是把实现收编）；(a) 是**终局**（前提复位、断根）。建议先发 (b)（作者面立刻有正解可依），(a) 按独立轮次做 probe 后再定。

> 🔴 **2026-09-30 更新（用户拍板）**：**(a) 是根治、(b) 是过渡** —— 判据 =「**这个缺陷类在平台层不再可能发生**」（含不可盘点的第三方仓与将来任何插件类型）；(b) 的实质是**把平台的债转成作者的纪律**（漏用一次仍是静默面间不一致），其价值在「立即能发」与「存量老包唯一可用」，**不覆盖「作者不知道」**。⇒ **(a) 已单独立格 = `E6#159`**，设计与前置侦察结果落在 [13-跨表面共享chunk-设计前置.md](./13-跨表面共享chunk-设计前置.md)（两轨道相对 import 可解析**已验**；唯一硬点 = **SDK assemble 落位错位**，构建侧问题、不动加载器 ⇒ 壳侧目标零改动；含 8 维度 ＋ 两项未实证探针 ＋ 升级写盘原子性）。

> ✅ **2026-09-30 实施追记（`E6#159` 轮 0 ＋ 轮 1 已落地）**：(a) 写进 SDK 构建内核——`lib.entry` 单次多入口 build（原「每表面一次独立 build ＋ assemble 搬位」整段删除），共享模块只产一份 chunk、各表面按 rollup 自算的相对 specifier 引用；两条产物判据（**G1 入口齐备 / G2 共享模块唯一**，看 `OutputChunk.modules`）随构建常驻、命中即 `PACKAGER_RED` 硬失败。**两项探针结果**：lib 多入口**真产 chunk 且入口导出零失真**（顺带订正 E6#15「空 facade」归属——那只是非 lib 的 `rollupOptions.input` 路由的问题，不是形态墙）；**真机多文件首次加载**（原「未消」）**已由轮 2 落读数（2026-09-30）**：marketplace **1.1.7** 走**真安装通道**进隔离实例 ⇒ 8/8 入口加载成功、共享 chunk 按相对 specifier `../index-<hash>.js` **只取一次**、后挂载的表面**复用同一 URL**、`__linkdesk_pluginSlots__marketplace` 全产物 **1 处**（1.1.6 = 7 处）⇒ **「模块级 = 跨视图唯一真相」在真机真件上复位**（1.1.6 的槽从此是保险带）。其余两条真机判据：跨表面搜索过滤 ✅（侧栏搜索框输入 ⇒ 另一表面「已装列表」~200 ms 过滤、清空即恢复）；「检查更新」同帧翻新 与 `events.on` 单次订阅 **◐**（前者隔离 profile 无待更新样本 ⇒ 无徽标增量可观测，后者壳侧 `window.linkdesk.events` 被 contextBridge 冻结 ⇒ 页面内挂不住计数器）——两 ◐ 的替代读数 = 新挂载详情页与侧栏行**版本读数一致**（`官方语言 v1.0.35`，1.1.4 的落差不再复现）＋ 产物侧机械证据（槽指纹 1 处、8/8 入口同指一份 chunk）。**「逐表面失败隔离」退场**＝批量原子化，已在 [02 格式规范](./02-linkdesk-plugin格式规范.md):48 记账。壳侧 `src/` `electron/` **零改动**（`bundleCss.ts` 层级假设原样成立）。⇒ (a) 的真正意义：**第三方面里没被盘点的插件、将来任何新插件类型、作者根本没听过这条规矩的情况，一并断根**——(b) 从「必须遵守的纪律」降回「有意跨表面共享时的显式接缝」。

**marketplace 侧的衔接承诺**：SDK 原语一发，插件仓 `src/services/realmSlot.ts` **整体换成 SDK 版、8 处调用点一个不动**（现 API 形状即照此预留）。

## 五、验收判据（实施时）

- (a) 判据（机械）：多表面插件的产物里，同一共享模块**只出现一次**——**✅ 已落地为构建期两条**（G1 入口齐备 ／ G2 共享模块唯一，判据取 `OutputChunk.modules` 的模块 id，见 [13 号档](./13-跨表面共享chunk-设计前置.md) §六；命中即 `PACKAGER_RED` 硬失败，单测 7 例 ＋ 反向对照 ＋ 真拦实证）；真机复验 = 「检查更新」后侧栏与详情页同帧翻新、跨表面搜索过滤生效、`events.on` 单次订阅（**归轮 2**，marketplace 源码零改动重建重发，与 1.1.6 对照）。
- (b) 判据：SDK 导出面快照（只加不删门禁）＋ 原语单测（同 key 同对象 / 跨实例共享 / 命名空间隔离）＋ 作者面两棵树同笔 ＋ （若落腿）人造违规样例判红。
- 两条路共同的回归样本 = marketplace（现成的 7 表面真仓）。

## 六、边界与挂账

- ⛔ **不是**「壳加载器的 cache-bust」题：池按 URL `import()` 表面 bundle、**同 URL 不随磁盘替换重载** ⇒ 插件升级须重启才生效。这是**另一个**已知面（已随本案如实记账，归加载器优化域，不并案）。
- 📌 **2026-09-30 补（落档去向）**：本面已按 04 台账规矩**立档防遗忘** → [04 待抉择池/插件更新须重启.md](../../../04-软件更新/待抉择池/插件更新须重启.md)（两层缓存键的出处 · 一条可达的缝 · 两案候选修法）。**本档只保留"不并案"的定性**，细账不在此处铺开。
- ⛔ **不是**「单例模式错了」：模块级单例在**单表面**语境下是正确且首选的写法；要修的是**多表面语境的前提保真**。
- 🔴 **作者面文档现状**：03-plugin-authoring / 03-插件制造 全树**没有一条**讲「多表面共享状态」（案发时现查）——(b) 的必要性由此坐实。
