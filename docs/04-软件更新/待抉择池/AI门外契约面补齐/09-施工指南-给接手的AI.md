# 施工指南 · 给接手的 AI

> **这份文档写给「下一个动手的 AI」**，不是写给评审看的。它回答四件事：**为什么做、按什么顺序做、每一步怎么做、哪里会翻车**。
> 设计细节在 02–06；任务编号在 [08-任务清单](08-任务清单.md)；本档只讲方法与判断。
> 🔴 **先读 [00 前言](00-提案.md)**——那里有全部前因后果；本档默认你已经读过。

## 一、开工前（30 分钟，⛔ 不许跳）

1. **读 00 前言 ＋ §〇 证据 ＋ §四 被反证**。三处的信息密度最高，读完能避免 80% 的重复劳动。
2. **跑 T0 复测**：拉一次 `describe` 全量，数命令/插件，核对 00 §三 每一行的 file:line。
   - 读数变了 ⇒ 先改文档再开工（⛔ 拿 13 天前的行号改代码）。
3. **确认三件事仍然成立**：
   - 你手里的壳版本 ≥ 0.2.64？官方各插件仓是最新？SDK dist 已构建？
   - 当前分支干净？`npm run check` 基线绿？（红灯先修基线，⛔ 在红基线上叠功能）
   - 「内测免兼容」仍有效？（若用户已开放下载，⛔ 按本档的直接改法，先回 00 §七 看 #10 的恢复条件）

## 二、为什么是这个顺序（每条都有理由，⛔ 随意调）

| 顺序 | 为什么不能提前/推后 |
|:--|:--|
| **S7 风险** 第一 | 它是**安全底线**：现在默认档下 AI 对 `send`/`reset` 免确认。其余都是体验问题，这条是「已经出事但没人发现」。且改动小（一个 `risk.ts` ＋ 一批声明），先落先安心。 |
| **S4 可达性/作用域** 第二 | 它**改注册表结构**。S5 的自检、S3b 的描述面、作者文档全长在这个结构上；先做后面的会返工。 |
| **S5/S6** 第三 | 有了 S4 的稳定结构，`doctor` 才能断言「哪条该可用、哪条该要视图」；否则 doctor 自己都得绕开不稳定的现实。 |
| **S3b/S1/S2** 第四 | 描述面与回执是「读」的契约；在前三者把「命令在哪、能不能调」定下来之前，补 schema 会白补一遍。 |
| **D1/D2** 第五 | **依赖 [通用能力底盘](../通用能力底盘/00-提案.md) 的串口最小面**（壳透传字节）。底盘没落就做，只能在 `{text}` 上打补丁 ⇒ 第二套解码 ⇒ 下一轮返工。 |
| **连锁面** 最后 | SDK/脚手架/文档必须跟着**已定稿的实现**走；先改文档再改代码 = 文档撒谎。 |

## 三、分阶段施工要点（怎么做，⛔ 细节看分档）

### 阶段 A · S7（T1–T4）

1. **先读 `policy/risk.ts` 与 `policy/decide.ts` 全文件**（都很小）。判定逻辑**不动**，只改「risk 从哪来」。
2. 写一张**语义对照表**再动手：每条命令 × 它真实能造成的最坏后果。对照表先给用户过一眼——这是安全语义，⛔ 自己拍。
3. 改完跑一遍「默认档下 send 会被问吗？」——这是本阶段唯一重要的断言。
4. `riskSource` 设计成**可枚举的字符串**，⛔ 布尔开关（以后要加来源）。

### 阶段 B · S4（T5–T9）

1. **先改池侧，再改壳侧**：上下文栈在池，注册表在壳；壳只消费结果。
2. 上下文栈用**同步压弹**；`registerCommand` 只读栈顶，⛔ 自己维护一套挂载判断。
3. 分区改造时**先删后加**：先把「整片摘＋补注册」删掉，跑测试看哪里红，再按红点补分区。这样不会留死代码。
4. 三错误码**只在一处映射**（壳桥接层）；⛔ CLI、MCP、插件各拼一份。
5. 串口是**验收样本不是特例**：改它的时候，任何 `if (pluginId === "serial-monitor")` 都是错。

### 阶段 C · S5/S6（T10–T11）

1. `doctor` 的**断言 = 通用不变式**：回执同深度、变更命令有后置状态、paused 如实、错误有码。⛔ 写「游标」「波特率」「AT」。
2. 每条断言给 `assertionId ＋ 期望 ＋ 实际 ＋ 复现命令`；⛔ 只打 FAILED。
3. 先让它**对现有缺陷红**（这是它的价值），再修缺陷转绿；⛔ 为了让 doctor 绿而弱化断言。
4. `opId` 注册表住壳；插件只在 `registerCommand` meta 声明 `async: true`（壳自动包 op）；⛔ 插件调 `runAsync`、⛔ 自建状态机。

### 阶段 D · 描述面与回执（T12–T15）

1. **S1 先复现再改**：CLI 与 MCP 各调同一条命令，把两份回执贴进文档对比；不复现就销账（决策 #4）。
2. S3b 的 `returns` 是**字段表**不是 JSON Schema；只到第一层键（必要时一层嵌套）。
3. `example` 必须**能直接执行成功**——写完就真跑一遍。
4. S2 的 `pluginError` 住 SDK；壳只透传，⛔ 解释语义。

### 阶段 E · 数据面（T16–T18）

1. **先确认底盘串口最小面是否已落**。没落 ⇒ 停下来问用户，⛔ 自己开一条临时通道。
2. 改 contracts 时**三处同笔**：`contracts` 类型 → 壳 service → SDK 透传；⛔ 先改一处跑起来。
3. 删 `text` 时全仓搜索消费方（含测试 fixture），一次删干净。
4. 「自动」档的回退顺序写成**具名常量**，⛔ 藏在 if 链。

### 阶段 F · 连锁（T19–T23）

1. **代码 → SDK 类型 → 脚手架 → 03 文档 → AI 手册**，一路顺推。
2. 每改一处 SDK 导出，跑一次 SDK 自己的 tsc ＋ 自测；dist 要重建（dev 轨道解析 dist）。
3. 03 文档**中英双树同笔**（`docs:check` 逐字节比对）。
4. AI 手册 02 章是生成区，⛔ 手改；跑 `manual:build`。

## 四、陷阱表（都是踩过的，⛔ 再踩）

| # | 陷阱 | 症状 | 规避 |
|:--|:--|:--|:--|
| 1 | `executeCommand(id, token, ...args)` 省掉 `token` | 参数整体左移，命令**静默不动作**、不报错 | 一律三参起手；测试里显式传 `undefined` |
| 2 | 池/壳两侧都维护「命令是否存在」 | 说法不一致、互相打架 | 执行真相源 = 池；显示真相源 = 壳；只看一处 |
| 3 | 用 `useRef` 存影响渲染的激活状态 | 视图不更新 | 渲染决策走 `useState`（硬约束 17） |
| 4 | StrictMode 双重 effect 重复注册 | 命令注册两次、注销一次 | `_loadingPromise` 防重（硬约束 13） |
| 5 | 模块顶层绑 IPC 监听器 | 僵尸回调 | 走 `useEffect` ＋ 引用计数（硬约束 19） |
| 6 | 改了 `src/components/shared/**` 不 `ui:build` | dev 里看不到变化 | 改完必跑 `npm run ui:build` |
| 7 | 信任 `open:true` | 拔插后状态撒谎（B2-1） | 状态必须能被 doctor 断言；⛔ 只信接口返回 |
| 8 | 为 AI 偷偷开一个不可见 tab | 用户布局被写脏 | 要无视图就真的无视图（⛔ 幽灵 tab） |
| 9 | 为兼容留一条旧分支 | 死代码、两套真相 | 内测免兼容：直接删（决策 #10） |
| 10 | 写动词表猜风险 | 第二语言命名即失效 | 只声明/兜底 R2 |
| 11 | 写 `if (pluginId === ...)` | 违反硬约束 10 | 走声明；需要引用走常量/注册表 |
| 12 | 测试 fixture 用真实插件名/文案 | 违反硬约束 21 | `demo-plugin` / `Demo View` |
| 13 | 在红基线上叠功能 | 分不清谁弄红的 | 先修基线再开工 |
| 14 | 改完不跑 `npm run check` | 提交被拦或 CI 红 | 提交前必跑；纯文档改动按分诊跑法 |
| 15 | B 覆盖隔离实例插件 bundle 后只重启 electron | `/@fs` 仍服务旧转译产物（插件目录在 watch 外），`activation`/`meta.async` 到不了池 | 每次插件同步后**重启 vite**（只重启 electron 不够）；判定 `curl "...?import" \| grep -c "async: !0"` |

## 五、停点（遇到这些，⛔ 自己拍板，停下来问）

1. **T0 复测发现读数大漂**（命令数变化 > 10%）：先对齐口径。
2. **风险语义对照表**（T2）：`send` 到底 R1 还是 R2？这是安全判断，必须用户确认。
3. **底盘串口最小面未落**（T16 前）：等，⛔ 自开通道。
4. **两档文档冲突**（如本档与底盘/表现层可替换化说法不一致）：先按 [12](12-相邻任务关系与边界.md) §一 的优先级规则裁；裁不了 ⇒ 记录冲突并问用户。
5. **要动「已发布 tag」或撤版**：归用户（AGENTS.md 红线）。
6. **要做破坏性契约变更**（删字段、改签名）：确认「内测免兼容」仍成立。

## 六、验收与收口

1. **逐任务验收**：08 每行「验收」列的断言全部通过，⛔ 凭感觉。
2. **跨领域**：`doctor` ＋ 可达性 ＋ 风险判据，在 file-tree（非硬件插件）上同样成立。
3. **实机**：`doctor --blind` 跑通，含**拔插 USB**。
4. **用户抽验**：至少一次人工确认（外部 AI 从零调用一遍）。
5. **归档**：整理成 `已落地/` 时，按归档规矩搬件并写收口报告；本档的 `07` 判据表随案走。

## 七、禁止事项（写在这，防止「做着做着」）

- ⛔ 减少命令、或把内部纯函数也命令化（[00 §〇 04 节](00-提案.md) 已修正 Codex 的误判）。
- ⛔ 为兼容写双轨（决策 #10）。
- ⛔ 把编码策略塞回壳、或在插件里写第二份解码器（[06](06-数据面-方向与编码.md)）。

- ⛔ 在壳里按插件 id/命令 id 特判。
- ⛔ 用一个「万能返回对象」掩盖不同的返回值（`{ok:true, data:...}` 之外再包一层）。

## 八、交棒协议（AI 换手必读 · 用户硬要求）

> **没有交接 = 任务未完成；交接里「经验」为空 = 无效交接。**
> 🔴 用户原话：AI 交棒时必须**总结好自己的经验**。⛔ 不许「做一半直接停」。

### 8.1 什么时候交棒

- 任务包做完；或上下文快满；或用户换台。
- 交棒是**主动动作**——⛔ 等被叫停才写。

### 8.2 写在哪

`docs/04-软件更新/待抉择池/AI门外契约面补齐/交接.md` —— **一个文件，append-only**。
每人追加一节；⛔ 新建第二份、⛔ 覆盖前人的、⛔ 把 08 的任务表抄进去。

### 8.3 必填七项（⛔ 缺一即无效）

```md
## 2026-MM-DD · <AI代号> · 任务包 <T…–T…>

### 1 读数
壳版本 / SDK 版本 / 命令面条数 / `npm run check` 状态

### 2 已完成（只列「断言过了」的）
T<id> · 一句话 · file:line · 断言结果

### 3 未完成 / 阻塞
T<id> · 卡在哪 · 需要谁（用户拍板？前置任务？另一个 AI？）

### 4 踩过的坑（经验 · 必填）
症状 → 原因 → 规避（一条一行，⛔ 写「注意小心」这类空话）

### 5 我做的判断 / 假设
没拍板时的临时决定，逐条标「待复核」

### 6 下一位禁止事项
不要碰 X / 不要按 Y 理解 / 不要重复我试过的 Z

### 7 我改过的共享面
contracts / manifest schema / SDK 导出 / 门禁腿 —— 下一位必须知道
```

### 8.4 接棒门禁（调度台执行）

接棒 AI 必须依次：① 读 `交接.md` 全部；② 读对应分档；③ 回**接棒确认**（三句话：做到哪、⛔ 做什么、下一步）。
调度台验收这三步后才派新任务。⛔ 跳过交接直接开工 = 打回。

### 8.5 归一化

- **一个** `交接.md`；⛔ 每 AI 一份、⛔ 按任务一份。
- 交接只写「08 没写的」；任务状态仍以 08 为准。
- 经验必须**可执行**（症状→原因→规避）；下一位读完应能**少走一遍弯路**。

## 九、成本纪律（每个执行 AI 必守 · 派单原文附上）

> 依据：用户 2026-11-25 明确要求「派遣 AI 必须从省钱角度」。本项目计费 = **调用次数 × 重放上下文**。
> 所以省钱的本质不是少干活，是**少调用、少重放**。

### 9.1 十条硬规则

1. **一条命令干多件事**（`&&`、循环）；互不依赖的读取**并行发**。
2. **只读自己那份**：包内分档 ＋ 08 ＋ 09 ＋ 自己代码；⛔ 通读全部 14 份文档。
3. **大文件按需取**：>100KB 先 grep 定位，再 `offset/limit`；⛔ 整份读。
4. **不重复劳动**：同一命令不为「确认一下」再跑；同一文件不重读；用 `git diff` 代替重读。
5. **报告只给结论**：关键行 ＋ `file:line`；⛔ 贴工具输出全文。
6. **分诊跑检查**：只改文档/门禁 ⇒ 只跑对应腿；改 `src/`/`electron/` 才全量 `npm run check`。
7. **⛔ 扇出子代理**：默认 0；确需最多 1 个，并在交接里写明原因。
8. **上下文到 60% 就准备交棒**；⛔ 撑爆再交（爆了要重读，最贵）。
9. **任务包边界内作业**：发现要跨包改 ⇒ 停下报调度台，⛔ 顺手改。
10. **模型分工**：结构活（壳/池）用强模型；体力活（14 仓/6 个有命令仓补 manifest、写文档）用便宜档；调度台按 `ListModels` 现状选，⛔ 为省钱用做不对的模型。

### 9.2 调度台自身也守

- 收到「一」：**一句回执**，⛔ 复述上下文。
- 验收：看 `git diff --stat` ＋ 断言结果 ＋ 交接，⛔ 重读全文。
- 派单：**一次给全**（任务 ID ＋ 分档 ＋ 验收 ＋ 禁止事项 ＋ 本纪律），⛔ 挤牙膏式多轮。

### 9.3 预算与止损

- 每个任务包开工前，调度台报一个**调用次数上限**（粗估：任务数 × 20–30 次）。
- 到 **80%** 提醒；到 **100%** 仍未完成 ⇒ 停下写交接，⛔ 硬撑。
- 🔴 **省钱不能省验证**：断言、跨领域验收、`npm run check` 全绿，一个都不能少。

## 十、收尾协议（最后完成者收尾 · 用户定）

> 问题：A/B/C 并行，谁先完成谁就停；总调度台可能沉睡着 ⇒ **没人收尾**。
> 解法：**最后一个完成的人自动成为「收尾人」**。收尾人只做**机械收口**，不做最终裁决。

### 10.1 三方共写的状态文件

`收尾.md`（本目录）——唯一真相源：三行状态（轨道/会话ID/状态/时间）＋ 收尾认领区 ＋ 进度清单。
每人**只改自己那行**；⛔ 删别人的行。会话 ID 由调度台建台时写入。

### 10.2 完成时必做三件

1. 自己那行改 `✅`（**只有断言过了才改**）＋ 写完成时间。
2. `交接.md` 追加七项（[09 §八](#八交棒协议ai-换手必读--用户硬要求)）。
3. **尽力**发一条短消息给调度台（queued 也算送达）；发不出去就记进 `收尾.md` §四——⛔ 反复重试、⛔ 死循环。

### 10.3 认领收尾（防抢）

```
若 三行全 ✅ 且 认领区为空：
  写入 | <你的代号> | <时间> |
  立刻重读 收尾.md
  若认领区不是自己 ⇒ 放弃（别人已抢），回一句「<代号> 已认领」
  若是自己 ⇒ 开始收尾
```

⛔ 三行没全 ✅ 就认领；⛔ 写完不回读就开工。

### 10.4 收尾人做什么（只做机械收口）

- [ ] 跑**全量** `npm run check`
- [ ] 汇总三份 `交接.md`（**读**，⛔ 重写）
- [ ] 对照 [08 §九 DoD](08-任务清单.md) 抽查每条「已完成」
- [ ] 跨领域验收：file-tree 跑 doctor / 可达性 / 风险断言
- [ ] 写 `收尾报告.md`：通过 / 未通过 / 待拍板 / 风险
- [ ] 更新 08 勾选（**只勾断言过了的**）
- [ ] 通知调度台 ＋ A/B/C（结论一段话）
- 发现别人的缺陷 ⇒ **写缺陷单 + `SendToSession` 回原主人**，⛔ 自己改别人的所有权范围

### 10.5 收尾人**不能**做的

- ⛔ 宣布「验收通过」——那是调度台 ＋ 用户
- ⛔ 改别人的代码/文档（自己所有权内的可以）
- ⛔ 归档 / 提交 / 发版
- ⛔ 为了绿而弱化断言

### 10.6 收尾失败怎么办

- 收尾人上下文不够 ⇒ 在 `收尾.md` 标「收尾待接棒」＋ 写半份报告；调度台醒来后指定接棒。
- 收尾人自己卡住 ⇒ 同上，⛔ 硬撑。
- 三行永远不全 `✅` ⇒ 未完成的轨道写 `🟠 交接中` ＋ 阻塞原因；调度台/用户处理。

### 10.7 消息不可靠，文件才可靠

`SendToSession` **能**叫醒 idle 会话（2026-11-25 实测：idle 的调度台收到消息即启动），但⛔ 不把它当保证。
所有结论**先落文件**（`收尾.md` / `收尾报告.md` / `交接.md`），消息只作提醒。
