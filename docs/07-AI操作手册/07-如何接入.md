## 一、先懂两件事：门锁与钥匙

| 件 | 是什么 | 默认 | 用户在哪开 |
|:--|:--|:--:|:--|
| **接入开关** | **门锁**——开了才接；**关着时本机任何程序都连不进来** | **关**（安全默认） | 设置页「AI 接入」分区，一键开 |
| **凭据（token）** | **钥匙**——开关开着但钥匙不对，**照样被拒** | 随开关生成 | 设置页「AI 接入」分区，可重新生成 |

**开关 = 用户说「我同意让 AI 接手」的落点。** 默认关不是保守，是**授权粒度**：装软件 ≠ 授权任何程序操作你的界面。

🔴 **与裸 CDP 的本质区别**：CDP 是**无锁的门**（本机任意进程可连，无名单、无账本）；
「AI 接入」这条正门带三样 CDP 永远没有的东西——**钥匙（token）· 名单（白名单能力）· 账本（操作日志）**。

## 二、完整安全图景 = 锁门 × 管成员

| 谁 | 归谁管 | 怎么管 |
|:--|:--|:--|
| **外部 AI 客户端**（Claude Desktop / Codex / 终端里的 CLI） | **接入开关** | 上面那把锁：默认关、要 token |
| **插件** | **「你装了/启用了它」** | 装 / 卸 / 禁用——**插件管理就是它们的开关** |

⚠️ **插件不受「AI 接入」开关管**（设计拍板原话）：框架**不知道**哪个插件是「AI 插件」（**核心无知原则**），
给某类插件单独设闸 = 造特权、反而不一致。所以别问「开了开关会不会让插件更能干」——**两者是两条独立的闸**。

## 三、三路手把手（按你手边那个 AI 长什么样选）

| # | 你的 AI 长什么样 | 怎么接 | 一步的成本 |
|:--:|:--|:--|:--|
| ① | **终端型**（Codex / Claude Code / 任何能敲 shell 的 agent） | 一句话交代它用 `linkdeskctl` | **零配置**——敲名字即用（`--help` 自举） |
| ② | **桌面型**（Claude Desktop 等有 MCP 配置的客户端） | 设置页**复制 MCP 配置片段** → 粘进客户端配置 | **一次配置**——连一次，永久顺手 |
| ③ | **任何 AI**（没有 MCP、也不敲 shell） | **把这份手册丢给它**（或告诉它软件内哪里能读） | 零配置（手册随包就在它手边） |

**用户侧的前置动作（三路共用）**：装好软件 → 设置页「AI 接入」→ **打开开关** → （需要时）复制凭据。
**「MCP 还是 CLI」不是选择题**——两条都做、共用同一套操作面，**手边有什么就用什么**。

### 3.1 终端型：一句话

> **「用 `linkdeskctl` 操作我的 LinkDesk。」**

AI 收到这句会自己 `linkdeskctl --help`（见 §四）→ 拿到子命令清单 → 干活。
**用户不需要教它命令语法**——CLI 的发现方式就是 **`PATH` ＋ 名字**。

### 3.2 桌面型：粘一段配置

1. 设置页「AI 接入 · 接入引导」→ 点**[复制 MCP 配置片段]**；
2. 粘进 AI 客户端的 MCP server 配置；
3. 重启该客户端 → 工具清单里出现 LinkDesk 的能力（`tools/list`）。

**形态（M4 回填）**：第一版**只做 stdio 皮**——**不需要开端口**（安全半径更小），由 AI 客户端**按需拉起**
（天然规避「常驻依赖」）。⛔ 下面是**形状示意，别照抄**，真实字段以设置页复制出来的那份为准：

```jsonc
// ⚠️ 形状示意（M4 回填真实片段）——键名与参数以软件复制出来的为准
{ "mcpServers": { "linkdesk": { "command": "<linkdeskctl 绝对路径>", "args": ["mcp"] } } }
```

**备选（也是形态）**：`linkdeskctl mcp config --for <client>` 直接生成该客户端的片段。

### 3.3 任何 AI：把手册丢给它

本手册就是这条路的路面——它**随安装包发货**，不依赖 GitHub、不依赖源码：

| 它在哪 | 怎么拿到 |
|:--|:--|
| **软件内** | 菜单 **帮助 → AI 操作手册**（标签页；左列章节目录，右列正文）——**今天可用** |
| **磁盘上** | 安装目录的 `resources/ai-manual/`（**8 个 `.md`**，就是本目录的原样副本）——**今天可用** |
| 仓库里 | `docs/07-AI操作手册/`（维护者视角；用户机器上没有源码树） |

⇒ 「把手册丢给它」＝ 让 AI 读上面任一处；AI 自己能读到磁盘那份就可以**不经过人**。

## 四、软件自述三件（AI 自己问路，不靠手册）

**为什么这三件比手册重要**：手册是**快照**，运行时聚合是**真源**——你要操作的是用户**现在这台机器**上的实例（含他装的一切插件）。

| # | 问什么 | 命令／入口 | 返回 | 今天 |
|:--:|:--|:--|:--|:--:|
| 1 | **CLI 能干什么** | `linkdeskctl --help` | 子命令清单（含用法一行） | ⛔ M4 |
| 2 | **有哪些工具** | MCP 客户端里 `tools/list` | 工具清单（MCP 客户端自己就会列） | ⛔ M4 |
| 3 | **有哪些命令、怎么调** | `await linkdesk.commands.getCommands()` | 每条命令的 `id`/`title`/`category`/`when`/**`description`**/**`params`** | ✅ **今天可用** |

⚠️ 第 3 件**今天就能用**，且**是手册 [02 章](02-命令与API索引.md) 的数据源**（那张表就是它的快照）。
⇒ **在软件内**（有 `window.linkdesk` 时）优先用它，永远比手册新。

## 五、今天就能接（绕行路，立即可用）

⛔ M4 未发货 ≠ 今天没法接。**带参启动 ＋ CDP** 就能做到全量操作（含读取面）：

```bat
LinkDesk.exe --remote-debugging-port=9222
```

**代价（诚实说明）**：这条路**没有锁**——不需要开关、不需要凭据、本机任意进程都能连
（这正是设计**选择不堵**它的原因：正门靠「更好用」取胜，不靠堵后门；堵了的代价是开发期自己也用不了）。
坑与正解见 [06-CDP坑表](06-CDP坑表.md)；安装版上的启动细节见 [05-够不着清单与安装版路径](05-够不着清单与安装版路径.md)。

**安装版上的两条附加行为**（全文在 [05 章](05-够不着清单与安装版路径.md) §2.4/§2.5）：

1. **自动更新这一跳不丢端口**——更新前生效的调试开关会随重启带过去（白名单：`--remote-debugging-port` ·
   `--remote-allow-origins`；⛔ 不带 `--remote-debugging-address`）⇒ 不用再盯着「更新完端口就没了」；
2. **二次带参启动不只是「再开一次」**——软件已在跑时带 `--remote-debugging-port=9333` 再来一次：
   ⛔ 不起第二个实例，旧实例接管请求并**自重启**到新端口（⚠️ 新端口约 1–2 秒后才可用：旧实例要等到
   那个端口空闲、且第二次启动的进程退场才重启——原因见 [05 章](05-够不着清单与安装版路径.md) §2.5）；
   ⚠️ 不带调试开关的二次启动（双击图标）**不会**把正在用的端口掐掉。

**两件今天已经可用的接入面**：

1. **命令面 ＋ 契约 API**（软件内）——见 [01 章](01-操作路径总览.md) 与 [02 章](02-命令与API索引.md)；
2. **手册本体**——菜单 **帮助 → AI 操作手册**（命令 `app.openAiManual`，可被 AI 直接驱动）。

## 六、接上了没有（自检三步）

| 步 | 做什么 | 通了的样子 |
|:--:|:--|:--|
| 1 | 问清单：`getCommands()`（或 MCP `tools/list` / `linkdeskctl --help`） | **有内容**，且能看到**用户自己装的插件**的命令 |
| 2 | 读状态：`tabs.list()` / `pool.getLayout()` | 返回**当前界面真实结构**（不是空壳、不是报错） |
| 3 | 做一次**无害动作**再读回：开一个插件标签页 → 再 `tabs.list()` | 读数**变了**，且变的方向就是你要的（[01 章 §四](01-操作路径总览.md) 的「读 → 调 → 读」） |

**不通时对照**：

| 现象 | 大概率原因 | 去哪查 |
|:--|:--|:--|
| 连不上 | **软件没在跑**（冷启动问题）；或开关**关着** | 先把软件打开；再查设置页开关 |
| 被拒绝 | 开关开着但**凭据不对** | 设置页「AI 接入」重新生成凭据 |
| 命令「调了没反应」 | `when` 门控不满足（合法地什么都不做） | [04-手势隐藏规则](04-手势隐藏规则.md) |
| 看得到界面但门上没有 | 那里**根本没有门**（OS 层动作等） | [05-够不着清单](05-够不着清单与安装版路径.md) |

## 八、边界（⛔ 不承诺的事）

1. **不给任意 JS 权限**——正门是**白名单能力**，不是「把整个 Electron 交出去」。
2. **第一版只开本机回环**——这是**配置的结果，不是代码的假设**（传输层抽象留了口子：将来加 HTTP／远程／手机 = 加一个皮 ＋ 改一项配置，⛔ 不返工内核）。
3. **插件业务动作的覆盖度看插件作者**——插件把动作注册成命令 ⇒ 自动进 CLI/MCP 工具清单；没注册 ⇒ 没有门（[00 章 §一](00-README.md) 边界 3）。
4. **「装插件」是要问一声的动作**——包括从官方目录装（授权不缓存）。
