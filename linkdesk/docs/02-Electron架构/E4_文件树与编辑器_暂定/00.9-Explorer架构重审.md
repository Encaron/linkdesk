### 层 2：压缩导航控制器

| VS Code | LinkDesk 当前 | 差距 |
|:--|:--|:--|
| `CompressedNavigationController` 类（~120 行） | `getCompactedPath()` + `findLeaf()`（~35 行） | **根本性差异** |
| 树模型层处理（`CompressedObjectTreeModel`） | 数据层外 `flattenTree` 预处理 | 压缩态/展开态切换由树模型保证——我们靠手动 `return` 跳过 |
| 压缩节点内的段间导航（←→ 键在段间移动） | 无 | 键盘导航 #97 不支持压缩段 |
| `isIncompressible`——文件不可压缩、根直子不可压缩 | 文件被吞进链里（Bug B 根因） | 对标缺失 |
| aria label + 屏幕阅读器支持 | 无 | 无障碍缺失 |

**这是今天三个 CompactFolder bug 的根因——我们不应该在 `flattenTree` 层做压缩。** 压缩应该是一个树模型层的概念：压缩节点 → 展开 → 树模型自动解压缩并展示子节点。VS Code 把这个逻辑封装在 `CompressibleAsyncDataTree`（平台层，不在 explorer 里）。

### 层 6：视图容器架构

VS Code Explorer 不是一个"文件树组件"，而是一个**视图容器（View Container）**，包含多个子视图：

```
EXPLORER (ViewContainer)
├── OPEN EDITORS (View) ——标签页列表
├── FOLDERS (View) ——这才是"文件树"
├── OUTLINE (View) ——符号大纲（可由其他插件提供）
└── TIMELINE (View) ——文件历史（可由 Git 插件提供）
```

每种子视图是独立的 `ViewPane`，有独立的：
- context key（`FoldersViewVisibleContext` / `OpenEditorsFocusedContext`）
- 可见性切换（右键视图标题→显示/隐藏）
- 菜单贡献（`MenuId.ViewTitle` 的 when 条件区分不同视图）

我们的架构是：
```
图标栏 📁 = 文件树侧栏内容
```
**缺少视图容器层——📁 和 🔍 之间的切换是手动管理的，没有通用的 ViewContainer 框架。**
