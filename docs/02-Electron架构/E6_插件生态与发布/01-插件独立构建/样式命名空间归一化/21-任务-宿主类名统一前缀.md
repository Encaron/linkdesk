| **合计** | — | **34** | **296** | 46 | **8** | **28 文件 / 392 处** |

**口径（别混）**：
- 「**独立定义**」= 某条规则的选择器（逗号拆开后）**恰好就是这个类名**、无祖先、无其它简单选择器 —— 即 `11-样式命名空间审计.md` §三 图例里说的「选择器主体就是这个类名本身、且无祖先」。**这才是「谁占了这个全局名」**，也是本轮要清干净的目标集。
- 「**带祖先/复合定义点**」= 该名字出现在选择器里但带祖先或与别的类复合（如 `.ctx-menu.show`、`.form-row > .input`）。**定义点仍在**，但形态是「消费 + 限定」，改不改要逐个判（多数情况下**跟着独立定义一起改前缀**即可，因为它们指向的是同一个名字）。
- 「**仅复合状态类**」（本轮**不动**）：`.active` / `.on` / `.show` / `.disabled` / `.hidden` / `.focused` / `.collapsed` / `.is-selected` / `.not-overflow` 这一族，**只作为复合选择器的后缀出现、从不独立定义** —— 这**本身就是硬约束 23 ③ 要求的合法形态**（「状态类一律复合，不裸写 `.active {}`」）。审计档 §三 实测「跨方全部以复合形式使用」仍然成立。
- **TS(TSX) 站点**只在 **class 语境**里数（`className` / `classList` / `class:` / `class=` / `querySelector` / `closest(` / `matches(`），避免 `active` / `close` / `error` 这类短名把数字灌水。

### 1.3 三方自有名 —— **不需要白名单**（这是本格能不能守住禁区的关键）

池文档里还有**第三方**带进来的类名（最典型：`@vscode/codicons` 的 `codicon` / `codicon-*`，`src/main.tsx:5` 与 `src/pool/pool-main.tsx:21` 直接 import 其 `codicon.css`；`fileIconMappings.ts` 里还有一整张 `codicon-*` 映射表）。**它们绝不能改名**（改了 = 全软件 60+ 图标当场变方块）。

**实测结论（这就是「不需要白名单」的机械依据）**：拿宿主域那 **244 个独立定义名**去比 `node_modules/@vscode/codicons/dist/codicon.css`（655 个类名）——**交集 = 0**。为什么？因为 **`codicon*` 在本仓从来不是「独立定义」，只被「消费」**（`src/index.css:679` 那条是 `.codicon[class*="codicon-"]` 属性选择器 override；其余是 `.plugin-icon--codicon` / `.pd-icon-codicon` 这类复合）。⇒ **「独立定义必须 `ldk-`」这条结构性规则天然把它们排除在外**，一个字的白名单都不用写。

> ⚠️ 判据写成「**独立定义**必须 `ldk-`」就够；**不要**写成「CSS 里出现过的类名必须 `ldk-`」——那会把 `codicon*` 连同第三方依赖一起卷进来，逼出白名单。

### 1.4 🔴 本轮最容易被忽略的代价：**共享组件改名会破坏跨仓 scoped 调优**

[11-样式命名空间审计.md](../11-样式命名空间审计.md) §五 记着当年**为什么把共享组件那 8 个裸定义推迟**：「破坏跨仓插件的既有 scoped 调优，今天无收益」。**本格对那 52 个做同一件事，所以必须先把代价量出来**：

**实测**：把 52 个名字拿去扫 **18 只官方插件仓**（`.css` ＋ `.ts(x)`，排除 `node_modules` / `dist`）⇒ **只有 1 个名字有跨仓消费**：

| 被消费的名 | 谁 | 在哪 | 形态 |
|:--|:--|:--|:--|
| `.theme-picker` | `settings` | `src/views/SettingsView-rows.css:127,131` | `.settings-row:has(.theme-picker)` ＋ `.settings-row:has(.theme-picker) .settings-row-control` |

⇒ **代价是 1 处 / 1 只插件**（远轻于当年 8 个名字的处境）。落地时**同笔**改 settings 那两行 ＋ 走一次插件发版（bump / verify / build / Release / 目录 / 种子），否则**主题选择器那两张设置行的版式会静默失效**（`:has()` 不再匹配）。

另有一族是**第三种命名形态**，也在那 52 里：`.tbadge` / `.tname` / `.tname-name` / `.pv-bar` / `.pv-dot` / `.pv-dots`（`ThemePicker.css`）——它们是 `.badge` 案当时用的**临时短前缀**，既不属 `ldk-`、也不属任何插件 id。本轮一并归位（`ldk-` 开头），**别把它们当成「已经有前缀了」跳过去**。

## 四、禁区

- 🔴 **不许引白名单 / 基线 / 棘轮**（本系列一贯禁区）——本轮**全部意义**正是「让它不需要白名单」。§1.3 已给出机械依据：判据写成「**独立定义**必须 `ldk-`」，三方名自动出射程。
- 🔴 **不许顺手改视觉**（只加前缀、不改一个属性值；要改视觉先调 design skill）。
- 🔴 **不许只改 CSS 不改 TSX**（漏一个渲染点 ＝ 那个元素**当场没样式**，而且门禁查不出「名字对但漏改」）。
- 🔴 **不许只改宿主域、漏共享组件域**（两个域同一次落地；分两次 = 作者轴要发两次版、插件要重发两次）。
- 🔴 **不许顺手改插件 ID / `data-*` / CSS 变量 / 元素 id**（本格射程 = **类名**；id 撞车是另一条账，插件前缀轮的 ⑧ 已实测「18 仓 id↔类名同名 0 处」）。
- 🔴 **不许并进 1.20**（1.20 是复核轮，规矩是「发现缺漏只点名回队列，不救火」）。
- ⚠️ 照旧：不跳 `npm run check` · **壳仓另有写手 ⇒ 只按路径 `git add`** · 推前**现测代理**（本机直连时好时坏，搬字节一律带 `-c http.proxy=http://127.0.0.1:7890`）· 推完**必须 `git ls-remote --heads origin <branch>` 对 SHA**（1.17 踩过：分支无 upstream 时裸 `git push` 静默失败而 tag 照样推成功）。
- ⚠️ **顺序**：本格必须在 **1.17（✅）/ 1.18 之后**（它们会改同一批文件的同类名字；先做它们能少改一遍、少一次实机核对）。
