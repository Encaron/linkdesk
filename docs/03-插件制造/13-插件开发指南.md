## 开写前——三条铁律

违反这三条，插件**装得上但会坏**（甚至带崩壳）。先记住，比写完再改便宜得多：

1. **只走 `window.linkdesk.*`**——禁止 `import` 壳内部（`@src/core/...`）。ESLint `noCoreImportInPlugin` 是 error 级，写下去就红。
2. **颜色走 CSS 变量 `var(--xxx)`**——禁止硬编码 hex，否则主题切换时你的插件不跟随。
3. **文案走 `t()`**——key 就是原文（中文插件用中文 key，中文自带兜底，英文译文放 `i18n/en.json`）。

> 全八条 + 适用范围 → [00-README §硬约束](00-README.md#硬约束写任何一行插件代码前)。

## 第 1 步：生成项目骨架

**做什么**

```bash
npm create linkdesk-plugin my-cool-plugin    # 名字必须 kebab-case（小写字母/数字/连字符）
cd my-cool-plugin
npm install
```

不带参数运行 `npm create linkdesk-plugin` 会交互式问插件名。

**怎么知道做对了**
新目录里出现 `plugin.json` + `src/index.tsx`，且 `plugin.json` 里的 `{{pluginName}}` 之类占位符**已替换成你的真实插件名**（还有 `name` / `description` / `author` 已填好，`author` 默认取 `git config user.name`）。

**细节点哪一篇**
[02-插件开发工具链/01-create-linkdesk-plugin脚手架.md](../02-Electron架构/E6_插件生态与发布/02-插件开发工具链/01-create-linkdesk-plugin脚手架.md)——生成产物的**逐文件契约**（每个文件为什么存在、占位符规则、11 个模板文件的角色）。**项目结构不要在这里找**，那篇是唯一真相源。

> 🔁 **建仓（第 7 层 7.6 轮落地后此注记改写）**：脚手架**将**代建 git 仓（照 `cargo new` 语义，生成即 `git init`，`--no-git` 可跳过）。**现状（2026-09-14）：尚未落地**——工程还不是 git 仓，发布前需自己 `git init` ＋ 接远端，见第 9 步的前置注记。工程该放哪、仓叫什么 → [15-多仓开发与本地工作区](15-多仓开发与本地工作区.md)。

## 第 3 步：写你的第一段 UI

**做什么**
改 `src/index.tsx` 里 `default export` 的那个 React 组件。壳就是这么渲染它的：

```tsx
export default function HelloPlugin({ isActive }: { isActive: boolean }) { … }
```

- `isActive` = 本标签页当前是否聚焦。**keep-alive 架构下所有标签页始终挂载**——别用 `isActive` 整块 blank 掉内容，它只配用来 gate「聚焦才该跑的副作用」（如自动保存、轮询）。
- `tabId` / `sourceId` = 本标签 id / 上下文数据（编辑器类插件靠 `sourceId` 知道用户打开了哪个文件）。

**怎么知道做对了**
预览宿主里 UI 随你改。**并且**：界面里没有任何裸 hex 颜色、没有硬编码中文（用 `t()`）——这两条肉眼可查，也是后面 `npm run lint` 会拦的。

**细节点哪几篇**
- 视图契约细节 → [05-插件UI写法规约](05-插件UI写法规约.md)（右键菜单/浮层/持久化/快捷键两轨道）
- 想放进侧栏或底部面板 → [08-ViewContainer-视图容器API](08-ViewContainer-视图容器API.md)

## 第 4 步：调一个 API

**做什么**
`window.linkdesk.` 后面能接什么，看**速查表**（45 个命名空间 / 242 个方法，从契约自动生成）：

- 👉 [plugin-sdk README §API 速查表](../../packages/plugin-sdk/README.md#api-速查表)
- 完整签名与逐方法说明 → `node_modules/@linkdesk/contracts/linkdesk.d.ts`（IDE 里能直接跳转）

例：读一个配置项、订一个变更。

```ts
const theme = await window.linkdesk.theme.getCurrent();
const dispose = window.linkdesk.configuration.onChange("my-plugin.greeting", (v) => { … });
```

**怎么知道做对了**
TypeScript 编译通过就是对的——`window.linkdesk.*` 的类型随 SDK 注入（`tsconfig.json` 的 `types` 已配好），**方法名拼错、参数类型不对，`tsc` 当场红**。这是契约给作者的免费防线。

**细节点哪几篇**
- 哪些面在池/壳哪一侧可用、`?` 标法什么意思 → [01-插件API契约 §三 唯一真相源](01-插件API契约.md)
- ⚠️ **速查表里带 `°` 的方法**（契约标 `?`）只在一侧 preload 注入，**多数是壳侧独有**——你的插件跑在池里，调之前先判存在。
- 插件间怎么传数据 → [07-插件间通信](07-插件间通信.md)（事件广播 / 命令调用 / 数据管道）

## 第 5 步：声明贡献点（命令 / 菜单 / 快捷键 / 配置 / 标签页 / i18n）

**做什么**
在 `plugin.json` 的 `contributes` 里声明。命令、菜单项、快捷键、配置项、视图、主题、i18n、顶栏按钮**全在这里登记**。

**怎么知道做对了**

```bash
npm run validate     # 校验 plugin.json：$schema / 字段合法性 / i18n 文件存在
```

输出无错即通过。声明了命令 → 按 `Ctrl+Shift+P` 能在命令面板里搜到它；声明了配置项 → 设置页出现该项。

## 第 6 步：用共享组件（别自己造右键菜单）

**做什么**

```bash
npm i @linkdesk/ui
```

右键菜单、下拉、开关这类控件走共享包——**玻璃/主题自动跟随**，不用自己调样式。

**怎么知道做对了**
切换主题时你的右键菜单外观跟着变（自造的实现通常不会）。仓库硬约束 3 明确：手写右键菜单是违规的。

## 第 7 步：装进真的 LinkDesk 里验证

**做什么**
预览宿主毕竟不是真壳。要确认真机行为（真串口、真文件、真窗口）：

```bash
npm run dev:real     # = linkdesk-plugin-sdk dev --real
```

**怎么知道做对了**
LinkDesk 主程序里能看到你的插件、行为与预览一致。**注意一个边界**：安装态插件跑的是**预构建 bundle**，改了源码必须重 build 才生效——这不是 bug，是分发纪律。

**细节点哪一篇**
[04-作者真机调试环.md](../02-Electron架构/E6_插件生态与发布/02-插件开发工具链/04-作者真机调试环.md)——真机环怎么自动化「重 build + 直写」，以及为什么安装态改 bundle 不算热更。

## 第 8 步：打包分发给别人

**做什么**

```bash
npm run build
```

**怎么知道做对了**
项目根出现**一个** `<pluginId>.linkdesk-plugin` 单文件（zip），外加 `dist/<pluginId>.linkdesk-plugin/` 解包目录。把这个单文件给别人，对方就能装。

⚠️ **别把源码目录当分发载体**——「整目录复制即安装」的时代已结束。而且 `plugin.json` 的 `version` 一旦 +1，**必须同笔在 `CHANGELOG.md` 补一段 `## v<新版本>（YYYY-MM-DD）`**，否则插件详情页会显示「此版本未提供变更说明」。

## 第 9 步：上架市场

**做什么**

```bash
npm run publish      # = linkdesk-plugin-sdk publish
```

**前置——工程必须已是推到 GitHub 的 git 仓库**

publish 的目标仓库 = 你工程的 git remote `origin`（发布到**你自己的** GitHub 仓：Release 资产 ＋ 仓库根 `marketplace.json`；多市场源模型）。跑之前 `git remote -v` 确认 origin 指向你的 GitHub 仓。

> ⚠️ **现状（2026-09-14）**：脚手架**尚未**代建 git 仓——新建工程需手敲三条：`git init` → `git remote add origin git@github.com:<你>/<仓>.git` → `git push -u origin main`（这也是 publish 缺仓时报错提示的三条）。脚手架代建落地后（E6 第 7 层 7.6 轮），本注记与第 1 步的建仓注记同笔更新，别让文档承诺没实现的东西。

**怎么知道做对了**
GitHub Release 上出现你的 `.linkdesk-plugin` 资产，LinkDesk 市场里搜得到你的插件、能装、能更新。

**细节点哪几篇**
