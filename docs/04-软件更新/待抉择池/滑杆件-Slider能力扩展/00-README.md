# 滑杆件 · Slider 能力扩展（单位值标签 ＋ 细调步进）

> **状态：📋 待拍板（2026-10-03 立案）——⛔ 本夹零代码改动。**
> 一句话：把「值标签」和「细调按钮」从设置仓的包裹层**下沉进 Slider 共享件本体**——可选声明、不声明＝旧版（只增宣言）。这是「设置行-控制只读同行」案的前置件。

## 一、你令的原话（2026-10-03）

> 「slider 脱离设置插件，其他插件单独使用就只有孤零零的滑杆？这是能力的缺陷对吧。」——**是，已取证坐实（§二）。**
> 「slider 自带单位文字声明……比如 xxms、xxFPS、xxpx、xxN、xx毫米……可以让这个显示在后面，前面，上面，下面……我们只给 slider 这个显示单位的能力，不声明则代表不用这个能力，单位是什么由插件作者自己决定。」
> 「在滑杆左右两边有个 − ＋ 按钮，细调 slider 值，同样，不声明则不显示这个，我们只给 slider 提供这个能力。」
> 「壳就相当于主题系统的主人，第一个使用这个能力的不是插件作者，不是别人，而是壳。」
> 「涉及到壳共享 ui 的改动，就要使用 skill 设计好 html：/impeccable、/ui ux pro max。」

## 三、要落的能力（两条，均为可选声明）

| # | 能力 | 契约要点 |
|:--:|:--|:--|
| ① | **单位值标签** | 新 props：`unit?: string` ＋ `unitPosition?: "before" \| "after" \| "above" \| "below"`（缺省 `"after"`）。显示**「当前值＋单位」**（如 `25 px`）——一步两得：提示步进刻度语境 ＋ 提示当前值（你 1.1 的原意）。**不声明 ＝ 不显示 ＝ 今天的观感** |
| ② | **细调步进** | 新 prop：`stepper?: boolean` → 轨道两侧 **− / ＋** 真按钮（按既有 `min/max/step` 夹取步进；`disabled` 联动置灰；`aria-label`「减少/增加」）。**不声明 ＝ 不渲染**。长按连发不做（NumberInput 前例：单击单发，[04 决策 D2](04-任务清单.md)） |

**只增宣言有门禁背书**：`check-api-surface-additive` 会拦任何删改——既有 props 一个不动，新 props 全部可选缺省 undefined。

## 四、与「设置行-控制只读同行」案的关系（先后顺序）

- **代码不相依**（本案动 `@linkdesk/ui` 组件；那案动配置声明语义＋SettingRow 布局），**可并行**。
- 但**建议本案权利在前**：① 壳是第一个用户（现有滑杆键全是壳的外观键）；② 设置仓的包裹层届时**一次清干净**，避免同一段行渲染动两次。
- 本案落地后：**单位脱离设置插件随处可用**（你第 4 点）——任何插件的任何界面直接 `<Slider unit="ms" stepper />`。
