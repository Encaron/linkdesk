## 二、要做

### 1. 四条路线逐条评估（每条给：**能解决什么 · 不能解决什么 · 对本仓的代价 · 适配性**）

| 路线 | 先验判断（**本格要自己验，可推翻**） |
|:--|:--|
| **`@layer`（级联层）** | ⚠️ **只解决「谁赢」，不解决「谁命中」**——插件的 `.badge` 仍会**匹配**宿主元素，只是丢掉级联。**对 `--x` 与元素选择器同理** ⇒ **不能替代命名空间**。价值另有一处：**让「宿主 > 插件」的次序显式化**（今天靠源码顺序，隐含且脆弱）。代价：**全库级联变更**，视觉回归面广（10 主题 × 18 插件 × 全部表面） ⇒ 风险等级与其他件**不在同一档** |
| **Shadow DOM** | ✅ **真隔离**（唯一能从构造上消灭这一类问题的手段）。代价：插件是**外部仓库**、产物是 `linkdesk://<id>/index.bundle.css` + React 组件直挂 —— 要做就得改**渲染模型**（挂载点、主题 token 穿透、`codicon` 注入、事件冒泡/委托、布局量测、a11y、DevTools、以及**全部 18 仓 ＋ 第三方**的适配）。⇒ **量级远超本系列全部件之和** |
| **CSS Modules** | ⚠️ **构建期**把类名改成哈希（**只对自家源码有效**）⇒ 管不到**第三方插件仓**（它们各自构建、各自 bundle），而这一类问题的另一半恰恰在插件侧 ⇒ **只能解决一半，且是已经解决的那一半** |
| **动态注入隔离**（每插件一张 `<style>` ＋ 运行时重写/scope 包裹） | ⚠️ 运行时要改写**别人构建好的 CSS**（解析 ＋ 重写选择器）⇒ 脆弱、有性能成本、且**绕过方式多**（内联样式、`@import`、`style` 属性）；**不解决 `--x` 与元素选择器**（重写后仍可能命中） |

### 2. 落决策（**本档推荐：不做隔离**，理由须由本格用上表实证支撑）

决策要写成**一句话可复述**，并**指明替代机制**：

> **决策**：**不做渲染隔离**（`@layer` / Shadow DOM / CSS Modules / 动态注入四路皆不采用）；改用**「命名空间约定（四条轴）＋ 静态门禁（结构性 ＋ 自测接线）＋ 运行时全表断言探针」**三层替代。
> **理由**：四种隔离手段在**本仓的多方同表 + 外部插件仓 + 独立构建**这套约束下，**代价与收益不成比例**（逐条见评估表）；而三层替代已把这一类问题收窄到**事实层**（有探针可证）、**构造层未消灭**（如实登记）。
> **影响**：第三方插件作者**必须**遵守命名空间与作用域规则（作者面 §12 ＋ 迁移说明）；**任何**新增的跨方样式都必须过门禁；本决策**不改变**用户可见行为。

### 3. 写死**触发条件**（什么情况下重新评估——**这是决策记录里最有价值的一段**）

至少四条，逐条写成**可判定**的：
1. **第三方插件上架数达到某个量**（给具体阈值并说明怎么定）——生态越大，约定越容易被人手滑破坏；
2. **出现第一次真实绕过门禁的事故**（不是门禁红，而是**门禁绿却出了事故**）——那说明有一条轴没被覆盖；
3. **上游/标准提供可用的隔离能力**（例：CSS 原生 **`@scope`** 的浏览器支持与工具链成熟度达标）——那时代价曲线会翻转；
4. **插件间冲突变成用户可见问题的频率超过某个阈值**（给判定方式）。

### 4. `@layer` 必须单独给结论

本格**必须**明确回答「**要不要为了「宿主 > 插件」的确定性而引入 `@layer`**」，三选一：
- **(a) 不做**（写明理由 ＋ 进触发条件）；
- **(b) 做** ⇒ 🔴 **本件不落地**，**另立一格**（它是全库级联变更，风险等级不同，必须有自己的实测/回归/发版链）；
- **(c) 先做一次代价测量再定** ⇒ 那就把「测量」写成下一格，别把结论悬空。
