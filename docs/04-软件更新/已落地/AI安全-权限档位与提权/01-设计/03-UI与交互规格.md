# 03 · UI 与交互规格

> 目标：用户能一眼看懂「AI 现在能做什么、刚才做了什么、要不要点头」；所有面都可被第三方替换（万物皆可插件），但**数据/判定只走壳命令**。

## 二、设置页「权限」分节

### 2.1 声明（壳）

在 `src/App/config/aiBridge.ts` 的「开放范围与安全」组新增：

| 键 | 类型 | 声明 | 说明 |
|:--|:--|:--|:--|
| `ai.policy.mode` | string（enum） | `uiHint:"aiPolicy"`，`enum:["read","ask","auto","full"]`，`default:"auto"`，`enumDescriptions` 四句人话 | 主控件 = 四段控件 |
| `ai.policy.summary` | string | `renderHint:"readonly"`，`statusCommand:"aiPolicy.statusSummary"` | 当前档 + 风险矩阵一行摘要（运行时生成，⛔ 不写死） |
| `ai.policy.openRiskTable` | string | `renderHint:"action"`，`actionCommand:"aiPolicy.openRiskTable"` | 打开完整风险表（或设置内联展开） |

- `enumDescriptions` 写「谁能做什么」，不写技术术语。**逐字用下表**（中英同键，落 i18n 字典）：

| 档 | 中文 | English |
|:--|:--|:--|
| `read` | AI 只能查看，不能修改。 | AI can look, but cannot change anything. |
| `ask` | AI 每次要修改，都会先问你。 | AI will ask before every change. |
| `auto` | 日常修改 AI 自己完成；装更新、删数据这类操作仍会先问你。 | AI handles routine changes; it still asks before updates or deleting data. |
| `full` | 所有操作都不再询问，直到你在这里改回来。 | Nothing is asked until you change this back. |

> 🔴 **文案纪律**：面向用户的话里⛔ 不出现「账本」「白名单」「R3」「回退」「被管的那个」这类实现词。要说「会记录」「只有你能改」「装更新、删数据」。
- 设置插件**零硬编码**：只按 `uiHint:"aiPolicy"` 渲染共享件；第三方设置 UI 用同一个 `@linkdesk/ui` 组件即得同能力。

### 2.2 四段控件（共享件）

`@linkdesk/ui` 新导出 `AiPolicyPicker`（只加不删）：

```
[ 只读 ] [ 逐次确认 ] [ 自主 ] [ 完全访问 ]
```

- 每段下方一行小字：该档「R0 ✅ · R1 ✅ · R2 ✅ · R3 询问」的摘要（数据来自 `aiPolicy.getState()`，⛔ 不写死）。
- 选中 `full` 时：控件下方出现**常驻提示条**「AI 现在可以执行所有操作，不会再询问。这个设置会一直有效，直到你在上面改掉。每一步都有记录，随时可以查看。」＋「改成自主」按钮（同一命令）。
- 选中 `auto`（默认）时：提示「日常修改直接执行；装更新、删数据这类操作仍会先问你。」
- 键盘：←/→ 切段，Enter 确认；聚焦环走 token。

### 2.3 切换动作（GUI ↔ 命令同一入口）

| 动作 | 命令 | AI 可调？ |
|:--|:--|:--|
| 读当前策略 | `aiPolicy.getState` | ✅（R0） |
| 切档位 | `aiPolicy.setMode`（`userOnly:true`） | ⛔ `EPROTECTED` |
| 复位默认（自主） | `aiPolicy.resetToDefault`（`userOnly:true`） | ⛔ `EPROTECTED` |
| 请求提权 | op `requestElevation` | ✅（但只是请求） |

- `setMode` 仍注册为命令（A 判据：GUI 动作必须有命令面），但靠 `userOnly` 让 AI 够不着；**GUI 与命令同一条实现**。

### 2.4 完整风险表（点开是什么）

- **触发**：`ai.policy.openRiskTable`（既有 action 行模式）。
- **现状**：`aiBridge.openScopeList` 是 `DialogService.alert()` 一段文字（`aiBridgeCommands.ts:229-241`）——用户看不出「哪条能做、哪条会问」。
- **目标**：`DialogHost` **内容模式**打开一张表（`max-width:80vw`，可滚）：

| 操作 | 是什么 | 风险 | 现在 |
|:--|:--|:--|:--|
| 读取界面状态 | 看标签、通知、布局 | 查看 | 允许 |
| 打开标签页 | 切到某个页面 | 可撤销 | 允许 |
| 写工作区文件 | 改你项目里的文件 | 会留下改动 | 允许 |
| 安装插件 | 装上会运行新代码 | 需要你同意 | 询问 |
| 装软件更新 | 重启并换掉程序 | 无法撤销 | 询问 |
| 修改权限设置 | 改的就是这一页 | 只有你能改 | 不允许 |

- 数据：`aiPolicy.getState().riskTable`（壳登记 ＋ 插件清单 `risk` 合并）；⛔ 前端不写死行。
- 底部图例：允许 / 询问 / 不允许；一句「风险由软件统一登记，插件自己的命令也要声明」。

### 2.5 细分管理（点开是什么）

- **触发**：`aiBridge.openSensitiveManager`（既有 action 行）。
- **现状**：只弹一段文字占位（`aiBridgeCommands.ts:261-275`：「后续版本提供」）。
- **目标**：`DialogHost` 内容模式的管理器（列表 + 状态/开关）：

| 能力 | 现在 | 说明 |
|:--|:--|:--|
| 安装 / 卸载插件 | 每次询问（固定） | 装上会运行新代码，不可关闭 |
| 发送串口数据 | 允许 | 关掉后 AI 不能替你发数据 |
| 打开调试端口 | 不允许 | 调试端口风险高，默认关 |
| 修改工作区文件 | 允许 | 关掉后 AI 只能读 |

- 顶部一句：「这些设置控制 AI 能做哪类事；它们不会绕过上面的权限档位。」
- 改动即时生效 + 一条轻回执；变更进账本。
- **落位**：`src/pool/shared/ai-policy/AiSensitiveManager.tsx` ＋ `DialogHost` 内容模式；数据/动作来自壳，⛔ 不放设置插件私有目录。

## 三、确认框（ask 档）

复用 `DialogHost`（`src/pool/floating/dialog/DialogHost.css`）：居中、`min-width:300px`、`max-width:80vw`、`--radius-lg`、遮罩 `--scrim-dialog`。

```
┌──────────────────────────────────────────┐
│ AI 想安装一个插件                         │
│                                          │
│ serial-monitor v1.0.41                   │
│ 安装后它会开始运行，所以先问你一声。       │
│                                          │
│ 当前权限：逐次确认                        │
│                    [ 不允许 ]  [ 允许 ]   │
└──────────────────────────────────────────┘
```

- 按钮：`不允许`（Esc）/ `允许`（Enter）；**不提供**「永远允许」——那由档位承担，⛔ 不在框里做第二套记忆。
- 文案：`what` / `subject` / `why` 三件，全部来自风险登记表（⛔ 不手抄）；`why` 用人话（见 §2.1 文案纪律）。
- 后续（可选）：`[ 去设置 ]` 次按钮，直达设置页对应分节；不是批准动作。
- 超时：无人应答 10 分钟 → 关闭并 `ESHELLTIMEOUT`（文案说「没选择就不会执行」）。

## 四、提权请求框（`requestElevation`）

```
┌────────────────────────────────────────────┐
│ AI 想提高权限                               │
│                                            │
│ Claude Code 想从「逐次确认」升到「自主」。   │
│ 原因：需要连续整理 12 个主题插件的资料。     │
│                                            │
│ 允许后，AI 可以自己完成日常修改；            │
│ 装更新、删数据这类操作仍会先问你。            │
│ 这个设置会一直有效，直到你在设置里改回来。    │
│                                            │
│          [ 暂不 ]  [ 允许 ]                 │
└────────────────────────────────────────────┘
```

- 标题用「AI 想提高权限」，不用「请求提权」；按钮用「暂不 / 允许」，不用「批准（只能你点）」。
- **允许 = 写档位**：在弹窗 handler 里执行，不经命令面（见 02 §四）；文案必须说「会一直有效」，⛔ 不藏常驻事实。
- 允许后立刻发 `onDidChangePolicy` 事件；设置页与状态栏同步。
- 拒绝：`{granted:false}`，并给一条轻提示「已拒绝，AI 的权限没有变化」（通知面板或 toast，按路由）。

## 五、状态栏 AI 徽标

| 档 | 徽标 | 行为 |
|:--|:--|:--|
| `read` | 灰点 + `AI 只读` | hover 提示；点击开设置 |
| `ask` | 灰点 + `AI 询问` | 同上 |
| `auto` | 紫点 + `AI 自主` | 同上 |
| `full` | 紫点 + `AI 全权`（常亮/呼吸） | 点击开设置；降档一键 |

- 数据源：`aiPolicy.getState()` + `onDidChangePolicy`。
- 通道关着（`ai.mcp.enabled=false` 且 `ai.cli.enabled=false`）⇒ 徽标隐藏（没门可管）。
- 无障碍：`aria-live="polite"`，档位变更播报一次；不抢焦点。

## 六、回执（拒绝/已执行/降级）

- **两个面、同一个 store**（`src/core/services/ui/toast.ts`）：
  - **轻提示** `TransientToast`——底部居中（`transient-toast.css:8-12`），3s，最多 3 条；
  - **铃铛面板** `StatusBarZone`——留存、分组、可回看。
- **路由判据**：`toastRouting.decidePresentation`——error / 动作 >1 / 显式换行 >2 / `ttl≥8000` / 常驻 ⇒ **面板**；其余短回执 ⇒ **轻提示**。⛔ 一条条目只进一个面，⛔ 不新建第二队列。

| 事件 | 面 | 文案（中） | 动作 |
|:--|:--|:--|:--|
| 切换档位成功 | 轻提示 | 已切换到「自主」 | — |
| 切到完全访问 | 铃铛面板（常驻留痕） | AI 现在可以执行所有操作 | 改回来 |
| AI 尝试修改权限设置 | 铃铛面板（error） | AI 不能修改权限设置，已阻止 | 去设置 |
| 提权被拒 | 轻提示 | 已拒绝，AI 的权限没有变化 | — |
| 无人确认超时 | 轻提示 | AI 的操作已取消（没有人确认） | — |
| R3 已执行（装更新） | 铃铛面板（留痕） | AI 已执行：装软件更新 | 查看 |
| 细分开关变更 | 轻提示 | 已更新：发送串口数据 = 允许 | — |

- 文案一律 **i18n key + 参数**（壳侧 `lang-defaults` 中英齐；设置插件侧进自己的 `i18n`）；`aiPolicy.receipt()` 返回 key，不返回裸中文。⛔ 插件自己拼。
- 轻提示位置**底部居中**（⛔ 右下）；铃铛面板从状态栏铃铛处展开（既有机制）。

## 七、替换边界（万物皆可插件）

| 可替换 | 不可替换 |
|:--|:--|
| 四段控件外观、风险表**表格渲染**、确认框外壳、状态栏徽标外观、设置分区整套、细分管理器外观 | 档位值、风险**数据**、`decide`、执行闸、`userOnly` 判定、批准写点 |

替换渲染体只消费：`aiPolicy.getState()` / `onDidChangePolicy` / `aiPolicy.receipt()`；⛔ 不许自己读 `settings.json` 或自己判风险。
