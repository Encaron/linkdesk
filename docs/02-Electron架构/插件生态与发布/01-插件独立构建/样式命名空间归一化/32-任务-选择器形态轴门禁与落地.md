## 一、🔴 定案：选择器形态轴的四条规则（**本轮要落地的规则原文**）

> **一句话**：**类名与 id 是「名字锚」；元素 / 通配 / 属性 / 伪类 / 伪元素不是** —— 后者**不需要与任何人同名**就能命中别人的元素，而它们在两侧门禁里**根本不存在**。
> **本轴 = 「无名字锚」的选择器**。带锚（含 `.x` 或 `#x`，`(...)` 内的内容不算锚）的归**轴 ①（类名轴）**＋ **R3**。

### R0 · 口径定义（**轴的射程**）

一个 compound **有名字锚** ⇔ 剥掉伪元素后，该 compound 里出现类选择器（`.x`）或 id 选择器（`#x`）—— 判据里 `(...)` 内的内容**不算锚**（那是过滤器不是主体）。
**无锚选择器**再分两级：**顶层无锚**（单 compound，如 `select` / `*` / `:root` / `::-webkit-scrollbar`）· **限定无锚**（多 compound 且全部无锚，如 `html body section`）。

### R1 · 宿主基线块（**文件级 ＋ 条数**，零名字清单）

宿主 CSS 里的**顶层无锚选择器只允许出现在「基线文件」里**（今天 = `src/index.css` 的文档级区块）。
**基线登记 = 逐文件登记「哪个文件、几条」**；**基线文件之外**出现顶层无锚选择器 ⇒ 🔴 红；**基线文件之内条数 ≠ 登记条数** ⇒ 🔴 红（新增一条基线**必须同笔**改登记数）。
⇒ 登记的是 **区块 ＋ 条数**，**不设名字清单、不设白名单**（名字级登记会腐 —— 本系列的旧病）。
⇒ 门禁与探针**对基线内站点也一律逐条打印**（含文件:行与选择器原文），让「哪几条」永远可见、不依赖任何人的记忆。

### R2 · 插件禁止无锚选择器

插件 CSS 里出现**任何无锚选择器**（**顶层或限定一律禁**；元素 / 通配 / 属性 / 纯伪元素 / **id** 一视同仁）⇒ 🔴 红。
要写元素样式**必须挂在自己的根类之下**：`.serial-monitor-root input { … }`。
⇒ 今天实测 **0 处**（官方 18 仓 ＋ 壳内 `plugins/` ＋ `dev-fixtures/`）⇒ **纯预防性，零存量、零重发成本**。

### R3 · 跨方命中必须自带自有命名空间

插件的**任何**选择器里**出现 `ldk-*` 类**（含 `:has(…)` 内的提及）⇒ 该选择器**必须同时含至少一个 `<pluginId>-*` 类**；否则 🔴 红。
⇒ 今天 **9 处提及全部合规**（§二.3）⇒ 纯预防性。
⇒ 🔴 **本规则管形态、不管意图**：**不禁止插件改共享组件外观**（那是**合法特性**，文档口径的 scoped 调优）；它只要求「带着自家前缀作锚」——即「调优必须在地盘里发生」。

> **三条规则共同的性质**：**全部结构性、零名字清单**（与判据①③⑥⑨ 同款）。R1 登记**文件＋条数**、R2/R3 判**形态**。

### 2.4 🔴 三条新发现（**本轮必须一起修**，否则门禁与探针继续漏）

**F1 · 两把尺子共同的盲区（静默丢）**
`subjectOf(":root") === ""`、`subjectOf("::-webkit-scrollbar") === ""` ⇒ `soleClassOf` 回 `null`（→ 轴 ① 不收）⇒ 再 `selectorShape()` 的 `if (!sub) return null` 把整条规则**丢掉**。
⇒ 5 个站点（`:root` ×1 ＋ `::-webkit-scrollbar` 一族 ×4）**在静态 seam 探针与运行时镜像里都不存在**，且**没有任何计数器**记下「丢了几个」——这正是本系列一句话根因的现场（**不是问题在长大，是尺子一直在漏**）。

**F2 · 运行时镜像独有的盲区（CSSOM 归一化 ＋ 同一句 if）**
CSSOM 的 `selectorText` 会把 `*::before` 序列化成 `::before`、`*:focus-visible` 序列化成 `:focus-visible`（`*` 被吃掉）⇒ 剥伪元素后又是空主体 ⇒ **再丢 5 个站点**（`*::before`×2 · `*::after`×2 · `*:focus-visible`×1）。
⇒ **轴 ④ 的运行时读数 = 6 个形态 / 11 个站点**（`universal:*`（并了 `*` 的 6 个站点里的 2 个 ＋ 2 个 @media 副本）· `element:html` · `element:body` · `element:select` · `attr:[data-theme="light"]` · `other:input[type="number"]`），静态 = **17 处**。

**F3 · `hasAncestor()` 对「伪类独体主体」误判为 `false`（假红风险源）**

```
.ldk-side-panel :focus-visible   ⇒ hasAncestor=false, subjectOf=".ldk-side-panel", soleClassOf="ldk-side-panel"
.a :first-child                  ⇒ hasAncestor=false, subjectOf=".a",                soleClassOf="a"
.a h1                            ⇒ hasAncestor=true,  subjectOf="h1",                 soleClassOf=null   ← 正确
.a::before                       ⇒ hasAncestor=false, subjectOf=".a",                 soleClassOf="a"
```
⇒ ① 既有「独立定义」口径把 `.x :pseudo` **算成 `.x` 的一次定义**（宿主侧实测 2 处：`.ldk-side-panel :focus-visible`）。**这是既有口径的已知偏差，本轮不许改它**（改它 = 动 258/89 两串全系列读数、动 18 仓 CI）；写进 §八 诚实边界。
⇒ ② **本轴的三条判据一律不许用 `hasAncestor()` / `subjectOf()` 判形态**——否则插件 `.my-root :focus-visible { }` 会被判「顶层无锚」⇒ **假红**（假红会让真红失效，[22 号档](22-收口总方案-跨方样式污染九件套.md) §10.3）。**必须新写 `formOf()`**（§三.1），它的正控就钉这条形态。

## 三、判据（判定式 ＋ 分级 ＋ 负控）——**本轮要落地的四组**

### 3.1 🔴 先写形态谓词 `formOf()`（**唯一实现，三处共用**）

**落点**：`scripts/lib/css-selectors.mjs`（新导出）＋ `packages/plugin-sdk/src/eslint/checks/css-selectors.ts`（同款，跨包各一份、**口径文本一致**）。

```
stripPseudoElements(c)  = c.replace(/::[a-zA-Z-]+(\([^)]*\))?/g, "")      // 只剥 :: 形态
compounds(c)            = stripPseudoElements(c).trim().split(/[\s>+~]+/).filter(Boolean)
hasNameAnchor(compound) = /[.#][-_a-zA-Z]/.test(compound.replace(/\([^)]*\)/g, ""))   // (...) 内不算锚
formOf(compound)        = {
    compounds.length === 0            ⇒ { kind:"anchorless", top:true,  purePseudo:true }   // ::-webkit-scrollbar
    compounds.some(hasNameAnchor)     ⇒ { kind:"anchored" }                                 // 归轴 ①／R3
    compounds.length === 1            ⇒ { kind:"anchorless", top:true }                     // A 段
    else                              ⇒ { kind:"anchorless", top:false }                    // B 段（限定无锚）
}
```

🔴 **三条纪律**：
1. **不改 `subjectOf()` / `hasAncestor()` / `soleClassOf()` 的任何语义**（既有口径冻结，见 F3）；
2. `formOf()` 与 `hasAncestor()` **可以同时为真/为假而互不干扰**——本轴只读 `formOf()`；
3. 跨包两份由 `check-css-namespace.mjs --self-test` 的**静态锚**钉住（照 1.24 的 `锚⑦` 先例：把一句**锚词**两边都写进注释/文案，改一边必红）。

### 7b. 「同族候选」（26 号档 §二.7b ⚠️）的结论：`var(--x)` 引用的可解析性 —— **不做（warn 也不做）**

理由三条：
1. **静态可解析集合是模糊的**：token 可以由主题引擎在运行时写（`ThemeEngine.applyOverrides`）＋ JS 侧写 inline（如 `--surface-bg-size`）⇒ 任何「本仓/宿主契约里有定义」的静态名单都**必然产生假红**（假红会让真红失效，§10.3）。

3. **将来真要做，应当在运行时做**：探针已经 dump 了**全部样式表**（含规则体的 `--x:` 与 `var(--x)`）⇒ 比 `var()` 引用集合与定义集合是**两个 dump 的集合运算**，没有静态名单问题。**触发条件**：出现一次「改 token 名忘了改引用」的真事故 ⇒ 在 `runtime-style-audit.mjs` 加一段（**不在静态腿加**）。
