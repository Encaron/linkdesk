## 一、每只插件仓自带 CI（一份 yml，零新代码）

`@linkdesk/plugin-sdk` **已自带 eslint preset**（壳仓 `linkdesk/*` 规则的仓外版本），而 `lint` / `validate` / `build` 三个 script **模板里已经有了**。所以一只插件仓的 CI 大致就长这样：

```yaml
# .github/workflows/ci.yml
name: ci
on: [push, pull_request]
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 24 }          # ⚠️ 版本对齐壳仓 engines（>=24）
      - run: npm ci
      - run: npm run lint                   # plugin-sdk lint（含 linkdesk/* 规则）
      - run: npm run validate               # plugin.json schema 校验
      - run: npm run build                  # 能出 zip 吗
      - run: npx vitest run                 # 有测试的才加（§二）
```

### 🔴 关键建议：这份 CI **直接放进脚手架模板**

这样「新插件一建出来就有检查」是**默认行为**，而不是每仓手加——**也正是你说的「给脚手架加东西」的另一半**。要放进模板的东西：`.github/workflows/ci.yml` + `vitest.config.ts`（§二）+ 必要时 `.gitignore` 里的 `.vite` / `dist`。

> ⚠️ 模板改动是 **npm 包改动**（`create-linkdesk-plugin` bump）——与 7.6 轮的脚手架改动**合并成一笔版本**，别分成两次发版。

## 三、eslint preset 迁出（壳仓插件块随源码走）

壳仓 `eslint.config.js` 里专给插件的那一块（`:167` 起）含几条**必须跟着插件走**的规则：

| 规则 | 现在的价值 | 搬走后 |
|:--|:--|:--|
| `linkdesk/no-cross-plugin-import` | 插件相对 import 解析进 `/plugins/<其他id>/` 即 error | 仓外插件不 import 别的插件源码，**规则改为「禁止 import 别的插件仓库」**（形态变了，精神不变） |

| 禁止硬编码颜色（硬约束 1） | 主题纪律 | ✅ 必须保留 |

**要做：** 确认 `@linkdesk/plugin-sdk` 的 eslint preset 里**到底带了哪几条**——带了的直接用；**没带的要么补进 preset（改 npm 包），要么在模板里内联**。**不许「默认它带了」**（这条正是「两套机制从没对上」的老病，[插件规范化层 §〇③](../插件规范化层/00-整理档案.md) 记的就是这个）。

### 六·二 🔴 严格门禁判红什么（本轮最需要说清的一件事）

**病灶**：SDK 的 `linkdesk-plugin-sdk lint` 是 **WARN 级、永不 fail**（07 §六·三档：
「警告不是封锁，WARN 永不 fail build/上传」）。作者写一段硬编码 hex、写一句裸中文，
`npm run lint` 只**打印一行警告然后 exit 0**，`build` 照样出 zip、`publish` 照样上传。
⇒ **光有 preset 就没有「避免出错」这回事**——CI 必须再加一道把 WARN 转成拦的门禁。

判红范围（**有意收窄，理由逐条**）：

| 判红 | 内容 | 为什么 |
|:--|:--|:--|
| ✅ | eslint 规则腿全部偏离（12 条注册规则，含 `no-hardcoded-hex` / `no-hardcoded-zh`） | 硬约束 1/2 那一档；负控点名的就是它们 |
| ✅ | css 硬编码腿（`.css` 里的 hex + rgb/hsl） | 硬约束 1 的 **.css 半边**——eslint 到不了 `.css`，只剩这条腿管。**实测 6 只代码插件全零偏离**，判红零成本 |
| ✅ | 跨插件 import（源码 import + `package.json` 依赖声明两处） | 壳仓 `linkdesk/no-cross-plugin-import` 的仓外形态（见六·三） |
| ✅ | 字典文件在/可解析/值非空；声明自洽（`entry`/`icon`/`views[].render`/themes·iconThemes 数据文件过 schema/`linkdesk://` 资产在/floatingPanel 三向） | 见六·四 |
| ⚠️ **只报告不拦** | `check-font-scale` 与 `check-spacing-grid` 两条腿 | 属**审美校准档**（SDK 07 §六），不是「绝对不能违反」；存量偏离实测 36 处（marketplace 19 / serial-monitor 11 / settings 5），**改它们要动插件源码 ⇒ 走发版链**，不属本轮。已在输出里**逐条打印**，不是放过 |
| ⚠️ **只报告不拦** | `Definition for rule '…' was not found` 那一类 | 见六·三 的「规则名归属」 |

### 六·三 eslint preset 覆盖面核清（**不许「默认它带了」**——核完才发现两条真缺口）

**preset 实际带了什么**（`packages/plugin-sdk/src/eslint/preset.ts` 实读）：
`react-hooks/rules-of-hooks` · `react-hooks/exhaustive-deps` · `linkdesk/no-async-init-guard-only` ·
`linkdesk/no-effect-callback-without-active-guard` · `linkdesk/no-dynamic-import-in-effect-cleanup` ·
`linkdesk/no-ref-current-in-jsx` · `linkdesk/no-hardcoded-zh` · `linkdesk/no-hardcoded-hex` ·
`linkdesk/no-hardcoded-radius` · `linkdesk/no-quickpick-render-item` · `import-x/no-unresolved` ·
`@typescript-eslint/no-explicit-any` —— **12 条，全部 `warn`**。

**两条缺口（§三 要的就是这个结论）**：

1. 🔴 **`linkdesk/no-cross-plugin-import` 根本不在 preset 里**（它只在壳仓 `eslint.config.js` 注册过）。
   仓外形态 = 「不得引用别的插件仓/包」：相对路径**越出本仓根**、或裸包名形如
   `linkdesk-plugin-*` / `@linkdesk/plugin-*`（`@linkdesk/plugin-sdk` 是作者 SDK 本体，显式排除——
   这一条是**实测踩出来的**：第一版正则把它当成了「另一个插件」）。⇒ 已写进各仓 `ci-verify.mjs` ②。
2. **全 WARN** ⇒ CI 侧必须有严格腿（六·二）。

**另一条实测收获**：`import-x/no-unresolved` 在 6 只代码插件仓里**报 102 处假红**——
根因是这些仓**没有 `tsconfig.json`**（脚手架模板有，18 只迁移时丢了），SDK 的 lint 拿不到
tsconfig 就把 resolver 设置剥掉，相对 import 一律解析不了。**补一份 tsconfig.json 后 102 → 0**
（file-tree 实测）。⇒ `sync:plugin-ci` 对有 `src/` 的仓补 `tsconfig.json`（与模板同字节）。

**③ 三条「仓外才现形」的环境坑**（都是本轮实测，已固化进模板）：

1. **`vitest.setup.ts` 必须随行**——那份 `window.linkdesk` 六命名空间 + `__ldkConfigStore` 是运行时地基，
   不是配置。丢了它，凡碰 `window.linkdesk` 的测试要么报错、要么**静默走错分支**。
2. 🔴 **`@linkdesk/ui` 要 `server.deps.inline`**：壳仓里它解析到**同仓源码**（CSS 由 Vite 顺手处理）；
