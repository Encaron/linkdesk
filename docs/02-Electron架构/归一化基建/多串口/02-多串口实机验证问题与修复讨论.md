## 0. 核心结论——一个结构性根因

**#29 只做对了「消费侧」的 per-tab 绑定（portFilter 过滤接收），但「产生侧」和「操作侧」仍停留在单口投影模型。**

分屏下两个标签页共享同一个模块级 `_sharedState`（一个 `sourceName` + 一个 `isOpen` 布尔），所有操作读这个全局投影口。第二口一开，操作就错乱。

> 归属分类 + 「E5.7 迁移根因」见 **§0.1**——决定哪些问题只动插件、哪些要动壳。

涉及文件：`plugins/user/serial-monitor/src/services/SerialContext.tsx`、`src/index.tsx`、`src/components/ControlPanel.tsx`。

**解法：§0.2 状态模型 per-tab 化（UI 维持现状，不搬动）。**

## 0.1 归属分类——软件侧 vs 插件侧（2026-08-20 用户问询，定修法边界）

| # | 问题 | 侧 | 根子 |
|---|------|-----|------|
| P1 | 系统消息串台 | **插件** | index.tsx 过滤策略 |
| P2 | 断开串台 | **插件** | closePort 读全局投影口 |
| P3 | 侧栏灯不亮 | **插件** | _setState 单布尔守卫 |
| P7 | 下拉自动打开 | **插件** | setSourceName 全局 isOpen 污染 |
| P9 | 删除会话无强提示 | **插件** | SessionListView 不判 open（弹窗能力走壳 dialog API） |
| P6 | 状态栏 TX/RX | **插件** | UI 设计 |
| P4 | 合屏接收区清空 | **壳** | MainZone/GroupPane 跨组移动 → remount（keep-alive 边界） |
| P5 | 聚焦失效 + 环没了 | **壳** | 分屏面板点击聚焦交互缺失 + 视觉回归 |
| P8 | 关标签页不弹警告 | **壳** | invokeBeforeClose 否决回路被 E5.7#43 停用 |

**6 个插件侧，3 个壳侧。**

**根子在 E5.7 极简Pool 架构迁移**：
- E5.5 之前 Per-Tab WebView：每标签页独立 WebView → 每实例独立模块级 `_sharedState`，「模块级单例」=「per-tab 单例」，天然正确。
- E5.7 极简Pool：所有标签页收进**同一渲染进程 / 同一 JS 上下文** → `useSerialSessions` 用 sourceId 跟上了（per-tab 会话隔离），但 **`SerialContext` 没跟上**——`_sharedState` 从「每实例独立」变成「真全局共享」，代码还按旧假设写。P1/P2/P3/P7 全从这洞来。
- 所以准确说：**代码在插件里，根子是壳架构迁移时插件没跟上**——E5.7 重构的遗留债务，多串口实机把盖子掀开。

**壳改动边界含义**（壳改动 = 加通用通道 ≠ 加设备业务）：
- P1/P2/P3/P6/P7/P9 **不动壳**——serial-monitor 插件内部改状态模型，壳 API 面保持 0。
- P4/P5/P8 **动壳，但都是通用机制，非串口专属**：
  - P4 = 壳 keep-alive 边界（跨组移动保状态）——任何插件都会遇到的通用标签页机制
  - P5 = 分屏面板聚焦——壳的通用交互，对标 VS Code
  - P8 = 壳捡回被自己停用的 invokeBeforeClose 通用通道——「加回通用通道」不是「加设备业务」

## 0.2 统一修复方向——UI 维持现状 + 状态模型 per-tab 化（2026-08-20 用户拍板）

**插件侧 6 个问题（P1/P2/P3/P6/P7/P9）统一解法：UI 不搬（12 项收发设置继续留软件侧栏），只做状态模型 per-tab 化。**

- **UI 维持现状：** 2026-08-20 拍板**放弃「per-tab 工作台重构」**（原方案：12 项设置搬进标签页内，侧栏只留会话列表）。串口插件长期使用，不做大搬动；未来若需新形态，**造全新串口插件**（按「侧栏=导航、主区=操作」从零设计），不在旧插件上动手术。
- **状态模型（关键，与 UI 独立）：** `SerialContext._sharedState`（模块级单例，P1-P9 核心根因）→ 按 sourceId/per-tab 读写 + **操作侧全部显式传 portName**（closePort/toggleOpen/setBaudRate/sendData），全局投影口仅作兼容视图。**UI 搬动与状态模型 per-tab 化是两件事，可拆开**——不搬 UI 也能做。
- **效果：** P2 断开定向（显式传口）；P3 灯按口显式写（open/close 写 `端口:isOpen`）；P7 换口判断读本标签页口；P1 状态消息按口过滤 + 错误消息全局显示；P9 靠 P3 产物（侧栏有 open 数据）做强提示；P6 TX/RX 放各标签页接收区工具栏一行，全局状态栏只留连接灯 + (N) 口数。
- **边界：** 全插件侧改动，壳 API 面 = 0（壳改动边界原则——状态模型重构是插件内部，非加设备业务）。
- **全部定案（2026-08-20）：** P7 换口行为（关旧开新保留 + per-tab 触发）；P6 TX/RX（各标签页工具栏一行 + ≥2 显数字）；P9 强提示（开着强提示 + 配置开关）。

- 实现需在 handler 内判断消息类型（或主进程给系统消息打类型标签）。

**待拍板**：

## 2. P2 断开串台——点对话1断开，断的是对话2 的 COM13

> ✅ **2026-08-20 拍板：接受「全部操作显式传口、投影口仅作兼容视图」——closePort/toggleOpen/setBaudRate/sendData 显式传 activeSession.port，不再读全局投影口。并入 §0.2 状态模型 per-tab 化。**

**症状**：双口都开着（COM3+COM13），点对话1（COM3）的断开，结果断的是 COM13；再点也断不掉 COM3。

**根因（代码实锤）**：
- `SerialContext.closePort()`（`SerialContext.tsx:326-334`）读**全局投影口** `_sharedState.sourceName`，不带 per-tab 的 portName。
- 分屏两面板共享模块级 `_sharedState`：打开 COM3 后 `sourceName="COM3"`，再打开 COM13 后 `sourceName` 被覆盖为 `"COM13"`。
- `ControlPanel.handleToggleOpen`（`ControlPanel.tsx:87-105`）的 `connected` 判定是 **per-tab 正确**的（`getOpenPorts().has(activeSession.port)`，COM3 确实开着）→ 走 `closePort()` → 关的是 `_sharedState.sourceName`="COM13"。
- 再点：`getOpenPorts()` 里 COM13 已被删、COM3 还在 → 还是去关 COM13 → 「一直点也断不了」。

**本质**：#29 只把**接收侧**（portFilter）做了 per-tab 定向；**发送/断开/换波特率/换口**（`closePort`/`toggleOpen`/`setBaudRate`/`setSourceName`）全部还在操作全局投影口。这是 #29 的核心遗留洞。

**候选修复**：
- 操作侧全部改为**显式传 portName**：`closePort(portName)`、`toggleOpen(portName)`，`ControlPanel` 传 `activeSession.port`——根除对 `_sharedState.sourceName` 全局投影的依赖。
- 灯写入同理改「按口写」（见 P3）。

**待拍板**：
- [x] **2026-08-20 拍板：接受「全部操作显式传口、投影口仅作兼容视图」——彻底最小修法。**

## 3. P3 侧栏灯不亮——COM13 打开后灯不亮

> ✅ **2026-08-20 拍板：灯写入从 `_setState` 单布尔守卫剥离、改为 open/close 动作路径显式写 `端口:isOpen`——谁打开写谁的，不短路。并入 §0.2 状态模型 per-tab 化。**

**症状**：先开 COM3（对话一），再开 COM13（对话2），对话2 旁侧栏灯不亮。

**根因（代码实锤）**：`SerialContext._setState`（`SerialContext.tsx:91-135`）的 isOpen 同步守卫是**单布尔**：
```ts
if (next.isOpen !== _sharedState.isOpen) {  // true !== true → 短路！
  pluginState.set(_scopeKey("isOpen", next.sourceName), next.isOpen)
}
```
- 开 COM3：isOpen `false→true` → 写 `COM3:isOpen` ✓
- 开 COM13：isOpen 已是 `true`，`true !== true` 短路 → **不写 `COM13:isOpen`** → 侧栏 `SessionListView` 的 `useSerialConnection`（订阅 `plugin-state:changed` 收集 `*:isOpen` key）收不到 → 灯不亮。

**本质**：产生侧不知道「哪个口」变了，只知道「isOpen 这个布尔」。单口投影模型与多口 Map 权威态（`_openPorts`）不匹配。

**候选修复**：
- `openPort()`/`closePort()` 成功后**显式写对应口的 pluginState key**（`COM13:isOpen=true`），不再依赖 `_setState` 的布尔守卫。

**待拍板**：
- [x] **2026-08-20 拍板：灯写入从 `_setState` 守卫剥离、改为动作路径显式写——接受。**

## 4. P4 合屏后接收区清空

> ✅ **2026-08-20 拍板：方向 c——合屏迁移 RingBuffer 内容（插件侧快照恢复：unmount 快照到 session、mount 恢复），不走 a（会话级持久化，太重）不走 b（跨组 keep-alive，违背 B22）。连接状态恢复靠 §0.2 per-tab 重构的 _initOnce。**

**症状**：左右分屏合并后，接收区空——数据全没了。用户记得之前修过。

**根因**：
- keep-alive（B22 平级渲染，`MainZone.tsx` 所有面板绝对定位平级 + `GroupPane.tsx` 内 `display:none/flex` 切换）只在**同一面板内**切标签页生效。
- **跨面板合并 = 标签页换父容器 = React 必然卸载重挂**：`GroupPane` 按 `group.tabs.map` 渲染，tab 从一个 group 移到另一个 group → 组件树换父节点 → `PluginComponent` 卸载再装载 → CM6 接收区 + `ringBuffer` 状态全丢。
- 用户记的「专门修过」是 **G1（`9727f9c`）**——只保了「合屏不丢标签页对象」（`reduceUnsplit` 把 tab 迁到存活面板，`reducers-layout.ts:190-219`），但**组件内部状态不随 tab 对象迁移**。

**候选修复（需架构取舍，未定）**：
- a) **会话级持久化**：CM6 接收数据存进 session（pluginState），remount 后恢复——改动大，但合屏/重启都受益。
- b) **跨组 keep-alive**：把被合并面板的标签页 DOM 以 portal/绝对定位藏在存活面板内继续保活——复杂，违背 B22 平级模型。
- c) 合屏时把被合面板的活动标签页数据**并入**存活面板（迁移 tab 时同步迁移 RingBuffer 内容）——折中。

**待拍板**：
- [x] **2026-08-20 拍板：方向 c——合屏迁移 RingBuffer（插件侧快照恢复），不选 a/b。**

## 5. P5 聚焦失效 + 聚焦环缺失

> ✅ **2026-08-20 拍板：① 补「点击面板空白处聚焦该面板」——P5 是 §0.2 per-tab 重构的前置依赖（命令路由依赖 activeGroupId）；② 聚焦环 = accent 色细边框（var(--accent) 走 CSS 变量，可主题化）。**

## 7. P7 下拉选口自动打开 + 「同口互斥失效」错觉

> ✅ **2026-08-20 拍板：换口自动「关旧开新」保留，触发条件从全局 isOpen 改为「本标签页口已开」（per-tab 判断，不误触全局）；新标签页选口只记配置、点「打开」才开（被 per-tab 判断天然覆盖）。P2 修好后「互斥失效」错觉自然消失。**

**症状**：对话1（COM3）窗口还开着且 UI 断不掉（P2 连带）时，新建对话3、下拉选 COM3（没点打开）→ 灯直接亮 + 接收区直接收消息。用户觉得 D8 同口互斥「没有意义」。

**根因（分两层）**：
1. **下拉选口自动打开**：`SerialContext.setSourceName`（`SerialContext.tsx:336-352`）有 `if (_sharedState.isOpen)` → 换口自动 `closePort(旧口) + openPort(新口)`。这是历史「标签页内换口 = 关旧开新」设计（D3）。但多标签页共享全局 `_sharedState.isOpen`——对话1 打开后 `isOpen=true`，**新建的任何标签页选口都会触发自动重开**。
2. **「互斥失效」是错觉**：服务层 D8 拒绝是有效的（`serial-service.ts:157-161`：`ports.has(portName)` → 抛错 + onSystem）。COM3 实际已被 P2 的误操作关闭（closePort 定向错乱），但对话1 UI 还显示「打开」→ 用户以为 COM3 占用中，结果能开 → 觉得互斥没拦。

**本质**：操作侧全局投影口 → UI 状态与真实端口脱节。修好 P2 后此错觉自然消失；「下拉自动开/关」的触发条件要改成「本标签页的口已开」而非全局 isOpen。

**待拍板**：
- [x] **2026-08-20 拍板：标签页内换口自动「关旧开新」保留，触发条件改为 per-tab 精确判断。**
- [x] **2026-08-20 拍板：新标签页选口不自动打开（只记配置、点「打开」才开）——被 per-tab 判断天然覆盖，无需单独拦。**

## 8. P8 关闭打开着的串口标签页——不弹警告、不自动断开（回归）
