# 11-主题制作（第三方主题插件作者指南）

> **状态：** 定稿（2026-08-23）——schema 已冻结（[05](../02-Electron架构/E5.8_归一化基建/外观主题化/05-主题数据模型.md) 决策 A-F）。
> **一句话：** 主题 = 插件的一种——一个配方 json（风格域 + 配色变体）+ 可选资产；「域贡献者」缺的域继承默认，写得越少越稳。
> **ai化 = AI 友好度：** 本文读者 = **人类 + AI**——AI 读本文能产出合法主题文件，AI 读示例主题（如迁移后的 mint-soda）能仿造同类。schema 每个概念只有一种写法（决策 F：一律 `colorways[]`）。

## 1. 主题插件是什么

- 主题是**插件**（硬约束 10：壳不写死任何插件 id，主题也走 plugin.json 声明）。
- 一个主题插件 = 1 个配方 json（`appearance` 风格域 + `colorways[]` 配色变体）。也可包含多个配方 json。
- **域贡献者**：只写你拥有的域，缺的继承壳默认（[03 域贡献者](../02-Electron架构/E5.8_归一化基建/外观主题化/03-域贡献者与混搭.md)）——纯配色主题 = 只写颜色；玻璃主题 = 写玻璃 + 颜色。
- **风格 vs 配色分离**：想要「1 个风格基座 + N 个配色」→ 一个配方里放 `colorways[]`（[05 §2](../02-Electron架构/E5.8_归一化基建/外观主题化/05-主题数据模型.md) 完整 schema）。

## 2. 写一个主题（先建目录 → 三步）

### ⓪ 目录结构（必读——禁止平铺在根目录）

主题插件目录 = 三类各归其位（对齐 [09-插件目录规范](09-插件目录规范.md) 通用约定）：

```
plugins/user/theme-myglass/
├── plugin.json              # 声明（contributes.themes）
├── themes/                  # 配方 json 唯一住处——禁止平铺在插件根目录
│   └── myglass.json
├── assets/                  # 资产：字体（woff2/ttf）+ 背景图（png/jpeg/webp）
│   ├── MyFont.woff2
│   └── bg.png
└── resources/               # 插件图标等元数据资产（09 §通用约定）
```

| 目录 | 放什么 | 规则 |
|:--|:--|:--|
| `themes/` | 配方 json（`appearance` + `colorways[]`） | **配方 json 一律放这里，禁止平铺在插件根目录**；一个插件可含多个配方 json（`contributes.themes` 每条 `path` 指向一个） |
| `assets/` | 字体（woff2/ttf）+ 背景图（png/jpeg/webp） | json 里写相对路径 `assets/...` → 壳 `getAssetPath(pluginId, path)` 统一解析（硬约束 12）；**禁止 `/assets/...` 绝对路径** |
| `resources/` | 插件图标等元数据资产 | 与 [09-插件目录规范](09-插件目录规范.md) 通用约定一致 |

> **为什么禁平铺：** 主题会越做越深——per-surface 精调 json、i18n、README、src（如需脚本/UI）都会陆续进插件目录。平铺根目录 = 未来每个新文件都要临时想放哪；`themes/`+`assets/`+`resources/` 三槽先立好，**每类定制化各归其位，扩展零搬动**（2026-08-23 用户拍板「未来肯定有更多东西要主题定制化，要容易加入主题制作」）。
>
> **最小主题 = 只要 `themes/` 一个目录**（纯配色主题不引资产连 `assets/` 都可以没有）；字体/背景图才需要 `assets/`。

### ① plugin.json 声明

```jsonc
// plugin.json —— 主题声明走 contributes.themes（对标 VS Code，schema 权威见 plugin.schema.json）
{
  "id": "theme-myglass",
  "name": "我的玻璃主题",
  "version": "0.1.0",
  "contributes": {
    "themes": [
      { "id": "myglass", "label": "My Glass", "uiTheme": "dark", "path": "themes/myglass.json" }
    ]
  }
}
```

### ② 配方 json（引用 05 schema）

```jsonc
// themes/myglass.json —— 见 [05 §2](../02-Electron架构/E5.8_归一化基建/外观主题化/05-主题数据模型.md) 全量 schema
{
  "id": "myglass", "name": "My Glass", "type": "dark",
  "appearance": {
    "radius": { "md": 10, "lg": 16 },
    "glass": { "blur": 16, "saturate": 1.3, "tint": "rgba(255,255,255,0.06)", "opacity": 0.9 },
    "font": { "ui": "assets/MyFont.woff2", "mono": "JetBrains Mono" },
    "background": { "image": "assets/bg.png", "opacity": 0.85, "mask": "rgba(0,0,0,0.3)" }
  },
  "colorways": [
    { "id": "violet", "name": "紫罗兰", "colors": { "bg-window": "#0E0B16", "accent": "#8B5CF6" } },
    { "id": "emerald", "name": "翡翠", "colors": { "bg-window": "#0A1410", "accent": "#34D399" } }
  ]
}
```

> **单配色主题** = `colorways` 数组只含 1 项（例：官方主题 dark 迁移后 = `colorways: [{ id:"dark", name:"Dark", colors:{…} }]`）——**没有第二种写法**（决策 F）。

### ③ 资产（可选）

- 字体/背景图挂在插件目录，json 里写**相对路径**（`assets/...`）——渲染时壳用 `getAssetPath(pluginId, path)` 统一解析（硬约束 12）。**禁止写 `/assets/...` 绝对路径。**
- 字体两种形式：①资产路径（随插件分发）②系统字体族名字符串（用户机器上已有的）。

### ④ 满配示例（六域全写 + 资产 + 3-4 配色——「几乎全部可主题化」的范本）

> 想一次写完所有可主题化域的作者照这份抄。**风格（appearance 六域）与配色（colorways）分离**——换配色只动数组项；资产全相对路径。范本源自 gallery 液态玻璃配方（[00-theme-gallery.html:1473](../02-Electron架构/E5.8_归一化基建/外观主题化/mockups/themes/00-theme-gallery.html#L1473)）。

```
theme-liquid-glass/
├── plugin.json              # contributes.themes 声明
├── themes/
│   └── liquid-glass.json    # 满配配方（六域全写 + 3 配色）
├── assets/                  # 资产：字体 + 背景图
│   ├── SpaceGrotesk.woff2   # font.ui 资产字体
│   ├── JetBrainsMono.ttf    # font.mono 资产字体
│   └── aurora.jpg           # background.image 资产
└── resources/
    └── icon.svg             # 插件图标
```

```jsonc
// themes/liquid-glass.json
{
  "id": "liquid-glass",
  "name": "液态玻璃",
  "type": "dark",
  "appearance": {
    "radius": { "xs": 2, "sm": 4, "md": 8, "lg": 14, "xl": 20, "2xl": 24 },
    "glass": { "blur": 20, "saturate": 1.8, "tint": "rgba(14,16,24,0.38)", "opacity": 0.9, "specular": 0.6, "morph": 400 },
    "font": { "ui": "assets/SpaceGrotesk.woff2", "mono": "JetBrains Mono" },
    "background": { "image": "assets/aurora.jpg", "opacity": 1, "mask": "rgba(0,0,0,0.88)" },
    "surface": { "inset": 8, "radius": 14, "shadow": true, "border": true }
  },
  "colorways": [
    { "id": "aurora", "name": "极光紫", "colors": { "bg-window": "#0E0B16", "accent": "#8B5CF6" } },
    { "id": "emerald", "name": "翡翠",   "colors": { "bg-window": "#0A1410", "accent": "#34D399" } },
    { "id": "ocean",  "name": "深海",   "colors": { "bg-window": "#0B121E", "accent": "#38BDF8" } }
  ]
}
```

| 域 | 写法 | 备注 |
|:--|:--|:--|
| radius | 六档尺寸 | `--radius-pill`/`--radius-full` 形态值不在此写（scale 排除，[08 §3](../02-Electron架构/E5.8_归一化基建/外观主题化/08-持久化与配置.md)） |
| glass | 六键全写 | specular/morph = 液态玻璃「反光/响应」（[02 §2.3](../02-Electron架构/E5.8_归一化基建/外观主题化/02-变量契约.md) 材质定位） |
| font | ui 资产路径 + mono 系统族名 | 资产字体两步：#50.17 先 @font-face 注册族名→写 `--font-ui` |
| background | image 资产 + opacity + mask | 相对路径 → getAssetPath（硬约束 12） |
| surface | inset/radius/shadow/border | 悬浮面板等厚度（#50.6） |
| colorways | 风格基座 + N 配色 | 3-4 个 = 推荐；单配色也写数组 1 项（决策 F） |

> **稀疏可省：** 满配只是「所有域都写了」——缺的域继承壳默认、域内缺的键继承（§3 稀疏覆盖），写越少越稳。纯配色主题 = 只写 colorways（连 `assets/` 都可以没有）。

## 3. 避坑

| 坑 | 说明 |
|:--|:--|
| 配方 json 平铺在插件根目录 | **禁（§2 ⓪ 目录规范）**——一律放 `themes/`；未来 per-surface/i18n/README 各归其位 |
| 写顶层 `colors`（无 `colorways`） | **旧格式已弃**（决策 F）——引擎只读 `colorways[]`；单配色也写数组 1 项 |
| 写绝对路径 | 打包后 `file://` 全炸——一律相对路径 + getAssetPath |
| 重复写全部颜色 | 稀疏覆盖 = 只写差异键，未写继承 `:root`，更稳 |
| 想摆脱强调色 | 用**自己的 token**（如 `--toggle-on-bg`），不读 `--accent`（[04 §6](../02-Electron架构/E5.8_归一化基建/外观主题化/04-两层调节与设置页.md)） |
| 大 blur 值 | `--glass-blur` 有性能上限（大面积 backdrop-filter 是 GPU 负担）——契约会写明数值（[02 §2.3](../02-Electron架构/E5.8_归一化基建/外观主题化/02-变量契约.md) 待拍板） |

## 4. 主题制作者能拿到什么

- 数据：`window.linkdesk.theme.listRecipes()`（含配色/预览色）——第三方 UI 也可以消费（[06 §6](../02-Electron架构/E5.8_归一化基建/外观主题化/06-主题API契约.md) 待拍板 3：通用 API 优先复用）。
- 应用：`setRecipe`/`setColorway` 或直接写 `app.theme` 配置。
- 事件：`theme:changed`（payload 带 tokens），做实时联动。
- 混搭：你的主题按贡献的域（`RecipeMeta.domains`）自动出现在设置页混搭来源里，**作者零额外工作**（[10 §2](../02-Electron架构/E5.8_归一化基建/外观主题化/10-混搭设计.md)）。

## 5. 迁移（现有主题插件——决策 F：零向后兼容）

引擎**只读新格式**（`colorways[]`），旧格式平铺不再兼容读（[05 §5](../02-Electron架构/E5.8_归一化基建/外观主题化/05-主题数据模型.md)）。现有主题插件改造：

| 插件 | 现状 | 迁移后 |
|:--|:--|:--|
| `theme-defaults` | dark.json + light.json（平铺 colors） | 单配方 json：`colorways: [{id:"dark",…},{id:"light",…}]` |
| `theme-mint-soda` | 4 json（mint-soda/mint-dew/sea-salt-mint/lime-mint） | 1 配方 json = 4 colorways（theme 列表收 1 卡片，推荐） |
| `theme-twilight-forest` | 4 json（green/purple/sunset/teal） | 同上 → 1 配方 4 colorways |

改造 = **纯数据编辑**（把 `colors` 包进 `colorways[]` 数组），不动引擎。合并后 theme 选择器列表更清爽（1 卡片多配色 vs N 卡片）。**迁移时顺手按 §2 ⓪ 目录规范归位**（json 入 `themes/`、资产入 `assets/`，平铺旧结构清零）。
