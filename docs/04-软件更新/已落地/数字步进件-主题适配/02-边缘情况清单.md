# 02 · 边缘情况清单

> 14 条。每条写清「什么情况 → 会怎样 → 要什么」。带 🔴 的是**改版亲手引进的**新风险（改完必须验）。

## 尺寸与字号

**E1** · 🔴 **内部某段又长出自己的圆角** —— 只要有人日后在按钮或字段上补一句 `border-radius`，症状②原样回来（而且是「大部分主题看不出、圆角档才犯」）。⇒ **契约**：内部零圆角；验收时把滑杆拉到 32 看一眼是不是一个整体。

**E2** · 🔴 **外框 `overflow: hidden` 被去掉** —— 分隔线在胶囊档会切到弧线上，看起来像「三块贴着放」而不是「一个胶囊裁出来的三段」。⇒ 保留 `overflow: hidden`；分隔线用 `::after` 内缩（`top/bottom: 4px`）。

**E3** · **`--ui-scale` 拉到 150%** —— 今天的病根之一就是「按钮高乘 scale、字段高不乘」。改后所有尺寸（含 padding、gap、分隔线内缩）一起乘 ⇒ 三段永远等高。⚠️ **`--radius-sm` 不乘 scale**（它是绝对 px 标尺，引擎口径）——所以 150% 下 26px 高的控件配 `--radius-sm: 32` 会更快到胶囊态。这是**对的**（圆角本来就不跟字号缩放），但验收时要看一眼**别觉得"糊"**。⇒ 目视：150% × 滑杆 32 应该是"一个圆润的小胶囊"，不是"糊成一团"。

**E4** · **字号档 85%（最小）** —— 容器高 `26 × 0.85 ≈ 22px`，值单元格最小宽 `46 × 0.85 ≈ 39px`。要确认三位数 `150` 不被挤到省略（`input` 是文本控件，溢出不显示省略号、会**横向滚字**）。⇒ 目视 `app.uiFontScale = 85` 时 `150％` 完整可见。

**E5** · **主题自带大圆角**（`app.appearanceMode` 非自定义、走跟随主题）—— 这时引擎不写 `--radius-*`，用的是**主题配方**的值 ⇒ 本件跟着主题走，无需特判。⛔ 不要写「只有自定义模式才圆」这类分支。

## 值与单位

**E6** · **无单位键**（`window.zoomLevel`）—— 不渲 `<span>`，单元格只剩输入框。⚠️ **宽度会与今天不同**（今天字段 `width: 44/56px` 裸放，改后是 `34px + 单元格 padding`）⇒ 设置页那一行的控件总宽略有变化，验收时确认**右对齐没被破坏**（`FormRow` 的 `flex-shrink: 0` 保证控件不被压，但整行左标签可能少几个字）。

**E7** · **值的位数变化**（`-8` ↔ `8`；`85` ↔ `150`）—— 值居中、单位跟随，位数变化会让「值＋单位」整体左右微移（居中轴不动）。⇒ 这是**要的**（居中比左对齐稳）；⛔ 不要改成固定宽度左对齐来"防抖"。

**E8** · **输入到一半的中间态**（用户清空准备重打）—— 今天是 `Number(e.target.value)`，空串与非法串**不触发 onChange**（值停在旧值）⇒ 实际打不出空。改版**不动这个行为**（它不是本件的范围），但要确认改版后**没把它弄丢**（`onChange` 的 `isNaN` 守卫仍在）。

**E9** · 🔴 **输入框缺 `aria-label`**（今天就缺）—— 屏幕阅读器只说「文本框」。⇒ 顺手补 `aria-label`（走 `t()`）。这是本件**唯一的 a11y 增量**，不加会显得改版只顾好看。

> ✅ 2026-10-04 落码：输入框补 `aria-label={t("数值")}` ＋ `inputMode="numeric"`；新串走的是既有 i18n 通道（⛔ 共享件里不写死中文），同笔外仓 `lang-defaults` 追加译名 **Value**（发 **1.0.47** ＋ 出厂种子箱追新；`audit-i18n --strict` 落码当场红过这一条，补译后转绿）。

## 状态

**E10** · **到极值只灰一端** —— `value <= min` 时只灰 `−`，`+` 仍亮。改后 `disabled` 只作用在该按钮段上（`opacity: .3`），**容器与外框不变**。⛔ 不要整件变灰。

**E11** · 🔴 **聚焦环与圆角打架** —— 用 `outline` 会画出**直角矩形**、盖住外框圆角（今天的病：`outline-offset: 1px` 的方环套在圆角控件外）。⇒ 只许 `:focus-within` ＋ `border-color` ＋ `inset box-shadow`（贴着圆角内侧走，与 [index.css:264-272](../../../../src/index.css) 的「聚焦面板 accent 环」同一套做法）。

**E12** · **快速连点（按住不加 / 双击）** —— 按下态是 `:active`，按住不放**不会连续加减**（今天也不支持，`onClick` 单发）。⇒ 本件**不改**行为，只改外观；「按住连发」若要另立件。

**E13** · **禁用态下的悬停** —— `:hover:not(:disabled)` 已排除；要确认灰掉的按钮悬停不亮（今天的选择器是对的，改版照抄）。

## 外部

**E14** · 🔴 **`@linkdesk/ui` 的 dev 轨道看不到变化** —— `packages/linkdesk-ui/dist` 是**构建产物**，dev 解析的就是它（CLAUDE.md 开发命令那条 `ui:build` 的警告）。⇒ 改完组件**必跑 `npm run ui:build`**，否则 dev 里「什么都没变」⇒ 会被误判成「改了没用」（这正是 memory 里记过的假阴性坑）。

**E15**（附） · **插件侧消费面够不着** —— 插件源码在仓外，壳仓 `check` 不覆盖它们；本件只改**控件本体**、不改导出面、不改声明 ⇒ 插件侧零改动。⇒ 回归验在壳侧 2 个键上做，插件侧靠「导出面只加不删」的既有承诺兜底。
