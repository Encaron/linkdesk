# 01-全量审计——Toast 通知现状

> 2026-07-29。逐项对照 VS Code 通知弹窗，标出差距。

## 一、骨架——几乎完美

Toast 是 E3.5 五个专题中**底子最好的一个**——入场动画、图标、工具栏、详情行、操作按钮全部对标 VS Code。

| 维度 | 实现 | 评价 |
|------|------|------|
| 入场动画 | `translateY(8px)` + `opacity 0→1`，300ms | ✅ 对标 VS Code |
| 容器定位 | `fixed` + `bottom: 30px` + `right: 6px` + `column-reverse` | ✅ |
| z-index | 2545——VS Code 精确值 | ✅ |
| 图标 | severity → codicon（error/warning/info）+ 颜色 | ✅ |
| 悬停工具栏 | 展开 chevron + 关闭 ×，`display:none` → hover 显示 | ✅ 对标 VS Code |
| 中键关闭 | `e.button === 1` → dismiss | ✅ |
| 双击展开 | `onDoubleClick` → toggle expanded | ✅ |
| 详情行 | source 文字 + 操作按钮（primary/secondary） | ✅ |
| 主按钮样式 | `background: var(--accent)` | ✅ |
| 颜色走 CSS 变量 | 全部 var()（severity 图标色是语义色，正确） | ✅ |
| 通知抑制 | `suppressed` 状态——Do Not Disturb | ✅ |

## 二、唯一实质差距——退出动画 🔴

**入场有动画，退出没有。** Toast 关闭时瞬间消失——`dismissToast` → 从数组移除 → React unmount → DOM 消失。

VS Code 的退出流程：
1. 去 `toast-fade-in` class
2. `transform: translateY(-8px)` + `opacity: 1→0`，~200ms
3. 动画结束后才真正 unmount

**实现：** 需要 ToastContainer 管理 "正在退出的 toast" 列表——dismiss 时不立即从数组移除，先标记 `exiting: true`，等 CSS transition 结束（`onTransitionEnd`）再真正移除。

改动量：~20 行 TSX + ~5 行 CSS。

## 三、可以不动的细节 🟢

| 项目 | 当前 | VS Code | 改？ |
|------|------|---------|:--:|
| border-radius | 4px | 3px | 不值得 |
| padding | 10px 5px | 偏紧 | 可接受 |
| main-row gap | 0（用 margin 替代） | flex gap | 可接受 |
| 关闭按钮 hover 色 | `var(--bg-hover)` | 略深 | 可接受 |
| 容器 gap | 4px | 4px | 一样 |

## 四、总结

**Toast 是当前最成熟的组件——入场动画、交互、对标全部到位。只有一个实质缺口：退出动画。**

| 优先级 | 项目 | 改动量 |
|:--:|------|:--:|
| 🔴 | 退出动画（exiting 状态 + CSS transition + onTransitionEnd） | ~25 行 |

**不改也行——退出瞬间消失用户基本注意不到。如果追求极致对标再加。**
