# 标签栏关闭焦点跳第一格 ＋ 开关联动动画（待抉择池）

> **已落地（2026-09-27 实现并归档；版本号随壳 v0.2.19 统一定号，发版时回填）**——2026-09-27 用户实测两问（预览替换的「缩口再拓回」动画厌恶 ＋ 关非焦点标签被抢焦点）。**归属：软件本体**——`src/hooks/useTabManager/`（焦点 reducer）＋ `src/pool/shared/group-tab-bar/`（动画）。

## 一、关闭焦点跳第一格（真 bug，两层叠加）

**用户所见**：焦点在 `app123.c`，hover 关掉旁边的 `style.css` → 焦点跳到本栏**第一个**标签；理论焦点该原地不动。

**根因**：
1. `reducers-tab.ts` 的 `reduceCloseTab` **无条件**重选焦点——不管关的是不是本组当前焦点；
2. `pickNextActive` 收到的是**已删掉目标的列表** → `findIndex` 恒 -1 → 恒返回 `tabs[0]`；其右邻/左邻分支（对标 VS Code 的邻位语义）因此**从未生效过**（死代码）。同款 bug 也在跨窗搬家的 `reduceRemoveTab`。

**修法（已实现）**：只在本组当前焦点被关时才重选；邻位语义从**原列表**找位次（优先右邻、退左邻）。`pickNextActive` 头注写明「必须传删除前列表」契约。测试 4 例（关非焦点不动／关焦点去右邻／关末尾焦点退左邻／跨窗摘非焦点不动）。

## 二、开关动画整删（用户拍板「直接替换／瞬时开关」）

**用户所见**：预览（斜体）标签在中间时点别的文件——旧格猛缩、新格从左猛长回，后面标签先左移再右移（「猛的缩口再猛的拓回来」）；关闭时后面标签跟着滑动补位。均不要。

**代码实况**：状态层 `reduceCreateTab` Step 3 的预览替换本就是**原位顶替**（后面的标签数据上一个都没动）——丑的全部来自 `GroupTabBar` 的两段 max-width 动画：进入 150ms（检测到新 tab id 就从 0 长宽；预览替换必换 id ⇒ 必触发）＋ 退出 120ms（收缩期间后面标签跟着滑）。

**修法（已实现）**：进入/退出动画**整删**——组件侧 `entering/exiting` 状态机、150ms 定时器、关闭前为动画服务的 120ms 等待、CSS 两套关键帧全部退役（组件与 CSS 各留墓碑注释）。效果：替换＝同槽位一帧换内容（后续标签位移量＝新旧标题宽度差，一帧完成）；新开＝完整大小瞬现；关闭＝`beforeClose` 确认一过立即 IPC，当帧消失。

## 连坐面

- 关闭后焦点若转移（关的是焦点标签），活动标签自动滚入视野照常生效（`revealActiveTab`）。
- `closingRef` 防重入保留（`beforeClose` 确认弹窗进行中二次点击仍被忽略）。
- 空组兜底（关到最后一个 → 欢迎页）与 unsplit 语义不受影响。
