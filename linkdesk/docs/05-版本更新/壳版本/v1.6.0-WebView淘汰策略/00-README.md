# v1.6.0 — WebView 淘汰策略

> **类型：壳级别** | 前置：v1.5.x 最新 PATCH

---

## 做什么

每个插件一个独立 WebView（独立渲染进程）。用户装 20 个插件 → 20 个进程 → 内存爆。淘汰策略：类似浏览器标签页休眠。

```
创建第 N+1 个 WebView 时：
  1. 找最久没被切换到的隐藏 WebView
  2. 保存状态 → 销毁 WebView（释放内存）
  3. 创建新 WebView
  4. 用户切回 → 重建 + 恢复状态
```

---

## 为什么 v1.6.0 才做

现在 5 个 WebView 远没到瓶颈。插件市场活了、用户装了 20 个插件以后再开。

---

## 壳改动

| 改什么 | 说明 |
|------|------|
| `WindowManager` 加 `evictLRU()` | 找最久未用的隐藏 WebView → 销毁 |
| 状态保存/恢复 | `PluginStateService` — 销毁前存、重建后取 |
| 内存阈值 | 超过 N 个 WebView 或内存 > X MB 触发淘汰 |

## 任务清单

| # | 任务 | 行数 |
|:--:|------|:--:|
| 1 | LRU 追踪——每个 WebView 的最后活跃时间 | ~30 |
| 2 | `evictLRU()` 销毁 + 状态保存 | ~50 |
| 3 | 切回重建 + 状态恢复 | ~60 |
| 4 | 内存阈值监控 + 自动触发 | ~30 |
| **合计** | | **~170 行** |
