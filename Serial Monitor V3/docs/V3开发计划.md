## 二、Phase 1：项目骨架 + 终端视图 + 串口收发

### 目标

打开 exe → 看到和 V2 一模一样的窗口 → 能打开串口 → 终端视图收发数据 → 蓝色回显、暂停、搜索、导出全通。

工作台和设置视图是空壳——框架在，内容等 Phase 2。

### ⚠️ 修订：Step 8 提前并入 Step 2

原计划 Step 8（顶栏 + 状态栏）在最后才加。读 V2 MainWindow.xaml 后发现：V2 的布局是 **3 行**（顶栏 / 内容 / 状态栏），顶栏的串口控制和右上工具按钮（中/EN、主题、?）是**全局控件**，贯穿所有视图，不是某个 Step 再追加的东西。因此顶栏 + 状态栏现在是 Step 2 布局骨架的一部分，和图标栏、侧栏、主区一起建好。

### ⚠️ 基础设施——从第一天铺好（V2.6 教训）

V2.6 在全部面板写完后再统一手术：93 处主题换色 + 515 条双语替换 + 10 个踩坑。改动量巨大，用户打开 exe 看到的变化只有"切主题不闪了"和"中/EN 按钮"。

V3 从 Phase 1 就内置。每个 Step 标注遵守情况。

**1. 所有颜色走 CSS 变量，禁止硬编码 hex。**

```
✅ var(--text-primary)
❌ #D4D4D4
```

21 色从 V2 ThemeMap 搬入 `:root`。亮色主题变量现在就定义（`[data-theme="light"]`），Phase 1 只激活暗色主题，但切主题的底层已经就绪——未来切主题 = 改 `<html>` 上一个 `data-theme` 属性。V2.6 的 93 处逐个换色 → V3 的 0 行。

**2. 第一行 UI 文字就走 `t()`。**

```
✅ <label>{t("时间戳")}</label>
❌ <label>时间戳</label>
```

翻译表从 V2 的 ~515 条 EnMap 搬入 JSON，Phase 1 先全中文。以后加英文 → 同一个 JSON 加 `"时间戳": "Timestamp"`，不碰组件代码。V2.6 的 515 条逐个替换 → V3 的 0 行。

**3. 组件不从 JS 设颜色，只从 CSS 读。**

切主题 = 改 `data-theme` → 浏览器 GPU 合成层处理全部重绘。不遍历控件、不调方法、不存在"漏掉某个面板"。V2.6 的 5 个面板 UpdateTheme 回调 → V3 的 0 行。

**4. 侧栏设置不走 React state，走 PreferenceService。**

```
用户点开关 → PreferenceService.savePrefs() → React 重新读 prefs → UI 刷新
AI 改 prefs.json → 文件监听 → PreferenceService 通知 → React 刷新
```

人和 AI 在同一个 JSON 文件上交汇。详见 Step 5。

### ⚠️ V2 Bug 模式——V3 如何根除

从 70+ commit 的 bug fix 中提取五类重复模式：

**A. 遗漏式 bug（最高频）——用集中注册表防**

| V2 发生了什么 | 根因 | V3 对策 |
|------|------|------|
| 加新面板 → 忘记在 5 处注册（动画/显隐/切换/退编辑/主题回调） | 注册逻辑散落 | CardRegistry 一处注册 |
| 加新配置项 → 忘记持久化 | 配置散落多个文件 | PreferenceService 唯一入口 |
| 切语言后侧栏标题不跟、菜单不跟 | Locale 调用分散 | react-i18next `t()` 统一，一处改全局生效 |
| CreatePopup 4 处遗漏 PlacementTarget | 重复代码未封装 | React 无此问题（无 WPF Popup） |

**B. 两套系统不同步——用单向数据流防**

| V2 发生了什么 | 根因 | V3 对策 |
|------|------|------|
| QuickSend 暗色菜单白底白字 | 该组件没走 DynamicResource | CSS 变量全量继承，不存在"没走的组件" |
| 拖拽摇杆后文字变黑 | MouseMove 热路径改色 | 组件不从 JS 设颜色，只从 CSS 读 |
| 暗色滚动条对齐偏移 | WPF ScrollBar 模板特判 | CSS `scrollbar-color` 原生支持 |

**C. 静默丢数据——用显式 unknown 处理防**

| V2 发生了什么 | 根因 | V3 对策 |
|------|------|------|
| 未知协议类型消息从接收区静默消失 | switch 无 default 分支 | 未知 ID → 自动建 generic 卡 + toast 通知（方案 §2.4） |

**D. WPF 专有 bug——换技术栈自动避免**

| V2 发生了什么 | 根因 |
|------|------|
| Path 水平线消失/斜线断 | WPF Canvas Shape 渲染缺陷 |
| TypeConverterMarkupExtension 崩溃 | BAML 编译缓存 + ico 路径 |
| Popup.PlacementTarget 遗漏 → 弹窗位置错乱 | WPF Popup 机制 |
| EmbeddedResource 子目录路径错 | MSBuild 资源管理 |
| SnapShapeToPixel + EdgeMode → 直线消失 | WPF 像素对齐 bug |

换 Tauri + React → 这些问题全部不存在。HTML5 Canvas 2D 渲染、Vite 打包、CSS 定位——没有 WPF 的 BAML/Popup/Path 陷阱。

**E. V3 新增风险——需要显式防范**

| 风险 | V2 没有此问题（为什么） | V3 的防范 |
|------|------|------|
| Rust 串口 panic 导致进程退出 | C# try-catch 兜底 | Rust `unwrap_or_else` + Result 传播，读线程 panic 不崩主进程 |
| CM6/Monaco 内存泄漏（长时间运行） | AvalonEdit 成熟稳定 | 行数上限裁剪 2000 行 → 砍 500（和 V2 同逻辑） |
| IPC 事件堆积导致 UI 卡 | WPF 直接同进程调方法 | RingBuffer 512 条上限，满则覆盖最老 |
| Tauri WebView2 版本兼容 | 无 | 最低版本检查，异常时提示安装 WebView2 Runtime |

### 实施顺序

```
Step 1: Tauri + React 脚手架 → tauri dev 能弹出窗口
Step 2: 整体布局 + 顶栏 + 视图切换 + 状态栏 + i18n 基础设施
Step 3: 终端视图 UI（CM6 接收区 + Monaco 发送栏 + 侧栏设置）
Step 4: 工作台 + 设置视图（空壳）
Step 5: 核心服务（DataConverter / ProtocolParser / RingBuffer / PreferenceService）
Step 6: Rust 串口层（枚举 / 打开 / 关闭 / 读写 / emit 事件）
Step 7: 接通数据管道（Rust → RingBuffer → CM6 → 蓝色回显 → 暂停 → 搜索 → 导出）
Step 8: ~~顶栏 + 状态栏~~（已并入 Step 2）
```

**原则**：先建 UI 骨架，再建无依赖的服务（DataConverter、ProtocolParser、RingBuffer），然后攻串口层（唯一不确定性），最后接通全链路。每一步编译通过再走下一步。

## 三、Phase 2：终端完善（Phase 1 后续）

### 为什么 Phase 2 不做卡片

Phase 1 的终端视图**骨架完整但多处有壳无实**：HEX 模式选了不生效、定时发送 toggle 在那没 timer、COM 口枚举写了但没调、发送历史完全没有、行号 toggle 不工作、编码切换不走真实编码器、TX/RX 计数器是硬编码。

对照 V2 收发界面逐项排查后，整理出 **P0 5 项 + P1 7 项 + P2 6 项 = 18 项基础功能**，另有 **4 项新架构红利**（Phase 2 后期可选）。Phase 2 的目标：**用 V3 替代 V2 做日常串口调试。**

**优先级：P0 → P1 → P2 → 🌟 新架构红利。** 先做到和 V2 功能对等并跑通，再做 WPF 做不到的事。

#### ⚠️ AI 友好约束（贯穿 Phase 2 所有实现）

1. **所有用户可配置的数据走 PreferenceService → prefs.json。** 快捷发送预设、终端设置、未来 Command Palette 注册表——AI 改 JSON 就能改配置，不动 React 源码。
2. **快捷发送的 prefs.json 格式必须是平铺 key-value：**
   ```json
   "quickSends": { "AT": "AT\r\n", "查询WiFi": "AT+CWLAP\r\n" }
   ```
   不做嵌套数组——AI 一眼看懂的格式。
3. **PreferenceService 写入时不做格式转换。** 读到什么写回什么——AI 手改的 JSON 不会因为程序重新序列化而变形。
4. **文件监听 → PreferenceService 对比 → UI 自动刷新。** Phase 3 接入 Tauri 文件系统后，AI 改 `prefs.json` 保存 → V3 不重启就生效。和设计方案 §1.5 一致。

### P0 — 真正影响使用

#### 1. 发送历史

V2 有 `RecordSendHistory()`——最近 20 条，下拉菜单回填到发送框。V3 目前输入发送后就没了。

- 点击弹出最近 20 条列表，选中回填到发送框
- 上下键（ArrowUp/ArrowDown）在 Monaco 中浏览历史
- 历史存 PreferenceService（内存中，暂不持久化——和 V2 一致）

**参照：** V2 `MainWindow.xaml.cs` 的 `RecordSendHistory` + `btnHistory_Click`

#### 2. COM 口枚举 + 热插拔

Rust `list_ports` 命令已就绪，但 TopBar 硬编码 `COM3`。

**实施：**
- TopBar 挂载时调 `invoke("list_ports")` 填充下拉框

- 当前端口消失 → 自动清空选择 + 系统消息提示

#### 3. HEX 模式真的工作

侧栏有文本/HEX 切换，但 `handleSend` 永远用 `TextEncoder`，接收也永远是文本。

**实施——发送侧：**
- HEX 模式下 `handleSend` 调 `DataConverter.HexToBytes(sendValue)` → 字节写串口
- HEX 输入自动格式化（`AutoFormatHexInput`）：
  - 过滤非法字符（只保留 `[0-9A-Fa-f]`）
  - 大写
  - 每两个字符插一个空格
  - 无效字符出现时显示黄色警告条（V2 `tbHexWarning`）
- HEX 模式下编码选择框禁用（HEX 不需要编码）

**实施——接收侧：**
- `appendLine` 中检查 `receiveMode`
- HEX 模式：`DataConverter.BytesToHex(bytes)` → CM6 显示 hex dump
- 文本模式：保持现有行为

**参照：** V2 `MainWindow.xaml.cs` `AutoFormatHexInput` / `SendRaw` / `OnLineReceived`

#### 4. 定时发送真的工作

侧栏 toggle + 间隔输入框已就绪，但没有 timer 逻辑。

**实施：**
- `useEffect` 监听 `autoRepeat` 和 `repeatInterval`
- `autoRepeat=true` → `setInterval(() => handleSend(), repeatInterval)`
- `autoRepeat=false` → `clearInterval`
- 发送区为空时跳过（不发空内容）

#### 5. 波特率/端口运行时切换

V2 允许不关串口改波特率。V3 TopBar 的 select 没有 onChange 逻辑。

**实施：**
- 波特率下拉框 onChange → `invoke("open_port", { portName, baudRate: newBaud })` 重建连接

- 切换期间状态圆点短暂变黄（"切换中"），300ms 后恢复绿
- 重建期间 RingBuffer 不清空（保留切换前的残留数据）

### P1 — 体验缺陷

#### 6. CM6 行号 toggle 生效

侧栏 `showLineNumbers` toggle 存在，但 CM6 `lineNumbers()` 初始化后不能动态关（技术债务 #3）。

**实施：** CM6 `reconfigure`——用 `EditorView.dispatch` 替换 extensions 中的 `lineNumbers()` 插件：
```ts
// 动态开关行号
view.dispatch({
  effects: StateEffect.appendConfig.of(showLineNumbers ? lineNumbers() : [])
})
```
或使用 `Compartment` 包裹 `lineNumbers()` 实现动态替换。

#### 7. 编码切换真的工作

侧栏选了 GBK，收发还是 UTF-8。

**实施——发送侧：**
- `handleSend` 中按 `sendCoding` 选编码器
- UTF-8/ASCII/Latin-1：用 `TextEncoder`
- GBK：前端用 `encoding-rs` WASM 或降级为 Rust 侧 `encoding_rs` crate 编码后返回字节

**实施——接收侧：**

#### 19. 实时过滤

不是搜索跳转，是 `grep` 式的持续过滤——输入关键字，接收区只显示匹配行，其余全部折叠。删掉关键字全部恢复。

**为什么 V2 做不到：** AvalonEdit 的 DocumentLine 是物理行，隐藏行 = 从文档删除 + 记录位置 + 恢复时插回——hack，不是功能。

**为什么 V3 能做到：** CM6 decorations 可以给不匹配的行 `display: none`。数据全在 document 里，过滤只改变渲染。搭配已有装饰系统，核心逻辑 ~50 行。

**实施：**
```
┌──────────────────────────────────────────────┐
│ 🔍 [POWER________]  ☑Aa  12 行匹配           │  ← React 过滤条
├──────────────────────────────────────────────┤
│  CM6 接收区（仅显示含 POWER 的行，其余折叠）   │
└──────────────────────────────────────────────┘
```
- 输入关键词 → `SearchCursor` 找所有匹配行号
- 不匹配的行用 `Decoration.line({ attributes: { class: "cm-line-hidden" } })` 隐藏
- `cm-line-hidden { display: none; height: 0; }`
- 实时响应用户输入（debounce 150ms），大数据量下也稳定

**涉及文件：** 可复用搜索条组件 + `TerminalView.tsx`

#### 20. 多视图 tab

同一份 RingBuffer 数据，三个渲染镜头：

```
[原始文本] [HEX 视图] [过滤: POWER]
```

三个 tab 是三个独立 React 组件，各自从 RingBuffer drain 副本消费。切 tab 不丢数据、不重建。

**为什么 V2 做不到：** AvalonEdit 单 document 架构——文本和 HEX 切换是清空+重建。三个并行镜头意味着三份文档拷贝+三方同步。

**为什么 V3 能做到：** RingBuffer drainAll 后 Pub/Sub 分发给多个消费者。每个视图组件维护自己的渲染状态。

**实施：**
- RingBuffer 改 `subscribe(listener)` 模式（当前 `drainAll` 是独占消费）
- `TabBar` 组件：三个 tab 按钮 + 高亮当前
- 每个 tab 对应一个 `TerminalTab` 组件实例，各自持有 CM6/虚拟列表 view

#### 21. Command Palette

`Ctrl+Shift+P` → 命令面板，模糊匹配所有操作：

```

  切换 HEX 模式
  切换 HEX 发送
> clear

  清空发送区

**为什么 V2 做不到：** V2 连搜索都没好好做——`SearchPanel.Open()` 了就没了。命令面板需要命令注册表 + 模糊搜索 + 键盘导航 + 弹出 UI，至少 500 行 WPF。

**为什么 V3 能做到：** React 组件的组合天性。一个 `input` + 扁平命令列表 + `String.includes` 过滤。~100 行。

## 五、Phase 3：卡片架构 + 工作台视图（原 Phase 2）

**⚠️ 一等公民功能：多 workspace 切换**

用户场景：一块 MCU 做 PID 调参，换一块 MCU 做心率课设，再换一块做车距报警——每套固件有不同的卡片 ID 和不同的卡片布局。顶栏下拉框切换 workspace，所有卡片立即替换，不删卡、不重建、不重启软件。

```
workspaces/
  workspace_pid_tuning.json    ← PID 调参：三滑杆 + 一波形
  workspace_heart_rate.json    ← 心率课设：波形 + 阈值滑杆 + 报警灯开关
  workspace_distance_alarm.json← 车距报警：距离 Gauge + 蜂鸣器开关 + 超声波波形
```

**设计约束：**
- 切换 workspace 不关串口。旧数据进来找不到 ID → 自动建 generic 卡——用户一眼知道"忘换固件了"
- 每个 workspace 独立平铺卡片数组，和设计方案 §1.5 一致
- workspace 文件本质上就是卡片列表 JSON，AI 可以直接生成（AI 友好）

**实施顺序：**

```
1. PreferenceService 切 Tauri 文件系统 API（读/写 JSON 文件）
2. Card Shell + Component 架构实现
3. CardRegistry（ID → Card 字典）
4. 卡片网格布局 + 拖拽重排（react-grid-layout）
5. Gauge / Switch / Slider / Plot / KeyPad / Terminal 组件
6. 编辑模式（⚙ 属性面板 + ✏ 插入/删除）
7. ProtocolParser 路由接通（ID 查 CardRegistry → OnData）
8. workspace.json 读写 + 多 workspace 切换（顶栏下拉框）
9. 未知 ID 自动创建 generic 卡
10. V2 旧协议兼容翻译层
11. 文件监听热加载（workspace.json 外部修改 → UI 自动刷新）
```
