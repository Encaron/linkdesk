# 05-插件更新 · 编辑器-打开方式适配（蓝图）

> 状态：📋 **蓝图起头**（2026-10-04，与壳案[文件打开方式与贡献点](../../04-软件更新/待抉择池/文件打开方式与贡献点/00-README.md)配套；实施归 editor 仓 `E:\linkdesk-plugins\official\editor`，收口后档案归还本仓 `docs/`）。
> 一句话：编辑器从「什么文件都硬吃」变成**打开方式体系里的一个普通参与者**——文本类仍归它（它声明的），二进制不再硬解成乱码，兜底位从「写死的名字」变成「它声明的一个角色」；未来第三方编辑器接管兜底位时，editor 零特殊、壳零改动。

## 一、编辑器在体系里的三重身份（先想清楚再动码）

1. **45 个文本扩展名的持有者**（plugin.json `fileAssociations`）——这是**声明**不是特权，第三方可声同扩展名竞争（壳案 D7 仲裁）。
2. **兜底位的当前承担者**——不是因为它叫 editor，而是因为壳 `DEFAULT_TAB_TYPE="editor"` 写死了它（壳案证据⑧，T7 去硬编码）；改后这个身份来自它**声明 `role:"text-fallback"`**，第三方 Eclipse 系编辑器声明同角色即可整体接管。
3. **兜底呈现的参考实现者**——「这是二进制」的**判定归壳**（`EncodingService.isBinary` 一处真相源），「警告怎么画」**归被兜底的插件**（用户 2026-10-04 拍板口径：编辑器也只是方式之一，警告归它自己弹）；editor 出参考实现，配方进 `@linkdesk/ui` 共享组件，第二个作者几行接线就有同款。

## 二、适配格（E1–E4）

## 三、判据

1. 单击 pdf/exe → editor 呈现兜底页（非乱码）＋两颗钮可用；负控：摘掉判定分支 → 乱码复现（证明判据真）。
2. 第三方样例插件声明 `role:"text-fallback"` 并激活 → 单击 .txt 开**它**而非 editor（接管位生效）；卸载后单击 .txt 回 editor。
3. md/ts/json 等文本类的打开行为与渲染**逐字节不变**（回归面）。
4. 仓内三门＋壳 `npm run check` 全绿（i18n 新串走 lang-defaults 外仓链）。

## 四、依赖与顺序

E1 吃壳案 T1 的判定面与 `@linkdesk/ui` 组件（组件先行，editor 接线）；E3 吃 T7 的 schema 扩展；E2 独立、等 MD 夹立项。壳侧三格攒批未发版期间，E1/E3 的插件版**先不发**（发旧壳装了也白装）——与壳发版同批出厂，口径记进各仓 CHANGELOG。
