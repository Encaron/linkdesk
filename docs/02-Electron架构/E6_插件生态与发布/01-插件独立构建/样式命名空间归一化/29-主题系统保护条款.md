# 主题系统保护条款（E5.8 成果不可冻结 · 本系列一切规则的**上位约束**）

> **为什么有这一档**：用户 2026-09-16 原话 —— 「**我费劲心思做的主题系统，各种玻璃，字体，当时在 E5.8 经历那么多，而且大部分测试插件都是主题类的。你自己去看看相关任务书和记忆，从 Phase 10 开始，若是不能变了，那简直对软件是毁灭打击。**」
> ⇒ 本档把 E5.8 **Phase 10–12** 的既有机制列成**保护对象**，并给本系列四条轴划出**必须留的口子**。**任何一轮的规则若与本文冲突，以本文为准**；发现自己那条规则会冻死主题系统 ⇒ **当场改规则，不许照做**。
>
> **非新能力声明（`check-design-flow` §8.4 ③）**：本档是**既有机制的保护清单与回归判据**（列 E5.8 Phase 10–12 的既有能力 ＋ 给本系列四条轴划边界），**不含新能力设计** —— 文中出现的 `contributes.themes` · token 名 · `ThemeEngine` / `commitTokens` / `preload-pool` 等标识符均为**引用既有实现**。⇒ **无需新能力设计前置**。
>
> **一句话**：**本系列只冻结「名字」，绝不冻结「能力」。** 新增 token / 新玻璃参数 / 新字体档位 / 新主题能力 / 新配方键 **全部是加法，明确欢迎**。

## 一、保护对象（E5.8 Phase 10–12 的既有机制，逐条不许动）

> 出处：`docs/02-Electron架构/E5.8_归一化基建/外观主题化/`（01 设计总纲 · 02 变量契约 · 03 域贡献者与混搭 · 13/17 重构与最终最优根治 · 20 能力闭环 · 21 玻璃饱和语义）＋ `度量体系归一化/00`（Phase 12）＋ 记忆 `appearance-audit-archive` / `theme-decisions`。

| # | 机制 | 为什么是命脉 |
|:--:|:--|:--|
| **P1** | 🔴 **`commitTokens` 是唯一写 `:root` ＋ 广播点**；variables **全量**经 `theme:changed` 广播 → `preload-pool` 写**池侧 `:root`** ⇒ **新 token 零新增自动带过去** | 这是主题系统「一设值、全壳联动」的唯一通道；**也是它可扩展的原因**（加 token 不需要改任何转发代码） |

## 二、🔴 唯一的真危险：把「名字」的规则误用到「机制」上

| 危险动作（**禁止**） | 后果 |
|:--|:--|
| 把 `commitTokens` / preload-pool 的**写 `:root`** 改成「挂到某个类/某个元素下」或「包裹进作用域」 | 🔴 **主题立刻不再全局生效** —— 等于毁掉主题系统（P1） |
| 认为「插件/宿主不得在文档级定义 token」这条**也管 JS 侧写入** | 同上（**本系列的 token 判据只管 CSS 源码里的定义**；JS 侧 `documentElement.style.setProperty` 与 preload-pool 写池 `:root` **不在管辖内，永远合法**） |
| 把 `[data-theme="light"]` 当"文档级污染"要求改成类限定 | 🔴 亮色契约块失效（P3/P5） |
| 为了"干净"把 `#ld-float-layer` 的 token 定义搬走 | 🔴 破 P2 的浮层唯一权威与磨砂地板 |
| 把主题配方键（`colorway.colors`）当成"影子契约"要求登记 | 🔴 冻死主题作者的自由（配方键**可以超出** `index.css` —— 引擎写入的就是它） |

## 三、「名字冻结」≠「能力冻结」（本节最重要的一张表）

| ✅ 允许（**加法，明确欢迎**） | ⛔ 禁止（本系列禁区） |
|:--|:--|
| **新增 token**（新玻璃参数 · 新字体轴 · 新档位 · 新语义色） | 把引擎的全局写入搬进某个作用域（P1） |
| **新增主题能力 / 新域 / 新配方键**（数据层，`contributes.themes` 面） | 删除或改动 `commitTokens` / `theme:changed` 广播链 |
| **改 token 的「值」语义 / calc / 默认值**（例：E5.8#66 把自引用改 `--surface-glass-blur`） | 改既有 token 的**名字**（本系列定型之后） |
| **新增组件族**（含公共族，见 §四.3） | 破坏三处「唯一权威」（P2） |
| **新增 `--font-size-*` 档位 / `--radius-*` 档位**（顺着既有标尺加） | 让规则要求第三方**必须**消费 token 或**必须**用官方组件 |

## 四、给本系列四条轴**必须留的口子**（缺一个就是冻死主题系统）

1. **token 轴（件 6）——允许作用域至少三类**：
   - ① **宿主契约块**：`:root` ＋ `[data-theme="light"]`（亮色）；
   - ② **类限定**：宿主 `.ldk-*`（**含伪元素限定**，如实测存在的 `.ldk-titlebar::before, .icon-bar::before, .side-panel::before` 那条 per-surface 玻璃系数）；
   - ③ **portal 面**：浮层宿主（实测 `#ld-float-layer { --float-blur-floor }`）。
   - 🔴 **契约名单的定义** = `index.css` 契约块 **∪ 主题配方键**（**两者都是数据源**）⇒ 名单**生成式**，且**配方键超出 `index.css` 是合法的**（不是"影子契约"）。
   - 🔴 **JS 侧写入不在管辖内**（§二 第二行）。
2. **选择器形态轴（件 7）——宿主基线清单必须把主题机制用到的都收进去**：`[data-theme="light"]`（契约块）· `*:focus-visible` · `html`/`body`/`#root`/`#pool-root` · `*` 三条 reset ⇒ **它们是有意基线，不许当污染**。
3. **族段轴（判据⑦）——必须允许一个「公共族」**：`ldk-common-*`，供**跨组件复用的原语**（例：将来做"共享玻璃表面 / 共享表面原语"）。否则门禁会把这类加法冻死。
   - 判定式照旧：族段 ∈ { 该组件目录的组件族 · **`common`** }；`--` / `__` 后缀允许。
4. **验收——主题能力回归清单**（承接 [19 号档](19-任务-收口批-遗留账与系列收口.md) §第 1.20 轮 §三b「横切机制零回归」，**每一轮实机都带跑**）：
   切主题（含**多配色**与**混搭**）· **玻璃三参**（模糊/饱和/不透明度，含 s=0 端点）· **浮层磨砂地板**（玻璃关仍可读）· **圆角六档 ＋ 滑杆 0/16/32** · **字号 85 / 100 / 125 / 150 四档**（＋ `window.zoomLevel` 正交）· **字体族切换**（`--font-ui` / `--font-mono`）· **背景**（panorama / mask）· **亮暗切换** · **monaco 内容孤岛**（字号不随全局、颜色跟随）。
   ⚠️ 任一项与今天不一致 ⇒ **该轮不算过**。

## 五、实测：本系列对**主题类**资产零影响（用户点名「大部分测试插件都是主题类的」）

| 资产 | 实测 | 本系列动不动 |
|:--|:--|:--|
| **10 只主题插件**（aurora-glass / defaults / iconset-pastel / mint-soda / panorama / pill / songti / terminal / twilight-forest / zones） | **0 个 CSS**（纯数据配方 `themes/*.json`） | **一个都不动**（1.21/1.21b/1.24 均不碰） |
| **主题配方键**（`colorway.colors` 里的 `bg-card` / `accent` / `glass-*` …） | 数据层，非 CSS | **不动**（含否决甲之后，配方键**一个都不用改**） |
| 主题相关**共享组件**（`theme-picker` / `theme-browser`） | 有 CSS | 只**加 `ldk-` 前缀** ＋ 那批临时短前缀并进族（1.21b）——**能力一字不动**；作者轴发版照 1.21b 流程 |
| **主题引擎**（`ThemeEngine/**` · `preload-pool/events.ts`） | JS 写入 | **不动**（P1 禁区） |

> 🔑 **这也是否决「甲」（宿主 token 改名 `--ldk-*`）的一笔实实在在的收益**：若做甲，**10 只主题配方 ＋ 全部主题读取点 ＋ 引擎写入格式**都要动，而主题系统正是你最不愿被碰的那块。⇒ 本档与 [22 号档 §10.4](22-收口总方案-跨方样式污染九件套.md) 的否决结论**互相印证**。
