### 第二步：读数模块（口径写死，⛔ 不许在别处复刻）

- 输入 → 输出（形状建议）：
  ```
  { pluginId, state, dangling: { count, names[] }, minAppVersion: "0.2.10"|null,
    shellVersion: "0.2.11", minAppSatisfied: true|false|null,
    lastUpdate: "2026-08-14"|null, shellBuiltAt: "2026-09-12"|null, unknown: ["…"] }
  ```
- **状态算法（逐条写进代码头注，判据唯一；用户面文案照抄，⛔ 不在本格发明词）**：
  | `state`（机器值） | 判据（**读数驱动，不靠人打标**） | 用户面词（[00 §〇d](00-整理档案.md) 定稿） |
  |:--|:--|:--|
  | `incompatible` | `minAppSatisfied === false`（`minAppVersion > 当前壳`）——**已有硬机制**（市场拒装 ＋ 加载器拒载），本格只是**读出**它 | **不适配** |
  | `drifted` | `minAppSatisfied !== false` 且 `dangling.count > 0` | **部分不适配** |
  | `current` | `minAppSatisfied !== false` 且 `dangling.count === 0` 且 `lastUpdate >= shellBuiltAt` | **正常** |
  | `compatible` | `minAppSatisfied !== false` 且 `dangling.count === 0` 且（`lastUpdate < shellBuiltAt` **或** 任一日期为 `null`） | **兼容** |
  | `unknown` | 关键输入缺失（未跑尺子 / 拿不到壳日期且拿不到插件日期 / 离线） | **—** |
  - 🔴 **两个日期的比较不是阈值**：`lastUpdate`（插件最后发版日，catalog `publishedAt` 或本地 `plugin.json`）与 `shellBuiltAt`（当前壳构建日，`product.json` 的 `date`）**都是真日期**，只比大小；⛔ **不许**出现「超过 N 天」这类发明出来的判据。

### 8.3 读数形状（**格 5 要照抄的东西**）

- **唯一入口**：`window.linkdesk.plugins.getCompatibility(req)`（**optional 面**——调用方先判存在；类型 `PluginCompatibilityRequest` / `PluginCompatibilityReading` 住 `src/core/api/linkdesk-api/types.ts`）。req = `{ pluginId, minAppVersion?, publishedAt? }`——后两项是**目录侧事实**（市场从 catalog 条目供给；**已装插件会被主进程用磁盘 manifest 覆盖 `minAppVersion`**——那是加载器执法的那份）。
- **读数**：`{ pluginId, state, dangling: {count, names[]} | null, minAppVersion: string|null, shellVersion, minAppSatisfied: boolean|null, lastUpdate: string|null, lastUpdate 为 YYYY-MM-DD, shellBuiltAt: string|null, unknown: string[] }`。
- **`null` 语义**：`dangling: null` = 未装/目录读不了（**缺数据 ≠ 有问题**）；`minAppSatisfied: null` = 没声明 minAppVersion；`lastUpdate/shellBuiltAt: null` = 目录拿不到 / dev 壳日期占位 `'—'`。`unknown[]` 是**机器码诊断面**（`dangling:uninstalled` / `dangling:scan-failed` / `lastUpdate:missing` / `shellBuiltAt:missing`），⛔ 不是用户面文案。
- **state ↔ 用户面词**（唯一代码内出处 = `compatibility.ts` 头注，逐字照抄 [00 §〇d](00-整理档案.md)）：`incompatible`→**不适配** · `drifted`→**部分不适配** · `current`→**正常** · `compatible`→**兼容** · `unknown`→**—**。⛔ 格 5 不许换词、不许在壳面加句子（文案归插件 i18n）。
- **状态优先级（判据②单点）**：`incompatible`（`minAppSatisfied === false`）→ `unknown`（`dangling === null`，**先于 drifted**）→ `drifted`（悬空 > 0）→ `current`（两日期齐且 `lastUpdate ≥ shellBuiltAt`）→ `compatible`（兜底，**含任一日期缺失**——保守且是真话）。
- **`shellBuiltAt` 的实际取法**：`product.json` 的 `date`（发布时 `write-product-json.mjs` 写入、随 asar 走）→ 主进程 `loadProduct().date`（`electron/product.ts`）→ handler 注入 `shellBuiltAtRaw` → `normalizeDay()` 归一化为 `YYYY-MM-DD`（dev 占位 `'—'` ⇒ `null`）。`shellVersion` = `app.getVersion()`（package.json 单点）。

### 8.5 残余边界（诚实清单）

1. **dev 壳日期 `'—'` ⇒ `current` 永远产不出**（一律落 `compatible`）——保守且是真话，但意味着「正常」只在安装版上有意义。
2. **运行时扫描腿是格 1 口径的移植**，不是同一份代码——对等性由对账测试钉住（桩 8 例 ＋ 真 6 zip）；格 1 口径若改，对账测试当场红（这就是设计意图），届时同笔改两处。
3. **静态尺子读不出动态拼接**（格 1 边界 1 原样继承）：运行时拼接的类名读不出 ⇒ 悬空读数下限，`skipped` 计数不在读数面里（只要 count）。
4. **只对已装插件算悬空**：zip 未解包态（货架未安装条目）不算 ⇒ `dangling: null` → `unknown`（—）——市场对未装条目只能显示 minApp 轴的「不适配」或「—」。
5. **宿主定义集随构建走**：`host-css.generated.ts` 是生成物，改壳 CSS 不同笔 regen 会被 `--check` 抓（进 check 链）——运行时读数与格 1 尺子的定义集**同一采集器**，无第二口径。
6. **`publishedAt` 依赖目录**：侧载/离线插件 `lastUpdate: null` ⇒ 落 `compatible`（不落 —）——按 00 §〇d「日期缺失落兼容」的裁。
7. **每次请求现算不缓存**：市场详情页每开一次扫一遍（一只插件几百 KB 级，主进程单线程无压力）；若日后有高频调用方需另议缓存（本格不做）。
