# 20 — 我的插件加一条配置项

> **本页回答一个问题：** 我的插件需要一个"用户可调的开关/数值/下拉"——**最少要写什么**？
>
> **三步：声明一条 → 设置页自动出现 → 代码里读它。** 不用写任何设置界面。

| | |
|---|---|
| 读者 | 已经有插件在跑，现在想加个可配置项的作者 |
| 形态 | **最小做法**（能抄完就完事） |
| 不是 | 「做一个设置插件」（那是**替换整套设置界面**，另一件事 → [10-如何造一个设置插件](10-如何造一个设置插件.md)）· 字段全表（→ [03-插件contributes规范](03-插件contributes规范.md)） |

> **两件事别混**（这是最常见的误会）：
> - **本页**：**给你的插件**加一条配置项 —— 出现在**已有的**设置页里，一个分组，零界面代码。
> - [10-如何造一个设置插件](10-如何造一个设置插件.md)：**你自己做一整套设置 UI** 去替代壳的设置页（`factoryRole: "settings"`）。绝大多数插件**永远不需要**这个。

---

## 一、第 1 步：在 `plugin.json` 里声明

```jsonc
{
  "pluginId": "my-plugin",
  "contributes": {
    "configuration": {
      "title": "我的插件",                       // ← 设置页左侧导航里的分组名
      "properties": {
        "my-plugin.autoSave": {                  // ← key 必须带 <pluginId>. 前缀
          "type": "boolean",
          "default": true,                       // ← default 必填
          "title": "自动保存",                    // ← 行名（可选；不写则行上显裸键）
          "description": "退出时自动保存"          // ← description 必填（渲染成提示）
        },
        "my-plugin.refreshInterval": {
          "type": "number",
          "default": 1000,
          "title": "刷新间隔",
          "description": "刷新间隔（毫秒）"
        },
        "my-plugin.units": {
          "type": "string",
          "default": "mm",
          "enum": ["mm", "cm", "inch"],
          "enumDescriptions": { "mm": "毫米", "cm": "厘米", "inch": "英寸" },   // ← 对象：枚举值 → 显示名
          "title": "显示单位",
          "description": "显示单位"
        }
      }
    }
  }
}
```

**做对了的标志：**

```bash
npm run validate     # 校验 plugin.json 合法
```

装进 LinkDesk 后，设置页左侧出现「我的插件」分组，右侧自动渲染出这三个控件——**布尔变开关、枚举变下拉、数字变输入框**。你没写一行界面代码。

**两个该补的可选名字。** `title` = 该行的人话短名——设置页显示它而不显示裸键，市场详情「功能」页把它显示在键的上方；不声明则回退显键。`enumDescriptions` = 下拉每个选项的名字（**对象**：值 → 显示名）；没给名字的选项回退显原文。两者约定都与 `description` 同——中文原文即 i18n key，英文译名进插件自己的 `i18n/en.json`。你仓的 verify 腿 `check-config-titles` 会在内测期把还没补的列成告警（v1 起判红）——详见 [06-plugin.json规范](06-plugin.json规范.md)。

## 二、第 2 步（可选）：让它长得更像样

| 想要的效果 | 加什么 |
|:--|:--|
| **换一个更合适的控件**（取色器 / 滑杆 / 文件选择…） | `uiHint`——见下表 |
| 同一分组里再分小标题 | `group`——同 `group` 值的几条会归到一个二级标题下 |
| 下拉选项**显示短标签**、鼠标悬停看全句 | `enum` ＋ `enumDescriptions`，并配 `uiHint: "segmented"` |
| 这一项不是给用户改的，而是**显示一个实时状态** | `renderHint: "readonly"` ＋ `statusCommand`——见 §二·2 |
| 这一项是个**按钮**（点一下去做某件事） | `renderHint: "action"` ＋ `actionCommand`——见 §二·3 |
| 分组名下面加一行说明 / 每个小分节加一行说明 | `subtitle` / `groupDescriptions`（写在 `configuration` 这一层，不是键上） |

**`uiHint` 已知值**（未知值会降级回按 `type` 默认渲染，不会报错）：

| `uiHint` | 渲染成 |
|:--|:--|
| `"color"` | 取色器 |
| `"slider"` | 滑杆（配 `minimum` / `maximum` / `step`，不写就按区间推） |
| `"segmented"` | 分段单选（配 `enum` ＋ `enumDescriptions`） |
| `"fontFamily"` | 字体族选择（`monoOnly: true` 只列等宽族） |
| `"fontSize"` / `"file"` / `"directory"` / `"image"` | 对应专用控件 |

```jsonc
"my-plugin.accent": {
  "type": "string", "default": "#3B82F6",
  "uiHint": "color", "description": "强调色"
},
"my-plugin.level": {
  "type": "number", "default": 50,
  "uiHint": "slider", "minimum": 0, "maximum": 100, "step": 5,
  "description": "灵敏度"
}
```

> ⚠️ **没有 `"integer"`**——整数也用 `"number"`（配 `step: 1`）。

### 二·1 分组与小分节的说明文字

分组名（`title`）下面可以加一行副标题，每个小分节（`group`）也可以各加一行——**写在 `configuration` 这一层**：

```jsonc
"configuration": {
  "title": "我的插件",
  "subtitle": "这个分组整体是干什么的，一行话",
  "groupDescriptions": { "采样": "这一节里的设置影响采样阶段" },
  "properties": { /* … */ }
}
```

两条都可选。`groupDescriptions` 的键**必须与键上写的 `group` 逐字相同**（否则那一行不会出现）；没有声明的分节保持原样，不会留空行。

### 二·2 只读状态行：显示**实时状态**，不是配置值

有些行不是让用户改的，而是让他（和 AI）**看见正在发生什么**——比如「通道状态：运行中 · 127.0.0.1:47001」。这类行用 `renderHint: "readonly"`：它的值来自**一条命令的返回值**，每次渲染后还会**每 3 秒重取一次**，所以显示的是活读数。

```jsonc
"my-plugin.engine.status": {
  "type": "string", "default": "",
  "description": "引擎当前状态",
  "renderHint": "readonly",
  "statusCommand": "my-plugin.engineStatus"   // ← 你自己注册的命令（返回一句话）
}
```

```ts
// 插件代码里注册这条命令——返回值就是那一行要显示的文字（可含 \n 换行）
window.linkdesk?.commands?.registerCommand?.("my-plugin.engineStatus", async () => {
  return connected ? `运行中 · ${endpoint}` : "未连接";
});
```

| 要点 | 说明 |
|:--|:--|
| 值从哪来 | **命令行**，不读 `configuration`——所以它能显示运行时状态；`default` 只为通过校验，不会显示 |
| 命令返回什么 | 一个字符串（多行用 `\n`，渲染成多行） |
| `statusCommand` 写谁的 | **你自己注册的命令**；写壳命令 id 也行（只要你清楚它返回什么） |
| 用户能改吗 | 不能——这是只读行，没有输入控件 |
| 命令还不存在会怎样 | 那一行**空着**（不报错、不占位）——所以别在命令注册前就指望它有字 |

### 二·3 按钮行：点一下去做某件事

```jsonc
"my-plugin.openDashboard": {
  "type": "string", "default": "",
  "description": "打开仪表盘",                  // ← 这一行就是按钮上的文字
  "renderHint": "action",
  "actionCommand": "my-plugin.showDashboard"    // ← 点击时执行这条命令
}
```

- **按钮文字 = `description`**（这行没有别的字符串可用，所以 `description` 要写成动作短语，别写成名词解释）。
- 点击时执行 `actionCommand`；命令可以是**你自己注册的**，也可以是**壳命令**（如 `app.openAiManual`）。
- 想「条件不满足时置灰」：加 `actionDisabledAll: [{ "key": "my-plugin.engine", "value": "off" }]`——**列出的每一项都匹配当前配置值**时按钮禁用。**不写这个字段就是永远可点**（写了却没有一项命中，同样可点）。

> 三样都是**通用能力**：任何插件声明就生效，宿主没有特权（设置页的渲染方换一只插件也照渲染——契约就写在 `plugin.schema.json` 里）。

## 三、第 3 步：在代码里读它

**读写一律走 `window.linkdesk.configuration`**（禁止 `localStorage`）：

```ts
// 读一次
const autoSave = await window.linkdesk.configuration.get<boolean>("my-plugin.autoSave");

// 订变化（用户在设置页一改，你这边立刻收到）
useEffect(() => {
  return window.linkdesk.configuration.onChange<number>("my-plugin.refreshInterval", (ms) => {
    restartTimer(ms);
  });
}, []);
```

**别忘了退订**：`onChange` 的返回值就是退订函数——在 `useEffect` 里 `return` 它（订阅一律挂在 effect 上，不挂模块顶层）。

> 想让"用户改了设置 → 界面上好几处同时跟着变"，见 [18-区域间互动 §配方 D](18-区域间互动.md)。

## 四、进阶：给**别人的**配置项提建议值

如果你想让某个键"默认值更好"，但**那个键不是你的**（比如给内置编辑器的字号提个建议），用 `configurationDefaults`：

```jsonc
{
  "contributes": {
    "configurationDefaults": {
      "editor.fontSize": 14
    }
  }
}
```

| 对比 | `configuration` | `configurationDefaults` |
|:--|:--|:--|
| 定义**自己的**设置项 | ✅ | ❌ |
| 给**别人的**键提默认值 | ❌ | ✅ |
| 用户手动设过之后 | 用户值优先 | 用户值优先（弱默认只在用户从未设过时生效） |

## 五、常见错误

| 症状 | 病根 | 正确做法 |
|:--|:--|:--|
| 设置项没出现在设置页 | `key` 没带 `<pluginId>.` 前缀，或漏了 `default` | key 一律 `my-plugin.xxx`；`type`/`default`/`description` 三个都得有 |
| 改完设置要重启才生效 | 只 `get` 了一次，没订变化 | `configuration.onChange` |
| `npm run validate` 报错 | `configuration` 写成了数组 / 少了 `properties` | 形状照本页 §一 抄 |
| 值重启就丢 | 用了 `localStorage` 或组件 state | `configuration.set` |
| 想要一个整页设置界面，但只是改字号 | 走错门了 | 本页三步就够；整页替代才去 [10](10-如何造一个设置插件.md) |
