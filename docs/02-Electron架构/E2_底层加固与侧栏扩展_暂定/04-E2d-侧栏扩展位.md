## 为什么取消

**原设计：** 侧栏双槽位——persistent（常驻）+ tagFollower（跟标签页走），两个区域同时显示。

**VS Code 源码实锤：** `SidebarPart` 继承 `AbstractPaneCompositePart`，只有一个 `activeViewletSettingsKey`。侧栏永远只显示一个 viewlet——点 Explorer 显示文件树，点 Search 整个切到搜索。**VS Code 没有双槽位。**

```typescript
// VS Code: src/vs/workbench/browser/parts/sidebar/sidebarPart.ts
export class SidebarPart extends AbstractPaneCompositePart {
  static readonly activeViewletSettingsKey = 'workbench.sidebar.activeviewletid';
  // 只有一个活跃 viewlet——单槽位
}
```

**LinkDesk 现状：** `SidePanel.tsx` 的 `lastSidebar` 机制已经是 VS Code 模式——侧栏记住上次显示的视图，切标签页不丢。点图标栏不同图标切换侧栏内容。完全不需要 `sidebarRole`。

**对文件树的影响：** 文件树就是侧栏中的一个普通视图——和终端会话列表一样。点 📁 → 侧栏显示文件树，点别的图标 → 侧栏切走。走现有路径即可，零架构改动。
