## 〇、设计原则（2026-08-30 用户拍板）

**更新通知/进度/交互全部复用壳已有 toast 系统，不新建任何 UI 表面。** 参照先例：03-插件市场 详情页「事件型提示一律走右下角 toast」（用户拍板：顶部横幅把整个 UI 往下推 + 影响性能，一律 toast 化）——更新通知同款。

> **与 TitleBar 更新按钮的分工（2026-08-30 拍板，色彩反转最终态）**：toast 承载**静默信息**（发现/进度/完成/失败/手动结果）；TitleBar 更新按钮承载**可见存在**（有更新才现、全文字 + 主题按钮色，03 §四）。按钮只演进「下载更新 → 更新中 → 重新启动」三态文字（03 §4.3），**不显示进度细节**——点了按钮，进度才走 toast 出来。两者互补不重复。

**复用清单（壳现状实锤）：**

| 现实 API / 组件 | 位置 | 用途 |
|:--|:--|:--|
| `pushToast({message, severity, icon, actions, ttl, isCloseAffordance, source})` | `src/core/services/ui/toast.ts:90` | 全部更新通知入口 |
| `updateToast(id, message)` | `toast.ts:123` | 下载进度循环改文字（注释原文「进度条模式用」） |
| `ToastAction {label, isPrimary, onClick}` | `toast.ts:16` | toast 内按钮（查看更新内容/立即更新/稍后/重启并更新） |
| `isCloseAffordance` | `toast.ts:33` | 点 × 关闭 → 持久化 → 同 source+message 不再弹（=「当天不重复打扰」现成机制） |
| Notification Center（铃铛） | `StatusBarZone.tsx:99-178` | 通知历史自动收录，可回看 |
| `TOAST_TTL_ERROR / SUCCESS / INFO` | `toast.ts:49-53` | 各场景自动消失时长 |
| 渲染 | `#toast-root`（bottom 状态栏上 + right 6px）`ToastHost.css` | 右下角，实时对齐 |

## 一、触发时机（何时弹 toast）

| 场景 | 行为 |
|:--|:--|
| 后台发现更新（周期/启动） | 弹发现更新 toast（§二） |
| 下载中 | 更新该 toast 消息为进度（§三） |
| 下载完成 | 更新为「重启」toast（§四） |
| 用户点「立即更新/重启并更新」 | 对应 toast 按钮触发（§二/§四） |
| 用户点 TitleBar 更新按钮 | `update.openUpdateFlow` 按状态分支（available→下载 / downloaded→重启）→ 进度走 toast（03 §4.3 三态：下载更新 → 更新中 → 重新启动，主题按钮色） |
| 手动检查无更新 | toast「当前已是最新版本」 |
| 检查/下载失败 | toast 错误（TOAST_TTL_ERROR） |

## 二、发现更新 toast

**默认折叠**（对齐真实 ToastHost：详情行 `.toast-details-row` CSS `display:none`，点 ⋁ / 双击展开后 actions 才现）——对标 VS Code 更新通知同样默认收起、展开才见按钮：

```
折叠态（默认）：
┌──────────────────────────────────────────────┐
│ (⬇图标) LinkDesk 有可用的更新 0.2.0   ⋁  ✕   │   ← 主行 42px：icon 16px + message + toolbar（hover 现）
└──────────────────────────────────────────────┘
     ↓ 点 ⋁ / 双击
展开态：
┌──────────────────────────────────────────────┐
│ (⬇图标) LinkDesk 有可用的更新 0.2.0   ⋁  ✕   │
│  来源: 主软件更新    [查看更新内容] [立即更新] │   ← 详情行：padding-left 28px + source + actions
└──────────────────────────────────────────────┘
  （右下角 #toast-root：bottom calc(22px×ui-scale+8px) + right 6px，column-reverse，max-width 450px）
```

**调用：**
```typescript
pushToast({
  message: i18n.t("LinkDesk 有可用的更新 {{version}}", { version: "0.2.0" }),
  severity: "info",
  source: i18n.t("主软件更新"),
  isCloseAffordance: true,   // 用户点 × → 该版本更新提示不再弹（Don't show again，现成机制）
  actions: [
    { label: i18n.t("查看更新内容"), isPrimary: false, onClick: () => openReleaseNotes("0.2.0") },
    { label: i18n.t("立即更新"), isPrimary: true, onClick: () => downloadUpdate() },
  ],
  ttl: 0,                     // 持久——直到用户选择/下载开始；或长 ttl（TOAST_TTL_INFO）
});
```

**「稍后」语义（用户权利保障）：**
- 点 × 关闭 → `isCloseAffordance` 持久化 → 该版本更新提示不再自动弹（用户想查 → 菜单「检查更新…」手动，恒显）。
- 这就是「用户有权一段时间不更新」的实现——**自动弹一次，尊重关闭，手动入口永在**。
- 想要彻底安静：设置 `app.update.mode = manual`（不自动检查，手动才查）。

## 三、下载进度（updateToast 循环改文字）

```
┌──────────────────────────────────────────────┐
│ (⬇图标) 正在下载更新 42%             ⋁  ✕    │   ← 主行 message 循环更新（updateToast）
└──────────────────────────────────────────────┘
     ↓ 展开（可选）
┌──────────────────────────────────────────────┐
│ (⬇图标) 正在下载更新 42%             ⋁  ✕    │
│  来源: 主软件更新                 [后台运行]   │   ← 「后台运行」= 收起 toast，进度进通知中心
└──────────────────────────────────────────────┘
```

**调用（对应 NotificationService.ts:8-10 原文「真进度条 UI 留未来」）：**
```typescript
const id = pushToast({
  message: i18n.t("正在下载更新 0%"),
  ttl: 0,                       // 持久——直到下载结束
});
// 下载进度事件 → 节流 ≤500ms 循环改文字
onProgress((p) => updateToast(id, i18n.t("正在下载更新 {{percent}}%", { percent: p.percent })));
```

> **进度条 UI**：真进度卡样式（VS Code 式右下角进度卡）壳内 `ProgressBar.css` 历史存在、`notification.show(message, {progress:true})` API 面现成（NotificationService.ts 注释）——**留未来**，本次用文字进度（updateToast）。不新造。

## 四、下载完成 / 重启

```
折叠态（默认）：
┌──────────────────────────────────────────────┐
│ (⬇图标) 更新已下载，重启后生效       ⋁  ✕    │
└──────────────────────────────────────────────┘
     ↓ 展开
┌──────────────────────────────────────────────┐
│ (⬇图标) 更新已下载，重启后生效       ⋁  ✕    │
│  来源: 主软件更新         [稍后] [重启并更新] │
└──────────────────────────────────────────────┘
```

**调用：**
```typescript
updateToast(id, i18n.t("更新已下载，重启后生效"));
// 或 pushToast 新 toast：
pushToast({
  message: i18n.t("更新已下载，重启后生效"),
  actions: [
    { label: i18n.t("稍后"), isPrimary: false, onClick: () => {/* 关 toast，状态回 idle，不重下 */} },
    { label: i18n.t("重启并更新"), isPrimary: true, onClick: () => restartToUpdate() },
  ],
  ttl: 0,
});
```

**重启流程（无新 UI——toast 直驱）：**
1. 点「重启并更新」→ `restartToUpdate()` → 主进程 `quitAndInstall()`。
2. 主进程 `app.relaunch` + `app.quit()` → 安装器静默覆盖 → 重启。
3. **无 3s 倒计时弹窗**（那是新造 UI）——toast 点击即执行；误点风险低（「重启并更新」是主按钮，用户主动点）。
4. 重启后首启自动弹发行说明（05 §2.5）。

## 六、与通知中心的关系

- 所有更新 toast 自动进 Notification Center（铃铛未读数）——用户关闭 toast 后仍可在中心回看「有可用更新/正在下载/重启」。
- 中心打开时 toast 被 suppress（现成 `setToastsSuppressed`），行为零改动。
