# E5.8-菜单嵌套通用化档案（#149）

> 2026-08-27。用户拍板（继 #148 菜单递归审查后）：「**以后任何调用我右键系统的，它可以使用嵌套子菜单功能，不管什么方式，只要那个作者愿意就行**」——把嵌套从「壳菜单专属」扩成「**所有菜单入口通用**」。用户进一步补：不管是把右键系统放在某个图标上、放在某个界面上、是运行时、还是直接声明——全都要能嵌套。
> **核心结论**：三条入口盘点后，类型层只剩一处洞——**插件声明式 `contributes.menus` 的 schema 没有 children 字段**（运行时 `registerItems` 的 `ManifestMenuItem` 早已递归，壳 `MenuItem` 早已递归）。#149 = 声明式补洞（schema + 文档三件套，加载器纯透传零改）；**任意深度渲染归 #148**（MenuRegistry 归一化递归 + ContextMenu 渲染递归）。实现顺序 **#148 → #149**。
> 清单指针：E5.8-执行清单 Phase 11.22 #149。

## 二、8 维度设计前置

> 任务性质：**插件契约能力补洞**（`contributes.menus` 菜单项加 children 递归）——依赖 #148 渲染递归先行。方向已由用户拍板（任何入口可嵌套）。

### ① 能力边界
- **插件能力**（第三方作者声明嵌套子菜单）。保底：无嵌套声明 = 现状平铺，零变化。
- 与 #148 分工：#148 = 壳侧渲染/归一化递归（壳菜单 + 插件菜单都受益）；#149 = 插件声明式契约（schema 字段 + 文档三件套）。

### ② API 设计
- **零新增 `window.linkdesk.*`**。运行时 `registerItems` 的 `ManifestMenuItem` 已含 `children`（[linkdesk.d.ts:374](../../../../contracts/linkdesk.d.ts#L374)）——插件运行时嵌套已是现成能力（只是被 #148 渲染截断），本任务不碰。
- `plugin.schema.json` `contributes.menus` 菜单项加 `children?: MenuItem[]`（递归自引用）+ `label` + `order`——**对齐 `ManifestMenuItem` 全字段**，契约一致化：声明式与运行时同一菜单项形状，两种写法同一心智模型。

### ③ 通信方式
- **零新 IPC/通道**。声明式嵌套声明 → 加载器透传（[contributions.ts:80-82](../../../../src/pluginLoader/contributions.ts#L80-L82)，`as ManifestMenuItem[]`）→ `registerMenuItems` → MenuRegistry（`children` 现成）→ #148 归一化递归 → ContextMenu 递归渲染。全链现成 + #148。

### ④ 壳侧代码设计
- **壳代码零改动**（加载器纯透传）。改动 = `docs/03-插件制造/plugin.schema.json`（文档目录 schema 文件）+ `docs/03-插件制造` 文档三件套。
- **单一权威**：菜单项形状 = `ManifestMenuItem`（壳类型）→ schema 补齐到同形（两形状合一）；渲染深度 = #148 MenuRegistry/ContextMenu 递归。

### ⑤ 插件侧代码设计
- 贡献点：`contributes.menus` 菜单项 `children` 字段（递归）。父项 `command` 可为空（对标 ManifestMenuItem 注释「有 children 时 command 可为空」）。
- 文档：03-插件制造 更新——嵌套声明语法 + 父项 label 语义 + 示例。
- **插件独立铁律**：第三方作者零壳改动即可声明嵌套——本任务正是为此。

### ⑥ 显示设计
- **位置**：任何右键菜单 / 顶栏下拉 / 汉堡的任意层级子菜单（作者把右键系统放哪都能用）。
- **控件**：ContextMenu 嵌套子菜单（#148 递归后现成，零新控件）。
- **显示内容**：插件声明的 children 子树，逐级 hover 展开。

### ⑦ 配置设计
- **零新增配置项**。嵌套是菜单结构声明，非运行时配置。

### ⑧ 代码规范 + 验收
- 归一化：声明式与运行时同一 `ManifestMenuItem` 形状（schema 补齐 = 消灭两个形状）；嵌套深度无代码上限（递归）。
- 无死代码：schema 字段即被加载器消费，零残留。
- **验收**：
  1. `npm run check` 全绿（含 #145 机械门禁 + check-contributes 审计）。
  2. schema 校验：嵌套声明合法通过 + 非法（command 空且无 children）拒绝。
  3. **CDP 实机**（依赖 #148 先行）：插件 plugin.json 声明两级嵌套 → 右键逐级展开 + 点击执行；既有平铺菜单零回归。
