# 05 · 接口预留（对齐「万物皆可插件」）

> 本档不实现「换皮」；只保证换皮时不用返工。

---

## 一、槽位映射

| 本档的面 | 万物槽位 | 换皮后仍成立 |
|:--|:--|:--|
| 设置页整套 | `factoryRole:"settings"`（已存在） | 第三方 UI 读同一 schema、调同一宿主动作 |
| 选图控件 | 共享件 `BackgroundImagePicker`；未来 `renderers` 可接管外观 | 起始目录/入库/受控 URL 全在壳 |
| 打开目录按钮 | 壳命令 `appearance.openDirectory` | 插件只调命令 |
| 来源/生效徽标 | 共享件 `SourceBadge` / `EffectiveBadge` | 派生规则来自 schema 声明 |
| 分组标题/顺序 | schema 的 `group` / `order` / `dependsOn` | 第三方 UI 照声明渲染 |

---

## 二、给替换体的契约

```ts
// 宿主声明（读）
workbench.action.listConfigurations()  // 含 group/uiHint/assetDomain/pickTarget/enum
// 宿主动作（写/选）
appearance.pickImage({ domain:"background", target:"app"|"zone" })
appearance.openDirectory()
// 写配置
workbench.action.setConfiguration({ key, value })
```

- 替换体 **⛔ 不出现**：`appData` / `userData` / `%APPDATA%` / `defaultPathKind` / `join(...)`。
- 替换体 **✅ 可以**：按 `uiHint` 映射到自己的控件；按 `group` 排分节；按 `enumDescriptions` 显示人话。

---

## 三、不可替换的深层

| 深层 | 原因 |
|:--|:--|
| 资产域定义（`hostAssets/appearance/defaults.ts`） | 安全边界：从哪选、允许什么扩展名、拷到哪 |
| `importAsset` 的拷贝/去重/受控 URL | 防越权读盘 |
| `openDirectory` 的路径解析 | 主进程解析，插件不拼 |
| 配置 schema 的 `assetDomain/pickTarget` | 语义源 |

---

## 四、那个任务落地时的接入步骤

1. `factoryRole:"settings"` 已被替换件接管 ⇒ 本档的「最小 UI」契约测试**应零改动通过**（它就是替换件的预演）。
2. `renderers` 槽位上线后，`BackgroundImagePicker` 的**外观**可换；`onPick` 仍调宿主动作。
3. 新增门禁：替换件出现路径/域字符串 ⇒ 红（K1/K2 同源）。
4. 逃生舱：`app.openSettings`（已有）＋ `settings.resetToOfficial`（既有 factoryRole 逃生舱）。

---

## 五、验收（跨任务）

- 换第三方设置 UI 后：R1–R7 契约测试全过；`app.backgroundImage` 落盘值与官方一致。
- 卸载替换件 ⇒ 回官方设置插件；值不丢。
- 替换件崩溃 ⇒ 回退＋一条回执（万物 §四-7）。

---

## 六、给实施 AI 的三句话

1. 先做「最小 UI」夹具——它比任何 grep 都更能证明语义是否归位。
2. 任何「为了让第三方 UI 能用」而复制路径/默认值 ⇒ 直接否。
3. 你不需要改 `factoryRole` 机制；需要的是把**声明补全**（`assetDomain/pickTarget/group/order`）。
