### #113 Multi-root 工作区（~80 行）

```typescript
// 🔥 对标 VS Code Multi-root Workspaces
// WorkspaceService 已有 openFolder / addFolder / onDidChangeFolders（E2c #14）
// 文件树消费这些 API

// 工作区文件格式（对标 VS Code .code-workspace）
// .linkdesk-workspace.json:
{
  "folders": [
    { "path": "/home/user/project-a" },
    { "path": "/home/user/project-b", "name": "库代码" }
  ],
  "settings": {
    "files.exclude": { "node_modules": true }
  }
}

// FileTreeModel 适配多根：
class FileTreeModel {
  private _roots: ExplorerItem[] = []; // 现在是数组——每个 workspace folder 一个根

  async setRoots(folderPaths: string[]): Promise<void> {
    this._roots = [];
    for (const folderPath of folderPaths) {
      const entries = await FileService.listDir(folderPath);
      this._roots.push(this._toRootItem(folderPath, entries));
    }
  }

  /** 🔥 查找文件所在的根——对标 VS Code findClosestRoot() */
  findClosestRoot(uri: string): ExplorerItem | null {
    for (const root of this._roots) {
      if (uri.startsWith(root.uri)) return root;
    }
    return null;
  }
}
```

**多根 UI 表现：**
- 每个根文件夹在文件树中是顶级节点
- 显示文件夹名称（如果有 `name` 则显示自定义名，否则显示路径最后一段）
- 右键根节点 → 移除文件夹 / 添加文件夹
- 拖放移动文件跨根 → FileService.copy + FileService.deleteEntry

### #114 工作区状态持久化（~70 行）——🔥 F5 不丢状态

```typescript
// workspace-state.ts
// 🔥 对标 VS Code storageService 持久化——F5 刷新后恢复展开/选中/滚动
// 🔥🔥🔥 走 PluginStateService——不另辟蹊径直接写文件或 localStorage！
//
// 历史教训：
//   B66——PluginStateService 和 ConfigurationService 往同一个 settings.json 写，互相覆盖
//   B67——quickSends 绕过 ConfigurationService 走 PreferenceService，多套路径
//   B68——beforeunload 和 LayoutService 各写各的 v3_layout，两套序列化不同步
//   当前：终端 useTerminalSessions.ts 绕过 PluginStateService 直接写 localStorage
//         → 待修（已知遗留问题）
//
//   E4 不开辟新的持久化路径——用已有的 PluginStateService 统一入口。
//   PluginStateService → StorageService → localStorage（同步，F5 安全）+ 文件（异步，持久化）

interface ExplorerState {
  expandedFolders: string[];    // 展开的目录 URI 列表
  selectedFile?: string;        // 选中的文件 URI
  scrollPosition: number;       // 滚动条位置（像素）
  workspaceFolders: string[];   // 当前打开的文件夹列表
}

// 🔥 正确的持久化模式——对标终端 ControlPanel.tsx 的 setPluginStateValue("terminal", "lastPort", port)
// 文件树用同一个入口、同一个模式：

async function saveExplorerState(): Promise<void> {
  const state: ExplorerState = {
    expandedFolders: [...model.expanded],
    selectedFile: treeView.getSelected()?.uri,
    scrollPosition: treeView.getScrollPosition(),
    workspaceFolders: model.roots.map(r => r.uri),
  };
  // 🔥 走 PluginStateService——不写 pluginDataDir + '/explorer-state.json'
  // PluginStateService 内部调 StorageService.write → localStorage + 文件双写 → F5 安全
  await setPluginStateValue("filetree", "explorerState", state);
}

async function restoreExplorerState(): Promise<void> {
  const state = await getPluginState<ExplorerState>("filetree")?.explorerState;
  if (!state) return; // 首次启动，无状态
  // 恢复工作区文件夹
  if (state.workspaceFolders.length > 0) {
    await model.setRoots(state.workspaceFolders);
  }
  // 恢复展开（逐层展开，保持正确的父→子顺序）
  for (const uri of state.expandedFolders) {
    await model.expandTo(uri);
  }
  // 恢复选中
  if (state.selectedFile) {
    treeView.selectByUri(state.selectedFile);
  }
  // 恢复滚动位置（在下一帧执行，等待 DOM 渲染完成）
  requestAnimationFrame(() => treeView.scrollTo(state.scrollPosition));
}

// 保存时机（对标 VS Code）：
// - 展开/折叠目录 → debounce 1s → saveExplorerState()
// - 选中文件 → debounce 500ms → saveExplorerState()
// - 关闭窗口（beforeunload） → PluginStateService 内部 writeSync 保底
// - 切换工作区 → saveExplorerState() immediately
```

**🔥 为什么不用 `FileService.writeFile(pluginDataDir + '/...')`：**
1. `pluginDataDir` 在代码库中不存在——没必要为文件树创建新概念
2. `PluginStateService` 已提供 localStorage+文件双写 + beforeunload 保底——你再写一套就是多路径（B66/B67/B68 的种子）
3. 终端在 `ControlPanel.tsx` 已经正确示范了 `setPluginStateValue("terminal", "lastPort", port)`——文件树照做即可
4. 一条持久化路径 = 一个地方排查 bug = 归一化

**🔥 配置归属原则（对标 VS Code）：**

| 配置项 | 声明方 | 消费方 | 原因 |
|---|---|---|---|
| `explorer.*` | file-tree 插件 | file-tree | 文件树自己的行为配置 |
| `files.exclude` | file-tree 插件 | file-tree + search | 共享基础设施配置，文件树先声明 |
| `files.watcherExclude` | file-tree 插件 | file-tree | 文件监听由 file-tree 管理 |
| `files.encoding` | **editor 插件** | editor + search | 编码检测/解码逻辑在 editor/encoding 中 |
| `files.autoSave` | **editor 插件** | editor | 自动保存是编辑器行为 |
| `files.autoSaveDelay` | **editor 插件** | editor | 同上 |

**🔥 `files.encoding`、`files.autoSave`、`files.autoSaveDelay` 移到 E4f editor 插件的 `contributes.configuration` 中。** 所有权跟随逻辑：编码逻辑在 editor 插件里 → 编码配置也由 editor 声明。文件树和搜索通过 `ConfigurationService.get("files.encoding")` 读取——不关心谁声明的。
