### 2.6 🔴 三类全局概念名的登记材料（**本格主要产出 → 交 [1.49](19-任务-门禁与作者面收口.md)**）

> 判据③④要求的形态：**三类各一条：是什么 / 为什么没有"主" / 证据出处（`file:line`）**。

**① 文件关联扩展名**

- **是什么**：`contributes.fileAssociations[].extension` 声明的扩展名（如 `.ts` / `.md`）。
- **为什么没有"主"**：🔴 **`.ts` 不可能是"editor 的 ts"**——扩展名指**文件格式**，是**操作系统与人类共识层**的全局概念，不是任何插件的私有物。加前缀（`editor.ts`）**不是改名，是改语义**（把"这是 TypeScript 文件"说成"这是 editor 的文件"）。**设计上它本就是加性扩展点**：`FileAssociationService.ts:36-40` 注释明写「**同一扩展名允许多个插件注册——"打开方式…"选择器消费全部**」⇒ 多方共用（**覆盖型花名册才需要"定主"**）。
- **实测佐证**：`editor` 声明 **45** 个扩展名（[13 §1.1](13-任务-清账-editor.md)，⚠️ 该档 2026-09-17 由 41 翻正为 45，见其 §1.2）⇒ 改名**改完更错**。
- **证据出处**：`src/core/services/files/FileAssociationService.ts:36-40`（加性设计原文）；`E:/linkdesk-plugins/official/editor/plugin.json` 的 `contributes.fileAssociations`（实测 45 条，去重后仍 45）。

**② 语言定义扩展名**

- **是什么**：`contributes.langDefs[].extensions` 声明的扩展名（`python` 的 `.py` / `.pyi`）。
- **为什么没有"主"**：**与第 ① 类同一性质**——它也是**文件格式**的标识，不是插件身份。🔴 判据④ 的机械检查点就在这里：**两格（1.43 / 1.48）必须给同一结论**，本格与 [1.43 §1.1](13-任务-清账-editor.md) **同结论：不改**。
- **证据出处**：`E:/linkdesk-plugins/official/python/plugin.json:13-21`（`langDefs[].id = "python"` / `extensions = [".py", ".pyi"]`）；一致性对账见 [13 §1.1](13-任务-清账-editor.md)。

**③ 语言包语言码**

- **是什么**：`contributes.languages[].id`（`lang-defaults` 的 `zh` / `en`；`lang-test-ja` 的 `ja`）。
- **为什么没有"主"**：语言码是**国际标准标识符**（BCP-47 风格区域/语言标签）⇒ 它是**标准层**的名字，不是命名空间。加前缀（`lang-defaults.zh`）会**破坏与外部工具的互操作**（它被拿来当"用户当前语言"的查找键）。
- **证据出处**：`E:/linkdesk-plugins/official/lang-defaults/plugin.json` 与 `.../lang-test-ja/plugin.json` 的 `contributes.languages`（实测 `["zh","en"]` / `["ja"]`）。

> 🔴 **三条共同的机械理由（写给作者面的一句话）**：这三类的名字**指的都是"世界上的那个东西"（文件格式 / 语言），不是"谁的插件"** ⇒ 命名空间归一化的射程**到"插件自造的名字"为止**，**不越过"指称外部世界的名字"**。

### 2.7 ⚠️ 一处**真缺陷**的登记：探针漏计 `iconThemes[].id`（判据⑤的交付）

§1.3 记的是**现象**（`theme-iconset-pastel` 被写成 0 处）。**2026-09-17 复量把机制钉死了**——这不是"抄错了数"，是**探针的一个 `total` 漏项**：

- `scripts/audit-plugin-scope.mjs:129` 的 `total` 求和式是
  `cmdBad + runtime + cfgBad + flagsBad + themeBad + recBad + hostHits(无证照)`。
- 其中 `hostHits`（`:120`）**确实含 `iconThemeIds`**，但它后面挂着 `.filter(x => HOST_APPEARANCE.has(x))`——`HOST_APPEARANCE` 取自 `appearanceIdGrants`，**今天只有 `light` 一个键**（实测 `Object.keys(HOST.appearanceIdGrants) === ["light"]`）。
- ⇒ `ld-iconset-pastel` **不在证照表里** ⇒ **既不进 `themeBad`**（那一项只扫 `themeIds`，`:118`）**也不进 `hostHits`** ⇒ **落进 `total` 的补集：它不属于求和式的任何一项**。
- 🔴 **实测复核**：全官方仓只有这一个 `iconThemes[].id`；按上面口径逐条复算，**它被判"不算需改"**。
- ⇒ **本格处置（按禁区）**：**只登记、不修脚本**——清账轮的射程是**名字**，不是**探针**；顺手改 `total` 会让 [1.47](17-任务-清账-主题族.md) 的读数中途变动、并可能与 [00 §〇c.4](00-整理档案.md) 的表打架。
- ⇒ **交 [1.49](19-任务-门禁与作者面收口.md)**：这是**收紧为红那一格的输入**——`total` 若仍是"根治"的机械定义，**`iconThemes[].id` 这条腿必须先补上**（否则 1.47 改完，探针**照样报 0**）。
- ⚠️ **诚实边界**：本格**没有**验证"补上这条腿之后 1.47 是否真能归零"——那是 1.47/1.49 的事；本格只**证明腿缺了**。
