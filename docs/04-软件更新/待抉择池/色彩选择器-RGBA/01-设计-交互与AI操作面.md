## 二、组件契约（共享层，不改壳核心）

### 2.1 ColorPicker

| prop | 类型 | 语义 |
|:--|:--|:--|
| `open` / `onClose` | boolean / () => void | 开合（调用方持有，锚点由调用方算） |
| `value` | string | 当前颜色（hex / rgb(a) / hsl(a) 均可） |
| `onChange` | (value: string) => void | 每次确认/输入即回调（**格式化后的值**） |
| `allowAlpha` | boolean（默认 false） | **能力档**：true 才显示 alpha 滑杆、才输出 rgba；false 强制 a=1、输出 hex |
| `presets` | string[] | 预设色（可含 alpha） |
| `anchor` | {x,y} \| null | 浮层锚点（视口内翻转/clamp 沿用现值） |

### 2.2 输出格式（唯一口径）

- `allowAlpha=false` 或 `a=1` ⇒ **hex**（`#RRGGBB`）——旧调用/旧值零变化；
- `a<1` ⇒ **rgba**（`rgba(r,g,b,a)`，alpha 保留 2 位）；
- 输入接受 `#RGB` / `#RRGGBB` / `#RRGGBBAA` / `rgb()` / `rgba()` / `hsl()` / `hsla()`；
- 解析失败 ⇒ 输入框红框 + 错误文案，**不改值**。

### 2.3 逐键能力声明（插件作者怎么用）

配置键（壳或插件）声明 `renderHint:"color"` 时加 `allowAlpha: true` 即开放 alpha；不写 = false。

```jsonc
// 例：玻璃叠加色允许 alpha（配色键）；强调色不写 ⇒ 默认不透明
{ "key": "app.glassTint", "renderHint": "color", "allowAlpha": true }
```

- **同一个组件**，不是两套调色器；作者不需要 alpha 时零改动（默认 false）。
- `allowAlpha` 只影响 UI 能力与输出格式；值本身仍是字符串（rgba/hex），落盘出口不变。

## 三、GUI 动作 ↔ 命令（死规定）

> 硬约束 26：**每个用户动作至少一条非鼠标路径**。调色器每个交互都落一条结构化命令；命令名是设计提案，实现时注册。**唯一持久化出口**仍是 `configuration.set`。

| GUI 动作 | 命令 | 载荷 |
|:--|:--|:--|
| 打开 / 读当前值 | `appearance.colorPicker.open` | `{ key, allowAlpha }` → `{ value, format }` |
| 拖动 SV 面板 | `appearance.colorPicker.setHsv` | `{ key, h, s, v }` |
| 拖色相 | `appearance.colorPicker.setHue` | `{ key, h }` |
| 拖 alpha | `appearance.colorPicker.setAlpha` | `{ key, a }` |
| 输入框改值 | `appearance.colorPicker.setValue` | `{ key, value }`（接受全部输入格式） |
| 点预设 | `appearance.colorPicker.applyPreset` | `{ key, index, value }` |
| 应用 / 取消 / 复位 | `appearance.colorPicker.apply` / `.cancel` / `.reset` | `{ key }` |
| 能力档切换（作者声明） | `appearance.colorPicker.setCapability` | `{ key, allowAlpha }`（仅演示/调试，正常由声明决定） |
| 真正落盘 | `configuration.set` | `{ key, value }` |

验收：设计稿里每次交互都在「AI 命令日志」留一行；实现时同款命令必须能在软件里直接调用（不靠鼠标）。

## 四、交互与视觉

- SV 二维面板 + 色相条 + alpha 条 + 棋盘格；预览块实时显示最终值；
- 输入框支持 hex/rgba/hsl；非法值不写；
- 预设可带 alpha（玻璃主题的 tint 预设）；
- 面板 232→300 自适应，右/下放不下翻左/上，恒在视口内；
- 键盘：Tab 顺序 SV → 色相 → alpha → 输入 → 预设 → 取消/应用；Esc 取消、Enter 应用；滑杆 `aria-valuetext`；
- `prefers-reduced-motion` 下过渡归零；焦点环可见。

## 五、边界情况

| 情况 | 行为 |
|:--|:--|
| `a=0` / `a=1` | 正常；1 输出 hex，0 输出 `rgba(...,0)` |
| `#RRGGBBAA` | 解析为 a=AA/255；输出按 §2.2 |
| `rgb()` 空格语法 / `hsl(… / a)` | 接受 |
| alpha 越界（1.2 / -1） | 钳到 0..1，提示 |
| `var(--x)` / `color-mix()` | **只读展示**：不能解析成色值，禁用编辑，不改用户变量 |
| 非法输入 | 红框 + 文案；值不变 |
| 面板超出视口 | 翻转 + clamp（沿用现有 `resolvePanelPosition`） |
| 键盘/读屏 | focus trap 不做（非模态）；Esc/Enter 可达；滑杆有可读值 |
| 旧值 | hex 打开/保存后零变化 |

> Q4 的 `var()` 说明：`var(--glass-tint)` 是 CSS 变量引用，浏览器在运行时才解析；调色器拿不到它的色值。所以遇到这类值只读展示（不猜、不改）。

## 六、工程结构（归一化 / 无硬编码 / 无死代码 / 高内聚低耦合 / 不平铺）

```
@linkdesk/ui
├── color/                  # 唯一解析/格式化：parseColor / formatColor / hsv↔rgb
├── color-picker/           # SV + 色相 + alpha + 输入 + 预设（只认 value/onChange/allowAlpha）
└── color-field/            # 色块（棋盘格）+ 文本；不弹层、不认识配置键
设置插件（或任何消费方）      # 注入 allowAlpha / 锚点 / 开合；⛔ 不重画调色器
```

- **单一实现**：解析/格式化只有一份（`@linkdesk/ui/color`），调色器、色块、校验共用（R4 无第二份实现）。
- **无硬编码**：颜色全走 `var(--…)`；尺寸/圆角走 token；无新 token。
- **无死代码**：`allowAlpha` 默认 false——旧调用零变化，不引死分支；不写未用的“未来字段”。
- **高内聚低耦合**：调色器不 import 壳 core、不认识配置键；设置插件只注入能力。
- **不平铺**：`color-picker/` 与 `color-field/` 各自成夹，子件不摊根目录。
- **AI 友好**：命令面见 §三；作者文档同步（`17-AI`/`21-命令化` 口径）。

## 七、验收（实现时）

1. 玻璃叠加色在设置里可调 alpha 并即时看到玻璃变化；

3. 旧 hex 配置打开/保存零变化；
4. 每个 GUI 动作都有可调用命令（§三），命令可脚本化验收；
5. 单测（解析/格式化/边界/键盘）＋ 作者文档 ＋ `@linkdesk/ui` 发版。
