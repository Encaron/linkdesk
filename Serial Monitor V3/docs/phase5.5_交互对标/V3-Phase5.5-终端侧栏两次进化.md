## 三、第二次进化——6 文件树就位后，会话持久化

### 会话 = 文件

每个终端会话存为一个 `.session.json` 文件：

```json
// .linkdesk/sessions/COM3-PID调试.session.json
{
  "name": "COM3 PID调试",
  "port": "COM3",
  "baudRate": 115200,
  "protocol": "protocol-bracket",
  "lastOpened": "2026-07-21T14:32:00",
  "tabId": "terminal-3"
}
```

### 侧栏——会话列表

```
┌──────────────────────┐

│   📟 COM5 CAN监控   [✕] │  ← 右键 → 重命名/删除/复制会话
│   📟 COM7 空闲      [✕] │
│                      │
├──────────────────────┤
│                      │
│ ▶ 控制面板            │  ← 可折叠（以下和第一次进化相同）
│ ▶ 设置               │
│                      │
└──────────────────────┘
```

### 文件树视角

```
📁 文件树
├── 📂 stm32-project
│   ├── src/

│   │   ├── settings.json
│   │   ├── sessions/
│   │   │   ├── COM3-PID调试.session.json    ← 双击 → 打开终端并连接 COM3
│   │   │   ├── COM5-CAN监控.session.json
│   │   │   └── COM7-空闲.session.json
│   │   └── workspace.json
│   └── CMakeLists.txt
```

### 交互流程

```
侧栏点 [+ 新建会话]
  → 弹出 QuickPick: "选择 COM 口" → COM5
  → 弹出 QuickPick: "选择协议" → protocol-json
  → 输入会话名: "COM5 JSON调试"
  → 创建 COM5-JSON调试.session.json
  → 侧栏会话列表出现新条目
  → 主区开新终端标签页 → 自动连接 COM5

侧栏点 [✕] 删除会话
  → 确认: "删除会话 'COM7 空闲'？"
  → 关闭对应标签页（如果打开）
  → 删除 .session.json 文件
  → 侧栏会话列表移除

文件树双击 COM3-PID调试.session.json
  → 侧栏自动切换到 📟
  → 主区开终端标签页
  → 自动连接 COM3 + 选择 protocol-bracket
  → 恢复上次关闭时的连接状态
```

### 会话迁移/分享

```
导出会话 → 选中 .session.json → 打包为 .zip
导入会话 → 拖入 → 侧栏会话列表出现 → 点击连接
跨 workspace 复制 → 文件树拖拽 session 文件到另一个 workspace
```

## 六、通用设计模式——侧栏 = 管理面板

> 2026-07-21。在讨论终端侧栏改名方案时发现：这个名字不应该通过标签栏 F2/双击/右键来改——应该**在侧栏里改**。侧栏是插件管理自己资源的操作面板。终端会话、卡片、文件、数据库表——任何插件有"可管理的条目列表"时，侧栏就是它的管理面板。

### 模式定义

```
标签栏 = 导航（快速切换当前在看什么）
侧栏   = 管理（增删改查插件自己的资源）
主区   = 内容（渲染/交互/编辑）
```

**改名不走标签栏——走侧栏。** 对标 VS Code：你不会在编辑器标签页上 F2 改文件名——你在 Explorer 侧栏里改。标签页标题只是"当前在看什么"的标签，不是管理入口。

### 终端已示范的模式

```

┌──────────────────┐  ┌─────────────────────┐  ┌──────────┐
│ ▼ 终端会话 (3)     │  │ [📟 COM3 PID] [📟 COM5]│  │ CM6 接收  │
│   📟 COM3 PID [✎] │  │                     │  │           │
│   📟 COM5 CAN  [✕] │  │  ↑ 标签标题自动跟     │  │           │
│   [+ 新建]        │  │  侧栏会话名同步       │  │           │
│ ▶ 控制面板        │  └─────────────────────┘  └──────────┘
│ ▶ 设置           │
└──────────────────┘
```

### 模式总结

| 插件 | 侧栏管理什么 | 操作 |
|------|-----------|------|
| 终端 | 会话列表 | 新建/改名/删除/切换 |
| 卡片工作台 | 卡片列表 | 添加/改名/删除/排序 |
| 文件树 | 文件/文件夹 | 新建/重命名/删除/移动 |
| 数据库浏览器 | 表列表/查询历史 | 打开/重命名/删除/收藏 |
| Git | 更改列表/分支 | stage/unstage/commit/switch |
| 任何"有列表"的插件 | 列表 | CRUD |

**这不是终端专属模式——这是 LinkDesk 的通用交互范式。** `<SidebarSection>` 是渲染组件，`CRUD` 操作是每个插件自己的逻辑，但**改名在侧栏不在标签栏**是统一的交互规则。

### 为什么好

1. **一致性——** 不管什么插件，用户知道"改名字去侧栏"
2. **标签栏纯粹——** 标签栏只管导航（切换/关闭/拖拽），不管管理（改名/删除）
3. **对标 VS Code——** Explorer 改名 / Extensions 管理 / Git 操作——全在侧栏
4. **AI 友好——** 新 AI 写插件时，文档一句话："有列表要管理？放侧栏，用 `<SidebarSection>`，改名走侧栏不走标签栏"

## 七、不做的东西

| 不做 | 理由 |
|------|------|
| 会话自动保存连接状态（实时同步） | 关闭标签页时保存即可——对标浏览器 session restore |
| 会话模板（"新建会话时从模板复制设置"） | Phase 7+——卡片工作台做的时候一起看 |
| 远程会话（SSH/串口服务器） | Phase 8+ |
