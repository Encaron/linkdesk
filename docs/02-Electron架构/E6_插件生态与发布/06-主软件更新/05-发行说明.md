## 一、VS Code 对标证据

- **自动弹**：`pkg.version !== lastVersion`（首次启动新版本）→ 自动打开内置「更新说明」tab。
- **数据源**：`https://code.visualstudio.com/raw/v{version}.md` 按版本拉取（独立静态文件，按版本 URL 直取）。
- **缓存**：本地按版本缓存（userData 下），同一版本不重复拉。
- **可关**：设置 `Update: Show Release Notes`（首启自动弹的开/关）。
- **失败降级**：拉取失败（离线/404）→ 通知条提示，不打扰、不阻塞启动。

## 二、LinkDesk 设计——发行说明 = 壳内标签页

### 2.1 载体决策（标签页 vs 浏览器）

| 维度 | 壳内标签页（推荐 ✅） | 浏览器新开 |
|:--|:--|:--|
| 体感 | 对标 VS Code 内置 tab，不离开软件 | 跳出软件，断裂 |
| 主题 | 跟随 LinkDesk 主题（玻璃态/深色） | 浏览器样式，不跟随 |
| 可交互 | 可后续接「从发行说明一键安装」等 | 纯静态 |
| 离线 | 缓存在本地，离线可看历史版本说明 | 无网打不开 |
| 实现 | 复刻欢迎页模式（壳直渲染 view） | 壳 api openExternal |
| 标签页哲学 | 「标签页 = 通用表面容器」——发行说明只是又一张表面 | 不占用 |

**结论：壳内标签页。** 符合「标签页 = 通用表面容器」记忆（任何新表达形式 = 加一个标签页）+ 对标 VS Code 内置 tab。

### 2.2 打开方式

| 入口 | 行为 |
|:--|:--|
| 帮助菜单「显示发行说明」 | 打开发行说明标签页（最新版本） |
| 更新 toast「查看更新内容 →」 | 打开发行说明标签页（新版本）+ 滚动到该版 |
| **首次启动新版本** | **自动打开**（对标 VS Code，见 §2.4） |
| 更新 toast「重启并更新」 | 重启安装（不进发行说明） |
| TitleBar 更新按钮 | 按状态分支（见 03 §4） |

### 2.3 标签页实现（复刻欢迎页模式）

- 载体：**壳直渲染 view**，`appearsIn.tabBar: true` + `tabBehavior.singleton: true`（对标 `WelcomePoolView.tsx` 的 `tabBehavior.isFallback` 模式，但**发行说明不是 fallback**——是普通单例标签页）。
- 组件：`src/pool/views/release-notes/ReleaseNotesView.tsx`（壳组件，非插件——对标欢迎页 `src/pool/views/welcome/` 先例，按「UI 功能域 = 文件夹」建夹；不是 `src/components/`）。
- 样式：`var(--*)` 主题 token + 壳组件（硬约束 16，落地走设计 skill）。
- **布局（2026-08-30 定稿）**：发行说明 = **主区标签页**（对齐插件详情页 [01 竞标 A](../03-插件市场/mockups/01-插件详情页-竞标.html) 骨架：头部集成 + 主体）。主体 = **左窄栏版本历史 220px（配角导航）+ 右主区更新内容（主角）**——**版本历史不是主角，不占一半**（用户 2026-08-30 指示「一个区区的版本历史占了标签页的一半？它是主角吗？」，按 skill 设计后定：Developer Tool 文档专注，VS Code 基准窄列表）。**内容不占声明式侧栏**——LinkDesk 侧栏 = 声明制专属面板、与标签栏不同时开，为发行说明搞侧栏容器（title/toolbarslot…）很麻烦（用户 2026-08-30 指示「把信息集成进一个主区标签页，不放单独侧栏」）。mockup 03 外层画出**完整软件框架**（图标栏 / 应用侧栏 / 状态栏）示意——那是软件本身的框架，发行说明只是主区其中一个 tab。
- 内容结构：

```
发行说明标签页（主区 tab，对齐插件详情页 01 A 骨架）
├─ 头部版本区：v0.2.0 + 发布日期 + 通道（stable）+「在 GitHub 查看全部」
├─ 主体：左窄栏 220px（配角导航）+ 右主区（主角）
│  ├─ 左：版本历史（git 历史列表，倒序）——选中即渲染该版 body
│  └─ 右：更新内容（Release body Markdown 渲染 + 首启自动弹横幅）
│     每版一个 Release body（GitHub 拉取/缓存）
└─ 尾部：「所有版本 → GitHub Releases」链接（浏览器打开全历史）
```

### 2.4 数据源与缓存

- **数据源 = GitHub Releases API**（与更新检查同源，不造第二套存储）：
  ```
  https://api.github.com/repos/encaron/linkdesk/releases?per_page=30
  ```
  （分页最多 30 条历史；每条含 `tag_name` / `published_at` / `body` / `html_url`）
- **缓存**：`{userData}/updates/releases-cache.json`，键 = `updatedAt`/版本列表 hash，24h 过期刷新（对标插件目录缓存惯例）。
- **渲染**：Release body 是 GitHub Flavored Markdown → **消费壳共享 MarkdownView 组件**（react-markdown + remark-gfm + DOMPurify sanitize，E6#54 分发 @linkdesk/ui；2026-08-30 拍板「md 渲染唯一组件」）。与插件详情页 README 同一渲染器（见 [03-插件市场/04-详情页设计.md §4.1](../03-插件市场/04-详情页设计.md)），跟随主题，网络内容统一过 sanitize。
- **失败降级**：拉取失败 → 缓存兜底；无缓存 → 空态「无法加载发行说明」+ 重试按钮 + 「在 GitHub 上查看」链接。

### 2.5 首启自动弹（对标 VS Code）

- 判断：`app.getVersion() !== lastSeenVersion`（存 `lastSeenVersion` 到壳存储，随启动写入当前版本）。
- 首次启动新版本 → 自动打开发行说明标签页（只开一次；此后该版本不再弹）。
- 可关：设置 `app.update.showReleaseNotes`（boolean，默认 true）——关了首启不弹，但「显示发行说明」菜单始终可用。
- 失败（离线）→ 不打扰，下次启动再试。

### 2.6 历史版本表示（用户第一问落地）

发行说明标签页 = **当前软件内看历史版本的地方**：

- 版本选择器 = GitHub Releases 列表（倒序），选中即显示该版 body。
- 「所有版本 → GitHub Releases」= 浏览器看完整历史（含 0.x 时代全量）。
- 与 [02-产品身份与版本.md](02-产品身份与版本.md) §2.4 呼应：**历史版本 = GitHub Releases 列表**，软件内提供前 30 条精选，浏览器提供全量。
