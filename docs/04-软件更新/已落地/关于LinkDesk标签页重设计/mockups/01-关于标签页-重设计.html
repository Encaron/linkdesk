根因与修法（01-设计 §2.2）：「整页拖不选」不是关于页的样式问题——是壳的全局规则 src/index.css:207（html, body, #root, #pool-root { user-select: none }，桌面软件观感）。本页照 E6#72b 通知面先例在内容层开回：user-select: text; cursor: text，而 button / a 保持 user-select: none——点按不误选、正文可摘取。⚠️ 不动那条全局规则（动它会波及整个软件，那是另一件事）。
与「复制」按钮的分工（两条路，不是替代）：划选 = 只摘一段（上面选中的版本号、一个邮箱、或一个 GitHub 账号）；「复制」= 一次性把全字段带走，贴进 issue 用。图中蓝色高亮是 ::selection 的静态模拟（真实高亮由浏览器画，本图零动效）。
邮箱为什么仍是可点的 mailto:（一条自我订正）：曾想把邮箱改成纯文本以求「少一个爬虫抓手」——这个理由站不住：主流爬虫同时扫 mailto: 与正文里的 @… 模式，纯文本只是少一类只认 href 的爬虫，却把「点一下就写信」降级成「先划选再 Ctrl+C」。⇒ 保留可点，且它与划选不冲突：想复制地址的人照样能划选。
