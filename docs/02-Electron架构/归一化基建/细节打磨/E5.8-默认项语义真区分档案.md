# E5.8-默认项语义真区分档案（#158）

> 2026-08-28。**用户实机：点「跟随主题」后「重置此设置/默认项」消失。** 用户阐明两选项语义本应不同——「跟随主题」= 跟随 app.theme 活动主题值；「默认项」= 通用保底（如用户没装任何主题，软件总要显示 GUI，那个 GUI 就是默认值）。用户拍板：**默认项 = 内置 dark/light 配方值**。
> 清单指针：E5.8-执行清单 Phase 11.22 #158。

---

## 一、背景与用户实机证据

用户在设置页齿轮菜单实测：打开外观键齿轮 → 见「重置此设置/默认项」→ 点击「跟随主题」后 → **再开齿轮「重置此设置/默认项」消失**。用户困惑「为什么我点了跟随主题，回到默认项那个选项不见了？」——根因 = 两语义被同一条路径抹平。

## 二、根因（file:line）——同调 resetConfigurationValue + when 依 userValue 存在性

| 位置 | 现状 |
|---|---|
| [coreCommands.ts resetSetting](../../../../src/core/commands/shell/coreCommands.ts) | 旧 handler = 一律 `resetConfigurationValue`（删 user scope → 主题胜出）；when = `settingModified`（userValue 存在性） |
| [coreCommands.ts followTheme](../../../../src/core/commands/shell/coreCommands.ts) | 与 resetSetting **同调** `resetConfigurationValue`——「默认项」无独立落点 |
| [SettingRow.tsx handleGearClick](../../../../plugins/builtin/settings/src/views/SettingsView/SettingRow.tsx) | 齿轮打开时设 `settingModified` = `inspectConfiguration().userValue !== undefined` |

**合成效应**：用户点「跟随主题」（删 user scope）→ `userValue=undefined` → `settingModified=false` → 「重置此设置/默认项」消失。且即便不消失，「默认项」与「跟随主题」行为相同（都删 user scope 回主题），两语义实际被抹平。

## 三、决策——用户拍板（三轮 AskUserQuestion）

1. **「默认项」落点** = 内置 dark/light 配方值（`:root` 硬兜底——无任何主题时 GUI 也显示的兜底）。
2. **可见性** = 跟随主题后也恒显。
3. **范围** = 先四键真区分（`fontFamily` / `fontFamilyMono` / `backgroundImage` / `zoneBackgroundImage`），玻璃/圆角**如实**（只显跟随主题，不显重置此设置——它们唯一能回的状态就是跟随主题，无独立默认项）。

**架构澄清**（用户问「这些判别逻辑都是壳方面的吗？总不能放在设置插件/主题插件下」）——三层全在壳侧：① 声明层 = 壳 schema（`ConfigurationProperty.resetsToDefault`）② 渲染层 = settings 插件镜像 context key（零主题知识，读到声明即显）③ 执行层 = 壳命令（resetSetting 分流）。第三方插件声明字段即得同能力，零壳改动。

## 四、实现（已交付）——核心洞察 = 零新机制

**关键洞察**：内置兜底配方是**空配方**（`colors: {}`，registry.ts:117-127），`:root` 硬兜底 font-ui = `SYSTEM_FONT_STACK`（constants.ts:155）= **`CONFIG_NONE_SENTINEL`（`__none__`）哨兵的值**。→ 「默认项」对四键 = **写 `__none__` 哨兵**，`getAppearanceOverrides` 已消费（字体→系统栈 / 背景→无图）、UI 已有写入口（renderControl「无背景」按钮）。零新机制。

**三态模型**：跟随主题（删 user scope → 主题胜出）/ 默认项（写 `__none__` 哨兵 → 系统栈/无图）/ 显式覆盖（自定义值）。

| 位置 | 改法 |
|---|---|
| [ConfigurationRegistry.ts:83](../../../../src/core/registry/ConfigurationRegistry.ts#L83) | `ConfigurationProperty` 加 `resetsToDefault?: boolean`（注释记 #158 语义 + 零新机制洞察） |
| [appearance.ts](../../../../src/App/config/appearance.ts) | 四键（fontFamily/fontFamilyMono/backgroundImage/zoneBackgroundImage）声明 `resetsToDefault: true` |
| [coreCommands.ts:228](../../../../src/core/commands/shell/coreCommands.ts#L228) | resetSetting handler 分流：`prop?.resetsToDefault` → 写 `CONFIG_NONE_SENTINEL`；否则 `resetConfigurationValue`；when 改 `settingResetsToDefault || (settingModified && !settingFollowTheme)` |
| [SettingRow.tsx:119](../../../../plugins/builtin/settings/src/views/SettingsView/SettingRow.tsx#L119) | handleGearClick 设 `settingResetsToDefault` = `!!prop?.resetsToDefault`；handleGearClose 清零 |
| [gearMenuWhen.test.ts](../../../../src/core/commands/shell/gearMenuWhen.test.ts) | `RESET_WHEN` 常量 + 四态测试：四键恒显（含未修改/已跟随）/ 普通键改后显 / 玻璃圆角已跟随不显 / 普通键未修改不显 |
