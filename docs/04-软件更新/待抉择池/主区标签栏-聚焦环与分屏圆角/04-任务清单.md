🔴 **另一条更硬的理由——缝的可见性靠它**：分屏两栏之间那条 4px 缝露出的是**主区板漆** `--bg-window`（[index.css:419-421](../../../../src/index.css)）；若 pane 面色**也**取 `--bg-window`，则**面与缝同色 ⇒ 缝几乎看不见**，D3-甲 就白做了（成面只有两个可见收益：圆角＋阴影边、缝显形）。⇒ `--bg-card` 同时满足两件事：一个 token 管一个角色（主题轴）＋ 与缝底有色差（功能）。

### 6.3 未来迁移点（写给将来翻主题的那个人）

1. **环占了 pane 的 `::after`**。未来若把**玻璃**（惯用 `::before`）／**切片**（惯用 `::after`）也扩到 pane，`::after` 会撞车 ⇒ 届时的动作 ＝ **把 D2-甲 升为 D2-乙**（环改专用元素），成本 = 撤 1 处 CSS ＋ 加 1 个元素；⛔ 届时**不要**去改 pane 的 `::before`——那是玻璃的位置。

3. **机械读数（本节的完成判据）**：`git diff src/index.css | grep '^+' | grep -o 'var(--[a-z0-9-]*'` 的**去重集合必须 ⊆** 上面那 6 个 key（新增行里允许 **0** 个 `--glass-*`）⇒ 超标即「偷偷开了新概念」。

### 6.4 唯一与「零增长」相悖的一件事（记在案，不改）

`ldk-group-pane` / `ldk-group-pane-split` 是**新公开类名**（本案已登记提案，[拟真度门 I3](mockups/校验-拟真度.cjs) 的正控）⇒ 它们会进 `scripts/gen-host-css-manifest.mjs` 生成的**宿主 CSS 面**（`npm run check` 的 `host-css:check` 腿守同步）⇒ 随 `host-css-names.json` 进 `plugin-sdk` 包。**这一笔躲不掉**（要成面就得有个可挂的钩），代价 ＝ 一次 manifest 重生成 ＋ 下一次 npm 发布带上它。⛔ **不要**为省这一步去写结构选择器（`:first-child`／`nth-child`）——那是把「谁是 pane」的判据藏进 DOM 顺序，未来主题系统更难认。
