# S7 · 命令风险声明与兜底（AI 档位的输入真相）

> 归属：[00-提案](00-提案.md) 主线 S7（2026-11-25 新增）。来源：I-1 内部审计。
> **一句话**：`risk` 是 AI 权限档位**唯一的判定输入**（硬约束 29 的 `decide(mode, risk)`）；现在这个输入大面积缺失，导致「默认档＝全放行」。本档把它补成**有真相源、有保守兜底、有门禁**的一条轴。

---

## 一、问题：`risk` 是空的，所以档位形同虚设

### 1.1 事实链

| 环节 | 现状 | 证据 |
|:--|:--|:--|
| 声明 | `contributes.commands[].risk` 字段存在，但**作者普遍不填**；`serial-monitor` 28 条命令**一条都没有** | `serial-monitor/plugin.json` |
| 判定 | `riskOfCommand` 三层：壳内建表 → manifest `risk` → 兜底 `R1` | `policy/risk.ts:130,141-143` |
| 档位 | `auto` 档下 `R1`/`R2` = **allow**，`R3` = **ask** | `policy/decide.ts:24-29` |
| 结果 | 默认 `auto` 下 `send`/`query`（R2）无需确认；`reset`/`reopen`/`toggleAutoRepeat`/`closePort`/`closeSession`（R3）会问 | 2026-11-25 用户裁定 #19 |

### 1.2 为什么另外三份档都管不到它

| 档 | 它管什么 | 为什么不管这条 |
|:--|:--|:--|
| 硬约束 29（AI 权限档位） | **判定**：`decide(mode, risk)` | 只管「拿到 risk 之后怎么判」，不管 risk 从哪来、缺了怎么办 |
| [插件权限系统](../插件权限系统/00-提案.md) | **插件能力轴**：`serial.open` 等，装的时候人授权 | 插件一旦获权，AI 调该插件的命令就绕过了能力授权那层 |
| [通用能力底盘 §轴四](../通用能力底盘/00-提案.md) | **能力声明**：`capabilities: string[]` + 运行期对账 | 粒度为「插件有没有这个能力」，不区分 `listPorts` 与 `reset` |

⇒ 这是**第四条轴**：命令级风险。缺了它，「AI 自己索取最高权限后直接放开干」这件事的安全边界不存在——因为**默认档已经放开干了**。

## 二、设计

### 2.1 真相源：插件命令只认声明

> 🔴 待拍 #7：**壳内建表不得覆盖插件命令**。

| 命令归属 | risk 来源 | 说明 |
|:--|:--|:--|
| 壳命令（`core.*` / `workbench.*` / `aiPolicy.*` …） | 壳内建表（唯一） | 壳自己的语义，壳自己知道 |
| 插件命令（含官方各仓） | `manifest.contributes.commands[].risk`（唯一） | 语义归插件（判据 A 的精神：壳不认识业务） |
| 冲突（壳表里恰好有同名插件命令） | **以声明为准** ＋ 记诊断 | 现状是壳表优先，违反声明式；本条要改 |

理由：壳内建表写死插件命令的风险值 = **硬编码插件语义**（硬约束 10 的同族）。第二语言、第二作者写的命令名一旦不匹配，表就失效。

### 2.2 兜底：未声明 ⇒ R2，⛔ 不得 R1

> 待拍 #6。

| 情形 | 兜底 |
|:--|:--|
| 声明了 `risk` | 用声明值（`R0`–`R3`） |
| 未声明、且属插件命令 | **`R2`（auto 允许 / ask 档问；真正兜底靠 loader 拒绝）** |
| 未声明、且属壳命令 | 壳表；壳表也没有 ⇒ `R2` |
| 声明值非法（非 `R0`–`R3`） | `R2` ＋ 加载诊断（⛔ 静默忽略） |

**为什么是 R2 不是 R1**：R1 连 `ask` 档也放行；R2 至少在 `ask` 档会问，且语义上「有副作用」。⚠️ 默认 `auto` 下 R2 **仍允许**——所以 R2 不是默认档的安全兜底；真正的兜底是 **schema 必填 ＋ loader 拒绝**（T3；`my-cool-plugin` demo 暂缓）。要让某条在 `auto` 也问，只能显式声明 R3。

**为什么不做「按动词猜」**（`send`/`write` ⇒ R2，`list`/`get` ⇒ R0）：

- 那是**词表硬编码**，第二语言命名（`enviar`、`发送`）立刻失效；
- 猜错的方向通常是「低估」（`reset` 看起来无害）；
- 归一化判据：⛔ 同一件事第二份实现。

想让只读命令在 `read` 档也放行，作者**显式写** `"risk": "R0"`——这是声明式，不是猜；`auto` 档下 R1/R2 本来就放行，想让它在 `auto` 也问只能声明 R3。

### 2.3 落地方式：内测期直接改（决策 #10）

**不做三段式迁移**——当前只有作者本人下载（决策 #10），兼容层只会变成死代码。

| 步 | 做什么 | 出口 |
|:--|:--|:--|
| ① 声明补齐 | 官方各仓同批补 `risk`（含串口 28 条）；R0 必须显式写 | 同一批提交 |
| ② 兜底切换 | `risk.ts` 兜底从 `R1` 改为 `R2`；壳表不再覆盖插件命令 | 同笔 |
| ③ 门禁生效 | `audit:plugin-commands` 判「未声明即黄灯」；`check-ai-policy` 加负控 | 同笔 |

- **一次性切换**，写进 CHANGELOG 段；⛔ 不保留「未声明仍按 R1 放行」的分支。
- `riskSource` 仍保留（值：`declared` / `shell` / `fallback`），但用途变成**诊断与 doctor 断言**，不再是迁移期标记。
- 🔴 **恢复兼容的时机**：首次对外开放下载之后，新增命令「缺声明即 R2」照旧，**但插件升级新增能力必须重新弹窗**（引用 [插件权限系统](../插件权限系统/00-提案.md) §7.1 第 3 条）——这一条现在不做，记在这里防止将来忘。

### 2.4 与 `userOnly` 的关系（⛔ 不合并，但要说清）

- `userOnly` = **永远不许 AI 调**（`EPROTECTED`），用于「改门本身」的命令（`aiPolicy.setMode` 等）；
- `risk` = **AI 可以调，但按档位判**，用于业务命令；
- 二者正交，⛔ 不要用 `risk: "R3"` 代替 `userOnly`（那只是「每次都问」，不是「不许」）。

### 2.5 默认档与危险命令（2026-11-25 用户裁定 #19）

- 默认档**保持 `auto`**（D1 矩阵不动：R0/R1/R2 允许，R3 问）；`full` 作「全部权限」按钮，`ask` 作逐次确认档。
- 串口 5 条**危险命令升 R3**：`reset` / `reopen` / `toggleAutoRepeat` / `closePort` / `closeSession`；`send` / `query` 留 R2（AI 调试核心）。
- ⚠️ 未声明兜底 R2 在 `auto` 下**不是安全兜底**；真正兜底 = schema 必填 + loader 拒绝（T3；`my-cool-plugin` demo 暂缓）。
- **2026-11-25 用户裁定 #20**：T2 补 8 条运行期命令——file-tree `removeFolder`/`selectForCompare`/`compareWithSelected` = R1；marketplace `enable`/`disable` = R2，`uninstall`/`retryInstall`/`retryUpdate` = R3（对齐旧壳表，堵「T1 分层后从 R3 掉到 R2」的安全洞）。

## 三、落地清单

| 落点 | 改什么 | 判据 |
|:--|:--|:--|
| `policy/risk.ts` | 分层改为：壳命令→壳表；插件命令→声明；均无→`R2`；输出带 `riskSource` | 唯一判定入口，⛔ 第二份表 |
| `policy/decide.ts` | **不改**（档位矩阵不变） | 判定与来源分离 |
| `describe` | 每命令输出 `risk` ＋ `riskSource`（`declared`/`shell`/`fallback`） | AI 可判断可信度 |
| `audit:plugin-commands` | 新判据：未声明 `risk` 的命令清单 ＋ 按插件计数（黄灯，只报不拦） | 只报不拦，⛔ 不进 check（与现约定一致） |
| `check-ai-policy` | 负控：构造一条未声明插件命令，断言 `riskSource:fallback` ＋ `risk:R2`（`auto` 下仍 allow）；真正兜底靠 loader 拒绝 | 机械兜底 |
| schema | `risk` **必填**；缺失 ⇒ loader 拒绝并给诊断（内测免兼容，⛔ 不留可选期） | 声明式 |
| 作者文档 | `21-插件命令化规范` 增「risk 必填建议 ＋ 语义对照」 | 一处定义 |

## 四、判据（对着 07 过一遍）

- **归一化**：risk 的**来源**只有一个（壳表管壳、声明管插件）；`decide` 仍是唯一判定。⛔ 出现第二份「哪些命令危险」的名单。
- **无硬编码**：⛔ 动词词表；⛔ 壳里写插件命令名；⛔ 按插件 id 特判。
- **无死代码**：`riskSource` 让「未声明」可见，⛔ 兜底值冒充声明值。
- **高内聚低耦合**：壳只知道「风险是一个 `R0`–`R3` 的数」，不知道任何业务语义。
- **AI 友好化**：AI 能读到 `risk` 与 `riskSource`，从而预测「这条会不会被问」——这是它规划多步任务的前提。

## 五、不做

- ⛔ 不做「按插件整体一个风险」：`listPorts` 与 `reset` 不同级，粒度错。
- ⛔ 不做「AI 自适应学习风险」：不可审计、不可解释；风险必须是人/作者声明。
- ⛔ 不做「R2 自动批准（记住本次会话）」——那是档位语义，归硬约束 29，⛔ 本档另造。
- ⛔ 不把 S7 做成权限系统的一部分：两轴正交，合并会让「装的时候授权」和「调的时候判」互相污染。

## 六、验收

1. **串口回归**：`listPorts`/`readSince`/`receiveStatus`/`listSessions` 显式 `"risk": "R0"` ⇒ `auto` 静默；`send`/`query` 显式 `"risk": "R2"` ⇒ `auto` 静默；`reset`/`reopen`/`toggleAutoRepeat`/`closePort`/`closeSession` 显式 `"risk": "R3"` ⇒ `auto` ask，确认卡能拦下。
2. **兜底生效**：临时造一条未声明命令 ⇒ `describe` 标 `riskSource: "fallback"`；`auto` 下按 R2 放行（**不是安全兜底**），`ask` 档下被问；loader 拒绝（T3 开启后）才是硬兜底。
3. **冲突以声明为准**：壳表与声明给不同值时，按声明判并出诊断。
4. **跨领域**：一个非硬件插件（文件树写操作）同样按声明判，⛔ 只有串口生效。
5. **免兼容落地**：旧插件未补 `risk` ⇒ loader 明确拒绝加载并给诊断（⛔ 静默按 R1 放行）；官方各仓同一批补齐后全绿（`my-cool-plugin` demo 暂缓，用户裁定不删）。
6. `npm run check` 全绿（含 `check-ai-policy` 负控）。
