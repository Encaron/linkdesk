## 一、为什么 M4 不会重演 E5.6（**本档最该先读的一节**）

[§9.1](../01-设计.md) 的 E5.6 根因原话：**聪慧组件搬进哑容器**——「组件依赖的三件事（取数据 / 执行 / 展开子级）本来在**同一个函数调用栈**里，拆分后**分到三个不同进程** ⇒ 碎」；**通则**：「设计任何跨边界组件前先问『**这个组件在哪个进程跑？它依赖的 API 在那个进程里存在吗？**』——**别问『这个组件怎么搬过去』**。」

**M4 的对照（[§9.2](../01-设计.md)）**：

| 自查问 | M4 的答案 |
|:--|:--|
| 有**新进程 / 新窗口**吗？ | ❌ 无——网关**住主进程**（依赖的 **IPC / 命令 / 插件管理全在主进程存在**） |
| 碰**渲染层**吗？ | ❌ 不碰 |
| **搬任何组件**吗？ | ❌ 不搬 |

**关键对照原话（[§9.2](../01-设计.md)）**：「OverlayWindow 倒下的地方是『**要承载渲染层聪慧组件**』；M4 建在『**命令 + 数据**』之上——这东西**本来就跨边界工作**（命令系统天天在池→壳→主进程三层间走；开发期 AI 每天经 CDP 在调）⇒ **不重复错误类型**。」

🔴 **开工自检（照 §9.1 通则问一遍，答案必须全是「无」）**：**这个网关在哪个进程跑？它依赖的 API 在那个进程里存在吗？** —— 若答案变成「要搬个组件过去」或「要新建一个进程承载它」，**立刻停下改设计**（那正是 E5.6 的翻车路径）。

## AI#31 ⬜ **spike**：CLI 一条命令控制运行中的软件（**最小垂直切片**）

**做什么**：跑通**最小垂直切片**——**本地通道选型**（命名管道 / 回环 ＋ token）＋ **一条命令真控制运行中实例** ＋ **含冷启动与失败路径**。

**目标 = 一次退掉 [§9.3](../01-设计.md) 三个难点**：① CLI ↔ 运行中实例的本地通道（Windows 细节）② MCP 冷启动悖论 ③ 多窗口 / 单实例锁。

🔴 **产出 = 结项判据**：**通 ⇒ 铺全；不通 ⇒ 停下改设计**（[§9.4 第 3 条](../01-设计.md)：「判据不成立**立刻暴露，不等到全做完**」——**这正是 spike 的全部价值**）。

**落点**：**临时原型**（⛔ 别一上来就建正式目录结构——spike 的产物允许被推翻）＋ **结论回写本格**。

**判据（逐条写死，别写「跑通即可」）**：
1. **通了** = 终端敲一条 `linkdeskctl …`，**运行中的实例真的做了那件事**（行为经 `AI#4` 读取面或视觉确认——**非坐标**）；
2. **冷启动路径**有明确行为（软件没开时是等 / 唤醒 / 明确报错，**不是静默挂死**）；
3. **失败路径**有明确行为（软件开了但开关关着 / token 不对 ⇒ **连接被拒且原因可读**）；
4. **多实例**情形有明确行为（不启第二个实例）。

**验收方式（[§三 验收面第 1 条](../01-设计.md)）**：全程**非坐标**；⚠️ **先过 dev 验收前置**（`D0#1`–`D0#3`）——**构建握手**对本格尤其关键（spike 会在 `electron/` 与新建 CLI 之间反复改，**分不清「没生效」还是「没修好」会直接毁掉 spike 的结论**）。

**风险 / 边界**：⚠️ 若 spike 结论是「Windows 下回环 ＋ token 有坑」⇒ **换命名管道再试**（[§9.3](../01-设计.md) 把两者并列为候选）；两条都不通 ⇒ **按 §9.4 的「全加法」口径换那一条路，⛔ 不是推翻整模块**。

## AI#32 ⬜ 内核：白名单语义操作面网关

**做什么**：建主进程网关。

🔴 **关键对照（[§9.2](../01-设计.md) 原话）**：「**依赖的 IPC / 命令 / 插件管理全在主进程存在** ⇒ **不新建进程/窗口、不碰渲染层、不搬组件**」。

**落点** = `electron/services/aiBridge/index.ts`（**新建**——`electron/services/` 新目录）。

**安全半径（[§四 M4](../01-设计.md) 原话）**：**给白名单能力，不给任意 JS 权限**（与 `e5.7-extreme-simple-pool` 哲学**同源**）；**token 鉴权 ＋ 本机回环默认**。

🔴 **「留口子」硬要求（用户 2026-09-28 拍板，本格是本条的**真正落点**）**：用户原话「做东西不能太死……比如**远程操控、手机操控**之类的，虽然说**现在不做**，但是这个**口子必须要留着**」。
⇒ 内核**不许假设「调用方在本机」**，四条逐条落到实现里：
1. **传输层抽象**——内核收「请求对象」不收「stdio/HTTP」，两个皮（CLI/MCP）只是它的适配器 ⇒ 将来加**第三种皮**不改内核；
2. **绑定地址可配**——默认**仅回环**（安全默认不变），但**地址是配置项**而不是写死的 `127.0.0.1`；
3. **token 机制可扩**——作用域/失效/轮换留字段（现在只有「一把 token + 重置」就够，但**结构上**能长）；
4. **白名单与日志不依赖来源**——⛔ 不写「本机才放行」这类硬判断（那等于把远程钉死）。
⚠️ **判据补一条**：**「现在只开回环」是配置的结果，不是代码的假设**——代码里出现写死的回环判断 = 本格不合格。

**判据**：网关能**按白名单**执行语义操作，且**无法**执行白名单外的东西（⛔ 不是「能执行任意 JS 再靠自觉」）。

**验收方式**：**反证**——构造一个白名单外的请求 ⇒ **必须被拒**（⛔ 别只测「正例能通」；**只测正例 = 没测白名单**）。

**依赖** = `AI#31` 通过。

**做什么**：定白名单——**与 M1 读取面 / M2 操作面共账**（**同一份能力清单供三处消费**：插件内 AI / MCP / CLI）。

**落点** = `electron/services/aiBridge/whitelist.ts`（**新建**）。

## AI#34 ⬜ CLI 皮：`linkdeskctl` 子命令

**做什么**：子命令覆盖 **状态查询 / 开标签 / 执行命令 / 装插件（含从 URL） / 读通知 / 弹通知按钮**。

🔴 **顺序 = CLI 皮先行、MCP 皮随后**（[§四 M4 实施顺序](../01-设计.md)）：**CLI 就是 §9.3 的最小切片**——零常驻、实现简单、当天见效、人和 AI 即刻可用；MCP 皮**建在同一个内核上**（「内核验证后再包一层标准协议」）。

**落点** = `cli/linkdeskctl/`（**新建**）。

🔴 **PATH 已现成，不需要补安装器项**：`build/installer.nsh:183` 已有「**添加到 PATH（重启终端后生效）**」勾选项（默认勾选，**E6#45 已落**）⇒ 本格⛔ **不要**再往安装器里加 PATH 项（那会是重复劳动＋改安装器的无谓风险）。

**判据**：上述子命令**真能操作运行中实例**；且**子命令列表 ⊇ 手册（`AI#11`）登记的操作**（两处对账）。

**验收方式**：逐条跑子命令 → 行为经读取面确认（非坐标）；⚠️ **「装插件（含从 URL）」要验「问一声」仍在**（`AI#29`：**装 = 问一声**，含官方目录，⛔ 不缓存授权）。

**风险**：⚠️ 「装插件」是**敏感能力**⇒ 粒度按拍板 A-8（`AI#42`）；CLI 不得**绕过**确认回路。

## AI#36 ⬜ MCP 皮：stdio server ＋ `tools/list` ＋ `tools/call`

**做什么**：MCP 皮建在**同一内核**上。

**形态按拍板 A-2（本档建议 stdio）**——理由：**stdio 不需要开端口**（安全半径更小、与「本机回环」默认一致）＋ 由 AI 客户端**按需拉起**（天然规避「常驻依赖」这个「贵」的来源）。⚠️ 若用户选 HTTP（本地端口 ＋ token），**回环默认**照 [§五 第 2 条](../01-设计.md)。

**落点** = `electron/services/aiBridge/mcp.ts`（**新建**）。

**判据**：MCP 客户端**开箱即用**、`tools/list` 列出的工具**与白名单一致**（对账断言，⛔ 不是「看起来差不多」）。

**验收方式**：真接一个 MCP 客户端（Claude Desktop / Claude Code / Codex 均可配 MCP server）→ `tools/list` → **与 `AI#33` 白名单逐条比对**。

**风险**：⚠️ 「工具清单占 AI 上下文 token」是「贵」的三个来源之一（[§四 M4](../01-设计.md)）⇒ **工具粒度要克制**（宁可少而语义清晰，别把 44 个命名空间原样倒出去当 200 个工具）。

## AI#37 ⬜ MCP 冷启动悖论处理

**做什么**：AI 客户端拉起 MCP server 时**软件可能没开** ⇒ 定「**等多久 / 怎么唤醒 / 只暴露离线能力**」。

**依据** = [§9.3 难点 2](../01-设计.md)（**如实列，不假装不存在**）。

**判据**：软件没开时 MCP 客户端有**明确而可用**的行为，**不是静默挂死**。

**验收方式**：软件**不开** → 客户端调 `tools/list` ＋ 调一个工具 → **两条都要有明确结果**（离线能力清单 / 明确报错）；软件**后开** → **无需重启客户端**即可用（若做不到，要**在手册里写清**该怎么处——[§八](../01-设计.md) 的「离线可做 / 在线可做」两栏就是给这一节用的）。

**可借的既有结论（[§八](../01-设计.md)）**：**离线可做**（软件不用开）= 改 `settings.json`（**80ms 生效**）/ 装插件（zip 丢 `{userData}/plugins/` ＋ 账本）/ 改布局与窗口状态文件——**文件面即通道，落盘即持久**。⇒ 冷启动期**只暴露离线能力**是一条**已实证**的退路。

## AI#39 ⬜ 默认关 ＋ 一键开 ＋ 「关着时连不进来」判据

**做什么**：**默认关**、设置页**一键开**；**关着时「本机任何程序都连不进来」**。

🔴 **这是与裸 CDP 的本质区别**（[§八 授权粒度表](../01-设计.md) 原话）：「开关 = **门锁**、token = **钥匙**——默认关，开了才接；**关着时『本机任何程序都连不进来』**（这是与裸 CDP 的本质区别：**CDP 是无锁的门，本机任意进程可连**）」。

**依据** = [§八 授权粒度表](../01-设计.md)｜判据 = 「**开关 = 门锁、token = 钥匙**」**可实测**。

**验收方式**：
1. **关着** ⇒ 构造连接 ⇒ **必须被拒**（**反证**，同 `AI#32`）；
2. **开着但 token 错** ⇒ **必须被拒**；
3. **开着且 token 对** ⇒ 通。

⚠️ **边界（[§八 授权粒度表](../01-设计.md) 必须照抄进实现与手册）**：**插件不受此开关管**——「它们能干活靠的是『**你装了/启用了它**』；**插件管理是它们的开关**；框架不知道哪个插件是「AI 插件」（**核心无知原则**），单独设闸 = **造特权、反而不一致**」。⇒ **完整安全图景 = 锁门（接入开关）× 管成员（装/卸/禁用）。**

**依赖**：本格判据要 `AI#32` ＋ `AI#34` 才能实测（台账硬次序第 4 条）。

## AI#43 ⬜ 操作日志（正门三件套之「账本」）

**做什么**：落**操作日志**（**谁在何时调了什么**）＋ **它的读取面**。

🔴 **依据（[§八](../01-设计.md) 原话）**：正门有三件 CDP 永远没有的东西——**钥匙（token）· 名单（白名单）· 账本（操作日志）**。⇒ 本格就是第三件，**也是「靠正门比后门好」这个论证的支柱**（[§八](../01-设计.md)：「靠『正门更好用』而不是『堵后门』」）。

**落点** = `electron/services/aiBridge/log.ts`（**新建**）＋ **`AI#1` 同族的读取面**。

🔴 **读取面不是可选项**——[§八](../01-设计.md) 的用意是**让 AI 也能读账**（「否则日志只是给人看的」）⇒ **AI 能自查「我刚才做了什么」**，这正是「全自动」闭环的一部分（例：AI 执行 → 读账确认 → 复述结果）。

**判据**：日志记全（谁/何时/调了什么/结果）＋ **AI 经读取面能读到自己与他人经通道的操作**。

**验收方式**：跑一串操作 → 读账 → **逐条对账**（条数、顺序、结果一致）；⚠️ 失败的操作**也要记**（否则「AI 以为没做、其实做了」这类最危险的情形查不出来）。
