# AI 门面可信化 —— 待决策提案

> **状态：待决策**（2026-11-12 立案；两个真实工程的零知识外部 AI 反馈已到齐，本档定稿待拍）。
> **一句话**：让**任何**外部 AI、零资料、看不见界面，也能确认「我做了什么、成没成、下一步怎么走」——把回执、错误码、可发现性、可达性、自检、数据面这六处补齐。
> **落点说明**：用户指示「大型任务分主题放在待决策区」；本档与 [通用能力底盘](../通用能力底盘/00-提案.md) **正交**——**本档管"能确认"，那档管"能动手"**。

> **🔴 与领域无关**：本档所有条目对**任何**插件都成立（小说阅读器、打卡插件、PLC 上位机同样受益）。⛔ 不因反馈来自硬件调试就把门面做成硬件专用。
> **证据时效**：2026-11-12（01 见 185 条命令 / 02 见 183 条——**两次观测不同，见 §〇bis-3**）。

- **命令数 183 vs 185** ⇒ 两次观测的命令面不同 ⇒ **外部反馈必须钉版本**，否则把已修的当未修；

## 二、六条主线（按证据重排）

### 🥇 S5 · `doctor --blind`（唯一能防复发的东西）

一条命令，按门外 AI 的真实路径自检：
`ping` → `describe` 严格 JSON ＋ `apiVersion` → 开串口 → `mark` → `readSince`（断言回执同一深度）→ **变更命令必须有后置状态**（禁 `{}`/`null`）→ **paused 下必须如实**（禁静默空数组）→ 错误路径带 `code`。
- ⛔ 不进 `npm run check`（要活实例），与 `dev:driver` 同级；发布前手动跑一次。
- **B2 的拔插场景是它的天然用例**：拔插后断言状态不撒谎。
- ⛔ **必须通用**：只是"门外 AI 的自检"，不许写成串口专用。

### 🥇 S6 · 异步相位可查询

- 异步命令回 `opId`；`exec --status <opId>` 或在 `log` 里带完成事件 ⇒ 「还在跑」变成可查。
- 机制住壳，插件只需回 id。

### 🥈 S4 · 视图外可达 ＋ 门③达标

- 机制：`when` 不得把**用户动作**锁进视图；视图不在场时要么可用、要么回可判读码（`EVIEWREQUIRED`），⛔ 不得静默不注册。
- 门③达标（用户要点 4）：**每个用户动作必须有命令**；插件侧可审计——`audit:plugin-commands` 加一条判据「动作类能力是否有命令」。
- 🔴 **范围（2026-11-12 用户定）**：**新旧一起补**——软件处于 v0 阶段，存量插件也一并补齐，不搞"只管新插件"。
- 意义：这不是硬件需求，**任何插件**都适用（打卡、阅读器、PLC 上位机同理）。

### 🥈 S3b · `describe` 补 `returns` ＋ `example`

- 每命令一个请求体示例 ＋ 返回字段表（**不必完整 JSON Schema**）；`describe` 顶层带 `apiVersion`。
- `--brief`（S3a）低优：02 证明全量可用。

### 🥉 S1 · 回执封装归一（先复现）

- 若复现：单一 `unwrap`（CLI ＋ MCP 共用），恒同一深度；配「多包输入」负控用例。
- ⛔ 不许当 P0：02 明确「exec 严格回传真结果」；先让 S5 的第 3 步把它测出来。

### 🥉 S2 · 插件命令侧错误码统一

- 插件抛结构化错误 ⇒ 透传 `code`；否则兜底 `EUNKNOWN`（**不猜语义**）。
- 壳/CLI 层三分类已达标（02 亲证），缺的只是插件自造码。

### 🥈 D1/D2 · 数据面：方向 ＋ 编码（**必须动壳**）

> 原判在插件侧，**已纠正**：数据到插件时已被壳解码成 `{portName, text}`（`contracts/linkdesk.d.ts:1738-1743`），方向与原始字节都丢了。

- **D1**：`SerialDataPayload` 增 `dir:"rx"|"tx"`（或 `echo:true`），壳在推送时打标；落点 contracts → 壳 service → SDK。
- **D2**：🔴 **不是新造开关**——串口插件侧栏**已有**「接收编码」下拉（`serial-monitor/src/constants.ts:31` `SERIAL_CODINGS = ["UTF-8","GB2312","Shift-JIS","Latin-1"]`，每会话一份 `receiveCoding`）。改法＝**在同一个下拉里新增「自动」档**（UTF-8 解不出 → GB2312），壳 `serial-service.ts:69 decodeBuffer` 认识该值。**四个手动档全部保留**（用户明确知道设备编码时手选最稳）。⚠️ 影响所有串口显示，回归四类样本：纯 ASCII / 纯中文 UTF-8 / GBK 混合 / 二进制。
- **消费方章节**：[01-消费方-设备文件系统](01-消费方-设备文件系统.md)（原拟 05，因交付必须有 D1 ⇒ 按分档判据翻 04）——它同时是 D1 的验收对象：协议应答与板子日志混流，没有方向标记就只能靠猜。
