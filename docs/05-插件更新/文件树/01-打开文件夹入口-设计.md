## 一、问题与现状（证据）

**用户痛点（原话概括）：** 打开文件夹的唯一 UI 入口在欢迎标签页里；欢迎页一关，就没地方再打开文件夹了——尤其把文件树目录清空之后。

逐条核实的现状：

| # | 事实 | 证据 |
|:--|------|------|
| 1 | 唯一 UI 入口 = 欢迎页「文件夹 → 打开文件夹」按钮 + 最近列表 | `src/pool/views/welcome/WelcomePoolView.tsx:130`（`handleOpenFolder` → `api.workspace.openFolder()`） |
| 2 | 欢迎页是**标签页保底**——可被关闭、被其他标签页顶替，不是常驻表面 | `WelcomePoolView.tsx` 头注；CLAUDE.md「欢迎页是壳的兜底」 |
| 3 | FoldersView 空态（无工作区根）= **纯空白**，连占位都没有 | `plugins/file-tree/src/views/FoldersView.tsx`——`roots.length > 0` 才渲染 Toolbar 与 FileTree |
| 4 | `explorer.openFolder` 命令**已注册**（→ `workspace.openFolder()`） | `plugins/file-tree/src/components/FileTreeContextMenu/commands/navigation.ts:66` |
| 5 | 但该命令当前**无任何常驻 UI 调用**——Pool 顶栏菜单（`src/pool/shared/menu-items.ts`）无此项 | grep 核实（2026-09-13） |
| 6 | 打开链路已全线打通：`openFolder()` = 系统目录选择框 → `addFolder(path)`（**添加**语义，非替换）→ `onDidChangeFolders` 广播 → 文件树刷新 + 欢迎页最近列表记录 | `src/core/services/layout/WorkspaceService.ts:78-89` |

**结论：缺口只在 UI 入口层。** 命令、对话框、工作区、事件链全部现成——本补丁零新壳通道、零壳侧改动，纯插件侧（file-tree）注册一个侧栏入口。

**UX 依据：** ui-ux-pro-max `ux-guidelines`「Empty States：Guide users when no content exists——Show helpful message and action；Don't: Blank empty screens」。现状 #3（空白）与 #4/#5（命令有 handler 无入口）双双违反。

## 二、竞标三版（信息架构之争）

> 竞争点只有一个：**入口的信息架构**（位置 × 常驻性 × 要不要带「最近」）。视觉皮肤一律走主题系统，竞标只定骨架。详见竞标图，此处只留结论差异。

| 版 | 信息架构 | 所用 skill | 有根时 | 最近列表 |
|:--:|------|------|------|:--:|
| **A** | 搜索下方**常驻** section「打开文件夹」：主按钮 + 最近 5 条 | `ui-ux-pro-max`（壳基线） | 照常驻留 | ✅ |
| **B** | **空态才注册**的 section：引导卡（图标 + 一句文案 + 按钮），有根即移除 | `impeccable` | 整段消失 | ❌（归欢迎页） |
| **C** | **双轨**：FoldersView 空态内嵌引导按钮（VS Code 正解位）+ 搜索下常驻瘦 section 单行按钮 | `minimalist-ui` | 轨道一消失，轨道二常驻 | ❌ |

**收口规则（拍板后生效）：** 竞标图即为历史记录不改结构；实现形态以拍板版本的细节详解 mockup 为准（下一批再画）；只取骨架 + token 写法，皮肤不硬编码。

> **✅ 拍板记录（2026-09-13，用户拍板）：A 定稿。** 原因（用户原话概括）：C 形态（空态显示打开文件夹）很久之前用过，后来被删了，用户记得与闪动有关。经 git 历史 + bug-atlas 查证：C 形态死于 **E4V#44 死锁**（见下 §二·五）——「有根/无根切换时组件被整体替换」是死锁与视觉闪动的共同根源。A 的常驻 section **永不卸载**，该故障形态在结构上不可能复发——拍板 A 与历史教训同向。B（空态才注册/有根即移除）正是死锁的近亲形态，淘汰；C（双轨）含同一风险面，淘汰，其「FoldersView 空态补一行提示」精华收进 FT#3。

## 二·五 历史档案——C 形态当年是怎么死的（E4V#44 死锁，实现必读）

| 时间 | 事件 | 证据 |
|------|------|------|
| 2026-07-29 E4 #90/#92 | **C 形态诞生**——FoldersView 空工作区时内部渲染 WelcomeView（「你没有打开文件夹。」+ 打开文件夹按钮 + 最近文件夹列表），对标 VS Code，写进 `00.5-UI布局规格.md` 空态状态表 | commit `ac8779e7c` |
| E4V#44 | 升级为壳机制 `registerViewEmptyContent(containerId, viewId, <WelcomeView/>, "!explorerView.hasWorkspace")`——空态时壳层**把整个 FoldersView 替换掉**（`const body = emptyContent ?? view.render()`） | commit `c10a7f073`；E4 执行清单 E4V#44 行 |
| 2026-08-03 | **死锁爆发**：FoldersView 被替换 = unmount = 它的 `onDidChangeFolders` 订阅被 cleanup 注销 → 用户点「打开文件夹」→ `addFolder` fire 事件 → **无人监听** → `hasWorkspace` 永 false → 欢迎页永驻。修复 = 整个机制连根删除，空态占位随之消失（留下纯空白）；`WelcomeView.tsx` 成孤儿文件死至今 | commit `231257d16`；**memory `bug-atlas` §D3 专条** |

**实现红线（从 D3 直接推出，FT#1 验收项）：**
1. **订阅只挂常驻组件**——监听文件夹变化的订阅必须活在永不卸载的组件里（A 版 = OpenFolderView 常驻注册、FoldersView 主体始终挂载，两者都满足）；禁止把订阅挂进任何「按条件出现/消失」的 UI。
2. **禁止复活 registerViewEmptyContent 式替换**——空态/有根态切换只允许「组件内部条件渲染内容」，不允许「外部替换整个组件」。
3. **`WelcomeView.tsx` 孤儿处置**——`plugins/file-tree/src/views/WelcomeView.tsx`（119 行，自 2026-08-03 无人 import）是死代码；其最近列表实现是 A 版现成素材，FT#3 复用后**当场整删**（§5.3 死代码不留）。

## 三、8 维度设计（三版共同部分）

### ① 能力边界
- **插件能力**：file-tree 自己向 `explorer` 视图容器注册新视图 section——照 FOLDERS/SEARCH 既有先例，属插件 `contributes.views` 正常权利，不改壳。
- **保底设计**：壳保底不变——欢迎页按钮**保留**（它同时服务「文件树插件被卸载/禁用」的场景）；本补丁是插件增强，不是入口搬家。卸载 file-tree 后侧栏 section 随插件消失，欢迎页兜底。
- **不做**：不做「拖拽目录进侧栏添加」（拖放入文件树已有独立链路）；不做多选目录；不做工作区文件（`.code-workspace` 类）——边界外。

### ② API 设计
**零新 API。** 全部复用现有面：

| 用途 | API | 现状 |
|------|------|------|
| 打开目录框 | `lk.commands.executeCommand("explorer.openFolder")` | 已注册（navigation.ts:66） |
| 语义（备选直连） | `lk.workspace.openFolder()` | 已通（WorkspaceService.ts:78，dialog→addFolder 添加语义） |
| 最近项添加 | `lk.workspace.addFolder(path)` | 已通 |
| 树刷新联动 | `lk.workspace.getFolders()` / `onDidChangeFolders` | 已通（FoldersView 在用） |
| 最近列表读 | `lk.pluginState.get("app", "recentFolders")` | 已有数据（欢迎页写入），本插件**只读消费** |

### ③ 通信方式
全走 `window.linkdesk.*`（插件通信标准铁律）；不 import `@src/core`，不加 ShellEvents 事件，不加 IPC 通道。

### ④ 壳侧代码
**零改动。** `viewContainer.registerView` 的动态注册/更新能力已被 FOLDERS 动态标题先例覆盖（B 版的「空态才注册」用同一机制，无需新 API）。

### ⑤ 插件侧（落点）
- `plugin.json` → `contributes.views.explorer` 增加一项（B 版若为纯动态注册则只动态声明，静态声明按拍板版本定稿再定）：`id` / `title`（i18n）/ `order: 2` / `render`。
- 新视图组件走 **feature-folder**：`src/views/OpenFolderView/`（`index.tsx` + `OpenFolderView.css` + 最近列表子件），门面路径遵守 SDK bundle key 规矩（照 FoldersView 先例：门面文件留在 `src/views/` 声明路径）。
- `i18n/en.json` 补英文键（UI 文字全走 `t()`，key = 中文原文）。
- 命令 handler **不动**——`explorer.openFolder` 原样复用。
- 插件版本 bump（`plugin.json` version + `plugins/file-tree/CHANGELOG.md`）。

### ⑥ 显示
- **在哪**：资源管理器侧栏容器内、搜索 section（order 1）下方，order 2。
- **什么**：按拍板版本（A 按钮+最近 / B 空态引导卡 / C 双轨）。
- **交互**：主按钮 hover 走 `--accent-hover`；最近项 hover 走 `--hover-overlay`；窄侧栏 216px 下路径右对齐省略号截断。
- **空态/有根态**：见竞标图各 frame-note ④。

### ⑦ 配置
**不新增配置项。** 判据：单一行为、无用户选择面（A 版「最近条数」沿用欢迎页既有 5 条口径，不做开关）；不预埋「未来可能要」的项（§5.3 禁未来再做）。

### ⑧ 验收
- **门禁**：`npm run check` 全绿（含 `check-contributes`——plugin.json schema 三件套同步）。
- **CDP/实机**（用户视角）：① 打开软件 → 关闭欢迎页 → 清空文件树目录 → 资源管理器侧栏仍有点击「打开文件夹」入口 → 系统目录框弹出 → 选中后树刷新、欢迎页最近列表同步出现该目录；② 有根态：按拍板版本验证 section 常驻/消失；③ 亮/暗主题各过一遍 + 侧栏拖窄到 216px 不破格。
- **邻近区域回归**：欢迎页按钮/最近列表（仍正常写入）、FOLDERS 动态标题、搜索 section、命令面板执行 `explorer.openFolder`。
