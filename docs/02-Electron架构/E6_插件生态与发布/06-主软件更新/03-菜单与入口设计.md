### 2.2 命令清单（`coreCommands.ts` / `settingsCommands.ts` 新增）

| 命令 id | 标题（i18n key） | 行为 | 可见条件 |
|:--|:--|:--|:--|
| `update.checkForUpdates` | 检查更新… | `updateService.checkForUpdate(true)` 手动检查；有更新→发现更新 toast；无→toast「当前已是最新版本」 | **恒显**（对比手机 App：检查更新选项永在） |
| `update.openUpdateFlow` | 处理更新 | 按当前状态分支：available→开始下载；downloaded/ready→重启并更新 | TitleBar 按钮专用（§四） |
| `update.showReleaseNotes` | 显示发行说明 | 打开发行说明标签页（05） | 恒显 |
| `app.about` | 关于 LinkDesk | 打开关于页（06） | 恒显 |
| `app.shortcutsReference` | 快捷键列表 | 跳转设置→快捷键分组 | 恒显 |
| `app.openHelp` | 打开帮助 | 浏览器开官方文档 | 恒显 |
| `app.viewLicense` | 查看许可证 | 浏览器开 LICENSE | 恒显 |
| `app.privacyPolicy` | 隐私政策 | 浏览器开隐私页 | 恒显 |
| `app.toggleDevTools` | 切换开发人员工具 | `win.webContents.toggleDevTools()` | dev 模式恒显（打包版隐藏） |

> **恒显原则（2026-08-30 用户拍板）**：检查更新永不消失，与 `update.mode` 无关。点开时——有更新 → toast 引导；已最新 → toast「当前已是最新版本」；失败 → toast 错误。**入口存在 ≠ 能力承诺，而是「随时可查」承诺。**

### 2.3 帮助菜单挂载点

`src/core/commands/input-bindings/shellMenus.ts` 的 `MENU_SLOTS.MenuBar` 新增「帮助」组（对标现有「文件」「查看」组写法）。**TitleBar 文本菜单栏是壳级**（`TitleBarZone.tsx:121-138` 文本按钮 → ContextMenu），`frame:false` 下这是唯一菜单入口。

## 四、TitleBar 更新按钮（声明制 + 有更新才现 + 全文字 + 主题按钮色）

### 4.1 决策记录（完整反转史——2026-08-30 三次表态）

> ① 中途曾拍板「有颜色的更新按钮」（toast 静默 → 按钮补可见存在，`appearance:"accent"` 强调色图标）。
> ② 当日用户说「我不要那个颜色提示」→ 被**误读**为去掉按钮颜色 → 全文件传播「无颜色灰图标」版本。
> ③ **当日晚澄清**（用户原话）：「我之前以为你说的是下拉菜单的『检查更新』那几个字有颜色，当时感觉不美观，刚才看清楚了，你说的是单独的那个『更新按钮』」→ **最终拍板：TitleBar 更新按钮 = 全文字 + 主题按钮色（跟随主题普通按钮）**。菜单里的「检查更新…」保持普通菜单项（无颜色）。

**教训**：用户说「不要颜色」时，先确认「哪个对象有颜色」——这里是指菜单文字，不是按钮本身。

**最终形态**：按钮 = 壳声明插槽 + **全文字**（无图标）+ **主题按钮色**（复用壳共享 Button 组件 `.button` = accent 实心 + `var(--text-on-accent)`，跟随主题切换）。toast 承载信息（04），按钮承载「有更新可处理」的可见存在——互补不重复。三态文字 = 「下载更新 → 更新中 → 重新启动」。

### 4.2 声明制落点（一次通用壳扩展）

```typescript
// 壳侧声明（APP_PLUGIN_ID，对标现有 registerTitleBarContribution 用法——MenuRegistry.ts:188）
registerTitleBarContribution(APP_PLUGIN_ID, "right", {
  command: "update.openUpdateFlow",   // 按状态分支：available→下载 / downloaded→重启
  label: "updateButtonLabel",          // 新增字段——context key 引用，动态三态文字（下载更新/更新中/重新启动）
  when: "updateActionable",            // 状态门控：有可处理更新才显示（对标 sidebarPosition 动态键先例）
});
```

- **渲染方**：`TitleBarZone.tsx:117-141` `titleBar.slots.right` → `renderSlotButton`。**本次新增 `label` 字段解析**——一次通用壳扩展：`label` 可为静态字符串或 context key 引用（`updateButtonLabel`），任何 TitleBar 按钮可用文字，不需图标。对标 `icon` 字段是通用能力而非更新专用。
- **样式**：壳共享 Button 组件（`Button.css .button` = `background: var(--accent)` + `color: var(--text-on-accent)` + `border-radius: var(--radius-sm)` + `padding: 4px 12px`）——**主题普通按钮实机形态，跟随主题切换**。高度对齐 TitleBar 22px 行高（`height: 22px` + `padding: 0 10px`）。
- **位置**：TitleBar 右侧槽位（窗口控制按钮左侧，对标 VS Code 标题栏布局）。
- **门控键**：`updateActionable` context key = `available/downloading/downloaded/ready` 任一为真。壳把 UpdateService 状态推成动态 context key（对标 `sidebarPosition` 由 usePoolSync 随布局推送——实现时核对 ContextKeyService 推送面）。
- **文字键**：`updateButtonLabel` context key——壳随状态推三态文字（available→「下载更新」/ downloading→「更新中」/ downloaded、ready→「重新启动」），TitleBarZone 解析 label 引用后渲染。
- **点击命令**：`update.openUpdateFlow` 按当前状态分支——下载中不重复触发（进度已走 toast）。

### 4.3 状态 × 形态映射（三态文字——用户 2026-08-30 拍板）

| 状态机 type | 按钮 | 形态 | 点击行为 |
|:--|:--|:--|:--|
| `idle` / `checking` / 无更新 | **隐藏**（when 门控） | — | — |
| `available` | 文字「**下载更新**」 | 主题按钮色（accent 实心 + `--text-on-accent`，全文字宽度自适应） | 开始下载（进度走 toast 04 §三） |
| `downloading` | 文字「**更新中**」 | 同上（宽度自适应） | 不重复触发 |
| `downloaded` / `ready` | 文字「**重新启动**」 | 同上 | `quitAndInstall()`（toast 04 §四） |

> **没有更新时不占位**——when 门控隐藏，避免「常驻无动作按钮」。手动「检查更新…」（恒显）仍随时可查。**主题按钮色**——复用壳共享 Button 组件（主题普通按钮），切换主题即变；菜单里的「检查更新…」保持普通菜单项（无颜色），互不混淆。三态文字由壳推 context key `updateButtonLabel` 动态显示。

### 4.4 为什么是「一次克制的通用壳扩展」（对比中途拍板的「accent 图标」）

最终版本含**一次壳改动**：`registerTitleBarContribution` 插槽新增 `label` 字段 + `TitleBarZone` 渲染文字按钮（解析静态字符串或 context key 引用）。这是**通用扩展**——任何 TitleBar 按钮可用文字（第三方插件同样受益），对标 `icon` 是通用能力而非更新专用；走 audit-contributes 三件套（plugin.schema.json 字段 + 加载器消费 + 文档说明）。

对比中途拍板的「accent 强调色图标按钮」：accent 版本需 `appearance` 字段 + 自绘强调样式；最终版本**样式零新增**——直接复用壳共享 Button 组件（`.button` = 主题普通按钮），唯一新增就是 `label` 通用字段。按钮的「有颜色」来自主题 accent 本身，不是新的强调色概念。
