## 一、为什么今天要「退出软件重进」或「等好几分钟」

三条机制各自独立，叠起来就是用户看到的现象（读数与 `file:line` 全在 [01-设计.md](01-设计.md) §二）：

| # | 机制 | 后果 |
|:--|:--|:--|
| 1 | 目录缓存 **5 分钟**（`CACHE_TTL_MS`）＋ 官方源走 raw CDN（自己还有 `max-age=300`） | 刚收录的新版本，几分钟内落不到目录里 |
| 2 | 发现循环**每进程只排一趟**（池代码首载 +10s；判不了才按 30s/60s/120s/300s 阶梯重试，走完本会话不再试） | 铃铛通知与新版本发现不会再自己发生 |
| 3 | 「可更新」徽标**只随目录重拉**才翻新 | 目录不重拉，徽标就不亮 |

**⇒ 全链路没有「现在就去查」的入口。** 唯一的手动强刷（`catalogStore.refresh` = `forceRefreshCatalog`）只接在**错误态重试**上（`ExploreView.tsx:80`）——正常态点不到。

## 二、本刀做什么 / 不做什么

- ✅ **做**：侧栏工具栏加一枚「检查更新」钮 ＋ 三态（默认／检查中／完成的就地注）；把「手动检查」抽成**插件内唯一动作**（一处实现，将来命令面板/快捷键/状态栏入口都能复用同一动作）。
- ✅ **画清楚**：发现到新版本之后**怎么升级**——行内徽标 → 详情页「更新」→ 确认卡。⚠️ 这条链**已存在**，本图只作落点指引，不改它。
- ⛔ **不做**：零壳改动、零新 IPC、零新配置项、零新 `window.linkdesk.*` API；不改自动更新的 opt-IN 性质（点「检查更新」≠ 授权自动更新）；不把行内徽标改成行内一键升级（是否要改 = §五 待拍板第 4 问）。
