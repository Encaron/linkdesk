# E5.8-强调色来源语义定案档案（#185）

> 2026-08-29。**用户实机问：「app.accentSource 一直选跟随主题，但强调色明显跟的是 app.themeColor 而不是 app.theme——是底下介绍写错了还是逻辑错了？」**。CDP 实机 1:1 复现 + 全链路坐实：**逻辑与领域模型自洽，介绍/命名在自定义模式下误导**。拍板改介绍（描述如实说清自定义模式语义）。
> 清单指针：E5.8-执行清单 Phase 11.22 #185。
> **非新能力声明**：零新增 API / 配置 / 贡献点——纯文案修正（description/enumDescriptions/i18n/注释），不改任何行为逻辑。

## 一、用户实机证据

用户当前配置（CDP 实机读取）：
```
app.theme          = songti-print（宋体印刷体，配方自带强调色 #4A463E 纸白墨黑）
app.appearanceMode = custom
app.themeColor     = aurora      ← 具体配色 id（极光玻璃配色的「极光紫」）
app.accentSource   = followTheme
computed --accent  = #7C3AED     ← 极光紫，不是 songti 的 #4A463E
```

用户描述：「无论 app.theme 选的是谁，只要 appearanceMode 不变、themeColor 不变，强调色就不变；只有改 appearanceMode 或选别的配色，强调色才变」。

## 二、根因链（file:line 坐实）

1. `getEffectiveAccentColor`（[accent.ts:59-67](../../../../src/core/services/ui/ThemeEngine/accent.ts#L59)）——`accentSource=followTheme` 分支返回 `getCurrentTheme().colors.accent`。
2. 自定义模式下 currentTheme 快照的 colors 取自 **colors 域来源**（[apply.ts:72](../../../../src/core/services/ui/ThemeEngine/apply.ts#L72) `resolveDomainSource("colors", ...)`，注释明言「accent 跟随主题取混搭颜色域来源的 accent，非整体配方默认」）。
3. colors 域来源 = `app.themeColor`（MIX_DOMAIN_KEYS `colors: "app.themeColor"`），`findColorwayOwner("aurora")`（[mix.ts:57](../../../../src/core/services/ui/ThemeEngine/mix.ts#L57)）命中 aurora-glass 配方 → colors = aurora 配色 → accent = aurora 紫。

**CDP 试验①坐实逻辑无坏**：`themeColor` 设成 `followTheme` → `--accent` 立即变 `#4A463E`（songti 自带）；再切 `app.theme` → dark → `--accent` 变 `#0078d4`（dark 自带）。→ **只要 themeColor=followTheme，强调色就正确跟随 app.theme，链路自洽。**

## 三、判定——逻辑对，介绍/命名在自定义模式误导

- **accent ⊂ colors 域**。自定义模式混搭配色来源（themeColor=aurora）时，强调色随来源是**混搭设计的一致性**——配色来源极光紫、强调色却是宋体棕，视觉打架。想要「A 配色 + 自选强调色」用 `accentSource=custom` 显式指定（这正是 #98 独立轴存在的意义）。
- 14-档案 §十二「强调色恒取当前主题配方 accent」解耦的是**外观主开关（appearanceMode）**，不是 colors 域——mix 模式下 accent 随 colors 域来源**不违反 #98**。
- 但文案「跟随主题配方——强调色取当前主题配色的强调色」在自定义模式下**误导**：用户读「当前主题」= app.theme（songti），实际行为是「跟随配色来源 themeColor（aurora）」。这就是困惑根源。

**结论**：改介绍——把自定义模式下「跟随主题配方」=「跟随当前配色来源（app.themeColor）」写进描述。
