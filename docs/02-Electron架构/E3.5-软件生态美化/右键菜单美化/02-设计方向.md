## P0：快捷键显示接线（~5 行）

**背景：** 渲染代码、CSS、数据字段全部就绪，只差把 `findKeybindingForCommand()` 的结果填入 `shortcut`。

**改 `ContextMenu.tsx`**——在 `resolved` useMemo 里加一行：

```tsx
// 第 79 行，原来是 shortcut: undefined
// 改为：
import { findKeybindingForCommand } from "../../core/KeybindingRegistry";

// 在 resolved useMemo 内：
shortcut: findKeybindingForCommand(item.command)?.key,  // E3.5: 接线 KeybindingRegistry
```

**改 `ContextMenu.css`**——快捷键用 keycap pill 样式而非纯文本：

```css
.ctx-item-shortcut {
  flex-shrink: 0;
  margin-left: 16px;
  font-size: 11px;
  color: var(--text-muted);
  /* 保持纯文本即可——VS Code 右键菜单快捷键也是纯文本非 keycap pill */
}
```

> **为什么右键菜单快捷键不用 keycap pill（`<kbd>`）？** VS Code 命令面板里用 kbd pill 是因为它醒目——用户在"搜索快捷键"。右键菜单里快捷键是辅助信息，纯文本足够，不需要 pill 的视觉重量。

## P1：文字对比度提升（ContextMenu.css ~10 行）

**背景：** 用户反馈右键菜单文字对比度偏低，尤其切换主题后选中项几乎看不清文字。

### 改动

```css
.ctx-item {
  /* 12px → 13px，加 weight 450（比 400 稍粗，比 500 克制） */
  font-size: 13px;
  font-weight: 450;
  /* padding 5px → 6px——字号大了给呼吸空间 */
  padding: 6px 12px;
}

/* hover 色走 CSS 变量而非硬编码 #fff */
.ctx-item:hover,
.ctx-item.focused {
  background: var(--accent);
  color: var(--text-on-accent);  /* 曾是 #fff */
}

/* 快捷键 hover 态也走变量 */
.ctx-item:hover .ctx-item-shortcut,
.ctx-item.focused .ctx-item-shortcut {
  color: var(--text-on-accent);
  opacity: 0.9;
}

/* danger 色从硬编码 #E06C75 → var(--danger) */
.ctx-item-danger { color: var(--danger); }
.ctx-item-danger:hover,
.ctx-item-danger.focused {
  background: var(--danger);
  color: var(--text-on-accent);
}
```

> `--danger` 已在 index.css 暗色/浅色主题中定义（`#EF4444` / `#D32F2F`），无需新增。

## P2：开合动画（ContextMenu.css ~20 行）

右键菜单是 `position: fixed` 在点击位置。动画需注意 `transform-origin` 要从菜单左上角开始（即 `top left`），而不是默认的 center：

```css
.ctx-menu {
  /* ...existing... */
  opacity: 0;
  transform: scale(0.95);
  transform-origin: top left;
  transition: opacity 100ms ease-out, transform 100ms ease-out;
}
.ctx-menu.show {
  opacity: 1;
  transform: scale(1);
}
```

**ContextMenu.tsx 改动：** 第一次渲染后下一帧加 `.show` class：

```tsx
useEffect(() => {
  const el = menuRef.current;
  if (!el) return;
  const frame = requestAnimationFrame(() => el.classList.add('show'));
  return () => cancelAnimationFrame(frame);
}, []);
```

**关闭动画：** 右键菜单关闭是 `onClose()` → 父组件 `setState(null)` → ContextMenu 直接 unmount。和命令面板不同，ContextMenu 的关闭动画很难做——因为父组件控制显隐（`{anchor && <ContextMenu />}`），无法延时卸载。

**折中：只做出现动画，关闭仍瞬间。** 出现比关闭重要 10 倍——用户看到菜单弹出来时有动画体感；关闭时菜单已经走了，用户不关心。

## 不改的

| 项目 | 理由 |
|------|------|
| 菜单项图标 | Encaron 决策——右键菜单保持文字为主的简洁风格 |
| submenu/嵌套菜单 | ContextMenu 暂无此需求，MenuBar 已有 MenuRenderer 支持 |
| checked/toggle 状态 | 无消费方，不加字段 |
| 快捷键用 `<kbd>` pill | 右键菜单是辅助信息不是搜索场景，纯文本更干净 |
| backdrop div 复用 | mousedown capture 已经是 #53 教训修好的——不要回退 |
