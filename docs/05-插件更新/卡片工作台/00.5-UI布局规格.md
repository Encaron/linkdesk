# 00.5 — UI 布局规格 + 状态矩阵

> 2026-07-28。**卡片工作台的 UI/UX 可视化规格 + 集中式状态矩阵。**
> 设计系统来源：`ui-ux-pro-max` → Dark Mode (OLED) / Inter / density 8 / motion 3
> 🎨 **交互预览：** [workspace-preview.html](workspace-preview.html) 在浏览器查看效果
> 填补 01-07 七份设计文档的 UI 可视化缺口 + 状态覆盖空白。
> **此文档是卡片工作台开发时的 UI 真相源——不凭感觉写 CSS，不走硬编码 px/hex。**

## 一、说明——指示灯颜色冗余

指示灯绿/红/灰三种状态仅靠颜色区分——违反 UX "Color Only" 规则（色盲用户无法区分）。

**解决方案：** 指示灯卡片的 `label` 属性默认可见——"● ON" / "● 故障" / "○ 关闭"，颜色 + 文字双重传达。该 `label` 字段在 02-卡片类型 §5 中已定义，只需确保默认值非空。

## 二、状态矩阵

### 2.1 画布级状态

| 状态 | 触发条件 | 视觉表现 |
|------|------|------|
| **空白画布** | 首次安装、无任何卡片集 | 居中显示："欢迎使用卡片工作台"（16px Inter，`--text-primary`）+ 副文字 "右键空白区添加卡片，或从模板新建"（13px，`--text-secondary`）+ [新建卡片集] 按钮 |
| **空卡片集** | 有卡片集但无卡片 | 画布显示网格 + 居中提示："此卡片集为空"（14px，`--text-secondary`）+ "右键空白区添加卡片"（12px，`--text-dimmed`） |
| **正常** | 有卡片、有数据 | 卡片正常渲染 |
| **MCU 断开** | 串口连接丢失 / 设备断电 | 所有卡片数据冻结（保持最后收到的值）+ 状态栏背景变黄 `#EAB308` + 文字 "设备未连接" + 画布顶部浮现横幅："设备连接已断开——数据已冻结"（h=28px，黄色背景，可关闭） |
| **MCU 重连** | 串口恢复 | 状态栏恢复正常 + 横幅消失 + 卡片追上当前值（2s 过渡） |
| **数据快照冻结** | 用户按 Space | 所有卡片叠蓝色半透明遮罩 10% + 右上角 `❄` 图标 + 时间戳 "14:32:05.128" |
| **数据快照解冻** | 再按 Space | 遮罩消失 + 卡片追上当前值 |
| **缩放 10%** | 缩到最小 | 卡片不可辨认——自动显示鸟瞰图（全貌缩略图 + 当前视口高亮框） |
| **缩放 200%** | 放大 | 卡片清晰——无特殊变化 |

### 2.2 卡片级状态

| 状态 | 触发条件 | 视觉表现 |
|------|------|------|
| **正常（有数据）** | cardId 绑定 + 数据到达 | 卡片正常渲染当前值 |
| **等待数据** | 卡片刚创建、cardId 已绑定但数据未到达 | 内容区显示 "等待数据…"（12px，`--text-secondary`，居中）+ 卡片默认外观（标题栏+边框正常显示） |
| **数据超时** | 创建后 5s 内未收到数据 | "等待数据…" 变为 "未收到数据"（12px，`--color-destructive`）+ 右下方小 ⚠ 图标 |
| **MCU 断开** | 串口丢失 | 卡片内容保留最后值 + 卡片边框变为黄色 `#EAB308` + 右上角小 ⚡ 图标（hover tooltip: "设备未连接"） |
| **公式错误** | ExpressionCard 公式语法错误 / 引用的 cardId 不存在 | 卡片显示 "公式错误"（红色文字）+ 下方灰色小字说明原因（如 "未找到变量: temp_x"） |
| **类型不可用** | 卡片 type 在 CardRegistry 中不存在（插件被卸载） | 卡片变为灰色占位——标题显示原始 type 名 + "[类型不可用]"（`--text-dimmed`）+ 内容区空白 + 卡片不可交互（拖拽/右键除外——允许删除） |
| **选中态** | 单击卡片 | 边框 `2px solid var(--accent)` + chrome 始终可见（不依赖 hover 2s 延迟） |
| **未选中** | 单击画布空白区 | 边框 `var(--border)` + chrome 仅 hover 时出现 |
| **hover** | 鼠标悬停 2s | chrome 淡入（≡+✕+▞+边框 accent+box-shadow） |
| **拖拽中** | 按住卡片拖动 | 卡片 `opacity: 0.8` + `box-shadow: 0 8px 24px rgba(0,0,0,0.5)` + 吸附到网格点时 200ms `power1.out` |
| **拖拽碰撞** | 松手时和已有卡片重叠 | 拖拽卡片弹回原位 + 目标位置红色闪烁 200ms × 2 次 |
| **拖拽对齐** | 拖拽经过其他卡片边缘/中心 ±3px | 品红色对齐线出现——实线（边缘对齐）/ 虚线（中心对齐） |
| **全屏中** | 双击折线图/仪表盘 | 半透明暗色遮罩（`rgba(0,0,0,0.7)`）+ 卡片最大化居中 + 退出按钮 |
| **删除确认中** | 点击 ✕ | `DialogService.confirm("删除此卡片？")` |
| **控制类——发送中** | 滑块松手/按钮点击/开关拨动 | 卡片右上角出现小 spinner（16px，`--accent`） + 3s 超时 → 回弹 |
| **控制类——MCU 拒绝** | MCU 回发值和发送值不一致 | 卡片恢复到 MCU 值 + toast "设备拒绝了此操作"（`--color-destructive`） |

### 2.3 弹窗级状态

| 状态 | 触发条件 | 视觉表现 |
|------|------|------|
| **正常** | 右键/≡ → 弹窗打开 | 弹窗在卡片右侧 8px 处弹出，320px 宽，内容完整 |
| **校验失败** | cardId 为空（控制类卡片必填） | cardId 输入框红色边框 + tooltip "此项为必填" |
| **类型切换** | 弹窗中改"类型"下拉 | 不适用的分组消失——如 value → gauge 切换时"子项"分组消失 |
| **弹窗外点击** | 点弹窗外部/画布 | 关闭弹窗——不保存 |
| **Esc** | 按键 | 关闭弹窗——不保存 |
| **确定** | 点确定按钮 | 保存 → 卡片即时更新 → 弹窗关闭 |
| **重置** | 点重置按钮 | 恢复到卡片类型的默认设置 |
| **焦点在弹窗内** | Tab 键 | 焦点在弹窗内元素间循环——不会漏到画布（focus trap） |

### 2.4 持久化级状态

| 状态 | 触发条件 | 视觉表现 |
|------|------|------|
| **工作区 JSON 损坏** | `workspace.json` 解析失败 | toast "工作区文件已损坏" + 自动备份损坏文件为 `workspace.json.bak.{timestamp}` + 回退到空白画布 |
| **工作区 JSON 不存在** | 首次打开该卡片集 | 正常空白画布——无错误提示 |
| **卡片集加载中** | 大文件读取 | 画布显示居中 spinner + "正在加载…" |
| **自动保存** | 卡片位置/设置改变后 1s | 静默保存——无视觉提示 |

### 2.5 协议级状态

| 状态 | 触发条件 | 视觉表现 |
|------|------|------|
| **协议解析错误** | 某行数据被活跃协议解析器全部拒收 | 输出面板记录 `[warn] 协议解析失败: "{rawLine}"` + 卡片不受影响（继续显示上次有效值）。不弹 toast——避免刷屏 |
| **卡片绑定的协议未激活** | 卡片 `protocolId="sbq"` 但 SBQ 协议未在侧栏勾选 | 自动激活该协议（不能绑了协议但不激活——见 04-数据流 §三的 `getActiveProtocols` 逻辑） |

## 四、卡片的 Tab 导航顺序

Tab 键在卡片之间导航。顺序：**行优先扫描——按 `(y, x)` 网格坐标排序。**

```
卡片 A: (x=0, y=0, 2×2)    B: (x=2, y=0, 2×1)
卡片 C: (x=0, y=2, 4×2)

Tab 顺序: A → B → C  (y 优先、x 次之)
```

**交错处理：** 不同尺寸的卡片在行优先扫描中按各自的 `y` 坐标分组——所有 `y=0` 的卡片先按 x 排序，然后 `y=1`、`y=2`……这样大小不同的卡片自然按它们在画布上的位置正确排序。

```
实现：
  cards.sort((a, b) => a.y - b.y || a.x - b.x)
```

## 五、弹窗 Focus Trap

弹窗打开后，Tab 键只在弹窗内的可聚焦元素（输入框/下拉/按钮）之间循环。不会跳到弹窗背后的画布。

实现：弹窗 `div` 上监听 `keydown`——Tab 时，如果焦点在最后一个元素且不是 Shift+Tab → focus 第一个元素；如果焦点在第一个元素且是 Shift+Tab → focus 最后一个元素。

## 六、动画规格补充

> 01-UI设计 §五 已有 7 种动画。以下为补充。

| 动画 | 时长 | 缓动 | 触发 |
|------|:--:|------|------|
| 数据超时 ⚠ 出现 | 200ms | `ease-out` 淡入 | 卡片创建后 5s 无数据 |
| MCU 断开⚡出现 | 200ms | `ease-out` 淡入 | 串口丢失 |
| 卡片边框正常→黄（MCU断开） | 300ms | `ease-out` 过渡 | 串口丢失 |
| 卡片边框黄→正常（MCU重连） | 500ms | `ease-out` | 串口恢复 |
| 断开横幅滑入 | 300ms | `power1.out` | 串口丢失 |
| 断开横幅滑出 | 200ms | `power1.in` | 串口恢复 |
| 控制类 spinner | 连续旋转 | — | 发送命令后 |
| 控制类回弹（MCU拒绝） | 300ms | `ease-out` | 回发值 ≠ 发送值 |
| 类型不可用占位出现 | 200ms | `ease-out` 淡入 | 插件卸载 |
| 欢迎文字淡入 | 500ms | `ease-out` | 空白画布首次显示 |

```css
  --dialog-section-gap: 24px;

  --toolbar-height: 32px;

/* === 动画 === */
@media (prefers-reduced-motion: no-preference) {
  .card-drag     { transition: transform var(--drag-snap-duration) power1.out; }
  .card-chrome   { transition: opacity 150ms ease-out; }
  .card-border   { transition: border-color 300ms ease-out; }

  .card-drag, .card-chrome, .card-border, .card-snapshot,
  .banner-slide-in, .banner-slide-out { transition: none; animation: none; }
}
```
