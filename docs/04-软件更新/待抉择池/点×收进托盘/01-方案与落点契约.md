# 01 · 方案与落点契约

> 本文件回答四件事：**点哪里会怎样**（行为规格）· **那个开关长什么样、声明在哪、改完要不要重启**（设置项规格）· **主进程怎么知道开关的值**（落点契约）· **托盘本体规格**。

---

## 一、行为规格（一张表说清「什么时候真退出」）

| 你的动作 | 默认（开关＝开＝收托盘） | 开关关掉后 |
|:--|:--|:--|
| 点主窗的 **×** | **收进托盘**：窗口消失、**进程留着**、右下角「显示隐藏的图标」里有它 | **直接退出软件**（＝今天的行为） |
| 右下角图标上**右键 → 退出** | **真退出**（不受开关影响） | 真退出 |
| 右下角图标上**双击** | 主窗回来并聚焦 | ——（开关关掉时没有图标） |
| 桌面图标／命令再启动一次 | 唤回已有窗口（单实例，已有：`electron/main.ts:729-745`） | 同左 |
| 软件里点「更新」安装 | **真退出**（不受开关影响）⚠️ 见 02 E3 | 同左 |
| Windows **关机／注销** | **不许拦**（必须让系统关掉）⚠️ 见 02 E2 | 同左 |

**判定法（实现判据，照抄即可）**：

```ts
// 谁在真退出？——只有"程序自己要退"时才置位
app.on('before-quit', () => { isQuitting = true; });
win.on('session-end', () => { isQuitting = true; });   // ⚠️ Windows 关机/注销不发 before-quit，必须单列这条
win.on('close', (e) => {
  if (!isQuitting && closeToTray) { e.preventDefault(); win.hide(); }
});
```

⛔ **不许**用「还有没有窗口」「有没有人拦」这类侧写判断——必须靠一个显式的退出标记。

### 极性与文案（为什么是「关闭到托盘」默认开，而不是「点 × 退出」默认关）

你原话是「**是否点 × 为关软件，默认为关**」。这句话的**行为**就是「**点 × 默认不关软件**」——和「『关闭到托盘』默认开」是**同一件事**。选后者的理由：开关的名字＝功能的正名，读起来不用绕两层否定（「点 × 退出软件 = 关」容易让下一个人误以为默认是退出）。

⚠️ 若你更想让**开关本身显示为「关」**，说一声，键名与文案一起翻过来（`window.closeQuits`，默认 `false`，`description` 写「点 × 时直接退出软件（关掉＝收进托盘）」）——**行为一个字都不变，只换说法**。本条列在 04 决策点 **C1**。

✅ **2026-10-03 已拍（C1）**：用户原话「**怎么顺手怎么来**」⇒ **照上表写法落地**（`window.closeToTray` · `default: true`）。翻镜像写法那条**不采用**，作为备选留在上面。

## 三、谁读谁写（落点契约：主进程怎么知道开关的值）

**三条腿，缺一条就会出现「开关改了不生效」**：

| 时机 | 怎么做 | 先例／代价 |
|:--|:--|:--|
| **启动**（窗口还没建） | 主进程直接读 `userData/settings.json` | 直接照抄 `electron/main.ts:82-88`（那份判 `ai.debug.remoteDebugging`）。⚠️ **读不到时必须按「开」处理**（＝默认收托盘），⛔ **别照抄它 `:89-91` 的 catch 语义**（那份是「读不到＝关」） |
| **改开关的那一刻** | 主进程**消费**现成的配置变更广播 `IPC.config.changed`（`electron/ipc/channels.ts:58-59`） | 今天主进程只是把它**转发**给壳／池（`electron/ipc/ipc-bridge.ts:179-182`）——我们在同一处顺手认这**一个** key（`if (key === "window.closeToTray") …`），**零新增 IPC 面** |
| **改完立刻点 ×** | 就是上一条的结果（内存里的值已换） | 验收判据见 04 的 3.3 |

⛔ **不采纳的备选**：新开一条 `window.setCloseToTray` 通道。同一件事要多付 `channels.ts` ＋ 双 preload ＋ `contracts/linkdesk.d.ts` ＋ 命名空间矩阵文档**四道门禁**，换个"好看"的通道名不值。

⚠️ **待查项**：主进程里那份「原生菜单取译文」的机制（见 §六 文案那条）——若今天没有现成机制，就按本仓 2026-10-01 的「显示名字面量只写中文原文」惯例直接写中文字面量，⛔ 不写双语。

## 四、真退出的四条通道（一条都不能断）

| 通道 | 链路 | ⚠️ 注意 |
|:--|:--|:--|
| 托盘菜单「退出」 | 新建：菜单项 → 置 `isQuitting` → `app.quit()` | 必须存在（用户唯一明确的"我要走"入口） |
| 开关关掉后点 × | 关闭拦截看开关值 | —— |
| 更新安装 | `update:quitAndInstall`（`electron/ipc/channels.ts:261`）→ `electron/services/update-service.ts:240` → `electron/services/update-install.ts:127` | 🔴 **绝不能拦**：Windows 文件锁，旧进程不退干净就覆盖不了 `LinkDesk.exe`（`:234-236` 注释）。今天有兜底 `app.exit(0)`（`:128`、`:182-185`），触发它＝能装上但很难看（进程被强杀） |
| `relaunch` 两条 | `electron/main.ts:321`（`shell.relaunch`）、`:725`（调试开关重启） | 走 `app.quit()`／`exit(0)`；`before-quit` 会置标记 ⇒ 自动放行 |

**为什么 §一 那个写法能同时满足「点 × 不退出」与「关机不卡」**：`app.quit()`（更新、relaunch、托盘退出都走它）会**先发 `before-quit`** ⇒ 标记置位 ⇒ 拦截放行；而**点 ×** 只走 `win.close()`、不发 `before-quit` ⇒ 被拦下收托盘。唯一例外是**系统关机／注销**——Electron 明文规定那种情况下不发 `before-quit`，所以必须单列 `session-end`（02 E2）。

## 五、多窗语义（主窗收托盘时，脱出窗怎么办）

- **主窗 × ⇒ 只 `hide()` 主窗**，脱出窗／工作区窗**不动**（它们是用户主动脱出来的，替它做决定更意外）。
- ✅ **这恰好化解了老拍板里那个顾虑**：`electron/main.ts:397-400` 之所以规定「主窗关闭＝整个应用退出」，是因为**主窗被销毁**后壳（＝主窗 webContents）就死了、脱出窗会变僵尸。**收托盘不销毁窗口**，壳还活着 ⇒ 脱出窗可以正常留着。
- ⇒ **真关闭（销毁）时那套连带语义原样保留**：`closed` → `app.quit()`（`electron/main.ts:393-401`）与 `window-all-closed`（`:686-689`）一个字不改。
- ⚠️ 副作用要在验收时看一眼：主窗收托盘后，若还有脱出窗在屏幕上，屏幕并不"干净"（那是用户自己脱出来的窗）。这条列在 04 决策点 **C3**。
- ✅ **2026-10-03 已拍（C3）**：用户「**同意，只对主窗有效，这也是合乎逻辑的**」⇒ 本节定案，**不改动**。

## 七、⛔ 不许（踩了就是返工）

- ⛔ 做成**退不掉**的软件（四条逃逸通道一条都不能少）。
- ⛔ 拦**更新安装**（装不上＝最严重后果）。
- ⛔ 拦**系统关机／注销**（会出现「此程序阻止关机」）。
- ⛔ 自绘托盘面板／给托盘菜单"我们自己的样式"（系统原生菜单，样式不归我们）。
- ⛔ 用 `minimize()` 冒充收托盘（最小化仍占任务栏、且 `restore()` 语义不同，02 E11）。
- ⛔ 用「先 `close()` 再重建窗口」冒充收托盘（壳会死、池的 pushLayout 与键盘路由会挂——正是 `electron/main.ts:398-399` 记录过的坑）。
- ⛔ 默认值只写在声明的 `default` 里，而主进程读不到时按**相反值**处理（首次启动＝没有 `settings.json`，那是最常见的路径）。
