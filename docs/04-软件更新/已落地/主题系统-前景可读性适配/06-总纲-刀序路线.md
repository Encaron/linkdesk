⇒ 耦合不是「引擎内部搅在一起」（内核刚被 #13/#17/#19 三轮根治收敛过），而是**一个 token 的一生横跨五层**：
`主题插件 json（colorway 逐键直通）→ 引擎合成（glass color-mix → commitTokens 广播）→ index.css :root/[data-theme] 静态兜底 → 池侧接收（setProperty＋差集清理）→ 44 个 CSS 消费`。
**动刀对象是层与层之间的缝，不是内核。**

## 三、第 0 刀的口径（token 全链对账门禁）

落点：新 `scripts/check-token-audit.mjs`（照门禁族惯例带 `--self-test`），接进 `npm run check`。
⛔ 动手前先查 `check-theme-audit.mjs` / `check-theme-schema.mjs` / `audit-plugin-dead-css.mjs` 的既有覆盖面——**别重复造**，有重叠就往里加判据而不是开新文件。

三个方向：

| 方向 | 判据 | 首跑预期 |
|:--|:--|:--|
| ① 消费→定义 | 每个 `var(--x)` 必须在 `index.css` / 引擎发射清单（`MANAGED_TOKEN_KEYS` 等）有定义处 | 即 B56 机械化 |
| ② 定义→消费 | `index.css` `:root`/`[data-theme]` 声明的键、colorway 直通可写的键——**零消费者即报警** | 当场抓出 `--icon-active` |
| ③ 引擎→消费 | `MANAGED_TOKEN_KEYS` 每键有 CSS 消费 | 防引擎发死键 |

## 四、每刀的回归网（每刀交付同笔跑，不另起验收阶段）

1. **token 快照对比**——CDP dump 根元素内联 style ＋ `getComputedStyle` 的引擎键全集，切主题/切 colorway 前后 diff＝空或预期。专防伤疤 2/4 复发（残留、顶栏岛）。
2. `npm run check` 全绿（第 0 刀之后含 token 对账）。
3. E5.8 全量回归矩阵 9 场景（既有）。
4. CDP 分档实测（照外观审计通则：字号 0.85/1.0/1.25；玻璃 α 0.38/0.5——**α 下调先伤激活态**，本夹 [02 E18](02-边缘情况清单.md)）。

## 五、刀序论证（为什么是这个顺序）

- **第 0 刀必须先于第 1 刀**：第 1 刀要删 `--icon-filter-*`、新增 `--icon-ink-*`——正是断链类伤疤的高发动作。网先装，落地当天机器就能验「新键有消费、旧键零残留」（后者顺带收编 [04 残余边界](04-任务清单.md) 里「icon-filter 机械化」那件）。
- **第 2 刀（主题仓同步修复）紧跟第 1 刀**：壳侧墨色契约落地**并发版**后，才知道主题仓要跟着动什么（普查实况：**8 只官方主题全在 colorway 里写着没人读的 `icon-active`/`icon-inactive` 死键**）。作者文档也放这——坑清单到此刻**封闭**（壳侧不再变化），写进 `docs/03-插件制造/主题/`。**自有仓先规范，第三方作者照着修好的模板＋文档走就规范了**（用户 2026-10-03）——修好的主题模板＋作者文档就是未来主题作者的「第一口奶」。
- **第 3 刀（旋钮正名）放第 1 刀后**：第 1 刀会新增墨色阶梯键，对账表一次画全，免得画两次。
- **第 4 刀垫后**：依赖第 1 刀的墨色阶梯在图标栏验收通过，才推广到其他表面。
- **⛔ 明确不做**：ThemeEngine 内核结构重构——三轮根治刚收敛，15 文件 5.2k 行不是痛点；热点文件（constants/tokens/seeds）的改动一律「先过第 0 刀对账、再动手」；**壳仓与主题仓之间零耦合**——主题仓是外部独立插件（历史上生在主仓 `plugins/` 后出仓），壳的验收＝装回实测，⛔ 壳代码/门禁/脚本引用主题仓路径。
