### 1.3 🔴 持久化：这是本件与「设置键」件**最不一样的地方**

| 事实 | 读数 | 出处 |
|:--|:--|:--|
| `app.theme` 存的是**配方 id 字符串** | 是 | `src/App/config/appearance.ts:58`（`"app.theme"` 的 schema 定义） |
| 读它的地方 | `src/App/config/appearanceApplier.ts:77`（`getActiveRecipe()?.recipeId ?? normalizeThemeValue(...)`） | 同上 |

⇒ **两条可判定的真害**：
- **P1 顶替后配置指向他物**：`app.theme = "aurora"` 被另一插件顶替 ⇒ 用户看到的主题变了，但**配置文字没变** ⇒ **归因必错**（他会以为是那个主题插件坏了）。

- ⚠️ **实测提醒**：`:118-130` 的注释提到「兜底 dark 配方配色 id 若仍为 `dark` 会与 theme-defaults 'light' 配方的 'dark' 配色冲突 → **自定义模式配色下拉 React key 碰撞**」——**说明"配色变体 id"这个第三层也存在**（`colorway` 的 id），本格**必须量清楚它是否也需要入账**（[29 号档](../样式命名空间归一化/29-主题系统保护条款.md) §四.1 明写「**配方键超出 `index.css` 是合法的**」⇒ **配方键不登记**；但**配方 id 与配色变体 id 是否要登记，是本格要裁决的**）。
