## 一、核心模型：currentRepo 是唯一浏览上下文

```
currentRepo = { authorId, repoId }        ← 首页/仓库内浏览上下文
首页 / 全部插件                           ← 只算 currentRepo
分类 / 搜索 / 排行                         ← 默认全源；页内「更多」落页可按页主预过滤
作者页（一页两模式）                       ← 跨作者切换 + 来源管理
作者坞                                   ← 快速换作者 → 该作者首位仓库
我的库                                   ← 例外：全局已安装插件，不是商店浏览
```

- **两个入口两种语义**：左栏直接点分类/搜索/排行 = 全源合并；从某个仓库页的板块「更多」进分类页 = 按**该仓库（currentRepo）**预过滤，页内「已过滤 · 仓库名 · N · ✕」+「显示全部」回全量（一次性：rail 重入即全量）。作者使用「全部主题」API 的意图 = 用户点进去只看**这个仓库**的主题。
- **官方市场 = 初始 currentRepo**（首次打开商店时的默认仓），不是「全源首页」。
- **官方 = Encaron 一个作者身份**；官方市场只是其中一仓；官方还可以有第二、第三仓。
- **删除权（D5）**：只有**官方核心仓**（`official-market`，含设置/插件市场/核心插件那一组）不可移除、不可停用；其余任何源——官方预置源、官方作者的其他仓、第三方作者仓——**用户都可删除**；作者无权把自己的仓标成「不可删除」（第三方清单里的 `core: true` 一律不认）。
- **官方作者组不是「不可移除组」**：它由官方核心仓锚定；组内其他仓可删。官方唯一特殊 = 核心仓不可删 ＋ 软件更新时可预置官方源（预置源也可删）。
- **命名口径**：作者域显示名 = **Encaron**；插件条目 `author` 字段仍可为「官方」（发布者/认证徽标）。⛔ 不把「官方」当成第二个作者身份。
- **「内置」不作为用户可见标签**：来源行、仓库卡、插件卡片、详情、库筛选都不显示「内置」；只剩官方核心仓「不可移除」。内部 `core: true` 仍用于隐藏卸载按钮。

### 1.1 旧「全源/统一池」拍板的处置

| 旧结论（2026-11-19） | 新结论（2026-11-22） |
|---|---|
| 分类/搜索/榜单吃全源合并池 | **恢复**：rail 直点分类/搜索/榜单全源；页内「更多」分类落页按当前仓库预过滤 |
| rank `scope` 缺省＝全源合并 | **恢复**：完整榜单 = 你添加的所有来源 |
| 首页 top 8＝全源 top 8 | 首页 top 8＝currentRepo top 8 |
| 门店卡横排＝官方＋各仓，硬保留 | 槽 2＝**当前作者的各仓**，硬保留；官方伪卡从第三方作者店删除 |
| 作者店渲染器可出现官方门店卡 | 第三方作者店只出现该作者的仓；官方只在该作者页/坞出现 |

## 二、首页／仓库首页：槽位固定，第一视觉是 hero

### 2.1 槽位（沿用 2026-11-19 固定槽位，仅改槽 2 内容）

| 槽 | 内容 | 规则 |
|---|---|---|
| **槽 1** | 第一个 `hero`（作者声明） | 只有第 1 个 hero 占槽 1；第 2 个起按声明顺序就地渲染；**没有声明 hero → 槽 1 空着，槽 2 变第一视觉** |
| **槽 2** | **当前作者的仓库卡横排**（硬保留，作者声明管不到） | 横向滚动；当前仓高亮；右侧「查看本仓全部 N 个插件」；**只列当前作者的仓**，不出现其他作者 |
| **槽 3+** | 作者声明板块（`sections` 原顺序） | 第 2 个 hero、合集、rank、grid 按声明顺序渲染 |

- 首页 = `currentRepo.homepage`；头部标题 = 仓库 `storeTitle`（官方市场可显示「Plugin Store」）。
- **首页不出现其他作者、不出现其他作者的仓**；跨作者只在作者页/作者坞发生。
- 「按分类浏览」瓷片作为商店标准件追加在页面底部（不是作者声明板块）；只列**本仓有货**的分类。
- 没有源 → 没有这个仓 → 没有这个首页。⛔ 不允许把所有仓平铺成一个首页。

### 2.2 仓库卡（槽 2）

- 卡面：仓库名（主）、作者名 + 徽标（副）、简介、插件数、「进入仓库」。
- 徽标：`官方 ✓` / `社区` / `本地`；**官方市场不额外标「内置」**，只在管理行/核心仓标「不可移除」。
- 当前仓高亮 `aria-current="true"`。
- 仓库卡在**本作者内**可长按拖动，与目标仓交换位置（见 §四）。
- 单仓作者：只显示一张，不假装扇出；多仓作者：横向滚动，不折叠成「+N」。

## 三、作者页（一页两模式）

### 3.1 页面定位：作者容器卡

- **作者页是唯一跨作者浏览入口**；标题「作者」，不是「仓库」。
- 页面按**作者分组**：作者名/头像/仓数/插件数作组头，底下该作者的仓卡；⛔ 不是一锅平铺的仓库网格。
- **作者容器卡（归一化）**：外层是一张容器卡（头部：头像/名字/计数/折叠/拖动；内容槽：浏览放仓库卡，管理放来源行）。浏览/管理共用同一外壳、同一拖动控制器；⛔ 不各写一套。以后要放别的卡片，只要能提供稳定 id + 拖放属性即可塞进内容槽。
- 它是市场卡片族的一员，沿用现有卡片的圆角/边框/底色/间距/悬停/焦点；属于市场私有 UI，⛔ 不抽到 `@linkdesk/ui`（硬约束 28：卡片长相归市场）。
- 两种模式：**浏览**（默认）／**管理来源**（原来源页并入）。
- 页头常驻：模式分段控件、「添加网络源」「添加本地插件」；管理模式下才显示源级状态与危险动作。

### 3.2 浏览模式

```
作者 A  [官方/社区]  N 个市场源 · N 个仓库 · M 个插件   [当前]   ▾   ⋮⋮
  ├─ 仓库卡 1（长按可与本作者内目标卡交换）
  ├─ 仓库卡 2
作者 B ...
  └─ …
[还没有添加作者源]（仅当第三方作者为空；官方组仍在）
```

- 点击仓卡 → 设置 `currentRepo` → 回到该仓首页。
- **页头醒目提示（用户文案）**：「长按拖动作者卡片可调整顺序；调整后，首页与右侧作者列表会同步。把常用作者放到最前，点进来更快。仓库卡也能长按拖动（管理模式显示为来源），只在本作者内交换。」
- 提示可关闭 ×；关掉后工具栏留小 `?` 重新打开；状态存 `pluginState`（marketplace/ui.prefs）的 `authorTipDismissed`。重开软件仍记住，清 app data/市场缓存才重置。
- **组头单击 = 折叠/展开**（▾/▸ 指示）；⛔ 组头不再承担「进入作者主页」——作者级入口只在作者坞（点作者进首位仓），仓级入口用行内「查看该仓」。
- 组头显示「N 个市场源 · N 个仓库 · M 个插件」；⛔ 不用「拖动可换作者顺序」替代计数。
- **长按整行/整卡 = 拖动**（不是只抓手）：按住 380ms 进入拖动；组头/仓卡/源行整条抬起虚化跟随；提前移动 >6px = 原生文字选择/复制；单击组头 = 折叠，单击仓卡 = 进仓。
- 官方组：组头只标「官方」；**只有官方核心仓标「不可移除」**（取消「内置」标签），官方作者的其他仓与第三方仓一样可删。官方核心仓锁组内第一；其他官方仓可排在其后。
- **默认顺序 = 安装/添加顺序**：官方核心仓预装在最前；用户之后添加的源依次追加；只有用户主动拖动作者组/仓后，才按手动顺序。本地组固定末尾、不参与作者排序。
- 作者坞列表/胶囊与作者页共用同一份作者顺序；选中作者用高亮，不强行置顶。
- 空态「还没有添加作者源」住这里（同时作者坞也保留一条）；首页不再出现该空态。

### 3.3 删除权（D5）

| 源 | 能不能删 | 能不能停用 | 说明 |
|---|---|---|---|
| **官方核心仓**（含设置/市场/核心插件） | ⛔ 不能 | ⛔ 不能 | 唯一「root 也不能删」；由壳/安装器保证 |
| 官方预置源（随软件更新加入） | ✅ 能 | ✅ 能 | 预置只是「默认帮你加」，不是「锁死」 |
| 官方作者的其他仓 | ✅ 能 | ✅ 能 | 与第三方同权 |
| 第三方作者仓 | ✅ 能 | ✅ 能 | 作者无权决定；清单 `core: true` 不认 |

- **为什么只锁官方核心仓**：它是用户装软件时就确定存在的仓，位置固定有意义；其他作者/仓的添加顺序因用户而异（先加脚本仓还是图标仓不确定），锁位置没有意义。锁定 ≠ 冻结：官方核心仓仍可刷新。
- 移除二次确认；已装插件默认保留（可勾选一并卸载）；移除当前仓 → 回退官方核心仓并提示。
- 作者页/作者坞的「不可移除」只出现在官方核心仓的行/卡上；⛔ 不挂在作者组头上。

### 3.4 管理模式（来源页并入）

作者组 → 源行：

```
仓库名    URL                          目录拉取时间 / 错误    [查看该仓] [刷新] [停用/启用] [移除]   ⋮⋮
官方市场  …/linkdesk-marketplace      …                      [查看该仓] [刷新] [不可移除]
```

- 源级动作：查看该仓、停用/启用、刷新、移除（二次确认，已装插件默认保留）。
- **每行都有单仓刷新（包括官方核心仓）**：只重拉该仓目录；顶部「刷新内容」是全量刷新，不能替代单仓刷新。
- **刷新结果必须 toast**：有更新报数量、无更新说「已是最新」、失败说「刷新失败 · 已用缓存」；⛔ 不能只改行内时间。
- 官方市场仓：不可移除/停用，但**可以刷新**；「行内只读」只指删除/停用。
- 本地插件组：与作者组并列，无作者身份、无仓首页，**不可拖动**；动作＝停用/卸载。
- **真机差异**：当前真实来源行没有「查看该仓」；实施时新增。组头不再有「进入该作者主页」——组头只负责折叠/拖动，源行「查看该仓」是唯一进仓入口；作者级入口在作者坞。
- 添加源弹窗、目录错误提示、声明提示（作者自查）沿用现有实现。

### 3.5 来源生命周期：停用 / 移除 / 重新添加 / 授权

| 动作 | 源 | 商店/分类/搜索/排行 | 已装插件 | 授权 | 怎么恢复 |
|---|---|---|---|---|---|
| 停用 | 保留在来源列表，不拉取 | 退出（首页/分类/搜索/排行都不显示） | 照常运行；库中仍在 | 不受影响 | 点「启用」，无需重新添加 |
| 移除 | 删源＋缓存；作者信息清理 | 退出 | 默认保留（可勾选一并卸载）；库中显示「来源已移除」，不能更新 | 不删除、不撤销（壳 licenses 按 pluginId） | 重新添加同一源；按 pluginId 匹配已装/已购，无需重新下载 |
| 官方核心仓 | 不可移除/停用 | 始终显示 | — | — | — |

- 停用 ≠ 删除：停用只是「不显示、不拉取」，源还在；删除后「启用」按钮不存在，必须重新粘贴源地址添加。
- 重新添加同一源：目录重新拉取；已装插件按 pluginId 识别为已安装；已购授权按 pluginId 识别为已购；版本变化才提示更新。
- 已购授权住壳（`licenses`，Ed25519 本地验签），不随源删除/卸载而消失；卸载插件不等于退授权。
- 删除当前仓：回退官方核心仓并提示；已装插件保留。

### 3.6 为什么合并

- 两页重叠的是「作者 → 仓库树」，不是职责；分开会重复实现分组、拖拽、空态、计数。
- 合并后：一棵树、一份顺序、一个拖拽实现；浏览=仓卡，管理=源行。
- 风险控制：管理动作只在管理模式出现；官方组只读；移除仍二次确认。

## 四、排序：一份顺序，交换语义

### 4.1 唯一真相源

- **`marketplaceSources` 数组顺序**就是唯一顺序源（真机键：`marketplace.marketplaceSources`）。
- **作者组顺序** = 该作者第一个源在数组中的位置（组块按首次出现排序）。
- **组内仓库顺序** = 该作者各源在数组中的相对顺序。
- 首页仓库卡、作者页浏览卡、作者页管理行、作者坞、作者页组头——全部读同一份数组；在任意一处长按拖动 → 全局同步。
- **仓库首页槽 2 与全部插件页顶部的仓库卡也读 `reposInOrder()`**，不是读作者数据里的原始数组；否则手动顺序不会反映到首页。

### 4.2 拖动规则：交换，不是插入

| 拖动对象 | 行为 | 约束 |
|---|---|---|
| 作者容器 | 拖到另一个作者容器上 → 两者交换位置 | 任何作者可交换；本地组不参与 |
| 仓卡 / 源行 | 拖到同作者另一张卡/行上 → 两者交换位置 | 跨作者不交换（提示「仓库只能在同一个作者内交换」）；官方核心仓不参与 |
| 官方核心仓 | 锁官方组第 0 位；不可拖/不可被换出 | 不可删/停用；仍可刷新 |

- **交换语义**：⛔ 不再出现上下插入线（横排卡片下出现竖线不合理）；目标卡/容器高亮 + `⇄`；松手两项交换并短暂高亮。
- **响应式网格**：浏览页一行 1–4 张随容器宽度变；交换按目标卡/数组索引，不按坐标；网格自动重排。拖到其他作者的卡上只提示不能交换，不显示跨作者落点。
- **长按整行/整卡**：380ms 进入拖动；提前移动 >6px = 原生文字选择/复制（页面仍可复制粘贴）；单击组头 = 折叠，单击仓卡 = 进仓；Esc 取消；拖到窗口边缘自动滚动。
- **拖动效果**：整条/整卡抬起（半透明 + 模糊 + 阴影 + 1.015 缩放）跟随指针；松手 220ms 落到新位置；原型已实现。
- 触控/键盘：实现用 pointer events；键盘兜底 Alt+↑/↓（不是可见箭头）。
- 每次交换立即写回 `marketplaceSources`；toast「顺序已保存 · 撤销」可选。
- **一套控制器**：作者容器与内部卡共用同一个 pointer 控制器；浏览/管理只是内容槽不同，⛔ 不各写一套。

### 4.3 排序的命令面（不露在产品 UI）

排序是 GUI 行为，必须同时有非鼠标路径；GUI 与命令调用同一个 swap 函数。**产品 UI 不显示 AI 排序区/命令名**（用户明确要求去开发者腔）；命令只作为接口/自动化入口。

| 命令 | 参数 | 行为 | 返回 |
|---|---|---|---|
| `marketplace.swapAuthors` | `authorIdA`, `authorIdB` | 交换两个作者容器 | `{ authorOrder: [...] }` |
| `marketplace.swapRepos` | `authorId`, `repoIdA`, `repoIdB` | 同一作者内交换两个仓 | `{ repoOrder: [...] }` |
| `marketplace.getOrder` | — | 读作者顺序与各作者组内仓库顺序 | `{ authorOrder, repoOrder }` |

- `getState` 同步暴露 `currentRepo`、`authorOrder`、`repoOrder`、`visibleAuthors`、`visibleRepos`。
- 命令 meta 必带 `description` + `params`；达标＝结构化读 → 带参命令 → 结构化结果。
- ⛔ 不引入第二套「AI 专用顺序」；命令失败时返回结构化原因（跨作者/官方锁/同项）。
- 产品界面只在交互本身提示（长按拖动），不展示命令名。

## 五、分类浏览：rail 全源直入，页内「更多」按页主预过滤

### 5.1 规则

- **左栏直点分类/搜索/排行 = 全部来源合并**；不按 currentRepo 过滤。
- **页内「更多」**（仓库页的「全部主题」「全部硬件」等 `more.target=category:<slug>`）= 该分类页 + **当前仓库预过滤**（currentRepo 的 entries）；过滤条常驻「已过滤 · 仓库名 · N · ✕」+「显示全部」，✕ 或 rail 重入回全源。**这就是作者「让用户看到他自己这个仓库的主题」的入口**（08 §123 的意图，2026-11-22 22:06 用户订正为按仓库）。
- 仓库首页的分类瓷片仍只列**本仓有货**的分类（空分类不出瓷片）；总共 8 类，按现有分类顺序。
- 点击瓷片 → **原地在下方展开**该分类的插件网格；再点收起；不跳全局分类页。
- 展开态瓷片箭头向下（或旋转 90°）；收起态向右；`aria-expanded` 同步。
- 作者页/仓库首页/全部插件页共用同一件「本仓分类瓷片」组件；⛔ 各写一套。

### 5.2 左栏分类

- 左栏分类计数 = **全部来源合并**计数（rail 直点页面的口径）。
- 空分类：保留可见但置灰/不可点（或隐藏，待实施时按真机密度定）；分类瓷片侧一律不显示空分类。
- 切仓不改变左栏计数（rail 是全局入口）。

### 5.3 搜索／排行

- 搜索框占位「搜索所有来源中的插件…」；结果来自全部来源。
- 排行榜 = 全部来源合并 top 50；副题「按下载量排序，来自你添加的所有来源」。
- 两者没有页主预过滤（「更多」只对 category 生效；rank 始终全源）。
- 「我的库」仍是全局已安装插件（例外，不是商店浏览面）。

### 5.4 分类页不跟手动顺序（重要边界）

- 作者容器/仓卡的手动顺序只影响：首页槽 2、作者页（浏览/管理）、作者坞。
- 分类页（开发/文档/硬件…）继续按既有排序（下载量/最近更新/名称/作者/仓），因为混排不同作者；⛔ 不套用作者/仓手动顺序。

| 边界 | 处理 |
|---|---|
| 只有官方、没有第三方源 | 首页正常；作者页显示官方组 + 空态卡；作者坞显示官方卡 + 空态 |
| 作者只有 1 仓 | 槽 2 一张卡；不假装多仓 |
| 作者 4+ 仓 | 槽 2 横滚；作者卡扇出前 2 + N |
| 空仓 | 首页诚实空态；全部插件页空态；分类瓷片隐藏 |
| 源停用/移除 | 若当前仓被停用/移除 → 回退官方市场仓并提示；作者页/坞同步 |
| 源加载失败 | 有缓存显示缓存 + 警告；管理行显示错误；不伪装成功 |

| 键盘 | 卡片/组头/瓷片/返回可 Tab+Enter；拖动有 Alt+↑/↓ 兜底 |
| 减少动效 | 直接切换，无动画 |
| 主题 | 只用主题变量；⛔ 新造色 |

### 8.4 响应式

- 浏览页仓库卡网格随容器宽度 1–4 列（`@container`，⛔ `@media`）；交换按目标卡/数组索引，不按坐标；网格自动重排。
- 作者容器在窄窗单列；仓卡 1–2 列；作者坞底部抽屉；分类瓷片/工具条按既有 `@container` 规则。
- 拖动 ghost 用 fixed 定位；窗口变化/滚动时按当前 rect 更新，不依赖行列数。
- 200% 缩放/300px 容器下，作者容器头、仓卡、源行不横向溢出。

### 8.5 轻 toast 反馈规范

- **判据**：动作改变状态、但结果不立刻可见 → 必须 toast；纯导航/展开/折叠/排序视图切换 → 不 toast（可见结果本身就是反馈）。
- **刷新类一律 toast，且必须区分结果**：
  - 单仓刷新：`「<仓名>」已刷新 · 发现 N 个更新` / `「<仓名>」已是最新` / `「<仓名>」刷新失败 · 已用缓存`（错误态 3.6s）。
  - 全部刷新：`正在刷新全部来源…` → `全部来源已刷新 · 发现 N 个更新` / `全部来源已刷新 · 已是最新`。
  - 检查更新：`发现 N 个可用更新` / `所有插件已是最新`；顶部徽标 = 实际可更新数，0 时隐藏。
- **轻 toast 规格**：底部居中、单条、2.4s（错误 3.6s）、不阻塞、`aria-live=polite`；成功/中性/错误三种描边。
- **已覆盖的状态动作**：添加网络/本地源、移除源、停用/启用、安装/更新/卸载、复制指纹/密钥、库批量操作、标为已读、拖动交换（含跨作者拒绝）。
- **审计结论（2026-11-22）**：真正缺结果反馈的是 **3 处**——单仓刷新（原「已重拉目录」泛泛）、顶部检查更新（写死 3）、刷新内容（固定「已是最新」）；已改为结果化 toast。其余状态动作已有 toast；导航/折叠/展开/排序视图/搜索/坞开合/模式切换不 toast（可见结果即反馈）。

### 8.6 用户文案口径

- 产品界面用「作者卡片 / 仓库卡 / 来源」；⛔ 用「作者头 / 组头 / 源行 / 本仓 / 不跨仓混算 / scope:self」这类内部词。
- 提示写用户收益：把常用作者放最前、点进来更快；调整后首页和右侧作者列表同步；不要解释内部机制。
- 设计说明抽屉/设计文档可以保留技术词（给维护者看）；⛔ 产品页面、tooltip、toast 不出现。
- 一次性提示可关闭且记住（`dockTipDismissed` / `authorTipDismissed`）；关掉后留小 `?` 重开；清 app data/市场缓存才回到首次显示。
