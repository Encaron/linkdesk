# 01 · 方案与落点契约

> 归属判定先行为主（本案本质上是一次**能力搬家**：从设置仓搬回共享件）。

## 〇、归属判定（为什么这是「住错层」的修正）

按 [设置行案 01 §〇](../../待抉择池/设置行-控制只读同行/01-方案与落点契约.md) 的归属三层框架：

- **值标签**（当前值＋单位）与**细调步进**是**控件能力**——归属共享件本体；
- 今天它们住在设置仓（`settings-slider-control` 包裹层 ＋ `sliderValueLabel.ts`）＝「能力住在第一个使用者手里」；
- 病征与你看到的「孤零零滑杆」是同一件事的两面：能力没下沉，第二个使用者出现之日就是复制粘贴之日。
- **修正＝搬家，不是新造**：`formatSliderValue` 的格式化语义（E5.8#77：`×` 倍数 / `px` / 裸数值）随迁进组件，设置仓那份删除。

## 一、API 契约（正表——全部可选，缺省＝现状）

| prop | 类型 | 缺省 | 语义 |
|:--|:--|:--|:--|
| `unit` | `string` | 无 | 单位文案（`px` / `ms` / `FPS` / `×` / `毫米`…由声明者自定）；**声明了才有标签（D6）**：未声明 ＝ 不渲染标签（裸滑杆＝组件在设置页之外的现状）；`""`（空串）＝ 有标签、无单位（＝设置页玻璃不透明度那行的 `0.5`）。⚠️ **空串 ≠ 未声明**——合并会让无单位键整批丢标签，判据 1 当场破 |
| `unitPosition` | `"before" \| "after" \| "above" \| "below"` | `"after"` | 值标签位置（你 1.1 的前后左右）。**几何**：`before`/`after` ＝ 贴「按钮对」的**外侧**（before 在 − 之前、after 在 ＋ 之后，与轨道同一行、垂直居中）；`above`/`below` ＝ 标签**脱离行内流、整行居中压在轨道中线上**，轨道不被压短 |
| `stepper` | `boolean` | `false` | 轨道两侧渲染 **− / ＋** 按钮；点击按既有 `step` 步进、`min/max` 夹取；`disabled` 联动；`aria-label`＝「减少/增加」＋所在控件标签 |

规则：

1. **基座不动**——仍是原生 `<input type="range">`（键盘方向键/PageUp/Down、原生 `role="slider"` 无障碍全部免费保留）；−/＋ 是**并存**的辅助通道，不接管拖拽。
2. **能力归属（D3 定）**——单位与步进是**组件自带的常驻能力**，任何使用方**声明即显、不声明即无**；配置键的声明经宿主 schema 流下来（见 §三·补），设置仓只**传递**、不自定义（插件对键名零知识铁律）。
3. 值标签文案 ＝ `formatSliderValue(value, unit)` 迁入后的统一格式化（继承 E5.8#77 语义：`×` 倍数去尾零、`px` 取整、无 unit 裸值）；**一体显示「值＋单位」**（D1 定，如 `25 px`）。
4. −/＋ **单击单发、常驻可见**（D2 定；长按连发不做——NumberInput 前例，[设置行/数字步进案 04 D-残余](../../待抉择池/数字步进件-主题适配/04-任务清单.md)同口径）。
5. `disabled` 时 −/＋ 同步置灰；`stepper` 不声明则一个 DOM 都不多。

## 二、设置仓接线（唯一消费者的迁移）

`renderControl.tsx` 的 `case "slider"`：

- 现状：`<Slider …/>` 外包 `settings-slider-control` ＋ 手拼值标签（`formatSliderValue`）。
- 改后：`<Slider … unit={prop.unit ?? ""} stepper={prop.stepper} unitPosition={prop.unitPosition ?? "after"} />`，包裹层值标签与 `sliderValueLabel.ts` **删除**（能力已迁入组件）。
- **声明从哪来**：配置键在**宿主 schema** 上声明 → 宿主 config API 把属性对象交给设置仓 → 设置仓原样直传。壳的主题组滑杆键（玻璃五配置 / `surfaceRadius` / `zoneRadiusScale` / `uiFontScale`…）**第一批声明 `stepper: true`**（＝你说的「壳是第一个使用这个能力的」）。

## 四、验收判据

1. **旧观感零回归**：设置页现有滑杆键逐键目视＝现状——**含无单位键仍显示裸数值 `0.5`**（D6/E3 的硬约束）。
2. **新能力四形态**：`after` / `before` / `above` / `below` 各一现场 ＋ `stepper` 现场＋组合现场。
3. **键盘全链**：Tab 到 −→Tab 到滑杆（方向键）→Tab 到 ＋→Enter，全程无鼠标可用（顺序＝**视觉顺序**，从左到右；⛔ 不做 `tabindex` 跳序）。
4. **脱离设置页**：任一非配置页场景（或临时 demo 页）直接 `<Slider unit="ms" stepper />` 成立——「孤零零」问题的正面验收。
5. `npm run check` 全绿（含 api-surface-additive ＋ plugin-schema-sync 三处字节同）＋ token 快照（值标签颜色走 `--text-*`/`--accent`，不引入硬编码）。
6. **第三方声明链通**：作者面 schema 补齐后，一个插件在 `package.json` 的配置键上声明 `unit`/`stepper` → 校验通过 → 设置页滑杆长出单位与 −/＋。**本条是「能力真的对第三方开放」的判据**（今天不成立，见 [00 §五·补](00-README.md)）。

## 五、⛔ 不许

- 改既有 props 语义 / 删任何既有导出（只增宣言）；
- 手写 pointer 拖拽状态机（原生 range 基座是组件的头号设计决定）；
- 第二套值格式化器（迁移，不是复制）；
- 设置仓保留双轨（包裹层与组件能力并存两套渲染）；
- **只补宿主 `ConfigProperty` 不补作者 schema**（半个声明面＝第三方写了报红，等于能力对他们仍是关着的）。
