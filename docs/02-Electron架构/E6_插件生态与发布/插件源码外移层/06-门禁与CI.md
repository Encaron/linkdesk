# 7.5 门禁与 CI——搬出去不等于脱管

> **任务号：** E6#102 · **前置：** 7.2（插件已在独立仓） · **产物：** 每只插件仓自带 CI + eslint preset 迁出 + 发布清单补步
> **这一轮存在的理由：** 搬到仓外之后，**插件立刻掉出 `npm run check` 的保护伞**（那份门禁只覆盖壳仓）。这不是猜测——`first-run-setup` 已经吃过这个亏，仓内档案白纸黑字记着：「它**不受 `npm run check` 保护**」（[插件规范化层/06-门禁扩域与验收.md:341](../插件规范化层/06-门禁扩域与验收.md)）。

---

## 〇、掉出去的是什么（先知道自己丢了多少）

壳仓 `npm run check` 现在**顺带**替插件考的这些：

| 壳仓门禁 | 对插件的覆盖 | 搬走后 |
|:--|:--|:--|
| `tsc --noEmit` | `tsconfig.json:28` 的四个 core:true 插件在编译图里 | ❌ 全丢 |
| `eslint --max-warnings 0`（含自定义 `linkdesk/*` 规则） | `eslint.config.js:12` 的 `plugins/**` glob | ❌ 全丢 |
| `vitest run` | `vitest.config.ts:12-13` 的 `plugins/**/*.test.ts(x)` glob | ❌ 全丢 |
| `check-file-size` / `check-empty-dirs` / `check-css-hardcode` / `check-font-scale-audit` / `check-theme-audit` / `audit-i18n` | 扫 `plugins/` 域 | ❌ 全丢 |
| `check-bundled-version-bump` | 对 `bundled-plugins/*.linkdesk-plugin` 指纹 | ✅ **仍在**（查的是 zip，与源码位置无关） |
| `check-contributes` | schema→docs→消费方三方一致 | ⚠️ 部分（壳侧契约仍在壳仓） |

**⇒ 结论：插件的类型、lint、测试、体量、i18n、主题审计六类检查，搬出去之后**一条都不剩**——必须重建，否则本层就是「用质量换独立性」。

## 一、每只插件仓自带 CI（一份 yml，零新代码）

`@linkdesk/plugin-sdk` **已自带 eslint preset**（壳仓 `linkdesk/*` 规则的仓外版本），而 `lint` / `validate` / `build` 三个 script **模板里已经有了**。所以一只插件仓的 CI 大致就长这样：

```yaml
# .github/workflows/ci.yml
name: ci
on: [push, pull_request]
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 24 }          # ⚠️ 版本对齐壳仓 engines（>=24）
      - run: npm ci
      - run: npm run lint                   # plugin-sdk lint（含 linkdesk/* 规则）
      - run: npm run validate               # plugin.json schema 校验
      - run: npm run build                  # 能出 zip 吗
      - run: npx vitest run                 # 有测试的才加（§二）
```

### 🔴 关键建议：这份 CI **直接放进脚手架模板**

这样「新插件一建出来就有检查」是**默认行为**，而不是每仓手加——**也正是你说的「给脚手架加东西」的另一半**。要放进模板的东西：`.github/workflows/ci.yml` + `vitest.config.ts`（§二）+ 必要时 `.gitignore` 里的 `.vite` / `dist`。

> ⚠️ 模板改动是 **npm 包改动**（`create-linkdesk-plugin` bump）——与 7.6 轮的脚手架改动**合并成一笔版本**，别分成两次发版。

## 二、🔴 测试基建随插件走（25 个测试文件的运行环境）

### 实测（2026-09-14）

| 插件 | 测试文件数 |
|:--|:--:|
| marketplace | 10 |
| file-tree | 6 |
| settings | 6 |
| editor | 2 |
| serial-monitor | 1 |
| python | 0 |
| 12 只 JSON 型 | 0 |
| **合计** | **25** |

### 问题

这 25 个文件今天**跑得起来是因为壳仓替它们准备了整套环境**：

| 壳仓提供 | 插件仓缺了它 |
|:--|:--|
| `vitest` 依赖（在根 `devDependencies`） | **跑不了测试** |
| `environment: "jsdom"`（[vitest.config.ts:7](../../../../vitest.config.ts)） | 多份测试直接用 `window` / RTL ⇒ `window` 不存在 |
| `globals: true`（[:6](../../../../vitest.config.ts)） | 测试直接写 `describe/it/expect/vi` 而不 import ⇒ 全局未定义 |
| `@src` / `@` 别名（[:19-24](../../../../vitest.config.ts)） | 别名不存在（**这正是 §三 那 3 处 `@src` 会报错的原因**） |
| 🔴 **`vitest.setup.ts` 里那份 `window.linkdesk` mock** | **这是最要命的一件**——它提供 `path` / `configuration` / `workspace` / `filesystem` / `tabs` / `events` 六个命名空间的最小实现，以及 **`globalThis.__ldkConfigStore`**（file-tree 的测试**直接消费它**来喂配置值） |
| `@linkdesk/*` 的解析（靠根 workspaces 提升） | 模块找不到（7.1 §一 已解决） |
| `@testing-library/react` / `@types/*` / `jsdom` 等测试依赖 | 同上 |

> 🔴 **`vitest.setup.ts` 必须随插件走**（或由 `@linkdesk/plugin-sdk` 提供一个共享版本）——**它不是「配置」，是插件测试的运行时地基**。丢了它，25 个文件里凡碰 `window.linkdesk` 的一律报错；而这件事**最容易在「拷了 config 忘了 setup」时静默发生**（config 里写着 `setupFiles: ["./vitest.setup.ts"]`，文件不在 ⇒ vitest 直接报错，那还是好的；坏的是文件在但内容不全 ⇒ **部分测试静默走错分支**）。

### 要做

1. **逐只确认它有哪些测试**（`find plugins/<id> -name '*.test.ts*' -not -path '*/node_modules/*'`）——**别按本文档的表抄**，表是 2026-09-14 的实测值，会过期。
2. 每只有测试的插件仓补：`devDependencies` 加 `vitest`（+ 需要 jsdom 的加 `jsdom`，用 RTL 的加 `@testing-library/react`）、补一份 `vitest.config.ts`（**环境与壳仓逐项对齐**——环境不同 ⇒ 本地绿、CI 红，是这类迁移最典型的坑）。
3. `package.json` 加 `test` script，CI 里跑起来。
4. 🔴 **不许把「测试跑不了」的插件直接放弃测试**——那是把 25 个测试文件的资产扔掉。若某只确实无法独立（例如深度依赖壳侧桩），**登记原因并按 [02 §三](02-出口打通.md) 的「本地桩」思路改造**，不许静默删除。

> 📌 **和 7.1 §三 的关系**：7.1 处置的是「测试**依赖壳内部实现**」（3 处 `@src`）；本节处置的是「测试**依赖壳仓的运行环境**」。**两件不同的事，都要做。**

### 🔵 7.1 登记（E6#98f，2026-09-14——**本轮只登记不修**）

**实测复核（7.1 轮重新数了一遍，不是抄上表）**：`find plugins -name '*.test.ts*'` = **25 个文件**，分布与上表一致（marketplace 10 / file-tree 6 / settings 6 / editor 2 / serial-monitor 1 / python 0 / 12 只数据型 0）。⇒ **上表的处置清单原样有效，7.5 轮照它做。**

**7.1 已经替 7.5 解掉的那一半**（§三 那一半，即「测试依赖壳内部实现」）：

- file-tree 的 3 处 `@src` 已清零——`FileTreeClipboard.test.ts` 的 `ContextKeyService` 换成**本地 key→value 桩**；`FileTreeModel.test.ts` 的两条 `vi.mock("@src/core/…")` 实测为**死 mock**（删后 `npx vitest run plugins/file-tree` 69/69 绿）。⇒ **7.5 补 `vitest.config.ts` 时不再需要 `@src` 别名**（别名只被这 3 处消费）。
- `grep -rn "@src" plugins/**/src` 现在**零 import**（命中全是注释）。

**7.1 新引入、必须交给 7.5 的三条环境事实**（都是「插件仓 `npm install` 会怎么解析」）：

1. **插件现在自己声明依赖了**（E6#98a）：六只 React 插件的 `dependencies` 里有 `@linkdesk/ui` / `@linkdesk/contracts`，`devDependencies` 里有 `@linkdesk/plugin-sdk`。**仓内**靠 workspaces 链接到本地包，**仓外**必须从 npm 货架拿——⇒ 🔴 **7.5 的 CI 能不能跑，取决于 `@linkdesk/plugin-sdk@0.1.14`（本轮新增 `pack` 子命令）与 `@linkdesk/contracts@0.1.13` 是否已发布**。本轮只 bump 版本号、**未发布**（发布是用户点头的外向动作），黄灯留在 `check-npm-release`。
2. **12 只数据型插件首次有了 `package.json`**（E6#98c）：`build` = `linkdesk-plugin-sdk pack`（目录整树打包），devDependencies 只有 `@linkdesk/plugin-sdk`。它们测试数为 0，但 **CI 模板必须覆盖它们**（`lint` / `validate` / `build` 三条对它们全部有效）。
3. **`vitest.config.ts` 的 `environment: "jsdom"` / `globals: true` 一条都不能省**——上表已列，此处只强调：它们是**静默生效**的配置（缺了报错还算好；环境不同 ⇒ 本地绿、CI 红）。

## 三、eslint preset 迁出（壳仓插件块随源码走）

壳仓 `eslint.config.js` 里专给插件的那一块（`:167` 起）含几条**必须跟着插件走**的规则：

| 规则 | 现在的价值 | 搬走后 |
|:--|:--|:--|
| `linkdesk/no-cross-plugin-import` | 插件相对 import 解析进 `/plugins/<其他id>/` 即 error | 仓外插件不 import 别的插件源码，**规则改为「禁止 import 别的插件仓库」**（形态变了，精神不变） |
| JSX 中文必须走 `t()`（硬约束 2） | 插件侧 i18n 纪律 | ✅ 必须保留 |
| 禁止硬编码颜色（硬约束 1） | 主题纪律 | ✅ 必须保留 |

**要做：** 确认 `@linkdesk/plugin-sdk` 的 eslint preset 里**到底带了哪几条**——带了的直接用；**没带的要么补进 preset（改 npm 包），要么在模板里内联**。**不许「默认它带了」**（这条正是「两套机制从没对上」的老病，[插件规范化层 §〇③](../插件规范化层/00-整理档案.md) 记的就是这个）。

**判据：** 在一只插件仓里**故意**写一段硬编码 hex 或裸中文 JSX ⇒ CI **必须红**。

## 四、发布清单补步（把跨仓顺序写成显式动作）

**文件：** `docs/06-发布管理/发布清单.md`（7.0 轮已加占位行，此处回填命令）

发布前清单要补的完整顺序（**这就是你新的出厂发布动作**）：

```
① 各插件仓：按需发版（npm run publish）→ 插件的更新走市场，不必与壳同批
② 壳仓：npm run sync:bundled --latest   → 刷新出厂种子（zip + lock）
③ 壳仓：npm run check                    → 含 check-bundled-freshness
④ 壳仓：npm run publish → 打 tag → CI 出安装包
```

⚠️ ⚠️ **①→② 是新增的跨仓顺序依赖**（[总档案 R3](00-整理档案.md)）——**它是代价，不是免费**。用一条命令替代「靠人记得」是本节的唯一目的；**别把它写成「一条命令搞定全部」**（① 那一步在别的仓里，壳仓看不见）。
