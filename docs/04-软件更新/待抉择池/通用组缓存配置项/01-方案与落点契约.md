## 一、先把「缓存」这个词拆开（不拆清，第 4 点必然出错）

真机实测（2026-10-02，全新安装态，`%APPDATA%\linkdesk` 合计 **70.6 MB**）：

| 目录 | 体积 | 能不能删 | 是什么 |
|:--|--:|:--|:--|
| `Cache` | 12.0 MB | ✅ 可再生 | Chromium 网络/资源缓存 |
| `GPUCache` / `DawnGraphiteCache` / `DawnWebGPUCache` | 1.6 + 0.5 + 0.5 MB | ✅ 可再生 | 着色器/GPU 缓存，删了自动重建 |
| `Code Cache` / `Local Storage` / `Network` / `Session Storage` / `Shared Dictionary` | ≈0.2 MB | ✅ 可再生 | 渲染层缓存与会话存储 |
| **`plugins`** | **55.5 MB** | ❌ **删不得** | **已安装的插件本体 = 数据** |
| `appearance` / `update` / 若干 json | ≈0.1 MB | ❌ 删不得 | 您的配置与更新状态 |

**结论**：能安心清的只有 **≈14.6 MB**。`plugins` 占 79%，它是「用户装的东西」，不是缓存。
⇒ **「清除缓存」这颗按钮，绝不允许碰 `plugins`、`appearance`、各类设置 json。** 想清插件那是「重置」的另一件事，不塞进这颗按钮（决策点 **D3**）。

## 二、设置页「存储」分节——逐行规格

**在哪**：设置 → 左导航 **通用**（通用组）→ 二级分节 **存储**。
**分节怎么来的**：设置页二级分节 = 配置项的 `group` 字段，不是新造 UI 概念。
**真相源**：新增配置文件 `src/App/config/storage.ts`（照 `src/App/config/appearance.ts` 的写法），⛔ 必须同笔登记进 `scripts/check-config-baseline.mjs` 的 `TARGETS`，否则机械门禁红。

### 行 1 · 缓存位置 —— **不造控件**

| 项 | 定 |
|:--|:--|
| 控件 | **现成的** `FilePathInput`（路径输入框 ＋ 📂 选择按钮） |
| 怎么来的 | 配置项写 `uiHint: "directory"` —— `settings` 插件 `renderControl.tsx:87` 已有这一条分支，直接渲染 `FilePathInput dialogType="directory"` |
| 点 📂 | 走既有 `IPC.dialog.open {directory:true}` → `dialog-handlers.ts:36`（`properties:['openDirectory']`，系统「选择文件夹」新样式） |
| 为什么不是「只读文本 + 按钮」 | 用户原话是「只读文本共享组件和按钮之类的」；但**能改的东西不该是只读**。`FilePathInput` 恰好就是「一个文本框 + 一个按钮」，形态与诉求一致，且**零新建控件** |
| 齿轮 | 该行右侧挂齿轮，菜单项见「行 3」下方说明 |

### 行 2 · 已用空间 —— `readonly` 状态行

| 项 | 定 |
|:--|:--|
| 控件 | **现成的** `ReadOnlyStatus`（`renderHint:"readonly"` + `statusCommand`） |
| 显示 | 形如 `14.6 MB / 70.6 MB`（可清 / 全部），运行时算，**不在配置里存数字** |
| 为什么 | 数字是**事实**不是设置，只读行正是为这种"运行时状态"准备的（`renderControl.tsx:48` 的既有分支，M4 AI#38.12 那套） |

### 行 3 · 清除缓存 —— `action` 按钮行

| 项 | 定 |
|:--|:--|
| 控件 | **现成的** 动作行（`renderHint:"action"` + `actionCommand`，`renderControl.tsx` 里那条分支） |
| 行为 | 确认框 → 删**可再生的那几项**（§一 上半张表）→ 提示 **「部分文件正被占用，重启 LinkDesk 后彻底清空」** |
| ⛔ 不许 | 不许碰 `plugins` / `appearance` / 设置 json；不许谎报"已全部清空"（占用是事实，见 02 §七） |

> ⚠️ **结构性事实（决策点 D1 要认这条）**：`readonly` 与 `action` 是**两条互斥分支**（`renderControl.tsx:48` 与 `:187`，`if` 在前、`switch` 在后）。所以**「只读的值」和「按钮」挤不进同一行**——这恰恰是下面把"打开"动作放进**齿轮**的原因，而不是硬凑。

### 齿轮是什么（不用改 settings 插件）

设置行右侧的齿轮**不是 settings 插件的代码**，是**壳注册的菜单槽**：

- 槽常量：`SETTING_ITEM_GEAR_MENU = "settingItemGear"`（`MenuRegistry.MENU_SLOTS.SettingItemGear`）
- 菜单项注册处：`src/core/commands/shell/coreCommands.ts`
- 可用条件变量（`when`）：`settingKey` / `settingModified` / `settingFollowTheme` / `settingResetsToDefault`

**照抄的先例（两个，都已存在）**：

| 先例 | 在哪 | 干什么 |
|:--|:--|:--|
| `workbench.action.openAppearanceStorage`「打开存储位置」 | `coreCommands.ts:317 / :341 / :359 / :379 / :400` | → `window.linkdesk?.appearance.revealStorage()` → 主进程解析 `userData/appearance` → **`shell.openPath(dir)`**（普通资源管理器弹窗，⛔ 不是模态框）；通道常量 `revealStorage: 'appearance:reveal-storage'` 在 `electron/ipc/channels.ts:248` |
| `IPC.shell.openPluginFolder` | `electron/main.ts:296-310` | 打开插件目录，同族做法 |

⇒ **缓存位置行齿轮里的「打开缓存目录」照抄 `appearance.revealStorage` 这一套**：通道 `storage:reveal-cache` → 主进程解析**当前生效**的缓存目录 → `shell.openPath`。**settings 插件一个字都不用改**（用户点名要的就是这个先例：「类似 `app.zoneBackgroundImage` 和 `app.backgroundImage`」）。

### 齿轮里还应有什么

| 菜单项 | 条件 | 行为 |
|:--|:--|:--|
| 打开缓存目录 | 恒显示 | 上面那套 |
| 恢复默认位置 | `settingModified` | 清掉 `app.storage.cacheDir` **并**清掉注册表种子（见 §三）——两处一起清，不留第二个地址 |
| 复制路径 | 恒显示 | 复制生效路径到剪贴板（小成本、高频便利） |

## 三、★ 落点契约（谁写谁读 —— 直答"安装器改了地址，软件内仍是旧地址"）

**这是整件事的核心，也是用户最怕的那句硬编码。**

```
【安装器】用户填了缓存目录                    【软件】启动
   │  仅当非空                                │
   │  写 HKCU\Software\LinkDesk\CacheDir  ────▶ 若「值存在」且
                                                「软件内 app.storage.cacheDir 为空」
   │                                                 │
   │                                                 ▼
   │                                        采用它作为 app.storage.cacheDir
   │                                        （= 写进设置，UI 上看得见）
   ▼                                                 │
（此时注册表只是"种子"）                              ▼
                                          此后【以软件内设置为准】
                                          注册表**不再被回读覆盖**
```

三条铁律：

1. **安装器只在"播种"时写注册表，且只在用户真填了值的时候写。** 留空 = 一个字都不写（⛔ 绝不把「默认路径」当值写进去——那会变成一个永远回弹的硬编码）。
2. **软件内设置是权威。** 启动时只在「软件内还没有值」时**采用**种子；一旦设立，之后用户在设置里改成什么就是什么，**注册表不会把它弹回去**（决策点 **D2**：采纳"播种制"，否决"注册表恒为准"）。
3. **任何地方都不再存第二份缓存路径。** 「打开缓存目录」永远在**主进程**解析**当前生效**的路径再去 `openPath`；卸载器、完成屏、关于页都不复制这个字符串。

⇒ 这套是**照抄壳里已有的先例**（`src/App/startup.ts:302-317`）：`app.osIntegration.fileMenu / .dirMenu / .fileAssoc` 这三个键就是「注册表状态 ↔ 配置项」的镜像——启动读注册表写进配置，`onApply` 写回注册表。缓存目录沿用同一手法，**同一套机制、同一处代码风格**，不是新发明。

## 四、安装器「更多配置」页规格

**入口**：欢迎屏动作行 → **「更多配置」**（在「自定义安装」旁边，第三个按钮）。
**为什么**：用户原话「这样未来添加新的配置项好添加」——竖向清单天然可长。

**布局（自上而下）**：

| 段 | 内容 |
|:--|:--|
| 品牌行 | 与其它屏一致：logo ＋ `LinkDesk` ＋ 标语 ＋ 版本 |
| 标题 | `更多配置` ＋ 一行副标题（说明"装前选项都在这里，随时可回来改"） |
| **竖向四项** | 文件右键菜单 ／ 目录右键菜单 ／ 注册为受支持文件类型的编辑器 ／ 添加到 PATH（重启终端后生效）——**文案与欢迎屏逐字相同**（同一批 i18n 键 `installer.opt.*`） |
| 缓存目录行 | 标签 `缓存目录` ＋ 小字副注 ＋ **路径输入框** ＋ **「浏览…」** |
| 动作行 | **立即安装**（主按钮） ＋ **返回** |

**⛔ 不放的东西（决策点 D5）**：**不放"安装位置"**。安装位置留在欢迎屏「自定义安装」的展开区里——同一件事**只允许一处可改**，否则「我在更多配置页改了，怎么装到别处去了」是必然事故。

**宿主侧要接的（件 2e，⚑ 未落）**：`main.cpp` 里
- 受理页面消息 `browse-cachedir` → 复用 `PickInstallDir` 的 `IFileOpenDialog(FOS_PICKFOLDERS)` 套路写一个 `PickCacheDir`，回 `{"type":"cache-dir-done","dir":"…"}`（页面已能收，见 03 §五）；
- 安装收尾时读 `cacheDir` 字段（`JsonGetString` 同级手法，⚠️ **空值不写注册表**，见 §三 铁律 1）；
- 写 `HKCU\Software\LinkDesk\CacheDir`（字符串值）。

## 五、为什么「清除缓存」不放进安装器（用户第 6 问我给否定）

| 维度 | 安装器 | 软件内 |
|:--|:--|:--|
| 时机 | 一辈子一次（装的时候） | **每天**（缓存是会长的） |
| 对象 | 还没装出来的东西 | 装好的东西 |
| 反悔 | 没法反悔（装完就走） | 随时可用、可再清 |

**安装器该管的是「装之前的决定」**（放哪、要不要右键菜单、PATH），**不是「装完之后的维护」**。把"清除缓存"塞进安装器 = 用户想清缓存时得重跑安装程序——这是反直觉的。
⇒ 安装器**只加「选择缓存目录」一行**（一次性播种），清除归软件内。
