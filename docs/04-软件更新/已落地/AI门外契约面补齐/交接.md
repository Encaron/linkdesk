### 5 T17 插件侧改造设计草案（⛔ 未落盘 · 等 C 的 `decodeBytes`）

**目标**：壳只给 `{portName,dir,data,at}`；插件自己完成「拼行 → 解码 → 方向/回显 → 日志/展示」。

**唯一入口模块（建议新建 `src/services/serialInbound.ts`）**：
- 订阅一次 `serial.onData`（entry 顶层，与 `ensureReceiveLogSubscribed()` 同位置）。
- per-port 状态：`pending: Uint8Array`、`coding: SerialCoding | "自动"`、`idleTimer`。
- `coding` 来自会话表：`getSharedState().sessions` 按 `port` 查 `receiveCoding`（优先活动会话）；会话变更时同步。⛔ 不复制第二份策略。
- 行装配：按 `0x0A` 切行；每行 `.trim()` 后非空才发（对齐旧壳 `flushLines` 语义）；无 `\n` 时 100ms idle flush（具名常量 `AUTO_FLUSH_MS = 100`）。
- 解码：`decodeBytes(lineBytes, coding)`；`"自动"` = `decodeBytes(bytes,"UTF-8",{strict:true})` 失败 → `decodeBytes(bytes,"GB2312")`；回退顺序写成 `AUTO_CODING_FALLBACK` 具名常量。
- 输出事件：`{portName, dir, text, bytes, at}`；`bytes` 用于 HEX（⛔ 不从 text 反推 hex）。
- tx：壳直接给 tx 字节；按 `dir:"tx"` 走同一解码（不拼行，保持旧「一条发送一条回显」）；显示受 `showEcho` 门控；**删除发送路径的本地 `onEcho`**（`useSendEditor.ts:59/64`），避免双显。

**三个消费方**：

| 消费方 | 改动 |

## 2026-11-25 · A 核心契约 · T11 规格（host op 注册表 ＋ opId 握手 · 给 C 的 SDK 面）

> 用途：A→C 直连的技术规格（调度台已授权 09 §十一）。**先落本文档，消息只作提醒。**
> ✅ **异步声明方式已裁（2026-11-25 · 00 §七 #21 / 05 §二 / 09 §C3 / 11 §一 / 08 T11·T19）：A 案（声明式）** ——
> `registerCommand` meta 声明 `async: true`；壳自动包 op 回 `{pending:true, opId}`；插件 ⛔ 调 `runAsync`；SDK 只导出 `AsyncCommandMeta` 类型。
> 依据 12 §一：归一化 / 硬约束 28 作者零负担 > 05 草稿字面。**B 案作废，SDK 运行时 `runAsync` 取消。**

### 1 契约形状（内核面，A 实现）

**请求侧不变**：`exec` 仍 `{commandId, args}`；同步命令回执不变。

**异步命令的 exec 回执**（新增形状，⛔ 与同步混用）：
```jsonc
{ "commandId": "x.y", "pending": true, "opId": "op_7f3a91c4", "startedAt": "2026-11-25T05:10:00.000Z" }
```
- ⛔ 不再返回 `{}`/`null`；⛔ 不挂住连接等结果（05 §二：把「还在跑」变句柄）。
- 同步命令**绝不**返回 `pending`（⛔ 不把同步包装成异步）。

**查询（新内核 op `opStatus`）**：
```jsonc
{ "opId": "op_7f3a91c4" }
→ { "state": "running"|"done"|"failed"|"expired",
    "result"?: any,                    // state=done
    "error"?: { "code": "...", "message": "...", "hint"?: "..." },  // state=failed
    "startedAt": "...", "elapsedMs": 1234 }
```
- `state` 是**封闭枚举**（running/done/failed/expired）——⛔ 插件自造 `"processing"`。
- 过期 ⇒ 查询**抛 `EOPEXPIRED`**（code），⛔ 回空对象。

**CLI**：`linkdeskctl exec --status <opId>` → 走 opStatus；**⛔ 不复用 `readSince` 的「游标」帮助文案**（04 §二 归一化注）。
**事件面**：`log` 账本流新增条目类型 `op.completed`，字段与 opStatus 的 done/failed 一致（`{opId, state, elapsedMs, commandId}`）——订阅方不必轮询。

### 2 注册表（唯一，住壳）

- `Map<opId, { status, result|error, startedAt, endedAt?, expiresAt }>`；**memory-only**（⛔ 落盘——op 是会话内相位，不是历史）。
- `opId` 形状：`op_` ＋ 8 位十六进制（不透明；⛔ 客户端解析其结构）。
- TTL：默认 **10 分钟**（`600_000ms`），到期转 `expired` 并释放结果引用（防内存钉住大回执）；查询过期 id ⇒ `EOPEXPIRED`。
- 上限：**500 条**，超出按「最老的已终态」先淘汰；running 永不淘汰。
- 失败：handler 抛错 ⇒ `state:"failed"` ＋ 统一错误信封（`coded` 的 code 原样；裸 Error ⇒ `EUNKNOWN`，与 T14 同一构造点）。
- `opStatus` 自身登记进 `OP_RISK` = **R0**（只读查询）。

### 3 插件侧：异步怎么声明（✅ 已裁：A 案 · 2026-11-25）

**A 案（A 推荐）：声明式，作者零负担**
- `contributes.commands[]` 增可选 `async: true`（manifest）；
- 壳执行该命令时：立即回 `{pending:true, opId}`，handler 在后台跑，promise 结算时写注册表 ＋ 发 `op.completed`；
- 插件代码**一行不改**（handler 本来就是 async 函数）；
- C 的 SDK 只需在**类型**里补 `async?: boolean` 的 manifest 类型（若有），⛔ 不需要 `runAsync` 运行时 API。
- 理由：归一化（一个真相源在 manifest）；作者零负担；与「声明式」判据一致。

**B 案（05 §二 原文）：插件调 SDK `runAsync(fn)`**
- 插件 handler 内 `const { opId } = await runAsync(work)`，把 opId 回传给壳；
- 需要 SDK 提供运行时 API ＋ 池→壳「代登 op」通道（新 IPC），作者要写代码、且 handler 仍要自己回 opId；
- 缺点：多一条 IPC ＋ 作者负担；优点：能表达「命令内多段异步」。

⇒ **A 优先、B 仅在「一条命令内多段独立异步」确实出现时再开**（届时按 07 §三 槽位规则加，⛔ 现在双轨）。
✅ 已裁：**A 案**。05 §二 的「插件只调 runAsync」字面已按裁定更新（调度台同笔改 05/00/09/11/08）。

### 4 C 的 SDK 面（裁定后）

- ✅ 已裁 A 案 ⇒ C **只做类型**：`AsyncCommandMeta`（`async?: boolean`）＋ aiBridge 客户端类型补 `pending/opId` 与 `opStatus` 回执。**⛔ 无运行时新增，⛔ 不做 `runAsync`。**

## 2026-11-25 · 0.2.66 热修（外部 AI 实测后的根因修复 · A）

> 背景：0.2.65 发版后，真实实例上 S4 失效——串口开过视图再关，**整插件命令消失（连 R0 都 EVIEWREQUIRED）**；外部 AI 报告另指出 `filter` 静默降级、`--blind` 不存在、`askFirst` 不含插件 R3、doctor 假红。

### 1 根因（设计层，不是实现疏忽）

- 「运行期注册上下文（可变栈）= activation 真值」这个模型有两个不成立的前提：
  1. **视图 bundle 导入时会顺带求值 entry**——模块顶层注册落在视图上下文里，被记成 `view`；
  2. 「首注册决定作用域」＋「跨作用域拒绝」⇒ 一次误判被模块缓存钉死，视图卸载摘光后重开视图也不重跑 entry。
- 另：B 的「声明面命令一律提升为插件级」把**真视图命令**（copy/exportLog）也提升，无视图时会执行并炸 handler（`cmView` null）。

### 2 修复（commit `5a29e6a0a`、`60aeb0eb2`、`ab2182a1d`，版本 0.2.66）

| 层 | 改动 |
|:--|:--|
| 信源 | **声明是地板**：manifest 声明 `entry` 不得被运行期降级为 view（保留＋诊断）；声明 view 可被运行期升为 entry（运行期真值优先） |
| 作用域 | 插件**任何模块**（entry 或 view bundle）求值期一律按 `entry` 记；视图 hook 在挂载后仍记 `view` |
| 恢复 | 视图卸载只摘「声明 view」的条目；声明 entry 的提升为 plugin（⛔ 不再"声明过就提升"）；声明集合支持空集重取（修池 preload 早于壳注册的竞态） |
| 契约 | `filter` 未知键 ⇒ `EBADFILTER`；`askFirst` 按当前档位实算（含插件 R3）；`doctor` 增加视图前置（开着视图时 `a-view-code` skip）；`doctor --blind` 别名 |
