## 一、发版轴与次序（两轴都动共享层 ⇒ 走 `@linkdesk/ui`）

**轴判定**：本次改动全部落在 `src/components/shared/**`（`InlineInput` 样式 ＋ 管理器视图组件）⇒ 属**共享 UI 包轴**（npm），⛔ **壳不发版**（2026-10-03 口径：壳只走 dev 攒批，时点归用户）。

| 次序 | 动作 | 判据／为什么 |
|:--:|:--|:--|
| 1 | 改 CSS／视图源码 | — |
| 2 | **`npm run ui:build`** | 🔴 **必跑**。ui 的 `dist` 是构建产物，**dev 轨道解析的就是它**（CLAUDE.md 开发命令行原话）——不重建则 dev 里看不到任何变化，会造成「改了没反应」的假阴性 |
| 3 | bump `packages/linkdesk-ui/package.json` 版本 | 现读数 **0.2.49** → 下一版 patch。理由：**导出面只加不改**（甲/乙两形状见 [01 §六](01-方案与落点契约.md)）⇒ 不涉 minor；若 D3 选「新增导出字段」仍属 patch 级追加 |
| 4 | `npm install` ＋ **`npm run check:lockfile-sync`** | 升 `packages/*` 版本后**必须**重跑 `npm install` 并**同笔**提交 lock（CLAUDE.md 开发命令行原话） |
| 5 | `npm run ui-surface:regen` 看账本 diff | `scripts/ui-surface.json`（导出名 → `since`）与 `check-ui-surface-additive` 守「只加不删」。本方案**不改导出名** ⇒ 期望 **diff 为空**；若因 D3 追加字段而变动，须确认是**追加**（缺 `since` 即红） |
| 6 | **`npm run check` 全绿** | 含 `audit-i18n --strict`（词典覆盖）· 字面量门 `linkdesk/no-hardcoded-chinese` · `check-no-deferred-placement` · `check-design-flow` · `check-spacing-grid` · `check-token-audit` · `check-css-hardcode` · `vitest run`（本夹新增的英文态断言在此跑） |
| 7 | 根 `CHANGELOG.md` **当前版本段**加一行 ui 条目 | 先例：`0.2.48`／`0.2.49` 都写在根 CHANGELOG 的当前段（「独立发版——共享 UI 包，软件本体不动」句式）＋ `check-changelog-section`／`check-version-bump` 门 |
| 8 | `npm run release:mark` → `npm run build` → `npm run publish` | `publish` **不重建**、只上传仓内产物（CLAUDE.md 硬约束 24）⇒ 先 build 再 publish；`check-npm-release`（判据⑤ 对货不对号）兜底 |
| 9 | 实机验收 | dev 起壳：四处输入框圆角（[02 E1–E8](02-边缘情况清单.md)）＋ 切英文看四处文字（E9–E16） |

**⛔ 本轴不需要的动作**（写明免得多做）：

- ⛔ **不起插件收录**——本次**零插件仓改动**（settings／file-tree／serial-monitor 一行不动）。理由：共享件随 `@linkdesk/ui` npm 包供货、由宿主构建时并入（插件**不打包**共享件，且 SDK 有腿禁插件 `import` ui 的 css）⇒ 插件侧无需跟版。若落地后实测发现**插件仓需要跟改**（例如它在本地复制了同名样式），那要**单独报告**再决定，⛔ 不许静默扩面。
- ⛔ **不发壳版**：本改动随下一批壳发布自然带到 dev／安装版（`build-pool-vendor` 有保鲜），不单独发。
- ⛔ **不动 `lang-defaults` 种子**：词典(编辑器插件自带 `"编辑器": "Editor"`)全，本次只补**调用**。

## 三、翻译三处纪律（本次只动第 ③ 处，⛔ 另两处别碰）

| # | 处 | 内容 | 本次 |
|:--:|:--|:--|:--|
| ① | 壳侧词典 | 壳自己 UI 词条 | ⛔ 不动 |
| ② | 插件侧词典 | 插件自带 `i18n/*.json`（编辑器插件 `"编辑器": "Editor"` 在此） | ⛔ 不动（**已全**，不是缺货问题） |
| ③ | **调用点** | `t()` 有没有被调 | ✅ **本次唯一改动面** |

⚠️ **实现纪律**：⛔ **不许**把具体插件名**硬编码**进 `t("编辑器")` 来「修好它」——那样字面量门会放行（包了 `t()` 就算合法）而 `audit-i18n` 会要求词条在册，看着很绿，实际对**任意第三方插件名**毫无用处。**必须是 `t(变量)`**（变量 = 模型吐的显示名原文）。这条纪律写进 [05](05-派工与交接.md) 的「谁许动」栏。

## 五、风险与护栏

1. **`ui:build` 忘跑** ⇒ dev 假阴性。护栏：§一.2 写死在次序里；交接时列为「下一棒第一件事」。⚠️ 报告判据：dev 里输入框仍是直角 ≠ 改动没生效，先问「dist 重建了吗」。
2. **导出面破坏**（D3 若更名）⇒ 违「只加不删」承诺。护栏：`check-ui-surface-additive`；更名一律走追加式。
3. **顺手扩面**（例如「既然改了 `InlineInput`，顺便把 `SelectBox` 触发器 2px 也统一成 4px」）⇒ ⛔ 不许。[02 E7](02-边缘情况清单.md) 已登记为「另立决定点」。
4. **门禁放宽凑绿**（例如给 `audit-i18n` 加白名单）⇒ ⛔ 绝对禁止。任何一条跑不通时改**实现**或**改口径并留痕**。
5. **提交纪律**：逐条**点名路径**（⛔ 不用 `git add -A`——工作区常有别的工作流在途，例：本会话期间 `docs/04-软件更新/00-README.md` 就带着别批未提交的一处新增行）。
