## 二、设计决策（每条都带理由）

1. **只抽「有第二个消费方」或「判定分支值得单独钉住」的纯逻辑，⛔ 不为凑覆盖率把视图拆稀碎。** 四处抽取各有实据：`dest` 是模块私有的三支判定（实机已验证落点却零单测）；`thumbs` 的两道换算内联在视图里且**同时要读两个常量**（162/164 极易写错，实机槽高 229 就是它）；`windowRange` 原先**内联了三份**（阅读区挂载、阅读区 drain、缩略图条）——三份各自漂移是必然；`errorCopy` 原先在 JSX 里三层嵌套三元，改一档文案要动渲染结构。
2. **把中文 key 从 `t("…")` 字面量搬进 `.ts` 数据表是安全的，但必须补一条硬断言。** 事实：`linkdesk/no-hardcoded-zh` 只在 **JSX 上下文**里开火（`node_modules/@linkdesk/plugin-sdk/dist/eslint/rules.js` 的 `isInJsxContext`），纯 `.ts` 表里的中文字面量不会被拦；`ci-verify` ⑧ 段的**源码侧**是一盏**黄灯**（只统计 `t("…")` 出现处），且**没有孤儿键/键被用没用的反向检查**。但是：键搬出 `t()` 后⑧段源码侧就看不到它们了 ⇒ 覆盖判据会**变松**。所以 `errorCopy.test.ts` 里专门加一条「逐键回读 `i18n/en.json` 取非空译名」，把这族的字典覆盖从黄灯挪成**红断言**——判据口径不降，只换到更硬的位置。
3. **`.pdf-reader-hit-current` 被判死类，是壳侧审计的误报，⛔ 不为了「凑绿」把字面量复制一份。** 该类的唯一来源是 `` `${HIT_CLASS}-current` ``（`services/textLayer/highlight.ts`），而 `scripts/audit-plugin-dead-css.mjs` 的动态前缀启发式只看**插值前**紧挨的标识符（`/([A-Za-z][\w-]*)\$\{/`），后缀跟在插值后面的形态它看不见。这类「派生单一来源」正是 T7 要保的东西，复制字面量去骗启发式等于把判据放宽。本档 §四.1 记了实机反证（该 class 在真机上确实挂着、底色确实换了）。
4. **`windowRange` 的文档里写明「放宽方向必须是可视区间之外」**（⛔ 不是从窗口自身再放宽）——写错会白渲染、且边界页（1 / numPages）容易越界。三个调用点共用一处，就是为了让这条语义只有一份。

## 五、教训与诚实边界

1. 🔴 **`unthrottle()` 解不了你自己的读数会话——`Emulation.setFocusEmulationEnabled` 是会话级的。** `scripts/dev/lib/cdp.mjs` 的 `unthrottle(target)` **自己开一条会话**，关掉即失效；而侧栏/阅读区的换档逻辑都是 `requestAnimationFrame` 节流（`onScroll → rAF(recompute)`）⇒ **在没解冻的会话里滚动，窗口永远不换**。本格为此白追一轮（先用合成 `new Event("scroll")` 试、又怀疑监听不在 `.pdf-reader-thumbs` 上）。**判据与解法**：在**同一条会话**里先 `Page.bringToFront` ＋ `Emulation.setFocusEmulationEnabled{enabled:true}`，再做「驱动＋读数」；页内探针 `new Promise(res => { requestAnimationFrame(()=>res("raf-fired")); setTimeout(()=>res("raf-frozen"), 2000) })` 可直接判活——本格实测：同会话带 focus 模拟 ⇒ **`raf-fired`**（随后滚动读数立刻正确）；不带 ⇒ 窗口纹丝不动。⚠️ 副作用：`Input.dispatchMouseEvent`（真轮子）在**未解冻**的会话里会**直接超时**（30s 无回执）——也是这条的连带现象，⛔ 别当成「CDP 不支持滚轮」。
2. 🔴 **池窗里「所有面都挂着、只有活动那张可见」——读数必须限定在可见面。** 本格第一版探针按全文档 `querySelector(".pdf-reader-status")` 取第一个，摸到的是**隐藏的那张面**（用户先前开的面/先前自己的面），于是「doc 认错、槽高读 0、目录找不到」三项一起错，看着像插件坏了。判据 = `[...document.querySelectorAll(".pdf-reader-root")].find(r => r.offsetParent)`，再**在它内部**查一切。
3. **标签 API 是分窗的**：`tabs.create/openOrFocus/focus/close/focusBySourceId/closeBySourceId` 在**主窗**可用而 `list()` 不在（主窗 `Object.keys(tabs)` 只有那 6 个）；池页反过来——`list()` 只看得见它自己那个（空）窗。⇒ **起标签在主窗、读 DOM 在池页**：`tabs.create("pdf-reader", {sourceId, label})`（返回 `undefined`，不抛即成功）会让新面**立刻成为可见面**；同名 `openOrFocus` 返回 `undefined` 且**不保证换面**（本格实测没换过来），所以最终用的都是 `create` ＋（必要时）`focusBySourceId`。
4. ⚠️ **`closeBySourceId` / `create` / `openOrFocus` 都返回 `undefined`**——`JSON.stringify(undefined)` 是 `undefined`（不是字符串），探针里 `.slice()` 会当场炸（本格踩过，白跑一次）。判成功的口径只能是「事后读状态」。
5. 🩸 **仍未在实机上复现的既有观察（⛔ 不是本格缺陷）**：T5 留的「canvas 不跟随换档、文本层与页卡却跟随」一次观察未复现；T5/T6 留的三条诚实边界（`preview.pdf` 字形乱码＝该文档无 `ToUnicode`；搜索浮条底色偏淡＝本机主题洗色 `--bg-card`，归主题侧；无 dest 条目故意渲染成不可点 `span`）**全部照旧**，本格一行未动。
6. ⚠️ **壳侧一处口径缺口（不在本棒可改范围，留给壳仓）**：本仓未进壳仓 `scripts/sync-plugin-agents.mjs` 的 FACTS 表（只列 editor / marketplace / python / settings 四个官方仓），故壳侧各审计脚本把 `pdf-reader` 标为「**第三方·只读**」——而它其实是官方示例级插件。壳仓对本棒**只读**（零 diff 是验收判据），此处只记录，不动手。
