# 01 · 方案与落点契约（T1–T7 逐格规格）

> 本文是 [00-README](00-README.md) §四任务表的逐格展开：每格 = 现状（file:line）→ 改法（改哪、怎么改、改成什么）→ 判据 → 门禁与文档连锁。**本文只规划，不动码**；开工照此逐格执行，边缘情况见 [02](02-边缘情况清单.md)，阶段拆分与文档连锁见 [04](04-任务清单.md)。
> 归属总纲（用户 2026-10-04 口径：无死代码、无硬编码、AI 友好、高内聚低耦合、万物皆可插件）⇒ 四条铁律：
> ① **判定归壳、呈现归插件**——壳只回答「这是什么、谁能开」，绝不画任何文件的内容或兜底页；
> ② **壳不认识任何插件 id**——兜底用**角色挂牌**解析（T7），不写死 `"editor"`；
> ③ **插件只声明、不耦合**——抢默认就声明 `fileAssociations`，做次要方式就声明 `menus.fileContext`＋命令；换掉任何一只，壳与别的插件零改动；
> ④ **默认打开方式的主权在壳（=用户覆盖表，背后是用户），插件只有提名权（声明=候选），文件树只有执行权（查表就开）**——插件永不自封默认。多只 PDF 阅读器共存（微软/Adobe/第三方）与两只编辑器同时挂牌（D7 冲突场景）全靠这条：谁都在选择器里并列，谁也不是特权层。

```
声明面（插件 plugin.json）          判定面（壳，多提供方多消费方）         呈现面（各插件自己画）
contributes.fileAssociations  ──▶  FileAssociationService（映射表        ▶ file-tree：选择器 UI
  [{ext, command?, displayName?,      ＋用户覆盖表＋角色解析）                 ▶ editor：文本/标签内提示页
    role?}]                       ──▶  getPluginFor / listHandlersFor      ▶ pdf·图片·md 阅读器：各自视图
contributes.menus.fileContext   ──▶  MenuRegistry（合并＋when 过滤）     ▶ 任何插件：菜单项
context keys（公共 resourceExtname）▶ ContextKeyService.matches
OS argv／安装器静态清单          ──▶  useOpenPathIntake（同一次解析）
插件装/卸事件                   ──▶  OS 登记同步模块（T6，按壳开关）
```

## T1 二进制守卫＋未关联兜底

**回答用户第一轮追问 7**：不是弹窗（没有要确认的事）、也不只是 toast（**标签区必须画点什么**——现状画的是乱码）。规格：

**现状**：`EncodingService.detect`（`src/core/services/files/EncodingService.ts:132-148`）无二进制检测；editor `EditorModel.load`（`E:\linkdesk-plugins\official\editor\src\services\EditorModel.ts:100-106`）强解文本 ⇒ 乱码标签页。

**改法**：
1. **壳判定**：`EncodingService` 新增纯函数 `isBinary(bytes)`（启发式：首 8KB 内 NUL 字节占比＋控制字符密度，阈值开工时定）并经 files IPC 面暴露（additive，落点按现 API 面探明后定）。
2. **editor 呈现**：`EditorModel.load` 接 `isBinary` ⇒ 标签区渲染**自有 JSX 提示块**（约 30 行，editor 仓自绘）：一句说明「此文件无法作为文本显示（当前以文本打开只会得到乱码）」＋两颗文字钮「打开方式…」（执行 T2 选择器命令）／「在市场搜索阅读器」（复用市场搜索，词=扩展名）＋**右下角 toast 同步一句**（复用现有 toast 通道）。
3. **⛔ 不预造 @linkdesk/ui 组件**（D10）：配方写进作者文档，第二个真实编辑器插件出现时才抽取共享（先例同律：Slider/ReadOnlyText/BackgroundImagePicker 均为「已有真实消费者」才搬）。

**判据**：① `isBinary` 单测（pdf/exe/png 头 → true；md/ts/json → false；负控摘 NUL 检查 → pdf 判假）；② editor 对 pdf 呈现提示页非乱码＋toast 出现；③ 「打开方式…」钮在 T2 未实施前先隐藏（特性开关式接线，不留死钮）。

**文档连锁**：提示串走外仓 `lang-defaults` 发版链（`audit-i18n --strict` 拦）；作者文档「编辑器如何处理二进制」一段（T5 交付物之一）。

## T2 打开方式选择器＋用户覆盖表

**回答用户追问 10（「小本本/右键改/总是用它到底是什么」）——完整交互规格**：

**现状**：`file-tree.openWith` 占位（`navigation.ts:63`）；`FileAssociationService` 无「列全部」无覆盖表；行为分叉（FoldersView 落兜底 vs SearchView 静默不打开，`SearchView/openMatch.ts:11-21`）。

**改法**：
1. **宿主新只读面**：`fileAssociation.listHandlersFor(ext)` → `[{pluginId, displayName, isCurrent}]`（IPC＋preload＋handler，additive）；内部与 `getPluginFor` 共用同一解析纯函数。
2. **解析序归一（一处真相）**：纯函数 `resolveOpenTarget(ext, override?)` = **用户覆盖表 → 声明表（先激活先得＋pluginId 字典序 tie-break）→ 角色兜底（T7）**；FoldersView／SearchView／`useOpenPathIntake.ts:66-71` 三入口同吃（消灭分叉）。
3. **覆盖表 = 壳配置键** `workbench.fileAssociations`（`{".pdf":"pdf-reader-x"}`，D1）：**唯一写入方 = 选择器的「设为默认」**；「恢复自动」删键；**没有点击计数、没有自动学习、设置页 v1 不展示**（防第二处真相源）。
4. **选择器 UI（住 file-tree）**——线框：

```
┌─ 打开方式 ────────────────────────────┐
│ （仅当存在覆盖时显示）                  │
│ 当前默认：X 阅读器        [恢复自动]     │ ←「恢复自动」删覆盖表该键
├──────────────────────────────────────┤
│ ▣ 插件 A（当前默认）   [打开] [设为默认] │ ←「打开」=仅此一次，不落盘
│ ▣ 插件 B              [打开] [设为默认] │ ←「设为默认」写覆盖表并即时生效
│ ▣ 插件 C              [打开] [设为默认] │
└──────────────────────────────────────┘
```
   入口：文件树右键「打开方式…」（主）＋命令面板（次，作用于当前活动文件）。**多选右键**（不同扩展名混合）⇒ 该项隐藏（02 E17）。**「设为默认」对编辑器已声明的扩展名同样可用**（如 .md）——那意味着单击从 editor 换成 X，是用户主权，不禁止但 UI 不诱导。
5. **第二只装上不静默漂移**（D7）：激活事件后发现新声明者且用户从未选过 → toast「检测到另一款 PDF 阅读器，当前默认仍是 X——右键→打开方式可换」（会话内一次）。
6. **设置页管理器（第二入口 · 设置插件升级，用户 2026-10-04 授权）**：新 uiHint `fileAssociationsManager`（先例＝BackgroundImagePicker 式声明即挂：宿主供数据 API、设置插件画 UI），三段式对标 Windows「默认应用」——① 检索框（过滤扩展名/插件名）；② **「需要你做选择的类型」**：仅 handler≥2 的扩展名出现，每行**下拉**选默认（单 handler 不进此区＝E29：没有选择可言）；③ **「按插件浏览」**：每插件展开其声明的扩展名与当前默认（只读为主）——长尾上百扩展靠 ②③＋检索摊开，**⛔ 永不平铺全量**（E30）。OS 登记块降级为本页折叠块（见 T6）。**双向同步**：host 新写面 `fileAssociation.setDefault(ext, id|null)`，选择器与管理器同写覆盖表、即时互见（E31）。🔴 设置页通用能力随之升级：**页内检索、二级视图切换**（壳缺承载则补壳任务——用户已授权）。

**判据**：① 覆盖表写入重启仍生效；「恢复自动」回声明序；② 三入口解析一致（改一处解析，另两处行为跟随——同一纯函数的机械保证）；③ 第二只装上：默认不漂移＋提示出现；④ 选择器在无 handler 时不可达（右键项 `when` 收敛）；⑤ 设置页下拉改动后文件树选择器**即时互见**（双向同步，E31）；⑥ 单 handler 类型不出现在竞争区（E29）。

**门禁与文档连锁**：`workbench.fileAssociations` 进 `check-config-baseline` TARGETS；`listHandlersFor` 进 host-reserved 三账本＋contracts＋`gen-api-surface`＋**AI 手册命令索引**（`manual:build`，`file-tree.openWith` 从占位转正）；新串走 lang-defaults。

## T6 OS 关联与插件状态同步（解「薛定谔的猫」）

**回答用户追问 11（开关归属与形态）**——完整规格：

**🔴 三层口径（动手前先分清——2026-10-04 用户对谈钉死，⛔ 三层不得混改）**：

| 层 | 是什么 | 谁管 | T6 动不动 |
|:--|:--|:--|:--|
| ① 全文件右键项「用 LinkDesk 打开」 | 注册在 `*` 通配（`syswrite.cpp:185-203`），**恒在、与扩展名清单和插件状态无关**——pdf/jpg/mp4 右键都有这一项；它只负责「把文件递进门」 | 安装器静态注册 | **⛔ 不动、也不条件化**（不许做成「装了阅读器才显示」——那会让右键菜单对部分文件凭空消失） |
| ② 「打开方式」子菜单候选 | 按扩展名登记（`OpenWithProgids`）：今天只有 13 个文本类 ⇒ 对 .pdf/.mp4 右键候选里**没有** LinkDesk | 安装器静态半（随包文本类）＋**运行期动态半（本案 T6）** | ✅ 本案主战场：随插件装/卸增撤（下述改法 1/2） |
| ③ 门内默认（文件进来归哪只插件） | Windows 只认识「LinkDesk」整体，递进门就完事；归哪只插件 = 应用内覆盖表→声明表→角色 | 应用内（T2/T7/D7 主权三层） | **与 OS 层无关**——OS 对插件零感知，两层语义互不越界 |

另：双击直接开 LinkDesk 靠 Windows 的 UserChoice（用户手选默认）——**壳只加候选、永不写 UserChoice**（E24，OS 主权在用户）。

**现状**：`syswrite.cpp:60-64` 写死 13 扩展＋ProgId＋全文件右键项。两个病：**第二真相源**（editor 声明 45 ↔ 安装器登记 13，已漂移）；**薛定谔态**（登记时刻在安装期、插件状态在运行期）。

**改法（三步）**：
1. **静态清单瘦身＋构建期生成**：随包 6 基础件的 `fileAssociations` 在安装包构建期**机械收割**（构建链已拉随包件、`bundled-plugins.lock` 在账）→ 生成 `syswrite.cpp` 数组。随包件全文本类 ⇒ 静态默认**不薛定谔**。**exe 永不登记**。
2. **运行期同步（归壳）**：主进程新模块订阅插件装/卸/激活事件 → 对「该插件声明了、随包件未声明」的扩展名按壳配置**增/撤** OS 登记（HKCU `OpenWithProgids`，per-user 无需提权）。
3. **开关（壳的，不是插件的）**：配置键 `app.osAssociations.followPlugins`（总开关，默认**开**）＋ `app.osAssociations.overrides`（稀疏逐类关，如 `{".pdf":false}`，v1 不出 UI、留作将来高级位）。**设置页形态（D6 修订）**：OS 块**降级**为「默认打开方式」分组底部的折叠块（summary 写明语义「关 = 停止替插件登记并撤回运行期已登记；安装器静态随包类不动；应用内默认不受影响」）＋一行只读状态——**逐类胶囊开关退役**（语义不明，用户 2026-10-04 点破）；**pdf 插件自己不声明任何开关**（OS 登记是壳的动作，开关归壳）。
4. **与「安装器-更多配置」合账**：安装时勾选 = 这份账的静态半；运行期同步 = 动态半。⛔ 不立第二处真相源。

**判据**：① 构建期清单与随包件声明逐字节一致（负控：手工塞未声明扩展 → 门禁红）；② 装阅读器 → OS 候选出现 LinkDesk；卸载 → 撤＋设置页该行消失；③ exe 永不出现；④ 总开关关 → 运行期登记全撤、静态不动；⑤ **①层恒在项回归验证**——安装前后任意文件类型右键「用 LinkDesk 打开」都在（T6 不得触碰 `*\shell` 项，对应上方三层口径表）。

**文档连锁**：两个新配置键进 `check-config-baseline`＋AI 手册；设置页新串走 lang-defaults；`syswrite.cpp` 生成脚本进安装器构建文档。

## T7 DEFAULT_TAB_TYPE 去硬编码（角色挂牌）

**回答用户追问 9（两只编辑器同时挂牌怎么办）**——冲突规格并入 D7 同一套仲裁：

**现状**：`tabs.ts:14` 写死 `"editor"`；file-tree 没写死（传空串）。

**改法**：① schema：`fileAssociations` 条目加可选 `"role"`（首版仅 `"text-fallback"`）；② 壳：`FileAssociationService` 建角色索引，`tabs.ts` 兜底改 `resolveFallbackTabType()`＝查「当前激活的挂牌者」——**解析序与 T2 完全同构：用户覆盖（覆盖表可写 editor role 吗？可——`workbench.fileAssociations` 的键本来就不限类型）→ 先激活先得＋字典序 tie-break → 无挂牌者走 T1 提示页语义**；③ editor 45 条原样保留、同笔补 role；④ **冲突零特殊逻辑**：极客编辑器挂牌装上（官方未卸）⇒ 默认**不静默换人**（先激活先得=官方 editor）＋toast 提示＋选择器两家并列——极客自己电脑上卸了官方再装自己的 ⇒ 只剩一家挂牌，自然接管。**同一套机制天然覆盖两个场景，无需为冲突写新规则**；⑤ `FALLBACK_PLUGIN_ID="welcome"` 不动（视图加载失败是另一件事）。

**文档连锁**：schema 四份拷贝（`check-plugin-schema-sync`）＋作者面 `role` 字段说明＋`FileAssociationService` 单测。
