# 06 · 组件户口与组合纪律（私有视图件 ↔ 共享组件）

> 2026-10-04 用户问询定稿（原话：「组合后是不是个新组件？」「共享组件居然能组合吗？」「还是说是文件树自己把组件组装起来自己用？」）。本文是**全案通用判据页**：任何「要不要造组件／造在哪／算不算共享件」的问题先过 §一 的表。选择器面板的具体落格在 [01 §T2 组件落格](01-方案与落点契约.md)；共享件的正典写法样板 = [03-组件规格](03-组件规格-按插件浏览-插件卡.md)（PluginCard）。

## 一、两级户口（核心判据）

组合的产物**是**一个新组件（一段新的组件代码）——但「新组件」≠「新**共享**组件」。户口决定它受什么门禁管：

| | **私有视图件** | **共享组件** |
|:--|:--|:--|
| 住哪 | 插件仓／壳仓视图目录 | `src/components/shared/` ＋ `@linkdesk/ui` 导出（`packages/linkdesk-ui/src/index.ts` +1 行） |
| 消费者 | 一家 | **≥2 家真实消费者才准入（D10 律）** |
| 发版 | 随插件／壳发版 | ui 包 npm 0.2.x 独立发＋宿主 CSS 清单重生＋CHANGELOG（[03 §7](03-组件规格-按插件浏览-插件卡.md)） |
| 门槛 | 「先用共享原子」纪律（§二） | 03 式规格：props 正表／token 消费表／可及性／解剖板＋硬约束 16 |
| 改坏波及 | 一家 | 所有插件 ⇒ 这就是它必须有规格与门禁的原因 |
| 本案实例 | 选择器面板（v1，file-tree） | `PluginCard`（已拍板造进共享包） |
| 同户口先例 | file-tree 自家 `Menu.tsx`、设置插件 `SettingRow.tsx`、editor 二进制提示（D4 拍板：约 30 行自绘） | `ContextMenu`／`OverlayPortal`／`PluginIcon`／`Badge`／`SourceBadge`/`EffectiveBadge` |

## 二、组合图景（选择器面板 v1 = file-tree 私有件）

```
file-tree 插件仓（自己家）
└─ OpenWithPanel（新写的面板 JSX，约 30–50 行）        ← 新组件，户口 = file-tree 私有
   ├─ OverlayPortal   ← 共享件（管「浮起来」：层级表/裁剪/Esc/锚定）
   ├─ PluginIcon      ← 共享件（管行图标：manifest 四源裁决）
   ├─ Badge           ← 共享件（管「当前默认」标记）
   └─ 行布局与双动作按钮（自己写）                    ← 唯一的新代码
```

共享包共享的是**原子与约定**（token／层级表／Esc·锚定规矩／图标裁决链——E5.7#14 浮层归一化把「怎么浮起来」收归 OverlayPortal 地基，各家只管「浮出来画什么」），**不是**「每个界面一个现成大件」。

⛔ **「私造」的真正含义 = 绕过共享原子手搓底座**（自画浮层层级／自写图标解析／硬编码色值／另立第二套弹出机制），**不是**「插件里出现了新 JSX」。插件视图里用共享原子拼新面板 = 纪律的正确执行，正是本条的合法形态。

## 三、组合是既定模式，不是权宜——三证

1. **`ContextMenu` 本身就是组装物**：`ContextMenu.tsx:27,29` import `OverlayPortal`＋`KeybindingHint`——右键菜单件内部就是拿浮层底座＋快捷键原子拼的；
2. **`EffectiveBadge` 头注正典**：「与 `ReadOnlyText` 是**组装关系非变种**：值文字段复用 ReadOnlyText 原子画」——代码库自带这个词；
3. **设置插件 `SettingRow.tsx`** 一行同屏组装 `SourceBadge`＋`EffectiveBadge`＋`ContextMenu` 三个共享件（用户天天在用的设置行就是这么造的）。

## 四、转正通道（私有件 → 共享件）

私有件出现**第二个真实消费者** → 照 [03 的写法](03-组件规格-按插件浏览-插件卡.md)（props 正表／解剖板／token 消费表／发版链与「壳不发版·dev 验收」策略）抽进 `src/components/shared/` ＋ ui 包导出发 npm。

- **已挂账待转正**：`OpenWithPicker`（选择器面板——触发条件：第三方文件管理插件／设置页要内嵌同款选择器；见 [01 §T2](01-方案与落点契约.md)）。
- **反面判据**：⛔ 不为假想消费者预造——D4/D10 已裁：警告配方 v1 editor 自绘，**第二只真实编辑器插件出现**才抽共享件（Slider/ReadOnlyText/BackgroundImagePicker 同律：先有真实消费者后搬移）。
