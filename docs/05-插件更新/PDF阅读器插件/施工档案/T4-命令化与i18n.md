## 二、设计决策（每条都带理由，别当成风格）

1. **id 前缀 = `pdf-reader.`（点号）**。文档与规格旧稿写的是驼峰 `pdfReader.`，两者只能活一个：id 第一段恒为本仓 `pluginId`（`check-command-ownership` 的判据），而 `pluginId` 是 `pdf-reader` ⇒ 全部改成点号形态，壳仓 7 份文档同笔对账（零残留）。⛔ 不保留旧写法别名（无死代码）。

2. **入口顶层注册、常驻**（`src/index.tsx` 顶层副作用调 `registerReaderCommands()`，幂等）。理由 = 21-规范 §7 之三第 1 条点名的坑：能在外层注册就别拖到视图 mount——否则「一份阅读器都没开过」时外部 AI 的 `getCommands()` 里根本没有这些 id，只能先撞一次 EUNKNOWN 再猜。本仓 handler 注册时不需要 store（目标在**调用时**才寻址）⇒「能在外层」成立。
   **配套决策：⛔ 不调 `unregisterCommands`**。那位口径是「视图没了、视图态命令就该没」，而本仓每条命令在空态都能**如实作答**（`no-document` / `hasDocument:false`）——读数面恰是「现在开着没有」的答案，不是空转。关标签只销 store 的号，命令面留着。
   池侧对「打到未注册命令」还有 on-command 激活链（缺命令 → `import()` 属主入口 → 入口顶层副作用装上 handler → 重试命中，先例 = serial-monitor）。

3. **meta 只带显示面三项**（`title`/`category`/`when`）；`description`/`params` **只写在 `plugin.json`**。理由：两处都写 = 两份文案迟早分叉；壳的池侧重注册「有值才覆盖」，不会抹掉声明面那份。

4. **params 的窄门与「载荷 vs 点名」**。本仓每条命令**只声明一个** `args` 对象参数（21-规范 §7 之三第 2 条：≤1 个 params 的命令**不展开**那个对象）⇒ 同一个 handler 既收具名 `{ page: 3 }`、也收逐位 `(3)`。
   🔴 **咬过一次**：`setBackground("night")` 的**逐位那一位是载荷（底色名）**，不是点名——首版把任何字符串实参都当 `sourceId` ⇒ `bad-source`（实机扫出，单测逮住）。正解 = `readTarget(args, payloadKey)` 两条判据：① 首位是**具名对象** ⇒ 在它里面认 `sourceId`（具名/逐位两形都走这条）；② 首位是**字面量** ⇒ 只在该命令**自带载荷键**（`payloadKey` 非 null：`gotoPage`→`page`、`zoomTo`→`scale`、`setBackground`→`bg`）时当载荷，无载荷的命令（`pageNext`/`fitWidth`/`getStatus` 这些）才当点名。
   于是 `gotoPage(5)` / `zoomTo(2)` / `setBackground("night")` 逐位那一位都是**载荷**；`getStatus("C:/docs/a.pdf")` 无载荷 ⇒ 逐位那一位**是点名**（实测命中点上那份）。

5. **回执三态**（21-规范 §7.4）——坏参数**走在载荷里不抛**（抛出去会变成用户可见的红 toast），点名找不到**列出可用的**，⛔ 不静默回退：

| 形态 | 何时 | 形状 |
|:--|:--|:--|
| 真做了 | 状态确实变了 | `{ ok:true, sourceId, field, previous, value, … }`——翻转类带**改动后读回**；翻页附 `numPages`，缩放附 `zoomMode` |
| 没做但不是失败 | 已在首页/末页、已适宽、已是该底色、一份都没挂 | `{ ok:true, noop:true, reason:"at-first-page｜at-last-page｜already-fit-width｜already-fit-page｜already-night｜no-document" }` |
| 这次调用本身错 | 坏参数/点名不存在 | `{ ok:false, noop:true, reason:"bad-page｜out-of-range｜bad-scale｜bad-bg｜bad-source", error:"…（点名找不到时列出：现有 …｜…）" }` |

🎯 **只有缺省寻址（无 id）才允许「活跃 → 第一份」回退**；点名点不到一律 `bad-source`。

6. **`getStatus` 与状态条同源一份数据**：handler 直接转 `store.getStatus()`（T3 落的读函数），⛔ 不另算一份——否则两处读数迟早分叉。

7. **配置项定案一条**：`pdf-reader.defaultZoom`（`enum ["fitWidth","fitPage","percent"]`，`default "fitWidth"`，2026-10-07 拍板）＋ `configurationDefaults` 同笔。落地函数 = `readerStore.applyDefaultZoom(mode)`：**只在用户还没自己缩放过时生效**（`userZoomed` 一锁，晚到的配置读数不再踩掉用户刚做的操作）；`percent` 档的「默认」即倍率 1（100%）。底色**不立**配置项（走工具栏钮＋命令同源）。

## 四、实机逮到、当场修好的两个缺陷（都补了回归测试）

1. **翻页/缩放把当前页打回第 1 页**（`src/views/readerSurface/index.tsx`）。缩放重锚读的是 `anchorRef`，而 `anchorRef` 只在滚动处理里刷新；后台窗口 rAF 冻结（`frames: 0`）时滚动处理根本不跑 ⇒ 锚点停在旧值/首屏 ⇒ 缩放以 `scrollTop = 0` 重算 ⇒ `pageAt(0 + ch/2) = 1` ⇒ `currentPage` 被打回 1，随后 `scrollTarget` effect 又把 DOM 拽回去（store 与 DOM 分家）。
   **修法**：锚点从 store 读（`const page = s.currentPage || anchorRef.current.page`），不再信只被滚动刷新的 ref；另起一个 `useLayoutEffect` 无条件把 `anchorOffsetRef` 跟到当前页。**实测**：`gotoPage 20` → `fitPage` → `fitWidth` 后仍 `currentPage:20`。

2. **同文件双视图，关掉后开的那份会把活着的阅读器一起销号**（`src/services/readerBridge.ts`）。首版registry 是 `Map<sourceId, store>` 单值 ＋ detach 即 delete：同一 `sourceId` 挂第二份视图时把第一份**覆盖**掉，关掉第二份时又按 key `delete` ⇒ 还开着的那份**当场失联**（点它 → `bad-source`）。
   **修法**：改 `Map<sourceId, store[]>`——attach 去重追加、detach 按**实例**销号（给不出实例才退最后一份）、空了才删 key；`resolveReaderTarget` 取最后挂上的那份（= 最近聚焦的那份视图）。
   **已知边界（本棒不改口径）**：同文件多视图下「精确到某一份视图」需要 `tab.id`，而对外寻址键仍是 `sourceId`（两份视图 = 同一份文档的两个视图，语义上本就分不开）——改口径归后续格，⛔ 本棒不动。

## 五、两条环境坑（下棒直接用）

1. **换包 ≠ 换模块：装完必须重载池页/重启**。池的 ESM 模块缓存按 **URL** 键，入口文件名恒为 `index.bundle.js` ⇒ 装上新包后**活着的池仍执行旧模块**。本棒实测现象：`describe` 已列出 11 条（那是 `plugin.json` 的**壳侧占位元数据**），而 `exec` 答「未在池内注册」——因为池里跑的还是 T3 那份 bundle（有视图、无命令）。`Page.reload { ignoreCache: true }` 后即好。
2. **后台窗口 rAF 冻结（`frames: 0`）**：读数前先解冻（CDP `Page.bringToFront` ＋ `setWebLifecycleState{active}` ＋ `setFocusEmulationEnabled`，见 `scripts/dev/lib/cdp.mjs` 的 `unthrottle`），否则渲染/滚动类读数失真——缺陷 §四.1 就是被这条放大的（它是真 bug，但「滚动处理从不跑」的土壤是这条）。
