# 格 2 · 任务 `E6#115`：**只加不删门禁**——把「插件能用的面」冻成快照，缺一项即红

> **一句话**：平台承诺「旧插件在新版本上仍然能跑」，但**今天没有任何门禁拦得住「把插件能用的名字拿走」**——`contracts:check` 是 d.ts 生成**字节比对**（管「生成器与产物一致」），`scripts/check-api-contracts.mjs` 只管「文档不指向假命名空间」，**两条都不拦删除**。本格把「插件能用的面」抽成一份快照，与**上一个已发布 tag** 比对：**新增放过，缺项/改名判红**。
>
> **编号**：`E6#115` ｜ **轮次**：第 8.2 轮 ｜ **队列位置**：**第 2 棒（共 6 棒）**
> **前置**：无硬前置（与格 1 互不依赖，可换序）｜ **提交轴**：壳仓 `scripts/` ＋ `package.json`（挂 check 链）＋ 文档
> **规模**：一个生成器（面快照）＋ 一个门禁（diff ＋ 判红）＋ `--self-test` ＋ 一条基线。**预期零 `src/` 行为改动、零 SDK 改动、零发版**
> **非新能力声明**（`check-design-flow` §8.4 ③）：本格产出的是**维护者侧的一条门禁**（比对自己仓里两个版本的面），**不新增对外 API、不给作者新能力、不改产品运行时** ⇒ **无需新能力设计前置**。文中出现的 `window.linkdesk.` / `contributes.` 是**被快照的对象名**，不是要新增它们。

5. **基线纪律**：tag **不许改**（改 tag / 重写历史会让基线变，见总纲 §六第 7 条）。

## 二、要做（**五步，缺一即半成品**）

### 第一步：面快照生成器 `scripts/gen-api-surface.mjs`

- 输出 `scripts/host-api-surface.json`（**随版本提交**，进 git）：
  ```
  { "version": 1, "generatedFrom": "<生成器口径说明>",
    "apiNamespaces": { "<ns>": ["<member>", …], … },      // ① 排序，集合语义
    "manifestFields": { "<path>": ["<enumA>", …], … },     // ② 字段与枚举
    "hostClassNames": ["ldk-…", …],                        // ③ 只收 ldk- 与账内保留名
    "reservedKeyframes": ["ldk-…", …],
    "ledger": { "commandPrefixes": [...], "configKeys": [...], … } }  // ④ 账各栏
  ```
- **集合语义**：数组**排序后**写入 ⇒ 只改顺序/注释**不产生 diff**（否则天天假红）。
- 挂 `"api-surface:regen": "node scripts/gen-api-surface.mjs"`；生成器自身带 `--check`（生成物 vs 实况一致，供人手工核）。

### 第二步：门禁 `scripts/check-api-surface-additive.mjs`（**进 `npm run check`**）

- 取**上一个 git tag**（`git describe --tags --abbrev=0` 或按 `v*` 语义取最近 tag）里那份 `scripts/host-api-surface.json`，与本工作区**重算**的面做 diff：
  - **缺项 / 改名 ⇒ 🔴 红**（打印：`面被拿走：apiNamespaces.plugins.xxx` ＋ 提示「若是有意的退役 ⇒ 走退役登记 `E6#116`」）。
  - **新增项 ⇒ 🟡 提示**（「面变多了——记得跑 `npm run api-surface:regen` 更新快照」；**不红**，因为「只加」正是被允许的方向）。
  - **tag 里没有快照**（本门禁首次落地）⇒ 跑 `--init` **建立基线**（把当前面写成快照，并在档里写明「基线自本格开始」），⛔ **不许静默放行**。
- 三条**硬边界**写进脚本头注：① 比的是**集合**（排序无关）② 只比**已发布 tag**，比不到就报「无法判定」并红（**离线/浅克隆 ⇒ 拒绝，不静默放行** —— 照 `release:mark` 的离线口径）③ **失败要给出可执行的下一步**（改回 + 走退役登记，二选一）。

### 第三步：自测（`--self-test`，正控 ≥ 负控）

- **正控 1**：桩「上一版快照」里删掉一个 API 成员 ⇒ **红**，且报点带成员名。
- **正控 2**：桩里改动一个类的名字（改名 = 一删一加）⇒ **红**。
- **负控 1**：桩里**新增**一个成员 ⇒ **不红**（黄灯提示）。
- **负控 2**：桩里只改**数组顺序 / 注释** ⇒ **不红**（集合语义的直接证据）。
- **负控 3（离线）**：拿不到 tag（桩一个空仓库）⇒ **红**（拒绝判定，不是「放行」）。

### 第四步：真跑一次红（**本格的「门禁真醒着」证据**）

- 在工作区**临时**删掉一个对外面（例如 `src/core/api/linkdesk-api/` 里某接口的一个成员）⇒ 跑门禁 ⇒ **EXIT=1**；`git checkout` 还原 ⇒ **sha256 与改前逐字节相同** ＋ 门禁回绿。
- ⚠️ 还原用 `git checkout -- <显式路径>`（本格动的是源码文件，不是生成物）；⛔ 不许 `git add -A`。

## 四、禁区

1. 🔴 **不许引白名单 / 豁免名单 / 基线棘轮**（禁区）：要放过某一项，**只能改机制**（例如它根本不是对外面 ⇒ 不列入快照的四栏之一，且把理由写进档）。
2. ⛔ **不许把「新增」判成红**——「只加不删」是被允许的方向；判红 = 把正常演进逼成绕过。
3. ⛔ **不许静默放行**：拿不到基线（tag 缺失/离线/浅克隆）必须**拒绝判定并红**（照 `release:mark` 的离线口径）。
4. ⛔ **不许改 `contracts:check` / `check-api-contracts.mjs`**（它们各管一件事，本格只**补**第三条）。
5. ⛔ **不许改 `src/` 行为**（本格只读面、只加门禁）；⛔ 不许改 tag、不许重写历史。
6. ⛔ **不许只比工作区**（必须比**已发布 tag**）——比工作区等于「自己跟自己比」，永远绿。
