## 二、核心准入原则（本纠正案的**判据源头**）

### 2.1 判据 A · 声明对等律

> **一个控件的用途若是「消费宿主声明」，它必须住在声明方与渲染方都够得着的地方（壳 / `@linkdesk/ui` 共享件），
> ⛔ 不得住在任何「可被用户卸载」的插件里。**

「宿主声明」的清单（非穷举，按实质判断）：

| 宿主面 | 声明来源 | 例子 |
|:--|:--|:--|
| 插件清单 / 图标 / 名称 | `pluginManager.list()` | 插件卡、处理器行 |
| 文件关联声明 | `contributes.fileAssociations` | 打开方式面板、竞争区 |
| 配置项 | `contributes.configuration` ＋ `configuration.get` | 设置页渲染器 |
| 主题 / 图标主题 / 键位 | 各自声明面 | ThemeEngine、快捷键页 |

### 2.2 三问决策链（**放任何东西之前必须走**，写进作者手册与 AI 手册）

```
Q1 它消费谁的数据？
     └ 宿主声明（上表） ⇒ 判据 A 定案：**壳或共享件**，与「现在有几个消费者」无关 ⇒ 结束
     └ 插件自己的私有数据 ⇒ 进 Q2
Q2 它要不要被 ≥2 处渲染 / 被别的插件用到？
     └ 是 ⇒ `@linkdesk/ui` 共享件
     └ 否 ⇒ **插件私有**（此时才允许私有；并写「私有」的理由注释）
Q3 它是不是一个**动作**（要能被 AI/CLI/别的插件触发）？
     └ 是 ⇒ **壳命令** ＋ `@linkdesk/plugin-sdk` helper（⛔ 别做成插件内部函数/事件）
```

### 2.3 D10 的口径校正（⛔ 最容易被人拿来当挡箭牌的一条）

| D10 原文含义（继续守） | 被废止的**反向用法** |
|:--|:--|
| 进共享池要 **≥2 个真实消费者**——⛔ 不为**假想**消费者预造共享件 | ⛔「现在只有 1 个消费者 ⇒ 先住在它里面，将来有第二个再共享」 |

**为什么不矛盾**：D10 管的是**「要不要为还不存在的需求提前造共享件」**（防过度设计）；
判据 A 管的是**「已经有人需要的能力该住哪层」**（防能力私有化）。
今天这个 bug 的成因正是把 D10 的反向用法当理由——**第二个消费者还没来，宿主能力就已经被插件把持了**。

### 2.4 落位判据表（可直接查表）

| 能力的性质 | 该住哪 | 先例 / 反例 |
|:--|:--|:--|
| 消费宿主声明的视图/控件 | **壳 或 共享件** | ✅ `PluginCard`（宿主清单）；❌ 打开方式面板（原住 file-tree） |
| 被 ≥2 处渲染的 UI 块 | **共享件** | ✅ `Button`、`PluginCard` |
| 只服务本插件私有数据、只被本插件渲染 | **插件私有**（并在注释写「私有 · 理由」） | ✅ `BinaryNotice`（判定的呈现归被兜底的插件） |
| 要能被 AI / CLI / 别插件触发的动作 | **壳命令 ＋ SDK helper** | ✅ `workbench.action.*` 家族；❌ `file-tree.openWith` |
| 纯函数工具（归一化、解析） | 壳 core 或工具包（**一处定义**） | ✅ `normalizeExt`（⛔ 别在插件里抄一份） |

## 三、机械层任务卡（**本格主体**）：五条门禁腿

> 落点照既有 `scripts/check-*.mjs` 家族（`check-manual-surface.mjs`、`check-doc-links.mjs`、`check-native-title`、`check-claude-md`…），统一挂 `npm run check`。
> 🔴 **每条腿必须自带负控**（本仓纪律：门禁要能**自证真会红**）——照 `check-manual-surface.mjs --self-test` 的写法：合成样本必须被判出、干净样本必须 0 命中、路径不误伤。

### R1 · 跨仓硬编码宿主命令 id（`check-no-foreign-command-ids.mjs`）

- **域**：`/e/linkdesk-plugins/official/*/src/**` ＋ 壳 `src/**`（排除测试与本文档）。
- **判据**：插件源码里出现 `"<别的插件id>.<命令名>"` 形式的字面量 ⇒ **红**（例外白名单：`file-tree.openWith` 兼容转发注册处，白名单**必须带到期说明**）。
- **怎么自证**：样本 `executeCommand("file-tree.openWith", p)` ⇒ 命中；`SHELL_COMMANDS.openWith` ⇒ 不命中。
- **这一腿今天就抓得住 3 处**（`settings` 常量、`editor` 常量、`file-tree` 自己）——**先跑给用户看它红，再修**（能抓住才算门禁）。

### R2 · 宿主能力私有化（`check-host-capability-placement.mjs`）

- **域**：`/e/linkdesk-plugins/official/*/src/**`。
- **判据（两条，命中任一 ⇒ 黄/红，附人工白名单机制）**：
  1. 插件源码里同时出现「`OverlayPortal`（或自建 `position:fixed` 弹层）」＋「`fileAssociation` / `pluginManager` 读取」⇒ **红**（＝在插件里渲染宿主声明 = 住错层的形状）；
  2. 插件源码里出现 `import ... from "@/core` / `@/components/shared` 之外的壳内部路径 ⇒ **红**（插件只能经 `@linkdesk/ui` / `@linkdesk/plugin-sdk` / `window.linkdesk`）。
- **为什么用「形状」而不是「名单」**：名单会被绕过（改个名就过）；形状（读宿主声明 ＋ 画弹层）抓的是**行为**。
- **白名单**：`file-tree` 的兼容转发期允许举例外，须写明到期条件。

### R3 · 菜单项可执行律（`check-menu-items-executable.mjs`）

- **判据**：本仓/本插件代码里出现菜单项 `command` 时，该 id 必须能从**命令声明面**（同仓 `plugin.json` 的 `contributes.commands[]` 或壳命令表）找到；⛔ 找不到 ⇒ 红。
  （这条当场抓得住 [02](./02-归一化-齿轮锚点与假菜单项.md) §四 的空转项——它指向的是**别的插件**的命令。）
- **配套（运行期半条）**：dev 构建下 `executeCommand` 遇未注册命令 ⇒ `console.error` 带命令 id（⛔ 生产静默不变）。
- **自证**：样本菜单项指向不存在的命令 ⇒ 命中。

### R4 · 同一能力的第二份实现（`check-duplicate-capability.mjs`）

- **判据（启发式，只报可疑不判死）**：跨插件出现 ① 同名组件文件（如两个 `OpenWithPanel.tsx`）② 同一 CSS 类前缀（如 `file-tree-*` 与 `editor-*` 里出现同形弹层）③ 同一条宿主数据的两种渲染入口 ⇒ **报黄**并在 CI 摘要里点名。
- **定位**：这一腿**允许误报**（宁可多报一次让人看一眼），⛔ 但**不允许漏掉已知形状**。

### R5 · 宿主命令常量对账（`check-shell-command-constants.mjs`）

- **判据**：壳侧常量模块的每个 `SHELL_COMMANDS.*` 值，在 `@linkdesk/plugin-sdk` 的同名常量里逐字相等（壳不依赖 SDK，只能机器对账——[04](./04-契约API与文档连锁.md) §三）。
- **自证**：故意改一边 ⇒ 红。

### R6（低成本顺手）· 共享件零壳依赖

- **判据**：`src/components/shared/**` 内出现 `window.linkdesk` / `import … "@/core` / 硬编码中文（已在别处守的照旧）⇒ 红。确保共享件「拎出来就能给第三方用」（判据 A 的前提）。

**交付物**：6 个 `scripts/check-*.mjs` ＋ `package.json` 的 `check` 串联行 ＋ 各腿的 `--self-test` 通过记录。⛔ 不许「先写腿不加负控」——那属于本项目已定性的「只改字不加尺」。
