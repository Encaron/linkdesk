### 现在怎么工作的

```
plugin.json                     loader                         viewRegistry                SidePanel
"sidebar": "src/sidebar.tsx" → import.meta.glob(           → registerViewPlugin({       → getViewPlugin(id)
                               sidebar.tsx) → import()        sidebarComponent: ...       .sidebarComponent
                               → sidebarComponent                                         → <SidebarComponent />
```

1. 每个视图插件在 `plugin.json` 声明 `sidebar: "src/sidebar.tsx"`

> 核心新增。准入三条全满足——① 多提供方：任何插件可注册 view  ② 多消费方：SidePanel + 未来底部面板  ③ 桌子不知道 view 内容。

### E36#1 ViewContainerService 类
**文件：** 新 `src/core/ViewContainerService.ts`  
**行数：** ~50 行  
**新增/改：** 新文件

**做什么：** 在 `src/core/` 下新建一张桌子。继承 `RegistryBase`（已有基类，`src/core/RegistryBase.ts`，登记注销自动对称）。

```typescript
// src/core/ViewContainerService.ts

import { RegistryBase } from "./RegistryBase";
import { Emitter } from "./CoreEvents";

export interface ViewContainerDescriptor {
  title: string;
  icon?: string;
}

export interface ViewDescriptor {
  id: string;
  title: string;
  render: React.ComponentType;
}

export interface ViewContainerChangeEvent {
  containerId: string;
  views: ViewDescriptor[];
}

export class ViewContainerService extends RegistryBase {
  private containers = new Map<string, ViewContainerDescriptor>();
  private views = new Map<string, Map<string, ViewDescriptor>>();
  // key = containerId, value = Map<viewId, ViewDescriptor>

  private _onDidChangeViews = new Emitter<ViewContainerChangeEvent>();
  readonly onDidChangeViews = this._onDidChangeViews.event;

  registerViewContainer(containerId: string, descriptor: ViewContainerDescriptor): void { ... }
  getViewContainer(containerId: string): ViewContainerDescriptor | undefined { ... }

  registerView(containerId: string, descriptor: ViewDescriptor): void { ... }
  getViews(containerId: string): ViewDescriptor[] { ... }   // 按注册顺序

  // RegistryBase 要求实现——插件卸载时清掉它注册的所有 view
  unregisterAll(pluginId: string): void { ... }
  // 遍历 this.views → 找到所有 pluginId 注册的 view → 删除 → fire onDidChangeViews
}
```

**Why：** 大厅新桌子。和 `CommandRegistry`、`ConfigurationRegistry`、`FileDecorationRegistry` 同一模式——Provider 登记、Consumer 查询、卸载自动清理。

**数据结构关键决策：** `views` 是 `Map<string, Map<string, ViewDescriptor>>`——两层 Map。外层 key = containerId（"explorer"/"serial-monitor"/"marketplace"），内层 key = viewId（"folders"/"sessions"/"installed" 等）。内层 Map 的插入顺序 = 注册顺序 = 侧栏从上到下的渲染顺序。

**验证：**
1. `new ViewContainerService()` → `getViews("explorer")` 返回 `[]`
2. `registerView("explorer", { id: "test", title: "测试", render: TestView })` → `getViews("explorer")` 返回 `[{ id: "test", ... }]`
3. `unregisterAll("test-plugin")` → `getViews("explorer")` 回到 `[]`
4. 连续注册 3 个 view → `getViews` 返回顺序 = 注册顺序

```typescript
  const containers = plugin?.manifest.contributes?.viewsContainers;
```

### E36#5 PluginManifest 类型 + loader 解析
**文件：** `src/core/types.ts` + `src/pluginLoader/loader.ts`  
**行数：** ~40 行（types.ts ~15 行 + loader.ts ~25 行）  
**新增/改：** 类型定义 + parseContributions 新增解析逻辑

**types.ts 新增类型：**
```typescript
// 在 PluginManifest 接口的 contributes 中新增
interface PluginContributes {
  // ... 现有字段 ...
  viewsContainers?: Record<string, { title: string; icon?: string }>;
  views?: Record<string, Array<{
    id: string;
    title?: string;
    render: string;      // 模块路径，如 "src/views/FoldersView.tsx"
    when?: string;        // context key 条件
  }>>;
}
```

**loader.ts 新增解析逻辑：**

在 `parseContributions` 函数末尾加：
```typescript
// 解析 viewsContainers
if (manifest.contributes?.viewsContainers) {
  for (const [containerId, descriptor] of Object.entries(manifest.contributes.viewsContainers)) {
    ViewContainerService.registerViewContainer(containerId, {
      title: descriptor.title,
      icon: descriptor.icon,
    });
  }
}

// 解析 views——动态 import render 组件
if (manifest.contributes?.views) {
  for (const [containerId, viewDefs] of Object.entries(manifest.contributes.views)) {
    for (const viewDef of viewDefs) {
      // 异步 import 视图组件
      const renderModule = await import(/* @vite-ignore */ viewDef.render);
      const RenderComponent = renderModule.default ?? renderModule;

      ViewContainerService.registerView(containerId, {
        id: viewDef.id,
        title: viewDef.title ?? "",
        render: RenderComponent,
      });
    }
  }
}
```

**关键决策——声明式 vs 命令式：**
`contributes.views` 中的 `render` 字段声明了模块路径。loader 在加载时动态 import。这和第 3 轮里 `activate()` 中手动调 `registerView` **不冲突**——两者都是合法的注册方式。声明式适合静态 view（marketplace 的"已安装"永远是 4 个固定分组），命令式适合动态 view（serial-monitor 的"收发设置"标题随 activeSession 变化）。loader 只管声明式，activate() 管命令式。ViewContainerService 不区分来源。

**向后兼容：** loader 中**不删除** `sidebar` 字段的解析逻辑——迁移期间两套系统共存。R3 迁移完成后，R4 清理。

**验证：**
1. plugin.json 写 `contributes.views.explorer: [{ id: "test", render: "src/TestView.tsx" }]` → 插件加载 → `getViews("explorer")` 包含 test
2. `render` 路径指向不存在的文件 → import 失败 → ErrorBoundary 捕获，不崩溃
3. 同时声明 `sidebar` 和 `contributes.views` → 两套都生效，不冲突
