# E5.8-跟随主题齿轮恒显档案（#157）

> 2026-08-28。**用户实机：点一次齿轮「跟随主题」后该选项消失，须改配置项才回来。** 用户拍板：**恒显**——「不如一直显示」；同时约束「别把跟随主题带到别的组别中」「别把『资源管理器打开』变成所有都能用」。
> 清单指针：E5.8-执行清单 Phase 11.22 #157。

---

## 一、背景与用户实机证据

用户在设置页齿轮菜单实测：打开任意外观键齿轮 → 见「跟随主题」→ 点击 → 值回主题（或本就已跟随）→ **再开齿轮该选项消失**。要让它回来必须先去改一下配置项（让键重新「被修改」）。用户困惑：「这是你加入的功能吗？」

## 二、根因（file:line）——两处语义打架 + 播种遮蔽

| 位置 | 现状 |
|---|---|
| [coreCommands.ts:258](../../../../src/core/commands/shell/coreCommands.ts#L258) | followTheme when = `settingModified && settingFollowTheme`——**settingModified 依 userValue 存在性动态判定**（SettingRow handleGearClick 设：`inspectConfiguration().userValue !== undefined`） |
| [SettingRow.tsx handleGearClick](../../../../plugins/builtin/settings/src/views/SettingsView/SettingRow.tsx) | 齿轮打开时设 context key `settingModified` = userValue 存在；关闭时清零 |
| #154 播种 | deriveAppearanceSeeds 把值写 **user scope**（字体播种空 `""` / 玻璃播种 rgba）→ `userValue` 对「其实已跟随主题」的行也存在 |

**合成效应**：字体/玻璃这些「已跟随主题」的行，因播种值在 user scope，`settingModified=true` → 齿轮显示「跟随主题」→ 点击 = `resetConfigurationValue` 删 user scope → 值本就 = 基准，**无可见变化** → 再开齿轮 `userValue=undefined` → `settingModified=false` → 选项消失。用户看到「点了没变化又消失」。

**归一化缺口**：#155 生效徽标的种子感知判定 `isFollowingThemeValue`（播种=基准=未修改）未用于齿轮门控——同语义两处判定，一处感知种子、一处不感知 = 打架。

## 三、决策——用户拍板恒显

- **恒显**：`workbench.action.followTheme` when 改 `settingFollowTheme`（去 `settingModified`）——声明 `resetsToTheme` 的键，齿轮**始终**显示「跟随主题」；已跟随的键点击 = 无操作（`resetConfigurationValue` 幂等）。选项永不消失，无需改配置项让它回来。
- **作用域保持**：`settingFollowTheme` 仍由 SettingRow 逐行设（`!!prop?.resetsToTheme`）——非 resetsToTheme 键不见（不扩散到别的键/组/第三方）。
- **「打开存储位置」不动**：`settingKey == 'app.backgroundImage' || settingKey == 'app.zoneBackgroundImage'` 门控原样保留（用户明确要求）。
