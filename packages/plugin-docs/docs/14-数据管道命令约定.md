# 04 — 数据管道命令约定

> **类型：壳级别** — 参考文档，定义命令 ID 格式约定 | 2026-07-26。**在写任何协议/卡片插件之前定死。** 命令 ID 格式、参数约定、返回格式——定了就不能随便改，改了就是 API 断裂。

---

## 管道模型

```
滑杆卡片拖拽
  → 协议.encode(value)
  → 终端.sendBytes(bytes)
  → MCU 接收→计算→回传
  → 终端.receiveData(raw)
  → 协议.parse(raw)
  → 波形图卡片更新
```

三个角色：**数据源**（终端/串口/网络）→ **协议**（encode/decode）→ **卡片**（UI 控件）。

---

## 命令 ID 格式

```
<pluginId>.<action>
```

| 角色 | 命令 | 示例 |
|---|---|---|
| 数据源 | `<pluginId>.sendBytes` | `terminal.sendBytes` |
| 数据源 | `<pluginId>.onData`（事件） | `terminal.onData` |
| 协议 | `<pluginId>.encode` | `bracket.encode` |
| 协议 | `<pluginId>.parse` | `bracket.parse` |
| 协议 | `<pluginId>.decode` | `modbus.decode` |

**规则：**
- 前缀 = 插件 ID（`plugin.json` 的 `id` 字段）
- 动作名 = 动词（`sendBytes` / `encode` / `parse` / `decode`）
- 数据源不叫 `send`——太模糊。字节级推送叫 `sendBytes`
- `onData` 是事件（Emitter），不是命令——走 CoreEvents 而非 CommandRegistry。此处列出只为命名一致性

## 参数格式

### sendBytes——数据源发送字节

```typescript
// 请求
{
  channel: number,          // 通道/串口号
  bytes: number[],          // 待发送的原始字节
}

// 响应
{
  success: boolean,
  error?: string,           // 失败原因（如 "port closed"）
}
```

### encode——协议编码（值 → 字节）

```typescript
// 请求
{
  channel: number,
  value: number,            // 应用层值（如滑杆 0-100）
}

// 响应
{
  success: boolean,
  bytes?: number[],         // 编码后的字节
  error?: string,
}
```

### parse / decode——协议解析（字节 → 值）

```typescript
// 请求
{
  channel: number,
  bytes: number[],          // 原始字节
}

// 响应
{
  success: boolean,
  value?: number,           // 解析后的应用层值
  fields?: Record<string, unknown>,  // 结构化字段（如 { temp: 25.3, humidity: 60 }）
  error?: string,
}
```

### 卡片更新——扩展版

```typescript
// 请求
{
  cardId: string,           // 卡片实例 ID
  fields: Record<string, unknown>,  // 字段→值映射
}

// 响应
{
  success: boolean,
  error?: string,
}
```

## 结果格式——统一信封

```typescript
interface PipelineResult {
  success: boolean;
  error?: string;           // 人类可读，短——适合 toast 显示
}
```

**规则：**
- 所有管道命令返回 `PipelineResult` 或其子类型
- `success = false` 时 `error` 必填
- `error` 是人类可读的短字符串——不是堆栈、不是 code
- 具体数据字段（`bytes` / `value` / `fields`）只在 `success = true` 时保证存在

---

## 注册方式

插件在 `contributes.commands` 中声明：

```json
{
  "contributes": {
    "commands": [
      { "id": "bracket.encode", "title": "Bracket 协议: 编码" },
      { "id": "bracket.parse", "title": "Bracket 协议: 解析" }
    ]
  }
}
```

调用方通过 `executeCommand`：

```typescript
const result = await executeCommand("bracket.encode", {
  channel: 1,
  value: 75,
}) as PipelineResult & { bytes?: number[] };
```

## 为什么现在定

| 不定 | 定了 |
|---|---|
| AI A 写 `terminal.send`，AI B 写 `serial.pushBytes`——接不上 | 所有数据源叫 `sendBytes`——管道自动对接 |
| 返回格式各写各的——`{ ok }` vs `{ success }` vs throw | 统一信封——调用方不猜 |
| 卡片不知道协议返回 `value` 还是 `fields` | 约定明确——AI 看此文档就知道怎么消费 |

---

## 不作为核心命令

这些命令**不在 `coreCommands.ts` 注册**——核心不知道协议/终端/卡片的存在。它们由各自插件注册，通过 CommandRegistry 互相发现。核心只提供 CommandRegistry 桌子。
