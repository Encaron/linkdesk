## 三、病灶与根因（逐条有证据）

> 🔴 **2026-10-03 动工前复核修正（已获用户认可 · 走 A 案 ＋ 订正口径）**：立案时症状 ① 的根因「栏**无 `overflow` 约束**」**不成立**——状态栏**按设计自裁剪**：[index.css:426-429](../../../../src/index.css) 对 `.ldk-status-bar` 下的正是 `overflow: hidden`（自 2026-08-26 commit `1c69f8c90f` 起，⛔ 非并行 AI 新增、⛔ 非本轮改），且设计档案**明令**表面必须自裁剪（「…补 `.icon-bar`/`.titlebar`/`.status-bar`」，[14-主题配置参考系根治档案.md:439](../../../02-Electron架构/归一化基建/外观主题化/14-主题配置参考系根治档案.md)）。⇒ 现状 hover 方底的出界部分**是被栏圆角裁掉的**（本质 ≈ B 案「整高裁角」，断口仅亚像素级），**不是**「盖出曲线外、透出背景图」；[05 局部图](05-设计图-状态栏右端.html) 的「现状」列漏画了这条 `overflow`，把表现放大了。下方 ①/③ 已按此改写；**②（用户真实诉求）不变**。

| # | 症状（复核后口径） | 根因 | 证据 |
|:--:|:--|:--|:--|
| **①** | 圆角模式右端 hover 的**全高方块被栏圆角裁切**——出界被裁掉，但方块直边抵住弧线，形成**亚像素级直角断口**（非穿帮到背景） | 按钮全高（22＝栏高）＋ hover 方底 `border-radius: 0`；靠栏 `overflow:hidden` 兜底裁切——**形状语言**（方块 vs 圆角栏）不一致 | StatusBarZone.css:62-78（btn 全高直角）× index.css:409（栏四角圆）＋ :426-429（栏 `overflow:hidden` 自裁） |
| **②** | 「三件有点太大」的读感（**用户真实诉求，不变**） | 按钮**吃满栏高（22/22）**＋铃铛图标 `--font-size-lg`（14px）；圆角把栏四角削小、实感变小，**全高方块的反差被放大**——不是栏变矮（高度没动），是形状语言打架 | StatusBarZone.css:15,62-69,86-88 |
| **③** | 半径一大，右端 hover 方块的**右缘直边与圆角弧线错位**（被裁的那一小角） | 栏 padding `0 8px` 死值不让位；半径实际被浏览器钳到 ≤11px（栏仅 22px 高），故错位幅度小、但存在 | StatusBarZone.css:16 × index.css:409 |

## 四、改案（三案，详见 [05-设计图](05-设计图-状态栏右端.html) §③ 可交互对照）

| 案 | 一句话 | 改动面 |
|:--|:--|:--|
| **A · 内缩药片**（✅ 2026-10-03 选定） | 按钮高度 22→**18px**（栏内上下各留 2px）、hover 方底变**药片**（`border-radius: var(--radius-pill)`；横向 padding **不动**——只收高度不加宽，加宽会抵消「太大」的诉求）、栏内边距**让位给真实圆角**：`padding: 0 max(8px, min(var(--surface-radius), var(--status-bar-pad-max)))`（`--status-bar-pad-max` = 11px×scale＝栏半高，单列派生量）——三个症状一枪三个。⚠️ 按钮那一改是 **D1 的固定改法、与半径无关**（半径 0 直角档照旧生效，[05](05-设计图-状态栏右端.html)/[06](06-设计图-整页拟真.html) 两图即如此）；只有**让位量**在半径 0 归零 | 只动 `StatusBarZone.css` 一个文件 |
| B · 整高裁角 | 栏加 `overflow: hidden`，按钮维持全高方块（被栏的圆角裁掉出界部分） | 最小一行，但角落 hover 被裁出直角断口——形状语言还是打架 |
| C · 右端内舱 | 右端三件装进一个内缩的「舱」容器（自带药片底/透明），圆角让位同 A | 结构多一层，收益与 A 重合 |

## 五、决策点（D1–D4 · ✅ 2026-10-03 全定 · 整案走 A）

| # | 问 | 定稿（✅） |
|:--:|:--|:--|
| **D1** | hover 形态：内缩药片 vs 整高裁角 | **A · 内缩药片**——按钮 22→18px、hover 方底改药片 `border-radius: var(--radius-pill)`；B 整高裁角弃（裁角断口＝把穿帮换成另一处穿帮） |
| **D2** | 右端让位：padding 随半径 vs 固定 8px | **随半径 · 钳到真实圆角**：`padding: 0 max(8px, min(var(--surface-radius), calc(11px * var(--ui-scale))))`——⚠️ 原稿 `max(8px, var(--surface-radius))` 有回归：`--surface-radius` 上限 32px（`RADIUS_MAX_PX=32`，constants.ts:63），而栏仅 22px 高、浏览器把圆角实际钳到 ≤11px，故半径 >11 时原式会把内容推离边缘多达 32px；钳到 `11px × scale`（＝栏高一半）即「让位量 = 配置半径 ∩ 真实圆角」。半径 0 时回到现状零变化 |
| **D3** | 内容降档（图标/字号） | **不降**——「太大」的根是全高方块不是内容；内容降档会伤可读性，半径适配后重新目视 |
| **D4** | 铃铛徽章位置 | **随钮内缩**——徽章现在钉在钮的 top/right 1px，按钮 18px 后照旧钉钮角，实机核一次是否顶到栏缘 |

## 六、边界（本轮明确不做）

- ⛔ **不动状态栏高度**（22px×scale 是与 VS Code 对齐的既定契约）。
- ⛔ **不动壳固定项的命令接线**（`workbench.action.selectLanguage` / `theme.pick`）与通知中心逻辑。
- ⛔ **不碰插件贡献项的渲染契约**（`PoolStatusBarItem` 三形态零变化——本件只治 `.ldk-status-bar-btn` 的形状语言）。
- 玻璃态（`--bg-window` 半透明）下的 hover 底色对比度**实机核一次**（半透明底上 `--tab-hover-bg` 的观感）。
