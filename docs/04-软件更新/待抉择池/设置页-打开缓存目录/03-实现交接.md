## 七、风险（★ 先看这三条）

1. **`gen-review.mjs` 的 `must()` 是"全部替换"陷阱** ——
   `function must(s, from, to) { return s.split(from).join(to); }`
   它替换**所有**出现位置。所以要给"更多配置屏的四项"定格成"已勾"，**不能**直接把 `data-opt="filemenu"` 换成带 `checked` 的版本——那会**同时改掉欢迎屏那一份**。
   ⇒ 必须加 **`inScreen(s, id, fn)` 切片助手**：先把该屏 `<div class="scr" id="s-…">…</div>` 切出来，在**切片内**做替换，再拼回去。
2. **安装器设计图是生成物，且不许叠到定版页上** —— 重生成命令（⛔ 产出文件永不手改）：
   `cd build/installer/bootstrapper && node tools/gen-review.mjs --only=home,<新屏 id> --out="<本任务的重做效果图路径>"`
   ⚠️ **别不带参数跑**——不带参数会写 `安装界面自绘/3d-九幕评审.html`，那是**已定版的参考页**（属另一任务），本任务不许改它。`mockups/` 下的历史快照**冻结**。⚠️ **旧的 `05-设计图-更多配置页.html` 已删**（`more` 屏已不在产品源 ⇒ `--only=...,more` 会报错）——重做时**先自己设计定稿 HTML**，落产品源后再按上面的命令出图。
   🔴 `06-设计图-设置页.html` **不是生成物、没有生成命令**（手绘示意）——别去写生成器，也别拿 05 的纪律要求它。**新绘的界面才必须一比一**（安装器），既有表单示意即可（设置页）。
3. **`main.cpp` 在本机编不了** —— `npm run check` 也**不**覆盖 C++。所以 C++ 改动一律走 CI；改动越小越好，能照抄就照抄。
