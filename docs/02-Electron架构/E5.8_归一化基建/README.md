## 为什么是归一化基建

用户的 10 准则去重后是 6 个轴：**归一化 / 低耦合高内聚 / AI 友好三层 / 插件独立·生态 / 整洁无死代码 / 健壮生存**。dsh 借鉴清单 v2 的四大支柱全部命中：

| 支柱 | 归一化对象 | 一句话 | Phase |
|:--|:--|:--|:--|
| 契约生成 | 壳↔池 wire 协议 | 每个 API 只有生成的契约一种写法——漂移编译期死（linkdesk.d.ts，VS Code vscode.d.ts 同款） | 4 |
| 可逆注册 | 生命周期 | 每个注册只有 disposer 一种退路——卸载必拆净 | 2 |
| 依赖编排 | 加载顺序 | 每个依赖只有 `requires` 一种声明——顺序框架算，不靠约定 | 3 |
| 工程纪律 | 门禁 | 重复/死代码/供应链风险有机械哨兵——不靠人眼 | 1 |

**共同主题 = "AI 不需要追踪"**（AI 友好第 3 层：你要的不是 AI 更聪明，是代码不给 AI 犯错的机会）。

**保留（身份，不抄）**：React 自由渲染、单 Pool（1 BrowserWindow + 1 WCV）、壳想池画、插件自由化、remember 权限模式、Hot Exit。不抄清单全文 → [00-dsh借鉴档案.md §3](00-dsh借鉴档案.md)。

## 清单与档案的分工（指路规则）

**清单是清单，档案是档案——两边互相指路，任务条目永远不搬家：**

| | 清单 | 档案 |
|:--|:--|:--|
| 文件 | `E5.8-执行清单.md`（唯一一个） | 各 Phase 子目录（工程纪律/ 可逆注册/ 依赖编排/ 契约生成/ 回归验证/） |
| 装什么 | 任务条目 + 勾选 + 执行注——一贯连续，不清洗重排 | 设计文档、摸底矩阵、落盘物（如原生模块清单） |
| 指路方向 | 任务条目里写档案路径（例：#8 → `可逆注册/02-可逆注册设计.md`） | 档案文件头写任务号（例：`对应清单任务：E5.8#7-#12`） |

**新任务产生档案时**：先在清单条目里写清档案路径（落点），档案写完在清单勾任务并写执行注——档案自身不复制任务状态。
