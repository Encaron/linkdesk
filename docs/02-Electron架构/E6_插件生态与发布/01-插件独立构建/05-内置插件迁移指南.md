## 一、现行架构——随壳发货 = 首启种子一次化（E6#18 重塑后）

### 1.1 发货夹 = 首启离线种子，非更新通道

```
项目根/
  bundled-plugins/                      ← 发货夹：随壳只读备份（打包 → resources/bundled-plugins）
    ├── editor.linkdesk-plugin
    ├── settings.linkdesk-plugin
    ├── serial-monitor.linkdesk-plugin
    ├── theme-defaults.linkdesk-plugin  ← 纯 JSON/theme 插件也在同一平铺根
    └── …（18 个，core:true 与否同层）
```

- **boot 播种路径**：`electron/plugins/bundled-install.ts` 把发货 zip 解压成 `{userData}/plugins/<id>/`，loader 单根从 userData 统一发现。发货 zip 里的插件与手动装的插件在同一棵树里并列——**差异只剩 manifest.core:true（纯 UI 藏钮防误删，无行为特权，E6#18）**。
- **一次性（E6#18g 决策序）**——boot 对每个发货包只做一次决定，此后任何「不见了」都尊重：

  | 序 | 状态 | boot 动作 |
  |:--:|------|----------|
  | ① | 目标目录在 | 跳过——同/异版都不覆盖（用户已物化副本按版本固化） |
  | ② | 账本记 `removed: true` | 跳过——用户故意删的永不复活（尊重） |
  | ③ | **无任何账本记录 + 目录缺** | **铺种子**——全新首启 / 更新后新随车件首现 |
  | ④ | 有活性记录（非 removed）+ 目录缺 | **跳过不铺**——不复活；墓碑化动作归 renderer 对账置章（boot 不伸手） |

  损坏目录修复（`recoverCorrupt`，目录在但 plugin.json 坏 → 重装修复）保留 = **完整性修复**，与「复活被删的」不混。

- **主进程只读账本**：`installed-plugins.json` 唯一 owner = renderer `PluginInstallService`（启动 reconcile 自会发现这批落盘插件）。boot 阶段 renderer 未起 → 只读直读 `{userData}/installed-plugins.json`，**绝不写**（无第二 owner）。

### 1.2 boot 两腿共享同一套 zip 规则

`bundle-zip.ts` 的 `installBundleCandidate()` 是单包安装决策的**唯一实现**，boot 的两条腿都是它的薄调用方：

| 腿 | 模块 | 来源 | 消费语义（参数走） |
|----|------|------|------|
| **bundled-install** | `electron/plugins/bundled-install.ts` | 发货夹 `bundled-plugins/`（prod `resources/bundled-plugins`） | `deleteSource=false`（永久备份）+ `recoverCorrupt=true` + `skipIfRecorded`（②④ 豁免） |
| **bundle-ingest** | `electron/plugins/bundle-ingest.ts` | 用户手动丢进 `{userData}` 的 zip（「认包」地基） | `deleteSource=true`（消费后删 zip）+ 无 removed 豁免（手动丢包照装） |

两腿零重复 zip 逻辑——差异全走参数。

### 1.3 removed 墓碑（E6#18 卸载模型）

- **卸载任意来源插件**（随车/市场/手动同款）= 目录真删 + 账本保留条目置 `removed:true`（`markRemoved`，保 version/installedAt/source）——**永不整条删账本条目**，否则种子腿把「卸载过」当「从未装过」重铺 = 复活缝。
- **装回销章**：任何来源装回同 id（市场下载/手装 zip 共用 `add()`）→ removed 清、isInstalled 复 true——用户改主意即解除豁免。
- 对账（renderer `reconcileDiff`）：目录在 + removed → 清章（重现=装回）；目录缺 + !removed → 置章（消失=尊重）；永不整条删。
- `isInstalled` = 在账本 && !removed（墓碑条目不显「已装」）。
- **真恢复通道**（用户卸载后反悔）= 网络市场装回 + 手动把发货 zip 经 `pluginManager.install` 装回。**boot 永不自动装回。**

### 1.4 防滞旧机制（E6#15n）

boot 不刷内容指纹 → 发货 zip **内容变更但自身 version 不 bump** → 已物化 userData 副本永滞旧内容（实证：python zip 忘 bump → 旧副本 LSP 全挂）。三道防线：

1. **发布纪律**——内容变更必 bump 插件自身 `plugin.json.version`（+ package.json 同步）；
2. **bundled-version-bump gate**（`scripts/check-bundled-version-bump.mjs`，挂 `npm run check`）——对 `bundled-plugins/` 每个 working-tree zip，取 git HEAD 同路径 blob 作基线，比 zip **内容指纹**（zip 内条目 sha256，不比重建时间戳/压缩差异）；`working version === HEAD version 且指纹 ≠` → 🔴 红拦「改内容没 bump」；
3. **dev/test 强制重物化开关**（`--force-rematerialize-bundled` / `LINKDESK_FORCE_REMATERIALIZE=1`）——跳过版本幂等删旧目录整树重解压 zip 当前内容；**非生产语义，removed 标记仍豁免**（不复活用户故意删的）。

## 二、新增随车插件配方（照做）

> 把 `plugins/` 下某插件做成随壳发货件——两条路按「有没有编译表面」分，别走错。

### 2.1 有 entry / 视图渲染的插件（React 系：editor/file-tree/marketplace/serial-monitor/settings…）

```bash
# 1. plugins/<id>/ 已有 SDK build 脚本（package.json）
#    "build": "node <…>/packages/plugin-sdk/dist/bin.js build"

cd plugins/<id>
npm install
npm run build
# → 产 <id>.linkdesk-plugin（zip，插件根）+ dist/<id>.linkdesk-plugin/（解包目录，调试面）

# 2. 把 zip 拷进发货夹（提交）
cp <id>.linkdesk-plugin ../../bundled-plugins/
```

### 2.2 纯 JSON / entryless 插件（theme×N / lang×2）

SDK build 要求 entry 或 `contributes.views[].render`，纯数据包两者皆缺 → 不走 SDK，走独立打包器：

```bash
npm run pack:bundled-json     # scripts/pack-bundled-plugins.mjs——只打 entryless 目录
                              # （无 plugin.json.entry 且无 src/），整树打 zip 直落 bundled-plugins/
```

React 系有 entry/src，各自 SDK build 产 zip，本脚本不碰（防双源漂移）。

### 2.3 铁律

- **内容变更必 bump 插件自身 version**（plugin.json 唯一真值 + package.json 同步）→ 过 `npm run check`（gate 红拦实证同版改内容）；
- 随车 ≠ 声明 `core:true`——两个正交维度：发货集看「在不在 bundled-plugins/」，防误删看 manifest.core；
- 别改已提交 zip 当热更——改了源码要**重 build + 重发**；dev 想强制重刷已物化副本用 1.4 的 force 开关。

## 三、迁移史实（E6#15 已做动作——不是未完成活）

> 本节留档：以下全部**已完成并落地**（2026-08 → 09 塌平单根 ba716f017 + #15a-o + #16/#17 收编）。看到任务描述不要重做——复读的是现状。

### 3.1 为什么要拆（当初动机，仍是「插件自带依赖」的现行理由）

壳的 `node_modules/` 曾被插件依赖污染——monaco-editor / @codingame/monaco-vscode-*（42 包）/ serialport / @codemirror / iconv-lite 全在壳里。违反：核心无知原则（壳"知道"了有编辑器/有串口）、万物皆插件（随车插件是特权阶级，和壳共享 node_modules）、通用容器（壳被污染具体用途的依赖）。

**迁移后**壳依赖只剩 react/react-dom + react-i18next + lucide-react + @vscode/codicons + electron + 工具链（vite/typescript/eslint）；monaco/serialport 的依赖全部 inline 进各插件自己的 zip。**今天再加一个重型依赖插件，同样要让它自带依赖、独立 build——别把依赖塞回壳。**

**依赖归属表（现行参考）：**

| 依赖 | 归属 | 原因 |
|:--|:--|:--|
| react / react-dom / react-i18next / lucide-react / @vscode/codicons | **壳** | UI 框架/国际化/图标——壳自己渲染用 |
| electron / vite / typescript / eslint | **壳** | 桌面壳 + 工具链 |
| monaco-editor / @codingame/monaco-vscode-* / monaco-languageclient | **editor 插件** | 只有编辑器用 |
| serialport / @serialport/* / iconv-lite | **serial-monitor 插件**（API 走壳 preload `window.linkdesk.serial.*`） | 只有串口用 |

### 3.2 已做动作清单

- **E6#15（#31-#35）独立 build**：给 `plugins/<id>` 加 package.json + SDK build 脚本；从壳 vite.config rollup input 移除插件 entries；从壳 package.json 移除 monaco/serialport/@codingame 依赖；插件预构建 zip 自包含（react 系 external，壳提供）。
- **2026-09-05 塌平单根（ba716f017）**：`plugins/builtin|user` 双目录废除 → `plugins/<id>` 平铺根；发货夹 bundled-plugins/ 平铺，无 builtin/user 子目录层；核心 semantic：随车插件与第三方同格（`core:true` = plugin.json 声明，非目录位置）。
- **E6#15d G3b（pack:bundled-json）**：补纯 JSON 插件打包腿（theme/lang 无编译表面，SDK build 走不了）。
- **E6#15e/i LSP 依赖收编**：python/pyright 路径解析 + spawn 基准确认（含 #15k/15l/15m 收束）。详见 `docs/02-Electron架构/00-元文档/00-旧Bug预警…` 及 LSP 三边界 memory。
- **E6#15n 拆 boot 内容指纹裁决**：bundled 夹 = 首启种子**非更新通道**，boot 不刷指纹；防滞旧改「发布纪律必 bump + bundled-version-bump gate + dev 强制重物化开关」（§1.4）。
- **E6#16 壳 node_modules 瘦身收官**：谁消费谁声明 workspaces 化 + LSP 三处向上解析 + buffer 隐形垫片显式化（浏览器消费 Node builtin 的垫片不再被无关传递依赖静默满足）。
- **E6#17（#17a 拆源遮蔽 / #17d 壳零插件 JS import）**：打包版壳侧不再 import 插件源码/组件（glob 外注册纯声明化 + statusBar 存在性声明化），池侧渲染。
- **E6#18 卸载尊重 + 种子一次化**（§1.3/§1.1）：auto 装回腿退役 → 首次种子；removed 墓碑对任何来源同款；详情 UI 藏钮防误删、API 层可卸可禁。

### 3.3 迁移期风险与对策（留档）

- **Monaco 的 @codingame/* 包依赖复杂**：42 个 override 包内部互相 import——用 SDK 默认 external（只 external react/react-dom），@codingame 内部依赖全 inline，tree-shaking 处理。
- **serialport 是 native module**：JS 部分打进 bundle，但 native `.node` 需针对 Electron ABI。定案 = serial 作为数据源留在壳 preload/服务（`window.linkdesk.serial.*`），插件只调 API 不背 native——ABI 由 electron-builder `npmRebuild` 保证。
- **插件代码直 import 全局依赖**：检查 `import ... from "monaco-editor"` / `"serialport"` ——一律改走 `window.linkdesk.*`（插件通信标准 memory）。

## 四、验证清单——现行行为（E6#18 改写版）

```
[ ] 新增随车插件独立 build → 落 bundled-plugins/ → npm run check 全绿（gate 红拦实证）
[ ] 安装 → 启动 → 发货插件种子落 {userData}/plugins/<id>/（首启一次）
[ ] 二启同版零重铺（幂等）
[ ] UI 卸 serial-monitor → 目录消失 → 重启仍消失（尊重，不再自动回来）
[ ] 手删某随车插件目录 → 重启不回来（手删=尊重，对账置墓碑）
[ ] 手装回随车 zip（pluginManager.install）→ 回来 + 账本销章 → 再重启仍回
[ ] settings 缺失时应用不崩（FactorySlots 回退 welcome/空槽 + Ctrl+, 兜底）
[ ] 首启零 toast、卸载流无「系统/内置/自动恢复」文案
[ ] 壳 package.json 不含 monaco-editor/serialport/@codingame；安装包体积小
```

> 旧版此段曾是「卸载随车插件 → 警告 → 确认 → 消失 → **自动恢复**」——该语义已随 E6#18 退役：卸载被尊重、装回走市场/手装销章、boot 永不自动装回。
