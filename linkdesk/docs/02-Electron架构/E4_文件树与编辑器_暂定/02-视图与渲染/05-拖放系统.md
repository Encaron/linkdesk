## 二、已修复的 Bug

| Bug | 症状 | 修复 | commit |
|:--|:--|:--|:--:|
| ENOTDIR | 拖 exe 报错 | `FileService.copy` 加文件/目录判断 | `5f0b9c7` |

| 🔴 OS 拖入无祖先检查 | 拖根目录到子目录→递归嵌套→1.85GB | OS 拖入加 `startsWith` 祖先检查 | `afc9bb6` |

**🔴 OS 拖入递归嵌套详解：**

树内拖拽（`text/plain` URI）有 `isAncestorOf` 检查——禁止拖祖先到后代。
但 OS 拖入（`dataTransfer.files`）只做了 `copy`——没有祖先检查。

**复现：** 从 Windows 资源管理器拖 `D:\工具软件\` 到树内的 `工具软件\串口助手\` 节点上
→ `copy(D:\工具软件, D:\工具软件\串口助手\工具软件)` 
→ 展开后看到 `串口助手\工具软件\串口助手\工具软件\...` 无限嵌套
→ 每次操作指数膨胀，最终 1.85GB

**修复：** `afc9bb6`——OS 拖入加入 `normalizedTarget.startsWith(normalizedSrc + "/")` 检查——源是目标祖先时跳过。

**⚠️ 遗漏：** `afc9bb6` 只覆盖了"祖先→后代"，未覆盖"自己→自己"。
场景：Explorer 拖 `tools/sub/` 到树上 `sub` 节点 → `joinPath(sub, "sub")` = `sub/sub/` → 递归。`startsWith` 不命中（`sub` 不以 `sub/` 开头）。
**待修 #14a：** 加 `normalizedSrc === normalizedTarget` 判断。

## 四、归一化方案——#14b

**当前问题：** OS 拖入和树内拖拽是两个独立分支，各自做安全检查。`afc9bb6` 给 OS 拖入加了祖先检查，但 `srcPath === targetDir` 又漏了——因为两分支不共享代码。

**根除：** 提取 `executeSafeDrop(sources, targetDir, operation)`——所有安全检查集中一处，两分支都调用。

```typescript
async function executeSafeDrop(
  sources: { path: string; name: string }[],
  targetDir: string,
  operation: "copy" | "move"
): Promise<void> {
  for (const src of sources) {
    const s = normalizePath(src.path);
    const t = normalizePath(targetDir);
    const dest = joinPath(t, src.name);

    if (t.startsWith(s + "/")) continue;  // 祖先→后代
    if (s === t) continue;                // 自己→自己
    if (s === dest) continue;             // 同路径

    await copy(src.path, dest);
    if (operation === "move") await deleteEntry(src.path);
  }
}
```

此后新增任何拖放场景只需调此函数——再也不会一半有检查、一半没有。
