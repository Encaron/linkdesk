# 通道范式 · 设备插件独立

> **架构层长期文档**——不随 E5.8 完结失效。设计真相源（完整论证/证据链/任务细节）→ [E5.8_归一化基建/通道范式/01-通道范式设计.md](E5.8_归一化基建/通道范式/01-通道范式设计.md)。
> **用户拍板 2026-08-20**（Phase 6 多串口开工前四轮问答）——专门解决「第三方作者独立做设备插件（多形态/多通道/新设备）是否依赖壳作者」。

## 宣言（四行）

```
设备无限归插件          —— CAN/逻辑分析仪/GPS/烧录器/示波器……设备永远在插件，壳一个都不认识
通道收敛归壳            —— 串口/USB/网络/蓝牙……传输介质可枚举，壳只提供「打开 → 流式读写 → 关闭」
平台测通道 · 作者测设备  —— 平台用最少硬件验证通道正确；设备协议正确性由作者自持
插件发布永不触发壳发版  —— 设备插件进市场，壳版本纹丝不动；壳发版仅因壳 bug 或加新通道
```

## 责任分工

| | 平台作者 | 插件作者 |
|:--|:--|:--|
| 职责 | 通道正确 + API 稳定承诺（版本化演进） | 设备测试 / 协议解析 / 发布 |
| 需要的硬件 | 最少（手头已有的够测通用字节流） | 自己的目标设备 |
| 领域知识 | 通道语义（打开/流式读写/关闭/错误/多实例/资源回收） | 设备协议（CAN 帧/NMEA/采样） |

## 改壳判定标准

**改壳 = 加通用通道，不是加设备业务。**

- **加通道**（允许，且是「改壳」的全部含义）：出现全新的传输介质（串口已建；USB/网络 → E6 后版本化演进候选）。通道 = 打开/流式读写/关闭/错误语义/多实例/资源归属，**不含任何插件专属行为**（插件 ID 零硬编码——CLAUDE.md 硬约束 10）。
- **加设备**（永远不允许）：任何具体设备协议、解析、交互长进壳。设备解析归插件，壳不认识任何设备。
- **次数是收敛的**：改壳 = 每通道一种（传输介质几十种封顶），不是每设备一次（设备无限）。
- **版本化演进**：E6 上架后加新通道 = 加 API + 版本声明（VS Code `engines.vscode` 同款）；加了不违约、不加不影响现有插件。破坏性变更窗口收敛在 E5.8（上架前无第三方存量插件）；E5.8 后改壳 = 破坏存量第三方 = 违约。
- **不能承诺「永远不改壳」**（不诚实）——真正的保证是：改壳只在出现全新资源通道类型时发生，且收敛、可枚举、走版本化演进。

## 可行性全景（第三方作者视角）

| 层 | 设备示例 | 通道 | 状态 |
|:--|:--|:--|:--|
| **串口系**（最大头） | USB-CAN 适配器（CH340/CP210x 虚拟串口）、GPS 模块（NMEA）、USB-TTL、便宜的逻辑分析仪 | `linkdesk.serial.*`（Phase 6 通用化后） | ✅ **Phase 6 后立即可写，零壳依赖**；多口/多插件并存成立 |
| **自定义 USB** | 专业逻辑分析仪（Saleae 类，自定义 USB 端点） | usb 通道 | ⏳ E6 后版本化演进加一条通用 usb 通道（一次性，同 serial 同构）；加完所有 USB 设备可写 |
| **厂商私有 DLL** | 高端设备（只有厂商 SDK/DLL） | 原生通道 | ⚠️ 独立架构课题（渲染沙箱无 Node 权限）；非 E5.8 范围 |

**每补一条通道，第三方生态扩大一大块，且是一次性。** 不补通道不违约（不建空框架）。

## VS Code 实证

VS Code 核心**零串口**（`src/vs/workbench/contrib/serial` 404 + 核心 package.json 无 serialport）；串口 = 微软官方扩展 `ms-vscode.serialmonitor` 独立发布。**殊途同归**：核心都不管具体设备——VS Code 把完整 Node 给扩展宿主（能力全、安全靠信任扩展），LinkDesk 收口成白名单 IPC 通用通道（更严安全、壳按需补通道）。设备逻辑永远在插件。

## 边界与不做

- **USB/原生通道现在立案实现** → 不做。无消费者 + 不建空框架；触发条件 = 真实设备作者需求出现时版本化演进。
- **平台作者买设备/写示例设备插件** → 不做。违背「作者测设备」分工，是抢第三方作者的活。
- **通用连接框架 `linkdesk.connections`** → 不做（同不建空框架边界）。
- **键控路由升格壳 hook** → 不做（E6 出现第二键控信息源时评估）。
