# 待抉择池 · 底部面板显隐「关闭后重启复现」（→ 已泛化为「面板/侧栏显隐持久化」一类）

> **已实现（2026-09-27，第四件随批；CDP 实机复现定根因后修复，待发版随壳 v0.2.19 定号）**——2026-09-13 立案（用户报告）。用户 2026-09-27 点单时定性升级：**这是一类任务**——左栏同样在「查看→界面」有显隐开关，同样需要持久化；并临时加一件小任务「面板右键菜单加『隐藏』」。
>
> ## 根因（CDP 实机三步复现，推翻档案全部三个嫌疑方向）
>
> **真凶 = `panelVisible` 挂载快照 racing**（`panelHost.ts:27`）：`useState(() => getPanelLayout()?.visible ?? true)` 在 App 首帧执行，而布局缓存 `_layoutCache` 要等 `initLayoutService`（异步文件兜底链）完成才填充——那一刻缓存是空的，`?? true` 把「**还没装载完**」误当「**旧布局缺字段**」⇒ 每次启动/重载显隐恒被顶回可见。与 `useUpdateScheduler` 的 A7（配置就绪前读档位）同类病，panelHost 没吃到 ready 化治疗。落盘链本身是好的：toggle 后 localStorage `layout:ws-1` 正确写入 `visible:false`（CDP 逐步实证）。
>
> **顺带实锤两个邻接缺陷**：① `layoutStorageKey()` = `layout:ws-1`（E6#47c 按窗分键）拼出的文件名**含冒号，Windows 非法**——文件写入实际打进 NTFS ADS（userData 下 0 字节 `layout` 文件即残骸），「文件优先/AI 可直接编辑」对该服务在 Windows 上是坏的（登记待办，未在本件修）；② `SidebarLayoutState` **没有 width 字段**——侧栏折叠态（zone 宽 ≤48）从未持久化，用户「侧栏也要」的直觉正确。
>
> ## 修复落点（已实现）
>
> | # | 改什么 | 位置 |

## 已核实的机制现状（2026-09-13 排查）

持久化与恢复链路**都在**：

- 落盘：`src/App/persistence.ts` — `useLayoutPersistence` 把 `panelVisible` 合并写进 `layout.json` 的 `panel.visible`（E5.8#31「显隐合并落盘——防抖保存可能未覆盖」，两处落盘点 96/165 行）。
- 恢复：`src/App/panelHost.ts:27` — `useState(() => getPanelLayout()?.visible ?? true)`，启动取持久化值，旧布局缺字段才缺省可见。
- 翻转：`src/App/panelHost.ts` — `panel:toggle`（Ctrl+J）翻转后**立即落盘**。

## 嫌疑方向（未验证，按可能性排）

1. **`panel.reveal` 自动展开**（`src/App/panelReveal.ts`，E5.8#34.5/#35.5）：启动恢复会话时若面板视图标签随会话恢复，可能触发 reveal → `setPanelVisible(true)`，把刚恢复的 `visible:false` 顶掉。
2. **落盘时序**：关闭面板到退出软件之间若防抖保存未及写入（#31 注释自认「防抖保存可能未覆盖」），盘上仍是 `visible:true`。
3. **旧布局缺省分支**：`?? true`——若关闭面板后落盘的是「无 panel 字段」形状而非 `visible:false`，重启即命中缺省可见。

## 验证建议

关闭面板后（不退软件）直接看 `%APPDATA%` 下 `layout.json` 的 `panel.visible` 值——一步区分「没写进去」（嫌疑 2/3）还是「写了但启动被顶掉」（嫌疑 1）。立案后再定修法。
