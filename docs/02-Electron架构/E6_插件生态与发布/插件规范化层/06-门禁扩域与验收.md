# 06 · 门禁扩域与验收（L3.7 第 3.7.6 轮）

> **本层前面五轮各修各的，这一轮回答一个问题**：这里面哪些**下次不会再犯**？
> 判据不是「能不能写个脚本」，而是**「这个错，人记得住吗」**——记不住才需要门禁（承 memory `e6-gate-philosophy-three-tier`：**三档梯度，不是墙是坡度**）。

## 〇、加门禁前先过三道闸

| # | 闸 | 不满足会怎样 |
|:--|:--|:--|
| **闸 1** | **零误报才配红灯** | 有误报的门禁 = 训练人「红灯可以忽略」= 真红灯也一起被忽略 |
| **闸 2** | **修复成本必须≈0** | 修起来贵的门禁会被绕过/关掉（本仓实证：`check-file-size.mjs` 的 `SCAN_PLUGINS` 被关了一个月，**34 处超限在绿灯下生长**，见 memory `file-split-thresholds`） |
| **闸 3** | **规则本身不许腐烂** | 硬编码路径 / 硬编码插件名 / 手维护第二份清单——**门禁自己会过期**，过期门禁比没有更糟 |

**结论：本层只加 3 条**（下面 §一–§三），其余候选**明确不加并记下理由**（§四）。

## 一、G1｜空目录扫描（**新脚本 · 红灯**）

### 1.1 为什么要

[04 §〇](04-资源与目录归位.md) 的事故：AI 探针在 `plugins/settings/src/` 下造了空目录，用完只删脚本没删目录 ⇒ **`git status` 报 clean**（Git 不记录目录），垃圾在仓里躺到用户肉眼发现。

> **`git status` 看不见未跟踪的空目录**——这一条**任何「提交前看一眼 git status」的习惯都防不住**，只能机械扫。

### 1.2 形态

新脚本 `scripts/check-empty-dirs.mjs`，接进 `npm run check` 链：

```js
// 扫 src/ plugins/ electron/ scripts/ docs/ 的目录树
// 排除：.git / node_modules / dist / dist-electron / .vite / *. linkdesk-plugin（解包物）
// 命中空目录 → 打印路径 + 退出码 1
```

- **红灯（exit 1）**：自审通过**闸 1**——空目录**没有任何合法存在形态**（git 不记目录，所以「占位空夹」本来就不成立；要占位必须放文件，那就不是空目录了）。**零误报。**
- **自审通过闸 2**——修法就是 `rmdir`，成本 0。
- 顺带加**「夹宽黄灯」同款的提醒行**？→ **不加**，夹宽已有独立门禁（memory `file-split-thresholds`），别混两件事。

### 1.3 交付

| 项 | 内容 |
|:--|:--|
| 新文件 | `scripts/check-empty-dirs.mjs` |
| 接线 | `package.json` 的 `check` 链里加 `node scripts/check-empty-dirs.mjs` |
| 负测试 | 人造一个空目录 → 必须红灯；删掉 → 必须绿（**不许只验绿灯**，承 memory `snapshot-shadows-truth-bug-class` 硬要求） |

## 二、G2｜标识符形态的 `t()` key（**扩既有脚本 · 黄灯**）

### 2.1 门禁盲区实证

[03 §四 B-i18n-1](03-官方插件补齐.md)：`t("newPattern")` ——**一个数据键名走了翻译**，靠回落成字面量碰巧能跑，且**一旦有人补上这条译文就把配置键写坏**。

**`audit-i18n.mjs` 报不出来**——它**只扫中文**（设计如此，作者可用任意语言原文当 key）。⇒ **英文/标识符形态的 `t()` key 是门禁盲区。**

### 2.2 实测误报率（**决定它能不能上**）

**全仓实测（2026-09-11，`src/` + `plugins/` 全扫）**，判据 = key 匹配 `^[A-Za-z][A-Za-z0-9_.-]*$`（无空格、无中文）且不在任何字典里：

| # | 命中 | 判定 |
|:--|:--|:--|
| 1 | `src/hooks/usePoolSync/windowLayout.ts:67` `t("LinkDesk")` | ✅ **合法**——产品专名，永不翻译（同 `languages[].name` / `themes[].name` 的专名跳过逻辑） |
| 2 | `plugins/marketplace/.../marketCategories.ts:27` `t("category.")` | ✅ **合法**——**动态前缀拼接**（`t("category." + id)`），运行时才成完整 key |
| 3 | `plugins/settings/.../ObjectEditor.tsx:39` `t("newPattern")` | 🔴 **真命中（就是 B-i18n-1）** |

**3 命中 / 2 合法 / 1 真** ⇒ **误报率 2/3，但绝对量极小（全仓仅 2 条）**，且两条都能机械化识别：

- 专名 → 白名单（**与 `audit-i18n.mjs` 既有的 `languages` / `themes` 专名跳过同源**，不是新机制）；
- 动态前缀 → key **以 `.` 结尾**（`category.`）或**是另一个长 key 的前缀**。

⇒ **可以上，但必须黄灯**（**闸 1 不满足：有误报，不配红灯**）。

### 2.3 形态

**扩 `scripts/audit-i18n.mjs`，不新开脚本**（同一件事、同一份字典加载——**开第二个脚本 = 字典加载两份 = 两套真相**，违 M1）：

- 新增一段「可疑 key」检查，输出形如：

```
⚠ 可疑 t() key（症状：标识符形态且不在任何字典里——确认是数据标识符还是漏翻）
  plugins/settings/src/views/SettingsView/ObjectEditor.tsx:39  t("newPattern")
```

- **永不 exit 1**（哪怕 `--strict`）——承三档哲学：「警告」档**永不 fail build**。
- 白名单机制与既有专名跳过**同一处**，不新建第二份名单（**闸 3**）。

### 2.4 顺手清掉一个过期条目 🔴

`audit-i18n.mjs` 的 `I18N_FILES` 里有一条 **死路径**：

```
plugins/first-run-setup/i18n/en.json     ← 该插件不在 plugins/ 下，每次运行都打 ⚠ 缺失
```

**它每次 `npm run check` 都打一行假警告**（实测输出首行就是 `⚠ 缺失: …`）——**门禁自己腐烂的实例**（**闸 3**）。本层**删掉它**——[00 §五 ②](00-整理档案.md) 已拍「源码**不搬**」⇒ 它在仓外**永远够不着**，**不必留待复活**。

## 三、G3｜脚手架生成物形状自检（**新脚本 · 红灯**）

### 3.1 为什么要

**判据 M4**：脚手架 = 第三方作者抄的第一份样本。**它歪，整个生态歪**（[05](05-脚手架换代.md) 列的 7 项缺口就是这么长出来的——**模板从 2.1 轮起就没被任何门禁照过**）。

### 3.2 形态

新脚本 `scripts/check-scaffold.mjs`：把模板生成到**一次性目录**（`E:\linkdesk-build+scratch\scaffold-check\`，**不落仓内**，承 memory `dev-artifact-hygiene`），然后**只做静态断言**（**不跑 `npm install`**——慢且要联网）：

| # | 断言 | 盯的是哪次回归 |
|:--|:--|:--|
| 1 | 生成物**文件清单** ⊇ {`plugin.json`, `package.json`, `tsconfig.json`, `README.md`, `CHANGELOG.md`, `.gitignore`, `.vscode/settings.json`, `resources/icon.svg`, `i18n/en.json`, `src/index.tsx`, `src/index.css`} | 有人删了模板文件 |
| 2 | `plugin.json` **不含 `pluginId`**；**含 `icon`** | [05 §2.5](05-脚手架换代.md) 的回归 |
| 3 | `plugin.json` 能被 **jsonc 解析**且 `entry` 指向的文件存在 | 占位符替换把 JSON 写坏 |
| 4 | `CHANGELOG.md` 每个段标题匹配切段正则（[02 §四](02-元数据链路归一.md)） | 模板教错格式 ⇒ publish 切不到段 |
| 5 | `package.json` 的 `scripts` ⊇ {`dev`, `build`, `publish`, `validate`, `lint`} | 有人又漏接 SDK 命令 |
| 6 | **`i18n/en.json` 的每个 key 都能在 `src/` 里找到 `t("…")` 调用**（零死 key） | [05 §2.8](05-脚手架换代.md) 的回归 |
| 7 | 模板里**没有残留的 `{{...}}` 占位符**（模板自身的占位符集合与 CLI 的 values 集合**必须相等**） | **新增占位符忘加 values** 那类静默失败 |

- **红灯**：**闸 1 满足**——断言 1/5/7 是纯集合比对，零误报；断言 2/6 是「零死代码」的机械形态。**若未来出现合法例外 → 降黄灯，不许为此放宽断言到形同虚设。**
- **闸 2 满足**——报告里直接给出「哪个文件少了什么 / 该加什么」，修法唯一。
- **闸 3 满足**——断言 1/5 的**期望集合从模板目录现场读**（不是手写第二份清单）？**不**——**恰恰相反**：期望是**契约**（[05 §2.9](05-脚手架换代.md) 清单），必须**显式写死**；从模板现场读 = 断言恒真 = 假门禁（**这正是 `check-file-size.mjs` 被关掉的同类错误**）。**契约要显式，实现要现场读** —— 别搞反。

### 3.3 交付

| 项 | 内容 |
|:--|:--|
| 新文件 | `scripts/check-scaffold.mjs` |
| 接线 | `check` 链 |
| 负测试 | 人造回归（临时删模板的 `README.md` / 给 `plugin.json` 加回 `pluginId`）→ **每次都必须红灯** |

## 三·五、G4｜npm 发布基线扩域（**2026-09-11 新发现 —— 不是加新脚本，是补既有脚本的漏网**）

**这不是新门禁，是把一个已经写好的门禁接全。** `scripts/check-npm-release.mjs` 的职责是「作者面内容变了但 npm 版本没跟上 → 亮黄灯」。它守住了 `@linkdesk/contracts` + `@linkdesk/plugin-sdk`，**但漏了两个同样发布在 npm、同样是作者面的包**（2026-09-11 实测 `npm view` 四包全部真实在架，版本与本地一致）：

| 包 | 在 npm 上 | 在基线 `PACKAGES` 里 | 后果 |
|:--|:--:|:--:|:--|
| `@linkdesk/contracts` | ✅ 0.1.3 | ✅ | — |
| `@linkdesk/plugin-sdk` | ✅ 0.1.6 | ✅ | — |
| **`create-linkdesk-plugin`** | ✅ 0.1.0 | ❌ **漏** | **模板改了不发版 ⇒ 第三方作者 `npm create linkdesk-plugin` 拿到的还是旧模板，且没有任何灯会亮** |
| **`@linkdesk/ui`** | ✅ 0.1.2 | ❌ **漏** | 共享组件改了不发版 ⇒ 插件作者拿旧组件 |

**为什么脚手架这个漏最要命**：它**恰是本层 3.7.5 整轮要改的东西**——**改完骨架却不发版 = 3.7.5 的全部劳动第三方作者看不到**。而「第三方作者的第一份样本」正是 memory `plugin-independence-iron-law` 的立身之本。**一个只在仓库里变新的教具，不是教具。**

**交付**：`PACKAGES` 加两项——`create-linkdesk-plugin`（surface = `packages/create-linkdesk-plugin/index.js` + `packages/create-linkdesk-plugin/template/**`）与 `@linkdesk/ui`（surface = `packages/linkdesk-ui/src/**`，versionFile = 各自 `package.json`）。🔴 **`index.js` 必须进 surface**——模板内容改了它会漂移，但 `index.js`（CLI 提示文案）改了同样是作者面变化。

**判据不变**（承 [00 §〇 三道闸](00-整理档案.md)）：**黄灯、永不 fail build**——它提醒的是「货架落后」，不是「代码错了」。**发完照跑 `npm run release:mark`。**

🔴 **顺序依赖**：**3.7.5 的 #94g（发脚手架）必须先有本条**，否则发完 `release:mark` 也只记两个包，脚手架仍无基线。

## 四、**明确不加**的门禁（记录理由，防下次又提）

| 候选 | 不加的理由 |
|:--|:--|
| **「插件必须有 `CHANGELOG.md`」** | **闸 1 不满足**——主题 / 语言包这类纯数据插件**没有变更史**，强制它们写 = 逼出一堆只有「初始版本」一行的噪音文件。本层的处理是**官方范本补齐（[03 §五](03-官方插件补齐.md)）**，**不是门禁**（门禁管「不许错」，不管「齐全」）。 |
| **「插件必须有 `README.md`」** | 同上。且 README 缺失的**后果是可见的**（详情页空白）——**让后果自己教育作者**，比门禁更符合三档哲学。**脚手架给范本即可。** |
| **「`resources/` 只能放被引用的文件」** | **闸 1 不满足**——「被引用」要解析 README + 所有 `linkdesk://` 字面量，**解析器自己就是新bug源**。本层靠**审计（[04 §三](04-资源与目录归位.md)）+ 人工清理**解决，**不上门禁**。 |
| **「`plugin.json` 字段必须都在 schema 里」** | **不可行**——顶层 `additionalProperties: true`（[02 §二](02-元数据链路归一.md) 实测），且**不能翻成 `false`**（会炸掉整个生态的既有写法）。**墓碑提示（[02 §五](02-元数据链路归一.md)）是这条的正确形态**：只对「**曾经合法、现已移除**」的字段开口，不追求全覆盖。 |
| **「所有插件目录结构必须一致」** | **闸 1 不满足**——20 只插件分五类形态（代码 / 主题 / 语言 / 演示 / 混合），「一致」定义不出来。**M4 的正确落点是脚手架范本 + 09 规范的目录契约表**，不是门禁。 |
