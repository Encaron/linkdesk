## 三、修复方案

和 E5#36 完全一致——硬编码中文 → `t("中文")` + 补 en.json 翻译。

### plugin.json 命令

```json
// 改前：
{ "command": "filesExplorer.copy", "title": "复制" }

// 改后：
{ "command": "filesExplorer.copy", "title": "%filesExplorer.copy%" }
```

然后用脚本或手动补 en.json：
```json
{
  "filesExplorer.copy": "Copy",
  "filesExplorer.cut": "Cut",
  ...
}
```

**注意：** plugin.json 的 title 不支持函数调用——不能用 `t()`。对标 VS Code 的 `%key%` 包语法，或者直接在运行时 `getCommand().title` 处包 `t()`。

### EditorTab / FileTreeContextMenu / StatusBar chord

和 E5#36 一样——直接在 `.tsx` 里 `"中文"` → `t("中文")`。

### 主题 JSON

主题名 `label` 字段——同样是 `"label": "浅色主题"` → `t("浅色主题")`。

## 四、插件 JSON 的 %key% 包语法

plugin.json 是静态 JSON，不能调用 JS 函数。对标 VS Code 做法——用 `%key%` 包语法标记可翻译字符串：

```json
{
  "commands": [
    { "command": "filesExplorer.copy", "title": "%filesExplorer.copy%" }
  ]
}
```

加载插件时 (`loader.ts` 或 `parseContributions`)，遍历所有 `title`/`description` 字段，遇到 `%...%` 包语法 → 调用 `i18n.t(key)`。不改 JSON Schema——只是 loader 加一个后处理步骤。

### 涉及 ~100+ 处 plugin.json 改动

四个插件的 `plugin.json` 中所有中文 title/description：
- `file-tree/plugin.json` ~41 处
- `editor/plugin.json` ~32 处
- `serial-monitor/plugin.json` ~24 处
- `marketplace/plugin.json` ~9 处

每个 `"中文"` → `"%i18nKey%"`，同时补 en.json 翻译。

## 五、可能遇到的问题

### 1. % 包语法与已有值冲突

**风险：** 如果现有 title 里真的有 `%` 字符（如 `100%`），`%key%` 解析可能误判。

**缓解：** 只处理 `%` 开头且 `%` 结尾的模式——`/^%[^%]+%$/`。

### 2. loader 后处理遗漏

**风险：** 加载管线改了但某些路径（如热安装 `loadPluginRuntime`）没用同一条处理链。

**缓解：** E5#12 已归一化 `loadPluginLifecycle` 为唯一入口——在 `normalizeManifest` 或 `parseContributions` 中统一处理 `%key%`。

### 3. 翻译 key 命名空间

**风险：** ~100+ 个新 key 可能导致 key 冲突。

**缓解：** 按命令 ID 命名——`filesExplorer.copy` 对应 key `filesExplorer.copy`。命令 ID 本身已全局唯一。
