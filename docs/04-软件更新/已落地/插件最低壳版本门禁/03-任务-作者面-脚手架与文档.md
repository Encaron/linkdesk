# 03 · 任务：作者面（脚手架与文档）

> 门禁（G2）解决"**声明为真**"；本件解决"**作者看得懂、写得对**"。两者必须**同批**——光有红，作者不知道红在哪、该填什么，等于把问题从他手上搬到我们的支持队列里。

---

## 一、为什么要专门做这一格（不是"顺手写文档"）

三条实测事实决定了文档必须写清、且必须**双语**：

1. **作者的"自然直觉"是错的**。他会认为 `minAppVersion` = "我测过的那版壳"。但 [01 §六](01-事故复盘-真机实证.md) 证明：**他测的那个"旧壳"根本不是他以为的那个旧壳**（ui 是 `@latest`、宿主是 mock）。⇒ 他**推不出**正确的数，**必须由文档告诉他工具会替他算**。
2. **默认 `dev` 全程不报错**（mock 宿主 + `node_modules` 的 `@latest` ui）。⇒ 文档必须明确写出"**默认 dev 跑不出这类问题**"，否则作者会把"本地全绿"当成"发出去没事"。
3. **官方插件与第三方同一条路**（[00 §三](00-README.md) 硬推论）⇒ 文档是**唯一**的跨环境真相源，不能靠"我们自己知道"。

## 三、T2 · 作者手册（壳仓 `docs/03-插件制造/`，**中英双语**）

> 纪律：[`check-author-docs-bilingual.mjs`](../../../../scripts/check-author-docs-bilingual.mjs) 是硬门禁——**每处改动中英同笔**，缺一即红。

### T2.1 [04-插件分发格式.md](../../../../docs/03-插件制造/04-插件分发格式.md) §minAppVersion（**主战场**）

必须新增/改写的内容：

- **`minAppVersion` 到底是什么**：它是「**这只插件要求的最低主软件版本**」；低于它 ⇒ **加载器直接拒载**（toast）⇒ 用户拿到的**不是"少个功能"，是"整只插件不可用"**。
- **它是怎么定的**（本案的核心认知）：**不是你测过的壳，而是你实际用的东西**。
  - `@linkdesk/ui` 由壳池 vendor，**哪个组件从哪个壳版本起才有**是**事实**；
  - 你导入了某个组件 ⇒ 你就至少要那个壳版本；
  - **工具（SDK lint）会替你算出这个下限** —— 你不需要自己推。
- 🔴 **静态 `import` 没有"局部降级"**：顶层导入一个旧壳没有的组件 ⇒ **整只插件链接失败**，不是"那个功能不出现"。**想局部降级 ⇒ 用动态 `import()` 或运行时 `guard`**（但这是**你的选择**，不是要求）。
- 🔴 **默认 `dev` 测不出这类问题**：默认 `dev` 是 **mock 宿主 + 你 `node_modules` 的 `@latest` ui**，组件全在、渲染正常；**要暴露必须 `dev --real` 对真壳、或装进真壳**。
- 🔴 **`dev --real` 是单向的**：它回答"**在这个壳上跑得起来吗**"，**不回答"我最老能在哪个壳上跑"**。要拿下限，**看门禁的输出**。

## 五、T4 · 报错文案（**也是产品面**）

门禁那条红报，作者会直接看到。要求（照现有腿的文案纪律）：

- **给三件**：① 地板值；② **越界的导入名 + 它在哪一行**；③ **可执行动作**（"把 `minAppVersion` 抬到 ≥ `X`，或别用这个组件"）。
- ⛔ 不写内部黑话（"重锚号""vendor 单实例"要翻译成人话）。
- 文案是**门禁自测的一部分**（[05](05-验收判据.md)）——文案错了等于门禁没做。
