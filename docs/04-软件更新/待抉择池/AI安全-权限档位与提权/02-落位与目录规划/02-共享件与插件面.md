# 02 · 共享件与插件面（谁画、谁判、谁存）

> 判据 A（声明对等律）＋ 判据「换掉 UI 插件，行为还在吗」。
> 一句话：**壳存策略、壳判策略、壳执行；共享件只画；设置插件只接线。**

---

## 一、三层分工

| 层 | 归属 | 本档内容 | 换掉后行为 |
|:--|:--|:--|:--|
| 数据/判定 | 壳 | `ai.policy.mode`、风险表、`decide`、`userOnly`、批准写点 | 不变 |
| 动作 | 壳命令/API | `aiPolicy.getState` / `setMode`(userOnly) / `requestElevation` | 不变 |
| 呈现 | `@linkdesk/ui` 共享件 ＋ 设置插件 | `AiPolicyPicker`、徽标外观、确认框外壳 | 可整套换 |

---

## 二、`@linkdesk/ui` 新增件（受控、零桥）

### 2.0 先分清：一个新组件，还是一个组合

「权限档位」那块大卡片**不是一个巨型新组件**，而是三段组成：

| 段 | 是什么 | 归谁 |
|:--|:--|:--|
| 四段选择器 | **唯一的新组件** `AiPolicyPicker` | `@linkdesk/ui`（受控、零桥） |
| 风险摘要行 | 既有 `ReadOnlyText`（`statusCommand` 模式） | 共享件（已有） |
| 风险表入口 / 管理细分入口 | 既有 action 行 + 宿主命令 | 设置插件只接线 |

> ⛔ 不要把整张卡片做成一个 `AiPolicyCard` 塞进插件或壳：那会把「档位/风险/入口」重新焊死，第三方设置 UI 又得整套重写。

### 2.1 组件契约

```ts
export interface AiPolicyOption {
  value: "read" | "ask" | "auto" | "full";
  label: string;              // 人话（由宿主声明传入，⛔ 不写死）
  summary: string;            // 「R0 ✅ · R1 ✅ · R2 询问」
}

export interface AiPolicyPickerProps {
  value: AiPolicyOption["value"];
  options: AiPolicyOption[];  // 来自 aiPolicy.getState()
  disabled?: boolean;
  onChange(value: AiPolicyOption["value"]): void; // 只上报，不写配置
}
```

- **零壳依赖**（R6）：不 import `@/core`、不调 `window.linkdesk`；由设置插件把 `getState` 的值和 `setMode` 回调注入。
- 样式吃 token：`--radius-*`、`--accent`、`--text-*`；零 hex。
- 无障碍：`role="radiogroup"`、每段 `role="radio"`、←/→/Home/End、`aria-checked`。
- 导出只加不删；`ui-surface.json` 账本同笔更新。

## 二·补 · 每个面住哪（先查表再写组件）

| 面 | 件 | 位置 | 备注 |
|:--|:--|:--|:--|
| 四档选择器 | **`AiPolicyPicker`（新）** | `packages/linkdesk-ui/src/ai-policy/` | 受控、零桥；第三方设置 UI 直接用 |
| 风险摘要行 | `ReadOnlyText`（既有） | `@linkdesk/ui` | `statusCommand` 运行时读数 |
| 完整风险表 | **`AiPolicyRiskTable`（新，只读）** | `@linkdesk/ui` | 由 `aiPolicy.openRiskTable` 在 `DialogHost` 内容模式打开 |
| 细分管理 | **`AiSensitiveManager`（新）** | `src/pool/shared/ai-policy/` ＋ `DialogHost` 内容模式 | 数据/动作来自壳；⛔ 不放设置插件私有目录 |
| 确认框 / 提权框 | `DialogHost`（既有） | `src/pool/floating/dialog/` | 壳给 DTO；池只回 `confirm/cancel` |
| 状态栏徽标 | **`AiPolicyBadge`（新）** | `src/pool/shared/ai-policy/` | 由 `StatusBarZone` 消费 |
| 轻提示 | **`TransientToast`（既有）** | `src/pool/floating/transient-toast/` | **底部居中**（`transient-toast.css:8-12`）；3s |
| 通知留存 | `StatusBarZone` 铃铛面板（既有） | `src/pool/zones/status-bar/` | 错误/多动作/需决策走这里 |
| 设置页「权限」分节 | 设置插件（可整套替换） | `official/settings` | **只接线**：读 schema、渲染共享件、调命令 |

> 🔴 一条条目的呈现面只有**一个**：轻提示（toast）与铃铛面板是同一个 store 的两种 `presentation`，由 `toastRouting.decidePresentation` 决定（error / 多动作 / 长文本 / 需留存 ⇒ 面板；短回执 ⇒ toast）。⛔ 同一条两边都发。

## 三、设置插件只做三件事

| 做 | 不做 |
|:--|:--|
| 读 `aiPolicy.getState()` | 不判风险、不默认档位 |
| 渲染 `AiPolicyPicker`（`uiHint:"aiPolicy"`） | 不写 `"auto"` 等字面量 |
| 调 `aiPolicy.setMode`（用户点击） | 不直接写 `settings.json` |
| 渲染 `ai.policy.summary` 只读状态行 | 不拼路径、不拼文案 |

> 设置插件是可整套替换的普通插件（硬约束 11 / 万物皆可插件 §3.3）。以上四条保证：**第三方设置 UI 用同一个共享件即得同能力**。

## 四、确认框与提权框

| 件 | 归属 | 说明 |
|:--|:--|:--|
| 对话框外壳 | 池 `DialogHost`（既有，唯一） | 未来由 `renderers.dialogChrome` 替换外壳 |
| 对话框内容 | 壳给 DTO（`what/subject/why` + 按钮语义） | 渲染体不自己判「该不该问」 |
| 批准写点 | 壳（dialog handler settle） | ⛔ 渲染体回传的只是 `confirm/cancel` 动作类型（既有机制） |

---

## 五、状态栏徽标

- 落 `src/pool/shared/ai-policy/AiPolicyBadge.tsx`，由 `StatusBarZone` 消费。
- 数据：`aiPolicy.getState()` + `onDidChangePolicy`；⛔ 不轮询配置、不读 settings。
- 未来：`contributes.statusBar` / `renderers` 槽位接管外观，数据命令不变。

---

## 六、回执

- 走通知面板缺省（铃铛），⛔ 不新建 toast 宿。
- 文案由 `aiPolicy.receipt()` 生成，设置插件/任何插件不手拼。
