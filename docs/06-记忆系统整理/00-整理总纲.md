### 判断口诀（执行时逐份自问）

1. **这份文件写的是「过程」还是「结论」？** 过程 → 🔴；结论 → 🟡/🟢。
2. **这个技术栈还活着吗？** 死了（Tauri / 多 WebView / 双 Pool）→ 血脉抽成一句进编年史，其余 🔴。
3. **删掉它，未来 AI 会重复犯同一个错吗？** 会 → 🟡 并入 bug 图谱；不会 → 🔴。
4. **它是不是只在工程 docs 里已经有一份了？** 是 → 🔴（记忆不该镜像工程文档）。
5. **它指向的是外部资产/用户拍板吗？** 是 → 🟢（禁删级）。

## 四、风险控制（三重保险）

记忆库**没有工程 git 可依**——这是本任务最大的不对称。故设三道闸：

1. **git 快照（已做）**——记忆目录自带仓库
   `C:\Users\fengy\.claude\projects\e--linkdesk\.git`
   整理前全量提交：**`b6e5048`**（250 份全部入库、工作区干净）。
   **回滚方法：** `git checkout b6e5048 -- memory/`（或 `git reset --hard b6e5048`）。
2. **物理副本（已做）**——`E:\linkdesk-build+scratch\memory-backup-20260911\`（250 份 / 1.9M）。
3. **批次档案**——每批次执行后写 `批次N-处置档案.md`，逐条记「删了什么 / 为什么 / 折进了哪 / 回滚指令」。
   **每批次独立提交一次 git**，批次之间形成独立回滚点。

### 硬性纪律

- **禁止跨批次混合操作**。一个批次一次审阅、一次提交、一次放行。
- **删除前必须 git commit 干净**（工作区零未提交）。删完立刻提交，形成 `删前 / 删后` 两个点。
- **合并文件写完后，原文才可删**。禁止"先删后写"。
- **任何一份文件被删前，执行者必须打开读过全文**——不许凭文件名/描述下判。

## 五、命名与放置规则

- 合并后的新文件用**主题名**，不用时代前缀：`evolution-chronicle.md` / `bug-atlas.md` / `toolbox-sop.md`。
- 保留原文件名者不动（避免断链）。
- 合并文件必须保留**原有 frontmatter 的 `name`/`description` 语义**，并在正文首行注明「本文件合并自：…」+ 原文件名单。
- 每批结束后同步更新 `MEMORY.md`（见 `02-索引重写规范.md`）。
