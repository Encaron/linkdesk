# v3 遗留与硬编码残余

> 2026-08-06。盲审 + 路径审计发现。E5 归一化扫尾。
> 位于 E5 收尾 → `05-收尾/架构债/`

## 一、`v3_` localStorage 前缀残留

### 问题

E5 迁移到 Electron 后，localStorage key 沿用 Phase 3 (Tauri) 时代的 `v3_` 前缀。这是历史残余——E5 没有统一清理。

### 审计

```bash
grep -r "v3_" src/ --include="*.ts" --include="*.tsx"
```

预估范围：`LayoutService`、`PluginStateService`（已迁到 `linkdesk.pluginState` IPC，但 localStorage 回退可能还在）、`useSerialSessions`（已重写但 localStorage 初始化可能留了 `v3_` key）。

### 修复

- `v3_layout` → `layout`
- `v3_settings` → `settings`
- `v3_` 前缀全删——Electron 有自己的 `userData` 目录，不和 Tauri 的 localStorage 命名空间冲突

### 迁移兼容

旧用户升级后 localStorage 里还有 `v3_` key。加一次性迁移——启动时检查旧 key → 搬到新 key → 删旧 key。对标 E5#59 WorkspaceService 的 `_migrated` guard。

## 二、`localhost:1420` 硬编码

### 问题

Vite dev server 的端口 `1420` 硬编码在多处。如果端口被占用（另一份 LinkDesk 在跑），用户改不了——不是 bug 但属硬编码。

### 审计

```bash
grep -r "localhost:1420\|1420" electron/ vite.config.ts --include="*.ts"
```

### 修复

提取为常量 `VITE_DEV_SERVER_PORT` 或读环境变量 `VITE_PORT`。环境变量方案更灵活——和 Vite 的 `server.port` 配置共享。

## 三、魔数散布

### 问题

超时值、重试次数、缓冲区大小散布在代码中——大部分没有命名常量。

### 已知魔数

| 值 | 位置（代表性） | 用途 | 建议常量名 |
|:--|:--|:--|:--|
| `2000` | `IpcBridgeHandler.ts` | IPC 请求超时 | `IPC_REQUEST_TIMEOUT` |
| `5000` | `MainContent.tsx` | WebView 就绪超时 | `WEBVIEW_READY_TIMEOUT` |
| `6000` | `plugin-shell-main.tsx` | 插件加载超时 | `PLUGIN_LOAD_TIMEOUT` |
| `8000` | `serial-monitor` | 串口重连延迟 | `SERIAL_RECONNECT_DELAY` |
| `250` | `useClickPreview.ts` | 双击检测窗口 | `DOUBLE_CLICK_WINDOW` |
| `150` | 多处 CSS | 动画时长 | 用 `var(--transition-fast)` |

### 修复

不是创建一个 `constants.ts` 全扔进去——按模块归置：
- IPC 相关 → `electron/ipc/constants.ts`
- WebView 相关 → `src/hooks/useWebViewSync.ts` 顶部常量
- 插件加载 → `src/pluginLoader/constants.ts`
- 串口 → `plugins/builtin/serial-monitor/src/constants.ts`

### 优先级

低——魔数不是 bug。但每次有人问"这个 2000 是什么意思？"都在消耗时间。命名常量 = 自文档化。
