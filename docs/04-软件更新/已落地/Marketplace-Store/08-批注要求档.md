# 批注要求档——用户指示的现行状态

> **为什么存在**：用户双重拍板——①「我所有提到的，你除了 html 的更改，都必须有一个文档专门记录」；②「**文档不是历史记录**……它是最终最终这个效果图就是改的什么样子，并不是说记录一下上一次改的什么，这次改的什么」。
> **性质**：本档按**主题**组织，每条＝该要求的**现行完整表述**；同一要求被多次修改时**就地更新为最终形态**，不保留迭代史。历史叙述（第几版改成什么）⛔ 不入本档。
> **使用规矩**：每条批注 → 改 HTML → 本档对应条目就地更新 → 07 对账表同步 →（推翻拍板才回改拍板档）。

## 一、交互与动效语言

1. 🔴 **机械守则（第 0 条）**：「一个元素的改变不会影响其他的……不会让导致其他的位置发生变化……也是机械守则之一」——hover/选中/进行中只许 transform／opacity／颜色／遮罩；⛔ display、height、width、margin 等参与文档流几何的属性不得参与状态展示。验收：hover 任意卡片，其他一切元素像素位置不变。
2. **通用设计语言（全域）**：「这样能体现咱们整个这个设计语言都是 hover 之后放大一点点」——**所有**可放大 UI（含英雄横幅，无豁免）hover＝自身显著放大、盖住邻元素，不是抬高一点/高亮一下。幅度：small/grid **1.1**（含展开层）、mega **1.12**、duo/分类瓷片/作者卡 **1.08**、rank **1.03**（origin left，行不横跳）、hero **1.02**（大版面微幅度＋封面图形 1.06）。
3. **统一过渡**：hover 内容与本体放大**同一时序一次完成**（单一 opacity/transform，出 ~200-240ms／收更快）；⛔ 分级/stagger 展开、⛔ 先放大再展开第二要素（原话「明明是一起出现……我坚决不要这种要素」）。
4. **mega hover 形态 ✅ 验收通过（B13）**：本体放大＋**底部灰条向上延伸**——脚区（名/分类/免费，60px）常驻不动，同底色延伸段（标语＋简介＋安装/查看详情）从其顶上滑出，封面图标上移让位；**字不碰封面**（原话「我仍就是要底下那种灰色的条……哪怕说这个灰色条往上延伸都行了」）。⛔ 文字压封面、分体延伸层、画面接管层均已否决。
5. **横排容器放大余量**：横滚容器 padding 上 22／左右 30／下 18px——首/末卡 scale＋外扩层不切边（原话「会被旁边剪切掉一点……真机上面不希望出现这种效果」）；**大卡行（mega/duo）底部余量加深至 56px＋负外边距 -32px 补节奏**——辉光与灰条上延层不出容器边界（横滚容器连垂直方向一起裁的实测 bug 的机械守则配套解）。
6. **环境辉光 ✅ 验收通过（2026-11-19「可以，满意」）**：「它这个阴影周围可能是偏绿色一点，那么它散出来那个光就偏绿色一点……哪怕不 hold 住之后，它周围散出来的光都是它图片那种颜色」——散光颜色实时跟随封面自身颜色：hero 静态即有微环境光、hover 增强；mega/duo hover 辉光；无封面数据回落中性。真机＝取封面主色喂 `--glow`（见 05 §二 环境辉光段）。
7. 🔴 **滚动交互纪律（2026-11-19 问询→拍板：横排 ⛔ 不劫持纵向滚轮）**：用户设想「鼠标停在横排上滚滚轮 → 横向滚动，滚到头再让页面继续」，自评「本来上下滚动，滚到某个区域就变成横向滚动……直到滚到头才继续」——**结论：不做**。理由：① 首页 6 条横排占据大部分纵向空间，捕获面积过大，滑过整页必被劫持；② 用户会误判页面卡死，到条尾才放行 = 典型 scroll hijacking；③ 收益已有替代——**触控板两指横滑原生可用**、**Shift+滚轮原生横向**、**键盘 ←/→ 翻页**（焦点在卡上即可，v3.35 已实现）。**顶部大屏例外但必须「到头放行」**：只在可前进方向 `preventDefault`，到首/尾交给页面滚动（⛔ 旧版无限循环 = 鼠标停在大屏上永远滚不出去，v3.35 修）。

| 类型 | 上限 | 做法 |
|---|---|---|
| 标题 / 插件名 / 作者名 | **2 行** | `-webkit-line-clamp:2` ＋ `overflow:hidden` |

## 三、页面与细节

- **文案自解释纪律（2026-11-19 用户批注）**：「二建是什么建嘛？这个建是个什么东西啊？又或者这个仓是个什么东西」——**UI 里 ⛔ 用内部缩写**（仓/件/源/条），一律写全：`N 个仓库` / `M 个插件` / `N 个市场源`；作者自建的仓库名（如「硬件仓」）属作者命名可保留；作者店内切仓 = 「切换到该仓库 / 当前仓库」。设计文档内部可继续用缩写，但**蓝图与真机文案以本规则为准**。
- 🔴 **角标与已读体系（2026-11-19 拍板：两类都做）**：**任务型（更新）**——库项显示可更新数字（`cnt.warn`），来源是 `updates` 真相源，**不可手动清除**，更新完自然消失（"清掉等于假装没更新"）；**发现型（新内容）**——分类项/作者项右上角 6px 小点（accent 蓝），表示该分类有新插件、该店有新内容；**进入即已读**（点分类/进作者店自动清除），并提供**「全部已读」**（库头部，仅清发现型）。边界：离线不产生新点；同一内容只点一次；「全部已读」⛔ 不碰任务型数字；徽标清除与否不改变数据，只改提示状态。
