## 二、设计决策（每条都带理由）

1. **侧栏是布局里的真列，⛔ 不是浮层——与 T5 搜索浮条**相反**，故意如此。** 00.5 §一是「工具栏 40px ＋ 阅读区 ＋ 状态条 24px」的列布局，缩略图侧栏占左缘 180px 列。开着它阅读区就窄了，`ResizeObserver` 据此重算适宽倍率**是有意的**（侧栏挡住的宽度不该算进「适宽」）。T5 的搜索条反而必须浮起来（它不该改倍率）——两处的差别是「用户想不想让阅读区为它让路」，不是风格。实机读数见 §三.3：侧栏关/开时阅读区 canvas 宽 **933 ↔ 753**。
2. **目录与缩略图合成一夹**（`views/outlineSidebar/`）。两者同住左缘那一列、同一份文档态、同一套开关，拆两夹反而要在 `ReaderView` 里并排挂两个组件、各自读 store ⇒ 一夹两个面。
3. **目录读在 `ready` 之后异步补，⛔ 不挡阅读。** `doc.outline()` 要逐条解 dest（每条一次 `getPageIndex`），放进打开链路会把首屏拖长；而书签是**附加物**——读不出来（畸形/无目录）就当没有，阅读器照常。落地前查 `openSeq`：换文件后旧目录作废（否则旧文档的书签会指到新文档的页上）。
4. **无 dest 的条目渲染成不可点的 `span`，⛔ 不立空命令、不放占位钮。** 三种 dest 形（Ref / 具名 / 0-based 整数）都要真跳；解不出页码的（`page: 0`、`Appendix (no dest)`）就只是**标题**——`cursor: auto`、没有 click。硬约束 ③「没有的功能不立钮」在这里的落点是「不可点的条目就不做成钮」。
5. **目录树用真 `ul/li` ＋ 真 `button`，⛔ 不挂 `role="tree"`。** ARIA 树要求方向键在树内走位（← → 收展、↑ ↓ 移动），本格没做那套键盘面；挂了 role 却不给完整键盘路径**比不挂更坏**（读屏用户按 tree 的规矩操作会卡住）。`button` 本身 Tab 可达、Enter/Space 可激活，够用且不撒谎。
6. **缩略图槽位：页位整本都铺、位图只挂窗口内 ±2**（同阅读区 `WINDOW_BUFFER` 口径）。判据是「滚动条长度必须等于整个文档」——只铺窗口那几条会把**滚动范围自锁**（见 §四.1，实机逮到过）。滚出窗口的位图**立即置 0 释放**（不等 GC 心情），渲染记录同时作废（滚回来要重画）。
7. **槽位高度按各页长宽比先占好**（`THUMB_IMAGE_WIDTH × 高/宽`，没实测过的页按首页尺寸铺位）——槽位先占位、位图后到，滚动位置与总高**不随渲染先后跳动**（同阅读区铺位口径）。
8. 🔴 **`THUMB_GAP` 同时是 `pageOffsets()` 的 gap 和列容器的 `padding-top`** ⇒ 纯函数算出的偏移与屏幕上的位置逐像素对齐（T3 阅读区同款口径：`.pdf-reader-pages` 的 padding 恰等于 `PAGE_GAP`）。
9. **`THUMB_PAD` 取 8px 而不是设计图的 10px。** 06-设计图 `.r-side` 写的是 `padding:10px`，但本仓有 4px 节奏门禁（`check-spacing-grid`），10 不在刻度上；设计图那一版是示意、00.5 只定了 180px 列宽 ⇒ 按门禁取 8。
10. **`ThumbRow` 是 `memo` 组件且吃整个 `store`**（⛔ 不是剥出来的回调）。`memo` 让滚动时只有进/出窗口的那几条重渲染（20 页文档滚动中不再全列重渲染）；`store` 原样传是因为 **`gotoPage` 是用 `this` 的方法**（见 §四.4）。
11. **`getStatus` 只加 `outlineCount`，⛔ 不把整棵树塞进回执。** 回执是给 AI 读数用的（「这份文档有没有目录」），整棵树是 UI 数据——要树就读 DOM/后续另立读法，别把回执撑成文档镜像。
12. **当前页缩略图带 `--pdf-accent` 描边 ＋ `aria-current="page"`**（00.5 §七 表的口径）；跳页一律走 `store.gotoPage`（⛔ 不另写一条跳页路径，否则侧栏与工具栏/命令的落点会各算一份）。

## 四、实机逮到的东西（四条，前两条是当场修掉的真缺陷）

1. 🔴 **只渲染窗口那几条 ⇒ 滚动范围自锁（真缺陷，当场修）。** 旧实现 `mounted.map(…)` 只铺窗口内 ±2 条 ⇒ 滚动容器的高度就是那几条之和，**滚动范围被自己锁死**：20 页文档滚到「第 3~10 页」就到底了（`scrollTop` 顶在 **1178** / `scrollHeight` **1430**），后面十几页的缩略图**永远够不到**；深页开栏的「摆到当前页」也随 `scrollTop` 被夹回 0（实测点第 18 页后开栏落在第 1 页）。修法照 `readerSurface` 的**同一形状**：**页位整本都铺（`heights.map`）、位图窗内（`hasCanvas={windowedSet.has(i+1)}`）**。修后读数 = §三.1（`scrollH` 4748、底部第 17–20 页有墨）。带回归测试：「页位整本都铺（滚动条长度 = 整个文档），但只有窗口内挂 canvas」。
2. 🔴 **`ref={(el) => setThumbRef(page, el)}` 的箭头每次渲染都是新身份（真缺陷，当场修）。** React 每轮重渲染都「旧 ref 交还 `null` → 新 ref 再给元素」，于是**还挂在屏上的 canvas 也被当成拆掉的**、位图被清零：症状极具误导性——格子尺寸样式都在（`style.width` 是 `renderPage()` 写的）、`canvas.width` 却是 **0**，怎么看都像「压根没渲染」。把外层包 `useCallback` **也挡不住**（变的是箭头本身，不是它的依赖）。修法：**ref 只登记、⛔ 不清位图**，清理只交给「窗口淘汰」那一个 effect（判据是**窗口**而不是「DOM 里在不在」——页位整本都铺着，拿 DOM 当判据会把整本页的位图都当成「还在窗口里」而永不释放）。
3. 🔴 **换包后 `Page.reload { ignoreCache: true }` 对自定义协议不生效（读数陷阱）。** `linkdesk://pdf-reader/index.bundle.js` 仍走 Chromium 缓存——判据：`performance.getEntriesByType('resource')` 那条 `transferSize: 0 / encodedBodySize: 0`；而页内 `fetch(url, { cache: 'no-store' })` 拿到的却是**新字节**（711295 = 盘上大小），两条证据当场打架。我因此在「盘上 md5 是新码、读数行为是旧码（6 个页位）」之间白追一轮。修法：重载前 `Network.enable` ＋ `Network.clearBrowserCache` ＋ `Network.setCacheDisabled`。**并叠加 T4 那条教训**：必须等 `performance.timeOrigin` **真变**（只等 `document.readyState === 'complete'` 会被**旧文档**立刻满足 ⇒ 全程在旧页面里跑）。
   - ⚠️ 诚实留档：本格的装包是**直接 `cp` 覆盖** `%APPDATA%\linkdesk\plugins\pdf-reader\`（逐文件 md5 对齐 dist），⛔ **不是 `pluginManager.install` 正门**；正门路径在 T5 档案 §三 有读数。两条路的共同要求是「重载池页」，自定义协议还**必须清缓存**。
4. 🔴 **`gotoPage` 是用 `this` 的方法，⛔ 别剥成回调传。** 起初 `ThumbRow` 吃 `onJump={store.gotoPage}`，两个跳页单测当场炸（`expected 1 to be 2` ＋ `readerStore.ts:244 Math.min(this.state.numPages, …)` 上抛 `this` 为 undefined）——`store.gotoPage` 离开实例就丢 `this`。改成整机 `store` 传进组件、内部 `store.gotoPage(page)`。⛔ 不要把这条「修」成在 props 里 `.bind(store)`（每轮新建函数身份 → `memo` 全线失效，等于白 memo）。
