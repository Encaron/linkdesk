## 〇、先纠一个错：settings 的「空」有两回事，别混着答

**用户观察**：「为什么 settings→src 下有文件是空的？难道是因为 settings 是早期的插件吗？」

**答案 = 一半对、一半错，而且这两半必须分开说：**

| 观察到的现象 | 真因 | 结论 |
|:--|:--|:--|
| **`src/` 下有空目录** | **不是历史遗留** —— 是**本仓 AI 自己的探针残留**：做 E6#88 门禁负测试时，脚本 `88c-probe.mjs` 为验证「超限检测」造了一批临时目录，用完只删了脚本没删目录。**已 `rmdir` 清理，当前全仓空目录数 = 0**（2026-09-11 实测） | ❌ 与「早期插件」无关 |
| **settings 没有 `i18n/`** | 🔴 **也不是问题** —— 初判「缺译文」，实测**证伪**：`t()` 走**全局** bundle，settings 的 46 条 key 有 **44 条已在 `plugins/lang-defaults/en.json`**（壳的默认语言包），`audit-i18n.mjs --strict` 早就报 0 缺。**与「早期插件」无关**（[03 §四](03-官方插件补齐.md) 有完整纠正过程） |
| **settings 的 CSS 散在 `src/views/`**（其余 5 只用 `src/styles/`） | **确实是历史遗留** —— settings 是**并列最老**的插件（首提交 **2026-07-22**），后来的插件才统一到 `src/styles/` | ✅ 与「早期插件」有关（[05 §2.7](05-脚手架换代.md) 记规则，**本轮不回填**） |

**🔴 这次事故真正要沉档的不是那三个空目录，是一个机制盲区：**

> **`git status` 看不见未跟踪的空目录。** Git 不记录目录，只记录文件——一个空目录在工作区里存在**一万年**，`git status` 也报 clean。所以「提交前看了一眼 git status 是干净的」**不能**作为「仓库没有垃圾目录」的证据。

- **门禁落点**：把「空目录扫描」加进机械门禁（[06 号档案](06-门禁扩域与验收.md)），而不是靠人记得看。
- **纪律落点**：**造测试用的一次性目录，造在 `E:\linkdesk-build+scratch\`，不要造在 `plugins/` / `src/` 里**（承 memory `dev-artifact-hygiene`：开发产物只落 build+scratch，仓内零残留）。

## 一、editor 图归位（本轮主任务）

### 1.1 现状——三张图全在插件根

| 文件 | 谁在用 | 位置 |
|:--|:--|:--|
| `cover.svg` | `README.md:3` 的 `![…](cover.svg)` → 市场**详情页说明区**的场景封面 | 🔴 插件根 |
| `icon.svg` | `plugin.json` 的 `"icon": "icon.svg"` → 图标栏 / 标签 / 市场身份图 | 🔴 插件根 |
| `cover-brutalist.svg` | **无人引用**（[实测 grep](#) 全仓零命中） | 🔴 插件根 |

**其余 14 只有 `resources/` 的插件，无一把图放在根。editor 是唯一的例外**——它比 `resources/` 惯例早，之后没回头。**M4（官方插件=教具）要求同形 ⇒ 归位。**

### 1.2 目标形态

```
plugins/editor/
├─ plugin.json        "icon": "resources/icon.svg"     ← 改
├─ README.md          ![…](resources/cover.svg)        ← 改
├─ resources/
│   ├─ icon.svg              ← git mv icon.svg
│   └─ cover.svg             ← git mv cover.svg
└─ src/
```

**三处必须同批改，漏一处即裂图/掉图标：**

1. `git mv icon.svg resources/icon.svg`
2. `git mv cover.svg resources/cover.svg`
3. `plugin.json`：`"icon": "resources/icon.svg"`
4. `README.md`：`](cover.svg)` → `](resources/cover.svg)`

**为什么第 4 条不能漏**：README 里的**相对路径就是随包依据**——SDK 打包时扫 README 的相对引用，把命中的文件拷进 zip（[vite-config.ts:553-555](../../../packages/plugin-sdk/src/vite-config.ts)）。改了图的位置不改 README ⇒ **文件不在 zip 里 ⇒ 详情页说明区裂图**（正是 E6#70a 修的那个坑）。

**不动 `version` 的理由不成立**——`plugin.json` 的 `icon` 值变了，**打包产物内容变了** ⇒ **bump**（`1.0.7` → `1.0.8`，`fix:`）+ **zip 重建**。

### 1.3 🟢 `cover-brutalist.svg` —— **用户 2026-09-11 拍板：删**

- **来历**：E6#68 封面批里做了 A/B 两版，A 定稿（`cover.svg`），B「**留存**」（checklist 原话）。
- **现状**：**全仓零引用**（README 不引、`plugin.json` 不声明、文档不引）——SDK 也不随包（只随 README 引用 + 声明字段）⇒ **仓库里的一件纯占位资产**，踩的正是本层判据 **M2**（声明必须有消费者）。
- **✅ 决定**：`git rm`。**先拷一份到 `E:\linkdesk-build+scratch\` 留档再删**（A/B 设计过程可回溯），然后从仓里删除。
- **它为什么此前不能由我自行处理**：这是**上一次拍板「留存」的东西**——按 memory `rule-extrapolation-not-consent`，「M2 要求删死文件」这条规则**不能自动外推**到一件已经被人拍过「留存」的资产上。**用户 2026-09-11 明确答复「同意」后才动**，痕迹留在这里。

### 1.4 举一反三——还有没有别的「图不在 resources/」？

**全仓实测（2026-09-11）：根目录有图的插件只有 editor 一只**（`ls plugins/*/icon.svg` → 仅 editor；`cover*.svg` 同理）。**归位一次就够，没有第二家。**

## 二、资源随包规则审计（为什么要归位）

**这一节解释「位置」为什么有实际后果。**

### 2.1 打包器**只**随包这六类（[vite-config.ts:547-562](../../../packages/plugin-sdk/src/vite-config.ts)）

| # | 随包对象 | 判据 |
|:--|:--|:--|
| 1 | `contributes.i18n` 声明的文件 | **声明** |
| 2 | `README.md` | 固定名 |
| 3 | `CHANGELOG.md` | 固定名 |
| 4 | **README 里相对引用的媒体** | **引用** |
| 5 | `manifest.icon` 指向的文件 | **声明** |
| 6 | `manifest.marketIcon` 指向的文件 | **声明** |

> 🔴 **读法**：`resources/` 这个**目录名本身没有任何魔法**——没有任何一行代码在扫 `resources/`。文件能进 zip，靠的是**被 README 引用**或**被字段声明**。`resources/` 是**约定**（放一起好找、好归位），不是**机制**。

### 2.2 反例：为什么不能「反正 resources/ 会自动随包」

见 [12 档案 §三 的 ℹ️](01-规范文档对齐.md)——规范收口到 `resources/` 是**规整性**要求。**一个放在 `resources/` 但从没被引用过的文件，照样不会随包，照样没人读。**

### 2.3 🔴 顺手抓到的冗余：`copyFileInto(root, pkgDir, "icon.svg")`

[vite-config.ts:548](../../../packages/plugin-sdk/src/vite-config.ts) 硬写死拷一次**根目录的 `icon.svg`**，**紧接着** 558 行又按 `manifest.icon` 声明路径拷一次。

- **同一件事两条路**（M1 违规）：声明字段是唯一真源（硬约束 11），第 548 行是**惯例推断**——正是硬约束 11 明令禁止的「用文件位置推断插件属性」的写入侧版本。
- **实测它的实际作用 = 0**：全仓只有 editor 有根 `icon.svg`，而 editor **同时声明了** `"icon": "icon.svg"` ⇒ 第 558 行已覆盖。**删掉 548 行，全仓随包结果零变化。**
- **顺带**：删掉它还能防一个未来的坑——作者把图标挪进 `resources/` 但忘了改字段时，第 548 行会**静默把一张没人用的根 `icon.svg` 也塞进包里**，掩盖错误。
- 👉 **建议：删**（`@linkdesk/plugin-sdk` 轴 +1 patch）。若担心第三方作者依赖，可先加一条 `validate` 提示再删——**但别留着**。

### 2.4 数据型插件走另一条路（**不是漏洞，别误判**）

主题 / 语言包这类**没有 `src/index.tsx` 的数据型插件**（`theme-*` / `lang-*`）**不走上表**——它们**整目录拷贝**进 zip。

**实证**（2026-09-11 `unzip -l`）：`theme-panorama.linkdesk-plugin` **1,536,836 B，内含 `resources/sailor-moon.jpg`**——而该文件只被 `themes/panorama.json` 以 `linkdesk://theme-panorama/resources/sailor-moon.jpg` 引用，**不在上表六类里**。同理 theme-zones 的 `zones-bg.svg` / `paper-texture.svg`、theme-aurora-glass 的 `aurora-bg.svg` 都在包里。

> ⚠️ **审计记录**：初查时曾怀疑「主题的 `resources/` 不随包」是 bug——`unzip -l` 一照即证伪。**写进档案以免下一个人再疑一遍。**

## 四、settings 的 `views/hooks/`（小项）

### 4.1 现象

settings 里 hooks 有两种摆法：

| 摆法 | 例 |
|:--|:--|
| **与视图同夹**（多数插件都这样） | `views/SettingsView/useSettingsEvents.ts`、`views/SettingsView/SettingRow/useSettingRowValue.ts` |
| **集中在一个 `hooks/` 夹** | `views/hooks/useBaselineSeedsIpc.ts` / `useConfigurationValueIpc.ts` / `useEffectiveTokensIpc.ts` / `useUserOverridesIpc.ts` |

### 4.2 判据（memory `shared-hooks-placement`）

> **共享 hook → `@linkdesk/ui`；域专属 hook → 插件本地。**

实测这 4 个 IPC hook 是**settings 域专属**（全仓只在 settings 里被引用，`@linkdesk/ui` 里没有对应件）⇒ **不违「共享 hook 归位」**。

**但同一个插件里两套摆法 = 不归一**（M1）。且这 4 个是**配置 IPC 层**，按壳目录规范的语义更贴 `src/services/` 而不是 `src/views/hooks/`。

### 4.3 结论

- **本层只记录规则，不做搬迁**——理由：① 它不是死代码，无功能损害；② 搬迁会动 4 个文件的 import 路径，属「搬家」可做但收益小；③ **本轮已有 editor 归位这个真实搬家，别在一个低收益项上分心**（memory `reduce-parallel-subagents` 的同理：一次做透一件）。
- **规则留给下次**：**插件内跨视图共享的域逻辑（含 IPC hook）→ `src/services/`；单视图专属 → 与视图同夹。** 新增文件按这条走，存量不专门回填。
- 👉 若要回填，**单独立轮**，别塞进 3.7.4。
