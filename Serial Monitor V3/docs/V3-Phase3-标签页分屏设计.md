## 1. 为什么在卡片之前做

Phase 2 只做完终端视图。当前主区一次只能显示一个视图（终端 / 工作台 / OLED）。进卡片开发后会出现两个问题：

1. **切来切去**——调 PID 想看串口原始输出 → 得从 📊 切回 📟，看完再切回去
2. **多 workspace 没法同时看**——心率和车距两个 workspace 各有一组卡片，想对比只能切换

方案：把主区升级为 **VS Code 编辑器区域模型**——顶部标签页 + 拖拽分屏。

## 2. 交互设计

### 基准状态（单标签页）

默认打开终端标签页，和现在的行为完全一致：

```
┌────┬──────────┬──────────────────────────────────────┐
│    │          │ [📟 终端]                              │ ← 标签栏
│ 📟  │  侧栏    ├──────────────────────────────────────┤
│ 📊  │         │                                      │
│ ⚙   │         │  📟 终端接收区                         │
│    │         │                                      │
└────┴──────────┴──────────────────────────────────────┘
```

### 打开多个标签页

点 📊 → 打开工作台标签页。标签页并排显示，点击切换：

```
┌────┬──────────┬──────────────────────────────────────┐
│    │          │ [📟 终端] [📊 心率检测]                 │
│ 📟  │  侧栏    ├──────────────────────────────────────┤
│ 📊  │         │                                      │
│ ⚙   │         │  📊 卡片网格（当前聚焦标签页的内容）      │
│    │         │                                      │
└────┴──────────┴──────────────────────────────────────┘
```

### 拖拽分屏

**拖拽触发：** 鼠标按住标签页 → 拖动 → 出现半透明预览 → 拖到目标位置 → 松开吸附。

**drop zone：** 左 / 右 / 上 / 下 四个方向。类似 VS Code 拖标签页到编辑器区域边缘。

**拖 📟 标签贴到右侧 → 左右分屏：**

```
┌────┬──────────┬──────────────────────────────────────┐
│    │          │ [📊 心率检测] │ [📟 终端]               │
│ 📟  │  侧栏    ├──────────────┼───────────────────────┤
│ 📊  │         │              │                       │
│ ⚙   │         │ 📊 卡片网格   │  📟 终端接收区          │
│    │         │              │                       │
└────┴──────────┴──────────────┴───────────────────────┘
```

**也可以上下分屏：**

```
┌────┬──────────┬──────────────────────────────────────┐
│    │          │ [📊 心率检测]                          │
│ 📟  │  侧栏    ├──────────────────────────────────────┤
│ 📊  │         │  📊 卡片网格（上半）                    │
│ ⚙   │         ├──────────────────────────────────────┤
│    │         │ [📟 终端]                               │
│    │         │  📟 终端接收区（下半）                    │
└────┴──────────┴──────────────────────────────────────┘
```

### 分屏预览效果

拖拽过程中——鼠标移动到右半区 → 右半区出现半透明高亮 → 松手吸附。类似 VS Code 的分屏拖拽动画。

**实现：** 纯 CSS + React。`onDragOver` 判断鼠标所在半区 → 显示 drop indicator。核心 ~150 行。

## 3. 图标栏角色变化

| | 原设计（§3.2） | 新设计 |
|------|------|------|
| 📟 | 切换到终端视图 | 打开/聚焦终端标签页 |
| 📊 | 切换到工作台视图 | 打开/聚焦最近的工作台标签页 |
| 🎨 | 切换到 OLED 视图 | 打开/聚焦 OLED 标签页 |
| ⚙ | 切换到设置视图 | 打开/聚焦设置标签页 |

**图标栏不再"切换"——它在"打开"和"聚焦"标签页。**

- 点已打开的标签页对应的图标 → 聚焦到该标签页
- 点未打开的 → 打开一个新标签页（或恢复上次关闭的）
- 所有标签页同时存活，切换不丢状态

**注意：** 这和 VS Code 的 Activity Bar 不完全一样（Activity Bar 控制侧栏内容）。但在 V3 的语境里，📟 和 📊 不是侧栏的不同面孔——它们是独立的主区内容，标签页是它们的天然容器。

## 4. 侧栏联动规则

| 当前聚焦 | 侧栏显示 |
|------|------|
| 📟 终端 | 收发设置（时间戳/回显/行号/编码...）——和现在一样 |
| 📊 工作台 | 卡片属性编辑器（选中卡时）/ 卡片概览列表（未选中时） |
| 🎨 OLED | 图形属性面板 |
| ⚙ 设置 | 导航菜单 |

**分屏时——哪个面板有焦点，侧栏就显示谁的设置。** 和 VS Code 的侧栏跟编辑器焦点联动一致。

## 5. 多 workspace = 多标签页

```
[📟 终端] [📊 心率检测] [📊 PID调参] [📊 车距报警]
```

- 每个 workspace 文件 = 一个 📊 标签页
- 所有标签页同时存活，切换不丢数据
- 数据管道（RingBuffer → CardRegistry）对每个标签页独立路由
- 旧 workspace 收不到当前 MCU 数据的卡片 → 自然不更新（超时变灰），用户一眼知道

**顶栏的 workspace 下拉框可以保留**——它可以和标签页共存：
- 下拉框 = 加载 workspace 文件（"打开已有 workspace"）
- 📊 图标 = 建新 workspace / 聚焦最近 workspace 标签页

## 6. 技术选型

### 方案 A：allotment + 自己写标签页（推荐）

**allotment**（VS Code 同款，GitHub ~2k stars）：

```tsx
import { Allotment } from "allotment";
<Allotment>
  <Allotment.Pane><WorkspaceView workspace="心率检测" /></Allotment.Pane>
  <Allotment.Pane><TerminalView /></Allotment.Pane>
</Allotment>
```

- ✅ 支持拖拽分割条 resize
- ✅ 支持嵌套分屏（左右 + 上下）
- ✅ VS Code 同款——久经考验
- ⚠️ 不包含标签页——标签页需要自己实现（`state.tabs[]` + JSX render）

**标签页自己写（~100 行）：**

```tsx
interface Tab {
  id: string;
  type: "terminal" | "workspace" | "oled" | "settings";
  label: string;
  workspaceName?: string;
}

const [tabs, setTabs] = useState<Tab[]>([{ id: "default-terminal", type: "terminal", label: "终端" }]);
const [activeTabId, setActiveTabId] = useState("default-terminal");
```

标签栏：CSS flex 一行，`overflow-x: auto`，滚轮横向滚动。

### 方案 B：dockview（完整 dock 系统）

（GitHub ~2k stars）

- ✅ 标签页、拖拽预览、drop zone 指示全内置
- ✅ 支持拖到窗口外变成独立窗口（IDE 级别功能）
- ❌ 重——API 复杂，侵入性强
- ❌ V3 不需要"拖出独立窗口"级别的功能

### 结论：方案 A

| 组件 | 实现方式 | 估行数 |
|------|------|:--:|
| 标签栏 UI | React state + CSS flex | ~100 |
| 单面板显示 | 条件渲染（和现在一样） | ~20 |
| 分屏 | allotment | ~30 |
| 拖拽预览 | mousedown + CSS overlay | ~150 |
| drop zone 指示 | onDragOver + CSS | ~50 |
| 布局持久化 | prefs.json layout 字段 | ~40 |
| **合计** | | **~390** |

## 7. 实施顺序

```
Step 1: 标签栏组件（TabBar.tsx）
  - tabs[] state 管理打开的所有标签页
  - 点击标签切换 activeTabId
  - 标签上 [×] 关闭按钮
  - overflow 滚轮横向滚动

Step 2: MainContent 改造
  - 接收 tabs+activeTabId → 渲染对应面板
  - 单面板模式：和现在外观一样，内部换实现
  - 本 Step 结束时用户看到的和现在一样——标签栏 + 一个面板

Step 3: 打开多标签页
  - 图标栏适配：📟/📊 点击 → 打开/聚焦标签页
  - 同类型标签页去重：点已打开的 → 聚焦
  - 本 Step 结束：能开两个标签页，点击切换

Step 4: 引入 allotment 分屏
  - npm install allotment
  - MainContent 判断：单标签页 → 直接渲染；多标签页且分屏 → Allotment 容器
  - 分屏布局数据结构：{ direction: "horizontal", panels: [{ tabId: "xxx" }, { tabId: "yyy" }] }
  - 本 Step 结束：左右分屏，中间分割条可拖拽 resize

Step 5: 拖拽标签页形成分屏
  - mousedown 标签页 → 追踪鼠标 → 半透明预览跟随
  - 鼠标移到主区左/右/上/下半 → drop zone 高亮
  - 松开 → 更新分屏布局
  - 从分屏拖回标签栏 → 合并

Step 6: 关闭分屏
  - 两个面板时关一个 → 另一个占满全部空间
  - 最后一个标签页关闭 → 回到单标签页模式（终端标签页保底）

Step 7: 布局持久化
  - prefs.json 新增 layout 字段：{ tabs, activeTabId, splitLayout }
  - 启动时恢复上次的标签页和分屏布局

Step 8: 侧栏焦点联动
  - 监听 activeTabId 变化 → 设置侧栏内容

Step 9: 打磨
  - 标签页拖拽动画（CSS transition）
  - 分屏 resize 最小宽度限制
  - CM6 在 resize 时 requestMeasure
  - 键盘快捷键（Ctrl+W 关标签页，Ctrl+Tab 切换）
```

## 8. 风险

| 风险 | 对策 |
|------|------|
| **allotment 和 React 18 StrictMode 兼容** | 测试：分屏 → StrictMode 卸载重挂载 → 布局是否丢失 |
| **TerminalView CM6 在分屏 resize 时断行错乱** | CM6 `view.requestMeasure()` 触发行重排 |
| **标签页拖拽在 Windows 上的性能** | 拖拽预览用 `transform: translate()`（GPU 合成线程），setInterval 16ms 更新位置 |
| **多 TerminalView 实例的 CM6 内存** | 每个 CM6 实例 ~5-10MB，2-3 个标签页可控 |
| **RingBuffer 多个消费者** | 当前 `drainAll` 是独占消费。分屏需要改为 Pub/Sub——TerminalView 和 WorkspaceView 各自订阅。Phase 3 先不改 RingBuffer，两个面板各自创建独立 RingBuffer，从不同的 `listen()` 消费 |

## 9. 方案 §3 设计更新

Phase 3 的标签页+分屏模型替换了原设计方案 §3.2 的"图标栏=视图切换器"：

**原设计（作废）：**
> 图标栏就是视图切换器。没有标签页。

**新设计：**
> 图标栏打开/聚焦标签页。主区顶部标签栏 + 可拖拽分屏。默认打开终端标签页（和原设计一致——"打开软件默认进入终端视图"）。

**三栏骨架不变。** 图标栏仍是 42px 左列，侧栏仍是 220px 可拖拽，主区仍是 flex:1。变化的只是主区内部——从"单视图切换"变成"标签页+分屏"。
