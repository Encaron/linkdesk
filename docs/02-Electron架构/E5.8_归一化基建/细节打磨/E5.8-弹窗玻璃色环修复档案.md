# E5.8-弹窗玻璃色环修复档案

> 2026-08-29 立案 E5.8#187（Phase 11.22 一般 bug）。用户实机：玻璃主题下确认弹窗/quick-pick/悬浮面板内文字与按钮行边缘有「加厚磨砂」玻璃框围住，与弹窗本身有色差，不协调。

---

## 一、现象

玻璃主题（aurora-glass 等）下，打开确认弹窗（如「确定要将「app.theme」重置为默认值吗？」），**消息文字行 + 底下「取消」「确认」按钮行**周围出现一圈比弹窗面板更厚的磨砂框（视觉上「加厚磨砂」边框，像右键菜单文字那种磨砂但叠在弹窗上）。quick-pick 输入/列表、悬浮面板标题/正文同构。

用户原话：*「这行字周围会有类似右键的加厚磨砂（和后面区分开）的样子……弹窗似乎本身的玻璃效果就有加厚磨砂的效果；我不知道是不是三层玻璃叠加的效果（zone，弹窗的，字体周围的），总之在主题为玻璃情况下不协调。」*

---

## 二、根因（file:line + 机制）

**隔离地板选择器 2 过宽——裸深度 3 内容被二次 backdrop-filter。**

`src/index.css` 浮层隔离地板（E5.8#107 建，`f2f3dd02`）两条结构规则：

```css
#ld-float-layer > *:not(#ld-scrim-plane) > *:not([data-overlay-wrapper]),   /* 深度 2 表面 */
#ld-float-layer > *:not(#ld-scrim-plane) > * > * {                          /* 深度 3 表面 */
  backdrop-filter: blur(max(var(--glass-blur, 0px), var(--float-blur-floor))) saturate(var(--glass-saturate, 1));
  ...
}
```

- **选择器 1（深度 2）**：弹窗面板 `.dialog-host-panel` 本身 → 一层磨砂。
- **选择器 2（深度 3）**：`> * > *` 匹配**所有**深度 3 元素，包括**裸内容**——`.dialog-host-message` / `.dialog-host-actions` / quick-pick 输入与列表 / floating-panel 标题与正文。这些不是独立表面，是坐在已磨砂面板上的**内容**，被二次 backdrop-filter → 面板单层磨砂上叠第二层 → 文字/按钮行边缘出现「加厚磨砂」框（双模糊+双 saturate 对比强化，玻璃主题才可见）。

### 为什么普通右键菜单文字不受影响（用户疑点）

右键菜单走 `<OverlayPortal rootId="context-menu-root">` → 深度 2 是 `[data-overlay-wrapper]` 包装盒（**被选择器 1 的 `:not([data-overlay-wrapper])` 排除**，E5.8#109），`.ctx-menu` 表面在深度 3（被选择器 2 命中一次），`.ctx-item` 文字在深度 4（**不再命中**）。所以右键文字恰好落在**单层磨砂表面**上——清晰且无叠加。

弹窗的 `.dialog-host-message` 是 `.dialog-host-panel` 的直接子元素（DialogHost.tsx:121），落在**深度 3**——被选择器 2 多命中一次，成为唯一叠层来源。

### 为什么「之前修好的右键更清晰」没被这次波及

E5.8#107/#109（`f2f3dd02`/`d127d9a3`）只给**深度 2** 加了 wrapper 排除，选择器 2 **从未收窄**。这是 #107 结构地板留下的「缝」——裸内容 vs 表面同处深度 3，结构规则无法区分。用户对「这是之前给右键修清楚留下的缝吗」的疑点成立：**是同一批结构规则留下的覆盖过度**，不是 #109 引入——#109 只保护了 wrapper 内表面，没碰到选择器 2。

---

## 三、改法（两处 CSS，零新 API/配置/贡献点）

| 文件 | 改动 |
|---|---|
| `src/index.css:615` | 选择器 2 收窄：`> * > *` → `> [data-overlay-wrapper] > *`——**只磨砂 wrapper 内表面**（右键主菜单/ColorPicker/dropdown-card/selectbox/status-bar-notif-panel 等 OverlayPortal 表面）。裸深度 3 内容（弹窗消息/操作、quick-pick、悬浮面板）不再二次磨砂 → 坐父面板单层磨砂，色环消除。同步更新隔离地板头注释（深度 3 语义 + #187 记录）。 |
| `src/pool/floating/toast/ToastHost.css` `.toast-item` | **补显式磨砂**：toast-item 是裸深度 3 表面（`#toast-root > .toast-container(display:contents) > .toast-item`，无 wrapper 且无父面板承接磨砂），收窄后失去结构规则覆盖 → 显式声明 `backdrop-filter: blur(max(var(--glass-blur, 0px), var(--float-blur-floor))) saturate(var(--glass-saturate, 1))` + `-webkit-backdrop-filter`（值与原地板常量一致，同 `.floating-panel-act.tip::after` tooltip 例外先例）。 |

**机制不变**：深度 2 表面（选择器 1）+ 深度 3 wrapper 内表面（选择器 2）+ 裸深度 3 内容（无独立磨砂，靠父面板）+ 显式例外（toast/tooltip）。深度是结构事实不是类名知识——第三方 OverlayPortal 进层即隔离，零类名知识零枚举零壳改动。

## 四、验证

### 1. CSSOM 实时模拟（修复前，ring-fix-simulate.js，临时脚本已清）

注入 `#ld-float-layer > *:not(#ld-scrim-plane) > * > *:not([data-overlay-wrapper] *) { backdrop-filter: none !important }` 模拟收窄（等价于本次改动）：
- `.ctx-menu` / `.ctx-item` / `.dialog-host-panel`：**字节级零变化**（blur(16px) saturate(1) / none / blur(16px) saturate(1)）→ **右键清晰度逐字保留** ✅
- `.dialog-host-message`：blur(16px) → none → **色环去除** ✅

### 2. A/B 像素差分（ring-ab-full.js，临时脚本已清）

真实弹窗双磨砂开 vs 关：message 区平均 Δ=9.38 / 53.6% 像素过重 / 最大 Δ=27；actions 区平均 Δ=7.31 / 53.4% / 最大 Δ=12——色环是真实可见的像素级差异，非感知偏差。
