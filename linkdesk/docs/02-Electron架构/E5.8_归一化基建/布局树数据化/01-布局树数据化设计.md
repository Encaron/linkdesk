## 1. Context：为什么改

**用户实机发现 E5.7 把 E5 的区域解耦能力面砍了**：原话「我估计现在底部面板和其他区域混成一谈……我一直以为是在 e5 的基础上做的，没想到把这么多东西都砍了……我记得当时还有个特点就是可以把左边的侧栏换到右边，我估计现在也没有了。」十条戒律校准后拍板「**做，对齐当时的 e5**」。

**2026-08-21 用户实机描述 VS Code 面板行为——证伪「模型 B（面板限于主栏内）」**：
- 默认：两侧栏全高 + 面板居主栏底（= center 对齐）。
- 对齐面板（底部时）：向左对齐 → 面板贯穿到最左、**左侧栏缩短**；向右对齐 → 镜像；两端对齐(justify) → 贯穿整个底部、双侧栏缩短；居中 → 双侧栏全高直通。
- 面板位置：底部（默认）/ 顶部 / 左 / 右——放右边时与右侧栏(agent)并存形成 5 带排布（iconbar | 主侧栏 | 主区 | 面板 | 右侧栏）。
- 主侧栏换边 ↔ agent 右侧栏自动跳对侧（互换）。
- **「对齐延伸到侧栏之下 + 侧栏缩短」当前池 flex 结构物理上表达不了**——PanelZone 在 `pool-main-column` 内（`src/pool/PoolZoneShell.tsx`），宽度 = 主栏宽。**必须池布局 grid 化。**

**引擎现状实证**：`_recalculate()` **已是 edge 驱动 + 同 edge 多 zone 堆叠**（left/right/bottom 各循环堆叠 + 总宽度校验）→ rightSidebar / 面板左/右的数学近现成；**缺 top edge 与 align**。池布局 CSS 在 `src/index.css`（pool-root column / pool-body row / pool-main-column column）。

**E5.7 砍掉的链路（git 实证）**：`c010bf1e`（#31.5）删 5 方法 + floating 分支 + ZoneConfig 的 float/undockable/visible；`a04374eb`（#12.5）删 bounds 推流改主进程满窗接管——架构转向非瘦身，旧推流数学新架构下是错的，不原样复活。

## 2. 架构决策

### 决策 1：树在壳（LayoutEngine 权威），池从树渲染
LayoutEngine 持布局树真相源。池 usePoolSync 读 getZone() 的 edge/align/尺寸组装 DTO 推池。zone 组件 props 零改动。

### 决策 2：推「树结构」不推「绝对坐标」
池 grid 化后，面板对齐的几何（列跨度/行位置）由**池从 DTO 尺寸（edge/align/sidebar.width/rightSidebar.width + 自身 CSS 常量）推导 grid-template/grid-area**。引擎仍 = 尺寸真相（面板高/宽、侧栏宽），不推 x/y 绝对坐标（避免 iconbar 42/48 漂移等引擎≠DOM 问题）。

### 决策 3：池布局 grid 化（取代模型 A/B 二元）——对齐延伸的唯一可行结构
`pool-body` 改 CSS grid：
- 列模板（按 panel.edge + 可见性）：`[iconbar] [左槽] [主] [右槽]`；顶/底面板占**行**，左/右面板**插列**。
- **顶/底面板**：grid item 占行（顶=row1 / 底=row2），**列跨度按 align**（center=主列 / left=左槽+主 / right=主+右槽 / justify=全列）。
- **左/右面板**：全高竖条列（主区与对应侧栏之间——5 带排布）。
- **侧栏行跨度按「是否被顶/底面板覆盖」**：覆盖 → 仅一行（缩短）；未覆盖 → 跨两行（全高）。
- **纯 CSS 几何 → 换边/换位/对齐切换零 React 重挂 → 换位丢视图状态问题消灭**。
- **隐藏面板 = 不渲染 grid item + 模板去 track**（保「无面板贡献 = 零 DOM」验收）。
- 主区 = 主列网格单元（原 pool-main-column 内 MainZone 直接成 cell；PanelZone 移出为独立 cell）。

**grid 否决 overlay**（绝对定位面板 + 侧栏 padding + z-index 掩膜 = hack，且换边/换位仍须重挂）；**grid 否决 flex**（flex 表达不了对齐延伸）。

### 决策 4：floating 不复活（防死代码）
Phase 8 浮层走 FloatingPanelService（池 overlay），可拖出走主进程新 BrowserWindow——都不走 LayoutEngine floating zone。只恢复 dock 能力面。

### 决策 5：全量复活 5 方法（用户拍板）
`dockTo`（面板位置 + 侧栏换边）+ `addZone`（右侧栏 zone 消费方）+ `setLayout`/`getAllZones`/`removeZone`（能力面，带测试）。**新增 `setAlign(zoneId, align)`**（E5 无）。edge 类型加 `"top"`。

### 决策 6：右侧栏 = 真 zone + 双槽互换规则
`addZone("rightSidebar", {dock:{edge:"right", width:300, minWidth:180, maxWidth:600, resizable:true}})`——recalculate 右边堆叠数学现成。`dockTo("sidebar", edge)` 附 swap 规则：**sidebar 与 rightSidebar 恒占对边**（sidebar→right 时 rightSidebar 自动→left），对应用户「主侧栏换右、agent 跳左」描述。grid 列顺序随 edge 变 → 互换 = 纯 CSS 列换位。

## 6. 方案取舍（已收敛）

1. **grid 化采用**——对齐延伸唯一可行结构；否决 overlay（z-index 掩膜 hack + 换位重挂）/ flex（表达不了延伸）。
2. **面板对齐几何 = 池推导**（grid-template/grid-area 从 DTO 尺寸推）——不推绝对坐标，主列 1fr 轨道与面板同轨道 → 像素级对齐，零漂移。
3. **默认对齐 = center**（两侧栏全高，与现状视觉一致）。引擎现测试 panel x=0 w=800 保留（x/w 本就不被消费，S6 已文档化）。
4. **面板左/右 = 主区与对应侧栏之间竖条**（5 带排布，对应用户描述；具体与 agent 共存规则实现时确认）。
5. **换位丢视图状态 → grid 下消灭**（零重挂）。
