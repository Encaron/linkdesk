## 〇、一句话总览（大白话）

软件现在有两套「通知」浮层，都是对同一份通知数据的渲染：
- **右下角自动弹的窄小卡片**（叫 ToastHost）——信息容量小、鼠标一碰就左右抖（隐藏的 × 号顶出来推文字）、还偶尔跟铃铛宽面板**叠在一起**；
- **点铃铛出来的宽面板**（Notification Center）——按钮/来源/时间全有，但**文字不能复制**、**没有进度条**、**不自动弹**。

用户点名：**小卡片没有任何优点，删除它**（叠一起的 bug 也顺带消失）；**以后只有一种宽面板**，让它**重要通知自动弹出**、**文字能复制**、**装上进度条**。成功/普通提示照旧几秒自己消失（Q1 定案），重要的（失败/进度/带按钮）才自动展开面板（Q2 定案）。

本档案把这件事拆成 E6#72a-g，**用户点名即开工**。

## 二、🔬 现状事实（读码 + 实机量测，file:line 证据）

### F1 两浮层共用**同一份**通知数据（`toast.ts` 单一 store）

- 通知数据唯一真源 = [toast.ts](../../../../src/core/services/ui/toast.ts) `_toasts` 数组：`pushToast`（ttl 默认 6000 / `TOAST_PERSISTENT_CAP=5` 常驻顶老 / setTimeout 自消）、`dismissToast`、`updateToast(id,message,percent)`（71i 进度第三参）、`getToasts`、`setToastsSuppressed`（面板开→隐小卡）。
- **宽面板读它**：壳 `usePoolSync/notif.ts` `buildNotif(t)`（`getToasts()` → 按 source 分组 → 未读优先 → NotifLayout 推池）→ 池 [StatusBarZone.tsx](../../../../src/pool/zones/status-bar/StatusBarZone.tsx) 渲染铃铛面板 `.status-bar-notif-panel`。
- **窄卡片读它**：壳 `bridges.ts` `serializeToasts()` → `poolApi.pushToast` → `IPC.pool.toastShow` → window-manager `pushToast` → `IPC.pool.toast` → 池 preload `buildToast` 缓冲 → `window.linkdesk.toast.onShow` → 池 ToastHost.tsx 渲染右下 `.toast-item`。
- ⇒ 「删小卡片」= 删窄卡这条**渲染喂食链路**，不是删通知数据。数据、铃铛、宽面板全保留。

### F2 窄卡片（ToastHost）细节——71h/71i/71j 的功能都做在它上面

- 71h 恒全显+可复制、71i 进度条、71j 长驻**当前都渲染在窄卡片上**（ToastHost.tsx：`.toast-main-row` icon/message + `.toast-progress` fill/indeterminate + `.toast-details-row` source/actions）。
- 用户 P5/P6 纠正：这些功能的**正确落点本来就是宽面板**；71h「复制」当时是对着宽面板说的，做成了窄卡（窄卡本就能复制）。

### F3 宽面板缺的三样（实机量测）

- **不能复制**：面板消息 `.notif-panel-msg`（[StatusBarZone.css](../../../../src/pool/zones/status-bar/StatusBarZone.css) ~:221）`user-select` 非 text（量测 computed = none）+ 单行 `overflow:hidden; text-overflow:ellipsis`。
- **无进度条**：NotifItem DTO/面板 JSX/CSS 均无 progress/percent（对照 E3e 时代曾有的进度卡样式，被 E5.7#27.5 删，git 历史 `ec88c40ec` 可复刻）。
- **不自动弹**：`panelOpen` 是 StatusBarZone 局部 state，只能铃铛手动点开。

### F4 用户对 Q2 的裁决（推翻安静角标建议）

原建议「重要通知只亮铃铛角标不打扰」被否决；用户选「**重要的自动展开宽面板**」——成功/普通提示自动消失不打扰，重要的（error/warning/带按钮/常驻/进度）自动开面板让人看见。
