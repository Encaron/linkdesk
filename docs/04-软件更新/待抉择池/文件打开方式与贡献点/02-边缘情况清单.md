# 02 · 边缘情况清单（28 条）

> 规矩照 [滑杆件 02](../../已落地/滑杆件-Slider能力扩展/02-边缘情况清单.md) 的口径：每条 = 场景 → 规格行为 → 落格。**开工日先用阶段 0 勘察核对「现行为」三处，与本清单冲突的以实测为准回填**。

## A. 多插件竞争类（D7 主权三层的直接考题）

| # | 场景 | 规格行为 | 落格 |
|:--:|:--|:--|:--|
| E1 | 两只 pdf 阅读器都装了，用户**从没选过** | 默认=先激活先得＋pluginId 字典序 tie-break；第二只激活时 toast 一次「当前默认仍是 X，右键→打开方式可换」；选择器两家并列 | T2.5/D7 |
| E2 | 两只都装了，用户**选过** A | 覆盖表说了算，B 装上**不漂移**＋同款提示；选择器里 B 随时可挑、可设为默认 | D1/D7 |
| E3 | **两只编辑器同时挂牌** `role:"text-fallback"`（极客编辑器＋官方未卸——用户点名的现实场景） | 与 E1 同规，**零特殊逻辑**：先激活先得（=官方 editor）、提示、选择器并列；极客自己卸了官方再装 ⇒ 只剩一家自然接管。⛔ 不写「冲突处理」新规则——一套仲裁天然覆盖 | T7 |
| E4 | 极客作者的编辑器**改名怪异**（`MyEEEEEditor pro plus max ultra`） | 识别**只看声明**（它声明了哪些扩展名/角色），与插件名无关；选择器显示 displayName＋pluginId 副文本 | T2/T7 |
| E5 | 插件**已安装但被禁用** | 不参选解析（禁用=不存在）；选择器不列；若它是覆盖表指向者 → 按 E6 处理 | T2 |
| E19 | 两只 pdf 插件**同刻安装**（市场队列） | 激活顺序=安装队列序（稳定）；tie-break 兜底，无随机性 | T2 |
| E24 | 用户在 Windows 手动选过别的程序为 pdf 默认 | 壳只写自己 ProgId 的 `OpenWithProgids` **候选**，⛔ 永不碰 Windows 的 UserChoice（用户手选默认）——「加候选」与「夺默认」是两件事，后者禁止 | T6 |
