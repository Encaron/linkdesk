## 一、来源标注
- 列表/详情显示**来源仓库名**——用户装之前知道这是谁发的。
- 数据来自 E6#30c 多源（每个源 = 仓库 URL）；UI 落点 = 列表卡片 + 详情页元数据（E6#30.6c）。

## 二、下载数
- **来源不是我们统计**——GitHub Releases API 每个发布资产自带 `download_count`（GitHub 替所有下载者统计，我们只读）。
- 市场启动时拉一次 + 缓存；未认证 API 限 60 次/小时，5 分钟缓存后绰绰有余。
- 诚实边界：Gitee 源走 Gitee 自己的 API（实现时核字段）；连 API 都没有的自定义源 → **不显示下载数，不伪造**。

## 三、许可证
- **作者在 marketplace.json 里自己填**（MIT / Apache-2.0 / 闭源）——纯声明数据，不用扒。
- `license` 字段（E6#29c 格式扩展）+ 详情元数据侧栏展示（E6#30.6c）。

## 四、安装确认（E6#30.8a）—— 🔄 **2026-09-10 修订：由「每次确认」降为「每来源一次」**（E6#71k）

> **改了什么**：确认弹窗**不再每次安装都弹**。新规则见 [18-通知系统全账与设计定案 §五 J](18-通知系统全账与设计定案.md)（本档只记与信任域相关的结论）。
>
> **为什么改**：核实发现「侧栏连装 7 个插件 = 14 下」——其中一半是这张卡的第二次点击。且卡的 7 行内容**相对详情页是 100% 子集、零独有项**（相对侧栏行只多：许可证 / 官方徽标 / 可点仓库外链）。更要紧的是**卡当初的定位是「信息透明」，不是安全闸**（见下 §四.1 的原始理由）——把它按「每次都必须」执行，等于用**没有信息增量的重复点击**去兑换一种**它本来就提供不了的保护**。

### 四.1 原始设计理由（保留存档，仍是本档的定性基准）

- 点 🟢安装前，轻量确认弹窗：来源仓库 + 发布者/作者 + 一句话描述 + 许可证 + 版本 + 大小（视觉 = mockups/02 帧 8）。
- 弹窗 = 壳共享 Dialog（#dialog-root 保底 UI，实机已具）；内容数据来自 catalog `marketEntry`（E6#30c 多源目录条目）。
- **装前一刻看见自己装的是什么（对标：浏览器装扩展前的确认）**——⚠️ **定位 = 信息透明，不是拦截**。本档 §六 明确拒绝用黑名单/裁决做真实把关（零服务器做不了）。
- v1 不做评分/评论——零服务器做不了真实评级，伪造没意义；下载数 + 来源 + 许可证已是零成本信任底座。

### 四.2 现行规则（E6#71k 定案，2026-09-10 用户「同意你的想法」）

| 场景 | 行为 |
|:--|:--|
| **默认源（官方目录）** | **不弹卡**，直接安装——官方目录 = 平台自策展（对映 VS Code 对 Marketplace 扩展不弹信任框） |
| **未信任的第三方来源** | **首次**安装弹卡一次；点「确认安装」= 信任该来源（写 `marketplace.trustedSources`） |
| **已信任的第三方来源** | 后续同源插件**不弹卡** |
| **来源读取失败 / 老 preload 缺面** | **回落到「弹卡」**——安全默认是「**未知即未信任**」；⚠️ 反向（读不到就当已信任）是**静默安装漏洞** |
| **更新（`update`）** | **走同一个门**——今天 [`DetailView.tsx:403`](../../../../plugins/marketplace/src/views/DetailView.tsx#L403) 直调 `pm().update`，无确认、无信任查询，`autoUpdate` 勾上后连点击都没有。不补这条，「信任可撤销」就只是空话（撤销只拦新装、不拦变码） |
| **撤销** | 必须补「**管理信任的来源**」（列出 / 移除）——**「同意可否收回」本就是同意的一部分** |
| **http 源** | **不可记忆**（可被 MITM）⇒ 永远逐次问 |

### 四.3 🩸 诚实边界（不得含糊）

**上述规则不是安全机制，且只在市场 UI 层成立。**

- `linkdesk.pluginManager.installWithProgress` / `install` 是**任何插件都能调的公共 API**（[`contracts/linkdesk.d.ts:1209`](../../../../contracts/linkdesk.d.ts#L1209)），主进程**只做一个 http/https 正则、零信任判定**（2026-09-10 实证）。⇒ **任何已装插件都能绕开市场与信任表，从任意网址静默装下一个插件。**
- 全仓**零签名 / 零 checksum 校验**。
- ⇒ 文档与 UI 文案**不得宣称「更安全」**。真解（壳侧加门 + 签名链）= **新能力，须单独立项**。

## 五、minAppVersion 校验（缝隙 G1 🔴——字段设计了零消费）

> 01 §三 定义了 `minAppVersion`（最低壳版本）但此前**无任何任务消费**——设计完字段忘实现。本档定行为。

- 安装/更新前校验：`marketEntry.minAppVersion` vs 当前壳版本（semver）。
- **不足 → 拒绝安装** + error toast「需升级 LinkDesk 至 x.x.x 才能安装」+ 详情页元数据区显示「需 LinkDesk x.x.x」。
- 已装插件版本高于本地壳 → 已装不崩（插件本身能跑则跑），只拦**新装/更新**。

## 六、恶意 id 抢占（缝隙 G11/A3——多源安全）

> 多源市场 = 任何人可发布。恶意源用合法插件 id 发布假插件，同 id 冲突取版本高者（01 §六.4）→ 可能顶掉真插件提示。

- **来源标注做显眼**：详情页「来源仓库」展示完整仓库 URL（可点击跳转），列表卡片来源名可见——用户一眼知道装的是谁的。
- 同 id 多源冲突维持「取版本高者」（不引入黑名单——零服务器做不了真实裁决）；**来源标注是防抢占的信任手段**。
- 安装确认弹窗（§四）已含来源仓库——抢占场景下用户装前看见「这个来源」。

### 六.1 🔄 抢占与「每来源一次」的冲突，及修法（2026-09-10 补，E6#71k）

> **冲突**：§四 改为「每来源一次」后，**同 id 抢占会绕过唯一的看见来源的机会**——场景：用户已信任来源 X（以前装过 X 的插件），此时 X 发布了一个**与官方同名但版本更高**的插件，多源合并**取版本高者** ⇒ 官方 id 被 X 顶掉，而「装前看见这个来源」恰被「已信任 X，不弹卡」抑制 ⇒ **静默装上**。

- **修法：同一 id 的来源发生变更时，强制重问**（不看信任表）。判据 = `id 相同 且 sourceName 与上次安装该 id 时的来源不同` → 弹卡。
- **理由**：信任的单位是「**这个来源**」，不是「**这个 id 现在归谁**」——换人发布是**新信息**，必须让用户看见。
- **配套**：http 源恒不记忆（§四.2）；来源标注的显眼度要求不变（§八 官方徽标判定不因此改动）。
- ⚠️ **本修法是「每来源一次」能成立的必要件**，不是可选项——少了它，§四 的简化会把 §六 原本防住的场景**反向打开**。

## 七、更新后权限变化（缝隙 E3）

- 插件更新后**新增**权限请求 → 重新走审批（E6#49 审批审计），**不清已有 remember 授权，只补新授权的询问**。
- 已装插件更新不重置既有授权（用户信任不因更新被清零）。

## 八、官方发布徽标（缝隙 G1——派生判定，零新字段）

- mockup 详情页头部「官方发布」badge（帧 1-10）**不新增 catalog 字段**，由**默认源**派生：`source.id === 'official'`（01 §六 默认源约定）→ 显示「官方发布」徽标。
- 判定逻辑单一权威：**徽标 = `marketEntry.source.id === 'official'`**，随多源合并产物（E6#30c）走——壳/市场插件读同一条目，无第二份判断（归一化）。
- 自定义源 → 不显示官方徽标（不伪造认证）；来源仓库名照常展示（§一）。→ 落 E6#30.8f

### 9.1 minAppVersion 比对完成路径断点——壳版本 API 全仓缺失

- **§五「minAppVersion vs 当前壳版本」缺完成路径**：src/ + electron/ 全仓 grep `getVersion`/`appVersion` **零命中**——壳侧无任何版本查询 API，设置「关于」页也拿不到版本号。「当前壳版本」从哪来 = 未定义（判据⑤ 完成路径前置——开工才发现做不了，overlay 分割线同型）。
- **定型：新增通用壳版本 API `app.getVersion()`**——新 API，走设计 8 维度 + 契约四齐全（contracts/linkdesk.d.ts 类型声明 + preload 实现 + 主进程 IpcBridgeHandler 分发 + 03-插件制造 文档说明）。主进程 `app.getVersion()`（Electron 内建）→ preload 暴露 → 插件 `window.linkdesk.app.getVersion()`。
- 连带受益：设置「关于」页未来显示版本号 = 消费同一 API（归一化——一个概念一处写，不另起来源）。
- ✅ **已交付（2026-09-10 核实，E6#57 域）**：`window.linkdesk.app.getVersion(): Promise<string>` 已上线——契约 `src/core/api/linkdesk-api/app.ts:13` + 双 preload 同步暴露（`electron/preload-pool/namespaces-data.ts:105` / `electron/preload-shell.ts:143`）+ 主进程直答（`electron/ipc/handlers/product-handlers.ts:26`，真值来源 = 主进程 `app.getVersion()`，package.json 单点）。**本档 §五 的 minAppVersion 比对即该 API 的首个消费方**（落 E6#30.8f）；上面的「定型」是 2026-08-30 的决策记录，实现已由 E6#57.2a/2b/3b 兑现，本档不重复实现、不在本档新增 API。
