## 二、修复方案

### 2.1 E5#34——render 路径相对化

**当前（marketplace/plugin.json）：**
```json
"render": "../../plugins/builtin/marketplace/src/views/SearchView.tsx"
```
**问题：** 路径从 repo 根出发——`../../` 要求插件目录在 `plugins/builtin/marketplace/` 的嵌套层数不变。

**修复——render 路径相对于插件根目录（和 entry 一致）：**
```json
"render": "src/views/SearchView.tsx"
```

**loader.ts 消费端改造（L467）：**
```typescript
// 当前
await import(viewDef.render);  // "../../plugins/builtin/marketplace/src/views/SearchView.tsx"

// 改为——拼接插件根路径
const pluginDir = getPluginDir(pluginId);  // "plugins/builtin/marketplace"
const renderPath = joinPath(pluginDir, viewDef.render);  // "plugins/builtin/marketplace/src/views/SearchView.tsx"
await import(/* @vite-ignore */ renderPath);
```

**影响：** 8 个 plugin.json render 字段 + loader.ts 的 import 逻辑。

### 2.2 E5#35——glob 模式常量化

**当前（loader.ts L61-103）：**
```typescript
const pluginModules = import.meta.glob("../../plugins/builtin/*/index.tsx", ...);
const pluginModulesSrc = import.meta.glob("../../plugins/builtin/*/src/index.tsx", ...);
// ... 10 个 glob，每个硬编码完整路径
```

**问题：**
- 新增插件类别（如 `third-party/`）→ 每个 glob 加一个
- 改成 `src/` 子目录统一 → 删一半 glob
- 目录名变了 → 全改

**修复——提取常量和工厂函数：**
```typescript
// src/core/pluginPaths.ts——目录约定唯一定义

/** 插件根目录 */
export const PLUGINS_DIR = "plugins";

/** 插件子目录 */
export const PLUGIN_SUBDIRS = ["builtin", "user"] as const;

/** 插件入口文件约定 */
export const PLUGIN_ENTRY_FILES = ["index.tsx", "src/index.tsx"] as const;

/** 生成 plugin.json glob 模式 */
export function pluginJsonGlobPatterns(): Record<string, unknown> {
  const patterns: Record<string, unknown> = {};
  for (const sub of PLUGIN_SUBDIRS) {
    patterns[`../../${PLUGINS_DIR}/${sub}/*/plugin.json`] = { eager: true, import: "default" };
  }
  return patterns;
}

/** 生成插件入口 glob 模式 */
export function pluginEntryGlobPatterns(): Record<string, unknown> {
  const patterns: Record<string, unknown> = {};
  for (const sub of PLUGIN_SUBDIRS) {
    for (const entry of PLUGIN_ENTRY_FILES) {
      patterns[`../../${PLUGINS_DIR}/${sub}/*/${entry}`] = {};
    }
  }
  return patterns;
}
```

**loader.ts 改为：**
```typescript
import { pluginJsonGlobPatterns, pluginEntryGlobPatterns } from "@src/core/pluginPaths";

const pluginManifests = import.meta.glob(pluginJsonGlobPatterns());
const pluginModules = import.meta.glob(pluginEntryGlobPatterns());
```

**影响：** loader.ts + plugin-shell-main.tsx + vite.config.ts——全部从 `pluginPaths.ts` 读目录约定。

### 2.3 融入 E5#20——`getAssetPath()` 审计

`getAssetPath()` 只被 TitleBar logo 用了一次。检查是否其他资产路径应该用它。

**保留在 `src/core/assetPath.ts`。** 它是硬约束 #12 的代码防线——不是"目前只用了一次所以不重要"，是"每个资产路径都必须经过它"。E5 标准化插件资源路径后，plugin.json 的 icon 加载也应走 `getAssetPath`。

## 🔴 预测 Bug

### Bug E5-34a 🔴 render 路径改为相对后 import 失败——Vite 不识相对路径

**触发条件：** `import("src/views/SearchView.tsx")`——Vite 必须知道这是相对于哪个目录的。

**🔥 防线——loader.ts 拼完整路径再 import：**
```typescript
// 不是直接 import(viewDef.render)——拼完整路径
const pluginDir = getPluginDir(pluginId);       // "plugins/builtin/marketplace"
const fullPath = `${pluginDir}/${viewDef.render}`;  // "plugins/builtin/marketplace/src/views/SearchView.tsx"
await import(/* @vite-ignore */ fullPath);
```

---

### Bug E5-35a 🔴 glob 模式字符串拼接——Vite 静态分析不识别

**触发条件：** `import.meta.glob` 的第一个参数必须是**字符串字面量**——Vite 在编译时静态分析。如果改成函数返回 → Vite 可能不识别。

**🔥 防线——验证 glob 是否支持变量：** Vite 5.x 的 `import.meta.glob` 支持字符串变量（不是字面量也行）。但保险起见，用 `as const` 和模板字面量。

**如果 Vite 不支持变量 glob：** 将所有字面量集中到 `pluginPaths.ts`，ESLint 自定义规则拦截在其他文件写 glob 字面量。两种方案等价——都是一处改全部生效。
