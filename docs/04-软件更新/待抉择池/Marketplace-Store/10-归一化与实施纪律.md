# 10-归一化与实施纪律（R4 落码的硬门槛）

> **为什么存在**：2026-11-19 用户明确要求——「你已有的插件市场情况会更复杂，因为它已经有很多已经实现的逻辑。你有的时候需要接线，有的时候需要创造新 UI，有的时候需要做别的东西。所以说你到时候这个归一化一定是记在深刻的脑子里。组件的归一化、UI 的归一化、逻辑的归一化，还有 AI 友好化、无硬编码、无死代码、高内聚低耦合——这么多要求都是必须一一实现的。哪怕你在 HTML 里没有做好，你必须把它记住，在真实实现里面必须把它做好。」
> **定位**：本档是**落码纪律**，不是设计稿。设计在 03/04/05/09，数据在 06；本档管「怎么动手才算合格」。
> **上游**：[00-README](00-README.md) §工程规范（六条总纲）；**下游**：R4 每一刀实现的提交自检与验收。

## 一、四层归一化（缺一层就不合格）

| 层 | 唯一来源 | 违规长相 | 怎么查 |
|---|---|---|---|
| **组件** | 同一种角色只有一个组件：ViewSeg（平铺⇄详细）／SortChips／EmptyState／Badge／ActionButton／RailItem／五类卡 | 同一按钮在 4 个页面各写一遍（蓝图 v3.53 已收口） | 同一 className 出现在多处 JSX、结构近似但实现不同 |
| **UI** | 颜色/字号/间距/圆角/阴影只走令牌；**顺序也是规范**（视图切换全站平铺在前） | 裸 `#E06C75`、`width:13px` 写死在组件里；两页按钮顺序相反 | grep hex／grep `style={{`；截图对比两页同类控件 |
| **逻辑** | 同一个事实只有一个求值入口 | 新商店自建第二份「已安装列表」「更新状态」 | grep 状态读取点；同一 IPC 被两处各自订阅 |
| **数据** | 见 [06-数据设计](06-数据设计.md)：单一目录、白名单、类型↔Schema↔白名单三方对账；偏好见 06 §八 | 目录/来源/偏好各写一套读写 | 三方对账测试 |

| 最低壳版本门 | `src/services/minAppVersionGate.ts` |

## 二、接管老代码的三种动作：接 / 改 / 删

| 动作 | 什么时候用 | 纪律 |
|---|---|---|
| **接** | 现有能力已覆盖需求 | 不改签名；新 UI 订阅现有 store/命令；⛔ 不复制逻辑进组件 |
| **改** | 现有能力覆盖 80%，差参数/差字段 | 在**原函数**上扩展（参数、返回字段、事件）；同笔补测试；⛔ 复制一份改 |
| **删** | 能力被新实现取代 | 同笔删干净：调用点、测试、样式、导出、注释块；grep 证明 0 引用 |

⛔ **第四种不允许**：新建一套并行实现、旧的留着「以防万一」。

## 三、AI 友好化（判据：新 AI 不看聊天记录也能改对）

1. **一个 feature 一个夹**，文件按职责命名（视图／行／动作／数据），⛔ 平铺。
2. **单一入口**：一个动作＝一条命令或一个函数；UI 只调入口。
3. **显式依赖**：props/context 传入；模块级可变单例要先证明必要（`realmSlot` 是既有例外机制，不是新代码的许可证）。
4. **注释写为什么**，不写做了什么；结论带理由。
5. **⛔ 隐式约定**：不靠文件名、不靠调用顺序、不靠「大家都知道」。
6. **GUI 动作 ↔ 命令一一对应**（2026-11-19 用户要求「一切 GUI 层面的动作都必须有 AI 的友好性操作」）：每个可点/可切的动作都要有可编程入口（命令或 API），**同一动作只有一个 id**，能复用壳能力的不在插件里再造。清单见 [09 §三·补](09-API设计.md)。⛔ 只做按钮不做命令。

## 四、无硬编码（逐类）

| 类别 | 正确来源 | 违规示例 |
|---|---|---|
| 颜色 | 主题令牌 | `#E06C75` 直写 |
| 尺寸/间距/圆角 | CSS 变量或工具类 | `style="width:13px;height:13px"` |
| 文案 | `t()` / i18n 文件 | 中文字面量进 JSX |
| 分类显示名 | 值表（04） | 渲染里写死中文 |
| 路径 | `env.pluginDataDir` / `storage.cacheDir()` | 手拼 `%APPDATA%` |
| 状态集合 | 枚举/常量 | `"installed"` 散落各处 |
| 版本/包名/仓库 | manifest 或常量 | 字面量 |
| 声明字段名 | 06/09 的 schema 常量 | 各处手写字符串 |

自查（R4 每刀跑）：`grep -rn "#[0-9A-Fa-f]\{6\}" src`、`grep -rn "[一-龥]" src/views --include=*.tsx`（人工确认是否该走 t()）、`grep -rn "AppData\|%APPDATA%" src`。

## 五、无死代码

- 被替代的旧实现**同笔删除**：调用点、测试、样式、导出、注释掉的整块。
- 删除判据：全仓 grep 0 引用 ＋ `npm run check` 绿。
- ⛔ 用 `// TODO 以后删` 当墓碑；要么现在删，要么在 [12](12-待讨论清单.md) 立项。

## 六、高内聚低耦合

- feature-folder；单文件行数预算照仓内既有判据，超限即拆（参考 DetailView 的六 hook 拆法）。
- 纯函数分离：解析/排序/筛选不进 JSX。
- 依赖单向：`views → services → @linkdesk/*`；⛔ services 反向 import views。
- 跨表面共享走 `realmSlot`／共享 chunk；⛔ 每表面各持一份模块级状态（实机已踩：检查更新后详情页不刷新，E6#158）。
