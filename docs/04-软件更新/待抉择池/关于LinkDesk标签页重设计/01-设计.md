## 三、设计理念（本设计的核心）

> **一句话：把「关于」从一张字段清单，变成一张完整的软件名片——居中立着、分区讲清、能点能选、一次带走。**

三条原则（后文所有取舍都从这三条推出来）：

**① 版心居中，卡内左对齐。**
居中的是**版心和区块**（hero 居中、卡片在版心中齐宽），**不是每一行文字都居中**。理由：`key: value` 逐行居中会让标签列与值列在每行各自摆动，读者的眼睛读不出一条竖线，反而不成表。这条是**口径声明**——若用户要的是「整体版心居中」，即本设计；若是「每行文字都居中」，改一行 `text-align` 即可（**已定 2026-09-26：采用本设计口径——版心居中、卡内左对齐**）。

**② 凡是身份/联系方式/出处，一律做成「可点」或「可选中」。**
- 邮箱 → `mailto:` 链接（点开系统邮件客户端）；**一主一备排两行**（主场走链接色，备用场降一档），读起来是「备用联系方式」而不是「两个都请来找我」；
- GitHub 主页 / 许可证全文 / 源码仓库 → 外链（走系统浏览器，**软件本身不离开**）；
- 整页文本 → 可划选（照 `E6#72b` 先例）。
⇒ 「复制」按钮**保留不变**：它解决的是**一次性整份带走**（贴进 issue），划选解决的是**只摘一段**（版本号 / 一个邮箱 / 一个 GitHub 账号）。两者是**两条路，不是新旧替代**。

> ⚠️ **一处自我订正（2026-09-26 二轮）**：曾提议把邮箱**从 `mailto:` 改成纯文本**以求「少一个爬虫抓手」。**这个理由站不住**——主流邮箱爬虫同时扫 `mailto:` 与正文里的 `@…` 模式，纯文本只是少一类**只认 href** 的爬虫，**不是少一个入口**；而它会把「点一下就写信」降级成「先划选再 `Ctrl+C`」，拿真金白银的便利换一个说不清的收益。⇒ **保留可点的 `mailto:`**（真要防爬得上混淆，那是另一件事）。**它与划选不冲突**：想复制地址的人照样能划选。

**③ 只搬既有命令，零新能力。**
本页新增的每一个动作都**已经有命令源**，本项一个命令都不新建：

| 动作 | 复用哪条既有命令 | 现状 |
|:--|:--|:--|
| 复制 | `app.aboutCopy` | 既有（`E6#57.14`） |
| 检查更新… | `update.checkForUpdates` | 既有（本页是它的**第四个**入口） |
| 发行说明 | `update.openReleaseNotes` | 既有（兄弟标签页的入口） |
| MIT 全文 | `app.viewLicense` | **既有**（`E6#57.10e`，2026-09-13） |
| 源码仓库 | 无命令——用 `window.open` 走 `E6#70c` 的全局外链路由 | 既有机制，零新增 |

**「入口可多处，命令源唯一」**（`E6#57.10`）——本页只是把这些命令的落点再加几处，不复制逻辑。

## 五、8 维度设计（对既有视图的增量）

### ① 能力边界
壳内视图的**版式重排 + 一个身份字段**，非新能力。**保底**：`author` 取不到时**整块卡片不画**（不是画一屏 `—`）——「没有作者信息」与「读不出来」是两件事，后者才是 `—`。无插件参与，卸载一切插件后本页完整可用。

### ② API 设计
**零新 API。** 唯一新增的是**数据**不是能力：`electron/product.json` 加 `author` 块（身份唯一真相源，见 [`02-产品身份与版本.md` §2.2](../../../02-Electron架构/E6_插件生态与发布/06-主软件更新/02-产品身份与版本.md)）。三处形状同笔：`electron/product.ts` 的 `DEFAULT_PRODUCT`、`src/core/types/ipc/product.ts` 的 `Product`、契约文档 `07-数据流通格式.md`。**发布脚本不必改**——`author` 是手写常量，不是构建期注入字段（同 `nameLong`）。

### ③ 通信方式
**零新通道。** 沿用既有两条：取数「**壳想池画**」（壳组 DTO → 挂 `PoolTab.about` → 池只 `map`）；动作池 → 壳走 `executePoolCommand` → `commands:execute`。外链不新开通道——`window.open` / `target="_blank"` 由 `E6#70c` 的 `setupExternalLinkRouting()` 统一转 `shell.openExternal`。

## 七、🔴 跨仓后果与机械门禁（开工前必须知道）

### 7.1 i18n 词典住在**外部插件仓**（最易漏）

本页所有界面文字走 `t()`，key = **中文原文**，而**应用级词典住在出厂插件 `lang-defaults`**（`src/i18n/index.ts:20`：第 1 层翻译资源由插件系统提供；`scripts/audit-i18n.mjs:72`：应用级字典 = lang-defaults 插件）。**本仓只有它的产物**（`bundled-plugins/lang-defaults.linkdesk-plugin`），源码在外部仓（L7 外移）。

⇒ 新增键（`作者` / `邮箱` / `本版本` / `运行环境` / `查看许可证` / `发行说明` / `通道` / `稳定版` / `源码仓库` / 版权行…）必须落**那个仓**的 `en.json` + `zh.json`，**同时**：该插件 PATCH 发版 → 官方目录收录 → `npm run sync:bundled -- --latest` 追账（种子盒与目录同版不同内容会被 `check-bundled-freshness` 判红）。

**判红机制**：`npm run check` 链里的 `node scripts/audit-i18n.mjs --strict`——源码里 `t()` 的字符串若不在随壳种子的词典里，**红灯**（脚本尾行原话：「修复：将以上字符串添加到对应插件的 i18n/en.json 或 lang-defaults/en.json」）。

⇒ **这一条不是"顺手"，它自带一次插件发版。** 开工前先跟用户确认这次要不要连发。

### 7.2 版式门禁（mockup 的值不能照抄进 CSS）

同 `AboutView.css` 头注记的那套（当年逐条记账过），重排后**照样要过**：

| 门禁 | 判据 | 对本页的影响 |
|:--|:--|:--|
| `check-spacing-grid` | `padding`/`margin`/`gap` 的 px 必须 **≤6 或 4 的倍数** | 参考图里的 `gap: 10px`/`padding: 14px` 之类一律吸附 |
| `check-font-scale-audit` | **禁裸 px 字号** | 必须落 `--font-size-2xs/xs/sm/lg/xl/2xl`（真值 11/12/13/16/18/22） |
| `check-css-hardcode` | **禁硬编码色** | 全 `var()` |
| `check-css-namespace` | 类名前缀 / token 作用域 / 选择器形态 | 继续 `ldk-about-*`；token 只许定义在宿主契约块 |
| `check-file-size` | 单文件上限 | 若 `AboutView.css` 膨胀过头，先看能否靠减少重复规则解决 |

### 7.3 版本类别（硬约束 22）

本项改 `src/` + `electron/` ⇒ 提交前必须**调 `version-bump` skill 判类别**：按现行口径 `feat:` → **MINOR**。⚠️ **本轮交的是文档与参考图（`docs/` 下），不触发版本号**；开工那一笔才判。
