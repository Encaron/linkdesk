### ⑶ 重点介绍你即将执行的轮次（7.2 逐个迁移）

**详案**：[03-逐个迁移.md](03-逐个迁移.md)（三步物理动作 + 批 A/B 切分 + 抽子树四验 + 12 类绑定拆除清单 + 逐只判据）。**本轮的难点不是 `mv`，是第 ③ 步「拆绑定」。**

**🔴 开工前必须先解决的阻塞（7.1 实测留下，必读）**：

1. **npm 两个包必须先发布，否则插件仓构建不起来**——7.1 给 `@linkdesk/plugin-sdk` 加了 `pack` 子命令（0.1.13 → **0.1.14**）、给 `@linkdesk/contracts` 加了 `PluginManifest.pluginId`（0.1.12 → **0.1.13**），**只 bump 未发布**（黄灯留在 `check-npm-release`，发布是要用户点头的外向动作）。插件仓里 `npm install` 拿到的 0.1.13 **没有 `pack`** ⇒ 批 B 的 12 只 JSON 插件构建必失败。**⇒ 开工第一件事：请用户发 `@linkdesk/plugin-sdk@0.1.14` + `@linkdesk/contracts@0.1.13`，然后 `npm run release:mark` 灭灯。**
   - 💡 **本轮仓外验证的现成做法**（7.1 已验证过 7 只）：`cd packages/plugin-sdk && npm pack --pack-destination <dir>` → 临时工程 `devDependencies` 指向该 tgz（等价于「货架上有这一版」）→ `npm install && npm run build`。**发布前想先跑通流程就用这招**，但**插件仓正式形态必须依赖 npm 版本号**，不许把 tarball 路径写进提交。
2. **🔴 重打的 zip 一定会与壳仓现存种子指纹不同 ⇒ 会要求 bump 版本**。原因不是搬迁，是 **7.1 给 18 只 `plugin.json` 各加了一行 `pluginId`**（7.1 实测：同一输入下 SDK pack 的产物与既有 zip **指纹逐字相同**；加了 `pluginId` 之后**只有 `plugin.json` 一个条目变了**）。`03 §3.3` 写的「搬迁不是内容变更、不 bump」在**本轮的具体数据下要照实测改判**：**先跑门禁再判**（`check-bundled-version-bump` 说 identical 就不用 bump；说 red-same-version-content-diff 就必须 bump）。反正批 A/B 都要进 7.3 上架发版，**bump 是顺路的**。
3. **`plugins/` 会只剩两只夹具**（`panel-demo` / `floating-panel-demo`）——它们**不发货、留在壳仓、脚本继续走相对路径**（7.1 只同步了它们的版本号，**没动脚本**，这是刻意的）。

**7.1 已经替 7.2 铺好的路（别重复做）**：

- **身份显式化（`#98g`）已落地**：`pluginId` 进 schema + **20 只全显式声明** + 兜底保留但打黄灯。**7.1 负控实测**：把插件拷成目录名 `renamed-dir-check` 构建 ⇒ 产物仍是 `file-tree.linkdesk-plugin`、包内 `pluginId=file-tree`。⇒ **「不许改目录名」这条迁移红线的原始目的（防身份漂移）已经达成**（[09 §六](09-命名规范.md)）。目录名现在**可以**改，但**仍建议保持 = id**（省得对账时多一层换算）；**不许改的是 `pluginId` 的值**。
- **`#98c` 的 pack 通道已落地且**：SDK 新增 `linkdesk-plugin-sdk pack`（`--out <path>`），**壳仓 `scripts/pack-bundled-plugins.mjs` 已改成只做编排**（打包实现全仓只此一份；SDK 未构建时它会自动 `tsc` 一次）。⇒ `03 §4.1` 第 10 条**已有答案**（取甲案）。批 B 的 12 只插件现在各自有 `package.json`（`build` = `linkdesk-plugin-sdk pack`）。
- **LSP 链已就位且抓到一处真缺陷**：`check-lsp-deps.mjs` 早就基准参数化（`cliBase ?? dirname(plugin.json)` + 向上解析），`check-lsp-args-base.mjs` 是**锚词门禁**不是路径门禁（**两处都不用改**）；`check-lsp-smoke.mjs` 原本缺向上解析 ⇒ pyright 被 hoist 到仓库根后**恒报缺失**（改动前就是红的），已修、现全链路绿。⚠️ **python 搬走后两件事要做**：① `package.json` 的 `lsp:smoke --base plugins/python` 改指新位置；② `check-lsp-deps` 扫 `plugins/` 将**扫不到任何 langDefs ⇒ 真空绿灯**——**逐条给结论，不许默默失效**（`03 §4.1` 第 9 条同款纪律）。
- **版本门禁已进 `check`**：`scripts/check-plugin-version-sync.mjs`（带 `--self-test`）。⚠️ 插件源码搬走后它对发货插件同样会**真空**——7.5 要给每只插件仓自己的那份检查（或共享 SDK 侧实现）。
- **根 `workspaces` 已加 `packages/*`**（`knip.json` 的 `ignoreWorkspaces` 同步）：插件的 `build` 改 npm 包形态后，**仓内靠 workspaces 链接到本地包、仓外靠货架**，同一份 `package.json` 两个环境都对。拆 `plugins/*` 时**别把 `packages/*` 一起摘掉**。

**🔴 三条不可违的红线**（层头已立，此处再钉一遍）：① **搬一只 → 构建验证一只 → 上架一只 → 壳仓那份删净一只**（中间态 = 双真相源，**无门禁可发现分叉**）；② **`git push` 与「写官方目录仓库」都要用户点头**（memory `push-wait-for-user`）；③ **壳代码零插件 ID 字面量**（硬约束 10）。

**顺手留意**：`10-作者文档族对账.md` 的 **B 批已基本落笔**（7.1 同笔改了 `03:623` / `09:94` / `06` 的 pluginId 行与最小示例 / `02` 的裁决行；`00-README` 的 15/16 入口 7.0 已有）；**C 批等你**——`04-插件分发格式.md`（两代码根表 → 三行，**改动最重**）、`13`（上架是两步）、`01`/`05`/`10`/`11` 里的 `plugins/<id>/` 路径引用、`06` 的「本文件恒指插件自己仓根」。**收口在 7.7，但 C 批随 7.2 搬完就该动**（搬一只改一只，别攒到最后）。
