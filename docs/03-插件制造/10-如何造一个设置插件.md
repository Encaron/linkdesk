# 如何造一个设置插件

> 2026-08-22（E5.8#41.15）。**给第三方插件作者。** 你的插件想给用户一个"设置 UI"？不用改壳——声明一个 `factoryRole: "settings"` 插件即可。这是**整套设置 UI 的完整替代品**，不是往里加一个设置项。

## 这是什么

**设置插件 = 一整套设置界面。** 声名 `factoryRole: "settings"` 的插件，会与内置设置并存：

- 用户打开设置（`Ctrl+,` / 齿轮）→ 进**当前激活套**的 UI（没切过 = 内置）
- 可装多套 → 每套设置 UI 顶部有个**通用区**，列出全部 N 套（含自身），点哪套切到哪套
- 激活套选择**持久化**，重启保持

关键心智：**设置插件的 UI 只是渲染器，数据永远在同一个地方。** 所有套 UI 都调同一个 `window.linkdesk.configuration` API、看到同一份数据——切套只是换渲染器，数据不动。这不是"数据私有/公开"之分，是**一致性**：人人看同一份。

## 最小声明——plugin.json 三步

照内置设置（`plugins/builtin/settings/plugin.json`）写：

```jsonc
{
  "$schema": "../../public/schemas/plugin.schema.json",
  "name": "漂亮设置",                       // 插件名——通用区按钮显示的就是它（走 t()）
  "version": "1.0.0",
  "icon": "resources/icon.png",
  "distribution": "user",                   // 用户插件 = 可卸载（core: true 才不可卸）
  "factoryRole": "settings",                // ① 关键——声明自己是"设置套"的一份子
  "entry": "src/index.tsx",                 // 标签页入口（appearsIn.tabBar 需要 entry）
  "appearsIn": { "iconBar": "bottom", "tabBar": true },
  "tabBehavior": { "singleton": true },     // 单例——切换时已开就不重复开
  "contributes": {
    "viewsContainers": {
      "settings": { "title": "设置", "location": "auxiliarybar" }   // ② 视图容器
    },
    "views": {
      "settings": [
        { "id": "settings", "title": "设置", "render": "src/views/SettingsView.tsx", "order": 0 }
      ]
    },
    "floatingPanel": { "viewId": "settings" }   // ③ 悬浮面板形态（可选）
  }
}
```

三个关键声明缺一不可：**`factoryRole: "settings"`**（进通用区候选列表）+ **`contributes.views`**（真实渲染组件）+ **`floatingPanel`**（`Ctrl+,` 兜底形态）。

## 数据 API 形状——全走 `window.linkdesk.*`

设置插件**禁止 `import @src/core/...`**（插件通信铁律 + ESLint `noCoreImportInPlugin`）。数据全在公开 API：

| 你要的 | 调用 | 返回形状 |
|------|------|------|
| 全部配置分组 | `window.linkdesk.configuration.getConfigurationContributions()` | `[pluginId, { title, properties }][]`（具名类型 `LinkDeskConfigurationContribution`） |
| 合并 schema | `window.linkdesk.configuration.getSchema()` | `LinkDeskConfigSchema`——含 `type/default/description/enum/enumDescriptions` + **`uiHint`/`minimum`/`maximum`/`renderHint`/`dependsOn`**（类型补全，官方控件切色的依据） |
| 读/写/订阅配置 | `configuration.get/set/onChange` | 通用 API，任何插件可用 |
| 设置页专用刷新 | `configuration.onDidChangeConfiguration(cb)` | 配置变 → cb(key, value)，UI 实时刷新 |
| 配置分组跳转 | `configuration.consumeSettingsGroup()` / `onRequestSettingsGroup(cb)` | 打开时切分组 |
| 滚动到某设置 | `configuration.consumeScrollToSetting()` / `onRequestScrollToSetting(cb)` | 打开时滚动定位 |
| 快捷键页数据 | `window.linkdesk.keybindings.getKeybindings()` | `Keybinding[]`（快捷键 UI 的数据源） |
| 主题选择器 | `window.linkdesk.commands.executeCommand("workbench.action.selectTheme")` | 唤起主题 QuickPick |
| 语言选择器 | `window.linkdesk.commands.executeCommand("workbench.action.selectLanguage")` | 唤起语言 QuickPick |
| 插件装卸刷新 | `window.linkdesk.configuration.onPluginLifecycleChange(cb)` | 装卸插件 → cb，重拉候选/按钮消失 |

**`settings.json` 文件名常量 = 数据契约一部分。** 内置设置"以 JSON 打开"按钮这么定位落盘文件：

```ts
const dir = await window.linkdesk.path?.appDataDir?.();
const filePath = dir ? window.linkdesk.path.join(dir, "settings.json") : "";
```

文件名就叫 `settings.json`，没有壳侧 map——照抄即可。

## 白名单共享控件

设置 UI 用的 8 个共享控件在 `@src/components/shared/`（**例外表白名单**，可以 import；`@src/core/` 不行）：

`ContextMenu` · `InlineInput` · `SelectBox` · `Toggle` · `ColorPicker` · `FontFamilySelect` · `FilePathInput` · `NumberInput`

vite glob 自动发现 `plugins/{builtin,user}/`（两级）——控件和插件同工程编译，不用额外配置。

## 编排层自由组合——数据一样，想怎么排就怎么排

数据 API 只决定"有什么数据"；**布局是你的自由发挥**。现役两个例子就是反例对：

- **内置设置**（`plugins/builtin/settings/`）= 左分组树 + 右表单 + 顶部平铺切换条
- **settings-demo**（`plugins/user/settings-demo/`）= **从零编排**的「漂亮设置」——banner 头 + 卡片分区（全部配置组 = 卡片，含角色胶囊行 + 快捷键键帽卡）+ 右下角胶囊切换套（E5.8#41.17 大改；形态二设计源 = 工厂角色并存 mockup `01-形态一形态二-复杂场景图.html`，非内置副本）

编排维度：分组导航 / 搜索框 / 控件渲染 / "以 JSON 打开" / 快捷键子页 / banner 头 / 卡片分区——每样都可以做、可以不做、可以换位置。

## 切换激活套——通用区按钮 + 全插件侧换套

每个设置插件的顶部通用区渲染**全部 N 套按钮（含自身）**，当前激活套高亮。点击切换 = **全插件侧换套**，零壳改动：

```ts
async function handleSettingsSwitch(targetId: string) {
  await window.linkdesk.factorySlots.setActive("settings", targetId); // ① 落盘持久化
  if (tabId) await window.linkdesk.tabs.close(tabId).catch(() => {}); // ② 关本套标签页（tabId 由壳注入）
  await window.linkdesk.tabs.create(targetId).catch(() => {});        // ③ 开目标套（singleton 去重）
}
```

组件在 `{ isActive, tabId }` props 里收 `tabId`（壳注入；浮动面板无标签页时为 `undefined`，此时只开目标套）。

通用区按钮数量 = **活集合运行时推导**——删任意一套 → `onPluginLifecycleChange` → 重拉 → 按钮自动消失。

## 造法一：复制内置（最快）

复制 `plugins/builtin/settings/` 整个目录到 `plugins/user/<你的id>/`，只改：

1. `plugin.json`——`name`/`description`/`distribution: "user"`（去掉 `core: true`），新增 UI 文案见下方 i18n 节
2. 追加你自己的风格到 `src/views/SettingsView.css`——**但覆盖规则必须挂你自己的根类**，见下方「🔥 CSS 作用域铁律」

内置设置**零 `@src/core` import**（历史两个 `@src/core` 依赖已随 E5.8#41.14 消除：`getFilePath` → `path.appDataDir()` 自推导；`useConfigurationIpc` → 直接调 `window.linkdesk.configuration.*`），复制即得自包含。

## 造法二：从零编排（参考 `settings-demo`）

`plugins/user/settings-demo/` 就是"数据一样、画布全换"的完整参考：**不复制内置组件结构**，组件只依赖数据 API + 8 个白名单共享控件，布局完全自己画——banner 头、卡片网格、角色胶囊行、快捷键键帽卡、右下角悬浮胶囊，全是 `settings-demo/src/views/SettingsView.tsx` 一手编排。

## 🔥 CSS 作用域铁律（E5.8#41.17）

**两个设置套的 CSS 注入同一个 Pool 文档。** 你的覆盖规则若写裸共享类（如 `.settings-form .settings-row`、`.settings-role-switch--gen`），会和内置套的同类规则打架——后注入者赢，内置套被你的样式污染（真机实测 bug 2：demo 的卡片气泡泄漏进内置套）。

结构性解法 = **你自己的根类命名空间**（`settings-demo` 是这么做的）：

- 根元素挂一个独有类（`.settings-demo`），所有覆盖/新增规则一律挂它：`.settings-demo .settings-row { ... }`
- 规则只命中你自己子树 → 内置套零受影响；且自带"样式自包含"（内置套 CSS 加载与否都不影响你）
- 自己的新组件类也用独有前缀（`.sd-*`），别用裸名（`.keycap` 也要挂 `.settings-demo .keycap`）

## i18n 新文案（i18n 审计门禁）

新增 UI 文案走 `t("中文原文")`；`npm run check` 的 i18n 审计要求**每个新 key 有英文翻译**，否则红灯。设置插件在 `contributes` 声明翻译文件即可：

```jsonc
"contributes": {
  "i18n": { "en": "i18n/en.json" },
  // ...
}
```

`i18n/en.json` = `{ "中文原文": "English" }`（zh 不需要——中文 key 自带兜底）。参考 `plugins/user/settings-demo/i18n/en.json`。

## 验证

- `npm run check` 全绿（tsc + ESLint 零警告 + vitest）
- 实机：装进 `plugins/user/` → 重启 → 图标栏出现 → 打开设置 → 通用区出现新按钮 → 点击切换 → 持久化重启保持
- 可卸载重装（可卸载 ⇒ 可重装 = 插件性定义本身）
