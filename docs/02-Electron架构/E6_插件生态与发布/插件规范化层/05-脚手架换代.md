## 〇、先回答用户的三问

### Q1：为什么生成 `.vscode/`？当时为什么这么造？

**不是失误，是 2026-08-30 那次夹具批（`85e3a98b2`，E6#21-#22）明确加的**（[01-脚手架档案 §二/§六](../02-插件开发工具链/01-create-linkdesk-plugin脚手架.md)）。

**它解决的问题是真的**：模板的 `plugin.json` 是 **JSONC**（带 `//` 注释 + 尾逗号，对标 VS Code 的 `package.json`）——而 VS Code **默认按 JSON 解析 `plugin.json`** ⇒ 作者一打开就是**满屏红波浪线**，注释全被标成语法错误。

```json
{ "files.associations": { "plugin.json": "jsonc" } }
```

这一行把 `plugin.json` 关联成 JSONC ⇒ 不标红。**这是 VS Code 官方机制**（`files.associations`），`yo code`（VS Code 官方脚手架）做法相同。

🔴 **但真正的缺陷不是这个文件，是它一句话都没写。** 一个第三方作者打开 `.vscode/settings.json`，看到的是一行他看不懂的配置——**他可能以为是垃圾顺手删掉，然后被红波浪线折磨一整天**。所以（**拍板 ④**）：**保留 + 加注释说明为什么**。

### Q2：这个包需要更新吗？

**需要。** 见 §一 的缺口表——**7 项缺口**，其中 3 项是「官方插件全有、生成物全没有」的结构性差距。

### Q3：`src/` 要预建 `[__tests__, components, services, styles, utils, views]` 这些夹吗？

**拍板 ③：不预建。** 理由（用户已认可）：

- 预建的**空文件夹在 git 里根本不存在**（git 不记录目录）——除非塞 `.gitkeep`，那就是为了留一个空夹而放一个假文件，**成本是真的、收益是假的**；
- 一个只做侧栏面板的小插件被塞 6 个空夹，**比不预建更劝退**；
- **"该放哪" 是知识，不是目录** —— 用 **README 里的目录契约表**教，比用空夹暗示更清楚（还顺带解决了 `README.md` 本来就缺的问题）。

## 二、template v2——逐文件改法

### 2.1 新增 `README.md`（**本轮最重要的一件**）

它一举解决三件事：① 官方插件必备的说明文件；② 用户 Q3 的**目录契约**落点；③ 市场详情页数据源。

**结构（照 first-run-setup 的体例）：**

```markdown
# {{displayName}}

> 一句话：这个插件做什么。

![{{displayName}} 场景封面](resources/cover.svg)     ← 有封面图时才有这一行；没有就删

## 怎么用
（安装后在软件里从哪打开、点哪、得到什么）

## 目录说明——东西该放哪
（见 §四 的契约表，整表搬进来）

## 写这个插件的三条纪律
（从 09 规范里挑 2-3 条最容易被违反的，直接抄）
```

🔴 **`README.md` 必须进模板**，且 **CLI 打印的最后一行要指向它**（§五）——**不然「目录契约」教了没人看见**。

### 2.2 新增 `CHANGELOG.md`

```markdown
# 更新日志

## v0.1.0（<生成日期>）

- 初始版本
```

- **生成日期**由 CLI 在 `walkReplace` 时注入（新增 `{{date}}` 占位符，`new Date()` 取 `YYYY-MM-DD`）。
- 段标题格式**必须**符合 [09 规范的新章节](01-规范文档对齐.md)：`## v<版本>（<日期>）`——**这是 publish 切段的解析依据，模板不能教错**。

### 2.3 新增 `.gitignore`

```gitignore
node_modules/
dist/
*.linkdesk-plugin
```

**理由**：三个目录/产物**都不该进作者的 git**（`*.linkdesk-plugin` 是分发包，由 Release 承载；`dist/` 是构建中间物）。**官方插件 0/20 有这文件**——因为它们是 monorepo 构建、走仓根 `.gitignore`；**第三方作者是独立仓，必须自带。**

### 2.4 新增 `resources/icon.svg` + `plugin.json` 补 `icon`

- 放一张**中性的占位图标**（不是一个有内容的设计——作者要替换它）。
- `plugin.json` 加 `"icon": "resources/icon.svg"`。
- **为什么模板要给图标**：不给 ⇒ 生成物在图标栏 / 标签页 / 市场里全是**默认插头块**，作者第一眼看到的是「我做的插件坏了」。给了占位 ⇒ **链路接通、形态与官方一致，作者只需换图**。
- 🔴 **图标资产属视觉改动 ⇒ 触发硬约束 16**（动手前先经 `Skill` 调设计 skill）。**开工时先调。**

### 2.5 🔴 `plugin.json` 删 `pluginId` 行

**现状**：

```jsonc
"pluginId": "{{pluginName}}",   // ← 删掉这一行
```

**为什么必须删**（三条独立理由，任一成立即可）：

| # | 事实 | 出处 |
|:--|:--|:--|
| ① | **20/20 官方插件一只都没写 `pluginId`** | `grep -ln '"pluginId"' plugins/*/plugin.json` → 空 |
| ② | **它是冗余的**——`{{pluginName}}` 就是**目录名**，而 `pluginId` 的兜底值**正是目录名** | [validate.ts:80-97](../../../packages/plugin-sdk/src/validate.ts)：`pluginId = manifest.pluginId ?? sourceDirName` |
| ③ | **schema 里没有 `pluginId` 这个属性**（只在别的字段描述文字里出现过），顶层 `additionalProperties: true` ⇒ **写了不报错、不校验、静默接受** | [plugin.schema.json](../../03-插件制造/plugin.schema.json) |

⇒ **模板教的是一个「写了等于没写、官方一只没用、schema 也不认」的字段。**

**改成注释教学**（保留能力、去掉冗余写法）：

```jsonc
  // ── 插件身份 ──
  // ID 默认 = 插件目录名。仅当「目录名要改、但安装身份不能变」时才取消下面这行的注释。
  // "pluginId": "{{pluginName}}",
  "name": "{{displayName}}",
```

### 2.6 `package.json` 补两个 script

```diff
   "scripts": {
     "dev": "linkdesk-plugin-sdk dev",
+    "dev:real": "linkdesk-plugin-sdk dev --real",
     "build": "linkdesk-plugin-sdk build",
+    "publish": "linkdesk-plugin-sdk publish",
     "validate": "linkdesk-plugin-sdk validate",
+    "lint": "linkdesk-plugin-sdk lint"
   },
```

**依据**：SDK 的 `bin.ts` **五个命令全都在**（`dev` / `dev --real` / `build` / `publish` / `validate` / `lint`），**模板只接了三个**。作者不知道其余两个存在，就得自己去翻 SDK 文档。

- `dev:real`——真机环（热改直写 `{userData}/plugins/<id>` + CDP reload），**真 IPC / 串口 / LSP 类插件唯一的秒级调试方式**，不接线作者永远不会发现。
- `publish`——一键发布（建 Release + 上传 + 更新 catalog）。**这是插件生态的入口动作**，模板不给等于让作者手搭。
- `lint`——SDK 自带门禁，**不接线 = 白送没人用**。

### 2.7 `src/index.css` —— **不动**

全仓官方证据：**多份 CSS 的插件统一放 `src/styles/`**（editor / file-tree / marketplace / serial-monitor / panel-demo）——**唯一例外是 settings（早期插件，4 份 CSS 散在 `src/views/`）**。

模板的 `index.css` 是**单份、且与入口 `index.tsx` 强绑定**（`import "./index.css"`）⇒ **同夹合法**，不必为了「看起来像别人」而多开一层夹。**规则写进 §四 契约表即可**（多份 → `src/styles/`）。

### 2.8 🔴 i18n：把死 key 变成活的

**现状**：`i18n/en.json` = `{"hello": "Hello from LinkDesk!"}`，而 `src/index.tsx` **一处 `t()` 都没有**（三行中文全硬编码）。

⇒ **生成物自带一个没有任何调用方的 key**——**这正是本层判据 M2 要消灭的东西，而它躺在教具里教人。** 作者会以为「i18n 就是这样用的」。

**改法**：`index.tsx` 用 `t()` 读中文原文当 key（与 editor 等官方插件同一套写法），`en.json` 提供英文：

```tsx
import { useTranslation } from "react-i18next";
// …
const { t } = useTranslation();
<h2 className="starter__title">{t("插件跑起来了 ✨")}</h2>
<p className="starter__text">{t("这是你的第一个 LinkDesk 插件。")}</p>
```

```json
{ "插件跑起来了 ✨": "Plugin is running ✨", "这是你的第一个 LinkDesk 插件。": "This is your first LinkDesk plugin." }
```

**两条纪律（写进模板注释）**：

- **key = 中文原文**，**不建 `zh.json`**（中文自带兜底，再写一份是冗余）。
- **只加你真的用 `t()` 读过的 key**——`en.json` 里出现没有调用方的 key 就是死 key（本项存在的意义）。

> 🔴 **注意**：`src/index.tsx` 里 `<code>src/index.tsx</code>` / `<code>npm run build</code>` 这类**代码标识符不翻译**（它们不是 UI 文案）——别整段包进 `t()`。

## 三、`.vscode/settings.json` —— 保留 + 加注释（拍板 ④）

```jsonc
{
  // 让 VS Code 按 JSONC 解析 plugin.json —— 它允许 // 注释与尾逗号（对标 VS Code 自己的 package.json）。
  // 没有这一行，VS Code 会按严格 JSON 解析，注释全被标红。
  // 不影响 LinkDesk / SDK：两边本来就按 jsonc 解析，本文件只是编辑器提示。
  "files.associations": {
    "plugin.json": "jsonc"
  }
}
```

> ℹ️ **顺带**：文件里的相对路径 `plugin.json`（不带 `**/`）在 VS Code 里是**全局文件名匹配**——插件工程通常只有一个 `plugin.json`，够用。**不改。**

## 四、目录契约表（拍板 ③ 的落点）

**这张表整表搬进生成的 `README.md`。** 它是「不预建文件夹」的替代品——**用文字说清该放哪，而不是用空夹暗示。**

| 路径 | 放什么 | 什么时候有 |
|:--|:--|:--|
| `plugin.json` | 插件清单 | **必有** |
| `README.md` | 说明——市场**详情页**页签的数据源 | 强烈建议 |
| `CHANGELOG.md` | 更新日志——市场**更改日志**页签的数据源 | 强烈建议 |
| `resources/` | 资产：`icon.svg` / `cover.svg` / README 里引用的图 | 有图就有 |
| `i18n/` | `en.json`（key = 中文原文；**不建 zh.json**） | 有 UI 文案就有 |
| `themes/` · `languages/` · `snippets/` | 数据型插件的载荷 | 数据型才有 |
| `src/index.tsx` | 入口（`plugin.json` 的 `entry`） | 视图插件必有 |
| `src/views/` | 视图组件（`contributes.views` 里 render 指向的文件） | 有侧栏/面板视图时 |
| `src/components/` | 本插件内部复用组件 | 需要时 |
| `src/services/` | 域逻辑 / IPC 封装 / 数据层 | 需要时 |
| `src/styles/` | **多份** CSS 时统一放这（单份且与入口同夹也可） | 需要时 |
| `src/__tests__/` | 单元测试 | 需要时 |

**两条硬规矩（表下面用一行黑体写）**：

> 🔴 **共享的东西不进这里**——跨插件复用的组件 / hook 走 `@linkdesk/ui`（壳提供的公共包），**不要在插件里再写一份**；域专属的才留在插件本地。
> 🔴 **资产一律住 `resources/`，插件根不放散图**（[12 §三](01-规范文档对齐.md)）——能进安装包的是**被 README 引用过**或**被 `icon`/`marketIcon` 声明过**的文件，目录名本身没有魔法（[04 §二](04-资源与目录归位.md)）。

## 五、CLI 文案更新（`index.js` 的最后一段）

**现状**只打印 `cd` / `npm install` / `npm run validate` / `npm run build`——**没提 `dev`**（模板 2.1 轮写这段文案时 `dev` 还不存在）。作者看不到热重载这条路。

**改成**：

```
  接下来：
    cd {{pluginName}}
    npm install
    npm run dev        # 浏览器热重载预览（改代码即时生效）
    npm run validate   # 校验 plugin.json
    npm run build      # 打包出 <pluginId>.linkdesk-plugin

  然后：先读 README.md —— 目录该放哪、三条纪律、怎么发布都在里面。
  plugin.json 的 name / description / author 是你的身份信息，src/index.tsx 是插件本体。
  完整插件能力（侧栏视图 / 命令 / 设置 / 协议……）见 docs/03-插件制造/。
```

**三处刻意的改动**：① 补 `dev`；② **把 README 指出来**（§2.1 的目录契约靠这一步被看见）；③ **不再提 `publish`**——它要 GitHub token，属于「准备好了再做」，README 里详说，**CLI 首屏不吓人**。

**另**：CLI 里 `{{date}}` 占位符要加进 `walkReplace` 的 values（`pluginName` / `displayName` / `author` / `date` 四个）。

### 🔴 收官时逼出的三条

1. **`#94a` 自己给自己埋了一颗雷，`#94e` 才引爆**——把 `npm run lint` 接进模板（`#94a`）之后，v1 留下的 `.starter__hint { font-size: 12px }` 立刻让**刚生成、还没写一行业务代码**的工程开局带黄灯（`check-font-scale` 偏离）。改成 `var(--font-size-xs)`（同一个 12px，但跟着全局字号缩放），并订正注释里那句**已经被门禁推翻的**「布局/字号这类结构值用普通 px（不违反）」。
   > **新加的验收动作：改模板之后必须把门禁跑一遍看生成物过不过。** 只测「能不能生成」不测「生成物干不干净」，等于把教具的毛病留给作者发现。
2. **`toISOString` 的时区陷阱**——`{{date}}` 若用 `new Date().toISOString().slice(0,10)`，在 UTC+8 的**早上 8 点前**会写成前一天。改用 `getFullYear/getMonth/getDate` 拼本地日期。**日期写错不影响功能，但会影响「更新日志的日期是错的」这种没人会去查的地方。**
