# 01 — 全量 UI/UX 审计

> 审的范围：1 个主组件 + 1 个 CSS 文件 + 1 个类型定义
> 审的维度：布局 · 配色 · 图标 · 间距 · 字体 · 无障碍 · 数据展示

---

## 严重度定义

| 标记 | 含义 |
|------|------|
| 🔴 | 用户困惑、功能受阻、违反硬约束 |
| 🟡 | 一致性/无障碍差距 |
| 🟢 | 不完美但功能正常 |

## 一、设置行标签

### 🔴 SV-1 — 标签显示 configKey 原文，不是人类可读名称

**位置**：[SettingsView.tsx:346](../../../src/components/views/SettingsView.tsx#L346)
**当前**：`<label className="settings-row-label">{configKey}</label>`
**效果**：用户看到 `app.theme`、`serial-monitor.statusBar.txrx` 这样的技术键名。
**对标 VS Code**：设置标签显示 `title` 字段——"配色主题"、"状态栏 TX/RX 计数"。
**问题**：`ConfigurationProperty` 类型没有 `title` 字段，只有 `description`。
**修复**：三步——
1. `ConfigurationProperty` 加 `title?: string`
2. `plugin.schema.json` 补 `title` 字段定义
3. `SettingRow` 渲染 `prop.title ?? configKey`（有 title 用 title，没有 fallback 到 key）
4. 各插件的 `plugin.json` 里给配置项补 `title`

### 🔴 SV-2 — 无修改标记，看不出哪些设置被用户改过

**位置**：[SettingsView.tsx:293-385](../../../src/components/views/SettingsView.tsx#L293-L385)（SettingRow 组件）
**当前**：所有行样式一模一样，无法区分"用户改过的"和"默认值"。
**对标 VS Code**：修改过的设置在左侧有蓝色竖线，`settingValueIndicator`。
**修复**：`SettingRow` 调用 `inspectConfiguration(configKey)`，若 `userValue !== undefined` 则加 CSS class `modified` → 左侧 2px accent 竖线。该函数已经 import 了，直接用。

## 二、导航

### 🟡 SV-3 — 导航列表无 `aria-current` 指示当前选中

**位置**：[SettingsView.tsx:232-239](../../../src/components/views/SettingsView.tsx#L232-L239)
**当前**：`<button className="settings-nav-item active">`
**问题**：屏幕阅读器无法识别哪个是当前选中项。
**修复**：`aria-current="page"`。

### 🟡 SV-4 — 设置分组无图标

**位置**：[SettingsView.tsx:250](../../../src/components/views/SettingsView.tsx#L250)
**当前**：分组标题只有文字 `{activeGroup.title}`。
**对标 VS Code**：设置分组标题有时带图标（插件 icon）。
**修复**：从 `getConfigurationContributions()` 中取 `pluginId` → 查 `PluginRegistry` 拿 icon → 渲染在标题前面。改动量小，但需确认 `getConfigurationContributions()` 返回值是否含 `pluginId`。

## 三、表单

### 🔴 SV-5 — `<label>` 无 `for` 属性，点击标签不聚焦控件

**位置**：[SettingsView.tsx:346](../../../src/components/views/SettingsView.tsx#L346)
**当前**：`<label className="settings-row-label">{configKey}</label>` 没有 `htmlFor`。
**问题**：用户点击设置名称时，焦点不跳到控件上。
**修复**：给每行的控件加 `id={configKey}`，`label` 加 `htmlFor={configKey}`。

### 🟡 SV-6 — 齿轮仅 hover 显示，键盘不可达

**位置**：[SettingsView.css:242-249](../../../src/components/views/SettingsView.css#L242-L249)
**当前**：`.settings-row-gear { opacity: 0; }` → `.settings-row:hover & { opacity: 1; }`
**问题**：Tab 导航聚焦到齿轮时，齿轮仍不可见（opacity 只响应 hover）。
**修复**：加 `.settings-row:focus-within .settings-row-gear { opacity: 1; }` + 齿轮本身 `:focus-visible` outline。

### 🟢 SV-7 — 搜索不标记匹配文本

**位置**：[SettingsView.tsx:157-174](../../../src/components/views/SettingsView.tsx#L157-L174)
**当前**：搜索过滤后只显示匹配的 key，不 `<mark>` 高亮匹配文本。
**修复**：对 key 和 description 做字符串分割，匹配部分用 `<mark>` 包裹。low priority。

## 四、Tab 栏

### 🟡 SV-8 — Tab 栏无 ARIA

**位置**：[SettingsView.tsx:183-196](../../../src/components/views/SettingsView.tsx#L183-L196)
**当前**：两个 `<button>` 实现 tab 切换。
**问题**：无 `role="tablist"` / `role="tab"` / `aria-selected`。
**修复**：`<div role="tablist">`、`<button role="tab" aria-selected={active}>`。

## 五、焦点与无障碍

### 🔴 SV-9 — 搜索输入框 `outline: none` 无替代焦点样式

**位置**：[SettingsView.css:65-69](../../../src/components/views/SettingsView.css#L65-L69)
**当前**：`.settings-search-input { outline: none; }` + `:focus { border-color: var(--accent); }`
**问题**：同串口监视器 SB-4——`border-color` 变化在深色背景下不够明显。
**修复**：加 `:focus-visible { outline: 2px solid var(--accent); outline-offset: -1px; }`

### 🟡 SV-10 — 导航按钮无 `:focus-visible` 样式

**位置**：[SettingsView.css:116-139](../../../src/components/views/SettingsView.css#L116-L139)
**当前**：`.settings-nav-item` 只有 `:hover` 和 `.active`，无 `:focus-visible`。
**修复**：加 `&:focus-visible { outline: 2px solid var(--accent); outline-offset: -1px; }`

### 🟡 SV-11 — JSON 弹窗"确定"按钮硬编码白色文字

**位置**：[SettingsView.css:297-298](../../../src/components/views/SettingsView.css#L297-L298)
**当前**：`.settings-json-close { background: var(--accent); color: #fff; }`
**修复**：`color: var(--text-on-accent)`（与串口监视器共用新增的全局变量）

## 六、交互

### 🟢 SV-12 — 切分组时表单整体 unmount/remount

**位置**：[SettingsView.tsx:247](../../../src/components/views/SettingsView.tsx#L247)
**当前**：`<div className="settings-form" key={activeGroup?.pluginId}>`
**问题**：`key` 变化 → React 销毁旧 DOM 建新 DOM → 滚动位置丢失。用户从"通用"切到"串口监视器"再切回来时回到顶部。
**修复**：去掉 `key={}`，用 `useEffect` 在 `activeGroup` 变化时调 `scrollTop = 0` 手动控制滚动。

### 🟡 SV-13 — 切换设置/快捷键 tab 时搜索文本未清理

**位置**：[SettingsView.tsx:186-196](../../../src/components/views/SettingsView.tsx#L186-L196)
**当前**：切 tab 时仅改 `activeTab`，`search` 状态不变。
**问题**：用户在"设置"tab 搜索了内容，切到"快捷键"tab 再切回来，搜索依然在，但用户可能忘记。
**修复**：切 tab 时清理搜索文本（或保留但这是设计选择）。
