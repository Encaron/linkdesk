## 一、需求（用户原话概括）

1. 「**总之我要的是一个能够完全自动化的软件。**」——AI 友好四层之层 1（运行时操作）的终局形态。
2. 「**AI 可以知道这个界面正在发生什么，可以掌握这个界面的每一处数据，可以操作它。**比如弹了一个 toast 铃铛，AI 应该清楚：它在什么位置、因为什么弹出、内容是什么、有几个按钮、按钮里有什么、该执行哪个按钮、执行之后应该做什么。」——**「读」与「操作」是一对**，缺一不可。
3. 「**MCP 和 CLI 最好两个都有，AI 习惯哪个用哪个。**」——外部 AI 接入通道双轨（用户听说 MCP 较贵、CLI 直接命令行；两条都要，详见 M4）。
4. 「至少 AI 得知道**怎么用 MCP / CLI 操作我这个软件**。」——操作知识必须成文可查（M3）。
5. 范围**不止 dev 版**——安装版上同样要让 AI 容易操作（M5 + M4 的既有实证）。

## 二、缘起现象与调查账（2026-09-14）

### 2.1 现象（起点）

A1 实机批场景 6：测试 AI 用自动化驱动「**把设置标签页拖到主区右半边形成分屏**」失败——按下/移动/抬起事件全到、标签页也进入 dragging 半透明态，但**松手不出分屏、也没有玻璃预览层**；测试 AI 上报口径「纯自动化问题，不是软件问题」，最后请用户手动拖了一下。用户质疑：**这是不是不符合 AI 友好化？是不是像 LabVIEW 那样只能手拖？**

### 2.2 调查结论（一句话账）

**标签页拖拽不是 LabVIEW 式死路**——分屏有完整直通车（命令 + 池 API），测试 AI 失败的真原因是两条**任何文档都没写的隐藏规则**；往全软件看，账是：**操作层整体健康 / 读取层半成品 / 知识沉淀空白**。

拖拽失败的两个真原因（读码核实，非 isTrusted 问题——代码零防自动化检查，单测就是用合成事件跑通分屏的）：

| # | 原因 | 证据 |
|:--|:--|:--|
| 1 | **手势门控**：reorder→split 相位切换要求**垂直位移 >15px 且光标越过 35px 标签栏进入"纯编辑区"**；横向拖（如沿标签栏拖到右侧）永远停在 reorder 相位 → 不分屏。**玻璃预览只在 split 相位渲染，"没有玻璃预览"恰是"从未进入 split 相位"的铁证** | `src/pool/hooks/useDragReorder.ts:196`（`dy > splitThreshold && inEditor`）、`src/pool/hooks/tabDragTypes.ts:22-38`（SPLIT_THRESHOLD=0.25）、`src/pool/zones/main/MainZone/DragOverlays.tsx:71-101` |
| 2 | **CDP 坐标缺陷**：Chromium 给合成鼠标事件的 `screenX` 不加窗口偏移 → 窗口屏幕原点推算错误 → 跨窗判定（脱出/吸附）全失效（工具层坑，不解释窗内不分屏） | `useDragReorder.ts:140-141, 240-254`；`src/App/windows/windowRelocation.ts:186-196` |

**它不知道的正解（这就是不友好的部分）**：分屏根本不用拖——

- **池 API 直达**：`window.linkdesk.pool.tabAction({action:"splitTab", direction:"horizontal", zone:"right"})`（支持精确 zone/targetGroup，比拖拽更精确）——`src/core/types/ipc/tabActions.ts:37`、处理端 `src/App/tabCallbacks.ts:401-412`；

## 三、判据定稿（什么是「AI 可全自动操作」）

**三条判据，缺一不算达标：**

1. **可读**：界面每一处状态（布局/标签页/通知/对话框/面板）都有**契约级读取路径**，不靠 CDP 读 DOM 猜。
2. **可操作**：每一个用户可做的动作，至少有一条**非鼠标路径**（命令 / API / CLI）——鼠标手势可以是"给人用的手感"，但**不得是唯一路径**；OS 层够不着的如实列册。
3. **可查**：操作知识有**单一真相源文档**（命令索引 / 隐藏规则 / 够不着清单 / 安装版路径），任意 AI 不读源码即可上手。

**验收锚点（用户 toast 例，逐条对账口径）**：位置 ✅（铃铛宽面板唯一面）｜因为什么 ◐（缺 wake 透传）｜内容 ✅｜按钮数/文字 ◐（缺 command/args）｜该执行哪个 ❌（M1 补齐）｜执行后做什么 ◐（行为在源码，契约未写 → M1/M3 补齐）。

**边界（本系列不承诺什么——防预期落空，2026-09-14 用户问答时补）：**

1. **OS 层动作够不着**（拖文件进出窗口等，A 类）——如实列册，不算达标范围。
2. **AI 是操作员，不是值守员**：AI 只在被调用时做事。「到时间自动执行」这类**持续逻辑归软件/插件**（如日程插件的到点提醒/自动打勾）——AI 可以把这类功能**配置**好，但"守着时间执行"的不是 AI。未来若要「AI 定时任务」，需另立自动化系统，**不在本系列**。
3. **插件业务动作的覆盖度取决于插件作者**：框架不知道插件是干什么的（核心无知原则）——插件把动作**注册为命令** ⇒ 自动进入 AI 操作清单；没注册 ⇒ AI 做不到（不用模拟点击兜底）。让"注册命令"成为插件规范与脚手架的默认动作 = **M2⑤**。

## 四、解决方向（五模块）

### M1 · 读取面进契约（↔P2，本系列地基）

- **做什么**：① 给 `linkdesk.notifications` 补 `list()` / `subscribe()`（或把 `pool.onLayout` 的 `statusBar.notif` 正式定格为读取通道并写进契约）；② **面板 DTO 的 actions 带上 `command` + `args`**（不剥）；③ `tabs.list()`（含活跃位）；④ 布局读取面（`layout.get` 或文档化 `pool.onLayout` 的 root/groups）；⑤ 对话框进行中状态可读；⑥ wake/ttl/persistent 透传；⑦ **命令/API 的 AI 可读描述**——发现面（`getCommands` / MCP tools）带 `description` + **参数结构**，AI 才能「知道怎么调」而不是猜（现状命令元数据无参数说明 ⇒ AI 只能凭名字猜参数，2026-09-14 用户问答时补）。
- **判据**：AI 全部经契约 API 即可回答 toast 六问 + 读出布局树与标签页列表——**零 DOM 读取**。
- **落点**：`src/core/api/linkdesk-api/ui.ts`（notifications 契约面）· `electron/preload-pool/namespaces-workspace.ts:33`（实现）· `src/hooks/usePoolSync/notif.ts:272`（command/args 透传）· `src/core/api/linkdesk-api/tabs.ts` · `src/core/types/pool/poolLayout.ts`（契约类型）· `docs/03-插件制造/01-插件API契约.md`（同笔更新）· `src/core/services/ui/DialogService.ts`。
- **碰撞**：`notif.ts` / 通知面与 E6#57.x 同区——开工前按新 HEAD 对齐。

### M2 · 操作面补齐（↔P4）

- **做什么**：① **浮动面板**补非鼠标路径（新增 `panel.setFloatingBounds`/移动命令，或 revealFloating 带坐标形参）；② B 类"存在但未文档化"的通道（`setSidebarWidth`/`panel:resize`/`updateSplitSizes`）进契约文档并补用户命令（如"重置面板尺寸"）；③ C 类"唯一鼠标路径"逐条补命令或键盘（QuickSend 编辑/删除、搜索结果打开、改键入口、关闭会话）；④ hover-only 按钮补 `aria` 与命令侧引用（可发现性）；⑤ **插件命令化规范**——「插件把主要业务动作注册为命令」进 `docs/03-插件制造/`（脚手架模板与示例示范）——这是**「插件自动被 AI 支持」的最大化路径**：按规范做的插件生来可被 AI 操作；存量插件（串口监视器/文件树/设置等）在 M2 里逐条补。
- **判据**：全软件「唯一鼠标路径」清单清零（或每条有命令替代并在手册登记）；浮动面板位置可被 API 设定；**新插件默认带命令面**（脚手架示范 + 规范可查）。
- **落点**：壳侧 = `src/pool/floating/floating-panel/FloatingPanelHost.tsx:156-198` · `src/pool/zones/main/MainZone/useDividerDrag.ts`；插件侧 = `serial-monitor` / `file-tree` / `settings` 三仓（**跨仓批次**——插件源码外移后，插件内改动落在各自独立仓，与壳仓改动配对发版）。

### M3 · 文档与手册（↔P3，最省事、最先做）

- **做什么**：① 新建**《AI 操作手册》**（仓内、进 git、给一切 AI 读）：命令/API 全索引（按任务组织：「分屏」「开标签」「读通知」「点通知按钮」…）· 手势隐藏规则表（拖拽相位门控等）· 够不着清单（A 类）· 安装版操作路径（带参 CDP / 静默装 / userData 文件面 / 更新后重连）· CDP 坑表沉淀（原只活在记忆 `cdp-ui-automation`，**移入仓内文档**）。② `docs/03-插件制造/` 同步：01-API契约 补读取面章 + 命名空间数量订正。
- **判据**：新 AI 只读手册即可列出「能操作什么、怎么操作、什么够不着」，**不读源码**；测试 AI 不会再在场景 6 一类手势上卡壳。
- **落点**：新文档（位置待拍板，见 §五）· `docs/03-插件制造/01-插件API契约.md`。

### M4 · 接入双通道：MCP + CLI（↔P5，方向 B 重开）

- **做什么**：一个**内核**（白名单 `linkdesk.*` 语义操作面网关，`toolbox-sop §5.2` 原方向 B 设计：本地 HTTP + token），**两个皮**：
  - **MCP Server**（按 MCP 标准、JSON-RPC，AI 客户端开箱即用）；
  - **CLI**（`linkdeskctl <命令>` 命令行；AI/shell 直接调，按需 `--help`，省上下文）。
- **「MCP 贵 vs CLI」的口径处理**（用户口径入档）：MCP 协议本身免费开源；"贵"的三个可能来源须在立项前逐项厘清——① 实现工程量、② 工具清单占 AI 上下文 token、③ 常驻依赖。CLI 的天然优势 = 零常驻、按需读帮助。**结论：两条都做，共用内核；AI 习惯哪个用哪个**（用户拍板口径）。
- **安全半径**：**给白名单能力，不给任意 JS 权限**（与 `e5.7-extreme-simple-pool` 哲学同源）；token 鉴权 + 本机回环默认。
- **判据**：任一通道可完整走通「开标签 → 执行命令 → 读通知 → 执行通知按钮」全链路；`--help` / `tools/list` 能自查操作清单。
- **落点**：主进程新服务（`electron/services/` 新目录）+ 安装版随包 + 设置页「AI 接入」分区（见增量图；开关/状态/token）。

## 七、验收（用户视角）

1. 对 AI 说「把设置标签页分到右半边」→ AI 一次性做成（走命令/API，不依赖拖拽）。
2. 弹通知后问 AI「铃铛里有什么」→ AI 报出：几条、各是什么、几个按钮、**每个按钮按下去会发生什么**、它打算执行哪个；执行 → 收掉 → 复述结果——**全程零 DOM 读取**。
3. 安装版：AI 用 CLI/MCP 完成「装一个插件 → 打开它 → 操作它」；**软件自动更新重启后，AI 连接不丢**。
4. 新 AI 进场读《AI 操作手册》→ 10 分钟内列出「能操作什么、怎么操作、什么够不着」——不再重新交今天这些调查的税。
5. 拖动/右键/双击等手势**全部仍在**（给人用的手感一个不少），只是**每一条都另有非鼠标路径**。
