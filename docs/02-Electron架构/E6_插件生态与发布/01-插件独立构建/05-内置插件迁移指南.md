# 内置插件迁移指南——从"和壳一起 build"到"独立 pre-bundle"

> 对应任务：E6#31-#35。
> 🔥 **核心无知原则。** 壳不应该知道 monaco-editor 是什么、serialport 是什么。这些是插件的事。

---

## 一、为什么要迁

### 现在的问题

```
壳的 node_modules/:
  monaco-editor/              ← 编辑器插件的依赖
  @codingame/monaco-vscode-*  ← 42 个包，编辑器插件的依赖
  serialport/                 ← 串口插件的依赖
  @serialport/*               ← 串口插件的依赖
  @codemirror/*               ← 谁的依赖？
  canvas                      ← 谁的依赖？
  iconv-lite                  ← 串口插件的依赖

违反了什么：
  ❌ 核心无知原则——壳"知道"了有编辑器、有串口
  ❌ 万物皆插件——内置插件是特权阶级（和壳共享 node_modules）
  ❌ 通用容器——壳被污染了具体用途的依赖
```

### 迁移后的样子

```
壳的 node_modules/:
  react / react-dom           ← UI 框架
  react-i18next / i18next     ← 国际化
  lucide-react                ← 图标库（壳功能——IconBar/TabBar 渲染图标）
  @vscode/codicons            ← 图标字体
  electron                    ← 桌面壳
  vite / typescript / eslint  ← 工具链（dev only）
  → 干净。壳不知道 monaco、不知道 serialport。

editor.linkdesk-plugin:
  index.bundle.js ← 内含 monaco-editor + @codingame/*（全部 inline 打包）

serial-monitor.linkdesk-plugin:
  index.bundle.js ← 内含 serialport + @serialport/* + iconv-lite（全部 inline 打包）
```

## 二、迁移步骤（以 file-tree 为例）

### Step 1：给插件加 package.json

```json
// plugins/builtin/file-tree/package.json
{
  "name": "linkdesk-plugin-file-tree",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "build": "linkdesk-plugin-sdk build",
    "dev": "linkdesk-plugin-sdk dev"
  },
  "dependencies": {
    "@linkdesk/plugin-sdk": "^1.0.0"
  }
}
```

### Step 2：确认入口

```
plugin.json → "entry": "src/index.tsx"  ← SDK build 从这开始
```

### Step 3：独立 build

```bash
cd plugins/builtin/file-tree
npm install
npm run build
→ 产出 file-tree.linkdesk-plugin
```

### Step 4：放到 bundled-plugins（保留 builtin/user 双层）

```
项目根目录/
  bundled-plugins/
    ├── builtin/                          ← core:true 生存插件
    │   ├── file-tree.linkdesk-plugin
    │   ├── editor.linkdesk-plugin
    │   ├── settings.linkdesk-plugin
    │   └── marketplace.linkdesk-plugin
    └── user/                             ← 出厂预装，可正常卸载
        ├── serial-monitor.linkdesk-plugin
        ├── lang-defaults.linkdesk-plugin
        ├── theme-defaults.linkdesk-plugin
        ├── theme-mint-soda.linkdesk-plugin
        ├── theme-twilight-forest.linkdesk-plugin
        └── python.linkdesk-plugin
```

> 🔥 **`builtin/` / `user/` 语义不变。** 只是内容从"源码"变成了"pre-bundle 后的 .linkdesk-plugin"。`core:true` 决定卸载按钮隐藏，`builtin/` 只是发货渠道。详见 `06-builtin-user-语义规范.md`。

`electron-builder.yml`:
```yaml
extraResources:
  - from: bundled-plugins
    to: bundled-plugins
```

### Step 5：壳启动时自动安装

```typescript
// main.ts 或 loader.ts 启动逻辑
async function installBundledPlugins() {
  const bundledDir = path.join(process.resourcesPath, "bundled-plugins");
  const userPluginsDir = path.join(app.getPath("userData"), "plugins");

  // 自动发现所有子目录——不硬编码目录名
  for (const sub of fs.readdirSync(bundledDir, { withFileTypes: true })) {
    if (!sub.isDirectory()) continue;
    const subDir = path.join(bundledDir, sub);
    if (!fs.existsSync(subDir)) continue;

    for (const file of fs.readdirSync(subDir)) {
      if (!file.endsWith(".linkdesk-plugin")) continue;

      const pluginId = file.replace(".linkdesk-plugin", "");
      const targetDir = path.join(userPluginsDir, sub.name, pluginId);
      //                                            ^^^^^^^^ 保留子目录

      // 已安装且版本相同 → 跳过
      if (fs.existsSync(targetDir)) continue;

      // 解压 + 安装
      const sourceFile = path.join(bundledDir, sub.name, file);
      await extractAndInstall(sourceFile, targetDir);
    }
  }
}
```

### Step 6：从 vite.config.ts 移除插件 entries

```typescript
// vite.config.ts
// 删掉 scanPluginEntries() 返回的插件 entries
// 内置插件不再作为壳 Vite build 的 rollup input
```

### Step 7：从壳 package.json 移除插件专属依赖

```bash
npm uninstall monaco-editor monaco-languageclient serialport iconv-lite
npm uninstall @codingame/monaco-vscode-api @codingame/monaco-vscode-editor-api ...
# ...42 个 @codingame/* 包
```

## 三、哪些依赖是壳的、哪些是插件的

| 依赖 | 归属 | 原因 |
|:--|:--|:--|
| react / react-dom | **壳** | UI 框架——壳自己的组件（IconBar/TabBar/StatusBar 等）需要 |
| react-i18next / i18next | **壳** | 国际化——壳有 UI 文字 |
| lucide-react | **壳** | 图标——IconBar/TabBar 渲染图标用 |
| @vscode/codicons | **壳** | 图标字体——StatusBar 等用 |
| electron | **壳** | 桌面壳 |
| vite / typescript / eslint | **壳** | devDependencies——构建工具 |
| monaco-editor | **编辑器插件** | 只有编辑器用 |
| @codingame/monaco-vscode-* | **编辑器插件** | Monaco 的 VS Code 模拟层 |
| monaco-languageclient | **编辑器插件** | LSP 桥接 |
| serialport | **串口插件** | 物理串口通信 |
| @serialport/* | **串口插件** | serialport 的子包 |
| iconv-lite | **串口插件** | 字符编码转换——串口数据用 |
| @codemirror/* | **待确认** | 检查哪个插件用了 CodeMirror |
| canvas | **待确认** | 检查是否是壳功能（FontFamilySelect 字体检测？） |

## 四、风险与注意事项

### 风险 1：Monaco 的 @codingame/* 包依赖复杂

`@codingame/monaco-vscode-api` 及其 42 个 override 包之间有复杂的内部依赖。pre-bundle 时需要确保它们之间的 import 正确解析。

**缓解：** 用 `defineLinkdeskPluginConfig` 的默认 external 配置——只 external react/react-dom。@codingame 之间的内部依赖全部 inline。Vite 的 tree-shaking 会自动处理。

### 风险 2：serialport 是 native module

serialport 包含 C++ 代码，需要针对 Electron ABI 编译。pre-bundle 后，JS 部分打进 bundle，但 native `.node` 文件仍需单独处理。

**缓解：**
- serialport 的 native 部分通过 `electron-builder` 的 `npmRebuild: true` 自动编译
- JS wrapper 部分打进 bundle
- 或者：serial-monitor 的 preload 直接暴露 serialport API（当前已这样做），插件只通过 `window.linkdesk.serial.*` 调用

### 风险 3：现有代码可能直接 import 了全局依赖

检查 plugins/ 下所有 `import ... from "monaco-editor"` / `import ... from "serialport"` ——这些在迁移前要走 `window.linkdesk.*` API。
