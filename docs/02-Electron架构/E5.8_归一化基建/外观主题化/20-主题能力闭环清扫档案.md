## 二、三处收尾

### #132 surface per-surface 死键（设计二选一，执行前用户拍板）

- **现状**：[theme.ts:92-95](theme.ts) `ThemeAppearance.surface` 注释自认「预留暂无 CSS 消费者；引擎 flatten 为 surface-<key> token 透传」——schema 有、引擎透传、**CSS 零消费、零插件实例**。
- **冲突**：与 E5.8#119-#121 浮层权威「结构地板统一磨砂」直接矛盾（per-surface 精调 = 又要按表面名枚举，正是浮层权威消灭的东西）。
- **方案二选一（用户拍板）**：
  - **A 删**（推荐）——surface 域从 schema/引擎移除，放弃 per-surface 精调，统一结构地板；符合归一化 + 无死代码。
  - **B 补消费**——为 surface 键加 CSS 消费者，恢复「主题作者精调某表面」能力；但与浮层权威设计张力，需一并画进 #131 层规则图。

### #133 图标主题闭环（「a 的图标」唯一没着落的一块）

- **现状**：机制已建——`contributes.iconThemes` 加载（contributions.ts:108）+ IconRegistry 登记本（对标 VS Code Product Icon Theme）+ `IconThemeMappings`（files/extensions/folders → CSS 类名）。**缺**：① `app.iconTheme` 设置项未注册（用户没得选）② 零插件实例（加载→登记→应用的路径从没走通）③ 消费方（文件树图标按当前图标主题映射应用）未验证存在。
- **方案**：注册 `app.iconTheme` 配置项（枚举 = IconRegistry 全部，动态刷新）+ 一个**虚构图标主题插件实例**（硬约束 21）打通「贡献→登记→选择→应用」全链 + 文件树/操作图标消费方 CDP 验证。

### #134 texture 纸纹 CSS 消费确认 —— ✅ 机制完整（2026-08-27 查实，零代码）

- **结论：纸纹分区独立消费 → 机制完整，档案记录即可。** 全链四件套实证：
  - **schema**：`ThemeSurface.texture`/`textureOpacity`（theme.ts:39-42）——与 glass 正交（⑬ 纸纹分区，不带玻璃也能 per-surface 纹理）。
  - **引擎**：`surfaceVariables(glass)`（tokens.ts:53-62）读 ThemeSurface.texture → 写 `--surface-bg-image`/`--surface-bg-opacity` token；mix.ts:143-146 纹理归 surface.texture 显式声明。
  - **CSS 消费**：index.css:578-593 `.panel-zone::after` 等 5 zone 表面 + `.status-bar::after` 消费 `var(--surface-bg-image)` / `--surface-bg-repeat` / `--surface-bg-size`；#125 玻璃激活读 `--glass-surface-bg-opacity`（原值 × alpha）合成淡出，未激活回退原值零变化。
  - **真实实例**：`plugins/user/theme-zones/paper-zones.json` `appearance.glass.texture` = paper-texture.svg 纸纹 + textureOpacity 0.45。
- **注**：texture 归属 `appearance.glass`（ThemeSurface 形态）——`appearance.surface` 是另一回事（#132 死 per-surface 映射），两者无混淆，纹理不在死键清理范围。
- 可选加分项：CDP 实机挂 paper-zones 主题像素采样纸纹，非必需。
