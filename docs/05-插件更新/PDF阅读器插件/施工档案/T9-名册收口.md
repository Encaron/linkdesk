## 一、这一格是怎么冒出来的

T7 记账留了一句「`pdf-reader` 未进壳仓 `scripts/sync-plugin-agents.mjs` 的 FACTS 表 ⇒ 壳侧审计把它标成第三方·只读」。T8 收口后用户追问这句话什么意思，当场核清：

- FACTS 表 = 「**哪些仓归本工程维护、由本脚本铺／校验 `AGENTS.md`**」的名册（脚本自己写明「表 = 官方仓名单的唯一真相源」）。
- 两只**只读**审计（`audit:plugin-tests` / `audit:plugin-commands`）**现读这张表**当官方名单，不在表里的仓打 `（第三方·只读）` 后缀；二者**都不在 `npm run check` 链里**（所以它不拦门禁，只是让读数把我们自己的仓标错栏）。
- 实跑 `node scripts/sync-plugin-agents.mjs --check` 的原文就是证据：`跳过 FACTS 表外仓 2 只（第三方作者仓——不渲染、不比对、不写）：geme-tihu-bicycle、pdf-reader`。

### 三.7 连带头一次：转官方把本仓扫进了 R4 闸门，当场冒红

「进名册」不是只改一张表——**名册同时是另一只门禁的扫描名单**。落盘后跑 `KNIP_DISABLE_RAW_TRANSFER=1 npm run check`，链子停在 `node scripts/check-duplicate-capability.mjs --self-test`：

```
🔴 真树读数：今日跨仓同名 4 组（index.tsx/Toolbar.tsx/SearchView.tsx/SearchBar.tsx）全部在复核表里（复核表未腐烂）
🔴 check-duplicate-capability self-test 1 例不符。
```

**成因（实测定因）**：该脚本按 FACTS 表判定「官方仓」，只扫官方仓的 `src/`。pdf-reader 在表外时**整棵树都不被扫**；进表那一刻，它的 `src/components/SearchBar.tsx` 与 `serial-monitor/src/components/SearchBar.tsx` 组成第 4 组跨仓同名，而复核表里没有这个名字 ⇒ 真树回归断言不成立 ⇒ `bad=1`。定因用的是抽放实验（不是推测）：

| 实验 | 真树读数 | self-test |
|:--|:--|:--|
| `git stash push -- scripts/sync-plugin-agents.mjs`（抽走 FACTS 改动） | 3 组（index.tsx / Toolbar.tsx / SearchView.tsx）全部在表里 | ✅ 全过（13 例） |
| `git stash pop`（放回） | 4 组（+ `SearchBar.tsx`） | 🔴 1 例不符 |

**复核结论（两份文件都读了，不是看名字放行）**：

| | serial-monitor | pdf-reader |
|:--|:--|:--|
| 搜什么 | **串口输出流** | PDF 正文（页内 ＋ 整篇） |
| 数据从哪来 | props 驱动（`text` / `matchCount` / `onNavigate`…） | 阅读器自己的 store（`useReaderState`） |
| 形态 | 条 ＋ 大小写开关、Ctrl+F 开条 | **绝对定位浮条**（不进 flex 布局——进布局会触发适宽重算、一开搜索就跳倍率） |
| 与 pdf.js | 无关 | 也不认识（扫描/偏移算法在 `services/textLayer/`） |

props 契约与数据模型**零交集**，改一处不影响另一处 ⇒ 按表的原意（「已看过、确认各干各的的同名组件」）登记进 `REVIEWED_BENIGN`，**不是**把判据放宽：判据（跨仓同名 ⇒ 报）照旧开火，只是补上它要的那次人工复核；表自带反向核对（名字不再跨仓出现 ⇒ 打 ⚠️ 该删），条目不会变成永久静音开关。⛔ 也**没有**改 pdf-reader 的文件名去躲这条闸门——那是「凑绿」，还会把这组同名从账上抹掉。

**同笔逮到的第二个缺陷（自测自身的脆性，必须修）**：正控⑤ 的期望值把**复核表长度写死成 `3`**（用例形状：传空同名集 ⇒ 表里每条都该被打 ⚠️）。任何合法的复核表新增都会让它**假红**。改法是把期望改成 `REVIEWED_BENIGN.size`（语义一字不变，量纲跟着表走），并在用例上方留一句「⛔ 别写死数字——表一加行就假红」。

⚠️ **一条工具面坑（未修，只记）**：那行真树读数的 ✅/🔴 **前缀是判据**，而**文字是写死的**——红的时候它照样打印「全部在复核表里（复核表未腐烂）」。本格第一轮就是被这句文字骗过去，把它当成「在表里、只是前缀奇怪」，白追一轮。根因是 `${okRaw ? "✅" : "🔴"} 真树读数：…（复核表未腐烂）` 这段模板不分叉；属壳侧门禁逻辑，⛔ 本格不改（不在授权面内），留给壳侧后续。

## 五、教训（工具面）

1. **名册漏一只仓，坏的不是门禁而是「账」**：`npm run check` 照样全绿（`--check` 对表外仓不比对、不判红），坏的是一份读数把自家门面插件标成第三方，以及那只仓的 `AGENTS.md` 从此**无人维护**。⇒ 「绿」不等于「账对」。
2. **共享骨架的手抄副本是定时炸弹**：本仓那份英文 `AGENTS.md` 从建仓起就冻结，脚手架之后怎么变它一概不跟，而没有任何门禁能发现——这正是该脚本存在的理由（「18 份手抄 = 18 份会各自漂移的副本」）。
3. **生成器自带两条判红尺子，事实段不许写内部坐标**：① 任务号正则（`E6#57` / `AI#47` 这一形）；② 裸层 / 轮名（`E`+数字 / `L`+数字 / 「第 N 轮」）。⇒ 写「源码外移之后」这种人话，别写内部编号。
4. ⚠️ **一处措辞瑕疵（未修，只记）**：通过时那句 ✅ 写「**18 只**仓的 AGENTS.md 与 .vscode/settings.json 全部与生成源一致」，用的是容器仓数（`ids.length`）而不是实校的表内仓数（17）——把跳过的 1 只也算进了「一致」的表述里。不影响判红，话比射程宽。
5. 🔴 **名册是「双重身份」的**：它既是生成器的输入，又是**另一只门禁的扫描名单**。往名册里加一只仓 ⇒ 那只仓的整棵树从此进入 R4（同名组件 / 浮层 CSS / 同一宿主声明的多消费方）的射程。加仓前应先问一句「这棵树的组件名会不会撞」，而不是等门禁红了再想。
6. 🔴 **同名 ≠ 第二份实现，复核表就是给这个判断用的**——但复核必须**读两份文件**得出（干什么 / 数据从哪来 / 形态），不能按名字放行；登记的是那次复核，不是静音。反面教训同样值钱：⛔ 改文件名去躲这条闸门 = 把同名从账上抹掉（凑绿），比红着更坏。
7. 🔴 **自测不许把产品数据的长度写死成期望值**：正控⑤ 里的 `3` 让任何合法的复核表新增都变成假红（本格就撞上了）。期望值该跟着真相源走（`REVIEWED_BENIGN.size`），这也是「一对账」该有的形状。
8. ⚠️ **只看文字不看前缀会被门禁骗**：那行真树读数的文字是写死的，红的时候照样说「全部在复核表里（复核表未腐烂）」。⇒ 读门禁输出**先看 ✅/🔴 前缀**，文字可能是模板常量。

- ⛔ **不动 `geme-tihu-bicycle`**：它仍在表外，本格只是把这个事实读出来；壳仓对第三方仓**只读**（不渲染、不比对、不写、不代改）。

- ⛔ **不动出厂种子**：`bundled-plugins.lock.json` 一行未改（壳仓该文件零 diff）。
