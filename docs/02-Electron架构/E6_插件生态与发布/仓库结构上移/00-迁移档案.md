## 1. 为什么做（病灶：三层根分离）

你的磁盘上三个「根」互不对齐：

| 根 | 迁移前 | 问题 |
|---|---|---|
| git 根 | `E:/linkdesk` | 历史路径全带 `linkdesk/` 前缀 |
| npm/工程根 | `E:/linkdesk/linkdesk` | package.json / lefthook.yml / src 在这里 |
| VS Code/终端打开根 | `E:/linkdesk`（一直右键打开） | 与上面两层脱节 |

**症状（每一条都实证过）：**
1. 每次 `git commit` 报 `No config files lefthook in "E:/linkdesk"` —— lefthook.yml 在 `linkdesk/linkdesk`，git 却在容器根找。
2. AI 跑 `git` 在 `E:/linkdesk`、跑 `npm run check` 要 `cd linkdesk/linkdesk`，来回跳错位 = 你常听到的「**cwd 漂移**」。
3. `git status`/`git log` 输出满屏 `linkdesk/xxx` 前缀。
4. 文档/记忆被迫写 `../linkdesk/docs/…` 双层相对锚。
5. `Serial_C_Language`（v3 时代设备端方案）仍以平级项目占根——2026-09-04 判断：它充其量是**未来某插件的下位机示例**，不是 LinkDesk 的平级物。

**还有一个 E6 战略动机：** E6 是第三方作者进来的里程碑，作者 clone 到的应是干净的 LinkDesk 工程，不是 `linkdesk/` 套娃 + 顶层杂物。对外门面 = 工程根。

### 6.1 `E6#0.7a`：删除 Serial_C_Language（含 .vscode cmake 键）

**为什么做：** 用户 2026-09-04 拍板永久删除——它是 v3 时代设备端配套，git 历史里已删（仓库内 status 0 行），磁盘是孤儿；未来若做「某插件的下位机 C 示例」，属**那个插件仓库**的事，不占 LinkDesk 工程根。

**怎么做：**
```bash

# 1) 确认它不在任何 git 追踪里、也没有别的引用它的东西（除 .vscode cmake）
git status --short -- Serial_C_Language/        # 预期：0 行输出
grep -rl "Serial_C_Language" --include="*.json" --include="*.md" --include="*.ts" . 2>/dev/null | grep -v node_modules
                                                 # 预期：只剩 .vscode/settings.json 的 cmake.sourceDirectory
# 2) 删掉容器根 .vscode 里指向它的 cmake 键（Serial 没了这键失效，VS Code cmake 扩展会报错）
#    → 编辑 E:/linkdesk/.vscode/settings.json，删 "cmake.sourceDirectory": "E:/linkdesk/Serial_C_Language/example", 行
# 3) 删除目录本体
rm -rf Serial_C_Language                          # Git Bash；若报占用，见坑
```

**坑：**
- `rm -rf` 报目录被占用/无权限（Windows）→ 关掉 VS Code / 终端里 cd 到该目录的进程 → 用 PowerShell `Remove-Item -Recurse -Force E:\linkdesk\Serial_C_Language`。

**验证：** `ls /e/linkdesk/Serial_C_Language` 报不存在；`git status --short` 零变化（它本就不追踪）；`E:/linkdesk/.vscode/settings.json` 里已无 cmake 行。

### 6.4 `E6#0.7d`：filter-repo 抽子树试点（临时目录，原仓库原封不动）

**做什么：** 在 `E:/linkdesk-filtered`（容器根之外）复制一个仓库，把历史**收缩成只有 linkdesk 子树**并去前缀。产出「新工程仓库」，交给用户验收（6.5）。**这一步不碰原仓库一个字节。**

**怎么做：**
```bash
# 1) 普通 clone（拿全历史，filter-repo 要求 fresh clone）
git clone E:/linkdesk E:/linkdesk-filtered
cd /e/linkdesk-filtered
# 2) 抽子树：只保留 linkdesk/，并把 linkdesk/xxx → xxx
git filter-repo --path linkdesk --force
#    --force：覆盖 filter-repo 的 "not a fresh clone / runs in place" 安全提示（clone 已是 fresh，一般不需；
#    若它拒绝，检查该 clone 是否有本地未提交改动）
# 3) 核对结果
git log --oneline | wc -l                        # 预期：< 原 6226（纯 Serial commit 被滤）
git log --oneline -1                             # 预期：= 迁移前最新 commit 的 message（同 d4cd83f7 那条）
git ls-files | head -20                          # 预期：路径不再带 linkdesk/ 前缀（src/electron/docs/… 直接在根）
git rev-parse --abbrev-ref HEAD                  # 预期：e6
# 4) filter-repo 出于安全会移除 origin remote——补回来（指向原远端，等用户拍板才推）
git remote add origin https://github.com/Encaron/linkdesk.git
```

**坑：**
- **filter-repo 永久改写该 clone 历史**——只对 `E:/linkdesk-filtered` 生效，原 `E:/linkdesk` 不受影响（它们是两个独立仓库目录）。
- 报 `Aborting: Refusing to destructively overwrite repo history since this does not look like a fresh clone` → 确保该目录是刚 `git clone` 出来、无本地改动；必要时加 `--force`。
- `--path linkdesk` 会滤掉一切不在 linkdesk/ 下的历史（顶层 .vscode/.gitignore/SOUL 等的 commit 只改顶层也会被滤——但 linkdesk/ 内含工程 .gitignore，工程配置不丢）。
- 中文/长路径在 Windows 下若 clone 失败，检查 core.longpaths：`git config --system core.longpaths true`。
- **别忘了 `git remote add origin`**——否则用户验收 clone 它推不上去（但推不推另说，先把 origin 记上）。

**验证：** HEAD message = 迁移前最新；`git log` 时间线连续（抽查首中尾几条 commit 的作者/日期/message 原样）；文件树 = 原 `linkdesk/linkdesk` 内容去前缀（`ls` 对照）；分支 = `e6`。
