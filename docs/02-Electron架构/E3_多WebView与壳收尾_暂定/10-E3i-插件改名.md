## 三、任务 2：布局迁移——`#70`（~20 行新代码）

### 3.1 为什么 LEGACY_TAB_IDS 不够

`LEGACY_TAB_IDS` 的操作是 `newId = tab.id + "-1"`（追记计数器后缀），不能处理 pluginId 前缀重命名。

### 3.2 设计

**文件：** `src/core/LayoutService.ts`

```typescript
function migratePluginIdRename(
  layout: WorkspaceLayout,
  oldId: string,
  newId: string,
  flag: string
): WorkspaceLayout {
  if ((layout as any)[flag]) return layout;

  const oldPrefix = `${oldId}-`;
  const newPrefix = `${newId}-`;

  return {
    ...layout,
    tabs: layout.tabs.map((tab) => {
      if (tab.id.startsWith(oldPrefix)) {
        const suffix = tab.id.slice(oldPrefix.length);
        return { ...tab, id: `${newPrefix}${suffix}`, type: tab.type === oldId ? newId : tab.type };
      }
      return tab;
    }),
    [flag]: true,
  };
}
```

### 3.3 调用点

在 `LayoutService.loadLayout()` 中，`LEGACY_TAB_IDS` 迁移之后：

```typescript
layout = migratePluginIdRename(layout, "terminal", "serial-monitor", "_migrated_terminal_to_serial_monitor");
```

## 四、任务 3：localStorage → PluginStateService——`#71`（~15 行）

### 4.1 问题

`useSerialSessions.ts` 绕过 `PluginStateService`，直接操作 `localStorage` 的 `"linkdesk:serial-monitor:sessions"` key——自建持久化路径。但 `ControlPanel.tsx:58` 已正确示范了 `setPluginStateValue("serial-monitor", "lastPort", port)` 的统一入口。

### 4.2 方案

```typescript
// ── 持久化（PluginStateService 统一入口——对标 ControlPanel.tsx:58）──

async function _restoreSessions(): Promise<void> {
  try {
    const data = await getPluginStateValue<{
      sessions: SerialSession[];
      activeSessionId: string | null;
      sessionCounter: number;
      colorIndex: number;
    }>("serial-monitor", "sessions");
    if (data) {
      _store.sessions = data.sessions.map((s) => ({ ...s, connected: false }));
      if (typeof data.activeSessionId === "string") _store.activeSessionId = data.activeSessionId;
      if (typeof data.sessionCounter === "number") _store.sessionCounter = data.sessionCounter;
      if (typeof data.colorIndex === "number") _store.colorIndex = data.colorIndex;
    }
  } catch { /* 首次启动或数据损坏 */ }
}

function _persistSessions(): void {
  setPluginStateValue("serial-monitor", "sessions", {
    sessions: _store.sessions,
    activeSessionId: _store.activeSessionId,
    sessionCounter: _store.sessionCounter,
    colorIndex: _store.colorIndex,
  }).catch(() => {});
}

// 模块初始化——异步恢复（React 首次渲染前完成）
_restoreSessions();

function notify(): void {
  _persistSessions();
  _listeners.forEach((fn) => fn());
}
```

### 4.4 旧数据迁移

改名前 localStorage key 是 `"linkdesk:terminal:sessions"`，改名后是 `"linkdesk:serial-monitor:sessions"`。改名流程（#69）中的 `_restoreSessions()` 已有旧 key fallback。现在换到 PluginStateService 后，迁移路径变为：

```
旧 localStorage "linkdesk:terminal:sessions"
  → 改名迁移（#69 坑 1 fallback）→ "linkdesk:serial-monitor:sessions"
    → 本次修复首次启动 → getPluginStateValue 返回空 → 
      fallback: 读旧 localStorage → setPluginStateValue 写入 → 
      下次启动直接从 PluginStateService 读
```

在 `_restoreSessions()` 中加一次性格林：

```typescript
async function _restoreSessions(): Promise<void> {
  try {
    let data = await getPluginStateValue<...>("serial-monitor", "sessions");
    if (!data) {
      // 一次性迁移：localStorage → PluginStateService
      const raw = localStorage.getItem("linkdesk:serial-monitor:sessions");
      if (raw) {
        data = JSON.parse(raw);
        await setPluginStateValue("serial-monitor", "sessions", data);
        localStorage.removeItem("linkdesk:serial-monitor:sessions"); // 清理旧 key
      }
    }
    if (data) {
      _store.sessions = data.sessions.map((s) => ({ ...s, connected: false }));
      // ...
    }
  } catch { /* 首次启动或数据损坏 */ }
}
```
