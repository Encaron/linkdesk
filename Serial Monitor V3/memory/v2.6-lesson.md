# V2.6 教训：大规模归一化重构，用户看不到任何变化

## 发生了什么

v2.6 做了两件大事：

**主题迁移 B+C：** 93 处 C# 代码替换——所有硬编码颜色改成 `SetResourceReference` 动态绑定。5 个面板注册主题回调。4 条新硬约束（#34-#37）。

**双语系统：** ~515 条 EnMap 翻译表。14 个 ComboBox 双语化。35 条系统日志双语化。10 个新踩坑（D39-D48）。

## 为什么是教训

这两件事改动量巨大，但用户打开 exe 看到的东西和 v2.5 **几乎一样**——只是：
- 切主题不闪了
- 多了一个"中/EN"按钮

**问题不是做了这些事——它们是对的。问题是它们应该在架构第一天就内置，而不是所有面板写完后再统一手术。**

## 用户说"不要重蹈 v2.6 覆辙"时，ta 的意思是

1. **不要在写完所有组件后再统一加主题/双语/错误处理。** 从第一天就内置。
2. **不要让用户经历"改了几个月，打开 exe 看起来一样"的感觉。** 每个阶段的交付物应该是用户能双击看到新东西的。
3. **基础设施先铺好，再盖楼。** V3 从第一天起就有 CSS 变量主题、react-i18next 双语、Web Worker 数据管道、PreferenceService 唯一入口。

## 对应到 V3 的设计

V3 的设计方案里已经内化了这个教训：

- 主题系统：CSS 变量，写第一个组件时就在用 `var(--card-bg)`
- 双语系统：react-i18next，写第一行 UI 文字时就是 `t("中文")`
- 数据管道：Web Worker + RingBuffer，从第一天就双线程
- 配置入口：PreferenceService 是唯一的，GUI 和 AI 都走它

**如果用户说这句话，你的回答应该是：** "放心，V3 从第一天就内置了这些，不需要事后手术。"
