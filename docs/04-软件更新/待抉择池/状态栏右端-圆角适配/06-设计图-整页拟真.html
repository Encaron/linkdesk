② 右端三件 · 半径 0 / 12 / 32 的真实形态（现状 vs A 案 · 已强制 hover）

三个半径档，每档上下对照：现状（全高方块 hover，被栏圆角裁切）／A 案（18px 药片 hover，栏 padding 让位真实圆角）。判据：让位量在半径 0 回到零（两案栏 padding 都是 8px＝现状），半径 ≥12 时 A 案让位到 11px（钳位上限），主动把右端带离弧线；按钮形状（22px 全高方块 → 18px 药片）是 D1 的固定改法、与半径无关，0 档也生效——这是「为适配圆角」之外的独立收益。注意 12 与 32 两档在栏上长得一样——22px 栏的圆角被浏览器钳到半高 11px 上限（条带已按「先钳位再放大」画，与实机同形），这正是 D2 要把让位量也钳到 11px 的原因：不钳的话半径 32 会把内容推到 32px 处，是回归。

③ 病灶与证据（含 2026-10-03 复核订正）

#症状（复核后口径）根因证据
①圆角模式右端 hover 的全高方块被栏圆角裁切——直边抵住弧线，亚像素级断口（非穿帮到背景）按钮全高 22＝栏高 ＋ hover 方底 border-radius:0；靠栏 overflow:hidden 兜底裁切 ⇒ 形状语言不一致StatusBarZone.css:62-78 × index.css:409 + :426-429
②「太大」读感（用户真实诉求）按钮吃满栏高 22/22 ＋ 铃铛 --font-size-lg(14px)；圆角把栏四角削小、实感变小 ⇒ 全高方块反差被放大。高度契约没动StatusBarZone.css:15,62-69,86-88
③半径一大，右端 hover 方块右缘直边与圆角弧线错位栏 padding 0 8px 死值不让位；半径被浏览器钳到 ≤11px（栏仅 22px 高），错位幅度小但存在StatusBarZone.css:16 × index.css:409

④ 决策点 D1–D4（✅ 2026-10-03 全定 · 整案走 A）

#问定稿（✅）
D1整体改法A · 内缩药片
D2右端让位padding 随半径 · 钳到真实圆角：max(8px, min(var(--surface-radius), calc(11px * var(--ui-scale))))（原式用未钳的 0–32px 会在半径 >11 时过度内缩 ＝ 回归）
D3内容降档不降——「太大」的根是全高方块不是内容
