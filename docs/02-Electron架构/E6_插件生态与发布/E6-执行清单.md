#### E6#8 🔴 plugin-shell-main.tsx 运行时动态加载——替代 import.meta.glob

> 📖 **🔥 2026-08-07 E5.5 对照审计发现。** [plugin-shell-main.tsx:30-33](linkdesk/src/plugin-shell-main.tsx#L30-L33) 用 `import.meta.glob("../plugins/builtin/*/src/index.tsx")` 发现插件入口。这是 Vite 编译时宏——在 build 时扫描目录生成静态映射表。E6 独立构建后，打包插件不在源码树中，glob 返回空对象 → 所有插件 "未找到插件"。
> **多 WebView 下的独特要求：** plugin-shell 在每个插件 WebContentsView 中独立运行。packed 插件入口路径在 loader 手中（`plugin.json` 的 `entry` 字段），但从未传给 plugin-shell。

- [ ] **E6#8a** `plugin-shell-main.tsx`——去掉 `import.meta.glob`，改为从 URL 参数读入口路径
  - [ ] 新增 `?entry=<encodedPath>` URL 参数——loader 创建 WebView 时附加
  - [ ] 源码插件：`entry=/@fs/C:/.../plugins/builtin/file-tree/src/index.tsx`（Vite dev server `/@fs/` 路径）
  - [ ] 打包插件：`entry=file:///{userData}/plugins/file-tree/index.bundle.js`
  - [ ] `import(entryPath)` 动态加载——替代 `pluginModules[modulePath]()`
- [ ] **E6#8b** `plugin-view-handlers.ts`——`plugin-view:create` handler 接收 `entry` 参数
  - [ ] `WindowManager.createPluginView(pluginId, { entry })` → WebView 加载 `plugin-view.html?plugin-view=${id}&entry=${encodeURIComponent(entry)}`
- [ ] **E6#8c** `loader.ts`——`loadPlugin()` 在调 `pluginViews.create()` 时传入入口路径
- [ ] **E6#8d** 验证——源码插件（dev）和打包插件（prod）都能在 WebContentsView 中正确加载
**验证：** `plugin-shell-main.tsx` 零 `import.meta.glob`。打包插件在 WebView 中正确渲染。

#### E6#45 🔴 文件关联与右键菜单

**目标：** 安装 LinkDesk 后，任意文本文件（`.txt`/`.py`/`.js`/`.json`/`.md`/`.html`/`.css`/`.ts`/`.tsx` 等）右键菜单出现"Open with LinkDesk"，且出现在根级（不展开"打开方式"子菜单）。文件夹和文件夹空白处同样。

- [ ] **E6#45a** `electron-builder.yml`——注册文件类型关联
  - [ ] `fileAssociations` 数组——`.txt` `.py` `.js` `.json` `.md` `.html` `.css` `.ts` `.tsx` `.yaml` `.xml` `.csv` `.log`
  - [ ] `ext` + `name` + `description` + `role: "Editor"` | +15 行
- [ ] **E6#45b** NSIS 安装脚本——右键根级菜单项
  - [ ] 新建 `build/installer.nsh`——写注册表
  - [ ] `HKCR\*\shell\LinkDesk`——任意文件右键 → "Open with LinkDesk"
  - [ ] `HKCR\Directory\shell\LinkDesk`——文件夹右键
  - [ ] `HKCR\Directory\Background\shell\LinkDesk`——文件夹空白处右键
  - [ ] icon 指向安装目录下的 `icon.ico`
  - [ ] `electron-builder.yml` → `nsis.include: build/installer.nsh` | +25 行
- [ ] **E6#45c** 验证——安装后右键 `.txt` → 看到 "Open with LinkDesk" → 点击启动

#### E6#46 🔴 命令行文件/文件夹 intake——接收并路由

**目标：** 应用收到文件路径后（来自右键打开 / 命令行 / 双击关联文件），正确路由：文件 → editor 插件打开，文件夹 → workspace 添加。

- [ ] **E6#46a** `electron/main.ts`——`app.on('open-file', ...)` 事件处理器
  - [ ] macOS: `open-file` 事件在 `app.whenReady()` 前可能触发——需要缓存
  - [ ] Windows: 第二个实例通过 `second-instance` 事件 + `process.argv` 获取路径
  - [ ] 路径传给已有窗口（IPC `shell:openPath`）
- [ ] **E6#46b** 渲染进程——`shell:openPath` IPC handler
  - [ ] `fs.statSync` 判断文件 vs 文件夹
  - [ ] 文件 → 从路径提取扩展名 → `FileAssociationService.getPluginFor(ext)` 查注册的插件
  - [ ] 如果无匹配 → fallback 到 editor 插件（E5#99 未知文件路由）
  - [ ] 文件夹 → `workspaceService.addFolder(folderPath)` + 如果已存在则 `setActiveWorkspace`
  - [ ] 🔥 **留口子：不硬编码 `pluginId: "editor"`。** 未来第二编辑器注册 `contributes.fileAssociations` 后，`getPluginFor()` 自动命中。FileAssociationService 已有 `getPluginsFor()`（多编辑器列表）和 "默认用第一个注册的" 语义——多编辑器并存时只需加用户偏好层，不返工路由代码。
- [ ] **E6#46c** 验证——`linkdesk.exe C:\some\file.txt` → editor 打开；`linkdesk.exe C:\some\folder` → workspace 添加

#### E6#47 🔴 多窗口支持——不同文件夹各自开独立窗口

**目标：** 对标 VS Code——右键两个不同文件夹各选"Open with LinkDesk"→ 出现两个 LinkDesk 窗口，各自独立 workspace，各自编译/运行。关键技术决策：一个 Electron 进程 + 多个 BrowserWindow（非多个 app 实例）。

- [ ] **E6#47a** `electron/main.ts`——移除 `!gotLock → app.quit()` 杀死逻辑
  - [ ] `second-instance` 解析 `process.argv`，提取文件夹路径
  - [ ] 创建新 BrowserWindow——调 `createWindow(workspacePath?)`，同进程新窗口
- [ ] **E6#47b** `electron/window-manager.ts`——多窗口管理
  - [ ] `createMainWindow(workspacePath?: string)` 方法
  - [ ] 每窗口维护独立的 workspace 状态
  - [ ] 窗口关闭时清理对应 workspace
  - [ ] 所有窗口关闭 ≠ app quit（macOS 惯例；Windows 最后一个窗口关闭 = quit）
- [ ] **E6#47c** WorkspaceService——多 workspace 隔离
  - [ ] 每窗口的 workspace 数据通过 URL 参数或 IPC 区分
  - [ ] 不同窗口的 `workspace.getFolders()` 返回各自 workspace，不串扰
- [ ] **E6#47d** 验证
  - [ ] 右键文件夹 A → "Open with LinkDesk"→ 窗口 1 打开 projectA
  - [ ] 右键文件夹 B → "Open with LinkDesk"→ 窗口 2 打开 projectB（不替换窗口 1）
  - [ ] 两个窗口各自独立——文件树/编辑器/终端互不干扰
  - [ ] 关闭窗口 2 → 窗口 1 不受影响
