**口径（别混）**：
- 「**独立定义**」= 某条规则的选择器（逗号拆开后）**恰好就是这个类名**、无祖先、无其它简单选择器 —— 即 `11-样式命名空间审计.md` §三 图例里说的「选择器主体就是这个类名本身、且无祖先」。**这才是「谁占了这个全局名」**，也是本轮要清干净的目标集。
- 「**带祖先/复合定义点**」= 该名字出现在选择器里但带祖先或与别的类复合（如 `.ctx-menu.show`、`.form-row > .input`）。**定义点仍在**，但形态是「消费 + 限定」，改不改要逐个判（多数情况下**跟着独立定义一起改前缀**即可，因为它们指向的是同一个名字）。
- 「**仅复合状态类**」（本轮**不动**）：`.active` / `.on` / `.show` / `.disabled` / `.hidden` / `.focused` / `.collapsed` / `.is-selected` / `.not-overflow` 这一族，**只作为复合选择器的后缀出现、从不独立定义** —— 这**本身就是硬约束 23 ③ 要求的合法形态**（「状态类一律复合，不裸写 `.active {}`」）。审计档 §三 实测「跨方全部以复合形式使用」仍然成立。
- **TS(TSX) 站点**只在 **class 语境**里数（`className` / `classList` / `class:` / `class=` / `querySelector` / `closest(` / `matches(`），避免 `active` / `close` / `error` 这类短名把数字灌水。

### 1.3 三方自有名 —— **不需要白名单**（这是本格能不能守住禁区的关键）

池文档里还有**第三方**带进来的类名（最典型：`@vscode/codicons` 的 `codicon` / `codicon-*`，`src/main.tsx:5` 与 `src/pool/pool-main.tsx:21` 直接 import 其 `codicon.css`；`fileIconMappings.ts` 里还有一整张 `codicon-*` 映射表）。**它们绝不能改名**（改了 = 全软件 60+ 图标当场变方块）。

**实测结论（这就是「不需要白名单」的机械依据）**：拿宿主域那 **244 个独立定义名**去比 `node_modules/@vscode/codicons/dist/codicon.css`（655 个类名）——**交集 = 0**。为什么？因为 **`codicon*` 在本仓从来不是「独立定义」，只被「消费」**（`src/index.css:679` 那条是 `.codicon[class*="codicon-"]` 属性选择器 override；其余是 `.plugin-icon--codicon` / `.pd-icon-codicon` 这类复合）。⇒ **「独立定义必须 `ldk-`」这条结构性规则天然把它们排除在外**，一个字的白名单都不用写。

> ⚠️ 判据写成「**独立定义**必须 `ldk-`」就够；**不要**写成「CSS 里出现过的类名必须 `ldk-`」——那会把 `codicon*` 连同第三方依赖一起卷进来，逼出白名单。
