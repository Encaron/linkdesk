## 工程规范（09-API 设计与后续实现的准入判据——2026-11-19 拍板）

> **每条怎么落地、怎么验收，见 [10-归一化与实施纪律](10-归一化与实施纪律.md)**——那里是动手清单，本节是总纲。

> 用户原话要点：「API 的设计、规范性、能力责任、边界……归一化、AI 友好化、**插件自由化**……无死代码、高内聚低耦合……**文件目录的规范性，禁止平铺**……每个文件的上限……还有文档的规范。」09 设计档与后续每一刀实现**逐条对照本节**，违反即返工。

1. **API 四问**：规范性（命名/结构照 SDK 既有约定）？能力与责任（每个字段谁写谁读谁校验）？边界（插件能做什么/绝不能做什么——05 §三·4 裁决层底线）？是否符合归一化（同类问题同一解法）？
2. **插件自由化**：作者能用声明表达的东西就不写死——声明清单越全越好，但**边界内**（分类浏览固定、第四方隔离、裁决层归壳）。
3. **无死代码／高内聚低耦合**：被替代的旧代码同笔清走；新模块单职责、依赖单向（照 06 §二·4 纯函数模式）。
4. **文件目录规范：⛔ 禁止平铺**——一切新文件进 feature-folder（照 marketplaceShared/ExploreView 既有模式），目录树每个夹有明确职责。
5. **文件上限**：新文件行数预算照仓内既有判据（超限即拆 feature-folder）；文档行数照各自档头约束。
6. **文档规范**：每档开头「为什么存在＋上下游」；结论必带理由；档非历史（脉络纪律 6）。

## 脉络维护纪律（后续每一步都要守）

1. **新文档必须挂进档案表**（一行：状态/回答什么/何时读），并与上下游**双向链接**——没有脉络的文档等于不存在。
2. **拍板必须落对应主题文档**，本页只留指针；README 变长 = 失职。
3. 每份文档正文开头写「上游/下游」与「为什么存在」；结论段必须带理由（为什么这么定、对应哪个失败模式），不是只写结论。
4. 产出物（HTML/mockup/验收单）编号续排挂进档案表，不散落。
5. **🔴 拍板必落任务（2026-11-19 用户硬性要求）**：每条拍板/设计结果必须能在 [12](12-待讨论清单.md)（I/E/B/U 项）或本页 §三（#n）找到**对应执行项**——「文档有了结果、清单里没任务」＝漏项＝违规；每轮拍板同笔补任务，对账自查看 10 §八·2。
6. **🔴 改蓝图前必须先调用设计 skill**（ui-ux-pro-max＋impeccable；2026-11-19 用户硬性命令）——**skill 已加载且在上下文中时不必重复调用**（同日用户放宽：加载过并记住即可，仅上下文丢失/新会话时必须重调）；用户批注**必须登 [08-批注要求档](08-批注要求档.md)**（就地更新至最终形态，非历史），非 HTML 改动一律有档可查。
7. **🔴 档非历史记录**（2026-11-19 用户硬性要求）：所有文档（含拍板档、要求档）只写**现行最终形态**——同一段被多次修改，就地改写，不保留「上次改了什么、这次改了什么」的叙述。
