# 数据设计——五层数据归属、类型草案、扩展性规则

> **为什么存在**：R1 拍板（03/04/05）说了「分类是数据」「合集是数据」「动作项是声明」，但没说**这些数据长什么形状、住在哪、谁校验、旧版本怎么兼容**。本文把这些提前构思好——R4 落地时照抄类型，不再临场发明。
> **上游**：[04-分类体系](04-分类体系.md)（分类/合集/榜单语义）、[05-卡片与动作槽](05-卡片与动作槽.md)（动作项契约语义）、[03-入口与数据归一](03-入口与数据归一.md)（store 归属纪律）；**事实底座**：[01-插件侧现状](01-插件侧现状.md) §二、[05] 引用的现有类型实读（`marketCatalog/types.ts` ＋ `parse.ts` 白名单）。

## 一、数据全景：五层归属（谁拥有、真相源在哪、换市场后活不活）

| 层 | 住哪 | 装什么 | 真相源 | 换市场后 |
|---|---|---|---|---|
| ① 作者声明 | 各插件仓 `plugin.json`（随包走） | 分类 slug（本次新增）；（未来）pricing/授权 | 作者 | 活——包内数据 |
| ② 目录数据 | 目录仓 `marketplace.json`（随源走） | 目录条目（含分类值副本）＋ **collections ＋ categoryRail（本次新增）** | 目录维护者 | 活——声明层同源 |
| ③ 市场插件配置 | `contributes.configuration`（用户盘） | `marketplaceSources`；（未来）图标点击开商店开关 | 用户 | 随市场插件走（它的私产） |
| ④ 运行时投影 | 市场插件 realmSlot store | catalog/plugins/disabled 三投影＋搜索态 | = ②⊕壳实时 | 死——纯缓存，重建即回 |
| ⑤ 壳 | 主仓 SDK schema ＋ 安装门 | schema 字段放行（本次）；付费裁决（未来立项） | 壳 | 谁也绕不过（05 §三·4） |

## 二、类型草案（逐层；R4 照此落码，改动即回改本档）

### 1. 作者 manifest 增量（plugin.json 顶层，SDK schema 同步）

```jsonc
{
  // ...现有字段不动...
  "category": "hardware",              // 主分类 slug，单值——决定抽屉归属（04 §三·机制2）
  "categories": ["hardware", "serial"] // 副标签 slug，多值可选——喂搜索与 chips
}
```

- **slug 规范**：`[a-z][a-z0-9-]*`，小写英文（E6#32b 既有语义）。
- **schema 只校形状、不校白名单**——未知 slug 合法（04 §三·机制 4；校白名单 = 审查流程 = 拓展性天花板）。
- 缺省 `category` ⇒ 归「其他」桶（other），不报错——**旧 manifest（未升级的仓）天然合法**。

### 2. 目录条目（CatalogEntry——**零 TS 改动，只做语义收敛**）

`marketCatalog/types.ts:23-24` 已有 `category?: string`／`categories?: string[]`——本次**不改字段，只定语义**：`category` = 主分类（抽屉归属），`categories[]` = 副标签（chips/搜索）。与 `categoryListFromEntry` 既有归并序（category 在前、categories 续后、去重保序）完全吻合。
（未来位：`pricing?: PricingDecl` 加白名单时一并补 types＋测试，见 §三。）

**媒体字段契约（2026-11-19 拍板：画廊收视频）**：`screenshots?` 由纯字符串数组**向后兼容地扩宽**为：

```ts
screenshots?: Array<string | { type: "video"; url: string; poster?: string }>;
```

- `string` ＝图片 URL（旧数据原样可读，解析器不迁移）。
- 视频项**最多 1 个且必须排第一**（封面视频）；多段或不在首位的，解析期丢弃该视频项并在来源页记声明提示（⛔ 不静默降级成图）。
- 播放语义照抄 README 视频（主仓 `MarkdownView` E6#70d）：**强制 controls、`preload="metadata"`、剥 autoplay、`poster` 优先**；⛔ 不做托管，只播作者给的直链/相对资源。
- R4 同步面：`CatalogEntry` 类型、SDK `marketplace.schema.json`、渲染器（画廊项类型分支）、白名单对账测试（见 [12](12-待讨论清单.md) I12）。

### 3. 根级新增：collections ＋ categoryRail ＋ sources（已审核源清单）

**`vendors[]`（厂商注册表，2026-11-19 拍板）**：官方目录根级，`{vendorId, name, domains[], githubOrgs[], verifiedBy, verifiedAt}`——只有官方运营者可写。判定链：条目 `authorId` 命中注册表 → 「官方 ✓」；未命中 → 「社区」。徽标语义从「分发事实」改为「发布者身份认证」。详见 09 §一·补2。

**`sources[]`（2026-11-19 拍板）**：官方目录里的「已审核第三方源」清单，`{url, authorId, addedAt}`。
- 作用＝**信任背书**：商店自动合并这些源；作者发新版走自己仓库，官方零复制、零过期。
- 合并顺序：官方源 → 收录源 → 用户手动添加源；同 pluginId 按 semver 高者胜。
- ⛔ 不收条目副本（会过期）；⛔ 作者不可在收录 PR 里改官方 curation。



```jsonc
{
  "version": "…", "updatedAt": "…",
  "plugins": [ /* CatalogEntry 不动 */ ],
  "collections": [
    {
      "id": "editor-picks",              // 稳定 id（引用/去重键）
      "title": "编辑推荐",               // 作者数据**直显不走 t()**——先例：目录条目标题/作者/来源仓库名是作者数据（ExploreView 头注）
      "subtitle": "装机必备的效率工具",
      "cover": "https://…/cover.svg",    // 可选
      "layout": "strip",                 // "banner"|"strip"|"duo"|"grid" → 卡片变体映射（05 §四）
      "items": ["editor", "pdf-reader"], // pluginId 引用；缺失条目**静默跳过**（防御，照目录 merge 语义）
      "order": 1
    }
  ],
  "categoryRail": {
    "order": ["development", "documents", "hardware", "network",
              "productivity", "themes", "reading", "entertainment"], // 展示顺序；slug 未注册于市场值表 → 该条目进「其他」桶
    "icons": { "development": "lucide:code" }  // 可选；插件仓 contribute.icons 或内置集
  }
}
```

TS 增量（`marketCatalog/types.ts`）：

```ts
interface CollectionDecl { id: string; title: string; subtitle?: string; cover?: string;
  layout?: "banner" | "strip" | "duo" | "grid"; items: string[]; order?: number; }
interface CategoryRail { order: string[]; icons?: Record<string, string>; }
interface MarketplaceCatalog { version?: string; updatedAt?: string; plugins: CatalogEntry[];
  collections?: CollectionDecl[]; categoryRail?: CategoryRail; }  // 两字段可选——旧目录天然合法
```

**向后兼容（关键）**：`parseCatalog` 现在只取 `plugins/version/updatedAt`——旧市场插件读新目录，根级新字段**自然忽略不炸**（JSON.parse 保留未知键，parse 白名单只认已知的）；新市场读旧目录，两字段 `undefined` ⇒ 合集槽/rail 不渲染。**双向兼容免费获得，靠的正是「可选字段」纪律——新增根级字段必须声明为可选。**

### 3b. 目录格式 v2＝文件夹级拓展（2026-11-19 拍板·规划）

> 用户原话：「一个 js（＝json）上就不够用了……针对于这个文件夹的更改，里面可能添加很多东西……把这个规划好，方便它未来可拓展。」

单 marketplace.json 承载不了作者域：作者卡需要**作者头像／介绍图片／作者介绍／总仓介绍**，作者主页需要**板块声明**（大屏/装机必备/主题专区/编辑精选/榜单…每板块的指令），还要**多仓归属**（一个作者多个仓＝同一 authorId）。v2 按**文件夹**拓展，目录仓根从单文件长成结构（示意，实施期定稿）：

```
linkdesk-marketplace/            # 目录仓根
├── marketplace.json             # 插件条目主文件（兼容现有，永不破坏）
├── authors/                     # 作者块（authorId 去中心化：每仓声明同一 id 即聚合）
│   └── <authorId>.json          # { name, avatar, introImage, intro, repos[], homepage:{sections[]} }
└── collections/                 # 合集声明（可从主文件拆出，向后兼容两读）
```

- **authorId 去中心化**：作者在自己**每个仓**的声明里写同一 id（如 GitHub 用户名）——同 id 即聚合为一个作者域，⛔ 无中心注册（万物皆可插件）。
- **作者主页板块声明**：每板块＝指令（类型+内容引用+order）；**「按分类浏览」不在可声明清单**（渲染器硬保留，作者删不掉）。
- **向后兼容**：v1 单文件目录继续可读；白名单/对账测试随 v2 扩展同步（§三）。
- **涉及面**：SDK schema、目录仓示范、市场插件解析/渲染、作者文档——全部列在任务 00「软件涉及面与任务清单」#2/#3/#4/#6/#7。

### 4. 市场插件运行时新类型（纯函数模块，vitest 直测，照 marketCategories.ts 模式）

```ts
/** 分类 rail 条目——展示层消费（左栏/首页网格） */
interface CategoryRailItem { slug: string; label: string; icon?: string; count: number; }

/** 主分类判定——category 优先，退 categories[0]，再退 OTHER（"other" 固定 slug） */
function primaryCategoryOf(entry: CatalogEntry): string;

/** 归桶——rail 顺序输出；不在 rail 的 slug 并入 OTHER 桶（恒在末位）；空桶不产出 */
function groupByPrimaryCategory(entries: CatalogEntry[], rail?: CategoryRail): Map<string, CatalogEntry[]>;

/** chips 推导——分类内 categories[] 副标签计数，<3 不出（04 §三·机制3 的类型化） */
function deriveChips(entries: CatalogEntry[], minCount?: number): string[];
```

动作槽契约类型（05 §三·1 的类型化，住 `services/` 新模块）：

```ts
type ActionState = "available" | "hidden" | "disabled" | "in-progress" | "failed";
type ActionKind  = "primary" | "secondary" | "menu";

interface ActionDescriptor { id: string; labelKey: string; icon?: string; kind: ActionKind; }
interface ResolvedAction  { descriptor: ActionDescriptor; state: ActionState;
  reasonKey?: string; jobId?: string; }   // reasonKey 供置灰 title；jobId 挂 installJobs 进度

interface ActionContext { entry: CatalogEntry; local?: InstalledPluginRef; online: boolean; }
type ActionExecutor = (ctx: ActionContext) => Promise<void>;

/** 动作项注册表——内置五项（install/update/uninstall/disable/enable）模块底注册；收费=未来增量注册（05 §三·2） */
interface ActionItem { descriptor: ActionDescriptor;
  evaluate: (ctx: ActionContext) => ResolvedAction;  // 纯判定：该条目此刻此动作什么状态
  execute: ActionExecutor; }
```

卡片变体（05 §四的类型化）：`type CardVariant = "sm" | "md" | "lg" | "hero"`；`CollectionDecl.layout` → 变体映射表一张（banner→hero、strip→sm 横排、duo→lg×2、grid→md 网格）。

## 三、parse 白名单纪律（🔴 本次实读发现的要害）

> **三方对账（2026-11-19 扩）**：类型 / parse 白名单 / **`marketplace-kit` Schema** 必须同源对账——
> 任一方多字段或少字段即红。作者本地 `validate` 的报错文案与市场侧 warnings 同一套（见 [11](11-作者模板与marketplace-kit.md) §五）。

现状：`parse.ts normalizeEntry` **逐条白名单归一，白名单外字段静默丢弃**（注释原话「漏字段 = 静默丢，务必同步」——E6#106/E6#77 乙各吃过一次）。本次设计的纪律：

1. **新增消费字段的固定三步**：types.ts 加字段 → parse 白名单加行 → **对账测试**（下条）。
2. **新增对账测试**（堵死静默丢的机械兜底）：vitest 断言「types.ts 所声明的每个 CatalogEntry 可选字段 ∈ normalizeEntry 产出 keys」——白名单漂移当场判红，不再靠注释自觉。
3. 根级新字段（collections/categoryRail）同样进 parse：`Array.isArray` 形状守卫（照 categories 先例），缺省 undefined。

## 六、内容热更新（首页/合集/顺序的即时生效——2026-11-19 拍板）

> **用户原话**：「第三方插件作者首页更新了，非得让我这个插件市场、这个软件、这个插件更新一下，这不合理……每一次点开就能看到这个改变」。
> **原则**：首页播放的内容（hero 轮播顺序、合集清单、新上架插件、店名、板块顺序）**全部是目录数据**，不是代码。
> 作者改自己的 `marketplace.json` / `authors/<id>.json` → 下一次拉取即生效，**⛔ 不需要插件/软件发版**。

### 1. 三层更新必须分清

| 层 | 变的是什么 | 生效方式 | 需要发版吗 |
|---|---|---|---|
| **内容** | 目录 JSON：hero/合集/板块/条目/顺序 | 打开商店时后台重拉＋变更检测 | **不需要** |
| **插件版本** | 某插件的发布包（新 ver） | 「检查更新」→ 下载安装 | 需要（该插件自己发版） |
| **软件本体** | 壳 | 软件更新 | 需要 |

⚠️ 三种更新在 UI 上必须是**不同入口/不同语义**：内容刷新 ⛔ 复用「检查更新」（后者只指插件版本）。

### 2. 触发时机（⛔ 不需要关软件、⛔ 不需要关标签页）

| 触发 | 检查范围 | 节流 |
|---|---|---|
| 应用启动 | 全部已添加源（官方＋作者） | 一次 |
| **打开商店标签页**（每次进入） | 全部 | 60s |
| 窗口重新获得焦点 | 全部 | 15min |
| **后台定时**（应用长期运行） | 全部 | **30min（±5min 抖动）** |
| 网络恢复（offline→online） | 全部 | 合并为一次 |
| 手动「刷新内容」（商店头部） | 全部 | 无视节流 |
| 手动「刷新」（来源页单源） | 该源 | 无视节流 |

**长期运行**：应用开十天也只是每 30min 拉一次最新快照（按 URL 覆盖缓存，不堆积）；页面隐藏时跳过，`visibilitychange` 恢复时补一次。

### 3. 提示分层（🔴 3 秒 Toast ⛔ 不是唯一渠道）

| 用户此刻在哪 | 即时提示 | 持久记录 | 可执行入口 |
|---|---|---|---|
| 正在看该店 | 轻 Toast「首页内容已更新 · 刷新」 | 铃铛面板一条 | 商店头部**刷新条**（常驻，直到刷新/忽略） |
| 在商店别的页 | ⛔ 不弹 Toast | 铃铛面板一条 | 商店头部徽标「内容已更新」 |
| 在别的标签 / 最小化 | ⛔ 不打断 | 铃铛面板一条 + 未读角标 | 下次进商店见刷新条 |
| 离线 | ⛔ 不提示 | 面板标「待联网」 | 联网后自动重试一次 |

**规则**：① Toast 只是"你恰好在场"的补充，**持久记录在面板**（可回看）；② 待刷新标记在「刷新」或「忽略」后清除，面板记录**保留**（忽略 ≠ 删除）；③ 只有**用户已添加的源**会被检查——没导入该作者的源就不会有它的提示。

### 4. 应用策略（什么时候换内容）

- **变更到达时商店不可见** → 静默写入缓存并置「待刷新」；**下次打开商店直接应用**，顶部一行一次性信息「内容已更新于 HH:MM」（可关闭，不阻挡）。
- **变更到达时用户正在浏览** → ⛔ 不静默替换（内容跳动／滚动位丢失，撞机械守则）；显示**常驻刷新条**＋面板记录，用户点「刷新」才换。
- **换内容时只替换内容区**：rail、滚动位置、当前分类、筛选/排序/视图全部保留（机械守则）。

### 5. 失败与退避

- 失败重试：**1 → 5 → 15 → 30min 封顶**；HTTP 403（限流）直接 30min。
- 失败 ⛔ 不弹 Toast；只在来源页该行标「加载失败 · 用缓存」，当前页面照常可用。
- 同一源连续失败不会重复打扰；恢复成功后清空退避。

### 6. 判定与边界

- **作者调顺序/换 hero**：属内容变更 → 下一轮拉取生效；R4 不需要任何代码分支。
- **作者新上架插件**：条目出现在其合集/网格，视作者是否把它放进 `hero/collection` 声明——**未声明的不会自动上首页**（声明驱动，不是 bug）。
- **官方首页**：与作者店**同一机制**（官方目录也是 URL 拉取）。
- **离线**：用缓存；恢复联网后按 §2 补一次。
- **CDN 缓存**：raw.githubusercontent 可能延迟数分钟——属正常延迟，⛔ 不为它加速。
- **本地源**：无网络请求，刷新＝重新读文件夹（手动或文件变更监听，R4 二选一）。
- **不引入服务端**：本阶段全静态文件；将来接服务器只换数据源，策略不变。

## 七、验收判据

- 旧市场插件读新目录：不炸、collections/rail 静默忽略（§二·3 双向兼容）。
- 新市场读旧目录：无 collections/rail ⇒ 槽位不渲染、无分类值 ⇒ 全部落「其他」桶（§二·1 缺省规则）。
- 白名单对账测试绿（§三·2）；未注册 slug 不出现在 rail、条目可见于「其他」桶（04 §三·机制 4）。
- 作者漏写 category：条目正常显示于「其他」桶，无报错。

## 八、UI 偏好（视图方式/排序）住哪（2026-11-19 拍板）

> 用户要求：「整个插件界面的都是有记忆功能的」——上次在作者页看详细信息、在库看平铺，这些要跨重启保持。

- **读写 API**：`window.linkdesk.pluginState.get/set("marketplace","ui.prefs", value)` → 壳 `plugin-states.json`（`StorageService` 统一原语：`appDataDir` 下；写文件的同时写 localStorage 兜底）。

## 九、本地安装记录（2026-11-19 拍板 A 复制安装）

- **存储**：`pluginState("marketplace","localInstalls")` → `[{ pluginId, sourcePath, installedAt }]`。
- **写点**：`installFromDirectory` 成功后由市场侧写入；卸载成功后删除该条。
