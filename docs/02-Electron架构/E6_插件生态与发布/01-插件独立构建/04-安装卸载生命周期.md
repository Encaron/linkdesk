# 安装/卸载生命周期

> 对应任务：E6#8a-c。定义插件从"用户点安装"到"可用的完整状态机。

---

## 一、插件状态机

```
                  install()
  ┌─────────┐ ───────────────→ ┌──────────┐
  │ 未安装   │                  │ 已安装    │
  │ (none)  │ ←─────────────── │ (active) │
  └─────────┘    uninstall()   └──────────┘
                                    │
                               update()
                                    ↓
                              ┌──────────┐
                              │ 已安装    │  ← 新版本
                              │ (active) │
                              └──────────┘
```

## 二、安装流程（installPlugin）

### 2.1 步骤分解

```
installPlugin(pluginId, bundlePath)
  │
  ├─ Step 1: 校验
  │   ├─ .linkdesk-plugin 文件存在？
  │   ├─ plugin.json 可解析？
  │   └─ 必填字段齐全？
  │
  ├─ Step 2: 解压
  │   └─ unzip → {userData}/plugins/<pluginId>/
  │
  ├─ Step 3: 记录
  │   └─ installed-plugins.json 写入条目
  │
  ├─ Step 4: 加载
  │   └─ loadPlugin(pluginId, { source: "bundled" })
  │       → normalizeManifest
  │       → parseContributions
  │       → register commands/menus/views/keybindings/config
  │       → import index.bundle.js
  │       → loadPluginLifecycle
  │
  └─ Step 5: UI 刷新
      ├─ emit "plugin:installed" ShellEvent
      ├─ IconBar 重读 viewRegistry → 新图标出现
      ├─ SidePanel 重读 viewsContainers → 新侧栏条目
      └─ marketplace 页面刷新 → "安装" → "已安装"
```

### 2.2 错误处理

每个步骤独立 try/catch，失败时回滚：

```
哪个步骤失败 → 清理该步骤的副作用
  Step 2 失败 → 清理已解压文件
  Step 4 失败 → 清理已注册的命令/菜单 + 删 installed-plugins.json 记录
```

### 2.3 幂等性

同一个插件再次安装：
- 如果已安装同版本 → 跳过（不重复下载/注册）
- 如果已安装旧版本 → 走更新流程

## 三、卸载流程（uninstallPlugin）

### 3.1 步骤分解

```
uninstallPlugin(pluginId)
  │
  ├─ Step 1: 确认
  │   └─ dialog.showConfirm("确定卸载 <name>？")
  │       取消 → return false
  │
  ├─ Step 2: 关闭标签页
  │   └─ tabs.closeByPluginId(pluginId)
  │
  ├─ Step 3: 注销
  │   └─ unloadPlugin(pluginId) 或 disposePlugin(pluginId)
  │       → 清理 CommandRegistry
  │       → 清理 MenuRegistry
  │       → 清理 ViewRegistry
  │       → 清理 ConfigurationRegistry
  │       → 清理 KeybindingRegistry
  │
  ├─ Step 4: 删除文件
  │   └─ fs.remove({userData}/plugins/<pluginId>/)
  │
  ├─ Step 5: 删除记录
  │   └─ installed-plugins.json 删除对应条目
  │
  └─ Step 6: UI 刷新
      ├─ emit "plugin:uninstalled" ShellEvent
      ├─ IconBar 移除图标
      ├─ SidePanel 移除条目
      └─ marketplace 页面刷新 → "已安装" → "安装"
```

### 3.2 core: true 插件不可卸载

```typescript
if (manifest.core) {
  throw new Error("核心插件不可卸载");
}
```

内置插件（file-tree/editor/settings/marketplace）标记 `core: true`。

## 四、更新流程（updatePlugin）

```
updatePlugin(pluginId, newBundlePath)
  │
  ├─ Step 1: 备份当前版本信息
  │   └─ const oldVersion = installed[pluginId].version
  │
  ├─ Step 2: 确认（如果有打开标签页）
  │   └─ "此插件有打开的标签页，更新需要关闭它们"
  │
  ├─ Step 3: 卸载旧版（部分——不删 installed-plugins 记录）
  │   ├─ 关闭标签页
  │   └─ unloadPlugin(pluginId)
  │
  ├─ Step 4: 替换文件
  │   └─ 删除旧 {userData}/plugins/<pluginId>/ → 解压新版
  │
  ├─ Step 5: 更新记录
  │   └─ installed[pluginId].version = newVersion
  │
  ├─ Step 6: 加载新版
  │   └─ loadPlugin(pluginId, { source: "bundled" })
  │
  └─ Step 7: UI 刷新
```

## 五、`.disabled/` 退役——市场时代真删除

> E6 之前：卸载插件 → 移到 `.disabled/`（软删除）。因为没有市场可以重新下载——删了就真没了。
> E6 之后：市场就是重新下载的渠道。真删除。

| 插件来源 | 卸载行为 | 恢复方式 |
|:--|:--|:--|
| 市场下载（`source: "marketplace"`） | `fs.remove()` 真删除 | 从市场重新下载 |
| 出厂预装 user/（`source: "user"`） | `fs.remove()` 真删除 | 从市场重新下载 |
| 出厂预装 builtin/（`source: "builtin"`） | `fs.remove()` 真删除 | 壳自动从 `bundled-plugins/` 恢复 + toast 通知 |
| 旧 `.disabled/` 残留（E6 升级前） | 迁移时检测——如果市场有同 ID 插件 → 提示"从市场重新安装或彻底删除" | — |

## 六、与现有 installPlugin 的关系

现有 loader.ts 中已有 `installPlugin` / `uninstallPlugin` / `reinstallPlugin` 函数——它们操作的是 `plugins/user/` 源码目录（复制/删除源文件）。

E6#8 的改造：
- **现有函数不变**——仍用于 builtin/user 源码目录的安装/卸载
- **新增** `installBundledPlugin` / `uninstallBundledPlugin`——用于 `.linkdesk-plugin` 打包格式
- 或在现有函数中加 `source` 参数分叉

最终调用方（marketplace 插件）根据插件来源选择调哪个。
