### E5.5#0e 🔴 文件树与标签页持久化一致性——退出/重启状态归一化

> 📖 **发现：** 2026-08-07 审计。当前退出软件后——**文件树工作区文件夹清零**（不持久化），但**标签页仍然保留**（持久化）。重启后标签页引用的文件路径可能已不在任何工作区中 → 标签页显示"文件不存在"或空白 → 不一致状态 = bug 种子。
>
> **根因：** 标签页持久化（`TabState` → StorageService/pluginState）和文件树工作区持久化（`WorkspaceService` → workspace.json）的持久化策略不同步。一个持久化、一个不持久化 = 退出/重启后两者脱节。
>
> **方案 A（推荐——都持久化）：** 文件树工作区在退出时写入、启动时恢复——和标签页同等对待。
>   - 退出时 `WorkspaceService` 写入 `workspace.json`（如有已有逻辑，验证是否生效）
>   - 启动时 `WorkspaceService` 读取 `workspace.json` → 恢复工作区文件夹列表 → 文件树自动展开
>   - 标签页恢复逻辑不变——引用的文件在工作区恢复后存在 → 正常打开
>   - 边界处理：工作区文件夹在磁盘上已被删除 → 跳过该文件夹，toast "工作区文件夹 xxx 已不存在"
>
> **方案 B（临时——都不持久化）：** 在方案 A 实现前，暂时禁用标签页持久化。
>   - 找到标签页持久化写入点 → 加 `return` 跳过
>   - 标注 `// TODO E5.5#0e 文件树持久化完成后恢复标签页持久化`
>   - 风险：用户手动打开的标签页重启后丢失——但至少不会出现"标签页在但工作区不在"的不一致状态
>
> **🔥 推荐方案 A。** 文件树持久化是正确行为——对标 VS Code 的 `storage.json` 中 `windowsState.lastActiveWindow.folderUris`。E5.5 的后续任务（E5.5#16 `linkdesk.workspace` API 补全）天然需要 workspace 持久化——本轮只做持久化读写，不碰 API。

### 第 2.5 轮：WebView 缩放联动——Ctrl+/- 壳↔插件同步

> 📖 **缺口发现：** 2026-08-07 审计。当前代码库 `electron/` + `src/` **零 zoom 相关代码**。`webContents.setZoomFactor()` / `setZoomLevel()` 从未调用。
> **问题：** 每个 WebContentsView 有独立的 `zoomFactor`（默认 1.0）和 `zoomLevel`（默认 0）。用户 Ctrl+/- 缩放壳 WebView → 只有 TitleBar/TabBar/StatusBar 变大，插件 WebView 保持 100%——视觉断裂。反过来，用户在插件 WebView 中 Ctrl+/- → 只有那个插件缩放，壳和其他插件不变——**和单 WebView 行为完全不同**。
> **对标 VS Code：** VS Code 的 `zoomLevel` 是窗口级——`window.zoomLevel` 配置项，所有 WebView（编辑器/侧栏/面板/终端）统一缩放。`workbench.zoomLevel` 默认 0，Ctrl+/- 每次 ±1（= ±20% `zoomFactor`）。
> **本轮目标：** 窗口级统一缩放——壳 Ctrl+/- → IpcBridge 广播 → 所有插件 WebView 同步 `setZoomLevel()`。插件可声明 `zoomIndependent: true` 选择独立缩放（如图片查看器）。
> **本轮可在第 1 层完成后开始——与第 2/2.4/3 层完全并行。**

## 第 3 层：OverlayWindow 叠加方案——根治 Z-order

> 🔥 **对标 VS Code。** WebContentsView 是 OS 原生视图，z-order 高于任何 HTML 元素。解决方案：把 HTML 悬浮层渲染在独立的透明无框 `BrowserWindow` 中，叠加在 MainWindow 上方——操作系统层面保证正确的 z-order。
>
> ```
> Layer 3 — OverlayWindow（透明无框，alwaysOnTop）
>   渲染：右键菜单 / SelectBox / Toast / Dialog / 命令面板 / 拖拽毛玻璃
>   鼠标穿透：无 overlay 区域 → 点穿到 MainWindow
>
> Layer 2 — MainWindow
>   壳 HTML：TitleBar + IconBar + TabBar + SidePanel + StatusBar
>   + WebContentsView × N（仅内容区，避开 TabBar/StatusBar）
>
> Layer 1 — 桌面
> ```
>
> **本层替换第 1 层 E5.5#6-#7 的临时方案。** 弹窗和毛玻璃不再需要 `setVisible(false)` hack。
>
> 涉及文件（新建）：
> - `electron/overlay-window.ts`——OverlayWindow 管理器（~200 行）
> - `src/core/services/OverlayService.ts`——壳侧 overlay 渲染协调器（~80 行）
> - `electron/ipc/overlay-handlers.ts`——IPC handler（~30 行）
