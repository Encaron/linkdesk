## 二、已修复的 Bug

| Bug | 症状 | 修复 | commit |
|:--|:--|:--|:--:|
| ENOTDIR | 拖 exe 报错 | `FileService.copy` 加文件/目录判断 | `5f0b9c7` |
| 拖后目录折叠 | twistie↓但空 | `refreshDir` 重载子节点 | `1e90f13` |
| `\` vs `/` 失配 | `isExpanded` 查不到 | `normalizePath` 归一化 | `a4a8aa6` |
| 🔴 OS 拖入无祖先检查 | 拖根目录到子目录→递归嵌套→1.85GB | OS 拖入加 `startsWith` 祖先检查 | `afc9bb6` |

**🔴 OS 拖入递归嵌套详解：**

树内拖拽（`text/plain` URI）有 `isAncestorOf` 检查——禁止拖祖先到后代。
但 OS 拖入（`dataTransfer.files`）只做了 `copy`——没有祖先检查。

**复现：** 从 Windows 资源管理器拖 `D:\工具软件\` 到树内的 `工具软件\串口助手\` 节点上
→ `copy(D:\工具软件, D:\工具软件\串口助手\工具软件)` 
→ 展开后看到 `串口助手\工具软件\串口助手\工具软件\...` 无限嵌套
→ 每次操作指数膨胀，最终 1.85GB

**修复：** OS 拖入加入 `normalizedTarget.startsWith(normalizedSrc + "/")` 检查——源是目标祖先时跳过。
