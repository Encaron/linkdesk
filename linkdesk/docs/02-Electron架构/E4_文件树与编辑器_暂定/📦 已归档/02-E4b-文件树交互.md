**🔥 跨平台注意——OS 拖入文件树：**

| 平台 | `dataTransfer.files` 行为 | 处理 |
|------|------|------|
| Windows | `file.path` 是真实路径 `C:\Users\...` | 直接用 |
| macOS | `file.path` 是真实路径 `/Users/...` | 直接用 |
| Linux | `file.path` 可能是 `file://` URI 需转 `/home/...` | 检查 `startsWith('file://')` → `decodeURI` |

```typescript
// OS 拖入统一处理：
function getFilePathFromDrop(file: File): string {
  let path = (file as any).path as string;
  if (!path) return '';
  if (path.startsWith('file://')) {
    path = decodeURI(path.replace(/^file:\/\/\/?/, '/')); // macOS/Linux 可能有 file:// 前缀
  }
  return path;
}
```

### #101 行内重命名（~50 行）——🔥 对标 VS Code Inline Rename

```typescript
// 对标 VS Code setEditable() / IEditableData
// F2 → 输入框替换文件名文本（inline，不是弹窗）
// Enter → 确认 → FileService.writeFile(newPath) + FileService.deleteEntry(oldPath)
// Esc → 取消 → 恢复原名
// Tab → 确认当前 + 自动跳到下一个可重命名的文件（VS Code 行为）

// 🔥 边界条件：
// - 文件名冲突：FileService.exists(newPath) → 提示 "已存在同名文件，是否替换？"
// - 文件被锁定：FileService.writeFile 抛错 → toast "文件被其他程序占用"
// - 重命名期间外部删除：watchFile 回调 → 自动取消重命名模式
// - 多选时重命名：只重命名聚焦的那个（不是批量重命名）

async function renameFile(oldPath: string, newName: string): Promise<void> {
  const newPath = dirname(oldPath) + '/' + newName;
  if (await FileService.exists(newPath)) {
    const ok = await DialogService.confirm(`"${newName}" 已存在。\n是否替换？`);
    if (!ok) return;
  }
  await FileService.writeFile(newPath, await FileService.readFile(oldPath));
  await FileService.deleteEntry(oldPath);
  model.refresh(dirname(oldPath));
}
```

**🔥 对标 VS Code 的粘贴重名处理：**
- 同一目录粘贴 → 自动加 " - Copy" 后缀
- 不同目录粘贴 → 保持原名
- 已存在 → " - Copy 2" 递增

### #102 剪贴板服务（~40 行）——🔥 对标 VS Code IClipboardService

> 🔥 **前置依赖：`FileService.copy(src, dest)`——同 #99。**

```typescript
// FileTreeClipboard.ts
// 🔥 对标 VS Code IClipboardService——区分剪切和复制
// 复制 → 粘贴 = 创建副本（" - Copy" 后缀）
// 剪切 → 粘贴 = 移动（源文件消失，等价于拖放）

class FileTreeClipboard {
  private _items: ExplorerItem[] = [];
  private _isCut = false;

  /** 复制到剪贴板 */
  copy(items: ExplorerItem[]): void { this._items = [...items]; this._isCut = false; }

  /** 剪切到剪贴板 */
  cut(items: ExplorerItem[]): void { this._items = [...items]; this._isCut = true; }

  /** 粘贴到目标目录 */
  async paste(targetDir: string): Promise<void> {
    for (const item of this._items) {
      const destPath = this._resolveName(targetDir, item.name);
      await FileService.copy(item.uri, destPath);   // 先 copy
      if (this._isCut) {
        await FileService.deleteEntry(item.uri);     // 剪切 → 再删源文件
      }
    }
    if (this._isCut) this.clear(); // 剪切只能粘贴一次（对标 VS Code）
    model.refresh(targetDir);
  }

  /** 文件名冲突时加后缀 */
  private async _resolveName(dir: string, name: string): Promise<string> {
    let dest = dir + '/' + name;
    if (!(await FileService.exists(dest))) return dest;
    // "file.txt" → "file - Copy.txt"
    const ext = name.lastIndexOf('.');
    const base = ext > 0 ? name.slice(0, ext) : name;
    const suffix = ext > 0 ? name.slice(ext) : '';
    let n = 2;
    while (await FileService.exists(`${dir}/${base} - Copy${n > 2 ? ` ${n}` : ''}${suffix}`)) {
      n++;
    }
    return `${dir}/${base} - Copy${n > 2 ? ` ${n}` : ''}${suffix}`;
  }

  get items(): ExplorerItem[] { return this._items; }
  get isCut(): boolean { return this._isCut; }
  get isEmpty(): boolean { return this._items.length === 0; }
  clear(): void { this._items = []; this._isCut = false; }
}
```

## 五、#99 拖放——路径归一化根除（#99a-#99c）

> 2026-07-29。#99 拖放实现后暴露 3 个路径分隔符不一致 bug。本节分析 VS Code 做法 + 提出根除方案。

### 5.1 VS Code 源码分析

**关键文件：** `src/vs/workbench/contrib/files/common/explorerModel.ts`

```typescript
import { URI } from '../../../../base/common/uri.js';
import { posix } from '../../../../base/common/path.js';       // ← POSIX 路径，永远是 /
import { joinPath, isEqualOrParent, basenameOrAuthority } from '../../../../base/common/resources.js';
```

**VS Code 不归一化——他们用 `URI` 对象本身就不存在 `\`：**

| VS Code 做法 | LinkDesk 现状 |
|:--|:--|
| 文件路径是 `URI` 对象 | 文件路径是 `string` |
| `URI` 内部永远是 `/`（RFC 3986） | `listDir` 返回 Windows `\` 路径 |
| `URI.fsPath` 仅在 OS 边界转 `\` | 全链路裸字符串——多源混用 |
| 比较走 `isEqualOrParent`（URI 语义） | `_expanded` 走 `Set.has()`（纯字符串相等） |
| `joinPath` 用 `posix.join` | `pathUtils.ts` 的 `splitPath` 用 `/`，`listDir` 返 `\` |
| `IFileService.copy(src, dest)` 两个入参都是 URI | `FileService.copy(src, dest)` 两个入参都是 string |

**结论：** VS Code 用 `URI` 类型做类型墙——`\` 永远进不到模型层。LinkDesk 没有这个类型墙，必须用归一化规则模拟。

### 5.2 现状——三个 bug 同一根因

| Bug | 现象 | 根因 |
|:--|:--|:--|
| 1 | 拖 `.exe` 报 `ENOTDIR` | `electron/file-service.ts` copy handler 只调 `copyDir`（假定源是目录），文件→`readdir` 炸 |
| 2 | 拖放后源目录 twistie↓ 但空 | `refreshDir` 未调 `getChildren`（首次实现缺失） |
| 3 | 修复 2 后仍折叠 | `dirname()` 输出 `/`，`_expanded` 存 `\` → `isExpanded` 查不到 |

Bug 1 是 `FileService.copy` 后端能力缺口（#83 为插件目录迁移写，源永远是目录）。
Bug 2 是 #99 初版逻辑缺口。
Bug 3 是系统级路径分隔符不一致——`listDir` 经 `path.join()` 产出 `\`，前端工具函数产出 `/`。

### 5.3 根除方案

**一步归一化：`FileTreeModel` 入口统一 `uri` → `/`。** 对标 VS Code `URI` 对象的"内部永远是 `/`"。

```

    │
    ▼
_toExplorerItem         ← 🔥 归一化点：entry.path.replace(/\\/g, "/")
    │
    ▼
ExplorerItem.uri = "/"   ← 全链路统一 / 格式
    │
    ├── _expanded.add(uri)     ← 一致
    ├── isExpanded(uri)        ← 一致
    ├── findClosest(uri)       ← 一致（已经内部 normalize）
    ├── flattenTree → item.uri ← 一致
    └── dirname(uri)           ← 一致
```
