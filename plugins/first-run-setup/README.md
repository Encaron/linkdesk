# 首次配置

![首次配置——本机就绪的青碧色块](resources/icon.svg)

一个官方样板插件。装上之后，它会在你这台电脑上落一份配置档案，然后**自己发一条通知**告诉你配好了。

它存在的理由只有一个：证明「装好了」和「配好了」是**两条互不掩盖的通知**——而且这件事真的能在你机器上发生。

## 你会看到什么

装好这只插件的一两秒内，通知面板（状态栏右端的铃铛）里会并排出现两条：

| 通知 | 谁说的 | 意思 |
|---|---|---|
| 已安装：首次配置 v1.0.0（即时生效） | 宿主 | 插件文件装进来了 |
| 首次配置完成——已在本机写好配置档案 | **这只插件自己** | 它在你这台电脑上配置好了 |

两条来自不同的生产者、说不同的两件事，所以**谁都不该盖住谁**。这不是巧合，是设计：

- 第一条由宿主发（安装流程的结论）；
- 第二条由插件自己发（`notifications.show(..., { source: "first-run-setup" })`）——**来源必须由作者显式报**，宿主进程分不出这次调用是哪只插件发的（池是单进程共享 realm）。

## 它到底配了什么

最朴素、也是任何真插件装完第一件要做的事：**记住自己在你这台电脑上的位置**。

装好后，LinkDesk 会给每只插件一个属于自己的数据目录。本插件把宿主给它的路径（数据目录 / 缓存目录 / 导出口）连同配置时刻，写成一份 `config.json`：

```
{用户数据目录}/linkdesk/plugins/first-run-setup/data/config.json
```

主区标签页里能直接看到这份档案的路径、写入时间和数据目录——点路径即可复制。想再跑一遍，点右上角的「重新配置」，或者从命令面板执行 `首次配置：重新配置本机`。

## 三条能直接抄走的纪律

写「安装后配置 + 出声」这类插件时，本插件踩过的坑都在代码里：

1. **`source` 只能你自己报。** 不传就全落进「其他」分组，跟宿主那条「已安装：X」混在一起——设计的意义就没了。
2. **配过一次就别再出声。** 配置是一次性的，重复播报就是噪声。本插件拿 `config.json` 在不在当标记，重跑必须显式要求（`force`）。
3. **并发要合并。** 视图和状态栏会各自触发一次，第二次必须复用第一次那个进行中的 Promise——否则同一次配置写两遍盘、发两条通知。

还有一条不是纪律、是前提：**插件没有「安装时执行代码」这回事**。插件 JS 只有两条惰性激活轨（表面挂载 / 命令触发）。所以「装完立刻配一次」这件事，只能挂在一个**一装上就会自己出现**的表面上——本插件用的是状态栏自绘组件（`appearsIn.statusBar`）。装好后注册表一变，状态栏下一次渲染就会把它挂起来。

## 怎么读这份源码

| 想看什么 | 看哪 |
|---|---|
| 配置流程 + 三条纪律 | `src/services/setup.ts` |
| 装上即自动运行的那个表面 | `src/components/statusBar.tsx` |
| 主区的「本机就绪报告」 | `src/views/SetupView.tsx` |
| 命令 handler 为什么必须在模块顶层 | `src/index.tsx` |

它是一份样板，改起来没有负担：数据目录是宿主给的，配置文件是本插件自己写的，卸载插件不会动它在别处留下的东西。
