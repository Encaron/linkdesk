## §一 立案原话与拍板记录（2026-09-19）

1. **用户愿景原话（综合对话）**：插件自由制造，允许插件自绘 UI，也想用壳 UI；用壳 UI 的插件天然统一——「壳改一次，只发一次壳的版本，所有插件跟着走」；死插件不再冻结旧 UI、不再永远吃不到 bug 修复。参照系 = Windows 集中控件 + 浏览器（组件原语由宿主供给、宿主升级全网受益、契约只加不删）。
2. **🔴 皮骨边界拍板（2026-09-19 用户：「我同意你的这个换肤不换骨头」）**：**皮全开放**——token/主题域越加越多，万物可换肤（侧栏/标签栏/底部栏样式都是 token 驱动，已成立）；**骨不开放**——壳 chrome 的**结构替换**永不作为插件能力（自锁风险/隔离墙破口/伪 UI 安全面三理由，详对话记录）；壳 chrome 只暴露**声明式配置槽**（壳枚举好的选项）。本批只动 `@linkdesk/ui` 的供给通道，与壳 chrome 无涉。
3. **🔴 发版授权（2026-09-19 用户：「我授权这个任务系列的发版」）**——本批全部发版轴（npm 四包 / 四只消费仓 / 壳 tag）**无需逐次请示**，但每轴发前仍须过既有机械门禁（`release:mark` / freshness / check 全绿），实机验收仍须用户点头（照 E6#120 §8.5 先例）。
4. **集中化的机制依据（为什么可进行）**：react 系今天就是这么供给的——`packages/plugin-sdk/src/vite-config.ts:57` `DEFAULT_EXTERNAL` + `scripts/build-pool-vendor.mjs` 多入口 esbuild split + import-map 注入 `dist/pool.html`（E6#15d G2b，2026-09-06 实证落地）。本批 = 把 `@linkdesk/ui` 加进这套**已实战验证**的清单，不是新发明。

## §二 设计前置（8 维度，照 design-flow）

- **① 能力边界**：壳能力。保底成立——壳自身不消费 `@linkdesk/ui`（组件仍居 `src/components/shared/`，壳直接引源码）；无插件消费时 vendor chunk 零 import 零加载，翻通道对壳零风险。
- **② API**：**零新 API**。props 契约、d.ts、`@linkdesk/contracts` 全部原样。⛔ 不引命令式 `window.linkdesk.ui.*`（07 号档否 B 的理由继续有效：盖不住嵌入控件 + 两套契约违反归一化）。
- **③ 通信**：不变。组件要壳数据仍走 `window.linkdesk.*` 桥，禁 `@src/core`。
- **④ 壳侧**：改动全在**清单与构建轨道**——`DEFAULT_EXTERNAL` 加一项、`build-pool-vendor.mjs` 的 `MAP_KEYS` 加一项、vendor 脚本补 css link 注入。单一权威不动摇：一份源码（`src/components/shared/`）→ barrel（`packages/linkdesk-ui/src/index.ts`）→ vendor 单实例。
- **⑤ 插件侧**：作者面零学习成本——`npm i @linkdesk/ui` 照旧（装的是**类型 + dev 解析体**，不再是随包分发的实现）；import 语句照旧；产物瘦身（组件代码/样式不再进 `.linkdesk-plugin`）。
- **⑥ 显示**：不变。token 层原样——主题/玻璃仍走 `var(--*)` 运行时继承，皮归壳、骨归契约。
- **⑦ 配置**：零新配置。钉线（`@linkdesk/ui@<线>` manifest 钉定）**本批不实现**、只留设计位（见 §六风险④）——0.x 期消费面小（4 只官方仓），先不背这个机制。
- **⑧ 验收**：真机 probe（具名导出链接 / 跨插件同实例 / css token 跟随 / 无插件零成本）+ `npm run check` 全绿 + 双插件实机「壳改一处、两插件同时变」+ 用户视觉验收。

## §三 版本策略（重锚定案——回答用户 2026-09-19 三问）

1. **现状澄清**：`@linkdesk/ui` 实际版本线是 **0.3.1**（不是 3.x），壳 **0.2.12**——两条线本来就近，重锚代价极小。
2. **定案：从此 `@linkdesk/ui` 版本号 = 发它的那个壳版本号，锁步走**。翻通道的这次发版即重锚点。理由：作者心里只留一条线（类型包版本 = 它是哪个壳的契约），无对照表可查——归一化「一个概念一个号」。
3. **npm 撞号规则（一次性）**：npm 版本不可复用——若壳新版本号已被 ui 包历史占用（如壳将发 0.3.0 而 ui 0.3.0 已在 npm），则**壳 bump 到下一个未占用号让位**（patch 位 +1 即可），记档原因。执行时用 `npm view @linkdesk/ui versions` 机械核对。
4. **同步是机械行为**：壳发版仪式（version-bump skill）的断言清单**加一条**——壳发版必带 `@linkdesk/ui` 同号 bump（落点 = `scripts/check-npm-release.mjs` 或 version-bump 档案，#124 落实）。此后每次发版零判断。
5. **存量插件**：源码 import 语句**不变**；每只消费仓一次 `devDependencies` 版本号 bump + 重新 build + 重发（#125）。运行时此后与插件自装版本无关——「装哪版类型」只影响 IDE 提示与能否使用新组件，不影响旧组件长相（**只加不删 ⇒ 类型旧 + 壳新 = 永远安全方向**；类型新 + 壳旧 = `minAppVersion` 拦）。

## §六 风险与可行性（用户令：不许做到一半发现做不下去）

1. **技术风险集中在 #122 一处，且前面有闸**：G2b 已趟平 rollup/esbuild 全部坑，`@linkdesk/ui` 的 dist 是纯 ESM（`packages/linkdesk-ui/scripts/build.mjs` 产真 ESM + 注入 css import）→ 走 vendor 脚本「原生 ESM 直连」路径，**不需要 react 系那套 CJS facade**。probe 四断言任一不过 = 停批。
2. **可逆性**：#122/#123 的改动全部是**清单加行 + 注入加段**，删掉即回分发式，零迁移残留。
3. **契约纪律（翻通道的地基，#121 先行）**：导出面快照 + 只加不删判红常驻 `npm run check`；**行为铁律**同笔入档：同版本内行为不变；行为变更 = 新 prop 或新组件名；token 内样式随意改。**这条不立，通道不翻。**
4. **钉线不实现的风险口**：旧插件 × 新壳的行为漂移由「行为铁律」挡；若 1.x 前需要真钉线，设计位 = import-map 双 URL（`@linkdesk/ui` 最新线 / `@linkdesk/ui@N` 钉线）+ manifest 声明 + 退役账——届时刻立格，本批不预造。
5. **CSS 通道是本批唯一的形态决策点**（组件样式必须随壳走，否则「样式更新跟着壳」的承诺破产）——定案见 [03 §三](03-任务-SDK-external化与vendor正式接线.md)：vendor css 由池注入 link，插件源码删 css import，dev 由壳 vite 兜底注入。

## §七 禁区

- ⛔ 壳 chrome（标签栏/侧栏/底部栏/窗口框）的**结构**永不开放给插件替换——只有声明式配置槽 + token 皮（§一拍板 2）。
- ⛔ 不引入任何 `window.linkdesk.ui.*` 命令式面。
- ⛔ 壳内组件消费方式不变（仍直接引 `src/components/shared/` 源码）——vendor 只服务插件侧，防环依赖（07 §①保底）。
- ⛔ `@linkdesk/ui` npm 包**不删不发空壳**——它是类型 + dev 解析体的唯一发布位（#124 定案）。
