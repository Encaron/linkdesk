# 04 · 手势隐藏规则（屏幕上看得见 ≠ 门开着）

> **本章的口径**：不是教你怎么拖，是告诉你 **别走手势**。
> 屏幕上那些「拖一下 / 悬一下 / 双击一下」的动作，**每一个都有命令或 API 替身**——而且手势路径带**隐藏门控**
> （位移阈值、相位切换、指针所在区域），少一个条件就**静默不生效**（不报错、不反馈，最难查）。
> 你要的是「把标签放进左分屏」，不是「复现人手的运动轨迹」。

## 一、总表：手势 → 隐藏门控 → 正解

| 屏幕上的动作 | 隐藏门控（少一个就静默失效） | 正解（命令 / API） |
|:--|:--|:--|
| 拖标签到另一个分组 | 位移 > 5px 才「拎起」（`threshold`）；插入位置按标签中线二分算缝 | `pool.tabAction({action:"moveTab", tabId, targetGroupId, newIndex?})` |
| 拖标签**分屏** | 🔴 **必须有垂直位移 > 15px**（`splitThreshold`）**且**指针在**编辑器纯区**（不悬在任何标签栏上方）才切到 split 相位 | `pool.tabAction({action:"splitTab", tabId, direction})`；或命令 `core.splitRight` / `core.splitDown {tabId}` |
| 往**左**拖出左分屏 | 🔴 纯水平拖动**永远进不去** split 相位（相位切换只看 `\|dy\| > 15`）⇒ 直觉动作会退化成「排序」 | `direction:"horizontal"` ＋ `targetGroupId`（要哪边就指定哪个组） |
| 拖标签**跨窗并窗** / 拖出**开新窗** | 🔴 依赖 `winScreenX = screenX − clientX` 推出的窗口屏幕原点；**合成事件（CDP）不带 screenX** ⇒ 归零 ⇒ 窗外判定与命测全错 | `core.openInNewWindow {tabId}`（脱出新窗）/ `core.mergeBackToMain {tabId}`（并回主窗）/ `moveTab`（跨组） |
| 拖分割条调分屏比例 | 需命中 0.4% 宽的分割条（`HANDLE_PCT`），并落在正确分支 | `pool.tabAction({action:"updateSplitSizes", anchorGroupId, sizes:[a,b]})` |
| 悬停标签才出现的 `[×]` | 需真实指针悬停（`:hover` / `mouseenter`）——CDP 的 `forcePseudoState` **不下传**到已存在的深层节点 | `tabs.close(tabId)` / `core.closeTab {tabId}` |
| 悬停才出现的**侧栏区块操作钮**（section `actions` 槽 / 溢出后的 `…`） | `:hover` 揭示（**键盘腿 = `:focus-within`**，Tab 进区块头即揭示，M2 `AI#22`）；`…` 出不出现还看容器宽（`ResizeObserver` 判溢出）⇒ 只在窄侧栏出现 | 钮背后全是命令（`view.titleActions` 声明的命令 id）⇒ 直接 `executeCommand(id)`；**不知道有哪些**就先 `getCommands()` 按前缀搜（[02 章](02-命令与API索引.md)） |
| 双击标签固定 / 中键关闭 | 双击时序 / 中键事件——CDP 合成不可靠 | `core.togglePin {tabId}` / `core.closeTab {tabId}` |
| 右键标签 → 菜单项 | 菜单**只列**当前上下文过 when 的项；且要先弹菜单 | 菜单项背后全是命令：`core.splitRight` / `core.closeOtherTabs` / `core.closeRightTabs` / `core.togglePin` …（`ctx` 就是菜单的上下文） |
| 悬停出提示（HintTip / 悬浮说明） | 需 hover 停留计时 | 直接读**数据面**（`getCommands()` 的 `description`、布局树、`viewContainer.getViews()`）——信息量只多不少 |
| 滚到底加载更多（虚拟列表） | 依赖滚动位置与分页时序 | 走数据 API（如 `filesystem.listDir` / `search.searchFiles`） |
| 拖文件进窗口 / 从窗口拖出 | OS 层拖放（见 [05 章](05-够不着清单与安装版路径.md)） | 文件用**路径**直接开：`tabs.create("editor", { filePath })`；导出走 `dialog` |

## 二、门控是怎么写的（给维护者：改动手势前先看这里）

| 门控 | 出处 | 行为 |
|:--|:--|:--|
| 拎起阈值 `5px` | `src/pool/hooks/useDragReorder.ts`（`threshold = 5`） | 未超阈值不启动，连浮块都不出现 |
| **分屏相位阈值 `15px`（只看垂直位移）** | 同上（`splitThreshold = 15`） | `phase === "reorder" && Math.abs(dy) > splitThreshold && inEditor` ⇒ 切 split |
| **回落到排序相位** | 同上 | `phase === "split" && !inEditor` ⇒ 回 reorder（只关毛玻璃，浮空克隆保留） |
| 落区判定（四边 / 中心） | `src/pool/hooks/tabDragTypes.ts`（`detectDropZone`） | 各边占 25%（`SPLIT_THRESHOLD = 0.25`）；**左右优先于上下**（照抄 VS Code）；中心 = 合并 |
| 窗口屏幕原点 | `useDragReorder.ts`（`winScreenX = (e.screenX ?? 0) − e.clientX`） | 合成事件缺 `screenX` ⇒ 原点错 ⇒ 跨窗命中/「窗外」标志全错 |
| 跨窗命中 | `src/App/windows/windowRelocation.ts`（`hitTestTabBar`） | 壳拿权威 window bounds ＋ 池上报的 TabBar viewport rect 转屏幕坐标；命中 TabBar ⇒ 并窗，命中空白 ⇒ 新窗（`{x: screenX−100, y: screenY−40, w:900, h:600}`） |
| 分屏树深度上限 `4` | `src/core/utils/splitTree.ts`（`MAX_TREE_DEPTH`） | 超限的布局被拒——嵌套前先读 `getLayout().root` 的深度 |
| **hover-only 揭示门控**（侧栏区块 `actions` / `…`） | `src/components/shared/sidebar-section/SidebarSection.css`（`.show-on-hover` → `:hover` / `:focus-within`） | 只认 `:hover` 就会出现「**键盘 Tab 进去的是看不见的钮**」（可聚焦但 `opacity:0`）⇒ 🔴 **键盘腿 `:focus-within` 与 hover 必须成对**（M2 `AI#22`） |

**为什么要写成表**：这些阈值散在池侧拖拽钩子里，**任何一条改动都会让「肉眼看着一样」的手势悄悄换行为**
（用户报「有时候拖不成分屏」多源于此）。AI 走命令面则**完全绕开这一层**——命令与阈值无关。

## 三、when 门控 ≠ 权限（一个常被误会的点）

- `when` 只决定**命令在菜单/命令面板里出不出现**（以及快捷键是否触发），**不拦 API 调用**。
  所以「菜单里没有这条」≠「这条不能调」：`executeCommand` 照样能调。
- 反过来：⛔ **不要**靠猜 when 去判断「这个动作现在能不能做」——**先读状态**（`tabs.list()` / `getLayout()` /
  `configuration.get()`），拿状态决定调什么。
- 幂等或「已在该侧则无动作」的命令（如 `workbench.action.toggleSidebarPosition` 已到位时、
  `alignPanel*` 已对齐时）**不报错也不动作**——这就是 [01 章](01-操作路径总览.md) §四 第③步「读回来验」存在的理由。

## 四、视觉兜底的三条纪律（真到了没有门的时候）

1. **先穷尽结构化路径**：`getCommands()` 里搜该插件前缀；再查 [02 章](02-命令与API索引.md) §三 API 面。
2. **兜底期间明确标注**「这是视觉兜底，不是结构化操作」——不要把它算进「达标」。
3. **兜底优先用 CDP 而非纯截图**：能拿到 DOM/表达式就别猜像素；但**手势本身在 CDP 下不可靠**（§一 第 3、6 行），
   所以即便用 CDP，也**优先调命令**，而不是派发 `Input.dispatchMouseEvent` 去重演拖拽。
   CDP 侧的坑单列一册：[06-CDP坑表](06-CDP坑表.md)。

## 五、一句话给 AI

**凡是「要手腕动作才能完成的事」，先假设它有一条命令**——去 `getCommands()` 找。
找不到再回来看本章确认它是不是真的只能手势；**真的只能手势的，如实报告做不到**（§四 纪律 2），别硬模拟。
