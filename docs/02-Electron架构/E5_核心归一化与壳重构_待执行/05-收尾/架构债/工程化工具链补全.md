## 一、`npm run fix`——自动修复

### 问题

`npm run check` 跑 tsc + ESLint + vitest，但不做 auto-fix。406 个 `no-explicit-any` warning 大部分在 `global.d.ts` 完成后可以 `eslint --fix` 自动消。

### 方案

```json
// package.json scripts
"fix": "eslint src/ plugins/ electron/ shared/ --fix"
```

`tsc` 没有 auto-fix，`vitest` 也没有——`fix` 只管 ESLint 可自动修复的规则。手动改的（如 `no-explicit-any` 需要人工判断类型）不动。

## 二、pre-commit hook——从源头拦截

### 问题

硬约束靠 ESLint 机械执行——但 ESLint 只在 `npm run check` 时跑。如果忘了跑就 commit → 硬约束形同虚设。

### 方案

**simple-git-hooks（轻量，无依赖臃肿）：**

```bash
npm install -D simple-git-hooks
```

```json
// package.json
"simple-git-hooks": {
  "pre-commit": "npm run check"
}
```

```json
// package.json scripts
"prepare": "simple-git-hooks"
```

不阻塞 commit（太慢会让人跳过 `--no-verify`）——但至少提醒。CI 上再做完整检查。

### 为什么不用 husky

husky v9 需要 Git 2.38+ + 复杂的安装步骤。simple-git-hooks 一行配置，零依赖（只依赖 lint-staged 可选）。

### 可选增强——lint-staged

只检查 staged 文件（不跑全项目 tsc/vitest，太快）：

```json
"lint-staged": {
  "*.{ts,tsx}": ["eslint --fix", "vitest related --run"]
}
```

但 vitest `--related` 有时漏——保守用全量 `npm run check`。团队大了再优化。

### 加一条——全局 unhandled rejection（现在就能做）

```typescript
// App.tsx initAll() 或 main.ts
window.addEventListener("unhandledrejection", (event) => {
  console.error("[LinkDesk] 未捕获的 Promise 拒绝:", event.reason);
  // 可选——reportError({ message: "未捕获错误", error: event.reason });
  event.preventDefault();
});
```

7 步异步 init 链中任何一步的 reject 没被 catch → 至少控制台能看到。**现在就能加，5 分钟。**
