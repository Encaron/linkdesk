# E5.8-跟随主题生效值徽标档案（#155）

> 2026-08-27。**用户实机：设置行处于「跟随主题」态时字段空，看不出当前生效成什么。** 实锤两例：`app.fontFamily` 跟随主题后显示空（不知生效字体）；`app.glassTint` 跟随主题后颜色框空（不知生效 rgba，主题值 rgba(59,77,148,0.35) 实际生效中）。用户拍板立案 **#155**（跟随主题徽标）。
> 清单指针：E5.8-执行清单 Phase 11.22 #155。

---

## 一、背景与用户实机证据

用户 4 条发现里的最后一条：`app.fontFamily` / `app.glassTint` 改成别的值 → 选「跟随主题」（下拉或齿轮）→ 配置变 `""`（[coreCommands.ts:245-258](../../../../src/core/commands/shell/coreCommands.ts#L245-L258) 齿轮「跟随主题」= resetConfigurationValue 回落 schema 默认），**字段/色框为空**——主题的生效值（字体栈 / rgba 玻璃色）不显示。

`""` = 跟随主题是**合法配置值**（设置层只存用户偏离量，主题值在配方里不物质化）。这不是 bug，是设计——但**「跟随主题时看不出生效成什么」是真 UX 缺口**：用户不知道当前字体实际是什么、玻璃实际是什么色。

## 二、现状（file:line）——数据源全现成，唯一缺口在显示层

| 位置 | 现状 |
|---|---|
| `getEffectiveTokens()` | 池侧**现成** API——`window.linkdesk.theme.getEffectiveTokens()`（[appearance.ts:24](../../../../src/core/api/linkdesk-api/appearance.ts#L24)）返回全部生效 CSS token（含 `font-ui` / `glass-tint`）；IPC 桥 handler [theme.ts:56](../../../../src/core/services/plugins/IpcBridgeHandler/theme.ts#L56) `theme.getEffectiveTokens` |
| `SettingRow.tsx:148-166` | 每行齿轮/值区现成渲染——徽标可落行尾（值区旁） |
| `renderControl.tsx` | 各控件 onChange 现成——改值后需刷新徽标（configuration.onChange 已有订阅机制） |
| 跟随主题语义 | `""` 或哨兵 = 跟随主题——判定现成（`resetsToTheme` 声明 + 齿轮 context key `settingFollowTheme`） |

**结论：零新 API、零新配置。** 徽标数据 = 读 `getEffectiveTokens()` 生效值，显示层增强。**壳改动 = schema 声明**：实现期用户拍板归一化（「你还不如归一化好」）——弃插件内映射表，`ConfigurationProperty` 加 `effectiveToken` 可选字段、appearance 三键声明 token key（对齐 `sourceKey` 先例）。

## 三、8 维度设计前置

> 任务性质：**壳 UI 显示层升级**（设置行「跟随主题」态 + 生效值徽标）。非新能力 API——数据源现成。

### ① 能力边界
- **壳能力**。跟随主题 = 壳级语义（`resetsToTheme` 声明 + 空值契约）；徽标只是**显示层**——不改变任何配置/应用行为。
- 保底：徽标数据源 getEffectiveTokens 无活动配方时返回空集 → 徽标不显示（安全降级，不崩）。

### ② API 设计
- **零新增 `window.linkdesk.*`**。数据源 = 现成 `theme.getEffectiveTokens()`。
- 按配置 key 解析对应生效 token（config key `app.fontFamily` → token `font-ui`）——**声明进配置 schema**（`ConfigurationProperty.effectiveToken?: string`，对齐 `sourceKey` 先例）。壳 appearance 三键声明（`fontFamily`→`font-ui` / `fontFamilyMono`→`font-mono` / `glassTint`→`glass-tint`）；settings 插件读 `prop.effectiveToken` 即解析，**零映射表**。第三方键声明即得同能力（零壳改动）。壳侧 getEffectiveTokens 语义现成。

### ③ 通信方式
- 单次拉取（挂载时 `getEffectiveTokens()`）+ 刷新（`configuration.onChange` 订阅——改值/切主题/切外观模式 → 徽标更新）。settings 插件已用 configuration.onChange（useConfigurationValueIpc 先例）。
- 数据流：壳 ThemeEngine（生效 token）→ 池 getEffectiveTokens → SettingRow 徽标渲染。单向，无回写。

### ④ 壳侧代码设计
- **schema 声明**（数据源现成）：`ConfigurationRegistry.ConfigurationProperty` 加 `effectiveToken?: string` 可选字段 + appearance.ts 三键声明 token key。壳 ThemeEngine 不动。
- 单一权威 = ThemeEngine getEffectiveTokens（生效值唯一来源）+ 配置 schema（token 映射唯一来源，防两份漂移）。

### ⑤ 插件侧代码设计
- settings 插件显示层增强：
  - `SettingRow.tsx`——行处于「跟随主题」态时渲染生效值徽标（行尾）。
  - `renderControl.tsx` / 各控件——不强制，徽标归 SettingRow 统一渲染（控件零改）。
  - `useConfigurationValueIpc.ts` 或新 hook——拉取生效 token + 订阅刷新。
- 首批徽标行：`app.fontFamily`（生效字体名）/ `app.fontFamilyMono`（生效等宽族）/ `app.glassTint`（生效色块预览）；后续按需扩展（backgroundImage 等）。
- **归一化（实现期用户拍板）**：无插件内映射表——`effectiveToken` 从 prop 读 schema 声明；展示形态 `formatEffectiveValue` 按值驱动（色值 rgba/#hex 带色块、字体栈截首族），token 键零知识。

### ⑥ 显示设计
- **位置**：设置行**行尾**（值控件右侧 / 齿轮左侧），跟随主题态才出现。
- **形态**：小徽标「生效：‹生效值›」+ 色块（玻璃色行）。具体视觉**实现时用 design skill 竞标**（对标 VS Code settings 的「从默认值继承」显示哲学——显示继承来源而非裸空）。
- **语义**：徽标 = 「当前跟随主题实际生效成什么」——补空值的可读性，不改值语义。

### ⑦ 配置设计
- **零新增配置项**。徽标是运行时显示态，无持久化。

### ⑧ 代码规范 + 验收
- 归一化：key→token 映射一处（**schema effectiveToken 声明**，对齐 sourceKey 先例）；跟随主题态判定一处（isFollowingThemeValue = deriveSourceBadge 用户条件取反，与来源徽标同源语义）；展示形态按值驱动（token 键零知识）。
- 无死代码：徽标组件随行渲染，无残留。
- **验收**：
  1. `npm run check` 全绿（含 #145 机械门禁）。
  2. 单测：跟随主题态判定 + key→token 映射 + 徽标渲染（跟随主题显示生效值 / 非跟随主题不显示）。
  3. **CDP 实机**：fontFamily/glassTint 设「跟随主题」→ 行尾见生效值徽标（字体名/色块）→ 改成具体值 → 徽标消失 → 切主题 → 徽标随新生效值更新。
