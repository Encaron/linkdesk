## 二、[09-插件目录规范.md](../../03-插件制造/09-插件目录规范.md)——新增一节

### 2.1 目录树补两行

`§标准目录结构` 的树里：

```
my-plugin/
├─ plugin.json           # 插件声明——唯一必选文件
├─ icon.svg              # 插件图标（可选）——根目录 或 resources/，由 plugin.json `icon` 字段声明
├─ README.md             # 插件说明（可选）            ← 改措辞
+├─ CHANGELOG.md          # 更新日志（可选）—— 新增这一行
├─ i18n/                 # 翻译文件
```

**`README.md` 那行的「（可选）」措辞要改。** 现在写「（可选）」暗示可有可无，但详情页「详情」页签的数据源**就是它**——没有它市场详情页只有一句 description。改成：

> `README.md` # 插件说明——市场详情页「详情」页签的数据源（强烈建议提供；缺失 = 详情页只剩一句 description）

`CHANGELOG.md` 那行同理：

> `CHANGELOG.md` # 更新日志——市场详情页「更改日志」页签的**唯一真源**（不提供 = 该页签显示「该插件未附带更改日志」）

### 2.2 新增章节「`README.md` / `CHANGELOG.md`——说明与更新日志」

要写进这一节的**五件事**：

**(1) 两者的分工与读者**

| 文件 | 喂给谁 | 缺了会怎样 |
|:--|:--|:--|
| `README.md` | 详情页「**详情**」页签（Markdown 渲染，支持图/视频/外链——见 [12](12-README说明区媒体契约.md)） | 详情页只剩一句 `description` |
| `CHANGELOG.md` | 详情页「**更改日志**」页签 | 该页签显示「该插件未附带更改日志」 |

**(2) 位置固定**——两者都放**插件根目录**（与 `plugin.json` 同级）。**不声明路径、不看 `plugin.json` 任何字段**：读取方按**固定文件名**读包内文件。

> 🔴 **写死这一条的理由**：以前有个 `plugin.json.readme` 字段说是「指向包内文件」，但**没有任何读取方**——读取方直接读 `README.md` 这个**文件名**。留着那个字段 = 留着一个骗人的写法。**本层把它删掉**（[02 号档案](02-元数据链路归一.md)）。

**(3) `CHANGELOG.md` 的格式约定**——SDK `publish` 要从它**切段**填目录条目，所以标题行格式有约束：

```markdown
# 更新日志                  ← 文档标题（自由）

## v1.0.0（2026-09-11）      ← 🔴 版本段标题：`## v<版本号>`，版本号严格等于 plugin.json 的 version
- 修了某某问题
- 加了某个能力

## v0.9.0（2026-08-01）      ← 旧版本往下排，最新在最上
- …
```

- **段标题必须能解析出版本号**（`## v1.0.0…` / `## 1.0.0…` 都认，`v` 可省）。**解析不出 → publish 该版本的目录条目留空**（诚实留空，不猜——见 [02 §四](02-元数据链路归一.md)）。
- **日期写在标题行括号里**（`（2026-09-11）`），只用于展示。
- **标题之外的正文 = 该版本的变更说明**（Markdown 原文照搬，不做二次解析）。
- **版本倒序（最新在最上）**——详情页按此顺序渲染。

**(4) 「一个概念一处表达」铁律**

> 🔴 **`plugin.json` 里没有 `changelog` / `readme` 字段，也不会有。** 更改日志**只**写在 `CHANGELOG.md`；说明**只**写在 `README.md`。**见到任何「在 plugin.json 里记更新日志」的写法都是过期资料。**

这一条要**显式写**——因为旧写法在旧提交、旧文档、旧插件里还有残影，不写清楚下一个人会抄回去。

**(5) 与版本号联动**

改 `README.md` / `CHANGELOG.md` 的内容 **= 内容变更 = 必须 bump `plugin.json.version`**（承 [04-插件分发格式 §四](04-插件分发格式.md)：软件只补缺失、永不刷新已装）——写一条交叉引用，不重复展开。

### 2.3 与 `plugin.json` 的关系写一句

**`version` 是两边的锚**：`CHANGELOG.md` 的段标题版本号 ↔ `plugin.json.version` ↔ 目录条目 `versions[].version`，**三处同源**。（读 [02 §四](02-元数据链路归一.md) 的切段算法。）

## 三、[06-plugin.json规范.md](../../03-插件制造/06-plugin.json规范.md)——删两行 + 一句交代

### 3.1 删

`§可选字段` 表里删掉两行：

```diff
-| `readme` | `string` | 附带说明文档路径——相对插件目录（如 `"./README.md"`）；`.linkdesk-plugin` 详情/市场展示数据源（E6#4a：作者包里有 README.md 就随包，本字段指向包内文件） |
-| `changelog` | `array` | 更新日志 `[{ version: string, date: string, changes: string[] }]` |
```

### 3.2 补一句「为什么没有这两个字段」

紧跟可选字段表之后：

> **为什么这里没有 `readme` / `changelog` 字段？**
> 说明与更新日志**以文件为准**——插件根目录的 `README.md` / `CHANGELOG.md`（见 [09-插件目录规范](09-插件目录规范.md)）。这两个字段在 E6 开发期曾存在，但**从无读取方**（读取方按固定文件名读包内文件），于 2026-09-11 随 L3.7 删除。**写进 plugin.json 不会生效，只会被忽略。**
> 若你从旧教程/旧提交抄到了这两个字段 → **删掉，改写成文件**。

### 3.3 连带检查（本轮一并核，改不改当场定）

- §完整示例（视图+侧栏+状态栏 / 主题 / 语言 / 协议 / 资源五个例子）里**有没有任何一个用了 `readme`/`changelog`**？→ 有则删。
- §最小示例（视图插件）**要不要顺手加 `README.md` / `CHANGELOG.md` 的提示**？→ **不加**。最小示例的卖点是「最小」，说明文件属「建议」不属「必需」，加进去会稀释。由 3.7.1 新增的那一节承接即可。

## 四、[12-README说明区媒体契约.md](../../03-插件制造/12-README说明区媒体契约.md)——封面位置收口

### 4.1 §三 第 1 条改措辞

现在写「`resources/cover.svg`、`cover.svg`、`./resources/x.mp4` 都行」——**技术上仍是对的**（SDK 按 README 引用抓资产，不看目录），但**规范上要收口**：

```diff
-1. **优先「相对路径 + 随包」**：文件放进插件目录（惯例 `resources/`），README 里写相对路径——`resources/cover.svg`、`cover.svg`、`./resources/x.mp4` 都行。
+1. **写「相对路径 + 随包」**：媒体文件放**插件根目录的 `resources/`**，README 里写相对路径 `resources/cover.svg`。**SDK 构建自动把这些被 README 引用的资产打进 zip**（零声明）。
+   🔴 **媒体一律住 `resources/`**——图标同理（`plugin.json` 的 `icon` / `marketIcon` 也写 `resources/…`）。**插件根目录不放散图**。
```

并在同一节末尾补一句**技术事实**（免得读者把「规范收口」误读成「放根目录会坏」）：

> ℹ️ **技术上放插件根目录也能工作**（SDK 只看 README 里写了什么路径）。**收口到 `resources/` 是规整性要求，不是正确性要求**——官方插件的 8 只范本全部用 `resources/`，新插件跟齐即可。

### 4.2 §六 样板名单同步

§六 现在写「看它们 README 顶部那张 `![…](resources/cover.svg)`（或 `cover.svg`）就是封面标准写法」——**去掉括号里的例外**，改成统一写法。（editor 在 [04 号档案](04-资源与目录归位.md) 里归位后，8 只范本就是**清一色 `resources/`**。）
