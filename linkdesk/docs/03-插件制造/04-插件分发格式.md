# 04 — 插件分发格式

> 2026-07-24。**插件如何打包、如何安装、版本兼容规则。** 对标 VS Code 的 VSIX。

---

## 一、分发格式

### 源码树插件（开发阶段）

插件放在 `plugins/<pluginId>/` 目录下。Vite 在构建时通过 `import.meta.glob` 扫描并独立打包每个插件的入口文件。

**目录结构：**
```
plugins/<pluginId>/
├── plugin.json          ← 必需
├── index.tsx            ← entry 指向的文件
├── sidebar.tsx          ← 可选侧栏组件
├── theme.json           ← 主题定义（theme 类型）
├── lang.json            ← 语言包（language 类型）
├── *.css                ← 可选样式
└── assets/              ← 可选资源（图片/字体）
```

**适用于：** 核心自带的 4 个插件（terminal/marketplace/settings/workspace）；开发者在源码树中写的测试插件。

### 独立构建插件（生产发布）

第三方插件需要自己的构建产物——不能依赖 Vite `import.meta.glob`。

**构建产物结构（`.linkdesk` 文件 = zip）：**
```
my-plugin.linkdesk (zip)
├── plugin.json
├── dist/
│   ├── index.js         ← 编译后的 JS（Vite/Rollup/webpack 产物）
│   ├── index.css        ← 编译后的 CSS
│   └── vendor.js        ← 第三方依赖（可选——也可内联到 index.js）
├── sidebar.js           ← 侧栏编译产物（可选）
└── assets/
    └── logo.png
```

**构建要求：**
- 入口文件必须编译为单文件 ES module（`dist/index.js`），包含所有依赖或与 `vendor.js` 有正确的 import 映射
- CSS 必须提取为独立文件或内联到 JS
- 资源文件（图片/字体）在 `assets/` 下，用相对路径引用
- `plugin.json` 的 `entry` 字段指向编译后路径：`"entry": "dist/index.js"`

**插件脚手架（计划——E3 后）：**
```bash
npx create-linkdesk-plugin my-plugin
# → 生成目录 + Vite 构建配置 + plugin.json 模板 + index.tsx 模板
```

### 资源类插件（无代码）

纯资源（theme / language / resource 类型）不需要构建——直接打包 `plugin.json` + 资源文件即可。

```
my-theme.linkdesk (zip)
├── plugin.json
└── theme.json
```

## 二、安装流程

```
用户拖 .linkdesk 文件到 LinkDesk 窗口（或从插件市场点"安装"）
  │
  ▼
壳解压 zip → 校验完整性（plugin.json 存在 + JSON 格式正确）
  │  失败 → toast 提示
  │
  ▼
壳检查版本兼容（minAppVersion ≤ 当前版本）
  │  不满足 → toast "需要 LinkDesk ≥ 1.2.0"
  │
  ▼
壳检查硬依赖（requires）
  │  依赖的插件未安装 → toast "需要插件 XXX v1.0.0" + 安装按钮禁止
  │
  ▼
壳检查权限（permissions 声明 vs 用户授权）
  │  E3 后：弹窗 "CAD 查看器请求访问文件系统 → [允许] [拒绝]"
  │
  ▼
壳复制文件到 .linkdesk/plugins/<pluginId>/
  │  冲突检测：已有同名插件 → 对比版本 → 选高版本 or toast 询问
  │
  ▼
壳注册插件 → 图标栏出现 → toast "已安装"
  │
  ▼
JS 激活时机由 activationEvents 决定
```

## 三、目录约定

### 插件安装目录

| 位置 | 用途 |
|------|------|
| `plugins/<pluginId>/` | 源码树插件（开发阶段——Vite glob 扫描） |
| `.linkdesk/plugins/<pluginId>/` | 用户安装的外部插件（生产运行） |
| `.linkdesk/plugins/.disabled/<pluginId>/` | 已卸载的插件（可恢复） |

### 插件数据目录

| 位置 | 读写权限 | 用途 |
|------|:--:|------|
| `.linkdesk/plugins/<pluginId>/data/` | 读+写 | 插件自己的持久化数据、缓存、导出文件 |
| `plugins/<pluginId>/plugin.json` | 只读 | 元数据——插件不能修改自己的 manifest |

**获取自己的数据目录：**
```typescript
const env = await window.linkdesk.env.get();
const myDataDir = env.pluginDataDir;  // .linkdesk/plugins/<pluginId>/data/
```

### 壳数据目录

| 位置 | 用途 |
|------|------|
| `.linkdesk/settings.json` | 全局设置 |
| `.linkdesk/layout.json` | 窗口布局（标签页/分屏/图标顺序） |
| `.linkdesk/plugin-states.json` | 插件启用/禁用/安装状态 |
| `.linkdesk/profiles/` | Profile 配置 |

## 四、版本兼容

### 语义化版本一致

`plugin.json` 的 `version` 字段遵循 semver（`major.minor.patch`）：

- **major 升级** → 可能有不兼容的 API 变更。卸载旧版、安装新版
- **minor 升级** → 新功能，向后兼容。直接覆盖旧版
- **patch 升级** → bug 修复。直接覆盖旧版

### 最低版本要求

```json
{
  "minAppVersion": "1.2.0"
}
```

`minAppVersion` 声明此插件需要的最低 LinkDesk 版本。壳安装前检查——不满足 → 拒绝安装 + toast "需要 LinkDesk ≥ 1.2.0"。

### API 版本化（远期——E3 后）

当 `window.linkdesk.*` API 发生不兼容变更时：

```json
{
  "apiVersion": ">=1.0 <2.0"
}
```

- 壳声明 `window.linkdesk.apiVersion = "1.2"`
- 插件声明需要的 API 范围
- 壳检查 → 不兼容 → 安装时 toast 提示

**API 分域独立版本：**
- `filesystem: 1.0`
- `serial: 1.0`
- `config: 1.0`
- `commands: 1.0`
- `events: 1.0`

每个域独立演进——改 `serial.*` 不影响 `filesystem.*` 的版本号。

## 五、权限声明

```json
{
  "permissions": ["serial", "filesystem", "network"]
}
```

| 权限 | 授予的能力 | 风险 |
|------|------|------|
| `serial` | `window.linkdesk.serial.*` 全部 API | 访问物理串口硬件 |
| `filesystem` | `window.linkdesk.filesystem.readTextFile/writeTextFile` | 读写文件系统（限制在插件数据目录 + 用户选择的文件） |
| `network` | 任意 HTTP/WebSocket（插件 Web 平台本就可以——此权限声明用于用户知情） | 数据外传 |

**安装时显示：** "CAD 查看器 请求以下权限：访问文件系统——[允许] [拒绝]"

## 六、插件市场协议（远期——E3 后）

### registry.json 格式

插件市场是一个可访问的 URL，返回：

```json
{
  "registry": "https://plugins.linkdesk.app/v1",
  "plugins": [
    {
      "id": "cad-viewer",
      "name": "CAD 查看器",
      "version": "1.2.0",
      "description": "DWG/DXF/STL 文件查看器",
      "author": "社区",
      "icon": "package",
      "download": "https://plugins.linkdesk.app/dl/cad-viewer-1.2.0.linkdesk",
      "size": 2457600,
      "minAppVersion": "1.0.0",
      "permissions": ["filesystem"],
      "rating": 4.5,
      "downloads": 1234
    }
  ]
}
```

### 安装按钮行为

1. 从 registry 读取 `download` URL
2. 下载 `.linkdesk` 文件到临时目录
3. 校验 SHA256（如果 registry 提供了）
4. 执行安装流程（§二）

## 七、开发→分发全流程

```
1. 开发阶段
   mkdir plugins/my-plugin
   写 plugin.json + index.tsx
   → npm run dev → 插件在源码树中运行 → HMR 即时热更新

2. 构建阶段
   npm run build （插件自己的 Vite 配置）
   → dist/index.js + dist/index.css

3. 打包阶段
   将 plugin.json + dist/ + assets/ 打包为 my-plugin.linkdesk (zip)

4. 分发阶段
   上传到插件市场，或直接发给用户

5. 安装阶段
   用户拖 .linkdesk 到 LinkDesk → 自动安装 → 图标栏出现 → 可用
```
