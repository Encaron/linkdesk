## 〇、大白话——这是在解决什么问题

把插件做成「独立打包、随壳发货、装进去启动」之后（E6#15），有个最后一公里没走完：

> **开发期（dev）**：插件还从**源码目录**（`plugins/<id>/src/*.tsx`）被壳的 Vite 直接编译加载——所以一直好好的。
> **打包版（安装后）**：没有 Vite 了。插件靠「发货夹 `bundled-plugins/` 的 zip → 首次启动自动解压到 `{userData}/plugins/<id>/` → 从**编译产物**（`index.bundle.js` 等 dist 文件）加载」。这一条链路**机制已全通**（解压、发现、解析都对），但真正**渲染**时崩两个地方：

1. **资源目录里还躺着一份插件源码**（老发货方式残留），发现逻辑「app 根优先」总先捡到源码那份 → 池子去加载 `.../src/views/*.tsx` 这种**没编译过的 TypeScript** → 浏览器根本不认 → 崩。
2. 删掉那份源码、让加载器终于用上编译产物后 → 产物里写着 `import "react"` 这种**裸依赖名**（打包时按约定不把 react 塞进每个插件）→ 打包版里没人告诉浏览器「react 在哪个文件」→ 崩。

本文档就是设计怎么把这最后一公里修通，让**打包版从 dist 完整消费所有内置插件**（React 8 个 + 纯 JSON 12 个），并定义「全功能正常」的验收。

## 二、现状盘点——消费链已落（证据）vs 真缺口

### 2.1 消费链已落的地基（探索实锤，2026-09-05）

打包产物与发货轨（React 8 半边 ✅，#15b 注）：

- **产物格式**：每个 React 插件独立 build 出 `index.bundle.js` + `views/*.bundle.js`（每 surface 一 lib build）+ `index.bundle.css` + dist 版 `plugin.json`（`render` 已改写指向编译产物）——见 [02-linkdesk-plugin格式规范.md](02-linkdesk-plugin格式规范.md) + plugin-sdk `vite-config.ts:104-131`（`collectSurfaces`/`rewriteDistManifest`）。
- **发货 + 自动装**：`bundled-plugins/` 平铺 zip（6 真件入库）→ boot `ingestPluginBundles` 自动解压到 `{userData}/plugins/<id>/` 单根（#15c 507 段③a，92c48d066 + 同日塌平改写）。
- **发现（双根、app 优先、去重）**：`pluginRoots()` = `[appPluginsDir, userPluginsDir]`（`electron/services/plugin-file-service.ts:38-41`）；`listPluginDirs` `seen` 去重（`:62-81`）；壳侧 `discoverInstalled` 走 IPC `listAll`（`src/pluginLoader/resolution/state.ts:152-166`）。**不双份注册**。
- **入口解析**：`resolveEntry` 返回 `{root, entry, bundle}`——`bundle` = 磁盘存在 `index.bundle.js` 的事实，命中则 `entry` 恒 `"index.bundle.js"`（`plugin-file-service.ts:175-193`）。
- **协议**：`linkdesk://<id>/...` 双根有序解析 + 穿越检查 + MIME 表**含 `.css: text/css`**（`electron/plugins/protocol.ts` 全篇）——css 走协议**不缺 MIME**。
- **池侧视图加载 + css 注入**：侧栏 view 走 renderPath（`linkdesk://<id>/views/X.bundle.js`）直接 `import(renderPath)`（`PluginComponent.tsx:63-90`）；主区无 renderPath 走 `resolveEntry` → 拼 URL import（`:105-119`）；css `<link>` 引用计数注入**机制已在**（`PluginComponent.tsx:164-189` 触发 + `bundleCss.ts` 全文：`cssUrlForRenderPath` 对 `.bundle.js` 编译面剥 `/views/` 回根派生 `index.bundle.css`，retain/release 按挂载实例数），**dev `/@fs` 与 prod `linkdesk://` 双形态都覆盖**。

> 一句话：**机制链基本咬合**。03 §3.4 当年标「待实现」的 css link 注入，代码层面已被 #9d/#9e 时代的 PluginComponent/bundleCss 实现覆盖——不是空白，是**打包实机从未走过**。真正让 #15d 崩的是下面三个缺口。

### 2.2 真缺口清单

#### 🔴 G1 —— 源遮蔽：resources 里躺着整棵插件源码，app-first 总捡到它

- **证据**：`electron-builder.yml:31-32` `extraResources: - from: plugins → to: plugins` = 把 repo `plugins/` **整棵源码目录**打进 `resources/plugins/`。prod `appPluginsDir` = `<resources>/plugins`（`electron/services/env-service.ts:25-29`），在双根里**排第一**。
- **症状**（#15d 实证崩溃①）：打包版里同 id 插件 = resources 源码副本 + userData dist 副本并存 → 发现/manifest 水合/`resolveEntry` 全解析回 **resources 源码**（`plugin-file-service.ts` app-first）→ 源码副本的 `plugin.json` 里 `render` 是原始 `src/views/X.tsx` → 池 `import(linkdesk://<id>/src/views/X.tsx)` → **裸 .tsx 浏览器无法加载** → `Failed to fetch dynamically imported module`。
- **本质**：老发货方式（壳源码树整拷）没随 pre-bundle 切换拆除，是**过渡残留**，不是新架构。

#### 🔴 G2 —— prod 无裸依赖解析（无 import-map）：dist 产物里的 `import "react"` 没人接

- **证据**：plugin-sdk 打包时把宿主依赖 external 成**裸 specifier**（`packages/plugin-sdk/src/vite-config.ts:53-54` `DEFAULT_EXTERNAL`，含 react/react-dom/react/jsx-runtime 及 react-i18next/i18next；`:217` 应用到每 surface）。**dev 兜底** = 壳 vite 插件 `resolveUserDataBundles()`（`vite.config.ts:56-83`，仅 importer 路径含 userPluginsHome 时 `require.resolve`）。**prod** = `loadFile(dist/*.html)` 无 Vite（`electron/main.ts:135-137` / `window-manager.ts:186-192`），全仓 grep `importmap` 零实现，`index.html`/`pool.html` 均无 `<script type="importmap">`。
- **症状**（#15d 实证崩溃②）：删源副本后 settings 改载 dist `index.bundle.js` → 产物内 `import "react/jsx-runtime"` → 浏览器无法解析裸 specifier → `Failed to resolve module specifier "react/jsx-runtime"`。
- **本质**：宿主（壳/池窗口）自己用 react 渲染 chrome，但没把 react 变成**可被动态 import 的模块**给插件产物引用——插件与宿主各自一份 react 会导致 hooks/context 断裂，所以不能塞进产物；正确姿势 = 宿主把 react 暴露为稳定模块 URL。

#### 🟠 G3 —— 纯 JSON 插件（theme×10 + lang×2）entryless 在 prod 会幻影 import

- **证据**：`loadPlugin` 的 isRuntime 分支对**每个** userData 发现的插件（含无 entry 的 theme/lang）都调（`src/pluginLoader/loader.ts:116-131`）；`runtimeEntryPath` prod 非 bundle 无 entry 时返回 `` `${pluginId}.js` ``（`src/pluginLoader/contributions/contributions.ts:288-297` 尤 `:296`）→ `:259 if(entryPath)` 真 → `:262` `resolveViewModule` 动态 import → **404** → `:281` catch → warn + toast「加载失败——可能未构建」**误报**（不阻断，贡献照常注册）。
- **症状**：打包版首启 JSON 12 自动装到 userData 后，每个纯数据插件都弹一次「加载失败——可能未构建」误报。
- **对照**：glob 分支有 `role==="data"` 显式跳过 entry（`runtime.ts:294-297`），isRuntime 分支**缺对称处理**——纯数据包该注册贡献但不 import 入口。

#### 🟡 G4 —— css link 注入：机制在，打包实机未走（归门禁验证，非新构造）

- css 注入 + css MIME 都已具备（见 §2.1）。剩余 = **在打包实机确认**：每个 React 内置插件渲染时 `index.bundle.css` 的 `<link>` 出现且样式生效（含视图面 renderPath 与主入口无 renderPath 两分支）。不建新机制。

## 三、方案（逐缺口）

### G1 —— 摘除 plugins 源码拷贝（= #17a 提前到本批）

- **改**：`electron-builder.yml:31-32` 删 `- from: plugins → to: plugins`。打包版 `resources/` **不再含任何插件**。
- **后果**：打包版插件唯一根 = userData（boot 解压产物）。双根在 prod 退化为「app 根**缺位** + userData 单根」。
- **连带适配（都要验）**：
  - `listPluginDirs` / `_findPluginDir` / `resolveLinkdeskPathMulti` 对**不存在的 app 根**不得崩/不得误判（空目录容错——先查现实现是否有 `existsSync` 守卫）。
  - `env-service.ts` appPluginsDir prod 语义从「必在」改「可能不存在」；dev 不变（dev app 根 = repo `plugins/` 源码树，消费切换相不碰 dev）。
  - 语义收敛：摘除后「app 根」在 prod 与「发货夹 + boot 自动装」职责彻底分离——resources 只放只读发货夹（bundled-plugins/），userData 是唯一运行根。**与塌平后「发货夹非运行根、装进去才是」的模型自洽**（06-builtin-user 语义规范）。

### G2 —— 宿主暴露 react 系为稳定模块，html 注入 import-map

**目标约束**：
1. 插件 dist 产物保持 external 裸 import（不改 SDK）——产物与宿主 react 版本解耦靠宿主侧兜底。
2. 每窗口内**单 react 实例**：插件组件与同窗口宿主 chrome 共享同一 React（hooks/context 不裂）。跨窗口各自实例（本来就无法共享，正确）。
3. 在**执行插件动态 import 的文档**注入 `<script type="importmap">`，且须**先于该文档首个 module script**（浏览器 import-map 生效前提）。
4. map 里 react 系 specifier → **稳定文件 URL**（file:// base 相对路径）。

**注入位置（按 §四 铁律/拍点②）**：插件代码唯一执行者在**池**——import-map **只注入 pool.html**（`PluginComponent` 的 renderPath / resolveEntry import 所在，主渲染面）。壳窗口（index.html）**不注入**——壳按「壳想池画」只消费声明；壳 loader 的 `resolveViewModule` 入口 import（`contributions.ts:318`）是待审残留（§四.2），不给残留配 react。注入形态 = 只进打包产物（dev 由 vite 解析插件、不需 map；若源码 pool.html 恒带 map 需 spike 证 dev 不误伤，见 §六 spike 3）。

**react 变稳定模块——实现方向（P0 spike 已裁决 2026-09-05，四探测结论见 §六）**：
- **朴素 A（map 直接指向 chrome 现有 react chunk）已否决**：实证该 chunk（dist/assets/index-B59MOzyB.js）是 CJS 惰性工厂 facade，结尾仅 `export{Ec as r}`——**零具名导出**。rollup 唯一静态消费者把 react 当整包 default 取，未合成具名；而真实插件 dist（settings）是 `import { useState, useEffect, … } from "react"` + `react/jsx-runtime`(jsx/jsxs) + react-dom(default) + react-i18next(useTranslation)，map 指过去拿不到名。
- **定方向 = 隔离 + 全量命名再导出**：池 build 内用 `manualChunks` 把 react 系（react / react-dom / react/jsx-runtime / react-i18next / i18next）隔离成**独立稳定名 chunk**，并加一个**可达的全量再导出入口**（`export *` + `export { default }`）逼 rollup commonjs **把全部具名导出合成到该 chunk**；产物名固定（去 hash，或构建期把真实名写回 html 的 map）。chrome **不外部化**——其静态 import 与插件运行时动态 import 落到**同一 chunk URL**（实测力学：同 URL = 同模块单例，§六 探测 4），单实例由结构保证。
- **落点两形态（倾向 manualChunks+再导出，独立 vendor ESM 构建为退路）**：① 池 build 内 manualChunks + re-export 入口（chrome 保持 bundled，单实例结构保证，零额外构建）；② 独立小型 vendor ESM 构建 + 池 build 外部化 react（react CJS→真 ESM 需独立产物）。实现时 build+smoke 钉——两者皆须满足**单 react 实例 + 具名导出齐 + 产物 URL 稳定**三约束，任一不满足换另一形态并记实证。
- 🔥 **实证落地 = 形态②**（2026-09-06，G2b commit a4042eedc）：形态① manualChunks + 全量再导出被 build-probe 否决——rollup commonjs 对 react 18 CJS opaque（index.js 二次 `module.exports=` 间接隐藏 `exports.X=` 字面赋值）**零具名合成**，产物 chunk 只出短别名（命名空间对象），浏览器 import-map 严格静态链接拿不到名。落地 = esbuild 多入口 split 独立 vendor ESM（`scripts/build-pool-vendor.mjs`）：react 系共享依赖自动提升 chunk → 各入口 stub **静态 import** 同 chunk（单实例由同 chunk URL=同模块结构保证）；react 系真-ESM facade 逐键合成具名（键清单 = node `require()` 实导，react 36/react-dom 12/client 2/jsx-runtime 3/jsx-dev-runtime 2），i18next/react-i18next 原生 ESM 直连；import-map 注入**打包产物** dist/pool.html（幂等剥旧；只进池窗不碰壳）。真 Chromium（Electron 43 + file://）probe 实证三约束全过：36+3+2+2 静态具名链接零缺、facade/stub/动态 import/跨模块同实例、createRoot 渲染 + react-i18next init 全通。

**否决项（不采用）**：SDK 把 react 内联进每插件产物——每插件一份 react = 多实例上下文断裂 + 体积爆炸 + 版本 skew，违反「宿主提供运行时」的铁律。

**宿主运行时契约（铁律 A 附带，§四.3）**：map 覆盖集 = plugin-sdk `DEFAULT_EXTERNAL` 全集（react 系 + react-i18next/i18next）；契约落 SDK 文档，作者不猜哪些裸依赖不用自己管。

**备注**：import-map 是 Chromium 原生特性（Chrome 89+），Electron 现行内核**免 polyfill**；file:// 下相对 URL 解析需 spike 确认（模块/import-map 在 file:// 的边角已知存在，但 Electron 通常可跑——实证为准，见 §六 spike 4）。

### G3 —— entryless 纯数据包：isRuntime 分支对称跳过入口 import

- **判定**（在 runtime isRuntime 主入口步 + `runtimeEntryPath` 内）：无 `manifest.entry` **且** 磁盘无 `index.bundle.js`（非 bundle）→ 纯数据包。
- **行为**：跳过主入口 `resolveViewModule`；仍走 `loadPluginLifecycle`（`parseContributions` 注册 themes/languages → registry 元数据）+ 数据加载（`loadThemeContributionData`/`loadLanguageContributionData` fetch `linkdesk://<id>/...` 协议可达，路径已在）。loadState 标 **active** 非 failed；无「加载失败——可能未构建」误报。与 glob 分支 `role==="data"` 语义对称（一个判定来源，两分支消费）。
- 🔥 **实现落点 = `runtimeEntryPath` prod 分支**（2026-09-06，G3a）：dev 本就 `manifest.entry || null` 天然跳过 entryless；prod 旧实现一律返 `${pluginId}.js`（`contributions.ts:296`）→ 纯数据包目录无此文件 → linkdesk:// 404 → catch 吞 + 误报 toast。改 = prod 且 `!opts.bundle` 且 `!manifest.entry` → 返 null（两调用点 runtime.ts:258/:429 均已 `if (entryPath)` 守卫，null 即跳过 import）。Step 5-7（loadPluginLifecycle 贡献注册 + 主题/语言数据 + markLoadSuccess active）照走。单测同步（loader.test.ts prod+entryless → null）。
- **JSON 12 补发（随 #15b JSON 半边，同批落地）**：lang-defaults / lang-test-ja / theme×10 各一个 `.linkdesk-plugin` 纯打包 zip（plugin.json + JSON 资源，无 build 步骤），直落 `bundled-plugins/` 平铺 → boot 自动装（机制已通）。**当前 `plugins/` 内 12 个 JSON 插件目录已在 dev 源码树**，zip 即打包其 plugin.json + 随包 JSON。
- 🔥 **补发走独立打包器**（2026-09-06，G3b）：**SDK build 无纯数据包路径**——`collectSurfaces`（vite-config.ts:178-183）要求 entry 或 contributes.views[].render，theme/lang 两者皆缺直接 throw；且 SDK 静态拷贝清单不含 `themes/*.json` 等数据本体。落 = `scripts/pack-bundled-plugins.mjs`（`npm run pack:bundled-json`）：扫描 `plugins/` 下 entryless 目录（无 entry 且无 src/）整树 → `<id>.linkdesk-plugin` 直落 `bundled-plugins/`，React 8 有编译表面由 SDK 产 zip 不碰（防双源漂移）。12 zip 已生成 + 顶层 plugin.json 平铺验过（18 = 6 React + 12 JSON）。

## 四、决策记录（2026-09-05 用户拍板「按你的想法来」）——十诫重筛：两铁律 + 两拍板点

> 原 D1-D4 是"机制怎么接"的四个技术选项；拍板前拿十条质量戒律当筛子重定：**被原则锁死的升格为铁律（不占裁决）**，真拉扯的两点单独拍板。本节 = 决策真相源，§三/§五/§六 的实现细节服从本节。

| # | 议题 | 裁决 | 依据（十诫） |
|---|---|---|---|
| **铁律 A**（原 D2） | react 系由**宿主**提供 + import-map；**禁 SDK 内联** | 宿主暴露 | 多 react 实例 = context/hooks 断裂 = 正确性破坏非风格差；map 一处写 → 内置 + 未来第三方 zip 自动受益（归一化 / 插件独立性 / 生态） |
| **铁律 B**（原 D3） | **物理摘除** plugins 源码拷贝（prod `resources/` 不含任何插件源码） | 提前 #17a | G1 = 老发货残留 = 死代码；物理捡不到源码才无特判（归一化 / 无死代码） |
| **拍点 ①**（原 D1） | dev 源码特快轨本批不切 dist | 保留 + **标注过渡态 + 挂退役锚** | 见 §四.1（归一化 / 慢工「100 插件后」判据） |

### 四.1 拍点 ① —— dev 源码特快轨：过渡态 + 退役锚 + dist 快验

- 本批 dev 零回归：插件仍从 `plugins/` 源码树被壳 Vite 编译加载（glob/HMR/LSP 跳转照旧）。消费切换相只管打包版轨道。
- **①a 退役锚**：dev=源码是**内置插件独享**的特快轨——壳启动时 vite 编译 100 棵插件源码树不可持续；且第三方永远走"装包消费"，内置/第三方两套 dev 体验违反"插件只有一个种类、一条消费路"（归一化）。退役条件 = **#15f（壳 Vite build 排除插件代码）**——dev 转成与第三方同一条 dist 消费 + 增量重建。**本批不实现，清单挂锚**。
- **①b dist 快验**：本批补一条"dist 面低成本日常照法"——否则每次 dist 面改动都要打包才知道崩没崩（#15d 这类 bug 全为 dist 面独有 = 禁硬编码判据「dev 与打包一致吗」的反面）。**spike 先验**：dev vite fallback（`resolveUserDataBundles`）对 userData 的 dist 包是否现成可达 → 若可达，日常即可"装一个 dist 包 → 验消费链"，G2 类提前到 fast loop（见 §六 spike 1b）。

### 四.2 拍点 ② —— 「壳只消费声明、池是插件代码唯一执行者」铁律

**论证（壳想池画 → 执行权归池）**：

- 壳 = 无可见 DOM 的"想"引擎（E5.7 §3.3：纯状态持有者，被池完全覆盖）。它 import 插件入口拿到的 React 组件**过不了窗口、壳永不挂载**——那份执行是**死执行**（无死代码）。
- 分工：壳只读 manifest 声明做注册（想）；模块代码执行、组件挂载全归池（画）。
- **推论 → import-map 只落池窗**：落点由分工派生，不是"双窗起手再实证收窄"的凑合。壳窗不需 react 解析。

**现状 + 审计**：

- 壳 loader 的 `resolveViewModule` 入口 import（`contributions.ts:318`）若确在 prod 执行 React 插件入口 = 过渡残留死执行，待审计：有无架构必需（如命令 handler 必须在壳侧执行）？有则显式列出论证，无则清除（顺带消灭"壳也要 react"整类问题）。
- **spike 是审计工具，不是 map 决策者**（§六 spike 1a）：只证壳 loader 那条 import 死/活；铁律已定 map 落池窗。
- 清理节奏：本批尾有余量则清，否则 #16/#17 壳瘦身（清单记锚，默认 #16/#17）。

### 四.3 铁律 A 的附带承诺 —— 宿主运行时契约

- 宿主接住的裸依赖 specifier 集合 = **plugin-sdk `DEFAULT_EXTERNAL` 全集**（react/react-dom/react/jsx-runtime/react-i18next/i18next），map 必须覆盖全集——漏一个，第三方今天装的包明天就崩（健壮性）。
- 把「宿主运行时契约」写进 SDK 文档：作者查 SDK 即知哪些裸依赖不用自己管（ai 友好第 3 层——不猜）。落点 = `02-linkdesk-plugin格式规范.md` + plugin-sdk 文档。

### 四.4 铁律 B 的语义收敛 —— prod app 根缺位 = 正常态

- 摘除后 prod `resources/` 无插件、appPluginsDir 缺位 = **正常状态**（非异常）。发现/协议/env-service 对不存在的根不得崩、不得误判（空目录容错，查 `existsSync` 守卫）——按健壮性处理，不按"prod 特例"加 if。

## 六、P0 风险 spike（动手第一步，先证后铺）

> spike 角色已随 §四 拍点② 定死：**审计 / 探测工具，不是决策者**。import-map 落池窗、react 宿主提供是铁律，spike 只证实现细节、并审计壳 loader 残留死活。

铺正式实现前用最小打包冒烟钉死四个未知（都影响方案细节、不该凭猜写码）：

1. **1a · 壳 loader 入口 import 死活审计**（§四.2）：打包版里壳 loader 的 `resolveViewModule` 主入口 import（`contributions.ts:318`）是否真对 React 插件执行？执行了为何没在启动即崩（被 catch / defer / 实际是池才挂）？→ 定壳窗残留清理范围（本批尾 vs #16/#17）。CDP 挂壳/池两窗 console，看 `Failed to resolve module specifier` 落在哪窗。
2. **1b · dist 快验姿势探测**（§四.1 ①b）：dev vite fallback（`resolveUserDataBundles`）对 userData dist 包是否现成可达 → 若可达，日常"装一个 dist 包 → 验消费链"即可成立，G2 类提前到 fast loop；若不可达，快验姿势的最小形态是什么。
3. **react 稳定 chunk 方案**：manualChunks 固定名（A）vs 独立 vendor 文件（B）哪个在 file:// 下干净可 import + map 相对 URL 解析正常；池 chrome 自身须 import 同一 chunk（单实例，§三 G2 约束 2）。
4. **file:// + import-map 兼容性**：Electron loadFile 下 `<script type="importmap">` 是否生效、相对路径基准是否 = 文档 URL。（风险最高点——若 file:// 下 import-map 有坑，备选：主进程在 `did-finish-load` 前用 `session.webRequest` 拦截 html 注 map，或壳用自定义协议页加载 dist。）

**探测结论（2026-09-05 实录，四探测完成）**：

| 探测 | 结论 | 对方案的影响 |
|---|---|---|
| **4 · file:// + import-map 兼容性** | ✅ **PASS（最高风险解除）**。独立 Electron 43 harness（忠实镜像 linkdesk:// 注册 standard+secure+corsEnabled + ACAO:\* 头）双变体实证：file:// 文档裸 `import("react")` 经 map → 相对 file 目标解析正常；**协议 origin 模块**（模拟 linkdesk:// 插件 bundle）内裸 `import from "react"` 经 map 落到同一 file:// vendor = 与文档侧**同一模块实例**（同 URL = 单例，双写同对象实证）；file 文档 → 协议模块跨 scheme module fetch 放行（顶帧 file 页 → Chromium 对整张图放行本地资源访问）。 | G2 import-map 方案**可行**，设计文档此前备选（webRequest 注 map / 自定义协议页）**不需要**。map 目标 file:// 或协议 URL 皆通。 |
| **3 · react 稳定 chunk** | **朴素 A 否决**。全新 build 实证 react chunk 是 CJS facade 零具名导出（见 §三 G2）；真实 settings bundle 具名导入面逐一核实（react 具名 + jsx-runtime + react-dom default + react-i18next）。→ §三 已改裁决方向（隔离 + 全量命名再导出）。 | map 目标必须是有真具名导出的模块；chrome 单实例由「同 URL = 同模块」结构保证。**落点已钉 = 形态②**（2026-09-06，commit a4042eedc，见 §三 G2 🔥 行）：形态① manualChunks+再导出 build-probe 否决（rollup CJS 零具名合成），esbuild split + facade 落地——三约束真 Chromium 全过。 |
| **1a · 壳 loader 入口 import 死活** | **代码审计判死**：`isRuntime = !manifestKey`（pluginManifestRaw glob 命中）；壳 build 仍 glob `plugins/` 源码树 → **打包后内置插件全在壳 glob 内** → 走 glob chunk（react 已进壳 bundle）→ **壳窗对内置不碰 dist、不撞 react 裸 import**；crash② 只落池窗（PluginComponent `import(linkdesk://…)` 绕过 glob 直拉 dist）。壳侧真会碰 dist 裸 import 的只有 **glob 外第三方插件** → try/catch 吞 + 误报 toast。 | 壳 loader 视图入口 import = §四.2 残留死执行确认；打包两窗 console 归属的实机确认**并入 #15d 批尾验收**（不单跑 electron:build）；残留清理默认随 #16/#17。 |
| **1b · dev dist 快验** | 机制在（`resolveUserDataBundles` + fs.allow 已含 `%APPDATA%/linkdesk/plugins`），未单跑——随 §三 实现首步「装一个 dist 包 → 验消费链」一并验。 | ①b 快验姿势本体，不单列重活。 |

spike 通过 → 按 §三 铺实现 → #15d 实机验收 → 大白话报告 → 拍板回勾。

## 七、验收判据（#15d 全功能 = 什么）
