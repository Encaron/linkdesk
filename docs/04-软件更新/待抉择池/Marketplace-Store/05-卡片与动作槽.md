# 卡片与动作槽——原子组件与未来扩展的唯一合法落点

> **为什么存在**：卡片是 Store 的原子组件（首页槽位流、合集槽、分类页网格、榜单全用它），动作槽是「收费/购买」等未来扩展的唯一合法落点。本文 2026-11-19 讨论拍板，实施与评审对照执行。
> **上游**：[04-分类体系](04-分类体系.md) §六/§七（卡片被哪些页面消费）；[02-病灶与目标](02-病灶与目标.md) §四（动作槽 = 七条质量要求的试金石）；[03-入口与数据归一](03-入口与数据归一.md) §二（数据纪律——卡片只许订阅 store）；**事实底座**：[01-插件侧现状](01-插件侧现状.md)（现有 CatalogRow 行态、installJobs 流水）。

## 一、卡片信息密度（拍板）

**取舍标准**：卡片放「决定要不要点进去」的信息（这是什么/谁做的/有多热/什么状态/能不能马上装）；验证性信息（版本/体积/日期）与深内容（README/截图/changelog）留给详情页。

| 卡片本体（默认中卡） | 不进卡片本体 |
|---|---|
| 图标（裁决序：已装→目录→默认块，仓规照旧） | 简介（**不进卡片静态本体**——进 hover 展开区与 lg/duo/hero 变体；用户 2026-11-19：默认卡不放简介「似乎也不影响什么」；浏览判定的活交给名＋图标＋热度＋状态） |
| 插件名＋作者 | 版本号、包体积、发布日期（验证信息 → 详情页） |
| 下载数（热度信号；`downloadCounts.ts` 已在抓） | README/截图画廊/changelog → 详情页 |
| 状态徽标：已安装 / 有更新 | 评分/评论（将来接服务器才有——**信息块位预留**，见 §二） |
| **动作钮（直装/更新——不进详情页直接装，用户原话「有的人就是要安装这个插件，多多爽」）** | 贡献点清单、依赖、minAppVersion → 详情页 |

信息块做成归一化小组件（图标块/标题块/简介块/统计块/徽标块）——变体只是块的排列差异（§四），将来弹窗/详情复用同款块。

## 二、hover 悬浮展开（🔴 拍板变更 2026-11-19：**本版实现**，不再延期）

> 🔴 **第 0 条·机械守则（2026-11-19 硬性要求，对本档一切模式与 R4 实现生效）**：**一个元素的状态变化不得影响其他任何元素**——hover/选中/进行中只许 transform／opacity／颜色／遮罩／portal 浮层；⛔ display、height、width、margin 等参与文档流几何的属性不得参与状态展示。验收判据：hover 任意卡片，页面上其他一切元素的像素位置不变。
>
> 变更缘起：v1 蓝图批注（用户原话「把这个 hover 给做上吧，不延期了，直接做上……我现在讲的很多都是后边儿的样子」）——原「本版不实现」作废，本条为现行拍板。

**定位不变**：展开区是预告，详情页是全部——简介＋关键统计，不放 README 全文。**实现 = 卡片原位放大展开（in-place expand）**（v3.1 批注定稿——用户原话：「我理解的那种 hover 态就是它自己放大，自己展开放大……而不是说底下出现一个弹窗」「它就是一种设计语言，表示我 hover 住了……自然而然要把旁边盖住一点，体现出我顶上去了」；⛔ v2.1 的 portal 脱体浮窗作废）：

| 模式 | 卡片 | hover 行为 | 出处 |
|---|---|---|---|
| **原位放大展开** | small（装机必备）／grid（分类网格） | 卡片本体 **scale 1.1**＋「放大展开层」`.x-over`（absolute 负偏移、垂直居中锚定：图标＋名＋分类＋动作钮＋简介 ≤2 行）同步 scale+fade 进入——**视觉上就是卡片自己长大、盖住邻元素**；展开层不占布局（第 0 条守则） | MS Store 小卡实测（WPS 卡 hover 自身放大盖住旁边＋出简介＋Install） |
| **整卡放大＋灰条上延** ✅ **验收通过（2026-11-19，B13）** | mega（主题专区超大卡） | 本体 scale 1.12；底部实色条（名/分类/免费，60px）**常驻不动**，hover 时同底色延伸段（118px：标语＋简介＋按钮）从它顶上**向上滑出**，封面图标同步上移让位——**字不碰封面、单一连续表面**，与放大同一时序（v3.7）——⛔ 文字压封面、分体延伸层（.cm-x 分界线）、画面接管层均已废弃 | v3.7 批注（「我仍就是要底下那种灰色的条……哪怕说这个灰色条往上延伸都行了」「字直接展示在 UI 图片上面……显示的不是很好」） |
| **原位替换** | rank（热门下载名次行） | hover 时下载量淡出、安装钮在同一位置浮现（absolute 定位）——几何不动 | 「跟别的元素没有关系」同款纪律 |

**小卡比例拍板（v3.1）**：**10:3.6（236×84），图标 48px**——对标 MS Store 10:3~3.5（用户原话「图标挺大的」；原 10:1.5 扁条废弃）。

**通用设计语言（v3.3 拍板；v3.8 全域铺满）**：**全部卡片与英雄横幅 hover＝自身显著放大、盖住邻元素**——不是「抬高一点/高亮一下」，大版面也不例外（用户原话：「这样能体现咱们整个设计语言都是 hover 放大一点点」）。幅度：small/grid **1.1**（含展开层）、mega **1.12**、duo/分类瓷片 **1.08**、rank **1.03**（origin left，行不横跳）、hero **1.02**（大版面微幅度，图标微放大 1.06）；全部 transform-only（第 0 条守则），衔接动画统一 `var(--ease)`（出 ~200-240ms/收 ~150ms）。

**环境辉光（v3.10 拍板，✅ 验收通过 2026-11-19「可以，满意」）**：放大散出的阴影光**实时跟随封面自身颜色**——偏绿的图散绿光、偏蓝的散蓝光（用户原话：「它这个阴影周围可能是偏绿色一点，那么它散出来那个光就偏绿色一点」）。实现：卡片根元素注入 `--glow`（封面主色）→ `box-shadow` 用 `color-mix` 混合辉光；hero 静态即有微环境光、hover 增强，mega/duo hover 辉光。真机接真封面后辉光色＝封面主色（canvas 取色或目录预存字段喂同一 `--glow` 变量），机制不变；无封面数据时回落中性阴影（`--glow` 缺省 transparent）。**辉光开关＝板块级可选声明（09 §二）**：`sections[].glow:false` → 整块回落中性阴影；缺省＝开；⛔ 自定辉光色（散光跟随封面是设计语言本体）、⛔ 卡级混排。

**硬细节**：① **统一过渡**——hover 内容与本体放大同一时序一次完成（单一 opacity/transform）；⛔ 分级/stagger 展开、⛔ 先放大再展开第二要素（用户原话：「明明是一起出现……我坚决不要这种要素」）；scale 进入 ~200ms ease-out，收起更快——消失比出现快；② 展开层 absolute＋卡片 transform——零文档流位移（第 0 条守则）；`.card` 默认 `overflow:visible`（否则展开层被裁），mega 封面圆角由 `.cm-art` 自带顶角；③ 触屏无 hover——点卡片本体即进详情页，功能无损；④ 键盘可达：卡片可聚焦，`focus-within` 同样展开；⑤ 展开层内按钮渲染同一 `actionBtn` 结果（动作槽正交）；⑥ 状态刷新保持滚动位，页面不跳；⑦ **横排滚动容器留放大余量**（`padding:22px 30px 18px`）——首/末卡 scale＋外扩层不切边（用户实测 bug：hover 展示被旁边切掉一点，真机不许出现）；⑧ **延伸区/辉光不出裁剪容器**——overflow 滚动容器连垂直方向一起裁，曾实测把 hover 延伸区/按钮整块吞掉（hover 后按钮「都没有了」）；大卡行（mega/duo）横滚的辉光/放大/延伸余量**做进容器 padding**（底部 56px＋负外边距 -32px 补节奏，见 §四 横排容器归一化），延伸层照常可见且机械守则不受影响。

## 三、动作槽抽象（⭐拍板：三段式契约）

### 1. 契约

```
动作项 = 声明 descriptor ＋ 可用性状态机 ＋ 执行器 execute
```

- **内置动作项**（市场核心注册五个）：安装、更新、卸载、禁用、启用。
- **槽解析**：条目（目录条目 ⊕ 本地状态）→ 数据层解析器 → 该条目此刻的动作项清单＋各自状态（可用/隐藏/置灰·带原因/进行中·挂 installJobs/失败·可重试）→ 卡片按 kind（主钮/次钮/菜单）渲染。
- **归属纪律**：解析器住 `src/services/`（数据层），**卡片组件只渲染解析结果**——卡片永远蠢、可删可换（02 §五可删除性的直接保障）；进行中/失败状态复用 installJobs 中央订阅（03 §二纪律，禁止视图自订）。
- **现状对照**：现在的动作逻辑焊死在两处视图（侧栏 `CatalogRowAction`＋详情页 `DetailActionBar`/hook 群）——本次重构把它们收敛为动作项注册＋解析器，视图只消费。

### 2. 扩展测试（收费来的那天，验收本契约）

目录条目加 `pricing` 字段＋注册一个「购买」动作项（自己的执行器）→ **卡片组件零改动、现有五动作零改动**，纯增量注册。二维码/收款是购买动作项自己的执行器内部事（支付宝/微信/Apple Pay/Google Pay 等支付方式与 90/10 分成 = 将来专项设计，今天不设计只留位）。

### 3. 付费生态蓝图（今天只留位，全部将来立项）

作者定价 → 购买动作项出二维码 → 用户付款 → **服务器记账**（用户-插件购买关系；重复下载/换机重装免付——用户原话「保存住用户信息，知道他把这个插件下载了，以后随便下载」）→ 下载放行。持续收费/买断+订阅/免费内容收费等模式 = 插件作者自己内部实现，市场只提供购买动作项与记账通道。

### 4. 🔴 硬约束：收费裁决点绝不在市场 UI——三层模型

**为什么**：市场插件本身可被整体替换（万物皆可插件，CLAUDE.md 硬约束 11 同源）。若「是否已付费/能否下载」由市场插件裁决，第三方市场一换，收费插件变免费——作者白干，生态崩（用户 2026-11-19 原话：「把这条路堵死……如果需要改软件方面的东西，最好也改掉」）。

**三层模型（2026-11-19 用户追问后定稿；判别一切新旧声明归属的标尺）**：

| 层 | 住什么 | 住在哪 | 换掉市场后 |
|---|---|---|---|
| **声明层** | 「插件是谁」的事实：category、pricing、授权声明 | 作者 manifest ＋ 目录条目（随包/随目录走） | 照样活着，谁都能读 |
| **解释层** | 展示语义：分类显示名、卡片、动作项、购买 UI | 市场插件（可替换） | 换掉无所谓——新市场按同一声明重新解释（分类即此类：壳只需 schema 放行字段，**不需懂语义**，04 §九·1） |
| **裁决层** | 权益执行：付费插件安装门、授权校验 | **壳层安装门**（与 `minAppVersionGate` 同位置模式，01 §二） | **谁也绕不过——这就是堵路的墙** |

**判别测试题**（将来每加一种新声明先问这一句）：「市场被替换后，这个字段还必须生效吗？」——是（收费、授权、许可）→ 声明进数据层＋裁决进壳（真壳改动，单独立项拍板）；否（分类、标签、展示别名）→ 数据层声明即可，壳只管 schema 放行。

**落点**：裁决住壳层安装门或包层数据（目录条目/包内 pricing＋授权校验）——**任何市场前端都绕不过壳的门**。这是本任务确认的**第二个壳接触点**（第一个 = 03 §一·3 方案 B），将来立项单独拍板，今天只把原则钉死：**实施期任何「市场插件内判断付费」的写法都算违反本条**。

## 四、卡片原型族（拍板：一个组件＋原型族＋hero，不是多个组件；v3.1 定稿，v3.23 增 row 详细行）

| 原型 | 内容 | 适用槽位 |
|---|---|---|
| `small` 小 | 图标 48＋名＋分类＋免费（**236×84·10:3.6**）；hover 原位放大展开；横排＝**两行形态**（2×N 列，✅ 验收） | 装机必备横排 |
| `grid` 网格 | 图标＋名＋作者＋徽标＋下载数（≥260 网格卡）；hover 同款展开 | 分类页网格、搜索结果 |
| `mega` 超大 ✅ 验收（B13） | 大封面 200px＋名＋分类＋免费；hover 本体放大＋**灰条上延** | 主题专区 |
| `duo` 双大卡 | 左文案（tag/名/简介/CTA）＋右大图；**无图态＝纯色渐变＋图标（水印占位已删 B15）** | 编辑精选 |
| `rank` 名次行 | 名次＋图标＋名＋分类＋下载量；hover 原位替换动作 | 热门下载 |
| `row` 详细行 | 图标 48＋名＋来源徽标（官方／第三方·作者）＋分类＋简介 1 行＋下载量＋动作钮；hover 1.02 origin left（行不横跳）——✅ 验收 | 分类页/搜索·「详细」视图 |
| `lib-row` 库行 | 复选框＋图标＋名/版本＋来源/分类＋包大小＋状态徽标（已安装/可更新/已停用/内置）＋主行动作＋`⋯`；hover 1.01 origin left | 我的库·详细视图（管理面） |
| `hero` 英雄 | 轮播横幅（标语＋CTA＋大图）；无图态同 duo（B15） | 首页推荐位 |

> 🔴 **大图区数据驱动（B15）**：封面优先级＝目录条目 `cover` 字段（将来扩展）→ `screenshots[0]` → 无图态（纯色渐变＋图标）。水印式占位物 ⛔ 不进真机。

原型由槽的 `layout` 字段驱动（04 §六呼应）。各分类下卡片怎么排列 = HTML 阶段定（用户 2026-11-19：到时候做 HTML 展示）。

**横排容器归一化（2026-11-19 批注）**：所有横排板块共用同一套 strip 机制——内容超一屏 → 装机必备同款左右圆钮＋原生横滑；不超一屏 → 箭头不显示；小卡横排＝**恒两行·列优先**（行高 `84px×2` 钉死、列宽 236px，窗口缩放只改可见列数、区块高度恒定——⛔ 行数随宽度变化的布局）；大卡行余量做进 padding（硬细节⑧）。R4 由单一容器组件承载，⛔ 各板块自造轮子。

**作者卡不是插件卡原型（2026-11-19）**：首页第一槽的作者卡是**独立组件**（身份 + 仓卡扇出），不并入五原型族；hover 语言同通用守则（1.08＋作者色辉光＋transform/opacity only），但**动效载体不同**——它不是「信息展开」，而是「多仓概念可视化」（一沓仓卡扇开）；⛔ 无 mega 式实体延伸板，全部层长在卡片自身表面。细则见 08 §二。

## 五、空态与边缘（拍板：照 proposed 执行）

沿用现有防御（01 §二：图标裁决序、离线置灰＋「联网后重试」、目录空态三分支），新增判据：超长名截断＋title；cover 缺失回落纯图标卡；卡片整体可点进详情、动作钮阻断冒泡；焦点环可见；动作钮 ≥44px 触达；弹窗预留位不破坏键盘导航。
