## 逐格详案

### R4-0.1 ⬜ plugin.schema 分类字段
**做什么**：`plugin.schema.json` 顶层 `properties` 加 `category?: string`（主分类 slug，封闭集合见 04 §五）与 `categories?: string[]`（副标签）；类型同步。
**判据**：作者在 plugin.json 写 `category:"development"` → SDK validate 绿；写未注册 slug → validate **警告不红**（归位规则在市场侧「其他」桶——04 §三机制4）。
**验收**：schema 在 VS Code 有补全；测试含合法/非法两例。

### R4-0.2 ⬜ marketplace.schema v2 全字段
**做什么**：09 §一/一·补/一·补2/**二（作者块正典）**/三·补3 逐字段落 schema＋TS（collections 以 §五 v2 清单复核；三·补2 是本地安装流程、与 schema 无关）——`authors/<id>.json`（`authorId`·`name`·`avatar`·`intro`·`repos[{id,name,intro,sourceUrl}]`·`homepage.sections[]`（type: hero/grid/collection/rank＋`more{label,target}`＋`hint`＋`glow`＋rank `scope`）·`publicKey`）；`vendors.json`（`{vendorId,name,domains[],githubOrgs[],verifiedBy:"domain"|"github-org"|"manual",verifiedAt}`）；根级 `sources[{url,authorId,addedAt}]`；条目 `pricing:{model:"paid"|"subscription",price?,currency?,period?,licenseUrl?,refundUrl?,trialDays?,channel?}`＋`screenshots:[string|{type:"video",url,poster?}]`。
**判据**：09 每个字段都在 schema 有定义且 TS 同名；⛔ 字段名与 09 漂移。
**验收**：对账测试绿；示例 JSON（03-任务档案级）过 validate。

### R4-0.3 ⬜ 目录仓骨架
**做什么**：`E:\linkdesk-plugins\linkdesk-marketplace\` 加 `authors/geek.json`（演示最小合法文件）·`collections/`（空夹＋.gitkeep 或示例）·`vendors.json`（含 LinkDesk 自身一行 `{"vendorId":"linkdesk",...verifiedBy:"manual"}`）·根 `marketplace.json` 加 `"sources":[]` 占位。
**判据**：旧消费者（现网市场插件 1.2.0）拉该目录**不炸**——新字段被忽略（06 §二·3 双向兼容）。
**验收**：curl/本地 serve 目录 → 旧插件 parse 正常；git 提交目录仓。

### R4-0.4 ⬜ 三方对账测试
**做什么**：既有 `marketplace-schema.test.ts` 扩三条腿：① schema allow-list ↔ TS optional keys 逐一相等；② 白名单（parse 认的键）↔ schema 逐一相等；③ `buildCatalogEntry` 真实产出过 schema。
**判据**：测试文件里出现**机械比对**（Object.keys 集合 diff），⛔ 手工例举。
**验收**：故意删 schema 一个字段 → 测试红。

### R4-0.5 ⬜ 兼容矩阵
**做什么**：按 06 §七写双向用例：旧市场读新目录（静默忽略新键）；新市场读旧目录（缺省规则：无 collections/rail ⇒ 槽位不渲染；无 category ⇒ 「其他」桶）。
**判据**：两组用例绿。
**验收**：CI（`npm run check`）纳入该测试文件。
