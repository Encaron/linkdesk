# 01 · 方案与落点契约

> 三件套：**词表正典**（判据 B）· **控件搬移与 ReadOnlyText 升级**（判据 A）· **徽标语义收编**（判据 C）。判据定义见 [00 §二](00-README.md)。

## 〇、词表正典（判据 B 的落地物）

### 0.1 真相源（2026-10-03 阶段 1.1 对账**改正**——原稿落点不可执行）

🔴 **事实**（本次对账查证）：`@linkdesk/contracts` 是**生成产物、纯类型、零运行时**——`package.json` 的
`files: ["linkdesk.d.ts"]`、`types` 直指生成契约、**无 `main`**；`README.md` 明写「types only … has zero
runtime」；内容由 `scripts/generate-contract.mjs` 从 `src/core/api/linkdesk-api.ts` 的**全部类型导出**逐字节生成。
⇒ 原稿「contracts 出 `export const CONFIG_NONE_SENTINEL` / `SETTINGS_UI_HINT_META`」**写不出来**（`.d.ts` 里没有值）。
本案按**同一判据**改落点，⛔ 不把 contracts 改成运行时包（那是作者面承诺的破坏，不在本夹授权内）。

| 正典的哪一半 | 落点 | 形态 |
|:--|:--|:--|
| **类型**（词表联合类型） | **`@linkdesk/contracts`**（正是它的用途） | 定义在生成器的收集源 `src/core/api/linkdesk-api/types.ts`，随 `node scripts/generate-contract.mjs` 进 `linkdesk.d.ts` → bump → 发 npm |
| **运行时值**（哨兵＋名单＋类型守卫） | **`@linkdesk/ui`**（判据 A 点名的层——「任何声明者与渲染者都取得到」） | 新件 `src/components/shared/settings-hints/settingsHints.ts` → barrel → `@linkdesk/ui` |
| **壳 core 的哨兵** | `ThemeEngine/constants.ts` **re-export 共享件**（旧 import 路径 `ThemeEngine/constants` 不破） | 哨兵从「核心私有常量」变「共享层正典 ＋ core 转出」——与判据 A 一致 |

```ts

export type SettingsRenderHint = "readonly" | "action" | "color";   // 🔴 "color" 是 1.1 对账补的第 3 值（见 0.4）

// ② @linkdesk/ui（运行时值，src/components/shared/settings-hints/settingsHints.ts）
export const CONFIG_NONE_SENTINEL = "__none__";
export const MIX_FOLLOW_THEME_SENTINEL = "followTheme"; // 顺带收编（设置仓 deriveSourceBadge.ts:24 现为本地字面量）

export const SETTINGS_RENDER_HINTS: readonly SettingsRenderHint[];
export function isSettingsUiHint(v: unknown): v is SettingsUiHint;
```

字面量收敛五处：`ThemeEngine/constants.ts`（re-export）、`FontFamilySelect.tsx:145`、设置仓 `imagePicker.tsx:15`、
`deriveSourceBadge.ts:24`（`followTheme`）、`ThemeEngine` 内 `MIX_FOLLOW_THEME_SENTINEL` 同字面量处。

⛔ **`SETTINGS_UI_HINT_META` 不落**（原稿唯一被删的条目，理由记档）：正典表每行的 `label`/`control` 是**文档**，
而 13 行的 `fallback` **完全一致**（全体＝只读展示）⇒ 机器可读的 META 不携带任何分支信息，却要把中文 label
硬编码进 `@linkdesk/ui`——正面撞硬约束 2（UI 文字走 `t()`）。机器可读面收敛为「**名单 ＋ 类型守卫**」，
正典表本体（语义/控件/降级）写进**作者面 schema description**（D6 的要求）与本档 §0.2。

### 0.3 宿主侧与作者面

- 宿主：`ConfigProperty.uiHint?: SettingsUiHint` / `renderHint?: SettingsRenderHint`（[ConfigurationRegistry.ts](../../../../src/core/registry/ConfigurationRegistry.ts):50,55 从裸 `string` 收窄）——**编译期抓 appearance.ts 写错**，现有值对表＝正典第一次实战（[02 E14](02-边缘情况清单.md)，对账结果见 §0.4，**零改动通过**）。
- 作者面：`plugin.schema.json` 的 `uiHint`/`renderHint` **保持开放字符串**（第三方自定义 hint 合法，:374-375 现有承诺不收回），但 description 改写为「已知 hint 清单见正典；未实现 hint 的行为＝只读降级（不再是可编辑兜底）」；**三处字节拷贝同笔**（`check-plugin-schema-sync` 跟跑）。
- ⚠️ **契约里的 `LinkDeskConfigProperty.uiHint` 也保持开放 `string`**（那是第三方 TS 消费面，收窄＝给自定义 hint 的作者判红）——正典以**并列导出的 `SettingsUiHint` 类型 ＋ JSDoc 指路**呈现，⛔ 不动 `LinkDeskConfigProperty` 的字段类型。
- 门禁：新增轻门禁，判据＝「改正典 hint 名单而不动作者面 description 时 `npm run check` 要红」；形态（grep 对账/清单比对）交实施 AI 定。

## 一、ReadOnlyText 升级（判据 A · **原地升级**，唯一不动件的案子）

### 1.1 新 props 正表（全可选，只增）

| prop | 类型 | 语义 |
|:--|:--|:--|
| `statusCommand?` | `string` | 轮询的命令 id；存在即进入轮询模式（`value` prop 被轮询值取代——同给时**轮询优先**，文档写明） |
| `runCommand?` | `(commandId: string) => Promise<string \| null>` | **执行句柄由使用方注入**——共享件不引宿主内核（`FontFamilySelect.tsx:139`「不得引 @src/core」同款纪律） |
| `intervalMs?` | `number` | 轮询间隔，缺省 3000；仅 `statusCommand` 存在时生效 |
| `value?` / `multiline?` | 既有 | 不动；轮询值含 `\n` 自动 multiline（照抄 ReadOnlyStatus 现行为） |

### 1.2 行为（＝今天 ReadOnlyStatus 的行为原样上移）

挂载即取一次 → `setInterval` 轮询 → 卸载清理；`alive` 守卫（StrictMode 安全）；命令抛错/返回空**静默保持现值**；空值不占位（`:19-22` 现行为）。

### 1.3 护栏（同笔落，规模答案）

1. **可见才轮询**：`document.visibilitychange` 隐藏即暂停、回可见**立即刷一次**再续节奏（行为差异 benign，验收明示——[02 E6](02-边缘情况清单.md)）。
2. **同命令去重**：模块级 poller registry 按 `commandId` 共享定时器＋引用计数，最后一个实例卸载才真停（[02 E5](02-边缘情况清单.md)）。
3. **作者契约句**：作者面 schema 的 `statusCommand` description 补「必须便宜、幂等、无副作用」。

### 1.4 落点与测试

- `src/components/shared/readonly-text/ReadOnlyText.tsx` ＋ 新 `useStatusPolling`（可独立导出复用）；`ReadOnlyStatus` 退场后设置仓 readonly 分支（`renderControl.tsx:48-50`）直接渲染共享件。
- 测试：`@linkdesk/ui` vitest（fake timers：节奏/去重/隐藏暂停/卸载清理）；设置仓 ai 五行（`aiBridge.ts` 5 个 statusCommand）回归＝**节奏与读数逐格一致**。

## 三、徽标语义收编（判据 C）

- **宿主**：配置读出面（设置仓 `loadSettingsData` 消费的那条 IPC/服务，具体落点实施时按现 API 面定）每键多给**解好的语义** `{ source, effective?: { value } }`——`deriveSourceBadge`/`resolveEffectiveBadge` 的判定逻辑**原样平移进宿主**（⛔ 先平移后简化，不顺手改语义）。
- **共享 `@linkdesk/ui`**：`formatEffectiveValue`（字体栈截首族/色值配 swatch/未知形状原样）＋ `EffectiveBadge`（props `{ label, value, color? }` **纯呈现**——较设置行案 06 §五·补 收窄：去掉 mode prop，显隐由编排层按宿主 `source` 决定，更符合三层分工。⚠ 与 `ReadOnlyText` 是**组装关系非变种**：badge 内部的值文字段复用 ReadOnlyText 原子画〔继承省略号/tabular-nums〕，badge 自己只管「生效：」前缀＋色块＋跟随主题态显隐——语义/结构/数据来源三样都不同，见 06 §六·补④）＋ `SourceBadge`（theme/user/mix；✅ D10 已拍板：分开两件，共享格式化原子）。
- **设置仓**：`SettingRow` 徽标段换两枚共享件；`deriveSourceBadge.ts`/`effectiveBadge.ts` 退场；「生效：」label 仍由插件传（文案自由）。
- **双轨期**（[02 E1](02-边缘情况清单.md)）：插件发版早于壳 ⇒ 宿主解好面不存在 ⇒ 插件保留本地计算 fallback（共享 formatter 照用）；壳攒批发版后切真路径、删 fallback（一次小改）。

## 四、降级契约（判据 B）

- ⛔ **无 `uiHint` ≠ 未知 `uiHint`**：无 uiHint 按 `type` 渲染是**大多数键的正常路径**，一字不动；降级契约只约束「**声明了** hint 但渲染器不认识」。
- 新契约：未知 hint ⇒ **只读展示当前值＋title 说明**（不再落进可编辑文本框——防裸字符串写穿值域，`app.backgroundImage` 露 `__none__` 那类）。
- 作者面 schema `uiHint` description 同笔改写（三处字节拷贝）。
- 演示判据：临时假键声明 `uiHint:"__no_such__"` ⇒ 只读＋说明、不可编辑。

## 五、逃生舱（D9）

- 命令 **`core.resetSettingsToBuiltin`**（⚠️ 2026-10-03 落码时改判：原稿写的 `settings.resetActiveToBuiltin` **不能落地**——`settings.` 是**设置插件自己的**命名空间（官方仓 `settings.editKeybinding` 就住那儿），宿主伸手占它会让 `@linkdesk/plugin-sdk` 的 `check-command-ownership` 判据②按账 `commandPrefixes` 把**官方设置仓判红**；语义不变，只把名字收进宿主自己的族，与 `core.openSettings` 同族）：把 settings 槽激活套回退到注册序首声明（内置即首声明）——[settingsCommands.ts](../../../../src/core/commands/shell/settingsCommands.ts) 注册。
- 齿轮菜单在「激活套非内置」时显示「回退内置设置页」兜底项；命令面板可达。
- 判据：dev 手放一个故意崩的第三方 settings 夹具 ⇒ 齿轮不再空转、逃生舱可用（今天 `core.openSettings` 打到坏套＝`settingsCommands.ts:208-209` 直接 return）。

## 六、发版链（顺序固定，环环相扣）

1. **contracts** bump（哨兵＋词表新导出）→ 发 npm（授权内）。
2. **`@linkdesk/ui`**：`npm run ui:build` → `check-api-surface-additive` 全绿 → bump → 发 npm（授权内）。⚠️ 消费方以 registry 为准，**先于**步骤 3/4。
3. **设置仓**：删本地件/接共享件/fallback 双轨 → 仓内 vitest 全绿 → bump `1.0.26 → 1.0.27` → release 市场（授权内）。
4. **壳侧落仓**（类型收窄/宿主解析面/逃生舱/哨兵改 import）→ `npm run check` 全绿 → **⛔ 攒批定号待发（不在授权内）**；壳发版后设置仓删 fallback（一次小改，随下一次插件发版走）。

## 七、验收判据

1. **词表对账**：正典 13 hint 在设置页逐条目视＝各自形态（含 `themePicker`/`select` 等不动项零回归）。
2. **ReadOnlyText**：ai 五行节奏与读数逐格一致；同 command 两行只走一个定时器（计数器证）；页签隐藏停、回可见立即刷。
3. **徽标四态**：默认/覆盖/混搭/跟随 逐格一致（判定逻辑平移不变，[02 E10](02-边缘情况清单.md)）。
4. **未知 hint 降级**：假键只读＋说明、不可编辑。
5. **换套冒烟**：临时第二台 settings 夹具（只渲染键名＋值）⇒ 主题组不崩、专属控件行以只读/共享件呈现。
6. `npm run check` 全绿（含 `check-api-surface-additive`、`check-plugin-schema-sync`）。
7. **用户目视**：截图交你点头。
