# E2b — 终端归一化

> 2026-07-24。从旧 P6b 迁移，适配 Electron。
> **目标：** 终端从 "验证产物" 变成 "正确参考实现"。E3 文件树、主题浏览器、语言选择器全以终端为模板来写——模板本身必须干净。
> **性质：** 纯 TS 改动，框架无关。Rust 后端已消失——6b 的术语迁移目标天然加速。

---

## 一、为什么终端需要拆干净

### 1.1 终端的历史角色

| Phase | 终端干什么 | 代码质量 |
|------|------|:--:|
| Phase 1-2 | 证明 React + CM6 + Rust 串口全链路能跑 | "先跑起来" |
| Phase 3 | 验证标签页 + 分屏 + keep-alive | 稳定性优先 |
| Phase 4 | 验证插件系统 + 视图注册 + 生命周期 | 加 plugin.json |
| Phase 5 | 验证 ConfigurationService + 命令系统 | 迁移到新配置 |

Phase 1-4 的代码是 "证明这条路能走"——不是 "这条路该怎么走"。

### 1.2 具体问题清单

| # | 问题 | 位置 | 为什么是问题 |
|:--:|------|------|------|
| 1 | `SerialContext` 在 `src/core/` | `SerialContext.tsx` | 核心不知道串口是什么——SerialContext 是终端插件的实现细节 |
| 2 | `portOpen` / `portName` 术语 | 遍布 Rust+TS | 核心只知道 "数据源"——端口是串口的实现 |
| 3 | 裸 `listen()` | `index.tsx` | B11 教训——事件监听要用 generation counter 模式 |
| 4 | `let _receiveMode` 模块变量 | `index.tsx` | 多标签页时互相覆盖 |
| 5 | `let _activeSessionId` 模块变量 | `index.tsx` | 同上 |
| 6 | 命令路由到 "最后 mount 的 TerminalView" | `index.tsx` | Ctrl+Shift+P 命令作用到错误的标签页 |

**对标 VS Code：** VS Code 源码 `src/vs/workbench/contrib/terminal/`——终端代码全在 `contrib/`，不在 `platform/`。LinkDesk 对应：终端代码全在 `plugins/terminal/`，不在 `src/core/`。

## 二、任务清单

### 任务 7：SerialContext 迁出 core/（~30 行）

**当前：** `src/core/SerialContext.tsx`（~150 行）
**目标：** `plugins/terminal/SerialContext.tsx`

**影响范围：**
```
SerialContext.tsx 当前被谁 import：
  plugins/terminal/index.tsx       → 改为相对路径 import
  plugins/terminal/ControlPanel.tsx → 同上
  plugins/terminal/sidebar.tsx     → 同上
  App.tsx（状态栏 TX/RX 计数）      → App.tsx 不应 import SerialContext！
                                     → 状态栏 TX/RX 通过 CoreEvents 获取
```

**App.tsx 的解耦：**
```
改前：
  App.tsx import { useSerialContext } from "@src/core/SerialContext"
  → 状态栏直接读 serialContext.txCount / rxCount

改后：
  SerialContext 内部 emit CoreEvents.onDidChangeSourceState
  → App.tsx 订阅 CoreEvents → 状态栏显示
  → 核心不知道 "串口"——只知道 "有数据源状态变化了"
```

**执行步骤：**
1. `cp src/core/SerialContext.tsx plugins/terminal/SerialContext.tsx`
2. SerialContext 加 `emit(CoreEvents.onDidChangeSourceState, { ... })`
3. App.tsx 状态栏改为订阅 CoreEvents
4. 更新终端插件内 3 个 import
5. 删 `src/core/SerialContext.tsx`
6. `npx tsc --noEmit` → 零错误

### 任务 8：术语迁移——portOpen → sourceOpen（~30 行）

**Rust 后端已消失，此项大幅简化。** 原 P6b 要改 Rust+TS 双端，现在只改 TS。

| 旧名 | 新名 |
|------|------|
| TS 类型 `PortState` | `SourceState` |
| TS 变量 `portName` | `sourceName` |
| IPC channel `serial:portState` | `serial:sourceState` |
| 事件名 `port-state-changed` | `source-state-changed` |
| `window.linkdesk.serial.*` 中的 `portName` 参数 | `sourceName` |

**不改什么：** Node.js `serialport` npm 包内部的 `port_name` 字段——第三方库 API。

### 任务 9：useIpcEvent 归一化（~20 行）

**问题：** 终端插件里可能有裸 `ipcRenderer.on()`。

**B11 教训：** 裸 `listen()` → 组件 unmount 但 cancel fn 没调用 → 旧 listener 残留 → 再次 mount → 双份回调。

**执行：**
```bash
grep -rn "ipcRenderer.on\|listen(" plugins/terminal/
```
逐条判断 → 改用 `useIpcEvent`（generation counter 模式）。不在组件内的 listener → 提取到最近的组件 useEffect。

### 任务 10：模块级可变状态消灭（~10 行）

**问题：**
```typescript
// ❌ 多个 TerminalView 实例共享
let _receiveMode: "text" | "hex" = "text";
let _activeSessionId: string = "";
```

**改法：**
```typescript
// ✅ 从 session 读——每个标签页独立
function TerminalView({ isActive, sourceId }: TerminalViewProps) {
  const session = useSession(sourceId);
}
```

**执行：**
```bash
grep -rn "^let _" plugins/terminal/ --include="*.tsx" --include="*.ts"
```
每一个 `let` → 判断常量（改 `const`）还是可变状态（迁入 hook/session）。允许 `const`，不允许 `let`。

### 任务 11：命令路由修复（~20 行）

**问题：** Ctrl+Shift+P → 复制/清空/切换模式 → 作用于 "最后一个 mount 的 TerminalView"。

**改法：**
```typescript
// 改前：
const cmViewMap = new Map<string, EditorView>();  // key 不区分实例

// 改后：
const cmViewMap = new Map<string, EditorView>();  // key = sourceId（保证唯一）
const activeSession = getActiveSession();
const cmView = cmViewMap.get(activeSession.id);

// 加 WeakMap + dispose 清理：
useEffect(() => {
  return () => { cmViewMap.delete(sourceId); };
}, [sourceId]);
```

### 任务 12：硬编码审计（~10 行）

**执行清单：**
```bash
# 1. 插件 ID 字面量
grep -rn '"terminal"' plugins/terminal/ --include="*.tsx" --include="*.ts"

# 2. 波特率硬编码
grep -rn '115200\|9600\|baudRate' plugins/terminal/ --include="*.tsx" --include="*.ts"

# 3. COM 口假设
grep -rn 'COM[0-9]\|port_name' plugins/terminal/ --include="*.tsx" --include="*.ts"

# 4. "串口" 假设
grep -rn '串口\|serial' plugins/terminal/ --include="*.tsx" --include="*.ts"
```

**判断标准：**
- UI 显示文字 → 走 `t()` 翻译
- 注释 → 改通用描述（"数据源"代替"串口"）
- plugin.json 声明 → 合理（终端插件自身描述）
- 变量名 → 改通用名（`dataSourceName` 代替 `portName`）

```
1. tsc 零错误，vitest 全过
```
