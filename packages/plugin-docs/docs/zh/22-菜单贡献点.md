# 22 — 菜单贡献点（把你的动作放进宿主的某个菜单）

> 🌐 **English version（作者面主显）→ [../03-plugin-authoring/22-menu-contribution-points.md](https://github.com/Encaron/linkdesk/blob/electron/docs/03-plugin-authoring/22-menu-contribution-points.md)**
>
> 2026-10-05 · **一句话**：**你在 `plugin.json` 里声明「哪个槽位、什么条件、跑哪条命令」，菜单项就出现在那里**——
> 壳不因你改一行代码，你也不用 `import` 壳的任何模块（**字符串即契约**）。
> 本文是**规范 ＋ 作者自查清单**；条目字段的 schema 定义在 [06-plugin.json规范](06-plugin.json规范.md)，
> 动作做成命令的纪律在 [21-插件命令化规范](21-插件命令化规范.md)，命令 id 的命名归属在 [16-命名规范](16-命名规范.md) §七。

---

## 一、最小可用（三件事同时成立才看得见）

```json
{
  "contributes": {
    "commands": [
      { "id": "my-plugin.exportMd", "title": "导出为 HTML" }
    ],
    "menus": {
      "fileContext": [
        { "command": "my-plugin.exportMd", "when": "resourceExtname == '.md'", "group": "1_navigation" }
      ]
    }
  }
}
```

| # | 条件 | 不满足时会怎样 |
|:--:|:--|:--|
| ① | `contributes.commands` 里**声明过**这条命令 | 菜单项渲染出来，但点下去什么也不发生（渲染用的是命令的 `title`，跑的是命令的 handler） |
| ② | 槽位 id 写的是**值**（`fileContext`），不是成员名（`FileContext`） | **静默消失**：那个键在壳注册表里查不到，不报任何错。门禁 `check-menu-slot-case` 专拦这一种（只差大小写） |
| ③ | `when` 求值为真 | 项隐藏（`when` 解析失败也按「不显示」处理——安全侧） |

改完 `plugin.json` 要**让插件重新激活**（重启应用 / 禁用再启用）才会生效——贡献点是激活时读的。

## 二、槽位（MenuId）：14 个宿主注册点

槽位 id 就是 `contributes.menus` 的**键**，值是宿主 `MENU_SLOTS` 常量的**值**（小驼峰）。

| 槽位值 | 出现在哪 | 常用 when 键 | 备注 |
|:--|:--|:--|:--|
| `commandPalette` | Ctrl+Shift+P 命令面板 | — | ⚠️ **当前无宿主渲染方**：面板条目来自 `contributes.commands`（按命令自己的 `when` 过滤）⇒ 投进本槽的条目看不见；当作**预留槽位** |
| `tabContext` | 标签栏里某个标签的右键 | — | 宿主自己往这里投「关闭/关闭其他/固定…」，插件项与之合并 |
| `panelViewContext` | 底部面板的标签栏右键 | — | 位置/对齐子菜单 ＋ 视图显隐清单由壳动态注入 |
| `editorContext` | 标签页**内容区**右键（终端接收区、编辑器…） | — | 面向「当前打开的东西」，不是面向文件 |
| `extensionGear` | 底部齿轮菜单（全局操作入口） | — | 常驻入口，慎用（用户每次都看得到） |
| `marketplaceItemGear` | 插件市场里**每个条目**的齿轮 | — | per-plugin 操作（启用/禁用/卸载是壳自己的项） |
| `menuBar` | ☰ 汉堡菜单栏 | — | `group: "panel"` 的条目会归并进汉堡里的「面板」分组（见 §四） |
| `panel` | 汉堡里的「面板」分组（专用槽） | — | 与上一行 `menuBar` ＋ `group:"panel"` 等效，二选一 |
| `fileContext` | 文件树节点右键 | `resourceExtname` · `resourceIsFile` | 按扩展名显隐的主战场，见 §五 |
| `cardContext` | 卡片右键 | — | — |
| `quickSendContext` | 快捷发送药丸右键 | — | — |
| `iconBar` | 图标栏右键 | — | — |
| `settingItemGear` | 设置页**每一行**的 hover 齿轮 | `settingKey` · `settingFollowTheme` · `settingModified` · `settingResetsToDefault` · `settingHasTitle` | 这五个是设置行的公开约定键，见 §五 |
| `viewTitleContext` | 侧栏/右栏**视图标题**右键 | — | 折叠/展开/隐藏/重置位置由壳投 |

**「常用 when 键」列的 `—` 不是「没有键可用」**，而是「没有**公共约定**的键」——
你在这些槽位里只能用宿主专用旗子（`activeEditor` 等，⛔ 插件禁设、只读）或你自己的 `<pluginId>.*` 旗子。

> 上表的「出现在哪」列取自壳的 `MENU_SLOTS` 常量表（宿主**意图**）——真机读数与它对不上时，以运行结果为准并反馈给我们。

> 🔴 **`MenuId` 是开放字符串**：你可以自造一个槽位 id（比如 `my-plugin.palette`），壳不会报错——
> 但**没有渲染方会读它**，除非你自己的插件去读（`menu.getItems("my-plugin.palette")`）。
> 往宿主槽位投条目才会出现在宿主菜单里；自造槽位是插件内部机制。

## 三、条目字段

| 字段 | 必填 | 说明 |
|:--|:--:|:--|
| `command` | ✅ | 要跑的命令 id。**有 `children` 的父项可以为空**（父项只展开子菜单，不跑命令，此时用 `label` 当显示文本） |
| `label` | — | 覆盖命令的 `title`（显示文本）。**父项（无 `command`）必填** |
| `group` | — | 分组名（见 §四）。缺省 = 兜底组 |
| `when` | — | 显隐条件（见 §五）。缺省 = 恒显示 |
| `order` | — | 同组内排序权重，**越小越靠前**，缺省 `100` |
| `children` | — | 子菜单，可任意深度。**父项 hover 展开**（`children: []` 空数组 + 池侧 `resolveChildren` 可以做动态子菜单，属于高级用法） |

```jsonc
// 简写：数组元素直接写字符串 = { "command": "…" }
"menus": { "fileContext": ["my-plugin.exportMd"] }
```

### 子菜单示例

```jsonc
{
  "menus": {
    "fileContext": [
      {
        "command": "",                      // 父项不跑命令
        "label": "我的工具",
        "group": "3_creation",
        "when": "resourceExtname == '.md'",
        "children": [
          { "command": "my-plugin.exportMd" },
          { "command": "my-plugin.wordCount" }
        ]
      }
    ]
  }
}
```

### 载荷：`commandArgs` vs `context`

`MenuItemDescriptor` 还差两个字段没说——它们在你**消费共享件弹出的菜单**时立刻要紧：

| 字段 | 说明 |
|:--|:--|
| `commandArgs` | **本项自己的入参**。每一项的身份只有这一个落点 |
| `context` | **整菜单共享**。菜单由共享件弹出时，由那个共享件供给（轮不到你设） |

> **菜单载荷律**：`ContextMenu` 的 `context` 是**整菜单共享**的；每一项的身份必须走 `MenuItemDescriptor.commandArgs`。
> 壳 handler 收到 `args = [...commandArgs, context]`。共享件（如 `PluginCard`）会固定送**它自己的** `context`
> （`PluginCard` = `{pluginId}`）⇒ 消费共享件齿轮的插件，handler 必须同时容忍 `args[0]` 是自己的载荷、
> **末尾**是共享件的 context——⛔ 不要假设 `args[0]` 一定是你的数据（除非该槽位无共享 context）。

```ts
// 消费 PluginCard 的齿轮菜单：args = [{ pluginId }, context]
// 自己的载荷（来自 commandArgs）在前，共享件的 context 在末。
linkdesk.commands.registerCommand("my-plugin.onCardGear", (args) => {
  const mine = args?.[0] as { pluginId?: string } | undefined;
  if (!mine?.pluginId) return;              // 没有目标 ⇒ 什么都不做（⛔ 不「清了个空的」）
  /* … */
});
```

## 四、`group` 与排序（决定菜单长什么样）

菜单渲染分两步，**都是壳做的**，你只提供 `group` 与 `order`：

1. **排序**：取该槽位全部条目（含壳自己的、别的插件的），按 `order` 升序（缺省 `100`）。
2. **分组**：按 `group` 归并，**组之间画一条分隔线**；组的先后 = **该组内最靠前的条目在排序结果里的位置**（即「首现顺序」，**不是**字母序）。

⇒ 想让「我的组」排在「导航组」后面，就给你的组一个**更大的 `order`**；组名本身不参与排序。

**命名约定（上下文菜单：`fileContext` / `tabContext` / `editorContext` / `cardContext`）**——用
`<序号>_<语义>` 的桶名，序号决定先后，语义给人看：

| 约定桶名 | 放什么 |
|:--|:--|
| `1_navigation` | 打开、在新标签打开、在系统中显示、在终端打开、打开方式… |
| `2_editing` | 剪切、复制、复制路径、粘贴… |
| `3_creation` | 新建文件、新建文件夹、新建终端… |
| `4_modify` | 重命名、移动… |
| `5_search` | 在此文件夹中查找… |
| `6_workspace` | 与工作区/根相关的操作（关闭文件夹…） |

**两个特殊组名**：

- `delete` —— 危险样式（红色）。**删除类操作建议单独成组**（默认 `ContextMenu` 只按这一个组名判危险色）。
- 缺省组 —— 没写 `group` 时归入，与显式组之间照样画分隔线。

> ⚠️ 组名是**自由字符串**：写中文（设置页的若干插件就这么写）也能跑，但上面这张表是**跨插件协调的约定**——
> 你的组要和别人的组拼在同一个菜单里，命名不一致就会多出几条没意义的分隔线。

### `menuBar` / `panel` 的归并

往 `menuBar` 或 `panel` 槽位投条目、并把 `group` 写成 `"panel"`，会**归并进汉堡菜单的「面板」分组**
（壳在那里放「打开/折叠面板」的招牌；插件条目跟在后面）。这是这两个槽位唯一的特殊约定。

## 五、`when`：条件显隐

`when` 是一个小型表达式，**判定的是宿主里的 context key**（键值由壳或别的插件在运行时写）。

| 语法 | 例 | 说明 |
|:--|:--|:--|
| 裸键 | `file-tree.itemIsFile` | 值为**真值**即成立（未定义 = 不成立） |
| `==` / `!=` | `resourceExtname == '.md'` | 字符串比较，空/未定义按空串比（见下面的坑） |
| `=~` | `resourceExtname =~ '\\.md$'` | 正则匹配（**区分大小写**，按 JS `RegExp` 原样执行） |
| `in` | `activeEditor in ['terminal', 'editor']` | 集合成员 |
| `&&` / `||` / `!` / `( )` | `resourceIsFile && !file-tree.inputFocus` | 布尔组合（`!` 优先级最高，`&&` 高于 `\|\|`） |
| `true` / `false` | `when: "false"` | 常量（`false` = 恒隐藏，留占位用） |

### 🔴 三个必须知道的坑

**坑 1 —— 字面量要加引号（单引号）。**
解析器只认 `'…'`（和数字）当字面量。写成 `resourceExtname == .md`（不加引号）**解析失败** ⇒
`when` 按「不显示」处理，菜单项**静默消失**，只在控制台留一行 `when 表达式解析失败`。

```jsonc
"when": "resourceExtname == .md"     // ❌ 解析失败 → 项永不出现
"when": "resourceExtname == '.md'"   // ✅
"when": "resourceExtname =~ '\\.md$'" // ✅ 正则也要引号（JSON 里反斜杠要转义成 `\\`）
```

**坑 2 —— `== ''` 会把「未定义」也判成真。**
`==` 内部是 `String(值 ?? "")`，所以**没写过这个键**和**值就是空串**无法区分。
想看「有文件上下文」，不要写 `resourceExtname != ''`（未定义时它也是 false），用布尔键：

```jsonc
"when": "resourceExtname == '.md'"   // ✅ 未定义 → "" ≠ ".md" → 不显示
"when": "resourceIsFile"             // ✅ 未定义 → 不成立
"when": "resourceExtname != ''"      // ❌ 未定义时 != 不成立，看着对但语义含糊
```

**坑 3 —— `when` 里的标识符 = **你递进去那个对象上的属性名**（**插件自有槽位**尤其要盯）。**
宿主读 `when` 是**裸属性查表**（`key in overrides ? overrides[key] : 全局值`）：表达式里的标识符**原样当属性名**用。
所以当你在**自己的槽位**上用共享 `ContextMenu` 渲染、并把「本行数据」通过它的 `context` prop 递下去时，
`when` 里写的名字必须与那个对象的字段名**逐字相同（含大小写）**；写错、或改名只改了一边 ⇒ **恒为假、项静默消失**——
不报错、不警告，**连坑 1 那行控制台都没有**。

```jsonc
// 菜单声明：读「本行有绑定」这个行局部旗子
{ "command": "my-plugin.copyKey", "when": "rowHasKey" }
```
```tsx
// 渲染时递下去的对象——字段名必须与 "rowHasKey" 逐字对上
<ContextMenu context={{ command, key, rowHasKey: key !== "" }} … />
```

> 🔴 2026-10-05 实况：官方 `settings` 1.0.32 的快捷键行齿轮菜单，三条门控项（复制快捷键／复制为 JSON／重置为默认）
> **一条都没出现**——声明写 `keybindingHasKey`／`keybindingIsUser`，而字段叫 `hasKey`、`isUser` 压根不存在。
> 九段门禁 ＋ 全部单测皆绿，因为**没有一条求值 `when`**。修法两条一起上：字段名用**计算属性名**从同一个常量取
> （改名即 TypeScript 编译错）＋ 一条**契约回归测试**（拿 `plugin.json` 的菜单声明与运行时行对象对账）。可作同类项的范式。

### 能用哪些键

| 键 | 取值 | 谁写 | 说明 |
|:--|:--|:--|:--|
| `resourceExtname` | **带点小写**扩展名（`.md` / `.txt`）；**无扩展名或点开头文件 = 未定义** | 官方 `file-tree` | 文件树右键时按目标节点注入；根节点/空白处右键也**未定义** |
| `resourceIsFile` | 布尔；根节点/空白处右键 = 未定义 | 官方 `file-tree` | 右键目标是文件还是文件夹 |
| `settingKey` · `settingFollowTheme` · `settingModified` · `settingResetsToDefault` · `settingHasTitle` | 字符串/布尔 | 官方 `settings` | 设置行齿轮槽位（`settingItemGear`）的公开约定面 |
| `activeEditor` · `editorCount` · `editorHasSelection` · `inputFocus` · `sidebarPosition` · … | 见账 | **宿主** | **只读**，插件禁设（完整清单见 [16-命名规范](16-命名规范.md) §七 与 SDK 包内 `schemas/host-reserved.json`） |
| `<你的 pluginId>.*` | 你自己定 | **你自己** | 你的私有旗子。⛔ 不能不带前缀（SDK 的 `check-context-ownership` 判红） |

**你自己写的旗子**（供宿主/别的插件的 `when` 读，或供你自己的菜单用）：

```ts
await window.linkdesk.contextKey.set("my-plugin.previewOpen", true);
// when: "my-plugin.previewOpen"
```

> ⚠️ context key 是**全局名册的键**：不带前缀就写别人的名字 = 静默顶掉别人的状态（`when` 时隐时现，两边都不报错）。
> 前缀规则与后果见 [16-命名规范](16-命名规范.md) §七，门禁跑在你自己的 `npm run verify` 里。

## 六、命令归属纪律

菜单项**只引用命令 id**，所以第 1 条永远是：

1. **命令 id 必须带你自己的前缀**（`my-plugin.`）——理由与门禁见 [16-命名规范](16-命名规范.md) §七
   ＋ [21-插件命令化规范](21-插件命令化规范.md)（界面上能做的每件事都该有一条命令）。
2. **⛔ 不引用别的插件的命令。** 别人的命令是别人的实现细节：他改名、他卸载、他禁用，你的菜单项就**静默失效**
   （或者更坏——点下去报错）。要跨插件协作，走**声明式契约**（对方声明命令为公开面，或走 [07-插件间通信](07-插件间通信.md)）。
   唯一例外是**宿主公开命令**（`theme.*` / `view.*` / `app.*` 等文档明示可调的那些）。
3. **可见文案要能翻译。** 菜单项显示的是命令的 `title`（或条目自己的 `label`）——这些串要进本仓
   `i18n/en.json`（key = 中文原文），规则见 [09-插件目录规范](09-插件目录规范.md)；`npm run verify` 第 ⑧ 段会数。

## 七、自查（看不到菜单项时按这个顺序查）

| 现象 | 最可能的原因 | 怎么确认 |
|:--|:--|:--|
| 整个槽位一条我的项都没有 | 槽位键写成了成员名（`FileContext`） | 门禁 `check-menu-slot-case`（`npm run lint` / `verify` 里）；或搜你的 `plugin.json` 看键是不是小驼峰 |
| 有时出现有时不出现 | `when` 为假 | 复制 `when` 到命令面板的调试入口 / 看控制台有没有「when 表达式解析失败」 |
| 我的项**恒不出现**（不是时隐时现），控制台也没有报错 | `when` 里的标识符与**你递进菜单的那个对象**的字段名对不上（拼写／大小写）——宿主是裸属性查表，查不到即为假 | 字段名用**计算属性名**从同一常量取；或写一条「声明 ↔ 运行时对象」的契约测试（见 §五 坑 3） |
| 出现了但点了没反应 | 命令没注册（只声明了 `contributes.commands`，池侧没 `registerCommand`） | 见 [21-插件命令化规范](21-插件命令化规范.md) §二「两条腿」 |
| 我的项排在最后/最前，压不过别人 | `order` 缺省 `100`，别人的组更小 | 调 `order` 或换组名（组序 = 首现顺序） |
| 报「不带本仓归属」 | 命令 id / 配置键 / 外观 id / context key 少了 `<pluginId>.` 前缀 | `npm run verify` 会报点并给出建议名（见 [16-命名规范](16-命名规范.md) §七） |

**一条命令跑完全部作者侧门禁**：`npm run verify`（lint ＋ 跨插件 import ＋ 字典 ＋ 声明自洽 ＋ 测试覆盖 ＋ …）。
