## 一、"多标签页不听话"——内容不切换

> 这是最大的一类。根子都是一个：软件里有两个终端标签页时，它们"共用了一个大脑"，不知道各自该显示什么。

### Bug：两个终端标签页永远显示同样的内容

**你的测试结果：** 新建"会话A"和"会话B"→ 标签栏多了两个标签页 ✅ → 但不管点哪个标签页，主区显示的都是同一个内容。侧栏点"会话A"→ 主区也不变。

**通俗解释：** 终端视图（就是中间那片黑色接收区）像个电视——所有标签页共用同一台电视，换台不换画面。正常应该是每个标签页有自己的电视。

**和谁有关：** 这是所有多标签页问题的"老祖宗"（代码里叫 C1）。下面几个 bug 都是它的徒子徒孙——修好它，下面这些自动好一大半。

**修好后：** 点哪个标签页就显示哪个会话的内容。侧栏点"会话A"→ 主区切到会话 A 的数据。

---

### Bug：命令操作错窗口（比如清空接收区清了隔壁的）

**你的测试结果：** 两个终端标签页（会话A 和会话B）。在会话 A 里 Ctrl+Shift+P → 复制 → 复制出的东西……确实有内容（说明命令执行了），但不确定是哪个窗口的。因为上面那个 bug 挡着，你没法确认内容对不对。

**通俗解释：** 快捷键和命令面板不知道"用户现在在看哪个标签页"，总是把命令发给最后一个打开的终端。就像你在 Word 文档 A 里按 Ctrl+C，结果复制的却是文档 B 的内容。

**修好后：** 在会话 A 里按复制，复制的一定是会话 A 的内容。

---

### Bug：改接收模式（文本/HEX）→ 另一个标签页也被改了

**你的测试结果：** 把会话 B 的接收模式改成 HEX → 切回会话 A → 会话 A 也显示 HEX 了。

**通俗解释：** 接收模式存在了一个"公共黑板"上——谁最后一个写，所有人读到的就是谁写的。

**修好后：** 每个会话各自独立——A 设文本就显示文本，B 设 HEX 就显示 HEX。

## 二、"端口设置不听话"——打开了还显示"未配置"

### Bug：打开串口后侧栏还是"未配置"，按钮不变色

**你的测试结果：** 新建会话 → 直接点"打开"（没手动选 COM 口）→ 串口确实打开了（能收发）→ 但侧栏该会话下面仍显示"未配置"，连接按钮仍是灰色。

**通俗解释：** 打开串口的时候，软件记下了"打开了 COM3"，但忘了告诉侧栏"这个会话的端口是 COM3"。侧栏不知道端口是多少，只能继续写"未配置"。

**和谁有关：** 同一个原因导致三个现象：
- 侧栏"未配置" + 按钮不变绿（你测到了）
- 两个会话的下拉框永远同步（你测到了——插新设备后两个都变成新端口）
- 拔掉所有 COM 口后下拉框还显示 COM3（看起来像有端口其实没有）

**修好后：** 打开端口那一瞬间，会话自动记住"我用的是 COM3"。侧栏立刻显示"115200 · bracket"，按钮变绿。

## 三、"快捷发送串了"——新建会话带了旧会话的东西

### Bug：新建会话出现了旧会话的快捷发送按钮

**你的测试结果：** "测试1"里加了 CMD1 → 新建"测试2" → "测试2"底下也有 CMD1 → 返回"测试1" → "测试1"的 CMD1 也不见了。

**通俗解释：** 快捷发送存错地方了——存在一个"公共抽屉"而不是"各人自己的抽屉"。新建会话从公共抽屉拿数据，旧会话改了公共抽屉，大家的快捷发送就混在一起了。

**修好后：** 每个新会话的快捷发送栏干干净净，只有默认的 AT 按钮。

### Bug：改名后标签栏标题不跟着变

**你的测试结果：** 侧栏把"新对话1"改名为"新电话消息"→ 侧栏显示新名字 ✅ → 但标签栏的标签页标题还是"新对话1" ❌。好消息：只影响自己，不影响"新对话2"。

**通俗解释：** 改名的时候只更新了侧栏，忘了通知标签栏。就像改了一个人的花名册记录，但没更新他的工牌。

**和谁有关：** 这个是新发现的（N1），原始 49 个 bug 清单里只说"可能串扰"，你实测发现不串扰，但标签栏不同步。

**修好后：** 侧栏改名 → 标签栏标题跟着变。

## 四、"关标签页不干净"——关了还在跑

### Bug：✕ 关终端标签页 → 没有确认弹窗

**你的测试结果：** 打开串口 → 点标签页的 ✕ → 标签页直接关了，没有任何提示。

**通俗解释：** 终端插件的配置文件里写了"关闭时要弹确认框"，但代码里没人读这句话。就像门禁系统装了但保安从来不看。

**和谁有关：** 这是 49 个 bug 里"写了但没人用"这类问题的典型代表。F2 整类都是这个问题——配置文件声明了某个功能，但代码里没接电线。

**修好后：** 关闭终端标签页时弹出确认框："关闭此标签页将断开串口连接"，用户确认后才关。

---

### Bug：关标签页后串口还在后台跑（🆕 新发现 N3）

**你的测试结果：** ✕ 关了终端标签页 → 标签页消失了 → 但通过"开始菜单"重新打开一个终端 → 发现串口还开着！数据还在正常收发。说明刚才关标签页只是关了"窗户"，没关"水龙头"。

**通俗解释：** 标签页✕ = 只关了窗帘。串口连接在后台继续跑。正常应该是：关标签页 = 关窗帘 + 关水龙头。

**和谁有关：** 你是在测"关闭无确认"（上一条）时不小心发现这个的。因为"标签页关不掉 + 侧栏点不开"逼你绕路，结果暴露了更深的问题——bug 之间是一环套一环的。

**修好后：** 关终端标签页 → 自动断开串口连接。当然，如果用户特意想要"关了窗口但串口还在后台收数据"，那需要单独的"后台运行"功能——但现在先让它断开。

### Bug：卸载终端插件后串口还在连

**你的测试结果：** 开着串口 → 插件市场卸载终端 → 主屏标签页消失 ✅ → 但侧栏两个会话条目还在 → 重装终端后通过欢迎页打开 → 串口仍开着，数据正常收发（卸载时没关串口）。

**通俗解释：** 卸载插件就像拆了房子的墙，但没关煤气阀门。插件被移除了，但它在底层打开的资源（串口连接）没人管。

**和谁有关：** 和上一条 N3 是同一类——"视图没了但连接还在"。

**修好后：** 卸载终端插件 → 自动关闭所有串口连接 + 清空所有会话数据。

## 五、"标签页变僵尸"——刷新后一片混乱

### Bug：F5 刷新后标签页还在但内容丢了

**你的测试结果：** 新建"新对话1"→ F5 刷新 → 标签栏仍有"新对话1"标签页 → 但主区内容显示"会话已失效"→ 侧栏会话列表为空。

**通俗解释：** 标签页被保存到"布局文件"里了（F5 后恢复），但会话数据是纯内存的（F5 后清空）。标签页恢复了，数据没了——一个空壳。

**修好后：** F5 后标签页恢复 → 自动为每个终端标签页重建会话。就像重启电脑后文件管理器自动恢复上次打开的文件夹。

---

### Bug：F5 后新建会话可能与旧标签页撞 ID

**你的测试结果：** F5 刷新 → 标签栏恢复出 terminal-1、terminal-2（僵尸状态）→ 侧栏新建 → 新会话也叫 terminal-1（和刷新前的 terminal-1 重名）→ 关闭新 terminal-1 时只关新的，刷新前那个僵尸还在。

**通俗解释：** 计数器只在内存里，F5 后归零。新会话从 1 开始编号，和刷新前的老标签页编号一样了——两个标签页同名同姓，关一个可能影响另一个。

**修好后：** F5 后计数器自动跳到"比所有已有标签页编号都大"，新会话不会和老标签页撞名。

## 七、"设置改了但没生效"

### Bug：把接收编码从 UTF-8 改成 GB2312 → 汉字仍然不乱码

**你的测试结果：** 改编码为 GB2312 → MCU 发来的汉字仍然正常显示（应该乱码才对，因为 MCU 实际发的是 UTF-8）。

**通俗解释：** 打开串口时，传给底层的是"UTF-8"，不管你侧栏选的是什么。因为打开串口的代码抄近路读了旧配置系统——旧系统里早就没这个值了，所以永远用默认的 UTF-8。

**修好后：** 侧栏选 GB2312 → 打开串口 → 用 GB2312 解码。如果 MCU 发的是 GB2312 数据，汉字正常显示。如果 MCU 发的是 UTF-8，则显示乱码（但你选 GB2312 就是选 GB2312，软件不该替你做决定）。

## 九、"小毛病但烦人"

### Bug：Monaco 发送框按 Enter 没反应

**你的测试结果：** 输入 AT\r\n → 按 Enter → 无反应 → 点"发送"按钮 → 正常发送 ✅。

**通俗解释：** 回车键绑定的"发送"函数是页面刚加载时取的快照——那时候发送框是空的，函数检查"发空内容就跳过"。后来你输入了内容，但回车键还在调那个旧函数，旧函数觉得"内容是空的，不发"。

**修好后：** 按 Enter → 发送框内容发送出去。和点"发送"按钮效果一致。

---

### Bug：定时发送间隔输入 0 → 自动变 1000

**你的测试结果：** 间隔输入框输入 0 → 点其他地方失焦 → 变成了 1000。

**通俗解释：** 这是 JavaScript 的一个经典陷阱。代码写的是"如果输入的值不存在（为假），就用 1000"。问题在于 0 在 JavaScript 里算"假"——所以 0 被当作"没填"处理了。

**和谁有关：** 和 H2（空串导致 session 数据全丢）同根——都是"用错了判断方式"。

**修好后：** 输入 0 就是 0（虽然 0 毫秒发一次没意义，但用户输入了什么就是什么，不该被偷偷改掉）。

---

### Bug：3 个分屏面板→拖标签页到目标面板→跑偏了

**你的测试结果：** 拖标签页到右边的面板 → 标签页出现在了左边的面板。

**通俗解释：** 拖拽定位算法只判断了"有没有在某个 TabBar 上方"，没判断"具体是哪个 TabBar"。三个面板时，算法选了第一个不是来源面板的——恰好是左边那个。

**修好后：** 拖到哪个面板就落到哪个面板。

### Bug：插件卸载后详情页还是显示"已安装"

**你的测试结果（复杂版）：** 你发现了一个更深的问题——图标栏点"插件市场"打不开标签页（见 N2）。所以你只能通过欢迎页打开插件市场标签页 + 点某个已安装插件弹出详情页 → 在详情页点卸载 → 图标栏消失 ✅ → 重新安装 → 详情页刷新 ✅。基本流程正常，但不走寻常路。

**通俗解释：** 这个 bug 原意是"插件已在别处被卸载，但详情页还不知道"。你的测试路径避开了触发条件，但暴露了 N2（图标栏打不开插件市场）——属于歪打正着。

**修好后（N2 修完后可正常测试）：** 插件市场标签页正常打开 → 点某个插件"详情"→ 去另一个标签页卸载该插件 → 切回详情页 → 详情页自动刷新，显示"未安装"。

### Bug：手动删除插件文件夹 → 软件里没反应

**你的测试结果：** 把插件移到 .disabled 文件夹 → 等 10 秒 → 没变化 → F5 手动刷新后才消失。

**通俗解释：** 文件监控只检测"有没有新插件出现"，不检测"有没有插件消失"。就像保安只盯着大门看谁进来了，不查谁从后门溜了。

**修好后：** 手动删除/移动插件目录 → 10 秒内软件自动检测到并卸载。

### Bug：非法版本号静默接受

**你的测试结果：** 把插件版本号改成 "1.beta" → 重启软件 → 版本显示为 1.beta。

## 十、无法在操作中复现的 Bug（代码层面）

> 这些 bug 你用鼠标点不出来——它们要么需要特殊条件（React 未来版本、Phase 6 功能），要么是代码质量问题但不影响当前使用。
> 但它们仍然需要修——否则将来升级 React 或加新功能时会炸。

### React 规则违规（现在不炸，将来可能炸）

**Bug：** 在组件渲染期间修改了"便签本"（ref）——React 的 Concurrent Mode（未来的渲染模式）下可能导致数据不一致。

**通俗解释：** 这就像在打印过程中改稿子——打印机可能拿到改了一半的稿子打印。React 当前版本不会触发这个问题，但升级到 React 19+ 后可能出问题。

**修复好处：** React 升级时不出 bug。代码更规范——修改数据的时机放在"渲染完成后"而非"渲染过程中"。

**修好后：** 用户完全感觉不到变化。但代码在 React 19 的 Concurrent Mode 下不会出现"标签页聚焦错误"的诡异现象。

---

**Bug：** 保存布局时用了一个"偷窥"当前状态的黑客手段——Concurrent Mode 下会失效。

**通俗解释：** 这个操作太 hack 了，从长远看必须换掉。不改的后果：React 19+ 下布局保存可能丢数据。

**修复好处：** 布局保存可靠，不依赖 React 内部实现细节。

**修好后：** 用户无感。但 F5 刷新后标签页恢复的准确性提高——不会因为布局数据损坏导致标签页恢复错乱。

---

### 内存/资源泄漏（现在看不见，累加起来占用资源）

**Bug：** React 严格模式下，串口统计数据的监听器没有被正确清理——每热重载一次就多一个监听器。

**通俗解释：** 就像每次开灯都多并一条线，时间久了电线乱七八糟。开发环境下的热重载会导致累积。日常使用不触发。

**修复好处：** 统计数据准确。热重载后不累积僵尸监听器。

**修好后：** 状态栏的 TX/RX 字节计数始终准确，不会因为修改代码触发热重载后数字跳变异常。

## 十一、已确认修复

### Bug：状态栏不响应插件安装/卸载 ✅

**你的测试结果：** 不符合！卸载终端后状态栏 + 图标栏全部消失，重装后显示。说明这个 bug 之前在某个版本里修好了。

**解释：** 状态栏虽然没主动"订阅"插件变化，但它所在的整个页面在安装/卸载时会重绘——沾了父组件的光。这是"碰巧能工作"——如果将来页面优化去掉多余的重绘，状态栏就停止更新了。修它需要给状态栏加上主动订阅。

## 十二、现在测不了但将来会暴露的 Bug

### 协议全局共享

**为什么测不了：** 当前只有一个协议（方括号），需要 Phase 7 加新协议后才暴露。

**通俗解释：** 如果将来你装了 JSON 协议，在会话 A 选 JSON → 会话 B 也会被强制改成 JSON。

---

### 多串口同时连接

**为什么现在不能：** 底层设计是单串口。Phase 7 重构。

**通俗解释：** 目前只能同时连一个 COM 口。如果要两个终端各连一个 COM 口（如 COM3 和 COM13），需要底层改造。

---

### dirty 标签页相关两个 bug

**为什么测不了：** "dirty"（有未保存修改）的概念要等 Phase 6 文件编辑器引入。

**通俗解释及修好后预期：**
1. **强制关闭不生效** — 如果你编辑了一个文件有未保存修改，按 Ctrl+W → 弹"确定关闭？"→ 确定 → 标签页还是关不掉。修好后：确认后强制关闭，标签页消失。
2. **关闭确认** — 和上文 E1 是同一类。修好后：任何插件都可以声明"关闭时要确认"，标签栏 ✕ / Ctrl+W 都会弹确认框。

---

### 运行时协议加载

**为什么测不了：** 动态安装插件的功能（plugin:// 协议）Phase 7 才启用。

**通俗解释及修好后预期：** 同一个插件，通过"文件复制到 plugins 目录"和"通过 plugin:// 协议动态安装"两个途径加载后，行为应该完全一致。目前协议安装会漏掉 `mode` 和 `resources` 配置。修好后：两种方式等价，插件行为不因安装方式而异。
