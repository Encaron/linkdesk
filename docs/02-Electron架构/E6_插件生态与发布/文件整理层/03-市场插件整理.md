# 03-市场插件整理——`plugins/marketplace/`

> **对应任务：E6#86（第 3.6.3 轮）。本层最重的一轮——marketplace 占超限总数的 10/34。**
> **12 档是唯一权威**（[12-插件目录与UI细节.md §一](../03-插件市场/12-插件目录与UI细节.md)），本档案是它的**执行版**：把「超限表」变成「怎么拆」。

## 〇、先读这个——三条硬事实（决定整个拆法）

**① SDK bundle key = basename，与子目录无关。**

```
packages/plugin-sdk/src/vite-config.ts:113
let key = basename(rel, extname(rel)).replace(/[^A-Za-z0-9_.-]/g, "_");
while (usedKeys.has(key)) key += "_";
surfaces.push({ key, finalName: `views/${key}.bundle.js`, abs });
```

→ **把 `views/SearchView.tsx` 移进 `views/sidebar/SearchView.tsx`，产物名不变**（仍是 `views/SearchView.bundle.js`）。
→ 🔴 **但 basename 必须保持唯一**：**门面文件绝不能改叫 `index.tsx`**（`index` 已被 entry 占用；第二个 index 会退化成 `index_`，语义混乱）。**门面保留原名。**

**② 只有 `contributes.views[].render` 指向的文件才是 bundle 表面。**

私有子组件（`DetailFeaturesTab` / `DetailChangelogTab`）**不在 plugin.json 里 → 不是表面**，随宿主 chunk 打包。移动它们**零构建影响**。

**③ 视图文件移动 → 必须同步 plugin.json `render`。**

dev 走源码路径；dist 走 `rewriteDistManifest` 改写为 `views/<Key>.bundle.js`。**少改一条 = dev 白屏 + 打包版白屏**（换插件后壳拿不到组件）。

## 五、`__tests__/` 处置

现 10 个测试平铺在 `plugins/marketplace/src/__tests__/`。**09-插件目录规范 §111 要求「与被测文件同目录，`__tests__/` 内保持相同相对路径」。**

**推荐：本轮不动**——测试文件不受行数门禁约束（`SKIP_DIRS` 含 `__tests__`），且平铺虽不规范但**不产生任何运行时/构建影响**。若要动，按被测域分 `__tests__/services/`、`__tests__/views/` 两个子夹，与 09 规范对齐。

> 🔴 **决策已拍板（[00 §五](00-整理档案.md) 第 4 条，2026-09-11）**：settings 用**同目录共置**、其余 4 插件用 `__tests__/`——**两套惯例并存，判为不合规**。拍板结果 = **settings 迁到 `__tests__/`**，走 3.6.4 轮（E6#87d）。**本档案（marketplace）自己的 10 个测试本轮仍不动**（见上）。

## 六、🔴 plugin.json 同步清单

**本拆分方案下，需要同步的 `render` 路径数量 = 取决于是否做 views 分组：**

| 方案 | plugin.json 改动 | 风险 |
|:--|:--|:--|
| **A：views 不分组**（只建同名字夹） | **0 条**（7 个视图全部原地不动） | 最低 |
| **B：views 按容器分组**（本档案 §二） | **7 条**（5 sidebar + 1 detail + 1 confirm） | 中——每条都要手改 + 验 |

**两方案都完整解决 10 个超限**（分组不解决行数，同名夹才解决）。**分组只换来「目录可见性」。**

> 🔴 **决策点（[00 §五](00-整理档案.md) 第 2 条）**：**推荐 B**——理由：9 个文件混 3 类角色本身就是「该建子文件夹」的信号；且 CSS 已按同轴命名，目录不跟上则两处地图对不上。**若选 A，本轮风险显著更低。**

**改 render 的机械流程（方案 B 时逐条走）：**

1. 改 plugin.json 的 `render`（如 `src/views/SearchView.tsx` → `src/views/sidebar/SearchView.tsx`）
2. **同步改源码里所有相对 import**（`../services/...` → `../../services/...`）——**层级加深一层，全部相对路径 +1 级**
3. `npm run check`（tsc 抓漏）
4. **实机验**：dev 起 Electron → 逐个打开 7 个视图（5 侧栏 + 详情 + 安装确认）→ 无白屏/无 console 报错

> ⚠️ **第 2 步最易漏**：`views/` 下每个文件都有 `../services/` `../components/` `../styles/` 的 import。**漏一个 = tsc 红**（这是好事，机械拦得住）。**但 CSS 的 `import "../styles/x.css"` 若写成动态或字符串拼接 → tsc 抓不到**（本项目无此写法，此处仅作提醒）。

| 风险 | 形态 | 规避 |
