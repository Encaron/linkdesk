# 插件安装/卸载单一路径归一化

> 2026-08-02。**E5 新增任务。** 审计发现两套安装/卸载 IPC 路径——不同的实现、不同副作用。
> 执行清单任务：E5#32

---

## 一、前因——两套路径

### 1.1 当前双路径

```
路径 A（shell 直调）:                   路径 B（bridge）:
  ipcRenderer.invoke                     ipcRenderer.invoke
    ('plugins:install', src)               ('plugins:call', { method: 'install', ... })
      ↓                                       ↓
  pluginFileService.installPlugin()       loader.ts installPlugin()
  只做文件操作——复制到 plugins/           做完整生命周期——emit 事件 + 更新禁用列表 + 清理 views

路径 A 安装的插件：
  ✅ 文件在 plugins/ 下
  ❌ loader.ts 不知道——不加载、不注册、不显示

路径 B 安装的插件：
  ✅ 文件在 plugins/ 下
  ✅ loader.ts 知道——加载、注册、显示
```

**插件安装两次——效果不同。** 这是一个"缝 bug"——两拨人（或 AI）在不同时间写了两套实现，没有归一化。

### 1.2 历史同类

**E3b #36j1——`loadPlugin` 和 `loadPluginRuntime` 两条加载路径不同步。** 已在 E3b 中归一化为 `applyPostLoadSteps`。

**E5#12——插件加载归一化。** `loadThemePlugin`/`loadLanguagePlugin` 合并到 `loadPluginLifecycle`。

**本任务是同一模式：** 安装/卸载也应该是单一路径。

---

## 二、解决方案

### 2.1 归一化——所有安装/卸载走 bridge 路径

```typescript
// electron/handlers/plugin-handlers.ts（改造后）

// 🔥 路径 A 的 handler 改为转发到路径 B
ipcMain.handle('plugins:install', async (_e, src: string) => {
  // 不再直接调 pluginFileService.installPlugin()
  // 改为——只做文件操作，完成后发事件让 loader 接管
  const pluginId = await pluginFileService.installPlugin(src);
  // loader.ts 已有 watcher 监听 plugins/ 目录变化——会自动发现新插件
  return pluginId;
});

ipcMain.handle('plugins:uninstall', async (_e, pluginId: string) => {
  // 文件操作——删除目录
  await pluginFileService.uninstallPlugin(pluginId);
  // loader.ts 通过 PLUGIN_REMOVED 事件处理生命周期清理
  // （已在 lifecycle.ts 中 dispatch）
  return;
});
```

**或者更彻底的方案——路径 A 直接删掉，全部走 bridge：**

```typescript
// 删 plugins:install/uninstall/reinstall handler
// loader.ts 暴露 IPC action "plugins.install" / "plugins.uninstall" / "plugins.reinstall"
// 所有调用方走 plugins:call bridge
```

### 2.2 推荐方案——bridge 成为唯一入口

```
所有安装/卸载操作:
  ipcRenderer.invoke('plugins:call', { action: 'install', ... })
    → ipc-bridge.ts 路由
      → loader.ts installPlugin()
        → pluginFileService.installPlugin()  // 文件操作
        → applyPostLoadSteps()               // 生命周期
        → emit PLUGIN_INSTALLED              // 通知 UI
```

**删掉 `electron/handlers/plugin-handlers.ts` 中重复的文件操作逻辑。** 或者保留 handler 但改为只做文件操作 + 通知 loader。
