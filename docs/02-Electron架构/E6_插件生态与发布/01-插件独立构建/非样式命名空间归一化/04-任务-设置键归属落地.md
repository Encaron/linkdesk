## 一、判据表（**含必须真跑过的负控**）

| 判据 | 要求 | 负控（**必须真能红**，覆盖它想抓的形态） |
|:--|:--|:--|
| **① 宿主保留键保护区** | 插件键不得 ∈ 账 | 在插件仓临时塞 `app.theme` ⇒ **红**（而且这正是"顶替宿主设置"的真形态）；**还原后 sha256 逐字节相同** |
| **② 归属前缀（黄）** | 插件新键 `<pluginId>.` | 塞一条 `zzz.something` ⇒ **黄**（**不是红**——这条自测要同时证明它**不红**，否则分级写错了） |
| **③ 同插件 merge 仍合法**（**反向负控**） | 同一 pluginId 两次 `registerConfiguration` ⇒ **merge、不出声、不丢键** | 单测：同一 pluginId 注册 `{a,b}` 再注册 `{b,c}` ⇒ 结果 `{a,b,c}`；**日志零输出**。⚠️ **这条是防"改坏既有语义"**，与 ② 同等重要 |
| **④ 异 pluginId 同 key ⇒ 首撞者保留 ＋ 出声** | 后来者**不覆盖**，日志 `console.error` 点名双方 | 单测：`alpha` 注册 `x.y`，`beta` 注册 `x.y` ⇒ 断言「值仍属 alpha」＋「有 console.error 点名 alpha/beta」 |
| **⑤ 伪 pluginId 保护区** | `pluginId` ∈ 保留面 ⇒ schema **报 pattern 不符** ＋ SDK `validate` **报点** | 造 `pluginId: "app"` ⇒ **两道防线各报一次**（照 E6#109h-b⑧ 的 NC2 形态：腿报 ＋ `validate` 报） |
| **⑥ 账 ↔ 实况双向对账** | 账与实况任一侧多出 ⇒ 红 | ① 只改账 ⇒ 红；② 只改实况（在 `src/App/config/` 加一个 `app.zzz` 键）⇒ **红** |
| **⑦ 零迁移面（加禁前实证）** | 18 仓 ＋ 官方目录 ＋ `third-party/` **无** pluginId 落入保留面 | 实测读数写进交接段（**不是"应该没有"**） |
| **⑧ 旧门禁未空转** | 盘一遍本格是否让某条旧 check 输入清零后跑绿 | 实测（不是看代码猜） |

## 二、禁区

- 🔴 **不许抛错**（`parseContributions` 无 try/catch ⇒ 抛错 = 整只插件装不上：[00 档 §2.7](00-整理档案.md)）。
- 🔴 **不许改坏「同插件多次注册 merge」**（`ConfigurationRegistry.ts:133-137`；`contributes.configuration` ＋ 自动注册的 statusBar 配置）。
- 🔴 **不许动配置的值语义 / applier / 主题 onApply**：`src/App/config/appearance.ts` 的 **13 覆盖键播种与回退链**、`appearanceApplier.ts`、`lifecycle.ts` 的主题切换监听 —— [29 号档](../样式命名空间归一化/29-主题系统保护条款.md) §三 的「新增 token / 新玻璃参数 / 新字体档位**全部是加法，明确欢迎**」**不许被本格的规则挡住**。
- 🔴 **不许改名存量 19 键**（除非 1.33 的论证同时满足「零 UI 变化」＋「用户设置无损迁移」两条）。
- 🔴 **不许引白名单 / 基线 / 棘轮**；账**必须生成式 ＋ 双向对账**。
- 🔴 **不许把「黄灯」写成「红」**：归属前缀这条**存量反例 19 个**就是它不满足「本仓可答 ＋ 有真害」的证据（[00 档 §10.3](00-整理档案.md) 宽容度模型）。
- ⚠️ **上位约束**：**零 UI 变化**（除版本号；含主题/字体/翻译三条横切零回归）· 只做加法且名字一次定对 · [29 号档](../样式命名空间归一化/29-主题系统保护条款.md) 优先 · 对外宽容。
- ⚠️ 照旧：不跳 `npm run check` · 推前现测代理 · 推完 `ls-remote` 对 SHA · **提交只按路径 `git add <本格文件>`**。
