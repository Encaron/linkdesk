## 一、事实：为什么它会卡在左上角（已核实到根因）

```
① 编辑器入口调用：executeCommand("file-tree.openWith", filePath)      BinaryNotice.tsx:63-65（裸字符串、无 anchor）
② file-tree 命令体：openOpenWithPicker({ uri, name, ext, anchor })     navigation.ts:50-110（anchor 缺省 = undefined）
③ 面板定位：const pos = useMemo(() => { if (!request.anchor) return undefined; … })   OpenWithPanel.tsx:139-144
④ 渲染：<div className="file-tree-openwith" style={pos ? {position:"fixed",…pos} : undefined}>   :150
        ⛔ pos === undefined ⇒ **不写任何 style** ⇒ 落到基础 CSS
⑤ 基础 CSS：.file-tree-openwith { position: fixed; width: 432px; … }   open-with.css:4-15
        ⛔ **没有 top/left** ⇒ `position:fixed` + 静态位置 = **视口左上角 (0,0)**
⑥ 左上角那块 = 面板头（含 ✕）⇒ 落在 **窗口顶部 30px 拖拽带**内 ⇒ OS 级截事件，`-webkit-app-region:drag` 吃掉鼠标 ⇒ **✕ 点不动**（CLAUDE.md 硬约束 18）
```

**附带两处**（都要在本格同笔修掉）：
- `OpenWithPanel.tsx:138` 的注释写着「**非右键入口居中**」——**实现里没有居中**，是**注释画饼**（AI 误导下一棒的典型）；
- 锚定分支有钳制 `top = Math.max(30, …)`（`:142`，对），无锚定分支**完全没定位**（错）——所以「注释说了一个分支、实现只做了一个分支」。

## 二、口径裁决（**居中为默认**，锚定为可选增强）

> 🔴 **本节已被文首 §0 改判废止**（2026-10-05：锚定不再存在）——下文留档，⛔ 不得据以实现。

### 2.1 为什么是居中而不是「给编辑器一个虚拟锚点」

用户原话（6.3.1）：「居中，因为如你所见，编辑器也用它了，就不能使用锚定这个方法了」——理由成立且更根本：

- **锚定是「从某个点长出来」的隐喻**：只有**右键**这类入口有那个「点」。编辑器那颗钮在提示块里，**没有任何点**可锚（硬造一个「钮的矩形」会让面板贴在提示块上，与「模态」语义冲突）。
- 设置页入口（[02](./02-归一化-齿轮锚点与假菜单项.md) 方案 A）同样**没有点**。
- ⇒ 口径：**有 `anchor` ⇒ 就近弹出；无 `anchor` ⇒ 居中模态**。两条路都是**一等公民**，都必须在实现中存在（⛔ 不许再有「注释里有一个分支、实现里没有」）。

### 2.2 三分支实现（写什么 · 照此写）

```tsx
// OpenWithPicker.tsx（共享件内）——三分支，⛔ 不留 undefined 落到基础 CSS 的路
const anchored = !!request.anchor;
const pos = anchored
  ? {                                     // ① 锚定：就近弹出 + 双向钳制
      left: Math.min(request.anchor!.x, window.innerWidth - PANEL_W - MARGIN),
      top:  Math.max(TOP_SAFE, Math.min(request.anchor!.y, window.innerHeight - PANEL_MIN_H)),  // TOP_SAFE = 30（硬约束 18）
    }
  : undefined;                            // ② 居中：**不写 inline 定位**，由 CSS 的居中类负责（见下）
// ③ 渲染：className = `ldk-openwith${anchored ? " ldk-openwith--anchored" : " ldk-openwith--centered"}`
//    ⛔ 禁止「pos 为 undefined 且无居中类」这一组合——那正是今天的 bug
```

```css
/* open-with-picker.css —— 居中走 CSS（不靠 JS 量测，抗窗口缩放） */
.ldk-openwith { position: fixed; width: 432px; ... }
.ldk-openwith--centered{ inset: 0; margin: auto; height: max-content; max-height: calc(100vh - 60px); }
  /* inset:0 + margin:auto = 水平垂直双居中；max-height 留出上下各 30px，
     ⛔ 不是给拖拽区让位（居中面板本就不进 30px 带），是给「面板超高时仍不出屏」兜底 */
```

> ⛔ 不用 `transform: translate(-50%,-50%)`：面板高度随处理器行数变化，`translate` 方案在超高时**顶边会滑出屏外**，`inset+margin:auto` 不会。两者选一，**选后者**。

### 2.3 尺寸常量要有名字（无硬编码）

现状魔法数：`460`（右缘留白）、`320`（高度）、`3000`（z）、`432`（宽）。本格要求：面板宽/最小高/安全边距/z 全部**具名常量**（同文件内 `const PANEL_W = 432; const MARGIN = 28; const TOP_SAFE = 30;`），CSS 与 TS 两边**只允许一处定义**（TS 常量导出、CSS 用 `var(--ldk-openwith-w)` 由组件写行内自定义属性，或反之——选一处，注释写明）。

### 3.0 拍板结果（实施照此）

| 项 | 定论 |
|:--|:--|
| 要不要遮罩 | **要**（与下面 §3.1 的推荐一致） |
| 用哪一层 | **壳既有模态遮罩**——即「关闭窗口」这类确认弹窗走的 `DialogHost` 用的**同一平面＋同一 token**：平面 `#ld-scrim-plane`（`OverlayPortal.tsx:23`，`FloatingLayerHost` 渲染），底走 `--scrim-dialog: rgba(0, 0, 0, 0.5)`（`src/index.css:54`，注释原文「模态遮罩——DialogHost 设计 §7.1」）；写法照 `src/pool/floating/dialog/DialogHost.tsx:115` |
| ⛔ 禁止 | ① 自造 `rgba(...)`／新色值；② 加磨砂（壳的既定美学是「遮罩满屏**无磨砂**」，`index.css:560`）；③ 为面板新立第二个遮罩 token |
| ~~锚定态~~ | ~~**仍不加**遮罩（只留透明点击层，见 §3.2 第二条）——用户裁的是「居中态四周变黑」，不是「每处都变黑」~~ ⇒ 🔴 **已被文首 §0 改判废止**（2026-10-05：锚定态整体取消，「一律居中 + 遮罩」） |

> 一句判据（写给下一棒）：**「周围变黑」= 复用壳已有的那层黑** ⇒ 这条是**归一**、不是新设计。任何实现只要写出一条**新的黑**（新 rgba／新 token／新平面）就没归一，设计门禁与 [05](./05-防复发-机械准入原则.md) §三 该拦。

### 3.1 备查：立案时的推荐（内容已被 §3.0 覆盖，留档用）

| 理由 | 说明 |
|:--|:--|
| ① 居中的模态必须有背景分离 | 面板居中后与卡片/标签页混在一起，没有压暗就分不清「现在这层在等谁」 |
| ② 编辑器入口是**阻断式**提示 | 用户此刻在为「这个文件打不开」做选择，焦点收束是帮助而非打扰 |
| ③ 与壳既有机制同源 | `OverlayPortal` 自带 scrim（`SCRIM_ROOT_ID = "ld-scrim-plane"`，`OverlayPortal.tsx:23`），注释写明「遮罩满屏**无磨砂**，与 surface 平面分离」——**壳的既定美学就是无磨砂** |
| ④ 锚定态**不**加遮罩 | 右键属于「顺手看一眼」，压暗会让连续操作变累 ⇒ **两种态两种表现**，与 §二 的三分支一一对应 |

### 3.2 具体实现（若拍板走推荐）

- 居中态：`<OverlayPortal onClose={close} trapFocus rootId=… >` **用默认 overlay 根**（⛔ 不再用 `rootId="context-menu-root"`、⛔ 不再手写 `zIndex="3000"`——那是「菜单级」取值，模态应回到遮罩平面：遮罩 `--z-overlay-backdrop = 500`，面板 > 500，取既有 token）；**遮罩层照 `DialogHost.tsx:115` 写**——portal 到 `getScrimTarget()`（`#ld-scrim-plane`）、底走 `--scrim-dialog`（§3.0 拍板；⛔ 不另写颜色）；
- 锚定态：**不渲染遮罩**，只 `closeOnOutsideClick`（现在是靠 scrim 抓外部点击——锚定态需要一层**透明**点击层，别把 scrim 的压暗也带过来；`OverlayPortal` 是否支持「透明 scrim」由实施者先探一步，探不到 ⇒ 在共享件内自建一层 `position:fixed; inset:0; background:transparent` 的点击层，⛔ 不改 `OverlayPortal` 的公共行为）；
- 面板自身 `z-index` 必须**高于遮罩**且**不破坏** `OverlayPortal` 的「wrapper 零 stacking-context 属性」要求（`OverlayPortal.tsx:140-143`）——任何 `zIndex` 值必须 > 500（`:46-52` 契约警告）。

### 3.3 当时问的话（原文留档 · ✅ 已有答复，⛔ 实施时不必再问）

> **「打开方式」面板现在改成居中了。要不要像普通弹窗那样，四周压暗一层（只压暗、不加磨砂——跟壳里其它遮罩一致）？**
> 我的推荐：**要**。理由：居中后没有背景分离会分不清层次；而且编辑器那个入口本来就是「这个文件打不开，请你选一个」的阻断式场景，压暗能帮你把注意力收在面板上。
> 你要「要」还是「不要」？（选「不要」也能做：面板居中、周边不压暗，点外面照样关。）
>
> **用户答复（2026-10-05）**：「直接用关闭窗口时候弹窗的周围变黑的效果就行」⇒ 落 §3.0，**本问已闭**。

## 五、任务卡（怎么改 / 改哪里 / 写什么 / 怎么验）

### C3.2 遮罩（§3.0 已拍板：复用壳既有模态遮罩）
- **改哪里**：共享件的 `OverlayPortal` 用法；⛔ 不改 `OverlayPortal` / `DialogHost` 的公共行为。
- **怎么改**：照 `DialogHost.tsx:115` 的遮罩写法——`getScrimTarget()`（`#ld-scrim-plane`）＋ 底 `--scrim-dialog`；**锚定态只留透明点击层**，⛔ 不渲染这层黑。

### C3.3 拖拽区护栏（硬约束 18）
- **怎么改**：锚定态 `top ≥ 30` 保留；居中态靠 `max-height: calc(100vh - 60px)` 保证**上下各留 30px**；交互元素（✕、行、按钮）**一律不许**用 `position:fixed; top:<30px` 自定位。
- **怎么验**：`grep -n "Math.max(30" ` 命中锚定钳制；实机把窗口拖到很矮（如 500px 高）⇒ 面板不覆盖拖拽带、✕ 仍可点。

### C3.4 关闭面（Esc / 点外 / ✕ / 焦点陷阱）
- **怎么改**：`trapFocus` 保留；Esc 关闭（若壳已有全局 Esc 处理，跟随它，⛔ 不新造第二套）；✕ 用共享 `Button`（`variant="ghost"`，用户第 2 条同一条纪律）。
- **怎么验**：键盘走一遍——Tab 只在面板内循环；Esc 关；Shift+Tab 反向；✕ 有可聚焦态。

## 七、风险与护栏

| 风险 | 护栏 |
|:--|:--|
| 居中后与「锚定」共用一套 inline 定位 ⇒ 又出现 undefined 落基础 CSS | §2.2 的「三类名互斥」＋ 单测断言 |
| 遮罩压暗导致锚定态变重 | 两态两表现（§四 矩阵）——锚定态不渲染遮罩 |
| 面板浮层影响 `OverlayPortal` 的 stacking 契约 | `zIndex > 500` 且 wrapper 零 stacking 属性（`OverlayPortal.tsx:46-52/140-143`） |
| 超高面板在窄窗口下溢出 | `max-height: calc(100vh - 60px)` ＋ 内部滚动（`overflow:auto`） |
| 共享件里写死 432/460/320 | §2.3 具名常量 ＋ 一处定义 |
