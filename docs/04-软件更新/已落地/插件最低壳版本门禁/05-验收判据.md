# 05 · 验收判据

> 判据写法照本仓既有纪律（[00 §八](00-README.md)）：**每条判据都写「读什么数、判什么号」**，

> 自测清单（[侧栏布局形态门禁化](../侧栏布局形态门禁化.md) 同族教训：**门禁自己要有人看着**）。

## 一、正控（必须变红/变"不适配"——本事故当场命中）

### 正控 1 · 读数腿端到端（**真机**）

**现场**：安装版 `0.2.41`（`D:\01link\linkdesk`）＋ 已装 settings（立项时 `1.0.35`；⚠️ 2026-10-06 验收实测本机已自动更到 `1.0.38`、假声明 `0.2.32` 原样未修——事故插件的新版没把声明修掉，恰证 G4 必要性，正控照样当场命中）。

| # | 读什么 | 期望 |
|---|---|---|
| 1 | 市场详情页兼容性词 | **「不适配」**（⛔ 不再是「正常」） |
| 2 | `getCompatibility` 返回的 `state` | `"incompatible"` |
| 3 | 同返回的 `minAppVersion` | `"0.2.48"`（**实际地板**＝`PluginCard` 的机械 `since`，⛔ 不是 manifest 里那个 `0.2.32`。⚠️ 2026-10-06 验收订正：初稿写 `0.2.44` 是 `@linkdesk/ui` 的**包号**，与壳版本不是同一把尺子——见 06 §九 9.4#1） |
| 4 | 同返回的 `minAppSatisfied` | `false` |

> ⚠️ 第 3 项是本格的**核心读数**：它证明"读数会自己算"，而不是照抄 manifest。

### 正控 2 · SDK 门禁（构建期）

夹具：一个 `plugin.json` 声明 `minAppVersion: "0.2.32"`、源码 `import { PluginCard } from "@linkdesk/ui"`。

- `linkdesk/no-ui-without-min-app-version` ⇒ 🔴 **红**，报文须**同时含**：实际地板号、越界的那条 import、修法（抬到 ≥ 地板）。
- ⛔ **不许**再出现"声明 ≥ 0.2.13 就放行"的旧口径（`UI_REANCHOR_APP_VERSION` 常量应已删除；grep 取证）。

### 正控 3 · 脚手架默认值

`create-linkdesk-plugin` 新出的模板：`plugin.json` 的 `minAppVersion` ＝ **模板自源码算出的地板**。

- 例：模板若引用了 `since = 0.2.48` 的组件（如 `PluginCard`）⇒ 生成即 `"0.2.48"`；
- 反例（须红）：模板引用了某组件，而生成物的 `minAppVersion` 被写成 `"0.2.13"`。

## 二、负控（**不许**变红——防过杀）

| # | 夹具 | 期望 |
|---|---|---|
| 负控 1 | 插件**完全不消费** `@linkdesk/ui` | 零报点（门禁静默），读数不受影响 |
| 负控 2 | 只有 `import type { … } from "@linkdesk/ui"` | 零报点（编译期擦除、零运行时依赖）；但 `import { type X } from "@linkdesk/ui"` **照算**（语句含运行时绑定） |
| 负控 3 | 消费的全部组件 `since ≤ 声明` | 绿（门禁**不是**"见 ui 就报"，是"见越界才报"） |
| 负控 4 | 产物读不到 / 离线 / 侧载无 catalog | 读数**退化成"只有声明地板"**，⛔ **不判坏消息**；`unknown` 语义照旧 |
| 负控 5 | 日期缺失 | 仍落 `compatible`（**⛔ 不落 `unknown`**）——G4 不得动既有日期口径 |
| 负控 6 | 壳版本 = 装修后的地板 | `versionGte` 边界：`0.2.41` vs `0.2.41` ⇒ **满足**（≤ 不算越界） |

## 四、七条原则逐条自检（[02 §七](02-设计-账本与门禁.md) 的验收面）

| 原则 | 本方案怎么满足 | 反证（若做不到就红） |
|---|---|---|
| **归一化** | 判定式**只有一处**（地板 = max{since}），账本**只有一份**（随 SDK 发） | 出现第二份"组件清单/版本表" ⇒ 红 |
| **插件独立化** | 插件仍只声明"我要求 ≥X"；⛔ 门禁**不要求**它写 try/catch 或动态 import | 门禁报文让作者"改成优雅降级" ⇒ 红 |
| **高内聚** | G2 改现成的 `ui-min-app-version.ts`（不新起检查腿）；G4 挂进 `compatibility.ts` 既有算点 | 新起第二个兼容算点 ⇒ 红（违反 E6#117 单点） |
| **低耦合** | 账本经 **SDK npm 包**下发（插件侧本就依赖 SDK）；G5 **只住壳仓** | SDK 里出现"最新已发布壳版本"字样 ⇒ 红 |
| **无硬编码** | 删 `UI_REANCHOR_APP_VERSION` 常量；地板来自账本计算 | 残留 `"0.2.13"` 之类的魔法地板 ⇒ 红（grep 取证） |
| **无死代码** | 账本回填后，旧常量与其单测一并删；模板默认值取代手写注释 | 常量删了但单测/分支还在 ⇒ 红 |
| **AI 友好性** | 报错三件套（**地板 ＋ 越界 import ＋ 修法**）＋ 账本是机器可读 json | 报"兼容性不足"却不给数字/出处 ⇒ 红 |

## 五、残余边界（**不在本轮判据内**，登记备查）

1. **动态 import / `require` 在运行时分支里**：门禁按"出现即算"处理（保守、可假红）；真值需运行时，本轮不做。
2. **`window.linkdesk.*` API 轴**：本轮**只做 ui 组件轴**。API 轴的地板由 `host-api-surface.json` 另行代表——[00 §六](00-README.md) 已划出，未并案。
3. **第三方用户的旧壳**：G4 对**所有人**生效；但第三方写不出 G5 那种"发布链"检查（结构上做不到）——**这是设计，不是缺口**。
4. **"壳先于插件"的反向**：本轮不管"壳发了、插件还没跟上"（那是**兼容**的正常形态，读数已有 `compatible`）。
