## 二、build 命令

### 2.1 实现

```bash
linkdesk-plugin-sdk build
```

实际步骤：

```
1. validatePluginJson("./plugin.json")
   → 失败 → 打印错误，停止

2. defineLinkdeskPluginConfig() → Vite build
   → 产出 dist/<pluginId>.linkdesk-plugin/
     ├── plugin.json
     ├── icon.svg (如果有)
     ├── i18n/*.json (如果有)
     └── index.bundle.js

3. zip dist/<pluginId>.linkdesk-plugin/ → ./<pluginId>.linkdesk-plugin

4. 输出：
   ✔ Build complete!
     File: ./my-cool-plugin.linkdesk-plugin
     Size: 245 KB
     Ready to publish!
```

### 2.2 Vite 配置要点

```typescript
// vite-config.ts 中
{
  build: {
    lib: {
      entry: pluginEntry,
      formats: ["es"],
      fileName: "index.bundle",
    },
    rollupOptions: {
      external: ["react", "react-dom", "react-i18next", "i18next"],
      output: {
        // 确保 CSS 也打进 bundle（如果有）
      },
    },
  },
}
```

## 三、发布入口——**唯一入口 = 命令行**（2026-08-30 定主路；🔴 2026-09-14 图形备路退役）

> **2026-08-30 拍板：主路 = 命令行 `npm run publish`**（作者终端一键发布，不打开 LinkDesk）。🔴 **2026-09-14 用户拍板：市场 UI「发布插件」按钮那条备路退役**（E6#26a/#26c 按退役结案）——理由：市场 UI 是**终端用户面**，LinkDesk 不是开发者软件，一百个用户里没几个真做插件；作者面已一站式（脚手架 + 一条 publish），GUI 发布属读者错位。**⇒ 现在只有命令行一个入口**，它单独消费自动发布底座（E6#26b）。总览 → [00-第三方作者旅程.md](../05-文档与发布/00-第三方作者旅程.md) §五。

### 3.1 入口形态

- **唯一入口（命令行）**：`npm run publish`（= `linkdesk-plugin-sdk publish`）——创建 Release + 上传 asset + 更新自己仓库 marketplace.json，全在 git bash 完成。
- **~~备路（图形，软件内）~~ 已退役（2026-09-14）**：原设计 = marketplace 插件顶部工具栏「发布插件」按钮 / 设置页「发布新插件」（PAT 登录后可见）。**不做了**；将来若有「纯图形作者」需求属**新立项**，不是复活这条备路。

### 3.2 流程（命令行，现行）

```
1. npm run build → 产出 <id>.linkdesk-plugin
2. 作者在终端跑 npm run publish（= linkdesk-plugin-sdk publish）
   · 预览 + 确认（--yes 可免交互；非 TTY 拒绝交互式确认）
   · 第一次要 PAT：环境变量 LINKDESK_GITHUB_TOKEN > SDK 配置档 > 交互式掩码输入并持久化
3. GitHub REST API：
   POST repos/{owner}/{repo}/releases 创建 Release（422 = tag 已占用，拦下）
   POST 上传 asset（.linkdesk-plugin）
   更新作者自己仓库根目录 marketplace.json（同 id 版本前插 + 同版本去重；Contents PUT 带 sha）
4. 返回结果："发布成功！几分钟后可在市场中看到。"
   → 想让所有用户默认看到，还要「上架第二步」：收录进官方目录
```

> 🔵 **退役前那条 UI 流程（存档备查，勿照做）**：点「发布插件」→ `dialog.open` 选 `.linkdesk-plugin` → 壳解压临时目录读 plugin.json 显示预览 → 确认 → 同一套 REST API 底座。底座与 CLI 完全同源，退役的是壳侧那个按钮与它的 token 配置面。

## 四、审视实锤（2026-08-30 第 2.2 轮——#26 自动发布拍板依据）

原 §3.3「不用 GitHub API——网页手动上传 + 手改 marketplace.json，v1.0 接受手动，后续迭代再自动化」——**「当前功能够了，等未来再加」话术，第 2.2 轮拍板否决（用户 2026-08-30 纠正）**。已删，改自动链路全自动。

### 4.2 自动发布链路（#26b/#26c 定型）

> 🔴 **2026-09-14 订正：入口只有命令行**（#26a/#26c 的 UI 面已按用户拍板退役），故下面的流程首行由「市场 UI 填 PAT」改为终端形态；底座本身一字未变（仍走同一套 GitHub REST API）。

```
作者在终端给 GitHub PAT（环境变量 LINKDESK_GITHUB_TOKEN > SDK 配置档 > 交互式掩码输入）
→ npm run publish → 选 .linkdesk-plugin
→ 预览确认（解压读 plugin.json → 作者/版本/图标）
→ GitHub REST API：
   POST repos/{owner}/{repo}/releases 创建 Release
   POST 上传 asset（.linkdesk-plugin）
   更新根目录 marketplace.json（加条目）
→ "发布成功！几分钟后可在市场中看到。"
```

**依赖：** 发布到作者自己的仓库（多市场源 §六，2026-08-17 用户拍板）——marketplace.json 在作者仓库根目录，别人添加该仓库为市场源即可发现。
