## 一、分发格式——一个 `.linkdesk-plugin` 单文件 zip

**LinkDesk 插件的交付形态 = 一个 `.linkdesk-plugin` 单文件**（zip 包，SDK 构建产物）。插件源码是一个普通目录（[09-插件目录规范](09-插件目录规范.md)），但**分发给用户/上架市场的永远是那个 zip**——整目录复制即安装的目录分发时代已结束（2026-09-05 塌平单根拍板）。

```
my-plugin/
├── <id>.linkdesk-plugin        ← 分发/安装/市场的唯一载体（zip）
│   ├── plugin.json             ← 改写克隆（contributes.views[].render → views/<View>.bundle.js）
│   ├── index.bundle.js         ← 主入口 bundle（loader 检测其存在即以 bundle 为运行时入口）
│   ├── index.bundle.css        ← 聚合样式
│   ├── views/<View>.bundle.js  ← 每个 contributes.views[].render 一次独立构建
│   ├── resources/ icon.svg 等  ← 资源随包
│   └── (themes/ assets/ i18n/ node_modules/ …)  按插件内容
└── src/ …                      ← 作者源码（不进 zip）
```

**谁产 zip：** [plugin-sdk](../../packages/plugin-sdk)（`npm run publish` 走 [E6 作者旅程](../02-Electron架构/E6_插件生态与发布/05-文档与发布/00-第三方作者旅程.md)）在**项目根**产 `<id>.linkdesk-plugin` + 解包目录 `dist/<id>.linkdesk-plugin/`。zip 内 JS 全部预构建自包含（react 系 external，壳提供）——**安装态没有源码编译**。

**为什么是单文件：** 壳 loader 对安装态插件只认预构建 bundle——`plugin-file-service` 检测到 `index.bundle.js` 存在即覆盖 entry 指向它（`resolveEntry`，bundle 入口恒 `index.bundle.js`）。zip 是「一个插件 = 一个可下载/可校验/可原子替换的文件」，装卸与市场下载都对着它。

> **源码目录 vs 分发文件是两回事：** 开发是目录（dev 源码树 HMR），分发是 zip（预构建产物）。别拿源码目录当安装载体，也别改 zip 里的 bundle 当热更——改了源码要**重 build + 重发**（见 §二 版本纪律）。

## 二、安装流程——zip → `{userData}/plugins/<id>/`

**安装目标恒为 `{userData}/plugins/<pluginId>/`**（`env.userPluginsDir`，{userData} = Electron `app.getPath('userData')`，Windows `%APPDATA%/LinkDesk`）。安装态**没有 builtin/user 双层**——随壳发货的插件与用户装的第三方在**同一棵树平铺并列**，差异只剩 manifest 字段（见 §三）。

**两条到达路径（同一条落盘路）：**

| 路径 | 谁 | 落点 | 语义 |
|------|------|------|------|
| **boot 自动装** | 随壳发货的 `bundled-plugins/*.linkdesk-plugin`（prod 在 `resources/bundled-plugins`） | `{userData}/plugins/<id>/` | 首启只补缺失；**永不覆盖已装**（同版异版都不动）；损坏目录视为缺失重装；`removed` 标记命中 → 不恢复（用户故意删的插件不复活） |
| **用户安装** | `pluginManager.install(url \| 磁盘 zip \| 目录)` | 同上 | 下载/解压/校验 → 落盘；目录源仅 dev 便捷用，分发主路是 zip |

**安装期校验（解压前拦截，不产生半装目录）：**
- zip 顶层定位 `plugin.json`（basename 匹配，容忍单层 wrapper 目录）——JSONC 解析（#55）
- `pluginId` 裁决：manifest 优先、zip 文件基名兜底，双源互验；必须过安全字符集（无路径分隔符/相对段）
- zip-slip 防护——条目路径拒绝逃逸解压目标
- 目标已装同版本 → 跳过（用户安装删源）；异版本 → 不动（升级是更新流职责，boot 不覆盖）

**开发/示例插件例外：** repo `plugins/<id>/`（`env.appPluginsDir`）是**源码树**，dev 下 Vite 即时编译 + HMR（`npm run dev` 热更）。它不进 zip、不落 userData——除非你把它打进 `bundled-plugins/` 随壳发货。两套代码根别混：

| 代码根 | 位置 | 形态 | HMR |
|------|------|------|:--:|
| repo 源码树 | `<repo>/plugins/<id>/` | 源码 + Vite chunk | ✅ |
| 安装态 | `{userData}/plugins/<id>/` | zip 解出的预构建 bundle | ❌（改包需重 build + 重装/重物化） |

> **卸载语义（2026-09-05 后）：** 安装态插件卸载 = **删 `{userData}/plugins/<id>/` 目录 + 账本销账**（不再是 `.disabled/` 移入）；只有 repo 源码树里的 app 插件卸载才移 `plugins/.disabled/` 坟场（可 reinstall 恢复）。账本 `installed-plugins.json` 唯一 owner = 渲染进程 PluginInstallService，boot 只读它的 `removed` 标记防误恢复。

## 三、目录分类——没有「内置/用户」两类，只有字段

**插件只有一类。** 安装态全在 `{userData}/plugins/<id>/` 平铺，身份差异全在 plugin.json 声明字段，不在目录：

| 字段 | 语义（唯一真相） |
|------|------|
| `core: true` | **UI 防误删旗标**——卸载按钮不显示/禁用（外壳依赖它提供设置页/市场等基础交互，删了壳就残）。**不是类别、无行为特权**——加载/装卸走同一条路 |
| `distribution` | ⚠️ **遗留字段**（schema 已标注）——塌平后不再对应任何目录，安装侧恒归一化为 `user`。**第三方插件请勿填写** |

措辞纪律（硬约束 11）：不叫「内置插件 vs 第三方插件」两类——说「**core:true 的插件**」（不可卸）与「**随壳发货的插件**」（bundled zip 里那份）。repo 现况：core:true 的 = `editor` `file-tree` `marketplace` `settings`；随壳发货 = [bundled-plugins/](../../bundled-plugins/) 18 个 zip（dev 示例 `floating-panel-demo` `panel-demo` 只在 repo，不进发货集）。

**插件数据目录（与代码根独立）：**

| 路径 | 用途 |
|------|------|
| `{userData}/linkdesk/plugins/<id>/data/` | 插件持久化数据——唯一可写目录 |
| `.../data/cache/` | 缓存（可安全删除） |
| `.../data/exports/` | 导出文件（用户可见） |

> 🔥 **两个 "plugins" 根别混：** `{userData}/plugins` = 代码根（zip 解压处，`userPluginsDir`）；`{userData}/linkdesk/plugins` = 数据根（`pluginsRootDir`）。卸载重装**不清数据**——数据在独立数据根。作者经 `window.linkdesk.env.get("<id>")` 拿 `pluginDataDir`（含 pluginId 才返回），壳自动建目录，插件无需自建。

## 四、版本兼容

### 语义化版本 + 更新路

`version` 遵循 semver（`major.minor.patch`）。**boot 永不刷新已装插件**（bundled 夹 = 首启离线种子，非更新通道）——已装用户拿新内容只有一条路 = **更新流**：`pluginManager.checkUpdates`（fetch catalog + semver 对比）→ `update`（stage 到 tmp → 原子替换 → 失败退旧版）。市场真实条目按版本发现更新。

### 🔥 内容变更必 bump 自身 version（2026-09-06 #15n 定案）

**分发过的插件，任何内容变更（代码 / 资源 / README / CHANGELOG）都必须 bump `plugin.json.version`。** 已装用户的副本是**按版本固化**的——boot 只补缺失、永不刷新已装；用户拿到新内容的唯一路 = **版本号**。改内容不 bump = 已装用户永远滞留在旧内容（2026-09-06 实证：bundled 发货 zip 加了 pyright 没 bump → 已装副本 LSP 全挂）。

**随壳分发的 bundled zip 同理**：重打 zip 内容变更必 bump——`npm run check` 的打包 gate 会在「同版内容 diff」时红拦（`scripts/check-bundled-version-bump.mjs`）。已装用户拿 bundled 内容修复 = 走市场真实条目（E6#26b）按版本发现/更新，**boot 不伸手**。

### minAppVersion / requires / permissions

三者 schema 均已声明（见 [03-contributes](03-插件contributes规范.md)），安装期不强制——语义与 [02 生命周期 §九](02-插件生命周期.md) 对齐：

- `minAppVersion` —— 加载期校验（不满足 → toast + 跳过）
- `requires` —— 运行期依赖编排生效（缺依赖挂起 PENDING + 环 fail-loud + 连带卸载逆拓扑，见 [02 §四](02-插件生命周期.md)）
- `permissions` —— 声明即用户知情，授权模型待 E6

## 五、资源路径——相对插件目录，壳解析（硬约束 12）

**🔥 禁止硬编码绝对路径。** 插件内资源（图标/图片/字体/任何资产）引用 = **相对插件目录的声明式路径**，壳加载时解析为当前协议下的绝对 URL（icon 走 `resolvePluginIcon`、`contributes.views[].render` / 资产走 `getPluginAssetPath`）——兼容 dev `http://localhost:1420` 与打包后 `file://`。**作者不 import 路径工具、不手拼 URL。**

```jsonc
// ✅ 正确——声明相对路径，壳解析（dev 与打包版通吃）
{ "icon": "resources/logo.png" }
// contributes.views[].render 同理： { "render": "src/views/MainView.tsx" }

// ❌ 错误——绝对路径字面量，打包后 file:// 下解析炸裂
// { "icon": "/assets/logo.png" }
```

> **dev 能跑是巧合**（http 服务把绝对路径兜住了），打包后 `file://` 才现形。需要自渲染资源时走声明路径由壳解析，见 [09 §静态资源](09-插件目录规范.md) 与 [01-插件API契约](01-插件API契约.md)。

## 七、开发 → 分发全流程

```
1. 开发（自己的项目 or repo plugins/<id>）
   写 plugin.json + src/ → 源码树跑 → HMR 即时热更新

2. 构建（第三方发布前）
   用 plugin-sdk（见 00-第三方作者旅程）→ 产 <id>.linkdesk-plugin

3. 分发
   交付 <id>.linkdesk-plugin 单文件 → 用户安装 / 上市场

4. 安装
   pluginManager.install(url | 磁盘 zip) → 校验 → 解压到 {userData}/plugins/<id>/
   → 重启或即时加载 → 图标出现

5. 更新
   内容变更必 bump version → 重 build 重发 → 用户 checkUpdates/update
```

## 八、与 VS Code 对照

| LinkDesk | VS Code |
|------|------|
| `.linkdesk-plugin` 单文件 zip（下载/解压到 `{userData}/plugins/<id>/`） | `.vsix` 单文件（下载/解压到 `~/.vscode/extensions/<id>/`） |
| `{userData}/plugins/<id>/` 安装目录（平铺单根） | `~/.vscode/extensions/<id>/` |
| `core: true` 插件不可卸（防误删旗标） | `builtin/` 内置扩展 |
| 卸载 = 删目录 + 销账（真删）；源码树 app 插件才移 `.disabled/` | 卸载 = 删文件（不可恢复） |
| `env.get(id).pluginDataDir` | `ExtensionContext.storagePath` |
| `core: true` 插件发货 = `bundled-plugins/*.linkdesk-plugin`（首启种子，非更新通道） | 随应用更新（安装包内置） |
| `requires` **运行期**依赖编排（[02 §四](02-插件生命周期.md)） | `extensionDependencies` 安装期解析 |
