# 04-两层调节与设置页（主题配方 vs 软件设置）

> **状态：** 拍板（2026-08-23）——玻璃连续 scale、全局 scale 系数、设置页主题区

## 1. 两个来源

| 层 | 来源 | 作用 | 持久化 |
|:--|:--|:--|:--|
| **主题层** | theme.json `appearance` 段 | 整套外观配方（字体/圆角/玻璃/背景图），缺的域继承默认 | 主题文件内，换主题即换配方 |
| **设置层** | 设置面板 slider/加减 | 用户对个别外观项的**覆盖**（圆角、玻璃透明度/模糊、字体…） | workspace.json 配置 |

## 2. 玻璃是连续 scale，不是二元开关

> 用户问：「玻璃是开关形式还是主题形式？」——两者不矛盾。

- **主题层**：主题自带玻璃效果（`--glass-blur: 20px` 等，配方一部分）
- **设置层**：全局拉强度，**拉到 0 = 关**
- 一个滑杆到底就是开关，不用额外二元开关

## 3. 优先级——对标 accentMode 先例

复用已有 `app.accentMode: "followTheme" | "custom"` 模式：

- **followTheme（默认）**：用主题值
- **custom**：用户设置值覆盖主题值

对应外观配置（#50.10）：`app.appearanceMode` 一词 + 具体项（`app.surfaceRadius` / `app.glassOpacity` / `app.glassBlur` / `app.fontFamily`）在 custom 时覆盖对应 token。

## 4. 覆盖粒度（拍板：全局系数 scale）

**主题作者管精致（per-surface 精调），普通用户管粗调（一个全局滑杆）。**

- **主题层** = per-surface 绝对值（每表面单独定义 6/8/12px）
- **设置层** = 全局**缩放系数** `--radius-scale` / `--glass-scale`（默认 1.0），不是绝对值
  - 例：×1.5 → 6/8/12px 变 9/12/18px，**相对差异保留，一个 slider 整体缩放**
  - 对标系统缩放 / 浏览器 zoom；避免绝对值覆盖压扁主题的 per-surface 差异
  - CSS 不能 `var * var` → ThemeEngine 在 applyTheme 时用 JS 把每个 radius token 乘 scale 再写入（`6px * 1.5` 内联 calc 或直接算好写死）。slider 一动 → 重写全部 radius 变量
- 用户心智 = 「让界面更圆润一点」，不是「把对话框圆角改成 14px」

## 5. 设置页主题独立建区

设置页加「主题」区，与通用区并列。纯 UI 层，不依赖 #48 factoryRole 拍板。建议立案为 #50.10 的一部分或独立小任务：

- 主题选择器 + 实时预览（ThemeBrowser 已有基础）
- 玻璃/圆角强度滑杆（设置层，走 §4 scale）
- 「选择图片」按键（#50.11）
- 混搭板块（排期靠后，域契约后，见 [03](03-域贡献者与混搭.md) §5）

## 6. 强调色与主题 token——主题可用自有 token 摆脱强调色

> 用户点：「有的主题比较特殊，胶囊开关是彩色形式，理论上不受强调色限制。」

- 强调色机制（accentMode）只覆盖 `--accent`/`--accent-hover`/`--accent-light` 三个变量
- **主题只要不消费 `--accent`、用自己定义的彩色 token（如胶囊开关的 `--toggle-on-bg: 彩虹色`），强调色就管不到它**——token 自由定义的自然结果，非新能力
- 文档写明约定：**主题作者想摆脱强调色 = 用自己的 token，不读 `--accent`**
