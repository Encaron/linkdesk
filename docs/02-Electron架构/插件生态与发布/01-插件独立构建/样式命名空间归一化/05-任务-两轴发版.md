## 一、为什么要发 SDK（不是顺手）

`@linkdesk/plugin-sdk` 的 `files` 含 **`schemas`** ⇒ `reserved-class-names.json` **是包内容**。四批改名把它摘成了空 `classes.shared`，于是：

- `npm run check:npm-release` **亮黄灯**（内容漂移但版本没动）。黄灯**永不 fail**（脚本头三行写死），但**本任务就是来关它的**；
- `npm run release:mark` 在漂移未 bump 时**拒绝记基线**（保护，不是提醒）⇒ **不 bump 就发不出去、也记不上账**。

⇒ 所以本任务是**两个包**，不是只有 ui。

---

## 二、步骤（照 runbook 五步走）

1. **改版本**：
   - `packages/linkdesk-ui/package.json`：`0.1.7` → **`0.2.0`**（0.x 阶段：破坏性变更走 **minor** 位——共享组件类名变了，作者侧 scoped 调优会失配）；
   - `packages/plugin-sdk/package.json`：`0.1.21` → **`0.1.22`**（PATCH：清单数据变化，判据逻辑未变）。
2. **刷 lock**：`npm install --package-lock-only`（⚠️ 升 `packages/*` 版本号后**必须**同笔刷 lock，否则 `check:lockfile-sync` 红）。
3. **先跑一次 pre-commit**：`git add` 之后、`npm publish` **之前**跑一次（runbook 坑④：尾空行会被钩子抓、trim 后内容又漂 ⇒ 会白发一位）。
4. **发布**（🔴 形状要对）：
   - `cd packages/linkdesk-ui && npm publish --registry=https://registry.npmjs.org`
   - `cd packages/plugin-sdk && npm publish --registry=https://registry.npmjs.org`
   - ⚠️ **不要**用 `npm publish <文件夹>`——本仓实测它会被当成「包规格」去解析货架上**别人**的同名包（runbook 坑②）；
   - ⚠️ 两个包都有 `prepack` 钩子 → 发布前自动 build，**不需要**手动 build；但 `linkdesk-ui` 的 `dist` 若在 `git status` 里显示为改动，**照常提交**（它是产物、随包走）。
5. **记基线**：`npm run release:mark`（**过货架核对**：逐包三关，任一不过即拒绝该包且整批不落盘、exit 1）。
   - 货架有约 **3 分钟复制延迟**（runbook 坑③）——刚 publish 完立刻 mark 可能拿到 404，等一下再跑。
6. **提交** + 推送（用户已授权推送）。
