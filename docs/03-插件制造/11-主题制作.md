# 11-主题制作（第三方主题插件作者指南）

> **状态：** 定稿（2026-08-23）——schema 已冻结（[05](../02-Electron架构/E5.8_归一化基建/外观主题化/05-主题数据模型.md) 决策 A-F）。
> **一句话：** 主题 = 插件的一种——一个配方 json（风格域 + 配色变体）+ 可选资产；「域贡献者」缺的域继承默认，写得越少越稳。
> **ai化 = AI 友好度：** 本文读者 = **人类 + AI**——AI 读本文能产出合法主题文件，AI 读示例主题（如迁移后的 mint-soda）能仿造同类。schema 每个概念只有一种写法（决策 F：一律 `colorways[]`）。

## 1. 主题插件是什么

- 主题是**插件**（硬约束 10：壳不写死任何插件 id，主题也走 plugin.json 声明）。
- 一个主题插件 = 1 个配方 json（`appearance` 风格域 + `colorways[]` 配色变体）。也可包含多个配方 json。
- **域贡献者**：只写你拥有的域，缺的继承壳默认（[03 域贡献者](../02-Electron架构/E5.8_归一化基建/外观主题化/03-域贡献者与混搭.md)）——纯配色主题 = 只写颜色；玻璃主题 = 写玻璃 + 颜色。
- **风格 vs 配色分离**：想要「1 个风格基座 + N 个配色」→ 一个配方里放 `colorways[]`（[05 §2](../02-Electron架构/E5.8_归一化基建/外观主题化/05-主题数据模型.md) 完整 schema）。

## 2. 三步写一个主题

### ① plugin.json 声明

```jsonc
// plugin.json —— 主题声明走 contributes.themes（对标 VS Code，schema 权威见 plugin.schema.json）
{
  "id": "theme-myglass",
  "name": "我的玻璃主题",
  "version": "0.1.0",
  "contributes": {
    "themes": [
      { "id": "myglass", "label": "My Glass", "uiTheme": "dark", "path": "themes/myglass.json" }
    ]
  }
}
```

### ② 配方 json（引用 05 schema）

```jsonc
// themes/myglass.json —— 见 [05 §2](../02-Electron架构/E5.8_归一化基建/外观主题化/05-主题数据模型.md) 全量 schema
{
  "id": "myglass", "name": "My Glass", "type": "dark",
  "appearance": {
    "radius": { "md": 10, "lg": 16 },
    "glass": { "blur": 16, "saturate": 1.3, "tint": "rgba(255,255,255,0.06)", "opacity": 0.9 },
    "font": { "ui": "assets/MyFont.woff2", "mono": "JetBrains Mono" },
    "background": { "image": "assets/bg.png", "opacity": 0.85, "mask": "rgba(0,0,0,0.3)" }
  },
  "colorways": [
    { "id": "violet", "name": "紫罗兰", "colors": { "bg-window": "#0E0B16", "accent": "#8B5CF6" } },
    { "id": "emerald", "name": "翡翠", "colors": { "bg-window": "#0A1410", "accent": "#34D399" } }
  ]
}
```

> **单配色主题** = `colorways` 数组只含 1 项（例：官方主题 dark 迁移后 = `colorways: [{ id:"dark", name:"Dark", colors:{…} }]`）——**没有第二种写法**（决策 F）。

### ③ 资产（可选）

- 字体/背景图挂在插件目录，json 里写**相对路径**（`assets/...`）——渲染时壳用 `getAssetPath(pluginId, path)` 统一解析（硬约束 12）。**禁止写 `/assets/...` 绝对路径。**
- 字体两种形式：①资产路径（随插件分发）②系统字体族名字符串（用户机器上已有的）。

## 3. 避坑

| 坑 | 说明 |
|:--|:--|
| 写顶层 `colors`（无 `colorways`） | **旧格式已弃**（决策 F）——引擎只读 `colorways[]`；单配色也写数组 1 项 |
| 写绝对路径 | 打包后 `file://` 全炸——一律相对路径 + getAssetPath |
| 重复写全部颜色 | 稀疏覆盖 = 只写差异键，未写继承 `:root`，更稳 |
| 想摆脱强调色 | 用**自己的 token**（如 `--toggle-on-bg`），不读 `--accent`（[04 §6](../02-Electron架构/E5.8_归一化基建/外观主题化/04-两层调节与设置页.md)） |
| 大 blur 值 | `--glass-blur` 有性能上限（大面积 backdrop-filter 是 GPU 负担）——契约会写明数值（[02 §2.3](../02-Electron架构/E5.8_归一化基建/外观主题化/02-变量契约.md) 待拍板） |

## 4. 主题制作者能拿到什么

- 数据：`window.linkdesk.theme.listRecipes()`（含配色/预览色）——第三方 UI 也可以消费（[06 §6](../02-Electron架构/E5.8_归一化基建/外观主题化/06-主题API契约.md) 待拍板 3：通用 API 优先复用）。
- 应用：`setRecipe`/`setColorway` 或直接写 `app.theme` 配置。
- 事件：`theme:changed`（payload 带 tokens），做实时联动。
- 混搭：你的主题按贡献的域（`RecipeMeta.domains`）自动出现在设置页混搭来源里，**作者零额外工作**（[10 §2](../02-Electron架构/E5.8_归一化基建/外观主题化/10-混搭设计.md)）。

## 5. 迁移（现有主题插件——决策 F：零向后兼容）

引擎**只读新格式**（`colorways[]`），旧格式平铺不再兼容读（[05 §5](../02-Electron架构/E5.8_归一化基建/外观主题化/05-主题数据模型.md)）。现有主题插件改造：

| 插件 | 现状 | 迁移后 |
|:--|:--|:--|
| `theme-defaults` | dark.json + light.json（平铺 colors） | 单配方 json：`colorways: [{id:"dark",…},{id:"light",…}]` |
| `theme-mint-soda` | 4 json（mint-soda/mint-dew/sea-salt-mint/lime-mint） | 1 配方 json = 4 colorways（theme 列表收 1 卡片，推荐） |
| `theme-twilight-forest` | 4 json（green/purple/sunset/teal） | 同上 → 1 配方 4 colorways |

改造 = **纯数据编辑**（把 `colors` 包进 `colorways[]` 数组），不动引擎。合并后 theme 选择器列表更清爽（1 卡片多配色 vs N 卡片）。
