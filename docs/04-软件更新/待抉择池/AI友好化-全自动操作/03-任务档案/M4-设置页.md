## 零、机制实证（本会话实测 · 开工前必须知道）

### 0.1 「AI 接入」怎么才能**真的**出现在左导航（用户担心的就是这一条）

**实测（逐字）** `settings:src/views/SettingsView/loadSettingsData.ts:32-37`：

```ts
for (const [pluginId, contrib] of contributions) {
  const keys = Object.keys(contrib.properties ?? {});
  if (keys.length > 0) {
    result.push({ pluginId, title: t(contrib.title ?? pluginId), keys });
  }
}
```

**即：导航项 = 一个 `pluginId` 一项**（渲染处 `settings:src/views/SettingsView/SettingsView.tsx:201-215`，以 `g.pluginId` 为 key，计数徽标 `:213` = **该组键数**）。

**先例（壳自己就是这么干的）**：`src/App/config/appearance.ts:55-56` = `registerConfiguration("appearance", { title: t("主题"), … })` ⇒ 左导航**多出一项「主题」**。

⇒ **可执行结论**：新建 `src/App/config/aiBridge.ts`，内写

```ts
registerConfiguration("ai-bridge", { title: t("AI 接入"), properties: { … } })
```

⇒ 左导航**必然**长出「AI 接入」。**零插件改动、零新机制**（`settings` 仓一行不用动）。

⛔ **反例（这一步踩了，用户担心的事就真的会发生）**：若把 AI 的键挂到**已有宿主身份 `app`**（`APP_PLUGIN_ID`）上，键会并进**「通用」**那一项里（`update.ts` 就是这么并进去的，见其头注「并入『通用』组」）——**左导航永远不会出现「AI 接入」**。⇒ **独立 `pluginId` 是硬要求，不是风格偏好。**

🔴 **计数徽标**：mockup 写「**4 项**」，实测徽标 = **声明键数**（`SettingsView.tsx:213`）。本档按 mockup 逐项展开约 **13 条键** ⇒ 徽标实际会是「13 项」这一类数字。**mockup 的「4」是示意值** ⇒ 归 §三 **P-1** 拍板（⛔ 不许为了凑「4」把项砍掉）。

### 0.6 🔴 控件选型原则 ＋ **P-2 / P-3 已拍板**（用户 2026-09-28）

**用户原话**：「设置页的调试配置项的 UI 逻辑**尽量不要复杂**，大多符合**开关、下拉、按钮、slider** 等等基础的就行，当然如果**必须要新控件**才能实现某些，那也可以。因为当时**文件树使用的那个 ignore 控件就让我挠头了**，不怎么会用当时。」

⇒ **控件选型原则**（本档与 `AI#38.12` 的选型判据，⚠️ 开工时逐条对照）：

1. **基础形优先**——开关（`type:"boolean"`）／下拉（`enum`）／按钮（`renderHint:"action"`）／数值／slider：**能用这些表达的一律用这些**（§0.2 全表）。
2. **一个新控件形只在「基础形表达不了」时才加**，且必须**一眼看懂**（不用读手册就会用）。
3. 🔴 **反例（前车之鉴）**：`file-tree` 的 **ignore 控件让用户挠头** ⇒ **「能实现」不等于「能看懂」**——本系列凡新增控件形（`AI#38.12`），验收里必须含**「不读文档会不会用」**这一问（⛔ 不许只验「渲染出来了」）。

**已拍板（P-2 ＋ P-3 一起，用户 2026-09-28）**：

- **P-2 = A**：加**通用只读状态行**控件（`AI#38.4` 消费，「运行中 · 127.0.0.1:9333」这类状态**真实可见**）——⛔ **不降级**进 ⚙ 详情。
- **P-3 = A**（用户原话：「你推荐的 P2 是 a，那自然 P3 也是 a 呀」）：加**分节副标题 / 行内小字**能力（`AI#38.2` 消费：「读」「做」「管外不管内」「仅本机回环」）。
- ⇒ **两形同批交付**（同一次跨仓发版）＝ 归 `AI#38.12` 一格做；⚠️ 走 `design-flow` 8 维 ＋ **先画 HTML 交用户拍板**（硬约束 16）。
- ⚠️ **与上述原则的相容性**：这两个形都**比开关更简单**（一行只读文字／一行小标题），不是复杂交互控件 ⇒ 合规；但**样式必须克制**——**不做可点、不做悬停花活，就是文字**（⛔ 别做成第二个「挠头控件」）。
- ⚠️ **配套**：`AI#38.12` 跨仓发版后要**取现场证**（读消费者 `node_modules` 版本 ＋ 塞违规看它红），⛔ lock 钉版 = 假绿（记忆《发布 ≠ 生效》）。
