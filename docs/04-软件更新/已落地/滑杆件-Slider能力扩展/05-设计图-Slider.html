读法：① 先看现状（今天这两根滑杆各长什么样）② 再看三 props 正表 ③–⑤ 是四种方位、细调、挤窄三组现场（本页可拖可点，键盘也能走）⑥–⑧ 是亮暗／字号／实测对比度 ⑨ 是声明链（谁声明、谁传递）⑩ 是落地判据。

① 现状：今天的两根滑杆，值标签不属于组件

组件本体是一根裸 <input type="range">，自带 130px 固定宽、4px 圆角轨道、12px 圆点 thumb；「当前值＋单位」那块文字住在设置仓的包裹层里（settings-slider-control ＋ sliderValueLabel.ts）。所以同一根滑杆，在设置页和在任何别的地方长得不一样。

A · 脱离设置插件：组件自带宽度 130px，没有值标签，没有细调（＝第三方插件今天拿到的全部）

② 新能力正表：三个 prop，全部可选，不声明＝旧版

prop类型缺省语义（D1–D3 定稿）
unitstring无单位文案（px／ms／FPS／×／毫米…由声明者自定）。声明了才有标签（D6）：未声明 ＝ 不渲染标签（＝① 那根裸滑杆）；"" ＝ 有标签、无单位（＝④ 玻璃不透明度那行的 0.5）。⚠️ 空串 ≠ 未声明
unitPosition"before" | "after" | "above" | "below""after"标签方位。before/after 贴「按钮对」外侧（before 在 − 之前、after 在 ＋ 之后，与轨道同一行）；above/below 脱离行内流、整行居中压在轨道中线上、不挤轨道。配置键一律用缺省 after
stepperbooleanfalse轨道两侧 −/＋ 真按钮，常驻（D2）；单击单发、按 step 步进、min/max 夹取、触边置灰；不声明则一个 DOM 都不多

能力归属（D3 口径）：单位与步进都是 Slider 组件自带的常驻能力——任何使用方声明即显、不声明即无。设置仓与任何渲染方都只传递、不决定。⛔ 不存在「某个使用方硬写 stepper」这种做法。

③ 单位值标签：四种方位现场

值标签文案 ＝ 迁入组件的 formatSliderValue（继承 E5.8#77：× 走倍数去尾零、其余单位数值去尾零后接后缀、无单位裸数值）。方位＝标签绕着轨道转：before/after 落在「按钮对」的外侧（before 在 − 之前、after 在 ＋ 之后，与轨道同一行、垂直居中），above/below 脱离行内流、整行居中压在轨道中线上。下面能改单位文案、能换方位，四个方位是同一根滑杆的同一份状态。

④ 细调：常驻两侧、单击单发、触边置灰

−/＋ 是辅助通道，不接管拖拽——原生 range 的键盘与无障碍一个不动。按钮按 step 步进、按 min/max 夹取，值触边时对应按钮置灰（「点了没反应」是可用性缺陷）；disabled 时滑杆与按钮一起灰。

⑤ 挤不挤：三种控制列宽度 × 三档字号

⑦ 键盘：一行三个 Tab 站，焦点环必须看得见

顺序是 Tab − → Tab 轨道 → Tab ＋（＝视觉顺序，从左到右同一条线）；轨道上 ←→（及 Home/End/PageUp/PageDown）按 step 走，−/＋ 上 Enter/Space 单击单发。焦点环走 --accent、outline-offset:2px。

已知代价（02 E5）：一行从 1 个 Tab 站变成 3 个，设置页现有 8 根滑杆 ⇒ 键盘用户的 Tab 次数明显变长。这是买「细调可达」付的价，接受；⛔ 不许用「按钮不可聚焦」去省这一步。

⑨ 声明链：谁声明、谁传递、谁渲染

这张图是 D3 更正后的口径。要点：能力在第三格里，前两格谁都不造能力——第一格只写「我要这个能力」，第二格原样搬运。

① 声明者

  • 壳：外观键在自己的配置声明上写 unit／stepper（第一批使用者）
  • 插件作者：自己 package.json 的配置键上写同样两个字段
  • 自绘界面：直接在 JSX 上传 props

② 传递者（零知识）

  • 宿主 config API：把属性对象交给设置面
  • 设置仓 renderControl：<Slider unit={prop.unit} stepper={prop.stepper} … />
  • ⛔ 它不判键名、不做决定、不再自己画标签（包裹层删除）

③ 能力本体（Slider）

  • 值标签格式化 ＋ 四方位排布
  • −/＋ 按钮、夹取、置灰、aria
  • 声明就显、不声明就没有

🔴 这一格是拍板时顺带挖出来的：unit 此前从未进过作者面 schema（public/schemas/plugin.schema.json 里出现 0 次，而配置属性对象是 additionalProperties:false）⇒ 第三方作者今天写 unit 会被校验打红——「单位由插件作者自己决定」此前只对壳成立。所以声明面要两处同笔补：宿主 ConfigProperty ＋ 作者面 schema（含 docs/03-插件制造/ 与 packages/plugin-sdk/schemas/ 两份字节拷贝），并随 plugin-sdk 发版才到作者手里（02 E10/E11）。

⑩ 落地判据（照 01 §四）

  1. 旧观感零回归：设置页现有滑杆键不声明新 props 的过渡期，逐键目视＝现状。
  2. 新能力四形态：after／before／above／below ＋ stepper ＋ 组合，各一现场。
  3. 键盘全链：不碰鼠标能改到值（本节 ⑦ 的顺序）。
  4. 脱离设置页成立：任一非配置页场景直接 <Slider unit="ms" stepper /> 成立。
  5. npm run check 全绿（含 api-surface-additive）＋ token 快照——标签与按钮零硬编码。
  6. 第三方声明链通：作者 schema 补齐后，插件声明 unit＋stepper 能长出控件。

本图未决、已记录的边缘项：值标签与设置行行尾生效值徽标可能同屏两个数字（02 E1，归「设置行」案统筹）；组件根节点由「一根 input」变成「一个包裹盒」（02 E13）——.settings-slider-control .ldk-slider{flex:1} 靠后代选择器仍匹配，但 130px 固定宽要让位给可伸缩。
