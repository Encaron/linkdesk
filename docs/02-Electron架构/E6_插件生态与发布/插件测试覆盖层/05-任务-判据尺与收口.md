## §一 `E6#153` 判据尺：`scripts/audit-plugin-tests.mjs`（只报不拦）

### 前因

- 本层立案的**第二件真缺口**（[总纲 §〇c](00-整理档案.md)）：**没有判据、没有尺子**——`ci-verify.mjs` 五段全是结构/声明，没有一段问「测试」。所以哪怕会话一~四把测试补齐了，**下一条新插件、下一次改动**也没人接着问这个问题 ⇒ 「虚掩的门」会自己再关上。
- 先例现成：L8 立的 `scripts/audit-plugin-dead-css.mjs`——**审计类只报不拦**，且**不在** `scripts/check-gate-health.mjs` 的域里（那域只认 `scripts/check-*.mjs`）⇒ **新审计脚本不需要自测接线**，也不需要进 `npm run check`。
- ⛔ **为什么不做「拦」**：判据本身还在长（结构判据 vs 百分比，见 06 待拍板 ②），且「够不够」是作者自己的事（作者面原则：**只给尺子、不判死**）。先跑一段时间，读数站稳了再谈拦。

### 修哪里

| 文件 | 改什么 |
|:--|:--|
| `scripts/audit-plugin-tests.mjs` | **新增**（唯一的新文件）；纯读盘、零写盘、退出码恒 0 |
| `package.json`（壳仓） | `devDependencies` 不动；`scripts` 加一行 `"audit:plugin-tests": "node scripts/audit-plugin-tests.mjs"` |
| `CLAUDE.md` | 开发命令段加一行 `npm run audit:plugin-tests` ＋ 半句说明「只报不拦」 |
| ⛔ 不动 | `ci-verify.mjs`（18 仓 CI）· `check-gate-health.mjs` · `sync-plugin-ci.mjs` · 任何插件仓 |

### 怎么修（脚本规格——照这份写）

**1. 扫描域**：容器 `E:\linkdesk-plugins` 下 **19 个仓**（5 个视图/逻辑仓 ＋ 12 个纯声明式 ＋ `python` 空壳 ＋ 第三方 `geme-tihu-bicycle`）。
- ⛔ **只读**，永不写（`geme-tihu-bicycle` 是别人的仓——**读它、报它、不碰它**）。
- 仓清单来源：与 `scripts/sync-plugin-agents.mjs` 的 18 官方仓清单**对照**（会话一刚同步过 AGENTS.md ⇒ 那份清单是新的），第三方仓单列。

**2. 判据（与 [总纲 §〇b](00-整理档案.md) 口径逐字同源——把那段定义抄进脚本头注，附本层立案日期）**：
- **生产行** = `src/**/*.{ts,tsx,css}`（含尾换行，与立案读数同法）；
- **纯逻辑单元** = `src/**/*.ts`，**排除**：`.d.ts`、`.test.ts(x)`、barrel（`types.ts` / `index.ts` / `constants.ts`）、文件名以 `use` 开头的 hook、以及**内容含 `window.linkdesk` 或 React 导入**的文件；
- **覆盖命中（两条任一即算）**：① 存在同名测试文件 `**/<单元名>.test.ts(x)`；② 任一测试文件里**出现了该单元的引用**（`grep` 其相对路径或模块名）。
  🔴 **两条都要实现**——只做 ① 就是立案读数里那种**假红**（`FileTreeModel/*` 被 `FileTreeModel.test.ts` 覆盖的教训）；
- **输出要求**：每个「零测」项标注**它是靠哪条判据判出来的**（`basename-miss` / `reference-miss`）＋ 在报告尾部打印一句**裁决提示**：「零测 = 待裁决，不是判死——同名判据看不见跨文件覆盖，请逐条核」；
- **声明式仓豁免**：无 `src/` 或无逻辑代码 ⇒ 报「不适用（声明式）」；`python` 仓照其 entry 头注自述（零逻辑）同样豁免——**豁免要有据**（脚本里写清凭什么豁免，别写白名单硬编码一句「skip」）；
- **⛔ 不做**：覆盖率百分比、阈值、红/黄灯、CI 接线、任何写盘。

**3. CLI**：`node scripts/audit-plugin-tests.mjs`（人类可读表）＋ `--json`（给以后别的工具吃）。表列：`仓 | 生产行 | 测试行 | 纯逻辑单元 | 零测单元 | 零测名单（前 N 个 + …）`。

**4. 实跑一次并留读数**：19 仓全表跑出来，与 [总纲 §〇b](00-整理档案.md) 的立案读数逐仓对照——**预期**：5 个视图仓的「零测」从立案数（16/11/6/3/15）掉到 **0 或只剩登记项**；12 声明式仓全部「不适用」；`geme-tihu-bicycle` **照原样报出**（本层不动它，见 06 ③）；`python` 不适用。
- 若某仓读数**与预期不符** ⇒ 不许改脚本去凑数字：先判断「是尺子错还是仓真缺」，写进收口报告（这正是「尺子第一次上场」的意义）。
- ⚠️ **别加 `--coverage`、别装 `istanbul`/`c8`**：口径是**结构判据**，不是行覆盖（06 ② 待拍板）。
