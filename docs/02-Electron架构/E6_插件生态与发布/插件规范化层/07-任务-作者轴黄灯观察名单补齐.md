# 07 · 任务 `E6#110`：作者轴黄灯「观察名单」补齐——`@linkdesk/ui` 的表面要接上产物真源

> **一句话**：`check:npm-release` 给 `@linkdesk/ui` 登记的观察名单盯的是 `packages/linkdesk-ui/src/**`——**那目录里只有一个 barrel**；真正进包的内容住壳仓 `src/components/shared/**`，**不在名单里** ⇒ **改共享组件不会点亮黄灯**（静默漏发）。
> **前置**：无（独立任务，与样式命名空间归一化系列无依赖）。承本层 [06 档 §三·五 G4](06-门禁扩域与验收.md)（**装灯**）与 §三·六 G5（**清积压**）——本条是 G4 那盏灯的**名单补正**。
> **规模**：`scripts/check-npm-release.mjs` 一处 surface 定义 ＋ 一条覆盖面断言 ＋ 重记 ui 基线 ＋ 文档一句。
> **提交轴**：scripts（**不 bump**——不是软件侧代码）。
>
> **非新能力声明（`check-design-flow` §8.4 ③）：** 本档是**既有门禁的覆盖面补正**，不新增能力。⇒ **无需新能力设计前置**。

## 一、事实（2026-09-15 实测，第 1.13 轮复核仍在）

| 面 | 现状 |
|:--|:--|
| **名单上写的** | `["packages/linkdesk-ui/src/**", "packages/linkdesk-ui/README.md"]`（`scripts/check-npm-release.mjs:120` 的 `PACKAGES[].surface`；该定义由 [06 档 §三·五 G4](06-门禁扩域与验收.md) 立） |
| **那目录里实际有什么** | **1 个文件**：`packages/linkdesk-ui/src/index.ts`（barrel） |
| **真正进包的内容** | 壳仓 **`src/components/shared/**`**——由 `packages/linkdesk-ui/scripts/build.mjs` 现场编译（`files: ["dist"]` ＋ `prepack`） |
| **为什么这样设计** | "改公共导出面只改 `src/index.ts` 一处"（build.mjs 头注）——**导出面**与**内容面**是两个东西，而名单只登记了导出面 |

**后果（实证，不是推演）**：第 1.9 轮四批改名（8 个共享组件全改）**只点亮了 SDK 一根黄灯，ui 一次都没亮** ⇒ `@linkdesk/ui` **0.2.0 是人主动想起来才发的**；若无那轮任务书，**这一整轮的劳动第三方作者拿不到**。漏发形态是静默的：**软件用户拿得到修复**（壳自己就渲染这些组件），**插件作者拿不到**（货架上仍是旧组件）⇒ 同一个组件两种表现；若那次是破坏性改动，作者**连「有个大版本要升」的信号都收不到**。

> 这条缺陷的原始记录：第 1.9 轮交接段 **F1**（[样式命名空间归一化/交接.md](../../01-插件独立构建/样式命名空间归一化/交接.md)）＋ E6 清单 `#2.5c` 格下的 2026-09-15 挂账行。

## 二 🔴 开工第一步：先量**精确**表面（别一把梭，否则造误报）

实测 `src/components/shared/` 有 **24 个目录**，而 barrel 只导出 **21 个**：

| 类别 | 目录 | 含义 |
|:--|:--|:--|
| **进包（21）** | `badge` `button` `color-picker` `combobox` `context-menu` `file-icon` `file-path-input` `font-family-select` `form-row` `hooks` `inline-input` `markdown-view` `number-input` `overlay-portal` `plugin-icon` `segmented-radio` `select-box` `slider` `string-list-editor` `theme-picker` `toggle` | 经 barrel 可达 ⇒ 改了**会**改包内容 |
| **不进包（3）** | **`language-picker`**（← `src/core/commands/shell/settingsCommands.ts`）· **`theme-browser`**（← 同上）· **`sidebar-section`**（← `src/pool/shared/pool-section-stack/PoolSectionStack.tsx`） | **壳内专用**：住 `shared/` 但**不在导出面**、也**无人从 shared 内部引用** ⇒ 改它们**不改包内容** |

⇒ **精确表面 = 那 21 个目录**（三个壳内专用的排除）。

🔴 **为什么不能写 `src/components/shared/**` 一把梭**：`expandSurface()` **只支持 `dir/**` 前缀与整文件路径，没有排除语法**（实测该函数实现）；而一把梭会把那 3 只的改动也判成"包内容变了" ⇒ **误报** ⇒ 训练人忽略黄灯（本仓三闸之**闸 1：零误报才配红灯**，见 [06 档 §〇](06-门禁扩域与验收.md)）。
> ⚠️ **开工时自己复核一遍这 3 只**（我这次是按"有没有人 import + 在不在 barrel"两条判的）。**若发现某只其实经别的组件被间接打进包 ⇒ 它必须留在名单里**；判据 = 解已发布 tarball 看有没有它的产物（比静态推断硬）。

## 三、要做（两步，推荐一起做）

### 第一步：surface 补上那 21 条
在 `PACKAGES` 里 ui 那条的 `surface` 追加 **21 条** `src/components/shared/<name>/**`（保留原有的 `packages/linkdesk-ui/src/**` 与 `README.md`——导出面与 README 也是内容），并在脚本里留一行注释写明**为什么不是 `src/components/shared/**` 一把梭**（引 §二 的 3 只壳内专用 + 闸 1）。

### 第二步：加一条**覆盖面断言**（防这把尺子自己腐烂）
> 承**闸 3：规则本身不许腐烂**——手维护的名单一定会漂（本仓吃过一次：`check-namespace-matrix` 因手维护表静默漂移一个月）。

**断言**：`packages/linkdesk-ui/src/index.ts` 里 export 的共享组件目录 **⊆** ui 的 surface 列表；**缺一个 ⇒ 红**（报点写清「`<name>` 已进导出面但不在黄灯名单里 —— 加上它，否则它以后的改动不会点亮黄灯」）。
- 实现只要**解析 barrel 的 import 行**（barrel 是简单 import 列表，不需要 TS 编译），**别引 TypeScript 解析器**。
- 这条断言让**将来新增共享组件**自动被抓住，不必让脚本去追 import 图。
- 带 `--self-test` 一例负控（桩 barrel 加一个未登记的目录 ⇒ 断言红）。

### 🔴 做完必须重记基线
surface 变了 ⇒ 哈希口径变了 ⇒ **`npm run release:mark` 重记 `@linkdesk/ui` 的基线**（否则下一次 check 会因为"口径变了"而亮假黄灯）。若基线重记前发现 ui 货架确实落后（内容漂移），按「**凡更新就发**」补发一版（那是另一件事，见 §五 禁区 4）。

## 五、禁区

1. **不许把整个 `src/**` 或整个 `src/components/shared/**` 塞进 surface**——那是误报工厂（闸 1）。
2. **不许把它改成红灯**——黄灯永不 fail 是既定设计（它提醒的是"货架落后"，不是"代码错了"）。
3. **不许顺手改 `expandSurface()` 的语义去支持排除语法**——除非同时确认其他 4 个包的 surface 不受影响；**显式 21 条更稳**（本条实现代价 ≈ 0，闸 2）。
4. **不许顺手 bump/publish `@linkdesk/ui`**——本条任务的目标是**让灯亮**，不是发版。真要发（比如量出 ui 确实落后）按 [作者轴npm发版.md](../../../06-发布管理/作者轴npm发版.md) 五步走，且**发完再重记基线**。
5. **不许把本条塞进样式命名空间归一化系列的 1.20（系列收口）那一格**——它是独立任务，混进去会让那轮的"四件终态复核"变得含混。
