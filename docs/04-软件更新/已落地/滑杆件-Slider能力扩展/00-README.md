## 一、你令的原话（2026-10-03）

> 「slider 脱离设置插件，其他插件单独使用就只有孤零零的滑杆？这是能力的缺陷对吧。」——**是，已取证坐实（§二）。**
> 「slider 自带单位文字声明……比如 xxms、xxFPS、xxpx、xxN、xx毫米……可以让这个显示在后面，前面，上面，下面……我们只给 slider 这个显示单位的能力，不声明则代表不用这个能力，单位是什么由插件作者自己决定。」
> 「在滑杆左右两边有个 − ＋ 按钮，细调 slider 值，同样，不声明则不显示这个，我们只给 slider 提供这个能力。」
> 「壳就相当于主题系统的主人，第一个使用这个能力的不是插件作者，不是别人，而是壳。」
> 「涉及到壳共享 ui 的改动，就要使用 skill 设计好 html：/impeccable、/ui ux pro max。」

## 三、要落的能力（两条，均为可选声明）

| # | 能力 | 契约要点 |
|:--:|:--|:--|
| ① | **单位值标签** | 新 props：`unit?: string` ＋ `unitPosition?: "before" \| "after" \| "above" \| "below"`（缺省 `"after"`）。显示**「当前值＋单位」一体**（如 `25 px`——**D1 定**，一次声明两得：提示步进刻度语境 ＋ 提示当前值）。**声明了才有标签（D6）**：`unit` 未声明 ＝ 不渲染标签＝裸滑杆；`unit=""` ＝ 有标签、无单位（设置页无单位键**今天就显示 `0.5`**，故设置仓一律 `unit={prop.unit ?? ""}`）——⚠️ 空串 ≠ 未声明 |
| ② | **细调步进** | 新 prop：`stepper?: boolean` → 轨道两侧 **− / ＋** 真按钮（按既有 `min/max/step` 夹取步进；`disabled` 联动置灰；`aria-label`「减少/增加」）。**D2 定：常驻**（不用悬停/聚焦才显——「这能点」的可供性不能被藏）。**不声明 ＝ 不渲染**。长按连发不做（NumberInput 前例：单击单发） |

**能力归属（D3 更正后的口径）**：单位与步进**都是 Slider 组件自带的能力**，能力一直在组件里；**谁使用谁声明**（插件作者/任何使用方在 props 上说一声就有了），不声明就是今天那根裸滑杆。⛔ **不存在「设置仓硬写 stepper」这种做法**——设置仓只负责把配置键上的声明**传下去**（插件对键名零知识铁律）。

**只增宣言有门禁背书**：`check-api-surface-additive` 会拦任何删改——既有 props 一个不动，新 props 全部可选缺省 undefined。

### 4.3 交接时的实测预算（今天在设计图里量的）

360px 控制列、滑杆含 −/＋ 与值标签：轨道 **258px**、按钮 20×20×2、值标签 `min-width 44px × scale`（180px 列下轨道 52px，仍高于 40px 下限）。

⇒ 那案 D2 若把伴生只读放**主控件右侧同排**，这一行右侧会同时出现**三个读数**：组件值标签（配置值）＋ 伴生只读（状态）＋（声明了 `effectiveToken` 时）行尾生效值徽标。**那案锁布局前必须在 360px 列实测**，不许估算——这是两案唯一会互相挤的地方。

### §五·补 · 顺带坐实的缺口：`unit` 从来没对第三方开放过

按你的更正去核声明链时发现一件此前没人报过的事：

- `unit` 只活在**宿主内部类型** [src/core/registry/ConfigurationRegistry.ts:80](../../../../src/core/registry/ConfigurationRegistry.ts)（`ConfigProperty.unit?: string`），由壳的外观键在 [appearance.ts](../../../../src/App/config/appearance.ts) 四处声明（`px` ×3、`％` ×1），消费方是设置仓的 `formatSliderValue`。
- **作者面 schema 里一个字都没有它**：`public/schemas/plugin.schema.json`（连带 `docs/03-插件制造/` 与 `packages/plugin-sdk/schemas/` 两份字节拷贝）中 `unit` 出现 **0 次**，而配置属性对象是 `additionalProperties: false`。
  ⇒ **第三方插件作者今天若在 `package.json` 里写 `unit`，会被 schema 校验直接打红**——你 1.1 那句「单位是什么由插件作者自己决定」，今天其实**只对壳成立**。
- 所以本案的声明面必须**两处一起补**：宿主 `ConfigProperty` ＋ 作者面 schema（含两份字节拷贝，受 `check-plugin-schema-sync` 字节级守卫），`unit` / `unitPosition` / `stepper` 三字段同笔——⛔ 只补一半＝给第三方留一道看不见的墙。
