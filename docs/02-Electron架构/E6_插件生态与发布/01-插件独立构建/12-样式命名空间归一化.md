## 一、为什么做——原排期判据未触发，为什么仍然做

E6#109g 原挂的排期判据是**三者取一**（① 真发生第二次撞车 ② 组件公共面要发大版本 ③ `@linkdesk/ui` 进 1.0），今天的读数：**三条都没触发**，所以当时判「今天无收益，明确不做」。

2026-09-15 用户改判为「做」，理由不在这三条里，而在**账的走向**：

| | 改名（处置 E） | 不改（维持登记豁免） |
|:--|:--|:--|
| **收益** | 恒定（8 个通用英文词的手滑撞名风险，从概率上消失） | 恒定 |
| **成本** | **随时间单调上涨** | 零 |
| **今天的成本** | 最低点（外部失效面 = 官方 6 处，全在自有仓；第三方生态**事实上为零**——官方目录 21 条的作者分布 = 官方 9 / LinkDesk 8 / Encaron 2 / 测试 1，`third-party/` 只有 README） | — |

⇒ **「记债不排期」在账面上是最差的一档**：以「今天无收益」为由，推迟一件**越晚越贵**的事。每多发布一只插件、每多一份学会当前清单的文档，改名就多一个静默失效点。

另有两层（用户 2026-09-15 点明，见 memory `ai-friendliness-three-layers`，2026-09-14 已定稿为**四层**）：

- **层 3 工程可读**：判据是「让 AI 不需要追踪」。今天壳的 `.toggle` 样式一改，要 grep 所有插件 CSS 才知道谁被影响；加前缀后**没有任何插件能被命中，追踪需求归零**。
- **层 4 插件易造**：今天一个陌生作者的 AI 写插件，必须**先记住 14 个保留名**（外加 9 个关键帧名）才不会撞；规则收敛成一句可复述的话之后，**AI 不需要知道任何一个具体名字**。这正是核心公式「你要的不是 AI 更聪明，你要的是代码不给 AI 犯错的机会」在 CSS 上的落地。

### 2.3 🔴 机制纠正——失效**不是运行时即时发生**，而是**插件升级 ui 时发生**

11 档原文（与 #109g 行）写的是「破坏跨仓插件的既有 scoped 调优」。本轮把这条机制的**时序**量准了，它决定发版顺序：

- **共享组件 CSS 是打进插件自己的 bundle 的**（`@linkdesk/ui` 在 L7 已确认为**非 external**——插件产物里带着 ui 的 CSS 副本，实读：`file-tree`/`marketplace`/`my-cool-plugin`/`serial-monitor` 的 `index.bundle.css` 里都有 `theme-card` 规则）。
- ⇒ **只改壳 + 只发 ui，对已发布的插件不构成即时破坏**：它们自带旧 ui 的 CSS，渲染什么就定义什么，自洽。
- ⇒ 真正的失效点在**插件升级 `@linkdesk/ui` 的那一下**：它的 scoped 调优（上表 4 处）失配，样式静默不再生效。
- ⇒ **结论（发版顺序的依据）**：壳与 ui 可以先发（零破坏窗口），**各插件仓必须同批适配重发**，否则它们下次升级 ui 时才炸（且是静默的）。

> ⚠️ 与 `.input` 的区别（§三·4）：`.input` 是**宿主 `index.css`** 的全局工具类，与插件视图**同表、运行时共享**——插件渲染 `className="input"` 是在**借运行时存在的那份**。所以对 `.input` 的任何改动都是**即时破坏**，不能与 8 个共享组件名同轮处理。

### 2.4 与「撞名」无关但同族的另外两条轴（本轮的收口对象）

| 轴 | 今天的状态 | 门禁覆盖 |
|:--|:--|:--|
| **插件 ↔ 插件** | 所有已加载插件同表（池文档实读 8 张样式表）。官方 9 只带 CSS 的插件**零裸定义**（靠纪律） | ❌ **完全没有**——SDK 那条腿只查「宿主保留名」，两只第三方插件都用 `.toolbar` 无人拦 |
| **渲染侧借用** | 插件把保留名渲染到自有元素上（`.toggle` 这类通用词极易手滑） | ❌ 只查「裸**定义**」——SDK 源码注释写明「scoped 调优是合法消费，不在本腿管辖」 |
| 渲染隔离 | 全仓**零** `@layer` / 零 shadow DOM / 零 CSS Modules | — （前缀降低撞名概率，**不等于隔离**；真隔离是另一条路，不在本轮） |

## 三、四件套（本轮方案定案）

> 每件**独立可发**；依赖关系见 §四。**判据一句话**：做完 1–3，规则是可一句话复述、无需查表、机器兜底的；第 4 件决定「归一化」是收敛到底还是留一条明写的尾巴。

### 3.1 件 1（E6#109g）· 共享组件 8 名加前缀——**原子事务，不可拆**

- **动作**：8 个裸类名 → `.ldk-badge` / `.ldk-button` / `.ldk-combobox` / `.ldk-mdv` / `.ldk-selectbox` / `.ldk-sle` / `.ldk-slider` / `.ldk-toggle`（变体同笔：`.ldk-button--sm`）。
- **不改词干**：`.mdv` / `.sle` 这类缩写**保持原样**——词干改名是第二次破坏面，零收益。
- **同笔必改**（少一样就是半成品）：
  1. 8 个组件的 CSS + 3 处根元素渲染点（§2.1）；
  2. 6 处外部 scoped 调优（§2.2）——**壳 2 处 + 官方 3 只插件仓 4 处**；
  3. 保留名清单 `packages/plugin-sdk/schemas/reserved-class-names.json` 的 `classes.shared` 组（**要么整组清空、要么改写成 `ldk-*`**——`check-css-namespace` 判据⑤「登记 ↔ 实况反向核对」会逼着清，表烂即红）；
  4. 作者面 §12 那张表（两棵树）+ 文档包重生成；
  5. `CLAUDE.md` 硬约束 23 与「关键文件」行（**同笔**，见 AGENTS.md 的总纲纪律）。
- **发版轴**：`@linkdesk/ui` 0.1.7 → **0.2.0**（0.x 阶段破坏性走 minor 位）· 壳 0.1.65 → 0.1.66 · 插件 ×3 PATCH（marketplace / serial-monitor / settings）· 出厂种子刷新 · `@linkdesk/plugin-docs` 再生成。
- **判据**：见 §五（发版链五步）。

### 3.2 件 2（E6#109h）· 插件侧门禁升级为「前缀不变量」

- **目标**：把「不许裸定义**保留名**」（黑名单，需查表）升级为「裸定义的类名**必须带自己的前缀**」（白名单式，**不需要任何清单**）。这条同时关掉 §2.4 的**插件↔插件轴**——今天完全没保护的那条。
- 🔴 **先评估再动手（本件的 a 步 = 方案评估，不要跳）**：前缀从哪来？实测官方仓的前缀**不是** pluginId（serial-monitor 用 `control-*`、marketplace 用 `mpd-*`/`ms-*`、settings 用 `settings-*`），所以两条路线各有代价：
  - **(a) 清单声明**：`plugin.json` 新增 `cssPrefix` 字段（照硬约束 11：插件身份唯一来源是声明）⇒ 要动 schema（三份字节相等的拷贝）+ 21 只插件仓回填 + SDK 轴发版；
  - **(b) id 派生**：裸定义必须以 `<pluginId>-` 开头 ⇒ 需要 `control-*`/`mpd-*`/`ms-*` 这类仓**改类名**（又是一次破坏面，且要重发）。
- **判据**：SDK 侧自测（正控 + 负控）+ **至少 1 只真插件仓跑红**（照 #109e 的做法：负控靠真跑，不靠自测）+ SDK 轴按 version-bump 判位真发。

### 3.3 件 3（E6#109i）· 保留名清单单一真相源（文档不再手抄）

- **现状（实测）**：机器侧是**真**单一真相源（一份 JSON，壳门禁与 SDK 腿读同一份 + 反向核对）。但作者面 §12 里那张表是**手抄的第二份**（中文 `docs/03-插件制造/` + 英文 `docs/03-plugin-authoring/` 两棵树，再生成进 `packages/plugin-docs`）。逐个脚本查过：`check-author-docs-symbols` 只查内部任务号，`generate-plugin-docs` 不做登记表替换，**没有任何脚本对账这张表与 JSON**。
- **为什么必须修**：这正是本仓自己命名过的「第 ① 类 bug：手维护清单缺对账门禁」——`check-namespace-matrix.mjs` 当初就是因为一张手维护表**静默漂移了一个月**（自称 40 契约、实为 45，还多一条死行）才诞生的。而作者面是本条规则**唯一的入口**：表烂 = 作者照不存在的面写代码。
- **动作（二选一，倾向 a）**：(a) §12 的表**从 JSON 生成**（生成器 + `--check`）；(b) 加一条**对账门禁**（文档 ↔ JSON 逐名比对，漂移即红）。无论哪条，**两棵树同笔**。
- **判据**：正控 = 手工改一个名字 ⇒ 门禁/生成器红；负控 = 还原即绿；`docs:check` 绿。

### 3.4 件 4（E6#109j）· 宿主 6 个工具类定格——**`.input` 与另 5 个分开处置**

- **另 5 个（`.titlebar` `.divider` `.about` `.rn` `.vta`）**：实测**零插件借用**（全量扫描：插件只借 `.input`）⇒ 前缀化成 `.ldk-titlebar` 等是**零破坏**的壳内改动，直接做。
- **`.input`**：实测被插件**直接渲染** 10 处（settings 8 + serial-monitor 2），且它是宿主 `index.css` 的运行时同表工具类 ⇒ 改动**即时破坏**。两条路线，**需拍板**：
  - **(a) 升格为正式公共面**：在作者面写死「`.input` 是宿主给你的输入框工具类」，保留名清单 `classes.host` 保留它；后续单独立项给插件一个**真 `<Input>` 组件**（10 处渲染点迁移）。⇒ 规则留一条**明写的例外**。
  - **(b) 前缀化 `.ldk-input`**：与 2 只插件仓的重发**同批**做（即时破坏 ⇒ 必须同批），并给作者面一条迁移说明。⇒ 规则无例外，但这次破坏是**同步发生**的，窗口比 §2.3 那种小得多、也危险得多（插件不重发就当场坏）。
- **判据**：`.input` 的裁决**必须有拍板记录**（写进本档 + 清单行）；5 个内部名有实测读数支撑「零借用」。

## 六、风险与回滚

| 风险 | 说明 | 对策 |
|:--|:--|:--|
| **静默失效**（本轮主风险） | 这个 bug 类的形态是「不报错、只是长得不对」——失配的 scoped 调优不会红，只会不再生效 | **唯一体检手段是眼睛**：实机逐屏看 6 个面 = 设置滑杆行 / 市场详情 changelog 与徽标 / 串口控制栏下拉 / 壳标题栏按钮 / 表单行开关 / 主题卡片徽标 |
| 登记表烂掉（死行） | 改名后 `classes.shared` 不清 ⇒ 表指向不存在的占名 | 判据⑤反向核对**会红**——这是设计好的拦截（`check-namespace-matrix` 的教训已固化） |
| 只改壳不发 ui | 作者与已装用户永远拿旧件（bug 图谱 §C4 传播链原话） | 发版链 ①–⑦ 不可跳步；`check:npm-release` 门禁兜底 |
| 插件仓漏改调优 | §2.2 那 4 处是**全量**清单，但只在它升级 ui 时才显形 ⇒ 漏了也不会当场红 | 逐仓 `npm run verify` + 实机看该插件的那一面 |
| 误伤视觉（硬约束 16） | 本轮是**纯标识符改名**：零颜色/间距/字体/圆角变更，不触发设计系统调用 | 若执行中发现必须改视觉属性 ⇒ **停下先调 design skill**，不许顺手改 |

**回滚**：改名是纯机械的，回滚 = `git revert` + 重发（npm 版本号不可回收 ⇒ 回滚走**新 PATCH**，不复用旧号）。

## 七、可证伪（照 11 档的手法：负控真跑，不靠自测）

1. **门禁负控**：把任一组件改回裸名（如 `className="toggle"`）⇒ `npm run check` 当场红，报点精确到「文件 + 类名 + 归属组件」；还原即绿。
2. **登记表证明**：`classes.shared` 清空后，往任一共享组件 CSS 塞一个裸类名 ⇒ 判据①红；塞进登记表再跑 ⇒ 绿（**逃生口仍然存在，但必须先写明理由**）。
3. **单表证明**：手工把 §12 的表改掉一个名字 ⇒ 件 3 的生成器/对账门禁红；还原即绿。
4. **实机证明**：6 个面逐屏截图/读数（§六）——**不是「跑通了」，是「看到了」**。

## 八、纪律（写给执行这一轮的 AI）
