> **已落地（2026-09-28）**：用户报 → 语义拍板 → 当日实现 ＋ dev/CDP 实测四方向全通；**⏳ 未发版**（用户原话「本次 dev 测后即可，暂时不发版」，改动先在 dev 累积，随下一批一起 release）。
> **用户原话**：「它原本设计的目的是**快速通过 title head 右键快速折叠某个 section**，但是不知道为什么现在这个不起作用了，再点应该可以再展开之类的（我已经忘记很早的设计思路了）」；
> 「**安装版同样无效**」（2026-09-28 实机确认）⇒ 不是 dev 独有现象。
> **语义拍板（决定性）**：「**这个设立的初衷是快速折叠，不是直接隐藏**」——子菜单 = **快速折叠 section**（点一下收成只剩标题条、再点展开），**不是视图显隐**；显隐是面板「视图清单」的事，两者不可混。
> **归属**：软件本体（壳折叠持久化 ＋ 池渲染 ＋ 池→壳回调通道）——不涉插件、不涉 SDK、不涉配置、**零契约改动**。

## 一、现象

侧栏容器标题（title head）右键 → 「视图」子菜单：

- 子菜单**列得出来**（插件市场 = 已安装 / 探索插件 / 已禁用 / 内置），但**点任何一项毫无反应**：section 不收、不展、无报错。
- 补充（修复前定下的判据）：菜单项必须**留在列里**并带勾选态——否则「折掉就再也开不回来」＝单向门。

## 二、根因（三层，缺一层就复现「点了没反应」或「画不出来」）

### A. 池侧：动态子项不带 per-item 身份 ⇒ 点击派发不到任何动作

- 出项：`SidebarZone.tsx` 的 `resolveChildren` 每条只回 `{ id: "workbench.action.toggleViewVisibility", label }`。
- 渲染：`ContextMenu.tsx` 动态子项映射写死 `{ id, label, group }`——`checked` / `commandArgs` 一律丢弃（对照同文件静态 `mapChildren` 路径两者都透传，**只有动态这条路漏了**）。
- 派发：点击 → `executeCommand(item.id, undefined, ...(item.commandArgs ?? []), context)`；动态项 `commandArgs` 恒为 `undefined` ⇒ 壳只收到**整菜单共享**的 `context`（`{ containerId }`）。
- 壳 handler：`shellMenus.ts` 的 `workbench.action.toggleViewVisibility` 当年读 `args[0].viewId` ⇒ **条件恒假 ⇒ 静默返回**。

**责任年份**：不是 E5.7 搬池弄丢的——搬走前那份壳版 `SidePanel.tsx` 的动态项同样只回 `{id,label}`，自 E5#44d 落地起就是死路（无测试覆盖 `resolveChildren`）。

**修法（04 定案）**：动态子项补**池侧回调** `onSelect`，就地执行——因为动作本就是**池构建的**，它该走池→壳回调通道（`onSidebarAction "setCollapsed"`），而不是绕一圈壳命令再回来。`ResolvedItem.onSelect` 在鼠标点击与键盘回车两条路径上同语义。

### B. 壳侧记录法表达不了「声明折叠 ＋ 用户展开」⇒ 勾选态印反、点击方向算反

- 旧记录是**单列** `collapsedViews`：只记「用户折叠过」，**缺省 = 未折叠 = 展开**。
- 于是**插件声明 `collapsed:true` 的视图一旦被用户手动拉开就无处记**——活例：`marketplace` 的 `explore` / `disabled` / `builtin` 在清单里声明折叠，而 `explore` 若被用户展开，记录面上与「从没折过」完全同形。
- 后果：菜单 ✓ 按持久化列算 ⇒ **声明折叠的视图勾选态印反**；点击方向由 `!isCollapsed` 反推 ⇒ **点「展开」发 `collapsed:false` = 空操作**（这正是「点了没反应」的第二条腿）。

**修法**：持久化拆**两列**——`collapsedViews`（用户显式折叠）＋ `expandedViews`（用户显式展开），同键在**两列之间搬移**（互斥）；壳侧算**有效折叠集**再推池：

```
有效折叠 = 显式展开 ? 展开 : 显式折叠 ? 折叠 : 插件声明 collapsed
（用户手势永远赢过插件默认；隐藏视图一并计入，隐藏再显示不丢折叠态）
```

### C. 渲染层两套真相 ⇒ 壳来的折叠翻转画不出来

- `PoolSectionStack` 里同时存在 `collapsedSet`（prop 派生，喂 `SidebarSection.defaultOpen`）与 `collapsedViewSet`（本地 state，喂 `ViewPane collapsed`）——**同一件事两个判据**；且 `SidebarSection` 的 `open` 只在挂载时 seed（无 prop 同步）⇒ 壳持久化回来也画不动。
- **修法**：本地 set 作**唯一折叠真相**（`defaultOpen` 与 `ViewPane collapsed` 同读它）＋ 按**差集**跟随壳快照（避免每次重推把用户本地开合覆盖回声明默认）＋ `SidebarSection` 增 `useEffect(() => setOpen(defaultOpen), [defaultOpen])`（只在值变化时同步）。

## 四、落地记录（dev ＋ CDP 实测读数）

修复前：子菜单 4 项**全部无 ✓**、点任何一项无任何变化。

**① 快照（壳→池）**：`collapsedViews: ["search","explore","disabled","builtin"]`——`search` 是用户显式折叠，`explore/disabled/builtin` 是**声明折叠**（旧实现里后三者永不入集）。

**② 勾选态对齐实际开合**（菜单列 ↔ section 真实高度）：

| 菜单项 | ✓ | section `aria-expanded` | 高度 |
|---|:--:|:--:|--:|
| 已安装 | ✓ | true | 1213px |
| 探索插件 / 已禁用 / 内置 | （无） | false | 22px（**只剩标题条**） |

**③ 声明折叠视图双向折叠**（核心修复点——旧实现此处发 `collapsed:false` = 空操作）：

- 点「探索插件」→ **22px → 1510px**、`aria-expanded=true`、菜单 ✓ 移到它 → 持久化 `expandedViews: ["marketplace:explore"]`（`collapsedViews` 同步摘除）。
- 再点 → **1510px → 22px**、✓ 撤销 → 持久化搬回 `collapsedViews`、`expandedViews` 清空。

**④ 非声明视图双向**：点「已安装」→ 1213px → 22px；再点 → 1213px（`expandedViews` 记名）。

**⑤ 菜单 ↔ section 箭头同真相**：点「内置」的 section 箭头 → `false → true`、322px；菜单 ✓ 随之出现（两条路径读写同一份有效集）。

**⑥ 跨重启**：曾用 CDP 直接调用 `pool.sidebarAction({action:"setCollapsed", …})` 验证写入 → `plugin-states.json` 落 `collapsedViews:["file-tree:search"]`（两列互斥成立）；页面 reload 后该 section 仍为折叠态（`aria-expanded=false`），且**有效集里仍带着三个声明折叠项**。

**⑦ 一处自己踩的坑（写进来免得后人误判）**：运行中的 dev 实例**HMR 没有吃到壳侧模块改动**——快照里 `collapsedViews` 一直是 `[]`、直连 action 也「没反应」，看着像修复无效；reload 两个页面（壳页 ＋ `pool.html`）后**全部成立**。⇒ **CDP 验证前先 reload，别把 HMR 陈旧当缺陷**。
