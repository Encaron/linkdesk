# 02 · 边缘情况清单

> 15 条（E13–E15 为 2026-10-03 出设计图时新增）。每条写清「什么情况 → 会怎样 → 要什么」。带 🔴 的是**本次改动亲手引进的**新风险（改完必须验）。

## 值标签面

**E1** · 🔴 **与设置页「行尾生效值徽标」可能同屏两份读数** —— 设置行的行尾已有效值徽标（E5.8#155，显示**生效 token** 的值）；组件现在自己再画一个「值＋单位」（显示**配置值**）。玻璃不透明度这类键上，**配置值与生效值在覆盖/混搭态下可以不同** ⇒ 同一行两个数字、且含义不同，用户会读成矛盾。⇒ 本轮**只记录不处置**，归「设置行」案统筹（它的伴生只读体系正要重排这一行）；⛔ 不许把组件标签硬改小改淡来"避开"——那是拿可读性换不撞车。

**E2** · 🔴 **施工顺序错了会"单位消失"** —— 若设置仓先接线（传 `unit`）而壳组件还没发版：老组件不认 `unit`，包裹层又被删 ⇒ 单位与值标签整段不见。⇒ **必须壳先行**（本案施工顺序已如此排：阶段 3 → 阶段 4）；设置仓接线那一笔必须在 `@linkdesk/ui` 发版之后。

**E3** · 🔴 **`unit` 空串与未声明必须是两件事**（初稿写反，2026-10-03 依实证改正）—— 初稿写「空/未声明 ＝ 不渲染标签」，但设置仓今天对**每个**滑杆键**无条件**渲染值标签（`renderControl.tsx:132` 直调 `formatSliderValue(val, prop.unit)`），且 `formatSliderValue(v)` 无单位时返回**裸数值**（单测：`formatSliderValue(0.45) === "0.45"`）⇒ 玻璃五配置这类**无单位键今天就显示 `0.5`**。按初稿写死＝这几行读数整批消失，判据 1（旧观感零回归）当场破。⇒ 契约写死：**未声明（`undefined`）＝ 不渲染标签**（裸滑杆＝组件在设置页之外的现状）；**`""` / 全空白 ＝ 渲染标签、不带单位**（`0.5`）。设置仓接线一律 `unit={prop.unit ?? ""}`（[01 §三](01-方案与落点契约.md)）。原文担心的「空标签占位挤轨道」不成立——标签里永远有值，不存在空盒。

**E4** · **`unitPosition` 的 above/below 撑破设置行高** —— 上一行/下一行的标签**脱离行内流**，需要容器高度自适应；设置页行高是固定的 ⇒ 若某个配置键声明 above/below，会顶破行高或叠到邻行。⇒ **配置键一律用缺省 `after`**（[04 §八](04-任务清单.md) 残余边界）；above/below 只留给插件自绘场景。

## 步进按钮面

**E5** · 🔴 **一行多出两个 Tab 站** —— 滑杆本身一个 tab stop，−/＋ 各一个 ⇒ 一行 3 个；设置页现有 8 个滑杆 ⇒ 键盘用户 Tab 次数明显变长。⇒ 这是**已知代价**，接受（键盘全链是硬判据，[01 §四](01-方案与落点契约.md) 判据 3）；但**焦点环必须明显**（走 `--accent` 环），⛔ 不许做「按钮不可聚焦」的偷懒解法。

**E6** · 🔴 **边界置灰** —— 值到 `min` 时 − 还亮着＝「点了没反应」，是可用性缺陷。⇒ **建议**：值触边时对应按钮置灰（原生 `disabled`），并把 aria 状态带出。落地前在设计图里定形。

**E7** · 🔴 **浮点步进误差** —— `step=0.05` 连点 ＋ 会累积成 `0.30000000000000004`（NumberInput 同族病）。⇒ 组件内部按 `step` 精度**收敛取值**（`round(v/step)*step` 到 step 的小数位），⛔ 不许把误差抛给值标签去显示。

**E8** · **`disabled` 联动** —— 滑杆置灰时 −/＋ 必须同灰（[01 §一](01-方案与落点契约.md) 规则 5）；漏了就会出现「杆不能拖、按钮还能点」的鬼状态。

**E9** · **尺寸乘不乘 `--ui-scale`** —— 按钮与标签盒尺寸应乘 `--ui-scale`（字号缩放 Phase 12 铁律：邻接度量随 scale），⛔ 不许裸 px。⇒ 门禁 `check-font-scale-audit` 已拦字号；尺寸靠设计图与验收盯。

## 声明链面

**E10** · 🔴 **作者面 schema 的补齐要经 npm 才到第三方手里** —— 三字段进 `public/schemas/plugin.schema.json` 后，**老版本 `@linkdesk/plugin-sdk` 包内的 schema 仍是旧的**（`additionalProperties:false` ⇒ 作者写 `unit` 照样打红）。⇒ schema 改动必须随 **plugin-sdk / contracts 的 npm bump** 一起发；作者升级 SDK 后才真正可用。验收判据 6（第三方声明链通）要按**升级后的 SDK** 验。

**E11** · **仓库内三处 schema 必须字节相同** —— live（`public/schemas/`）、作者文档区（`docs/03-插件制造/`）、SDK 包内（`packages/plugin-sdk/schemas/`）由 `check-plugin-schema-sync` 做**字节级**守卫；只改一处 ⇒ 门禁红。⇒ 三处同笔改，⛔ 不许"先改 live 回头补拷贝"。

## 主题与文案面

**E12** · **颜色与文案两级铁律** —— 值标签文字走 `--text-*`（⛔ 不硬编码 hex，`check-css-hardcode` 会拦）；−/＋ 字形走 `currentColor`（图标继承墨色，正好与「前景可读性」案同源）；`aria-label`（「减少/增加」＋控件名）与单位文案走 `t()`，⛔ 不许写死中文字面量。

## 结构与实测面（出设计图时新增）

**E13** · 🔴 **组件根节点从「一根 input」变成「一个包裹盒」** —— 值标签与 −/＋ 要住进组件，`<input class="ldk-slider">` 不能再是根。今天 `.ldk-slider` **自带 `width:130px` 固定宽**，而设置页是靠**外部**的 `.settings-slider-control .ldk-slider{flex:1;min-width:0}` 把它撑满的。⇒ ① 根节点换名（如 `.ldk-slider-root`）后，`.ldk-slider` 仍留在 input 上（后代选择器照旧匹配，设置仓 CSS 不用改）；② 130px 固定宽改成「有容器时伸缩、无容器时保持 130px」，否则 `stepper` 挤进来会把轨道压到不能拖（**结构＝网格**：左右方位多一列放标签、上下方位多一行；标签在按钮对**外侧**、上下时**居中压在轨道中线**。设计图实测：360px 控制列下轨道 258px、180px 列下 52px——距 40px 下限仍有余量）；③ `style` prop 今天落在 input 上，⛔ 不要顺手挪到新根（那是删改既有 API 语义）。判据：设置页观感零回归 ＋ 脱离设置页仍是一根 130px 的正常滑杆。

**E14** · 🔴 **未填充轨道贴着行底几乎看不见（实测 1.25 / 1.36）** —— 轨道余段用 `--border`，行底用 `--bg-card`：暗面 CR **1.25**（`#3C3C3C` on `#2D2D2D`）、亮面 **1.36**（`#D4D4D4` on `#F5F5F5`），两头都远低于非文本图形 3:1。⇒ 用户实际是靠 **accent 填充段有多长**在判断值的——**这正是值标签存在的硬理由**（补上"当前到底多少"）。⚠️ **本轮不改轨道视觉**：改余段颜色要重算两种主题下「轨道 vs 行底 vs 卡片」三层关系，属另一件事。只记录 ＋ 在设计图 ⑧ 里实测留档。（同组实测：填充段 accent 暗 3.04／亮 4.15，thumb 9.29／12.63，值标签文字 5.08／6.33——都过线。）

**E15** · **步进按钮的「盒子」本身对比度很低（实测 1.25 / 1.09）** —— −/＋ 的底走 `--bg-input`、行底走 `--bg-card`：暗面 CR **1.25**（`#3C3C3C` on `#2D2D2D`，与 E14 同一对）、亮面 **1.09**（`#FFFFFF` on `#F5F5F5`，实际靠 1px `--border` 描边 **1.36** 才认得出边）。字形自身过线（暗 **7.44**／亮 **13.77**）⇒ 按钮「看得见」靠的是墨色、不是盒子。⚠️ **本轮不改**：提亮按钮底／边与 E14「提亮轨道余段」是**同一件事**（动的是 `--bg-input`/`--border`/`--bg-card` 之间的一层关系，两种主题要一起重算），留档归主题案。设计图 ⑧ 实测表已补此格。
