## 🔴 致命陷阱——每个 AI 进场必读

### 陷阱 1：plugins/ 源码目录不进包（E6#17a 消费切换相）——resources/ 不含任何插件源码

```
当前配置（electron-builder.yml，E6#15d #17a）：
  files:        [dist/**、dist-electron/**、package.json、node_modules/**]  → 进 ASAR
  extraResources:
    - from: bundled-plugins      → to: bundled-plugins     （只读发货 zip 夹）
    - from: build/icon.ico       → to: icon.ico
    - from: node_modules/pyright → to: node_modules/pyright

打包版 resources/ 无插件。插件唯一运行根 = {userData}/plugins/：
boot 自动装把 bundled-plugins/*.linkdesk-plugin 解压落 userData；第三方装包同落 userData（可写）。
dev 才有 <项目根>/plugins/ 源码树 = app 根槽位；prod 该槽缺位 = 正常态（发现/协议/三表扫描
全 existsSync 空目录容错——勿按 "prod 特例" 加 if）。
插件数据文件走 linkdesk:// 协议——由 electron/plugins/protocol.ts 解析（双根有序 404 落 userData）。
勿把用户安装写进 resources/plugins/（只读）。
```

### 陷阱 2：linkdesk:// 协议——只读 plugins/ 源码目录

```
electron/protocol.ts 当前逻辑：
  1. 剥离 linkdesk:// 前缀
  2. 试 builtin/ → user/ → 裸 plugins/
  3. net.fetch 返回

⚠️ 这个协议只处理 resources/plugins/。用户安装的打包插件（{userData}/plugins/）
不在这个协议的处理范围内。需要扩展——或走 fs 直读 + IPC。
```

### 陷阱 3：build-plugins.mjs——已有独立构建，但用 v3CoreExternalPlugin

```
scripts/build-plugins.mjs 当前：
  - 每个插件独立 Vite library mode build
  - 用自定义 plugin 拦截 core import → window.__v3_core__

⚠️ E6#3 应基于这个改造，但不依赖 window.__v3_core__。
新方案：插件构建时把所有依赖（除 React/react-dom）inline 打包，完全自包含。
```

### 陷阱 4：React / react-dom 不能打进插件 bundle

```
壳已经带了 React。如果插件也打包一份 React → 两份 React 实例 → hooks 全炸。
插件 Vite 构建时必须 external: ["react", "react-dom", "react-i18next", "i18next"]。
```

### 陷阱 5：loader.ts——loadPlugin() 唯一入口，改坏了影响所有插件

```
loadPlugin() 是插件加载的唯一入口。改打包格式分支时：
  - 源码目录分支保持完全不变
  - 新分支用独立的代码路径
  - 先在 dev 模式测源码分支 → 再测打包分支
```

### 陷阱 6：终极验证——全链路不动命令行

```
E6#25：Encaron 打开安装版 LinkDesk → 市场安装 hello-world → 所有操作纯 UI。
如果这一步不通过 → E6 不算完成。
```

### 陷阱 7：npm run check 每步必跑

```
tsc + ESLint + vitest + spacing。一个命令。
改 loader.ts 后必须跑全量 vitest——loader 测试覆盖了加载全路径。
```
