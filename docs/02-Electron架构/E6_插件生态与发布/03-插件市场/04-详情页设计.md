## 一、数据流（壳侧零新 API）

```
市场视图 ──tabs.create("plugin-detail", { pluginId, marketEntry, pinned })──► 壳 PluginDetailPoolView
                                                                              ├─ marketEntry（catalog 目录信息）
                                                                              └─ 实时状态（pluginManager.list / isDisabled）
```

- `marketEntry` = catalog 完整条目（icon/desc/readmeUrl/screenshots/versions/license…），作 tab 参数传入——**壳详情页保持哑，数据由市场插件带进来**（插件独立铁律）。
- 动作 API 全走已有 `pluginManager.install/disable/enable/uninstall`——壳零新 API。
- `marketEntry` 缺失（旧调用方）→ 走现有 installed 逻辑兜底；未装显示空态 + 提示「去市场探索」。

### 一·五、详情页标签的去重与预览语义（2026-08-30 补——壳引擎实测）

`tabs.create("plugin-detail", { pluginId, ... })` 的去重 = **identityField + preview/pinned 双机制**，**不是 singleton**：

| 场景 | 行为 | 壳机制 |
|:--|:--|:--|
| **同插件**重复打开 | **聚焦已有**，不新建 | Step 1 `findTabByIdentity` 按 `tabBehavior.identityField:"pluginId"` 匹配（reducers-tab.ts:27） |
| **异插件**打开 | **默认预览替换**——新详情斜体（`pinned:false`）占掉当前未固定详情 tab（对标 VS Code preview editor） | Step 3 preview replacement，显式 opt-IN（reducers-tab.ts:51-75） |
| 用户**双击**详情 tab | 斜体 ⇄ **正体（固定）** 切换——固定后异插件只**新增并存**，不再被替换 | `reducePinTab`（useTabManager.ts:375，对标 VS Code 双击 doPin） |

- **禁 singleton**：`tabBehavior.singleton` 是**类型级**匹配（reducers-tab.ts:42 Step 2），会让所有插件详情归一成一个 tab（点 A 变 B）——详情页身份按 `pluginId` 区分，**必须用 identityField 而非 singleton**。
- 默认新标签页 = 预览模式（斜体，defaults.ts:44 `pinned ?? false`）；详情页打开走默认预览，用户双击固定后持久（对标 VS Code 扩展详情心智）。

## 二、三态 action bar

| 状态 | 按钮 | 动作 API |
|:--|:--|:--|
| 未安装 | 🟢 安装（带进度） | `pluginManager.install(marketEntry.downloadUrl)` |
| 已装 · 启用 | 禁用 + 卸载 | `disable` / `uninstall` |
| 已装 · 禁用 | 启用 + 卸载 | `enable` / `uninstall` |

- 按钮随状态**自动切换**（订阅 `plugin-lifecycle:changed`——安装完成自动变「禁用/卸载」，卸载完成变「安装」）。→ E6#30.5c
- 安装按钮背后（进度/失败/断网/多窗一致）→ [09-安装细节.md](09-安装细节.md)。

**缝隙：内置插件（core:true）action bar**（C3/G10）——`core:true` 定义不可卸载，从 UI 无删除入口（进文件夹删是文件系统手改，非 UI 路径）。详情页对内置插件：
- 卸载按钮**灰掉 + tooltip「内置插件不可卸载」**——不是隐藏，是让用户看到「不可卸」这个事实（可及性）。
- 禁用按钮正常（内置可禁用不可卸载，对标 VS Code 内置扩展）。
- **缝隙：本地插件详情**（A2）——已装但 catalog 无 marketEntry（用户本地开发/文件夹安装）→ 详情显示本地 `plugin.json` 信息 + 动作按钮（禁用/卸载）正常；**市场数据区（下载数/来源/版本历史）隐藏**（无数据不显示空位）。

### 二·五、有更新可用——第四维展示规则（mockup 帧 6/10 定稿）

有新版（`semver.gt(versions[0].version, localVersion)`，05 §一）时，详情页**不改变三态**，叠加「更新可用」第四维：

| 位置 | 显示 |
|:--|:--|
| header 版本号 | **本地已装版本**（如 v1.2.0），**不是市场最新** |
| 主区顶部 | 「有新版本可用」块——当前安装 v1.2.0，市场最新 v1.3.0，**更新内容见「更改日志」tab** |
| action 区 | 「禁用/卸载」旁叠加主入口「⬆ 更新到 v1.3.0」（蓝色） |
| 版本下拉 | 变「v1.2.0 ▸ v1.3.0」升级路径指示（05 §四） |
| 更改日志 tab | 亮紫色小点（●）引导 |
| 侧栏该行 | 徽标「可更新 v1.3.0」 |

**数据源切换（用户 2026-08-29 追问定稿——「没新版本读本地？有新版本读网上？」）：**
- **无更新** → 详情页全读**本地**（包内 CHANGELOG.md + README.md），**离线可读**，更改日志 tab 无 dot。
- **有更新** → 联网拉 catalog 判定；但**已装插件的基础信息/README 永远读本地**（离线可读优先，对照总表「包内 README.md」行），**只有新版 changelog 走远程**。
- 更改日志 tab 有更新时**合并显示两版并排**（mockup 帧 10）：v1.3.0「最新」徽标（内容 = 远程 `versions[].changelog`）+ v1.2.0「已安装」徽标（内容 = 本地 CHANGELOG.md）——用户一眼看到「这次更新变什么」再决定更不更新。
- dot = 「**有新内容可看**」的信号，不是更新提示本身（更新提示 = 侧栏徽标 + 状态栏铃铛，05 §三）。

### 二·六、挂起·缺依赖拦截态（缝隙 M1，mockup 帧 7 三通道）

依赖缺失（`dependencies.ts` pendingReason，E5.8#14/#15 已实现）→ 详情页叠加「挂起·缺依赖」拦截维（**不改变三态，不拦不装**）：

| 位置 | 显示 |
|:--|:--|
| action 区 | 「🚫 安装不可用（缺依赖）」——**非禁用/卸载按钮**，纯信息 + 缺依赖项入口 |
| 主区顶部 | 「依赖未满足」块——列出缺失依赖清单 |
| 依赖行 | 缺失标黄 ✕，点击 → 跳其详情页 |

→ 落 E6#30.5e（mockup 帧 7 三通道反馈：事件型 = toast / 状态型 = 主区块 / 一望即知 = 侧栏徽标）。

## 三、富展示（VS Code 对标）

**VS Code 怎么做：客户端 Extensions 详情页 = 渲染插件包内 `README.md`（markdown）+ 元数据侧栏；web 市场再加 longDescription(markdown) + screenshots + 评分。就是 md 文档。** manifest 有 `readme` 字段指 README.md。

LinkDesk 目标形态：

```
┌────────────────────────────────────────────┐
│ [icon] 插件名          v1.2.0  🔒内置       │   ← 作者图标 + 名称 + 版本
│        作者名 · 来源仓库                     │
│        一句话描述                            │
│   🟢 安装  ⏷版本↓   [✓]自动更新             │   ← 三态 action（版本下拉/自动更新勾选）
├────────────────────────────────────────────┤
│ [截图1] [截图2] [截图3]      ← 画廊（横向滚动）│
│                                            │
│ # 标题                                      │
│ README markdown 渲染（代码块/图片/列表正常）  │
│                                            │
├────────────────────────────────────────────┤
│ 标识符 / 版本 / 大小 / 分类 / 许可证 / 来源   │   ← 元数据侧栏（未装也有）
│ 依赖 / 被依赖 / 更新                         │     依赖 = 本插件 requires；被依赖 = 谁在用我（dependencies.ts，E5.8#14/#15 已实现；缺失标黄 ✕ 点击跳详情）
└────────────────────────────────────────────┘
```

- **README 来源**：已装 = 包内 `README.md`（IPC 读取）；未装 = fetch `readmeUrl`；都没有 → 降级显示 description（现状）。
- **markdown 渲染 = 壳共享 MarkdownView 组件**——README 渲染是通用能力，走 E6#54 分发（`@linkdesk/ui` 可复用），不塞进市场插件。
- **安全：markdown 走 sanitize（去脚本/事件属性）+ `<img>` src 限 https**（缝隙 E2——README 图来自作者仓库，防外部 URL 追踪 + 注入）；catalog 的插件名/描述/分类渲染同理 sanitize（缝隙 E1）。
- **信任信息**（来源/下载数/许可证/安装确认）→ [08-信任与安全.md](08-信任与安全.md)。
- **元数据侧栏字段（2026-08-29 对标 VS Code 追加）**：大小 = catalog `size`（未装 = 包大小；已装可另显安装目录大小）；仓库/问题 = 来源 URL 派生（`github.com/x/y` → 仓库链接 + `/issues` 问题链接，**零新字段零服务器**，「来源」目录保留）；首次发布 = `versions[最后].publishedAt`；更新时间 = `versions[0].publishedAt`（最近发布，现状已显示）。**诚实边界**：评分/评论/下载趋势/Star 数**不做**——无自有服务器、GitHub 不给插件级数据，不伪造（09 §二 先例）。
- **功能 tab**（视觉 = mockups/02 帧 9，落 E6#30.6d）：渲染 manifest `contributes` 清单（commands / configuration / keybindings / menus——壳侧已有，E5.8），详情页只做「功能」渲染面，**壳零新 API**。作者不写介绍，contributes 自动渲染。**点击交互（M2，30.6d）**：命令项点击 → 复制命令 ID（clipboard 既有 API）；配置项点击 → 跳设置页对应 group；keybindings/menus 只读展示。数据 = `list().manifest.contributes`。
- **更改日志 tab**（视觉 = mockups/02 帧 10，落 E6#30.6e）：数据源**分装态**——未装 = `catalog versions[].changelog?`（marketplace.json 扩展字段）；已装 = 包内 `CHANGELOG.md`（E6#4a 打包结构补「原样复制」）。**已装读包通道（K2，30.6b）**：包内 `README.md`/`CHANGELOG.md` 经 `workspace.readTextFile` 读取（插件目录可由 plugins 命名空间定位），实现时无现成通道则按设计前置新增 scoped API。**渲染（M3，30.6e）**：版本倒序 + 已安装/最新徽标；有更新（§二·五）→ 两版并排（远程 changelog「最新」+ 本地 CHANGELOG.md「已安装」）；无更新 → 只本地。**E6 新增渲染面**（实现后实机逐帧验收）。

> **验收契约**：mockups/02 全状态详解（10 帧）是详情页**实机逐帧验收基准**——实现阶段每帧对照复现，不画虚帧。

### 4.1 #30.6a markdown 渲染库定案（非「开工拍板」deferral）

- **原清单「壳零依赖需加渲染库——开工拍板」是待定尾巴**（违反 no-deferral 铁律——设计当下定型，不「开工再定」）。
- **定型：react-markdown + remark-gfm + DOMPurify sanitize**（对标 VS Code marked 系渲染 README）。package.json 零 markdown 渲染依赖已实测坐实（全仓 grep）。
- 打包分发走 E6#54（`@linkdesk/ui`）——壳共享 MarkdownView 是通用能力，不塞进市场插件（§三 L108 已定性，本锚点只补库选型）。
- **消费方（2026-08-30 拍板「md 渲染唯一组件」）**：插件详情页 README + 发行说明 Release body 同为消费方（[05-发行说明.md §2.4](../06-主软件更新/05-发行说明.md) 已同步），未来第三方插件经 @linkdesk/ui 复用同一渲染器。

### 4.2 #30.6b 已装读包通道 = workspace.readTextFile（复用既有 API，零新 API）

- **原「实现时无现成通道则按设计前置新增 scoped API」（§三 L113）是 deferral 尾巴**——已坐实现成通道存在。
- **定型：`workspace.readTextFile`（src/core/api/linkdesk-api/workspace.ts:29）**——已装插件目录路径由 plugins 面 listDirs/readManifest 派生，包内 README.md/CHANGELOG.md 经它读取。**复用既有 API，零新 API**。
- 已装读包通道（K2）三源回落不变：已装 = 读包内 / 未装 = fetch readmeUrl / 无 → 降级 description（§三 L107）。
