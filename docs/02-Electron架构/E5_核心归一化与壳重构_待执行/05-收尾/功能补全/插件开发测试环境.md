# 插件开发测试环境

> 2026-08-06。建议——插件作者写完代码后没有轻量验证手段，只能启动完整 Electron。
> 位于 E5 收尾 → `05-收尾/功能补全/`

---

## 一、问题

插件开发循环：

```
写代码 → npm run electron:dev（启动完整 Electron，~3 秒）→ 手动点图标 → 切到插件 → 看效果
```

对标 VS Code Extension Development Host：`F5` → 新窗口只加载你的插件 → 秒开。

LinkDesk 的 `plugin-shell-main.tsx` 自举加载已经做到了"插件 WebView 入口独立"——缺的是一个**快速启动命令**。

---

## 二、方案

### 方案 A：`npm run dev:plugin <pluginId>`——轻量

```bash
# package.json scripts
"dev:plugin": "vite --mode plugin-dev --open /plugin-shell.html?pluginId=$1"
```

启动一个最小壳：空 MainContent + 空 StatusBar + 空 SidePanel + 只加载指定插件的 WebView。`plugin-shell.html` 已存在（多 WebView 资产），只需加一个 query param 指定加载哪个插件。

```html
<!-- plugin-shell.html?pluginId=file-tree -->
<script>
  const pluginId = new URLSearchParams(location.search).get("pluginId");
  // import.meta.glob 只匹配此 pluginId 的组件
</script>
```

### 方案 B：Marketplace 内"开发模式"按钮

在 marketplace 插件详情页加一个"在隔离窗口打开"按钮——调用 `window.open("/plugin-shell.html?pluginId=xxx")`。不依赖命令行。

### 对比

| | 方案 A | 方案 B |
|:--|:--|:--|
| 目标用户 | 插件开发者（有终端） | 插件试用者（GUI 用户） |
| 启动速度 | 秒级（Vite HMR） | 同方案 A |
| 实现成本 | `vite.config.ts` 加入口 + 命令 | 同 A + UI 按钮 |

**推荐：先做 A（10 分钟），后做 B（v0.3）。**

## 三、最小壳 vs 完整壳

"最小壳"需要什么：

| 组件 | 需要？ | 原因 |
|:--|:--|:--|
| IconBar | ❌ | 不加载其他插件 |
| SidePanel | ❌ | 同上 |
| MainContent | ✅ 空 | 标签页容器——插件视图需要 |
| StatusBar | ❌ | 最小——不需要 |
| TabBar | ✅ 空 | 至少一个标签页 |
| LayoutEngine | ❌ | position:fixed 不必要——全屏足够 |
| 快捷键系统 | ❌ | Ctrl+C/V 走浏览器原生 |
| 主题系统 | ✅ | 插件需要 --bg / --text 等 CSS 变量 |
| 配置系统 | ✅ | 插件可能读配置 |

**结论：不可太简。** 至少需要主题 CSS 变量、配置系统、linkdesk.* API。`plugin-shell-main.tsx` 已经初始化了这些——关键是不初始化**其他**插件（不调 `loader.loadAllPlugins()`，只加载指定 ID 的插件）。

## 四、可能遇到的问题

### 1. `linkdesk.*` API 依赖 IPC

**风险：** Electron main process 的 IPC handler 不在 Vite dev server 中——`linkdesk.filesystem.listDir` 等所有 IPC 调用全部失败。

**缓解：** Vite dev server 模式下，`preload` 脚本不存在。需要 mock 层——`dev:plugin` 模式自动注入 mock API（返回空数组/默认值）。插件开发者如果需要真实文件系统交互，还是要启动完整 Electron。

### 2. Monaco / LSP 不可用

**风险：** Monaco editor 插件依赖完整的 VS Code 服务层初始化——在轻量壳中可能初始化失败。

**缓解：** `dev:plugin` 不是给编辑器插件用的——是给 file-tree / marketplace / serial-monitor 等 UI 插件的。编辑器插件的开发复杂度和这个轻量模式不匹配。
