## 一、判据表（**含必须真跑过的负控**）

| 判据 | 要求 | 负控（**必须真能红**，覆盖它想抓的形态） |
|:--|:--|:--|
| **① 宿主专用旗子** | 插件源码 `contextKey.set("<专用名>")` ⇒ 红 | 在插件仓临时塞 `contextKey.set("activeEditor", "x")` ⇒ **红**（这正是"改宿主行为"的真形态，实机会让命令面板过滤错乱）；**还原后 sha256 逐字节相同** |
| **② 约定面旗子** | 账里标为约定面 ⇒ **不红**（但要按 1.37 裁决处理） | 塞 `contextKey.set("settingFollowTheme", true)` ⇒ 按裁决断言（**若裁决是"出声不拦"，自测要证明它不红**——分级写错会被这条抓住） |
| **③ 插件旗子归属（黄）** | name 必须 `<pluginId>.` | 塞 `contextKey.set("zzzFlag", true)` ⇒ **黄**（自测证明**不红**） |
| **④ 运行时仲裁** | 异 pluginId 设宿主专用旗子 ⇒ `console.error` 点名双方 | 单测：两个 pluginId 设同一专用旗子 ⇒ 断言日志点名双方（＋ 按 1.37 裁决断言值语义） |
| **⑤ 账 ↔ 实况双向对账** | 两侧任一侧多出 ⇒ 红 | 只改账 ⇒ 红；只改实况（`src/hooks/usePoolSync.ts` 新增一个 `setValue`）⇒ **红** |
| **⑥ 生成器过滤陷阱** | 账不许把 `false` / `true` / 比较值（`'left'`）当旗子名 | **实测**：故意让生成器读含 `== 'left'` 的 `when` ⇒ 断言它**不把 `left` 收进账**（照 CSS 系列 1.16「裸 grep 会命中 `app.about`」的教训） |
| **⑦ 静态射程边界自证** | 模板字符串拼名看不见 | 造一个 `` contextKey.set(`exp${x}`, 1) `` ⇒ **断言它不被抓**（**登记为残余边界，不是 bug**） |
| **⑧ 活体样本零回归**（若动 `settings`） | 齿轮菜单三项行为**逐项与今天一致** | **实机逐项**：`settingFollowTheme` 项显隐 · `settingResetsToDefault` 项显隐 · 「打开存储位置」的 `settingKey` 门控 —— **不是"看起来没变"** |
| **⑨ 旧门禁未空转** | 盘一遍本格是否让某条旧 check 输入清零后跑绿 | 实测 |

## 二、禁区

- 🔴 **不许动 `when` 解析器与 `matches()` 的求值语义**（`ContextKeyService.ts:363-373` 的「解析失败 ⇒ false，安全起见不显示」是**既有安全设计**）。
- 🔴 **不许动多窗广播**（`electron/ipc/ipc-bridge.ts:205-207`）。
- 🔴 **不许改 `settings` 插件的行为**——除非 1.37 论证不违反「零 UI 变化」**且**给出两侧同笔改 ＋ 发版 ＋ 目录回填完整方案；**任一条不可行 ⇒ 判不改名**。
- 🔴 **不许把「快捷键 chord 缺陷」拉进来**（**已立案、不属本轴**）。
- 🔴 **不许抛错**（[00 档 §2.7](00-整理档案.md)）。
- 🔴 **不许引白名单 / 基线 / 棘轮**；账**必须生成式 ＋ 双向对账 ＋ 分两段**。
- 🔴 **不许把「黄灯」写成「红」**（存量 `explorer*` 9 个是反例）。
- ⚠️ **上位约束**：**零 UI 变化**（除版本号；含主题/字体/翻译三条横切零回归）· 只做加法且名字一次定对 · [29 号档](../样式命名空间归一化/29-主题系统保护条款.md) 优先 · 对外宽容。
- ⚠️ 照旧：不跳 `npm run check` · 推前现测代理 · 推完 `ls-remote` 对 SHA · **提交只按路径 `git add <本格文件>`**。
