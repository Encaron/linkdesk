### 8.2 `retired[]` 最终形状 ＋ 首条登记（**本格的裁**）

**七个字段，一个不多一个不少**（`ENTRY_FIELDS`；缺字段 ／ 类型不对 ⇒ 形状断言当场红）：

| 字段 | 类型 | 讲什么 | 谁填 |
|:--|:--|:--|:--|
| `name` | string | 退役的**那个名字**（末段形：`commands.foo` ／ `ldk-x` ／ `app.k`） | 人 |
| `kind` | 9 档词表 | 它算**哪一栏**的退役——匹配时只豁免**同栏**（`KIND_COLUMNS:65`） | 人 |
| `since` | `YYYY-MM-DD` | 退役**动作发生的那天**（⛔ 不是版本号——版本号不是时间轴） | 人（查 commit 日期） |
| `why` | string | 为什么退（合并 ／ 改名 ／ 语义变了） | 人 |
| `replacedBy` | string | 替身名；没替身就写 `无落点` | 人 |
| `landing` | string | **落点**：旧名今天还在宿主的哪儿被读 ／ 清扫（`file:line` ＋ 一句）；真删净了 ⇒ 写 `无落点` | 人 |
| `approvedBy` | `用户 · YYYY-MM-DD` | 谁批的——**必须用户本人**（AI 自签 ⇒ 形状断言当场红，`:280`） | **用户** |

### 8.4 残余边界（诚实清单 · 9 条）

1. **只有 `configKey` 才有「活性」判定**：断言1 对 configKey 用「**写入/声明点 = 0**」（`scanWriteShapeInHost:218`），其余 8 档用「必须不在快照活面上」⇒ 一个只被**读**、从不被写的键，会被判成「还活着」（保守方向）。
