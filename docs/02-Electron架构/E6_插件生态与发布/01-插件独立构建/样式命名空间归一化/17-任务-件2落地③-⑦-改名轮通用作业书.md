## 一、每仓六步配方（**一步都不能省**）

### 步 1 · 进场取基线（**先证明「改之前是绿的」**）
```bash
cd <仓目录>                     # 例 E:\linkdesk-plugins\official\file-tree
git rev-parse HEAD              # 记下：改名前的提交（交接段要写）
npm run verify                  # 必须 EXIT=0；不为 0 ⇒ 先报告，别在红的地基上动土
node E:/linkdesk/scripts/plugin-css-prefix-audit.mjs . --json > <暂存>.json   # 工具在 ① 交付
```
> 工具产物 = **本仓旧名清单 ＋ 每条「旧名 → 新名」映射 ＋ 文件:行**。🔴 **不许手抄名单**（本仓打过的「手抄第二份清单」就是 1.15 花一整轮修的）。

### 步 2 · 改名（**形状 = 叠加，不是替换**）
- **类名**：在原名前**插入** `<pluginId>-`——`ms-item-name` → **`marketplace-ms-item-name`**；`session-item` → **`serial-monitor-session-item`**。
- **关键帧**：`fadeIn` → `serial-monitor-fadeIn`；**并同笔改 `animation:` 引用处**（漏了引用 = 动画静默消失）。
- **渲染点同笔改**：`className="…"` / `` className={`…`} `` / `querySelector` / `classList` / 测试断言里的类名——**一处不漏**（这就是本路线的主风险）。
- 🔴 **补扫（1.14④ 加的必做步）：工具的射程 = CSS 定义点，看不见「只在渲染点存在、CSS 零定义」的类名。** 实证：settings 的 `keybindings-col-key-cell` / `text-muted` 在 TSX 里各一处、**全仓 0 条 CSS 规则** ⇒ 工具从来不报；是补扫抖出来的。**每仓开工与收工各跑一遍**：
  ```bash
  node E:/linkdesk/scratch/scan-render-tokens-109h-b4.mjs "<仓目录>"   # 改仓路径即用（1.14④ 交付）
  ```
  **判据** = TSX 里每个 className token 只能三选一：① `<pluginId>-*` ② 宿主保留（`ldk-*` / `codicon*` / 登记表 `classes.host` 里的 `input`）③ **复合状态类**（CSS 里以 `.你的类.x` 形态出现，如 `.settings-keybindings-inline-btn.confirm`）。**不在这三类里的 = 漏网**，按「叠加」补前缀（这类通常零 CSS 规则 ⇒ 改名零视觉影响）。
- 🔴 **不许改**：颜色 / 间距 / 字号 / 圆角 / 任何视觉属性（硬约束 16）；**不许改词干**；**不许动 `className="input"`**（宿主保留名的 scoped 消费，属 [1.17](13-任务-宿主input裁决与落地.md)）。
- 🔴 **不许改**：`ldk-` 开头的名字（宿主命名空间——那是共享组件/宿主自己的，插件本来就不该有）。

### 步 3 · 机械证明（**两条，缺一不可**）
1. **token 判据 0 残留**：旧名在 **CSS ＋ 渲染点**里**整词**匹配命中 **0**（`marketplace-badge` ≠ `badge`），且**正控 ≥1**（拿一个确定在用的新名验证尺子有效）。脚本照 1.16 的 `scratch/judge-class-tokens.mjs`（带 `--control`）。
2. **形状证明**（走「叠加」时适用）：每个改动文件**逐字节等于「HEAD ＋ 逐行只插入 `<pluginId>-`」**——剥注释后仍相同 ⇒ **零视觉声明变化**。照 1.16 的 `scratch/prove-prefix-only-109j-a.mjs`。
   > 🔴 **证明脚本自己要有负控**：拿它去跑**改名前**的文件 ⇒ 必须**红**（否则证明是恒绿的，等于没有）。

### 步 4 · 该仓全绿
```bash
npm run verify     # 五段全过（含 ① lint 严格腿 = 新判据已生效）
npm run test       # 有测试的仓必跑（改名常撞断言，见 1.11 的 233/10/31 例）

```

### 步 5 · **git 一次** ＋ 记账
```bash

```
- bump：`package.json` ＋ `plugin.json` ＋ `CHANGELOG.md`（新段非空）**三处同笔**。
- 🔴 **一仓一提交**（本档的硬要求）——**不要把两只仓塞进一笔**：出错时要能单仓 revert。

### 步 6 · **实机界面查询一次**（见 §二）＋ 然后重发

## 二、实机核对 recipe（**把 1.12 / 1.16 踩过的坑一次性固化**）

**起法**（照 1.16）：
```bash
# 插件目录要进 vite 的白名单（临时配置放 scratch/，不进仓）
# 隔离 userData 必须放 %TEMP%（放仓内会让 vite 的 watcher EBUSY 崩掉）
npx vite &
electron . --remote-debugging-port=9223 \
  --user-data-dir=%TEMP%\ldk-109h-<仓名> \
  --disable-features=CalculateNativeWinOcclusion --disable-backgrounding-occluded-windows
```
- ⚠️ **`server.fs.allow` 只放行 `[仓库根, %APPDATA%\linkdesk\plugins]`** ⇒ 隔离 userData 下的插件 bundle 经 `/@fs/...` 取不到（表现为「视图落壳保底」）⇒ 临时 vite 配置加白名单（1.12 的 `scratch/vite.live.config.ts` 先例）。
- ⚠️ **重定向 `APPDATA` 环境变量对 Chromium 无效**（走 Known Folder API）⇒ 会撞用户已装实例的单实例锁，**秒退且 EXIT=0**、只留一行 `DevTools listening`。
- ⚠️ 装该仓的新构建到隔离 profile：**dev 下「市场 → 确认更新」会 `EPERM`**（vite 持着文件句柄）⇒ 手动把 `<id>.linkdesk-plugin` 解到 `%TEMP%\ldk-109h-<仓名>\plugins\<id>\` 再重启。
- ⚠️ 两个开关（`CalculateNativeWinOcclusion` / `backgrounding-occluded-windows`）**是必需的**：窗口被遮挡时 Chromium 不重绘 ⇒ 截出来是一片纯色。
- 🔴 **先搞清「这个视图怎么打开」，再动手点**（1.14④ 绕了半天的坑）：
  - **`location: auxiliarybar` 的容器在壳里恒不渲染**——`src/hooks/usePoolSync.ts:258` 把 `rightSidebar.visible` **写死 `false`**（注释：「壳侧暂无容器内容生产者」）。settings 的容器就是 `auxiliarybar`，它的视图实际落在**浮动面板**上：在池里执行 `window.linkdesk.commands.execute('core.openSettings')`（命令实现见 `core/commands/shell/settingsCommands.ts`：先 `focusTabByPluginId`、否则 `panel:reveal-floating`）。
  - 🔴 **图标栏那个同名按钮可能弹的是壳的右键菜单（`.ctx-menu`），不是插件视图**——面板长得像就能骗过眼睛。**验证法**：查 `document.querySelectorAll('*')` 里的类名有没有该插件的 `<pluginId>-*`，或查 `[...document.styleSheets]` 里有没有该插件的 CSS；**没有 = 那不是插件视图**（settings 第一遍就是这么被抓出来的）。
  - ⚠️ **隔离 profile 的 `plugins/` 目录可能整个消失**（而 `installed-plugins.json` 还在）⇒ 再启动走「异版本不动」分支、不重装、插件全灰。修法 = **整块重来**（删 profile → 起一次让它种 6 只 → 停 → 换成新件 → 再起），**别去手改 `installed-plugins.json`**。

**查询什么**（CDP `Runtime.evaluate`，照 memory `cdp-ui-automation`）：
| # | 查询 | 期望 |
|:--:|:--|:--|
| 1 | `document.querySelectorAll('[class*="<旧前缀>"]').length` | **0**（旧名一个都不剩——注意用**整词**判据，`file-tree-badge` 不等于 `badge`） |
| 2 | `document.querySelectorAll('[class*="<新前缀>"]').length` | **> 0**（新名真的渲染出来了） |
| 3 | 抽 1–2 个元素读 `getComputedStyle`（尺寸 / 颜色 token / 字号 / 内边距） | **与改名前一致**（这是「零视觉变化」的正面证据） |
| 4 | 控制台（`Log.enable` / console 消息） | 无新增报错 |
| 5 | 该仓**可见面**逐屏看（见 §三 附录） | 「**看到了**」——不是「跑通了」 |

**取证写进交接段**：面（哪个视图）、读数（选择器命中数）、抽到的 computed style 值、以及**任何看不出结论的面如实写**（1.12 的面 6「本机插件集无渲染点」就是如实记的先例）。
