## 三、我已查清的技术事实（新 AI 不必重查）

### 3.1 数据模型**已经支持媒体**（不是缺 API）

`CatalogEntry`（市场仓 `src/services/marketCatalog/types.ts`）已有：

- `screenshots?: CatalogScreenshot[]`——`string` = 图片 URL（旧数据原样可读）；视频对象
  `{type:"video", url, poster?}` **至多 1 段且必须排第一**（封面视频；多段/越位解析期丢弃并记声明警告）。
- `cover?: string`——合集/板块封面（schema 里有）。
- `icon` / `marketIcon`——图标；`marketIcon` 服务**未装态**，必须绝对 URL（publish 自动 URL 化）。
- 详情页 `DetailOverviewTab` 已有**截图画廊**（横向滚动，img + 封面 video，controls/preload=metadata/⛔ autoplay）。
- 卡片 `cardParts.Art` 已经会取 `screenshots[0]` 当封面图；**没有就回落成「渐变色块＋图标」**。

⇒ **结论：媒体链路已经存在；现在的「单调」是数据缺（作者没给图）＋展示层没把媒体用起来（hero/大卡仍按渐变+图标画）**。
⇒ ⛔ 不要再造第二套媒体字段/第二套画廊；要**在同一份 `screenshots/cover` 上做归一化渲染**。

### 3.2 展示层缺口（要设计的部分）

| 位置 | 现状 | 目标 |
|---|---|---|
| Hero 英雄页 | 左文案 + 右「渐变色块＋一枚小图标」（用户截图 3 实拍：巨空） | 媒体铺满/大面积展示（用户口径 **3:2 或 2:1**）；图片/封面视频；文案压在 scrim 上；无图时有**设计过的回落** |
| 主题专区 mega 卡 | 图标在渐变上 | 封面图/多图轮播（hover 在卡内播放预设几张） |
| 双大卡 duo | 图标在渐变上 | 同上 |
| 小卡/行卡（靶场横滚、榜行） | 图标 | **保持图标**（用户明确：小卡只显示插件图标） |
| 详情页 | 已有画廊 | 可保留/微调，不是本轮重点 |

### 3.3 无媒体时的回落（用户明确在问）

- 图片用谁的？**作者的**：`screenshots/cover` 是作者在 `marketplace.json` 声明的绝对 URL。
- 作者没图怎么办？**不要手工给存量插件画图塞进 git**（不可扩展、也不是作者资产）。设计一个**生成式封面**回落：
  用插件身份色（现有 `entryHue`）＋ 图标（`marketIcon`）＋ 分类/作者信息，排版成一张有设计感的「无图封面」；
  小卡仍用图标；大卡用放大的图标＋色场＋纹理/渐变，而不是现在的空渐变。
- 官方插件是否补图？这是**产品决策**，交新 AI 与用户确认；默认建议：官方各仓在各自仓库里补 `screenshots`（走 publish 自动 URL 化），壳仓不代画。

### 3.4 硬约束（用户反复强调，必须写进设计说明）

- **归一化**：媒体消费一个入口（`screenshots/cover`），渲染一个原语 + 变体（hero/duo/mega/small）；⛔ 各卡型各写一套。
- **无硬编码**：⛔ 按插件 id / 具体图片名写死；比例、轮播数、模糊/遮罩走 token/声明。
- **无死代码**：旧的无图渐变路径要么被新原语吸收，要么删掉；不留两套。
- **高内聚低耦合**：数据解析（已有）→ 视图模型（媒体选择/回落）→ 渲染件；三层不互相知道细节。
- **共享边界**（2026-11-21 拍板）：卡片长相/编排属**市场插件私有**，⛔ 抽进 `@linkdesk/ui`；壳只提供能力（媒体播放、浮层、主题/玻璃）。
- **视频**：只播作者给的直链，⛔ 不托管；controls 强制、⛔ autoplay（用户想「以后能放动态视频」——先支持**封面视频/悬停预览**，不做自动播放）。
- **未装态可达性**：所有图/视频必须绝对 URL（包内相对路径在未装用户那里 404，先例 = `marketIcon` 的 URL 化）。

## 四、用户口径（原话要点，设计时逐条对）

1. 首屏（hero）图片丰富度要上来——「硕大的图片中间只有一张图标，非常单调」；hero 的图可以占 **3:2 / 2:1**。
2. 大卡（双大卡、主题专区、hero）可以放**多张预设图**，hover 时在**卡内**轮播；小卡（横滚/榜行）只放插件图标。
3. 主题页（THEMES）每个卡片都该有图，而不是纯图标；主题卡本来就大，适合放图。
4. 板块节奏（大小卡交替）**主要是作者声明的责任**；我们该做的是把 API/声明设计好，让作者容易喂——不要替作者编排。
5. 策展（人工专题/编辑精选/榜单叙事/合集标签）：**只在能复用现有素材时做**；不要为了首页造一套新的编辑系统。
6. 动态/个性化（最近、推荐、折扣、活动）：不确定，可以给想法（HTML6 里演示），但别假设有服务器。
7. 社会证明（评分/评论）：**没有服务器**，先不做；可复用本地已有的下载量/已装状态。
8. 视觉材料：现在只显示图标；希望支持大图、截图、封面、**以后视频**。
9. 设计语言沿用现有：hover 浮空/放大、主题色光晕（MS Store 首页那种泛光）——这正是我们已有的设计语言。
