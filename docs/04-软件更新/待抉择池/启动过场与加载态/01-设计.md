## 一、用户诉求（原话归档）

1. 启动软件（安装版 / 免安装版 / dev 都一样）刚进去先是一片黑，只有一个「欢迎」标签页，然后十几个标签页「刷刷刷」一个一个出来，**主题系统最后才启动、跟着变色**——像没有加载态装饰的样子。
2. 侧栏好像也是「刷」出来的；**基本上每个地方都像是没有加载态装饰地直接蹦出来**。（凭多次启动的记忆，非实地演示。）
3. 看到「关于页」参考图的加载骨架后反问：启动是不是没有加载态？⇒ **立项做一个加载态**。
4. **拍板：三案合并**——「只改加载态难免有点少」，主题先行 / 首帧过场 / 加载态合为一项；过场要「**更自然**」；参考图要画好；文档必须让**下一棒 AI**（不一定是现在的 AI）明白要做什么、为什么做。

### 2.2 三个版本的差别

序列**三条路同一条**，差别只在速度：

- **dev**：走 Vite dev server（`main.ts:151-152`），每个 chunk 首次请求现编译 ⇒ ③⑤ 的「逐个蹦」观感最强。
- **安装版 / 免安装版**：同走 `app.isPackaged` 分支从 dist 加载静态文件（`main.ts:153-155`）⇒ 序列一样、快得多。两版代码路径**无差别**。
- **首次启动**额外慢一步：内置插件拷进 userData（`electron-builder.yml:63`「boot 首启自动装」）。

### 2.3 两条记忆的裁定

- **「从底部一点一点启动」：代码里不存在。** 池整框是一次 `pushLayout` 一次 React commit 画出来的（`PoolZoneShell.tsx:57-127` 一个 flex/grid 树），状态栏（Row 3）不比别处早。最接近的真相是幕③图标栏按插件顺序逐个亮，记忆把它压缩成了「从下往上」。**不要为这句话设计任何东西。**
- **「没有加载态装饰」：成立，且是结构性的。** 池被定为哑渲染器（`PoolZoneShell.tsx:20`「Path B：池 = 哑渲染器……池不知道世界为什么长这样」），结构上就没有「正在加载」的概念；壳 ready 前整体 null，等于放弃声明过场。全产品唯一加载态 = `PluginComponent.tsx:205` 的「加载中...」纯文字。

## 三、设计原则（五条，开工时逐条对照）

1. **真相源不挪，只加镜像。** 主题真相源仍是 `theme-defaults` 贡献 + `app.theme` 配置；快照只是「上一次权威结果的镜像」。权威管线照旧跑完并落地——**同值则零视觉变化，异值则一帧校正**。
2. **自然 = 整帧出现，不是「给逐个蹦加装饰」。** 逐个蹦的根因是「推得早 + 装饰少」；本方案选**消灭**（首推延后到插件就绪，§4.2）而不是给每个蹦出的图标配动画。用户拍板口径：「更自然一点」。
3. **安静动效：呼吸，不扫光。** 本机 IPC / 本地 chunk 加载是毫秒级，扫光是网络产品「要等很久」的心理语言；用透明度呼吸（详见 §4.3 规格表）。用户问「要不要一闪一闪」⇒ 答：**要动效但不要扫光**，且快于阈值根本不显示。
4. **可降级。** 快照坏了 / 没了 / 版本不符 → 静默回退现状行为（`:root` 暗兜底），绝不因过场挂掉启动。reduced-motion 下动效静止、骨架保留形状。
5. **零新 i18n。** 骨架与过场都不带文案，`aria-label` 复用既有 key「加载中...」⇒ 不触发 `lang-defaults` 发版（§六）。

## 四、合并方案（④A + ④B + ④C，④D 可选）

### 4.1 ④A 主题快照先行——消灭「先黑后变色」

**机制**：把「上一次权威应用的完整主题结果」（`data-theme` 值 + 全量 CSS 变量映射）镜像进 `localStorage`，开机在**首次绘制之前**同步读回并写上。

| 环节 | 落点 | 做什么 |
|:--|:--|:--|
| 写侧（唯一） | `src/core/services/ui/ThemeEngine/snapshot.ts`（新文件）；接线在 tokens 应用处（`ThemeEngine/tokens.ts:145` 附近） | 每次权威主题应用后，`localStorage.setItem("ldk.theme.snapshot.v1", JSON.stringify({ v: 1, type, vars }))`。只壳写（池同源共读，见读侧）；`typeof localStorage === "undefined"` 时跳过（单测环境） |
| 读侧·壳 | 根 `index.html` `<head>` 内联脚本（样式表之后、body 之前） | 同步读快照 → 校验（`v===1`、`vars` 为对象且含 `--bg-window` 等关键键）→ `documentElement.dataset.theme = type` + 逐键 `setProperty`。**无快照 / 校验失败 = 什么都不做**（现状兜底） |
| 读侧·池 | `pool.html` 同款内联脚本 | 池与壳同源（打包同 `file://` dist、dev 同 dev server host），读**同一个 key** ⇒ 池第一帧就是主题色 |
| OS 层背景 seed | `electron/main.ts:489`（首窗）+ `electron/windows/window-manager.ts:231`（池 WCV） | 主进程启动时 `fs.readFileSync` 读 userData 的 settings.json 取 `app.theme`（~1KB，try/catch 包死），dark→`#1e1e1e`、light→`#f5f5f5`，替换写死值。E5.8#6.6 hex 豁免注释模式照抄 |
| 失效与降级 | snapshot.ts 内 | JSON 坏 / 版本不符 / 关键键缺失 → 读侧返回 null，一切按现状走。**不重试、不写默认值、不打日志刷屏**（一次 `console.info` 足矣） |

**诚实边界（要写进验收）**：用户在软件外手改 `settings.json` 换主题后启动 → 先现快照（旧主题），权威管线落地后一次翻色。这是镜像机制的固有代价，频率极低，**不做**额外消解。

**为什么不用「只提前读 app.theme」就够**：`app.theme` 只是主题 id，完整观感含混搭/强调色/字面覆盖等全量变量——只提前 id 会在自定义外观用户身上仍看到一次变色。快照存**全量变量**才能做到「第一帧即上次的像素」。

### 4.2 ④B 首推延后 + 池首帧过场——消灭「半截框架」和「逐个蹦」

| 环节 | 落点 | 做什么 |
|:--|:--|:--|
| 首推门槛 | `src/hooks/usePoolSync.ts` 主推送 effect（:126 起）；`src/App.tsx:218` 传入新参 | 新参 `bootReady`：为假时**跳过 pushLayout**（后续每次 effect 重跑自然补推；池侧本就有缓冲回放，不怕晚）。门槛值 = ① **`setReady`（本设计推荐）**或 ② 更早的「主题已应用」信号（initAll Step 5 完成即推，早几百毫秒）——**待拍板 §八①** |
| 池首帧过场 | `pool-main.tsx` 的 `if (!layout) return null` → 渲染 `<BootMark />`（新组件，建议 `src/pool/shared/boot-mark/`） | 中央 logo（48px，取既有 `logoUrl` 同源资产）+ 产品名，低透明度呼吸。**延迟 150ms 才出现**（快启动根本看不到它，杜绝「logo 闪一下又没了」）；首份布局到达即淡出（120ms）替换。**无任何文字**（零新 i18n） |
| 幕②的「欢迎页先行」去哪了 | —— | 首推延后后，恢复的标签头随整帧一起到（restoreLayout 本就一次 setState）；welcome 兜底页仅在「上次全关光了」的场景自然出现，不再承担「启动占位」职责 |

**这一案的直接效果**：现状幕②③（半截框架、图标逐个亮、侧栏空框）整体消失——池要么是「主题色底 + 品牌 mark」，要么是**完整的一帧**。串行加载还在（④D 才动它），但它的过程被藏进了过场里。

### 4.3 ④C 内容加载骨架——给剩下的真实加载穿衣服

首帧之后仍在异步的只有两件事：各标签**内容 chunk** 的懒加载、侧栏 file-tree 的**读盘**。给它们统一的骨架。

**组件**：`src/pool/shared/view-skeleton/ViewSkeleton.tsx`（+ 同名 css）。纯展示，Path B 红线内。

**接线**：`PluginComponent.tsx:205` 的 Suspense `fallback` 从「加载中...」文字换成 `<ViewSkeleton />`；`aria-label` 复用既有 key `t("加载中...")`（**零新 i18n** 的关键）。

**规格（参考图 Frame 3 与规格卡同源）**：

| 项 | 值 | 理由 |
|:--|:--|:--|
| 结构 | 标题条（宽 40% × 高 12）+ 卡片块 ×2 + 行条 ×4（宽梯度 100/85/60%） | 与「关于页」mockup Frame 3 同一语言，全仓骨架一个长相 |
| 条高 / 间距 / 圆角 | 12 / 8 / 4 | 间距栅格 4 的倍数 |
| 出现延迟 | **100ms**（loaded 即不渲染） | 本地 chunk 毫秒级——快于阈值根本不出现，**不闪** |
| 动效 | **呼吸**：opacity 0.55 ↔ 1，1.4s ease-in-out 往复 | 安静；「一闪一闪」的扫光明确不用（§三原则 3） |
| reduced-motion | 动效静止，骨架形状保留 | 系统级无障碍 |
| 读屏 | 骨架条 `aria-hidden`，容器 `role="status"` + `aria-label`（复用「加载中...」） | 沿用关于页 mockup 的判定 |
| 侧栏 file-tree | 树行骨架（行高 20，与真树行同高）——挂在 file-tree 插件自己的视图里还是通用骨架兜底？**通用兜底即可**，插件侧改造不归本项 | 本项零插件参与 |

### 4.4 ④D（可选，高风险）插件并行分波加载

`loader.ts:96` 的串行 for + await 是「逐个蹦」的**时长**来源（④B 把它藏进过场，但没有缩短它）。可选改造：按依赖关系拓扑分波，波内 `Promise.all`。

- **收益**：启动过场总时长直接缩短（bundled 插件 6 个，串行改分波预计省 30–50% 过场时间）。
- **风险**：load-state 状态机（`loadState.ts`）、失败诊断日志（`loader.ts:141`）、依赖补装顺序都假设了串行语义；`dependencies.test.ts` 走真实 loadPlugin 验证。
- **裁决建议**：做，但**独立验收、可后置**——④A/④B/④C 落地后先量过场时长，不够快再上 ④D。**不与前三案同笔交付**。

## 六、跨仓后果

- **零新 i18n key（设计目标）** ⇒ **不触发 `lang-defaults` 发版**、不动目录与 `sync:bundled` 种子。`aria-label` 复用「加载中...」；若开工时加了任何新文案，先回来改本节并补 `lang-defaults` PATCH 发版链。
- 本项改 `src/` + `electron/` ⇒ 提交前必须调 `version-bump` skill 判类别：按现行口径 **`feat:` → MINOR**。
- 新增 CSS 走既有门禁面（`check-css-hardcode` / `check-spacing-grid` / `check-font-scale-audit` / `check-theme-audit`）：骨架与过场的颜色全部 `var(--xxx)`、间距 4 的倍数、字号走 token。
- 内联脚本是新面：`index.html` / `pool.html` 两份必须**逐字同源**（建议同笔加一条脚本对账或构建期注入，落点在 §八⑥ 一起拍板）。

## 七、验收（用户视角）

1. 亮色 / 自定义主题用户冷启动：**第一帧就是自己的主题色**，全程无「黑 → 变色」。
2. 全程看不到「半个框架」：要么品牌过场，要么完整一帧；图标栏**不再逐个蹦**。
3. 恢复的标签头一批出现；内容骨架 → 真身，替换无跳动。
4. 快于 100ms 的加载**不出骨架**（本地 chunk 命中时看不到任何加载态）。
5. 系统开「减少动态效果」→ 骨架静止、过场无呼吸，功能不缺。
6. 删掉 / 弄坏 localStorage 快照 → 回退现状行为，启动不崩、无报错刷屏。
7. 软件外改 settings.json 主题后启动 → 快照先现、权威值落地校正（允许一次翻色，§4.1 诚实边界）。
8. dev / 安装 / 免安装三版序列一致；首次启动（bundled 拷贝）不因过场变得更迷惑。
9. 多窗（ws-2+）与壳崩重建路径不受影响（`shellWindowOptions()` 同源继承 seed）。
10. `npm run check` 全绿；`audit-i18n --strict` 无新增面。
