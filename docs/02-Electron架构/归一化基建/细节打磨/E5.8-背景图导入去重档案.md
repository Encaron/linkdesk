## 一、现状与实机证据

`C:\Users\fengy\AppData\Roaming\linkdesk\appearance\`（实测）：

```
脉搏心率检测UI界面设计 (1)-1.png … (1)-19.png   ← 同一张 3.88MB × 19+
exported_image.png / -1 / -2 / -3              ← 同一张 × 4
```

来源文件名「脉搏心率检测UI界面设计 (1).png」→ 重选 N 次 → 后缀 `-N` 递增，全组同尺寸同内容。

## 二、根因（file:line + 机制）

**链条**：选图 → [renderControl.tsx:257-272](../../../../plugins/builtin/settings/src/views/SettingsView/renderControl.tsx#L257-L272)（每次点选无条件调 `importImage`）→ 主进程 [appearance-handlers.ts:23-47](../../../../electron/ipc/handlers/appearance-handlers.ts#L23-L47) 拷贝进 `userData/appearance/`。

**去重判据错**：`let dest = base; for (i=1; exists(dest); i++) dest = stem-N.ext`——判「目标名存在」而非「内容已入库」。每次复制都造出新名（`-N` 永不存在）→ 同源同内容永远复制一份新的。这是**名字去重，不是内容去重**。

**入口两个**：`app.backgroundImage`（[appearance.ts:293](../../../../src/App/config/appearance.ts#L293) uiHint "image"）+ `app.zoneBackgroundImage`（[appearance.ts:439](../../../../src/App/config/appearance.ts#L439) 同）→ 同一个 BackgroundImagePicker → 同一个 importImage IPC。**一个机制，两个受害者**（同玻璃 tint 结构）。渲染侧每次选都调 importImage，所以「重选同一张」也会复制。

**为什么必须拷贝**：沙箱挡 `file://` 直读（实机 bug 13），受控协议 `linkdesk-userdata://` 只服务 userData 内文件——「不拷贝、直引用原路径」架构不可行。VS Code 能直读工作区文件是它 webview 沙箱模型不同，不可借鉴；Obsidian/Notion 类 vault 也拷贝资产但**同样不去重**，非好榜样。**照片库/备份工具的内容哈希去重**才是正解。

## 三、修复 #152——importImage 内容哈希去重

改 `electron/ipc/handlers/appearance-handlers.ts`（零新 API/配置/贡献点）：

1. 源文件算内容哈希（读取流 SHA-256，MB 级图一次读取成本可忽略）。
2. 扫 `appearance/` 现有文件，逐文件算哈希比对 → 同内容 → **直接返回已有受控 URL，零拷贝**。
3. 无同内容 → 复制（保留 `-N` 命名处理「同名不同图」）。

**归一化**：哈希比对逻辑抽单 helper；目录列表一次性读。未来任何资产导入（图标/字体/素材）复用同 helper = 「资产入库内容去重」通用规则（本 bug 的「类定义」）。

**验证**：`npm run check` + 单测（同图重选 → 返回同 URL 且目录文件数不变；同名不同图 → 仍 `-N`）+ CDP 连续选同一图目录不增、配置值不 churn。
