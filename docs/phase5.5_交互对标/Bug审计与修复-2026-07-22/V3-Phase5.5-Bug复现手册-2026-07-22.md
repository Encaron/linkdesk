### A1 — 快捷发送串扰

**复现步骤：**
1. 侧栏点「+ 新建」→ 输入名称"测试1"→ 回车
2. 在"测试1"的快捷发送栏，点「+ 添加」→ 名称填"CMD1"，内容填"TEST1"→ ✓
3. 侧栏再点「+ 新建」→ 输入名称"测试2"→ 回车

**复现现象：**
"测试2"的快捷发送栏出现了"CMD1: TEST1"。

**如果没有这个 bug：**
每个新会话的快捷发送栏应该只有默认的 `AT: AT\r\n`，不会从其他会话串数据过来。

### G21 — 暂停/继续过渡期数据丢失 ⚠️ 本次实测无法确认

**复现步骤：**
1. 打开串口，以 115200 或更高波特率持续接收数据
2. 点「暂停接收」
3. 等待 2-3 秒
4. 点「继续接收」

**复现现象（预期）：**
暂停期间累积的数据中，最后约 16ms 的一帧数据永久丢失，不显示在接收区中。

**2026-07-22 Encaron 实测：**
发了日志文件。暂停约 8 秒，缓冲 105 条数据，继续后全部补回。数据速率太低（约 13 行/秒），16ms 过渡窗口内约 0.2 行——概率上基本不会触发。需要在 115200 波特率下（每秒 300+ 行）才能暴露。

**如果没有这个 bug：**
暂停→继续应无缝过渡——暂停期间缓冲的所有数据都应在继续时完整补回接收区。

### G23 — 拔掉所有 COM 口后下拉框不刷新 ⚠️ 部分确认（现象和原分析不同）

**复现步骤：**
1. 拔掉所有 COM 口设备
2. 新建终端会话
3. 观察 COM 口下拉框 → 仍显示已拔掉的端口（如 COM3）
4. 点「● 打开」

**2026-07-22 Encaron 实测：**
拔掉所有 COM 口 → 新建对话 → 下拉框仍显示 COM3 → 点打开 → 报错"串口打开失败：系统找不到指定的文件"。**Rust 正确拒绝了**（端口不存在），但下拉框没有刷新为空。

**和原分析的差异：**
原 bug 清单写的是"portName 为空时静默用残留值打开"——但实测发现 Rust 端会报错拒绝。真正的问题是**端口列表轮询后 UI 未同步清空已消失的端口**——下拉框显示了实际不存在的 COM 口。

**如果没有这个 bug：**
拔掉所有 COM 口后，下拉框应在 2 秒内刷新为空（或显示"无可用端口"），点打开应提示"请先选择串口"。

### G4 — Tauri listen 泄漏

**复现条件：** React StrictMode（开发环境默认开启）或 Vite HMR 热重载。

**复现步骤：**
1. 开发环境启动应用（`npm run dev` 或 `npx tauri dev`）
2. 触发 HMR（修改任意源码文件保存）
3. 多次触发后观察串口统计数据

**复现现象：** TX/RX 字节计数跳变异常——因为多个 listener 同时运行，每次数据到达被多次累加。

**如果没有这个 bug：** HMR 热重载后旧 listener 被正确取消，始终只有一个 listener 在计数。

### G5 — render 期间改 ref

**复现条件：** React Concurrent Mode（React 18 需主动开启，React 19+ 可能默认启用）。

**复现现象：** 在 Concurrent Mode 下，render 可能被丢弃并重放，ref 中的 `lastFocusedByType` 数据可能不一致，导致 `openOrFocusTab` 聚焦错误的标签页。

**如果没有这个 bug：** ref 更新在 `useEffect` 中（commit 后），保证数据和 DOM 一致。

---

### G6 — toLayoutData 在 Concurrent Mode 下崩溃

**复现条件：** 同 G5——React Concurrent Mode。

**复现现象：** `toLayoutData()` 返回的布局数据为空或包含 undefined，`saveTabLayout` 写入错误数据。

**如果没有这个 bug：** 布局保存使用 ref 而非 setState hack，Concurrent Mode 下正常工作。

### G8 — 卸载失败撕裂状态

**复现条件：** Rust `invoke("uninstall_plugin")` 抛异常（权限不足/目录被锁定/杀毒软件拦截）。

**复现步骤（极难触发）：**
1. 用外部程序锁定插件目录（如打开插件文件夹的资源管理器）
2. 插件市场卸载该插件

**复现现象：**
- 前端：插件已消失（图标栏移除、标签页关闭、注册表清理）
- 后端：文件仍在磁盘
- 用户无法恢复，只能 F5 刷新

**如果没有这个 bug：** 前端清理在 Rust 操作成功后才执行——invoke 失败时前端状态不受影响。

### G13 — loadPluginRuntime 不处理 mode/resources

**复现条件：** Phase 7 运行时（plugin:// 协议）加载协议/资源插件时。

**复现步骤（Phase 7）：**
1. 通过 plugin:// 协议安装一个 `"mode": "text"` 的协议插件
2. 观察协议是否注册到 ProtocolRegistry

**复现现象：** 协议解析器不注册——`manifest.mode` 被忽略。

**如果没有这个 bug：** `loadPluginRuntime` 和 `loadPlugin` 行为完全对等，同一份 manifest 两种加载路径结果一致。

### G16 — 手动删插件目录不自动卸载

**复现条件：** 用户手动在文件系统中删除插件目录（非通过 UI 卸载）。

**复现步骤：**
1. 用文件管理器手动删除 `plugins/` 下的某个插件目录
2. 回到应用，等待 10 秒以上

**复现现象：** 插件在 UI 中仍然存在——图标栏、已安装列表均未变化。

**如果没有这个 bug：** 文件监控应双向检测：新增 → 自动加载，删除 → 自动卸载。
