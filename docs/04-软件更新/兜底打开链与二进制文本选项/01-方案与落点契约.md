## 二、前半 · A 兜底打开链（T1–T4）

### T1 — 主进程总闸：空扩展名不再短路【壳】

落点：`electron/ipc/handlers/registry-handlers.ts`（`IPC.fileAssociation.getPluginFor` 处理器）

```ts
// 前
ipcMain.handle(IPC.fileAssociation.getPluginFor, async (_event, extension: string) => {
  if (!extension) return undefined;
  return resolveOpenTarget(extension, await readOverrideTable());
});

// 后
ipcMain.handle(IPC.fileAssociation.getPluginFor, async (_event, extension: string) => {
  // 空扩展名（无后缀 / 点开头文件）**不再在这里改道**——交 resolveOpenTarget 的最后一档（角色兜底）。
  // 服务层本就如此（FileAssociationService 用例 ⑥ 已钉），此前这行的 if 把设计意图掐了。
  return resolveOpenTarget(extension, await readOverrideTable());
});
```

- **契约不动**：`getPluginFor(ext): Promise<string | undefined>` 返回形保留（`undefined` 只可能来自更外层异常），⛔ 不改 d.ts、⛔ 不动 `IPC.fileAssociation.*` 通道集。
- **连带必改**：该处理器上方那段注释（原文「…空扩展名返回 undefined」）——注释与行为不许各说一套。
- **判定**：`resolveOpenTarget("")` 今天的实际返回 = 挂牌者（editor）；无挂牌者才落 `welcome`。

## 三、后半 · B 二进制文本选项（T5–T9）

### T5 — 编辑器能「强制文本加载」【插件 · editor】

落点：`editor/src/services/EditorModel.ts`（`load` / 字段 / `save`）

**状态拆成两个旗子**（这是本半的设计核心）：

| 旗子 | 语义 | 谁写 |
|---|---|---|
| `isBinary` | **事实**：壳判定这是二进制（判定归壳，一处真相源） | `load` 时由壳面回答 |
| `forcedText` | **用户选择**：「我知道是二进制，仍要拿文本看」 | 只有第三颗钮（或命令）能置位 |

```ts
// load 增加选项（默认 false —— 现有调用点行为零变化）
static async load(filePath: string, opts?: { forceText?: boolean }): Promise<EditorModel> {
  const normalized = lk.path.normalize(filePath);
  const buffer = await lk.filesystem.readBinaryFile(normalized);
  const probe = (lk.encoding as { isBinary?: (b: Uint8Array) => Promise<boolean> } | undefined)?.isBinary;
  const isBinary = typeof probe === "function" ? await probe.call(lk.encoding, buffer) : false;

  if (isBinary) {
    if (!opts?.forceText) return new EditorModel(normalized, "", "utf-8", true);   // 原路：提示页
    // 强制文本：照常 detect + decode（会得到乱码——用户已经知情并选择）
    const encoding = await lk.encoding.detect(buffer);
    const content = await lk.encoding.decode(buffer, encoding);
    return new EditorModel(normalized, content, encoding, true, /* forcedText */ true);
  }
  const encoding = await lk.encoding.detect(buffer);
  const content = await lk.encoding.decode(buffer, encoding);
  return new EditorModel(normalized, content, encoding);
}
```

`save()` 的守卫按 **D1** 收口（甲：`forcedText` 仍不可写；乙：可写，写前一次确认）。⛔ 无论走哪支，`isBinary && !forcedText` 那条**必须继续 throw**（提示页态没有内容可写）。

### T6 — 提示页加第三颗钮 ＋ 点亮后切态【插件 · editor】

落点：`editor/src/components/BinaryNotice.tsx`（加钮 ＋ 一个 `onForceText` 回调）· `editor/src/components/EditorTab.tsx`（切态与警示条）

- 三钮**同律**：视觉用共享 `Button variant="ghost"`；动作仍然**探测接线**（面不在就隐藏）——第三颗钮不需要探测（它是编辑器自己的动作，永远在）。
- 灯泡语义：第三颗钮 = **恢复**「T1 之前编辑器硬吃一切」的那条路，但**只在用户点名时**走。
- 点亮后：`state.model` 换成 `forceText` 加载的 model ⇒ `EditorTab` 自然落到 Monaco 分支；顶部挂一条**细警示条**（`已按文本强制打开 · 只读`，⛔ 不占标签栏那 35px），点击可**退回提示页**（重置 `forcedText`）。

### T7 — 呈现与保存策略【插件 · editor】

按 **D1**：
- **甲（推荐）· 只读**：Monaco `readOnly: true` ＋ 命令面同挡（`editor.save` 在只读态直接 no-op，⛔ 不许只挡 UI）；状态栏显示 `只读` ＋ 编码；⚠️ 语言映射回落 `plaintext`（`language-map` 对无后缀/未知扩展名的既有回落）。
- **乙 · 可编辑**：保存前一次确认（文案点明「写回会覆盖原二进制内容」）；⛔ 不做「静默可写」。

### T8 — 文案链【插件 · editor】

- i18n 新串一条：`仍旧以该编辑器插件打开`（`editor/i18n/en.json` —— 该册是「中文键 → 英文值」形态，按既有条目同格式追加）。
- 提示块描述句**不动**（`「{{name}}」是二进制文件，以文本打开只会得到乱码。`）。
- toast 文案（`binaryNoticeToastKey(canOpenWith, canSearchMarket)`）要不要提第三路 = **D3**：改则四组合 → 六组合，且**只描述真的渲染出来的钮**（该文件的既有纪律）。

### T9 — 命令面（硬约束 26 · 每个用户动作至少一条非鼠标路径）【插件 · editor】

- 新命令：`editor.forceOpenAsText`（名字待 **D5** 定稿时一并核准；⛔ 不得跨仓占用别家 id，R1 会拦）。
- 注册处：editor 插件自身命令面 ＋ `contributes.commands`（meta 必带 `description` ＋ `params`）；作者文档按 T5 交付物口径同步。
- 自查：`npm run audit:plugin-commands`（只报不拦）＋ 命令面板可见性人工确认。

## 五、不变量（本件不许碰的东西）

3. `FALLBACK_PLUGIN_ID = "welcome"` 的语义（无挂牌者时的兜底）——⛔ 不改成 editor 硬编码（铁律②：壳不写死插件 id）。
