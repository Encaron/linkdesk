#### E5.5#3+ 🔴 侧栏内容区——多 WebView 渲染模型切换

> **当前（单 WebView）：** `SidePanel.tsx` → `ToolbarSlot` + `SectionStack` 在壳的 React 树里渲染插件的 `sidebarComponent`。插件组件和壳共享 JS 堆 + DOM。
> **多 WebView 下问题：** 插件在自己的 WebContentsView 里跑。`ToolbarSlot`/`SectionStack` 不能直接渲染插件的 React 组件——组件在另一个进程里。
> **更关键的问题：** 同一个插件可能同时在侧栏（`viewRole: "sidebarPrimary"`）和主区（标签页）打开。一个 WebContentsView 只能在一个位置——不能同时在侧栏区域和主区显示。
>
> **方案 A（推荐先试）：** `sidebarPrimary` 插件的侧栏内容留在壳 WebView 渲染（和单 WebView 一样），只有主区标签页用 WebContentsView。`viewRole: "sidebarPrimary"` 的插件天然做了壳内渲染——它们的 sidebarComponent 本来就是被壳 import 的。崩溃隔离的主要价值在主区。
> **方案 B（如果方案 A 不够）：** 每个插件创建两个 WebView——侧栏一个 + 主区一个。内存翻倍，但完全隔离。
>
> **E5.5 默认走方案 A——简单、内存友好、侧栏内容不崩（壳兜底）。** 如果后续需要完全隔离再切方案 B。

- [ ] **E5.5#3f** 识别渲染模型——`viewRole: "sidebarPrimary"` 的插件在侧栏中 → **壳内渲染**（不创建 WebView，走现有 `ToolbarSlot`/`SectionStack` 路径）| 判断逻辑 ~5 行
- [ ] **E5.5#3g** 侧栏插件的 WebView 仅在其作为**主区标签页**打开时创建——位置在标签页内容区，不在侧栏 | 验证

## 第 3 层：OverlayWindow 叠加方案——根治 Z-order

> 🔥 **对标 VS Code。** WebContentsView 是 OS 原生视图，z-order 高于任何 HTML 元素。解决方案：把 HTML 悬浮层渲染在独立的透明无框 `BrowserWindow` 中，叠加在 MainWindow 上方——操作系统层面保证正确的 z-order。
>
> ```
> Layer 3 — OverlayWindow（透明无框，alwaysOnTop）
>   渲染：右键菜单 / SelectBox / Toast / Dialog / 命令面板 / 拖拽毛玻璃
>   鼠标穿透：无 overlay 区域 → 点穿到 MainWindow
>
> Layer 2 — MainWindow
>   壳 HTML：TitleBar + IconBar + TabBar + SidePanel + StatusBar
>   + WebContentsView × N（仅内容区，避开 TabBar/StatusBar）
>
> Layer 1 — 桌面
> ```
>
> **本层替换第 1 层 E5.5#4-#5 的临时方案。** 弹窗和毛玻璃不再需要 `setVisible(false)` hack。
>
> 涉及文件（新建）：
> - `electron/overlay-window.ts`——OverlayWindow 管理器（~200 行）
> - `src/core/services/OverlayService.ts`——壳侧 overlay 渲染协调器（~80 行）
> - `electron/ipc/overlay-handlers.ts`——IPC handler（~30 行）
