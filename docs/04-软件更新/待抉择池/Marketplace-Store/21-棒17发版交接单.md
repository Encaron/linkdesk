## 三、宿主环境坑（下一位必读）

1. **Node 出网被本机拦**：`curl` 直连 `api.github.com` 200、`gh` 可用；`node:https` 直连与经代理均 `socket hang up`。
   - Node `fetch` 可用：`NODE_USE_ENV_PROXY=1 HTTPS_PROXY=http://127.0.0.1:7890`（实测 200）。
   - `node:https` **不吃**该开关 ⇒ `linkdesk-plugin-sdk publish` 的网络腿不可用。
   - 本次 publish 用 `gh`/`curl` 按 SDK 语义复刻（顺序：建 Release → 传 asset `uploads.github.com` → Contents API upsert marketplace.json），资产与目录均以 SDK 导出纯函数（`collectManifestView`/`withCatalogIdentity`/`buildCatalogEntry`/`upsertCatalogEntry`/`sliceChangelogSection`）计算，零手抄。
2. **匿名 API 限流**：`sync:bundled` 读官方目录要走 GitHub API，必须 `GITHUB_TOKEN=$(gh auth token)`。
3. **`npm run check` 退出码会被管道吃掉**：`npm run check | tail` 恒 0；本地曾因此漏掉 `lockfile-sync` 与 `token-audit` 两处红。跑全量门禁一律重定向到文件再读 `EXIT:`。
4. **pre-push 的 release rehearsal 对 tag 推送显示 “no matching push files”**（本次实测被跳过）⇒ **CI 才是真门禁**，不要拿本地 hook 过没过当发版依据。
5. **安装版 userData 里的 marketplace 已是 1.3.0 的「开发构建」**（与发布资产文件哈希不同）；目录同为 1.3.0 ⇒ 应用判定「已装、无更新」。想观测「检查更新→真装上」必须先把装的那份降回 1.2.1（安装动作要用户点头）。
6. **插件仓本地 main 落后远端一个提交**：远端因 publish upsert 多了 `f20dd49`（只动 marketplace.json）；本地 main 仍指向 `e8b0a32`（作者身份 9 提交）。**下次推作者身份前先 `git pull --rebase`/merge**，否则被拒。
