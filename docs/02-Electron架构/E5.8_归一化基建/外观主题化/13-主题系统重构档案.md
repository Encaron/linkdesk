### #72 pool 侧主题广播陈旧键清理（P0，一石三鸟）

- **依据：** 用户痛点 3「themeColor=bubble 极限圆角切 dark 仍是极限圆角」、痛点 4「顶栏/区域间缝隙仍是深紫色/灰色」、痛点 6「切不带字体的主题字体不变」。审计根因 1：**用户所见 UI 全在 pool WCV**（BW 壳 DOM 空，`src/App.tsx` 返回空 `<div className="app-shell">`），而 pool 侧 `electron/preload-pool/events.ts:54-70` theme:changed handler **只 `setProperty` 新变量，从不 removeProperty 陈旧键**（line 60）；壳侧有完整清理（`src/core/services/ui/ThemeEngine.ts:281-289` `_lastCommittedKeys` 差集 removeProperty），pool 侧没有。
- **现象链条：** bubble 写 `surface-radius: 999px`（appearance.glass.radius）+ `radius-*: 999px` → 切 dark（无 radius/glass 域）→ 壳侧 removeProperty 回落 OK（但壳无可见 DOM）→ **pool 残留 999px 极限圆角**。极光玻璃写 `bg-titlebar: rgba(16,26,51,0.55)` 深紫 → 切 light（defaults 无 bg-titlebar）→ pool 残留深紫。宋体写 `font-ui: SimSun` → 切无字体主题 → pool 残留宋体。
- **具体解法：** preload-pool/events.ts theme:changed handler 对标壳侧 commitTokens 加差集清理：
  ```ts
  let _lastThemeKeys: string[] | null = null;
  // handler 内，setProperty 循环之前：
  if (_lastThemeKeys) {
    for (const key of _lastThemeKeys) {
      if (!(key in variables)) root.style.removeProperty(`--${key}`);
    }
  }
  // setProperty 循环（line 60）后：
  _lastThemeKeys = Object.keys(variables);
  ```
  注意边界：
  1. **量测键隔离**——`--surface-<zone>-bg-position` / `--surface-bg-size` / `--surface-bg-zones` 由 surface-zones.ts 自己写、**不在广播 variables 里**，差集清理只针对广播键集，天然隔离，不会误删量测键。
  2. **fontFaces 整表替换已有**（`applyFontFaces` 单 style 整表替换，幂等），`--font-ui` 值残留才是问题——`--font-ui` 若在 variables 键集里则自动清理。
- **落点：** `electron/preload-pool/events.ts`
- **验收：** CDP 实机三场景：① bubble → dark 切主题，`surface-radius`/`radius-*` 不残留极限圆角；② 极光玻璃 → light，`bg-titlebar` 不残留深紫；③ 宋体 → 无字体主题，`--font-ui` 回落系统字体。补 preload 侧单测（mock root.style）。**此任务完成 = 用户痛点 3/4/6 根治**，也是痛点 5「缺值不跟随」的根解法（缺值自动回落 `:root`）。
- **实现（2026-08-25，commit `27683422`）：** preload-pool/events.ts theme:changed 镜像壳侧 `_lastCommittedKeys` 差集 removeProperty（广播键集内陈旧 `--key` 清理；surface-zones 自写量测键不在广播集天然隔离）+6 单测（mock root.style）。

- **依据：** 用户想法 1「整软件各 zone 是否圆角——要一个开关」+ 想法 2「自定义圆角弧度——目前弧度只影响下拉框等；01 mockup 的 app.surfaceRadius 是按倍数来的（如 ×1.0）」+ 痛点 2「app.surfaceRadius 似乎只调组件圆角，不是 zone 圆角」。

### #83 字体切换下拉卡死 + 性能卡顿——实机复现专项（痛点 13 全实锤：定位溢出 + overlay 全屏拦截 + 性能排除）

- **依据：** 用户痛点 7「切换某些字体后下拉菜单点击就卡死」+ 痛点 13「有时拉 slider 卡、点按钮无响应；不同主题卡的程度不同；1057MB、6 子进程（107.4/10.2/572.5/112.9 效率模式/114.3/137.9）」。
- **CDP 实锤①（2026-08-25，玻璃态 dark）——OK 键点不动 = 弹窗定位溢出视口（根因 A）：**
  1. 只读排除层遮挡：zone 切片 `::after`（index.css:470-485 `pointer-events:none`+`z-index:-1`）、玻璃 tint `::before`（index.css:442-461）、BackgroundLayer 全 `pointer-events:none`；ColorPicker portal body、panel z600 > overlay z500 > 表面 z1，OK 键 `cursor:pointer`（ColorPicker.css:137）。
  2. **elementFromPoint 决定性**：真实路径点击 glassTint 色块 → 面板 `y=993→1258`（视口 `innerH=900`），**OK 键 `y=1187→1213` 全屏外 → `null`**。对照组面板 `top:150` → OK 键命中 `.colorpicker-ok`——组件本身无遮挡无指针问题。
  3. **根因链路**：SettingRow.tsx:96 `anchor={x:rect.right+4, y:rect.top}`（色块右上角）→ ColorPicker.tsx:181 直接 `left/top`，**无视口边界碰撞/翻转** → 色块在视口靠下（主题组 y≈993）时面板向下溢出。
- **CDP 实锤②（2026-08-25，新增）——overlay 全屏拦截 + 点击不关闭（根因 B）：**
  1. ColorPicker 打开时 `.colorpicker-overlay`（ColorPicker.css:4-8 `position:fixed; inset:0`，**无 pointer-events:none**）z500 全屏盖住设置页 → **elementFromPoint(可见 slider 轨道中心) → `.colorpicker-overlay`**（不是 slider）→ 背景所有 slider/按钮点击被拦截 = 「点按钮无响应」。
  2. **OverlayPortal.tsx:42-50 外部点击检测 `contentRef.contains(target)`**：`.colorpicker-overlay` 是 contentRef 的 **children** → 点击背景（命中 overlay）`contains=true` → **不触发 onClose** → 无法点击背景退出。
  3. 唯一关闭出路 = Escape（OverlayPortal.tsx:56-61）或 OK 键——OK 键屏外（根因 A）→ **用户被困在 ColorPicker：设置页全点不动 + 确认不了 → 体感「卡/失灵/按钮无响应」**。
  4. 修复方向：overlay 点击应关闭（对标 VS Code modal：点遮罩关闭）——overlay 排除于 contentRef 之外或绑 onClick→onClose；或 OverlayPortal 加「backdrop 属 content 外」语义。
- **CDP 性能实测（2026-08-25，新增）——slider 引擎/IPC/CSS 层无性能瓶颈（候选假说全推翻）：**
  1. 广播链：`theme:changed` 到达 pool **21ms**；CSS 变量应用 **~90ms**；单步往返（dispatch input → `--glass-opacity` 更新）**21-40ms**（p90 37ms）。
  2. 60Hz 突发（8ms 间隔 60 步）：dispatch 结束 2075ms（每步 ~35ms）→ **6ms 内收敛**、**恒定 1 步滞后**、零 longtask、值不丢失。
  3. 同步 burst 60 次（同宏任务）→ React 自动批处理合并 → **10ms dispatch + 66ms 收敛**（非真实拖动场景）。
  4. **推翻**：backdrop-filter 合成压力（A/B 玻璃 5px vs 非玻璃 fps 均 61 满帧、60 步 1197 vs 1120ms ~6% 差）；IPC/广播风暴（21ms 到达）；主题广播（#59 已收敛 7→1）。
  5. **「743ms/761-1019ms 往返」= 后台节流测量伪影**（窗口 `visibility:hidden` → setTimeout 节流 1s，轮询间隔被放大；同步 evaluate 正常、await 型全超时、`ticksIn200ms=1`）。窗口激活（CDP `Page.setWebLifecycleState active` + bringToFront + focus emulation）后恢复 21-40ms。
  6. **结论**：slider「卡」真实来源 = 根因 B（overlay 打开时 slider 拖不动）+ 值反馈缺失（slider 无数值显示，用户想法 4.2 / #77）；性能层无引擎瓶颈。
- **1057MB / 6 进程**：未单独深挖——E5.7 极简池预期 ≈5-7 进程属 Chromium 常态；内存/进程数留待 #83 修复回归时顺带核对。
- **修复方案（落点）：**
  1. 根因 A：`shared/color-picker/ColorPicker.tsx` 加视口边界翻转/收拢（下方放不下向上翻/clamp）——回归验证 OK 键任意滚动位置可 hover/点击。

  3. 性能：无引擎瓶颈无需专项；#77 slider 数值显示为反馈层补充。
- **验收：** glassTint 弹窗任意滚动位置 OK 键可 hover/点击；ColorPicker 可点背景/overlay 关闭；关闭后背景 slider/按钮立即可操作；slider 拖动无引擎层卡顿。
