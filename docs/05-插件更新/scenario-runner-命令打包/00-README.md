# scenario-runner · 命令打包（把常用命令串成一份"剧本"，一条命令跑完）

> **状态：📋 立案待实施**（2026-11-12 用户拍板建夹；**急用再发**，不排期）。
> **定位**：**普通插件 · 零宿主新能力**——只用壳已有的 `commands.executeCommand` 与 `commands.getCommands`，不新增任何通道。
> **用户定调（2026-11-12）**：「很多地方可能都会用到它」——某个工程经常要连着跑七八个命令、且很多人都在用 ⇒ 把这一串包成一份剧本随插件发布，别人装上就能用。
> **归属**：05（纯插件侧）。⛔ 不碰壳、不碰其它插件源码。

## 〇、它是什么 / 不是什么

**是**：一个"命令打包器/动作录像"。把 N 条命令按顺序存成一份文件，装了这个插件后，调**一条**命令就能从头跑到尾。

**不是**：
- ⛔ 不是命令归类器——它**不会**把别的插件的命令收进自己的索引，也不改命令面板；
- ⛔ 不是调度系统——不做条件分支、循环、变量替换（DSL 一膨胀就是死代码）；
- ⛔ 不拥有任何业务——它不认识串口、不认识文件、不认识硬件。

## 一、真实痛点（为什么值得一个插件）

- 机械化工程：一次验收要连着跑七八条命令，**每次都要复述一遍**；
- 这些命令**很多人都在用**（比如 Electron 工程的「启动 dev 模拟 → 跑检测 → 读结果」）⇒ 写一次、随插件分发，别人不用重学；
- 人也要用：不想每次都让 AI 代劳，点一下即可；
- 失败时要能定位**第几步挂的**，而不是"这一串里不知道哪坏了"。

## 二、设计（数据驱动，代码里零命令 id）

### 剧本形态

```json
{
  "version": 1,
  "id": "electron-dev-smoke",
  "title": "Electron 开发冒烟",
  "description": "起 dev 模拟 → 等就绪 → 跑三项检测",
  "steps": [
    { "command": "some.plugin.startDev", "args": [], "label": "启动 dev" },
    { "command": "some.plugin.waitReady", "args": [{ "timeoutMs": 30000 }], "label": "等就绪" },
    { "command": "some.plugin.check", "args": ["a"], "label": "检测 A" }
  ]
}
```

- **命令 id 只出现在数据里**（⛔ 不写进代码）——这就是"无硬编码"；
- `version` 留槽位，未来只加字段不删字段；
- 每步只允许 `command / args / label`（**最小**，防止变成编程语言）。

### 剧本放哪

1. **随插件内置**（`resources/scenarios/*.json`）——装了就有的常用剧本；
2. **用户自定义**（追加目录）——落点必须先在 [用户机落点规范](../../开发管理/用户机落点规范.md) 登记（硬约束 27）。

### 跑之前必须校验（防静默坏）

1. 每条命令是否还在（`getCommands()`）——不在就**当场报错并列明第几条**；
2. 参数形状是否对得上（能校验的部分）；
3. ⛔ **不许跳过坏的步骤假装跑完**。

## 三、命令面（meta 必须带 description ＋ params，硬约束 26）

| 命令 | 作用 | 回执 |
|:--|:--|:--|
| `scenario.list` | 列出可用剧本（内置＋用户） | `{ok, scenarios:[{id,title,description,source,steps}]}` |
| `scenario.describe <id>` | 一份剧本的完整步骤（跑之前先看清） | `{ok, scenario}` |
| `scenario.run <id>` | 顺序执行 | `{ok, scenarioId, steps:[{label,ok,tookMs,error?}], failedAt?, tookMs}` |

- `failedAt` = 失败步骤的序号与 label（人话可读）；
- 默认**遇错即停**（`stopOnError:true`），不提供"继续跑"选项（先不做，防死代码）。

## 四、边界

- **卸载即消失**：其它命令完全不受影响，壳零改动；
- **不反向依赖**：剧本引用的插件没装 ⇒ `scenario.list` 仍列出，但 `run`/`describe` 明确标「缺命令」，⛔ 不假装可用；
- **不做**：定时/触发/监听（那不是它）、跨机器同步（先不做）、变量与条件（先不做）。

## 五、验收判据

1. 装上 → `describe` 多出 3 条命令，meta 带 description/params；
2. 一份内置剧本 + 一份用户剧本各跑通；`failedAt` 能准确定位；
3. 故意写一条不存在的命令 → 跑前就报错并指出第几步，⛔ 不执行任何一步；
4. 卸载 → 其它命令照常、壳无残留（`grep` 壳侧零命中）；
5. 门禁：插件仓 `verify` 九段全绿；命令 meta 完整。
