# 记忆文件通胀——归档与瘦身

> 2026-08-06。127 个 memory 文件，MEMORY.md ~200 行索引。每次 session 全量加载。
> 位于 E5 收尾 → `05-收尾/架构债/`

---

## 一、问题

127 个记忆文件，涵盖 Phase 3 (Tauri)、E3、E4、E5 四个时代的 bug 记录、设计决策、专题文档。很多引用代码行号已过期（E5#42 目录重组后大量文件路径变更）。

MEMORY.md 每次 session 都加载全量索引——200 行。但对当前工作有用的可能只有 30 行。

类比盲审对 CLAUDE.md 的建议：历史记录对考古有用，对"现在干活"是噪声。

---

## 二、方案

```
memory/
├── MEMORY.md              # 索引——只列 active/ 下的文件
├── active/                # 当前有效（日常 session 加载）
│   ├── e5-execution-progress.md
│   ├── keybinding-architecture.md
│   ├── terminal-serial-monitor-disambiguation.md
│   ├── api-naming-mandatory-read.md
│   ├── hard-constraints.md
│   ├── ui-ux-pro-max-rules.md
│   ├── user-profile.md
│   ├── dev-environment.md
│   └── ... (~20 个核心记忆)
├── archive/               # 历史记录（考古时手动翻）
│   ├── e3-complete.md
│   ├── e4-complete.md
│   ├── v2-lessons.md
│   ├── e4-sticky-abandoned.md
│   ├── phase3-drag-bugs.md
│   └── ... (~100 个历史记忆)
└── index-active.md        # MEMORY.md 的当前精简版
```

**判断标准：** 新 AI 进场时"必须知道"的放 active，"可能想知道"的放 archive。

**Active 留存标准（同时满足）：**
1. 引用的代码路径和行号仍然正确
2. 描述的行为当前软件中仍存在
3. 新 AI 如果不知道这个信息会踩坑

---

## 三、执行

不是一次性搬完——按优先级：

1. **先搬已确认过期的：** E3、E4、Phase 3 的 bug 记录 → archive
2. **再搬"看一眼就够了"的：** 设计决策、架构理论、参考文档 → archive
3. **保留在 active 的：** 硬约束、API 命名、快捷键架构、终端歧义、E5 进度、UI 规范、用户档案

---

## 四、涉及

| 范围 | 改动 |
|:--|:--|
| `memory/MEMORY.md` | 重写——只列 active 文件 |
| `memory/archive/` | 新建——搬 ~100 个历史记忆 |
| 记忆文件 frontmatter | 可选——加 `status: active | archived` |

**改动量：** ~30 分钟整理，零代码改动。
