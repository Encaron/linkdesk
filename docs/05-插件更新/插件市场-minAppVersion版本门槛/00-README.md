## 一、机制全景——三层

### ① 详情页安装门（既有硬拦，E6#30.8c）✅

- 比对点：市场插件 `src/views/detail/DetailView/useInstallAction.ts:70`——`compareVersions(app.getVersion(), entry.minAppVersion) < 0` → **拒装**。
- 提示：error toast「**需升级 LinkDesk 至 {{version}} 才能安装**」＋ 元数据「需 LinkDesk vX」**标红**（`info-groups.tsx:140`，`warn={appBelowMin}`）。
- 实机已验证（E6#30.8c：demo-minapp 声明 99.0.0，确认弹窗前即拒）。
- 诚实边界：壳版本读失败 → **放行不拦**（fail-open，「诚实不缺省拦装」，E6#30.8c 原口径）。

### ② 三道缝（本案要补的）⚠️

| 缝 | 位置 | 现状 |
|:--|:--|:--|
| 手动更新 | `useDetailVersionAction.ts` | 只有离线／缺下载地址／缺执行面／来源确认卡／降级确认——**无 minAppVersion 比对** → 能更到要求更高壳的版本 |
| 自动更新 | `services/updateDiscovery/plan.ts`（planDiscovery／selectAutoCandidates） | 只比 semver 新旧 ＋ 钉版／通知记账——**不查 minAppVersion** → 会自动更到用不了的版本 |
| 侧栏行内安装 | `views/sidebar/ExploreView/useCatalogInstall.ts` | 只有来源确认卡（installGate），**不过详情页那道版本门** → 行内装得上详情页装不上的包 |

### ③ 壳加载门（唯一引擎侧硬机制，兜住所有路径）✅

- 壳仓 `src/pluginLoader/resolution/runtime.ts:202-220`：加载时读**包内 manifest** 的 `minAppVersion`，高于当前壳 → `markLoadFailed` ＋ error toast「插件「X」需要新版主软件才能用（它要 Y 或更高，当前 Z）——已跳过，请先更新 LinkDesk」。
- 兜住：市场更新、自动更新、行内安装、手装 zip、任何插件调壳 API 静默装——壳安装／更新 API 本身零版本判定（installGate 诚实边界自认「主进程零信任判定」）。壳本体不受影响，只是该插件功能缺席。

### 辅助：兼容读数（只显示、不拦人）

- 详情页「兼容性」组调壳 `getCompatibility`（E6#117，壳仓 `src/core/compat/compatibility.ts`）显示五态——不满足显示红标「**不适配**」。
- 壳会算**实际地板**（G4）：扫插件产物对 `@linkdesk/ui` 的具名导入查 `since` 账本取 max，生效地板 = max(声明, 实际)；账本查不到的名字 fail-closed 按不满足。**读数不拦人**（原文：「既有硬机制的读出，本模块不拦人」）。

## 三、补缝方案（✅ 2026-11-05 用户四项全拍：立项／四入口一次到位／停旧版＋通知／跳转入口不做）

把 `useInstallAction.ts:70` 的比对提为**市场内共享单点**，四个入口统一过门：

1. 详情页安装（已有，改为调单点）；
2. 侧栏行内安装（补）；
3. 手动更新 `doVersionAction`（补）；
4. 自动更新候选过滤（补——不满足的版本**停在旧版**，而不是更到用不了；与 pinnedVersion「停在旧版」语义同向）。

**拍板记录（2026-11-05 选择题四问，全按推荐）**：

- ① **立项做**；
- ② **四入口一次到位**（比对提市场内共享单点，四个入口全走同一道门）；
- ③ 自动更新遇不满足候选 = **停在旧版＋铃铛通知一条**（「新版本需要 LinkDesk X」；复用既有 `lastNotifiedVersion` 去重，不重复打扰）；
- ④ toast 跳转软件更新入口**本刀不做**（保持纯插件侧零壳改动；将来单独一刀）。

不满足时提示口径照抄 30.8c（toast「需升级 LinkDesk 至 X」＋ 元数据标红），更新路径同文案。

## 四、分档拍板：为什么记 05 不记 04

- **2026-11-05 用户拍板**：「凡是任何涉及到动软件本体，导致软件必须升级的，无论插件侧比重多大，都应该加入到软件更新中」；反之**壳零改动 → 05**。判据 = 动没动壳本体、产不产生壳发版需求，**不看插件侧比重**（memory `docs-04-05-filing-rule`）。
- 本案补缝全在市场插件仓、随插件独立发版 ⇒ **05**；`04-软件更新` 收壳本体更新点与发版攒批，本案在那边没有落脚格。
- **边界**：若实施中发现光靠市场 UI 拦不干净、需要壳引擎侧（安装／更新 API）也加校验——动了壳 ⇒ **整案翻 04**。就现状查账不需要：加载门（壳侧已有）已兜底所有路径。
