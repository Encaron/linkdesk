> **一句话**：把 CSS 类名从「14 个名字的**登记豁免表**」收敛成**一句不需要查表的规则**——插件自有前缀、共享组件 `ldk-` 前缀、宿主工具类定格；并让规则**机器可验**（门禁）且**只有一份真相源**（文档不手抄）。
>
> **前档**：[11-样式命名空间审计.md](../11-样式命名空间审计.md)——`.badge` 真案的审计与处置五级（A–E）。**本档是处置 E 的展开、立项与派工。**
> **硬约束**：23（[CLAUDE.md](../../../../../CLAUDE.md)）——本系列是它的**存量清账**，不是新增约束。
> **接力入口**：[交接.md](交接.md) 顶部那段（**一个 AI 一个任务**）。
> **立案**：2026-09-15 用户拍板「做」＋ 同日拍板「拆成多个 AI 一人一件执行」。
>
> **非新能力声明（`check-design-flow` §8.4 ③）：** 本档是**专项方案与执行实录**（现状读数 / 派工表 / 完成读数），**不含新能力设计**——文中出现的类名、字段、命令、`contributes.*` 声明均为**引用既有实现**（登记表、门禁脚本、插件清单的既有字段），本档只是把它们**记下来 / 验一遍**。⇒ **无需新能力设计前置**。

⇒ **「记债不排期」在账面上是最差的一档**：以「今天无收益」为由，推迟一件**越晚越贵**的事。

另有两层（用户点明，见 memory `ai-friendliness-three-layers`，2026-09-14 已定稿为**四层**）：

- **层 3 工程可读**：判据是「让 AI 不需要追踪」。今天壳的 `.toggle` 样式一改，要 grep 所有插件 CSS 才知道谁被影响；加前缀后**没有任何插件能被命中，追踪需求归零**。
- **层 4 插件易造**：今天一个陌生作者的 AI 写插件，必须**先记住 14 个保留名**（外加 9 个关键帧名）才不会撞；规则收敛成一句可复述的话之后，**AI 不需要知道任何一个具体名字**。这正是核心公式「你要的不是 AI 更聪明，你要的是代码不给 AI 犯错的机会」在 CSS 上的落地。

### 1.3 🔴 机制纠正——失效**不是运行时即时发生**，而是**插件升级 ui 时发生**

11 档（与 #109g 原行）写的是「破坏跨仓插件的既有 scoped 调优」。本轮把**时序**量准了，它决定发版顺序：

- **共享组件 CSS 是打进插件自己 bundle 的**（`@linkdesk/ui` 在 L7 已确认为**非 external**——实读：`file-tree` / `marketplace` / `my-cool-plugin` / `serial-monitor` 的 `index.bundle.css` 里都带 ui 的样式）。
- ⇒ **只改壳 + 只发 ui，对已发布的插件不构成即时破坏**：它们自带旧 ui 的 CSS，渲染什么就定义什么，自洽。
- ⇒ 真正的失效点在**插件升级 `@linkdesk/ui` 的那一下**：它的 scoped 调优（§1.2 那 7 处）失配，样式**静默**不再生效。
- ⇒ **结论（发版顺序的依据）**：壳与 ui 可以先发（零破坏窗口），**各插件仓必须同批适配重发**，否则它们下次升级 ui 时才炸。

> ⚠️ 与 `.input` 的区别（件 4）：`.input` 是**宿主 `index.css`** 的全局工具类，与插件视图**同表、运行时共享**——插件渲染 `className="input"` 是在**借运行时存在的那份**。所以对 `.input` 的任何改动都是**即时破坏**，必须与插件重发同批（见 `#109j-b`）。

### 1.5 门禁的现状与已知盲区

- 壳侧 `scripts/check-css-namespace.mjs`：4 判据（① 共享组件新增裸定义 ② 跨组件借用 ③ 宿主新增全局工具类 ④ 关键帧重名）+ **判据⑤ 登记 ↔ 实况反向核对**（表烂即红）。
  - 🔴 判据⑤ 是**本系列能分批推进的关键**：清了 `classes.shared` 的条目，门禁**立刻**会红——所以**每批必须同笔清自己那几项**。
  - 判据① 的「裸」= **类名不含连字符**（带前缀的已自带命名空间，不在本条判据内）。
- 插件侧 `@linkdesk/plugin-sdk` 的 `check-css-namespace` 腿：读**包内** `schemas/reserved-class-names.json`（随包下发，作者自己可读）。
- ⚠️ **盲区 1（本轮新发现）**：「裸 = 不含连字符」这条启发式**看不见组件之间的族名借用**——活例：`Combobox` 渲染 `selectbox-open` / `selectbox-disabled`，而 `.selectbox-disabled` 是 `SelectBox.css` 的**裸定义**（同一 §C4 形态，今天靠「同包内协调」相安）。本系列**保持该借用不变、只加前缀**（`ldk-selectbox-*`），把「拆不拆」留给将来。
- ⚠️ 盲区 2：`.input` 这类**运行时同表**的宿主工具类，插件渲染 10 处，门禁不管。

| 风险 | 说明 | 对策 |

| **静默失效**（本系列主风险） | 这个 bug 类的形态是「不报错、只是长得不对」——失配的 scoped 调优不会红，只会不再生效 | **唯一体检手段是眼睛**：1.12 实机逐屏看 6 个面（设置滑杆行 / 市场详情 changelog 与徽标 / 串口控制栏下拉 / 壳标题栏按钮 / 表单行开关 / 主题卡片徽标） |

## 六、边界（**本系列不做**，别顺手做）

1. **不做渲染隔离**：`@layer` / shadow DOM / CSS Modules 一条都不上（前缀降低撞名概率 ≠ 隔离；隔离是另一条路，独立立项）。
2. **不改词干**：`.mdv` / `.sle` 这类缩写**保持原样**，只加前缀——词干改名是第二次破坏面、零收益。
3. **不拆组件间族名借用**：`Combobox` 复用 `SelectBox.css` 的 `selectbox-dropdown/list/item/empty` 是**有意设计**（`Combobox.css` 文件头写明「一个视觉语言一处写（jscpd 0 克隆门禁）」）——只加前缀，不重构。
4. **不动宿主 `.input`**：在 `#109j-b` 拍板前，`.input` 保持原样（它是运行时同表的即时破坏面）。
5. **不动关键帧命名空间**（`selectbox-in` 等 9 个）：另一条轴，今天跨方重名 0，无收益。

### 9.4 发现的意外（三条，都值得下一棒记住）

1. **dev 实机与 vite 的放行表**：`server.fs.allow` 只有 `[仓库根, %APPDATA%/linkdesk/plugins]` ⇒ 隔离 userData（或 junction 指向）下的插件 bundle 经 `/@fs/...` 取不到（返回 SPA 兜底 HTML，表现为「详情视图落壳保底」条条刷屏）。**解 = 临时 vite 配置**（`mergeConfig` 加白名单，放 `.gitignore` 的 `scratch/` 里，不进仓）。⚠️ 附带一个陷阱：**重定向 `APPDATA` 环境变量对 Chromium 无效**（走 Known Folder API），进程会落回真实 userData → 撞上用户实例的单实例锁 → **秒退且 EXIT=0**、只留一行 `DevTools listening`。
2. **dev 下「市场 → 确认更新」会 `EPERM`**：`plugins:commit-update` 的 `rename plugins/<id> → <id>.bak` 被 vite 持有的文件句柄挡住。**非产品缺陷**（打包版经 `linkdesk://` 读盘、不持句柄），但 **dev 里别指望这条更新路径**——改用「停 app → 手动解包到 `plugins/<id>/` → 重启」。
3. **两处面点名的选择器在当今生态里没有渲染点**：`.titlebar .ldk-button--sm`（要插件 `contributes.titleBar`）与壳共享 `FormRow`（`.form-row > .ldk-toggle`，壳内零消费、唯一落点在插件侧）。⇒ 想常态化回归这两处，**得先有夹具插件**；否则「看不到」是**正确结论**，不是回归失败。

⚠️ **另一条流程实况**：E6 执行清单里 `#109g-1…g-7` **七格此前一直是未勾状态**（前几棒只写了层头轮次进度行、没动格子，勾选纪律被漏掉）——1.12 收口时一并补齐（每格一行结论），`#109g` 总任务同笔勾掉。
