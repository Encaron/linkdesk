### 1.1 冲突处理现状（两条注册路径）

| 路径 | 归属怎么来 | 出处 |
|:--|:--|:--|
| **`plugin.json` 静态声明** | **真 `pluginId`** | `src/pluginLoader/contributions/contributions.ts:65`（`registerCommand(pluginId, {...})`） |
| **运行时注册**（池 / 壳各半程） | 🔴 **`commandId.split(".")[0]`——名字第一段** | `src/core/registry/commands/CommandRegistry.ts:150`（`registerPoolCommandMetadata`）· `:186`（`registerShellLocalCommand`）· `electron/preload-pool/commands.ts:36-39`（`commandOwnerId()`，同一约定） |

**覆盖分支**（`src/core/registry/commands/CommandRegistry.ts:57-73`）：

```ts
if (_commands.has(command.id)) {                       // :58
  const existing = _commands.get(command.id)!;
  for (const [pid, ids] of _pluginCommands) {          // :62
    if (ids.has(command.id) && pid !== pluginId) {     // :63
      console.warn(`[CommandRegistry] "${command.id}" 被覆盖——原注册者: ${pid}，新注册者: ${pluginId}`); // :65
      break;
    }
  }
  existing.handler = command.handler;                  // :67  ← 覆盖照旧发生
  existing.title = command.title;
  existing.placeholder = command.placeholder;
  return () => {};                                     // :71  ← 首注册者持删除权（防误删他人命令）
}
```

⇒ **warn 只是打印，覆盖照旧**；且**删除权归首注册者**——即「后来者的注册被记住、却由别人持有删除权」，语义已经拧了。

### 1.2 🔴 本格新发现：三个**可判定的真害**（30 号档未记）

| # | 真害 | 机制 | 出处 |
|:--:|:--|:--|:--|
| **H1** | **覆盖告警会被整段吞掉** | 两个插件都**运行时注册** `acme.doThing` ⇒ 推导归属**都是 `"acme"`** ⇒ `pid !== pluginId` **恒 false** ⇒ **静默覆盖，一声不响** | `:63` ＋ `:150,186` |
| **H2** | **注销会牵连别人的命令** | `unregisterCommands(pluginId)` 按 `id.startsWith(pluginId + ".")` **整片删** ⇒ 插件 `beta` 注册的 `acme.foo` 会在**卸载 `alpha`** 时被一并摘掉 | `electron/preload-pool/commands.ts:82-87` |
| **H3** | **`on-command` 激活会去 import 别人** | 命令 handler 池内 miss 时，池按 `commandOwnerId(commandId)` **去 import 那个"属主插件"** ⇒ **名字的第一段被当成身份用** | `electron/preload-pool/commands.ts:45-61` |

> 🔑 **H1 是本轴的样板级发现**：它说明**「归属」这件事在本仓有两种表达——「表里记的」与「从名字推的」——而两者可以互相矛盾**。修法不是「把 warn 喊大声点」，而是**让归属只有一个来源，且那个来源是身份而不是名字**。

### 2.3 存量 21 个 `explorer.*` 的裁决（**必须逐条给结论，不许含糊**）

#### 10.2.2 🔴 「还回 `editor.*`」的确切含义（**与 1.42 的两处口径必须一致**）

- **本条（1.31）的裁决**：`editor.selectForCompare` / `editor.compareWithSelected` → **`file-tree.selectForCompare` / `file-tree.compareWithSelected`**。
- **「还回」= 还回命名空间，不是搬走功能**：这两个功能的**实现**（`_selectedForCompare` 模块状态 ＋ Diff 打开逻辑）**就在 `file-tree` 里**（`commands/compare.ts:11-29`），`editor` 插件**从未声明、也从未实现过它们**（实测：全容器只有 `file-tree` 的 4 处命中）⇒ 它们**本来就是 `file-tree` 的命令**，只是**借了 `editor.` 这个牌子**（后果：卸载 `editor` 会删掉 `file-tree` 的命令 —— §〇c.3 第 1 条活体）。
- ⇒ **改名后 `editor.` 命名空间只剩 `editor` 自己的命令**，这就是"还回"。
- ⚠️ **另一读法（本次不采纳）**：「把 Diff 比较功能整体搬进 `editor` 插件」——那是**跨仓功能搬迁 ＋ 产品决策**（会改变右键菜单的归属方），**不在本轴射程**，也不该由评估轮静默决定。⇒ **登记为「不属本件」，如需仍由用户拍板**。
- 🔴 **1.42 引用本条时，口径必须逐字一致**（[12 号档](12-任务-清账-file-tree.md)把这两条写作「还回项」；本格确认**还回 = 换回 `file-tree.` 前缀**，**不是**搬代码）。

## 十一、归属来源的方案裁决（§2.2 —— 四路线**逐条裁，选出一个**）

### 11.0 裁决先行

> 🔴 **选（甲）「让运行时注册带真身份」为主干。**
> **（乙）与（丙）不是并列选项，而是甲的「静态前置」与「运行时候裁语义」——两者都必须做，但都不能单独成立**（理由见 11.1）。**（丁）否决。**
>
> 一句话：**根因是"归属从名字推"，所以修法只能是"让归属从身份来"；（乙）保证名字这条退路也还能用，（丙）规定身份冲突时怎么办。**

### 11.1 四条逐条裁

| 路线 | 裁决 | 理由（含**为什么它单独不够**） |
|:--|:--:|:--|
| **（甲）运行时注册带真身份** | ✅ **主干，选中** | **唯一直接消灭根因的一条**。H1（告警被吞）· H2（注销连坐）· H3（错方激活）**三条全部**由「归属 = `commandId.split(".")[0]`」派生 ⇒ 换掉这个来源，三条一起消失。**代价可接受**：身份来自**注册方显式申报**（`notifications.source` 已有先例，`ui.ts:26-32`），谎报问题**与既有先例同级**（先例已接受）。🔴 **可行的关键实证**：**"声明面"本身就是一份身份真相源** —— `contributions.ts:65` 用**真 `pluginId`**（来自 plugin.json）注册每一条声明命令 ⇒ **绝大多数命令的真归属在壳里早就有了，只是运行时那条路没去问它**（见 11.2 的落地形状） |
| **（乙）名字前缀结构化 ＋ 禁止跨界** | ✅ **必做，但只是静态前置** | 它把「`<pluginId>.`」变成**可机械判的红线**，让第三方作者**在自己仓里就被拦下**（§〇c.2 ① 的全部意义）。**但单独不够**：它是**静态**的——运行时仍然**从名字推归属**，所以 ① 动态拼名的插件 ② 不遵守规则的插件 ③ 存量未清账的 46 条，**照样静默相撞**（H1 一条都不减）。⇒ 它是**预防层**，不是**修复层** |
| **（丙）运行时仲裁（首撞者保留 ＋ 后来者不覆盖 ＋ `console.error`）** | ✅ **必做，但依赖甲才能正确** | 它是「撞了以后怎么办」的**唯一正确语义**（比 warn 有效、比抛错温和，§2.7）。**但单独不够**：**它的检测条件本身就是坏的** —— 覆盖分支判的是 `if (ids.has(id) && pid !== pluginId)`（`CommandRegistry.ts:62-66`），而 `pluginId` 是**推出来的** ⇒ 同前缀时**恒 false**，仲裁逻辑**根本不会被触发**。⇒ **丙必须先有甲（真身份）才能判得出来** |
| **（丁）复合键 `pluginId:commandId`** | 🔴 **否决** | ① **砸公共 API**：命令 id 是跨方引用面（`contributes.menus[].command` / `keybindings[].command` / 跨插件 `executeCommand` / **用户 `keybindings.json`**）——改形状 = 全部引用点 ＋ 用户已存文件都要跟着改；② **撞禁令**：§七「不许改机制」，且它**收益 ≈ 乙**（都只是给名字加归属），**代价却大一个量级**；③ **样板不可照抄**：视图 id 的复合键（`pluginId:viewId`）是**宿主内部标识**，不对外做引用面——两者契约位阶不同，**不能类比**。⇒ **否决（不是"代价大"，是"收益不成立"）** |

### 11.2 甲路线**怎么落地**（可行性已被本格核实，不是设想）

**关键实证**：壳侧**已经有**一份"真身份 → 命令名"的表 —— loader 执行 `plugin.json` 时用**真 pluginId** 注册（`contributions.ts:63-77`）。所以真身份不必凭空造，**问它就够**。

⇒ **归属解析的优先级（1.32 照此实现）**：

| 序 | 来源 | 什么时候命中 | 置信 |
|:--:|:--|:--|:--|
| ① | **声明面查表**（`contributes.commands[]` → 真 `pluginId`） | **所有声明过的命令**（本轴 46 处里 **44 处**走这条 —— 21 声明 ＋ 23 个与声明同名者） | 🟢 权威（身份来自 plugin.json） |
| ② | **注册方显式申报**（运行时载荷里的 `pluginId`，**新增可选字段 = 只做加法**） | 声明面没有、但注册方如实报了（H5 的两条、动态命令） | 🟢 权威（照 `notifications.source` 先例） |
| ③ | **名字第一段**（今天的做法） | 前两条都没有（**老第三方插件**零申报） | 🟡 **降级为「推定」** —— 只用于兼容，且**冲突时必须出声**（这正是治 H1 的地方：两条真实来源都拿不到时才回落到名字，两条都拿到且不同 ⇒ 报错） |

🔴 **两条硬注意（1.32 必须处理，否则新机制自己有洞）**：

1. **乱序到达**：池侧运行时的注册可能**早于** loader 的声明注册 ⇒ 条目先以「推定归属」建好，**声明随后到达时没有回头纠正**（`registerCommand` 的 existing 分支只改 handler/title/placeholder，**不动归属**）⇒ 1.32 必须补「声明到达时**重挂归属**」这一步。**且这一步不许动「同插件重注册只更新 handler/title」的既有语义**（禁区 3）——两者是**不同触发条件**，别混在一处改。
2. **`_poolCommandWindows`（多窗归属表）一个字都不许动**（禁区 4）——归属解析只影响 `_pluginCommands` 的记账与覆盖判定，**不碰路由**。

### 11.3 为什么不选「loader 上下文注入」（本格核实过、**否决**的技术备选）

**设想**：池侧 import 插件入口时（`resolvePluginViewLoader` 知道 `pluginId`）把身份"注入"，从而**不给作者加字段**。

**否决理由（两条实证）**：

1. **命令注册不都发生在 import 期间**：作者契约允许**视图挂载时**注册（`entryActivation.ts:15-17` 明写「在视图组件内注册的命令仍只随视图挂载激活」）⇒ 那一刻**没有"正在加载的插件"可注入**；
2. **注入点不存在**：`window.linkdesk` 是 `contextBridge.exposeInMainWorld` 出来的**共享单例**（`preload-pool` 单进程共享 realm），**不能按插件作用域化**，也无从 monkey-patch。⇒ 同一条 concluion 压在 `notifications.source` 上：**壳无从自动注入，只能显式报**（`ui.ts:26-32` 的既有措辞）。

⇒ **结论：① 声明面查表 ＋ ② 显式申报**是唯一可行的组合（且 ① 已能让**零申报**的存量走对，② 只兜剩下的两条）。

### 11.4 协议 id（§1.5 同族）的裁决

- **同形判定**：`ProtocolRegistry.ts:34-42`（`Map` ＋ `if (has) console.warn` ＋ 照旧 `set`）＝ **last-wins ＋ warn**，与命令 id **四条判据全中**（扁平 / 多方写 / 无归属校验 / 冲突静默）。
- **实测**：官方 18 仓 **零使用**；内置协议由宿主用 `pluginId: APP_PLUGIN_ID` 注册（`registerBuiltinProtocols.ts:48`）⇒ **宿主已报真身份**。
- ⇒ **裁决：与命令 id 合并成同一条腿**（同一本账 ＋ 同一套归属解析 ＋ **同一份 `--self-test`**）。**不单立判据、不单立轮次**——它今天没有消费者，单独立一条腿等于**养一条恒绿的腿**（记忆 `gate-idle-vs-zero-violation`：报绿先问"输入里还有违规形态吗"）。
