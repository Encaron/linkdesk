## 两件独立的事

### 任务 1：终端仿真器——真正的命令行

> 对标 VS Code 的 `Ctrl+\`` → 底部弹出终端面板 → PowerShell / cmd / bash。

```
┌──────────────────────────────────────────────┐
│  壳窗口                                        │
│  ┌────────────────────────────────────────┐  │
│  │ 主区（标签页 + 分屏）                    │  │
│  │                                          │  │
│  ├────────────────────────────────────────┤  │
│  │ 底部面板（Panel）                        │  │
│  │  [终端 1: PowerShell] [终端 2: bash] [+]  │  │
│  │  PS C:\Users\fengy> ls                   │  │
│  │  ...                                     │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

**技术方案：** Electron 主进程 `node-pty`（伪终端）+ WebContentsView 渲染 xterm.js。

```
主进程（Node.js）
  node-pty → spawn("powershell.exe")
    ↓ IPC（pty 数据流）
壳 WebView（xterm.js）
  TerminalInstance[] → xterm.js 渲染
```

- `node-pty` 在主进程 spawn 真正的 shell 进程
- 每个终端实例是一个 xterm.js 组件，渲染在壳的底部面板 WebView 中
- 不需要独立的 WebContentsView——xterm.js 本身是纯 JS，跟壳同一个渲染进程即可

**对标参考：** VS Code 的 `src/vs/workbench/contrib/terminal/`——`node-pty` + `xterm.js`，同样的技术栈。但要简单得多——VS Code 的终端系统有 ~50 个文件（profile/color/detection/link/shell-integration...），LinkDesk 只需要基础版：spawn + xterm.js 渲染 + 标签页切换。

### 任务 2：插件输出面板——不独占标签页的轻量显示

> 对标 VS Code 的 Output 面板 + Terminal 面板的"插件可写入"能力。

**场景：** 插件不想独占一个标签页——只是想在底部面板显示一些输出。例如：
- 串口插件想显示 "端口已打开，115200bps" 日志
- Git 插件想显示 `git push` 的实时输出
- 构建插件想显示编译进度

**方案：** 壳提供 `OutputChannel` API——插件创建频道，写入文本，壳在底部面板渲染。

```typescript
// 插件侧——对标 VS Code 的 vscode.window.createOutputChannel()
const channel = window.linkdesk.output.createChannel("串口日志");
channel.appendLine("端口 COM3 已打开，115200bps");
channel.appendLine("收到数据: 0x48 0x65 0x6C 0x6F");

// 壳侧——底部面板的 Output 标签页
// [终端: PowerShell] [终端: bash] [输出: 串口日志] [输出: Git]
// 用户点 "输出: 串口日志" → 看到插件写的文本
```

这个其实 E2c 已经留了接口——`LogChannel`（[03-E2c-基础设施缺口.md](../../../02-Electron架构/E2_底层加固与侧栏扩展_暂定/03-E2c-基础设施缺口.md) 第 3c 节）。当前 `LogChannel` 只有内存存储，没 UI。终端系统补上 UI 渲染层。

## 与当前 terminal 插件的关系

| | 当前 terminal 插件 | 未来 serial-monitor 插件 | 真正的终端系统 |
|------|------|------|------|
| 是什么 | 串口监视器（独占标签页） | 同上——改个名字 | PowerShell/cmd/bash 终端面板 |
| 在哪显示 | 主区标签页 | 主区标签页 | 底部面板 |
| 技术 | React + CM6 + Tauri serialport | 同左，IPC 化 | node-pty + xterm.js |
| 谁用 | 串口调试用户 | 同左 | 所有用户——通用命令行 |

**不冲突。** serial-monitor 是串口专用视图。终端系统是通用命令行面板。两者共存——就像 VS Code 里既有"终端"面板，也可以有串口助手插件。

---

## 与插件生态的关系

**终端面板不是替代标签页——是额外选项。** 插件开发者自己决定：

| 插件想做什么 | 选什么 |
|------|------|
| 独占 UI——地图/CAD/编辑器/示波器 | `entry` → 标签页（独占 WebContentsView） |
| 简单输出——日志/进度/构建结果 | `output.createChannel()` → 底部面板 |
| 交互式命令行——REPL/数据库 CLI | 终端面板（创建专用终端实例） |

**对标 VS Code：**
- VS Code 的 Extension Host 可以调 `vscode.window.createTerminal()` 创建终端实例
- LinkDesk 的插件可以调 `window.linkdesk.terminal.create()` 创建终端实例
- 插件不需要自己实现 xterm.js——复用壳的终端面板

## 为什么终端面板是壳级不是插件

跟 CommandPalette 同样的道理。自检："卸载所有插件后，终端面板还能用吗？" 必须能——它是紧急出口，跟命令行一样是基础工具。

**但 xterm.js 本身可以作为插件替换。** 壳提供默认的 xterm.js 终端渲染器。如果第三方做了一个更好的终端（比如支持 GPU 加速渲染），可以通过 `factoryRole: "terminal"` 替换。
