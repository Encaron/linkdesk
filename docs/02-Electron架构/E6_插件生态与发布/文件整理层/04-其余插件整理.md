## 〇、先读这个——三个插件专属的坑

**① `plugins/*/src/index.tsx` = entry，不是「视图之一」。**

`appearsIn.tabBar === true` + 有 `entry` 声明 → 该插件可创建为标签页，**入口的 default export 就是主视图组件**（`src/pluginLoader/contributions/viewRegistry.ts:145`）。`contributes.views` 是**侧栏/附加视图**。

→ 所以 `serial-monitor/src/index.tsx`（**1642 行**）里那坨 `SerialMonitorView` **是主视图本体**，不是入口胶水。**正解 = 视图搬去 `views/`，入口瘦成薄门面**（照 marketplace 的形状）。这是本轮最大的一个动作。

**② `hooks/` 与 `utils/` 是既有房间，只是门禁没登记。**

`serial-monitor/src/` 下有 `hooks/`（`useSerialSessions.ts`）与 `utils/`（`useSendData.ts` / `RingBuffer.ts`）——**09 规范认可这两类，但 `check-file-size.mjs` 的 `ROLE_LIMITS` 只登记了 views/components/services/styles**。第 5 轮扩域时必须补上（见 [05](05-门禁扩域与验收.md)），否则门禁会对它们**抛错**（`未知 role 夹`）而不是放行。

**③ 模块级 mutable 状态 = 拆分时的一号杀手。**

| 文件 | 模块级状态 | 拆错的表现 |
|:--|:--|:--|
| `serial-monitor/src/services/SerialContext.tsx` | `_openPorts` / `_listeners` / `_portListeners` | 串口开着但界面说没开 / 监听器重复注册 |
| `serial-monitor/src/index.tsx` | `_cmdMap` / `_receiveSnapshots` | 发送无回显 / 切换标签页后接收区空白 |
| `file-tree/src/components/FileTreeContextMenu.tsx` | `FileTreeHandle` 引用 / `OpenFileFn` | 右键菜单点了没反应 |
| `editor/src/services/lsp-bridge.ts` | `_clients` / `_states` / `_stateSubs` / `_pending` / `_blockedNoticed` | LSP 客户端重复起 / 状态不刷新 |

> 🔴 **铁律（照 0d.10-8）**：模块级 mutable 状态**各归单域属主**，跨域读走公开 accessor。**拆完 grep 一次变量名，确认全仓只有一处 `const _xxx =` 声明。**

### 5.1 🔴 版本号怎么定（E6#87 前置订正，2026-09-11 补）

> 原文只写「各自 `fix:` bump patch」——**太粗，与本层实证冲突**：3.6.3 / 3.6.3b 拆完 marketplace（`services/` 门面归位 16→12、`styles/` 分三组、views 分三组），**一次没 bump**（全程 1.0.27）。两句话打架，必须写清判据。

**判据 = 机械门禁 [`scripts/check-bundled-version-bump.mjs`](../../../../scripts/check-bundled-version-bump.mjs) 的输出**（已挂 `npm run check`）。它比的是 **`bundled-plugins/<id>.linkdesk-plugin` 的内容指纹**（zip 内每个条目的 `{规范化名: sha256}` 排序拼接）**vs git HEAD 同路径 blob**，三档：

| 门禁判定 | 含义 | 要不要 bump |
|:--|:--|:--|
| `identical` | 重打的包**内容指纹与 HEAD 逐字节相同** | **不 bump**——零实质变更，门禁自过 |
| `red-same-version-content-diff` | 内容变了、version 没动 | **必须 bump**——否则已装用户永滞旧内容（E6#15n） |
| `version-bumped` | version 已动 | 过 |

**✅ 实证（2026-09-11，本订正时跑）**：18/18 全 `identical`，含 3.6.3/3.6.3b 拆完重打的 `marketplace.linkdesk-plugin`。⇒ **纯搬移可以做到产物零字节变化**，这就是 3.6.3b 不 bump 的正当理由（不是「忘了」）。

**🔴 但本层不许照抄这个结论。** 3.6.4 的拆法比 3.6.3 激进得多（serial-monitor `index.tsx` 1643 行拆成 entry + 十几个文件），**产物字节很可能变**。所以纪律是：

1. **拆完 → 重打该插件 zip → 跑一次门禁**，按上表判定。**不许「我觉得搬移不影响产物」就跳过重打**（打包文件生成与来源无关的假定 = 猜）。
2. 判定 `red-…` ⇒ bump 该插件 `plugin.json` version，commit message 带 `fix:` 前缀。**一轮共享一次 bump**（3.6.3 先例），不逐 commit bump。
3. **软件轴恒不动**（`src/` / `electron/` 本轮零改动）——软件 version 保持 0.1.47。判据见 memory `version-axes-separated`。
4. 判定结果（四个插件各是什么）**回填本表**。

> 拆完第一次重打 zip 得到 `（271.6 KB, **2/2** 表面）`，门禁判 `red` → 我按「内容变了」处理，**没意识到它少了两块**。
> 真因：我把 `views/SessionListView.tsx` / `views/SerialSettingsView.tsx` 拆成了**夹内 `index.tsx`**，
> 而 `views/` 的門面**必须留同级同名文件**（[06 §〇 铁律](06-目录结构二次收口.md)：`render` 字段 = SDK bundle key，有 basename 约束）。
> `plugin.json` 的 `render` 仍指向旧路径 → SDK `collectSurfaces` 遇缺失文件 **`continue` 静默跳过**（源码注释原话「build 不 abort」）
> → 包里**没有**这两块 bundle；`tsc` 不报（serial-monitor **不在根 tsconfig 的 include 里**）；`npm run check` 全绿；
> 唯一炸的是 **dev 运行时**（池按 `render` 路径 `import()` 直接 404 → ErrorBoundary 兜住）。
> **修完再重打：`4/4 表面 / 544.7 KB`。** ⇒ 两条硬规则：
> ① **重打 zip 时核「表面数」**——`N/N 表面` 的 N 必须等于该插件的可编译表面数（entry + 每个 `contributes.views[].render` + statusBar），**数字掉了就是掉了块，不是「变快了」**；
> ② **`views/` 拆门面只准「夹旁散门面 + 同名夹」**，夹内 `index.tsx` 是**静默错误**（`services/` `components/` `hooks/` `utils/` 才是夹内 `index`）。
