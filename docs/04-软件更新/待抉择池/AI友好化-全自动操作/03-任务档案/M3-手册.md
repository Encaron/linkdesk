## AI#10 ⬜ 手册骨架与落点落仓

**做什么**：建 `docs/07-AI操作手册/`，`00-README.md` 作索引，**按任务组织**目录（「分屏」「开标签」「读通知」「点通知按钮」「装插件」…）。

**判据**：目录结构**被用户过目点头**——这是「可按任务查」的载体（[§三 判据「可查」](../01-设计.md)：操作知识有单一真相源文档）。

**为什么「按任务」不按「按 API 名」**：读手册的是**带着任务来的 AI**（或人）——「我要分屏」不该先知道「有个叫 `splitTab` 的动作」。⚠️ 但索引章（`AI#11`）要**同时给 API 名**（两条检索路径：任务 → 做法、API 名 → 用法）。

**验收方式**：拿 [§十 12 例](../01-设计.md) 当**目录压力测试**——每一例在目录里都该有落点；有例找不到落点 = 目录缺章。

**风险**：⚠️ 建新顶层 `docs/` 目录 = **结构级动作** ⇒ 按仓库纪律**先与用户确认目录名与章划分**（拍板 A-3），⛔ 别自己开完再问。

## AI#11 ⬜ 命令 / API 全索引（生成式，不手抄）

**做什么**：手册的**命令与 API 全索引**——「能操作什么、怎么操作」的单页答案。

🔴 **生成式，不手抄**（[§四 M3](../01-设计.md) 原文：「命令部分建议**从实现生成**，防漂移」）。

**数据源 = `AI#7`/`AI#8` 的命令元数据**（`description` ＋ 参数结构）⇒ **这就是「本轮必须排在 M1 之后」的原因**：手工抄一份命令表，下个版本就漂（**本系列立项的原始病根之一正是「没有时刻表告诉 AI 直通车在哪」**——再手抄一份新时刻表，等于把病换个地方养）。

**建议加一条门禁**：**生成物与实现逐字节比对**（照 `docs:build` / `docs:check` 既有同款机制）——否则「生成式」只是首日生成、次日手改，又漂。⚠️ 照记忆《两把尺子必须同一份实现》：若已有别的腿在做相似判断，**必须共用同一份判据实现**，别fork 出第二把尺。

**判据**：**新 AI 只读本索引**即可列出「能操作什么、怎么操作」——不读源码（[§四 M3 判据](../01-设计.md)）。

**验收方式**：抽 5 条索引条目 → **照索引盲调**（不看源码、不看别处）→ 全部调通 = 索引是真的。

**依赖**：**`AI#7` ＋ `AI#8` 全落地后才做**（硬次序第 2 条）。

## AI#12 ⬜ 手势隐藏规则表（本系列缘起的那两个坑）

**做什么**：把「**任何文档都没写的隐藏规则**」写清——这是**本系列的缘起病根**（A1 场景 6）。

🔴 **两坑实测行号（本会话复核，与设计原文略有出入，以本档为准）**：

| # | 坑 | 实测落点 | 原话机制 |
|:--|:--|:--|:--|
| ① | **拖拽相位门控** | `src/pool/hooks/useDragReorder.ts:196`：`if (ds.phase === "reorder" && Math.abs(dy) > splitThreshold && inEditor)`；`splitThreshold` 默认 **15**（`:98`）；另有 `src/pool/hooks/tabDragTypes.ts:29` 的 `SPLIT_THRESHOLD = 0.25` | **横向拖永远进不了 split 相位**——而「**没有玻璃预览**」恰是「**从未进入 split 相位**」的铁证（`src/pool/zones/main/MainZone/DragOverlays.tsx`） |
| ② | **CDP 坐标缺陷** | `src/App/windows/windowRelocation.ts` | Chromium 给**合成**鼠标事件的 `screenX` **不加窗口偏移** ⇒ 跨窗判定失效 |

**正解也要写进去（这是本节最有价值的一段）**：**分屏根本不用拖**——
- 池动作：`window.linkdesk.pool.tabAction({ action: "splitTab", direction: "horizontal", zone: "right" })`（类型 `src/core/types/ipc/tabActions.ts:37`，处理端 `src/App/tabCallbacks.ts`）；
- 或有命令：`core.splitDown` / `core.splitRight`（`src/core/commands/shell/coreCommands.ts:148,159`）。

**判据**：测试 AI **不会再在场景 6 一类手势上卡壳**（[§四 M3 判据](../01-设计.md)）。

**验收方式**：⚠️ **重跑场景 6 的原操作**——但**用命令而非拖拽**（§七 第 1 条：「对 AI 说『把设置标签页分到右半边』→ 一次性做成（走命令/API，**不依赖拖拽**）」）。同一条 `AI#12` 也是 `AI#45` 第 1 条的输入。

**边界**：⛔ 本节**不是**「教 AI 怎么拖」（拖拽是给人手感留的）；本节要写的是「**这个手势有隐藏门槛，所以 AI 别走它、走这条命令**」。口径同 §七 第 5 条：手势**全在**，只是每条**另有非鼠标路径**。

## AI#13 ⬜ 够不着清单 ＋ 安装版操作路径

**做什么**：**A 类「OS 层真够不着」如实列册** ＋ **安装版操作路径**章。

**A 类清单（依据 [§2.4](../01-设计.md) ＋ [§2.3 A 类](../01-设计.md)）**：移动窗口本身 · OS 拖文件进出 · 系统文件对话框。

**安装版操作路径（同章）**：带参 CDP 启动 · 静默 `/S` 安装 · `userData` 文件面 · **更新后重连**。

**判据**：有一份**可查的、不吹牛的**「什么够不着」清单——**边界①防预期落空**（[§三 边界①](../01-设计.md)：OS 层的事软件管不了，**如实说**比装作能做好）。

**为什么这条不能省**：不写这份清单的直接后果 = **下一个 AI 花一整轮去试「怎么用代码移动窗口」**（今天已经付过这个税）。**如实列册 = 省下未来每一次重试。**

**验收方式**：`AI#46` 跑 §八 三条追问场景时，**逐条对账**——凡场景触及 A 类的环节，手册里**必须先有这条"够不着"**。

## AI#14 ⬜ CDP 坑表入仓（从记忆搬进仓）

**做什么**：把 CDP 坑表（**合成事件 / `el.click()` / SelectBox 三坑**等 **11+ 条**）**从记忆搬进仓内文档**。

**现状**：这套知识**原只活在记忆 `cdp-ui-automation`**（[§四 M3](../01-设计.md) 原文）。⇒ 换机器/换会话就丢；而**它恰恰是开发期 AI 每天要用的**。

🔴 **搬法有硬规矩**（照 [AGENTS.md](../../../../../AGENTS.md) 记忆条目《报告文件给全路径》与《文档/记忆里不许引 gitignore 的文件》）：**只搬内容，不搬指针**——⛔ 仓内文档**不许**写「详见记忆 `cdp-ui-automation`」（记忆库在仓库外、`memory/` 被 gitignore ⇒ **换机器就是死链**，且 `check-doc-links` **看不见「文档→记忆」这类引用**，不会报红）。**这条是本格最容易踩的坑。**

**判据**：开发期 AI 进场**能读到这张表**（在仓内、能 grep 到）。

**验收方式**：`npm run check` 全绿（链接腿）＋ **换机模拟**：把手册路径当唯一入口，确认坑表内容**自足**（不需要外部指针就能读懂）。
