## 五、风险（★ 先看这三条）

1. **生成器 `must()` 是"全部替换"陷阱** ——
   `function must(s, from, to) { return s.split(from).join(to); }` 替换**所有**出现位置。
   要给容器里四项定格成"已勾"，**不能**直接把 `data-opt="filemenu"` 换成带 `checked` 的版本——那会**同时改掉紧凑态那一份**。
   ⇒ 用 **`inScreen(s, id, fn)` 切片助手**：先把该屏切出来，在**切片内**替换，再拼回去。
2. **效果图这一摊有两种，别混** —— **本轮那份（05）是手绘示意**（可以改，它就是给你点头用的）；**落地之后**才换成生成物（见 §二 的命令），那时才"永不手改"。生成物一律**不许叠到定版页上**；`mockups/` 下的历史快照**冻结**。
   触类旁通：**设置页那张图不是生成物**（手绘示意，没有生成命令）——别拿这条纪律要求它，也别去给它写生成器。
3. **`main.cpp` 在本机编不了** —— `npm run check` 也**不**覆盖 C++。C++ 改动一律走 CI；**改动越小越好，能照抄就照抄**（照 `PickInstallDir` / `browse-dir` 那一支写）。
4. **`app.js` 会越改越长** —— `check-file-size.mjs` 的档 A **不含 `build/`**，但**别因此把它撑爆**：新逻辑尽量收成小函数，注释写"为什么"，不写"做了什么"。
