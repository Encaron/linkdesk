## 〇 一句话

**同一批散文（CHANGELOG）同时住在三个分发面上，而三个面都没有上限**——市场目录 `marketplace.json`（每个用户每次「检查更新」全量下载）、插件 zip 内的 `CHANGELOG.md`（每次安装/更新下载并常驻）、各仓 `CHANGELOG.md`（仓库体积）。**壳的三个面早已按行业正解做完**（安装包白名单不带 CHANGELOG · Release 正文每版独立 · npm `files` 白名单不带），缺的只是**插件分发面的一条窗口**：目录与 zip 各自只带**最近 N 版**的 changelog 文本，更早版本仍保留版本条目（可回装），只是不再把历史散文塞进每份下载。

**读数的两条含义**：

1. 行业里"每版独立"的那套（Release）你**已经做对了三处**——膨胀不是"没做 Release"，而是**插件分发面缺一条窗口**。
2. 目录的 9.2 KB/天与壳 CHANGELOG 的 2.2 KB/版 × 约 4 版/天**同数量级**——**驱动两者的是同一种写作习惯**（见 §六 T1），不是两个独立问题。目录里 38% 是散文这件事，意味着**每多写 1 KB 说明，每个用户每次刷新多下 1 KB**。

## 二 网络上怎么解决（六类，带真实先例）

1. **文件内只留最近 N 版 ＋ 归档另起文件**——Node.js 每条主线一份 `CHANGELOG_V18.md`、主 `CHANGELOG.md` 只是索引；Kubernetes 用 `CHANGELOG/CHANGELOG-1.30.md`（按 minor 一行一份）。口径：主文件 = **当前支持窗口**。
2. **按版本一文件**——`changelog/v1.2.3.md` ＋ 顶部索引。（反例同样是正解：Rust 一份巨大的 `RELEASES.md` 活到今天 ⇒ 不解决也活得下去，**代价只是体积**。）
3. **片段制（fragment）**——towncrier（pytest / pip / Zulip 的 `changelog.d/`）· Changesets（monorepo 主流，PR 里加 `.changeset/*.md`，发版时消费并删除）· Vite/Vue 的 `changelog.d/`。它解决的**真问题是多人并行编辑文件顶部造成的冲突**，不是体积。
4. **不手写、从提交生成**——`git-cliff` · `conventional-changelog` · GitHub 自动 Release notes（`.github/release.yml` 分类）· `release-please`。文件退化为构建产物 ⇒ 可以不入库。
5. **产品面收敛（Keep a Changelog 的本意）**——"changelog 给人看，不给机器看"：只记 notable，**一条一句话**，细节留给 git log / PR。标杆是 VS Code：单文件很长，但每版十几行短条目；本仓单版 2.2 KB 的中文叙述性长文（含"为什么这么修""防误判"的推理过程）属**重量级形态**。
6. **分发面裁剪**（与本条最相关）——npm `files` 白名单排除 · 打包器白名单排除 · Release 每版独立。**这三条本仓已全部具备**，缺的是插件的目录与 zip。

## 四 设计前置（8 维度）

> 描述的是**已拍板的最小路径**（T2：目录窗口 ＋ zip 窗口）；**N = 5**、zip 同窗口、归档阈值与作者面口径见 §六 拍板结论。

**① 能力边界** ＝ **平台层写入/打包判据 ＋ 一条发布纪律**。既非壳能力、也非插件能力、更不是 UI 能力。
**保底** ＝ **不需要任何开关或开关式保底**：读侧**前向兼容**——老目录（含全量 changelog）与老 zip 照常渲染，收敛只发生在**新写入**上；无插件、无目录、无网络三种情形下市场页签行为**一字不变**。

**② API 设计** ＝ ⛔ **零新增 `window.linkdesk.*`**；⛔ **零新增 `contributes.*`**；⛔ **零 schema 变更**。
唯一契约面 = `MarketplaceCatalog.versions[].changelog` 的**写入窗口**——在 SDK `publish.ts` 的 `upsertCatalogEntry`（唯一写入点）把语义从"每版都写文本"改为"**最近 N 版写文本，更早版本仍保留条目、`changelog` 缺省**"。
契约位置 = `packages/plugin-sdk/src/publish.ts`（`.d.ts` 随 `MarketplaceCatalog` 类型，字段不变）；`changelog` 缺省**已有渲染语义**（市场详情页签"缺即显示未提供"），故读侧零改动。

**③ 通信方式** ＝ **无运行时通信**。数据流单向：作者仓 `CHANGELOG.md` →（发版时）SDK 切段 → 目录 `versions[].changelog`（窗口内）／zip 内 `CHANGELOG.md`（窗口内）。零 IPC、零事件、零持久化新面。

**④ 壳侧代码** ＝ ⛔ **`src/` 与 `electron/` 零改动**。壳的 Release 取段腿（`scripts/lib/changelog-section.mjs` ＋ `check-publish-gate.mjs --changelog-body`）只取**当前版本段**，归档后**依然成立**（当前版本段恒在主文件）。
本条的"壳侧"只有两处**文档**：新归档件 ×1（住 `docs/04-软件更新/`）＋ [发布清单](../../../06-发布管理/发布清单.md) 一条口径。

**⑤ 插件侧代码** ＝ ⛔ **作者仓零改动**（不需要任何代码、依赖或构建改动）。🔴 **作者面文档也不写**（2026-10-01 用户裁决，见 §六 拍板④）——CHANGELOG 的**写作纪律不进** [03-插件制造](../../../03-插件制造/)／作者面两棵树；真要提示作者，走**工具面（hint 显示）**，不污染作者文档。同理，zip 里少了几段正文**是平台行为**（不是作者该改的写法），作者侧同样零文档负担。

**⑥ 显示设计** ＝ 市场详情「更改日志」页签（`ChangelogTab`，已装/未装双源）：**已装** = 包内 `CHANGELOG.md`（窗口内 N 版）；**未装** = 目录 `versions[].changelog`（窗口内 N 版，窗口外沿用既有的"未提供"渲染）。**版本下拉的条目列表不变**（`version` / `downloadUrl` / `publishedAt` 仍全量）⇒ **回装旧版的能力零损失**。

**⑦ 配置设计** ＝ **零产品配置项**。N 是**编译期常量**（SDK 内一处，单一真相源）；⛔ 不做成设置项——否则每个用户的目录形状互不相同，等于把平台常量变成用户态漂移。

**⑧ 代码规范 + 验收** ＝ 窗口判据必须是**纯函数**（可单测、可反向对照）；`npm run check` 全绿。
验收四条：① SDK 单测——窗口边界（前 N 版全写 / 第 N+1 版起仅留条目）＋**反向对照**（拿旧行为输入跑必"多"）；② 目录体积回归——新增一版后 `marketplace.json` 增量 ≤ 单版文本；③ zip 打包后 `unzip -l` 列条目，确认包内 `CHANGELOG.md` 只含窗口内段落；④ 市场详情页签实机：窗口内可读、更早显"未提供"、下拉全量可选。

## 五 十条核心理念对照

- **禁硬编码 · 归一性**（6/8）：N 与口径**单点定义**（SDK 一处常数），三处消费同源；⛔ 不在壳、市场插件、CI 各写一份。
- **利未来插件生态**（2）：作者越多、版本越多，目录越大——**窗口是唯一能把"目录体积"变成常数的机制**（插件数×版本数的双向增长被削掉一半）。
- **低耦合高内聚**（7）：目录是**数据**，不是档案；把历史散文搬出下载路径，正是把"档案"与"分发数据"解耦。
- **无死代码**（4）：窗口外的历史文本，是**被每个用户重复下载却几乎不被打开的负载**。
- **插件独立**（3）：本条**不动作者代码、不动作者构建**，作者零感知——符合"第三方不须改壳、也不必改自己"。
- ⚠️ 与**易操作**（11）的张力：已装用户看历史版本会少看到更早正文 ⇒ 用"条目保留 ＋ 可回装 ＋ 远端可查"抵；若用户要求全史可读，退路是加**按需拉的直链**（见 §六 T2·退路），而不是把散文塞回目录。**2026-10-01 拍板未取该退路**——N=5 已够，退路留档、触发条件写死在 §六。

## 七 验收判据（可证伪）

## 八 边界与不做

- 🔴 **插件仓 CHANGELOG 归档必须随下一次发版同笔**——"分发过的插件，任何内容变更（代码/资源/README/CHANGELOG）都必须 bump 版本"（[03-插件制造/04-插件分发格式.md](../../../03-插件制造/04-插件分发格式.md):99）；且**同版本重打 zip 内容会变** ⇒ `check-bundled-version-bump` 会红。**zip 裁剪同理**。
- 🔴 **Release 正文与文件同源这条不变**：切段只取**当前版本**；归档后当前版本段恒在主文件 ⇒ CI 两处取段（`--changelog-body` / `--changelog-date`）不受影响。
- 🔴 壳 CHANGELOG 归档后，`check-doc-links` 必须能找到归档件（新链接要真实存在，不能只写文字）。✅ 首次归档四条链已实测可解（根 `CHANGELOG.md` 顶部索引 / 本档 §一 / [04-软件更新/00-README §一](../../../04-软件更新/00-README.md) / 归档件回指）。
- 🔴 **归档单位 = 已封版的版本线，不是「最近 50 版」**——机械倒切会把一条版本线劈成两半，读者无法判断「这条线还剩多少在根文件里」（Node.js 每条主线一份 `CHANGELOG_V18.md` 正是这个单位）。判据：**当前版本段恒留主文件**（CI 的 `--changelog-body` / `--changelog-date` 从主文件切段），被搬走的只有**已封版**的整条线。
- ⛔ **作者面文档一个字都不加**（拍板④）：写作纪律与窗口机制**都不进** `docs/03-插件制造/` 与作者面两棵树——作者零感知、零文档负担；真要提示作者就走**工具面**（载体待单独立案，见 §六 拍板④ 注）。
