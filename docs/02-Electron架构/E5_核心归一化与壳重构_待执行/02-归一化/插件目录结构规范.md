## 一、前因——零规范

### 1.1 当前乱象

| 插件 | 结构 | 问题 |
|------|------|------|
| **editor** | 14 文件全部摊在 `src/` | 零子目录——最严重的反面教材 |
| **file-tree** | 16 文件摊在 `src/` + views + tests | CSS 和 TSX 混放、utils 不分类 |
| **marketplace** | 5 文件摊在 `src/` + views | `marketplaceShared.ts` 摊在根 |
| **serial-monitor** | 8 文件摊在 `src/` + components + views + tests | 最好的——但仍不完整 |

**缺失的标准目录：**

| 目录 | 存在 | 应该放什么 |
|------|:--:|------|
| `components/` | 仅 serial-monitor | 可复用 UI 组件（`SessionListItem.tsx`） |
| `hooks/` | **零个插件** | `useSerialSessions.ts` 现在是摊在 src/ 里 |
| `services/` | **零个插件** | `FileTreeModel.ts`、`EditorModel.ts`、`FileTreeClipboard.ts` |
| `utils/` | **零个插件** | `pathUtils.ts`、`layoutTokens.ts`、`icon-mappings.ts` |
| `styles/` | **零个插件** | 所有 CSS 和 TSX 混在 src/ 根 |

### 1.2 后果

一个第三方开发者看 file-tree 的源码想学怎么做插件：
- 看到 16 个文件摊在 `src/` → 不知道哪些是必需、哪些是可选
- 看 editor 的源码 → 14 个文件全部摊在 `src/` → 完全不同的结构
- 看 serial-monitor → 有 `components/` 了——但为什么 file-tree 没有？

**三个官方插件，三种结构。** 第三方作者不知道该学哪个——最后大概率学个四不像。

## 二、标准插件模板

### 2.1 目录结构

```
plugins/<scope>/<plugin-id>/
├── plugin.json                    # 🔥 插件声明——唯一入口
├── README.md                      # 插件说明（可选——给市场展示）
├── resources/                     # 静态资源
│   └── icon.svg                   # 插件图标（SVG 优先）
├── src/
│   ├── index.tsx                  # 🔥 入口——export default React 组件
│   ├── components/                # 可复用 UI 组件
│   │   └── MyWidget.tsx
│   ├── views/                     # 侧栏/面板视图
│   │   └── MySidebarView.tsx
│   ├── hooks/                     # React hooks
│   │   └── useMyData.ts
│   ├── services/                  # 数据模型/业务逻辑（非 UI）
│   │   └── MyModel.ts
│   ├── utils/                     # 纯工具函数
│   │   └── formatDate.ts
│   ├── styles/                    # CSS 文件
│   │   └── index.css
│   └── __tests__/                 # 单元测试
│       └── MyModel.test.ts
└── dist/                          # 构建产物（Vite 自动生成——不手动管理）
```

### 2.2 目录规则

| 目录 | 规则 | 对标 |
|------|------|------|
| `components/` | 只放可复用的 UI 组件。**不包含业务逻辑**（业务逻辑在 services/ 或 hooks/） | VS Code 扩展开发——`src/` 分类 |
| `views/` | 侧栏 view、面板 view、标签页内容——被 ViewContainerService 注册的组件 | E3.6 ViewContainer |
| `hooks/` | 所有 `use*` hooks——数据获取、状态管理、副作用封装 | React 社区标准 |
| `services/` | 数据模型、注册表、Manager 类——非 React 组件、非 hook | `FileTreeModel`、`EditorModel`、`FileTreeClipboard` |
| `utils/` | 纯函数——字符串处理、路径工具、常量定义 | `pathUtils`、`layoutTokens` |
| `styles/` | 所有 `.css` 文件——不放在 `src/` 根 | 对标 `src/styles/` |
| `__tests__/` | 所有 `.test.ts(x)` 文件 | 对标 `src/__tests__/` |

### 2.3 plugin.json 位置

`plugin.json` **必须在插件根目录**——不在 `src/` 内。这是 `import.meta.glob` 扫描的唯一位置。

### 2.4 entry 规则

`entry` 字段指向 `src/index.tsx`——唯一的 React 组件入口。数据插件（`pluginRole: "data"`）不需要 `entry`。

## 三、官方插件迁移

### 3.1 editor 迁移（最严重——14 文件零子目录）

**当前结构：**
```
editor/src/
├── index.tsx
├── EditorView.tsx
├── EditorTab.tsx
├── EditorModel.ts
├── EditorBreadcrumb.tsx
├── EditorContextMenu.tsx
├── EditorStatusBar.tsx
├── DiffEditor.tsx
├── language-map.ts
├── lsp-bridge.ts
├── monaco-init.ts
├── navigation-bridge.ts
├── theme-sync.ts
├── ts-intelligence.ts
└── editor.css
```

**迁移后：**
```
editor/
├── plugin.json
├── resources/icon.svg             # 🆕 补图标
└── src/
    ├── index.tsx                  # ← 唯一入口
    ├── views/
    │   ├── EditorView.tsx         # 编辑器主视图
    │   ├── EditorTab.tsx          # 标签页包装
    │   └── DiffEditor.tsx         # Diff 对比视图
    ├── services/
    │   ├── EditorModel.ts         # 文件内容模型
    │   ├── language-map.ts        # 语言映射
    │   ├── lsp-bridge.ts          # LSP 桥接
    │   ├── monaco-init.ts         # Monaco 初始化
    │   ├── navigation-bridge.ts   # 导航（F12/Ctrl+Click）
    │   ├── theme-sync.ts          # 主题同步
    │   └── ts-intelligence.ts     # TS 智能提示
    ├── components/
    │   ├── EditorBreadcrumb.tsx   # 面包屑
    │   ├── EditorContextMenu.tsx  # 右键菜单
    │   └── EditorStatusBar.tsx    # 状态栏
    ├── styles/
    │   └── editor.css
    └── __tests__/                 # 🆕 补测试
        └── EditorModel.test.ts
```
