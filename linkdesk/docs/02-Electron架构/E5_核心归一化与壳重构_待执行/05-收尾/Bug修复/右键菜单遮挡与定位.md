# 右键菜单遮挡与定位

> 2026-08-06。Filed by Encaron。
> 位于 E5 收尾 → `05-收尾/Bug修复/`
> 两个关联问题：层叠上下文遮挡 + 预估尺寸定位不准。

---

## 一、Bug A：右键菜单被分割线遮挡

### 复现

1. 在文件树（侧栏内）或编辑器（主区内）右键
2. ContextMenu 弹出
3. 菜单边缘经过侧栏与主区的分割线（resize handle）→ 分割线覆盖在菜单上方，菜单项被遮挡无法点击

### 根因

App.tsx（L594-621）五个 zone 全是 `position: fixed` + 显式 zIndex：

```
IconBar:    position:fixed, zIndex: 10
Sidebar:    position:fixed, zIndex: 5
Main:       position:fixed, zIndex: 1
StatusBar:  position:fixed, zIndex: 10
Resize handle: position:fixed, zIndex: 15   ← 最高
```

**CSS 规范：** `position: fixed` + 非 `auto` 的 `z-index` → 创建独立层叠上下文（stacking context）。子元素的 z-index 只在其父上下文内有效。

ContextMenu 渲染在 `<SidePanel>` 或 `<MainContent>` 内部，`.` 有 `position: fixed; z-index: var(--z-overlay)` = 600，但：
- 在侧栏内：父级 zIndex 只有 5 → 永远低于 resize handle 的 15
- 在主区内：父级 zIndex 只有 1 → 更低

600 > 15，但 ContextMenu 永远飞不出父级层叠上下文。

### 修复

**ContextMenu 通过 `createPortal` 渲染到 `document.body`**：

```tsx
// ContextMenu.tsx
import { createPortal } from "react-dom";

return createPortal(
  <>
    <div ref={menuRef} className="ctx-menu" style={{ left: ..., top: ... }}>
      {/* 菜单项 */}
    </div>
    {/* 子面板同样 portal */}
  </>,
  document.body
);
```

脱离所有 zone 的层叠上下文后在根级以 `z-index: var(--z-overlay)` = 600 渲染，高于一切。

### 连带风险

| 风险 | 评估 | 缓解 |
|:--|:--|:--|
| 定位偏移 | `anchor` 用 `e.clientX/Y`（viewport 相对），portal 后不变 | 无需处理 |
| React 冒泡断裂 | 关闭逻辑走 window 级 `mousedown`/`wheel`/`blur`/`Escape`，不依赖 React 冒泡 | 无需处理 |
| 调用点兼容 | 所有 `<ContextMenu>` 走同一组件，portal 改一处全生效 | 审计 confirm |

## 二、Bug B：视口定位不准——预估尺寸替代量测

### 复现

1. 在窗口右边缘或下边缘附近右键
2. 菜单部分项超出窗口边界——跑出屏幕或被裁切
3. 带快捷键的长菜单项尤为明显——预估宽度 180px 不够

### 根因

`ContextMenu.tsx` L161-168 用硬编码预估值替代真实 DOM 量测：

```typescript
const adjustedAnchor = useMemo(() => {
  const estWidth = 180;                                    // ← 硬编码
  const estHeight = Math.min(resolved.length * 30 + 8, 400);  // ← 硬编码行高
  let left = anchor.x, top = anchor.y;
  if (left + estWidth > window.innerWidth) left = Math.max(0, window.innerWidth - estWidth - 4);
  if (top + estHeight > window.innerHeight) top = Math.max(0, window.innerHeight - estHeight - 4);
  return { left, top };
}, [anchor, resolved.length]);
```

三个问题：

1. **预估宽度不准：** 菜单项 label + shortcut 实际渲染宽度取决于内容，"删除 Ctrl+Shift+Delete" 远超 180px
2. **预估行高不准：** `resolved.length` 包含分隔符，但分隔符高度 ≠ 菜单项高度（`margin: 4px` + `height: 1px` vs `padding: 6px` + `line-height: 20px`）
3. **无后验量测：** 应该渲染到 DOM 后用 `getBoundingClientRect()` 拿真实尺寸后再修正——当前先猜后渲染，没法纠正

### 修复

**两阶段渲染：先量测，再定位。**

```typescript
const [measured, setMeasured] = useState<{ width: number; height: number } | null>(null);

useLayoutEffect(() => {
  if (menuRef.current && !measured) {
    const rect = menuRef.current.getBoundingClientRect();
    setMeasured({ width: rect.width, height: rect.height });
  }
}, [resolved, measured]);

const adjustedAnchor = useMemo(() => {
  if (!measured) return { left: -9999, top: -9999 }; // 首帧隐藏
  let left = anchor.x, top = anchor.y;
  if (left + measured.width > window.innerWidth)
    left = Math.max(0, anchor.x - measured.width);   // 右溢出→翻左
  if (top + measured.height > window.innerHeight)
    top = Math.max(0, anchor.y - measured.height);   // 下溢出→翻上
  return { left, top };
}, [anchor, measured]);
```

对标 VS Code：`Menu` 组件先量测真实 `offsetWidth/offsetHeight`，优先右下、空间不够翻左上。

### 连带风险

| 风险 | 评估 | 缓解 |
|:--|:--|:--|
| 首帧闪烁 | 隐藏渲染在 `(-9999, -9999)` | 首帧不加 `show` class（`opacity: 0`），量测完成后加 |
| 异步内容尺寸过期 | `remoteItems` 异步返回后尺寸变化 | `resolved` 变化时重置 `measured = null` |
| 子菜单方向 | 主菜单翻左后子菜单也应翻 | 统一处理——根据主菜单实际位置决定子菜单方向 |
