# 23 — 市场目录与作者主页（marketplace.json / 作者块 / 合集）

> **一句话**：把你的仓库变成 LinkDesk 插件市场里的一个「源」——最简单什么都不用做（只放 plugin.json），想上架多只插件、开作者主页、策划合集时才需要本文。
> 本文是**市场数据作者**的规范 ＋ 菜谱：`marketplace.json`（目录）、`authors/<id>.json`（作者块）、`collections/`（合集）三件东西怎么写、怎么自检、怎么发布。
> 字段级权威 = `@linkdesk/marketplace-kit` 自带的 JSON Schema（编辑器 `$schema` 补全与红波浪线）；本地自检 = `npx marketplace-kit validate`。

---

## 一、三种作者形态（先选形态，再动手）

| 形态 | 仓库里有什么 | 你要做什么 | 用户看到什么 |
|:--:|:--|:--|:--|
| **单插件仓（零配置）** | 只有 `plugin.json` | **什么都不用做** | 仓库地址被加为市场源 → 自动出现你这 1 只插件 |
| **多插件仓** | `plugin.json`×N ＋ 根 `marketplace.json` | `npx marketplace-kit init` 生成骨架 → 填条目 | 一个源，多只插件 |
| **独立市场仓** | `marketplace.json` ＋ `authors/<id>.json`（＋ `collections/`） | `npx marketplace-kit init --author <你的GitHub用户名>` | 一个源＋作者卡＋作者主页（多仓聚合） |

**选择指引**：
- 只有一只插件 → **单插件仓，到此为止**（本文其余部分都可以不读）。
- 多只插件想被一个源带出来 → 多插件仓。
- 想要**作者卡**（头像/简介/仓库数）与**作者主页**（自己排首页板块）→ 独立市场仓（或多插件仓加作者块）；把你所有仓库都声明同一个 `authorId`，市场会自动把它们聚合成一个作者域。

⚠️ **单插件仓不要手写根 `marketplace.json`**——市场读到它（哪怕内容是空的）就不再回落读 `plugin.json`，你的插件会从商店里消失。单插件仓想要作者主页：`init --author` 只补 `authors/<id>.json`，不动根目录文件。

## 二、分类声明（主分类 ＋ 小分类，全是「选」不是「创作」）

插件在**自己的 plugin.json** 顶层声明分类（英文 slug）：

```json
{
  "pluginId": "demo-plugin",
  "category": "development",
  "categories": ["code-editing"]
}
```

- `category`（单值）= 主分类，决定你在商店分类抽屉里住哪个桶；
- `categories`（多值，选填）= 小分类副标签，喂商店里的小类筛选 chips 与搜索。

### 2.1 可用清单（只能从这里选，不能自创 slug）

| 主分类 | 中文 | 可选小分类 |
|:--|:--|:--|
| `development` | 开发 | `code-editing` 代码编辑 · `terminal` 终端 · `vcs` 版本控制 · `runtime` 运行时 · `i18n` 本地化 · `debug` 调试诊断 · `snippets` 代码片段 |
| `documents` | 文档 | `viewer` 阅读器 · `convert` 格式转换 · `markdown` Markdown · `files` 文件管理 · `office-doc` 办公文档 · `notebook` 笔记本 |
| `hardware` | 硬件 | `serial` 串口 · `flash` 烧录 · `probe` 设备探针 · `smart-control` 智能控制 · `home-automation` 智能家居 · `sensor` 传感器 · `iot` 物联网 · `can-bus` 总线调试 |
| `network` | 网络 | `browser` 浏览器 · `chat` 聊天 · `cloud` 网盘 · `download` 下载传输 · `packet-capture` 抓包 · `proxy` 代理 · `remote` 远程连接 |
| `productivity` | 效率 | `clipboard` 剪贴板 · `notes` 便签 · `ai` AI 助手 · `color` 取色 · `todo` 待办清单 · `timer` 计时专注 · `launcher` 快速启动 · `calculator` 计算器 |
| `themes` | 主题 | `color-scheme` 配色 · `icon-pack` 图标包 · `font-pack` 字体包 · `wallpaper` 壁纸 · `cursor-set` 光标 · `sound-pack` 音效 |
| `entertainment` | 娱乐 | `player` 播放器 · `game` 游戏 · `music` 音乐电台 · `comic` 漫画 · `novel` 小说 · `stream` 直播 |

### 2.2 怎么选

- 主分类**单选**，从上表 7 桶里挑「装得下你这只插件」的那个；
- 小分类**选填**，从主分类对应的名单里挑（可以多个）；不选也完全合法——你的插件照常显示，只是不参与小类 chips；
- 实在想不出主分类 → 不声明，插件会进「其他」桶，永远可见（不丢、不报错）。

### 2.3 写了名单外的值会怎样

- **不会崩、不会消失**：插件照常上架，落「其他」桶（或小类归「未标注」兜底 chip）；
- **会有提示**：`npx marketplace-kit validate` 会警告，商店来源页也会记一条「声明提示」；
- 警告信息**直接列出当前可用清单**——照着报错改就行，不用翻文档。

### 2.4 名单会扩充吗

会——由市场运营按需扩（纯数据操作，不需要任何人发版）。**作者要做的只有一件事：以 `marketplace-kit validate` 报错里列出的清单为准**，它永远是最新的。

## 三、`marketplace.json` 字段全表（多插件仓 / 独立市场仓的根文件）

```json
{
  "$schema": "https://unpkg.com/@linkdesk/marketplace-kit/schemas/marketplace.schema.json",
  "plugins": [ "……条目，见下……" ],
  "collections": [ "……可选，见 §五……" ],
  "categoryRail": { "order": ["development", "documents"], "icons": { "development": "lucide:code" } }
}
```

**条目字段（`plugins[]`）**——发布（`publish`）会自动维护你工程产出的条目；手填时照下表：

| 字段 | 必填 | 说明 |
|:--|:--:|:--|
| `id` / `name` / `version` | ✅ | 身份三件（`id` 建议与 pluginId 一致） |
| `downloadUrl` | ✅ | `.linkdesk-plugin` 分发件直链（GitHub Release 资产） |
| `versions[]` | ✅ | 版本历史，**最新在前**；每条 `{version, downloadUrl, publishedAt, changelog?}`。目录保留全史——商店详情页只展示最近几版，旧历史不影响显示 |
| `description` / `license` / `repository` | 选 | 展示与详情页 |
| `author` / `authorId` | 选 | `author` 显示名（`{name, url}` 或字符串）；`authorId` 是**聚合键**（推荐 GitHub 用户名）——同名即聚合作者域，也是「官方 ✓」认证的判定输入 |
| `icon` / `marketIcon` | 选 | **绝对 URL**（未安装状态也要能打开）；`marketIcon` 优先作为商店行图 |
| `screenshots[]` | 选 | 字符串 = 图片直链；至多 1 个视频项且必须排第一：`{"type":"video","url":"…","poster":"…"}`（不自动播放） |
| `category` / `categories[]` | 选 | 见 §二 |
| `pricing` | 选 | 付费声明，见 §八 |
| `minAppVersion` | 选 | 需要的最低壳版本 |
| `publishedAt` / `readmeUrl` / `size` | 选 | 发布时间（`versions[]` 任一有即可）/ README 直链 / 字节数 |

**根级字段**：`version`/`updatedAt`（发布工具维护）；`sources[]` 只有官方目录仓用（已审核第三方源清单，作者不写）；`collections`（§五）；`categoryRail`（分类展示顺序——slug 顺序数据，写了自己仓的顺序偏好；只官方目录的 rail 生效）。

兼容纪律：**只加字段、不改语义**。旧版市场插件读新目录，认不得的字段自动忽略，永不崩。

## 四、首页布置菜谱（作者主页 `homepage.sections`，可复制片段）

作者主页的板块全部声明驱动（`authors/<id>.json` 的 `homepage.sections[]`，按声明顺序渲染）。
**「按分类浏览」不用声明**——它永远排在最后，作者删不掉。

```jsonc
// 大屏轮播：3–5 张，自己挑上大屏的插件
{ "type": "hero", "title": "编辑精选", "hint": "店主推荐",
  "slides": [ { "plugin": "demo-plugin", "tag": "主打" } ] }

// 合集板块：引用一个合集 id（合集在哪声明见 §五）
{ "type": "collection", "collection": "must-have", "layout": "duo",
  "hint": "大家都在装", "glow": false,
  "more": { "label": "看全部", "target": "category:hardware" } }

// 全量网格
{ "type": "grid", "title": "全部插件" }

// 榜单：按下载量换排序键的计算位
{ "type": "rank", "top": 6, "scope": "self",
  "more": { "label": "完整榜单", "target": "rank" } }
```

**板块通用字段**：`title`（板块标题，完全归作者）· `hint`（副题说明字，不声明不渲染）· `glow`（环境光晕，缺省开，`false` 回落中性阴影，⛔ 自定颜色）· `more`（标题旁跳转字：`label` 随意，`target` 封闭集合——`category:<slug>` / `rank` / `repo:<id>`，⛔ 任意网页地址）。

边界：hero 轮播一个店只认第一个（多个会警告，其余就地渲染）；`type` 只认 `hero/collection/grid/rank` 四件；声明里引用不存在的合集 → 板块空转并有声明提示。

## 五、合集的两种写法（两读并存，选一种）

**写法 A（inline，直接写在根文件里）**——适合 1–3 个合集：

```json
"collections": [
  { "id": "must-have", "title": "装机必备", "layout": "strip",
    "hint": "由店主编排", "items": ["demo-plugin", "demo-tool"], "order": 1 }
]
```

**写法 B（拆分文件夹）**——合集多、或想让首页数据独立维护时：
根 `marketplace.json` 的 `collections` 写**字符串 id 引用**，完整声明放 `collections/<id>.json`：

```json
"collections": ["must-have", "themes-picks"]
```

```json
// collections/must-have.json —— 内容与写法 A 的对象完全一致
{ "id": "must-have", "title": "装机必备", "layout": "strip", "items": ["demo-plugin"], "glow": false, "more": { "label": "看全部", "target": "category:hardware" } }
```

规则：
- 市场看到**字符串引用才去拉对应文件**——什么都不写就零请求（旧目录零负担）；
- 同一个 id 两种写法都出现 → **根文件里的 inline 对象生效**，文件夹那份被忽略并有声明提示（别两边都写）；
- 文件里的声明形状与 inline 完全一致（`id/title/items` 必填，`subtitle/hint/cover/layout/glow/more/order` 选填）；
- 合集 `items` 引用的插件 id 不存在 → 该成员静默跳过（防御语义，商店不炸）。

## 六、作者块（`authors/<authorId>.json`）

```json
{
  "$schema": "https://unpkg.com/@linkdesk/marketplace-kit/schemas/authors.schema.json",
  "authorId": "your-github-username",
  "name": "你的显示名",
  "intro": "一句话介绍（GitHub 能取到头像与名字，这里是非 GitHub 兜底）",
  "storeTitle": "某某的插件商店",
  "publicKey": "……（付费作者才需要，见 §八）",
  "repos": [
    { "id": "main", "name": "主仓", "sourceUrl": "https://raw.githubusercontent.com/you/your-marketplace/HEAD/marketplace.json" }
  ],
  "homepage": { "sections": [ "……§四的菜谱片段……" ] }
}
```

- **聚合**：同一个 `authorId` 出现在你每个仓的源根 → 市场自动聚合成一个作者域（头像/名字以 GitHub 为正典）；
- **repos[]**：你的每个市场仓一段（`sourceUrl` = 该仓 marketplace.json 直链）——作者店里的「仓切换卡」由此来；
- 位置：独立市场仓放仓库根 `authors/` 夹；单插件仓/多插件仓想让插件挂作者域，也可以在自己的仓库根放同名文件（市场按源根寻找）。

## 七、marketplace-kit 使用（本地自检与骨架）

```bash
npm i -D @linkdesk/marketplace-kit

npx marketplace-kit init                 # 生成骨架（自动识别仓形态；不覆盖已有文件）
npx marketplace-kit init --author your-github-username   # 补作者块
npx marketplace-kit validate ./          # 校验整个目录（含跨文件合集引用）
npx marketplace-kit validate ./marketplace.json          # 校验单文件

# 付费作者（见 §八）：
npx marketplace-kit keygen --author your-github-username
npx marketplace-kit sign-license --key your-github-username.private.key --plugin demo-plugin --exp 30d
```

- `validate` 的**错误**（结构/未知字段/封闭集合拼错）退出码 1，**警告**（分类名单外、合集引用等声明提示）退出码 0——警告码与商店来源页「声明提示」是同一套词汇，商店里看到什么这里就是什么；
- 未知字段直接报错并列出可用键（市场解析会静默丢弃认不得的键——拼错了等于没写，宁可发布前拦住）。

## 八、付费插件（声明、公钥、签发）

1. **声明定价**（条目级，只展示不裁决）：

```json
"pricing": { "model": "paid", "price": 9.9, "currency": "USD",
             "licenseUrl": "https://你的销售页", "refundUrl": "https://你的退款说明", "trialDays": 14 }
```

   收钱发生在你自己的销售页（LinkDesk 不代收、不抽成）；`trialDays` 只是展示（真试用逻辑在你插件代码里做）。

2. **生成密钥对**：`npx marketplace-kit keygen --author your-github-username` → 私钥文件（**别提交进 git、别外传；丢了换钥 = 旧密钥全部失效**）＋ 公钥（一行 base64）。

3. **放置公钥**：粘进 `marketplace.config.json` 的 `publicKey`（发布时会写进作者块）或直接粘进 `authors/<id>.json` 的 `publicKey` 字段。

4. **签发许可**：买家付款后，用其机器指纹签发——

```bash
npx marketplace-kit sign-license --key your-github-username.private.key \
  --plugin demo-plugin --machine <买家的machineFingerprint> --exp 2027-12-31
```

   `--exp` 支持 `30d`/`12w`/`6m`/`1y` 或具体日期；`--machine` 给了就是一机一码（买家在壳「本机信息」里查指纹）。把输出的 `v1.…` 密钥发给买家，其在商店「我有密钥」粘贴即完成**离线验签**（壳本地完成，无服务器）。

5. **退款 / 换钥**：退款走你的销售渠道；换钥 = 重新 keygen + 更新公钥 + 重发旧买家的许可（旧公钥签发的密钥随即失效）。

## 九、发布流程（多插件仓 / 独立市场仓）

```bash
npm run build      # 产出 <id>.linkdesk-plugin（每只插件各自工程）
npm run publish    # linkdesk-plugin-sdk publish：建 GitHub Release → 传分发件 → 更新本仓 marketplace.json
```

工程根放了 `marketplace.config.json`（`init` 生成）时，`publish` 会**同笔维护作者面文件**：

| 文件 | 谁写 | 内容 |
|:--|:--|:--|
| `marketplace.json` | publish | 你的插件条目（`versions[]` 历史、README 直链、版本日志） |
| `authors/<authorId>.json` | publish（以 config 为准） | 身份/店名/公钥/主页板块声明 ＋ 本仓的 repos 段 |
| `collections/<id>.json` ＋ 根级字符串引用 | publish | config 里声明的合集（拆分写法） |

- 同版本重跑会被拦（Release tag 已存在 → 先 bump 再发）；新版本自动追加历史；
- `--dry-run` 先看将执行的动作；`--yes` 给 CI；
- publish 更新的是**远端**仓库文件，收尾提示会提醒你 `git pull` 同步本地。

## 十、别人怎么用你的仓

- 把仓库地址（或 raw `marketplace.json` 直链）粘进 LinkDesk 市场「添加市场源」；
- 官方收录 = 在官方目录仓提交 PR 把你的源加进 `sources[]`（收录是信任背书，不复制你的条目——你发新版官方那份**永不过期**）；认证流程与「官方 ✓」徽标见官方目录仓的收录说明；
- 所有源合并进**同一个池**：分类页混合展示所有来源；你的插件带来源徽标；作者域（作者卡/作者主页）是池之上的门面，不抽走任何插件。

## 十一、版本与兼容

- Schema 随 `@linkdesk/marketplace-kit` 发版；**动 schema 必发版**（黄灯自动盯）；
- 旧目录文件永远可读（新字段全部可选）；旧版市场插件读新目录，认不得的键自动忽略；
- `$schema` 一行让 VS Code 即时补全与报错——升级 kit 版本即可拿到新字段的补全。

## 十二、AI 协作面（给自动化助手）

- 一切结构问题先跑 `npx marketplace-kit validate`——**报错即规范**：错误信息直接列出可用清单与可用键，照着改即可，不需要翻本文档；
- 生成骨架/作者块/合集文件时以 kit 的 JSON Schema 为准（`$schema` 引用让编辑器与 AI 共用同一份契约）；
- 许可签发只有两条命令（`keygen` / `sign-license`），密钥格式由壳的验签实现唯一约束——不要自己发明第二套签名格式；
- 本文档与 kit 随版本同步：validate 的输出比本文更“新”（名单扩充时先反映在报错里）。
