# 「当前项」标记两把尺子（对勾 ✓ vs 文字「当前」）

> **来源**：2026-10-06 用户实机观察——`Ctrl+K Ctrl+T`（主题选择器）里当前配方**前面打对勾**；`Ctrl+K Ctrl+L`（语言选择器）里当前语言**后面写着「当前」**。
> **状态**：🟢 **缺口成立·已拍板·已落码**（用户问「是不是不归一？」——**是**；同日选择题 **D1–D3 全按建议值**＝语言改对勾、不留「当前」二字、补锁；U1–U3 全落仓＋锁测试全绿）· ⏳ **待用户 dev 实机验收**（无误后放行归档）· 🔴 **与同夹 [01](01-快捷键文案三把尺子.md) 合成一个任务**，攒批不发版、dev 测。
> **一句话**：**同一个语义**（「这一项 = 当前生效的那个」）在 QuickPick 家族里有**两种表达**——三处用 `checked`（label 左侧 ✓）、一处用 `category`（label 右侧灰字「当前」）；而 `category` 的既有房客**全是归属与附注**，语言选择器是全仓**唯一**把「当前生效项」写进它的地方。

## 〇、现象（用户原话）

> 「我按 ctrl k 加 ctrl t，弹出的这个选择主题的界面，我选择了某一个主题前面是打的对勾。我按 ctrl k 加 ctrl l，弹出命令院长〔原文如此，指语言选择器〕的选择菜单界面，在这个界面上我选择了哪个语言后面显示的是『当前』，换句话说目前的情况就是对于同一种确定的当前的这个样子的东西它这个规定权不一样，是不是不归一？」

**今天就能看到的最小对照**（同为「打开后当前项有标记」的 QuickPick）：

| 选择器 | 入口 | 当前项标记 | 落点 |
|:--|:--|:--|:--|
| 主题选择器·阶段 1（配方） | `Ctrl+K Ctrl+T` | **label 左侧 ✓** | [`ThemeBrowser.tsx:132`](../../../../src/components/shared/theme-browser/ThemeBrowser.tsx)：`checked: originalActive?.recipeId === r.id` |
| 主题选择器·阶段 2（配色变体） | 同上 | **label 左侧 ✓** | [`ThemeBrowser.tsx:101`](../../../../src/components/shared/theme-browser/ThemeBrowser.tsx)：`checked: …colorwayId === cw.id` |
| 语言选择器 | `Ctrl+K Ctrl+L` | **label 右侧灰字「当前」** ❌ | [`LanguagePicker.tsx:38`](../../../../src/components/shared/language-picker/LanguagePicker.tsx)：`category: l.id === currentLang ? i18n.t("当前") : undefined` |
| 面板 [+] 视图选择器 | 面板头 `+` | **label 左侧 ✓** | [`panelCreatePicker.ts:68`](../../../../src/App/panelCreatePicker.ts)：`checked: it.viewId === activeViewIdRef.current` |

⇒ 同一件事（「当前生效项」）**3 处对勾 vs 1 处文字**。用户的判词成立：**不归一**。

## 一、根因：一个状态语义，两种字段

**两个字段在池侧的渲染位置与契约自述**（同文件、同一排代码）：

| 字段 | 池侧渲染 | 契约自述 |
|:--|:--|:--|
| `checked` | [`QuickPickHost.tsx:381-385`](../../../../src/pool/floating/quick-pick/QuickPickHost.tsx)：`label` **之前**的固定宽槽，`true` 渲染 `codicon-check` | [`poolQuickPick.ts:23`](../../../../src/core/types/pool/poolQuickPick.ts)：**「已激活项勾选标记——label 左侧 ✓」** |
| `category` | [`QuickPickHost.tsx:387-389`](../../../../src/pool/floating/quick-pick/QuickPickHost.tsx)：`label` **之后**的 `.ldk-quick-pick-item-category` | [`poolQuickPick.ts:27`](../../../../src/core/types/pool/poolQuickPick.ts)：**「第一行右——已 t() 解析」**（⛔ 无一字提「状态」） |

**再看 `category` 的既有房客——清一色是「归属／分类／附注」，没有一个表达状态**：

| 房客 | 写什么 | 出处 |
|:--|:--|:--|
| 命令面板 | **命令分组**（视图／标签页／首选项／帮助） | [`commandPalette.ts:31`](../../../../src/core/commands/palette/commandPalette.ts) |
| 主题·阶段 2 | 配色**归属**的配方名 | [`ThemeBrowser.tsx:100`](../../../../src/components/shared/theme-browser/ThemeBrowser.tsx) |
| 面板视图选择器 | `插件 · 容器` ／ `已隐藏` | [`panelCreatePicker.ts:64-66`](../../../../src/App/panelCreatePicker.ts) |
| 命令面板·启动页 | `开发人员` | [`startup.ts:232`](../../../../src/App/startup.ts) |
| 插件 `quickPick.show` | 插件的 `description` 直通 | [`QuickPickHost.tsx:85`](../../../../src/pool/floating/quick-pick/QuickPickHost.tsx) |

⚠️ **诚实记账**：面板视图选择器确实在 `category` 里写过状态词「已隐藏」——但那是**可见性附注**，与「当前生效项」正交；**同一份 serialize 里**「当前生效项」走的是 `checked`（`:68`）。这不构成反例，反而是同一文件内两字段分工的正面样板。

⇒ **语言选择器是全仓唯一把「当前生效项」写进 `category` 的地方**（1 vs 3）。它没有走错语义——它是**借了一个注释字段来表达状态**，因为那里当时没有更顺手的口子。

**顺带一条旁证**：语言选择器是**唯一没有测试文件**的 QuickPick 消费者（`src/components/shared/language-picker/` 下只有 `LanguagePicker.tsx` 一件；主题那侧有 [`ThemeBrowser.test.tsx`](../../../../src/components/shared/theme-browser/ThemeBrowser.test.tsx)）。⇒ 这条错位从没人拦。

## 二、影响面（谁会看到这一幕）

| 面 | 今天的形态 | 改成对勾后 |
|:--|:--|:--|
| `Ctrl+K Ctrl+L` 语言选择器 | 当前语言行右侧灰字「当前」 | 该行 label 左侧出现 ✓，**全行**多出勾选槽（与主题／面板同形） |
| `Ctrl+K Ctrl+T` 主题选择器（两段） | 已是对勾 | **一字不变**（回归面） |
| 面板 `+` 视图选择器 | 已是对勾 | **一字不变**（回归面） |
| 命令面板／插件 `quickPick.show` | 无当前项概念（`checked` 为 `undefined`） | ⛔ 不碰（`undefined` 不渲染槽，零回归） |
| 英文界面 | 显示 `Current` | 显示 ✓（**词条消费归零**，见 §四 连贯带） |

**全产品口径（旁证，支撑「对勾是正典」）**：菜单侧的当前项也一律是对勾——[`ContextMenu.tsx:436`](../../../../src/components/shared/context-menu/ContextMenu.tsx)（「当前项 √——固定宽占位保证选中项标签不错位（VS Code 菜单同款）」）＋ [`panelCommands.ts:59`](../../../../src/core/commands/shell/panelCommands.ts)（面板右键「当前项 √（单选）」）。⇒ 「✓/√ = 这一项是当前的那个」是**跨面惯例**；「当前」二字是**孤例**。

## 三、实证读数（读码 ＋ 用户实机口述，两处互证）

用户看到的「**前面**打对勾／**后面**显示当前」与池侧渲染顺序**逐字对上**：

```
QuickPickHost.tsx:379-389（同一排三件）
  <div class="ldk-quick-pick-item-row">
    [checked !== undefined ? <span class="…check">…codicon-check…</span> : 无]   ← 前
    <span class="ldk-quick-pick-item-label">{item.label}</span>                  ← 中
    [item.category ? <span class="…category">{item.category}</span> : 无]        ← 后（灰字）

语言选择器 serialize（LanguagePicker.tsx:34-40）
  { key, searchText, label, category: 当前语言 ? "当前" : undefined, detail: l.id }
  ⇒ checked 字段：缺省 ⇒ 不渲染勾选槽
主题选择器 serialize（ThemeBrowser.tsx:128-138）
  { key, searchText, label, checked: 打开前活动配方 === 本行, detail: … }
  ⇒ category 字段：缺省 ⇒ 不渲染右侧灰字
```

**已锁的部分（既有测试）**：[`QuickPickHost.test.tsx:282`](../../../../src/pool/floating/quick-pick/QuickPickHost.test.tsx)「E5.8#32：壳推送 checked 勾选标记——true 渲染 codicon-check，false 空占位」——勾选**渲染机制**有锁，⛔ 缺的是「**语言选择器该不该用勾选**」这条**消费者侧**的锁。

## 四、修法（✅ D1 已拍板：把语言选择器接上正典）

| 步 | 落点 | 改动 |
|:--:|:--|:--|
| 1 | [`LanguagePicker.tsx:38`](../../../../src/components/shared/language-picker/LanguagePicker.tsx) | `category: … ? i18n.t("当前") : undefined` → **删**；同笔加 `checked: l.id === currentLang`（与 `ThemeBrowser.tsx:132` / `panelCreatePicker.ts:68` **同一形态**） |
| 2 | 机械锁 | 补语言选择器最小测试（先例 ＝ [`ThemeBrowser.test.tsx`](../../../../src/components/shared/theme-browser/ThemeBrowser.test.tsx)）：断言 ① 唯一命中项 `checked === true` ② 非当前项 `checked === false` ③ DTO **不含** `category` |
| 3 | 连贯带（顺手核一次，不单独动） | 撤掉唯一消费者后，外仓 `lang-defaults` 的 `en.json:53 "当前": "Current"` 成**孤儿词条**（壳侧唯一消费者 ＝ `LanguagePicker.tsx:38`，官方插件仓零消费者）——⛔ **不改词典**，只在 `audit-i18n` 报告里确认一次「不再有缺翻译、只剩未用词条」即可 |

### 排除的替代方案

| 案 | 为什么不选 |
|:--|:--|
| **反向统一：把主题／面板两处改成文字「当前」** | 要改 **3 处**去迁就 **1 处**；还要推翻 [`QuickPickHost.test.tsx:282`](../../../../src/pool/floating/quick-pick/QuickPickHost.test.tsx) 的既有锁与全产品 √ 惯例（§二 旁证）——与本夹 §四 判定尺子第 3 条正相反 |
| **两处都标（✓ ＋ 「当前」）** | 同一行同屏两种标记＝更啰嗦，且没解决「一个语义两套表达」，只是把两套并排摆着 |
| **把「当前」挪到 `detail`（第二行左）** | `detail` 在主题那侧是**清单信息**（「浅色主题 · 3 配色」）、面板那侧是视图说明——把状态塞进信息位仍是**第二把尺子** |
| **不动代码，只当风格差异接受** | 用户问的「规定权不一样」正是**漂移的开始**：今天只是观感不一致，明天新增一个选择器时没人知道该抄哪一处（memory `two-rulers-one-caliber`） |
