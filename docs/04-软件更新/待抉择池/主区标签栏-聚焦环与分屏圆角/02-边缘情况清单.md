# 02 · 边缘情况清单

> 每条写「**什么情形** → **会怎样** → **本件怎么算**」。🔬 已实测 ／ 🧠 据码（file:line 在证）／ 🗣 你的观察。
> **必测** = 拍板后动手前先跑基线、落地后再跑对照；**登记** = 只记预期，不在本轮改动面内。
> 编号 **E1–E12（轴一 聚焦环）／ E13–E22（轴二 分屏成面）**。⛔ 本清单**不改任何口径**，只固定「什么算对」。

## 轴一 · 聚焦环

| # | 情形 | 会怎样 | 本件怎么算 | 类 |
|:--:|:--|:--|:--|:--:|
| **E1** | 内置 **dark**（`:root` 兜底：`--bg-card: #2D2D2D` ／ `--bg-window: #1E1E1E`，全不透明） | 🔬 环 **100% 不可见**（像素采样 accent = 0） | 修法甲**必须**让它在 dark 下可见——否则等于没修（**这是主判据**） | 必测 |
| **E2** | **玻璃主题**（`--bg-card` / `--bg-window` 取 `rgba()`：aurora-glass ／ panorama ／ zones） | 🔬 环**透出**（浮在颜色里）——即你原话①「一般情况下……会出现那个框」的来源 | 修法后**仍**可见，且**不再依赖**内容透明度（同一条规则） | 必测 |
| **E3** | 插件详情页含**不透明附图** | 🗣 附图局部盖住环（你的原话③） | 修法甲下附图在环**之下** ⇒ 不再盖 | 必测 |
| **E4** | 视图根自带不透明底（先例 `.ldk-welcome-page { background: var(--bg-window) }`） | 🧠 整圈不可见（内容层三边全盖） | 同 E3（甲覆盖） | 必测 |
| **E5** | `app.zoneRadius` 关 ⇒ `--surface-radius: 0px` | 🧠 环直角、内容直角 ⇒ **同形**（巧合正确） | **现状零变化**（护栏）——甲在 0px 下渲染与今天同形同厚 | 必测 |
| **E6** | `--surface-radius > 0`（分区圆角拉大） | 🗣 环的圆角弧**横切**方内容（原话④「一点点直角，它就斜掉」） | 甲**单独**不做 D4 ⇒ 此态**仍在**；甲＋D4 同期 ⇒ 同形 | 登记 |
| **E7** | `--ui-scale = 1.25`（`app.uiFontScale`） | 🧠 环 1px **不随 scale 变**，`inset: 0` 亦然；标签条 35 → 43.75px | ⛔ 不改口径（环粗不缩放＝现状）；只确认**不因此消失** | 登记 |
| **E8** | 显示缩放 / DPR > 1（125% / 150% / 200%） | 🧠 1px 环可能被亚像素柔化，但**不再被盖死**（今天会整圈消失） | 截图放大看即可；⛔ 不得把「柔化」判为缺陷 | 登记 |
| **E9** | **单面板**（无分屏）聚焦 | 🧠 环**仍常显**（今天如此，`:278` 兜底分支） | 若 **D1** 选「只在分屏显示」⇒ 单面板无环——**归你拍板**，本清单不预设 | 登记 |
| **E10** | 键盘 Tab 走到面板内元素（`*:focus-visible`：`outline: 2px solid var(--accent); outline-offset: 2px`） | 🧠 与**面板环是两回事**：键盘环在元素**外**、面板环在面板**内**；可能同屏叠加 | 甲**不动**键盘环；叠加态只需「两层都看得见」 | 登记 |
| **E11** | 环的层级与命中：内容层是**兄弟节点、DOM 在后**（E5.8#141 保活层） | 🧠 环若 `z-index ≤ 0` 或 `z:auto` ⇒ 被内容层盖（＝今天）；若加 `pointer-events: auto` ⇒ **吃掉**面板 `mousedown` ⇒ 点空白不再聚焦 | 🔴 **甲的两条硬前提**：`z-index: 1`（＞内容层）＋ `pointer-events: none`。两条缺一即**红** | 必测 |
| **E12** | 把手（缝上的 resize handle）层级 `--z-sticky` = 200 | 🧠 环 `z:1` ＜ 200 ⇒ 悬停时 accent 竖线压在环上，互不遮蔽（分屏时同屏） | 目视一次即可 | 登记 |

## 轴二 · 分屏成面（pane 吃 zone 的表面契约）

| # | 情形 | 会怎样 | 本件怎么算 | 类 |
|:--:|:--|:--|:--|:--:|
| **E13** | 左右分屏 50 / 50 | 🧠 方案甲：两栏**各成一面**（面色 `--bg-card`）＋ 内容按 `--surface-inset` 内缩 ⇒ 相邻内容可见间隔 ≈ 2 ＋ **0.4%** ＋ 2px；**缝的位置本来就有**（`layout.ts:34`／`:62`）——今天只缺颜色（[01 §三 第 5 条](01-根因与修法.md)），把手恰好居中填满那条空带。⚠️ 「位置有」≠「分配对」：那 0.4% 今天是从**总量之外**多出来的（第二栏越界，**E21**） | 缝**不新造**：位置用既有 `HANDLE_PCT = 0.4%`（⛔ 不改它的**值**），颜色由面色补；**但分配必须先扣缝**（[01 §5.5 甲](01-根因与修法.md)／**E21**）——这是甲的便宜之处与其配套账 | 必测 |
| **E14** | 不对称分屏（把手拖到 20/80） | 🧠 缝宽 = **0.4% × zone 宽**（比例值，非像素常量）：1280px 宽 ⇒ ≈5.1px；600px 宽 ⇒ ≈2.4px。⚠️ 与 zone 缝的**像素常量 4px** 不同源同值——这是**现状口径**，⛔ 本轮不改（改＝动 `HANDLE_PCT` 的**值**，[01 §5.3](01-根因与修法.md) 否决案） | 缝宽与把手**位置**无关；⛔ 不得出现「缝随把手位置变宽」。🔬 扣缝修正（[01 §5.5 甲](01-根因与修法.md)）后此口径**逐字不变**——缝宽仍 `0.4% × 宽`，变的只是两栏各让出 `0.2%` | 必测 |
| **E15** | **单面板** | 🧠 方案甲里 pane 内缩 = 0 ⇒ 与今天**逐像素一致**（零新增面/缝） | 🔴 **现状零变化**是甲的护栏：单面板截图与改前一致 | 必测 |
| **E16** | 上下分屏 ＋ **嵌套**（先左右再上下） | 🧠 横缝/竖缝各 0.4%（同 E14 口径），**交叉点**由把手填满——零重叠零空隙（先例：[index.css:432-435](../../../../src/index.css) zone 缝的同一算法｜pane 缝先例 [layout.ts:62/75](../../../../src/pool/zones/main/MainZone/layout.ts)） | 嵌套一次目视；缝不得在交叉点错位 | 必测 |
| **E17** | 内容视图**自带不透明底**（`--bg-window`，与 zone 底色同色） | 🧠 这正是今天缝不可见的原因（缝里露的 `--bg-window` ＝ 内容色）；甲案给 pane 补**面色** `--bg-card`（与标签条同面）后，面色与内容底色**不同色** ⇒ 面与缝都显形 | ⚠️ D3 需定「面色取什么」：`--bg-card`（与标签条同面）／`--bg-window`（与内容同面 ⇒ **缝又会隐身**） | 登记 |
| **E18** | 池**脱出窗**（floating window）里的主区 | 🧠 分屏几何同源（同 pool 根、同 `computeLayout`）⇒ 同行为；脱出窗尺寸不同但缝仍是像素常量 | 脱出窗里分屏一次目视 | 登记 |
| **E19** | 把 `app.surfaceRadius`（**组件**圆角）拉大 | 🧠 ⛔ **不动**分区面圆角、不动 pane 缝（两把标尺各管各，[01 §四](01-根因与修法.md)） | 🔴 护栏：本案**不得**把两轴合流（合流 = 改配置语义 = 超范围） | 必测 |
| **E20** | 第三方主题**不声明** `--surface-shadow` | 🧠 `var(--surface-shadow, none)` ⇒ 面**无阴影**，靠缝＋圆角仍成立 | 不必要求主题补键；⛔ 不得为显影而写死阴影（硬约束 1） | 登记 |
| **E21** | **分屏第二栏越出容器**（S5）——`computeLayout` 用**未扣缝**的总量切分（`w0 + w1 = 100%`），却把第二子盒放在 `x + w0 + HANDLE_PCT`、宽度不减 | 🔬 第二栏外缘 = **100.4%**（≈4px @1000px）；`.ldk-main-zone` **无** `overflow:hidden`（E5.8#98 为保环四角而撤，[index.css:270-271](../../../../src/index.css)）⇒ 越界落在窗口外。🗣 症状＝右栏**右边那条环**／下栏**底下那条环**不见了——「很底下那一点点」。⛔ 与 S1 不同源：这里环是**被移出可视区**，不是被内容盖 | 🔴 **必测 → 必改**：⛔ 不算「已知不修」。判据：分屏后**两栏四边环全周可见**（玻璃／内置主题都要看）；机读口径＝第二栏 `x + w ≤ 100%`（[01 §5.5 甲](01-根因与修法.md)／[D5](04-任务清单.md)） | 必测 |
| **E22** | 扣缝修正（[01 §5.5 甲](01-根因与修法.md)）波及**公共几何**：拖拽比例、双击复位、嵌套分屏、标签拖拽命中 | 🧠 甲只改「可分配总量」（`wEff = w - HANDLE_PCT`）⇒ ① 50/50 时两栏各 **49.8%**（仍等宽）② 单面板**不进该分支**，零影响 ③ `HandleRect.sizes` 语义不变（仍记用户拖拽比例）⇒ 把手位置与回读**不变**；⚠️ 每栏窄 **0.2%**（≈2px）⇒ 标签拖拽的落点判定可能跨过 1–2px 边界 | 🔴 回归必测：① 拖动把手改比例（两栏仍等宽、把手居中）② 双击复位 50/50 ③ 嵌套（先左右再上下）四栏均在容器内 ④ 逐栏拖一个标签换组 ⑤ 单面板逐像素零变化（E15）⑥ 把手命中区宽度仍 `HANDLE_PCT`（手感不变） | 必测 |
