>
> **非新能力声明（`check-design-flow` §8.4 ③）：** 本档是**门禁判据的落地方案**，规则对象是**既有** CSS 类名、既有关键帧名与既有 manifest 字段（`pluginId`）；不新增作者面能力。⇒ **无需新能力设计前置**。

## 一、判据（四条，**全部可机械校验**）

| # | 判据 | 报红条件 |
|:--:|:--|:--|
| **①** | **裸定义类名必须带本仓前缀** | 某 CSS 选择器的「裸定义」类名不 `startsWith(pluginId + "-")` |
| **②** | **`@keyframes` 名必须带本仓前缀**（拍板 Q3=(A)） | 某 `@keyframes <name>` 的 `name` 不满足同上 |
| **③** | **`ldk-` 边界**（拍板 Q4=(A)） | `pluginId` 本身以 `ldk-` 开头 ⇒ 红（它在借宿主命名空间，且会让 ①② 全部失效） |
| **④** | **fail-closed 兜底** | `plugin.json` 不存在 / 解析失败 / **既无 `pluginId` 也无法从目录名推出** ⇒ **红**（**不许静默放过**——拿不到前缀就无法校验，静默放过 = 门禁变瞎子） |

**「裸定义」的口径与既有腿一字不差**（必须复用现成实现，别新写一套解析）：`packages/plugin-sdk/src/eslint/checks/reserved-classes.ts` 里的 `splitSelector` / `subjectOf` / `hasAncestor` / `stripComments` / `isTestOrMockRel` / `collectFiles`——**它就是壳仓 `scripts/check-css-namespace.mjs` 的同源判据**（「逗号切开后的某个 compound、无祖先、主体是单个类名」），**照抄或提取共用**，**不许另写一个近似版**。

**`pluginId` 的读法**：`<root>/plugin.json` —— 🔴 **JSONC 解析**（`jsonc-parser`，SDK 已依赖；先例 `validate.ts:172`）。缺 `pluginId` 时**按 loader 的既有兜底取工程目录名**（硬约束 11 的 `derivePluginId` 语义），并在报告里**明确打印这一行**（让作者知道门禁用的是目录名）。

## 二、腿的形状（一条推荐 ＋ 一条必须记录的理由）

**推荐：并入现有 `check-css-namespace` 腿，保留同一 `CHECK_IDS.cssNamespace`。**

| 选项 | 利 | 弊 |
|:--|:--|:--|
| **(A) 并入现腿（推荐）** | 少一条腿、少一份作者面说明；**既有 `eslint-disable` 注释继续有效**（作者面已有 disable 惯例）；报点文案可以一句话说清「不是你的前缀」 | 已知口径：**既有 disable 注释会同时盖住「保留名」与「前缀」两条判据**（作者面已声明 disable = 知情绕行，可接受，但**必须在作者面写清**——那是 ⑧ 的活） |
| (B) 新开一条腿 / 新 checkId | 两条判据分别计数、分别豁免 | 插件仓可能**已有**针对保留名的 disable 注释 ⇒ 新 id 会让它们失效并**突然报红**；且作者面要多讲一条 |

🔴 **无论选哪个，把理由写进交接段**（这条是公共面口径，不许悄悄定）。

**旧「宿主保留名」判据怎么办**：在「裸定义」这一轴上，**前缀判据完全覆盖了它**（插件再也不可能有裸定义 `.badge`——它必须以 `<pluginId>-` 开头）。⇒ 建议**保留名为「报点措辞的补充」**：命中时在消息里补一句「且这是宿主保留名（`reserved-class-names.json`）」，**不要**两条独立判据重复报同一处。⚠️ **保留名清单本身不许删**：它仍是**作者面**（§12 表 ↔ 对账门禁）与 **scoped 调优**纪律的真相源。

**射程**：只扫 `.css`（`EXT_CSS`，与现腿一致）；`isTestOrMockRel` 跳过测试/mock（同现腿）。
