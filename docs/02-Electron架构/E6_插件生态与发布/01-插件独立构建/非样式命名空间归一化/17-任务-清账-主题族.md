### 1.1 🔴★ 本格头号风险：`theme-defaults` 的 `light` **是宿主交接位**

- 宿主在**插件加载前**先注册两个兜底配方：`{ id: "dark", … }` 与 `{ id: "light", colorways: [{ id: "light", colors: {} }] }`（**空配色**）——出处 `src/core/services/ui/ThemeEngine/registry.ts:114-130`。
- 宿主的注释**逐字写着**：「**插件主题（theme-defaults）后注册同名配方（id "light"）→ 覆盖亮兜底**」；且 `ThemeEngine/registry.ts:38-46` 对「覆盖**无 `pluginId`** 的兜底」**明写不告警**（**有意交接**）。
- 🔴 **后果（可判定）**：若把 `theme-defaults` 的 id 从 `light` 改成别的名字 ⇒ **宿主那个空兜底 `light` 不再被覆盖**：
  1. 设置页主题下拉里会**多出一个空洞条目 `light`**（选了它 = 空配色 = 什么都没变/变成 `:root` 硬兜底）；
  2. `app.theme = "light"` 的老用户**指向空兜底**；
  3. 与 `app.theme` 的 **enum 同步**（`src/App/startup.ts:220-236` 的 `syncAppThemeEnum` / 死 id 清扫）交互复杂。
- ⇒ 🔴 **本格的路线只有两条**（**必须选一条并留读数**）：
  - **(甲) 连宿主兜底一起改**：宿主把兜底 id 改成保留名（如 `<宿主保留前缀>-light`），并把"交接位"写成**显式声明**（不靠同名意外相遇）；`theme-defaults` 用 `<pluginId>-light`。⇒ **零错配窗**的前提是**壳与该插件同年批发**（它是 `seed:true`，**可以做到**）。
  - **(乙) 明文保留 `light` 为「宿主公开交接位」**（登记在宿主保留名账的「约定面」段，作者面说明"这个 id 是宿主的亮色兜底交接位，`theme-defaults` 是它的实现方"）。⇒ **本仓零改名**，但**必须在交接段写明"这是裁决结果，不是漏做"**。
- ⚠️ **不许选"直接改 id 不管宿主"**（那是亲手制造上面 1/2/3 三条后果）。

### 1.2 其余 9 只：形状清楚，风险中等

- 它们的 id（`aurora-glass` / `mint-soda` / …）**不带归属**，改成 `<pluginId>-…`（形状以 [1.35](05-任务-外观族id归属评估.md) 的结论为准）。
- 🔴 **三处 id 要一起改**：① `plugin.json` 的 `themes[].id`（或 `iconThemes[].id`）· ② `themes/*.json` 里的 `id` **与** `name`（**两个字段**）· ③ 若 `themes/*.json` 里还有**配色变体 id**（`colorways[].id`），**它同样会进 `app.themeColor`** ⇒ 一起改 ＋ 一起迁移。
- ⚠️ **`name` 是给人看的标签**（`极光玻璃 Aurora Glass`）——**要不要改？** 按 [1.35](05-任务-外观族id归属评估.md) 的裁决执行；**若判不改**，在交接段写明（它**不是** id，改它会影响设置页显示文字）。
