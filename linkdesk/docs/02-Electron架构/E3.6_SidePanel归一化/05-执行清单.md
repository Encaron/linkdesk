### Bug 1 🔴🔴🔴 L6 两条注册路径不同步

**历史：** `loadPlugin` ↔ `loadPluginRuntime` 两条路径——每次给 loadPlugin 加能力，loadPluginRuntime 就漏掉。已发生 4 次：主题颜色数据（E3b Bug 2 `cea1476`）、语言资源、i18n 资源、sidebar/statusBar（`03d0f01`）。根因：两条路径各自写各自的逻辑，没有共享函数。修复：E3b #36j1 提取 `applyPostLoadSteps` 归一化函数。

**E3.6 触发条件：** `loader.ts parseContributions`（声明式 `contributes.views`）和插件 `activate()`（命令式 `registerView()`）是两个入口。

**🔥 防线——代码级：**
```typescript
// src/core/ViewContainerService.ts
// ✅ 声明式和命令式同走 registerView() 一个方法——不是两条路径
registerView(pluginId: string, containerId: string, descriptor: ViewDescriptor): void {
  if (!containerId) { console.warn("[ViewContainer] registerView: containerId 为空"); return; }
  this._ensureContainer(containerId);
  const model = this._models.get(containerId)!;
  const existing = model.allViewDescriptors.find(v => v.id === descriptor.id);
  if (existing) {
    // 更新已有——不创建第二条记录
    Object.assign(existing, descriptor);
  } else {
    model.allViewDescriptors.push(descriptor);
  }
  this._onDidChangeViews.fire({ containerId, views: model.allViewDescriptors });
  this._updateActiveViews(containerId);
}
// 声明式（loader）和命令式（activate）都调用此方法——单一路径。
```

### Bug 2 🔴🔴🔴 L6b 卸载时 revert 时序颠倒

**历史：** `revertThemeIfCurrent` 在 `onWillUninstall` 之后执行 → 主题已注销 → revert 找不到 → 静默跳过。主题/语言/toast displayName 三次重演（`1ba6a25` + `4475f78` + `5668db3`）。根因：需要旧状态的逻辑在清理之后执行。修复：revert 移到 `onWillUninstall` 之前。

**E3.6 触发条件：** 卸载 file-tree → explorer 容器开着 → `unregisterAll("file-tree")` 后 explorer 的 views 和容器定义都没了 → SidePanel header 空白。

**🔥 防线——代码级：**
```typescript
// src/App.tsx —— PLUGIN_REMOVED 消费端（L197-210）
// ⚠️ 顺序至关重要——revertContainerIfCurrent 必须在 closeTab 之前！
useEffect(() => {
  const handler = (e: Event) => {
    const { pluginId } = (e as CustomEvent).detail as { pluginId: string };

    // Step 1: 先 revert 容器——需要 ViewContainerService 里还有数据
    revertContainerIfCurrent(pluginId);
    // 此时 ViewContainerService 里还有该插件的 viewsContainers 声明
    // revertContainerIfCurrent 能查到 "explorer" 容器属于 file-tree → setSidebarView(null)

    // Step 2: 再关标签页——需要 tabState 里还有数据
    for (const group of tabState.groups) { ... forceCloseTab(tab.id); }
  };
  // ...
}, [tabState.groups, forceCloseTab]);

function revertContainerIfCurrent(pluginId: string): void {
  // 查当前 sidebarView 对应的容器是否属于被卸载的插件
  if (!sidebarView) return;
  const plugin = getViewPlugin(pluginId);
  const containerIds = Object.keys(plugin?.manifest.contributes?.viewsContainers ?? {});
  if (containerIds.includes(sidebarView)) {
    setSidebarView(null);  // 关闭侧栏——不等 ViewContainerService.unregisterAll 后再关
  }
}
```

```typescript

  // 然后 unregisterAll("p1") → explorer 容器消失
```

### Bug 3 🔴🔴 StrictMode 双重 effect 竞态

**历史：** `initPluginLoader` async → StrictMode 第二次调用看到 `_initialized=true` 直接 return → `applyConfiguration` 在第二次 effect → 主题未注册 → 闪回暗色（#59c Bug 1）。根因：async init 的 `_initialized` guard 不防重入。修复：`_loadingPromise` 模式（ESRint `no-async-init-guard-only` 机械拦截）。

**E3.6 触发条件：** ViewContainerService 是纯同步（Map 操作），不涉及 async init。但 SidePanel 组件 mount-unmount-remount（StrictMode）时，`useEffect` 订阅 `onDidChangeActiveViews` 会重复。

**🔥 防线——代码级：**
```typescript
// src/components/SidePanel.tsx
useEffect(() => {
  if (!effectiveContainerId) return;  // ← active guard
  const sub = ViewContainerService.onDidChangeActiveViews.event(({ containerId }) => {
    if (containerId !== effectiveContainerId) return;  // ← 只处理当前容器
    forceUpdate();  // 触发重渲染
  });
  return () => sub.dispose();  // ← cleanup 退订——StrictMode remount 时旧订阅被清理
}, [effectiveContainerId]);
```

**ESRint 已覆盖：** `no-effect-callback-without-active-guard` 检测 `if (!open)` 守卫缺失。

## AI 友好度检查清单（每任务执行前自问）

> 来源：git 历史十堂课 + E4 执行清单 AI 友好度模式

- [ ] 涉及路径拼接？→ `normalizePath()` / `joinPath()`——防 `\` 混入
- [ ] 涉及动态 import？→ 外裹 try/catch + console.error 明确报哪个文件
- [ ] 涉及事件订阅？→ useEffect cleanup 返回 unsubscribe——防 StrictMode 双重订阅
- [ ] 涉及 useEffect + 回调 prop？→ 加 `if (!active) return` 守卫——防闭态副作用
- [ ] 涉及 async init？→ `_loadingPromise` 模式——防 StrictMode 竞态
- [ ] 涉及持久化？→ `PluginStateService` / `LayoutService`——禁止 localStorage
- [ ] 新建文件在 `plugins/` 下？→ `npm run lint` 必须扫到
- [ ] import 核心类型？→ `import type { ... } from "@src/core/..."`——不重定义
- [ ] 硬编码颜色/文字/路径/pluginId？→ CSS 变量 / `t()` / `getAssetPath()` / 声明字段
- [ ] 新增注册表逻辑？→ register + unregisterAll + onDidChange 三件套——缺一个就是 bug
- [ ] 卸载路径？→ `revertXxxIfCurrent` 在 cleanup 之前——不是之后
- [ ] 两个入口写同一逻辑？→ 归一化到一个函数——不走两条路径（L6 预防）
