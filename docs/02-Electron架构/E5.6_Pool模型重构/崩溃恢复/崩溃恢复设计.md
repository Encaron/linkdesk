# Pool 崩溃恢复设计

> 📖 架构全景：[01-Pool模型设计.md](../01-Pool模型设计.md)
> 📖 执行清单：[E5.6#27-#30](../E5.6-执行清单.md)——Phase 7：崩溃恢复

---

## 1. 概述

每个 Pool 是独立渲染进程。一个 Pool 崩 ≠ 全壳崩。崩溃恢复策略按 Pool 类型分层——**侧栏恢复快（1-2s），主区恢复慢（3-5s）但保持标签页状态**。

---

## 2. 心跳协议

```
壳 → Pool: pool:ping（每 5s）
Pool → 壳: pool:pong

超时 10s 无 pong → 判定崩溃
```

```typescript
// 壳侧
const POOL_TIMEOUT = 10_000;

class PoolHeartbeat {
  private _lastPong = new Map<string, number>();

  start(zone: string): void {
    const interval = setInterval(() => {
      this._pools.get(zone)?.webContents.send('pool:ping');
      const elapsed = Date.now() - (this._lastPong.get(zone) || 0);
      if (elapsed > POOL_TIMEOUT) {
        this.handleCrash(zone);
      }
    }, 5000);
    this._intervals.set(zone, interval);
  }

  handlePong(zone: string): void {
    this._lastPong.set(zone, Date.now());
  }

  handleCrash(zone: string): void {
    // 见 §3 / §4
  }
}
```

## 3. SidebarPool 崩溃恢复

**影响范围：** 侧栏消失。主区编辑器不受影响。

```
时序：

T+0s: SidebarPool render-process-gone
T+0s: 壳检测崩溃（事件直接触发——不等心跳超时）
T+0.1s: 壳清除旧 SidebarPool WCV
T+0.2s: 壳创建新 SidebarPool WCV → pool.html?zone=sidebar-left
T+0.5s: Pool 就绪 → ready()
T+0.6s: 壳 pushLayout——恢复侧栏到崩溃前的状态（viewId + width）
T+0.7s: SidebarRenderer mount 对应视图
T+1-2s: 恢复完毕。用户感知：侧栏短暂闪烁
```

**为什么快？** 侧栏只渲染一个视图——没有编辑器状态、没有未保存内容。

---

## 4. MainPool 崩溃恢复

**影响范围：** 所有主区标签页消失。用户正在编辑的文件可能丢失未保存内容。

```
时序：

T+0s: MainPool render-process-gone
T+0s: 壳检测崩溃
T+0.1s: 壳渲染崩溃覆盖层（OverlayWindow）：
        ┌──────────────────────────────┐
        │  ⚠ 插件运行时崩溃，正在恢复…   │
        │  [x] 未保存的更改可能已丢失    │
        └──────────────────────────────┘
T+0.2s: 壳清除旧 MainPool WCV
T+0.3s: 壳创建新 MainPool WCV → pool.html?zone=main
T+1.0s: Pool 就绪 → ready()
T+1.1s: 壳 pushLayout ← 从 tabState 恢复全部标签页/分屏
T+2.0s: MainRenderer 重建所有标签页组件
T+3.0s: Monaco Editor / CM6 等重建完毕
T+3-5s: 崩溃覆盖层消失。恢复完毕。
```

**关键设计决策：**

1. **不尝试保存未保存内容。** 崩溃时 DOM 状态全丢。编辑器显示 "未保存的更改已丢失"。
2. **标签页结构从 tabState 恢复。** `tabState` 在壳 React 里——不依赖 Pool 进程。
3. **插件重建后从 `sourceId` 恢复。** 文件编辑器重新读文件、串口重新打开端口。
4. **崩溃覆盖层提供可选的 "重新加载" 按钮**——如果自动恢复卡住，用户可手动触发。

---

## 5. BottomPanelPool 崩溃（未来）

**影响范围：** 底部面板消失。终端会话全部丢失。

```
T+0s: BottomPanelPool render-process-gone
T+0-0.5s: 重建 Pool → pushLayout { views, activeViewId, height }
T+0.5-2s: 终端插件重启 → 用户需重新打开终端会话
```

**终端会话丢失是不可恢复的。** node-pty 进程随 Pool 进程一起被杀。和 VS Code 行为一致——VS Code reload 窗口后终端也全部丢失。

---

## 6. OverlayWindow 重建

OverlayWindow 崩了 → 浮层全部消失 → 立即重建：

```
T+0s: OverlayWindow render-process-gone
T+0.1s: 重建透明 BrowserWindow
T+0.3s: 恢复。右键/命令面板/tooltip 立即可用
```

OverlayWindow 无状态——纯渲染。重建 = 零点几秒。

## 7. 内存监控

```typescript
// 壳侧——每 30s 采样
async function monitorMemory() {
  for (const zone of windowManager.listPools()) {
    const info = await window.linkdesk.pool.getMemoryInfo(zone);
    if (info.privateBytes > MEMORY_WARN_THRESHOLD) {
      // Console warn + 可选：建议用户关闭一些标签页
    }
  }
}
```

**不自动杀 Pool**——只在内存达到危险阈值时 Console 警告。用户决定是否关闭标签页。

---

## 8. 总结

| Pool | 崩溃影响 | 恢复时间 | 数据丢失 |
|:--|:--|:--|:--|
| SidebarPool | 侧栏消失 | 1-2s | 无 |
| MainPool | 主区标签页全丢 | 3-5s | 未保存编辑内容 |
| BottomPanelPool | 底部面板消失 | 0.5-2s | 终端会话全部丢失 |
| OverlayWindow | 浮层消失 | 0.1-0.3s | 无 |

**核心原则：tabState 在壳 React 里——不随 Pool 崩溃丢失。** 标签页/分屏/侧栏视图等所有结构信息持久化在壳侧。Pool 只是它们的渲染载体。
