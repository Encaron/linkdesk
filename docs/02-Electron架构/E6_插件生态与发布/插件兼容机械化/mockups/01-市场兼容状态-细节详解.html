⑦ 帮助卡是谁造的 · 怎么触发 · 字从哪来（用户 2026-09-18 四问 ＋ 触发方式纠正后的答案）

问答
容器（portal / 层级 / 关闭谁管）壳的共享件：OverlayPortal（壳仓 src/components/shared/overlay-portal/OverlayPortal.tsx，经 @linkdesk/ui 导出给所有插件）——portal 目标（#overlay-root）、z 序、Esc、焦点都归它 ⇒ 零新增壳组件、零 SDK 发版。市场插件今天就在用：src/views/sidebar/SearchView/AddSourcePopup.tsx（<OverlayPortal onClose triggerRef>）。本格用法与它不同的一点：不传 trapFocus（不循环焦点、不自动聚焦）＋ closeOnOutsideClick={false}（鼠标按下不该关掉一张只靠「移开」消失的卡）；onClose 仍要传给 Esc 用
卡片（长什么样）市场插件自己的组件（marketplace- 前缀），照 AddSourcePopup 的形状写：<OverlayPortal onClose triggerRef={状态标} closeOnOutsideClick={false}> ＋ 自己一段 JSX。卡内不可交互（pointer-events:none）：纯文本、无链接无按钮，三句话以内
触发鼠标停在状态标上 → 出卡；鼠标移开 → 消失（先约 400ms 悬停意图延时，防划过闪烁）。键盘：标可 Tab 聚焦 ⇒ 聚焦即出卡、失焦 / Esc 关；触屏：无 hover ⇒ 点一下出、点外关（退化路径）。⛔ 不是点击弹层（点状态标不做任何事，不占点击语义）· ⛔ 不用右键（本行的右键已是齿轮菜单的语义）· ⛔ 不做 toast / 弹窗 / 暗屏大面板（那是「把注意力拽过来」的一类，不是帮助卡）
位置贴状态标（triggerRef 量位置 + fixed 定位）：信息栏在主区右侧 ⇒ 卡向左展开，不会盖住状态标自己；贴到窗口边缘就翻转到另一侧。⛔ 不居中大面板、⛔ 不推挤布局（浮着，不动内容）
字（预设文案）预设，住在市场插件的 i18n/en.json（key = 中文原文）；壳只给机器态（state 枚举 ＋ 两个真日期 ＋ minAppVersion 事实）——⛔ 壳不下发任何用户可见句子（否则多语言和文案口径会分裂到核心里）
能不能给别的小提示复用（通用帮助卡）先分清两件东西：①容器（悬浮层挂哪、怎么关）今天就有，是壳共享件 OverlayPortal，任何插件现在就能用；②「瞄一眼就出、移开就消」的帮助卡本身（触发语义 ＋ 延时 ＋ 定位翻转 ＋ 键盘/触屏退化 ＋ 不可交互）今天没有——壳 src/components/shared/ 的 24 个零件里没有 tooltip / hover 卡这类件。
要做成全壳通用件 = 新能力：按 design-flow 走 8 维度 ＋ @linkdesk/ui 与作者面 docs 发版（⚠️ 不涉 18 仓接腿，见下）。准入先例是通的——[E6 07 号档](../../01-插件独立构建/07-共享组件独立分发设计.md) 把 @linkdesk/ui 零件判为壳能力（多提供方 = 任何插件消费 / 多消费方 = 内置＋第三方 / 壳不懂业务），帮助卡是通用控件、不带业务语义，同一条成立。⇒ 🔴 2026-09-18 已单独立格：E6#120（第 8.7 轮 · 本批最后一棒），详案 = 08-任务-通用悬停提示卡.md（8 维度设计前置已填满）。⚠️ 两处实测更正：① 该件落地后壳夹数是 25 个（今天 24）；② 不涉「18 仓接腿」——@linkdesk/ui 只被 4 只官方插件消费，且零件是编译进各插件 bundle 的（不在 SDK external 名单）⇒ 要用新件得各自升依赖 ＋ 重新构建 ＋ 发新版，不存在一次铺开（18 仓那条腿是 SDK 判据的事，不是本件的事）。本层先用「容器 ＋ 插件自有卡片」落地——格 7 先做完则格 5 直接用共享件（两条路只留一份实现）。

HoverCard⛔ 不用：名字对得上触发方式，但在设计系统惯例里 HoverCard 意味着富内容且可交互（里面能放链接、表单，鼠标能移进去）。我们这张偏偏不可交互（pointer-events:none）⇒ 叫这名字等于给未来的人留一个「往里塞表单」的坑
HintCard（推荐）✅ 名的是用途（一张短解释卡），不把交互写进名字——「纯展示、不可交互、≤3 句」作为契约写进组件文档。中文叫「提示卡」。备选 HelpCard（贴用户原话「帮助小卡片」，但「help」易被读成「帮助中心入口」）。⛔ 更不许 onlyMarketplaceCanUse_hoverCard / marketplaceHintCard / compatHintCard 这类带消费方或业务字样的名字（用户 2026-09-18 点名）
落地地址（若立格）壳仓 src/components/shared/hint-card/HintCard.tsx；类名 ldk-hint-card（照 ldk-badge / ldk-form-row 惯例；多词长名可如 context-menu→ldk-ctx-* 那样缩写，本件词短，全拼即可）＋ 经 @linkdesk/ui 导出。同夹必须带 HintCard.test.tsx（夹内惯例：tsx ＋ css ＋ 测试同夹）——🔴 实测：knip.json 的 ignore 名单里那 4 个共享件（FilePathInput / FormRow / NumberInput / Toggle）正好都是没有测试文件的，而带测试的（badge / theme-browser / string-list-editor）都不在名单里 ⇒ 带测试就不被判死代码
🔴 但不进保留名账（2026-09-18 实测更正）reserved-class-names.json 的 classes 整块已在 E6#109l-b 删除，今天只剩 $comment / version / keyframes（关键帧 8 条）；scripts/host-reserved.json 的十二个家族里也没有类名栏。类名规则早已是结构性的「自己定义的类名一律 ldk- 开头」——ldk-* 在作者面文档里是一行通配，从不逐个登记 ⇒ 新件零登记动作；唯一要求是 CSS 真的落在壳 src/**/*.css 里（check-reserved-names-doc-sync 会核「表里每个名在宿主真实存在」）
若立格：发版三条轴① @linkdesk/ui 0.3.0 → 0.3.1（0.x 阶段一切向后兼容变更走 patch 位，minor 位留给破坏性——version-bump 判据）＋ 真发 npm；② 壳 PATCH（src/ 新增共享件 ＋ 随包种子同步）；③ 消费方插件（要用它的那几只 PATCH ＋ lock 抬版）。

名字铁律（照进格 4 的机械判据）：共享件（src/components/shared/ 目录名 ＋ 组件名 ＋ ldk- 类名）grep marketplace|compat|file-tree|filetree|explorer|serial|settings|editor ⇒ 零命中；命中任一 = 名字里带了消费方或插件业务 ⇒ 红。壳平台概念可以用（theme-picker / theme-browser 就在共享件里——主题是壳基建，不是某插件业务）。

谁管管什么（机制 / 内容切法）
壳（机制，插件看不见）触发接线（悬停意图延时约 400ms、鼠标移开消失、键盘聚焦出卡 / 失焦关、触屏点一下出 / 点外关）· 定位（贴锚点、边缘翻转）· 层级（#overlay-root、不抢焦点、无遮罩）· 磨砂玻璃（卡面进层即吃 E5.8#107 结构地板的 backdrop-filter——与右键菜单同一条规则、同一种效果，零新增 CSS；🔴 但卡面必须是 [data-overlay-wrapper] 的直接子元素（深度 3），若在中间多套一层定位盒，玻璃规则够不着 ⇒ 该处 src/index.css:526-558 注释已明写「新浮层若嵌到深度 4+ 且需磨砂，先想结构归位，不要学那个例外」）· Esc · 无障碍（aria-describedby 把卡与触发器关联）· 与原生 title 互斥。
⚠️ 触发接线必须归壳——若让插件自己接 onMouseEnter，延时 / 触屏退化 / 键盘 / a11y 这几件事就会在每个消费方各错一遍（正是本仓历史上类名撞车、各家自写 portal 的同一类病）
插件（内容与策略）触发元素是谁（这颗状态标）· 卡里写什么（JSX / i18n 文案）· 卡多宽、出现在哪一侧（可给偏好，壳有权按空间翻转）· 什么时候不出卡（如读数缺失时的文案）
保底（design-flow 8 维度① 要求）这个壳件删掉 / 没被用时界面不残废：状态标本身已经把「正常 / 兼容 / 部分不适配 / 不适配 / —」说清楚，卡只是补充解释 ⇒ 保底 = 标，不依赖卡
非目标（写进契约，防被人越用越大）⛔ 不做富交互内容（链接 / 按钮 / 表单 / 可滚动区）——那需要「鼠标能移进卡里 ＋ 离开宽限期」，是另一个组件；⛔ 不做「替代原生 title」的全仓清扫（另一条轴的事）；⛔ 不做点击展开 / 固定 / 多卡同屏
