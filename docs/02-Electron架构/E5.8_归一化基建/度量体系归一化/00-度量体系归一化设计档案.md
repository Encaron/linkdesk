## 一、背景与目标

### 1.1 用户需求溯源

1. **痛点**：文件树内字体太小，不像 VS Code；图标「小的不像话」。已有 `window.zoomLevel`（整体窗口缩放）但不是「文件树内字体」这个诉求。
2. **违和恐惧**：只放大文件树 → 与全软件字体不匹配，十分违和。**宁缺时间不缺满意度**——E5→E5.5→E5.6→E5.7 多次改架构已证明。
3. **最终形态（用户 4.3 原话）**：各个显示的文字统一大小后，壳声明一个调制所有字体大小的设置项，以此调制所有字大小的比例。**zone 大小、高低、字体大小不能写死代码**，硬编码需要像主题、翻译那样「动起来」。
4. **十准则（8.1-8.10）**：精益求精·慢工出细活·低耦合高内聚·AI友好（三层）·归一化（不重蹈 v2.6，一 bug 不多处出现）·插件自由化（第三方作者零壳改动）·禁硬编码·声明式·易拓展·健壮。
5. **monaco 例外（点 9）**：monaco 内字体单独属于 monaco，在「编辑器」分组下有它单独的放大缩小——如同 monaco 背景至今不变玻璃。
6. **Q11 必答**：是否每个插件都要接入 API？插件声明设置项出现在设置页、字号比例却由壳调控——关系是什么？是否有机协调体？换设置 GUI 方案后是否仍可调字号？

### 1.2 勘察结论（三路合成，2026-08-28）

| 勘察面 | 结论 |
|---|---|
| **字号分布全景** | 全仓库无任何字号 token 变量。硬编码 px 档：9/10/11/11.5/12/13/14/16/18/20/24/26/28/48px。**主体 12px**（壳 body 基线 + 大量控件）、**次要 11px**、**主视觉 13px**（菜单/tab/文件名）、**图标 14px**、标题 18px。壳 zone CSS ~38 处 + 插件 ~183 处 + index.css 4 处 ≈ **303 处字号声明**。 |
| **壳 chrome 溢出高危** | 30+ 处「固定上界」不随字号动：顶栏 30px（用户举例的精确溢出点）、状态栏 22px/line-height 22px 链、主区 tab 条 35/30px、侧栏 header 35px、面板 tabbar 28px、控件 line-height 20px 写死（ContextMenu/SelectBox/Combobox）、InlineInput 22px 档、badge 18px 等。**纯放大字号不改这些上界 = 必溢出。** |

## 二、机制设计（新能力 8 维度）

### ① 能力边界

- **壳能力**（多提供方 = 任意插件文本 / 多消费方 = 壳 chrome + 全部插件 UI / 桌子不知内容 = 壳只发 token 不懂语义）。**保底 = scale 1.0**（默认恒成立，零插件也成立）。
- 与 `window.zoomLevel`（Chromium 整体 zoom，`setZoomFactor` 1.2^level）**语义区分**：zoom = 整窗等比放大（含像素级）；Phase 12 = **仅字号比例调制**（文本 + 文本相邻度量），布局结构不缩放。

### ② API 设计

- **零新增 `window.linkdesk.*`**。字号是壳级 surface 全局属性（硬约束「壳级功能不放插件」），走**配置键 + CSS token**，不是 API。
- 唯一新东西 = `app.uiFontScale` 配置项（壳注册，进「主题」组）。契约位置：`src/App/config/appearance.ts`（registerAppearanceConfiguration）。

### ③ 通信方式

- **配置 → token → 广播 → 消费**，一条链，零新事件：
  1. 用户调 `app.uiFontScale`（slider）→ `onApply` → `debouncedApplyThemeIfReady`（先例：app.surfaceRadius）
  2. 引擎 `applyOverrides` 合并 `--ui-scale` + `--font-size-*`（先例：radius 绝对化）
  3. `commitTokens` 写壳 :root + 广播 `theme:changed`（variables 全量，**零新增**）→ preload-pool 写池 :root
  4. 壳 + 插件 CSS 消费 `var(--font-size-*)` / `calc(... * var(--ui-scale))`
- 持久化 = 壳配置（configuration 服务）。插件只读 token，无状态。

### ④ 壳侧代码设计

- **目录**（壳目录规范）：常量进 `core/services/ui/ThemeEngine/constants.ts`；覆盖计算进 `tokens.ts applyOverrides`；播种进 `seeds.ts`（若进 custom 覆盖键）；配置进 `src/App/config/appearance.ts`；:root 默认进 `index.css`。
- **单一权威**：
  - `FONT_SIZE_STEPS`（档名数组）+ `FONT_SIZE_BASE_PX`（档名→基准 px 映射）——**单一源**，对标 `RADIUS_SCALE_STEPS`（types/theme.ts:70）先例。
  - `UI_FONT_SCALE_DEFAULT = 1`——单一默认。
  - 概念键分离：`app.uiFontScale`（全局比例）≠ `editor.fontSize`（monaco 内容独立键）——两个正交轴，不共键。
- **硬约束合规**：字号走 token（零硬编码 px 进新代码）；文字走 t() 不涉；插件 ID 不硬编码（audit 不枚举插件名）。

### ⑤ 插件侧代码设计

- **零贡献点改动、零 schema 改**。第三方插件**只需消费 token**：`font-size: var(--font-size-md)`。想给自家内容独立字号 → 已有 `contributes.configuration`（先例 editor.fontSize）——那是「该内容自己的尺度」，不进全局比例。
- 内置插件迁移 = 把硬编码 px 换成 token 消费（file-tree/settings/marketplace/serial-monitor/editor chrome/panel-demo）。虚构实例：无新插件。

### ⑥ 显示设计

- 设置页「主题」组新分节「字号」：`app.uiFontScale` slider（`uiHint:"slider"` + `unit`），对标 app.surfaceRadius 渲染（renderControl.tsx:101-119）。
- monaco 内容字号：保持现有「编辑器」组 `editor.fontSize`（`uiHint:"fontSize"` → NumberInput 8-72）。

### ⑦ 配置设计

| 项 | 值 |
|---|---|
| key | `app.uiFontScale` |
| 类型 | number（**整数百分比**） |
| 默认 | `100`（`__none__` 哨兵 → 100，resetsToDefault） |
| 范围 | min 85 / max 150 / step 5 |
| uiHint | `fontSize`（**NumberInput** 渲染，− 数字 + 步进——用户拍板要这个控件） |
| group | 「字号」（主题组下分节） |
| resetsToTheme | **否**——主题不规定字号，字号是独立全局轴 |
| dependsOn | **无**——恒显恒生效，不依赖 appearanceMode（用户质疑修正：主题不碰字号，无需跟随/覆盖开关） |
| onApply | `() => debouncedApplyThemeIfReady()`（引擎 `value/100` → 比例 → token） |
| renderControl | `"fontSize"` 分支改读 `prop.minimum/maximum/step`（editor.fontSize 不声明 → fallback 8/72/1，零回归） |

> **四项拍板（2026-08-28）**：① 控件 = **NumberInput 百分比步进**（85-150 step 5，非滑杆）② 字号**恒显恒生效 + resetsToDefault**（非 dependsOn custom——主题不规定字号，字号是独立轴）③ 档位归一化轻微视觉变化（11.5→12 / 9→10）**接受** ④ serial-monitor CM6 **随全局**（非孤岛——是插件 UI 非编辑器，简单 + 统一双赢）。

### ⑧ 代码规范 + 验收

- 机械门禁：新 `check-font-scale-audit`（raw `font-size: NNpx` 在 src + builtin 插件 CSS 中拦截，须走 `var(--font-size-*)`）。
- 验收：`npm run check` 全绿 + CDP 实机（字号变化 → 全 surface 跟变 + 零溢出 + monaco 内容不动）+ 用户视觉验收。

## 三、消费模型（归一化 + 比例调制的统一）

### 3.1 两个 token，两个角色

| token | 值 | 消费者 | 用途 |
|---|---|---|---|
| `--ui-scale` | 比例（默认 1） | 度量（高度/行高/间距/图标盒） | `height: calc(22px * var(--ui-scale))` |
| `--font-size-<档>` | 基准 px × scale（引擎算好） | 文字 | `font-size: var(--font-size-md)` |

引擎**在 JS 侧算好 `--font-size-*` 的最终 px**（`${base * scale}px`），消费者一个 var 搞定；度量用 `--ui-scale` 乘。这样**文字零计算、度量显式缩放**——声明式、归一化。

### 3.2 字号档位单一源（收敛 303 处散乱 px → 语义档）

| 档 | 基准 px | 收敛来源（现存散值） |
|---|---|---|
| `--font-size-2xs` | 10 | 9（徽章）、10（路径/次要 label） |
| `--font-size-xs` | 11 | 11（次要文本/按钮/统计）、11.5（role-switch-btn） |
| `--font-size-sm` | 12 | **12（主基线）** |
| `--font-size-md` | 13 | **13（菜单/tab/文件名）** |
| `--font-size-lg` | 14 | **14（图标字形/面包屑）** |
| `--font-size-xl` | 16 | 16（圆钮箭头） |
| `--font-size-2xl` | 20 | 20（行图标） |
| `--font-size-3xl` | 26 | 26（pd-name） |
| `--font-size-4xl` | 28 | 28（welcome-title） |

> 18px（页/区标题 settings group-title / marketplace section-title）**归 2xl=20**（拍板③接受归一化轻微变化，避免 3 档并 2 档）。
> 24/48px 属**独立显示图标**（plugin-icon--emoji/hero-icon），不随字号比例缩放（见 §五 图标裁决）。

### 3.3 度量缩放（32 个固定上界的处理三类）

| 类别 | 处理 | 例 |
|---|---|---|
| `line-height: NNpx` 写死 | 改 **unitless 比例**（`line-height: 1.5`）——随字号自动缩放，最健壮 | ContextMenu `.ctx-item` 20px → 1.6；SelectBox/Combobox 20px → 1.6；toast-message 22px → 1.83 |
| `height: NNpx` 文字行容器 | `height: calc(NNpx * var(--ui-scale))` | 顶栏 30px、状态栏 22px、tab 30/35px、侧栏 header 35px、tabbar 28px、badge 18px |
| `padding: Npx Npx` 垂直含字 | 垂直分量乘 scale | `.titlebar-menu-btn` `4px 8px` → `calc(4px * var(--ui-scale)) 8px` |

> 32 个溢出点全清单见 §五。**纯结构**（缝/边/玻璃 ::after）不缩放。

## 五、控件/浮层适配策略（用户点 7）

1. **右键菜单框（ContextMenu）**：`line-height: 20px` 写死 → 改 unitless `1.6`；图标 14px 随 lg 档；快捷键 11px 随 xs。项高随字号自然增长。
2. **选择框（SelectBox）/ Combobox**：`line-height: 20px` 写死 → unitless `1.6`；下拉项同款；max-height 260px 不动（面板上限，超长滚动）。
3. **弹出框（Dialog/QuickPick/Toast/FloatingPanel）**：Dialog 按钮 28px 高乘 scale；QuickPick 无固定高（padding 弹性，安全）；Toast `line-height: 22px` → unitless；FloatingPanel title 38px/act 26px 乘 scale。
4. **badge/微字**（9-10px → 2xs）：height + line-height 同步乘 scale，否则文字顶破。
5. **图标裁决（用户 4.3「字旁边的图标」）**：
   - **文本相邻图标**（文件树图标盒、tab 图标、菜单项图标、switcher 勾选）——盒/字形随 `--ui-scale` 缩放（语义 = 配文）。
   - **独立显示图标**（图标栏 24px、marketplace hero 48px、行图标 20px、codicon 大图）——不随字号比例（与文本不直接相邻，语义 = 装饰/品牌）。
   - codicon 是字体字形，缩放 = 改其 font-size 或容器盒——**归文本相邻轨道**由各 surface 裁定。

## 六、monaco 边界（用户点 9，专项）

### 6.1 现状（勘察坐实）

- monaco 内容字号唯一入口 = `editor.fontSize`（plugin.json:30，`uiHint:"fontSize"` → NumberInput 8-72，default 14），EditorTab.tsx `buildMonacoOptions()` → `updateOptions()`。
- 键盘字号缩放已被摘除（EditorView.tsx:226-228 删 `editor.action.fontZoomIn/Out/Reset`），仅 `editor.mouseWheelZoom` 保留。
- `theme-sync.ts` 只同步 vs/vs-dark 颜色主题，不碰字号——**monaco 内容与全局字号域完全解耦**。
- 壳侧另有 `window.zoomLevel`（整窗 zoom，`view.zoomIn/Out` Ctrl+=/-）。

### 6.2 边界定案（推荐）

| 面 | 进全局字号比例？ | 依据 |
|---|---|---|
| **monaco 内容**（代码/行号/minimap/悬停） | ❌ **不随 --ui-scale** | 用户点 9「monaco 字体单独属于 monaco，编辑器分组下单独放大缩小」——与「monaco 背景不变玻璃」同构的孤岛原则 |
| **monaco chrome**（EditorTab/面包屑/状态栏） | ✅ 随全局比例 | 属通用 UI chrome（顶栏 tab 同族） |
| **serial-monitor CM6** 接收/发送区 | ✅ 随全局比例（**拍板**） | 无独立字号控制键；是插件 UI 文本非编辑器。简单（CSS 换 token 即随全局）+ 统一（工具栏/统计全随、独它不随 = 违和）双赢 |

### 6.3 一致性验证

CDP：`app.uiFontScale` 1.0→1.25 → monaco 内容字号**不变**（读 editor.fontSize 14px），editor 状态栏/面包屑随变；`editor.fontSize` 8→20 → 内容随变、全局不动。两轴正交，各自独立滑动。

## 十、Q11 答复（有机协调体模型）

> 用户问：**是否每个插件都需要接入 API？插件声明设置项出现在设置页、字号比例由壳调控——关系是什么？是否有机协调体？换设置 GUI 后仍可调字号？**

**不是 API 集成，是 token 契约。** 关系分三层：

1. **零 API**：插件**不接入任何 `window.linkdesk.*`**。字号比例是壳的一个配置项（`app.uiFontScale`）+ 一组 CSS token（`--font-size-*`/`--ui-scale`）。插件文本只要写 `font-size: var(--font-size-md)` 就**自动进入协调体**——壳调比例，全员同步跟变。
2. **两种设置，两个正交轴**：
   - **全局字号比例** = 壳声明（`app.uiFontScale`）——管壳 chrome + 全部插件 UI 文本。
   - **内容级字号** = 插件声明（先例 `editor.fontSize`）——管该内容自己的尺度（monaco 孤岛），**不进全局比例**。
   - 两者都出现在设置页（壳键在「主题」组，插件键在插件自己的组），互不覆盖、正交滑动。这**就是**用户说的「有的插件声明设置项出现在设置页，字号比例由壳调控」的机制——壳键管比例，插件键管自家内容尺度。
3. **有机协调体 + GUI 可替换**：数据永远在 `window.linkdesk.configuration` 一处，设置插件只是**渲染器**（memory settings-plugin-replaceable-ui 先例）。换第三方设置 GUI / 换未来 GUI 方案——读同一份配置、渲染同一组 uiHint，`app.uiFontScale` 照常可调。字号缩放**不绑定任何 GUI**。

**一句话**：有机协调体 = 「壳管比例 token、插件消费 token、数据在配置服务、GUI 只是渲染器」——不是每个插件接 API，是每个插件消费 token。

### 与 `window.zoomLevel` 的关系（正交双轴，2026-08-28 定案）

> 用户问：zoomLevel 和本任务系列正交吗？——**正交，分叉点正好在 monaco 内容上。**

- **`window.zoomLevel` 是什么**（E5.7#79，VS Code 同款）：整数 -8..8、每 ±1 = ×1.2，注册在「通用」组，命令 view.zoomIn/Out/Reset（Ctrl+=/-/0）。onApply → `setZoom(1.2^level)` → 主进程 `poolView.webContents.setZoomFactor()`（main.ts:174-186）——**Chromium 合成器光栅级整页缩放**：文字/图片/图标/布局/monaco 内容全部像素统一放大。
- **正交论证**：
  | 轴 | 作用层 | 覆盖 | 粒度 | monaco 内容 |
  |---|---|---|---|---|
  | `window.zoomLevel` | 光栅缩放 | 全页面所有像素 | 20% 跳变 | **会放大**（在池 WCV 里被光栅缩放） |
  | `app.uiFontScale` | CSS token 重排版 | 文字 + 文字邻接度量 | 5% 步进 | **排除**（孤岛，editor.fontSize 自有） |
  - 两者**乘性组合**：有效尺寸 = fontScale × zoomLevel，互不覆盖。
  - 唯一差异点 = **monaco 内容**——zoomLevel「放大一切」，fontScale 唯一拒绝碰的就是内容孤岛。这是两条轴清晰的语义分界。
- **UX 定位（写设置描述语的依据）**：zoomLevel = **整体放大镜**（界面+内容一起放大，看不清整个应用时用）；fontScale = **文字密度标尺**（只有文字和文字邻接度量变，布局/图片不动，字太小/太大时用）。用户原始痛点「文件树字体太小，zoomLevel 不匹配」正是这层语义差。两个开关并存不冲突，但描述语必须区分，避免用户误以为重复。
