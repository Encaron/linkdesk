| E21 | 黄灯→红灯升级（v1 正式版） | SDK 黄灯腿留 `--strict` 开关；v1 前官方各仓**黄单清零**后统一切红（`sync:plugin-ci` 铺装轮次执行）；黄单本身就是给作者的升红预告——⛔ 不做「无预告突然判红」；壳侧无此过渡（一步红灯） |
| E22 | `enumDescriptions` **对象 / 数组**两形态 | 插件 manifest 的 schema 规定**对象**（`值 → 显示名`；数组形态过不了 `npm run build`），而壳内部类型与动态推送是**数组**。渲染取字必须走双形态函数（settings 仓 `enumDescription.ts` `enumDescriptionAt`）——⛔ 按下标直读会让插件声明的对象形态**恒取不到**，下拉裸显英文值、D7 目标落空（2026-10-04 第 2 波实证：`renderControl.tsx:209` 旧写法即此病，已修随 settings 1.0.31；契约回写 [01 层 2](01-方案与落点契约.md)） |
| E23 | **池→壳命令桥的 token 占位槽**（`commands:execute`） | 壳桥契约是 `(commandId, token, ...realArgs)`，而插件作者按 `linkdesk-api` 调 `executeCommand(id, ...args)` **不带占位槽** ⇒ 池侧 fallback 若把原始实参直接铺进桥，**第一个实参会被壳当成 CancellationToken 吃掉**（`core.openSettings` 的 `{pluginId, scrollTo}` 即此形，表现为「点了不跳类别」；具名实参展开亦随之失效）。处置：池侧统一补 `undefined` 占位再铺 `realArgs`（两种调用形归一），回归单测锁死（2026-10-04 第 3 波；⛔ 任何新增桥通道照此位解构） |
| E24 | **导航请求被面板身份开关吞掉** | 悬浮面板 reveal 是**身份开关键**（同 viewId 再 reveal = toggle-close，`floatingPanelReveal.ts`）。导航语义（带 `pluginId`/`scrollTo`）走同一条链 ⇒ 面板已开着时点配置项 = **关掉用户眼前的面板**。处置：`core.openSettings` 按**意图**分流——导航请求且面板已是本套设置页则不再 emit reveal（分组/滚动请求照发）；裸调（齿轮/命令面板/Ctrl+,）保留 toggle（2026-10-04 第 3 波；控制项 S4 复测） |
| E25 | 插件更新时**旧版本目录被占用**（rename EPERM） | 判据只吃占用/权限三码（EPERM／EACCES／EBUSY）——目录被 `fs.watch` 不影响、目录是 CWD 报 EBUSY，**只有「目录内某文件被外部进程持句柄」会出 EPERM**（本机 node 实测）。处置：退避重试（0/250/700/1500/2500ms），全败才抛并给可执行提示（说清关掉谁）；其余错误码立刻上抛——重试不掩盖真问题（2026-10-04；同 `commit-update` 两步 rename） |
