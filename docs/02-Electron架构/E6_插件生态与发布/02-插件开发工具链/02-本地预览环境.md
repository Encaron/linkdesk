## 三、实现方案（实装——SDK 自带 dev-host/，随包发布）

> 代码真身：`packages/plugin-sdk/src/dev-server.ts`（本文 §三 = 其实装决策记录）+ `packages/plugin-sdk/dev-host/`。清单 #23.5a-c/#24a-b 已回勾。

### 3.1 `linkdesk-plugin-sdk dev` 做的事

```
1. 读当前目录 plugin.json → derivePluginId + 校验 entry（缺 entry = 纯 contributes 分区视图插件 →
   无浏览器宿主（dev-host 渲染 entry 组件）→ 友好报错指向 E6#28 壳侧 dev / **#28.5 真机环**——真机环直写产物目录，纯 contributes 插件同样可验证，§10.3）
2. 现读 contributes.i18n 声明的各语言 JSON → { 语言码: { translation } }（语言码 = 文件名去 .json；
   单语言文件坏 → 跳过该语言，dev 不阻断——validate 报真错）
3. createServer（Vite dev server）：
   - root      = SDK dev-host/ 目录（随包 raw 资产，不预编译——vite dev 现役转换 tsx，预编译会杀掉 HMR 源码模块态）
   - port      = 1421（strictPort，避开壳 1420）；LINKDESK_DEV_PORT 环境变量可覆盖（CI/占用逃生门）
   - fs.allow  = [dev-host, 插件根]（root 在 node_modules 内，vite 默认 allow 不含作者工程）
   - alias     = /^__linkdesk_dev_entry__$/ → plugin.json entry 绝对路径
   - define    = __LINKDESK_DEV_I18N__ / __LINKDESK_DEV_PLUGIN_ID__（字面量表达式注入，非逐插件虚拟模块路径）
   - plugins   = [@vitejs/plugin-react]（JSX + fast-refresh）
4. 打印 http://localhost:1421/?pluginId=<id> → 尽力平台开浏览器（win32 = cmd /c start；开不了不阻断，URL 手抄）
5. 挂起直到 Ctrl+C → server.close()（dev 无退出码语义，正常退出 = 0）
```

### 3.2 宿主页（dev-host/ = index.html + dev-main.tsx + mock.ts）

- **index.html**——极简壳：顶部 dev 条（绿点 + pluginId + 「本地预览 · 无 Electron/IPC · 改码 HMR」）+ `#ld-root` + `:root` 兜底主题 CSS 变量（插件 `var(--xxx)` 不至全黑；此页 = SDK 工具 UI，非壳渲染树，固定值不违反壳硬约束 16）。
- **dev-main.tsx**——接线端：`i18next` init（lng = 第一个声明的语言；`useSuspense:false`）→ `injectDevMockApi()` → `import PluginView from "__linkdesk_dev_entry__"` → `<I18nextProvider><PluginView isActive /></I18nextProvider>`。宿主把插件当「激活标签」渲染，对标壳渲染视图插件语义；`tabId`/`sourceId` 是壳标签页系统概念，纯浏览器 dev 无对应物。
- **mock.ts**——**E6#23.5c 注入锚点，E6#27（2026-09-07）替换注入体完成**（`injectDevMockApi()` 签名与调用点不变）。现注入体 = 递归 Proxy 包 `linkdeskMock`（第三输出目标自动生成树，见 §10.1/§10.2）：树内方法 = 类型驱动中性默认 + 调用即打 `[linkdesk-mock] <path>` 日志；**树外方法名（拼写错/契约外）调用时抛「不是 linkdesk API 方法」**（整链 dotted path + 同源说明），不再静默 `undefined`/裸 TypeError——单源同构下 mock 缺 = 生产也缺，早抛早纠正。

### 3.3 entry 加载——`/@fs/` 语义 + 静态 import（HMR 全链）

清单 #23.5b/#24b 字面的「`/@fs/` 加载」= vite dev 服务 root 外绝对路径文件的语义。实装 = `resolve.alias` 把虚拟 id 映射到 entry **绝对路径** + dev-main **静态 import**：入口成为模块图常规成员 → HMR 走 vite 标准全链（改码即热更）。若改浏览器端运行时 `import('/@fs/…')`，计算型动态 import 不在静态图，HMR 会退化成整页刷新。alias 解析出的绝对路径文件由 vite 按需转换 + 注入 HMR——**即 `/@fs/` 加载**（无偏离拍板，§九.1）。

### 3.4 与壳的关系

```
壳 dev server（端口 1420）:     npm run electron:dev → 完整壳（产品，极简 Pool）
插件 dev server（端口 1421）:   npm run dev → 纯浏览器最小壳（SDK 自带，不进壳）
壳侧 dev（仓库内跑）:           npm run dev:plugin -- <插件id> --electron → 完整壳，单插件 dist 消费 + 真 IPC
```

**工具链三层使用场景**（详见 [04-作者真机调试环.md](04-作者真机调试环.md) §四 四形态表）：
- **浏览器 dev-host（1421）**：逻辑正确 / UI 布局微迭代（亚秒 HMR，mock IPC）——非真 IPC 插件主路径。
- **壳侧 dev**（本轮 E6#28b/#62c 实装）：壳团队 / 出厂插件作者——在**壳仓库**跑 `npm run dev:plugin -- <插件id> --electron`，dev 门控只加载在开发插件 → 走**物化 dist 目录消费**（与第三方同一条 loadPlugin bundled 路径）→ 改码 = 增量重建单插件（~1s）→ renderer reload（不重启 electron）。真 preload-pool IPC + CDP 9222。
- **真机环（A，#28.5）**：第三方作者在**自己工程**跑 `linkdesk-plugin-sdk dev --real`——生产真环境（直写 `{userData}/plugins` + reload）。

两个 dev server 独立运行——第三方插件作者不需要壳源码/构建，不需要启动完整 Electron。真实 IPC/真机环 = **SDK `dev --real`**（#28.5，第 2.3 轮）：自动化 build → **直写 `{userData}/plugins/<id>`** → CDP 清缓存 + reload——仍是生产真环境（`linkdesk://` 逐请求读盘；`protocol.handle` 响应无 Cache-Control 会被 Chromium 缓存，故 reload 先 `Network.clearBrowserCache` 才落盘生效，见 [04 §二 事实#1](04-作者真机调试环.md)），只是把 §10.3 的「装进 LinkDesk」自动化成循环；壳零码、作者不碰壳源码/构建，仍不造第二壳。机制与拍板详见 [04-作者真机调试环.md](04-作者真机调试环.md) + §10.3。

### 10.2 默认值策略（#27a 颗粒度补齐）

- `linkdesk-api.ts` 是纯类型图（实测无 sync/async/fire 标注）——**sync/async 从返回类型推断**（返回 Promise = async、返回 void = fire-and-forget），机械可行。
- **类型驱动默认值**：Promise → `Promise.resolve(undefined)`、void → `() => {}`、其余 → `undefined`——够 UI 骨架开发（mock 本质 = 不崩 + 可感知调用，真数据走真实 IPC / 作者自 mock）。〔2026-09-07 E6#27 落地精化：纸面「Promise→undefined 其余→undefined」按**返回类别细分**——PROMISE<arr/tuple>→`[]`、PROMISE<string|boolean>→`""`/`false`、同步 string→`""`、**fn-ret 订阅类→`()=>{}`**（49 个，void 默认会崩骨架）；每方法调用打 `console.info("[linkdesk-mock] <path>")`。实测分布见 E6-执行清单 #27a 勾行〕
- **个性化默认值 override 表按需追加**（如 `path.join` → `""`）——不承诺逐方法手写默认值（几十命名空间几百方法，纯手工 = 第二份维护，违背本任务初衷）。**纸面完美陷阱规避**：这是「按返回类型生成」的原意边界，先行定死避免开工才发现默认值怎么定。〔2026-09-07 E6#27 落地：同源构造下**无手工 override 表**——分类默认值即保底，杜绝第二份维护；mock 方法集 = 标注源 = 构造保证〕

### 10.4 #28b 机制——dev 门控并入发现集（`?path=` URL 路由废弃）

- **原 `?path=<cwd>&dev=true` 是 E5.6 多 WebView URL 路由话术——极简 Pool 无 URL 路由**（pool-main.tsx 零 `?zone=` 路由，第 1.2 轮实锤），且 #23.5 已定宿主 = SDK 页（无壳），`?path=` 无处消费。
