# 多串口支持设计——E5.8 Phase 6

> 对应清单任务：**E5.8#26-#30**。2026-08-17 用户拍板升格为正式 Phase 6（原末位 #26 单任务"多串口支持"颗粒度重拆为五任务）。
> 执行时机 = **E5.8 基建收官后**（Phase 1.5 broadcast 通道 + Phase 4 契约生成先就位——载荷变更被契约门禁 + #22.5 DTO 校验兜底）。
> 本档案 = #26-#30 的设计真相源。清单条目只装任务+验收，设计细节全在本文件。

## §1 为什么多串口

**现状 = 单串口架构**。SerialService 单例持**单端口字段组**（`port/lineBuffer/isClosing/encoding/portName/baudRate`），`openPort` 打开新口前先关旧口（互斥语义）。一个串口监视器标签页开 COM3，另一个标签页开 COM13 → 后开的把先开的顶掉。

用户场景：双串口同时收发（COM3 收传感器 + COM13 收 GPS，互不干扰）。E5.5#9l 已做过 per-tab 隔离打底（pluginState key 加端口前缀），但**服务层、wire 契约、推送面仍是单口假设**——本 Phase 把三层全部升级。

## §2 现状摸底（代码级证据）

| 层 | 文件 | 单口假设点 |
|:--|:--|:--|
| 服务层 | [electron/services/serial-service.ts](../../../../electron/services/serial-service.ts) | 单例单口字段组：`port/lineBuffer/isClosing/encoding/portName/baudRate/flushTimer`（L71-78）；`openPort` L109-111 先关旧口；`getStatus()` 无参返回单口快照；`closePort/sendData/sendText/setDtr/setRts` 全操作 `this.port` |
| IPC 层 | [electron/ipc/serial-handlers.ts](../../../../electron/ipc/serial-handlers.ts) | `setCallbacks` 三回调（onData/onStats/onSystem）**无端口名**——推 `_mainWindow` + 全部 pool views（广播）；`getStatus/closePort` handle 无参数透传 |
| wire 契约 | [src/core/types/ipc/serial.ts](../../../../src/core/types/ipc/serial.ts) | `SerialStatus` 单口快照；`SerialStats` 无 portName；推送载荷无 portName |
| preload API | [src/core/api/linkdesk-api.ts](../../../../src/core/api/linkdesk-api.ts) L304-316 | `onData(cb: (text: string) => void)`——回调只收 string，端口信息丢失 |
| 插件消费① | [plugins/user/serial-monitor/src/services/SerialContext.tsx](../../../../plugins/user/serial-monitor/src/services/SerialContext.tsx) | 模块级共享状态（单口）；**onData hack（L195-200）**：`events.emit("serial:rawData", {sourceName: _sharedState.sourceName, text})`——用"当前状态里的口"标注到达数据，多口并发时**数据会错标到别的口** |
| 插件消费② | [plugins/user/serial-monitor/src/index.tsx](../../../../plugins/user/serial-monitor/src/index.tsx) L522-572 | **字符串解析 hack**：从系统消息文本 `"---- 已打开串行端口 COM13 ----"` 用正则挖端口名（L526）决定激活哪个标签页——结构化数据靠字符串解析，E3j #78 原则（"结构化数据、消费者无需解析"）的反例 |
| 插件消费③ | [src/hooks/useIpcEvent.ts](../../../../src/hooks/useIpcEvent.ts) L8-24 | 映射表 `serial-data → onData`，回调收 string |

**三个单口 hack 必须随本 Phase 消灭**（否则多口并发数据错标——不是新功能，是修根）：

1. SerialContext `events.emit` 用 `_sharedState.sourceName` 贴端口名（数据到达时状态可能已切到别的口）
2. index.tsx 正则解析系统消息字符串挖端口名
3. `useIpcEvent` 映射表 string 载荷（端口信息在推送层已丢失）

## §3 目标架构

```
┌─ 插件（serial-monitor 标签页 ×N）─────────────────────┐
│ 会话 A（绑 COM3）     会话 B（绑 COM13）               │
│  onData({portName,text}) 按 portName 过滤 ──┐  ┌── 同 │
└─────────────────────────────────────────────┼──┼──────┘
        linkdesk.serial.*（preload API）      │  │
┌─ IPC 层 ────────────────────────────────────┼──┼──────┐
│ serial-handlers：载荷对象化广播              ▼  ▼      │
│  serial:data → { portName, text }（含口名）            │
└───────────────────────────────────────────────────────┘
┌─ 服务层（主进程）──────────────────────────────────────┐
│ SerialService 单例不变                                │
│   Map<portName, PortState>                            │
│   PortState = { port, lineBuffer, isClosing,          │
│                 encoding, portName, baudRate,         │
│                 flushTimer }——六字段内聚，互不串扰     │
└───────────────────────────────────────────────────────┘
```

**五个设计决策（本档案拍板定死，执行不回炉）：**

| # | 决策 | 内容 |
|:--|:--|:--|
| D1 | Map 化内部结构 | `Map<portName, PortState>`；`openPort` 删除"先关旧口"互斥语义；`callbacks` 保持单组（推送路由是 IPC 层职责，不进服务层——低耦合） |
| D2 | 请求面 API 扩展 | 全部状态/操作方法加**可选 portName 参数**。缺省语义 = **唯一打开口**：0 口 → 抛"串口未打开"（现网同文案）；≥2 口 → 抛"多串口已打开，请指定 portName"（防歧义——静默选错口比报错更糟，健壮性准则） |
| D3 | getStatus 双形态 | `getStatus()` 无参 → `SerialStatus[]`（全部打开口，空数组 = 全关）；`getStatus(portName)` 有参 → 单口快照（旧语义）。Hot Exit 遍历恢复 + 壳诊断面靠无参形态 |
| D4 | 推送载荷对象化 | `serial:data/stats/system` 三通道载荷全部对象化：`{portName, text}` / `{portName, tx?, rx?}` / `{portName, message}`；onData/onStats/onSystem 回调签名同步对象化。**破坏性变更——窗口论证见 §5** |
| D5 | 插件按口过滤 | 数据路由用载荷 `portName` 字段精确比对会话口（替代字符串正则 hack + 全局 portOpenRef）；三态 isMyPort 容错保留（portName 缺失时行为不变——防御性） |

## §4 五任务设计细节

### #26 服务层 Map 化

**改动文件：**
- [electron/services/serial-service.ts](../../../../electron/services/serial-service.ts)——主战场：`private port/lineBuffer/isClosing/encoding/portName/baudRate/flushTimer` 七字段 → `private ports = new Map<string, PortState>()`
- [electron/ipc/serial-handlers.ts](../../../../electron/ipc/serial-handlers.ts)——handle 透传 portName 参数
- [src/core/api/linkdesk-api.ts](../../../../src/core/api/linkdesk-api.ts)——serial 命名空间签名
- [src/core/types/ipc/serial.ts](../../../../src/core/types/ipc/serial.ts)——契约（#28 才动载荷，本任务先不动 wire 形状——只加 PortState 内部类型注释）

**设计要点：**
- PortState 六字段内聚——**flushTimer/isClosing/lineBuffer/encoding 必须每口独立**（否则 A 口关闭期间 B 口数据被 isClosing 丢弃 / A 口 100ms 冲刷计时器把 B 口残留提前冲刷）
- 读循环注册改用闭包捕获 PortState（现网 `this.port.on('data')` 读 this 字段——Map 化后每口读自己的 state）
- 删除 `openPort` 的 L109-111 先关旧口逻辑——多口并存
- ~15 处 `this.port` 引用机械替换（openPort/closePort/getStatus/onData/sendData/sendText/setDtr/setRts）
- **行为严格保持**：单口流程零变化（缺省唯一口语义 D2 覆盖旧调用路径）

### #27 状态查询与 Hot Exit 恢复

**改动文件：** serial-service.ts（getStatus 双形态）+ SerialContext.tsx（`_initOnce` 消费方）

**设计要点：**
- `getStatus()` 无参 → 遍历 Map 返回 `SerialStatus[]`；有参 → 单口快照
- SerialContext `_initOnce` 升级：数组遍历 → 按 portName merge 各口状态（侧栏绿灯按口亮——pluginState `_scopeKey` per-port 前缀 E5.5#9l 已就位，直接复用）
- F5 恢复流程：插件重启 → `_initOnce` 拿全口数组 → 每个标签页用自己会话口比对恢复

### #28 推送路由 portName 字段（wire 契约破坏性变更）

**改动文件：**
- [src/core/types/ipc/serial.ts](../../../../src/core/types/ipc/serial.ts)——`SerialDataPayload { portName, text }` / `SerialStatsPayload { portName, tx?, rx? }` / `SerialSystemPayload { portName, message }`；linkdesk.d.ts（Phase 4 契约生成就位后走生成流程）
- serial-handlers.ts——setCallbacks 三回调签名对象化；广播面走 Phase 1.5 broadcast 通道
- preload-pool / linkdesk-api.ts——onData/onStats/onSystem 签名
- [src/hooks/useIpcEvent.ts](../../../../src/hooks/useIpcEvent.ts)——映射表泛型改对象
- serial-monitor 插件（见 #29）

**设计要点：**
- 单端口兼容：portName 缺失时旧消费方行为不变（三态 isMyPort 容错已就位——index.tsx L532）
- **顺带删除字符串正则解析 hack**（index.tsx L526 正则挖端口名）→ 载荷 portName 字段——归一化（结构化数据不靠字符串解析）
- 契约同步走 Phase 4 生成流程（本任务在 Phase 4 之后执行，不是手改 linkdesk.d.ts）

### #29 插件会话-端口绑定

**改动文件：** serial-monitor 插件四件套（SerialContext.tsx / index.tsx / useSendData.ts / ControlPanel.tsx）+ useSerialSessions.ts

**设计要点：**
- 会话模型绑 portName 键（session ↔ portName——两个会话同时连 COM3+COM13）
- ControlPanel 按端口显状态（per-tab connected 决策——现网已按 per-tab 决策，升级数据源为端口级状态）
- useSendData 带 portName 调 sendData/sendText（缺省唯一口语义兜底旧调用）
- RingBuffer 按口过滤：每会话自有 ringBuffer（现网已 per-session）
- **修根①**：SerialContext `events.emit("serial:rawData", ...)` 的 sourceName 从 `_sharedState.sourceName`（错标风险）→ `payload.portName`（到达数据自带口名）
- **修根②**：index.tsx 系统消息正则 → payload.portName 精确比对

### #30 双端口实机冒烟 + 收口

- 双端口同时收发 + 断一个不影响另一个（COM3 拔线 COM13 数据不断）
- 单口场景回归无损（旧插件路径 D2 兜底）
- 回归矩阵场景 6（多会话）勾选
- 验收：用户实机验证双端口场景

## §5 破坏性变更窗口论证

**为什么现在做（E5.8）而不是 E6 之后：**

1. **上架前无第三方存量插件**——E6 才上架，serial 命名空间唯一生产消费方 = 仓库内 serial-monitor 插件 + serialHandlers.test.ts + useIpcEvent 映射表，三处同步升级一次性切干净
2. **不留兼容尾巴**——"旧 string 通道 + 新对象通道"双轨会留死代码（准则 4），契约生成（Phase 4）会把双轨抓出来当漂移
3. **Phase 4 契约生成先就位**——载荷形状变更在生成流程里走，不会手改漏一处

**升级路径（一次性切换，无过渡态）：** 服务层 Map 化（#26）→ 状态查询（#27）→ 契约 + 推送对象化 + 三处消费方同步（#28+#29）→ 实机（#30）。每任务独立 commit + `npm run check` 全绿。

## §6 风险与回归

| 风险 | 对策 |
|:--|:--|
| 每口独立计时器/标志漏迁（isClosing/flushTimer 共用 → 跨口数据丢/串） | #26 验收点：双口并发冲刷测试；PortState 六字段设计时即内聚 |
| 缺省"唯一口语义"在插件旧代码路径静默作用到错的口 | D2 决策：≥2 口时抛错而非静默——失败可见性（uninstall-bug-recurring 教训：错误静默是 bug 温床） |
| wire 对象化漏改某消费方（编译期抓不到——IPC 载荷是运行时） | 消费方清单 = 三处（SerialContext/index.tsx/useIpcEvent 映射表）+ 测试；#28 验收含 grep 旧签名清零 |
| 推送量 ×N（每口独立 100ms 冲刷 → IPC 量线性增长） | 多口场景本就不高频；16ms 批量推送注释现状已变 100ms——若双口实测 IPC 拥塞，冲刷计时器改共享队列（#30 实机判断，不预设） |
| Hot Exit 恢复顺序竞态（多口同时恢复） | #27 验收：COM3+COM13 F5 重启两状态各自恢复 |

**回归面：** 单口场景零变化（#26 验收）+ E5.7 场景 6 多会话回归（#29 验收）+ 双口实机（#30 验收）。

## §7 明确不做（边界）

- **多服务实例/多进程**——Map 化够了（E5.7 极简 Pool 原则：安全靠 preload 沙箱不靠进程数）
- **串口虚拟化/设备模拟层**——09-Serial-Simulator 插件自会做
- **PortInfo 缓存/热插拔事件推送**——listPorts 按需拉取现状不动（#0d 用户补充区若有需求另立案）
- **并发打开同一口的仲裁**——Map 天然拒绝（第二个 openPort 同口报错"端口已被占用"——serialport 库底层报错透传，不额外加锁）
