# 01 · 操作路径总览

> 读完这一页，你就知道「**有没有门、门在哪、怎么走、走完怎么证明走通了**」。
> 具体命令 id / 方法名 / 参数去 [02-命令与API索引](02-命令与API索引.md)；按任务找配方去 [03-按任务操作](03-按任务操作.md)。

## 一、三条门（从首选到兜底）

| 门 | 入口 | 覆盖什么 | 什么时候用 | 状态 |
|:--|:--|:--|:--|:--:|
| **① 命令面** | `linkdesk.commands.executeCommand("<id>", undefined, ...args)` | 用户**点得到的一切**：菜单项、右键菜单、命令面板、标题栏按钮 | **首选**——凡用户能做的，先来这里找 | ✅ 今天可用 |
| **② 契约 API** | `window.linkdesk.<命名空间>.<方法>()` | 命令没覆盖的**原语**：标签页、文件系统、串口、配置、主题、布局读取 | 命令找不到，或要**读状态**／要细粒度参数 | ✅ 今天可用 |
| **③ CLI / MCP** | `linkdeskctl …` / MCP `tools/list` | 软件**外部**进程（没有 Electron 上下文时的通道） | 你的 AI 客户端在软件外；或要暴露给别的 agent | ✅ 今天可用（设置页「AI 接入」一键开；见 [07 章](07-如何接入.md)） |

**这两条门不是两套系统**：命令**就是**调用 API 的那条路（命令 handler 内部调 API）。
所以你走门①时不是在「模拟用户」，而是在**走用户点的那条代码路径**——语义完全一致。
反过来，门②的部分命名空间（`tabs.list` / `pool.getLayout` / `notifications.list`）是**专为配合门①而造的读取面**：
它们不改变状态，只回答「现在是什么样」——即本轮操作的**前置条件**与**验收证据**。

## 二、池与壳——你要的东西在哪个进程

LinkDesk 是双进程：**壳**（Electron 主窗口的 React）＝ 显示真相源；**池**（WebView 里的插件运行时）＝ 执行真相源。

| 谁 | 管什么 | AI 从哪碰 |
|:--|:--|:--|
| **壳** | 布局/标签页真相（`useTabManager`）、通知中心、对话框、主题、设置、主进程 IPC | 壳 preload 的 `window.linkdesk`；命令系统就在壳里 |
| **池** | 跑插件代码、持有命令 handler（`_poolCommands`）、池内本地注册表（装饰/quickPick/menu） | 池 preload 的 `window.linkdesk`（＝ `@linkdesk/plugin-sdk` 那套面） |

🔴 **对 AI 最重要的一条**：命令的 **id / 标题 / when 门控**在壳侧注册表（显示面），
**handler** 在池侧（执行面）——两边靠 `registerCommand` 的桥接对齐。
所以你调命令不需要知道它在哪侧：**从任一侧的 `commands.executeCommand` 发出去都能到**。
（`getCommands()` 在池侧读到的就是**合并后的全量**，含宿主命令与各插件注册的命令。）

## 三、🔴 调命令的正确姿势（开头那个 `undefined` 不能省）

```js
// ✅ 宿主命令 / 任何命令——三参起手：id, token, ...真实参数
await linkdesk.commands.executeCommand("core.closeTab", undefined, { tabId: "tab-1" });

// ❌ 省掉 undefined ⇒ 参数整体左移一位，命令**静默不动作**（不报错，最难查的坑）
await linkdesk.commands.executeCommand("core.closeTab", { tabId: "tab-1" });
```

原因：命令的签名是 `executeCommand(id, token, ...args)`——`token` 是**插件身份令牌占位**，
壳侧靠它判「这条命令是谁发的」（权限/归属）。池侧 preload 会把它剥掉
（`electron/preload-pool/commands.ts`），但**位置必须占住**，否则真实参数被当成 token 吃掉。

- 传参方式：命令 `params` 里**逐个列出的**参数 ⇒ 依次平铺（见 [02 章](02-命令与API索引.md) §二「参数（调用实参）」列）。
- **插件命令**不校验 token，但为了同形一致**一律照样传 `undefined`**。
- 不确定有哪些命令 ⇒ `await linkdesk.commands.getCommands()`（运行时真源，永远比手册新）。
  ⚠️ **视图态命令**（插件在视图 `mount` 时才注册的那批）没开过视图就不在里面——插件内先 `tabs.create(pluginId)`；
  外面接进来的 AI 看 `describe` 的 `commandsPending`（已声明未注册 ＋ 该开哪个视图），`open-tab` 返回时命令面已落定。

## 四、一轮操作的形状：读 → 调 → 读

```
① 读现状   tabs.list() / pool.getLayout() / notifications.list() / configuration.get(…)
              ↓  据现状决定调什么（含参数里的 id：tabId、groupId、containerId…）
② 调命令   executeCommand("<id>", undefined, …)   或   linkdesk.<ns>.<method>(…)
              ↓
③ 读结果   再读一遍同一批读取面 —— **差异就是操作生效的证据**
```

**为什么必须有③**：命令**可能合法地什么都不做**（`when` 门控不满足 ⇒ 菜单里没这条，但 API 调它不报错；
或「已在该侧则无动作」这类幂等命令）。没有③，你只能声称「我调了」，不能声称「生效了」。
**③ 的读数要写进你的报告**——用户要的是「改成什么样了」，不是「我执行了什么」。

## 五、结构化操作 vs 视觉兜底

| | **结构化（本手册教的路）** | 视觉兜底（截图→找像素→点） |
|:--|:--|:--|
| 读状态 | 契约 API / 命令返回值（精确、带类型） | 看图猜，字小/滚动/遮挡即失败 |
| 定位目标 | 用 `id`（`tabId`/`viewId`/`containerId`），**唯一** | 猜坐标，窗口一动全废 |
| 操作 | `executeCommand` / API —— 精确到参数值 | 点、拖、滚——只能近似 |
| 证据 | 前后两次读取面的**结构化差异** | 「看起来变了」 |
| 速度/可重复 | 毫秒级、可脚本、可批量 | 每步一次截图，且不可重复 |

**视觉只在一种情况下允许兜底**：某插件视图**内部**的交互（例如画布上拖一根线）——
框架不知道它是什么，插件也没把它注册成命令。这时：
① 先确认「真的没有命令」（`getCommands()` 里搜该插件）；② 兜底时**明确标注这是兜底**，
不要把它说成结构化操作；③ 建议用户/插件作者把它注册成命令（[00 章](00-README.md) §一 边界 3）。

## 六、今天有什么可读（读取面清单）

| 想读什么 | 用哪个 | 返回什么 |
|:--|:--|:--|
| 有哪些命令（含插件命令 + 参数说明） | `linkdesk.commands.getCommands()` | 命令清单：`id`/`title`/`category`/`when`/`description`/`params` |
| 开着哪些标签页（全窗、含活跃位） | `linkdesk.tabs.list()` | `{ windows: [{ windowId, mode, ready, activeGroupId, root, groups }] }` |
| 当前窗的**布局树**（分屏结构） | `linkdesk.pool.getLayout()` | `{ root, groups }`——`root` 是分裂树（`type:"split"` 带 `direction`/`sizes`/`children`，叶子是 `groupId`） |
| 通知（含「按了会跑哪条命令」） | `linkdesk.notifications.list()` | `NotifLayout`：`unread` + 分组 + 每条 `{ message, timeLabel, sourceLabel, wake, ttl, persistent, actions[{label,command,args}] }` |
| 设置项的当前值 / 是否被改过 | `linkdesk.configuration.get(key)` / `inspectConfiguration` | 值 + 来源（默认/用户/主题覆盖） |
| 有哪些主题 / 当前主题 | `linkdesk.theme.getAvailable()` / `getCurrent` | 主题清单与当前生效项 |
| 侧栏/面板/视图容器结构 | `linkdesk.viewContainer.getViews()` / `getViewContainer(viewId)` | 容器与视图的公开字段 |
| 串口状态与端口 | `linkdesk.serial.listPorts()` / `getStatus()` | 端口清单 + 打开状态 |
| 工作区文件夹 | `linkdesk.workspace.getFolders()` / `getActive()` | 文件夹清单 + 活跃项 |

⚠️ 读取面**是池侧独有还是双端**见 [02 章](02-命令与API索引.md) §三（`⚠️`/`°` 标注）——用前判存在。
⚠️ 读不到的东西**不代表不存在**：先看 [05-够不着清单与安装版路径](05-够不着清单与安装版路径.md)，别去猜坐标。

## 七、验收纪律（AI 自检三条）

1. **不能只说「已执行」**——要读回来验，报告里给**读数**（「侧栏现在是右侧」「活动组是 `g-2`，里面有 3 条标签」）。
2. **调了没反应，先查两处**：[04 手势隐藏规则](04-手势隐藏规则.md)（屏幕上看得见 ≠ 门开着）与
   [05 够不着清单](05-够不着清单与安装版路径.md)（这一类从来就没有门）。
3. **别自造入口**——手册与 `getCommands()` 里没有的 id/方法，就是不存在的；不要凭「应该有这么个命令」去猜。
