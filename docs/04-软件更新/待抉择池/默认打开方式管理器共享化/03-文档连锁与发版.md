## 四、发版链与时序（2026-10-06 收窄后的授权边界）

**用户已授权（逐字要点）**：⛔ **软件本体不发版**（平时 dev 测、攒够更新点再请用户发——「软件本体发一次版 20 分钟多，太慢了」）；🟢 **npm 包 与 插件版照旧自主发**（7.1 原话：「我允许当即打包打版发货（npm 和插件市场）」；2026-10-06 复述：「其余的，插件仍旧继续按原本定的，该发版就发版」）；⛔ 仍归用户：**撤版**、**改写已发布 tag**。

| 序 | 物件 | 能否即刻做 | 依赖／注意 |
|:--:|:--|:--|:--|
| 1 | `@linkdesk/ui` minor+1 → npm 发 | 🟢 即刻 | `check-npm-release` ＋ `release:mark`；推必带代理 `127.0.0.1:7890` |
| 2 | settings 插件 minor+1 → build → **打包／发版** | 🟢 即刻 | 插件仓自己的 SDK CLI；CHANGELOG 用户面文案同笔 |
| 3 | 壳侧改动（摘 hint／注释／新共享件／PluginCard 槽） | ⛔ **随壳攒批** | dev 验收、攒够再请用户发；其间「settings 新版 × 旧壳」实机跑一遍为验收关（[04 §风险](04-任务清单.md)） |
| 4 | **官方目录收录（＝上架）/ `sync:bundled --latest`** | 🟢 即刻 ｜⚠️ **看黄灯** | 新导出 ⇒ `minAppVersion` 地板随 `ui-surface.json` 的 `since` 抬高；**地板 > 最新已发布壳** ⇒ `check-plugin-shell-ahead` 黄灯——黄灯出现必须**报出来人工确认**（⛔ 不许静默）；本案这类「地板 > 已发布壳」**只在我们手上有未发布壳源码时才出现**（C6） |

✅ **C6 已定（2026-10-06 用户拍板，原话）**：「**先 dev 测，不发版，这种状况是我们既有壳源码才会遇到的情况，我只用 dev 测，好了再发版再说**」＋「**其余的，插件仍旧继续按原本定的，该发版就发版**」⇒ ① **壳体**：dev 测、⛔ 不单独发版（随攒批，发壳时点归用户）；② **插件与 npm 包照原定自主发**——该发版就发版（7.1 授权不变），只是上架前看黄灯；③「插件地板 > 已发布壳」**只在我们手上有未发布的 dev 壳时才会遇到** ⇒ 不是用户面风险，但黄灯仍须报出来；⛔ 不可取：settings 留自绘本体等壳（两份实现，犯硬约束 28／R4）。
