# 许可证方案待选（LICENSE 文件 + 帮助菜单「查看许可证」）

> 🔵 **2026-09-12 立案（用户口头裁决，见 `E6-执行清单.md` 的 `#57.10e`，不新增计数）。**
> 用户原话：**「关于 LICENSE 文件，这个到时候你推荐出来，让我选择，当然，那时候的推荐自然也是有任务的。」**
> ⇒ **推荐归 AI，选择归用户**。本档案是这条任务的要求书；**开工前先读完**。

---

## 一、现状（2026-09-12 实测，不是推测）

| 事实 | 证据 |
|:--|:--|
| **仓库根没有 `LICENSE` 文件** | `ls` 实测无此文件（`package.json` 也无 `license` 字段） |
| 帮助菜单**没有**「查看许可证」项 | `#57.10b` 实况——`helpLegal` 组是**预留锚点**，空的 |
| 全仓**没有**许可证相关命令 | 无 `app.viewLicense` 之类的 id |

⇒ 所以这条任务不是「把已有的许可证挂到菜单上」，而是**从零决定**：

1. 用什么许可证（**技术 + 产品决策**）；
2. 加 `LICENSE` 文件（**法律文件落地**）；
3. 帮助菜单怎么让人看到它（**UI + 呈现面**）。

---

## 二、为什么不能直接抄一个

LinkDesk 的产品定位是**「通用容器 + 万物皆插件」**——这决定了三件事同时要成立：

| 诉求 | 含义 | 对许可证的约束 |
|:--|:--|:--|
| **第三方作者敢写插件** | 别人要基于我们的 API 做东西、卖东西 | 不能是阻碍商业插件的条款（GPL 系在这里代价极高） |
| **软件本身能分发** | 要能随安装包发出去、可能上架 | 不能与 Electron/Chromium 等既有依赖的许可冲突 |
| **厂商想保留空间** | 未来可能有商业版/企业版 | 纯 copyleft 会把这条路堵死 |

⇒ **三个诉求交集的最小集大致指向 MIT / Apache-2.0 / 双许可（如 MIT + 商业授权）这一带**——
但**具体选哪个、要不要加商标条款、插件与壳的许可关系怎么划**，是本任务要逐条答的，
**不在本档案里预先拍板**（那是推荐环节的输出，要摆理由和取舍给用户）。

## 三、开工后的四步链（顺序不许换）

| 步 | 做什么 | 谁做 | 产出 |
|:--:|:--|:--|:--|
| **①** | 出**推荐表**：2-3 个方案，逐个写「是什么 / 为什么适合 LinkDesk 的三诉求 / 代价是什么 / 别人怎么做（VS Code 等先例）」 | **AI** | 一页推荐表 |
| **②** | **选** | **用户**（🔴 不许替选，也不许「推荐即默认」直接落地） | 一句裁决 |
| **③** | 仓库根加 `LICENSE` + `package.json` 的 `license` 字段 | AI | 文件落地 |
| **④** | 帮助菜单 `helpLegal` 组声明「查看许可证」+ 命令 | AI | 菜单项 + 命令 |

### ③ 的细节要求

- **`LICENSE` 放仓库根**（业界惯例，工具链到处都在找这个路径）；文件名**全大写无扩展名**。
- 全文**逐字照抄**官方文本（含版权行年份与持有者）——**不许改写、不许节译**。
- `package.json` 的 `license` 字段用 **SPDX 标识符**（如 `MIT` / `Apache-2.0`），不是文件名。
- 若走**双许可**，`LICENSE` 之外的第二份要另起文件名并互相引用（当场定，写进本档案）。
- ⚠️ **`LICENSE` 进包**：确认打包配置把它带上（`check-packaging-files.mjs` 是既有门禁，
  新文件是否需登记以该脚本实读为准，别凭印象）。

### ④ 的细节要求

- 菜单项归 `helpLegal` 组（与「隐私政策」同组——**两个法律文本放一起**是从一开始就定好的落位，
  见 `#57.10b` 的分组锚点表）。
- **呈现面当场讨论**（命令行内标签页读全文？还是交给系统浏览器打开一个 URL？）——
  这一条与 [`发行后-帮助菜单待补项.md`](发行后-帮助菜单待补项.md) §二-5 是同一个问题，
  **两边结论必须一致**（不许一个内嵌一个外链）。
- **判据（可证伪）**：① 帮助菜单第一组之后的 `helpLegal` 组里出现「查看许可证」，
  与相邻组之间**有**分隔线；② 点击能读到**完整**许可全文（不是摘要）；③ 非壳环境（无 preload）
  点了不崩。

## 四、明确不做（本任务边界）

- ❌ **不替用户选**（用户原话就是「让我选择」）；
- ❌ **不动第三方插件的许可**——插件作者用什么许可是作者的事，本任务只管**壳自己**；
- ❌ **不动 `@linkdesk/contracts` / `plugin-sdk` 的 npm 包许可**——那是**另一条轴**
  （作者轴，见 [`.claude/skills/version-bump/SKILL.md`](../../../.claude/skills/version-bump/SKILL.md) §〇 多轴模型）。
  若两者要统一，**单开一条任务**，不许在本任务里顺手改（会绕开各自的发布检测）。
