### 6.11 缺陷：快捷键齿轮「未在池内注册」根因与修复（2026-11-25）

**症状**：快捷键页齿轮的「清空快捷键 / 重置为默认」报 `命令 "settings.keybinding.clear" 未在池内注册`；已绑的键清不掉。

**根因（结构性，不是设置插件写错）**：
1. **入口副作用被误记成视图作用域**：池 preload 用「当前视图上下文栈顶」判定注册作用域。设置插件入口的六条齿轮命令**只在 entry 顶层注册**；当 entry 是在某个视图挂载期间被 **on-command 激活** import 时，六条被记成 `view:<实例>`。该视图一卸载（切页/关页/弹窗重挂），`leaveViewContext` 把它们整批摘掉；而 ESM 模块缓存让 entry **不会二次执行** ⇒ 之后齿轮菜单永远 miss。
2. **SDK 打包未改写 dist manifest 的 `entry`（独立缺陷，⛔ 不是本 bug 根因）**：包内 `plugin.json.entry` 仍是源码路径 `src/index.tsx`（实际入口 = `index.bundle.js`）。壳的 `resolveEntry` 有 bundle 兜底（故 LinkDesk 本身能跑），但按 manifest.entry 取入口的第三方宿主/读者会 404；且没有门禁在打包时拦截。**更正**：§6.11 初稿曾把「未在池内注册」归因于此，实为第 1 条的命令作用域/ESM 缓存；清单改写只是包内自描述正确性。
3. **缺打包期断言**：dist `entry` 指向包内不存在的文件也能出包。

**修复**：
- 池 preload：`import` **入口**前后压/弹 `_entryImportDepth`（`commands.ts`），期间注册一律 `plugin` 作用域；`PluginComponent` 的入口 import（含 on-command 激活）走 `importEntry()` 包裹。视图 import 语义不变（仍随实例卸载清理）。
- SDK：`rewriteDistManifest` 同笔把 `entry` 改写为编译产物；打包末尾断言 dist `entry` 必须在包内（缺文件当场红）。
- 回归测试：`commands.test.ts` 两条——「视图内激活入口 → 命令为 plugin 作用域，卸载后仍可执行」＋对照「普通视图注册仍随卸载清理」。

**用户侧恢复**：更新壳后重启一次（或池重载）让 entry 重新执行；之后齿轮的「清空/重置」即可正常用。

### 6.12 同类回归：S4 作用域分区导致「声明的命令在视图卸载后丢失」（2026-11-25）

**证据**：`_activationStack` / `view:<实例>` 作用域机制由 `726483063 feat: AI 门外契约面补齐（S1–S7/D1/D2）与壳 0.2.65 发版` 引入。它按 import 时的视图栈顶判定命令作用域，导致「清单 `contributes.commands[]` 声明过的公共命令」若首个注册发生在某个视图挂载期间（市场把注册放在首个被 import 的池面模块、设置齿轮命令经 on-command 激活导入），会被记成 `view:*`；视图一卸载即整批摘除，模块缓存又让 entry 不再执行 ⇒ 图标/齿轮报「未在池内注册」（用户实机：快捷键齿轮清空/重置、点市场图标开商店）。重启恢复 = 重新 import entry。

**第二层修复（与 §6.11 同笔）**：声明面命令 = 插件级，与 import 上下文解耦——
- 预取壳注册表 `placeholder:true` 的 id 集合（`ensureDeclaredCommands`）；
- `leaveViewContext`：声明面命令**提升**为 `plugin`，不随视图删；
- `registerCommand`：`view → plugin` 视为提升（入口级注册权威），反向仍保留插件级；
- 回归测试 +3（声明命令卸载后仍可执行 / 私有命令照旧清理 / view→plugin 重注册提升）。

### 6.13 快捷键「真实键盘录不上」：夹具用错壳侧专属 API（2026-11-25 收尾）

**结论**：壳的录制链没坏；坏的是**零 UI 夹具**。夹具录制 `if (!kb?.onForwardedEvent) return;`——而 `onForwardedEvent` 在契约里明示 **shell-side only**，池 preload 不注入（`KeybindingsAPI` 注释），于是整个录制 effect 静默退出，真实键盘按什么键都没反应。官方设置页走的是本地 `window.addEventListener("keydown", …, true)` ＋ `setKeybindingCaptureActive(true)`（主进程直通放行），与夹具是两条链。

**修复**：
- 夹具录制改为与官方同款：本地 keydown（capture）收键 → `keyboardEventToKeyString` → `remove`/`register`/`save`；只用池内存在的 API。
- `test:replaceability` 新增结构硬检：夹具源码出现 `onForwardedEvent` / `syncToMainProcess` 即红（负控已覆盖）——防止「第二个作者照壳侧示例写、装进池静默失效」再发生。
- SDK `rewriteDistManifest` 修正：入口与视图共用同一源文件时（夹具 `entry`/`render` 同指 `index.tsx`），`entry` 曾被 rel 映射覆盖成 `views/index_.bundle.js`（视图 shim）；改为单独传 `entryFinal`，入口恒 `index.bundle.js`。

**实机复测（隔离实例 0.2.66 · 夹具为 settings 套）**：快捷键页 163 行 → 首行点「录制」→ `AppActivate` 聚焦本实例 → OS 级 `SendKeys('^k')` → 行绑定变为 `ctrl+k`，按钮回到「录制」。`ctrl+k` 是内置 chord 前缀，若主进程直通没生效会被吞掉——因此这条也反证了直通链正常。

**读账**：`npm run check` exit 0（320 文件 / 4269 例）；`test:replaceability --self-test` 正控＋三条负控全过。
