# 04 — 插件分发格式

> 2026-07-24 · E5.8 全量更新 2026-08-21。**插件怎么交付、怎么安装、版本兼容规则。** 对标 VS Code 的扩展——但 LinkDesk 用**目录分发**，没有 VSIX 式单一文件。

---

## 一、分发格式——就是一个目录

**LinkDesk 的插件就是一个普通目录。** 不需要打包成 zip / `.linkdesk` 单一文件——`plugin.json` + 源码 + 资源，整目录复制即安装。

```
my-plugin/
├── plugin.json          ← 必需（清单——名字/入口/贡献点全在这里）
├── src/
│   └── index.tsx        ← entry 指向的入口组件（源文件路径）
├── resources/           ← 可选（图标/图片/字体，走 getAssetPath——§五）
└── __tests__/           ← 可选（插件层测试约定）
```

**为什么是目录不是单一文件：** 插件和壳在同一个 Pool 渲染进程跑，入口组件经 Vite 编译成 JS chunk——dev 由 `/@fs/{绝对路径}` 即时编译，prod 由 `linkdesk://{pluginId}` 协议解析预构建 chunk（§二）。单一 zip 文件没有"代码被 Vite 编译"的路径。

> **目录结构细节**（`resources/`/`dist/`/`src/utils/` 的准入与语义）见 [09-插件目录规范](09-插件目录规范.md)。**插件源码目录不产生 `dist/`**——构建时 Vite 把每个插件打成独立 chunk 到应用根 `dist/plugins/<sub>/<id>.js`，插件作者不用关心构建产物。

**目录分类（放在 `plugins/` 下的位置决定身份）：**

| 目录 | 身份 | 谁放 |
|------|------|------|
| `plugins/builtin/<id>/` | 内置插件（随应用分发，`core: true` 不可卸载） | 壳作者 |
| `plugins/user/<id>/` | 用户安装的第三方插件 | 安装流程写入（§二） |
| `plugins/.disabled/<id>/` | 已卸载插件（**可恢复**） | 卸载流程移入（§二） |

> `builtin/` + `user/` 是构建期 `import.meta.glob` 静态扫描范围（`src/core/utils/plugin/pluginPaths.ts` `PLUGIN_SUBDIRS`）——这是打包范围，**不是运行期白名单**（主进程 `scanPluginSubdirs` 扫全部子目录）。`core: true` 插件不可禁用/卸载；用户插件可卸载。

**开发阶段：** 把插件目录放进 `plugins/user/<id>/` → `npm run dev` → HMR 即时热更新。改 `plugins/builtin/<id>/` 的代码同理。

**内置插件清单（2026-08-21 实况）：** `plugins/builtin/` 现有 `editor/` `file-tree/` `marketplace/` `settings/` 四个；`plugins/user/` 有 `serial-monitor/` `panel-demo/` `theme-defaults/` `lang-defaults/` `python/` 等出厂示例（第三方可仿照 `panel-demo/` 起步）。

## 二、安装流程——目录复制

**入口：** 插件市场「安装」按钮 → 壳 `installPlugin(sourcePath)` 把**已经就位的目录**复制进 `plugins/user/<pluginId>/`。**没有 zip 解压、没有 SHA256 校验、没有拖放安装。** 第三方交付目录，壳复制 + 校验 + 热加载：

```
installPlugin(sourcePath)                    // sourcePath = 插件目录
  │  ① 前置校验（复制前失败——不产生半装目录）
  │     - plugin.json 存在 + JSON 可解析
  │     - validateInstallManifest：pluginId 合法（manifest.pluginId 优先，
  │       缺省回退源目录名；须过 SAFE_PLUGIN_ID /^[A-Za-z0-9][A-Za-z0-9._-]*$/）
  │       + version 必填
  │     - E5.7#81 版本冲突：目标 plugins/user/<id> 已存在 → 读盘比对
  │       同版/旧版 → 拒绝（报双方版本号）；新版 → 提示先卸载再装
  │       （Windows 文件锁，不覆盖安装）
  ▼
  ② 目录复制 → plugins/user/<pluginId>/
  ▼
  ③ 消毒 manifest → distribution=user, core=false 落盘
  ▼
  ④ notifyManifestChanged() → 主进程重扫 langDefs/fileAssociations 三表
  ▼
  ⑤ loadPlugin(pluginId, "install") 热加载
     theme/language 插件即时生效；视图插件 → toast「运行 npm run build 后生效」+ 重启按钮
```

**字段强制检查现状（诚实标注）：**

| 字段 | schema 已声明？ | 安装期强制？ |
|------|:--:|:--:|
| `pluginId` | ✅ | ✅（SAFE_PLUGIN_ID 校验 + 版本冲突裁决） |
| `version` | ✅ | ✅（必填 + resolveVersionConflict） |
| `minAppVersion` | ✅ | ⏳ **未强制**——声明即文档，校验归 E6 |
| `requires` | ✅ | ⏳ 安装期不拦截——**运行期依赖编排**生效（缺依赖挂起 PENDING + 环 fail-loud，见 [02 §四](02-插件生命周期.md)） |
| `permissions` | ✅ | ⏳ **未强制**——声明即用户知情，授权模型归 E6 |

## 三、目录约定

### 插件安装目录（随应用分发 / 用户安装）

| 位置 | 用途 | 读写 |
|------|------|:--:|
| `plugins/builtin/<id>/` | 内置插件（打包到应用资源目录） | 只读 |
| `plugins/user/<id>/` | 用户安装的第三方插件 | 只读（安装流程写） |
| `plugins/.disabled/<id>/` | 已卸载插件——**可一键恢复** | 只读 |

> **可卸载 ⇒ 可重装（E5.7 生命周期契约）：** 卸载 = `copy(源 → .disabled/<id>)` + `remove(源)`——**先复制后删除**（Windows 跨目录 rename 因文件锁失败，教训 commit `aec1564`）。重装 = 反向移回 `user/<id>` → `loadPlugin` 热加载。**任何能被卸载的插件，重装必须同 session 恢复全部贡献**（视图/命令/菜单/主题/语言，与插件形状无关）——详见 [02 §九.6](02-插件生命周期.md)。

### 插件数据目录（`window.linkdesk.env.get`）

| 路径 | 用途 |
|------|------|
| `<userData>/linkdesk/plugins/<id>/data/` | 插件持久化数据——**唯一可写目录** |
| `<userData>/linkdesk/plugins/<id>/data/cache/` | 缓存（可安全删除） |
| `<userData>/linkdesk/plugins/<id>/data/exports/` | 导出文件（用户可见） |

```typescript
// 插件作者把自己的 pluginId 传给 env.get——主进程按 id 解析数据目录
const env = await window.linkdesk.env.get("my-plugin");
const myDataDir = env.pluginDataDir;    // <userData>/linkdesk/plugins/my-plugin/data/
```

> `<userData>` = Electron `app.getPath('userData')`（Windows `%APPDATA%/<AppName>`）。**源码目录（`appPluginsDir`）与数据目录（`pluginsRootDir`）是两棵树**——源码随应用分发/用户安装，数据在用户数据区（卸载重装**不清数据**）。壳在插件安装时自动 `ensurePluginDataDir` 建目录，插件无需自建。

### 壳数据目录

| 位置 | 用途 |
|------|------|
| `<userData>/linkdesk/settings.json` | 全局设置 |
| `<userData>/linkdesk/` 其余 | 布局/插件状态/Profile 等壳持久化（插件不要写这里） |

## 四、版本兼容

### 语义化版本

`version` 遵循 semver（`major.minor.patch`）。版本处理**只在安装时生效**（E5.7#81 `resolveVersionConflict`）：目标已存在 → 同版/旧版拒绝并给出双方版本号；新版提示先卸载再装。**没有覆盖安装**（Windows 文件锁）——真升级流程归 E6 `PluginUpdateService`。

### 🔥 内容变更必 bump 自身 version（2026-09-06 #15n 定案）

**分发过的插件，任何内容变更（代码 / 资源 / README / CHANGELOG）都必须 bump `plugin.json.version`。** 已装用户的副本是**按版本固化**的——boot 只补缺失、永不刷新已装（同版异版都不覆盖，见 memory `bundled-same-version-no-refresh`）；用户拿到新内容的唯一路 = **版本号**（更新按 `semver.gt` 发现新版）。改内容不 bump = 已装用户永远滞留在旧内容（2026-09-06 实证：bundled 发货 zip 加了 pyright 没 bump → 已装副本 LSP 全挂）。

**随壳分发的 bundled zip 同理**：重打 `bundled-plugins/*.linkdesk-plugin` 时内容变更必 bump 插件自身 version——`npm run check` 的打包 gate 会在「同版内容 diff」时红拦（`scripts/check-bundled-version-bump.mjs`，E6#15n）。已装用户拿 bundled 内容修复 = 走市场真实条目（E6#26b）按版本发现/更新，**boot 不伸手**（bundled 夹 = 首启离线种子，非更新通道）。

### minAppVersion / requires / permissions

```json
{
  "minAppVersion": "1.2.0",
  "requires": ["serial-monitor"],
  "permissions": ["filesystem"]
}
```

三者 schema 均已声明（见 [03-contributes](03-插件contributes规范.md)），但**安装期均未强制**（归 E6）：

- `minAppVersion` —— 当前不校验，声明即文档
- `requires` —— **运行期依赖编排**已经生效（缺依赖挂起 PENDING + 环 fail-loud + 连带卸载逆拓扑，见 [02 §四](02-插件生命周期.md)），只是安装阶段不拦截
- `permissions` —— 授权模型归 E6。当前插件与壳同池运行，写操作全走 `window.linkdesk.*` 桥（filesystem guard 守卫数据根，见 memory `guard-api-contract-alignment`），无安装弹窗

## 五、资源路径——getAssetPath（硬约束 12）

**🔥 禁止硬编码路径。** 插件内引用图标/图片/字体/任何资产，一律走 `getAssetPath()`（`src/core/utils/path/assetPath.ts`）——返回 `${BASE}${relativePath}`，兼容 dev `http://localhost:1420` 与打包后 `file://`。

```tsx
// ✅ 正确——资产经 BASE 前缀解析
import { getAssetPath } from "@src/core/utils/path/assetPath";
const logo = getAssetPath("plugins/builtin/my-plugin/resources/logo.png");
// <img src={logo} />

// ❌ 错误——打包后 file:// 协议下绝对路径解析炸裂
// const logo = "/assets/logo.png";
```

> **dev 能跑是巧合**（http 服务把相对路径兜住了），打包后 `file://` 才现形。插件自定义图标同理——`icon` 字段路径经 `resolvePluginIcon` 内置走此路（见 [09 §图标位置](09-插件目录规范.md)）。

## 六、插件市场协议（未实现——归 E6）

**远程插件市场（registry 拉取 + 下载安装）尚未实现。** 当前 `plugins/builtin/marketplace/` 是**本地市场**——浏览本地已安装 / 已禁用 / 已卸载（`.disabled/` 扫描）插件，不涉及远程分发。

以下均为**未实现**（归 E6 上架任务，勿照此写代码）：

- ❌ 远程 registry.json 协议
- ❌ `.linkdesk` 单一文件格式
- ❌ 下载 + SHA256 校验
- ❌ 插件脚手架 `create-linkdesk-plugin`（E6 交付）

## 七、开发→分发全流程

```
1. 开发
   mkdir plugins/user/my-plugin
   写 plugin.json + src/index.tsx
   → npm run dev → 源码树运行 → HMR 即时热更新

2. 构建（第三方发布前）
   npm run build          ← 主 vite.config 多入口——dist/plugins/<sub>/<id>.js
   → 插件 entry 编译为独立 chunk

3. 分发
   交付目录 = plugins/user/my-plugin/ 整目录（不打包单一文件）
   → 上架（放入应用 plugins/user/）+ 重启 / 或走安装流程（§二）

4. 安装
   壳 installPlugin(sourcePath) → 前置校验 → 复制 → 消毒 → 热加载（§二）
```

**「构建」边界：** 开发期 `npm run dev` 下 Vite 即时编译源码，**无需先构建**。`npm run build` 产生的是安装后视图插件生效所需的预构建 chunk（安装 toast 提示「运行 npm run build 后生效」）。**纯 theme/language 插件无需构建**，复制即生效（`loadPlugin` 即时注册）。

## 八、与 VS Code 对照

| LinkDesk | VS Code |
|------|------|
| 目录复制安装（无单一文件） | `.vsix` 单一文件（下载/解压到扩展目录） |
| `plugins/user/<id>/` 安装目录 | `~/.vscode/extensions/<id>/` |
| `plugins/builtin/<id>/` 内置 | `builtin/` 内置扩展 |
| `plugins/.disabled/<id>/` 已卸载可恢复 | 卸载 = 删文件（不可恢复） |
| `env.pluginDataDir`（`env.get(id)`） | `ExtensionContext.storagePath` |
| `getAssetPath()` 资产解析 | `context.extensionUri` 相对路径 |
| `requires` **运行期**依赖编排（[02 §四](02-插件生命周期.md)） | `extensionDependencies` 安装期解析 |
| `minAppVersion` schema 声明未强制 | `engines.vscode` 安装期强制 |
