## 〇、设计原则（2026-08-30 用户拍板）

**更新通知/进度/交互全部复用壳已有 toast 系统，不新建任何 UI 表面。** 参照先例：03-插件市场 详情页「事件型提示一律走 toast」（用户拍板：顶部横幅把整个 UI 往下推 + 影响性能，一律 toast 化）——更新通知同款。

> 🔴 **2026-09-10 载体修正（E6#72 通知面归一）**：本档初稿写的「右下角窄小卡」**已不存在**——E6#72a 把 `ToastHost.tsx/.css` 整删，**通知只有一处面**：**铃铛宽面板**（`StatusBarZone`，[17 档案](../03-插件市场/17-通知面归一任务档案.md) / 记忆 `notification-surface-single-panel`）。下文凡「右下角 / `#toast-root` / 折叠展开」的表述一律按本节读：**条目进面板、恒全显、可拖选复制**。**不再有第二个浮层，也不再有「面板开着时压住 toast」这回事**。

> **与 TitleBar 更新按钮的分工（2026-08-30 拍板，色彩反转最终态）**：通知面条目承载**静默信息**（发现/进度/完成/失败/手动结果）；TitleBar 更新按钮承载**可见存在**（有更新才现、全文字 + 主题按钮色，03 §四）。按钮只演进「下载更新 → 更新中 → 重新启动」三态文字（03 §4.3），**不显示进度细节**——点了按钮，进度才走通知面出来。两者互补不重复。

> 📐🔴 **验收图（2026-09-11 挂上）**：[mockups/02-更新通知与关于.html](mockups/02-更新通知与关于.html)——**Frame 0** 两条路完整流程 / **Frame 1** 发现 / **Frame 2** 下载进度（4px 真条）/ **Frame 3** 完成重启 / **Frame 4** 手动无更新 / **Frame 5** 失败 + `[重试]` / **Frame 6** 关于页。**本档 §二-§五 每一节都对应一帧，实现时逐帧对。** 旧稿 `02-更新通知toast与关于.html`（右下小卡 + 默认折叠 + 无进度条）**已于 2026-09-11 作废删除**。

> 🔴 **多窗口规则（2026-09-11 补——本档写于多窗口之前）**：**通知面只在主窗口有**（定案见 [03-插件市场/18-通知系统全账与设计定案.md](../03-插件市场/18-通知系统全账与设计定案.md) §八㉚）。⇒ 开 N 个文件夹窗口时，**同一个更新只出 1 条条目**（主窗口面板），副窗口铃铛零未读；`update.getState` 广播是全局的、**弹条目不是**。配套的「谁是调度者」见 [01 档 §2.2 / 清单 #57.9f](01-更新机制设计.md)。

## 一、触发时机（何时弹 toast）

| 场景 | 行为 |
|:--|:--|
| 后台发现更新（周期/启动） | 弹发现更新 toast（§二） |
| 下载中 | 更新该 toast 消息为进度（§三） |
| 下载完成 | 更新为「重启」toast（§四） |
| 用户点「立即更新/重启并更新」 | 对应 toast 按钮触发（§二/§四） |
| 用户点 TitleBar 更新按钮 | `update.openUpdateFlow` 按状态分支（available→下载 / downloaded→重启）→ 进度走 toast（03 §4.3 三态：下载更新 → 更新中 → 重新启动，主题按钮色） |
| 手动检查无更新 | toast「当前已是最新版本」 |
| 检查/下载失败 | toast 错误（TOAST_TTL_ERROR） |

## 二、发现更新 toast

**恒全显**（🔴 2026-09-10 修正：初稿写的「默认折叠、点 ⋁ 展开」**已随 `ToastHost` 一起作废**——E6#71h 定案「两态删除、恒全显」，消息与 actions 常驻，用户不必先找展开箭头）：

```
┌──────────────────────────────────────────────┐
│ (⬇图标) LinkDesk 有可用的更新 0.2.0       ✕   │   ← 主行：icon 16px + message
│  来源: 主软件更新    [查看更新内容] [立即更新] │   ← 来源行 + actions（常驻，不再折叠）
└──────────────────────────────────────────────┘
  （通知面板内；面板只此一处，无第二个浮层）
```

**调用：**
```typescript
pushToast({
  message: i18n.t("LinkDesk 有可用的更新 {{version}}", { version: "0.2.0" }),
  severity: "info",
  source: "app.update",   // 生产者身份 id（壳域 app. 前缀，app = 既有 APP_PLUGIN_ID）；人类可读名「主软件更新」不写进 source，由通知面按来源名机制解析（见 E6#73g）
  isCloseAffordance: true,   // 用户点 × → 该版本更新提示不再弹（Don't show again，现成机制）
  actions: [
    { label: i18n.t("查看更新内容"), isPrimary: false, onClick: () => openReleaseNotes("0.2.0") },
    { label: i18n.t("立即更新"), isPrimary: true, onClick: () => downloadUpdate() },
  ],
  ttl: 0,                     // 持久——直到用户选择/下载开始；或长 ttl（TOAST_TTL_INFO）
});
```

**「稍后」语义（用户权利保障）：**
- 点 × 关闭 → `isCloseAffordance` 持久化 → 该版本更新提示不再自动弹（用户想查 → 菜单「检查更新…」手动，恒显）。
- 这就是「用户有权一段时间不更新」的实现——**自动弹一次，尊重关闭，手动入口永在**。
- 想要彻底安静：设置 `app.update.mode = manual`（不自动检查，手动才查）。

## 三、下载进度（updateToast 循环改文字）

```
┌──────────────────────────────────────────────┐
│ (⬇图标) 正在下载更新 42%                  ✕   │   ← 主行 message 循环更新（updateToast）
│  ▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░  42%                │   ← 4px 真进度条（updateToast 第三参 percent）
│  来源: 主软件更新                 [后台运行]   │   ← 「后台运行」= 关面板，进度进通知中心
└──────────────────────────────────────────────┘
```

**调用（真进度条能力已于 E6#71i 落地）：**
```typescript
const id = pushToast({
  source: "app.update",   // 生产者身份 id（同 §二）
  message: i18n.t("正在下载更新 0%"),
  ttl: 0,                       // 持久——直到下载结束
});
// 下载进度事件 → 节流 ≤500ms 更新文字 + 唯一真值来源的百分比
onProgress((p) => updateToast(id, i18n.t("正在下载更新 {{percent}}%", { percent: p.percent }), p.percent));
```

> **进度条 UI 已实现，不再「留未来」**：`updateToast(id, message, percent?)` 的第三参非空时，通知面板画 **4px 真进度条**（确定态按 percent 填充 / 不定态扫动）——E6#71i 落地、E6#72c 在宽面板上定型、**E6#73k 由 3px 加粗到 4px**。本档直接用它，**不新造任何进度 UI**。
> 🔴 **阶段切换必须显式传 `percent: undefined`**（进「校验/解压」这种无百分数的段）——**留着上一段的 42% 不动会被读成卡死**（01 §2.4 同款约定）。

## 四、下载完成 / 重启

```
┌──────────────────────────────────────────────┐
│ (⬇图标) 更新已下载，重启后生效            ✕   │
│  来源: 主软件更新         [稍后] [重启并更新] │
└──────────────────────────────────────────────┘
```

**调用：**
```typescript
updateToast(id, i18n.t("更新已下载，重启后生效"));
// 或 pushToast 新 toast：
pushToast({
  message: i18n.t("更新已下载，重启后生效"),
  source: "app.update",   // 生产者身份 id（同 §二，来源行靠它渲染）
  actions: [
    { label: i18n.t("稍后"), isPrimary: false, onClick: () => {/* 关 toast，状态回 idle，不重下 */} },
    { label: i18n.t("重启并更新"), isPrimary: true, onClick: () => restartToUpdate() },
  ],
  ttl: 0,
});
```

**重启流程（无新 UI——toast 直驱）：**
1. 点「重启并更新」→ `restartToUpdate()` → 主进程 `quitAndInstall()`。
2. 主进程 `app.relaunch` + `app.quit()` → 安装器静默覆盖 → 重启。
3. **无 3s 倒计时弹窗**（那是新造 UI）——toast 点击即执行；误点风险低（「重启并更新」是主按钮，用户主动点）。
4. 重启后首启自动弹发行说明（05 §2.5）。

## 六、与通知中心的关系

- 所有更新条目自动进通知面板（铃铛未读数）——用户关掉某条后仍可在面板回看「有可用更新/正在下载/重启」。
- 🔴 **修正（2026-09-10）**：初稿写的「中心打开时 toast 被 suppress（`setToastsSuppressed`）」**已不存在**——该函数随 E6#72a 整删（面板就是唯一通知面，没有第二个浮层可压）。现行规则只有一条：**面板开着时新条目即时标已读**（归属 E6#73g）；「面板开合镜像」`setNotifPanelOpen` 保留，但语义只剩「面板已开 ⇒ `autoOpen` 不再重复请求展开」。
