## 〇 一页看完（甲方视角，只看这节也够）

1. **齿轮里现在本来就有东西。** 每一行右上角那个齿轮（鼠标移上去才显形）里，**所有行**都自动带着壳给的通用项：「重置此设置」「复制设置 ID」「复制为 JSON」；外观那几行还多一项「打开存储位置」。我们要加的，是**只属于存储三行的专用项**。

## 二、「存储」三行齿轮 —— 逐行定稿草案

> 三行的身份（真名以落代码为准，这里用 06 图的名字）：
> 行1 `app.storage.cacheDir`（缓存位置，输入框＋选文件夹）· 行2 `app.storage.used`（已用空间，只读）· 行3 `app.storage.clear`（清除缓存，按钮）。

### 2.0 先说一个前提：齿轮里已经躺着一批通用项

用户看到的那一格里，**不是只有我们放的东西**。以「缓存位置」行为例，真机上它会是这样（分三组、组间有分隔线）：

| 组 | 菜单项 | 谁放的 | 什么时候出现 |
|:--|:--|:--|:--|
| navigation | 重置此设置 | 壳（通用，所有行） | 这一行被改过时（`settingModified`） |
| navigation | 复制设置 ID / 复制为 JSON | 壳（通用，所有行） | **恒有** |
| （新组） | 打开缓存目录 / 复制路径 /（可能还有）恢复默认位置 | **本件新增** | 见下表 |

⇒ **所以"给齿轮加东西"的完整效果 = 通用项 ＋ 我们的专用项。** 设计时必须连着通用项一起看，否则就会出 §二.5 那个打架。

### 2.1 行 1 · 缓存位置 —— 专用项三项（一揽子推荐）

| 菜单项 | 条件（`when`） | 点了干什么 | 为什么值得放 |
|:--|:--|:--|:--|
| **打开缓存目录** | `settingKey == 'app.storage.cacheDir'`（若也想出现在行 3，写成两个键的 `\|\|`） | 主进程解析**当前生效**的缓存目录（配置为空则解析成默认位置）→ 目录不存在就先建 → `shell.openPath`（普通资源管理器窗口，⛔ 不是要人处理的模态框） | 用户第 ③ 问的原话诉求；零新控件；照抄先例「打开存储位置」 |
| **复制路径** | 同上 | 把**当前生效**的完整路径写进剪贴板 ＋ 弹一条「已复制：…」 | 用户经常要把路径贴到别处（聊天、配置文件）；成本极低 |
| （可选）**恢复默认位置** | `settingKey == 'app.storage.cacheDir' && settingModified` | 清掉这一项的设置 **＋ 清掉注册表里的种子** | ⚠️ **只在你选乙案时才加**，见 §二.5 |

> 🔴 **「打开缓存目录」必须解析"当前生效"的路径，不许复制一份字符串**——配置为空时它要能算出默认位置。这条是 [01-方案与落点契约.md](01-方案与落点契约.md) §三 铁律 3 的落点。
> 🔴 **点「打开」时目录可能还不存在**（刚装完、还没跑过软件）：先建再开，别弹"找不到"。见 [02-边缘情况清单.md](02-边缘情况清单.md) E27。

### 2.2 行 2 · 已用空间 —— 推荐：**不放任何专用项**

| 候选 | 建议 | 理由 |
|:--|:--|:--|
| 「刷新」 | ❌ 不要 | 这个数字**每 3 秒自己刷**（事实 7）。放「刷新」等于告诉用户"它不会自动更新"，是误导 |
| 「复制已用空间」 | 🔵 可有可无，**默认不加** | 值本身没什么可粘贴的用处；真想要，用户在通用项里也拿不到它（见下行）——但为此单开一项不划算 |
| 通用「复制为 JSON」 | ⚠️ **照旧留着，但要如实记一笔** | 在只读行上它复制的是**配置里存的值**（通常是空的），**不是屏幕上那个数字** ⇒ 天然误导。这是壳的既有行为、**全软件所有只读行都这样**，⛔ **不在本件改**（改它 = 动通用件，属另一件事），本件只登记这条事实 |

⇒ **行 2 的齿轮 = 只有通用项，我们不加东西。** 一句话理由写进实现注释即可。

### 2.3 行 3 · 清除缓存 —— 推荐：**只借一项「打开缓存目录」，其余不加**

| 候选 | 建议 | 理由 |
|:--|:--|:--|
| 「打开缓存目录」 | ✅ **加**（与行 1 是**同一个命令**，只是 `when` 多认一个键） | 清之前想看看里面有什么、清之后再打开确认——这是这条命脉上唯一有用的动作 |
| 「清除缓存」也塞进齿轮 | ❌ 不要 | 它在**行上已经有一颗大按钮**了，重复放 = 同一动作两个入口，还得再问一次"要不要确认" |
| 任何危险项（红色 `delete` 组） | ❌ 不要 | 齿轮是**hover 才显形**的角落（事实 5），不该藏不可逆动作 |

> ⚠️ 顺带一个**明确的界限**：齿轮里的东西**不算"主要入口"**。硬约束 26 要求「每个用户动作至少一条非鼠标路径」——这一条我们靠**把动作注册成命令**满足（齿轮项本身就是命令，AI 与命令面板可调），**不是靠齿轮**。所以"打开缓存目录"即使只住在齿轮里，也必须是一个正经注册的命令（见 §二.6 的规格表）。

### 2.4 行 3 的按钮文字与长解释放哪（06 图要改的地方）

真实渲染器的规矩（事实 8）：**动作行的按钮文字 与 行的副标题 是同一个字段**（`description`）。

- 若照 06 图写成长句「清除缓存（只清可再生的临时文件，不动插件与设置）」⇒ 这一行里 **同一句长话出现两遍**，而且按钮宽度撑到近百像素的字宽，在「存储」这一列里会显得很突兀。
- **推荐写法**：
  - 行 `description` = **「清除缓存」**（短；它同时当副标题和按钮文字，短句重复两遍不刺眼）；
  - 长解释搬到**「存储」分节的 `groupDescriptions`**（事实 9 的正式落点，显示在分节标题下面一行小字）：
    > 缓存目录只放可再生的临时文件；清除只清这些，**插件与设置一律不动**。
- 这样 06 图那两颗"长按钮"要改画——**但图先别动**，等你在 §四 点了头再一次改到位（改图 = 改 06 那个手绘示意文件，属"动下一格"）。

### 2.5 【★ 核心讨论】通用「重置此设置」与注册表种子会打架

**问题怎么来的（一步一步）**：

```
装的时候你选了 D:\cache      → 安装器把 D:\cache 写进注册表（= 种子）
第一次开软件                  → 软件里还没值 ⇒ 采用种子 ⇒ 设置里显示 D:\cache    ✅ 这一步是对的
你在设置里点通用「重置此设置」 → 设置被清空（= 回到"没设过"）
下次开机                      → 软件里又没值了 ⇒ 又采用种子 ⇒ 又变回 D:\cache     ❌ 弹回来了
```

⇒ 用户会得出「我改了没用 / 这软件有问题」的结论。**这是必须现在定掉的分叉**，三个解法：

| 案 | 做法 | 代价 | 评价 |
|:--|:--|:--|:--|
| **甲案（推荐）· 种子一次性** | 启动读种子的那一次，**读完就把它从注册表删掉**（无论采用与否）。之后"重置"就真是回到默认了 | 要写一个"消费种子"的动作；注册表不再长期保存"安装时选了什么"（本来就没人读） | **最少的新增件**：不加菜单项、不加命令、不加 IPC。且和契约精神一致——「只有一处权威」 |
| **乙案 · 留种子 + 专用项** | 注册表保留种子；新增齿轮项「恢复默认位置」（清设置 ＋ 清种子）；**同时**把通用「重置此设置」在缓存位置这一行隐去（改通用项的 `when` 加一条排除） | 多一条命令 ＋ 一条 IPC ＋ 动通用项的 `when`（通用件里出现具体键名——已有背景图那两行的先例，不算破例） | 好处是**文案直白**（"恢复默认位置"比"重置此设置"清楚）。适合你想让这一行更好懂 |
| 丙案 · 只加专用项，通用项不动 | ❌ **不推荐** | — | 用户点了通用那个 → 设置清了、种子还在 → 下次开机弹回来。**就是上面那个 bug 原样留着** |

> 📌 **说明**：现草案（[01-方案与落点契约.md](01-方案与落点契约.md) §二）写的是"新增恢复默认位置"，但**没提通用「重置此设置」还在**——所以草案不算错，是**不完整**。这一格必须补。
> 📌 无论选甲还是乙，[01-方案与落点契约.md](01-方案与落点契约.md) §三 铁律 2 的措辞都要同笔改一句（甲案下"种子"变成"一次性种子"）。

### 2.6 三个新菜单项的命令规格（实现期照抄，末列是待你点头的取舍）

| 字段 | 打开缓存目录 | 复制路径 | （乙案才要）恢复默认位置 |
|:--|:--|:--|:--|
| 命令 id | `workbench.action.openStorageCache` | `workbench.action.copyStorageCachePath` | `workbench.action.resetStorageCacheDir` |
| 标题（菜单上显示） | 打开缓存目录 | 复制缓存目录路径 | 恢复默认位置 |
| 分类 | 首选项 | 首选项 | 首选项 |
| 说明（AI 读的那句，必填） | 在系统资源管理器中打开缓存目录（当前生效的位置） | 把当前生效的缓存目录完整路径复制到剪贴板 | 把缓存目录恢复为默认位置（并清掉安装时写入的种子） |
| 参数 | `{ settingKey: string }`（照 `SETTING_KEY_PARAM` 共用常量） | 同左 | 同左 |
| 菜单槽 / 分组 | `SettingItemGear` / `navigation` | 同左 | 同左 |
| `when`（菜单门控） | `settingKey == 'app.storage.cacheDir' \|\| settingKey == 'app.storage.clear'` | `settingKey == 'app.storage.cacheDir'` | `settingKey == 'app.storage.cacheDir' && settingModified` |
| 干活的地方 | 走壳 IPC（主进程解析路径 → 建目录 → `shell.openPath`） | 渲染层剪贴板服务 ＋ 一条提示 | 清设置 ＋ 走壳 IPC 清注册表种子 |

> ⚠️ **一个代价，如实告诉你**：因为 `when` 是**命令和菜单项共用的同一个字段**（事实 12），带 `settingKey` 门控的命令**在命令面板里搜不到**（事实 11）——先例「打开存储位置」今天也是这样。影响 = 普通用户没法从命令面板找到"打开缓存目录"，但 **AI 可以照常调用**（命令带参数调用不受面板过滤影响）。
> 若想让它在命令面板也能搜到，需要给壳的命令注册循环**补一个"菜单专用条件"字段**（约 3 行）——属**动核心注册机制**，我**默认不做**，列在这里供你选（要不要为这一条便利动核心，你说了算）。

### 3.1 布局（现状复述 + 一处预算复核）

### 3.3 缓存目录行：判词与回填（逻辑已落，逐条对照）

| 情形 | 现在的行为 | 谁保证 |
|:--|:--|:--|

### 3.4 宿主侧「件 2e」—— 实际是 **四件**（现档案只写了三件）

🔴 **这是本档最重要的补漏。** [03-实现交接.md](03-实现交接.md) §五 只列了三件（受理浏览 / 收尾读字段 / 写注册表），但**页面早就在等第四件**：「缓存目录的默认位置由宿主自报」（`app.js` 里 `q.get('cachedir')` 已能收，`main.cpp` 里零命中）。少了它，输入框里的灰字提示永远只有兜底文案——用户看不到"默认会装到哪"。

| # | 落点（`build/installer/bootstrapper/main.cpp`） | 做什么 |
|:--:|:--|:--|
| 2e-① | **启动 URL 参数拼装块**（和 `dir=` / `udata=` 同一处，约 :1865 一带） | 加一个 `cachedir=` 参数，值是**默认缓存目录**（复用现成的 `UserDataDir()`，卸载屏已经在用它）。⚠️ 页面侧要求：**只落灰字提示、不落实际值**——所以这里报的是"默认在哪"，不是"用户选了什么" |
| 2e-② | 消息派发链（照 `browse-dir` 那一支写，约 :1748） | 受理 `browse-cachedir` → 弹目录选择框 → 回 `{"type":"cache-dir-done","dir":"…"}` |
| 2e-③ | 新增 `PickCacheDir()`（照 `PickInstallDir` :1128 抄） | `IFileOpenDialog(FOS_PICKFOLDERS \| FOS_FORCEFILESYSTEM \| FOS_PATHMUSTEXIST)`，标题「选择缓存目录」。⚠️ **必须在已 `CoInitialize` 的线程调用**（原注释就这么写，抄的时候别丢） |
| 2e-④ | 安装收尾 | 读页面送来的 `cacheDir` 字段（照 `JsonGetBool` 写一个 `JsonGetString`，已存在）→ **只在非空时**写 `HKCU\Software\LinkDesk\CacheDir`；留空 = **一个字都不写** |

> ⚠️ **两条硬提醒**：
> ① 2e-④ 的注册表写入与壳侧读取要走**同一套键名口径**——壳那边 `electron/services/registry-integration.ts` 已经有 `HKCU\Software\LinkDesk` 这个常量与 `reg.exe` 执行器（事实 13），**新代码别另起一套**。
