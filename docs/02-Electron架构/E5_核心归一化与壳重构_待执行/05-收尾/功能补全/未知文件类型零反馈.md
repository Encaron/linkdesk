# E4 遗留 UX——未知文件类型零反馈

> 2026-08-06。Filed by Encaron。E4 遗留项。
> 位于 E5 收尾 → `05-收尾/功能补全/`

---

## 一、问题

双击 `.key` 等无注册编辑器的文件扩展名 → `console.warn` 一行完事，UI 上**零提示**。用户双击后期望看到内容——什么都没有发生，不知道出了什么问题。

对标 VS Code：未知扩展名弹出"没有为 .key 文件注册编辑器"提示，或弹出"选择编辑器"对话框。

---

## 二、前因

`FoldersView.tsx` 的 `doOpenFile`（L348-365）：

```typescript
const doOpenFile = useCallback((filePath: string, name: string, mode: "preview" | "pin") => {
  const ext = extension(name);
  if (!ext) {
    console.warn(`[file-tree] 无法识别文件类型（无扩展名: ${name}）`);
    return;  // ← 静默退出——用户不知道发生了什么
  }
  const pluginId = getPluginFor(ext);
  if (!pluginId) {
    console.warn(`[file-tree] 没有注册处理 ".${ext}" 的编辑器（文件: ${name}）`);
    return;  // ← 同样静默
  }
  tabs?.create(pluginId, { filePath, sourceId: filePath, label: name, pinned: mode === "pin" });
}, [tabs]);
```

两个静默 `return`——开发者能在 Console 看到，用户看不到。

---

## 三、修复方案

`console.warn` 保留（开发者诊断），加 toast 提示（用户反馈）。

```typescript
const lk = (window as any).linkdesk;

if (!ext) {
  console.warn(`[file-tree] 无法识别文件类型（无扩展名: ${name}）`);
  lk?.dialog?.alert?.(`无法打开「${name}」——文件没有扩展名`);
  return;
}
const pluginId = getPluginFor(ext);
if (!pluginId) {
  console.warn(`[file-tree] 没有注册处理 ".${ext}" 的编辑器（文件: ${name}）`);
  lk?.dialog?.alert?.(`没有为 .${ext} 文件注册编辑器`);
  return;
}
```

**对标 VS Code：** VS Code 对未知扩展名弹"选择编辑器"对话框。LinkDesk 当前没有"选择编辑器"功能——先 toast 提示，未来可扩展为 Modal 提供"选择打开方式"。

---

## 四、可能遇到的问题

### 1. toast 未就绪

**风险：** `linkdesk.dialog.alert()` 依赖 DialogService + IpcBridgeHandler——如果文件树跑在独立 WebView 中，IPC 可能未就绪。

**缓解：** 当前单 WebView 下 dialog API 已验证正常（E5#67）。多 WebView 恢复后需验证。

### 2. 文件树批量操作

**风险：** 用户可能多选文件后按 Enter——同时打开 10 个文件，其中 2 个未知类型 → 弹 2 个 toast。

**缓解：** 先收集所有未知文件，合并为一条 toast："XX 和 YY 没有注册编辑器"。或不做——单文件双击是最常用路径。

### 3. `.key` 文件是否真的需要编辑器

**风险：** `.key` 是 SSH 私钥格式——用户可能确实不需要编辑器打开它。但在 LinkDesk 中注册它的插件（如证书管理）未来可能出现。

**缓解：** toast 是"告知"不是"阻断"——用户看到后理解为什么没反应，不会困惑。
