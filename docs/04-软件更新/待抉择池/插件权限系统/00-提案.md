# 插件权限系统 —— 待决策提案

> **状态：📋 种子版 ＋ 立项前置已定（2026-11-12 用户「同意」）**——待**专门立项**（用户：会像「默认打开方式管理器共享化」那样做完整档）。本夹现记录：权限总表初稿、三个面、**三件最难**、五条铁律、波次 W0–W7、成案结构。
> 用户原话：「这是一个很大的任务，但很重要，涉及软件核心的安全，作为受控进程的前置」；「权限系统很大，涉及 UI 设计、设置页配置、逻辑配置、各个插件适配、版本限制」。
> **一句话**：给每只插件一张**权限清单**——作者声明什么才有什么；装的时候让用户看见并可选；用不了的时候给一句**轻提示**。运行期默认拒绝。
> **落点说明**：单独一档（不并入 [通用能力底盘](../通用能力底盘/00-提案.md)）——那边管"壳能做什么"，本档管"**谁被允许用什么**"。两者是"能力"与"门禁"的关系。
> **与 AI 正门的关系**：外部 AI 那套「白名单 ＋ 闸门 ＋ 账本」是**同一套思想的既有实现**（`askFirst` / scope / `log`）——本档把它扩到**插件侧**，⛔ 不另造第二套。

## 〇、用户原话（2026-11-12）

1. 「安装时候给予安全警告，安装后把权限列好，比如位置信息、摄像头、麦克风」——**照安卓权限页的形态**；
2. 「插件作者什么都不声明，则什么权限都不给；声明什么权限，给什么权限」；
3. 「安装弹窗默认打勾，可以取消勾选」——不给也不影响安装；
4. 「使用时候被拒 → 弹`需要开启某某权限`，轻弹窗、一会消失」；
5. 「受控进程的确认不要每任务弹窗；给权限的方式，给了之后就不再问」；
6. 「这个轻提示还能复用到别处，比如`默认打开方式已切换为 xxx`」。

## 二、权限总表（初稿 · 你增删）

> 原则：**按能力种类列**，不按插件列；每只插件从这张表里勾自己要的。
> 「默认」= 安装弹窗里的预勾选状态。**高危三项默认不勾**（其余默认勾），这是唯一一处我建议偏离"全部默认打勾"的地方——原因：进程执行与越权读写一旦默认给，用户不会回头看。

| 组 | 权限键 | 含义 | 默认 |
|:--|:--|:--|:--:|
| **文件** | `files.ownData` | 读写本插件私有隔离目录 | ✅（配额约束） |
| | `files.readWorkspace` | 读工作区文件 | ✅ |
| | `files.writeWorkspace` | 写工作区文件 | ✅ |
| | `files.userPicked` | 读写用户在弹框里指定的位置 | ✅ |
| **剪贴板** | `clipboard.read` | 读剪贴板 | ✅ |
| | `clipboard.write` | 写剪贴板 | ✅ |
| **外部程序** | `process.exec` | 启动外部程序（附**允许清单**） | ⛔ **不勾** |
| **串口** | `serial.enumerate` | 枚举端口 | ✅ |
| | `serial.open` | 开/关端口 | ✅ |
| | `serial.control` | DTR/RTS 等控制线（可复位设备） | ✅ |
| **数据流** | `stream.open` | 打开高速字节流 | ✅ |
| **连接** | `connections.own` | 登记/读自己的连接 | ✅ |
| | `connections.all` | 读**其他插件**登记的连接 | ⛔ **不勾** |
| **命令** | `commands.invokeOthers` | 执行其他插件的命令 | ✅ |
| **网络** | `network.fetch` | 对外发起网络请求 | ✅ |
| **系统** | `notify` | 系统通知 | ✅ |
| | `tray` | 托盘图标/菜单 | ✅ |

**补充**：串口日志存盘**不是新权限**——它落在 `files.ownData` 里（私有区，免逐次授权），仍受配额与落点登记约束。

## 三、三个面（一套模型，三处显现）

### 面 1 · 安装弹窗

- 列出该插件声明的全部权限（人话描述＋图标组）；
- 默认勾选（高危三项不勾）；
- 用户可取消 → **仍可安装**（⛔ 不拦安装，拦功能）；
- 文案：「这只插件想使用以下能力，你可以取消任何一项」。

### 面 2 · 权限页（安装后可查可改）

- 位置：设置页新增一组（**设置插件**承担，不是壳——硬约束 11）；
- 内容：按插件分组，逐项开关；显示「最近一次使用时间」；
- 改开关即时生效（运行中插件下一次调用即按新值判）。

### 面 3 · 运行时降级（轻提示）

- 能力被拒时**不崩、不静默**：回结构化错误 `{ok:false, code:"EPERMDENIED", permission:"serial.open", hint}`；
- 同时弹**轻提示**：「需要开启「打开串口」权限 · 去设置」——一会自己消失；
- 🔴 **轻提示是共享 UI 组件**（判据 A：消费宿主声明的状态，不该由每只插件自己画），同时服务其他场景：`默认打开方式已切换为 xxx`、`已复制`、`更新失败` 等。

## 四、与「通用能力底盘」的关系

| | 回答的问题 | 例子 |
|:--|:--|:--|
| 通用能力底盘 | 壳**能不能**做这件事 | 壳能启动外部程序 |
| **本档** | 这只插件**许不许**用它 | 这只插件没勾 `process.exec` ⇒ 拒绝 |

⇒ 顺序：**能力先有，权限后门**；但两者**同批设计**（否则先上线的能力只能"全放行"）。

## 五、批次与验收

- **批次**：① 权限总表定稿 → ② 清单 `capabilities` 声明 ＋ 默认拒绝 ＋ 对账门禁 → ③ 安装弹窗 → ④ 权限页 → ⑤ 轻提示共享件 → ⑥ 运行时降级与错误码。
- **一次验证**：
  1. 不声明任何权限的插件 ⇒ 调任何受控面都回 `EPERMDENIED`，且**不崩不静默**；
  2. 安装时取消 `serial.open` ⇒ 装得上，用串口时弹轻提示并可跳权限页；
  3. 权限页改开关 ⇒ 下一次调用即生效（无需重启）；
  4. 卸载插件 ⇒ 权限记录一并清理。
- **🔴 存量迁移（必须先定）**：现在所有官方插件都没有声明。若直接默认拒绝，升级后**全线失效**。建议：首个版本对**存量插件全放行**并标注"未声明"，插件**下次发版时补声明**（门禁从新发版起判红）。

## 七、立项前置（2026-11-12 用户"同意"，成案时照此升级）

> 本夹现为**种子版**；正式立项时在**本夹基础上升级**为完整档（照 [默认打开方式管理器共享化](../../已落地/默认打开方式管理器共享化/00-README.md) 的 8 件套），⛔ **不另建第二个夹**。

### 7.1 三件最难的事（W0 必须解）

1. **身份**：权限检查第一句是"谁在要"。检查必须落在**主进程调用边界**，按"调用方 = 哪只插件"判；插件自查＝等于没有。
2. **迁移**：17 只官方插件一条声明都没有。三段式——**先全放行并标记"未声明" → 各插件下次发版补声明 → 覆盖完整后翻"默认拒绝"**；过渡必须有明确截止条件。
3. **升级扩权**：插件更新新增能力 ⇒ **必须重新弹窗**（只针对新增项）。否则等于用户批准了没见过的东西——权限系统反而制造虚假安全感。

### 7.2 五条铁律

1. 执行点只在主进程；SDK 侧检查只是提前报错，不是安全边界。
2. 只有壳能弹授权窗；插件不许自己弹（= 钓鱼）。
3. 权限按插件算，不按视图/标签页算。
4. 撤销立即生效（下一次调用即拒），不重启。
5. 授权变更进账本（谁/何时/给了什么），与 AI 正门同源。

### 7.3 版本限制

- 壳声明**支持的能力清单**，插件声明**要的能力**；壳不认识的 ⇒ 加载时明确告知，⛔ 不静默失效；
- **能力 → 最低软件版本自动推导**（照共享件地板的"静态导入即算"先例），⛔ 不手填。

### 7.4 波次（顺序不得倒置：地基先于 UI）

**W0 判据**（权限总表 · 身份方案 · 执行点）→ **W1 地基**（身份映射 → 主进程检查 → 授权存储 → 审计）→ **W2 声明与兼容**（清单字段 · 默认拒绝 · 存量放行 · 版本推导）→ **W3 安装弹窗** → **W4 权限页**（设置插件内，数据走壳命令面）→ **W5 运行时降级 ＋ 轻提示共享件** → **W6 插件适配**（17 仓补声明 ＋ 作者文档）→ **W7 收口**（未声明即红 ＋ 迁移收尾）。

### 7.5 成案时的文件结构（8 件套）

`00-README`（案由/判据/状态）· `01-方案与落点契约`（执行点/身份/声明/存储/审计）· `02-边缘情况清单`（迁移/升级扩权/运行中撤销/卸载重装/多实例/AI 调用/非官方插件/壳不认识的能力）· `03-文档连锁与发版` · `04-任务清单`（波次＋决策点 C1…）· `05-派工与交接` · `06-启动令-AI-1` · `07-设计图元素与对照台账` ＋ `mockups`（安装弹窗/权限页/轻提示 三张拟真图＋校验脚本）。
