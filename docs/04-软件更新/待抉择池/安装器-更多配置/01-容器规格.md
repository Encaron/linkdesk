# 01 · 容器规格（本摊的核心）

> 这一份回答三件事：**容器长什么样（分组）· 什么时候出现（入口与门）· 值从哪来（默认值 ＋ 单源）**。
> 全部对着**当前真实产品源**写（`build/installer/bootstrapper/app.html` / `app.css` / `app.js`），标「实测」的出处可查。
>
> 🔴 **本件是设计规格（文档）。** 2026-10-03 用户定：本轮**只做文档、不改代码** ⇒ 下文的「改造／落点」都是**设计意图**，产品源**尚未落地**（落地归 [04-任务清单.md](04-任务清单.md) 阶段 1）。标「实测现状」的行 = 照当前产品源**读出来**的事实，用来说明"新绘的只该是新绘的那部分"。

## 一、入口与门（「更多配置」这颗按钮什么时候出现）

**实测现状**（`app.html:84-88`）：欢迎屏动作行 `.actions` 里现在有两样东西——主按钮「立即安装」＋ ghost 按钮「自定义安装」（`#custtoggle`，`data-action="toggle-custom"`）；点它会展开 `#custom`（`.cust-wrap` 折叠层，`app.css:220-225`）。

**本轮设计改造（待落地）**：

| 步 | 谁 | 做什么 |
|:--:|:--|:--|
| 1 | 用户 | 在欢迎屏点「自定义安装」→ 展开区打开（**现状不变**） |
| 2 | 界面 | 展开区打开的**同时**，动作行里**再露出**一颗 ghost 按钮：「**更多配置**」 |
| 3 | 用户 | 点「更多配置」→ 展开区**变身**成容器（动画见 §四） |
| 4 | 用户 | 容器底部「**返回**」→ 变回紧凑态（**不丢任何值**）；「**继续安装**」→ 与欢迎屏的「立即安装」**同一个出口** |

- 🔴 **「更多配置」只在「自定义安装」被点开之后才出现**——用户 2026-10-03 两次说「点击自定义安装之后…再出现一个按钮」。所以它不是一个恒常可见的第三按钮。
- 🔴 两颗按钮**并存**：「自定义安装」不会消失、不会变身（用户：*「在自定义旁边，再出现一个按钮」*）。点「自定义安装」= 收起/展开紧凑区；点「更多配置」= 进容器。
- ⛔ **不要**给「更多配置」另开一屏（`.scr`）。它是**同一块区域的另一种长相**——用户说的是「整个这个页面样子大变」，不是"跳到下一页"。

## 二、★ 二级分组规划（用户 2026-10-03 点名要提前定）

容器内的项按**二级标题**分组，**组间一条发丝线分隔**（照壳内 ContextMenu 的分组视觉与设置页分节的既有语汇）。

> 组间的分节视觉（发丝线 / 标题层级）见 §四 F 段与设计图；**组序**见下（★ 与用户口述的先后不同，已标出）。

### 组 ①「安装位置」（容器里的第一组）

> 用户原话：「有的是这个**改变目录**之类的」。

| 项 | 控件 | 备注 |
|:--|:--|:--|
| **安装目录** | 路径输入框 ＋ 「浏览…」（**现成的 `.pathrow`，零新控件**） | 现状就在展开区里，进容器后**归入本组**（位置几乎不动 ⇒ 变形最干净） |
| **缓存目录** | ⏸ **预留槽位，本轮图上不画** | 见下方红字 |

- 🔴 **组序说明（★ 请用户点头）**：你口述的先后是「权限 → 插件 → 目录」；本规格**把「安装位置」提到第 ① 组**。三条理由：① 它是这批里**唯一所有用户都该看一眼**的一项（"装到哪"）；② 它与紧凑态里 `.pathrow` 的**位置最近** ⇒ 变形最干净、最不容易看晕；③ 它天然是"以后还要往里加目录类项"的那一组。**若你要按原顺序，改回来只是换个次序，机制一字不动。**
- 🔴 **「缓存目录」这一行本轮不画**（⏸ 预留槽位）：宿主侧**今天没有** `PickCacheDir`（`main.cpp` 只有安装目录那一支 `browse-dir`）⇒ 画一个**点了没反应**的输入框＝**真缺陷**，不是"先行示意"。要画它，先做 [04-任务清单.md](04-任务清单.md) 阶段 2（宿主）。
- 🔴 **这一条推翻了旧决策点 D5**（旧 D5＝「更多配置页**不给**安装位置」，理由是"同一件事只许一处能改"）。**改判理由**：现在**只有这一处**——展开区**就是**容器的紧凑态，两者**共享同一份 DOM 与同一份值**，不存在"两处各存一个值"⇒ 旧 D5 担心的「我在这儿改了怎么装到别处去了」**在机制上不成立**。详见 §五 的单源规则。
- ⚠️ **宿主侧还没接**：「浏览…」要能回填，得宿主受理（C++），今天**点了没反应**——**已知的、独立的**一件（旧档案叫「件 2e」），进 [04-任务清单.md](04-任务清单.md) 阶段 2，**不阻塞出图**。

### 组 ②「给 LinkDesk 的权限」

> 用户原话：「有的是**给权限**对不对给 link desk 权限」。

今天真实存在的 4 项，**文案与欢迎屏逐字相同**（同一批 i18n 键 `installer.opt.*`；⛔ 不新写一套文案）：

| 项 | 今天默认 | 说明 |
|:--|:--:|:--|
| 文件右键菜单「通过 LinkDesk 打开」 | 未勾 | 改注册表，属于"向系统要权限" |
| 目录右键菜单「通过 LinkDesk 打开」 | 未勾 | 同上 |
| 注册为受支持文件类型的编辑器 | **已勾** | 改文件关联 |
| 添加到 PATH（重启终端后生效） | **已勾** | 改用户环境变量 |

⇒ 这 4 项**本来就是**「向系统要的权限」，归一组天然成立。默认值**照现状一字不改**（理由见 §三）。

### 组 ③「随包安装的插件」

> 用户原话：「有的是**挑选哪些插件需要安装**」。

**⚠️ 今天没有数据源，如实记**：安装器只是把安装包里的一个 7z 解开（`main.cpp` 里**没有任何按名字枚举插件的代码**），界面**从不列出插件清单**。所以：

- **组先立着**（用户要求：别等项多了再补分组），图上画成**如实的空态**——标题 ＋ 一行「本次安装包未随带可选插件。」。
- ⛔ **不许编造插件名**：第三方插件 id 不许出现在壳内任何文件（硬约束 10）；凭空虚造官方插件名同样是造假。**真名单要等产品源能枚举 payload 时再接**（见 [04-任务清单.md](04-任务清单.md) 阶段 3）。
  设计图 05 上另有一个**可切换的演示态**（工具条「⊕ 装几个示例插件」），六个名字**全部标了 `DEMO`**、只为让人看到"插件多了怎么逐个勾"——⛔ 那六个是假数据，不许抄进产品源；真清单落地后该演示态**删掉**（04 阶段 3.3）。
- 组在**空的时候**怎么表现（显示"未随带"／整组隐藏）＝ [02-边缘情况清单.md](02-边缘情况清单.md) E40；**推荐 C2**（标题 ＋ 一行说明，＝设计图所画）。

## 三、两类用户（用户点名要考虑的）

用户 2026-10-03：*「有的用户一股脑直接全部一直点安装…他就不需要看那个界面，有的用户…需要酌情安装一些东西，很多权限它可能需要酌情的给」*。

| 用户 | 他的路径 | 界面必须保证 |
|:--|:--|:--|
| **A · 一路点安装** | 开窗 → 「立即安装」→ 装完。**永不打开容器** | ① 默认值必须能装出一个**能用的**软件（今天 `editor` / `path` 已勾、两个右键菜单未勾——**照旧不动**）；② 「更多配置」**不许挡路、不许抢焦点**；③ 容器里的空组／空态**不能报错**（他没进来，但代码路径要在） |
| **B · 酌情** | 开窗 → 「自定义安装」→ 「更多配置」→ 逐项调（含权限）→ 「继续安装」 | ① 每一项都能**单独**关掉；② 权限类项要能**说清代价**（关掉它 = 少了什么），不是干勾；③ 返回／再进**值不丢**；④ 容器**能滚**，项多了不挤 |

**默认值策略（本轮不动产品默认）**：用户没说改默认，就**照现状**——"一路点安装"的人拿到的和今天**完全一样**的东西。⛔ 不许借这次改造偷偷改默认。

## 四、动画规格（用户点名：做动画效果；走 skill `impeccable`）

**变形的实质**：同一批 DOM 节点，从「2×2 网格 ＋ 无组标题」变成「单列 ＋ 三组标题」。

| 层 | 做法 | 出处／为什么 |
|:--|:--|:--|
| **面板开合** | 沿用既有 `#custom` 的 `grid-template-rows: 0fr ↔ 1fr`（**已验、检测器友好**） | `app.css:220-225`。⛔ **不许回到 `transition:max-height`**——那会被设计检测器判 `layout-transition`（台账 §五 F 记着这次返工） |
| **列数变形** | `.opts` 的 `grid-template-columns: 1fr 1fr → 1fr`（**可动画**） | 用户点名的"变成数列"就是这一条 |
| **节点连续性** | **FLIP**：变之前量一次各节点的位置 → 换类 → 再量一次 → 用 `transform` 反推回原位再归零（纯 vanilla，约 20 行，⛔ 不引库） | 让 4 个项**看起来是"移"过去**，而不是"没了又出现" |
| **组标题显现** | 组标题 `opacity + translateY` 错峰淡入（复用既有 `land` 关键帧语汇） | `app.css:164-169` |
| **hero 收起** | `.hero` 包一层裁剪层，同样走 `0fr ↔ 1fr` ＋ 淡出；高度让它自然让给清单 | 用户第 6 条：「这些字就没了」 |
| **时长／曲线** | ⛔ **沿用现成 token**：`--mo-dur` / `--mo-ease` / `--ease` / `--mo-step` | `app.css:59-65`。**不许**新编一组时长常数 |
| **降级** | 尊重 `prefers-reduced-motion`（产品源已有该覆盖，`app.css:330-331`） | 无障碍底线 |

### 九条"画出来才发现"的硬约束（画设计图时验证过，实现时照做）

| # | 约束 | 为什么 |
|:--:|:--|:--|
| F1 | **容器不换表面**：面板在 `.win` 内铺满，但**背景透明**——窗自己的底（`--glass-win`）与双光球透上来；被它让位的品牌行、英雄区**真淡出**，不靠一层底色去遮。面板**绝不加 transform** | ① 换底色 ＝ 换了一层肤：本图第一版给面板铺了不透明 `--bg`，用户 2026-10-03 一眼看出**「为什么色调变了」**；② 面板上的位移会让 FLIP 量到的"终态"偏掉；③ `✕` 与语言药丸挂在 `.win` **之外**（`.frame` 上）⇒ 容器态照旧能关窗、能切语言，不是"关不掉的模式" |
| F2 | **布局一次到位**：英雄区的高度、面板里的列数，**都不做高度过渡** | 过渡进行中量到的是**被插值的中间值** ⇒ FLIP 的位移会算错；"重排感"全部由 FLIP 的同一拍补上 |
| F3 | `prefers-reduced-motion` 必须**在 JS 里判**（`matchMedia`），别指望 `app.css` 那条 `@media` 覆盖 | 那条覆盖管的是 CSS 动画；**Web Animations（`el.animate`）不受它管** |
| F4 | 容器里 `Enter` 的"主按钮"要让位给「继续安装」 | 现实现查的是 `$('.scr.on [data-primary]')`，这条查询**不看可见性** ⇒ 不让位就会点到已被盖住的「立即安装」 |
| F5 | `Esc` 多分**一层**：容器态 → 先回紧凑态，再按才关窗 | 与 `#lkdd` 下拉的既有分层同构（先收弹层、再按屏分流）；`✕`／Alt+F4 一律仍关窗 |
| F6 | 新令牌**只加一条** `--mo-morph`＝0.52s（重排位移时长），JS 也读它 | 别在 JS 里硬编码时长/曲线（否则产品与评审页两张皮）；其余时长曲线**一律沿用既有** `--mo-*` |
| F7 | **整条 flex 链每一节都要是 flex 列 ＋ `min-height:0`**：面板 → `.cust-wrap` → `.cust-in` → 滚动层，**四节缺一不可** | 少一节，压矮窗口时滚动层就不肯收缩，「继续安装／返回」被**挤出窗外**（画图实测：窗口压到 452px 时动作行整个越界）。⚠️ `.cust-wrap` 在产品源里是 `display:block`（`app.css:220`）⇒ 容器态必须**显式补** `display:flex;flex-direction:column`，别指望它本来就对 |
| F8 | **主按钮跨态占同一个槽位**：欢迎屏＝「立即安装」(主) ＋「自定义安装」(次)；容器里就**必须**是「继续安装」(主) ＋「返回」(次)——主按钮恒在窗内左下那一格（左内边距 52px 处），次按钮紧随其后 | 元素位置不许轻易换（用户 2026-10-03：**「为什么下面继续安装跑右边了？这十分不合理…一个元素的位置，不能轻易换」**）。⚠️ 弹窗那套"取消左／确认右"是**另一套**约定；本产品现行约定是**主按钮在前**，要改它得连欢迎屏一起翻，⛔ 别只在容器里翻 |
| F9 | **第三组「随包安装的插件」与第二组权限项共用同一枚勾选原件**（同一方框、同一勾选动画、同一行距），⛔ 不另造一套 | 一页里两套勾选框，用户会以为它们不是一回事，落地还要写两遍逻辑。⚠️ 同时：**`core` 插件（如「设置」）不给勾选框**，右侧标「内置」——本仓硬约束（`core:true` ＝ 界面不给卸载按钮）在安装器里同理：它随壳装，没得选。画法见 [05-设计图-更多配置容器.html](05-设计图-更多配置容器.html) 的**演示态**（六个名字**全是假数据**、已标 DEMO） |

> 🔴 **动画的第一验收标准不是"炫"，是"不跳版、不闪、能看懂发生了什么"**。做完照 [04-任务清单.md](04-任务清单.md) 验收口径逐条看。

## 五、单源规则（逻辑自洽的根，照抄旧档最值钱的一条经验）

**所有值只有一份**，容器态与紧凑态**读的是同一个对象**：

| 值 | 落在哪 | 谁保证一致 |
|:--|:--|:--|
| 4 个勾选 | 一个 `uiOpts` 对象（**不扫 DOM**） | 改哪边都写回它；两边进入时都按它重画 |
| 安装目录 / 缓存目录 | `uiPath` / `uiCache` 字符串 | 控件**受控回填**，不靠 DOM 自己记 |

⇒ 这是旧档被撤之前**已经踩对**的一条（旧 [02-边缘情况清单.md](02-边缘情况清单.md) E1／E2 记着「两屏读同一份，任何一屏改动都写回这份，没有第二份 DOM 状态可以漂移」）。**重做时照抄这条**，别退回"两处各自记"。
