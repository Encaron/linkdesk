## 标准目录结构

```
my-plugin/
├─ plugin.json           # 插件声明——唯一必选文件
├─ icon.svg              # 插件图标（可选）——根目录 或 resources/，由 plugin.json `icon` 字段声明
├─ README.md             # 插件说明——详情页「详情」页签的数据源（强烈建议提供）
├─ CHANGELOG.md          # 更新日志——详情页「更改日志」页签的唯一真源（强烈建议提供）
├─ i18n/                 # 翻译文件——每种语言一个 JSON（可选）
│  └─ en.json            # key=原文, value=译文
├─ resources/            # 静态资源——图标/字体/图片（可选——相对路径声明，壳解析）
│  └─ icon.png
└─ src/
   ├─ index.tsx           # 入口——export default React 组件（≤120 行，薄门面）
   ├─ views/              # 页面级组件——每个对应一个 ViewContainer 视图（≤150 行）
   │  ├─ MainView.tsx
   │  └─ SettingsView.tsx
   ├─ components/         # 可复用 UI 组件——被 views/ 或外部引用（≤150 行）
   │  └─ Toolbar.tsx
   ├─ hooks/              # React hook——use* 前缀，一个文件一个 hook（≤150 行）
   │  └─ useToolbarState.ts
   ├─ services/           # 业务逻辑——数据模型、状态管理、API 封装（≤200 行）
   │  ├─ model.ts
   │  └─ api.ts
   ├─ utils/              # 纯函数工具——无副作用、无实例状态（≤150 行）
   │  └─ format.ts
   ├─ styles/             # CSS 文件——每个视图/组件一个 .css，不内联（≤300 行）
   │  ├─ MainView.css
   │  └─ Toolbar.css
   └─ __tests__/          # 测试——与被测文件同名 + .test 后缀，保持相同相对路径
      ├─ services/
      │  └─ model.test.ts
      └─ views/
         └─ MainView.test.tsx
```

## `README.md` / `CHANGELOG.md`——说明与更新日志

> 🔥 **2026-09-11 E6#90a**（第 3.7.1 轮规范文档对齐）。**此前本文档一个字都没提这两个文件**，于是「补说明 / 补日志」这类事**没有权威判据**。这一节就是那把尺子。

### 分工与读者

| 文件 | 喂给谁 | 缺了会怎样 |
|:--|:--|:--|
| **`README.md`** | 插件详情页「**详情**」页签（Markdown 渲染，支持图 / 视频 / 外链——见 [12-README说明区媒体契约](12-README说明区媒体契约.md)） | 详情页**只剩一句 `description`** |
| **`CHANGELOG.md`** | 插件详情页「**更改日志**」页签 | 该页签显示**「该插件未附带更改日志」** |

### 位置固定——放插件根目录，不声明路径

两者都放**插件根目录**（与 `plugin.json` 同级），**文件名固定**。**不写进 `plugin.json`、不看任何字段**——读取方按**固定文件名**读包内文件。

> 🔴 **为什么把这条写死**：`plugin.json` 曾经有过 `readme` / `changelog` 两个字段，但**从无读取方**（读取方直接读 `README.md` / `CHANGELOG.md` 这两个**文件名**）。留着它 = 留一个**骗人的写法**。**2026-09-11 已删除** ⇒ **见到任何「在 `plugin.json` 里记说明 / 记更新日志」的写法，都是过期资料。**

### `CHANGELOG.md` 的格式约定

SDK `publish` 要从它**切段**填目录条目，所以**段标题格式有约束**：

```markdown
# 更新日志                  ← 文档标题（内容自由）

## v1.0.0（2026-09-11）      ← 🔴 版本段标题：`## v<版本号>`
- 修了某某问题
- 加了某个能力

## v0.9.0（2026-08-01）      ← 旧版本往下排，最新在最上
- …
```

- **段标题必须能解析出版本号**——`## v1.0.0…` / `## 1.0.0…` 都认（`v` 可省），**版本号严格等于 `plugin.json` 的 `version`**。
- **解析不出版本号 → 该版本的目录条目留空**（**诚实留空，不猜**）。
- **日期写在标题行括号里**（`（2026-09-11）`）——**只用于展示**。
- **标题之外的正文 = 该版本的变更说明**——Markdown 原文照搬，不做二次解析。
- **版本倒序**（最新在最上）——详情页按此顺序渲染。

### 🔴 「一个概念一处表达」铁律

> **`plugin.json` 里没有 `changelog` / `readme` 字段，也不会有。**
> 更改日志**只**写 `CHANGELOG.md`；说明**只**写 `README.md`——同一件事**只有一个住处**。

这条要**显式写下来**：旧写法在旧提交、旧文档、旧插件里还有残影，**不写清楚，下一个人会照着抄回去**。

### 与版本号联动

改 `README.md` / `CHANGELOG.md` 的内容 **= 内容变更 = 必须 bump `plugin.json.version`**，并重新构建分发件——已装用户的副本**按版本固化**，软件只补缺失、永不刷新已装（详见 [04-插件分发格式 §四](04-插件分发格式.md)）。

**`version` 是三处的锚**：`CHANGELOG.md` 段标题的版本号 ↔ `plugin.json.version` ↔ 目录条目 `versions[].version`——**三处同源**。

---

**⚠️ 插件源码目录不产生构建产物（Vite 开发 chunk 是构建内部物，不落 `dist/`）。** 分发物 = 用 plugin-sdk 构建的单文件 `<id>.linkdesk-plugin` zip（内含 `index.bundle.js` + `views/*.bundle.js` + 改写后的 plugin.json，loader 检测到 `index.bundle.js` 即以 bundle 为入口）——作者不需要关心构建产物，只管上面的源码结构；分发细节见 [04-插件分发格式](04-插件分发格式.md)。

## 静态资源与图标

**图标位置：** 插件根目录 或 `resources/`——由 `plugin.json` 的 `icon` 字段声明。裸字符串 = 内置图标集（codicon 名 / `iconSource:"lucide"` 白名单名），如 `"icon": "FolderTree"`；路径 = 相对插件目录的文件，如 `"icon": "resources/icon.png"`（serial-monitor 官方用法）。

> ℹ️ **规范收口**：新插件把图标与媒体**一律放 `resources/`**（见 [12-README说明区媒体契约 §三](12-README说明区媒体契约.md)）。「根目录也行」是**技术事实**（壳按你声明的相对路径解析），**不是推荐写法**——官方范本统一用 `resources/`，跟齐即可。

**读取资源（作者视角 = 只声明相对路径，壳解析）：** plugin.json 声明字段里出现的资源路径（`icon` / `contributes.views[].render` / 主题配方 json 的 `assets/...`）一律写**相对插件目录**——壳在加载/渲染时经 `getPluginAssetPath(pluginId, path)` 解析成当前协议下的绝对 URL（dev `http://localhost:1420` 与打包后 `file://` 通吃）。**作者不 import 任何路径工具、不手拼 URL**（硬约束 12 禁的是作者手写 `/assets/...`、`/resources/...` 等绝对路径字面量——打包后 file:// 下全炸，dev 能工作只是巧合）。

```
resources/
├─ icon.svg             # 插件图标——plugin.json icon 字段指向
├─ logo.png             # 详情页/市场横幅图
└─ manual.html          # 附带文档（`docs` 字段指向）
```

## 主题插件目录（themes/ + assets/——禁平铺根目录）

> 主题 = 纯数据插件（`contributes.themes` 声明 + 配方 json + 资产），通常**不产 `src/` 代码**。目录规范权威：[11-主题制作](11-主题制作.md) §2 ⓪。

```
theme-myglass/
├─ plugin.json           # contributes.themes 声明——配方 json 路径指向 themes/ 下
├─ themes/               # 配方 json 唯一住处——禁止平铺在插件根目录
│  └─ myglass.json
├─ assets/               # 字体（woff2/ttf）+ 背景图（png/jpeg/webp）——json 相对路径
│  ├─ MyFont.woff2
│  └─ bg.png
└─ resources/            # 插件图标等（上方通用约定）
```

| 目录 | 放什么 | 规则 |
|:--|:--|:--|
| `themes/` | 配方 json（`appearance` + `colorways[]`） | **禁止平铺根目录**；`contributes.themes[].path` 指向；一个插件可多个配方 json |
| `assets/` | 字体/背景图 | json 写相对路径 `assets/...` → 壳 `getPluginAssetPath` 解析；禁绝对路径（硬约束 12） |
| `resources/` | 插件图标 | 通用约定（上方「静态资源与图标」） |

主题作者带 `src/`（如自定义 UI/脚本）时按通用结构走——纯数据主题没有 `src/`。

## 每类文件的判断标准

> 🔥 **2026-09-11 E6#84b 补「行数上限」列**（第 3.6 层文件整理层）。**上限由 `npm run check` 里的体积门禁机械执行**——权威规则见 [壳目录规范 §7.8](../开发管理/壳目录规范.md)，本节是作者的第一手依据。**超限必拆**（走 feature-folder，见下）。

| 目录 | 放什么 | 不放什么 | 行数上限 |
|:--|:--|:--|--:|
| **views/** | 页面级 React 组件——有独立路由或 ViewContainer 入口 | 工具栏按钮、状态栏条目（→ components/） | ≤150 |
| **components/** | 可复用 UI 组件——被多处引用的无状态/弱状态组件 | 直接操作文件系统的逻辑（→ services/） | ≤150 |
| **hooks/** | React hook——`use*` 前缀，**一个文件一个 hook** | 组件（→ components/）、service（→ services/） | ≤150 |
| **services/** | 业务逻辑、数据模型、API 封装 | JSX 渲染代码（→ views/ 或 components/） | ≤200 |
| **utils/** | 纯函数工具——无副作用、与 UI/业务无关的通用函数（格式化/解析/数学） | 有状态/有副作用逻辑（→ services/）；React hook（→ hooks/） | ≤150 |
| **styles/** | 独立 .css 文件——每个视图/组件一个 | 内联 style（禁止手写——走 CSS 变量） | ≤300 |
| **resources/** | 静态资源——图标/字体/图片/文档（相对路径声明，壳解析） | 会被 import 的模块（→ src/） | — |
| **`src/` 根单件** | 跨层共享的类型定义（`types.ts`）/ 常量（`constants.ts`） | 有逻辑的模块（→ 各 role 夹） | ≤150 |
| **`src/index.tsx`** | 插件 entry（薄门面，注册贡献点） | — | ≤120 |
| **__tests__/** | Vitest 测试——`<被测文件名>.test.ts(x)` | 测试辅助工具（→ `__tests__/helpers/`） | 不限（>1000 行按 describe 组拆同夹多文件） |

🔴 **上表是你自己写的目录**（`views`/`components`/`hooks`/`services`/`utils`/`styles`）。**另建顶层目录 = 门禁当场报错**（fail-loud：「未知 role 夹」）——这不是拦你，是**逼你显式说清「这是什么角色、该给多少行」**。诚实的做法是**登记**（例：serial-monitor 的 `cm6/` = CodeMirror 纯逻辑域，登记为 150 档），**不是**把代码挪进 `utils/` 去凑表。**这条加进规范前，先想清楚它是不是真的一类新东西。**

🔴 **`.css` 一律 300，不看它放在哪个目录**——组件自带样式（co-located，如 `views/SettingsView.css`）与 `styles/` 下的 CSS 用同一把尺。

🔴 **聚合器档（上限 ×2）——两形**：门面长什么样，取决于它有没有「basename 约束」。

| 形 | 长什么样 | 谁用 |
|:--|:--|:--|
| **(a) 夹旁散门面** | 文件 `X.ts(x)` 旁边**存在同名夹 `X/`** | `views/`——文件名 = `contributes.views[].render`，**改名即改产物** ⇒ 门面只能留在夹旁、只能叫原名 |
| **(b) 夹内入口** | 路径是 **`<roleDir>/<Feature>/index.ts(x)`** | `services/` / `components/` / `hooks/` / `utils/`——服务名/组件名不是任何声明字段（**无 basename 约束**）⇒ 门面就是夹的入口，根目录不留额外散件 |

两形都按本档 **×2** 计（`views`/`components`/`hooks`/`utils`→300 · `services`→400）。**这是上限放宽不是目标值**——门面仍应尽量薄，且**不许含纯逻辑**（纯函数/数据变换/类型必须下沉子模块）。

> ⚠️ **别把「同名夹」当成唯一判据**——你在 `services/` 下建 `services/foo/index.ts` + 子模块时，**门禁认它是聚合器**（形 b）。反过来，`views/` 下**不要**把门面改叫 `index.tsx`——那会改掉 `render` 指向的名字。

> **超限处置**：走 **feature-folder（同名夹 = 聚合器 + 子模块）**——门面保留原路径原文件名（**外部 import 零变更**），子模块进同名夹。**禁止拆成同 domain 平铺多文件。**

> 🔔 **夹宽黄灯（阈值 12）——只提醒，不阻断**：**一个夹的直接子项（文件 + 子夹）超过 12 个**时，`npm run check` 会打一条提醒（**`check` 照样绿**）。它不拦你，只逼你**看一眼 + 给一句理由**——实测 14 盏、逐盏有结论，见 [06 §三](../02-Electron架构/E6_插件生态与发布/文件整理层/06-目录结构二次收口.md)。**别为了消灯去建 3 文件的碎片夹**——那比平铺更糟。一个夹很宽==往往说明里面藏着两三个不同的功能域，值得一读。
>
> 📌 **门禁怎么读**：收尾那行会打出当前生效的档位（`档 A … ；档 B plugins/<id>/src 按角色表 · 档 C entry ≤120`）。**若哪天插件档被关掉，那行会变成 `⚠️ 插件档已关闭——插件域当前无人看管`**——所以「门禁在不在岗」是**看输出就知道**的，不用去读脚本。

### 判断流程

```
这个文件包含 JSX/React 渲染？
  ├─ 是 → 它是对应一个 ViewContainer 的页面吗？
  │        ├─ 是 → views/
  │        └─ 否 → components/
  └─ 否 → 它是 React hook（use* 前缀）吗？
           ├─ 是 → hooks/（一个文件一个 hook）
           └─ 否 → 它操作数据/状态/文件/网络吗？
                    ├─ 是 → services/（有副作用）
                    └─ 否 → 它是纯函数（无状态无副作用）吗？
                             ├─ 是 → utils/
                             └─ 否 → 它是 CSS 吗？
                                      └─ 是 → 跟它服务的视图/组件放一起（co-located 合法），
                                              否则放 styles/。**门禁按扩展名管（恒 300），
                                              不看它放在哪个目录**
                                               ├─ 是 → __tests__/
                                               └─ 否 → src/（根目录，特殊情况）
```

### 🔴 `utils/` 与 `services/`、`hooks/` 的边界（2026-09-11 E6#84b 补）

`utils/` 只收**纯函数**——无实例状态、无副作用、不碰 React。**两条机械判据**：

- **有实例状态 / 有副作用**（持有 `Map`/`Set`/缓冲区、读写盘、发 IPC、维护单例）→ **不进 `utils/`，进 `services/`**。
- **是 React hook（`use*`）** → **不进 `utils/`，进 `hooks/`**。

> **实况教训**：`serial-monitor/src/utils/` 里曾同时躺着 `RingBuffer.ts`（**有状态的类**）与 `useSendData.ts`（**React hook**）——两个都不该在 `utils/`。这条边界以前没写死，作者只能靠猜。

### 🔴 `__tests__/` 的路径与命名（2026-09-11 E6#84b 明确化）

**`__tests__/` 是插件层约定，一律使用**——壳层测试走壳自己的结构（`src/**/` 与壳代码同夹紧邻），**插件不采用同夹紧邻**（那是壳层做法）。插件测试用 Vitest。

**命名**：`<被测文件名>.test.ts(x)`——**`__tests__/` 内保持与被测文件相同的相对路径**：

```
src/services/model.ts        → src/__tests__/services/model.test.ts
src/views/MainView.tsx       → src/__tests__/views/MainView.test.tsx
src/views/Detail/state.ts    → src/__tests__/views/Detail/state.test.ts
```

**行数**：测试文件**不受体积门禁约束**（门禁跳过 `__tests__/`）——fixture 天然长，不设上限；**但 >1000 行的测试按 `describe` 组拆到同夹多文件**。

> ⚠️ **迁移既有测试时最易翻车的点**：测试文件加深一层后，**所有相对 import 全变**（`./model` → `../../services/model`）。**漏改的表现是 Vitest 静默跳过该文件（`0 test`）而不是报错**——迁完必须核对用例总数没掉。

- **`index.tsx`**——插件入口，必须放在 `src/` 根
- **高度内聚的单文件插件**（总文件数 ≤ 3）——不强制建子目录
- **跨层共享的类型定义**（如 `types.ts`）——放 `src/` 根，被多个子目录 import

## `i18n/` 翻译目录

插件自带翻译文件，每种目标语言一个 JSON。key = 插件 UI 字符串原文（建议用作者母语），value = 译文。

```
i18n/
├─ en.json     ← { "在文件树中显示": "Reveal in File Tree" }
└─ ja.json     ← { "在文件树中显示": "ファイルツリーで表示" }
```

**声明：** `plugin.json` 的 `contributes.i18n` 字段声明各语言文件路径：
```json
"contributes": {
  "i18n": { "en": "i18n/en.json", "ja": "i18n/ja.json" }
}
```

**不需要为作者母语写回退文件**——缺译文的 key 由 `parseMissingKeyHandler` 返回原文：中文插件不必建 `zh.json`，纯英文/纯法文插件同样不必为英文/法文建回退文件——key 就是原文，缺译文时静默回退显示 key 本身。

**翻译对象：** `plugin.json` 中的 `title`/`description`（命令、配置项、视图容器名）+ `.tsx` 中 `t()` 调用的 UI 字符串。

**切语言行为：** 壳自动加载各插件的 `contributes.i18n` → 注册到 i18next → 切语言时即时生效，无需重启。渲染时调 `t()` 即可，不要求 `namespace` 参数——翻译注册在全局 `"translation"` 命名空间。

## 命名约定

- **文件名：** PascalCase（组件）、camelCase（非组件）、kebab-case.css（样式）
- **测试文件：** `<被测文件名>.test.ts(x)`——放 `__tests__/`，**内保持与被测文件相同的相对路径**（见上方「`__tests__/` 的路径与命名」）
- **CSS 文件：** 与被 styled 的组件同名——`MainView.tsx` → `MainView.css`

## 对标 VS Code

VS Code 扩展没有强制目录结构，但官方示例遵循类似约定：

| VS Code | LinkDesk |
|:--|:--|
| `src/extension.ts` | `src/index.tsx` |
| `src/commands/` | 无——命令在 `index.tsx` 中注册 |
| `src/views/` | `src/views/`——完全相同 |
| `src/test/` | `src/__tests__/`——Vitest 约定双下划线 |
| `media/` | `src/styles/`——LinkDesk 统一放在 src 下 |
| `package.nls.json` / `l10n/` | `i18n/`——LinkDesk key=中文原文，只提供目标语言 JSON |
