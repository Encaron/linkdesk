# 第一部分：设计方案（2026-07-24）

## 一、主题三层退路（照抄 VS Code）

| 层 | VS Code | LinkDesk |
|------|------|------|
| 第 1 层 | `settings.json` → `workbench.colorTheme` | `settings.json` → `app.theme` |
| 第 2 层 | `theme-defaults` 扩展（10 个内置主题，可卸载） | `plugins/theme-defaults/`（出厂预装，可卸载） |
| 第 3 层 | `defaultThemeColors` 硬编码对象 | `index.css` `:root` 的 CSS 变量值 |

```
#2 出厂主题：
  plugins/theme-defaults/plugin.json → {"contributes":{"themes":[{"id":"dark","uiTheme":"dark","path":"dark.json"}]}}
  卸载后回退到第 3 层。

#3 硬兜底：
  index.css :root { --bg: #1e1e1e; --fg: #cccccc; ... }
  永远存在。不依赖任何插件或 JSON 文件。
```

---

## 二、主题贡献格式（对标 VS Code `themeExtensionPoints.ts`）

```json
{
  "name": "Dracula",
  "contributes": {
    "themes": [
      {
        "id": "dracula",
        "label": "Dracula",
        "uiTheme": "dark",
        "path": "dracula.json"
      }
    ]
  }
}
```

**和 VS Code 的差异：**
- `uiTheme` 值：`dark` / `light` / `highContrast`（简化——我们没有 textmate token 渲染）
- `path` 指向 CSS 变量 JSON（VS Code 指向 .tmTheme）
- `id` 用于 `settings.json` 的 `app.theme`

**兼容逻辑：** loader 检测主题——有 `contributes.themes` → 新格式注册；有旧 `file` 字段 → 升级为 contributes.themes 等价注册。

---

## 三、CSS 变量跨进程广播

多 WebView 后，主题切换的核心问题：

```
切到 Dracula：
  1. 壳读 dracula.json → 得到 CSS 变量键值对
  2. 壳写入自己的 :root（壳 WebView 生效）
  3. 壳通过 IPC 广播给所有插件 WebView
     → { channel: "theme:changed", payload: { themeId, variables: {"--bg":"#282a36",...} } }
  4. 插件 WebView 收到 → 动态注入 <style> 覆盖 :root
```

## 五、产品图标主题（Product Icon Theme）

消费 ThemeRegistry，插件可贡献图标集：

```json
{
  "contributes": {
    "productIconThemes": [
      { "id": "codicon", "label": "Codicon", "path": "codicon.json" }
    ]
  }
}
```

图标引用：`{ "icon": "folder", "iconSource": "codicon" }`。未指定 iconSource → 默认图标集。

# 第二部分：敌对审计与加固（2026-07-26）

## 八、架构澄清——两种齿轮，两个归属（✅ 正确）

| | 全局左下齿轮 | 插件卡片齿轮 |
|---|---|---|
| `MenuId` | `ExtensionGear` | `MarketplaceItemGear` |
| 位置 | 图标栏底部（`iconLocation: "bottom"`） | 插件卡片右侧 ⚙ 按钮 |
| 消费方 | `IconBar.tsx`（壳） | `marketplace/sidebar.tsx`（插件） |
| **菜单项由谁注册** | **核心** (`coreCommands.ts` + `APP_PLUGIN_ID`) | **marketplace 插件** (`ensureMarketplaceCommands()`) |
| 换 marketplace 插件后 | 全局齿轮不受影响 | 新 marketplace 自己注册 per-plugin 菜单项 |

**大厅模型的正确理解：** `MenuRegistry` = 大厅里的"菜单本"桌子，`ContextKeyService` = 大厅里的"条件本"桌子。全局齿轮 → 核心登记到 ExtensionGear 分区。插件卡片齿轮 → marketplace 插件登记到 MarketplaceItemGear 分区。**这是 Encaron 的设计，不是违规。**

## 十、运行时健壮性——13 漏洞审计

> 敌对审计方法：假设每次 async 都有竞态、每个模块变量都是陈旧的、每次清理都漏了。

### 🔴 高严重度（3 个）

**H1. FactorySlots 不支持运行时热换。** `initialize()` 只在启动时调用一次。卸载旧设置插件 → slot 仍指死 ID。修复：加 `refreshFromPlugins()` 方法（→ ⏭️ #36e2b 已覆盖）。

**H2. revertThemeIfCurrent 漏掉旧格式主题。** `ThemeRegistry` 只存新格式 `contributes.themes`（由 `parseContributions` 注册）。旧格式 `manifest.themes` 调了 `registerTheme()` 但没调 `ThemeRegistry.register()`。卸载旧格式主题插件 → 当前主题不回退。修复：`loadThemePlugin()` 中也调 `ThemeRegistry.register()`（→ #36f1）。

**H3. loadPluginRuntime /@fs/ 端点在生产环境不可用。** Vite dev server 专有端点。Electron 生产构建中无 Vite → 动态 import 失败。修复：生产环境用 `linkdesk://` 加载（→ #36f15）。

### 🟠 中严重度（5 个）

**M1. SettingsView consumeSettingsGroup 空依赖——设置已打开时不跳转**（→ #36f7+#36f8）
**M2. 没有内置 "Dark"/"Light" 兜底注册**（→ #36f2）
**M3. setConfigurationValue 不做枚举验证**（→ #36f9，⚠️ 验证需清 localStorage）
**M4. 旧+新格式 themes 共存时双重注册**（→ #36f4）
**M5. 注册机制双轨——merge vs mutate 竞争**（→ #36f3，删 App.tsx 二次 registerConfiguration）

### 🟡 低严重度（5 个）

**L1. Context keys 不清理**（→ #36f10）
**L2. 枚举原地突变依赖 React 批处理**（→ #36f11，注释标记时序依赖）
**L3. ThemeBrowser 打开时不订阅生命周期**（→ #36f12）
**L4. revertThemeIfCurrent 未被 await**（→ #36f13）
**L5. 旧格式 theme/language 互斥——`else if` → 独立 `if`**（→ #36f14）

## 十一、扩展审计——E1-E3 全量原则对照

> 检查大厅模型、核心无知、归一化、硬约束、注册/注销对称性。

### 🔴 硬约束违规

**H4. `coreCommands.ts`——18 处中文硬编码未走 `t()`**（→ #36i1）。CLAUDE.md 硬约束 #2 违规。18 个字段——`"设置"` / `"命令面板"` / `"选择颜色主题"` 等。切换到英文后仍显示中文。

**H5. `lifecycle.ts`——`unregisterPluginFileAssociations` 死代码，从未被调用**（→ #36i2）。消费端 2b 注销了 8 个注册表——唯独漏了文件关联。每次卸载/禁用时文件关联泄漏。

**H6. `loader.ts`——i18n 语言资源从未注销**（→ #36i3）。`loadLanguagePlugin` 调 `i18n.addResourceBundle()`。lifecycle.ts 无任何消费端调 `i18n.removeResourceBundle()`。卸载/禁用语言插件后翻译永久残留。

### 🟠 E2b 归一化不完整——声称 DONE 但未落地

**M6. 串口术语仍在核心代码中**（→ #36h1-#36h3）。E2b #8 声称 "portName→sourceName" 完成，但 `CoreEvents.ts` 仍用 `portName`；`SourceStateContext` 仍有 `PortInfo` 类型；`resetTerminalCounter` 硬编码 `"terminal"` 插件 ID。

**M7. `tabIdentity.ts` 硬编码 6 个插件 ID**（→ #36i4）。`FALLBACK_META` 表含 terminal/workspace/settings/marketplace/oled/editor——违反硬约束 #10。

**M8. `LayoutService.ts` `LEGACY_TAB_IDS` 硬编码 4 个插件 ID**（→ #36i5）。过渡性遗留迁移桥接（B78），但核心代码中存有插件 ID 字面量。

### 🟠 注册/注销不对称

**M9. 终端命令注册无清理**（→ #36k2）。`TerminalView` 在 `useEffect` 中注册 12 个命令，无对应清理。组件卸载后 handler 保留在 `CommandRegistry` 中——handler 调 `getActiveCmd()!` → **crash**。

**M10. `loadThemePlugin` 不调 `ThemeRegistry.register()`**（→ #36f1 已覆盖）。

### 🟡 归一化问题

**L6. `loadPlugin` ↔ `loadPluginRuntime` 两条路径不同步——🔥 系统性 bug 工厂**（→ #36j1）

| 能力 | `loadPlugin` | `loadPluginRuntime` | 修复 |
|------|:--:|:--:|------|
| 加载 sidebar.tsx | ✅ glob | ❌ → Bug 3 无侧栏 | `03d0f01` |
| 加载主题 JSON 数据 | ✅ getPluginDataFile(glob) | ❌ → 空壳主题 | `cea1476` |
| 重装后出现在已安装列表 | ✅ glob 可见 | ❌ → #34 bug 6 | metadata cache 路径 |

修复：提取 `applyPostLoadSteps(pluginId, manifest, reason)` 共享函数。**不是消重复——是堵缝。** 从此不再出现"glob 路径有、runtime 路径没有"这类 bug。

**L6b. 生命周期事件顺序无机械保障——🔥 同一类缝的不同表现。** A 需要 B 还没改的状态，但 A 在 B 之后执行。编译器不报错、运行不崩溃——静默跳过。已发生 3 次：`revertThemeIfCurrent` / lifecycle toast / marketplace 列表刷新。暂无机械方案——当前靠代码注释 + git blame。

**L7. ThemeEngine ↔ ThemeRegistry 重复 `pluginId → theme names[]` 映射**（→ #36e2c 评估合并）
**L8. 主题颜色提取循环 ×3**（→ #36j2，提取 `extractThemeColors`）
**L9. `appendToIconOrder` ↔ `removeFromIconOrder` 近重复**（→ #36j3，提取 `updateIconOrder`）
**L10. 两个竞争的事件系统**（待 Phase 6 统一，当前不改）
**L11. Settings/workspace 插件是薄包装器**（非紧急）

## 🔥 UAT 发现——Encaron 实测（2026-07-27）

> `loadPlugin`↔`loadPluginRuntime` 两条路径不同步和生命周期时序问题的再次发作。

**L6b——卸载当前主题不回退。** `revertThemeIfCurrent` 在 `onWillUninstall` 之后执行 → 主题已注销 → revert 静默跳过。修复：revert 移到 onWillUninstall 之前。`1ba6a25`

**L6——重装后主题无颜色（空壳）。** `parseContributions` 中 `getPluginDataFile` 依赖 glob，runtime 插件不在 glob 中 → ThemeEngine 无颜色数据。修复：runtime 路径从文件系统 fetch JSON 补充注册。`cea1476`

两个 bug 根因相同——L6 两条路径不同步 + L6b 生命周期时序无机械保障。堵缝靠 #36j1。
