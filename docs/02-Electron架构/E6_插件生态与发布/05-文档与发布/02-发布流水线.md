## 一、GitHub Actions CI（E6#42）

### 1.1 工作流

文件：`.github/workflows/build.yml`

```yaml
name: Build and Release

on:
  push:
    branches: [electron]
    tags: ["v*"]

jobs:
  build:
    runs-on: windows-latest

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22

      - name: Install dependencies
        run: npm ci

      - name: Check
        run: npm run check

      - name: Build
        run: npm run electron:build

      # TODO: v1.0 发布前启用代码签名
      # 方案 A——Azure Trusted Signing（免费预览期）
      # - name: Sign Windows executable
      #   uses: azure/azure-trusted-signing-action@v1
      #   with:
      #     path: release/*.exe
      #     endpoint: ${{ vars.AZURE_SIGNING_ENDPOINT }}
      #     account: ${{ vars.AZURE_SIGNING_ACCOUNT }}
      #     profile: ${{ vars.AZURE_SIGNING_PROFILE }}
      # 方案 B——开源免费证书（SignPath Foundation）
      # - name: Sign Windows executable
      #   uses: signpath/github-action-submit-signing-request@v1
      #   with:
      #     artifact-path: release/*.exe
      #     organization-id: ${{ vars.SIGNPATH_ORG_ID }}
      #     api-token: ${{ secrets.SIGNPATH_API_TOKEN }}
      # 方案 C——正规证书（DigiCert/Sectigo，$200-500/年）
      # - name: Sign Windows executable
      #   run: |
      #     signtool sign /fd SHA256 /a /f certificate.pfx /p ${{ secrets.CERT_PASSWORD }} release/*.exe

      - name: Upload artifact
        uses: actions/upload-artifact@v4
        with:
          name: LinkDesk-Setup
          path: release/*.exe

      - name: Release
        if: startsWith(github.ref, 'refs/tags/v')
        uses: softprops/action-gh-release@v2
        with:
          files: release/*.exe
          generateReleaseNotes: true
```

### 1.2 触发条件

| 事件 | 干什么 |
|:--|:--|
| push 到 `electron` 分支 | build + check + 上传 artifact |
| push tag `v*` | build + check + 发布到 GitHub Releases |

### 1.3 Release 步骤

```
push tag v1.0.0
  → CI 跑 build + check
  → 产出 LinkDesk Setup 0.1.0.exe
  → 创建 GitHub Release v1.0.0
  → 上传 .exe
  → 自动生成 Release Notes
```

## 二、官网下载页（E6#43）

### 2.1 方案

**最简版：** GitHub Pages + 静态 HTML

```
github.com/encaron/linkdesk.io/
  └── index.html → 重定向到下载页

linkdesk.io/download/
  └── index.html
      - Windows 下载按钮 → 指向最新 GitHub Release 的 .exe
      - 版本号
      - 系统需求
```

### 2.2 页面内容

```html
<!DOCTYPE html>
<html>
<head>
  <title>LinkDesk - Download</title>
</head>
<body>
  <h1>LinkDesk</h1>
  <p>Universal Container. Plugins for everything.</p>

  <a href="https://github.com/encaron/linkdesk/releases/latest/download/LinkDesk-Setup.exe">
    Download for Windows
  </a>

  <p>Version 1.0.0 · Windows 10/11 · 64-bit</p>

  <p><a href="/marketplace">Browse Plugins</a></p>
</body>
</html>
```

### 2.3 自定义域名

- 买域名 `linkdesk.io`（~$12/年）
- GitHub Pages → Settings → Custom domain → `linkdesk.io`
- DNS 加 CNAME 记录指向 `encaron.github.io`

## 三、发布清单（E6#44）

文件：`docs/06-发布管理/v1.0-发布清单.md`

### 3.1 发布前

```
[ ] npm run check 零错误
[ ] E5.8 全量回归矩阵场景通过
[ ] E6 全链路验证通过（E6#25 Encaron 确认）
[ ] electron-builder 配置正确（appId / productName / icon）
[ ] NSIS 安装包测试：安装 / 卸载 / 覆盖安装
[ ] 所有文件路径在打包后不404（dist/ / plugins/ / icon.ico）
```

### 3.2 发布

```
[ ] git tag v1.0.0
[ ] git push origin v1.0.0
[ ] 等待 GitHub Actions build 完成
[ ] 检查 GitHub Release 页面——.exe 存在
[ ] 更新 linkdesk.io/download 的版本号和下载链接
```

### 3.3 发布后

```
[ ] 从官网下载安装包 → 安装到干净电脑
[ ] 启动 → 全功能正常
[ ] 市场安装一个插件 → 正常
[ ] git checkout -b v1.0.x（创建维护分支）
```
