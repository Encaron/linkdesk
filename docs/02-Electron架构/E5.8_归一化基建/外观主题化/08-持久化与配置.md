## 2. 播种先例（appearanceMode → custom）

对标现有 accentMode→custom 的真实代码（startup.ts L101-105：读当前 DOM `--accent` 播种 `app.accentColor`）：

> 用户切 `appearanceMode: custom` 的瞬间，把**当前生效值**（来自配方）播种进 6 个覆盖 key——不是从 0/默认值开始。否则一开覆盖，玻璃归零、圆角回 1×，配方被「重置」。

```
appearanceMode: followTheme → custom
  → 读 ThemeEngine.getEffectiveTokens()（[06](06-主题API契约.md)）
  → app.surfaceRadius = 当前 --radius-md / 配方半径 …（反向除 scale）
  → app.glassBlur = 当前 --glass-blur（配方值）
  → …6 项全播种
```

用户动 slider = 覆盖配方值（绝对）；切回 followTheme = 覆盖丢弃回配方。**设置层永远只存用户偏离量**，配方是默认。

## 3. scale vs 绝对——粒度决策（拍板 2026-08-23 提案）

| 项 | 粒度 | 理由 |
|:--|:--|:--|
| 圆角 | **scale 系数**（×0.5–2） | 八档有**层级差异**（xs→2xl），乘算保留相对差异，一个 slider 整体缩放（[04 §4](04-两层调节与设置页.md)） |
| 玻璃 | **绝对覆盖**（blur px / opacity / tint） | `--glass-*` 是连续单值，无 per-surface 档位可缩放；用户心智 =「拉模糊到 18」 |

> 修订说明：04 §4 拍板时玻璃也是 scale；本文档精化为「玻璃走绝对」——玻璃没有八档语义，scale 无意义，绝对覆盖更直观。#50.10 的 `app.glassBlur` 键名本就是 px 语义，与本文一致。
>
> **scale 乘算边界（2026-08-24 审视补）：** ×0.5–2 只乘 **`--radius-xs`~`--radius-2xl` 六档**（尺寸值）；**`--radius-pill`(999px) 与 `--radius-full`(50%) 是形态值，排除不乘**——否则胶囊 ×1.5 → 1498px、圆形 ×1.5 → 75% 椭圆，胶囊/圆形态被拖破。scale=1 时八档全 = 主题原值（兜底恒成立）。

### 7.3 接线总则（实现约束）

1. **注册唯一入口**：全部走 `src/App/startup.ts` `registerConfiguration`（L61），挂第二个配置贡献 `pluginId:"appearance"`（标题「主题」，§5）——主题组 key 全挂它。
2. **控件 = uiHint 声明驱动**：settings 插件 `renderControl.tsx` switch（L27-62）按 uiHint 渲染——本表每行 uiHint 对应一个分支（已有：`color`/`fontFamily`/`file`/`select`；新增：`slider`/`themePicker` + `optionsFrom` 动态源）。
3. **显隐 = dependsOn 声明驱动**：SettingRow `if (prop.dependsOn && depValue !== prop.dependsOn.value) return null`；`optionsFrom` 是**渲染器扩展**，不改主进程配置注册表结构。
4. **生效单一写入点**：所有 key 的 onApply → ThemeEngine 覆盖面（对标 accentColor），避免 onApply/applyTheme 双写不一致；任一 key 生效 → 广播 `theme:changed`（payload 带 tokens）。
5. **播种 = 永远只存用户偏离量**（§2）：切 custom 时反推播种，切回 followTheme 时删除覆盖 key，主题配方即默认。
