# 标签页生命周期归一化——外部事件驱动

> 2026-08-03。**E5 新增任务。** TabManager 成为标签页生命周期的唯一权威——外部事件只发 ShellEvents，TabManager 自己决定怎么响应。
> 执行清单任务：E5#54

---

## 一、前因——分散的标签页关闭逻辑

### 当前

| 外部事件 | 谁负责关闭标签页 | 状态 |
|---------|----------------|:--:|
| 串口会话删除 | `SessionListView` 调 `closeTabBySourceId` | ✅ |
| 文件树删除文件 | — | ❌ 忘了 |
| 插件卸载 | `App.tsx` PLUGIN_REMOVED handler 遍历 tabState → forceCloseTab | ✅ 但绕了路 |
| 工作区文件夹移除 | — | ❌ 没处理 |
| 文件被外部改名 | — | ❌ 没处理 |

**五个外部事件，三个地方处理，两个遗漏。** 根因：标签页的生命周期权威分散在 App.tsx、SessionListView、FileTreeContextMenu 三个地方。每次加新触发源都要记得加——和 E5 全部归一化是同一个问题。

### 目标

```
外部事件       →    ShellEvents     →    TabManager 响应
─────────          ──────────           ────────────────
文件删除           "file:deleted"       closeTabBySourceId(filePath)
文件外部改名        "file:renamed"       updateTabBySourceId → 新 sourceId+label
插件卸载           "plugin:removed"     遍历 → forceCloseTab
工作区文件夹移除    "workspace:folderRemoved"  遍历 → closeTabBySourceId
串口会话删除        "session:deleted"    closeTabBySourceId(sessionId)

所有调用方只需要知道一件事：emit 对应事件。剩下的 TabManager 做。
```

## 二、设计方案

### TabManager 集中订阅外部事件

```typescript
// src/hooks/useTabManager.ts——新增 useEffect

useEffect(() => {
  // ── 文件删除 → 关闭标签页 ──
  const unsub1 = shellEvents.on("file:deleted", (filePath: string) => {
    closeTabBySourceId(filePath);
  });

  // ── 文件外部改名 → 更新标签页 sourceId + label ──
  const unsub2 = shellEvents.on("file:renamed", ({ oldPath, newPath }: { oldPath: string; newPath: string }) => {
    const newLabel = normalizePath(newPath).split("/").pop() || newPath;
    updateTabBySourceId(oldPath, { sourceId: newPath, filePath: newPath, label: newLabel });
  });

  // ── 插件卸载 → 关闭该插件所有标签页 ──
  const unsub3 = shellEvents.on("plugin:removed", (pluginId: string) => {
    // 🔥 从 App.tsx PLUGIN_REMOVED handler 迁到这里
    // forceCloseTab——绕过 dirty guard（插件已卸载，保存无意义）
    for (const tab of allTabs.filter(t => t.pluginId === pluginId || t.type === pluginId)) {
      forceCloseTab(tab.id);
    }
  });

  // ── 工作区文件夹移除 → 关闭该文件夹下所有文件标签页 ──
  const unsub4 = shellEvents.on("workspace:folderRemoved", (folderPath: string) => {
    const prefix = normalizePath(folderPath) + "/";
    for (const tab of allTabs.filter(t => t.filePath?.startsWith(prefix))) {
      closeTabBySourceId(t.filePath!);
    }
  });

  return () => { unsub1(); unsub2(); unsub3(); unsub4(); };
}, [closeTabBySourceId, forceCloseTab, updateTabBySourceId, allTabs]);
```

### ShellEvents 加事件

```typescript
interface ShellEvents {
  // ... 现有 ...
  "file:deleted": string;                         // filePath
  "file:renamed": { oldPath: string; newPath: string };
  "plugin:removed": string;                       // pluginId
  "workspace:folderRemoved": string;              // folderPath
}
```

## 🔴 预测 Bug

### Bug E5-54a 🔴 文件删除后 TabManager closeTabBySourceId——dirty 标签页不关闭

**触发条件：** 编辑器有未保存修改 → 用户删除文件 → `file:deleted` → `closeTabBySourceId` → `reduceCloseTab` 遇到 dirty → `return { closed: false }`

**🔥 防线——E5#51 修好后自动解决：** E5#51 让 closeTab 对 dirty 标签页弹确认框 → 用户确认 → forceCloseTab → 标签页关闭。未保存内容丢失——但文件已经被删了，保存无意义。
