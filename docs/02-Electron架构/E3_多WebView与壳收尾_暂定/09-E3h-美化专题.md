## 零、现状——新 AI 必读

### 0.1 两个菜单渲染器的当前关系

```
MenuRegistry (数据源——归一化 ✅)
    │
    ├──→ TitleBar.tsx      横排菜单按钮 + 下拉面板 + 子菜单
    │    ├─ 文件: src/components/TitleBar.tsx + .css
    │    ├─ 读: getMenuItems(MenuId.MenuBar) → 按 group 分组
    │    ├─ 渲染: 每个 group 一个按钮 → 点击弹出下拉面板 → hover children 右侧子面板
    │    └─ 缺: 无快捷键显示、无 when 条件过滤、无禁用态
    │
    └──→ HamburgerMenu.tsx  ☰ 按钮 + 竖排全菜单 + 子菜单
         ├─ 文件: src/components/HamburgerMenu.tsx + .css
         ├─ 读: getMenuItems(MenuId.MenuBar) → 按 group 分组
         ├─ 渲染: 全 menu 在一个面板 → 分组显示 → hover children 右侧子面板
         └─ 有: 快捷键显示 (getKeyLabel)、hover 延迟防闪烁
```

**归一化了的（两份共用同一机制）：**
- 数据源——都读 `MenuRegistry.getMenuItems(MenuId.MenuBar)`，同一份注册数据
- 排序——都从 `order` 字段读，不再硬编码 `GROUP_ORDER`
- 标签——都从 `label` 字段读，不再硬编码 `GROUP_LABELS`
- 插件扩展——注册新 `group: "terminal"` → 两个菜单自动出现，零代码改动

**没归一化的——v2.6 风险点：**
- 菜单项渲染代码（hover 高亮逻辑、chevron 展开箭头、子面板弹出/关闭）**写了两遍**
- HamburgerMenu 有 `scheduleHover` 延迟（防闪烁），TitleBar 也有——同样的逻辑独立维护
- HamburgerMenu 显示快捷键（`getKeyLabel`），TitleBar 不显示——同一个菜单项在两个地方看起来不一样
- 将来加图标、分隔线、禁用态 → 两个组件各改一遍 → 不一致 → bug

### 0.3 MenuItem 类型（MenuRegistry.ts）

```typescript
export interface MenuItem {
  command: string;       // 命令 ID——空字符串 = 父菜单项（不执行命令）
  label?: string;        // 显示标签——已通过 i18n.t() 国际化
  group?: string;        // 分组——决定放在哪个菜单按钮/章节
  when?: string;         // context key 条件——当前未消费！
  order?: number;        // 排序——越小越靠前
  children?: MenuItem[]; // 嵌套子菜单——hover 右侧弹出
}
```

## 一、#64 `<MenuRenderer>` 归一化渲染（~80 行）

### 目标

从 TitleBar 和 HamburgerMenu 提取公共菜单渲染逻辑，归一化到一个共享组件。之后两个菜单只负责各自的**外壳布局**（横排 vs 竖排、全 menu vs 单 group），菜单项渲染全部委托给 MenuRenderer。

### 当前两份重复代码

**TitleBar.tsx 中的菜单渲染（~60 行）：**
```typescript
// renderSingleItem —— 单个菜单项
function renderSingleItem(item: MenuItem & { pluginId: string }) {
  const key = item.command + (item.label ?? "");
  const hasChildren = item.children && item.children.length > 0;
  return (
    <button
      key={`${item.pluginId}:${key}`}
      className={`titlebar-item${hoveredKey === key ? " titlebar-item-hovered" : ""}`}
      onMouseEnter={() => scheduleHover(hasChildren ? key : null)}
      onClick={() => { if (hasChildren) return; handleCommand(item.command); }}
    >
      <span className="titlebar-item-label">{getLabel(item)}</span>
      <span className="titlebar-item-right">
        {hasChildren && <span className="codicon codicon-chevron-right titlebar-chevron" />}
      </span>
    </button>
  );
}

// scheduleHover —— 防闪烁延迟
const scheduleHover = useCallback((key: string | null) => {
  if (hoverTimerRef.current) clearTimeout(hoverTimerRef.current);
  if (key === null) hoverTimerRef.current = setTimeout(() => setHoveredKey(null), 150);
  else hoverTimerRef.current = setTimeout(() => setHoveredKey(key), 100);
}, []);

// hoveredChildren 计算——当前 hover 项的 children
const hoveredChildren = (() => { /* ... */ })();
```

**HamburgerMenu.tsx 中的菜单渲染（~40 行——几乎相同的逻辑）：**
```typescript
// 同样的 getLabel、scheduleHover、hoveredChildren 模式
// 区别：HamburgerMenu 多一层 group 分组显示 + 快捷键标签
```

### 接口设计

```typescript
// src/components/shared/MenuRenderer.tsx（新）

interface MenuRendererProps {
  /** 菜单项列表 */
  items: Array<MenuItem & { pluginId: string }>;
  
  /** 点击叶子项的回调 */
  onCommand: (command: string) => void;
  
  /** 是否显示快捷键（HamburgerMenu=true，TitleBar=false） */
  showKeybindings?: boolean;
  
  /** 是否按 group 分组显示（HamburgerMenu=true，TitleBar 单 group 时=false） */
  showGroups?: boolean;
  
  /** 外部传入的 group 排序列表（showGroups=true 时需要） */
  groupOrder?: string[];
  
  /** CSS 类名前缀——用于区分两个菜单的样式命名空间 */
  cssPrefix: string; // "titlebar" | "hamburger"
}
```

### 做什么

1. **创建 `src/components/shared/MenuRenderer.tsx`**
   - 接收 items + onCommand + showKeybindings + cssPrefix
   - 内部实现：`scheduleHover` 延迟、`hoveredKey` 状态、`hoveredChildren` 计算
   - `renderSingleItem(item)`——单个菜单项按钮
   - `renderSubPanel(children)`——右侧弹出子面板
   - 当 `showGroups=true` → 渲染 group 标签 + 分组
   - 快捷键显示：当 `showKeybindings=true` → 读 `KeybindingRegistry.getKeybindings()` 显示在 item 右侧

2. **重构 `TitleBar.tsx`**
   - 删除内部 `renderSingleItem` / `scheduleHover` / `hoveredChildren` / `renderDropdown`
   - 改为调用 `<MenuRenderer items={flattened} onCommand={handleCommand} cssPrefix="titlebar" />`
   - TitleBar 保留：`openGroup` 状态、group 按钮渲染、下拉面板定位

3. **重构 `HamburgerMenu.tsx`**
   - 删除内部菜单项渲染循环（`groupItems.map(...)`）
   - 改为调用 `<MenuRenderer items={allItems} onCommand={handleCommand} showKeybindings showGroups groupOrder={sortedGroupNames} cssPrefix="hamburger" />`
   - HamburgerMenu 保留：☰ 按钮、`open` 状态、面板定位

4. **创建 `src/components/shared/MenuRenderer.css`**
   - 提取 `.titlebar-item` / `.hamburger-item` 的公共样式
   - 用 CSS 类名前缀区分两个菜单的视觉差异（如 HamburgerMenu 需要 group-label，TitleBar 不需要）

### 验证

- Ctrl+Shift+P → ☰ → File 展开子菜单 → 点击"设置" → 打开设置页 — 行为和重构前完全一致
- 顶部标题栏 → 文件▼ → "设置" → 打开设置页 — 行为和重构前完全一致
- tsc + vitest 全过

- TitleBar 和 HamburgerMenu 的代码行数各减少 ~40 行

## 二、#65 快捷键显示归一化（~10 行）

### 目标

当前只有 HamburgerMenu 显示快捷键（如 `Ctrl+,`），TitleBar 没有。统一为 MenuRenderer 的 `showKeybindings` prop 控制。

### 做什么

1. `MenuRenderer.tsx`：`showKeybindings=true` 时渲染快捷键标签

   从 HamburgerMenu 搬运 `getKeyLabel` 函数到 MenuRenderer 内部

2. HamburgerMenu 删掉自己的 `getKeyLabel` 逻辑

## 三、#66 TitleBar 声明式扩展区域（~40 行）

### 目标

对标 VS Code `titleBar` contributions。TitleBar 预留左右扩展槽，插件通过 `contributes.titleBar` 注册自定义按钮，自动渲染。

### 当前问题

TitleBar 结构硬编码在组件内部：
```
LD  ─  菜单按钮  ─  拖拽区
```

未来加"切换侧栏"按钮、"打开 AI 智能体"按钮 → 要改 TitleBar.tsx 源码。

### 槽位设计

```
┌──────────────────────────────────────────────────────────┐
│ LD  [slot:left]  文件▼ 查看▼  [slot:right]    ─ □ ×    │
└──────────────────────────────────────────────────────────┘
```

- `titlebar-left`：Logo 右侧、菜单按钮左侧——适合放导航类按钮
- `titlebar-right`：拖拽区右侧、窗口控件左侧——适合放状态/工具按钮

### 数据模型

**plugin.json 声明：**
```json
{
  "contributes": {
    "titleBar": {
      "left": [
        { "command": "workbench.action.toggleSidebar", "icon": "codicon-layout-sidebar-left" }
      ],
      "right": [
        { "command": "ai.openAgent", "icon": "codicon-sparkle", "when": "aiAvailable" }
      ]
    }
  }
}
```

**类型扩展（MenuRegistry.ts）：**
```typescript
export interface TitleBarContribution {
  command: string;
  icon?: string;         // codicon 类名或图片路径
  when?: string;         // context key 条件
  order?: number;
}
```

### 做什么

1. **`src/core/MenuRegistry.ts`**：加 `registerTitleBarContribution(pluginId, slot, item)` + `getTitleBarContributions()`
   - 对标 `registerMenuItems` 的简约版——只存 command+icon+when

2. **`src/components/TitleBar.tsx`**：
   - 在 Logo 后渲染 `titlebar-left` slot：`getTitleBarContributions("left")` → map → `<button>` 
   - 在拖拽区后渲染 `titlebar-right` slot
   - 每个按钮：点 `icon` 显示 → 点击 `executeCommand` → `-webkit-app-region: no-drag`

3. **`src/pluginLoader/loader.ts`**：`parseContributions` 中加 `contributes.titleBar` 处理

### 验证

- 创建测试插件声明 `contributes.titleBar.left: [{ command: "core.openSettings", icon: "codicon-settings" }]`
- TitleBar Logo 右侧出现齿轮按钮 → 点击 → 打开设置
- 卸载插件 → 按钮消失
- 没有 `contributes.titleBar` 的插件 → TitleBar 外观不变（零影响）

## 四、#67 菜单 when 条件 + 禁用态（~20 行）

### 目标

当前菜单项注册了 `when` 字段但两个渲染器都没消费。对标 VS Code——不满足 when 的项 **保留位置但灰显禁用**（不是隐藏）。

### 为什么保留位置而不是隐藏

- VS Code 的菜单结构是用户可以学习的——命令 A 永远在命令 B 上面
- 隐藏 → 菜单内容随状态跳动 → 用户找不到命令 → 困惑
- 灰色禁用 → 用户看得见但知道"现在不能用" → 不加困惑

### 做什么

1. **`MenuRenderer.tsx`**：渲染每个 item 前求值 `when`
   ```typescript
   const disabled = item.when ? !ContextKeyService.matches(item.when) : false;
   ```
   传 `disabled={disabled}` 到按钮 → CSS 类 `menu-item-disabled`

2. **`MenuRenderer.css`**：
   ```css
   .menu-item-disabled {
     opacity: 0.4;
     cursor: default;
     pointer-events: none;
   }
   ```

3. **TitleBar + HamburgerMenu 自动受益**——因为渲染归一化到 MenuRenderer 了

### 验证

- 注册 `{ command: "test", when: "sourceOpen" }` → sourceOpen=false 时该项灰显
- 打开串口 → sourceOpen=true → 该项可点击
- 灰显项不可点击，不触发 `onCommand`
