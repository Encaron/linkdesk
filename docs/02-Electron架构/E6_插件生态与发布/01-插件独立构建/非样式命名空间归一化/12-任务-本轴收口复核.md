### 4.6 🔴 给用户的大白话（**硬交付物**）

按记忆 `plain-language-for-client` 的口径（**用户 = 普通甲方**；**禁「黑话＋(推荐)标签＋事后归咎」**），讲清四件事：

| 要讲的 | 例 |
|:--|:--|
| **查出什么** | 「软件里有 X 本『公共花名册』——谁都能往上写名字，撞了只在小字日志里嘟囔一句，用户看不见、被覆盖的插件作者也看不见」 |
| **哪些是真危险** | 「最危险的是**上下文旗子**：插件能悄悄让宿主菜单项消失/出现，界面一点没变，你根本不会怀疑」 |
| **打算怎么治** | 「两条：① **给每本花名册立一份"宿主保留名单"**（随 SDK 发给插件作者，他们自己就能查）；② **撞了要出声，而且先写的不许被顶掉**」 |
| **还剩什么不治** | 「有几类**故意不改**：**照抄 VS Code 的共享设置键**（如 `files.exclude`）——改了会让你已有设置失效；**i18n 文案键**——技术上看不出谁撞了谁，只能给建议」 |

### 4.7 本格**不做**的（写清，防越界）

- ❌ **不改代码**（发现必须改的 ⇒ **立新格 ＋ 在报告里点名**，**不许顺手改**）。

- 🔴 **不许顺手改代码**（发现必须改的 ⇒ **立新格 ＋ 点名**）。

- 🔴 **不许改起点让对账好看**。
