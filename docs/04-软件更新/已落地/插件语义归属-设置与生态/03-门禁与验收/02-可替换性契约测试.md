# 02 · 可替换性契约测试（用户 D3 单独立项）

> 判据（一句话）：**把官方设置插件整套换成一只「只会读 schema、不会任何特判」的最小 UI，关键行为必须一模一样。**
> 不一样的地方，就是「住错层」的残渣——比 grep 更准。

---

## 一、被测对象

| 项 | 内容 |
|:--|:--|
| **对照组** | 官方 `settings` 插件（当前实现） |
| **实验组** | `scripts/contract/minimal-settings-ui/`（🆕 测试夹具，**不发布**）：一只 `factoryRole:"settings"` 的最小插件，只做三件事：① 读配置声明；② 按 `group/uiHint/enum` 渲染；③ 回调写配置 |
| **宿主** | dev 隔离实例（`--user-data-dir` + CDP），同一份壳 |
| **判据** | 每个场景的**可观察行为**一致：值、落盘、界面呈现的语义（文案可不同，语义必须同） |

> 夹具**禁止**出现任何 `app.*` 键名字面量、路径拼接、域字符串——它就是「第三方作者不看源码」的化身。

---

## 二、场景清单（首版）

| # | 场景 | 操作 | 必须一致的结果 |
|:--|:--|:--|:--|
| **R1** | 选背景图（app） | 点「选择图片」→ 选一张 | 起始目录 = `userData/appearance`；拷贝入库；`app.backgroundImage` = 受控 URL |
| **R2** | 选背景图（zone） | 同上，目标 = zone | 同目录、同入库、`app.zoneBackgroundImage` 正确 |
| **R3** | 主题选择 | 选主题 / 复位 | `app.theme` 落盘；主题生效；来源徽标语义一致 |
| **R4** | 分组与顺序 | 打开主题组 | 八个分节名/顺序/门控（appearanceMode）一致 |
| **R5** | AI 权限档位（任务 A） | 切四档 | `ai.policy.mode` 落盘；风险摘要一致；`userOnly` 命令仍拒 AI |
| **R6** | 只读状态行 | 看 AI 接入 | 状态来自运行时命令，不是写死 |
| **R7** | 旧壳兼容 | 壳无新命令 | 夹具降级为只读，不崩 |

---

## 三、跑法

```bash
npm run test:replaceability            # 首版：手动/半自动（CDP 驱动）
npm run test:replaceability -- --json  # 机读报告
```

- 首版不进 `npm run check`（起实例、装夹具、耗时）；进**发版前清单**。
- 稳定后：把「最小 UI」的行为抽成 headless 契约测试（mock 壳），进 CI。
- 报告输出：`scratch/replaceability/<date>.json`（不进 git）。

---

## 四、失败即证据（本档要的产出）

| 失败形态 | 说明 | 归谁修 |
|:--|:--|:--|
| 夹具选图起始目录不对/为空 | 默认目录仍在设置插件 | 壳补 `defaults` + 声明 |
| 夹具切主题后来源徽标语义不同 | 徽标派生在插件里 | 迁到 schema 声明/共享件 |
| 夹具改档位不生效 | 档位写点绑在官方插件 | 壳命令/API |
| 夹具崩但官方不崩 | 官方插件有隐式依赖 | 记录并补齐契约 |

---

## 五、与万物皆可插件的关系

- 这个夹具就是「第二个作者」的**最小化身**——正是硬约束 28「未雨绸缪」的验收物。
- 万物任务落地后，夹具应能**零改动**跑通（它是 `factoryRole:"settings"` 的普通替换件）。
- 若夹具需要特权/壳内部知识才能工作 ⇒ 槽位契约不完整，先补契约。

---

## 六、边界

- ⛔ 不要求第三方 UI 长得一样；只要求**行为语义**一样。
- ⛔ 不把夹具发布到市场；它是测试件。
- ⛔ 不为夹具在壳里开后门（开了就失去判据意义）。
