## 一、一句话病根

**「打开方式」这项能力（选择器面板 ＋ 打开调用面）住在它的第一个可替换消费者 `file-tree` 里 = 住错层。**

由此派生出四类可见缺口 ＋ 一条制度缺口（本纠正案按此分章）：

| # | 缺口 | 症状（用户可见） | 归哪一章 |
|:--|:--|:--|:--|
| 1 | **住错层** | 卸载/禁用 file-tree ⇒ 设置页的入口与编辑器的「打开方式」按钮一起消失；插件把持了宿主能力 | [01](./01-住错层纠正-选择器转正与壳级打开面.md) |
| 2 | **不归一（齿轮）** | 设置页「按插件浏览」齿轮里「在文件树中打开选择器」点了空转；`复制插件 id` 用户报无效果 | [02](./02-归一化-齿轮锚点与假菜单项.md) |
| 3 | **不归一（面板口径）** | 编辑器入口弹出的小卡片卡在**窗口左上角**、✕ 点不动；同一份面板在文件树里是「就近锚定」，两处体感完全不像一个东西 | [03](./03-面板口径-居中与遮罩.md) |
| 4 | **契约缺口** | 命令 id `file-tree.openWith` 被**三个仓**硬编码；面板的调用契约（裸路径）不自洽 | [01](./01-住错层纠正-选择器转正与壳级打开面.md) §四 ＋ [04](./04-契约API与文档连锁.md) |
| 5 | **制度缺口** | 「先放在第一个消费者里，将来有第二个再共享」这句**曾被 AI 拿来当推荐**（主题配置项先例），导致今天返工 | [05](./05-防复发-机械准入原则.md) |

## 五、本纠正案新增的口径铁律（制度层 · 详文见 05）

1. **判据 A · 声明对等律**：控件的用途若是「消费宿主声明」，它必须住在声明方与渲染方**都够得着**的地方（壳 / 共享件），⛔ 不住任一可替换插件。
2. **D10 · ≥2 真实消费者**：进共享池要**两个真实消费者**——但**本纠正案废止它的反向用法**：⛔ 不再允许拿「现在只有一个消费者」当「先住插件里」的理由。两者不矛盾：D10 管**进池时点**（不能为假想消费者预造），判据 A 管**住哪层**（消费者一出现就必须转正，且不许等第二个）。
3. **禁「先放这里，将来再共享」**（用户 8.6.2，附惩戒条款原文）。
4. **菜单项可执行律**：任一菜单项必须满足「命令已声明 ∧ 载荷形状与 handler 读取一致 ∧ 有可见回执」，否则不许上屏。
5. **既有 UI 冻结（迁移为主 · 用户 2026-10-05）**：本轮对**已有控件的外观**只做**迁移**，⛔ **不重画**——下拉、齿轮菜单、徽标、行布局一律**照在产形态平移**。用户原话：「已有的 UI 表现我是满意的，任务做的更多是迁移」。**在产 UI 的像素权威 = `mockups/05–09`**（画的就是今天的真实界面）；本纠正案的 07/08 两图只画**改动点**（位置／居中／遮罩／菜单项）——**两处冲突以 mockups 为准**。落地判据：同一控件**改动前后 DOM 结构与类名不变**，只换宿主与位置（新 D12）。
