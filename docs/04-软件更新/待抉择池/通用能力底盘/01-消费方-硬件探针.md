# 消费方 · 硬件探针（hardware-probe）

> **本档身份**：04 主档 [通用能力底盘](00-提案.md) 的**消费方章节**——不是独立插件任务。
> **为什么在这里**：它自己零壳改动，但**交付必须等壳的受控进程能力**（产不产生壳发版需求 = 产生）⇒ 按 04/05 分档判据整案归 04。
> **来源**：01 工程外部 AI（「本项目最痛」：UI 验收靠人眼 6 轮；崩了全盲；查内部状态只能 printf 重烧）。

## 一、它要壳给什么（即轴一的验收对象）

| 要的 | 用来干什么 |
|:--|:--|
| 受控进程（argv 数组 / 超时 / 结构化回执 / 白名单） | 调 `pyOCD` / `OpenOCD` / `JLink` 命令行 |
| 连接/端点登记（可选） | 记住"这块板子接的是哪个探针"，换 COM 号仍认得出 |

## 二、插件自己做什么（零壳语义）

**不自己实现 SWD/JTAG**，只做"翻译与收口"：

| 命令 | 作用 | 回执关键字段 |
|:--|:--|:--|
| `probe.list` / `probe.info` | 有哪些调试器 / 当前目标 | `{serial, kind, chip, halted}` |
| `probe.halt` / `probe.resume` | 停 / 继续 | `{halted}` |
| `mem.read <addr\|sym> <len>` | 读内存 | `{addr, hex, values}` |
| `mem.write` | 写内存（**高危**，走确认） | `{ok, before, after}` |
| `reg.read <name>` | 读寄存器 | `{name, value}` |
| `sym.resolve <name>` | 符号 → 地址 | `{name, addr, file, line}` |
| `fault.analyze` | 崩溃黑匣子 | `{fault, pc, fn, file, line, cause}` |
| `capture.frame` | 帧缓冲 → PNG | `{artifact:{path,sha256,w,h}}` |

- **符号解析**：直接读工程编译产物 `.axf` / `.map`（纯文件解析）；
- **抓屏**：读一块帧缓冲内存 → RGB565/RGB888 → PNG；
- **认目标**：工具自己列探针序列号与芯片——**不猜**。

## 三、边界（止损线在硬件侧的落点）

- ⛔ 壳里不出现"调试器/探针/寄存器"任何概念；
- ⛔ 不绑一家后端（pyOCD / OpenOCD / JLink 至少两家，命令面不变）；
- ⛔ 不做烧录 → [烧录器章节](02-消费方-烧录器.md)；
- 卸载即消失，壳零改动。

## 四、验收（同时是轴一的验收）

1. 拔掉探针 → 明确报错（有码、有 hint），⛔ 不挂起；
2. `halt` 后读出 PC/LR/SP，接 `.axf` 翻译成函数名＋行号；
3. 制造 HardFault → `fault.analyze` 给可读结论；
4. `capture.frame` 的 PNG 与屏幕一致（人工比对一次）；
5. 换后端，命令面不变。
