## 一、总账（照 [总档案 §五](00-整理档案.md) 七条逐条跑）

### 1.1 结构账

```bash
# ① 壳仓 plugins/ 下只剩夹具
git ls-files plugins/ | cut -d/ -f2 | sort -u
#   期望：panel-demo / floating-panel-demo（发货插件归零）

# ② 壳侧绑定归零
grep -rn "plugins/\(editor\|file-tree\|marketplace\|settings\|python\|serial-monitor\)" \
  tsconfig.json vitest.config.ts eslint.config.js knip.json package.json scripts/*.mjs
#   期望：零命中，或每条都有解释（夹具/注释/文档指针）
```

### 1.2 独立性账（**每条都在壳仓之外验**）

```bash
# 逐只：全新临时目录
git clone <插件仓> /tmp/verify-<id> && cd /tmp/verify-<id>
npm ci && npm run build && npm run lint && npm run validate
ls *.linkdesk-plugin        # 期望：产出 zip
```
🔴 **不许在壳仓里验**——在壳仓里 `npm ci` 会把根 workspaces 的一切都装上，**那验不出独立性**（这正是本层要治的病）。

### 1.3 分发与新鲜度账

```bash
npm run check:bundled-freshness      # 期望：绿灯
node -e "const l=require('./bundled-plugins.lock.json'); console.log(l.plugins.length)"
#   期望：= 出厂插件只数（含 12 只 JSON 型）
```

## 二、回归对照（本层最容易忽略的一条）

**`npm run check` 的覆盖会变小**——插件从壳的编译/测试图里摘出去了。**这不是回归，是本层的目的之一**（壳只考壳）。

但要**如实登记前后数字**（🔵 **L7 前基线已于 2026-09-14 L7 立案当天实测**，见下表「L7 前」列——**这就是比对的基准，别重测**）：

| 项 | L7 前（2026-09-14 实测） | L7 后 | 说明 |
|:--|:--:|:--:|:--|
| 壳仓 vitest 文件数 / 用例数 | **178 文件 / 2,429 用例**（`npm run check` EXIT=0） | 记录 | 下降量应 ≈ 25 个测试文件（**逐条核对去向，不许只说「少了就对」**） |
| `npm run check` 耗时 | 记录 | 记录 | 应该变快 |
| 出厂插件只数 | **18** | 18 | **必须不变**（少了 = 迁移丢件） |

🔴 **判据：出厂插件只数不变 + 每个消失的测试文件都能在插件仓里找到对应物。**
