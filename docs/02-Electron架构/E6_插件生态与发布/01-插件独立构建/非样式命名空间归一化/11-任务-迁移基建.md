## 一、事实与读数（**已有落点，逐条给 `file:line`**）

### 1.1 三处「用户已经存了旧名」的地方

| # | 存哪 | 形态 | 出处 |
|:--:|:--|:--|:--|
| **①** | **`settings.json`（user / workspace 两 scope）** | 键 = 设置键名（`explorer.confirmDelete` …）⇒ **改名后旧值不再被读** | `src/core/services/configuration/StorageService.ts` · 读取面 `src/core/services/configuration/ConfigurationService` |
| **②** | **`settings.json` 里的三个「存 id」键** | `app.theme`（配方 id）· `app.themeColor`（配色变体 id）· `app.iconTheme`（图标主题 id） | `src/App/config/appearance.ts`（三键定义；实测 `grep -oP '"app\.[a-zA-Z]+"'` ⇒ 这三个是存 id 的） |
| **③** | **用户 `keybindings.json`** | `Array<{command, key, when?}>` —— **`command` 是命令 id** ⇒ **命令 id 改名后用户自定义键位直接失效（静默死键）** | `src/core/registry/commands/KeybindingRegistry/persistence.ts:34-47`（`getKeybindingsPath()` ＋ `JSON.parse` ＋ `registerKeybinding({... source:"user"})`） |

> 🔴 **③ 是最容易被漏的一条**：它**不在 `settings.json` 里**、不在任何 schema 里、**没有 enum 校验兜底** ⇒ 漏了它，用户按惯的键**就是没反应**，而且**没有任何提示**（正是本轴最恨的那种无声失效）。

### 1.2 三个**现成先例**（照抄它们的形状，不发明新机制）

| 先例 | 形状 | 出处 |
|:--|:--|:--|
| **配置 schema 迁移** | `registerConfigMigration({ version, name, migrate })` ＋ `ctx.setMany(values)` / `ctx.deleteMany(keys)`；版本标志 = `app.schemaVersion`（未注册内部键，设置 UI 不可见）；**幂等 / presence 自查 / 原子（抛错则不落盘不提升版本）**；源码自述「**未来语义切换的唯一入口**，禁止再手写 startup.ts 一次性迁移块」 | `src/core/services/configuration/schemaMigrations.ts` |
| **主题 id 旧值归一 + 死 id 清扫** | `normalizeThemeValue(rawTheme)`（**映射表** `Dark`/`Light` → `dark`/`light`）＋ 启动时「**死 `app.theme` id 清扫**」（不在当前 enum ⇒ 回退默认并落盘） | `src/App/startup.ts:218-236`（含注释「旧值归一化 + 落盘……**映射表，不弹窗不重置**」） |

### 1.3 🔴 一条设计约束：映射表是**一次性迁移数据**，不是登记表

本轴禁区明写「**不许引白名单 / 基线 / 棘轮**」。⇒ 本格产出的**旧名→新名映射**必须满足：
- **数据驱动**（一个 JSON，从 1.33/1.35/1.37 的改名映射表汇总），**不是代码里的 if 链**；
- 🔴 **用完即失效**：迁移跑完 ⇒ `app.schemaVersion` 提升 ⇒ **同一段映射永不再被读**（幂等重跑只走一次）；
- 🔴 **不许被门禁当判定输入**（它只服务迁移；判定归 SDK 的账与腿）⇒ 这条**可机械核**（grep 门禁脚本零命中）。

## 二、要做（**含「同笔面」：源码 ＋ 门禁 ＋ 文档，缺一件即半成品**）

### 2.1 配置键迁移（承接 [1.33](03-任务-设置键归属评估.md) 的映射表）

- 用 `registerConfigMigration` 新增一步：`version` = 下一个可用号（**读 `SCHEMA_VERSION_INITIAL` 与既有登记，别硬编码**），`migrate(ctx)` 里 `ctx.setMany(新名→旧值)` ＋ `ctx.deleteMany([旧名])`。
- 🔴 **两个 scope 都要搬**（user ＋ workspace；照 `inspectConfiguration` 的既有姿势）。
- 🔴 **presence 自查**：旧键没值 ⇒ **不加变更**（零变更零写）。
- ⚠️ **顺带处理**：`configurationDefaults` 里若出现旧键名，**同笔改**（它是另一本账，见 [1.33 §1.4](03-任务-设置键归属评估.md)）。

### 2.2 外观 id 迁移（承接 [1.35](05-任务-外观族id归属评估.md) 的映射表）

- 三个键 `app.theme` / `app.themeColor` / `app.iconTheme` 各一张**旧 id → 新 id** 映射。
- 🔴 **照抄 `normalizeThemeValue` 的形状**（映射表 ＋ 不弹窗不重置 ＋ 落盘），**并与它合并成同一个归一化入口**（避免出现第二套 id 归一逻辑——归一化纪律）。
- ⚠️ **死 id 清扫已有**（`startup.ts:228-236`）⇒ 本格要**扩它而不是另写**（同一处只维护一次）。

### 2.3 用户自定义快捷键迁移（**本格最容易漏、也最值钱的一条**）

- 读 `keybindings.json` ⇒ 对每条 `command` 走命令 id 映射 ⇒ 命中则**改写并落盘**（保持行序与其余字段原样）。
- 🔴 **三个边界**：① 文件不存在 ⇒ **零动作**（不许新建空文件）；② 命令 id 未命中映射 ⇒ **原样保留**（不许删、不许报错——用户可能引用第三方命令）；③ **幂等**（跑第二遍零变化）。
- ⚠️ **`when` 子句里也可能含被改名的旗子**（`when: "explorerItemIsFile"`）⇒ 本格要一并处理（旗子映射由 [1.37](07-任务-上下文旗子归属评估.md) 给）。
- 🔴 **落盘时机**：与 schema 迁移同批（都是"版本提升前一次性"）⇒ 若失败**不许提升版本**（原子性照 `schemaMigrations` 的约定）。

### 2.4 改名执行器（**供 7 个清账轮复用**）

- 一个脚本（住 `scratch/`，**不进仓**）＋ **形状证明**：对每个被改文件，**剥掉插入的前缀后与改名前基线 `git` blob 逐字节相等**。
- 🔴 **必须带的四条**（照记忆 `css-rename-round-toolkit` 的实测坑）：① 基线要**显式给 `--base <改名前 sha>`**（中途 amend 会让默认 HEAD 悄悄缩范围）；② **比 git blob 不比工作区字节**（本机 CRLF 检出态会让 `git status`/`diff` 假红）；③ **负控要自证真的变异了**（否则假绿）；④ **要改的面有五类**——**CSS 定义点 · 渲染点 · scoped 后代选择器与注释 · 别的仓的消费点 · 只在渲染点存在而零定义的名字**（工具只覆盖第一类）。
- ⚠️ **本轴特有的面（比样式那边多两类）**：⑤ **`plugin.json` 的 `when` 子句**（旗子名）· ⑥ **菜单/键位引用的 `command` 字段** —— 执行器**必须把这两类算进射程**（渲染点 token 补扫的同类问题）。

### 2.5 「同笔面」（缺一件即半成品）

**源码**（三处迁移 ＋ 执行器）· **门禁**（迁移自己的单测：幂等 / presence / 原子 / 未命中保留）· **文档**（作者面**迁移说明**要讲清「用户侧什么都不用做」）· **`app.schemaVersion` 提升与既有迁移共存**（不许与 #85 圆角迁移 / #90 键删除冲突）· **E6 清单勾格与轮次进度行**。

### 2.6 写齐 [1.42](12-任务-清账-file-tree.md) 的正式任务书

至少补齐：**执行器用法与参数** · **映射表路径与格式** · **`file-tree` 的 75 处逐条映射（旧名 → 新名）** · **它借 `editor.*` 两个命令的还回方案** · **它设 `inputFocus` 的还回方案** · **改完要跑的三条实证**（设置项 / 快捷键 / 主题）。

## 三、判据表（**含必须真跑过的负控**）

| 判据 | 要求 | 负控（**必须真能红**，覆盖它想抓的形态） |
|:--|:--|:--|
| **① 配置键值搬得过来** | 造「旧名有非默认值」的 `settings.json` ⇒ 迁移后**新名下读得到同值**，旧键已清 | 把迁移函数改成恒真（不搬）⇒ **顺序跑出的断言必须红**（照 CSS 系列 NC6 的教训：判据要能被变异测出） |
| **② 幂等** | 迁移跑两遍 ⇒ 第二遍**零变化**（`settings.json` 字节相同） | 造一个非幂等的迁移（无条件 `setMany` 同值也算变化时）⇒ 断言红 |
| **③ presence 自查** | 旧键不存在 ⇒ **不写任何东西**（文件字节不变） | 在干净 profile 上跑 ⇒ **文件 mtime/字节零变化**（不是"值相同"，是"没写过"） |
| **④ 原子** | 迁移中途抛错 ⇒ **不落盘 ＋ 不提升版本**（下次启动全量重试） | 在 migrate 里注入 throw ⇒ 断言「`app.schemaVersion` 未变 ＋ settings.json 未改」 |
| **⑤ 快捷键迁移** | ① 命中 ⇒ 改写；② **未命中 ⇒ 原样保留**；③ 文件不存在 ⇒ **零动作（不新建）** | 三条各一条负控；**② 的负控最关键**（不许把用户引用的第三方命令删掉） |
| **⑥ 外观 id 迁移** | `app.theme` / `app.themeColor` / `app.iconTheme` 三个键各自搬对 | 三条单测 ＋ 造一份「旧 id」的配置跑真迁移 |
| **⑦ 映射表不是登记表** | 门禁脚本里**零引用**该映射文件 | `grep -n "<映射文件名>" scripts/check-*.mjs` ⇒ **应命中 0** |
| **⑧ 旧机制未被破坏** | #85 圆角迁移 / #90 键删除 / 死 theme id 清扫**改前改后读数一致** | 在既有迁移上重跑 ⇒ 读数逐字节相同 |
| **⑨ 逐项操作实证**（**本格的对外交付**） | 改过名的设置项**仍能切换** · 改过 id 的快捷键**仍能触发** · 改过 id 的主题**仍能选、仍跟随** | **实机跑并留三项读数**（不是"看起来没变"） |

## 四、禁区

- 🔴 **不许改机制**：三处迁移都**复用既有落点**（`registerConfigMigration` / `normalizeThemeValue` / 键位文件读写），**不许另造第二套**。
- 🔴 **不许碰主题机制**（[29 号档](../样式命名空间归一化/29-主题系统保护条款.md) P1）：`commitTokens` · `theme:changed` 广播链 · `preload-pool` 写池 `:root` —— 本格只搬 **id 字符串**，不碰写入链。
- 🔴 **不许引白名单 / 基线 / 棘轮**：映射表是**一次性迁移数据 ＋ 用完即失效**（§1.3），**不许进任何门禁判定路径**。
- 🔴 **不许"顺手"把迁移写成会重置用户的形态**（例：id 未命中就回默认）—— **未命中一律原样保留**。
- 🔴 **不许丢用户数据**：任何"清旧键"必须在**新值确实写成功之后**（照 `schemaMigrations` 的原子约定）。
- 🔴 **不许改 pluginId**（硬约束 11：发布后不可变）——本格搬的是命令 id / 设置键 / 旗子 / 外观 id，**不含 pluginId**。
- ⚠️ **上位约束**：**操作体验零变化**（名字可变，取值与功能不许变）· 只做加法且名字一次定对 · [29 号档](../样式命名空间归一化/29-主题系统保护条款.md) 优先 · 对外宽容。
- ⚠️ 照旧：不跳 `npm run check` · **提交只按路径 `git add <本格文件>`**（禁 `git add -A`）· 推前现测代理 · 推完 `ls-remote` 对 SHA。
