### 2.3 🔴 活体样本的处置（**核心产出 2**）

`settings` 插件的 4 个裸名旗子**是宿主契约的一部分**。候选：

| 路线 | 形状 | 要回答 |
|:--|:--|:--|
| **(甲) 把他们提升为「宿主公开旗子」并登记** | 账里明确列出这 4 个名字 ＋ 注明「宿主公开面：插件可设，文档化」 | **它和"宿主保留＝插件不许占"矛盾吗？** ⇒ 需要区分两类：**宿主专用**（插件设了 = 红）vs **宿主公开约定面**（插件可设，**但只有约定的插件该设**）。**谁有权设？** 只有 `settings`（第一方）？⇒ 那需要一条「**声明式授权**」（`plugin.json` 声明 `setsContextKeys: [...]`？）——**这是新机制，要论证** |
| **(乙) 改名成保留前缀（`app.settingKey`）** | 两边同笔改 | 🔴 **要改 `settings` 插件 ＋ 宿主命令 ＋ 官方目录回填 ＋ 一次发版** ⇒ **代价可测**；**是否算 UI 变化？**（旗子名不改 UI，但**若改名过程中有一侧漏改 ⇒ 齿轮菜单项消失 = 真 UI 变化**） |
| **(丙) 不动 ＋ 登记为「已登记的宿主-插件约定面」** | 账里列出来，标注「约定面」；第三方设它 ⇒ 按仲裁出声 | **最省、零风险**；但**第三方冒充 `settings` 设 `settingFollowTheme` 这条路仍然开着** ⇒ 靠运行时仲裁"出声"兜（**出声 ≠ 拦住**） |

⇒ **本格要给的结论（照 §〇c 的零例外口径）**：账里分「**宿主专用（红）**」与「**宿主约定面**」两段；🔴 **宿主约定面也要给一条明确路线**（连两侧改名带归属，**或**明文登记为「宿主公开约定面」并说明它为何**不是**漏网 —— **两条都要给代价与读数，不许含糊**）。🔴 **`file-tree` 借用共享组件的 `inputFocus` 必须还回**（[00 §〇c.3 活体 2](00-整理档案.md)）。**若判引入 `setsContextKeys` 声明**，必须论证它是不是"新机制"（**大概率越界**）。

### 2.4 插件旗子的归属规则（**核心产出 3**）

- 规则候选取 1.31 的结论一致：**插件旗子必须 `<pluginId>.` 开头** ⇒ 🟡 黄（存量 `explorer*` 9 个是反例）。
- 🔴 **但这里比命令 id 更微妙**：旗子**没有"公共 API"属性**（不像命令 id 被 `menus[].command` 引用），改名**不会破坏跨插件引用**——**只破坏「宿主/其他方的 `when` 表达式」**。⇒ 本格必须实测：**谁在读 `explorer*` 旗子**？（**预期：只有 `file-tree` 自己的 `plugin.json` 的 menus/keybindings**）⇒ 若是，则 **`explorer*` 的改名代价 = 只改自己仓**，**但要过「零 UI 变化」**（旗子名不改 UI；若改名有落点遗漏 ⇒ 菜单项消失 = 真 UI 变化）⇒ **本格要量清"改名后哪些形态会变"**。

### 2.5 运行时仲裁（与 1.32/1.34/1.36 **同一套写法**）

- 异 pluginId 设**同一个**「宿主专用」旗子 ⇒ **出声点名双方 ＋ 不静默**。⚠️ **但"不覆盖"对不对？** 旗子是**状态**不是**注册**——两个插件争设同一个旗子的正确语义**不是"先者保留"，而是"这本就不该发生"** ⇒ 本格要定：**出声 ＋ 让后来者照样设（因为 set 是幂等的状态写）**，还是**拒绝**？（**建议：出声 ＋ 允许**，理由是"状态写"没有"先者"的概念；**但要在结论里写清为什么它与注册表类面不同**）。

### 10.4 🔴🔴 **本格头号发现：`when:` 抽取正则在第一个单引号处截断**（**假绿**，比假红更危险）

`gen-host-reserved.mjs:214` 的抽取正则：


字符类 `[^"'`]+` **把 `'` 也当作终止符** ⇒ 遇到 `when: "sidebarPosition == 'left'"` 时**在第一个 `'` 就停**，抓到的是 `sidebarPosition == `（**截断**），**不是**完整表达式。

| `when` 原文 | 实际抓到 |
|:--|:--|
| `"sidebarPosition == 'left'"` | `"sidebarPosition == "` ← **被截断** |
| `"explorerFocus && !inputFocus"`（无引号字面量） | `"explorerFocus && !inputFocus"` ← 完整 |
| 🔴 `"settingKey == 'app.x' && myFlag"` | `"settingKey == "` ← 🔴 **`myFlag` 整个丢了** |
| 🔴 `"a && b == 'x' \|\| c"` | `"a && b == "` ← 🔴 **`c` 整个丢了** |
| `'sidebarPosition == "left"'`（单引号包表达式，合法写法） | `"sidebarPosition == "` ← 截断 |

**两个后果，方向相反：**

1. ✅ **侥幸的一面**：正因为截断，比较值 `left` / `right` / `app` / `backgroundImage` / `zoneBackgroundImage` **没被收进账** ⇒ §2.2 担心的「裸 grep 把比较值当旗子名」**今天没发生**——**但不是因为过滤器对，是因为正则错**。**账今天是对的，理由是错的。**
2. 🔴 **真害的一面（假绿）**：**任何写在引号字面量之后的旗子名，生成器一律看不见**。今天宿主 `when` 恰好「比较值都在末尾」，所以没暴露；**只要有人写一个 `when: "settingKey == 'x' && myNewFlag"`，`myNewFlag` 就静默不进账** ⇒ 对账双向比对本该**红**的地方**静默变绿** ⇒ 保护面**悄悄漏一个洞**。这是**假绿**（漏报），比假红（误报）危险得多：假红会被人发现并修，假绿不会。

**⇒ 1.38 必做**：修 `gen-host-reserved.mjs:214` 的抽取（**按表达式整体取，不做单引号字符类排除**；再对**取出的完整表达式**做 token 切分，并把比较值过滤**显式**做掉——**过滤要写在明处、可自测**，不能像今天这样**靠正则出错**侥幸达成）。**负控见 §十六 ⑥/⑥′。**

## 十二、🔴 核心裁决：旗子是「**状态写**」不是「**注册**」（§2.5）

### 12.1 结构性依据（**不是口味，是代码事实**）

| 事实 | `file:line` | 推论 |
|:--|:--|:--|
| 🔴 `contextKey:set` **过 IPC 时零身份** | `electron/ipc/ipc-bridge.ts:204-208`——`const [key, value] = args`，**只解出两个值**；对比**同文件** `commands:register`／`executeResult`／`unregister` **显式追加 `windowId`**（`:210-214`） | **宿主根本不知道是谁写的** ⇒ **「先者」这个概念在旗子面上不存在** |
| `setValue` 无 owner 参数 | `ContextKeyService.ts:327-334`——签名 `setValue(key, value)`，只做「值未变则早退」 | 与 `registerCommand(id, pluginId, fn)` **形态不同**：注册**带归属**，状态写**不带** |
| 状态写**幂等** | `:328-329` `if (old === value) return` | **后写者覆盖前写者是「正常」，不是「侵占」**——它就是"把状态改成新值"这个动作本身 |

### 12.2 裁决

> 🔴 **同名旗子被两方先后写 = 正常运行时行为。仲裁 = 出声点名双方 ＋ 放行（让后来者照样写）。不许拒绝，不许「先者保留」。**

**三个「为什么不」：**

| 候选 | 为什么不行 |
|:--|:--|
| **先者保留**（照搬 1.36） | 🔴 **结构上做不到**：`:204-208` 过桥时**身份已丢**，运行时拿不到「谁是先者」。硬做要**改 IPC 通道加身份**（`ipc-bridge.ts`）＋ **改公共 API 签名**（`ui.ts:49-52`，**对外契约**）⇒ **远超本件射程**，且**改变对外契约**。**另**：语义也错——旗子是状态写，**先写者的值就该被后写者取代**（同一个 `settingKey` 从 A 行移到 B 行**正是要靠覆盖实现**）。 |
| **拒绝后来者**（静默丢弃） | 🔴 **会打断合法流程**：`gearMenu.ts` 的 `handleGearClose`（`:36-43`）**主动把 4 个旗子写回 false/undefined**；若「宿主专用」判定为拒绝，正常关闭齿轮菜单都可能被拦。**另**：静默拒绝 = **更隐蔽**（调用方 `await` 成功，行为却没发生）。 |
| **抛错** | 🔴 [00 §2.7](00-整理档案.md) **明令不许抛错**（对外宽容）。 |

**⇒ 唯一自洽解**：**出声（`console.error` 点名双方 pluginId ＋ 旗子名）＋ 放行**。出声的价值**不是拦住**，是让「这本就不该发生」**可见**（今天完全静默）。

### 12.3 ⚠️ 出声在运行时**做不到的部分，必须如实登记**

运行时**只能对「宿主专用」旗子出声**——因为「谁先写」不可知，且**宿主自己也在写**（`initCoreKeys` / `lifecycle.ts:84` / `usePoolSync.ts:130,136,137` **都不带 pluginId**）。

§2.3 问「若判引入 `setsContextKeys` 声明，必须论证它是不是新机制」。**裁决：是，且越界，本格不引入。**
