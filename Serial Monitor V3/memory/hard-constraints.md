# V3 硬约束

## 配置约束

1. **workspace.json 禁止嵌套。** 卡片列表必须是一层平铺数组。`{ "cards": [ {...}, {...} ] }` 是上限。不允许 Cards → Groups → Items 多层嵌套。每多一层，AI grep 目标字段的难度翻一倍。

## 协议约束

2. **卡片 ID 不可含逗号。** 逗号是唯一分隔符。ID 如 `chip_temp`——英文/数字/下划线。
3. **协议字段顺序固定，末尾可省略，中段用双逗号留空。** 和 V2 完全相同。
4. **`!` 前缀表示卡片定义，不带 `!` 表示数据。** 这是唯一的协议类型区分。

## 组件约束

5. **组件只实现 OnData(fields) + OnSend。** 加新组件 = 新建一个文件 + 注册一行。不改路由、不改卡片壳、不改其他组件。
6. **改卡片类型 = 替换组件。** 旧组件销毁，新组件从空开始。不要做跨类型数据迁移——MCU 几十 ms 一帧，几秒填满。
7. **用户手动修改过的字段不被 `!` 覆盖。** Dirty 标记存 workspace.json。用户 > MCU。

## 数据管道约束

8. **串口 I/O 在 Web Worker。** UI 线程只消费 RingBuffer，永远不直接调串口 API。
9. **滑杆发送走节流器，走 SendQueue。** 不直接在 ValueChanged 里写串口。
10. **波形点队列存卡片级 store。** 不随 React 组件 unmount 销毁。虚拟化卸载组件时保护历史数据。

## 配置入口约束

11. **PreferenceService 是唯一配置入口。** GUI 操作、文件监听、未来 WebSocket——三条路全走同一个 Service。没有"人用的 API"和"AI 用的 API"两套东西。

## 主题 / 双语约束

12. **所有颜色走 CSS 变量。** 不硬编码 hex 在任何组件里。
13. **存原 key 不存翻译结果。** state 里存中文 key，显示时调 `t()`。和 V2 的 T() 原则相同，只是 API 从 C# 变成 react-i18next。

## 来自 V2 的通用约束（需要翻译到 V3 语境）

14. **DataConverter 四个方法不可改。** 算法从 V2 平移。
15. **编辑模式下冻结数据更新。** 编辑时卡片值不应跳动。
16. **虚拟化卸载需防抖。** 离开视口 200ms 后再卸载，避免快速滚动抖动。
