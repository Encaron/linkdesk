## 1. `src/core/`——圆形大厅（桌子集合）

**准入标准（三条同时满足）：**
1. 多提供方——多个插件可能登记到这张桌子上
2. 多消费方——多个插件可能翻这张桌子
3. 桌子不知道内容——桌子本身不知道登记的信息是什么意思

## 4. `src/hooks/` / `src/pool/hooks/` / `src/components/shared/hooks/`——React hooks 归位

纯 hooks——`use*` 前缀，一个文件一个 hook。不夹带组件、不夹带 service。

> 🔥 E5.8#0d.7-5 + E6#15h 兑现后实况（2026-08-18 立 / 2026-09-05 E6#15h 更新，详见 08-共享hook归位.md）：
> - **`src/hooks/` = 壳侧状态 hooks**（壳逻辑专用）——useTabManager, usePoolSync, useHeartbeat, useMemoryMonitor。只被壳代码 import。
> - **`src/pool/hooks/` = 池 UI 交互 hooks**（只被 Pool zone/视图使用）——gridLayout, tabDragTypes, useDragReorder, useResizeDrag。E6#15h 后此夹**纯壳布局 chrome**——插件不再能 import @src/pool/hooks/*（eslint 拦截）。
> - **`src/components/shared/hooks/` = @linkdesk/ui 零件 UI hooks**（E6#15h 收编）——useClickPreview, useClipboardKeys, useDebouncedInput。插件侧共享的**交互** hook 归此：源码壳侧单一副本，插件经 `@linkdesk/ui` 分发（同一源码防漂移模型，07 设计 §四）。

## 7.8 体积门禁——全仓行数上限（`src/` + `electron/` + `plugins/*/src`）

> 🔥 **2026-09-11 E6#84a 新增**（第 3.6 层文件整理层）。**机械执行 = [`scripts/check-file-size.mjs`](../../scripts/check-file-size.mjs)**，挂在 `npm run check` 里。**本节是人工依据，脚本是唯一权威**——两者不一致以脚本为准，并**立刻回来改本节**。

### 三档制

| 档 | 范围 | 阈值 | 豁免 |
|:--|:--|--:|:--|
| **A** | `src/**` + `electron/**` | **800** | ✅ allowlist 拍板制（文件头注 `@E6#0.6b` token） |
| **B** | `plugins/*/src/**` | **按角色表**（见下） | ❌ 无豁免通道——拆分是正解 |
| **C** | `plugins/*/src/index.tsx`（entry） | **120** | ❌ 同上 |

### 角色表（**按扩展名与首段目录定，不看更深层级**）

```
.css                                   → 300     （放在哪都算样式，含 co-located 的 views/*.css）
plugins/*/src/index.tsx                → 120     （entry = 薄门面）
plugins/*/src/<role>/**.{ts,tsx}       → 角色档
```

| role | 常规档 | 聚合器档（同名夹存在时 ×2） |
|:--|--:|--:|
| `views` / `components` / `hooks` / `utils` | 150 | 300 |
| `services` | 200 | 400 |

**判定细则：**
1. **`.css` 恒走 300**——不看目录。
2. **未知 role 夹 → 门禁 `throw`**（fail-loud）——新增顶层目录（如 `src/store/`）必须**显式上档**，不允许静默落进 800 兜底。
3. **同名夹聚合器 → role 档 ×2**：文件 `X.ts(x)` 同级存在 `X/` 夹 = 它已是聚合门面（feature-folder 的产物），按 ×2 计。**这是上限放宽，不是目标值**——门面仍应尽量薄。
4. **聚合器不许含纯逻辑**——纯函数 / 数据变换 / 类型定义必须下沉子模块（照 §4 `0d.10-8` 铁律）。

### 超限怎么办

**必拆，走 feature-folder（同名夹 = 聚合器 + 子模块）——禁止拆成同 domain 平铺多文件。** 详见 §4 的 11 条 `0d.10-*` 先例。

## 8. 反模式——加文件前自检

| 反模式 | 正解 |
|--------|------|
| "不知道放哪，先放 `core/` 根目录" | 对照此表——找不到归属 = 不应该进 core |
| "就一个文件，建子目录太早了" | 正确目录宁可只有一个文件——命名就是文档 |
| "这个和那个有点像，放一起吧" | "像"≠"同类"。Registry 和 Service 都管理数据，但一个纯查询一个有副作用——不同目录 |
| "这个界面/控件/页面只有几行，平铺放着吧" | **UI 功能域 = 文件夹**——界面/控件/页面一律建夹（tsx + css + 测试 + 子节同夹）；各宿主/控件 = 一个功能域就一夹（floating 三宿主已按此细化 #0d.7-6b——教训：平铺"例外"必须先有用户拍板，不能档案写"共识"就当成定案） |
| "以后再说" | 以后不会再说——E5#42 就是"先分堆"的教训 |

**测试政策（2026-08-17 全树复查定）：** `*.test.ts(x)` 与单元**同夹紧邻**（判据 5），不建中央 `__tests__/`。**E5.8#0d.7-8 已兑现**（23 测试随单元同夹，中央 __tests__ 6→1）。**#0d.8-5（2026-08-19）serialHandlers.test 随单元归位 electron/ipc/handlers/——中央 __tests__ 清零收官（0）**。跨工程边界（electron/）测试需两处配套：vitest.config include 补 `electron/**/*.test.ts`（否则静默掉出测试集）+ electron/tsconfig.json `exclude: ["**/*.test.ts"]`（否则 electron:dev/build 发射测试进 dist-electron 打包产物）——详见档案执行踩坑表。
