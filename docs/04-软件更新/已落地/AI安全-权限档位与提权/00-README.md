## 四、设计要点（详见 01–05）

1. **四档**：只读 / 逐次确认 / 自主（默认）/ 完全访问；冒烟判据 = 「不点头就不做」不变。
2. **一个策略引擎**：`decide(mode, action) → allow | ask | deny`，纯函数、单一求值入口。
3. **一个执行闸**：`runShellCommand` 改为过策略；`install` 同源。
4. **防自提权三层**：`ai.*` 配置拒写（已有）＋ `userOnly` 命令拒调（新增）＋ 批准只能由用户在弹窗里点（新增）。
5. **提权回路**：AI 只能调 `requestElevation`（请求），批准动作写在用户的确认框 handler 里，⛔ 不经命令面。
6. **表现层可替换**：确认框/设置分区/状态栏徽标/回执全部挂到「万物皆可插件」的槽位，数据只走壳命令。

## 五、边界（不做什么）

- ⛔ 不改插件权限系统、不改 MCP 传输层、不做远程/手机（M4 已留口子）。
- ⛔ 不新建第二个弹窗面、第二个通知面（`StatusBarZone.tsx:15-22` 已明令 ToastHost 删除；「看一眼就过去」走通知面板缺省）。
- ⛔ 不为本档在设置插件里写宿主语义：档位/风险/默认值全部由壳声明，设置 UI 只渲染。
- ⛔ 软件本体发版仍归用户（攒批纪律）。
