## 一、SDK 导出面（`@linkdesk/plugin-sdk`）

### 1.1 类型与签名

| 导出 | 形态 | 作者要做什么 | 归属任务 |
|:--|:--|:--|:--|
| `registerCommand(id, handler, meta?)` | 不变；`meta` 增 `description`/`params` 已在；**`activation`/`scope` 由宿主填** | ⛔ 作者不传 `scope`；`activation` 写在 manifest | T19 |
| `pluginError({ code, message, hint?, details? })` | 新增 | 业务错误一律用它，⛔ `throw new Error("中文")` | T14/T19 |
| `AsyncCommandMeta`（`meta.async: true`） | 新增类型 | 长任务在 `registerCommand` meta 声明；壳自动包 op；⛔ 调 `runAsync`/自建状态机 | T11/T19 |
| `decodeBytes(data, coding)` | 新增（纯函数） | 解码字节；⛔ 自己 `new TextDecoder` ＋ 手写 GBK | T17/T19 |
| `SERIAL_CODINGS`（规范清单） | 新增常量 | 引用它；⛔ 各插件抄一份 | T17/T19 |
| `LinkDeskCommandParam` / `CommandReturns` 类型 | 新增/扩展 | `returns` 用类型描述，编辑器可提示 | T12/T19 |

### 1.2 三条纪律

- **导出只加不删**（L9 契约纪律）：旧导出保留，新能力用新名；⛔ 破坏插件仓编译。
- **dist 必须重建**：dev 轨道解析 `packages/plugin-sdk/dist`，改源码不重建 = dev 看不到。
- **零壳依赖**：SDK 不得 import 壳内部（R6）；类型可从 `@linkdesk/contracts` 取。

## 六、发版顺序（⛔ 倒序会炸）

```
contracts → 壳（实现新字段）→ SDK（d.ts/dist 同步）→ 脚手架（模板）→ 官方各仓（manifest/行为）→ 03 文档 → AI 手册
```

- 插件声明新字段时，壳必须已经认识 ⇒ 壳先行；
- 插件声明 ⇒ **最低壳版本自动推导**（照共享件地板先例，⛔ 作者手填）；
- 出厂种子追新 `sync:bundled --latest`；文档 `docs:check`；手册 `manual:build`。
- 🔴 **2026-11-25 实测发布依赖**：`@linkdesk/contracts` 本地 **0.1.57 未发布**，marketplace 已依赖 `^0.1.57`（干净 `npm install` 会 notarget）；SDK 本地 tarball 与已发布 **0.1.116 同版本不同内容**（本地含 `./runtime`，registry 包没有）。⇒ T23 **必须先发 contracts 0.1.57**，SDK **bump 新版本（如 0.1.117）**，⛔ 同版本覆盖。

## 七、验收（作者视角的「能不能做全」）

1. 用一个**全新目录**跑脚手架 → 不改任何行，`npm run check` 绿。
2. 按 README 加一条 entry 命令：不开视图，外部 AI 直接 `exec` 成功。
3. 按 README 加一条 view 命令：`describe` 显示 `activation:"view"`，无视图调用得 `EVIEWREQUIRED`。
4. 故意漏写 `risk` ⇒ 加载被拒/门禁红，错误信息**指向 21 规范的具体字段**。
5. 故意 `throw new Error("中文")` ⇒ ESLint 提示改 `pluginError`。
6. 全程**未打开任何官方插件源码**——这是本档对「共享包交付完整」的定义。
