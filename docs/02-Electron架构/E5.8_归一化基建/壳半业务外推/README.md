# Phase 10 壳半业务外推 + 装配清单展望——开工说明

> 2026-08-17 立案。**dsh framework-level 收敛深潜的第二落点**（第一落点是 Phase 6-9 面板窗口）。核心追问：LinkDesk 还能在哪向"万物皆插件"的框架哲学靠拢——壳里还残留了哪些"壳不认识、却由壳在维护"的业务状态？
>
> 对应清单任务：E5.8#47-#50。

---

## 一句话

**壳半业务外推 = 把"壳在维护、但壳并不懂"的串口业务状态，外推回插件自管。** 不做新机制——机制（contextKey.set 通用 API）早已存在，只是壳一直在镜像一份串口的真值。这是**不一致**的修正，不是**能力缺口**的补齐。

**装配清单展望 = profile / 装配清单设计（#50）。** dsh 用 `cordis.yml` 声明"装哪些插件 + 它们是什么"。LinkDesk 目前靠用户手动逐个装插件 + 出厂预装 04/05 目录。profile 让"一台 LinkDesk 装什么"成为一份可分享、可版本化、可重放的装配清单——对标 cordis.yml 的思想，但产品形态是 LinkDesk 自己的（不做 yml 配置，走壳内 UI + 分享快照）。

## 执行纪律（Phase 10 专属）

- **#47 是唯一"现在就能动手"的任务**——执行草案已含逐文件删除清单，基建收官后第一个干它。
