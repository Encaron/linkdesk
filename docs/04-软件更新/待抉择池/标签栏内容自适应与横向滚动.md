# 标签栏内容自适应与横向滚动（待抉择池）

## 一、需求（用户 2026-09-13 描述，AI 复述经用户确认）

1. **标签宽度 = 内容宽度，不挤压、不省略。** 现在开的标签越多，每个格子越窄、文字越少；目标是每个标签按自己的内容撑开——开 10 个就是 10 段自然宽度的和，谁都不被压。
2. **装不下就横向滚。** 鼠标停在标签栏上滚轮 = 左右滚，滚到最左/最右即停；想看被"盖住"的第一个标签，滚过去点它即可，不必先关后面的。
3. **伴随行为（用户未明说、实现必需）：** 切标签 / 新开标签（默认落在最右）/ 关标签 / 键盘切标签时，**目标标签自动滚进视野**；拖拽标签到可视区边缘时**自动滚动**——否则变宽后的标签会直接落在屏幕外，拖不过去也看不见。
4. **边界（待拍板）：** 单个超长标签（如 80 字的文件名）宽度是否封顶——见 §三。

## 三、待拍板项

1. **超长标签是否封顶。** 按「内容多少显示多少」字面执行 ⇒ 一个超长标签就能占满整条，连滚动都无从谈起。**AI 建议：自适应 + 一个高上限（上限值待定，可参考 VS Code 量级）**，超上限才省略——请用户拍板「无上限」还是「带上限」。
2. **滚轮语义判据（立项时写死，不留给执行期）：** 建议——纵向滚轮（`deltaY`）→ 横向滚动（现状保持）；横向滚轮（`|deltaX| > |deltaY|`）用 `deltaX`；**`Ctrl + 滚轮` 不拦截**（字号缩放优先，硬约束语义）。
3. **pinned（双击固定）标签的宽度语义：** 现状 pinned 无特殊宽度 → 建议同样内容自适应，不新造第二套规则。

## 四、连坐面（实现时逐项回归）

- **分屏**：每个组各一条标签栏，**各自独立滚动**（互不联动）。
- **`--ui-scale` 字号缩放**：所有尺寸现口径都是 `calc(... * var(--ui-scale))`——新宽度口径必须同样乘 scale。
- **拖拽**：组内换位 / 跨组分屏 / 吸附插入竖线（`group-tab-drop-indicator`）在滚动坐标系下的命中与指示位置。
- **其余既有行为不受影响**：中键关闭、双击 pin、预览态斜体（`.preview`）、`[+]` 菜单、右键菜单（`TabContext`）、enter/exit 动画（`max-width` 关键帧 `:232-243` 需与新宽度口径对齐）。
- **主题**：颜色全走 `var(--)`，本项不动配色。
- **标签条高度 35px / 标签 30px 不变**（`GroupTabBar.css:8,44`）——只动宽度轴。

## 五、明确不改（现状已对，别误改）

- `[+]` 按钮与右侧动作区在**滚动区之外**（`.group-tab-list { flex: 1 }` + 兄弟 `flex-shrink: 0`）——保持钉住，不跟着滚。
- 滚动条隐藏、箭头条件出现（只在有溢出的一侧出现）——保持。

## 七、立项后验收（用户视角）

1. 开 10 个长名标签 → 每个都完整显示 → 滚轮左右滚可达最左/最右 → 点最左的标签能切过去。
2. 在中间位置新开一个标签 → 它自动滚进视野。
3. 分屏成两组 → 两条标签栏各自滚动、互不影响。
4. `--ui-scale` 放大一档 + 亮/暗主题各过一遍 → 不破格。
5. 邻近回归：拖拽换位/跨组、中键关闭、双击 pin、`[+]` 菜单、右键菜单。
