§四 三态取色 —— 以及 FT#4 当场抓到的那处缺陷 hover / active 是走查的主要战场：静态截图永远看不出「hover 掉了底」

4.1 三个状态的实物对照（暗色）

常态（--bg-card）
:hover（--tree-bg-hover ＋ accent 边）
:active（--tree-bg-selected）

4.2 缺陷：hover 越「生效」越糟

时点主按钮 background主按钮 border-color最近项 background
常态 rgb(45, 45, 45) rgb(60, 60, 60) = --border #3C3C3C rgba(0, 0, 0, 0)
强制 :hover （修前 · 1.0.19） rgba(0, 0, 0, 0) ← 底掉光 rgb(0, 120, 212) rgba(0, 0, 0, 0) ← 零反馈
强制 :hover （修后 · 1.0.20） color(srgb 0.831373 0.831373 0.831373 / 0.06) rgb(0, 120, 212) 同上 6% 叠加
真因（可指认到行）：--tree-bg-hover / --tree-bg-selected 只声明在 .file-tree-root（file-tree-shell.css:23/25），而本 section 的祖先链里没有 .file-tree-root ⇒ var() 取到空串 ⇒ background 简写在计算值期判非法 ⇒ 落到 unset（＝ transparent）。所以「hover 生效」的可见结果恰好是有底变没底；而同一规则里的 border-color: var(--accent) 反而正常（accent 是全局 token）——这个不对称就是最刺眼的病灶。
修法：三处 var() 补 fallback，写法与 SearchView.css 既有两处完全一致（不发明第二种写法）：
background: var(--tree-bg-hover, color-mix(in srgb, var(--text-primary) 6%, transparent));
自带交叉验证（值得记一笔）：修后实测色的 RGB 三元组 0.831373 = 212/255 正好就是 --text-primary——即 fallback 公式与「若在 .file-tree-root 作用域内本该取到的值」逐位相同。修的是作用域缺失，不是换了个颜色。
取证方式：CDP CSS.forcePseudoState（driver --mode force，脚本自带机制自证）；修后是在全新隔离实例上装 1.0.20 真货复测，不是改完源码就地看。

§六 红线与范围外

红线①（本文件存在的全部理由）：本 section 永不卸载——订阅（目前只有 pluginState.onChange）只挂这类常驻组件。
红线②：空态／有根态只允许组件内部条件渲染，⛔ 绝不做「外部替换整个组件」（registerViewEmptyContent 形态：FoldersView 当年被整替换 ⇒ 订阅被 cleanup ⇒ addFolder 广播无人听 ⇒ 永久死锁）。本补丁的三态读数逐字段相同，就是这条红线的机械证据。
打开动作走命令、不直连 API：主按钮打 file-tree.openFolder（handler = workspace.openFolder()），与文件菜单、命令面板同一条链，不写第二份逻辑——data-hint 也才能带出该命令的快捷键。
⛔ 范围外（本图明确不认领）：搜索 section 的窄栏裁切（§二 图内已标注）、最近列表条目内容逐条对账（FT#4 只核了计数与截断读数）、命令面板入口、主题切换跨插件回归、实机 nsis 那半——都归 FT#5 残余，见执行清单。
