# E5.8-zone 分割线换边归一化档案（#146）

> 2026-08-27。用户报（一般 bug）：侧栏换边后 zone 分割线落在侧栏与图标栏之间，而非侧栏与主区之间——「理论上 zone 的分割线应该出现在主区和侧栏之间，就像底部面板放到上面，也没见它的分割线换到上面去和顶栏挨着」。用户自问：是分割线不归一化？还是侧栏特殊？未来添加右栏 + 左右侧栏呼唤是否同病？
> **这是第一次完整走「新能力设计流程」的任务**（用户拍板「先按流程走」）——8 维度设计前置见 §二。任务性质 = 归一化修复（非新能力）：无新 API / 配置 / 贡献点 / 控件，多数维度 = 现状确认。
> 清单指针：E5.8-执行清单 Phase 11.22 #146。

## 一、根因（file:line + 机制）

### 机制：网格槽位动态、handle 边缘硬编码

池网格列位随 `sidebarEdge` 动态推导（[gridLayout.ts:90-103](../../../../src/pool/hooks/gridLayout.ts)），**图标栏恒贴主侧栏外侧**（E5.8#37.6.5）：

```
sidebar 左槽（默认）:  [iconbar][sidebar][main][rightSidebar]   ← 硬编码恰好全对
sidebar 右槽（换边后）: [rightSidebar][main][sidebar][iconbar]  ← 两个全错
```

换边（`workbench.action.toggleSidebarPosition`，E5.8#37.6 swap 规则）把 SidebarZone/RightSidebarZone 整体换槽（gridLayout.test.ts:136-158 已锁此行为），但两个组件的 handle 边缘 + 拖拽方向**写死**：

| zone | handle 类（写死） | growSign（写死） | 证据 |
|---|---|---|---|
| SidebarZone（主侧栏） | `vertical right` | `+1` | [SidebarZone.tsx:99](../../../../src/pool/zones/sidebar/SidebarZone.tsx#L99) / [:74](../../../../src/pool/zones/sidebar/SidebarZone.tsx#L74) |
| RightSidebarZone（右栏） | `vertical left` | `-1` | [RightSidebarZone.tsx:166](../../../../src/pool/zones/right-sidebar/RightSidebarZone.tsx#L166) / [:56](../../../../src/pool/zones/right-sidebar/RightSidebarZone.tsx#L56) |
| PanelZone（面板） | 四向 `handlePosition` **派生** | 按 edge **派生** | [PanelZone.tsx:54](../../../../src/pool/zones/panel/PanelZone.tsx#L54) / [:58](../../../../src/pool/zones/panel/PanelZone.tsx#L58) |

### 结果（两状态对照）

- **sidebar 左槽（默认）**：硬编码恰好对——sidebar 右缘 handle 正对主区 ✓；rightSidebar 左缘 handle 正对主区 ✓。
- **sidebar 右槽（换边后）**：sidebar 硬编码右缘 → handle 落在 **sidebar 与图标栏之间** ✗（用户观察到的症状）；rightSidebar 硬编码左缘 → handle 落在窗口最左缘 ✗。拖拽方向连带错（growSign 不随槽镜像——侧栏在右时向右拖才增宽，朝主区拖反而变窄）。

### 判定

**是分割线不归一化，不是侧栏特殊。** PanelZone 已是归一化样板（handle 落点 + 拖拽方向全从 edge 派生，所以「底部面板放上面分割线不会挨顶栏」——面板在上 → handle 锚底缘正对主区）。SidebarZone/RightSidebarZone 缺同一派生。且**问题现在就在**（右栏已存在 + 换边已存在），不是「未来右栏/呼唤才会同病」。

## 二、8 维度设计前置（首次全流程——设计摘要 + 关键决策）

> 任务性质注记：**归一化修复（非新能力）**——按 design-flow 定义可不走全流程；用户明确要求首次完整走流程作为试点，故逐维度回答（无变化维度 = 显式确认「现状即正确」）。

### ① 能力边界
- **壳能力**（池布局交互，非插件）。修复不改变能力边界，只修正已有行为的方向错误。
- **保底**：无插件时池分割线照常工作（换边机制是壳内置 #37.6）——不涉及新能力，无新增保底需求。

### ② API 设计
- **零新增 `window.linkdesk.*`，契约零变化。**
- rightSidebar 的 `edge` 由**池侧派生**（PoolZoneShell 从 `sidebar.edge` 对边反推，作 prop 传入），非插件 API——对齐 RightSidebarLayout 设计（[poolLayout.ts:84-85](../../../../src/core/types/pool/poolLayout.ts#L84-L85)「不携带自身 edge，swap 规则反推，防两处字面量」）。
- **通用优先**：复用 gridLayout 既存纯函数推导模块（S10 单一来源），新增 handle 方向派生 helper，零新设施。

### ③ 通信方式
- **零变化**。拖拽 commit 仍走 `window.linkdesk.pool.sidebarAction("setSidebarWidth")`（SidebarZone）+ `window.linkdesk.events.emit("rightSidebar:resize")`（RightSidebarZone）。数据流不变。

### ④ 壳侧代码设计
- 改动文件（零新文件）：
  - `src/pool/hooks/gridLayout.ts` — 增 handle 方向派生 helper（`handleEdgeForSlot(slot)`：左槽→`right`、右槽→`left`，handle 恒朝向主区）——与列位推导同一模块 = 单一权威。
  - `src/pool/zones/sidebar/SidebarZone.tsx` — handle class + growSign 从 `sidebar.edge`（DTO 已携带，[poolLayout.ts:57](../../../../src/core/types/pool/poolLayout.ts#L57)）派生。
  - `src/pool/zones/right-sidebar/RightSidebarZone.tsx` — 接收 `edge` prop，handle + growSign 派生。
  - `src/pool/PoolZoneShell.tsx` — 向 RightSidebarZone 传 `edge = sidebarEdge 对边`（sidebarEdge 已算出喂 grid，同一真相源，零第二字面量）。
- **单一权威**：edge 真相源 = LayoutEngine dock → 壳推 DTO；池侧 SidebarZone 读 `sidebar.edge`，RightSidebarZone 从 grid 同一输入反推。handle 方向派生集中在 gridLayout 一处，Sidebar/RightSidebar 消费。
- **硬约束合规**：无颜色 / 文字 / 路径 / 插件 ID 改动。归一化（#8）对齐 PanelZone 派生模式——同概念单写法。

### ⑤ 插件侧代码设计
- **零改动，零贡献点。** 分割线是壳机制（zone 分界线定义，非插件声明）——插件作者不感知。

### ⑥ 显示设计

- **与 #143 正交**：#143 改 handle **长相**（常态三点→hover 成线 + 线端圆角镜像 zone），本任务改 handle **位置派发**——不冲突，可先后独立实现。

### ⑦ 配置设计

- 换边仍走 `workbench.action.toggleSidebarPosition`（#37.6，既存）。池布局 DTO 零变化（SidebarLayout.edge 已存在；RightSidebarLayout **不加** edge——沿用反推设计）。

## 三、实现足迹（file:line 现状 → 改法，实现时对照）

| 位置 | 现状 | 改法 |
|---|---|---|
| `src/pool/hooks/gridLayout.ts` | 纯列位/行跨推导 | 增导出 `handleEdgeForSlot(slot: "left" \| "right")`：左→`right`、右→`left`（handle 恒朝向主区 = main 两侧栏之间） |
| `src/pool/zones/sidebar/SidebarZone.tsx:99` | `className="zone-resize-handle vertical right"` | `className={zone-resize-handle vertical ${handleEdgeForSlot(sidebar.edge ?? "left")}}` |
| `src/pool/zones/sidebar/SidebarZone.tsx:74` | `growSign: 1` | `growSign: sidebar.edge === "right" ? -1 : 1`（右槽朝主区=向左拖增宽） |
| `src/pool/zones/right-sidebar/RightSidebarZone.tsx:166` | `className="zone-resize-handle vertical left"` | `className={... vertical ${handleEdgeForSlot(edge)}}`（edge 新 prop） |
| `src/pool/zones/right-sidebar/RightSidebarZone.tsx:56` | `growSign: -1` | `growSign: edge === "right" ? -1 : 1`（右槽左缘 handle 朝主区 = 向右拖增宽 → +1；左槽右缘 → -1） |
| `src/pool/PoolZoneShell.tsx:109-113` | `<RightSidebarZone rightSidebar={...} />` | 加 `edge={sidebarEdge === "left" ? "right" : "left"}`（sidebarEdge 已算：`layout.sidebar?.edge ?? "left"`，行 40 同源） |
| `src/pool/hooks/gridLayout.test.ts` | — | 补 handleEdgeForSlot 断言（两槽） |

> **growSign 语义核对**（对 PanelZone.tsx:58 先例）：`edge === "bottom" || "right" ? -1 : 1`——右缘 handle 朝左拖（负 delta）增宽 → -1。故**左槽**（handle 右缘）growSign = +1；**右槽**（handle 左缘）growSign = -1。两栏各自按自己槽位取号，与侧栏/右栏身份无关——派生唯一，语义单一。
