# 06 · 尾巴总账与验收（「换一套设置插件，GUI 不退化」）

> 本篇是你的第 1／4 条令的落点：**「完善尾巴，确保万物皆可插件，当前设置插件内的不能留尾巴」**、**「若有大量还没接上的，必须接上。我哪怕换了一个设置插件，接上线仍能够 GUI 层面操作，而不是说 GUI 退化」**。
> 做法照你的第 2／3 条令：**「你修 `@linkdesk/ui` 和插件仍在自画的都是修，为什么不按归一化修」**、**「设置插件是外部插件引用 `@linkdesk/ui` 的一个官方示例插件，必须标准」**。
> 逐格清点的是**实况**（文件 ＋ 行号），不是意图：顺手把本夹旧版里「两份拷贝」「A 案先止血」那些作废口径一并改掉。

## 一、判据：什么算「尾巴」

| 代号 | 判据 | 算不算尾巴 |
|:--|:--|:--|
| **T-A** | **消费宿主声明的控件／动作**（`uiHint` / `renderHint` / `type` 词表里的形态 ↦ 有内部几何或交互组成的**复合控件**），而渲染体住在插件私有件里 | 🔴 **算**——换一个渲染方就要重画一遍，且大概率画得不一样（本案的串色就是活证据） |
| **T-B** | 单个**原生元素** ＋ **宿主 CSS 类**（如 `<input className="ldk-input">`），外观由宿主供给 | ⚪ **不算**（宿主已供给外观）；但若它其实是某个 `uiHint` 的组成半，按 T-A 一起收 |
| **T-C** | 渲染方**自有**的布局／派生逻辑（行怎么排、搜索怎么过滤、分组怎么折叠、菜单项怎么列） | ⚪ **不算**——那正是「插件」该做的事；⛔ 强行共享会把共享层变成第二套设置页 |

⇒ 一句话：**凡「宿主声明的控件」，共享件里必须有它的渲染体；渲染方只许做接线（把宿主命令/数据注进共享件）。**
