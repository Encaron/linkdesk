# 原生模块清单——E5.8#4 落盘物

> **对应清单任务：E5.8#4**（[../E5.8-执行清单.md](../E5.8-执行清单.md) Phase 1）。
> 目的：供应链纪律——记录项目每个带安装行为（install script / 二进制下载）的依赖，**干什么、为什么需要、风险面**。
> 现状盘点（2026-08-19）：仅 2 个（serialport 的 C++ 绑定 + electron 的二进制下载），均为**预编译下载/加载**，无编译期任意代码执行。

## 1. @serialport/bindings-cpp@13.0.0（serialport 的原生绑定）

| 项 | 值 |
|:--|:--|
| 安装链 | `serialport@13`（主包，纯 JS）→ 依赖 `@serialport/bindings-cpp@13.0.0` |
| install script | `node-gyp-build` |
| 干什么 | `node-gyp-build` 在安装时查找随包分发的预编译二进制 `prebuilds/<platform>-<arch>/`（上游用 `prebuildify --napi` 预构建），**找到则直接加载（零编译）**；找不到才抛错提示需编译环境 |
| 为什么需要 | 串口 API 是 OS 原生能力（Windows WinAPI / Posix termios），纯 JS 无法访问——bindings-cpp 是唯一 C++ 桥。安装失败 = `require('serialport')` 报 native module 错 |
| 风险面 | prebuilds 无匹配 ABI → 安装报编译错（本机 Node 24 的 prebuilds 已覆盖，实测 `npm install` 零告警）；不做编译期任意代码执行 |

## 2. electron@43.2.0（桌面运行时二进制）

| 项 | 值 |
|:--|:--|
| 安装链 | `devDependencies.electron`（dev 工具链，运行 `electron .` 用） |
| install script | **无 package.json scripts**（43 起不再 postinstall）——下载逻辑在 `install.js`（bin 名 `install-electron`）+ `index.js` 懒触发 |
| 干什么 | electron 包 = JS 壳（`index.js`/`cli.js`/`electron.d.ts`）+ 下载器。`require('electron')` 时若 `path.txt`/`dist/` 缺失 → `index.js downloadElectron()` spawn `node install.js` → `install.js` 用 `@electron/get` 的 `downloadArtifact` 下载预构建二进制到 `dist/` |
| 为什么需要 | Electron = 预编译桌面运行时（Chromium + Node + 主/渲染进程），npm 包不携带二进制（~200MB），安装/首次使用时从发布源下载 |
| 风险面 | 下载源被墙 → 走 `.npmrc` `electron_mirror`（中国镜像，@electron/get 读取）；`node_modules/electron/dist` 被删后 require 自动重下；electron 官方校验和 `checksums.json` 校验二进制 |

## 关联配置

| 配置 | 值 | 作用 |
|:--|:--|:--|
| `.npmrc` `electron_mirror` | `https://npmmirror.com/mirrors/electron/` | @electron/get 专属镜像（npm 不认此 key，警告无害）——中国加速下载 |
| `.npmrc` `engine-strict` | `true` | 配合 `package.json` `engines.node >= 24.0.0`——错 Node 版本 `npm install` 立即 EBADENGINE 拒绝 |
| `package.json` `engines` | `node >= 24.0.0` | 开发机 v24.16.0；Electron 43 自带 Node，engines 只管 dev 工具链（vite/tsc） |

## 供应链纪律总结

- **不装**：`pyright` / `@codemirror/language` / `@monaco-editor/react` / `@types/iconv-lite` 等死依赖（#2 knip 已删）。
- **不切包管理器**：pnpm 10+ 的 `allowBuilds` 白名单是 pnpm 专属——npm 等价物 = 本清单 + `engines` + `engine-strict`。
- **若未来切 pnpm**：把本清单的 2 个原生模块记入 pnpm `allowBuilds`（build scripts 白名单），再切。
