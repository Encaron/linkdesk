# 门外自检与异步相位（S5 · S6）

> 归属：[00-提案](00-提案.md)。S5 是**唯一能防复发**的机制；S6 把「还在跑」从感觉变成句柄。

---

## 一、S5 · `doctor --blind`（🥇）

### 为什么是它

现有百余条 `check-*.mjs` 全是**从里往外看**（源码/门禁/构建）。没有一个机制站在门外，按外部 AI 的真实路径走一遍。所以 B1/B2 踩到的坑，都能在 CI 全绿的情况下存在。

### 设计

一条命令，模拟「零资料、看不见界面」的调用者：

```
ping
 → describe（严格 JSON ＋ apiVersion ＋ 每条带 activation/risk/returns）
 → 选一条 entry 级命令：openPort（或任意可逆的写操作）
 → mark
 → readSince（断言回执同一深度）
 → 变更命令（send/set 类）：必须有后置状态可读，⛔ 禁 {} / null
 → paused 场景：必须如实（⛔ 禁静默空数组）
 → 错误路径：无视图调 view 命令 ⇒ EVIEWREQUIRED；不存在命令 ⇒ EUNKNOWNCOMMAND
 → returns 漂移抽样：声明的键 vs 真实回执的键
 → 收尾：closePort / reset，确认无残留
```

### 铁律

- ⛔ **不进 `npm run check`**——要活实例，与 `dev:driver` 同级；**发版前人工跑一次**（决策 #1）。
- ⛔ **必须通用**：只是「门外 AI 的自检」，⛔ 不写成串口专用。断言里只允许出现**通用不变式**（深度/后置状态/如实/有码），⛔ 不出现串口知识（游标语义、波特率、AT 指令）。
- **B2 的拔插场景是它的天然用例**：拔插后断言状态不撒谎（`open:true` 必须是真开的）。
- **断言失败必须可定位**：每条断言给 `{assertionId, 期望, 实际, 复现命令}`，⛔ 只打「FAILED」。

### 归一化

- 断言与执行共用**同一套** CLI 客户端（`bridge-client.mjs`）——⛔ 为 doctor 另写一套 HTTP/JSON 处理，否则测的不是 AI 走的路。
- 每个断言一条 id；`doctor --list` 能列出全部断言，`doctor -k <id>` 能单跑——这同时是文档的真相源（⛔ 另写一份「自检项说明」）。

### 不做

- ⛔ 不做自动修复：doctor 只诊断，改由人/AI 决定。
- ⛔ 不把断言数量当 KPI：**一条能抓住回归的断言 > 十条永远绿的断言**。

## 二、S6 · 异步相位可查询（🥇）

### 问题

B2-5：「EPENDING 后没法确认何时结束，只能干等」。`EPENDING` 只说「还在跑」，没有句柄。

### 设计

| 环节 | 形态 |
|:--|:--|
| 命令声明 | meta 增可选 `async?: true` |
| 执行 | 异步命令立即回 `{ok:true, pending:true, opId}`，**不再干挂** |
| 查询 | `exec --status <opId>` ⇒ `{state:"running"\|"done"\|"failed", result?, error?, startedAt, elapsedMs}` |
| 事件 | `log` 流里带 `op.completed` 事件（字段同上），订阅方不必轮询 |
| 生命周期 | `opId` 有 TTL（默认 10 分钟），过期 ⇒ `EOPEXPIRED`（⛔ 返回空对象） |

### 归一化

- **op 注册表只有一份**，住壳（与「判定唯一实现」同构）；⛔ 插件自建 op 表、CLI 自建缓存。
- 插件只做一件事：在 `registerCommand` 的 meta 里声明 `async: true`；壳自动包 op 并回 `{pending:true, opId}`；⛔ 插件调 `runAsync`、⛔ 自己管状态机。
- `state` 的取值是**封闭枚举**（`running/done/failed/expired`），⛔ 插件自造 `"processing"` 之类。

### 边界

- ⛔ 不把同步命令包装成异步（无必要，且破坏现有调用方）。
- ⛔ 不做 `--wait` 长轮询内建到命令里：等待是**调用方**的策略（05 案的 `--wait/--until-regex` 是插件语义），本档只提供**查询句柄**。

## 三、判据（对着 07 过一遍）

| 判据 | 本条要求 |
|:--|:--|
| 归一化 | doctor 复用同一 CLI 客户端；op 注册表一份；断言 id 即文档 |
| AI 友好化 | 失败可定位（assertionId ＋ 复现命令）；异步有句柄可查（opId） |
| 无硬编码 | ⛔ 断言里写插件 id/串口语义；⛔ 命令特判 async |
| 无死代码 | 每条断言都有「它防的是哪条回归」的来源（B1-x / B2-x / I-x） |
| 高内聚低耦合 | doctor 只依赖门外契约（CLI/describe），⛔ 不 import 插件源码 |
| 文件禁止平铺 | 两主线住本一档，各自验收分节 |

## 四、验收

1. **doctor 能抓回归**：人为把某条命令改成返回 `{}` ⇒ doctor 红，并指出断言的 `复现命令`。
2. **doctor 通用**：同一份 doctor 对 file-tree（或编辑器）也跑通；改串口插件不会让 doctor 变成串口专用。
3. **拔插**：运行中拔掉设备 ⇒ 断言「状态不撒谎」红（当前 `open:true` 撒谎是已知缺陷，修好后转绿）。
4. **S6**：`async` 命令立即回 `opId`；`--status` 三次采样能看到 `running → done`；过期回 `EOPEXPIRED`。
5. **事件**：订阅 `log` 能收到 `op.completed`，字段与 `--status` 一致。
6. `npm run check` 全绿（doctor 不在其中，人工跑通即可）。
