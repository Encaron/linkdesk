## 一、四档语义（用户可见）

| 档 | id | R0 读 | R1 可撤销写 | R2 有副作用写 | R3 不可回退 | 一句话 |
|:--|:--|:--:|:--:|:--:|:--:|:--|
| **只读** | `read` | ✅ | ⛔ | ⛔ | ⛔ | 只让 AI 看 |
| **逐次确认** | `ask` | ✅ | 询问 | 询问 | 询问 | 每一步都点头 |
| **自主**（默认 D1） | `auto` | ✅ | ✅ | ✅ | 询问 | 干活模式；危险动作仍问 |
| **完全访问** | `full` | ✅ | ✅ | ✅ | ✅ | 全权，常驻到用户关（D2） |

- **默认值**：`auto`（D1 已拍板）。理由：AI 通道本身默认关（`ai.mcp.enabled`/`ai.cli.enabled` 默认 false），**用户主动开通道 = 一次授权**；把默认档再设成「每步都问」等于授权了还要反复确认，正是用户抱怨的形态。
- **完全访问常驻**（D2）：不做 TTL；靠「常显徽标 + 一键降档 + 通道关闭即失效」兜底。
- **升档**：只读→逐次→自主→完全访问；升到 `full` 必须二次确认（D8）。
- **降档**：任何档位→任意更低档，立即生效，不需确认。

> 🔴 不变式：**「没点头 = 不做」**。所有档位都遵守 fail-closed（见 02 §五）。

## 二、风险分级 R0–R3

判据三条：**可不可回退 / 影不影响别人 / 动不动程序本体**。

| 级 | 定义 | 例子（初稿） |
|:--|:--|:--|
| **R0 读** | 只读，无副作用 | `describe` / `ping` / `tabs` / `notifications` / `log`；`getConfiguration` / `listConfigurations` / `getLayout` 等读命令 |
| **R1 可撤销写** | 可一键撤回、不碰盘上用户数据、不跑陌生代码 | `openTab`；开关面板/视图显隐；布局分屏；切主题/外观；搜索/过滤；`setConfiguration` 写**非安全**键 |
| **R2 有副作用写** | 落盘、改插件状态、跑已装代码、发数据 | 写工作区文件；装/停用/启用插件（`install`）；串口发数据；`clearConfiguration` 清用户覆盖；批量操作 |
| **R3 不可回退/动本体** | 换掉正在跑的代码、删数据、起任意进程 | `update.openUpdateFlow`（下载并装新版本）；卸载插件；删除工作区/回收站清空；打开 CDP 调试端口；**任何新增的「起进程」能力** |

**默认分级的保守规则**：命令未登记 ⇒ 按 **R1** 处理并打 warn（不是 R0，也不阻断）；`kind:"write"` 的 op 未登记 ⇒ **R2**。登记表是白名单式增补，见 §三。

## 三、风险登记表（唯一真相源）

落点：`electron/services/aiBridge/policy/risk.ts`

```ts
export type Risk = "R0" | "R1" | "R2" | "R3";
export const COMMAND_RISK: Record<string, Risk> = {
  // R0
  "workbench.action.getConfiguration": "R0",
  "workbench.action.listConfigurations": "R0",
  // R1
  "workbench.action.setConfiguration": "R1", // ai.* 另有拒写（settingsCommands.ts:41）
  "workbench.action.openKeybindingsSettings": "R1",
  // R2
  "workbench.action.clearConfiguration": "R2",
  // R3
  "update.openUpdateFlow": "R3",
};
export const OP_RISK: Record<string, Risk> = {
  describe: "R0", ping: "R0", tabs: "R0", notifications: "R0", log: "R0",
  openTab: "R1",
  exec: "R1",        // 占位：真正判的是目标命令，见下
  install: "R2",
  notifyAction: "R1", // 真正判的是按钮绑定的命令
  requestElevation: "R3", // 请求本身不改状态，但按最高风险走人工
};
```

- **`exec` / `notifyAction` 的判定对象是目标命令**，不是 op 本身：`decide` 取 `riskOfCommand(targetCommandId)`。
- 原 `ASK_FIRST_COMMANDS` / `ASK_FIRST_OPS` **并入本表**（`R3` 项 = 必问），⛔ 不保留第二份名单（无死代码 / 单一真相源）。
- 新命令进入命令面时，`check-ai-policy` 要求登记（见 03 门禁）；未登记不阻断但 warn，并在 `describe` 自述里标 `unregistered`。

### 3.1 第三方命令的风险声明（新增契约）

壳无法从外部插件命令推断语义 ⇒ 清单新增可选字段 `contributes.commands[].risk`（`enum R0–R3`）。

**合并优先级**（`riskOfCommand` 唯一实现）：

```
壳内建 COMMAND_RISK（安全关键命令，壳说了算）
  > manifest commands[].risk（作者声明）
  > 兜底 R1（kind:"write" 的 op 兜底 R2）
```

- 官方（FACTS 15 仓）**写命令必须声明** `risk`（门禁硬红，D11）；第三方先 **WARN** 引导，不阻断发布。
- 壳不认识的风险值 ⇒ 加载时明确告知，⛔ 不静默按 R1 放行（对齐插件权限系统「壳不认识的能力」口径）。
- 市场安装确认是否展示「最高风险」= D10，未拍板不实现。

## 四、判定矩阵（`decide` 的唯一实现）

| 档 \ 风险 | R0 | R1 | R2 | R3 |
|:--|:--:|:--:|:--:|:--:|
| `read` | allow | deny | deny | deny |
| `ask` | allow | ask | ask | ask |
| `auto` | allow | allow | allow | ask |
| `full` | allow | allow | allow | allow |

```ts
export type Decision = "allow" | "ask" | "deny";
export function decide(mode: PolicyMode, risk: Risk): Decision;
```

- 纯函数、零 IO、零 UI import；单测覆盖 4×4=16 格 + 3 条未登记兜底。
- **不做「按插件/按页面」的第二套策略**（插件权限是另一档，⛔ 混进来）。

## 五、状态与事件（单一来源）

| 项 | 落点 | 说明 |
|:--|:--|:--|
| 当前档位 | 配置键 `ai.policy.mode`（`enum`，默认 `auto`） | 声明在 `src/App/config/aiBridge.ts`，归「开放范围与安全」分节 |
| 策略求值 | `policy/decide.ts` 纯函数 | 所有入口唯一调用点 |
| 状态读取 | 命令 `aiPolicy.getState`（R0） | 返回 `{ mode, riskTable, protectedCommands, effectiveAt }` |
| 变更事件 | `onDidChangePolicy`（壳内事件） | 状态栏徽标、设置页、账本三处订阅同一事件，⛔ 各自拉取 |

- 档位变更**必须**同时：① 写配置（user scope）；② 打账本（谁/何时/从什么到什么/是否用户批准）；③ 发事件。
- 账本条目复用 aiBridge 既有 ledger（`whitelist.ts` 的 `LedgerEntry`），不新建第二条审计流。

## 六、审计

| 事件 | 记什么 | 去向 |
|:--|:--|:--|
| 档位变更 | `mode_from` / `mode_to` / `approvedBy:"user"` / `via:"settings"|"elevation"` | 内存账恒记；盘上日志受 `ai.auditLog.enabled` 控制（沿用既有语义） |
| allow 执行 | op / commandId / risk / mode | 同上 |
| ask 结果 | allow/deny / 用户等待时长 | 同上 |
| deny | op / commandId / risk / mode / 建议（requestElevation） | 同上 |

> 审计不是安全边界，但必须回答「AI 以为没做、其实做了」与「谁把档位改了」两类问题。
