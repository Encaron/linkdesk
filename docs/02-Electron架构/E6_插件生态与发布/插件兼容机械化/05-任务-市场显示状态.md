### 第四步：显示口径四条 ＋ 帮助卡纪律两条（**写死，判据要机械核**）

1. 🔴 **只说用户能感知的事**：能不能装、会不会显示不正常、他该做什么。⛔ **不出现处数、名字、依赖、源码、文件行号、「重新打包」**——那些是插件作者面的说法（三套词表 = [00 号档 §〇d](00-整理档案.md)；领域类比：手机厂给用户的更新说明不写改了哪个文件）。
2. 🔴 **只陈述事实，⛔ 不派活给用户**：改造插件是插件作者的事；用户能做的只有「更新 LinkDesk」「更新插件」两件。
3. **不设阈值**：「久未更新」**不是罪**，日期只做事实展示 ⇒ **新增文案里不许出现**「超过 N 天 / 过期 / 不推荐」这类词。
4. **状态词定稿五个**（正常 / 兼容 / 部分不适配 / 不适配 / —）：与 [00 号档 §〇d](00-整理档案.md) **逐字一致**，⛔ 不许临时换词、不许加第六个词；**只在真有问题时给警示色**（部分不适配 / 不适配）；动作与状态分离：**标不改按钮行为**。
5. 🔴 **帮助卡只走既有共享件 ＋ 悬停触发**：容器 = `@linkdesk/ui` 的 `OverlayPortal`（照 `SearchView/AddSourcePopup.tsx`）——⛔ 不许插件自己写 portal / 定位 / z 序（⚠️ **卡体本身**：格 7 已落地就用共享件 `HintCard`，见 §二第三步；本格临时自有卡的情形，那一棒负责替换）；**触发 = 鼠标停在状态标上出、移开消失**（约 400ms 悬停意图延时；键盘 <kbd>Tab</kbd> 聚焦同样出卡、失焦 / Esc 关；触屏点一下出、点外关）。⛔ 不上右键（本行右键已是齿轮菜单）、⛔ 不做 toast / 弹窗 / 暗屏大面板、⛔ 不做「点击弹出」的弹层、⛔ 卡内不放链接与按钮（`pointer-events:none`）。
6. 🔴 **入口不靠文字行、也不靠原生 `title`**：信息栏「兼容性」组**只留一行状态**，⛔ 不写「点这里看说明」「鼠标停上来看」这类提示（悬停本身就是入口；而且那是指使鼠标，触屏用户看不懂）；⛔ 状态标上**不挂 `title`**（`ldk-badge` 自带 `title` 提议，但原生提示会与卡同屏打架）。
