# 01-任务书 · PDF 阅读器插件（pdf-reader）

> 立项日 2026-10-07 · 提出与拍板 = 用户（Encaron）· 施工 = AI 接力制（一棒一格，见 [02-执行清单.md](02-执行清单.md)）。
> 本任务书照 [docs/开发管理/新能力设计流程.md](../../开发管理/新能力设计流程.md) §三「立任务 → 实现」强制步骤 ＋ §六 8 维度设计清单写全——方案写全，不写一句话概括（ai-workflow-canon §1.4）。

## §一 目标与非目标

**目标**：官方示例级 PDF 阅读器插件——单击 pdf 开真阅读器（渲染/翻页/缩放/搜索），卸载即退回；入库官方市场集市；全程零壳改动、零壳依赖。
**非目标**（不做，立项即冻结）：编辑/另存 pdf；内容提取面（pdf 转文本）；右键菜单贡献（v1）；进厂种子；向壳申请任何新 API/通道；**「仍旧以本插件强开」兜底钮/命令**（editor 的 forceOpenAsText 是文本兜底角色自有动作，pdf 无此角色——2026-10-07 用户拍板，错误态改照 editor `BinaryNotice` 同款两钮）。**后续升级点（未立案、非 v1 承诺）**：手势动作、编辑（涂鸦/批注）、保存、打印机选项（直接打印）、打开资源管理器——见 [02-执行清单 §残余与远期](02-执行清单.md)。

## §二 红线（每棒进场重读，违者返工）

1. **不碰壳**：`E:\linkdesk` 一行不改（`src/` `electron/` `scripts/` `package.json` 全在内）。**只读参考是本棒的优势**：壳仓里能看到「默认打开方式与贡献点」整套机制的实现与 git 历史（`docs/04-软件更新/已落地/文件打开方式与贡献点/`），用它把声明面与打开链路写准、把示例做真。但判据反过来也成立：**插件必须做到「第二个作者不看壳源码也能做全」**——只允许依赖 npm 公共面（SDK 类型定义、作者面文档）。
2. **npm 纪律**：LinkDesk 侧基建只取 `~fengyili` 名下包（§五表 A）；纯第三方库允许直接装，但**逐个登记**进 §五表 B（名字、版本、为什么非它不可）。版本一律钉进 lockfile，禁 `latest`。
3. **质量七条（用户 2026-10-07 拍板，逐条落法）**：
   - **无硬编码**：颜色值收进插件自有 CSS 自定义属性（挂在 `pdf-` 命名空间类下，⛔ 禁定义 `ldk-*`）；命令 id、扩展名、默认值等常量收进单一常量模块；⚠️ **有意例外一处**：阅读底色**不跟主题系统**（用户拍板）＝插件自有固定配色，这不是硬编码违规、是产品决策——落法见 §四⑥。
   - **无死代码**：命令、配置、组件随其功能同棒上（没有「占位命令」「预留接口」）；每棒收尾 grep 自查未引用导出。
   - **归一化**：同一概念全仓一个名字（`filePath` 进出一致、页码一律 1-based、缩放一律倍率数字）。
   - **高内聚低耦合**：一域一夹一出口——引擎封装只从 `services/pdfDoc/` 聚合器露面、视图不摸 pdf.js 原语；命令层是视图与引擎之间唯一通道（视图不直调引擎、引擎不知视图）；对壳只经 `window.linkdesk.*` 一层。feature-folder 拆法（聚合器＋子模块，禁平铺大卸八块）。
   - **AI 友好化**（尤其）：每个用户动作至少一条非鼠标路径——命令族 `pdfReader.*` 全带 `description`＋`params`（照 [21-插件命令化规范](../../03-插件制造/21-插件命令化规范.md)）；结构化读数（当前页/总页数/缩放）可由命令返回；i18n 自有字典全覆盖（`ci-verify` ⑧段守）。
   - **插件自由化**：视角永远 = 第三方作者，只用 `window.linkdesk.*` 公共面；不假设壳里有什么特殊待遇。
4. **测试/门禁/机械检查一样不能少**（2026-10-07 补充）：插件仓三门 `test` / `verify` / `build` 每棒全绿才提交；T7 专项把覆盖补到位（SDK `vitest-setup` 基建，替身照契约非实现）。

## §三 验收总纲（发布那棒的判据）

- 壳侧 `git status` 干净（**零 diff** 是硬判据，不是口号）。
- dev 壳实机：文件树单击 pdf → 阅读器标签页（图标上标签栏）；**卸载本插件 → 退回**（壳若已落 T1 二进制兜底页则是干净提示，未落则还是 editor 乱码——如实记录，不粉饰）。
- 市场实机：官方目录搜得到、装得上、「检查更新」点得到（**发版 = 用户能在软件里点更新**，硬约束 24 口径）。
- Windows「打开方式」：装后 LinkDesk 出现在 pdf 的候选里。

## §四 8 维度设计前置（答案表）

**① 能力边界**：接管 `.pdf` 单击与 OS 打开方式；只读不写；不碰其他扩展名（svg 等不声明）。保底设计＝天然成立：没装本插件时 pdf 走壳现状（editor／兜底页），装了才接管——无需壳做任何保底。
**② API 设计**：零新宿主 API。只用现成面：`window.linkdesk.filesystem.readBinaryFile`（字节）、标签页创建（fileAssociations 声明驱动，壳自动路由）、`window.linkdesk.*` 其余按 SDK 0.1.89 类型定义取用。**以 SDK `.d.ts` 为唯一接口真相源，不对照壳源码写调用**（红线的自证）。
**③ 通信方式**：全走 `window.linkdesk.*`（插件通信标准铁律）；pdf.js worker 走插件包内自带的 worker 文件（vite 打包），不与宿主共享任何 worker/线程。
**④ 壳侧代码**：**零**。本插件不产生任何壳侧任务格；若施工中发现「非壳改不可」，停下上报用户——那说明设计错了，不是壳该改。
**⑤ 插件侧代码**：`contributes.fileAssociations`（pdf）＋ `contributes.commands`（§四⑥ 命令族）＋ `contributes.i18n`（自有字典）＋ `icon`；`appearsIn` 只开 `tabBar`；`tabBehavior.identityField = "filePath"`（同文件多开归一个标签，与 editor 同口径）；`core` 不填、`distribution` 不填（废弃字段）。目录形态 = [03-工程目录规范.md](03-工程目录规范.md)。
**⑥ 显示设计**（2026-10-07 已拍板定稿，规格 = [00.5-UI布局规格.md](00.5-UI布局规格.md)＋设计图 [06-设计图.html](06-设计图.html)）：标签页内全自绘（工具栏＋canvas 阅读区＋缩略图侧栏＋状态条）；**无图标栏图标**；插件图标 `resources/icon.svg` 上标签栏＋市场＋打开方式选择器＋README——**定稿 = 案 A 红带文档**（[07-插件图标-定稿.svg](07-插件图标-定稿.svg)，T1 原样取用）。阅读底色固定不跟主题：**纸白＋夜间两档**（用户拍板；sepia 留档不实现），token 表见 00.5 §二，切壳主题阅读区纹丝不动（实机验收）；工具栏/状态条用 `@linkdesk/ui` 跟主题（好看可用，用户拍板允许）。
**⑦ 配置设计**（2026-10-07 已拍板）：v1 只立一条 `pdfReader.defaultZoom`（`fitWidth | fitPage | percent`，出厂默认 **fitWidth 适宽**）——带 `description`（声明数据）＋ title/group（UI 文字，过 i18n）。底色档**不立配置项**（随环境频繁切的动作，走工具栏钮＋`pdfReader.setBackground` 命令同源）；缩放记忆、阅读进度记忆等不进 v1（不漫无目的加）。
**⑧ 验收**：每棒三门全绿＋实机验证点（清单见 02 各条）；发布棒加 §三 全套。
