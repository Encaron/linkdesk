# 02 — 卡片类型

> 8 种内置卡片——显示类 5 + 控制类 3。第三方插件可注册新类型（`CardRegistry.registerCard()`）。

---

## 类型总览

```
                        卡片
                         │
      ┌──────────────────┴──────────────────┐
      │                                      │
   显示类（MCU → 卡片）                   控制类（卡片 → MCU）
   只展示，不可操作                       可交互，发送命令
      │                                      │
  ┌───┼───┬─────┬──────┐          ┌──────┬───┴──┬──────┐
  │   │   │     │      │          │      │      │      │
 数值 仪表 折线  进度  指示灯      滑块   按钮   开关  （旋钮）
 卡片 盘  图    条                                      未来
```

## 一、显示类

### 1. 数值卡片（ValueCard）

```
┌──────────────┐
│ ≡ 温度    ✕  │
│              │
│   37.2 °C   │  ← 大字 + 单位
│              │
│  [进度条子项] │  ← 可选
│  [波形图子项] │  ← 可选
└──────────────┘
```

| 属性 | 默认值 | 说明 |
|------|------|------|
| `cardId` | 创建时绑定 | 对应 `[cardId, value]` |
| `cardId2` | `null` | 第二个数据源——`null` = 单值模式 |
| `protocolId` | `null` | `null` = 跟随标签页 / 显式绑定 "bracket"/"sbq"/... |
| 单位 | `""` | °C / bps / % / V |
| 小数位 | `1` | 0 / 1 / 2 / 3 |
| 升降箭头 | `true` | 最近 3 个采样点→↑/↓/→ 三角 + 颜色（绿涨/红跌/灰平） |
| 默认尺寸 | 2×2 | 允许 1×1 / 2×1 / 2×2 / 3×2 |
| 子项 | 无 | 可加进度条 / 波形图 / 数值大字 |

**双值模式（`cardId2` 非空时）：**
```
  室内 22.0°C ↑        ← cardId: temp_in
  室外 18.0°C ↓        ← cardId2: temp_out
```
两个值上下排列，各自升降箭头。

**渲染：** Fira Code 28px 粗体数字 + 12px 单位标签。数字变化时 300ms 过渡动画。

---

### 2. 仪表盘（GaugeCard）

```
┌──────────────┐
│ ≡ 压力    ✕  │
│    ╱╲       │
│   ╱  ╲      │  ← SVG 弧形仪表盘
│  ▕  ●       │
│   ╲  ╱      │
│    ╲╱       │
│  102.5 kPa   │
└──────────────┘
```

| 属性 | 默认值 | 说明 |
|------|------|------|
| `cardId` | — | 对应 `[cardId, value]` |
| `cardId2` | `null` | 第二个数据源——`null` = 单指针。设了 → 双指针（如设定值 + 实际值） |
| `min` | `0` | 仪表盘最小值 |
| `max` | `100` | 仪表盘最大值 |
| 单位 | `""` | kPa / °C / rpm |
| 颜色阈值 | `[]` | `[{ value: 80, color: "#EF4444" }]`——超过 80 变红 |
| 默认尺寸 | 2×2 | 允许 2×2 / 3×2 / 4×4 |
| 子项 | 无 | 通常不加子项——自身已占满空间 |

**双指针模式：** 两个指针不同颜色——指针 1 = 蓝色（实际值），指针 2 = 橙色（设定值/目标值）。

**渲染：** `<svg>` 弧形 + 径向指针。指针动画 300ms `ease-out`。

---

### 3. 折线图（LineChartCard）

```
┌──────────────────────┐
│ ≡ 心率趋势        ✕  │
│ ╱╲   ╱╲            │
│╱  ╲_╱  ╲___        │  ← Canvas 折线图 / 面积图
│              ╲ ╱╲  │
│               ╲╱  ╲ │
│  60s              0  │
└──────────────────────┘
```

| 属性 | 默认值 | 说明 |
|------|------|------|
| `curves` | `[{ cardId, label, color }]` | 曲线数组——长度 ≥ 1。颜色自动取 8 色轮（蓝绿橙红紫青黄粉），弹窗可覆盖 |
| `renderer` | `"canvas2d"` | 渲染后端——`"canvas2d"` / `"webgl"` / `"webgpu"`。低数据量 Canvas 2D 足够，百万点切 WebGL |
| 测量 | `{ enabled, items }` | 半透明叠加文字——每条曲线一块锚定四角。默认 Vpp + Freq，可选 Vmax/Vmin/Avg/RMS/Duty/波形类型 |
| 默认尺寸 | 4×2 | 允许 3×2 / 4×2 / 4×4 |
| 时间窗口 | `60` | 秒——显示最近 N 秒数据 |
| 采样率 | `10` | 次/秒——MCU 发多快就采多快，降低可平滑 |
| Y 轴范围 | `auto` | `auto` 自适应 / `[min, max]` 固定 |
| X 轴标签 | `""` | X 轴名称（如"时间"） |
| Y 轴标签 | `""` | Y 轴名称（如"°C"） |
| 样式 | `area` | `line` 折线 / `area` 面积图 / `bar` 柱状图 |
| 默认尺寸 | 4×2 | 允许 3×2 / 4×2 / 4×4 |

**多曲线模式：**
```
┌──────────────────────────┐
│ ≡ PID 整定           ✕  │
│ ╱╲   ── 设定值 (蓝)      │
│╱  ╲_╱╲  ── 实际值 (绿)   │
│        ╲╱╲    ── 输出 (橙)│
│           ╲___           │
│──────────────────────────│
│ 30s │ 60s │ 120s │ ⋯    │
│ 设定值 ☑ 实际值 ☑ 输出 ☑ │  ← 每条曲线独立显隐
└──────────────────────────┘

curves: [
  { cardId: "pid_sp",  label: "设定值", color: "#3B82F6" },
  { cardId: "pid_pv",  label: "实际值", color: "#22C55E" },
  { cardId: "pid_out", label: "输出",   color: "#F97316" }
]
```

**图例：** 右上角半透明浮层——每条曲线一行：色线 + label。自动生成，曲线 ≥ 2 时出现。单曲线不出现图例（不需要——就一条线）。

**曲线数量不设上限。** 一条 = 数组长度 1，两条 = 长度 2，PID = 长度 3+。底部显隐标签自动跟随曲线数量。

**渲染：** `<canvas>` 逐帧重绘。数据点存在内存环形缓冲区——窗口 60s × 采样率。

**高频操作：** hover 出现浮动工具栏——暂停/播放、时间窗口标签切换、曲线显隐、拖拽缩放。详见 [03-交互模型 §G-2](03-交互模型.md)。

### 4. 进度条（ProgressCard）

```
┌──────────────┐
│ ≡ 湿度    ✕  │
│              │
│ 58%          │  ← 数值
│ ██████░░░░   │  ← 水平填充条
│              │
└──────────────┘
```

| 属性 | 默认值 | 说明 |
|------|------|------|
| `cardId` | — | 对应 `[cardId, value]` |
| `min` | `0` | 进度条最小值 |
| `max` | `100` | 进度条最大值 |
| 样式 | `fill` | `fill` 填充 / `segments` 分段 |
| 默认尺寸 | 2×1 | 允许 1×1 / 2×1 / 2×2 |
| 子项 | 无 | 自身就是进度条，不需要子项重复 |

**渲染：** 圆角矩形背景 + 填充层。填充宽度过渡 300ms `ease-out`。

### 5. 指示灯（IndicatorCard）

```
┌────┐
│ ●  │  ← 绿 = 开
└────┘

┌────┐
│ ●  │  ← 红 = 故障
└────┘

┌────┐
│ ○  │  ← 灰 = 关
└────┘
```

| 属性 | 默认值 | 说明 |
|------|------|------|
| `cardId` | — | 对应 `[cardId, on/off/error]` |
| 状态映射 | `{ on: green, off: gray, error: red }` | 可自定义 |
| 标签 | `""` | 灯下方文字 |
| 默认尺寸 | 1×1 | 允许 1×1 |

**渲染：** 40px 圆点 + CSS `box-shadow` 发光。颜色过渡 200ms。

## 二、控制类

### 6. 滑块（SliderCard）

```
┌──────────────┐
│ ≡ 转速    ✕  │
│              │
│  75 %        │  ← 当前值
│ ●━━━━━━○───  │  ← 拖动条
│  0        100│
└──────────────┘
```

| 属性 | 默认值 | 说明 |
|------|------|------|
| `cardId` | — | 显示绑定 + 发送目标 |
| `protocolId` | `null` | `null` = 跟随标签页 / `"bracket"` / `"sbq"` / ... |
| `min` | `0` | 最小值 |
| `max` | `100` | 最大值 |
| `step` | `1` | 步进值——支持小数：0.1 / 0.01 / 0.001 |
| 单位 | `%` | % / rpm / V |
| 发送格式 | `[{cardId}, {value}]` → 用卡片自己的协议 encode | 拖动完成时发送 |
| 默认尺寸 | 2×1 | 允许 2×1 / 3×2 |

**步进精度：** `step: 0.01` → 滑块在 0–100 范围有 10000 个离散位置。拖动时显示两位小数。MCU 端 `analogWrite` 通常 0–255 → `step: 1, max: 255`。PID 参数 → `step: 0.01, min: 0, max: 10`。

**交互：** 拖动滑块 → `onChange` 实时更新本地显示 → 松手 → `onAfterChange` 发送 `[{cardId}, {value}]` 回 MCU。拖动期间不发送——避免串口洪水。MCU 回发确认后滑块位置不变（回发值 = 本地值 → 无变化）。

**双向逻辑：**
```
MCU 发 [speed, 50]   → 滑块在 50%
用户拖到 75%         → 本地显示 75%
松手                  → LinkDesk 发 [speed, 75]
MCU 执行              → 发 [speed, 75] 确认
```

### 7. 按钮（ButtonCard）

```
┌──────────────┐
│ ≡ 水泵    ✕  │
│              │
│   ┌──────┐   │
│   │ 启动 │   │  ← 点击触发单次命令
│   └──────┘   │
│              │
│  状态: 运行中 │  ← 硬件回发的状态
└──────────────┘
```

| 属性 | 默认值 | 说明 |
|------|------|------|
| `cardId` | — | 显示绑定 + 发送目标 |
| `protocolId` | `null` | `null` = 跟随标签页 / `"bracket"` / `"sbq"` / ... |
| 按钮文字 | `"启动"` | 按钮上显示的文字 |
| 发送前确认 | `true` | 默认开——点击 → 弹"确认发送 [fan, off]？"→ 确认 → 发送 |
| 发送格式 | `[{cardId}, {label}]` → 用卡片自己的协议 encode | 确认后立即发送 |
| 默认尺寸 | 1×1 | 允许 1×1 / 2×1 |

**为什么按钮默认开确认：** 开关拨动、滑块松手——这两个动作本身就是确认。但按钮一碰就发——最容易误触。防的不是"发了想撤回"，是"发之前确认一次"。MCU 几毫秒就收到——撤回没有意义。

**交互：** 点击 → 发送 `[{cardId}, {label}]` → 硬件执行 → 回发最新状态 → 按钮下方状态文字更新。按钮本体不锁——用户可多次点击（由硬件决定是否响应重复命令）。

### 8. 开关（SwitchCard）

```
┌──────────────┐
│ ≡ 风扇    ✕  │
│              │
│   OFF  ●    │  ← 拨动开关
│   ────      │
│              │
│   ON   ○    │
│   ────      │
└──────────────┘
```

| 属性 | 默认值 | 说明 |
|------|------|------|
| `cardId` | — | 显示绑定 + 发送目标 |
| `onLabel` | `"ON"` | 开启标签 |
| `offLabel` | `"OFF"` | 关闭标签 |
| `onValue` | `"on"` | 开启发送值 |
| `offValue` | `"off"` | 关闭发送值 |
| 默认尺寸 | 2×1 | 允许 1×1 / 2×1 |

**交互：** 点击 → 拨动动画 150ms → 发送 `[{cardId}, {onValue|offValue}]`。MCU 回发确认值 → 开关状态以回发为准。

**双向逻辑：**
```
MCU 发 [fan, on]  → 开关拨到 ON
用户点击 OFF      → 本地拨到 OFF → 发 [fan, off]
MCU 执行          → 发 [fan, off] 确认
```

**如果 MCU 拒绝命令：** 硬件回发仍是 `[fan, on]` → 开关回弹到 ON。**硬件是真相源。**

### 9. 表达式卡片（ExpressionCard）🆕

> 纯虚拟卡片——无 cardId，无 MCU。数据来自其他卡片的实时值，公式算出。

```
温度 → [temp_c, 37.0]          湿度 → [humid, 58]
  │                                │
  └── 数值卡片（cardId: temp_c）     └── 进度条卡片（cardId: humid）
        │                                │
        ├────────────────┬───────────────┘
        │                │
        ▼                ▼
  表达式卡片 A          表达式卡片 B
  "temp_c * 9/5 + 32"  "humid > 60 ? '潮湿' : '舒适'"
  → 98.6°F             → "舒适"
```

```
┌──────────────┐
│ ≡ 华氏度  ✕  │
│              │
│   98.6 °F   │  ← 公式: temp_c * 9 / 5 + 32
│   ← 37.0°C  │  ← 源数据提示（灰色小字）
└──────────────┘
```

| 属性 | 默认值 | 说明 |
|------|------|------|
| 公式 | `""` | 表达式——引用其他卡片的 cardId 作为变量 |
| 单位 | `""` | °F / kph / % |
| 小数位 | `1` | 0 / 1 / 2 / 3 |
| 依赖 | 自动检测 | 扫描公式中出现的 cardId → 自动订阅 |
| 默认尺寸 | 2×2 | 允许 2×1 / 2×2 |

**表达式语法：** 标准 JavaScript 表达式——`+` `-` `*` `/` `>` `<` `>=` `<=` `==` `!=` `&&` `||` `? :`。

公式中引用的 cardId 就是变量名——`temp_c` 自动取温度卡片的值，`humid` 自动取湿度的值。

**依赖自动追踪：** 扫描公式中的单词 → 匹配已存在的 cardId → 订阅它们的数据变化 → 任一依赖变化 → 重新求值 → 卡片更新。

**零 MCU 改动。** MCU 只管发 `[temp_c, 37.0]` 和 `[humid, 58]`——华氏度和"潮湿/舒适"判断全在 LinkDesk 侧完成。

### 10. 多字段卡片（MultiFieldCard）🆕

> 一个 cardId 发多个字段——`[imu, 0.12, -0.05, 9.81]` → X/Y/Z 三轴一张卡片。

```
┌──────────────┐
│ ≡ IMU     ✕  │
│              │
│ X:    0.12 g │
│ Y:   -0.05 g │
│ Z:    9.81 g │
│              │
│      ●       │  ← Canvas 3D 方向点
└──────────────┘
```

| 属性 | 默认值 | 说明 |
|------|------|------|
| `cardId` | — | 对应 `[cardId, field1, field2, ...]` |
| 字段定义 | `[]` | `[{ key: "fields[0]", label: "X", unit: "g" }]` |
| 可视化 | `null` | `null` 仅数字 / `"dot3d"` 3D 方向点 / `"bar"` 柱状图 |
| 默认尺寸 | 2×2 | 允许 2×2 / 3×2 / 4×2 |

**字段 key：** `fields[0]` = 第一个参数，`fields[1]` = 第二个。简单的数组下标——不用学新语法。

**GPS 示例：**
```
MCU 发: [gps, 116.40, 39.90, 45.5]

字段定义:
  fields[0] → 经度 116.40°
  fields[1] → 纬度 39.90°
  fields[2] → 海拔 45.5m
```

**三张单字段卡片 → 一张多字段卡片。** 减少画布碎片。

## 三、卡片类型注册（给第三方插件）

```typescript
// 第三方插件注册自定义卡片类型
import { CardRegistry } from "@src/core/CardRegistry";

CardRegistry.registerCard("thermometer", {
  type: "display",           // "display" | "control"
  label: "温度计",
  icon: "thermometer",
  defaultSize: { w: 2, h: 2 },
  allowedSizes: ["1x1", "2x1", "2x2", "3x2"],
  defaultSubItems: ["value"], // 默认启用的子项
  render: ThermometerCard,    // React 组件
});
```

注册后 → 工作台的"添加卡片"面板自动出现"温度计"选项。零核心改动。

## 四、卡片尺寸约束

每个卡片类型声明自己允许的尺寸范围：

```typescript
// 尺寸枚举
type CardSize = "1x1" | "2x1" | "1x2" | "2x2" | "3x2" | "4x2" | "4x4";

// 每个类型声明
interface CardTypeDefinition {
  defaultSize: CardSize;
  allowedSizes: CardSize[];   // 弹窗和 resize 把手只在这些尺寸间切换
}
```

**resize 行为：** 拖右下角把手 → 按 `allowedSizes` 数组顺序循环切换。不是任意像素拖拽——是固定尺寸枚举间切换。

## 五、卡片模板——存一套配置，一键套用 🆕

> 同一个项目建 5 张温湿度卡片——每张都重设单位、小数位、子项、规则。模板 = 存一次，套 N 次。

### 工作流

```
建好一张完整的温湿度卡 → 右键 → "保存为模板" → 命名 "温湿度标准"

下次建新卡片：
  右键空白区 → "从模板新建" → 选 "温湿度标准"
  → 新卡片出现，只需改 cardId 绑定
  → 其他设置（单位/子项/规则/尺寸/颜色）全部继承

改了模板 → 不影响已创建的卡片实例（模板是快照，不是引用）
```

### 存储

```json
// .linkdesk/workspace/templates.json
{
  "温湿度标准": {
    "type": "value",
    "w": 2, "h": 2,
    "settings": {
      "unit": "°C",
      "decimals": 1,
      "subItems": ["progress", "wave"],
      "rules": [
        { "condition": "value > 80", "color": "#EF4444", "blink": true }
      ]
    }
  },
  "指示灯——状态": {
    "type": "indicator",
    "w": 1, "h": 1,
    "settings": {
      "rules": [
        { "condition": "value == 'error'", "color": "#EF4444", "blink": true },
        { "condition": "value == 'ok'",    "color": "#22C55E", "blink": false },
        { "condition": null,                "color": "#64748B", "blink": false }
      ]
    }
  }
}
```

## 五-A、高自由度原则——所有可见元素可开关

> 卡片不替用户做决定。每一个可见元素 = 弹窗中一个开关。默认全开，用户自己关。

**通用开关（所有卡片类型都有）：**

| 开关 | 默认 | 说明 |
|------|:--:|------|
| 标题栏 | ☑ | 关掉 → 标题栏消失（纯内容卡片——适合指示灯/按钮） |
| 边框 | ☑ | 关掉 → 无边框（融入画布背景） |
| 阴影 | ☑ | 关掉 → 扁平化 |

**类型专属开关：**

| 卡片类型 | 可开关元素 |
|------|------|
| 数值卡片 | 标题栏 / 单位标签 / 升降箭头 / 边框 / 阴影 + 子项独立开关 |
| 仪表盘 | 标题栏 / 数字叠加 / 边框 / 阴影 |
| 折线图 | 标题栏 / X/Y 轴标签 / 图例 / 边框 / 阴影 |
| 进度条 | 标题栏 / 百分比数字 / 边框 / 阴影 |
| 指示灯 | 标题栏 / 标签文字 / 边框 / 阴影 |
| 滑块 | 标题栏 / 数值显示 / 刻度标记 / 边框 / 阴影 |
| 按钮 | 标题栏 / 边框 / 阴影 / 发送前确认 |
| 开关 | 标题栏 / ON/OFF 标签 / 边框 / 阴影 |
| 表达式 | 标题栏 / 单位标签 / 升降箭头 / 源数据提示 / 边框 / 阴影 |
| 多字段 | 标题栏 / 逐字段标签 / 边框 / 阴影 |

**和 `dependsOn` 的关系：**

```
dependsOn 管：这行该不该存在？（选了 A 才出现 B）
开关管：    B 存在后你要不要显示？（你不喜欢就关掉）

两个机制各管各的，不冲突。

例：
  dependsOn: accentMode=custom → 颜色选择器出现
  颜色选择器可见后 → 你仍然可以通过开关关掉整个"外观"分组
```
