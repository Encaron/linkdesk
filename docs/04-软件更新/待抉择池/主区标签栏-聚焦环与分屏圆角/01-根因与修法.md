# 01 · 根因与修法

> 回答两问：**为什么**（一条根因 → 五个症状 S1–S5）＋ **怎么修**（候选 ＋ 推荐 ＋ 已否决）。
> 证据分三类：🔬 实测 ｜ 🧠 据码（file:line 在证）｜ 🗣 你的观察（原话在证）。
> ⛔ 本档只写方案，**不写任务分工**（[04](04-任务清单.md)）／**不写发版连锁**（[03](03-实现交接.md)）。

## 一、轴一 · 症状 S1：环**画在被围住的内容之下**

**一条根因**：环挂在一个 `inset` 盒阴影上，而 `inset` 阴影的绘制次序是「**自身背景之上、子元素之下**」——面板里任何不透明的东西都会把它盖住。

```css
/* src/index.css:272-275（现状，逐字） */
.ldk-group-pane-focused {
  border-radius: var(--surface-radius, 0px);
  box-shadow: inset 0 0 0 1px var(--accent);
}
```

被谁盖住（三条，按面积）：

| 盖住者 | 覆盖范围 | 证 |
|:--|:--|:--|
| **35px 标签栏** `--bg-card`（内置主题不透明） | 面板上边一整条（左右贴边） | [GroupTabBar.css:8](../../../../src/pool/shared/group-tab-bar/GroupTabBar.css)；`TAB_BAR_HEIGHT = 35`（[layout.ts](../../../../src/pool/zones/main/MainZone/layout.ts)） |
| **视图内容层**（`top:35px → bottom:0`、左右贴边） | 下、左、右三边 | [TabContentLayer.tsx:57-67](../../../../src/pool/zones/main/MainZone/TabContentLayer.tsx)（`left:0 right:0 top:35 bottom:0`） |
| **不透明附图**（详情页里的图） | 局部 | 🗣 你的原话③「这个配图很可能就会把这个圈给盖住一下」 |

🔴 视图根多为不透明（欢迎页先例 `.ldk-welcome-page { background: var(--bg-window) }`）⇒ 内置主题下**三边全盖**。

## 二、轴一 · 症状 S2：可见性由内容不透明度**偶然**决定（实测）

🔬 手法：最小 Electron 页复刻真实结构（面板 div ＋ 不透明 35px 标签栏 ＋ `top:35px` 内容层）→ `capturePage().toBitmap()` 逐像素采样（一次性探针，未进仓）。

| 主题 | `--bg-card` / `--bg-window` | 实测 accent 像素 |
|:--|:--|:--|
| 内置 **dark**（`:root` 兜底） | `#2D2D2D` / `#1E1E1E`（不透明） | **0**（整圈不可见） |
| 内置 **light**（`public/themes/light.json`） | `#F5F5F5` / `#FFFFFF`（不透明） | **0**（整圈不可见） |
| 玻璃主题（`theme-aurora-glass` / `theme-panorama` / `theme-zones`） | `rgba(...)` | **透出**（环浮在颜色里） |

⇒ 🗣 你的原话①「**一般情况下**我聚焦之后周围会出现那个框」里那个「一般」，＝ 你当前主题的内容半透明的**偶然**结果，**不是设计**；原话③「**根据里面的内容**盖住」正是这条根因的直接印证。

## 三、轴二 · 症状 S3：左右分屏「这两栏其实是**连着的**」

1. 分屏的两栏**不是两个 zone**，是**同一个** `.ldk-main-zone` 里两个 `position:absolute` 的 div：`left/top/width/height` 全百分比，**无背景、无圆角、无阴影**（[MainZone.tsx:212-232](../../../../src/pool/zones/main/MainZone.tsx)）。
2. 「面」的契约只写在**六个 zone 类**上——`border-radius: var(--surface-radius)` ＋ `box-shadow: var(--surface-shadow, none)`（[index.css:404-417](../../../../src/index.css)）：`.ldk-titlebar / .ldk-icon-bar / .ldk-side-panel / .ldk-main-zone / .ldk-panel-zone / .ldk-status-bar`。**pane 一个都不吃。**
3. 缝系统（`--surface-inset`，2px/格 ⇒ 相邻两格 4px）只在**池网格格**生效：`.ldk-pool-grid-cell { padding: var(--surface-inset) }`（[index.css:358-362](../../../../src/index.css)）。pane 住在**格之内**，拿不到缝。
4. 缝上唯一的区分物 = `.ldk-split-handle`：**4px 级别的透明命中区**，静止只露 **3 个 2px 点**（`::before`，`--text-muted`，中心距 5px），**悬停**才把 2px accent 竖线淡入、点淡出（`::after` opacity 0→1）（[index.css:445-509](../../../../src/index.css)）。
5. 🔴 **缝其实已经存在——只是它没有颜色**：`computeLayout` 在两栏之间**留了一条 `HANDLE_PCT = 0.4%` 的空带**（[layout.ts:34](../../../../src/pool/zones/main/MainZone/layout.ts)；右栏从 `x + w0 + HANDLE_PCT` 起，[layout.ts:62](../../../../src/pool/zones/main/MainZone/layout.ts)），把手正好填满它（`w: HANDLE_PCT`）。**今天看不出它是缝**，两条原因：① **面板没有背景**（`MainZone.tsx:220-227` 只给定位 ＋ `overflow:hidden`）⇒ 空带里露的是 zone 的 `--bg-window`，而视图内容也涂 `--bg-window` ⇒ **同色**；② 命中区本身**透明**（把手只画那 3 个点）。⚠️ 这条空带的**分配**本身有账要还——它把第二栏整体推到 **100.4%**，导致外缘环被裁（**S5**，见 [§四之二](#四之二轴二--症状-s5第二栏越出容器外缘环被切)）。

🧠 结论：两栏共享同一张面（同 `--bg-card` 标签条 ＋ 同视图底色），彼此之间**没有背景、没有圆角**，那条 0.4% 的缝又**缺颜色**，只有 3 个 2px 小点 ⇒ 静止时在视觉上**就是一张面**——正是你说的「连着」。
⇒ 这条也决定了修法**很便宜**：缝的**位置**不必新造，**颜色**由「面」和「缝」补（[§5.2](#52-轴二--分屏成面p2) 甲／乙）；但那条空带**怎么扣**要动一行分配算式（[§5.5](#55-轴二--缝的几何归属s5)，[D5](04-任务清单.md)）——否则第二栏会越出容器（**S5**）。

## 四之二、轴二 · 症状 S5：第二栏**越出容器** ⇒ 外缘环被裁

🗣 **你的观察⑥**：「左右分屏后右半边那边外边的环的右边那一部分就没有了」「上下分屏的时候下边分屏的那个地方如果我聚焦的时候，那么下边那个部分的那个外面聚焦环的下半部分就没了——就是很底下那一点点」。

**一条根因（算术级）**：`computeLayout` 把**总宽**按比例切成 `w0 = w*s0`、`w1 = w*s1`（`s0 + s1 = 1` ⇒ **`w0 + w1 = 100%`**），却把第二个子盒放在 **`x + w0 + HANDLE_PCT`**，**宽度不减**：

```
第一栏：left = 0%          width = 50%    ⇒ 右缘 = 50.0%   ✅ 在容器内
第二栏：left = 50% + 0.4%  width = 50%    ⇒ 右缘 = 100.4%  ❌ 越界 0.4%
```

| 事实 | 读数 | 证 |
|:--|:--|:--|
| 切分用**未扣缝**的总量 | `w0 = w * s0` ／ `w1 = w * s1`（竖分同构：`h0 = h * s0` ／ `h1 = h * s1`） | [layout.ts:59-60](../../../../src/pool/zones/main/MainZone/layout.ts) ／ [:72-73](../../../../src/pool/zones/main/MainZone/layout.ts) |
| 第二子盒起点**加了**缝宽 | `computeLayout(node.children[1], x + w0 + HANDLE_PCT, …)`（竖分同理走 `y + h0 + HANDLE_PCT`） | [layout.ts:62](../../../../src/pool/zones/main/MainZone/layout.ts) ／ [:75](../../../../src/pool/zones/main/MainZone/layout.ts) |
| 缝宽 | `HANDLE_PCT = 0.4`（百分比） | [layout.ts:34](../../../../src/pool/zones/main/MainZone/layout.ts) |
| ⇒ 第二栏外缘 | **100.4%**（≈4px @1000px 宽） | 上式 |
| 容器**不裁** | `.ldk-main-zone` **没有** `overflow:hidden`（E5.8#98 为「环的四角不被切」而撤掉） | [index.css:270-271 注释](../../../../src/index.css) |

**为什么表现成「就没了很底下那一点点」**：面板自己的行内样式**有** `overflow:hidden`（[MainZone.tsx:220-227](../../../../src/pool/zones/main/MainZone.tsx)）⇒ 越界的是**整个 pane 盒**，它把自己连内容一起**平移**出容器，最外侧那 **1px 环带**整条落在窗口之外（环＝`.ldk-group-pane-focused` 的 `inset` 阴影，画在 pane 的几何边上）⇒ 右栏**右边那条**／下栏**底下那条**看不见，其余三边照常。⛔ 这不是「环被内容盖住」（那是 S1），是**环被移出可视区**——两症**同源不同病**。

**为什么只有第二栏**：第一栏 `left = 0`、宽 ≤ 100% ⇒ 永远在容器内；越界只发生在**第二个**子盒（以及嵌套时每一层的第二个子盒）。

**为什么一直没被发现**：① 越界量只有 **0.4%**（4px 级），且落在**窗口外**——没有滚动条、没有重叠错位可看；② 今天环在**内置主题下本来就整圈不可见**（S1/S2）⇒ 「少了右边一条」根本无参照；③ 你是在**玻璃主题**（内容半透明、环能透出）下才看到它——正好印证 [§二](#二轴一--症状-s2可见性由内容不透明度偶然决定实测) 的口径。

🧠 **性质**：这是**几何真源的一处记账错**，不是 CSS 能补的（`overflow` 那条路已在 §5.3 判死）。修法见 [§5.5](#55-轴二--缝的几何归属s5)。

## 四、轴二 · 症状 S4：圆角「变扭」与「斜掉」

三条机制各管一段，**谁都不管分屏 pane**：

| 机制 | 管什么 | 够不着 |
|:--|:--|:--|
| `app.surfaceRadius`（0–32 绝对 px，一拉六档 `--radius-*` 同值） | **组件**圆角 | 分区面 |
| `app.zoneRadius` ＋ `app.zoneRadiusScale`（0–32）⇒ 派生 `--surface-radius` | 六个 **zone** 的面圆角 | **分屏 pane** |
| 缝法则 `--surface-inset`（`--surface-radius` 为 0 则 0px，否则 2px；[constants.ts:10](../../../../src/core/services/ui/ThemeEngine/constants.ts) ＋ [tokens.ts:308-313](../../../../src/core/services/ui/ThemeEngine/tokens.ts)） | zone 之间的**缝** | **pane 之间** |

- **单面板**：pane 的四个外角**不是它自己的圆角**，是外层 `.ldk-main-zone` 的 `border-radius` ＋ `overflow:hidden` **裁**出来的（[index.css:419-434](../../../../src/index.css)）。
- **一分屏**：内侧那两个角**没有任何机制** ⇒ 直角；两栏也各自**不成面** ⇒ 「非常的变扭」。
- **「斜掉」**：环带 `--surface-radius` 圆角而内容直角 ⇒ 圆角弧**横切**方角（[index.css:270-271 的注释](../../../../src/index.css) 已承认「inset 阴影沿元素圆角走」，但没解决「环有角、内容没角」的**不同形**）。

### 四之三 · 方角的**两个来源**（2026-10-07 补录 · 回答你原话⑦之问）

> 三问：「**单独成面**是不是「单独成 zone」」／「我分两个屏**不就是多两个 zone**」／「如果没有强调色边框，那么**一切问题都将没有**」。

**1 · 层级：pane ⛔ 不是 zone。** 唯一真相链 ＝ `pool` → `pool-grid-cell`（网格格，由池 DTO／`computePoolGrid` 决定）→ `zone`（六个：titlebar／icon-bar／side-panel／main-zone／panel-zone／status-bar）→ **主区** → `group`（标签组，**即分屏槽位 pane**）→ `tab`（标签页）→ `view`（插件渲染）。
分屏动的是主区**内部**的 `layout.panels`（几个 `position:absolute` 的 div）⇒ ⛔ **不新增网格格、不改 DTO、不改 zone 计数** ⇒ **分两屏仍然是 6 个 zone**。「成面」＝借 zone 的**表面契约（形式 token：`--surface-radius`／`--surface-shadow`／`--surface-inset`／面色）**，⛔ 不是把 pane 提升为 zone（后者已在 §5.3 判死）。

**2 · 方角的两个来源（两者**都与环无关**）。** DOM 真相：`GroupPane.tsx` 注释「本组件**只渲染标签栏**」＋ `TabContentLayer.tsx` 注释「所有标签页内容**提升到 .main-zone 根级平级渲染**」。

| 角的来源 | 机制 | 为什么 pane 的圆角救不了 |
|:--|:--|:--|
| **上两角**（标签栏那侧） | 标签栏是不透明 `--bg-card` 的**子元素**，而 pane 自身**无圆角** ⇒ 标签栏方角盖在主区的圆角弧上 | 要给 **pane** 圆角＋自裁（D3-甲）才**顺带**裁掉标签栏直角 |
| **下两角**（内容层那侧） | 内容层是 pane 的**兄弟**、DOM 排在 pane **之后**、铺满 `top:35px` 以下 ⇒ 方角压在**主区自己的圆角弧**上 | 兄弟关系 ⇒ pane 的 `border-radius`／`overflow`／`padding` **一概够不着**内容 ⇒ 必须在 **`TabContentLayer` 内层**补圆角（D4-乙） |

**3 · 与环的因果关系（订正原话⑦点 3）。** 🔬 把环整圈拿掉，上面两处方角**一个不少**——成因是「子元素／兄弟元素盖住了主区自己的圆角」；环**只是让方角「看起来斜掉」**（环是圆的、切过方角 ⇒ 两者**不同形**）。⇒ ⛔「如果没有强调色边框，那么一切问题都将没有」**不成立**；反之 **修 S4 不需要动环**——环的存废（D1／D6）与 S4 **互相独立**。

**4 · 主题联动（实现前必看）。** 面色取 `--bg-card`、缝露的是 `--bg-window` ⇒ 二者**近色时「面」不可辨**（只剩把手 3 点）；兜底＝**D3-丁**（缝上常显 1px 分隔线）。🔴 实现前逐主题核对两键取值（内置 dark／light ＋ 官方 15 配色），见 [02 E17](02-边缘情况清单.md)。

## 五、修法（候选 ＋ 推荐）

### 5.1 轴一 · 环（P1）

| 案 | 做法 | 成本 | 判据 |
|:--|:--|:--|:--|
| **甲（推荐）** | 环从「pane 自身的 inset 阴影」改成 **pane 的覆盖层**：<br>`border-radius: inherit`（值仍由 pane 的 `var(--surface-radius)` 供给）、`inset: 0`、`border: 1px solid var(--accent)`、`z-index: 1`、`pointer-events: none` | **小**（CSS 1 处改 ＋ 1 处加；**不动 TSX**——挂类的条件与画环的条件天然重合） | ① 环压在标签栏与内容**之上** ⇒ 任何主题、任何内容（含附图页）都**全周可见**；② 全局 `box-sizing: border-box`（[index.css:199-201](../../../../src/index.css)）＋ `inset:0` ⇒ **零布局位移**（E5.8#30.15 的原不变量保住）；③ `pointer-events: none` ⇒ ⛔ 不吃点击，面板聚焦仍走 `mousedown`；④ `z-index: 1` > 内容层（`z:auto`，且是**兄弟节点、DOM 在后**——[TabContentLayer.tsx:50](../../../../src/pool/zones/main/MainZone/TabContentLayer.tsx) 原注释）＜ 把手 `--z-sticky`(200) |
| 乙 | 专画环的元素（TSX 加一层 `<div class="ldk-pane-ring">`） | 中（动 `MainZone` 池层热文件 ＋ markup） | 控制最强（可做环外发光 / 双环 / 失焦动画）；⚠️ 与甲等价效果却多动一处 markup |
| 丙 | 保留 inset 阴影，另给 pane 加 `outline` | 小 | ⛔ **判死**：`outline` 与 `inset` 阴影同属**元素自身的绘制层**，同样在子元素之下 ⇒ 盖住问题**一字未解**（这条是「看起来像修了」的陷阱，[02 E11](02-边缘情况清单.md) 之外单列于此） |

**推荐甲**。⚠️ 甲**不改** pane 的圆角值 ⇒ 「环与内容同形」的另一半（内容自己的圆角）属 **D4**；D4 不做时，`--surface-radius > 0` 下甲仍留 S4 的「圆角环套方内容」。

### 5.2 轴二 · 分屏成面（P2）

| 案 | 做法 | 成本 | 评价 |
|:--|:--|:--|:--|
| **甲（推荐）** | **分屏时才让 pane 成面**（pane 加稳定类 `ldk-group-pane` ＋ 分屏修饰类 `ldk-group-pane-split`，规则全走既有 token）：<br>① pane `border-radius: var(--surface-radius)` ＋ `background: var(--bg-card)`（面色）＋ `box-shadow: var(--surface-shadow, none)`；`overflow: hidden` **已在**行内样式上（圆角自裁现成）；<br>② 内容按 `--surface-inset`（2px）**内缩** ⇒ 相邻两栏的可见间隔 ≈ 2 ＋ 0.4% ＋ 2px（约 8px）——**缝的「位置」本来就存在**（§三 第 5 条），补上「颜色」就显形；⚠️ 但那条缝的**分配**要同笔还账（第二栏越界 0.4% ⇒ **S5**／[§5.5](#55-轴二--缝的几何归属s5)），否则成面后是「三边有框、一边被切」的残面；<br>③ **单面板不带修饰类** ⇒ 内缩 0、零新增 ⇒ 现状**逐像素零变化** | 中（CSS ＋ pane 加类 ＋ **`TabContentLayer` 内层补内缩**——⚠️ 内容是**兄弟**不是子节点，pane 的 `padding` **够不着它**，见 [03 §一](03-实现交接.md)） | ✅ **推荐**：一件解两症——「内侧直角」（各栏自裁圆角，[S4](#四轴二--症状-s4圆角变扭与斜掉)）＋「两栏连着」（面色 ＋ 缝）；判据与 [D1](04-任务清单.md) 的「是否分屏」**同一处** |
| 乙 | 缝上**常显** 1px 分隔线：把手 `::after` 由「**hover 才亮**」改为「**常显** `--text-muted`」（⚠️ 原写 `--separator`，2026-10-07 订正——见下方红字），hover **只换色**为 accent | **小（1 处 CSS 覆盖，零新 token）** | 最小改动；与产品先例（编辑器分组用 1px 边分隔）一致；⚠️ 只给「一条线」，**内侧直角仍在** ⇒ 你原话④的「圆角变扭」未解（可作降级案） |
| 丙 | 只把把手做大 / 常态点加深 | 小 | ⛔ 3 点**已在**（常态）而你仍觉得连着 ⇒ 已被你的观察筛掉 |

### 5.3 已否决

> ⚠️ **本节口径 2026-10-07 修订**（症状 S5 立案后）：「⛔ 不动几何真源」这句**不再无条件成立**——`HANDLE_PCT` 的**值**仍不许动、缩 rect 的 CSS 把戏仍不许用，但**缝的分配**（谁承担那 0.4%）**必须**动一行算式（[§5.5](#55-轴二--缝的几何归属s5)）。判断分界：**改「缝的宽／位置取值」＝否决；改「切分时先扣掉缝」＝必做**。

- ⛔ **给 pane 加 `margin` / `inset` 缩 rect**：pane 走 `left/top/width/height` **百分比**绝对定位（`MainZone.tsx:220-227`），`margin` 会把 `50%` 变成 `50% + 4px`（溢出），`inset` 与 `width/height` **互斥** ⇒ 只能改 `computeLayout` 做 px↔% 换算（几何真源被 CSS token 反噬）。**缝可由 pane 内层表达**，⛔ 不必把 CSS 变成几何真源的客户。

### 5.5 轴二 · 缝的几何归属（S5）

**目标**：两栏外缘都**落回容器内**（第二栏右缘／下缘 ≤ 100%），且缝的位置与宽度**一个字不变**。
