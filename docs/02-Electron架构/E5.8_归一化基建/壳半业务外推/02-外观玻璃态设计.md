## 一句话

**外观新增一个「图片配液态玻璃」主题风格——图全窗铺底（含主区），所有 UI 表面（标题栏/图标栏/侧栏/工具栏/面板/主内容区）变成半透明 + `backdrop-filter: blur` 的液态玻璃漂浮在图上。** 不删现有单色调主题——它是新增的独立风格，与 dark/light 正交可组合。壳给机制，玻璃主题业务做插件。

## 目标视觉模型（对标 macOS/VisionOS，非 VS Code）

```
图片层（全窗，z-index:0，position:fixed; inset:0）      ← 永远在，永远铺满（含主区）
  └─ 遮罩（rgba(0,0,0,var(--bg-mask))，对标 dsh mask-photo 0.88）   ← 可读性生命线
       └─ UI 表面（标题栏/图标栏/侧栏/工具栏/面板/主内容区）
            │  默认单色主题：不透明 + 直角贴边 → 图片完全盖住（= 现状）
            └─ 玻璃主题：rgba + blur + saturate + 发丝光边 + 悬浮圆角面板 → 图透出来，液态玻璃漂浮感
```

参照（ui-ux-pro-max 已查——硬约束 #16 已调用）：
- Glassmorphism：`backdrop-filter: blur(10-20px)`，`rgba(255,255,255,0.15-0.3)`，`border: 1px rgba(255,255,255,0.2)`，Z-depth 阴影
- VisionOS/Spatial：`blur(15-40px) saturate(180%)`，`rgba(255,255,255,0.15-0.3)`，`border-radius`，深度阴影

**VS Code 不是参照**——VS Code 无原生背景图（`backgroundImage` 假配置静默忽略，只靠第三方 CSS 注入 hack），且 UI 保持实心只挖透明洞。用户明确否定了「主区实心、四周露边」的折衷——要的是全窗图 + 全表面玻璃。

### 形态拍板（2026-08-17 mockup 验证）：悬浮圆角面板

mockup 实测暴露：**直角贴边 + 无缝 + 无投影的表面，玻璃化后图被糊成一块、与玻璃无边界**（用户反馈「侧栏模糊的看不了」）。三选一形态拍板——**悬浮圆角玻璃**（VisionOS 灵魂）：

- 每个表面 = **圆角悬浮面板**：四周留缝 + 投影 + 发丝光边 + 顶部高光（受光）
- 图从面板缝隙透出 → 玻璃「浮在图上方」，表面与图有清晰边界
- **不写死代码**：悬浮 = 三个变量 `--surface-radius`/`--surface-inset`/`--surface-shadow` 的一个取值，**默认零值 = 现状直角贴边无缝无投影**（旧主题零变化，互切零残留）
- 圆角大小、留缝宽窄、投影有无全部可在设置滑杆/主题声明中调——**用户自由度三层**（滑杆全局默认 / 主题 per-surface 覆盖 / 用户配置覆盖基线）

另：**per-surface blur 差异化**（mockup 实测）——窄表面（侧栏/图标栏）blur 大 → 图糊成色块不可辨，降到 8px；大表面（主区/状态栏）氛围 blur 18px；悬浮面板 20px。

## 技术方案细节

### 主题类型：C 组合式（正交质感轴）

`type` 保持 `dark/light` 二值——只管**明暗对比度**这一轴（文字可读性），现有 CSS `[data-theme="dark"]`/`[data-theme="light"]` 选择器**零改动**。质感是另外两根正交轴：

```jsonc
{
  "name": "Aurora Glass",
  "type": "dark",                          // 照旧——管对比度
  "colors": { "--bg-window": "rgba(30,30,30,0.6)", ... },   // 表面变半透明
  "surface": {                              // 质感轴 1：玻璃 + 悬浮圆角面板
    "type": "glass",
    "blur": 18,                             // backdrop blur px
    "saturate": 1.5,                        // 饱和度增强
    "tint": null,                           // 玻璃着色（可选）
    "radius": 10,                           // 悬浮圆角 px（默认 0 = 直角）
    "inset": 8,                             // 四周留缝 px（默认 0 = 贴边）
    "shadow": true                          // 投影浮起（默认 false = 无浮起）
  },
  "background": {                           // 质感轴 2：图片
    "image": "assets/aurora.jpg",          // getAssetPath 解析
    "opacity": 1,
    "mask": 0.88                            // 深罩——可读性生命线（dsh mask-photo）
  }
}
```

- 不声明 `surface`/`background` 的旧主题 → **零变化**（玻璃变量默认零值 = 无玻璃无图 = 现状）
- 组合自由：dark 玻璃+图 / light 玻璃+图 / dark 玻璃无图 / 任意 → **越自由越好**，靠两根正交轴乘出来
- ThemeBrowser 对声明了 surface/background 的主题显示徽标（"Glass"/"图"）区分风格（#50.12 或 #50.6 收尾时顺带）

### CSS 变量面（ThemeEngine applyTheme 写的）

| 变量 | 默认 | 含义 |
|:--|:--|:--|
| `--glass-blur` | `0px` | 表面 backdrop blur——**0 = 现状零开销** |
| `--glass-saturate` | `1` | 表面饱和度增强 |
| `--glass-tint` | `transparent` | 玻璃着色（颜色选择器消费） |
| `--bg-image` | `none` | 图片层 background-image（getAssetPath 解析后 URL） |
| `--bg-opacity` | `1` | 图片层不透明度 |
| `--bg-mask` | `0.88` | 图片遮罩明暗（深罩保可读性） |
| `--surface-radius` | `0px` | 悬浮圆角——**0 = 现状直角** |
| `--surface-inset` | `0px` | 四周留缝——**0 = 现状贴边** |
| `--surface-shadow` | `none` | 投影浮起——**none = 现状无浮起** |

### BackgroundLayer（#50.8）

```css
.background-layer {
  position: fixed;
  inset: 0;
  z-index: 0;
  pointer-events: none;         /* 不挡任何交互，避开硬约束 #18 拖拽区 */
  background-image: var(--bg-image);
  background-size: cover;       /* 相对当前窗口视口 */
  opacity: var(--bg-opacity);
}
.background-layer::after {      /* 遮罩——可读性生命线 */
  content: '';
  position: absolute;
  inset: 0;
  background: rgba(0, 0, 0, var(--bg-mask));
}
```

### root 透明化（#50.7）

`html/body/#root/#pool-root` 现在背 `--bg-window` 不透明底色（index.css L129-139）——这会让图片层完全被盖住。改为 `background: transparent`，让 BackgroundLayer 垫最底。**默认主题视觉等价**：玻璃变量默认零值时表面仍是实色，图片层看不见。

### 用户配置 vs 主题基线（#50.10）

对标现有 `app.accentColor` 覆盖主题 accent 同款模式：
- 主题声明 `surface`/`background` = 基线
- 用户设置 `app.glassOpacity`/`app.glassBlur`/`app.glassTint`/`app.backgroundImage` = 覆盖基线（改了就以用户为准）
- 还原 = 清空用户配置 → 回主题基线

### 选图入库（#50.11，2026-08-17 定案 A）

用户任选本地图不能直接 `file://` 读（dev 是 `http://localhost`，Electron 安全模型禁止任意路径）。**A 拷贝入库**：选图 → 拷进 app userData appearance 目录 → 存受控路径到 `app.backgroundImage` → 重启还在。对标 `getAssetPath` 受控来源。配「清除图片」还原无图。

## 可拖出标签页继承（Phase 9 #42 联注）

用户拍板 ⑤：脱出窗口（Phase 9 #42-#46，v1.3 槽位）继承图片 + 玻璃。

- 脱出窗口是**新 document** → 图片层与玻璃是 **per-window** 的，不是主窗专属
- 新窗口创建时：ThemeEngine `applyTheme` 对其 document 执行 + BackgroundLayer 在其 root 渲染
- 图片源路径（`getAssetPath` 解析后绝对路径）从新窗口可解析
- 图片大小 = `cover` 相对**该窗口**视口——OS 多显示器壁纸模型，不钉死主窗尺寸（拖出窗口大 = 大裁剪，小 = 小裁剪）
- **约束在 Phase 9 立案时已带（#42 ⑦）**，不是事后补——否则拖出窗口白底死色视觉断裂

## 风险与对策（诚实标注）

| 风险 | 对策 |
|:--|:--|
| **性能**：全窗 blur = GPU 合成开销 | 桌面单窗 + 图片静态不重绘，15-20px blur 可扛；VisionOS 的 40px 才需要担心。可测 |
| **可读性**：玻璃 + 图下文字对比度崩 | **遮罩层（--bg-mask 0.88 深罩）是整个设计的生命线，不是可选项**（dsh mask-photo 思路） |
| **插件视图透光**：第三方插件硬编码背景色则玻璃盖不住 | 这是主题自由度——token 用的越好玻璃越完整，符合圆形大厅 |
| **Electron backdrop-filter 坑** | 与 `-webkit-app-region` 拖拽区、合成场景可能有坑——真机实测，唯一不能纸上定的点 |
