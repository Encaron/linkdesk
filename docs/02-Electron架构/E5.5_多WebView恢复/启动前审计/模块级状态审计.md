# 模块级共享状态审计——E5.5#0b

> 📖 **根因：** [[multi-webview-root-cause]]——`useSerialSessions._store` 模块级变量 → 壳 WebView 和插件 WebView 各一份独立副本 → 状态不同步（原 Bug 3/4/6）。

## 问题模式

```typescript
// ❌ src/core/services/someService.ts
const _store = new Map<string, State>();  // 模块级变量
export function getState(key: string) { return _store.get(key); }
export function setState(key: string, val: State) { _store.set(key, val); }

// 单 WebView：壳 + 所有插件共享同一个 _store Map
// 多 WebView：每个 WebView 有自己的 _store Map 副本
//   → 壳 setState → 壳的 _store 更新
//   → 插件 getState → 插件的 _store（未更新）→ 返回旧值
//   → 不报错。静默不同步。
```

## 审计范围

```bash
# 1. 模块级可变状态——最常见的问题模式
grep -rn "const _[a-z].*=.*new Map" src/core/
grep -rn "let _[a-z].*=.*new Set" src/core/
grep -rn "const _[a-z].*=.*\[\]" src/core/
grep -rn "^let _[a-z]" src/core/
grep -rn "^const _[a-z].*=.*{" src/core/

# 2. 类实例——每个 WebView 有自己的实例
grep -rn "export const.*=.*new" src/core/
grep -rn "export let.*=.*new" src/core/

# 3. 单例模式——getInstance() 在不同 WebView 中返回不同实例
grep -rn "getInstance\|_instance" src/core/
```

## 逐条判断

对每个找到的变量/实例，回答三个问题：

| 问题 | 回答 "是" 的含义 | 处理 |
|:--|:--|:--|
| 需要跨 WebView 共享吗？ | 壳写、插件读 → 必须 IPC | 迁移到主进程或加 IPC handler |
| 每个 WebView 独立可以吗？ | 该状态是进程本地缓存 | 放行，加注释说明 |
| 已在 IPC 通道中吗？ | 通过 IpcBridge 代理 | 验证通路完整 |
