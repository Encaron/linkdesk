# 01 — UI 布局规格

> 2026-07-28。**主题制作器——双栏式可视化主题编辑器。** 对标设计工具（Figma 属性面板 + 实时预览）。
> 设计系统来源：`ui-ux-pro-max` → Vibrant & Block-based + 属性面板 UX 模式
> 原 `02-主题制作器.md` 是概念草图——此文档是完整 UI 重设计。
> **AI 是独立插件——不在本插件内。** AI 插件通过 `executeCommand` 操作主题制作器的色键。

---

## 一、原始概念文档的差距

原文档 131 行描述了"三块能力"——可视化调色、AI 辅助、导出。但作为 UI 设计基本为零：

| 缺口 | 严重度 | 说明 |
|------|:--:|------|
| 三块能力如何布局？ | 🔴 | 调色面板、AI、预览是三个 tab？分屏？还是什么？——完全没有布局设计 |
| 33 个颜色键未列出 | 🔴 | 原文只说 `...`——实际有 33 个键，不分组全堆在一起就是灾难 |
| 预览在哪？ | 🔴 | 原文只在"即时预览"旁标注了 `applyTheme()`——但没有预览区 UI 设计 |
| ColorPicker 打开位置 | 🟡 | "色块点击 → ColorPicker 弹出"——但色块多大？排列方式？ |
| AI 交互无 UI | 🟡 | 原文档将 AI 理解为内置功能——实际上 AI 是独立插件，通过命令操作本制作器 |
| 导出 UI 太简 | 🟢 | 只是一个 checkbox 列表——没有主题名称、类型标注 |
| 主题元数据在哪编辑？ | 🟢 | 主题名称、作者、dark/light 类型——这些字段在哪？ |
| 零状态覆盖 | 🔴 | 新建空白主题 vs 编辑已有主题 vs 导入 JSON——视觉完全不同 |

**这是第二个市场插件——对标设计工具的属性面板来重新设计。**

## 三、左栏——调色面板（220px）

### 3.1 33 个颜色键的分组

> 这是我和 Encaron 一起制作"薄荷苏打"时实际用到的全部颜色键，按逻辑分组：

| 分组 | 可折叠 | 色键 |
|------|:--:|------|
| **主题信息** | ❌ 始终展开 | 名称（text input）、类型（dark/light 下拉） |
| **窗口/背景** | ✅ 默认展开 | `bg-window` `bg-card` `bg-input` `bg-icon-bar` `bg-side-panel` `bg-toolbar` `bg-status` (7) |
| **文字** | ✅ 默认展开 | `text-primary` `text-secondary` `text-muted` (3) |
| **强调/交互** | ✅ 默认展开 | `accent` `accent-hover` `icon-active` `icon-inactive` `toggle-knob` `dirty-dot` `hover-overlay` (7) |
| **边框/分隔** | ✅ 默认折叠 | `border` `separator` (2) |
| **状态** | ✅ 默认折叠 | `status-connected` `status-disconnected` (2) |
| **标签页/拖放** | ✅ 默认折叠 | `tab-hover-bg` `drop-indicator` (2) |
| **滚动条** | ✅ 默认折叠 | `scrollbar-thumb` `scrollbar-thumb-hover` (2) |
| **日志/数据** | ✅ 默认折叠 | `system-log` `sent-echo` `received` `cm-timestamp` (4) |
| **阴影** | ✅ 默认折叠 | `context-menu-shadow` `drag-preview-shadow` (2) |

**共 33 个色键。** 9 个分组 + 3 组默认展开 → 首次打开看到 20 个核心色键，其余折叠。

### 3.2 色键行格式

```
┌──────────────────────────────────┐
│ ▾ 窗口/背景                      │  ← section header (22px, 复用 SidebarSection)
│                                  │
│ bg-window     [#1C2428] ●       │  ← 色键行 (h=28px)
│ bg-card       [#243033] ●       │     label: 11px, mono font, --text-secondary
│ bg-input      [#243033] ●       │     hex: 11px, mono font, --text-primary, 右对齐
│ bg-icon-bar   [#161E20] ●       │     ● = 16×16px 色块, 点击弹出 ColorPicker
│ bg-side-panel [#181E20] ●       │       圆角 3px, border, hover 变 accent
│ bg-toolbar    [#181E20] ●       │
│ bg-status     [#0d9488] ●       │
└──────────────────────────────────┘
```

| 元素 | 规格 |
|------|------|
| 色键行高 | 28px |
| label 字体 | 11px "Fira Code", `--text-secondary` |
| hex 字体 | 11px "Fira Code", `--text-primary`, 右对齐 |
| 色块 | 16×16px, 圆角 3px, `border: 1px solid var(--border)`, cursor: pointer |
| 色块 hover | border-color: `--accent`, scale(1.1) 150ms |
| 点击色块 | 弹出 ColorPicker, 锚定在色块右侧 |
| 色值变化 | 即时 `applyAccentColor()` → 中栏预览同步 |

## 七、与 AI 插件的关系

**AI 是独立插件——不在本制作器内。** 关系如下：

```
AI 插件（plugins/ai/）
  │
  │  executeCommand("theme-maker.setColor", { key: "accent", value: "#C8A42A" })
  │  executeCommand("theme-maker.setAllColors", { colors: {...} })
  │  executeCommand("theme-maker.save", { name: "AI生成的主题" })
  │
  ▼
主题制作器（plugins/theme-maker/）
  │
  │  registerCommand("theme-maker.setColor", ...)
  │  registerCommand("theme-maker.setAllColors", ...)
  │  registerCommand("theme-maker.save", ...)
  │
  ▼
左栏色键更新 → 中栏预览即时显示
```

**AI 生成主题 JSON → 调用 `theme-maker.setAllColors` → 色键自动填入 → 用户在制作器中手动微调。** 两个插件各干各的，通过命令系统松耦合。

## 八、状态矩阵

| 状态 | 触发条件 | 视觉表现 |
|------|------|------|
| **新建空白主题** | 点"新建" / 首次打开 | 左栏所有色键 = 默认灰值 + 名称 "未命名主题" + 预览区灰色 |
| **编辑已有主题** | 导入 JSON / 点右栏主题名 | 左栏加载色值 + 预览区即时显示 |
| **改色值——即时预览** | 点色块 → ColorPicker → 选色 | 中栏预览区即时更新——不弹确认 |
| **改色值——Esc** | ColorPicker 中按 Esc | 色值恢复到改之前——预览区同步恢复 |
| **AI 填入色值** | `theme-maker.setAllColors` 被调 | 左栏全部更新 + 中栏预览更新 + 名称自动填 |
| **保存** | 点 [保存] / Ctrl+S | 写入 JSON 文件 → 右栏列表刷新 |
| **导出** | 点 [导出选中] | 生成 zip → 触发下载 |
| **名称冲突** | 新建/保存时名称已存在 | 自动加 " - 2" 后缀 |
| **导入 JSON 格式错误** | JSON 解析失败 | toast "文件格式不正确——无法解析为主题" |
| **导入 JSON 缺少色键** | JSON 只有 20 个键 | 有值的填入、缺失的用默认灰值——不报错 |
