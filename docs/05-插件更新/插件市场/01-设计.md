## 一、需求拆成两半（本设计的骨架）

用户这一句里其实是**两个**需求，必须分开看，否则会做出一个「按了没反应」或「按了就升级」的错东西：

| # | 需求 | 现状 | 本刀 |
|:--:|:--|:--|:--|
| ① | **发现**：有没有新版本 → 立刻能查一次 | ⛔ **没有手动入口**（只能重启软件或等） | ✅ **本刀新增**（工具栏「检查更新」钮） |
| ② | **升级**：发现之后在软件里点一下就能升 | ✅ **早已存在**：行内徽标 → 点行 → 详情页「更新」→ 确认卡 | 📐 **不改**，只在参考图末帧画清楚它落在哪 |

**判据：** ①解决的是「我等不到」，②解决的是「我不能升」。把①做成「按了就升级」是**加了口子**——自动更新在本仓是**逐插件 Opt-IN**（默认关，2026-09-08 拍板 §五），手动检查**不能**变成一次隐式授权。所以：**「检查更新」只发现、只通知，绝不代用户升级**。

## 三、语义定死（本设计的核心）

| 动作 | 语义 | 何时可见 | 是否绕缓存 | 是否改盘上状态 |
|:--|:--|:--|:--:|:--|
| **检查更新**（本刀新增） | 现在就去查：强刷目录 + 补跑一趟发现 | 恒可见（检查中禁用） | ✅ 绕 5min 目录缓存 | ❌ **只读 + 记账/通知**：不装、不升、不改用户授权 |
| **升级**（既有，不动） | 把某个插件升到目录里的稳定版 | 已装行有可更新徽标时 | ❌（走目录现有数据） | ✅ 装新版本（用户确认后） |
| **自动更新**（既有，不动） | 后台静默升（仅勾选过的插件） | 无需用户在场 | — | ✅ 由 Opt-IN 授权 |

**三条不合并的理由：** 一个是「查」、一个是「做」、一个是「授权」。合并任两条都会造出**隐式授权**（点一下就把别人的插件换版本），那是把 2026-09-08 的拍板推翻。

**「检查更新」按下去必然发生的事**（与既有启动发现**完全同一套**，零新语义）：
1. `forceRefreshCatalog()` → 目录重拉（官方源 + 全部作者源）→ 订阅者收通知 → 行内徽标翻新；
2. `runUpdateDiscovery(true)` → 读已装快照 → 与目录比 → 铃铛通知（有新版本）+ 对**勾了自动更新**的插件按既有规则落地 + 销账（卸载残留记账）；
3. 返回小结（发现 N 个可更新）供按钮就地注。

## 四、8 维度设计

### ① 能力边界

- **插件能力**，不是壳能力。核心准入三条件（多提供方/多消费方/桌子不知道内容）一条都不成立：编排的 owner 2026-09-08 已拍板归**市场插件自己**（`installedUpdateMeta.ts:2-7` 原话：「发现/自动更新编排定案归市场插件后，壳 update 流零消费」）。
- **保底设计**：无网络/目录坏 parse → **既有列表与旧目录原样保留**（`forceRefreshCatalog` 的 `.catch` 保持旧结果，`catalogStore.ts:104-107`），按钮回可用，详情落回唯一通知面（铃铛）。⇒ **不产生「点一下就白屏」的新失败面**（与 04 那次的保底判据同款）。
- **不做**：定时/后台轮询增强（既有启动发现已是那条腿）、下拉刷新（非移动端）、把行内徽标改成行内一键升级（见 §五·4）。

### ② API 设计

**零新契约面**——两枚入口都已存在：

| 用到的既有导出 | 位置 |
|:--|:--|
| `forceRefreshCatalog()` | `src/services/marketSources/index.ts:34` |
| `runUpdateDiscovery(force = true)` | `src/services/updateDiscovery/index.ts:70` |

**可选、但建议不做**：在 `contributes.commands` 加一条 `marketplace.checkUpdates` 让命令面板/快捷键可达。判据：那是**新的作者面贡献点**（要走 `audit-contributes` 三件套 + 文档），收益只是一次点击；且本刀已把动作抽成插件内单一函数（§四·⑤），将来真要加命令/快捷键，**接上去是几行的事、不必现在付契约面的钱**。

### ③ 通信方式设计

**全在插件 bundle 内**（视图 → 服务层），**零 IPC、零壳通道、零 DTO 字段**。

```
[检查更新] 钮
   └→ checkForPluginUpdates()            ← 本刀新增的唯一动作（插件内）
        ├→ forceRefreshCatalog()          → catalogStore 通知订阅者 → useCatalogEntryById 重建
        │                                   ⇒ 行内「可更新 vN」徽标翻新（正控）
        └→ runUpdateDiscovery(true)       → 铃铛通知 / 勾选的自动更新落地 / 销账
   ← 返回小结 { updated, checkedAt, failed }
```

- **数据流**：谁产生 = 市场源（远端 `marketplace.json`）；谁消费 = catalogStore → 各列表行/详情页；谁持久化 = 目录缓存（`marketSources` 既有）、更新记账 `installedUpdateMeta`（既有）。**本刀不新增任何存储**。
- **铁律对齐**：插件通信全程不 `import @src/core/*`（本刀连壳 API 都不用调）。

### ④ 壳侧代码设计

**零改动。** 唯一的边界情况已由壳既有机制覆盖：

> 侧栏被拖窄（最小 170px）时，动作行三个钮放不下 ⇒ CSS 允许换行、toolbar 变高 ⇒ **壳侧 `PoolToolbarSlot` 的 `ResizeObserver → onHeightChange` 自动把新高度通知给布局**（`PoolToolbarSlot.tsx:20-38`）。⇒ 不需要壳为新钮加任何能力。

（宽度账：侧栏默认 280px − 左右 padding 24px = 256px（动作行自身盒宽 255px，差 1px 是分隔线边框）；三钮实测 90.8 + 62.8 + 74.8 ≈ 229px，含两道 6px gap **合计 ≈240px < 255px** ⇒ 默认宽度下**一行放得下（余约 15px）**；侧栏窄于约 **265px** 才换行。参考图里量了实数，见 mockup 页底 `#audit` 读数。）

### ⑥ 显示设计

- **在哪里**：侧栏 toolbar 槽（`.ldk-side-panel-toolbar`）里的动作行 `.marketplace-ms-header-actions`，右对齐组的**最左端** ⇒ `[检查更新][安装][市场源]`。
  **为什么放最左**：① 既有两钮的相对次序**零改动**（老用户肌肉记忆不破）；② 三钮同属「往市场里加/查」一类，而「查」是无副作用的读操作且最常用，放组外缘与两个「写」操作形成天然分隔。
- **怎么显示**：`<Button variant="ghost" size="sm">` = 图标 + 文字（**不用纯图标钮**——省下的 30px 换不来可发现性；且这一区是用户点名要加的显式入口）。`title`（走 `data-hint`，非 DOM `title=`）写清语义：「立即向市场源查询插件新版本（忽略 5 分钟缓存）」。
- **显示什么 / 三态**：
  1. **默认**：⟳ 图标 + 「检查更新」；
  2. **检查中**：图标转圈 + 文字改「检查中…」+ `disabled` + `aria-busy`；**列表与目录保持旧内容，不回骨架**；
  3. **完成**：按钮回默认 + 就地 muted 一行注——无新版「已是最新 · 刚刚」／有新版「发现 N 个可更新 · 刚刚」（**不弹窗、不新造提示面**）；
  4. **失败**：按钮**立即回可用**（失败不许永久禁用）+ 列表原样保留 + 详情落回**唯一通知面**（铃铛宽面板），页面内不自造错误条。
- **设计 skill 依据（硬约束 16）**：`ui-ux-pro-max`——「Loading Indicators：操作 >300ms 必须给反馈，禁止 UI 冻结」「Loading States：异步操作期间显示反馈」（两条均 High）。⇒ 转圈 + 改文案 + 禁用防连点 + 正文不冻结。`prefers-reduced-motion` 下动画关掉、**文字仍在**（状态不丢，双保险）。

## 七、验收（用户视角）

1. 打开插件市场侧栏 → 搜索框上方那行有「检查更新」→ 点一下 → 变「检查中…」（转圈、不可连点）→ **列表不闪不白**。
2. **正控**：某插件刚在官方目录收录了新版本（还没到 5 分钟缓存过期）→ 点「检查更新」→ **行内「可更新 vN」徽标当场出现** ⇒ 这是本需求的正控（今天必须重启软件或等）。
3. 无新版 → 按钮回默认 + 就地「已是最新 · 刚刚」（**不弹窗**）。
4. 断网点 → 列表**照旧显示**（不白屏）→ 按钮**立即可再点** → 铃铛里有失败条目（唯一通知面）。
5. 勾了自动更新的插件 → 点「检查更新」⇒ 按既有规则落地并（成功/失败各有通知）；**未勾选的插件绝不被升级**（Opt-IN 不破）。
6. 侧栏拖到最窄（170px）→ 三钮换行、**被压住的搜索框仍在**、toolbar 高度自适应（壳既有 `ResizeObserver`），无横向溢出/裁切。
7. 亮/暗主题 + `--ui-scale` 放大一档 → 按钮不破格、图标不糊。
8. 邻近回归：「安装」「市场源」照常；探索页错误态「重试」照常；详情页升级链（徽标 → 更新 → 确认卡）照常。
