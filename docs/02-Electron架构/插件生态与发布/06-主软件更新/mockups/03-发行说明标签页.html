要点（为什么补这一帧）：原稿只有「有内容」和「彻底拉不到」两态，**中间那段「正在拉」没有图**——实现者要么自己发明一个 spinner（新造 UI 表面 = 违反「载体只有一个」），要么**白屏**（用户以为标签页坏了）。本帧把第三态钉死：
① 骨架占位——头部版本区 + 左窄栏三条 + 右主区两段的灰条，**形状与 Frame 1 的真实布局一一对应**（不是居中转圈）；不用 shimmer 动效（拉取通常 <1s，动效只会闪一下；且 prefers-reduced-motion 下本来就要关）。
② 不阻塞别的标签页——发行说明页自己在骨架态，用户可照常切走、关掉；首启自动弹的那次同样（05 §2.4「不打扰、不阻塞启动」）。
③ 骨架 → 内容 / 空态 的二选一由拉取结果决定：成功 → Frame 1（缓存命中则先渲染缓存再静默刷新，**不回到骨架**）；失败 → Frame 2。**没有第四态**。
