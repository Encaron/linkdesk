## 一 逐条回应

### 1 · HTML 演示 —— 已出

[01-提案演示.html](./01-提案演示.html)：左边安装器、右边应用内设置页，都**逐字沿用各自既有的设计系统**（安装器用 `build/installer/bootstrapper/app.css` 的暖纸 token 与药丸按钮；应用内用 `src/index.css` 的浅色 token 与 `settings` 插件的行结构）。

⚠️ 依硬约束 16 走了 `Skill ui-ux-pro-max`，其 `--design-system` 给出的是「Dark Mode (OLED) / Space Mono / #0F172A」，与你明确要求的**复用两套既有视觉**不符 ⇒ **未采用**，改为复用项目自己的 token。另：「渐进式披露」这个 UX 查询**返回 0 条结果**（据技能自身规则，此处如实披露，不当数据用）。

### 2 · 缓存到底在哪 —— 三个概念必须分开

**你问的路径是对的**：`C:\Users\fengy\AppData\Roaming\linkdesk`（Electron 规定的位置，`package.json` 的 `name` 决定的，代码里没有任何一处改过它）。

但你说「缓存文件，**比如插件下载的、主题之类的**」——**插件和主题不是缓存，是数据**。这两类混在一起，第 4 点就会做错。真机实测（2026-10-02，装机第 2 天）：

| 类别 | 目录 / 文件 | 实测体积 | 删掉的后果 |
|---|---|---|---|
| 🔵 **可再生缓存** | `Cache` | 12.0 MB | 无感，下次访问重建 |
| 🔵 | `GPUCache` / `DawnGraphiteCache` / `DawnWebGPUCache` / `Code Cache` / `Shared Dictionary` | 2.6 MB | 无感 |
| 🟡 **站点状态**（半可再生） | `Local Storage` / `Session Storage` / `blob_storage` / `Network` / `SharedStorage*` | 0.2 MB | 可能丢窗口/界面状态 |
| 🔴 **数据（不可再生）** | **`plugins`** | **55.5 MB** | **已装插件全没** |
| 🔴 | `appearance`（主题/背景图） | <0.1 MB | 主题与背景图丢失 |
| 🔴 | `settings.json` / `keybindings.json` / `layout-ws-*.json` / `installed-plugins.json` / `plugin-states.json` / `ai-bridge.*` | ~0.3 MB | 设置/键位/布局/凭据丢失 |
| 🔴 | `update` | 0.1 MB | 已下载的更新包丢失（重下即可） |

总额 ≈ 70.6 MB，其中**真正可清的缓存只有约 14.6 MB**（浏览器缓存），**55.5 MB 的插件是数据**。

> 另有一处既有约定：插件数据目录下的 `cache` 子目录（`electron/services/env-service.ts:86`）——插件自己的缓存也归「缓存」口径，清除时应一并清（但要**先看插件是否把它当持久数据**）。

**这一条直接决定第 4 点**：界面上必须让用户看见「清 14.6 MB 缓存 / 保留 55.5 MB 插件」，否则一次点击 = 恢复出厂。

### 3 · 打开缓存目录 —— 照抄现成的，零新机制

✅ **完全可行，且是六点里最省事的**。壳里**已经有两处**同款实现，做的就是你要的「普通资源管理器弹窗」：

| 现成实现 | 位置 | 手感 |
|---|---|---|
| 「打开存储位置」（背景图齿轮那个） | 命令 `appearance.revealStorage`；IPC `appearance:reveal-storage`（`electron/ipc/channels.ts:248`） | `shell.openPath(目录)` → 开**目录内容** |
| 打开插件的安装目录 / 数据目录 | IPC `shell.openPluginFolder`（`electron/main.ts:296-310`） | 同上，注释里明写「与 appearance.revealStorage 同一手感」 |

你担心的「必须处理的框」= `dialog.showMessageBox`（模态）；这两个用的是 `shell.openPath`，**根本不弹窗，直接开资源管理器**。✅ 就是你要的。

**唯一要做的事**：这两处都**把目录写死了**（一处写 `userData/appearance`、一处写插件目录）。所以不能直接复用，要么新加一条 `app.storage.reveal`，要么把它们**泛化成「传目录」**（推荐后者：三处收口成一处，正合台账 §六「一物一处」的铁律）。

### 4 · 清除缓存 —— 可以做，但有三个硬约束

✅ 可实现。但**不能**简单粗暴地删目录：

**约束 A｜运行中删不掉。** 软件正开着，Chromium 占着 `Cache` 里的文件，`fs.rm` 会失败——这与台账 §五 H（安装器清不干净 WebView2 目录）**是同一个成因**。所以必须二选一：
- 清完提示「**重启软件后完全生效**」（演示稿采用这条，诚实且改动小）；或
- 写入一个「**下次启动时清理**」标记，启动早期（Chromium 起来之前）执行。

⛔ 不能假装当场就干净了——那是在骗用户。

**约束 B｜范围必须写死成白名单。** 只清：`Cache` / `Code Cache` / `GPUCache` / `DawnGraphiteCache` / `DawnWebGPUCache` / `Shared Dictionary` ＋ 各插件数据目录下的 `cache`。⛔ 不清：`plugins` / `appearance` / `settings.json` / `keybindings.json` / `layout-*.json` / `Local Storage` / `blob_storage` / `ai-bridge.*`。

**约束 C｜必须有二次确认，且把两类分开列。** 演示稿的确认框已经这么写了（「会删：浏览器缓存 12 MB…」/「不会删：你的设置、已装插件、主题、布局」）。

### 5 · 改缓存存放位置 —— 分两档，推荐先落档一

| | **档一：只搬浏览器缓存** | **档二：整个数据目录搬家** |
|---|---|---|
| 搬什么 | 上表蓝色那 14.6 MB | 全部 70.6 MB（含 55.5 MB 插件） |
| 省 C 盘 | 少 | 多 |
| 代价 | `app.setPath('cache', 目标)`，须在 `app ready` **之前**调用 | 需处理：已有数据迁移、单实例锁、自动更新器路径、安装器/卸载器都得知道新位置 |
| 风险 | 低（缓存丢了无所谓，最坏重建） | 中高（搬一半 = 用户的设置和插件消失） |
| 可逆 | 改回默认即可 | 不可逆（数据已在新位置，改回要再搬一次） |
| 建议 | ✅ **先做这个** | 🕐 后续可选，单独一批 |

**档二的鸡生蛋问题及解法（关键）**：数据目录的位置自己不能存在数据目录里。解法 = **把指针放注册表**——`HKCU\Software\LinkDesk` 这个键**本来就有**（安装器已写 `InstallDir` 等），加一个 `UserDataDir` 值，启动时读它 → `app.setPath('userData', X)`。注册表位置固定，循环就断了。

> ⚠️ 边界：台账 §六 的「⛔ 不做」禁的是 **portable / 绿色模式**（位置随 U 盘走、免安装任意选）。档二**不违反**该条——指针仍在固定注册表键，只是值可变，本质是「可配置的安装位置」而不是「绿色模式」。**但这条边界需要你点头**（§五 待定 ③）。

### 6 · 「清除缓存」放安装器里合适吗 —— 一半合适

**你的直觉一半是对的，一半会白做**：

| 配置项 | 安装器 | 应用内 | 为什么 |
|---|---|---|---|
| 选择缓存目录 | ✅ **该有** | ✅ 该有 | 安装时选定初值（写进注册表指针），装完即生效，省得再进去改一次 |
| **清除缓存** | ❌ **不该有** | ✅ **只在应用内** | **全新安装那一刻，缓存体积 = 0，没有任何东西可清。** 它是使用期动作。放进安装器 = 用户点一下发现什么也没发生 |
| 打开缓存目录 | ❌ 不必 | ✅ 该有 | 安装时打开一个空目录没有意义 |
| 文件/目录右键菜单、文件类型关联、PATH | ✅ 已有（4 项） | ⚠️ 部分有（3 项，见下） | — |

**关于「更多配置」按钮（含一个新发现的不一致）**：

1. **按钮本身：建议不加。** 今天「自定义安装」点开就是那 4 个勾选框；再加个「更多配置」点开还是同一块区域 ⇒ 两个按钮做同一件事，用户不知道该点哪个。**建议直接把这 5 项做成一个竖向列表，挂在「自定义安装」展开区内**（演示稿右半就是这样画的）。演示稿里两个按钮都画了，方便你对比后取舍。
2. **顺带发现的不一致** 🔴：安装器给了 **4** 个系统集成选项（文件右键 / 目录右键 / 文件类型关联 / **添加到 PATH**），而应用内「设置 → 通用 → 系统集成」**只有 3 项**——**「添加到 PATH」在应用里不存在**。也就是说装完之后用户**没法在软件里改这个**，只能重装。是否借这次补齐，是决策点（§五 待定 ②）。

**A3 🔴 一行一件事（重要约束）**：现有渲染层里 `readonly` 与 `action` 是**互斥分支**（`settings` 插件 `renderControl.tsx:48` / `:187`），**一个属性只能是一种**。所以「只读路径 + 按钮挤在同一行」**做不到**，必须**拆成两行**：
- 行 1：`app.storage.path`（只读值）
- 行 2：`app.storage.relocate`（按钮）
> 这与 AI 接入分区完全同构（5 个只读行 + 9 个按钮行，全是独立行）。若要真挤一行，得改 `settings` 插件渲染层——**跨仓改动，另立任务**，不建议为首个版本付这个成本。

**A4 分组**：4 键 `group: t("存储")`，新分节自然出现在「通用」页底部（分节按 `group` 字段派生，见 `settings` 插件 `grouping.ts`）。

**A5 壳侧命令与 IPC**（`src/core/commands/shell/` ＋ `electron/`）：
- `appStorage.statusPath` → 返回 `app.getPath('userData')`（档一则返回缓存目录）
- `appStorage.reveal` → **优先泛化**已有实现：把 `appearance.revealStorage`（`electron/main.ts:298`）与 `shell.openPluginFolder`（`:296-310`）收口成一个「传目录就开」的通道，三处共用。退而求其次才新加 `app.storage.reveal`。

## 三 三个必须先解决的坑（复述，因为最容易翻车）

1. **运行中的文件删不掉** ⇒ 「清除缓存」必须「重启后生效」或「标记下次启动清」，⛔ 不许假装当场干净。（同 §五 H 成因）
2. **只读 + 按钮挤不进同一行** ⇒ 拆两行；要挤一行得改 `settings` 插件（跨仓）。
3. **「缓存」≠「数据」** ⇒ 55.5 MB 的插件**不是**缓存；确认框必须把「会删/不会删」分开列。
