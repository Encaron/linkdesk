# 发行说明累计跳版（待抉择池）

> **2026-10-05 用户点单立案**——壳走「不发版、dev 攒批」之后，一次发版会跨过若干**从未发布过**的中间版本；而 CI 的 Release 正文只切**当前版本那一段** ⇒ 用户升级后「查看更新内容」只看到最后一笔，跳过的版本干的活一个字都不露。
> **本件只管「怎么让这件事在发版时不漏」**——🔴 **版本号口径一字不改**（0.x 中间数字仍只表「破坏性」，跳号本身无罪）。

---

## 一、问题（2026-10-05 实测）

- 现状：发布端停在 **`0.2.41`**，壳已攒到 **`0.2.48`**；中间 `0.2.42`–`0.2.47` **七段各写过 CHANGELOG、各 bump 过 `package.json`，但谁也没发过**（段里都标着「⛔ 软件本体未发版——照规矩攒批」）。
- 机制：[build.yml](../../../.github/workflows/build.yml) 的 Release 正文 = `scripts/check-publish-gate.mjs --changelog-body` 切出的 **`## v{当前版本}` 那一段**。
- ⇒ 真发 `0.2.48` 时，用户从 `0.2.41` 升上来，看到的发行说明**只有 0.2.48 一笔**；前面七段里的打开方式选择器、市场跳设置修复、快捷键清空、键盘直通……**全不可见**。
- **结论：号跳了不是病，说明缺了才是病。**

## 三、待拍板（本件剩下的唯一决定）

**要不要再补一条机械腿**——在发布链上自动「数跳过的段」并提示？

| 候选 | 落点 | 形态 | 成本 |
|:--|:--|:--|:--|
| **A（建议）软提醒** | `scripts/check-publish-gate.mjs` | 发版前置打印「⚠️ 自上一发布版 `v{X}` 起有 N 段未发布（列版本号），请确认本版正文已累计」；**黄灯不拦** | 小（只读枚举 `git tag` ＋ CHANGELOG 切段） |
| B 硬门禁 | 同上 | 本版段必须出现累计标记（如列出中间版本号），否则**红** | 中；「累计」是写作题，机械判「写全了没」不可靠 ⇒ 易误伤 |
| C 只留纪律 | — | 上面 §二 两条即止 | 零 |

**建议 A**：跳版是**常态**（壳天天攒批），硬拦会天天误伤；而在 `npm run publish` 那一刻把「数跳了几段」从人脑里挪给脚本，收益最大、口径风险最低。

> ⚠️ **归属**：流程/门禁件，**不占版本号**；若走 A，改的是 `scripts/`（非 `src/`/`electron/`），提交类别按 `check-version-bump` 判定。
