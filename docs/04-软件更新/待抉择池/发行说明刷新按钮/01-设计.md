## 一、需求（用户原话概括）

发行说明标签页**没有任何刷新按钮**，数据是 **24h 落盘缓存** ⇒ 刚发布的新版本，用户当天可能一直看不到，只能等缓存过期。**要给发行说明标签页加一个手动刷新。**

## 二、现状（2026-09-13 读码核实）

| 层 | 事实 | 证据 |
|:--|:--|:--|
| 数据腿 | GitHub Releases（`releases?per_page=30`，最多 30 条）→ 缓存 `{userData}/update/releases-cache.json`；**TTL = 24h**（05 §2.4 定死）；**失效判据两条**：24h 过期 ＋「所请求那版不在缓存里」；**只有成功的网络结果才写缓存**，兜底走缓存**不回写** `fetchedAt` | `electron/services/update-release-notes.ts`（`CACHE_MAX_AGE_MS` / `isFresh` / `contains` / 文件头 ①②③） |
| IPC | 壳侧 `fetchReleaseNotes` 由 update handler 调；**当前无 force 形参** | `electron/ipc/handlers/update-handlers.ts:28` |
| Hook | `loadReleaseNotes(version?)` 取数入口（带 `_seq` 竞态序号）；**已有 content 时不打回 loading**；`retryReleaseNotes()` = **重试当前那一版** | `src/hooks/useReleaseNotes.ts:181` / `:264` |
| 池 | 三态（loading / empty / content）；头部 `.rn-actions` **只有**「在 GitHub 查看全部 →」外链 | `src/pool/views/release-notes/ReleaseNotesPoolView.tsx`（Frame 1 段） |
| 命令 | 四条：`update.openReleaseNotes`（人发起，命令面板可见）+ `select` / `retry` / `dismissBanner`（池发起，`when:"false"`，池经 `executePoolCommand`→命令通道） | `src/core/commands/shell/releaseNotesCommands.ts` |

**缺口定位：** 全链路没有任何「忽略缓存、重新拉取」的入口——`retry` 只在**拉失败**（空态）时可用且语义是「重试当前版」，管不了「拉到了、但是旧的」。

## 三、语义定死（本设计的核心）

| 动作 | 语义 | 何时可见 | 是否绕过缓存 |
|:--|:--|:--|:--:|
| **刷新**（本次新增） | 重新拉**最新列表**（用户主动问「现在有没有新的」） | **内容态与空态都可**（内容态 = 主入口） | ✅ 绕过 24h 缓存 |
| **重试**（既有，保留） | 重试**当前那一版**（拉失败后再来一次） | 仅空态 | ❌ 否 |

**两者不合并**：一个问「有新东西吗」，一个问「刚才那个再来一次」——合并会让空态的语义变成「顺便忽略缓存」，那是凭空改既有行为。**边界写进按钮 `title`**（「忽略缓存，重新获取版本列表」）。

## 四、8 维度设计

### ① 能力边界
壳内视图增强（发行说明标签页是**壳直渲染视图**，非插件）。**保底不变**：刷新失败时页面**继续显示缓存内容**，不因新按钮而出现「点一下就白屏」的新失败面。不做：定时自动刷新（既有 4h 检查已是另一条腿）、下拉刷新（本仓非移动端，无此手势面）。

### ② API 设计
- **新增一条壳内命令**：`update.releaseNotesRefresh`（`when:"false"`，池发起，`category: "帮助"`）——照 `retry` 的既有形状，**零新契约面**。
- **取数入口加 force**：`fetchReleaseNotes(..., { force })` 形参一路从 IPC handler 透传，`force` 时**跳过 `isFresh` 短路**。**成功仍写缓存**（铁律③不变：缓存只由成功结果写）。
- 池侧 DTO 需带「刷新中」这一位（见 ④）。

### ③ 通信方式
池 → 壳走既有的 `executePoolCommand` → `window.linkdesk.commands.executeCommand`（`commands:execute` 通道，池→主进程→壳 CommandRegistry）——**不开新 IPC 通道、不加 DTO 之外的字段**。数据返回仍走既有「壳推 `PoolTab.releaseNotes`」单向推送（壳想池画）。

### ④ 壳侧
| 落点 | 改什么 |
|:--|:--|
| `electron/services/update-release-notes.ts` | `fetchReleaseNotes` 增 `force` 选项；`force` ⇒ 跳过 `isFresh`（但「所请求那版不在缓存」这条判据在 force 下无意义，一并跳过）；**写缓存逻辑不动** |
| `electron/ipc/handlers/update-handlers.ts` | 透传 `force` |
| `src/hooks/useReleaseNotes.ts` | 新增 `refreshReleaseNotes()`（= 忽略缓存重新拉，复用 `_seq` 竞态守卫）；新增 `refreshing` 相位标志并随推送下发 |
| `src/core/types/pool/poolLayout.ts` | `PoolReleaseNotesData` 的 content 态加可选位（如 `refreshing?: boolean`）——**契约文档 `07-数据流通格式.md` 同笔更新**（表结构与推送点） |
| `src/core/commands/shell/releaseNotesCommands.ts` | 注册 `update.releaseNotesRefresh` |

### ⑤ 池侧
`ReleaseNotesPoolView.tsx` 头部 `.rn-actions` 加按钮 + 三态渲染（默认 / 刷新中禁用 / 就地注）。**池不自己判状态**——「是否刷新中」由壳推下来（同款先例：三态判别联合 `state` 就是壳推的）。CSS 走既有 `.ghost-btn` 皮肤 + 一个新类（新增类名建议 `.rn-refresh`），颜色/尺寸全 token（`var(--)` + `--ui-scale` 口径）。

### ⑥ 显示
位置 = 头部动作区 `.rn-actions`，**在「在 GitHub 查看全部 →」左侧**（本页动作的既有归属地）。形态 = ghost 次按钮 + 图标 + 文字（不新造按钮皮肤；不用纯图标按钮——省下的 30px 换不来可发现性，且本区只有 2–3 个按钮）。三态：

1. **默认**：图标 + 「刷新」，`title` 说明忽略缓存；
2. **刷新中**：图标转圈 + 文字改「刷新中…」+ `disabled` + `aria-busy`（**正文保持旧内容**，不回骨架）；`prefers-reduced-motion` 下动画关掉、**文字仍在**（状态不丢）；
3. **完成/失败**：按钮回可用；无新版 → 就地 muted 一行「已是最新 · 刚刚」；失败 → 页面保留缓存内容 + `.rn-meta`/状态栏如实写「刷新失败 · 显示的是本地缓存（时间）」，**详情落回唯一通知面**（铃铛宽面板，复用既有 `UpdateError` 通道）。

> **设计 skill 依据（硬约束 16）：** `ui-ux-pro-max` ——「Loading Indicators：操作 >300ms 必须给反馈，禁止 UI 冻结」（High）＋「Loading States：异步操作期间显示反馈」（High）。本图据此定「转圈 + 文案 + 禁用防连点 + 正文不冻结」。**不新造提示面**的约束来自本仓既有红线（通知只有铃铛宽面板一处）。

### ⑦ 配置
**不新增配置项。** 判据：单一行为、无用户选择面（刷新是即时动作，没有任何"要不要/多久"的可选项）；4h 检查频率仍按既有拍板**是内置常量、不暴露**（`config/update.ts` 文件头）。

## 五、待拍板项

1. **刷新后视野**：保持**当前所选版本**（推荐——刷新只更新数据，不搬走用户的视线；列表里若来了新版，左栏既有「新」徽标会标出来），还是**自动跳到最新版**（更符合"我想看看有没有新东西"的直觉，但会打断正在读旧版的人）。
2. **空态「重试」是否并入「刷新」语义**：保留两个入口（推荐，语义不同，见 §三），或空态里也换成「刷新」（少一个词，但丢了"重试当前版"的语义）。
3. **是否加「缓存 24h · 上次拉取 …」元信息**（图里 Frame 1 画了）：能让用户明白"为什么昨天看不到新版本"，但也给页面添了一行信息——**可不加**，刷新按钮本身已解决痛点。

## 七、验收（用户视角）

1. 打开发行说明 → 头部有「刷新」→ 点一下 → 按钮变「刷新中…」（转圈、不可连点）→ 正文**不闪不白**。
2. 刚发了新版但缓存还没过期 → 点刷新 → **新版立刻出现在左栏**（带「新」徽标）——这是本需求的正控。
3. 断网点刷新 → **页面照旧显示缓存内容**（不白屏）→ `.rn-meta`/状态栏写明「刷新失败 · 显示的是本地缓存（时间）」→ 铃铛通知里有这一条 → 按钮仍可再点。
4. 连点刷新 → 不会并发打出多次请求（禁用 + `_seq` 竞态守卫）。
5. 亮/暗主题 + `--ui-scale` 放大一档 → 按钮不破格、图标不糊。
6. 邻近回归：空态「重试」照常；左栏换版照常；GitHub 外链照常；首启自动弹横幅照常。
