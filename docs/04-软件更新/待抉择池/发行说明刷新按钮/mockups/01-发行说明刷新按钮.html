发行说明标签页 · 刷新按钮 本图 = 06-主软件更新/mockups/03-发行说明标签页.html 的增量版：骨架 / 布局 / 文案**逐字照抄原图**，唯一新增 = 头部动作区多一个「刷新」按钮及其三态。原图三帧（主态 / 断网空态 / 加载骨架）仍有效，本图只画「刷新」这条新支路，不重复原图内容。
为什么要它：发行说明的数据是主进程 24h 落盘缓存（update-release-notes.ts 的 CACHE_MAX_AGE_MS，失效判据两条：24h 过期 ＋「所请求那版不在缓存里」）。所以刚发的新版本，用户在当天可能一直看不到——没有任何手动刷新入口。空态里那个「重试」只在拉不到时出现，管不了「拉到了但是旧的」。
语义边界（本图定死）：刷新 = 忽略 24h 缓存重新拉列表（用户主动问「现在有没有新的」）；重试（既有）= 重试当前这一版（拉失败后再来一次）。两者都保留，不合并。
设计 skill：ui-ux-pro-max —— 「Loading Indicators：操作 >300ms 必须给反馈，禁止 UI 冻结」「Loading States：异步操作期间显示反馈」（两条均 High）；本图据此规定：点击后按钮转圈 + 文字改「刷新中…」+ 禁用防连点，正文保持旧内容不回到骨架。

① 有内容就绝不打回空态——空态（mockup 03 Frame 2）的成立前提是「无缓存 + 拉不到」。刷新失败时本地还有缓存 ⇒ 继续显示缓存，只在 .rn-meta 与状态栏如实说明「刷新失败 · 显示的是本地缓存（时间）」。
