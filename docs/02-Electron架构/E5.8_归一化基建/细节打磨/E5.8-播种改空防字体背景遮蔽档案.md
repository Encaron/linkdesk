# E5.8-播种改空防字体背景遮蔽档案（#154）

> 2026-08-27。**用户实机：app.mixFont 选「跟随主题」「宋体印刷体」「终端机」从外观上看不到任何变化。** 根因 = 重播种把生效字体物质化成非空 `app.fontFamily` → 覆盖 `--font-ui` → mixFont（字体域来源）被永久遮蔽。**用户拍板：播种改空（A）——`fontFamily` / `fontFamilyMono` / `backgroundImage` 三键播种恒空，范围 = 字体+背景域一并。**
> 清单指针：E5.8-执行清单 Phase 11.22 #154。

---

## 一、背景与用户实机证据

用户 4 条发现（2026-08-27）：

1. 选 `app.themeColor` 才会让字体（含字体颜色）跟着改
2. **要让 mixFont 跟着变，`app.fontFamily` 必须选「跟随主题」**——否则哪怕显示原生栈 / Cascadia Mono 也遮蔽 mixFont（「终端机」→ `"app.fontFamily": "Cascadia Mono"`；用户修正：任何非空值都遮蔽）
3. 主题默认字体栈为什么那么长
4. 「跟随主题」（下拉或齿轮）→ 配置变 `""`（`"app.fontFamily": ""`，只有两个冒号；类似还有玻璃 `rgba(59,77,148,0.35)`）

## 二、根因（file:line + 机制）——重播种把生效 token 物质化进覆盖键，域来源被盖死

**链条**：进 custom（[appearance.ts:179](../../../../src/App/config/appearance.ts#L179) `seedAppearanceOverrides`）与切主题重播种（[appearance.ts:91](../../../../src/App/config/appearance.ts#L91) `reseedAppearanceOnThemeSwitch`）共用 [deriveAppearanceSeedMap](seeds.ts)（seeds.ts:118）→ [deriveAppearanceSeeds](seeds.ts)（seeds.ts:82）把**生效 token** 反推成覆盖键：

- [seeds.ts:104](../../../../src/core/services/ui/ThemeEngine/seeds.ts#L104) `fontFamily: fam && !fam.startsWith("__ld_") ? fam : ""`——aurora 等无字体域主题的生效 `--font-ui` = :root 默认长栈（[index.css:48](../../../../src/index.css#L48)）或具体族 → **物质化成非空 app.fontFamily**
- [seeds.ts:110](../../../../src/core/services/ui/ThemeEngine/seeds.ts#L110) `fontFamilyMono` 同构
- [seeds.ts:103](../../../../src/core/services/ui/ThemeEngine/seeds.ts#L103) `backgroundImage: bgPath` 同构（剥 url() 存受控路径）

**遮蔽**：app.fontFamily 非空 → 覆盖层胜出（apply.ts mix 分支 mergeMixDomains 后 overrides 再盖）→ `--font-ui` 永远被用户级值盖死 → **mixFont 无论选哪个主题的字体域都无效**。

**冻结效应**：播种物化的 fontFamily 一旦写进配置，就锚定当前字体——之后 mixFont 怎么切都反转不回来（只有手动「跟随主题」清空才解锁）。

**资产字体已有先例**：`__ld_` 前缀（插件 @font-face）播种空 = 跟随主题（seeds.ts:78 注释，#50.20 边界）——本修复把「播种空」从资产族推广到**全字体/背景**。

## 三、修复设计（用户拍板 A：播种改空）

改 [seeds.ts](seeds.ts) `deriveAppearanceSeeds` 三处（零新 API/配置/贡献点）：

| 行 | 现状 | 改后 |
|---|---|---|
| :103 | `backgroundImage: bgPath` | `backgroundImage: ""`（恒跟随主题——背景域来源 mixBackground 唯一通道） |
| :104 | `fontFamily: fam && !fam.startsWith("__ld_") ? fam : ""` | `fontFamily: ""`（恒跟随主题——字体域来源 mixFont 唯一通道） |
| :110 | `fontFamilyMono: monoFam && !monoFam.startsWith("__ld_") ? monoFam : ""` | `fontFamilyMono: ""`（同） |

**语义**：设置层只存用户偏离量（08 §2 既有哲学）——字体/背景覆盖键只该存**显式偏离**，不存物质化的主题生效值。播种改空后：

- **视觉不变**：空值不覆盖（seeds.ts:20「其余空值不覆盖」）→ 主题字体/背景照常生效
- **mixFont/mixBackground 解锁**：域来源成为字体/背景唯一通道，切换主题字体域**立即可见**
- **显式值永不被播种吞**：用户显式设的 fontFamily（≠""）与播种值（""）比较 → reseed 计划判定「显式修改」→ 保留（deriveReseedPlan 既有逻辑）
- **附带修正**：用户显式选的字恰与主题同值时，旧逻辑误判「未修改」切主题重基线丢用户选择；改空后显式非空恒判显式 → 保留（seeds.test.ts:631 语义扩展）

**玻璃/表面域同构但本次不动**：glassTint（seeds.ts:102）同样物质化（可遮蔽 mixSurface 表面域）——用户拍板范围 = **字体+背景域一并**，玻璃留待另行决策（21-档案 #150/#151 已另案）。同结构，不同步，护 #10 健壮。

**安全论证（进 custom 播种路径）**：`seedAppearanceOverrides` 只在 followTheme→custom 边界触发（appearance.ts:179）；切回 followTheme 时批量复位清 13 覆盖+6 域来源（appearance.ts:185-188）→ **进入 custom 那一刻三键必已在 schema 默认 ""** → 播种改空不可能覆盖任何用户显式值。字体/背景控件 `dependsOn: appearanceMode=custom`（followTheme 下隐藏），无其他写入路径。
