# 插件加载归一化——loadPluginLifecycle 唯一入口

> 2026-08-05 重写。**E5 第 2 层第 5 轮 + 第 6 轮联合设计。** 三条加载路径归一化为一条，声明系统（pluginRole/appearsIn）与加载管线共享不可变原则。
> 执行清单任务：E5#12 + E5#13 + E5#14
> 联合设计 plan：`C:\Users\fengy\.claude\plans\e5-serene-eagle.md`

## 🔥 三条铁律（来自两次失败）

1. **glob manifest 只读** → `import.meta.glob({ eager: true })` 返回冻结对象。任何 `manifest.xxx = value` 都会抛异常。推导用局部变量，永不写 manifest。
2. **normalizeManifest 不设空 contributes** → 只有真正有 `themes`/`languages`/`file` 旧字段的插件才创建新 contributes 对象。settings（无 contributes）走此函数返回 `undefined`，安全。
3. **加载管线不知道 UI** → `loadPluginLifecycle` 不 import IconBar/SidePanel/TabBar。`appearsIn` 的消费只在 UI 层（`viewRegistry.getIconLocation` / `IconBar.tsx`）。

---

## 一、前因——三条互不知道的路径

### 1.1 当前状态（loader.ts）

```
loadPlugin(pluginId)                    ← 总入口
  ├── loadViewPlugin(pluginId, manifest)    ← 有 entry → 加载 React 组件 (L875)
  ├── loadThemePlugin(pluginId, manifest)   ← 有 themes/file → 注册主题 (L933)
  ├── loadLanguagePlugin(pluginId, manifest)← 有 languages/file → 注册 i18n (L1096)
  └── parseContributions(pluginId, c)       ← 有 contributes → 分发到各 Registry (L344)

loadPluginRuntime(pluginId)            ← 运行时加载（非 glob 插件）(L725)
  └── 重复了大量 loadPlugin 的逻辑
```

**问题：**
1. `loadThemePlugin` 和 `loadLanguagePlugin` 逻辑和 `parseContributions` 的 `contributes.themes`/`contributes.languages` 分支重复——两条路径做同一件事
2. `loadViewPlugin` 内部还调了 `parseContributions` 中没有的 langDefs 解析——寄生在视图插件里
3. `loadPluginRuntime` 是 `loadPlugin` 的复制粘贴——E3b #36j1 提取了 `applyPostLoadSteps` 堵了一部分缝，但加载逻辑本身仍重复
4. Python 纯数据插件被迫声明 `entry` + 写空 `index.tsx`——因为 langDefs 解析寄生在 `loadViewPlugin` 里

### 1.2 目标

```
loadPlugin(pluginId)                    ← 唯一总入口
  ├── loadPluginLifecycle(pluginId, manifest)  ← 所有插件都走这个
  │     ├── parseContributions()  ← 公共步骤——主题/语言/命令/菜单/视图容器/文件关联/langDefs
  │     └── loadPluginComponent() ← 仅当 entry 存在——加载 React 组件
  └── 不再有 loadThemePlugin / loadLanguagePlugin
```

### 2.1 核心——拆分公共步骤和视图步骤

async function loadPluginLifecycle(
  pluginId: string,

### 2.3 normalizeManifest——旧格式兼容（纯函数，不 mutate）

`themes`/`languages`/`file` 是 E3 时期的遗留字段。3 个使用这些字段的插件（theme-defaults、lang-defaults、theme-mint-soda）在 E5#12 中迁移 plugin.json 到 `contributes` 格式。

**向后兼容函数**——不修改原 manifest：

```typescript
/**
 * 纯函数。返回 contributes 对象，不修改原 manifest。
 * 无旧格式字段 → 返回 undefined（settings 等插件安全通过）。
 */
function normalizeManifest(manifest: PluginManifest): Record<string, unknown> | undefined {
  if (manifest.contributes) return manifest.contributes as Record<string, unknown>;

  const old = manifest as Partial<OldFormatManifest>;
  const hasThemes = Array.isArray(old.themes) && old.themes.length > 0;
  const hasLanguages = Array.isArray(old.languages) && old.languages.length > 0;
  const hasFile = typeof old.file === "string" && old.file.length > 0;

  if (!hasThemes && !hasLanguages && !hasFile) return undefined; // ← settings 走这里

  const c: Record<string, unknown> = {};
  if (hasThemes) c.themes = old.themes;
  if (hasLanguages) c.languages = old.languages;
  return c;
}

interface OldFormatManifest { themes?: unknown; languages?: unknown; file?: unknown; }
```

迁移完成后旧字段从 `PluginManifest` 类型和 `plugin.schema.json` 中删除。

### 2.4 与第 6 轮的衔接——pluginRole 推导

`loadPluginLifecycle` 是两轮的桥梁。第 6 轮的 `pluginRole` 在此函数内用**局部变量**推导，不写 manifest：

```typescript
// 在 loadPluginLifecycle 内部
const role = manifest.pluginRole
  ?? (!manifest.entry && (contributes || manifest.contributes) ? "data" : undefined);

if (role !== "data" && manifest.entry && !opts?.skipView) {
  await loadPluginComponent(pluginId, manifest);
}
```

`appearsIn` 的消费在第 6 轮——只在 UI 层（viewRegistry / IconBar）读，不经过加载管线。

```typescript
async function loadPluginLifecycle(pluginId: string, manifest: PluginManifest): Promise<void> {
  // Step 1: parseContributions——出错不阻塞视图加载
  try {
    if (manifest.contributes) {
      await parseContributions(pluginId, manifest.contributes as Record<string, unknown>);
    }
  } catch (e) {
    console.error(`[loader] ❌ parseContributions 失败: plugin=${pluginId}`, e);
  }

  // Step 2: loadPluginComponent——出错不阻塞其他插件
  if (manifest.entry) {
    try {
      await loadPluginComponent(pluginId, manifest);
    } catch (e) {
      console.error(`[loader] ❌ 加载视图组件失败: plugin=${pluginId}`, e);
    }
  }
}
```

**验证：** 故意写错一个插件的 contributes → Console 红色报错 → 其他插件正常加载。
