## 细节① 标签栏拖拽竖线——点住就整排右移 1px（任务 #51）

### 现象（用户原话要点）
「标签栏点住时最左边出现竖杠导致整排标签右移 1px（点 × 尤其明显），类比之前串口底部快捷发送键「点住放大」因挤旁边按键被删，要求去掉竖杠（**上方横杠保留**）。」

### 根因（代码实证）
- 竖杠不是聚焦指示——是 `.group-tab-drop-indicator`（**组内拖拽插入指示器**），不是 `#46.10` 的跨窗吸附竖线。
- 渲染点：`src/pool/shared/group-tab-bar/GroupTabBar.tsx` L280-282（条件 `dragInsertIndex === idx && draggingId !== tab.id`）+ L348-350（末尾指示器）。
- **时序 bug**：`useDragReorder.ts` L141 `startDrag` 在 **mousedown 同步 `setInsertIndex(fromIndex)`**，而 `draggingId` 仍为 null，L162-165 才在 5px 阈值后设 `draggingId` → **纯按下（没拖动）就显示竖杠**。
- 竖杠是流内 flex 项（`GroupTabBar.css` L180-185，2px `flex-shrink:0`）→ 参与布局 → 整排标签右移 1px。

### 方案（2026-08-23 竞标 D 定稿——用户拍板）
区分两个机制——**只动组内拖拽指示器**，`#46.10` 跨窗吸附竖线（整条高亮改细竖线）是用户刚拍板的独立机制，**不动**。

**竞标过程**：用户先提「要不要重新设计标签栏样式，比如圆角、标签间留空隙」→ 出 5 形态对比 mockup（`mockups/01-标签栏形态对比.html`），用户补充关键洞察「**如果两个标签栏中间本来就有空隙，那么插入一个竖杠是理所当然的**」→ 再让多 design skill 竞标（`mockups/02-标签栏风格竞标.html`：A minimalist-ui 编辑部极简 / B high-end 液态玻璃 / C high-end 双贝塞尔 / D ui-ux-pro-max 基准进化）→ **用户拍板 D**。

**D 定稿（2026-08-23 实机验收打回一次后修订——时机 + 坐标双修正）**：
- **形态（不变）**：tab 独立圆角矩形（`border-radius: 6px`）+ tab 间常驻 `4px` 空隙 + active 顶部 2px accent 横杠（独立 `::before` 短横杠）+ active 白底 `bg-window` + `separator` 描边 + 轻投影浮起。
- **时机修正（useDragReorder.ts）——竖杠 = 独立的落点指示，不跟被按 tab 绑定**：删 `startDrag` 的 mousedown 同步 `setInsertIndex(fromIndex)`（原 L141）→ **长按（未拖动）不出竖杠**；越过阈值拎起时（L162-165）`setInsertIndex(ds.fromIndex)` 显示起始落点；拖动中 `computeInsertIndex` 继续跟随（既有逻辑）；跨栏吸附竖线（#46.10）保持「拖到目标缝才出现」。
- **坐标修正（GroupTabBar.css）——竖杠居中于两胶囊空隙正中**：空隙 G=4px、竖线 W=2px → `margin-left: −3px` + `margin-right: +1px` = 净占 0（整排纹丝不动）且竖线落 `[P+1, P+3]`（P=前一 tab 右缘，空隙 `[P, P+4]` 两边各留 1px）——正正好好站两个胶囊空隙中间，不被圆角挡。
- `GroupTabBar.tsx`：**渲染结构零改动**——指示器渲染条件（L280-282 组内 / L348-350 末尾）保持原样。
- 兜底验收：**长按任一标签（含 ×）→ 无竖杠、整排零位移**；拖起后竖线跟随落点；拖到另一标签栏旁 → 竖线出现在目标缝且居中于空隙；active 横杠保留。

### 落点

## 细节③ 右键/浮空面板外层聚焦蓝框——难看违和（任务 #53）

### 现象（用户原话要点）
「右键/浮空面板（Ctrl+,）外层出现聚焦蓝框（白主题蓝色、换主题变色），难看违和。」

### 根因（代码实证）
- 全局 `*:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }`（`src/index.css` L225-228）波及**程序化聚焦的覆盖层容器**——ContextMenu.tsx L246/284、FloatingPanelHost.tsx L118/242 用 `tabIndex=-1 + .focus()` 让容器抢键盘焦点，`focus-visible` 命中 → 冒蓝框。
- 类选择器 `outline: none`（FloatingPanel.css L35、DialogHost.css L33）**同特异性被后声明的全局规则盖掉**——不是没写，是写不赢。

### 方案
提高覆盖层特异性，让「容器级别 outline:none」稳压全局 `*`：
- 覆盖层根类显式 `:focus-visible { outline: none }`（`.context-menu:focus-visible` / `.floating-panel:focus-visible` / `.dialog:focus-visible`……）——类 + 伪类特异性(0,1,0)+(0,1,0) > 全局 `*`(0,0,0)。
- 或全局规则排除覆盖层容器（`*:focus-visible:not(...)`）——不推荐，类加特异性更直白、不碰全局。
- 保留**键盘导航**：ContextMenu 内部菜单项仍有各自 focus-visible 样式（那是用户要的键盘焦点反馈），只消除「容器本身」的框。

### 落点
`src/index.css`（若改全局）、`ContextMenu.css`、`FloatingPanel.css`、`DialogHost.css`（各覆盖层根类补特异性）。CSS 改动 → 实现时过 ui-ux-pro-max。

### 验收 / 门禁
右键菜单弹出 / Ctrl+, 浮空面板 / 对话框 → 外层无蓝框；菜单内键盘上下选仍有高亮焦点；Esc 关闭等交互零回归 → `npm run check` 全绿 → commit → 实机验证 → 回勾。

✅ **已回勾（2026-08-23 用户确认）**：commit `9ed662db`。三覆盖层根类（.ctx-menu / .floating-panel / .dialog-host-panel）补显式 `:focus-visible { outline: none }`，特异性(0,2,0)稳压全局。

## 细节④ 状态栏串口灯+计数——四现象（任务 #54）

### 现象（用户原话要点）
① 分屏先开 COM3 灯亮，再开 COM13 灯不变、无数字 2；② 点击 COM3 标签灯灭不恢复（两串口都开着）；③ 把 COM13 拖回与 COM3 同组松手才出现数字 2；④ 数字 2 与绿灯之间不该有竖杠分隔，分屏时该显示 2 却没显示。

### 根因（代码实证）
串口插件状态栏组件：`plugins/user/serial-monitor/src/components/statusBar.tsx` + 状态服务 `SerialContext.tsx`。

- **现象 ① 开第 2 口不计数**：`SerialContext.tsx` L328 `_setState`（通知）在 L329 `_openPorts.set`（把新口加进 Map）**之前** → `useOpenPortCount`（L418-426 读 `_openPorts.size`）重读时仍是旧 size=1，之后无新通知 → 停在 1。对照 `closePortFromModule` L278 delete → L279 通知顺序正确 → 关口能更新、开口不能——**不对称**。
  - 叠加：`_openPorts` 是**模块级每 JS 上下文独享** Map（L92），脱出窗/分屏多窗各一份 → 主池上下文永远感知不到别的窗口打开的口。
- **现象 ② 点 COM3 标签灯灭不恢复**：绿灯绑「活动会话口」（statusBar.tsx L61-63）；点标签 → index.tsx L353-357 `setActiveSessionId` → 状态栏 `useIsOpen("COM3")` 依赖变 → L27 **先强制 `setIsOpen(false)`** 再等 `plugin-state:changed` 事件补状态——**事件不重放**，COM3 的 `:isOpen=true` 写入发生在很久前，此刻订阅收不到旧事件 → 灯停在 false。
- **现象 ③ 拖回同组才出现 2**：是现象 ① 的「症状」。合并/移动标签触发跨组 remount → ControlPanel 重新 mount `refreshPorts()` → `_setState` → `useOpenPortCount` 借机重读 Map（此刻 COM3+COM13 都在）→ 才读到 2。**碰巧重读到，非打开时正确推送**。
- **现象 ④ 灯与计数间竖杠**：statusBar.tsx L80 显式插入 `<span className="status-divider" />`，与状态栏**分组分隔线**同一样式（`StatusBarZone.css` L30-36）——分组级分隔被误用于灯的附属计数。

### 方案
1. **现象 ④（最简单，独立）**：删 statusBar.tsx L80 竖杠 span，灯与 `(N)` 用间距/CSS 紧贴，不用分组分隔线。
2. **现象 ① 开口计数顺序**：`openPort` 把 `_openPorts.set` 挪到 `_setState` 之前（对齐 closePortFromModule 顺序）。
3. **现象 ② 换口播种真实状态**：`useIsOpen` 换口时先异步 `pluginState?.get("serial-monitor", `${port}:isOpen`)` 播种真实值，再订阅事件兜底后续变化——「事件不重放」通用解法（初始 mount 也直接显示真实状态）。
4. **现象 ①③ 跨上下文根治**：计数统一到**事件/pluginState 通道**而非局部 `_openPorts` Map——灯已靠 `plugin-state:changed` 跨窗口同步，计数同理按「多少 `:isOpen=true` 键」计（复用 `_writePortState` 单一咽喉，写 `:isOpen` 时顺带维护/广播总口数）。从根上消除「脱出窗/分屏主池感知不到别窗打开的口」。
   - 若根治方案改动面大 → 先落 2+3（同上下文正确性）+ 单独核实分屏/脱出窗计数缺口，是否本次补全由实机验证定（用户拍板粒度）。

### 落点
`plugins/user/serial-monitor/src/components/statusBar.tsx`、`plugins/user/serial-monitor/src/services/SerialContext.tsx`（+ 需要处 `ControlPanel.tsx`）。**注意插件侧代码**——串口插件自身实现，改插件不违插件独立铁律。

### 验收 / 门禁
开第 2 口 → 数字立刻 2；点回 COM3 标签 → 绿灯保持亮；合并拖拽 → 计数不闪变；灯与计数间无竖杠、紧贴显示；分屏/脱出窗下两窗口各开一口 → 计数正确反映全局 → `npm run check` 全绿 → commit → **实机验证（分屏两串口场景用户亲测）** → 回勾。

✅ **已回勾（2026-08-23 用户确认）**：commit `6b304d2f`（根治）+ `491545da`（打回补修）。计数权威上移主进程 getStatus() 全口 + 事件重拉；useIsOpen 播种 pluginState 真实值；openPort 记账顺序对齐；删竖杠 + 灯/(N) 同组 inline-flex 垂直对齐紧凑间距。

## 细节⑤⑥⑦ 菜单系统统一——顶部/汉堡/右键三面归一（任务 #55）

### 现象（用户原话要点）
⑤ 顶部菜单栏/汉堡菜单/右键菜单**不是同一套 UI**：顶部无子菜单、汉堡有子菜单但主面板被拉长与子面板对齐、「面板」一项占同高大面板；⑥ 顶部菜单栏和汉堡没必要另搞一套，应统一到右键菜单系统（对标 VS Code 顶部菜单丰富嵌套子菜单：查看→外观→活动栏位置→顶部/底部/隐藏，对齐面板→…）；⑦ 查 git 历史搞清为什么当时造两套新菜单。

### 根因（git 历史实证）
**不是三套系统，是「两套渲染器 + 三种表面」**：
- 顶部菜单栏 + 汉堡菜单**共用 `MenuItemList` 渲染器**（cssPrefix 不同），右键菜单 ContextMenu 独立。
- **数据源已同源**——都从 `MenuRegistry`（MENU_SLOTS.MenuBar/Panel）读，壳序列化推送。
- **⑦ 历史局限（用户假设成立）**：ContextMenu 诞生 2026-07-21 时**无子菜单能力**（ResolvedItem 只有 {id,label,group,shortcut}，`if(!cmd) continue` 丢弃父项）→ E3f #52 另立 MenuRenderer/MenuItemList 体系（07-27）；此后 ContextMenu 反超（子菜单 08-05 / √checked 08-21 / commandArgs / 键盘导航 / portal），MenuItemList 停在 E3h 水平 + flex 拉伸 bug。
- **三现象代码根因**：
  - 顶部无子菜单 = 数据层 `usePoolSync/titlebar.ts` `buildTitleBarMenuGroups` **展平父项**（L77-94）——渲染器其实支持子面板，数据不给。
  - 汉堡主面板拉长对齐子菜单 = `IconBarZone.css` `.hamburger-dropdown` flex + 主/子面板 flex 兄弟 `align-items:stretch` 强制等高（L149-185）。
  - 「面板」一项占同高大面板 = 同上（flex stretch 一锅端）。

### 方案 A（推荐）——保留菜单栏按钮行 chrome，下拉渲染整体切 ContextMenu
- `TitleBarZone`（菜单栏）+ `IconBarZone`（汉堡）下拉替换为 **ContextMenu 渲染器**：
  - `buildTitleBarMenuGroups` 去掉父项展平（保留层级 → 顶部也能出子菜单）。
  - ContextMenu 加 2-3 个可选 prop：**backdrop 开关**（菜单栏下拉不需要全屏遮罩）、**组标签显示开关**（汉堡现状显示组标签 vs 顶部隐藏）、（如需要）定位模式。
- **删除 MenuItemList** + 相关 CSS + 序列化侧收窄（`usePoolSync/titlebar.ts` 展平逻辑可简化——具体按数据流定）。
- **插件侧零影响**：菜单贡献走 MenuRegistry 字符串槽位契约，命令/组/子菜单数据不变，只换渲染器。

### 方案 B（备选，不推荐）
保持两套渲染器，仅修 MenuItemList 的 flex 拉伸 bug + 顶部加子菜单。工作量小但**两套系统继续并行维护**，违背用户「统一」主张。

### 落点

### 验收 / 门禁
