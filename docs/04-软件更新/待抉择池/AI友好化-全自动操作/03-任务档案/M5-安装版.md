## AI#17 ⬜ 更新重启保留调试参数（**唯一必须改行为**的一格）

**做什么**：修「**应用内自动更新重启后 CDP 参数丢失**」。

🔴 **根因（本会话实读确认，行号订正）**：`electron/services/update-install.ts:171-173` 的 `defaultLaunch`：

```ts
function defaultLaunch(installerPath: string): void {
  app.relaunch({ execPath: installerPath, args: [SILENT_SWITCH, FORCE_RUN_SWITCH] });
}
```

**注释原文即答案**：「`args` 显式给全，**不继承我们自己的命令行**」⇒ `--remote-debugging-port` **必丢**（[§2.3 D 类](../01-设计.md) / [§十 第 9 例](../01-设计.md) 的落点）。

⚠️ **行号订正**：设计 §四 M5 写 `update-install.ts:169-171`，**实测为 `:171-173`**（见 [../02-目录与切片规划.md §四 C](../02-目录与切片规划.md) 漂移表）。开工按新 HEAD 再核。

**两条修法（拍板 A-1 / 设计 §四 M5 ① 给了两选）**：

| 修法 | 做法 | 评估 |
|:--|:--|:--|
| **保参数** | 重启后**带上原调试参数**（把当前 `process.argv` 里的调试 switch 透传给 `app.relaunch`） | 直接、改动局部；⚠️ 但把「调试参数」变成**会被继承的状态**——要在「只透传调试类 switch」上写死白名单，⛔ 不要整串 `argv` 无脑继承 |
| **设置内开关** | 提供**设置内的调试端口开关** | **更安全、可发现**（本档倾向）：用户/AI 不必知道命令行语法，开关即状态；⚠️ 但引入「端口号从哪来 / 与单实例锁怎么处」两个新问题 ⇒ 与 `AI#18` 同批做 |

**判据**：[§七 第 3 条](../01-设计.md)——「装 → 更新 → **更新后 AI 仍能操作**」不中断。

**验收方式**：⚠️ **打包态才见效 ⇒ 必须凑在发版批次里**（[04 README §一](../../../00-README.md) 攒批例外条款；同 `AI#19`）。⛔ dev 里验不了这条——**别在 dev 报绿**。

**风险 / 边界**：
- ⛔ 这条**不是**「把 CDP 变成常开」——[§八 绕行路径](../01-设计.md) 明确**默认不监听**，且设计**选择不堵** CDP 后门（三个理由在 §八）。本格只修「**更新这一跳**把已有参数弄丢」，⛔ 不动「默认开不开端口」。
- 同族还有 `electron/services/update-install.ts` 里的静默安装/重启链 ⇒ 改动要**顺带核一遍同文件其余 `relaunch` 调用点**（别只修 `defaultLaunch` 一处）。

## AI#18 ⬜ 调试端口设置开关 ＋ 单实例锁交互

**做什么**：把「**单实例锁 × 调试端口**」的交互**写清并落地**——**二次带参启动路由给旧实例**（不启第二个实例，参数交给旧实例处理）。

**依据** = [§四 M5 ③](../01-设计.md) ＋ [§9.3 难点 3](../01-设计.md)（原文：「多窗口 / 单实例锁交互——**与 M5 合并处理**」）。

**为什么这两件必须同格**：`AI#17` 的「设置内开关」路线一旦落地，**端口就成了一个可能被二次启动请求改动的量** ⇒ 单实例锁下的行为定义**不可回避**（[§9.3](../01-设计.md) 把它列为 M4 三个已知难点之一，设计已拍**与 M5 合并**——本格就是那个合并点）。

**判据**：二次带参启动**不启第二个实例**、且**参数被旧实例正确处理**。

**验收方式**：软件已在跑 → 再带参启动一次 → 断言**进程数不增**（`tasklist` 只一个主进程树）＋ 参数生效（如端口按请求切换）。

**风险**：⚠️ 与 `AI#41`（M4 的多窗口/单实例）**同口径**——两格写的是**同一套行为的两个侧面**（本格 = 端口，M4 = 通道）⇒ **`AI#41` 直接复用本格结论，不重做**。

## AI#19 ⬜ 安装版端到端验收

**做什么**：在**真安装版**跑一遍「**装 → 更新 → 更新后 AI 仍能操作**」。

🔴 **打包态才见效 ⇒ 必须凑在发版批次里验收**（[04 README §一](../../../00-README.md) 攒批例外条款）。

**判据** = [§七 第 3 条](../01-设计.md) **全绿**——注意它**同时含两件**：① CLI/MCP 完成「装一个插件 → 打开它 → 操作它」② **软件自动更新重启后，AI 连接不丢**。⇒ 本格的验收**顺带吃 M4 的成果**（① 需要通道）⇒ 实践上**`AI#19` 要等 M4 有道可用**；若 M4 未成，本格**只验 ②**（`AI#17` 的直接判据）并在台账注明「① 挂 `AI#44` 之后复验」。

**依赖**：`AI#17`（② 的前提）；① 软依赖 `AI#34`/`AI#36`。

**验收方式（照 [§三 验收面第 1 条](../01-设计.md)）**：
- 全程**非坐标**（命令 / API / CLI）；
- 🔴 **验收回路与物理指针无关**——期间用户随便动鼠标不构成干扰；
- ⚠️ **先过「dev 验收前置」**（`D0#1`–`D0#3`）——尤其是**构建握手**：本格改的是 `electron/` 主进程代码，**必须确认跑的是新构建**，否则「更新后仍连不上」会分不清是**没修好**还是**根本没生效**（这正是 `D0#1` 要治的假阴性）。
