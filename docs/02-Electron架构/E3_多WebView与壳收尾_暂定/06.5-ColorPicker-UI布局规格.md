## 四、各区域详细规格

### 4.1 二维面板（饱和度 × 亮度）

```
实现方式：HTML Canvas（不用 CSS 渐变）
原因：CSS 渐变方案中 white → hsl(hue,100%,50%) 的饱和度过渡是非线性的——白色端不纯。
      Canvas 逐像素 hsl(currentHue, sat, light) 计算 → 精确。

Canvas 尺寸：180×180px
像素算法：
  for x in 0..179:
    saturation = x / 179 * 100          // 左 → 右：0% → 100% 饱和度
    for y in 0..179:
      lightness = (1 - y / 179) * 100  // 上 → 下：100% → 0% 亮度
      color = hsl(currentHue, saturation%, lightness%)

叠加层（亮度黑渐变）：
  // 在这个 HSL 层之上，CSS absolute：
  // background: linear-gradient(to bottom, transparent, black);
  // 这样亮度轴就是自然过渡——不需要 canvas 自己算。

实际上最简单的方案：
  Canvas 背景层：CSS background 组合
    1. background: linear-gradient(to right, white, hsl(currentHue, 100%, 50%))
       → 饱和度轴（白→纯色）
    2. overlay: background: linear-gradient(to bottom, transparent, black)
       → 亮度轴
    两层叠加 = 完整的 HS 二维空间

  结论：用 CSS 两层渐变叠加——比 Canvas 简单、GPU 加速、不需要 JS 逐像素。
  对标 VS Code：VS Code 也是 CSS 两层渐变。

⚠️ 注意：CSS 的 linear-gradient(to right, white, hsl(h,100%,50%)) 
  在 h 接近黄色(60°)时白色端过渡自然，但在 h=0°(红)时白色端会带品红色偏。
  这是 CSS 色彩空间的局限性——但 VS Code 也接受这个 tradeoff。
  未来的 Canvas 方案可彻底解决——v1 用 CSS 两层渐变，v2 可选切 Canvas。
```

```
两层渐变结构（DOM）：

┌─────────────────────────────────────┐
│ <div class="cp-sat-light-panel">   │  ← position: relative; 180×180px
│                                     │     border-radius: 4px
│   <!-- 层 1：饱和度（白→纯色） -->    │     overflow: hidden
│   <div class="cp-sat-layer" />      │  ← 全尺寸 absolute
│                                     │     background: left white
│   <!-- 层 2：亮度（透明→黑） -->      │     background: right hsl(var(--cp-hue),100%,50%)
│   <div class="cp-light-layer" />    │  ← 全尺寸 absolute
│                                     │     background: top transparent
│   <!-- 当前色指示器 -->              │     background: bottom black
│   <div class="cp-cursor-dot" />     │  ← absolute, 跟随鼠标
│                                     │     8×8px, border-radius 50%
│                                     │     border: 2px solid white
│                                     │     box-shadow: 0 0 0 1px rgba(0,0,0,0.4)
│                                     │     pointer-events: none
│                                     │     transform: translate(-50%, -50%)
└─────────────────────────────────────┘
```

**饱和度层 `--cp-hue` CSS 变量更新机制：**
- 拖拽色相条 → `document.documentElement.style.setProperty('--cp-hue', hue)` → 二维面板即时重绘
- 切换过程中不重新设置 background——CSS 变量搞定一切

### 4.3 hex 输入框 + 预览方块

```
┌──────────────────────────────────┬──────┐
│ <input class="cp-hex-input"     │ <div │
│   value="#0E639C"              │  class="cp-preview" />
│   maxlength=9                   │      │
│   placeholder="#000000" />      │      │
│                                 │      │
│   w=144px h=30px                │      │  ← 30×30px, border-radius: 4px

│   background: var(--bg-input)   │      │
└──────────────────────────────────┴──────┘
```

**hex 输入框校验行为：**

| 用户输入 | 行为 |
|------|------|
| 输入合法 hex（`#0E639C` / `#0e639c` / `0E639C`（无 #）） | Enter/blur → 解析为颜色 → 面板 + 色相条 + 预览同步更新 → `onChange` |
| 输入非法值（`#GGG` / `xyz` / `#12345`） | 即时红色边框 `var(--cp-input-error)` + tooltip "无效的颜色值"。失去焦点时恢复到上次有效值 |
| 粘贴 `rgb(255,0,0)` | 🔥 v1 不支持——只接受 hex。v2 加格式解析 |
| 输入 3 位 hex（`#F00`） | 自动展开为 6 位 `#FF0000` |
| 输入无 `#` 的 6 位（`0E639C`） | 自动补 `#` |

**双向同步：**
- 拖面板/色相条 → hex 值实时更新（每 mousemove）
- 改 hex 输入 → Enter/blur 后面板 + 色相条跳到对应位置
- 防止循环更新：mousemove 更新 hex 时设 `_internalUpdate=true`，hex onChange 检查此标记跳过触发

### 4.4 预设色 + 最近使用

```
预设色                                     ← 11px label, var(--cp-dimmed)
● ● ● ● ● ● ● ●                           ← 8 圆点, 16×16px, gap: 8px
  ↑ hover: scale(1.15)
  ↑ active: scale(0.92)
  ↑ 当前选中: border: 2px solid var(--accent)
  ↑ 没有匹配 → 无选中环

最近使用                                   ← 11px label, var(--cp-dimmed)
○ ○ ○ ○ ○                                 ← 最多 5 圆点, 16×16px, gap: 8px
                                            无最近使用 → 整行不渲染
                                            (不显示 label 也不显示空白)
```

**默认预设色（8 个，对标 VS Code）：**
```
#FFFFFF  #E53E3E  #DD6B20  #38A169  #3182CE  #805AD5  #D53F8C  #000000
  白       红       橙       绿        蓝       紫       粉       黑
```

**最近使用存储：**
- 🔥 走 `PluginStateService`（对标 E4e #90 教训——不另辟蹊径写 localStorage）
- key: `"colopicker"` → `"recentColors"` → `string[]`（最多 5 个 hex）
- 选择颜色确认时 → 推入数组头部 → 去重 → trim 到 5
- 首次使用 → 数组为空 → 最近使用行不渲染

### 4.5 选中的预设高亮逻辑

```

当前色为 #1A1A2E → 预设中无匹配 → 无圆环
```

## 五、弹出浮层定位

### 5.1 锚定规则

```
触发元素（色块按钮）
  │
  ├── 下方空间 ≥ 320px → 浮层出现在触发元素下方
  │     anchored: trigger.bottom + 4px gap
  │
  └── 下方空间 < 320px → 浮层翻转到触发元素上方
        anchored: trigger.top - panel.height - 4px gap
```

- 水平：浮层左边缘与触发元素左边缘对齐（若浮层超出窗口左边界 → 改为右边缘对齐）
- 实现：`createPortal` 到 `document.body`，绝对定位基于 `trigger.getBoundingClientRect()`
- 滚动/窗口 resize → 浮层重新计算位置（`ResizeObserver` + `scroll` event）

### 5.2 z-index 层级

| 浮层 | z-index |
|------|:--:|
| 右键菜单 ContextMenu | 1500 |
| **ColorPicker** | **1600** |
| SelectBox 下拉 | 1700 |
| QuickPick 命令面板 | 2000 |
| ConfirmDialog | 2100 |

> 对标 ContextMenu onClose 竞态教训（memory `e3f-53-setting-gear-bugs.md`）：
> ColorPicker 关闭时用 `mousedown` 监听外部点击（不是 `click`——避免和 ContextMenu 的 `click` 时序冲突）。

## 六、交互规格

### 6.1 面板拖拽

| 操作 | 行为 |
|------|------|
| mousedown | 记录起始坐标 → 设置 `isDragging=true` |
| mousemove | 计算 saturation = x / 180, lightness = 1 - y / 180 → 更新当前色 → hex 输入框 + 预览方块 + 指示器即时同步 |
| mouseup | `isDragging=false` → 不确认——用户可以继续拖 |
| 光标 | `cursor: crosshair` |
| 触摸 | `touchmove` 同 mousemove（移动端兼容） |

### 6.2 色相条拖拽

| 操作 | 行为 |
|------|------|
| mousedown | 记录起始 x → `isDragging=true` |
| mousemove | 计算 hue = x / 180 * 360 → `document.documentElement.style.setProperty('--cp-hue', hue)` → 面板重绘 + 指示器移动 + hex 同步 |
| mouseup | `isDragging=false` |
| 光标 | `cursor: ew-resize` |

### 6.3 确认与取消

| 操作 | 行为 |
|------|------|
| 点预设色圆点 | → 颜色立即切换到该预设 → `onChange(hex)` 回调触发 |
| 点最近使用圆点 | → 同上 |
| hex 输入框 Enter | → 校验 → 有效 → 面板+色相条同步 → `onChange(hex)` |
| 面板外 mousedown（非触发元素） | → 恢复 `value` prop 的初始值 → 关闭浮层 → **不**触发 `onChange` |
| Esc | → 同上——恢复旧值 → 关闭 |
| 点触发元素 | → toggle 关闭（同上逻辑） |

### 6.4 键盘导航

| 按键 | 行为 |
|------|------|
| Tab | 面板 → 色相条 → hex 输入框 → 预设色列表 → 循环回面板 |
| Shift+Tab | 反向循环 |
| ↑↓←→（面板聚焦时） | 微调 saturation/lightness ±1% |
| ↑↓（色相条聚焦时） | 微调 hue ±1° |
| Shift+↑↓←→ | 微调 ±10%（快速调整） |
| Enter | 确认当前色 → `onChange(hex)` → 关闭 |
| Esc | 取消 → 恢复旧值 → 关闭 |

## 七、动画规格

> 来源：`ui-ux-pro-max` motion 3/10 (Subtle)。所有动画尊重 `prefers-reduced-motion`。

| 动画 | 时长 | 缓动 | 说明 |
|------|:--:|------|------|
| 浮层打开 | 150ms | `ease-out` | `transform: scale(0.95)` + `opacity: 0` → `scale(1)` + `opacity: 1` |
| 浮层关闭 | 120ms | `ease-in` | 反向——比打开快 20%（`exit-faster-than-enter` 原则） |
| 预设圆点 hover | 150ms | `ease-out` | `scale(1)` → `scale(1.15)` |
| 预设圆点 active | 100ms | `ease-out` | `scale(1.15)` → `scale(0.92)` |
| 面板指示器移动 | 0ms | — | 即时跟随鼠标——不加过渡否则拖拽有延迟感 |
| hex 边框错误 | 200ms | `ease-out` | 非法 hex → 边框色从 `--cp-border` 过渡到 `--cp-input-error` |
| hex 边框恢复 | 300ms | `ease-out` | 合法 hex → 边框色回 `--cp-border` |
| 面板饱和度层切换 | 0ms | — | `--cp-hue` CSS 变量变化 → 浏览器即时重绘（GPU 合成层） |
| focus ring 出现 | 150ms | `ease-out` | `box-shadow` 过渡 |

**实现方式：** 纯 CSS transition，不引入 GSAP（motion 级别为 Subtle 且这是微交互不是页面级动效）。

## 八、状态矩阵

| 状态 | 触发条件 | 视觉表现 |
|------|------|------|
| **正常** | 有合法 hex value + 有 presets | 完整浮层渲染 |
| **面板拖拽中** | mousedown on 面板 + 移动 | `cursor: crosshair` + 指示器 + hex + 预览实时同步 |
| **色相条拖拽中** | mousedown on 色相条 + 水平移动 | `cursor: ew-resize` + 面板渐变实时切换 + 指示器 + hex 同步 |
| **预设列表非空** | `presets` prop 有值 | 渲染预设行（默认 8 个 + 自定义） |
| **预设列表为空** | `presets` 不传或传 `[]` | 预设行不渲染——不显示空 label |
| **无最近使用** | 首次使用，`recentColors` 为空 | 最近使用行不渲染 |
| **有最近使用** | `recentColors` 有 1-5 个 hex | 渲染最近使用行 + 圆点 |
| **hex 合法** | 输入 3/6 位有效 hex | 输入框正常边框 |
| **hex 非法** | 输入 `/^#([0-9a-fA-F]{3}|[0-9a-fA-F]{6})$/` 不匹配 | 输入框红色边框 + tooltip "无效的颜色值" |
| **hex 为空** | 清空输入框 | 不报错，失去焦点时恢复上次有效值 |
| **当前色在预设中** | `value` 匹配某个预设色 hex | 对应圆点显示 `2px solid var(--accent)` 圆环 |
| **当前色不在预设中** | `value` 不在预设列表 | 无圆环标记 |
| **value 外部变化** | prop `value` 更新 | 面板指示器 + 色相指示器 + 预览 + hex 输入框全部同步更新（但不触发 `onChange`） |
| **键盘导航** | Tab/Shift+Tab | focus ring 可见，当前聚焦元素有 `box-shadow: 0 0 0 2px var(--accent)` |
| **`prefers-reduced-motion`** | 系统设置减少动效 | 所有 transition 设为 `0ms`——浮层直接出现不缩放 |
| **浮层溢出视口** | 窗口高度 < 浮层底部 | 浮层内部滚动（`overflow-y: auto`）——面板和色相条不动，预设/最近使用区域可滚动 |

## 九、可访问性

| 元素 | ARIA | 说明 |
|------|------|------|
| 浮层容器 | `role="dialog"` `aria-label="颜色选择器"` | 屏幕阅读器识别为对话框 |
| 二维面板 | `role="img"` `aria-label="颜色饱和度与亮度选择区域"` | 面板是不可交互的 img——颜色通过鼠标坐标计算 |
| 色相条 | `role="slider"` `aria-label="色相"` `aria-valuemin="0"` `aria-valuemax="360"` `aria-valuenow={currentHue}` | 可键盘操作（←→ 微调） |
| hex 输入框 | `<input>` + `<label class="sr-only">十六进制颜色值</label>` | label 关联 input（UX 规则：不只用 placeholder） |
| 预设色列表 | `role="listbox"` `aria-label="预设颜色"` | |
| 预设色圆点 | `role="option"` `aria-label="选择预设色: {hex}"` `aria-selected={isCurrent}` | 每个圆点 = 可选择项 |
| 最近使用列表 | `role="listbox"` `aria-label="最近使用的颜色"` | |
| 预览方块 | `aria-hidden="true"` | 纯装饰——颜色信息已在 hex 输入框提供 |
| Esc 关闭 | 浮层监听 `keydown` → `Escape` → 恢复旧值 → 关闭 → focus 回到触发元素 | React focus trap 规则 |

## 十、接口定义

```typescript
// src/components/shared/ColorPicker.tsx

interface ColorPickerProps {
  /** 当前颜色（hex 字符串，如 "#0E639C"） */
  value: string;
  /** 用户确认颜色后的回调 */
  onChange: (hex: string) => void;
  /** 自定义预设色列表（不传 = 使用默认 8 个） */
  presets?: string[];
  /** 触发元素 ref——用于锚定浮层位置 */
  triggerRef: React.RefObject<HTMLElement>;
  /** 是否显示浮层 */
  open: boolean;
  /** 请求关闭浮层（点外部/Esc）——不触发 onChange */
  onClose: () => void;
}
```
