# 07-共享组件独立分发设计（@linkdesk/ui + token 契约）

> 2026-08-29 立案 **E6#54**。用户拍板方向 A：壳共享 UI 组件打包成 `@linkdesk/ui` npm 包 + SDK 内置 eslint token 门禁，让第三方插件作者独立写出与内置插件同款、自动跟随主题/玻璃的界面。

---

## 设计前置（8 维度）

### ① 能力边界
- **壳能力还是插件能力？** 壳能力——共享组件是壳对全体插件开放的 UI 资产，多提供方（任何插件消费）/ 多消费方（内置 + 第三方）/ 壳不知道内容（组件是通用控件，不知道业务）。符合核心准入三条件。
- **保底设计：** 无插件时组件无消费方，零影响（组件只在 import 它的插件 bundle 内存在）；壳自身不依赖 @linkdesk/ui（壳内组件仍直接引用 `src/components/shared/` 源码——包只服务插件侧，防环依赖）。

### ② API 设计
- 不新增 `window.linkdesk.*` 方法——组件契约是 **React props + 既有 linkdesk API**（组件内部经 `window.linkdesk.*` 取数据，见④⑤），零新 API（通用优先铁律）。
- 包的 API 面 = 每个组件的 props 契约（`{ value, onChange }` 等）+ TS 类型导出；契约位置 = `packages/linkdesk-ui/` 的 d.ts（由壳 `src/components/shared/` 源码派生，防漂移）。

### ③ 通信方式
- 组件内部需要数据时走既有 `window.linkdesk.*` 桥（如 ContextMenu 经 `lk().menu.getItems`、ThemePicker 经 `window.linkdesk.theme.listRecipes`）——铁律：插件通信全走 window.linkdesk.*，禁止 import @src/core。
- 数据流：壳 Registry → IPC preload 桥 → 组件 props/内部调用；插件把数据经 props 传进组件，组件不反向握插件内部状态。

### ④ 壳侧代码设计
- 单一源码：组件**仍居** `src/components/shared/`（壳目录规范 components/shared 准入），`packages/linkdesk-ui/` 只产构建产物/类型，从源码编译——**一份源码，杜绝两份漂移**。
- 解耦硬约束：每组件零 `@src/core` import（组件内部需要的壳服务一律经 `window.linkdesk.*`）、零 hex（全 var(--*)）、数据纯 props 注入。
- eslint-local-rules PLUGIN_IMPORT_WHITELIST（`eslint-local-rules.js:797`）今天已放行 `@src/components/shared/*`；解耦后该放行保持，不新增拦截。

### ⑤ 插件侧代码设计
- 内置插件（file-tree/settings/serial-monitor…）`@src/components/shared/*` → `@linkdesk/ui`；第三方插件直接 `npm i @linkdesk/ui` + `import { ContextMenu, SelectBox, Toggle } from "@linkdesk/ui"`。
- 走 .linkdesk-plugin 打包格式（index.bundle.js，react/react-dom/react-i18next/i18next 外部化——壳提供），@linkdesk/ui 属"其它皆内联"——组件源码编译进各插件 bundle（"壳的身子，插件的座"延续）。
- 插件独立铁律满足度：第三方作者不再需要壳改代码即可用壳控件。

### ⑥ 显示设计
- 显示位置：插件自己布局内任意处（设置页齿轮、文件树右键、串口接收区右键……现状延续）。
- 显示样式：组件全 token 化（var(--*)/--accent/--glass-blur/--glass-saturate/surface 变量）→ 进 pool DOM 即自动跟随主题 + 玻璃态，无需插件感知主题。

### ⑦ 配置设计
- 无新配置项。组件不引入 app.* 或插件配置——控件值由插件 props 注入、插件自行持久化（现状不变）。
- 玻璃/主题跟随是 CSS 变量继承的既有能力，非新配置。

### ⑧ 代码规范 + 验收
- 命名/注释/测试卫生：组件经解耦审计（E6#54a）后零 @src/core；SDK eslint 预设（no-hardcoded-hex / no-hardcoded-zh）机械门禁第三方代码。
- 验收：`npm run check` 全绿 + 第三方独立构建插件实机（右键/下拉/开关与内置同款 + 玻璃切换自动跟随）+ 用户视觉验收。

## 一、问题：组件特权（为什么立案）

今天壳共享组件在 `src/components/shared/`，**只有能 import `@src` 的内置插件能引用**（编译期 Vite 别名）。用户三处右键实机证据：

| 位置 | 引用的组件 |
|---|---|
| 文件树右键 | `FileTreeContextMenu.tsx:10` → `@src/components/shared/context-menu/ContextMenu` |
| 串口接收区右键 | `serial-monitor/src/index.tsx:45` → 同一个 ContextMenu |
| 设置齿轮右键 | `settings/.../SettingRow.tsx:11` → 同一个 ContextMenu |

结论：**共享机制对（一处源码多处消费），分发路径错（只有特权插件能用）**。E6#15 把内置插件也独立 build 后连内置都失去 `@src` ——共享组件分发成了 E6 生态的硬缺口：E6 数据/逻辑/构建/分发独立全部达成，唯独 UI 控件不可达，第三方作者要么自己重画（样式漂移、玻璃不跟随）、要么来让壳改代码（违反插件独立铁律）。

## 二、三候选路裁决（方向 A 定案）

| 方案 | 做法 | 裁决 |
|---|---|---|
| **A（定案）** | `@linkdesk/ui` npm 包 + SDK eslint 门禁；组件编译进各插件 bundle | ✅ 现状延续 = VS Code `webview + @vscode/webview-ui-toolkit` 模型；一套契约 |
| B | 命令式 API（`linkdesk.ui.showMenu({items})`） | ❌ 盖不住嵌入控件——齿轮/下拉/开关是要**摆进插件布局**的 React 组件，不是一次性弹层；且和 A 并存 = 两套契约违反归一化 |
| C | 插件自带 UI 库，壳不管 | ❌ 样式漂移、玻璃/主题不跟随，生态碎片化 |
| D | 共享组件留在壳内不分发 | ❌ 就是今天的现状 = 第三方无法独立，不解决立案问题 |

A 的三条铁证：① 通用优先——复用既有组件源码与 `window.linkdesk.*` 桥，零新 API；② 归一化——一套组件源码、一种分发方式；③ 插件独立——第三方 `npm i @linkdesk/ui` 即得，永远不需要壳改代码。

## 三、组件解耦审计（E6#54a）

全量盘点 `src/components/shared/` 下每组件，三依赖轴核查：

1. **纯 props 契约**：控件值/事件是否全经 props 传入（`{ value, onChange }` 类）；禁止组件内直接读插件私有状态。
2. **var(--*) token**：样式零 hex/零硬编码 px 色；全走 CSS 变量（--text/--bg/--accent/--glass-*/surface 等）——玻璃/主题跟随的自然继承点。
3. **window.linkdesk.\* API**：组件内部要壳数据必须经 linkdesk 桥（ContextMenu → `lk().menu.getItems`、ThemePicker → `window.linkdesk.theme.listRecipes`）；**禁止 `@src/core` import**（Registry/Service 模块态不跨进程共享）。

审计产出：每组件一张表（三轴 ✅/❌），❌ 即"带专属假设"→ 解耦改造清单（逐项给出改法）。目标态：全组件三轴全绿，@linkdesk/ui 可直接发布。

组件盘点清单（**实盘 16 个**——#54c 消费锚点，审计对齐 2026-08-29）：ContextMenu / **ColorPicker** / SelectBox / DynamicSelect / Slider / Toggle / NumberInput / Button / FontFamilySelect / FilePathInput / ThemePicker / SegmentedRadio / InlineInput / Combobox / FormRow / **PluginIcon**。**在范围未消费**：ConfirmDialog / OverlayPortal（审计实锤：settings 用 ColorPicker、marketplace 用 PluginIcon）。

## 四、@linkdesk/ui 包设计（E6#54b）

```
packages/linkdesk-ui/
  ├── package.json          # name: "@linkdesk/ui", main: "./dist/index.js", types: "./dist/index.d.ts"
  ├── src/                  # ← 不拷源码！这里是构建入口，import 壳 src/components/shared/* 经别名
  │   ├── index.ts          # barrel 导出全部共享组件
  │   └── …
  └── dist/                 # 构建产物（react 等 external，shell 提供）
```

**单一源码防漂移（关键决策）：** 组件源码**只存在于** `src/components/shared/`（壳目录），`packages/linkdesk-ui/` 的 `src/index.ts` 通过路径别名引用源码，`dist/` 是编译产物。改组件只改一处，壳与包同源。防漂移机制 = 包构建时校验源码变更（或直接发布前 `npm run check` 兜底），不设第二份拷贝。

- 零 `@src/core` 依赖；React 组件 + 全 token；react/react-dom/react-i18next/i18next 外部化（壳提供，不重复打）。
- **repo 侧接线（#54c 硬前置，审计补 2026-08-29）**：仓库现无 `packages/`、无 npm workspaces、无任何 @linkdesk 依赖——内置插件切 `import "@linkdesk/ui"` 后 node 解析不到包，当场编不过。**必选其一**：npm workspaces（根 workspaces + packages/linkdesk-ui）或 file: 依赖（`"@linkdesk/ui": "file:./packages/linkdesk-ui"`）。**先接线再切**，#54c 的 29 处才可编译。
- **sideEffects + ESM 具名导出（审计补 2026-08-29）**：package.json `sideEffects: ["**/*.css"]` + barrel 具名导出——否则 tree-shaking 失效，只用 Toggle 的插件背上全部组件（CSS 有副作用不可摇，必须声明）。
- 发布：npm 账号 fengyili；**npmmirror 不能发布 → 显式 `--registry=https://registry.npmjs.org`**（见 memory `e5.8-contracts-npm-publish-ready`）。

## 六、门禁机制定案：推荐/警告/知情绕行（E6#54d）

`@linkdesk/plugin-sdk` 新增 `eslint/` 预设 + 知情声明机制。规则从壳审查体系全量盘点外移（15 条）。**机制定案（2026-08-29 用户拍板——自由与统一不二选一，串成一条坡度）**：

### 三档梯度（不是墙，是坡度）

| 档 | 机制 | 含义 |
|---|---|---|
| **推荐**（默认正路） | 脚手架模板示范 var()/t()/@linkdesk/ui | 照抄即对，做对成本 ≈ 0 |
| **警告**（偏了亮灯） | lint 15 条全 WARN 级自解释，**永不 fail build / 上传** | 人机都能即时纠偏，可修可绕 |
| **知情绕行**（坚持放行） | 红灯须标准 eslint-disable 声明（`// eslint-disable-next-line <rule> -- 理由`） | 自由保留，代价是「知情」（浏览器危险网站「仍要访问」） |

每档都比前一档「贵」——理性的作者自然滑向正路，靠引导不靠封锁。

### 人机双通道（门禁不是 AI 专用）

门禁是**人机通用的即时反馈环**：
- **大神手写**：红灯自读 → 自己改 或 写 disable 声明绕行
- **AI 火力全开**：红灯 → AI 自动修 或 问作者决策（AskUserQuestion）

规则四硬指标：① 报错自解释（错在哪 + 换成什么 + 为什么——人不看文档能改，AI 照着能修）② 修复建议机械可执行 ③ 绕行统一格式 ④ 豁免区明确。

### 15 条规则清单

**React 通用陷阱 6 条**（非 LinkDesk 专属，任何 React 插件通用）：
- `no-async-init-guard-only`：async init 必须配 `_loadingPromise` 防 StrictMode 竞态。
- `no-effect-callback-without-active-guard`：effect 回调 prop 必须有活跃守卫（`if (!open) return`）。
- `no-dynamic-import-in-effect-cleanup`：cleanup 禁动态 import()（StrictMode 重挂载误删新数据）。
- `no-ref-current-in-jsx`：ref 禁止参与渲染（ref 更新不触发重渲染）。
- `react-hooks/rules-of-hooks` + `react-hooks/exhaustive-deps`：hooks 官方规则。

**视觉统一 5 条**（和软件搭配）：
- `no-hardcoded-zh`：禁 UI 文案中文字面量——推荐 `t()`，i18n 自动成立。
- `check-css-hardcode.mjs` 移植：非 token 颜色字面量 hex/rgb/hsl 全拦——**强化版 no-hardcoded-hex**（eslint hex 正则漏 rgb()/hsl()，插件作者会绕）。覆盖颜色域（含文字颜色——作者 `var(--text-*)` 即自动跟随 fontTone）。
- `check-font-scale-audit.mjs` 移植：font-size/line-height 裸 px 拦——推荐 `var(--font-size-*)` 或 unitless / `calc(*var(--ui-scale))`，跟随全局缩放。**现成脚本直接搬**。
- `no-hardcoded-radius`：禁 border-radius 裸 px——推荐 `var(--radius-*)` / `var(--surface-radius)`，跟随圆角滑杆（**新写**）。
- `import-x/no-unresolved`：模块路径拼错。

**审美 4 条**（有正当例外）：
- `no-quickpick-render-item`：@linkdesk/ui QuickPick 禁 renderItem（视觉统一）。
- `check-spacing-grid.mjs` 移植：padding/margin/gap 4px 节奏。
- `@typescript-eslint/no-explicit-any`：卫生。
- `jscpd`：克隆检测（项目级可选）。

**不设门禁的域（契约文档引导）**：字体族（作者合法自选字体，机械判定必误伤）、玻璃组合形态（3-4 键 + 伪元素结构，机械判定难）、fontTone（壳/主题配置，作者不写，只需 var(--text-*) 跟随其结果）。

**规则载体双轨（审计对齐 2026-08-29）**：check-*.mjs 是**整工程扫描脚本、非 eslint rule**——SDK 的 `npm run lint` = eslint（新规则）+ 跑三个移植脚本两条腿都走（对标壳 check 同款双轨）。「15 条」按**门禁检查项**理解，载体是 rule 或脚本皆可，不硬扭成纯 eslint 插件。

### 知情绕行与市场标签

- **知情声明 = 标准 eslint-disable 格式（审计对齐 2026-08-29）**：`// eslint-disable-next-line <rule> -- 理由` 或文件级 `/* eslint-disable <rule> -- 内容画布 */`。eslint 原生解析 `--` 后为理由，市场偏离收集器直接扫标准注释零自定义；壳 no-hardcoded-hex 现有报错即此格式（eslint-local-rules.js:1022），**非发明新语法**。
- **构建/上传不硬拦**：lint 红灯 + 无声明 = 标记「未处理偏离」；有声明 = 「知情偏离」。
- **市场标签非门禁**：上传不拒收，偏离统计（N 处知情硬编码）随包可见——用户看到偏离标签，作者自由保留。

### 最丰富的保证（E6 总体目标）

门禁只是「最丰富的保证」之一环，让作者无论人机都最高效做对：

| 保证 | 给作者什么 | 时间线支撑 |
|---|---|---|
| 脚手架 | 三分钟可跑的骨架 | 3 分钟无视图 demo / 10 分钟带视图 |
| @linkdesk/ui | 同款控件现成 | 1 小时简单逻辑视图 |
| @linkdesk/contracts | 类型安全 | 半天 UI 复杂逻辑简单 |
| **门禁** | 写错即时发现 + 自解释修复 | 一天逻辑+复杂 UI |
| 文档/清单 | 正确姿势 + AI 火力全开前提 | 一周复杂插件（多插件配合/3D） |

时间线哲学：**用「让做对更便宜」代替「让做错不可能」**——推荐/警告/知情绕行三档构成坡度，理性作者自然滑向正路；React 自由绘图是天然豁免区，自由永远保留，代价只是知情。脚手架模板默认启用（见八）。

## 七、token 契约文档（E6#54d.5）

`docs/03-插件制造/05-UI写法规约.md` 加 **token 契约节**，五块（第三方作者知道有哪些变量才写得出动态 + 内容/数据纪律落点）：

1. **token 目录六域矩阵**——每域列 var() 键 + 作者写法 + 门禁覆盖（作者知道有哪些变量才写得出动态）：

   | 域 | var() 键 | 作者写法 | 门禁覆盖 |
   |---|---|---|---|
   | 颜色 | `--text-primary/--text-secondary/--text-muted`（fontTone 控来源）/ `--bg-*` / `--accent-*` | `color: var(--text-primary)` | no-hardcoded-hex |
   | 表面 | `--surface-*` | `background: var(--surface-*)` | no-hardcoded-hex |
   | 圆角 | `--radius-xs..2xl` / `--surface-radius` | `border-radius: var(--radius-md)` | no-hardcoded-radius |
   | 玻璃 | `--glass-blur/--glass-saturate…` + `--surface-*-solid` | `backdrop-filter: blur(var(--glass-blur))…` | 契约引导（组合形态） |
   | 字号 | `--font-size-2xs..4xl` + `--ui-scale`（app.uiFontScale 缩放轴） | `font-size: var(--font-size-md)` 或 em/rem | check-font-scale-audit.mjs 移植 |
   | 字体族 | `--font-ui` / `--font-mono` | `font-family: var(--font-ui)` | 契约引导（作者合法自选字体） |

   用 var(--*) = 自动跟随主题 + 玻璃 + 全局缩放，零插件感知。
2. **诚实边界/知情绕行语义**——作者硬写死品牌色壳管不住（任何生态都管不住：VS Code 也有不跟随主题的扩展）。门禁把「做对」变默认、「做错」变显式红但可**知情绕行**（`// eslint-disable-next-line <rule> -- 理由` 声明带理由 = 浏览器危险网站「仍要访问」）。豁免类别明确：var() 回退 hex（合规形态）/ 取色器色板 / canvas 绘图 / 引擎区 / **内容画布视图级豁免**。
   **内容 vs chrome 边界（2026-08-29 愤怒的小鸟考核实证）**——游戏 / 数据可视化 / canvas 主区 = **内容世界，不是 UI chrome**：UI chrome 跟主题走（var()/t()/@linkdesk/ui），内容可以有自己的天空。作者可**视图级声明一次豁免**——文件级 `/* eslint-disable no-hardcoded-hex -- 内容画布 */`（审计对齐 2026-08-29：标准注释即批量知情绕行的合法形态，不发明 plugin.json descriptor 标记），门禁对内容区**不逐条亮灯**——一个游戏 5-10 处硬编码颜色（天空/草地/血条红）逐条写 disable 太吵，视图级一次声明搞定。**背景不被玻璃化是机制层天然成立**——backdrop-filter 只刷壳 surface 元素，不套插件视图根节点，作者画蓝天草地本就不被玻璃化。
3. **非 CSS 引擎适配模式**——引擎自渲染（monaco 式）不走 CSS 变量，要跟随主题走翻译桥：订阅 `theme:changed` → 翻译成引擎 theme API（theme-sync.ts 先例）。monaco 当前背景不透明、只二态跟随 = **过渡态绕开，不落死边界**（未来可能彻底适配主题）。
4. **插件私有数据通道**——作者自建设置界面/自管存档（不走壳设置页声明）时，数据落地按语义选（考核第 8 条实证——作者嫌 explorer.xxx/app.xxx 太专业，自建界面）：

   | 通道 | 适用 | 示例 |
   |---|---|---|
   | `linkdesk.pluginState`（**首选**） | 插件自管存档——集中缓存 + 文件持久化（E5#71 正牌 API，`get/set/onChange(pluginId, key)`；api-preference-existing-first 正牌 API 优先，审计补 2026-08-29） | 游戏分数/关卡进度/高分榜/皮肤偏好 |
   | `config.set(key)` 私有命名空间 | 跟设置语义走、可被其他插件/主题读、要进壳设置页 UI | 贡献到 contributes.configuration 即进 UI；不声明则纯私有键照写持久化 |
   | `linkdesk.filesystem` 私有文件 | 大文件/二进制/跨插件共享 | 截图导出/存档文件 |
   | `localStorage` | 补充——池内 WCV 临时缓存（无跨机/无壳管理） | 会话内高频临时值 |

   铁律：**不声明 `contributes.configuration` 的私有键不进壳设置页 UI**——config.set 对无 schema 键照写持久化（仅 enum 才过滤，ConfigurationService.ts:265 实证），作者要壳设置页就声明贡献、要自建界面就私有键直存，两不干扰。
5. **壳纪律转移清单**——非 UI 写法的壳纪律按落点沉对应规范文档：插件独立（唯一入口 window.linkdesk.* 禁 import 壳 → 01-API契约）/ 配置订阅不读一次（linkdesk.configuration 事件驱动）/ linkdesk.events 订阅时序（事件可能先于 mount → 顶层或守卫）/ 不写死其他插件 ID（→03-contributes）/ 配置键必给 default（→06-plugin.json）/ 只用文档化 API 命名空间（→01-API契约）。
