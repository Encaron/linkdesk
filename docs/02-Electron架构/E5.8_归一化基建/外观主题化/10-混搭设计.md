# 10-混搭设计（按域拼装外观——方向定稿，执行排期靠后）

> **状态：** 方向定稿（2026-08-23）——[03 §5](03-域贡献者与混搭.md) 已定「架构可行、排期靠后」；本文把**模型 + 设置页 UI + 复位**钉死，执行仍排期靠后。
> **一句话：** 混搭 = 「配方是整体默认，混搭是按域显式覆盖」——用户对 6 个域各选一个来源，引擎按域合并 token，一键复位回整体配方。

## 1. 模型：域来源映射

```
mixProfile = {
  colors:     "mint-soda",      // 来源 = 配方 id / 配色 id / "followTheme"
  font:       "font-plugin-xi", // 字体插件（只贡献 font 域）
  radius:     "followTheme",    // 跟随整体配方
  glass:      "glass-aurora",
  background: "followTheme",
  surface:    "twilight-forest"
}
```

- **来源粒度 = 配方**（不是「配方+配色」二元组）——选配色仍是整体配方的事；混搭只按**域**换来源。来源带多配色时用该配方默认配色（可后续细化到「配方+配色」二元来源，排期更靠后）。
- 引擎 = [05 §4](05-主题数据模型.md) 合并算法的推广：`:root` → **每个域各自取来源** → 设置层覆盖 → 生效 token。CSS 变量天生适合按域拼（[03 §5](03-域贡献者与混搭.md) 已证）。
- **followTheme 值 = 尊重整体配方**——混搭开启时未设来源的域照常跟当前配方，零心智负担。

## 2. 设置页 UI（详见 mockup「混搭区」）

```
混搭模式 (app.mixMode)      [整体配方 ▾ | 混搭 ▾]      ← 默认整体配方
  ↓ dependsOn 混搭 → 6 行域来源 + 复位：
  颜色     → SelectBox [跟随主题 ▾ | 清凉薄荷包·薄荷苏打 | Glass Aurora | 暮色森林包…]
  字体     → SelectBox [跟随主题 ▾ | 霞鹜文楷 | JetBrains Mono | 系统默认…]
  圆角     → SelectBox [跟随主题 ▾ | Glass Aurora | 暮色森林包…]
  玻璃     → SelectBox [跟随主题 ▾ | Glass Aurora | 清凉薄荷包…]
  背景     → SelectBox [跟随主题 ▾ | Glass Aurora 背景 | 自定义图片…]
  菜单/表面 → SelectBox [跟随主题 ▾ | 暮色森林包…]
  [⟲ 全部复位为整体配方]                    ← 一键复位（心智负担兜底）
```

- **来源 SelectBox 的选项 = 动态**：`linkdesk.theme.listRecipes()` 按 `RecipeMeta.domains` 过滤（该配方贡献哪些域就出现在哪些行，[06](06-主题API契约.md)）——复用配色动态 enum 机制。
- **实时预览**：换来源即重合并 + 广播 `theme:changed`，全窗即看效果（引擎已是纯函数合并，混搭零新机制）。
- **一键复位**：`app.mixMode→recipe` + 6 来源清空 + 命令面同步（[09](09-命令面.md)）。

## 3. 与配方/设置层的关系

| 层 | 粒度 | 覆盖谁 | 默认 |
|:--|:--|:--|:--|
| 配方 | 整包 | 全部域 | 选中即整体生效 |
| 设置层覆盖（appearanceMode） | 个别 token（scale/绝对） | 配方 | followTheme |
| **混搭（mixMode）** | **域** | 配方 | 整体配方（followTheme 全域） |

- 三层叠加顺序：混搭按域换来源 **→** 设置层 scale/绝对覆盖 **→** 生效。混搭是「配方层面」的拼装，设置层是「用户微调」——混搭晚于配方、先于用户覆盖。
- 心智模型（用户原话）：既想要主题 A 的菜单样式，又想要主题 B 的玻璃——混搭就是给「每个域选谁说了算」。

## 4. 边界（不做清单）

- 不做**像素级**混搭（如「只取 A 的颜色里的 accent」）——域是粒度下限。
- 不把混搭做成独立「主题类型」——它是设置状态，不是主题文件格式（[05](05-主题数据模型.md) 不因混搭加字段）。
- 不做配色级来源（见 §1）——排期更靠后。

## 6. 待拍板点

1. 来源粒度 = 配方（非「配方+配色」）——提案接受，配色级来源排期更靠后。
2. 混搭区 UI 是否与主题区同一组（同一「主题」配置贡献下）——提案是（05 组归属拍板后随它）。
3. 复位按钮 vs 复位置灰逻辑：提案**有域非 followTheme 时按钮才可用**（全 followTheme 置灰，减少噪音）。
