1. **关闭 `electron:dev`。** 运行的 electron.exe / node.exe 会锁住 `plugins/` 下的文件，`git mv` 会 Permission denied。
2. **`git status` 干净。** 每一步一个 commit，出了问题好回滚。
3. **每步执行顺序不变。** #86a → #86b → #86c → #86d → #86e，不可颠倒——Electron 侧改完后前端才能正确加载。

## #86c：Electron 侧 `plugin-file-service.ts`（~30 行代码）

### 做什么

加 `_findPluginDir()` 查找函数，所有路径解析走它。

### 具体操作

#### 1. 加 `_findPluginDir()` 方法

```typescript
/** 查找插件所在的子目录——"builtin" | "user" | null */
private _findPluginDir(pluginId: string): string | null {
  const dir = this.pluginsDir();
  for (const sub of ['builtin', 'user']) {
    if (existsSync(path.join(dir, sub, pluginId))) return sub;
  }
  return null;
}
```

#### 2. 改 `listPluginDirs()`——扫两个子目录

```typescript
// 旧：const entries = await fs.readdir(dir, { withFileTypes: true });
// 新：
const names: string[] = [];
for (const sub of ['builtin', 'user']) {
  const subDir = path.join(dir, sub);
  if (!existsSync(subDir)) continue;
  const entries = await fs.readdir(subDir, { withFileTypes: true });
  for (const entry of entries) {
    if (!entry.isDirectory()) continue;
    if (entry.name.startsWith('.')) continue;
    if (existsSync(path.join(subDir, entry.name, 'plugin.json'))) {
      names.push(entry.name);
    }
  }
}
```

#### 3. 改 `installPlugin()`——装到 `user/` + 安装消毒

```typescript
// 旧：const destDir = path.join(this.pluginsDir(), name);
// 新：const destDir = path.join(this.pluginsDir(), 'user', name);

// 安装后强制消毒——在 copyDir 之后、return 之前加：
const destManifestPath = path.join(destDir, 'plugin.json');
const manifest = JSON.parse(await fs.readFile(destManifestPath, 'utf-8'));
manifest.distribution = 'user';
manifest.core = false;
await fs.writeFile(destManifestPath, JSON.stringify(manifest, null, 2), 'utf-8');
```

#### 4. 改 `uninstallPlugin()`——用 `_findPluginDir` 定位源

```typescript
// 旧：const src = path.join(dir, pluginId);
// 新：
const subdir = this._findPluginDir(pluginId);
if (!subdir) throw new Error(`插件 "${pluginId}" 不存在`);
const src = path.join(dir, subdir, pluginId);
```

`.disabled/` 保持不变——仍在 `plugins/` 根下：
```typescript
const dest = path.join(dir, '.disabled', pluginId);  // 不变
```

#### 5. 改 `reinstallPlugin()`——恢复到 `user/`

```typescript
// 旧：const dest = path.join(dir, pluginId);
// 新：const dest = path.join(dir, 'user', pluginId);
```

**Why `user/` 而不是 `builtin/`：** 重装的插件变为用户管理——即使原来是 builtin，用户主动重装后归 user 管。

#### 6. 改 `readManifest()`——用 `_findPluginDir`

```typescript
// 旧：const manifestPath = path.join(this.pluginsDir(), pluginId, 'plugin.json');
// 新：
const subdir = this._findPluginDir(pluginId);
const manifestPath = subdir
  ? path.join(this.pluginsDir(), subdir, pluginId, 'plugin.json')
  : path.join(this.pluginsDir(), pluginId, 'plugin.json');  // 兜底：直接查根
```

`.disabled/` fallback 保持不变。

#### 7. 改 `resolvePath()`——用 `_findPluginDir`

```typescript
// 旧：const p = path.join(this.pluginsDir(), pluginId);
// 新：
const subdir = this._findPluginDir(pluginId);
const p = subdir
  ? path.join(this.pluginsDir(), subdir, pluginId)
  : path.join(this.pluginsDir(), pluginId);  // 兜底
return p.replace(/\\/g, '/');
```

### 验证

```bash
npm run check   # tsc + ESLint + vitest 全过
npx eslint electron/services/plugin-file-service.ts   # 零错误
```

### 注意事项

- **`.disabled/` 不拆分 builtin/user。** 已卸载插件全进 `plugins/.disabled/<id>/`，简单。
- **`isCorePlugin()` 不改。** 它接收的是已解析的路径（调用前 `_findPluginDir` 已确定子目录），内部读取 plugin.json 不受影响。
- **卸载前检查 core。** `isCorePlugin(src)` 中 `src` 已指向正确子目录 → 核心插件仍不可卸载。
- **卸载教训（`uninstall-bug-recurring`）。** cp+rm 不用 rename，错误不能静默吞掉——现有代码已遵守。

## #86e1：glob 模式——`loader.ts` + `plugin-shell-main.tsx`（~25 行代码）

### 做什么
8 个 `import.meta.glob`（7 在 loader.ts + 1 在 plugin-shell-main.tsx）每个拆为 builtin + user 两份。

### 具体操作

以 `pluginModules` 为例（其他 6 个同理）：

```typescript
// 旧：
const pluginModules = {
  ...import.meta.glob("../../plugins/*/index.tsx", { eager: false }),
  ...import.meta.glob("../../plugins/*/src/index.tsx", { eager: false }),
};

// 新：
const pluginModules = {
  ...import.meta.glob("../../plugins/builtin/*/index.tsx", { eager: false }),
  ...import.meta.glob("../../plugins/builtin/*/src/index.tsx", { eager: false }),
  ...import.meta.glob("../../plugins/user/*/index.tsx", { eager: false }),
  ...import.meta.glob("../../plugins/user/*/src/index.tsx", { eager: false }),
};
```

**要改的 7 个 glob 变量：**
- `pluginModules`（2 个 glob → 4 个）
- `pluginSidebarModules`（2 个 → 4 个）
- `pluginStatusBarModules`（2 个 → 4 个）
- `pluginManifests`（1 个 → 2 个，**保持 `eager: true`**）

#### 8. `plugin-shell-main.tsx`——插件 WebView 自举入口

```typescript
// 旧：
const pluginModules = import.meta.glob("../plugins/*/src/index.tsx");

// 新：
const pluginModules = {
  ...import.meta.glob("../plugins/builtin/*/src/index.tsx"),
  ...import.meta.glob("../plugins/user/*/src/index.tsx"),
};
```

**⚠️ 关键：** 这个文件是每个插件独立 WebView 的入口（E3f #58b）。glob 不匹配 → 所有插件 WebView 白屏显示"未找到插件"。


## #86e2：extractPluginId + fetchPluginDataFile + plugin-shell-main modulePath（~25 行代码）

### 做什么
1. `loader.ts`：`extractPluginId()` 跳过 "builtin" / "user" 段
2. `loader.ts`：`fetchPluginDataFile()` dev URL 试两个子目录
3. `plugin-shell-main.tsx`：`modulePath` 构造适配两个子目录

### 具体操作

#### 1. `extractPluginId()`——跳过中间段

```typescript
// 旧：
function extractPluginId(path: string): string {
  const parts = path.split("/");
  const idx = parts.indexOf("plugins");
  return idx >= 0 && idx + 1 < parts.length ? parts[idx + 1] : parts[parts.length - 2];
}

// 新：
function extractPluginId(path: string): string {
  const parts = path.split("/");
  const idx = parts.indexOf("plugins");
  if (idx < 0) return parts[parts.length - 2];
  // plugins 后面是 "builtin" 或 "user" → 再跳一段才是 pluginId
  const next = parts[idx + 1];
  if (next === "builtin" || next === "user") {
    return idx + 2 < parts.length ? parts[idx + 2] : parts[parts.length - 2];
  }
  return idx + 1 < parts.length ? parts[idx + 1] : parts[parts.length - 2];
}
```

#### 3. `fetchPluginDataFile()`——dev URL 试两子目录

```typescript
// 旧：
const url = import.meta.env.DEV
  ? `http://localhost:1420/plugins/${pluginId}/${filePath}`
  : `linkdesk://${pluginId}/${filePath}`;

// 新：
let url: string;
if (import.meta.env.DEV) {
  // dev 模式：先试 builtin 再试 user
  url = `http://localhost:1420/plugins/builtin/${pluginId}/${filePath}`;
  // fetch 后如果 404 → 试 user
} else {
  url = `linkdesk://${pluginId}/${filePath}`;  // protocol.ts 自动处理
}
```

**注意：** dev 模式下需要处理 404 回退。可以先用 `fetch` 试 `builtin/`，404 再试 `user/`。或者加一个辅助函数 `fetchWithFallback(pluginId, filePath)`。

**简化方案（推荐）：** `fetchPluginDataFile` 先试 `builtin/` 再试 `user/`：

```typescript
async function fetchPluginDataFile(pluginId: string, filePath: string): Promise<Record<string, unknown> | null> {
  try {
    const subdirs = import.meta.env.DEV ? ['builtin', 'user'] : [''];
    for (const sub of subdirs) {
      const url = import.meta.env.DEV
        ? `http://localhost:1420/plugins/${sub}/${pluginId}/${filePath}`
        : `linkdesk://${pluginId}/${filePath}`;
      const response = await fetch(url);
      if (response.ok) return response.json();
    }
    return null;
  } catch { return null; }
}
```

#### 3. `plugin-shell-main.tsx`——`modulePath` 适配两个子目录

```typescript
// 旧：
const modulePath = `../plugins/${pluginId}/src/index.tsx`;
const loader = pluginModules[modulePath];

// 新：遍历 glob keys 查找匹配的路径
let modulePath: string | undefined;
for (const path of Object.keys(pluginModules)) {
  if (path.includes(`/${pluginId}/`)) {
    modulePath = path;
    break;
  }
}
const loader = modulePath ? pluginModules[modulePath] : undefined;
```

**Why 不用字符串拼接：** `../plugins/${pluginId}/src/index.tsx` 不知道在 `builtin/` 还是 `user/`。遍历 glob keys 用 `includes` 匹配。

### 验证

```bash
npm run check                    # tsc + ESLint + vitest 全过
npm run dev                      # 纯前端能启动、所有插件正常加载
npm run electron:dev             # Electron 下所有插件 WebView 正常渲染（不是白屏）
```

### 注意事项

- glob 中 `eager: true` 只用于 `pluginManifests`——其他保持 `eager: false`
- `extractPluginId` 的兜底逻辑保留——兼容非标准路径
- `fetchPluginDataFile` 的 prod 模式走 `linkdesk://`——`protocol.ts` 在 #86d 已处理
- `plugin-shell-main.tsx` 的 `includes` 匹配可能误匹配（如 `my-settings` 匹配到 `settings` 路径段）——但目前 9 个插件 ID 都是单一名词，无此问题。未来加新插件时注意 ID 不要互相包含
