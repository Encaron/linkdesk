# E5.8-zone 显隐勾选菜单档案（#148）

> 2026-08-27。用户需求演化：① 想把「面板」「主侧栏」显隐做成**勾选 toggle**（显示→✓，点击→隐藏→去勾，右键菜单「面板位置/对齐」单选 ✓ 同款机制）→ ② 顶栏下拉不显示勾 → 补序列化链路 → ③ 提出**嵌套子菜单**「查看→外观→(面板, 主侧栏)」（汉堡可能要三层）→ ④ 拍板：子菜单名 **「界面」**（避开 LinkDesk「外观」=主题域语义撞车）+ **移除**「面板」菜单的「打开面板」招牌（VS Code 向——无「面板」顶级菜单，Ctrl+J + View→Appearance→Panel 模式）。
> **核心结论**：顶栏下拉两层嵌套现成支持；**汉堡三层不支持**——ContextMenu 子面板单层平铺（数据层 children 抹平 + 渲染层无递归），**#148 核心实现 = ContextMenu 子菜单递归**。勾选态序列化 = 顶栏下拉另一缺口（PoolMenuItem 无 checked）。
> 清单指针：E5.8-执行清单 Phase 11.22 #148。

## 二、8 维度设计前置

> 任务性质：**壳能力升级**（ContextMenu 子菜单递归 + 菜单勾选序列化）+ 菜单结构改造。用户已拍板方向（界面子菜单 / 移除打开面板）。

### ① 能力边界
- **壳能力**。保底：无插件时 查看→界面→(面板✓, 主侧栏✓) 照常工作（壳命令 togglePanel/toggleSidebarVisibility 都无插件可空转——面板无贡献无可见效果，命令安全 no-op 现状）。
- ContextMenu 递归子菜单 = 共享组件能力升级——插件 `contributes.menus` 深层嵌套自动受益（通用优先）。

### ② API 设计
- **零新增 `window.linkdesk.*`**。命令全复用：`togglePanel`（已存在）+ `toggleSidebarVisibility`（已存在）。
- `PoolMenuItem.checked?: boolean` = 池 DTO 字段（菜单栏序列化契约，非插件 API）。
- ContextMenu `MenuItemDescriptor` 已有 `checked`（[ContextMenu.tsx:75](../../../../src/components/shared/context-menu/ContextMenu.tsx#L75)）——只缺序列化透传，零契约新增。

### ③ 通信方式
- **零新 IPC**。点击 → 既有命令 → 既有事件链（`panel:toggle` / `sidebar:toggle` → App host）。
- checked 数据流：壳侧 `buildTitleBarMenuGroups` 序列化时按命令 ID 动态算（`panelVisible`/`isSidebarVisible`——usePoolSync 主推送 deps 已含，显隐变化重推重算）→ `PoolMenuItem.checked` → `poolMenuToDescriptors` → ContextMenu ✓。对标 `resolvePanelChecked` 先例（[panelCommands.ts:49-55](../../../../src/core/commands/shell/panelCommands.ts#L49-L55)）。

### ④ 壳侧代码设计
- 改动文件（零新文件）：
  - `ContextMenu.tsx` — **子菜单递归**：数据层 `ResolvedItem.children` 递归保留 + 渲染层递归子面板（subData 链或渲染树）+ 键盘/Enter/方向、Escape 逐级收、mousedown contains 守卫、定位翻转钳制全级覆盖。
  - `poolLayout.ts` — `PoolMenuItem.checked?: boolean`。
  - `usePoolSync/titlebar.ts` — `resolveItemNode` 序列化 checked（command → 显隐谓词解析，传 zone 显隐上下文）；`buildTitleBarMenuGroups`/`buildHamburgerMenuGroups` 增参。
  - `pool/shared/menu-items.ts` — `toDescriptor` 透传 checked（顶栏 + 汉堡两路径共用）。
  - `shellMenus.ts` — 查看 menu 加「界面」子菜单（无 command 父项 + children：`面板`=togglePanel、`主侧栏`=toggleSidebarVisibility，group "view" 靠近移动到左/右）。
  - `panelCommands.ts` — **移除「面板」菜单招牌「打开面板」**（父项「面板」保留下 or 删——菜单留插件贡献，组标签由插件项兜底，实现时按 flattenGroupItems 语义定）。
- **单一权威**：勾选态 = 壳真相源（面板 `panelVisible` / 侧栏 zone 宽 ≤48 派生 `isSidebarVisible`）。序列化一处解析，ContextMenu 哑渲染。
- **硬约束合规**：label 走 t()；零新命令 ID 硬编码；无颜色/路径改动。

### ⑤ 插件侧代码设计
- **零改动，零贡献点**。`contributes.menus` 深层嵌套子菜单由 ContextMenu 递归自动支持（通用能力，非插件契约变化）。

### ⑥ 显示设计
- **位置**：顶栏「查看」→「界面」子菜单（(面板✓, 主侧栏✓)）；汉堡 ☰→查看→界面 三层。
- **控件**：ContextMenu 嵌套子菜单（既存组件，递归升级）。
- **视觉**：勾选 ✓ = 对应 zone 当前可见（checked 显隐随推送刷新）。
- 与 #147 交叉：主侧栏菜单入口从「面板」菜单挪到「界面」子菜单——#147 复用已存在命令 + 落位 #148 结构。

### ⑦ 配置设计
- **零新增配置项**。勾选 = 运行时状态（非配置）；显隐持久化沿用现状（panelVisible 落盘 layout.json / sidebar zone 宽持久化）。

### ⑧ 代码规范 + 验收
- 归一化：checked 解析一处（resolveItemNode 内，command→谓词映射）；ContextMenu 递归一处实现全消费者受益。
- 无死代码：移除打开面板后无残留引用；删单层子面板遗留逻辑。
- **验收**：
  1. `npm run check` 全绿（含 #145 机械门禁）。
  2. 单测：titlebar.test.ts 补「界面子菜单序列化 + checked 勾选态」断言 + 移除打开面板断言；ContextMenu 递归渲染测试（孙级 children 渲染 + 点击执行）。
  3. **CDP 实机**：顶栏 查看→界面→(面板✓, 主侧栏✓) 勾选态正确 + 点击 toggle 显隐 + 勾选随状态刷新；汉堡三层（☰→查看→界面→面板/主侧栏）；移除打开面板后「面板」菜单只剩插件贡献（或消失）；面板/侧栏显隐 + 折叠交互零回归（与 #146/#147 交叉）。
