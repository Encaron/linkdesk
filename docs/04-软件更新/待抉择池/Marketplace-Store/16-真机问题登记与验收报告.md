### F1 · 无作者第三方条目的作者行显示「官方」 🟡 P2
- **是什么**：目录条目未声明 `author`/`authorId` 时，卡面作者行显示「官方」。
- **发生了什么**：真机截图 02/04/05——「Bulk 件 0」「旧目录件A」等第三方件名下是「官方」；而 hover 展开层的来源徽标正确显示「社区」（同一条目两处口径相反）。
- **为什么**：作者行文案的缺省回落落到了「官方」字样（疑在 `catalogText`/`cardParts` 的作者行取字链），与来源徽标判定链（`entry.official`/vendorId）不同源——两条尺。
- **怎么修**：作者行回落改走来源语义（来源名或「社区」），与 `sourceBadge` 同一判定源，⛔ 第二把尺；同类回落全仓自查。
- **修后预期**：无作者第三方件名下显示来源名或「社区」；官方件才显示「官方」。
- **纪律核对**：归一化 ✓（单一判定源）· 无硬编码 ✓（走 t()）· AI 友好 ✓ · 无平铺 ✓（改现有取字函数不新增文件）。

### F2 · 订阅件卡面价格徽标显示「买断」 🟡 P2
- **发生了什么**：真机截图 02——`pricing.type:"subscription"` 的条目卡面徽标写「买断 CNY12」。
- **为什么**：价格徽标只按金额渲染，未按 `pricing.type` 分支文案（08 v3.64c 正典：「买断/订阅/剩 N 天/许可过期」）。
- **怎么修**：priceTag 按 `pricing.type` 分支（subscription→「订阅 ¥N/月」或词典既有键），与详情付费说明行（已正确显示「订阅制」语义）同源。
- **修后预期**：卡面徽标与详情说明行语义一致。
- **纪律核对**：同上（改现有 descriptor 分支，不新增实现）。

### F3 · openStore 裸 type 当插件 id——商店命令/侧栏钮在真机打不开 🔴 已修（本棒）
- **发生了什么**：真机点侧栏「进入 Plugin Store」或执行 `marketplace.openStore` → 主区画「插件 "marketplace-store" 不可用」；jsdom/宿主测试全绿——声明面↔运行时缝。

- **怎么修**：`marketplaceCommands.openStoreTab` 补 `{pluginId: OWNER, label: i18n.t("插件商店")}`（词典既有键零新增）；tabId 回执从「等 `tab:activated` 的 pluginId===type」改为按 `pluginId===OWNER` 匹配（带 opts 后 tab.pluginId=marketplace；序列化 DTO 无 type 字段，`tabs.list` 认领路不通；详情标签 DTO pluginId 恒 "plugin-detail" 天然区分）。测试同笔钉新契约。
- **修后预期**：真机命令/侧栏钮/入口别名三条路都开店（本棒已复验：store:true · rail 12 项 · 标签「插件商店」）。
- **纪律核对**：✅ 全过（改唯一入口函数＋注释写为什么；无第二实现）。
- **回执边界**：真机「新建」路径壳不发 `tab:activated` ⇒ 命令回执 `tabId` 可能空串（09 `{ok, tabId}` 的 tabId 本就 best-effort，`openPlugin` 先例同款）——已写进命令头注。
