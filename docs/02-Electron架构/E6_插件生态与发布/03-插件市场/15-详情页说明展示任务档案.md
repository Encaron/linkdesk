## 〇、一句话总览（大白话）

插件详情页里那个「说明」区，现在只能显示纯文字——作者放进去的图（封面、截图、演示动图）读者**一张都看不到**。用户要它变成跟 VS Code 插件主页一样：作者想放一张把全部款式拼起来的大图就放，想按每个功能配一张演示动图就放，想放「封面+▶点开播视频」就放，甚至想放直接在页里播的视频就放——**读者不用安装、不用下载任何文件，打开说明就能亲眼看到这插件长什么样、怎么用**。静态图、动图、视频，人家 VS Code 全都有，作者自由组合；我们也要全都能放，**不许问用户「你要图还是动图还是视频」**——那是拿二选一问本来全都要的事（2026-09-09 用户斥责原话）。

## 三、🔬 现状事实（为什么现在一张图都显示不出来）

已读代码实证（2026-09-09）：

1. **说明区渲染器** = 共享组件 [MarkdownView](../../../src/components/shared/markdown-view/MarkdownView.tsx)（react-markdown + remark-gfm + rehype-raw + rehype-sanitize）。img 渲染走 `isSafeImage(src)`——只放行 `https://` 开头 + 相对路径两种。
2. **相对路径图不解析到「被查看插件的包」**：说明文本由市场详情页读**被查看插件的 README**（`readInstalledPackageFile(id, "README.md")`）后丢给 MarkdownView 渲染；MarkdownView 没有「这张图相对哪个插件」的基址概念 → `resources/cover.svg` 这类相对路径会被当成**市场插件自己页面**下的地址去找 → 市场插件没有这文件 → **裂图/空位**。远程 `https://` 图理论上能显示（未放行也会被 rehype-sanitize 按白名单处理），但作者普遍用包内相对路径 → 全裂。
3. **README 引用的资产不在随包 zip**：SDK 打包器只随包拷「声明为 icon/marketIcon 的资产 + README + bundles + LSP runtime」；cover.svg 自 #69 从 marketIcon 撤下（改指 Type-2 图标）后不再声明 → **不进 zip**。即已装插件包里没有 README 引用到的 cover.svg（源仓库有、安装包没有）。
4. **#69b 现状**：8 只 README 顶部嵌了封面（editor `cover.svg` 根位 / 余 7 只 `resources/cover.svg`）——只在**源仓库/GitHub** 能显示；软件内详情页说明区裂图。hello 独立仓同理。

> 结论：#69b 的「嵌」是字面完成（文件确实嵌了引用、资产确实留在 resources/），但「软件里打开就能看见」这层**没接通**——差的就是 #70 要补的「渲染器能真正把作者放的媒体显示出来」。

## 四、🎯 目标与拆分草案（实现轮，待用户点名开工时细化）

**目标**：详情页说明区 = VS Code 同级开放展示画布。作者在 README 里放的五形态媒体（静态大图 / 演示动图 / 整体 demo / 封面外链视频 / 页内视频）全部原样显示；**远程 https 与「被查看插件自己的包内资源」两种图源都能解析**；读者打开说明即见，零下载零跳转（外链视频点开跳外部 = 作者选择，读者点不点是另一回事）。

**拆分草案（E6#70a-#70e，子任务行 = 未开工·点名后按 design-flow 细化再锁定义）**：

- **70a · 静态图显示打通（核心缺口）**：MarkdownView 增「资源基址解析」——说明渲染时知道「当前在被查看插件 X 的 README」→ README 里相对路径图（`./resources/cover.svg`、`resources/icon.svg`…）解析到 **X 自己的包内资源**（`linkdesk://{X}/{路径}` 或等价面），`![]()` markdown 图与内嵌 `<img src>` 一视同仁；已装与未装（目录源）两种态各走对的路。配套：SDK packager 把 README 引用的资产一并随包（规则设计：声明引用 vs 自动收集，见 §五 待定点）。
- **70b · 动图 gif 支持**：与静态图同一链路（img 即 gif），验证 gif 在说明区真会动即可，不单列实现。
- **70c · 封面外链视频（<a>包<img>）**：GitLens 式 `<a href="外链视频"><img src="封面"></a>` 在说明区透传为可点击封面（点击按作者 href 外开——App 内如何处理外链打开见 §五 安全/行为待定点）。
- **70d · 页内视频（<video>/mp4）**：VS Code 更新页式 `<video src="…mp4" controls …>` 在说明区显示可播。视频文件源（远程 https vs 随包资源）+ 体积现实 + 播放行为（autoplay 默认禁、reduced-motion）+ 安全裁决见 §五。
- **70e · 文档与生态**：[06-图标.md](06-图标.md) 或本档案补「第三方作者最小契约」——作者放 README 媒体（相对路径放包内 / 远程 URL / 视频外链 / mp4）的写法规约；随包规则文档化（memory `stale-sdk-built-plugin-zip`：动 SDK build 配置必重建已提交 zip）。涉及软件侧用户可见 → version-bump 判定（0.x 向后兼容 patch 向）。

**当前 8 只 README 封面是首批受益样本**（editor/file-tree/serial-monitor/settings/python/theme-terminal/theme-aurora-glass/lang-defaults + hello）——70a 接通后它们在软件说明区即显形；不必等全部封面铺完。

## 五、⚠️ 设计待定点（开工前 design-flow + html-blueprint mockup 逐条定，别默认）

1. **资源基址语义**：说明文本是被读出来的纯文本，渲染器如何知道「当前属于哪个插件」？详情页渲染处注入插件来源（已装 id / 目录 entry）→ MarkdownView 收一个可选 `assetBase`/`resolveAsset` 参数（不写死任何插件，纯数据注入，硬约束 10/共享组件零插件名）。壳其他 markdown 消费点（发行说明、未来 main-area store）同组件同能力，基址由各自调用方给。
2. **未装态（目录源）图从哪来**：未安装插件 README 里的包内图 = 下载前没有本地副本 → 图源解析到「该插件 catalog 声明/远程资产」还是「未装态不显图只显文」？需要与 downloadUrl/zip 结构对齐（作者包内 README 引用图 → zip 里图与 README 同目录，未装时可暂不显示图、装后才全显，是最省事又诚实的第一版）。
3. **随包资产规则**：SDK packager 自动带 README 引用的资产（扫描 README 里的相对路径 → 收集随包）vs 作者声明（如把封面挪回声明字段）。自动扫描最贴合作者零心智，但要防 glob/路径逃逸与体积失控；两案取舍 design-flow 定。
4. **远程媒体安全/信任模型**：允许加载作者声明的远程 https 图/视频 = 扩展信任边界（数据面：说明区从纯文本 → 会拉外部网络）。先守：仅 `https://`、禁 `file://`/`data:` 大余量、`loading=lazy`、禁脚本；`<a href>` 外链视频点击行为 = 壳内新窗 vs 外部浏览器（对标 VS Code「在浏览器打开」/ 壳外链处理既有面）；mp4 体积/带宽现实。这条是安全加固层（E6#48-#52）同类问题，设计时对照 [08-信任与安全.md](08-信任与安全.md)。
5. **rehype-sanitize 白名单**：现渲染允许哪些 img/属性？`<video>`/`<source>`/`controls`/`poster`/`autoplay`（autoplay 默认禁）要进白名单才有 70d；rehype-raw + sanitize 顺序确认不放大 XSS 面。样式（说明区图宽/视频宽/排版）走 ui-ux-pro-max + 壳 token，零硬编码。
6. **验收基准**：对照本档案 §二 五形态，取现成样本 README（如 theme-terminal 的 cover.svg、某远程 gif、GitLens 式外链封面、一个 `<video>` mp4）在 app 内说明区逐一显示验证。
