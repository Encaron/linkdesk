## 一、项目概况

V3 是 V2 的重架构——保持 V2 全部功能，底盘从 WPF .NET 8 换成 Tauri + React。

| | V2 | V3 |
|------|------|------|
| 框架 | WPF .NET 8 | Tauri v2 + React 18 + TypeScript |
| 接收区 | AvalonEdit | CodeMirror 6 |
| 发送栏 | 多行 TextBox | Monaco Editor 单行 |
| 主题 | DynamicResource | CSS 变量 21 色 |
| 双语 | 自研 T() 函数 | react-i18next `t()` |
| 串口 | C# SerialPort | Rust serialport + tokio |
| 协议 | `[type, subType, ...]` | `[卡片ID, 字段...]` |

### Rust 串口层

| 命令 | 功能 |
|------|------|
| `list_ports` | 枚举 COM 口 |
| `open_port` | 打开 + 启动 tokio 读线程 |
| `close_port` | 关闭 + 冲刷残留 |
| `send_data` | 发送字节 |
| `set_dtr` / `set_rts` | 硬件流控 |
| 读线程 | 100ms 超时 → `\n` 拆行 → emit `serial-data` |

### 数据管道

```
STM32 → Rust serialport 读线程 → emit("serial-data")
→ React listen → RingBuffer.write() → rAF drainAll()
→ CM6 appendLine(三色) → 暂停/搜索/导出/裁剪
```

### Phase 3 关键架构决策

| 决策 | 说明 |
|------|------|
| **图标栏只聚焦不循环不创建** | 📟/⚙ 隐式创建，📊 不创建（tooltip 引导）。点击行为可预测，不依赖 tabs[] 顺序 |
| **CSS display 切换 keep-alive** | 所有标签页同时挂载，`display:none/flex` 控制显隐。CM6 + Monaco 状态不丢 |
| **独立 RingBuffer** | 每个标签页各自调用 `useTauriEvent`。Phase 3 预期 ≤5 标签页，无需 Pub/Sub |
| **递归分屏（SplitNode 树）** | 对标 VS Code 自由布局——支持 3-pane、2x2、左上下+右单等任意嵌套。数据模型 `SplitNode = leaf \| branch`，绝对定位平铺渲染——所有面板平级兄弟，树只算尺寸，分屏/合屏不 unmount 面板 |
| **drop zone 照抄 VS Code** | `SPLIT_THRESHOLD=0.25` + 左右优先顺序（`editorGroupView.ts onDragOver`） |
| **毛玻璃面板内定位** | rect-based 面板命中（不依赖 elementFromPoint），CSS 50%半边/100%满面板，absolute 在 `.tab-group-pane` 内 |
| **中央放手=合并** | 对标 VS Code center zone → moveTab |
| **Phase 3→4 硬约束** | 标签页系统永远不持有/访问/导入 `CardRegistry`。唯一接触点 = `Tab.workspaceName: string` |
| **SplitPane 纯 CSS flexbox 递归** | 零外部依赖。leaf→renderGroup，branch→flex 容器+两个递归子+独立分割条 |

## 六、V3 踩坑记录

见记忆系统 `v3-pitfalls.md`。

Phase 3 新踩坑（前期，Phase 3 v4）：
- **B4 布局塌陷**：`.app-shell` 用 3 行 grid，TabBar 作为第 2 子元素抢了 `1fr` 行，`.app-body` 被挤到底部。修法：TabBar 移入 `.editor-area`
- **B5 右键活跃标签页分屏无反应**：`reduceSplitTab` 在 `tabId === activeTabId` 时拒绝分屏。修法：自动找下一个标签页配对
- **B6 SplitPane resize 性能**：`localSizes` 在 useEffect deps 中导致每像素重注册。修法：用 ref 读取最新值

Phase 3.x 递归分屏踩坑（2026-07-19 同日实施）：
- **B13** 单 tab 组分屏变空面板 → solo-tab split 阻止
- **B14** 3-pane 第三方画面板不渲染 → SplitPane 递归化
- **B15** 毛玻璃越界/不区分中央 → rect-based 面板命中 + center zone=移动
- **B16** drop zone 与 VS Code 不一致 → 照抄 SPLIT_THRESHOLD=0.25
- **B17** 面板内容坍缩 → child div 加 display:flex
- **B18** 跨标签栏移动失效回归 → findOtherContainer 改 boolean
- **B19** inline style 覆盖 CSS 毛玻璃定位 → 去 inline 尺寸
- **B20** 分裂源组而非目标面板 → reduceSplitTabAt 目标定位
- **B21** 毛玻璃指示左侧切分松手落右侧 → newLeafSide 参数控制子节点顺序
- **B22** 分屏/合屏导致终端数据丢失 → 递归 DOM 嵌套导致 React unmount CM6 → 改为绝对定位平铺（面板层）。**但 tab pane 层未平铺，同根 B33 潜伏到 Phase 4。**

**核心教训：不要自创算法，照抄 VS Code。** 自创 closest-edge+50% → bug，照抄 SPLIT_THRESHOLD=0.25 → 零问题。

Phase 4 踩坑（2026-07-20，B27-B35）：
- **B27** 图标栏只有终端图标
- **B28** 终端缺串口控件
