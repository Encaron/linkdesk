## 一、#141 分屏 1↔2 面板渲染模式切换 → pane 子树整 remount（设置页分组跳回通用）

### 现象

设置页在「主题」分组下 → 进行分屏操作（splitDown / splitRight）→ 光标（左侧导航 active 高亮）和界面（右侧表单内容）自动跳到第一个「通用」组。

### ① 原因（根因 file:line + 机制）

**MainZone 双渲染分支，1↔2 面板切换时 React 整棵 pane 子树 remount**，设置页 `selectedGroup` 局部 state 丢失 → fallback 到第一个组。

- **双分支**：[MainZone.tsx:165-166](MainZone.tsx) `useAbsolute = root && getAllLeafGroupIds(root).length > 1` ——单面板走 flex fallback，多面板走 absolute 平铺。
  - 单面板分支：[MainZone.tsx:264-286](MainZone.tsx) `groups.map((group) => <div key={group.id} style={{flex:1,...}}>)` ——`.main-zone` 首子 = `div[key=groupId]`。
  - 多面板分支：[MainZone.tsx:186-261](MainZone.tsx) `<>` Fragment 包裹 `layout.panels.map((p) => <div key={p.groupId} style={{position:absolute,...}}>)` + handles ——`.main-zone` 首子 = **Fragment**。
- **机制**：1↔2 切换时 React 在 `.main-zone` 子位 0 看到旧 `div`（flex）→ 新 `Fragment`（absolute）**元素类型不同** → 整个 pane 子树（含 GroupPane → keep-alive tab → ShellViewRenderer/PluginComponent → SettingsView）**unmount + remount**。`key={groupId}` 同级不变只覆盖 2+ 面板间增删，不覆盖 1↔2 分支切换。
- **后果**：[SettingsView.tsx:40](SettingsView.tsx) `selectedGroup` useState 随 remount 重置 `null` → [SettingsView.tsx:210-213](SettingsView.tsx) `activeGroup = find(...) ?? filteredGroups[0] ?? null` fallback 到第一个「通用」组。
- **连带影响（同一根因）**：**任何 tab 本地状态**（Monaco 编辑器、CM6、插件视图内部 state）在 1↔2 分屏时全部重置——B22 防护（[MainZone.tsx:11-14](MainZone.tsx) 注释「分屏/合屏时面板 DOM 深度不变 → React 不 unmount」）存在 1↔2 空洞。

### ② 改法

**主修（根因，低风险）**：[MainZone.tsx:186-261](MainZone.tsx) 多面板分支**去掉 `<>` Fragment 包裹**，panes + handles 直接作为 `.main-zone` 兄弟子元素。两分支首子均为 `div[key=groupId]`（同元素类型 + 同 key）→ React 跨 1↔2 **按 key 复用 pane 子树，零 remount**。保留 `useAbsolute` 守卫（`root` 类型可选，兜底 root 缺失路径）。DragOverlays 位置后移会 remount（纯拖拽视觉浮层，无状态，无害）。

**备选（更彻底，执行时二选一）**：恒走 `layout.panels` 绝对定位单分支（删 flex fallback）。与 B22「所有面板绝对定位平级渲染」对齐，但 `root` 可选类型需先核对恒定义（initial [defaults.ts:121](defaults.ts) 恒设 + 全部 reducer 恒设，仅类型标注可选）→ 核对通过才可落地。

**不做**：SettingsView `selectedGroup` 持久化（band-aid）——只遮设置页症状，remount 空洞（Monaco/CM6 状态丢失）仍在，属治标。

### ③ 可执行性

- `npm run check` 全绿（tsc 双工程 / eslint --max-warnings 0 / vitest / jscpd / pool-css）。
- **CDP 实机复现 + 验收**：打开设置 tab → 选「主题」组 → splitDown/splitRight → 断言左侧 nav active 仍「主题」+ 表单内容仍主题组（非「通用」）；挂 remount 探针（pane 内组件 mount 计数 / `tab.id` key 观察）确认 1↔2 分屏零 remount。
- **连带验证（根因修复额外收益）**：一个编辑器（Monaco）tab 1↔2 分屏后光标/内容/未保存状态保留；2↔3 面板分屏原 B22 行为零回归。

## 二、#142 浮层 z 分层缺口——overlay-root 内容 + toast 低于悬浮面板（下拉在面板后）

### 现象

设置页悬浮面板（ctrl+, 或右键标签栏 →「在悬浮面板中打开」）内点击下拉菜单 → 下拉出现在**悬浮面板后面**（玻璃主题半透明下一眼看出）。影响同类浮层次表面：面板内的下拉/取色器/dropdown-card/通知面板 + toast。

### ① 原因（根因 file:line + 机制）

**浮层权威 #107/#119-#121 建了 `#overlay-root` + `#toast-root` 但未配 z 层**——Z_INDEX 表缺「通用 surface 根」层，overlay-root 内容（z600-650）与 toast（z-auto）低于悬浮面板（1500）。

- **层上下文**：[FloatingLayerHost.tsx:51-57](FloatingLayerHost.tsx) `#ld-float-layer` z2000（Z_INDEX.toast）建 stacking context；其内 sub-roots 自分层。
- **z 实况（全部相对 `#ld-float-layer` 内层）**：
  - `.floating-panel` = **1500**（[FloatingPanelHost.tsx:246](FloatingPanelHost.tsx) inline `Z_INDEX.floatingPanel`）+ backdrop 1499（:234）。
  - `#overlay-root` 无 zIndex（[FloatingLayerHost.tsx:90](FloatingLayerHost.tsx)）→ 内容落自身 z：`.selectbox-dropdown` 650（[SelectBox.css:86](SelectBox.css) `--z-dropdown`）、`.dropdown-card` 650（dropdown-card.css:18）、ColorPicker 600（[ColorPicker.css:13](ColorPicker.css) `--z-overlay`）、notif 600（status-bar CSS:124）——**全 < 1500**。
  - `#toast-root` 无 zIndex（[FloatingLayerHost.tsx:94-96](FloatingLayerHost.tsx)）→ toast z-auto（0）——**< 1500**。
  - context-menu 3000 / quick-pick 4000 / dialog 5000 / tooltip 6000（[constants.ts:17-19](constants.ts)）——**> 1500**，右键/命令面板/对话框在面板内开**正常**（用户猜测「有的面板需要右键…弹窗」实际这两类 OK，坏的是 overlay-root 内容 + toast）。
- **根因归属**：#107 浮层权威把 5 浮层 + 通用 surface 根归位时，`#overlay-root`/`#toast-root` 建根未配 z 层；遗留 `--z-dropdown 650`/`--z-overlay 600` 是 E5#98 时代的裸 z，未随层化迁到 Z_INDEX 常量——浮层权威「自分层」不完整。

### ② 改法

1. **constants.ts**：Z_INDEX 增 `overlayRoot: 2000`（注释：通用 surface 根层——下拉/取色器/dropdown-card/notif，盖悬浮面板 1500、被 context-menu 3000 盖）。
2. **FloatingLayerHost.tsx**：
   - `#overlay-root`（:90）加 `zIndex: Z_INDEX.overlayRoot`——root 建 stacking context，内容 z600/650 被收纳，整 root 以 2000 参与自分层，盖面板 1500。
   - `#toast-root`（:94）加 `zIndex: Z_INDEX.toast`（2000，`position:fixed` 可配 z）——toast 盖面板 + 盖 overlay（DOM 序 toast-root 在 overlay-root 后，同级 2000 → toast 胜）。
   - 结果层序：panel 1500 < overlay 2000 = toast 2000 < context 3000 < quick-pick 4000 < dialog 5000 < tooltip 6000。
3. **不碰** `--z-dropdown`/`--z-overlay` 遗留值（root 已收纳，语义仍是「root 内相对层」）；不碰结构隔离地板（[index.css](index.css) 结构选择器与 z 无关）。

### ③ 可执行性

- `npm run check` 全绿。
- **CDP 实机**：悬浮面板开设置 → 主题组点下拉 → `elementFromPoint`/像素采样确认下拉在面板之上（玻璃半透明可辨）；面板开启时触发 toast → toast 在面板之上；面板内取色器同样盖面板。
- **零回归**：普通窗口（非悬浮面板）下拉/右键/对话框行为不变——overlay-root 只提升层序不改结构，context 3000/dialog 5000 仍盖下拉；`#ld-float-layer` 层基准 2000 不变。
