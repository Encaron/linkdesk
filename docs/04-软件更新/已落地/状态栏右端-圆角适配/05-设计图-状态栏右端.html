状态栏右端三件（语言 / 主题 / 铃铛）—— 圆角模式下为什么显得又大又穿帮

本页是局部图：只画状态栏。现状列是照产品 CSS 一比一复刻的（StatusBarZone.css）——右端三件你可以真 hover：直角半径下一切正常，把半径拖到 8 以上，hover 的方底当场盖出圆角曲线外（玻璃态下角落透着背景图，最刺眼）。

你的原话（2026-10-03）：「状态栏右边的选择语言，选择主题，铃铛是不是有点太大了？是状态栏在圆角模式下太小了吗？为了适配圆角，需要做调整。」

① 现状 —— 形状语言打架：全高方块 × 圆角栏

先把结论说破：状态栏高度没有变小（22px×scale，契约未动）。是三件事叠出了「太大」的读感：按钮吃满栏高（22/22）、hover 是顶天立地的方底（border-radius: 0）、栏四角却按 app.surfaceRadius 全圆了而没有 overflow 裁剪——半径一大，直角方块与圆角曲线打架，右端的铃铛正压在曲线上。

👀 操作指引：hover 右端任意一件（尤其铃铛）→ 方底盖出曲线外；切到自定义·玻璃 → 栏变半透明磨砂、角落透出背景图，穿帮最清楚；拖半径到 32 → 22px 的栏近乎胶囊，右端两枚钮顶进弧里。左区文字条目不受影响（对照）。

③ 三案同台 —— 半径拉满，看谁不崩

判据：半径 0→32 全程，(a) hover 底任何时刻都在圆角内；(b) hover 形状与栏的形状语言一致（圆角栏配药片）；(c) 半径 0 时回到现状零变化。把半径拖到 32、hover 每案右端铃铛现场比。

A 案 · 内缩药片（建议）——按钮 18px＋药片 hover＋padding 让位

⎇ main*⓪ 0 ⚠ 0

按钮 22→18px（栏内上下各留 2px）、hover 变药片、栏 padding: 0 max(8px, var(--surface-radius))（半径 0＝现状零变化）。只动 StatusBarZone.css 一个文件。

C 案 · 右端内舱——三件装进内缩舱
