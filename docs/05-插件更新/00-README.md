## 一、每个插件只更新自己

- **版本号各插件独立**（各自 package.json 的 semver），不占软件版本号；插件补丁档案（如 文件树 `FT#` 清单）就是该插件的进度真相源。
- **开发工作流（2026-09-14 起为现行规矩，E6 第 7 层判据先立）**：插件**源码真相源 = 插件自己的 GitHub 仓库**（`Encaron/linkdesk-plugin-<id>`），壳仓只留构建产物（`bundled-plugins/` 出厂种子快照）与文档档案（判据五条 → [`../03-插件制造/09-插件目录规范.md` §源码位置与分发物的关系](../03-插件制造/09-插件目录规范.md)）。单个插件的新版本在仓外独立工程目录开发（布局 → [../03-插件制造/15-多仓开发与本地工作区.md](../03-插件制造/15-多仓开发与本地工作区.md)），直接装到安装版上实测，不必回本仓库全量构建。每只插件单独建仓、单独写文档；本目录只留「这个插件想往哪更新」的档案，不承担开发目录。
- ✅ **源码物理搬迁已完成（2026-09-14，E6 第 7.2 轮）**：18 只发货插件源码已外移各自独立仓并推送，壳仓 `plugins/` 只剩两只开发夹具（`panel-demo` / `floating-panel-demo`）。**整层已于 2026-09-14 全层封层**（七条判据 ＋ 四本账 ＋ 回归对照 ＋ 作者面三档计时全跑完）——总账与全部实测读数 → [`../02-Electron架构/E6_插件生态与发布/插件源码外移层/08-全层验收.md`](../02-Electron架构/E6_插件生态与发布/插件源码外移层/08-全层验收.md)。
- **出厂随包只装 6 只基础插件**（设置 / 插件市场 / 语言 / 基础主题 / 文件树 / 编辑器；判据 =「断网、零插件时用户能不能自救」）。**其余（含串口监视器、Python、各主题）走市场按需安装**——都在官方目录里，卸了随时装得回来。谁随包由账 `bundled-plugins.lock.json` 的 `seed` 字段声明（**数据，不是代码**），新鲜度由门禁 `check-bundled-freshness` 守。

## 三、未来更新点：逐插件补测试覆盖（2026-09-15 记账 → **已立案为 E6 第 11 层**）

> 🆕 **2026-09-25 已立案**：本条已成体系立案为 **E6 第 11 层「插件测试覆盖层」**（`E6#144`-`E6#154` 十一格，5 会话接力）——⏳ **未开工**（用户 2026-09-25 明令该批「只写任务文档与清单，无需执行代码任务」）。**总纲（19 仓读数总表 ＋ 「虚掩的门」精确诊断 ＋ 版本账 ＋ 首件事「把 `vitest.setup.ts` 收进 SDK」）= [插件测试覆盖层/00-整理档案.md](../02-Electron架构/E6_插件生态与发布/插件测试覆盖层/00-整理档案.md)；队列与接力 = 同夹 `交接.md`**。⬇️ 下面那段是 2026-09-15 的**原始记账**（出处，保留不改）。

> 出处：2026-09-15 全软件评审（V2 对照）发现——壳仓门禁很严（153 个测试文件 / 2,063 用例 + `npm run check`），但插件仓 CI（`ci-verify.mjs`）只查结构与声明（schema / 跨插件引用 / i18n 字典 / 声明自洽），**测试这道关在插件层是虚掩的**。实证：serial-monitor 约 6,000 行生产代码仅 1 个测试文件 148 行，RingBuffer / autoFormatHex / portFilter / cm6 扩展等纯逻辑零测试。

- **做什么**：18 只发货插件逐只补测试覆盖——先补纯逻辑（utils / hooks / 服务层），再补视图交互。
- **怎么干（2026-09-15 用户拍板的流程）**：**不回壳仓做**——届时逐插件进入其独立仓（`E:\linkdesk-plugins\official\<id>`），与该仓工程里的 AI 详细对话来完善该插件的测试；插件仓测试基建已随 E6 第 7.5 轮就位（vitest + 独立 CI），届时账也记在各插件仓自己的档案里。
- **起点建议（待拍板）**：serial-monitor——评审实证最薄，且 RingBuffer 等纯逻辑最适合先测。
- 本条只是记账防忘，不是实施中的补丁；各插件动工时在其插件仓内立案。
