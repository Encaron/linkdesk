# E2b — 终端归一化

> 2026-07-24。从旧 P6b 迁移，适配 Electron。
> **目标：** 终端从 "验证产物" 变成 "正确参考实现"。E3 文件树、主题浏览器、语言选择器全以终端为模板来写——模板本身必须干净。
> **性质：** 纯 TS 改动，框架无关。Rust 后端已消失——6b 的术语迁移目标天然加速。
> **⚠️ 此步不改插件 ID。** 插件 ID 从 `"terminal"` → `"serial-monitor"` 的改名为 E2b+E2c 完成后的独立操作——届时壳已不再引用插件 ID，改名是低风险的全局替换。`"terminal"` 这个名字留给未来的真终端（PowerShell/Git Bash/bash）。

---

## 一、为什么终端需要拆干净

### 1.1 终端的历史角色

| Phase | 终端干什么 | 代码质量 |
|------|------|:--:|
| Phase 1-2 | 证明 React + CM6 + Rust 串口全链路能跑 | "先跑起来" |
| Phase 3 | 验证标签页 + 分屏 + keep-alive | 稳定性优先 |
| Phase 4 | 验证插件系统 + 视图注册 + 生命周期 | 加 plugin.json |
| Phase 5 | 验证 ConfigurationService + 命令系统 | 迁移到新配置 |

Phase 1-4 的代码是 "证明这条路能走"——不是 "这条路该怎么走"。

### 1.2 具体问题清单

| # | 问题 | 位置 | 为什么是问题 |
|:--:|------|------|------|
| 1 | `SerialContext` 在 `src/core/` | `SerialContext.tsx` | 核心不知道串口是什么——SerialContext 是终端插件的实现细节 |
| 2 | `portOpen` / `portName` 术语 | 遍布 Rust+TS | 核心只知道 "数据源"——端口是串口的实现 |
| 3 | 裸 `listen()` | `index.tsx` | B11 教训——事件监听要用 generation counter 模式 |
| 4 | `let _receiveMode` 模块变量 | `index.tsx` | 多标签页时互相覆盖 |
| 5 | `let _activeSessionId` 模块变量 | `index.tsx` | 同上 |
| 6 | 命令路由到 "最后 mount 的 TerminalView" | `index.tsx` | Ctrl+Shift+P 命令作用到错误的标签页 |

**对标 VS Code：** VS Code 源码 `src/vs/workbench/contrib/terminal/`——终端代码全在 `contrib/`，不在 `platform/`。LinkDesk 对应：串口监控代码全在 `plugins/serial-monitor/`，不在 `src/core/`。

## 二、任务清单

### 任务 7：SerialContext 迁出 core/（~30 行）

**当前：** `src/core/SerialContext.tsx`（~150 行）
**目标：** `plugins/terminal/SerialContext.tsx`

**影响范围：**
```
SerialContext.tsx 当前被谁 import：
  plugins/terminal/index.tsx       → 改为相对路径 import
  plugins/terminal/ControlPanel.tsx → 同上
  plugins/terminal/sidebar.tsx     → 同上
  App.tsx（状态栏 TX/RX 计数）      → App.tsx 不应 import SerialContext！
                                     → 状态栏 TX/RX 通过 CoreEvents 获取
```

**App.tsx 的解耦：**
```
改前：
  App.tsx import { useSerialContext } from "@src/core/SerialContext"
  → 状态栏直接读 serialContext.txCount / rxCount

改后：
  SerialContext 内部 emit CoreEvents.onDidChangeSourceState
  → App.tsx 订阅 CoreEvents → 状态栏显示
  → 核心不知道 "串口"——只知道 "有数据源状态变化了"
```

**执行步骤：**
1. `cp src/core/SerialContext.tsx plugins/terminal/SerialContext.tsx`
2. SerialContext 加 `emit(CoreEvents.onDidChangeSourceState, { ... })`
3. App.tsx 状态栏改为订阅 CoreEvents
4. 更新终端插件内 3 个 import
5. **修 `src/core/v3Api.ts`——当前 `import { useSerialContext } from "./SerialContext"` 会断裂**
   - 方案：创建 `src/core/useSourceState.ts`（通用数据源 hook）→ v3Api + 终端插件都用它
   - 核心只知道"数据源"有 `{ name, isOpen, stats }` 状态——不知道"串口"
   - `useSourceState()` 内部从 `window.linkdesk.serial.getStatus()` 或 CoreEvents 获取
   - 终端插件 `useSerialContext → useSourceState`（接口兼容）
6. 删 `src/core/SerialContext.tsx`
7. `npx tsc --noEmit` → 零错误

### 任务 8：术语迁移——portOpen → sourceOpen（~30 行）

**Rust 后端已消失，此项大幅简化。** 原 P6b 要改 Rust+TS 双端，现在只改 TS。

| 旧名 | 新名 |
|------|------|
| TS 类型 `PortState` | `SourceState` |
| TS 变量 `portName` | `sourceName` |
| IPC channel `serial:portState` | `serial:sourceState` |
| 事件名 `port-state-changed` | `source-state-changed` |
| `window.linkdesk.serial.*` 中的 `portName` 参数 | `sourceName` |

**不改什么：** Node.js `serialport` npm 包内部的 `port_name` 字段——第三方库 API。

### 任务 9：useIpcEvent 归一化（~20 行）

**问题：** 终端插件里可能有裸 `ipcRenderer.on()`。

**B11 教训：** 裸 `listen()` → 组件 unmount 但 cancel fn 没调用 → 旧 listener 残留 → 再次 mount → 双份回调。

**执行：**
```bash
grep -rn "ipcRenderer.on\|listen(" plugins/terminal/
```
逐条判断 → 改用 `useIpcEvent`（generation counter 模式）。不在组件内的 listener → 提取到最近的组件 useEffect。

### 任务 10：模块级可变状态消灭（~10 行）

**问题：**
```typescript
// ❌ 多个 TerminalView 实例共享
let _receiveMode: "text" | "hex" = "text";
let _activeSessionId: string = "";
```

**改法：**
```typescript
// ✅ 从 session 读——每个标签页独立
function TerminalView({ isActive, sourceId }: TerminalViewProps) {
  const session = useSession(sourceId);
}
```

**执行：**
```bash
grep -rn "^let _" plugins/terminal/ --include="*.tsx" --include="*.ts"
```
每一个 `let` → 判断常量（改 `const`）还是可变状态（迁入 hook/session）。允许 `const`，不允许 `let`。

### 任务 11：命令路由修复（~20 行）

**问题：** Ctrl+Shift+P → 复制/清空/切换模式 → 作用于 "最后一个 mount 的 TerminalView"。

**改法：**
```typescript
// 改前：
const cmViewMap = new Map<string, EditorView>();  // key 不区分实例

// 改后：
const cmViewMap = new Map<string, EditorView>();  // key = sourceId（保证唯一）
const activeSession = getActiveSession();
const cmView = cmViewMap.get(activeSession.id);

// 加 WeakMap + dispose 清理：
useEffect(() => {
  return () => { cmViewMap.delete(sourceId); };
}, [sourceId]);
```

### 任务 12a：statusBar.tsx + 侧栏 onMouseDown——动态渲染标准化（~25 行）

**目标：** 终端当前状态栏 TX/RX 能正常更新（已有机制），但用的是非标准路径。创建 `statusBar.tsx` 统一为推荐模式——让未来编译器插件等照抄同一个模板。

**修法：** 创建 `plugins/terminal/statusBar.tsx`——从 SerialContext 读 TX/RX 计数，实时渲染。替代当前的非标准更新方式。

```typescript
// plugins/terminal/statusBar.tsx —— ~20 行
export default function TerminalStatusBar() {
  const { txBytes, rxBytes } = useSerialContext();
  return <span>TX:{txBytes} RX:{rxBytes}</span>;
}
```

**侧栏 onMouseDown 修正（+5 行）：** 终端侧栏会话列表当前用 `onClick`——对标 03-插件制造 UI 规约 §7，侧栏垂直列表选中条目必须用 `onMouseDown`（防止快速点击跨元素丢事件）。`sidebar.tsx` 中会话列表条目的 `onClick` → `onMouseDown`。

**验证：** 打开串口→发数据→状态栏 TX/RX 数字实时跳动。两个终端标签页各开不同串口→状态栏显示当前活跃标签页的计数。侧栏快速点击切换会话→不丢事件。

### 任务 12b：终端状态栏开关注册到 ConfigurationRegistry（~15 行）

**问题：** 终端 `plugin.json` 声明了 `statusBar` 项（TX/RX 计数、连接状态指示灯），但用户无法选择显示或隐藏。Settings Editor 里没有"串口监视器"分组。

**原则：** Settings Editor 只管全局默认值。波特率、COM 口、编码、HEX 模式等是每会话独立的——它们留在侧栏 ControlPanel，不进入 Settings Editor。

**注册到 Settings Editor 的：**

| 设置项 | 默认值 | 说明 |
|--------|:--:|------|
| `serial-monitor.statusBar.txrx` | `true` | 状态栏显示 TX/RX 计数 |
| `serial-monitor.statusBar.connection` | `true` | 状态栏显示连接状态指示灯 |

**修法：** 终端 `plugin.json` 加 `contributes.configuration`，声明以上 2 项。`statusBar.tsx`（任务 12a）读取这两项配置决定是否渲染。

**验证：** Settings Editor → "串口监视器"分组出现 → 两个开关 → 关掉 TX/RX → 状态栏 TX/RX 消失 → F5 → 仍是关的。

## 五、插件改名路线——`terminal` → `serial-monitor`

**E2b 不做改名——只拆架构。** E2b 的任务是让 SerialContext 离开 core/、消灭模块级状态、术语统一为"数据源"。插件 ID 保持 `"terminal"`。

**E2b+E2c 完成后，改名是低风险操作：**

| 改名前 | 改名后 |
|--------|--------|
| `plugins/terminal/` | `plugins/serial-monitor/` |
| plugin.json `name: "terminal"` | `name: "serial-monitor"` |
| 插件内部 16 处 `registerCommand("terminal", ...)` | `registerCommand("serial-monitor", ...)` |
| 插件内部 `createTab("terminal", ...)` | `createTab("serial-monitor", ...)` |

**不再需要改的地方（E2b+E2c 已消灭，共 3 项）：**
- ~~`tabIdentity.ts` `terminal: { ... }`~~ → 19d 消灭硬编码表
- ~~`App.tsx` `setPluginStateValue("terminal", ...)`~~ → 19f 移除
- ~~`App.tsx` `createTab("settings", ...)`~~ → 19f 改为工厂插槽查找

**数据迁移（新路径——LEGACY_TAB_IDS 不够用）：**

> ⚠️ **2026-07-24 审计发现：** 原方案"`LEGACY_TAB_IDS` 加 `"terminal"` → 自动迁移为 `"serial-monitor"`"在机械上不可行。原因：
> 1. 终端 tab ID 是 `terminal-1`、`terminal-2`——`LEGACY_TAB_IDS.has("terminal-1")` 返回 `false`（集合里只有 `"terminal"` 字符串）
> 2. `LEGACY_TAB_IDS` 的操作是 `newId = tab.id + "-1"`（追记计数器后缀），不能处理 pluginId 前缀重命名
>
> **正确方案：** 新增专用迁移函数 `migratePluginIdRename()`——遍历 `workspace.json` 中所有 tab，匹配 `id` 前缀 `"terminal-"` → 替换为 `"serial-monitor-"`，同时 `type` 字段同步替换。一次迁移后写入 flag `_migrated_terminal_to_serial_monitor: true` 到 layout JSON，后续重启跳过。**幂等：** 第二次启动 flag 已存在 → 不执行。

**为什么叫 `serial-monitor`：** 对标 Arduino IDE Serial Monitor、PlatformIO Serial Monitor——行业标准术语。`"terminal"` 这个名字留给真终端（PowerShell/Git Bash/bash），对标 VS Code Integrated Terminal。
