# 待抉择池 · 底部面板显隐「关闭后重启复现」

> 2026-09-13 立案候选（用户报告）。**现象**：关闭底部面板 → 关闭软件 → 重新打开，底部面板又回来了。**疑点不是没持久化，而是重启后被某条路径重新展开。**

## 已核实的机制现状（2026-09-13 排查）

持久化与恢复链路**都在**：

- 落盘：`src/App/persistence.ts` — `useLayoutPersistence` 把 `panelVisible` 合并写进 `layout.json` 的 `panel.visible`（E5.8#31「显隐合并落盘——防抖保存可能未覆盖」，两处落盘点 96/165 行）。
- 恢复：`src/App/panelHost.ts:27` — `useState(() => getPanelLayout()?.visible ?? true)`，启动取持久化值，旧布局缺字段才缺省可见。
- 翻转：`src/App/panelHost.ts` — `panel:toggle`（Ctrl+J）翻转后**立即落盘**。

## 嫌疑方向（未验证，按可能性排）

1. **`panel.reveal` 自动展开**（`src/App/panelReveal.ts`，E5.8#34.5/#35.5）：启动恢复会话时若面板视图标签随会话恢复，可能触发 reveal → `setPanelVisible(true)`，把刚恢复的 `visible:false` 顶掉。
2. **落盘时序**：关闭面板到退出软件之间若防抖保存未及写入（#31 注释自认「防抖保存可能未覆盖」），盘上仍是 `visible:true`。
3. **旧布局缺省分支**：`?? true`——若关闭面板后落盘的是「无 panel 字段」形状而非 `visible:false`，重启即命中缺省可见。

## 验证建议

关闭面板后（不退软件）直接看 `%APPDATA%` 下 `layout.json` 的 `panel.visible` 值——一步区分「没写进去」（嫌疑 2/3）还是「写了但启动被顶掉」（嫌疑 1）。立案后再定修法。
