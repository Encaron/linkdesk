## 二、目标规则（**唯一权威，写完照抄**）

### 2.1 三档制

| 档 | 范围 | 阈值 | 豁免 |
|:--|:--|--:|:--|
| **A** | `src/**` + `electron/**` | **800** | ✅ allowlist（`@E6#0.6b` 拍板制，现状不变） |
| **B** | `plugins/*/src/**` | **按角色表**（见 2.2） | ❌ **无豁免通道**——拆分是正解 |
| **C** | `plugins/*/src/index.tsx`（entry） | **120** | ❌ 同上 |

### 2.2 角色表（**按扩展名与首段目录定，不看更深层级**）

```
.css                                       → 300   （放在哪都算样式，含 co-located 的 views/*.css）
plugins/*/src/index.tsx                    → 120   （entry = 薄门面；**精确路径**，不按 basename）
plugins/*/src/<Name>.{ts,tsx}（根级非 entry） → 150   （跨层共享单件，细则 4）
plugins/*/src/<role>/**.{ts,tsx}           → ROLE_LIMITS[role]
```

```js
const ROLE_LIMITS = {
  views: 150,      components: 150,
  hooks: 150,      utils: 150,          // ← 新增（G3）
  services: 200,
  cm6: 150,                             // ← #88a 实装时新增（细则 5）
};
```

**五条判定细则：**

1. **`.css` 恒走 300**——不看目录。这样 settings 的 `views/SettingsView.css`（630）与 marketplace 的 `styles/*.css` 用同一把尺。
2. **未知 role 夹 → `throw`（保持现状的 fail-loud）**——新增一个顶层目录（如 `src/store/`）时门禁**报错逼显式上档**，不允许静默落进 800 兜底。
3. **同名夹聚合器 → role 档 ×2**（见 2.3）。
4. **根级 `*.ts(x)`（非 entry）给一档 150，不 `throw`**——09-插件目录规范「特殊情况：跨层共享的类型定义放 `src/` 根」已授权 `src/types.ts` / `src/constants.ts` 这类单件（serial-monitor 实存 2 件，51 行以内）。**给一档 ≠ 放行膨胀**：它仍受 150 约束，只是不必为「根级」另造一个目录。⚠️ **`src/index.ts` 仍 `throw`**——entry 只认 `index.tsx`，撞上 `index.ts` 是写错了，不是「未登记」。
5. **`cm6: 150`（#88a 实装时新增）**——serial-monitor 的 CodeMirror 6 域 5 个纯逻辑模块（`appendLine` / `decorations` / `scroll` / `search` / `theme`：无 JSX、无状态，语义与 `hooks`/`utils` 同级）。**这是「登记」而非「搬家」**（2026-09-11 用户拍板原话「**登记它们**」）——fail-loud 机制的正解就是**显式上档**，不是把代码挪进 `utils/` 去凑目录表。新增顶层目录时同理：先问「它是什么角色、该给多少行」，再决定登记还是重构。

### 2.3 聚合器档（**新增**）

**判定条件（纯机械，零内容分析）——🔴 两形，都要认**（E6#87 前置订正，2026-09-11 补）：

| 形 | 判据 | 谁用 | 实存实例（2026-09-11 实测） |
|:--|:--|:--|:--|
| **(a) 夹旁散门面** | 文件 `X.ts(x)` 的**同级存在同名夹 `X/`** | `views/`（basename 受约束，门面必在夹旁） | **14 件** |
| **(b) 夹内入口** | 路径形如 **`<roleDir>/<Feature>/index.ts(x)`**（`dirs.length ≥ 2`） | `services/` `components/` `hooks/` `utils/`（无 basename 约束，门面就是夹内 `index`） | **14 件** |

**📋 逐件清单（#88d 实测，共 28 件）：**

| 形 | role | 件数 | 说明 |
|:--|:--|--:|:--|
| (a) | `views/` | **12** | 各插件视图门面（`EditorView` 48 / `FoldersView` 160 / `SearchView` 128 / `DetailView` 283 / `ExploreView` 132 / `SearchView` 121 / `SerialMonitorView` 146 / `SerialSettingsView` 67 / `SessionListView` 104 / `SettingsView` 270 / `SettingsView/renderControl` 268 / `SettingsView/SettingRow` 138） |
| (a) | `components/` `services/` | **2** | `editor/EditorTab.tsx` 87 · `editor/lsp-bridge.ts` 13（**views 之外也出现了夹旁门面**——判据按机械条件认，不按「谁该用哪形」认） |
| (b) | `services/` | **8** | file-tree ×3（`FileTreeDnD` 11 / `FileTreeKeyboard` 67 / `FileTreeModel` 209）· marketplace ×4（`marketCatalog` 56 / `marketplaceShared` 62 / `marketSources` 34 / `updateDiscovery` 71）· serial ×1（`SerialContext` 20） |
| (b) | `components/` `hooks/` | **6** | file-tree ×4（`FileTree` 199 / `FileTreeContextMenu` 14 / `FileTreeContextMenu/commands` 39 / `FileTreeNode` 118）· serial ×2（`ControlPanel` 65 / `useSerialSessions` 18） |

> 🔴 **实存数从「1 对 + 4 件」涨到「14 + 14」——分裂是拆分自己制造的。** 前置订正（#87 前）时测得 1+4 = 5 件，那是因为当时 `DetailView.tsx`（1258）、`marketplaceShared.ts`（779）、`SettingsView.tsx`（630）这些**巨型门面还没拆**；3.6.2/3.6.3/3.6.4 四轮拆完，每个被拆的大家伙都**长出一个门面**（且 `services/` 支按铁律拆成 `<Feature>/index.ts`）。⇒ **聚合器档不是「少数特例的优待」，是本层拆法的常规产物**：没有 ×2 档，下一轮拆的人就会被 150 逼着把门面也拆碎（正是 12 档明令禁止的「同 domain 平铺多文件」）。28 件里最大 `DetailView.tsx` 283 ≤ 300、`renderControl.tsx` 268 ≤ 300，**全部在档内**。

**两形都按 role 档 ×2 计。** 为什么必须两形——判据来自 [12 档 §一·〇 门面形态铁律](../03-插件市场/12-插件目录与UI细节.md)：**有没有 basename 约束**决定门面落在夹旁还是夹内。只认 (a) 的后果：14 件 `services/*/index.ts` **一个都判不出来**（basename 是 `index`、夹名是 `marketCatalog`，`hasSameNameFolder` 两边都不匹配）⇒ 它们只会拿 200 档而非 400。

> ⚠️ **实装时这里踩了一个真坑（#88a）**：形 (b) 的判据最初拿 `dirs` 的**末段**去比对 `index.tsx`——而末段是**夹名**，于是判据**恒 false**。翻开关后当场暴露：`file-tree` 的 `components/FileTree/index.tsx`（199）与 `services/FileTreeModel/index.ts`（209）被误报超限。改为按**文件 basename** 判后归零。⇒ **两形判据必须各拿对各自的那一半**：形 (a) 比「文件 stem ↔ 同级夹名」，形 (b) 比「文件 basename ↔ `index`」。这就是 §五 人造红灯 **C 必须两形都验**的理由——只验形 (a) 的话，形 (b) 烂成恒 false 也测不出来。

> **`views/**/index.ts(x)` 不适用 (b)**——铁律规定 views 门面必在夹旁，夹内 `index` 在 views 里不该出现（实测：**0 件**）。门禁对 `views/` 下的 `index` 按普通 150 计，**不静默给 ×2**；真出现了属于铁律违例，由 #88 验收逐面比对时暴露。

仓库现有 **10 对**同名夹（`App.tsx`+`App/`、`KeybindingRegistry.ts`+`KeybindingRegistry/`、`useTabManager.ts`+`useTabManager/` …），**这个信号本来就是 0d.10 feature-folder 拆法的产物**——用它当聚合器判据，既准确又零额外约定。

| role | 常规 | 聚合器 |
|:--|--:|--:|
| views / components / hooks / utils | 150 | **300** |
| services | 200 | **400** |

> 🔴 **决策点（[00 §五](00-整理档案.md) 第 1 条）**：**推荐采纳**。
> 理由：本层拆完的 marketplace `DetailView.tsx` / `marketplaceShared.ts` **本来就是聚合门面**——不给它们一档，下一轮拆的人会为了「凑 150」把门面拆成更碎的碎片（正是 12 档明令禁止的「禁止拆同 domain 平铺多文件」）。
> **注意**：这是**上限放宽**，不是**目标值**。门面仍应尽量薄；300 是「不许超过」，不是「应该做到」。

## 三、代码改动（`scripts/check-file-size.mjs`）

**改动面：常量 + `marketLimit()` + 扫描循环。逻辑框架不动。**

```js
// ① 常量：改名 + 扩域（名字要跟语义走，别留着 MARKETPLACE 的旧壳）
const SCAN_PLUGINS   = true;                 // ← E6#88 翻开关（#30.11 挂靠已废除）
const PLUGINS_ROOT   = "plugins";            // 只扫 <plugin>/src/**
const MARKET_ENTRY_LIMIT = 120;              // ← 重命名 ENTRY_LIMIT（语义已是「所有插件 entry」）

// ② 角色表：去扩展名维度，补 hooks/utils
const ROLE_LIMITS = {
  views: 150, components: 150, hooks: 150, utils: 150, services: 200,
};
const CSS_LIMIT = 300;

// ③ marketLimit() 重写
function pluginLimit(relPath) {
  const seg  = relPath.split("/");
  const base = seg[seg.length - 1];
  if (base.endsWith(".css")) return CSS_LIMIT;              // 扩展名优先
  const dirs = seg.slice(seg.indexOf("src") + 1, -1);
  const limit = dirs.length === 0
    ? (base === "index.tsx"
        ? MARKET_ENTRY_LIMIT
        : (() => { throw new Error(`根级入口未上档（仅 index.tsx → ${MARKET_ENTRY_LIMIT}）：${base}`); })())
    : (() => {
        const role = dirs[0];
        if (ROLE_LIMITS[role] === undefined)
          throw new Error(`未知 role 夹「${role}」未上档——需在 ROLE_LIMITS 显式登记（E6#88）`);
        return ROLE_LIMITS[role];
      })();
  return isAggregator(relPath, dirs) ? limit * 2 : limit;    // 聚合器档
}

/**
 * 聚合器判据——两形（见 §2.3）。刻意不认第三形：
 * `views/<功能夹>/<Named>.tsx`（夹名≠文件名、不叫 index，如 keybinding-settings/KeybindingSettingsView.tsx）
 * = 功能域文件集合，按 views 档 150 计、子件留本夹内（12 档 §一·〇「第三种形」）。
 */
function isAggregator(relPath, dirs) {
  // 形 (a) 夹旁散门面：同目录存在去扩展名同名夹——views 支
  const abs = resolve(ROOT, relPath);
  const n   = basename(abs).replace(/\.(ts|tsx|css)$/, "");
  if (existsSync(join(dirname(abs), n)) && statSync(join(dirname(abs), n)).isDirectory()) return true;
  // 形 (b) 夹内入口：<roleDir>/<Feature>/index.ts(x)——services/components/hooks/utils 支
  const base = dirs[dirs.length - 1];
  if (dirs.length >= 2 && dirs[0] !== "views" && (base === "index.ts" || base === "index.tsx")) return true;
  return false;
}

// ④ 扫描循环：plugins/*/src 逐个插件走
if (SCAN_PLUGINS) {
  for (const e of readdirSync(resolve(ROOT, PLUGINS_ROOT), { withFileTypes: true })) {
    if (!e.isDirectory()) continue;
    const src = resolve(ROOT, PLUGINS_ROOT, e.name, "src");
    if (!existsSync(src)) continue;                          // theme-*/lang-* 无 src，自然跳过
    for (const f of walk(src)) scanned.push({ rel: rel(f), full: f, plugin: true });
  }
}
```

**同时更新的注释**（脚本头 §1/§4、`SCAN_*` 处的门开关说明）——**把「翻开关」的历史写进去**，下一个读代码的人才知道为什么它曾经休眠。

**`EXEMPT_FILES` 守卫**：`!f.market` → `!f.plugin`（字段改名，语义一致：allowlist 只管 A 档）。
