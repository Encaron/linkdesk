## 一、归属解析（甲路线的落地形状 —— **本格的主干工程**）

> 出处：[1.31 §11.2](01-任务-命令id归属评估.md)（含可行性实证与「为什么不用 loader 上下文注入」的否决理由）。

### 1.1 优先级（**身份优先于名字**）

| 序 | 来源 | 命中面 | 置信 |
|:--:|:--|:--|:--|
| ① | **声明面查表**：`contributes.commands[]` → 真 `pluginId`（loader 用真身份注册，`contributions.ts:63-77`） | 本轴 46 处里 **44 处** | 🟢 权威 |
| ② | **注册方显式申报**：运行时载荷新增**可选** `pluginId` 字段（**只做加法**，照 `notifications.source` 先例 `src/core/api/linkdesk-api/ui.ts:26-32`） | 未声明者（`explorer.removeFolder` / `explorer.closeAllEditors` / 动态命令） | 🟢 权威 |
| ③ | **名字第一段**（今天的做法） | 前两条都拿不到（老第三方插件零申报） | 🟡 **降级为"推定"**——只作兼容，**冲突时必须出声** |

### 1.2 两条硬注意（**不处理就是新机制自己有洞**）

1. **乱序到达**：池侧运行时注册可能**早于** loader 的声明注册 ⇒ 条目先以「推定归属」建好，**声明随后到达时今天不会回头纠正**（`registerCommand` 的 existing 分支只改 handler/title/placeholder，**不动归属**）⇒ 必须补「**声明到达 ⇒ 重挂归属**」。
   🔴 **但这一步与「同插件重注册只更新 handler/title」是两条不同触发路径**——**不许混进 `:57-73` 那个分支**（禁区 3）。
2. 🔴 **`_poolCommandWindows` / `_poolPending` 一个字都不许动**（禁区 4）：归属解析只影响 `_pluginCommands` 的记账与覆盖判定，**不碰路由**。

### 1.3 显式申报的传递链（照 `commands:register` 现状延伸）

```
插件代码  lk.commands.registerCommand(id, handler, meta?)
   ↓ contextBridge（preload-pool，单进程共享 realm）
preload   _poolCommands.set(id, handler) ＋ ipcRenderer.invoke(IPC.commands.register, id, meta)
   ↓
壳         registerPoolCommandMetadata(id, meta) → 归属解析（①→②→③）
```

⇒ **`meta` 加一个可选 `pluginId`（或新增第 4 参）即可，通道不变**。⚠️ **通道与 IPC 形状能不动就不动**（禁区 5「不许重构注册表 / 换数据结构」——**加字段是加法，换通道不是**）。

## 七、禁区（**逐条照抄，一条都不许破**）

- 🔴 **不许抛错**：`contributions.ts` 的命令注册调用点在 `parseContributions` 内 ⇒ 抛错 = **整只插件装不上**（[00 档 §2.7](00-整理档案.md)）。修法只能是 **不覆盖 ＋ `console.error`**。
- 🔴 **不许改坏「同插件重注册」的合法语义**：`loader 先注册元数据 → 组件 mount 重注册 handler（只更新 handler/title，不动元数据）`（`CommandRegistry.ts:59-61`）——**这是既有设计，逐字保留**。（新增的「声明到达重挂归属」**必须是另一条路径**。）
- 🔴 **不许动多窗归属表**（`_poolCommandWindows` / `_poolPending`，`:110,301`）。
- 🔴 **不许引白名单 / 基线 / 棘轮**；保留名账**必须生成式 ＋ 双向对账**。
- 🔴 **不许重构注册表 / 换数据结构**（「丁 复合键」**已被 1.31 否决** ⇒ 本格**不许自己发明**）。**加字段是加法，换通道不是**。
- 🔴 **不许改命令 id 的「公共 API」语义**：命令 id 是跨插件调用面（`executeCommand`）＋ `menus[].command` / `keybindings[].command` 的引用目标。
- ⚠️ **上位约束（§〇c 修订后口径）**：**操作体验零变化**（点每个设置项仍能切换 · 每个快捷键仍能触发 · 每个主题仍能选仍能跟随 · 翻译仍能切换；**名字可变，用户已存的值不许丢**）· **只做加法且名字一次定对** · [29 号档](../样式命名空间归一化/29-主题系统保护条款.md) 冲突时以它为准 · **对外宽容**（第三方侧新判据默认黄灯）。
- ⚠️ 照旧：不跳 `npm run check` · 推前现测代理 · 推完 `ls-remote` 对 SHA · **提交只按路径 `git add <本格文件>`**（**禁 `git add -A`**）· 🔴 **不许引 gitignore 里的文件**（`check-doc-links` 看不见"文档→脚本"）。
