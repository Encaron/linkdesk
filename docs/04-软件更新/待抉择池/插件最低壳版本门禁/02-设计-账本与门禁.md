# 02 · 设计：账本与 SDK 门禁

> 本件把 `minAppVersion` 从「**作者手写的声明**」改成「**由工具算出的结论**」。核心只有一句：
> **门禁不看那个数字从哪来——它自己重算地板。**
>
> 判定式（一句话）：**地板 = `max{ since(x) | x ∈ 插件静态具名导入的 @linkdesk/ui 导出 }`；`minAppVersion < 地板` ⇒ 红。**

---

## 一、判定式的形状

```
输入 A：插件源码/产物里对 "@linkdesk/ui" 的静态具名导入清单（名字集合）
输入 B：账本 —— 每个 @linkdesk/ui 导出名 → since（首次随哪个壳版本提供）
输出： 地板 = max(since(x) for x in A)
判据： declared.minAppVersion >= 地板
       ├─ 否 ⇒ 🔴 红（报错给出：地板值 / 越界的导入名 / 建议取值）
       └─ 是 ⇒ 放行
fail-closed：任一名不在 B 里 ⇒ 🔴 红（"查不到" = 另一种不同步，不许静默放行）
```

**为什么这样就能防住 [01](01-事故复盘-真机实证.md) 的场景**：设置插件导入了 `PluginCard`（`since = 0.2.44`）⇒ 地板 = `0.2.44`；它声明 `0.2.32` ⇒ `0.2.32 < 0.2.44` ⇒ **构建期就红，包发不出去**。`@latest` 在这里**帮了忙**——正是它让 SDK 里的账本**知道** `0.2.44` 这条。

## 二、G1 账本（唯一数据源）

### 2.1 形态

**升级现有 [scripts/ui-surface.json](../../../../scripts/ui-surface.json)，不新造第二个文件。** 今天它是：

```json
{ "generatedAt": "...", "components": ["BackgroundImagePicker", "Badge", ...],
  "hooks": [...], "helpers": [...], "types": [...], "count": 62 }
```

升级为**同一份文件里**每个名字带 `since`（四栏 **components / hooks / helpers / types** 全要——导出面不止组件）：

```json
{ "generatedAt": "...", "shellVersion": "0.2.48",
  "components": { "Badge": { "since": "0.2.13" }, "PluginCard": { "since": "0.2.44" }, ... },
  "hooks": { ... }, "helpers": { ... }, "types": { ... } }
```

> ⚠️ **`since` 的语义必须是「壳版本」而不是「ui 包版本」**——因为 `minAppVersion` 比的是**壳版本**。而 ui「同号锁步」已退役（`a8b42bbe9`「对货不对号」，E6#166）⇒ **绝不能靠版本号大小推**，只能**显式记录**。
> ⇒ 生成器在**壳发版那一刻**知道"当前壳版本 + 本次新增了哪些导出"，打上即可。**壳池 vendor 的 ui 与该壳锁在同一 tag**，所以"这个导出首次随壳 `X` 提供"是**可判定的事实**，不是估计。

### 2.2 `since` 从哪来（可行性关卡）

**一次性回溯**：走壳仓 tag 历史，对每个 tag 取该 tag 的 `ui-surface.json`（**导出面只加不删**，E6#121 已有只加不删门禁保证这一点）⇒ 每个导出的**首个出现 tag** = 它的 `since`；最老那批（vendor 机制起点）= `0.2.13`。

**此后增量**：`since` 是**只增不改**的账——新导出出现时由生成器补一行（与 `release:mark` 同族纪律：**内容不许跑在版本号前面**）。这正好可以复用既有的 `check-ui-surface-additive` 的 **tag → HEAD → 工作区**基线链（[check-ui-surface-additive.mjs](../../../../scripts/check-ui-surface-additive.mjs)）来算增量。

> 🔴 **动手前必须验证这一条**：`since` 能不能**机械回溯**出来。若某个历史 tag 缺 `ui-surface.json` 快照（基线降级链会走"HEAD/工作区"那一档而失去该时点真相），就要**从 barrel 源码的 git 历史**补——**这一步的可行性决定 G1 成不成立**，先做它。

### 2.3 下发路径（插件独立化的生死线）

```
壳仓（生成）  →  packages/plugin-sdk/schemas/ui-surface.json（随包拷贝）
                                  ↓  npm publish
第三方插件仓  →  node_modules/@linkdesk/plugin-sdk/schemas/ui-surface.json（离线可得）
```

**照 `host-css-names.json` / `plugin.schema.json` 的既有先例**（壳生成 → 随 SDK 包发）。⛔ **绝不让插件仓去读壳仓、壳的 tag、或联网**——那样插件就不独立了（[00 §三](00-README.md) 硬推论 1）。

## 三、G2 SDK 门禁（**改造**现有那条，不新写）

**落点**：`packages/plugin-sdk/src/eslint/checks/ui-min-app-version.ts`（现有 `runUiMinAppVersionCheck`）。

**复用（一行不动）**：四形态消费采集器（静态 import/export、`import()`、`require()`、side-effect import）、`type-only` 剔除、注释剔除、测试/夹具跳过、报点落 `plugin.json:1`、fail-closed 文案风格。

**改动**：

| 项 | 今天 | 改成 |
|:--|:--|:--|
| 地板 | 常量 `UI_REANCHOR_APP_VERSION = "0.2.13"` | **从账本算**：`max(since(x))`，`x` = 本插件实际导入的导出名 |
| 判定 | `declared >= 0.2.13` | `declared >= 地板` |
| 未声明/形态坏 | 红 | 红（不变） |
| 导出名查不到账本 | （今天不存在这个情形） | **红**（fail-closed） |
| 报文 | 指"低于重锚号" | 指"**你导入了 `X`（首次随壳 `0.2.44` 提供），但声明 `0.2.32`；请抬到 ≥ `0.2.44`，或别用 `X`**" |

**接线（必须默认开）**：挂 `npm run check`（壳仓）＋ 脚手架 `verify` / `lint` / `build` / `publish`（插件仓）⇒ **作者必跑的链上默认就在跑**。opt-in 的脚本 = 等于没有（[00 §三](00-README.md)）。

> ⚠️ **本条无豁免出口**（照现有腿的纪律：disable 注释对它无效）——"知情地把插件放到撑不住它的旧壳上"不是合法偏离，是语义错误。

## 四、G3 脚手架默认值（把失败方向翻过来）

**今天**：模板 [plugin.json](../../../../packages/create-linkdesk-plugin/template/plugin.json) 写死 `"minAppVersion": "0.2.13"`——**这是最危险的方向**（默认声明"我能在最旧的壳上跑"）。

**改成**：默认值 = **该插件自身导入的地板**（同一份账本算出来）。

- 模板自己只用极少组件 ⇒ 默认值自然低而**正确**（不是无脑抬高，避免"hello world 也拒绝跑在旧壳"）；
- 此后再加组件 ⇒ **门禁（G2）自动把地板抬上去**，作者不必自己盯。

**被否的替代方案**：把默认钉在"最新壳版本"（0.2.x latest）——过度保守，会让只用旧组件的插件无谓地拒绝旧壳。**也否**"保持 0.2.13 由作者负责抬"——那正是**本次事故的形态**。

## 五、G4 / G5 在本案里的位置

见 [04](04-任务-读数腿与流程腿.md)。要点：
- **G4（读数腿）**：让**已经装坏的那一份**也不再显示「正常」——读数的判据从"只信声明"扩到"`max(声明, 实际)`"。
- **G5（流程腿）**：第一方特有，⛔ **不进 SDK**，落壳仓发布链。

## 六、🔴 为什么"优雅降级"**不能**写成门禁要求

事故的 changelog 说"更低的软件上这一组不出现"——但静态 `import` 做不到局部降级。天然的反应是"那就在门禁里**要求作者用动态 `import()`**"。**这条必须否掉**，理由三条：

1. **那是风格约束，不是正确性判据**。门禁的职责是**让声明为真**；"要不要在旧壳上跑"是**产品/作者的选择**——想跑就动态导入，不想跑就抬声明，两条都合法。
2. **它违反插件独立化**：拿一个实现手法去绑作者的代码结构，等于把壳的偏好塞进作者的源码。
3. **对第三方根本不存在这个场景**：第三方只声明**自己测过的壳**，本来就不会有"想在更旧壳上跑"的诉求。为第一方一厢情愿的需求去约束全体作者，是本末倒置。

⇒ **正解是"声明诚实"**：抬到 `0.2.44` 后，加载器会给出明确的 toast、读数会显示「不适配」，而不是静默死。**产品要不要额外给 settings 一条真降级路，是 G0 的事（等用户拍），与门禁无关。**

## 七、七条原则逐条对照（用户点名的检验）

| 原则 | 判定 | 依据 / 约束 |
|:--|:--:|:--|
| **归一化** | ✅ | **只有一份账本**（`ui-surface.json`），三道消费者共用：壳仓只加不删门禁（E6#121）／SDK lint（G2）／兼容读数（G4）。⛔ 不另造第二份映射（"两份必然漂移"是 [plugin-repos.mjs](../../../../scripts/lib/plugin-repos.mjs) 头注立的规矩）。**且 `0.2.13` 常量折进账本后删除** |
| **插件独立化（自由插件）** | ✅ | 账本**随 SDK 包下发**；插件仓**离线、无仓、无网、无 tag** 即可判定。**连官方插件也不例外**（官方插件也是独立仓，等级与第三方一致） |
| **高内聚** | ✅ | 账本生成留在壳的 ui-surface 生成器（一处）；lint 是与现有那条并列的**改造**（不新写采集器）；读数复用同一份数据 |
| **低耦合** | ✅ | 插件仓 → 只依赖 SDK 包，**零跨仓**。🔴 **G5 不许进 SDK**（第一方发布顺序是壳仓家务事） |
| **无硬编码** | ✅ | 常量 `UI_REANCHOR_APP_VERSION = "0.2.13"` **删除**，由账本数据取代；作者手写的数字从"被信任"变"被校验"；`since` 值**由生成器算**、⛔ 不手写 |
| **无死代码** | ⚠️ **需动手两处** | ① 老常量折进账本后**必须删**，⛔ 不许两套并存；② 新 lint 必须有**活的红目标**（`settings 1.0.35` 就是天然的）+ **自测** + 接 [`check-gate-health`](../../../../scripts/check-gate-health.mjs)（否则又是一道"永远绿"） |
| **AI 友好性** | ✅ | 作者侧 AI 读 `node_modules/@linkdesk/plugin-sdk/schemas/ui-surface.json` **一个文件**即得地板，**不需要跨仓推断**；报错文案必须给「**地板值 + 越界的导入名 + 建议动作**」三件 |

## 八、残余边界（诚实列明，⛔ 别假装覆盖了）

1. **只覆盖"组件不存在"造成的硬崩**。组件还在、但 **props/行为变了**的软崩**不覆盖**——`check-ui-surface-additive` 只比**名字集合**、不比签名与可选性（其文件头自述：「⛔ 不收可选性、不收签名与返回类型」），这是**既有边界**，靠软件方"向前兼容"的承诺兜大部分。
2. **覆盖形态 = 现采集器的四形态**（静态具名 `from`／动态 `import()`／`require()`／side-effect `import "…"`；`import type`/`export type` 不算）——**动态形态照算**，见 §九 D6 建议 A（fail-closed：宁可假红、绝不漏红）。**真正会漏的只有** `re-export from "@linkdesk/ui"` 与**字符串拼接**的 specifier（正则看不见）——与现有腿**同口径**，本次不求更全。
3. **只覆盖 `@linkdesk/ui`**。`window.linkdesk.*` **宿主 API 有同类问题**（调不存在的 API = `TypeError`），而 mock 宿主**同样源自 `@latest`、同样会藏住它**。同账本思路可扩展（[host-api-surface.json](../../../../scripts/host-api-surface.json) 已有 `ledger` 结构），但**本件不铺**——先把 ui 这条腿做扎实。
4. **判定只对"申明侧"生效**。若作者手动把 `minAppVersion` 抬到**高于地板**，门禁**放行**——这是合法的（他可以选择更保守）。
