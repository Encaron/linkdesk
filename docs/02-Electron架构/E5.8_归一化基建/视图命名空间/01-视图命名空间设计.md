> **状态：✅ 已执行（2026-08-21）——#41.9.1（注册层复合键）+ #41.9.2（解析链调用点迁移 + 持久化键迁移）双 commit 落地，vitest 799 全绿，两插件同名视图共存互不踩 + fail-loud 可诊断 + 卸载归主 + 存量插件零回归。**
> **背景：** E5.8#41.5 止血（收发设置 viewId `"settings"` → `"receive-and-send"`）暴露裸 id 全局命名空间 + 静默覆盖的系统缺陷——同名视图靠改名躲，撞名靠 last-wins 猜。用户拍板「止血 + 系统改造」：止血已收口（#41.5），系统改造 = 本任务。
> **🔒 硬门槛（审视 2026-08-21）：getView 调用方全表是 #41.9 开工的前置条件——表没补齐、每个调用方没标清「手里有没有 pluginId」，#41.9 代码一行不许动。** 本档案 §3 = 该全表。

## 1. 问题定义

**裸 id 全局视图命名空间 + 静默 last-wins 覆盖**违反三铁律：

1. **插件独立性**——插件作者为避开别人撞名被迫改名（#41.5 收发设置改名就是这个：`"settings"` 撞上内置设置插件）。改名是「数据决定命名」，插件身份应唯一来源 plugin.json（硬约束 11），命名空间归属插件而非全局。
2. **归一化**——`(pluginId, viewId)` 本来就有（`registerView` 签名第一参就是 pluginId，ViewDescriptor 也带 `_pluginId` 标记），但 `_viewIndex` 反查用裸 id 丢掉 pluginId——**身份信息已持有却弃用**，是「归一化没走完」。
3. **健壮性**——撞名静默 last-wins → 解析链拿到错误视图 → 弹错面板 / 读错元数据 / 删错状态，错误不可见不可查。

## 3. 复合键方案

### 3.1 注册键：`(pluginId, viewId)` 复合

- `registerView(pluginId, containerId, descriptor)` 签名不变（pluginId 已是第一参），**内部**键从裸 `descriptor.id` 改为复合 `${pluginId}:${viewId}`（冒号分隔符——**全量验证 2026-08-21：当前所有 pluginId（serial-monitor/file-tree/marketplace/settings…）与 viewId（folders/search/installed/receive-and-send…）均不含冒号**，无歧义；若未来第三方引入冒号 id → 切复合数组 `{pluginId, viewId}` 存，见 §3.4 备选）。
- **同 pluginId 同 viewId** → 幂等更新（现状 registerView 已有 `existing` 判定，见 line 156-159：`v.id === descriptor.id && v._pluginId === pluginId`——模型层其实已经是复合匹配了，只是 `_viewIndex` 没跟上）。
- **异 pluginId 同 viewId** → **共存**，不覆盖（两个同名视图各占各的复合键位）。
- 效果：`serial-monitor:settings` 与 `settings:settings`（#41.5 后为 `settings:settings` 与 `serial-monitor:receive-and-send`）永不互踩——**插件作者永不因别人撞名改名** = 插件独立性。

### 3.2 解析 API：`getView(id)` 废弃 → `getView(pluginId, viewId)`

```ts
// 旧——全局裸查，撞名返回覆盖者
getView(id: string): ViewDescriptor | undefined

// 新——显式归属，撞名不歧义
getView(pluginId: string, viewId: string): ViewDescriptor | undefined
```

### 3.3 容器归属：`_containerOwner` 防覆盖

- `registerViewContainer` 幂等分支（line 100 `Object.assign` 后 `this._containerOwner.set(...)`）：**归属已存在且 pluginId 不同 → 保留首主 + fail-loud 警告**（不是无条件覆盖）。
- 语义：**首主保有**——先声明容器者为属主，后声明者获警告（「容器 X 已归属插件 A，你的声明被忽略」）。卸载时 `_containerOwner.get(containerId) === pluginId` 判定（unregisterAll:362）才成立——归属不被覆盖 = 卸载不会删错容器。

### 3.4 持久化键：`pluginId:viewId` 复合

| 键 | 现状 | 改后 |
|----|------|------|
| `hiddenViews` | 裸 viewId 数组 | `pluginId:viewId` 复合数组 |
| `collapsedViews` | 裸 viewId 数组 | `pluginId:viewId` 复合数组 |
| `viewOrder.${containerId}` | 裸 view.id 数组 | `pluginId:viewId` 复合数组 |

**存量裸键静默弃**：`loadHiddenState`/`loadCollapsedState`/`loadViewOrder` 读到不含复合分隔符的旧键 → 忽略（不迁移、不报错）。折叠/隐藏态升级损失一次 = 纯观感（状态重排一次），非数据丢失。

> **分隔符防歧义备选（仅当未来第三方引入冒号 id 时启用）：** 复合键运行时用 `Map<string, Map<string, ...>>` 嵌套或 `{pluginId, viewId}` 复合对象键（零字符串拼接歧义）；持久化数组存 `[{pluginId, viewId}]` 对象而非 `"pluginId:viewId"` 串。当前全量无冒号 → 冒号串方案落地，备选留档。

### 3.5 `_emptyContents` 复合键

`registerViewEmptyContent(containerId, viewId, ...)` 签名**加 pluginId 参数**（键 `pluginId:viewId`），同名视图空态各存各的。当前零外部消费方（grep 仅定义无调用——见 §5 移交项），签名改动零成本。

### 4.1 声明扫描语义（调用方 #1 专属）

`revealFloating(viewId)` 是插件在 plugin.json 声明 `contributes.floatingPanel` → 点击触发（IpcBridgeHandler/ui.ts:140-149 命令 `workbench.action.revealFloatingPanel`）。插件作者声明时**知道自己是谁**，但 IPC 链路只传 viewId。

- **扫描逻辑**：`getView` 改复合键后，`_viewIndex` 的 key = `pluginId:viewId`。声明扫描 = 遍历 `_viewIndex` 找 viewId 后缀匹配（`key.endsWith(SEP + viewId)`），匹配数：
  - **1** → 唯一命中，返回该 view
  - **>1** → **fail-loud** `console.error` 点名多个 `(pluginId, viewId)` 对（对标 #24.6 失败必出声、loader requires 环先例）
  - **0** → no-op 不崩（#39.5 验收：卸载声明插件后 no-op）
- **为什么不能直接让插件带 pluginId**：`revealFloating(viewId)` 契约已发布（#39.5 验收），改签名破坏存量插件。声明扫描向后兼容——插件作者不需要改任何东西，撞名时才被发现。

### 4.2 迁移期 fail-loud 兜底（审视 2026-08-21）

裸 id 解析遇**多命中** → **fail-loud 报错点名，绝不静默 no-op**。静默 no-op 比 fail-loud 更难查——用户以为没效果，实际是撞名。落地方式 = 统一走声明扫描基元（唯一命中返回 / 多命中 console.error / 零命中 no-op）。

## 6. fail-loud 接口

```ts
// 注册期撞 id 探测——registerView 内，异 pluginId 同 viewId 共存时对后注册者警告
// 对标 loader requires 环 / 版本错配先例（#24.6 失败必出声）

  `[ViewContainer] 视图 id 撞名：插件 "${pluginId}" 注册 view "${viewId}" 已存在（容器 "${containerId}"）。
  已共存（复合键 $(pluginId):$(viewId)），但解析链用裸 id 时会歧义——请显式携带 pluginId 解析。`
);

// 容器归属防覆盖——registerViewContainer 内，首主保有
console.error(
  `[ViewContainer] 容器 "${containerId}" 已归属插件 "${existingOwner}"，插件 "${pluginId}" 的声明被忽略（首主保有）。`
);

// 解析期多命中 fail-loud——声明扫描基元内
console.error(
  `[ViewContainer] 裸 viewId "${viewId}" 解析到 ${matches.length} 个视图（${matches.map(m => `"${m.pluginId}:${m.viewId}"`).join(", ")}）。
  歧义——调用方必须携带 pluginId 精确寻址，或插件改名。`
);
```
