**归口设计：** 边界 ~156 处（preload 三兄弟 + linkdesk-api.ts）不做孤立 patch——先定义 **IPC wire DTO 契约类型**（一处定义，壳/池/插件作者三处消费），函数签名接上后 body 内 any 大半自动消除或收窄。真正无法定型的（Monaco 内部、动态模块加载）落 `unknown` + 守卫，不落 any。插件侧 + 壳 src 属纯债，同原则逐修。

### §3.2 294 处"疑似 pluginId 硬编码比较"（no-restricted-syntax）

现 selector `BinaryExpression[operator=/^[!=]==?$/] > Literal[value=/^[a-z]/]` 匹配**任何**与小写字符串字面量的比较——误伤率极高（例：`label === "typescript"`、`distribution !== "user"` 都是合法 tag 判别，与 pluginId 无关）。真 pluginId 硬编码只占一小撮。

**收窄设计（#95）：** selector 限定左操作数为名字含 `pluginId`/`plugin` 的 MemberExpression/Identifier——294 → 预计 20-40 处真违规。顺手补盲点：现规则拦不住 `switch (pluginId) { case "literal" }` 和 `arr.includes("literal")`——同一危害类三种写法只拦一种，归一化不完整。

**剩余比较分类归口（#96）——三类，每类有归一化终点，不做 294 个孤立 patch：**

1. **跨堆协议值**（layout 的 location/mode、distribution、panel location……壳写池读的 wire 字符串）：两边各写一遍裸字面量 = v2.6"一个 bug 多个地方"的缝 → 归口 wire 契约类型模块的 union literal type（与 #97 同模块），壳池双端 import type；
2. **进程内 closed union 判别**（`item.location === "top"` 等，类型本身已是 union）：字面量就是类型安全值，**不提取常量**（形式主义、常量爆炸反而脏）；同一字面量重复 3+ 处才提；
3. **可疑处**（对 `string` 类型比字面量）：逐个修。
