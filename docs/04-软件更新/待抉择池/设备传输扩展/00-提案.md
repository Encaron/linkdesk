# 设备传输扩展（USB HID / BLE）· 任务提案

> **状态：待硬件**（2026-11-25 从「AI 门外契约面补齐」剥离）· 归属：通用能力底盘（轴三）
> **开工条件**：用户手上有对应硬件（HID 或 BLE 任一）并可接本机实测；⛔ 无硬件不写代码。

## 一、目标

给宿主补 `hid` / `ble` 两个 `DeviceTransport`，让 HID/BLE 设备复用已落地的设备会话契约
（属主/幂等/僵尸/recover 全部不用重做）。

## 二、进场只读这些（⛔ 不要重读整个已归档系列）

1. 本目录 `01-USB-HID-BLE传输层.md`（范围、要补什么、验收）；
2. 已归档契约的两节（**只读 §八**）：
   - [14-设备会话共享契约 §八](../../已落地/AI门外契约面补齐/14-设备会话共享契约.md)（transport 接口/六条不变式/能力闸）；
   - [15-插件间事件契约 §八](../../已落地/AI门外契约面补齐/15-插件间事件契约.md)（`device.added/removed` 事件面）；
3. 代码参照（可选）：`electron/services/deviceSession/`（registry/transport/tcpTransport）与 `dev-fixtures/device-probe/`。

## 三、任务拆分（按顺序）

1. `hid` transport（node-hid / hidapi；热插拔差分；Windows 驱动权限）；
2. `ble` transport（noble；扫描/连接/断连 → stale）；
3. 原生依赖打包（asarUnpack＋重建链＋冷启动冒烟）；
4. `device.added/removed` 接入事件总线；
5. 夹具/验收（见 01 §四）。

## 四、验收（拿到硬件后）

- 第二/第三个设备插件只读 §八 规格即可做全，不引用 serial 代码；
- 拔插语义与 3a 同口径（`open:false/stale:true` → `recover` 成功有耗时）；
- `doctor` 设备断言对 `--profile hid-*` / `ble-*` 成立；
- 打包实例（非 dev）能加载原生依赖。

## 五、不做的代价

HID/BLE 设备只能各写壳外桥，AI 无法经 LinkDesk 统一控制它们；旋钮/手柄/传感器/穿戴进不了生态。
