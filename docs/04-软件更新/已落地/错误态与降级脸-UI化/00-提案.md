## 一、现状（详证 = [01-现状出现点清单.md](01-现状出现点清单.md)）

同一条渲染管线（`PluginComponent` → 主区 tab / 侧栏 / 底部面板 / 悬浮面板 / 对话框 / 状态栏 / 工具槽，共 9 个挂载点）上的四个兜底态，**待遇割裂**：

| 态 | 现状实现 | 视觉待遇 |
|---|------|------|
| 加载中 | `ViewSkeleton`（呼吸骨架，全 token，reduced-motion） | ✅ **验收级设计**＝家族视觉基准 |
| 插件不可用 | `PluginUnavailable`（`plugin-missing-view`） | 🔴 **全仓零 CSS 规则**——裸文本顶格左上，观感＝「坏了个东西贴在角落」 |
| 视图崩溃 | `ErrorBoundary` 内置 crash 界面 | 🔴 28 行 **inline style**：无类名、无变体、无窄容器适配、无屏读增强；`「xx」已崩溃` ＋ 裸 button |
| 空态 | 插件自判 ＋ `ViewEmptyContentDescriptor`（when 条件） | ◐ 机制通用，视觉各插件自理（壳三页里 `ldk-rn-empty` 是验收范式） |

**病灶四条**：① 降级态零样式；② 崩溃态组件化缺失（inline style 绕开类名/变体/适配体系）；③ 同家族不同待遇（加载有骨架、崩溃没脸）；④ 语义色缺位（`--error` token 已有却没用上；「没有这只插件」是**状态不是错误**——`PluginComponent.tsx:37` 注释原话哲学——却与崩溃共用「丑」这一种表达）。

**参照组（新家族的视觉与文案基准）**：`ReleaseNotesPoolView` 空态 `ldk-rn-empty`＝图标（20px lucide）＋标题＋说明＋动作区（primary 重试 ＋ 次级）——壳三页里已验收的错误态范式；`ldk-view-skeleton`＝加载态基准。**新家族不发明第二套语言，是把这套语言推广到全家族。**

## 二、新设计（详图 = mockups/01）

**统一降级脸家族 `ldk-fallback`（暂名），五段结构**：

```
图标（codicon 真字形，随变体换形换色）
→ 标题（一句话事实，md 号 600 字重）
→ 说明（一句下一步建议，sm 号 secondary 色）
→ 动作区（primary 重试 ＋ 次级动作 ＋ 详情披露）
→ 诊断详情（<details> 默认收起，mono 键值，屏读可读）
```

- **三变体**：`--crash`（图标点 `--error` 色）/ `--missing`（全套中性 muted——「没有」≠「坏了」）/ `--empty`（中性）。
- **三尺度（通用功能＝一张脸管九个挂载点）**：`--full`（主区 tab / 底部面板等横宽容器：图标 24px、五段全出——横宽不改尺度，原样复用）／ `--panel`（侧栏 section 窄栏：图标 16px、说明收敛、详情不渲染——窄容器不披露，靠 AI 通路读）／ `--micro`（状态栏条目 / 工具槽极窄档：横排单行、无说明、小重试钮——砍视觉不砍通路）。**机制保证**：九个挂载点全走同一条 PluginComponent / ErrorBoundary 加载链，**新 zone 挂上即自动继承这张脸，零新增代码**；尺度与变体由容器 props 决定，与挂载点解耦。
- **纪律**：全 token（`--font-size-*` ＋ `calc(N * var(--ui-scale))`，零手填 px/hex）；`prefers-reduced-motion` 静止；屏读 role/aria 齐备；类名 `ldk-` 族段（共享件纪律，硬约束 23）。
- **动作反馈三分工**（2026-11-21 用户验收 mockup 时拍板方向）：**重试的即时反馈 → 轻 toast**（真源 `src/pool/floating/transient-toast/`，底部居中、TTL info 6s / success 5s、栈 ≤3 最旧先退场——「正在重试「xx」…」）；**「查看详情」→ 页内原位展开**（诊断是多行结构化数据，轻 toast 两行 clamp 装不下，⛔ 不进 toast）；**回退链通知（母案 §四-7）→ 右下铃铛面板常驻**（失败待办住那）。三通路各司其职、⛔ 互相客串（历史教训：右下角同角落堆两层）。
- **AI 取数＝命令直取，不读屏**（2026-11-21 用户点名）：详情五段数据由结构化命令供给（建议 `app.getViewFallbackData`，meta 必带 description＋params 出契约）——AI 经 ai-bridge / linkdeskctl / MCP **直接拿同一份 JSON**，GUI 页内展开只是同一数据的另一个渲染；**⛔ AI 读屏**（截图→视觉理解→猜坐标）不是通路（硬约束 26③「读结构化状态 → 调命令带参数 → 读结构化结果」）。aria/role 语义面向**视障用户的读屏软件**（无障碍面），与 AI 通路无关——两个「读」，一个是无障碍、一个是 AI，不许混。
- **全脸可命令调出**（AI 友好化终极判据，用户 2026-11-21 口述「哪怕没有崩溃，我让 AI 把崩溃页面调出来，AI 都可以调出来」）：三张脸**不依赖真实故障**即可被命令主动渲染——建议 `app.previewFallbackFace`（参数 variant / scale / name，meta 出契约）；演示、视觉验收、AI 验证共用同一入口。推论：GUI 的一切能力都同时存在于命令面——所见 AI 能见、所操作 AI 能操作、指哪打哪。
- **反面判据＝模拟鼠标不是通路**（用户 2026-11-21 口述 LabVIEW 血泪史）：一切操作只能靠人拖拽、AI 只能截图分析＋模拟鼠标点击/拖动的软件＝**AI 不友好化的下限**——「远没有直接在程序里写 C 语言代码方便快捷」。本档验收据此反向执行：三张脸的**每一条能力**（查看 / 调出 / 重试 / 详情 / 将来的切换 / 回退）都以**结构化命令可达**为唯一合格线（硬约束 26③）；GUI 只是命令面的渲染之一，不是能力的本体——能力本体永远住在命令与契约里。
- **变体判定零新增机制**：`crash` ＝ ErrorBoundary catch（既有）；`missing` ＝ loader 存在性闸 null（E6#162 既有）；`empty` ＝ when 空态 ＋ 插件自判（E5.6#11g 既有）——**全部是既有出口换脸，判定逻辑不新增**。
- **文案规格**：说明区两行（行1 事实 · 行2 出路，如「重试即可恢复；」／「若反复出现，请展开详情查看原因。」）；**禁口语化**（「通常」「试试」类词——「请更换关键词」不写「换个关键词试试」）。
- **加载态不并入**：`ViewSkeleton` 已是验收件，保持独立——本家族只收「结果不是内容」的脸（崩了/没有/空），加载是「内容在路上」，语义不同。

## 三、衔接《万物皆可插件-表现层可替换化》（契约预留，机制不抢跑）

| 槽位契约（那边 §3.0–3.2 的铁律） | 本设计的预留 |
|---|---|
| **铁律 A 数据同源**（渲染者只准走命令取数） | 五段内容全部由**结构化数据**驱动：插件 id / 变体 / 错误消息 / 建议动作——渲染体只画；将来命令化（如 `app.getViewFallbackData`，建议名）后任何渲染者可取同一份数据 |
| **§四-4 降级脸归 emptyStage 槽位族** | 本家族就是那张「内置脸」的定型稿；将来 `contributes.renderers` 落地时整套可被插件替换，替换体照走同一五段契约（数据同构 ⇒ 换皮零迁移成本） |
| **§四-7 回退链机械化**（替换体崩溃→自动回退内置实现＋一条通知） | 本内置脸＝**回退链的终点站**：任何替换体崩了，用户看到的兜底就是它——这决定了它必须先于槽位机制做到验收级 |
| **铁律 B 双通道归一**（切换/回退命令化） | 动作区按钮全部指向**命令位**（重试＝重新加载视图命令；详情＝结构化读取），GUI 与 AI/CLI 最后指向同一通路（硬约束 26）；命令 id 与注册随槽位落地同笔做，本档只留位 |
| **终态判据：命令面＝跨皮稳定契约**（用户 2026-11-21 口述「未来即便换成通用 UI 的形式，底层命令不变」） | 将来皮被 `contributes.renderers` 槽位替换，**同一批命令与参数照常工作**——AI 与用户的操作面永不因换皮重写；命令 id 是比任何一张脸都长寿的 API |

**一句话**：本档＝那张脸的「皮」的定型＋「骨」（数据/动作/回退）的接口预留；槽位总线的拍板与实施在母案那边，两边互不阻塞。

## 四、工程纪律映射（用户点名逐条落位）

| 纪律 | 落位 |
|---|---|
| 高内聚低耦合 | 一个家族一个目录（建议 `src/pool/shared/fallback/`）；五段结构与变体全在该目录内收口；消费点只换 props |
| 无硬编码 | 全 token：色 `var(--xxx)`、字号 `--font-size-*`、尺寸 `calc(*var(--ui-scale))`、圆角 `--radius-*` |
| 无死代码 | 落地同笔：删 `PluginUnavailable` 裸实现与 `ErrorBoundary` 28 行 inline style（两处替换为新家族消费），不留双份实现（R4「第二份实现」门禁同款纪律） |
| 可替换化 | 渲染体走 `@linkdesk/ui` 导出契约纪律（R6/G1）——将来槽位替换体与内置体同一契约，天然可换 |
| 归一化 | 与 `ldk-rn-empty` 验收范式同构；九个消费点收敛到一张脸（消除一类多实现残余） |
| AI 友好化 | ① 诊断详情＝同一份结构化 JSON 的两个渲染：GUI 页内展开 ＋ AI 命令直取（ai-bridge / linkdeskctl / MCP，**⛔ AI 不读屏不截图**，硬约束 26③）；② 动作全部指向命令位（GUI 点击与 AI 调用同源，硬约束 26①）；③ `--panel`/`--micro` 尺度不砍 AI 通路（只砍视觉披露，命令照返回） |
| 禁止平铺 | 目录族结构（组件 + css + 变体同夹），⛔ 不在 `shared/` 根散放 |
| 控代码量 | 组件预估 ≤120 行 ＋ css ≤160 行（含变体与两尺度）——超了拆 `FallbackFace`（脸）/ `FallbackActions`（动作区）/ `FallbackDetail`（披露）三件 |

## 五、实施落点建议（拍板后照此立单；当前不动任何代码）

1. 新建 `src/pool/shared/fallback/`：`FallbackFace`（五段结构＋三变体双尺度）＋ `.css`；icon/文案走 codicon ＋ `t()`。
2. 替换消费点：`PluginComponent.tsx` 的 `PluginUnavailable` → `<FallbackFace variant="missing">`；`ErrorBoundary.tsx` 内置 crash 界面 → `<FallbackFace variant="crash">`（ErrorBoundary 机制层不动，只换脸）。
3. 九个消费点自动收口（都经前两者）——`PoolSectionStack` / `TabContentLayer` / `FloatingPanelHost` / `DialogHost` / `PoolStatusBarComponent` / `PoolToolbarSlot` / `PanelZone` / `SidebarZone` 零改动；三尺度由各容器现有形态决定（主区 / 底部面板＝full，侧栏＝panel，状态栏 / 工具槽＝micro），消费方只传 props。
4. i18n 新词条随件登记；`audit:nonnaming` 六尺过一遍；若 `--panel` 窄容器需要新断点逻辑，落 css 容器查询或 props 尺度（实施时定）。
5. 状态栏通知面板失败行（`ldk-notif-*`）**不在本档范围**——它有自己的设计系统与三段结构（18 档 §五 I），只对齐动作语义（重试优先于取消的视线纪律已存在）。

## 六、开放问题（拍板后移 §六表；AI 建议值已录 ⭐，非拍板）

1. **动作集第一批给哪些**：重试必给；「打开插件管理器」（missing 变体次级动作）⭐ 给——市场/管理器已是插件，壳只引命令 id 不碰插件内部（硬约束 10 不破）；「查看详情」⭐ 给 full 尺度，panel / micro 尺度不给。
2. **missing 变体要不要写「插件已卸载/未安装」的细分文案**：⭐ 第一批不细分（数据面拿不到可靠细分，别让脸撒谎）；细分随数据命令落地再加。
3. **空态（--empty）是否纳入本家族第一批**：⭐ 纳入设计稿但不强制迁移——各插件自判空态（E5.6#11g）是既有拍板，本家族只提供**可选**统一件，插件愿用即用（归一化不等于强制收编）。
4. **实施时机**：⭐ 攒批独立实施（不依赖母案 M2 槽位机制；契约三件是预留不是阻塞）——可与壳攒批节奏合并发版。
5. **加载超时兜底**（2026-11-21 用户问「加载态与崩溃区分好了没」暴露）：import **永久 pending** 时骨架无限呼吸——「慢」与「挂」用户不可辨（React.lazy 无超时机制，pending 无出口）。⭐ 建议立第四变体 `--timeout`：加载超时（阈值可配，默认 15s 量级，loader 侧计时）→ 转降级脸（hourglass 图标＋「加载时间过长」事实行＋重试出路）——「还在加载」与「等了太久没结果」对用户是两种事实，脸不该装没看见；随第一批实施顺手做。
