> 状态：📋 **蓝图起头**（2026-10-04 用户点名，未立项未拍板）。源码仓尚未建（立项时起 `E:\linkdesk-plugins\official\md-preview`）。🧭 **开单时机（2026-10-05 归口）**：**等两格**——T3 公共 context key（04 案第 2 波）＋编辑器 E2 同屏契约（占位，需本插件立项时两仓对定）⇒ 最早在第 2 波之后；先后见 [04 案 07 §五](../../04-软件更新/待抉择池/文件打开方式与贡献点/07-插件侧适配-文件树与编辑器.md)。
> 一句话：对标 VS Code 的 Markdown Preview Enhanced（MPE）——**单击仍是编辑器**（不抢 `.md` 的默认打开方式），右键多出「MD 预览：侧边打开／导出 HTML」；分屏左代码右效果，远期同屏滚动。

## 一、定位与用户故事

用户原话：「html 阅读和 md 文档比较特殊……直接取代单击直接进入预览模式是**极其愚蠢的**。VS Code 的处理方法：装了 MPE 这类插件后，进入编辑器界面右键会多出『MPE:打开侧边预览』等菜单项……甚至可以实现同屏滚动；『打印为 HTML』则命令面板会提示选择保存地址。」⇒ 本插件是**次要打开方式**的样板：单击归编辑器（`.md` 在 editor 的 fileAssociations 45 名单里，本插件**不声明**它），预览走**菜单贡献＋命令**。

## 二、贡献什么

| 声明 | 作用 |
|:--|:--|
| `contributes.menus.fileContext` | 三项：`MD 预览：侧边打开`／`MD 预览：新标签打开`／`导出为 HTML`，全部 `when: "resourceExtname == .md"`（公共 context key = 壳案 [T3](../../04-软件更新/待抉择池/文件打开方式与贡献点/01-方案与落点契约.md)；未落地前 `when` 写宽＋判据降级） |
| `contributes.commands` | 同名三命令进命令面板（命令 id 归属纪律：`md-preview.*`） |
| `contributes.configuration`（可选） | 预览字号/主题/同步滚动开关——走设置页现成渲染，零新控件 |
| **不声明** `fileAssociations` | **不抢单击**——这是本插件与 PDF/图片阅读器的本质区别；哪天做「纯阅读版」变体也是让用户在选择器里自己换默认（壳案 T2 语义），不改本仓声明 |

**多家并存（用户 2026-10-04 追问 4 的直接答案）**：右键注册几都无所谓、互不知晓——作者 1 与作者 2 各自声明各自的 `menus.fileContext` 项，用户右键看到一列「以 A 预览／以 B 预览」挑着用；壳侧选择器也会把它们并列列出。**次要方式不存在「默认」之争**（单击永远归 editor）；若某家非要声明 `.md` 抢单击，那是壳案 D7 仲裁的普通情形（用户没选过=先激活先得＋提示，选过=覆盖表说了算），本插件不参与。

## 三、打开逻辑与渲染

右键的文件路径（菜单 context）或当前活动文件（命令面板入口）→ `filesystem.readTextFile` → markdown 引擎 → HTML → 插件视图渲染（只读，**编辑仍归 editor 插件**——边界不重叠）。侧边打开 = 开第二个标签进既有分屏形态（立项时对现 API 定形态：分屏／并排标签／悬浮面板三选，池侧机制都在）。

## 四、引擎选型

| 方案 | 结论 |
|:--|:--|
| **markdown-it（推荐）** | 插件生态全（GFM/脚注/任务列表）；**渲染 token 自带源行映射（`token.map`）→ 每块 DOM 挂 `data-line` —— 这是同屏滚动的地基**，选型时就按这个能力选 |
| highlight.js | 代码高亮（轻）；shiki 精美但重，M2 再议 |
| marked | 快但无源行 map ⇒ 与同屏滚动冲突，**否** |
| remark | 太重，否 |

## 五、同屏滚动（分层承诺，不写做不到的票）

| 层 | 形态 | 依赖 |
|:--:|:--|:--|
| MVP | 预览打开即渲染**当前磁盘内容**＋「刷新」钮；编辑器改动**不自动**进预览 | 无（零跨插件契约） |
| 增强 | **editor→预览单向同步**：editor 插件贡献「滚动比例／内容变更」事件（节流广播），预览按 `data-line` 锚点定位 | 需要 editor 侧配合——已单独立格：[04 案 07 §二 E2](../../04-软件更新/待抉择池/文件打开方式与贡献点/07-插件侧适配-文件树与编辑器.md)（**占位未实施**，等本插件立项时两仓对契约）。**这是插件间契约，壳不掺和** |
| 远期 | 预览→editor 反向同步（点预览跳源行） | 同上，E2 扩展 |

## 六、导出 HTML（对标「打印为 HTML」）

命令 → 宿主 dialog 选保存路径（**先例：工作区导入导出**的 `dialog.openWorkspaceImport` 通道，additive 加一条保存对话框）→ 离线单文件（内联 CSS＋高亮样式，图片走相对路径原样引用）。「批量打印」M2 再议。

## 七、任务布置（立项时展开）

1. 本夹展开 → 拍板引擎／侧边形态／M1 范围。
2. 起仓 → 声明（menus＋commands）→ M1（渲染＋刷新）→ 三门 → publish → 收录（不进种子）。
3. 验收：右键 .md 出三项、右键 .txt 不出（T3 落地后）；导出 HTML 双击可开；与 editor 同屏各改各的不互抢焦点。

## 八、边界

不做编辑（那是 editor 的地盘）；不做 md→pdf；HTML **阅读器**另案（同属「次要打开方式」家族，机制同本件——将来立项照抄本夹骨架）；不做壳侧任何机制。
