# 七大陷阱逐条验证——E5.5#45

> 📖 **来源：** [[multi-webview-pitfalls-and-solutions]]——7 大陷阱，每一条都是多 WebView 特有的隐蔽 bug 类别。
> E5.5#45 逐条验证——确认每个陷阱有防御方案且验证通过。

## 陷阱 1：CSS 样式同步 + 缩放联动

**问题 A（CSS）：** 插件的 CSS 变量/主题色需要从壳 WebView 同步到每个插件 WebView。preload-plugin.ts 必须有 `theme:changed` 监听。

**问题 B（Zoom）：** 🔴 **2026-08-07 新发现——E5.5 文档原缺。** 每个 WebContentsView 有独立的 `zoomFactor`（默认 1.0）。用户 Ctrl+/- 缩放壳 WebView → 只有壳的 TitleBar/TabBar/StatusBar 变大，插件 WebView 保持 100%——视觉断裂。反过来插件内 Ctrl+/- → 只有那个插件缩放。**和单 WebView 行为完全不同。**

**防御方案 A（CSS）：**
```typescript
// preload-plugin.ts
ipcRenderer.on('theme:changed', (_event, theme) => {
  for (const [key, value] of Object.entries(theme.colors)) {
    document.documentElement.style.setProperty(`--${key}`, value);
  }
});
// 启动时立即获取当前主题（不等第一次广播）
ipcRenderer.invoke('theme:getCurrent').then(theme => {
  for (const [key, value] of Object.entries(theme.colors)) {
    document.documentElement.style.setProperty(`--${key}`, value);
  }
});
```

**防御方案 B（Zoom）——E5.5#25：**
```typescript
// electron/main.ts——壳侧 zoom 监听
mainWindow.webContents.on('zoom-changed', (event, zoomDirection) => {
  const zoomLevel = mainWindow.webContents.getZoomLevel();
  ipcBridge.broadcast('window:zoomLevelChanged', { zoomLevel });
});

// preload-plugin.ts——插件侧 zoom 接收（模块顶层，不等 React）
ipcRenderer.on('window:zoomLevelChanged', (_e, { zoomLevel }) => {
  _suppressZoomEvent = true;
  webFrame.setZoomLevel(zoomLevel);
  _suppressZoomEvent = false;
});
// 启动时主动拉取
ipcRenderer.invoke('window:getZoomLevel').then(zoomLevel => {
  webFrame.setZoomLevel(zoomLevel);
});

// 插件内 Ctrl+/- → 转发到壳（不自己缩放，防止不同步）
// preload-plugin.ts 模块顶层
const _zoomChangedHandler = (_e, zoomDirection) => {
  if (_suppressZoomEvent) return; // IPC 到达的 setZoomLevel → skip，防死循环
  ipcRenderer.send('window:zoomRequest', zoomDirection);
};
webFrame.on('zoom-changed', _zoomChangedHandler);
```

**验证：**
- [ ] 切换深色/浅色主题 → 插件 WebView 的背景色同步更新
- [ ] 插件 WebView 加载完成时已有正确主题（不闪白/不闪黑）
- [ ] `theme-sync.ts` 中的广播频率合理（不过度频繁）
- [ ] Monaco 编辑器的 `loadThemes:true` 正常（Monaco 暗色字体竞态不复现——[[monaco-dark-font-race-condition]]）
- [ ] 🔴 壳 Ctrl++ → TitleBar + 所有插件 WebView 内容同步放大 20%
- [ ] 🔴 壳 Ctrl+- → 同步缩小
- [ ] 🔴 壳 Ctrl+0 → 同步归零
- [ ] 🔴 插件 WebView 内 Ctrl+/- → 转发到壳 → 全窗口统一缩放（不各自为政）
- [ ] 🔴 `zoomIndependent: true` 的插件不跟随窗口级缩放
- [ ] 🔴 Monaco Ctrl+鼠标滚轮 → 仅编辑器字体变化，壳不变（独立事件）
- [ ] 🔴 重启后 zoomLevel 持久化恢复（`window.zoomLevel` 配置项）
- [ ] 🔴 无转发死循环——`_suppressZoomEvent` guard 正确

## 陷阱 2：IPC 竞态

**问题：** IPC 消息在 React mount 前到达 → 事件丢失。preload 模块级缓冲是唯一安全解法。

**防御方案：** 已修复——`_readyBuffer` + 模块级 `ipcRenderer.on` 模式。

**验证：**
- [ ] `notifyReady` 在任何时序下正确送达（快速/慢速启动）
- [ ] 多个插件并发创建 → 无 ready 事件丢失
- [ ] React StrictMode 双重 mount → 无重复 ready 回调
- [ ] 插件 WebView reload → ready 事件正常

## 陷阱 3：内存积累

**问题：** 每个 WebContentsView (~50-100MB 内存) + JS heap + DOM tree。长时间运行多个插件→内存积累。

**防御方案：**
- WindowManager `scheduleViewDestroy` 60s grace period
- `flushGracePeriods` 1GB 内存阈值
- 未激活 WebView 的 background throttling

**验证：**
- [ ] 打开/关闭 10 个不同插件标签页 × 10 轮 → heap 无明显增长（< 50MB 增量）
- [ ] 内存达到 1GB 阈值 → flushGracePeriods 触发 → 未激活 WebView 被回收
- [ ] 回收后内存下降至少 100MB
- [ ] 无 renderer 进程泄漏——关闭标签页 60s 后对应进程退出

## 陷阱 4：调试困难

**问题：** 每个 WebContentsView 有独立的 DevTools。调试跨 WebView 通信需要同时看多个 DevTools。

**防御方案：**
- `window.linkdesk.debug.getBroadcastLog()` → 查看最近 50 条广播
- `window.linkdesk.debug.getPushQueue(pluginId)` → 查看某个插件的 push 队列
- `window.linkdesk.debug.getWebViewInfo()` → 列出所有 WebView + 状态

**验证：**
- [ ] `getBroadcastLog()` 返回正确的广播历史
- [ ] `getPushQueue()` 返回插件的待处理消息数
- [ ] `getWebViewInfo()` 返回的 WebView 数和任务管理器一致
- [ ] DevTools 可以通过 `pluginViews.toggleDevTools(pluginId)` 打开/关闭

## 陷阱 5：开发体验

**问题：** 多 WebView 下 Vite HMR 复杂——改壳代码要刷新壳 WebView，改插件代码要刷新对应插件 WebView。Vite dev server 端口竞争。

**防御方案：** 单 WebView 模式（dev 模式不启用多 WebView）
```typescript
// loader.ts
const USE_MULTI_WEBVIEW = !import.meta.env.DEV;  // dev 永远单 WebView
```

**验证：**
- [ ] `npm run electron:dev` 下 → 单 WebView 模式（所有插件在同一 WebView）
- [ ] `npm run build` + 启动 → 多 WebView 模式
- [ ] Vite build 后切换回 dev → 不残留多 WebView 状态

## 陷阱 6：视觉接缝

**问题：** 壳 WebView 和插件 WebView 之间可能有 1-2px 缝隙（舍入误差），背景色不一致时可见。

**防御方案：**
- 插件 WebView 的背景色走 CSS 变量（同壳）
- bounds 计算取整（`Math.round`）

**验证：**
- [ ] 深色主题下——壳和插件 WebView 之间无可见缝隙
- [ ] 浅色主题下——壳和插件 WebView 之间无可见缝隙
- [ ] 窗口 resize 后——无缝出现
- [ ] 标签页切换后——无缝出现
- [ ] 侧栏展开/收起后——无缝出现

## 陷阱 7：安全——contextBridge 隔离

**问题：** `contextBridge.exposeInMainWorld` 暴露的 API 可能是攻击面。插件 WebView 的 preload 和壳 WebView 的 preload 暴露不同 API。

**防御方案：**
- `preload-shell.ts` 暴露 20 个 `linkdesk.*` 命名空间（管理面大）
- `preload-plugin.ts` 暴露 26 个 `linkdesk.*` 命名空间（功能面大）——但去掉了 `pluginViews.create/destroy` 等管理能力
- `contextKey._getValue` 正确区分壳 vs 插件——只在 `preload-plugin.ts` 中注入

**验证：**
- [ ] 插件 WebView 不能调用 `window.linkdesk.pluginViews.create()`（未暴露）
- [ ] 插件 WebView 不能调用 `window.linkdesk.pluginViews.destroy()`（未暴露）
- [ ] 插件 WebView 不能访问壳的菜单注册（未暴露）
- [ ] `contextKey._getValue` 在壳 WebView = 壳 contextKey 的 `_store` → `_getValue`（值为 `'shell'`）
- [ ] `contextKey._getValue` 在插件 WebView = 插件 preload 注入的 `_getValue`（值为 `'plugin'`）
- [ ] 快捷键事件根据 contextKey 区分——壳快捷键只在壳触发，插件快捷键在对应插件触发
