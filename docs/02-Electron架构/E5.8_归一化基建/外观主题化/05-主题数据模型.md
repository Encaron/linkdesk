## 1. 三个概念

| 概念 | 定义 | 对应 UI |
|:--|:--|:--|
| **配方 Recipe** | 一个主题文件 = 一个完整外观配方「包」：风格域共享 + 配色变体列表 | 主题选择器卡片（ThemePicker） |
| **配色变体 Colorway** | 颜色域的一组具体取值（`--bg-*`/`--text-*`/`--accent`…） | 配色下拉（app.themeColor 动态 enum） |
| **域 Domain** | token 命名空间（[03 §1](03-域贡献者与混搭.md) 六域） | 混搭的来源选择行（[10](10-混搭设计.md)） |

- **风格 vs 配色分离**（[03 §4](03-域贡献者与混搭.md) 实证）：mint-soda 4 变体共享 Claymorphism 风格，只换配色 → schema 用 `appearance`（风格域）+ `colorways[]`（颜色域）两个正交轴表达。
- **单配色主题** = 省略 `colorways`，`colors` 平铺顶层——向后兼容现状 `{name, type, colors}`。

## 2. 完整 schema（mint-soda 配方包为例）

```jsonc
{
  // ── 身份 ──
  "id": "mint-soda",              // 全局唯一 = 配方 id（惯例 = 插件短名）。app.theme 存这个
  "name": "清凉薄荷包",            // 配方显示名（主题选择器标题）
  "type": "light",                // "light" | "dark"（沿用 uiTheme 语义，标题栏按钮/深浅底用）

  // ── 风格域（单值）── 共享给所有配色变体；缺的域/键不写（稀疏）
  "appearance": {
    "radius": {                   // 键 = [02 §2.2](02-变量契约.md) 八档子集（xs/sm/md/lg/xl/2xl/pill/full）
      "sm": 6, "md": 10, "lg": 16, "xl": 20, "2xl": 26   // 只写想覆盖的档，其余继承 :root
    },
    "glass": {                    // 键 = [02 §2.3](02-变量契约.md)（--glass-blur/saturate/tint/opacity）
      "blur": 14,                 // px；0 = 关。给上限（性能预警，02 待拍板数值）
      "saturate": 1.2,
      "tint": "rgba(255,255,255,0.55)",
      "opacity": 0.9
    },
    "font": {                     // 键 = --font-ui/--font-mono（壳零内置字体，[01 §5](01-设计总纲与边界.md) 决策 1）
      "ui": "assets/NotoSansSC.woff2",   // 两种形式：①资产相对路径 → getAssetPath(pluginId, path) ②系统字体族名字符串（如 "Noto Sans SC"）
      "mono": "JetBrains Mono"           // 字体插件 = 只贡献 font 域的主题/插件（[03 §6](03-域贡献者与混搭.md)）
    },
    "background": {               // 键 = [02 §2.4](02-变量契约.md)（--bg-image/--bg-opacity/--bg-mask）
      "image": "assets/bg.png",           // 资产相对路径 → getAssetPath
      "opacity": 0.9,
      "mask": "rgba(0,0,0,0.25)"          // 压暗保证前景可读
    },
    "surface": {                  // 菜单/表面域（per-surface 精调，可选——[04 §4](04-两层调节与设置页.md)「主题作者管精致」）
      "menu-blur": 12,
      "menu-radius": "lg"                 // 引用 radius 档位名
    }
  },

  // ── 配色变体（颜色域多值）── 每个 = 一组完整颜色 token；键 = [02](02-变量契约.md) 颜色族
  "colorways": [
    { "id": "mint-soda", "name": "薄荷苏打",
      "colors": { "bg-window": "#FFFBF5", "bg-card": "#FFFFFF", "text-primary": "#1F2933",
                  "accent": "#2BA876", "border": "#E4EDE8" /* 未列出的颜色 token 继承 :root */ } },
    { "id": "mint-dew", "name": "薄荷露",
      "colors": { "bg-window": "#F7FBF8", "accent": "#3E9E8C", "border": "#DCEBE4" } },
    { "id": "sea-salt-mint", "name": "海盐薄荷",
      "colors": { "bg-window": "#F6FAFD", "accent": "#2F8F9E", "border": "#DCE8F0" } },
    { "id": "lime-mint", "name": "青柠薄荷",
      "colors": { "bg-window": "#FBFFF5", "accent": "#7BB44A", "border": "#E6EFDC" } }
  ]
}
```

**字段规则：**
- 顶层 `colors`（无 `colorways`）= 隐式单配色配方——向后兼容现状平铺格式，**旧主题插件 json 零改造可读**（ThemeEngine 读时归一化：`colorways: [{id: 文件id, name, colors}]`）。
- `appearance` 各域的键 = 变量契约 token 名去掉 `--` 前缀；值 = 裸值（ThemeEngine 写入 `:root` 时拼回 `--radius-sm: 6px`）。
- 颜色域示例只列了变体之间的差异键——**每个变体不必重写全部颜色**（稀疏同样适用，未写的继承 `:root`）。

## 3. 稀疏覆盖与继承

CSS 变量天生稀疏——主题只写拥有的域/键，未定义落回 `:root` 壳默认，**零变化**（[03 §3](03-域贡献者与混搭.md)）。纯配色主题 = 只有 `colorways`；玻璃主题 = `appearance.glass` + 颜色；字体插件 = 只有 `appearance.font`。

## 4. 合并算法（继承链）

```
:root 壳默认（最保守现状）
  ⊕ recipe.appearance（风格域，稀疏）
  ⊕ 当前 colorway.colors（颜色域，稀疏）
  ⊕ 设置层 userOverrides（[08](08-持久化与配置.md) app.*：radius=scale 乘算、glass=绝对覆盖）
  = 生效 token 集 → 写入 :root → 广播 theme:changed
```

```ts
// ThemeEngine.applyRecipe(recipe, colorwayId, overrides)——伪代码
function mergeDomains(recipe, colorwayId, overrides): Record<string, string> {
  const colorway = recipe.colorways?.find(c => c.id === colorwayId) ?? defaultColorway(recipe);
  const tokens = { ...cssDefaults };                          // ① :root 壳默认
  Object.assign(tokens, flattenDomains(recipe.appearance));   // ② 风格域
  Object.assign(tokens, toTokenMap(colorway.colors));         // ③ 颜色域
  for (const [token, v] of Object.entries(overrides)) {       // ④ 设置层
    tokens[token] = isScaleToken(token)                        //    scale（--radius-*）：
      ? px(parseFloat(tokens[token]) * v)                       //    JS 乘算（CSS 不能 var*var）
      : v;                                                      //    绝对覆盖（--glass-* 等）
  }
  return tokens;                                              // 写入 :root + 广播
}
```

> **关键：** 设置层只存**用户覆盖**，不存整套 token——继承链合并发生在应用时，`:root` 永远保留壳默认兜底。

## 5. 对现状的迁移

| 现状 | 迁移后 | 方式 |
|:--|:--|:--|
| 主题文件 `{name, type, colors}` 平铺 | `{id, name, type, colors}` = 隐式单配色配方 | 引擎读时归一化，**数据零改造** |
| mint-soda 1 插件 4 json | 1 配方 json（4 colorways）——可选合并 | 纯数据编辑，可保留 4 文件（4 个独立配方）也可合并（推荐） |
| ThemeEngine `Theme{name,type,colors}` 接口 | `Recipe + Colorway`（可读任一） | [07](07-代码规划.md) A 段 |
| `app.theme: "Dark"/"Light"` | `"dark"/"light"` 壳内置配方 id | [08](08-持久化与配置.md) §4 迁移表 |

## 6. 待拍板点（本文提案，拍板后本文冻结为契约）

1. **字段命名**：`appearance.radius/glass/font/background/surface` + `colorways[].colors`——是否顺眼？备选：`style`/`palettes`。
2. **colorway 是否允许覆盖风格域**：提案**严格只颜色**（正交轴清晰）；若允许多配色各带微调风格（如某配色配更大圆角），加 `colorways[].appearanceOverride` 字段（不默认）。
3. **`surface` 域是否进契约**：菜单/表面 per-surface 精调是「主题作者管精致」的落点，但 token 表未定（02 §2.5 阴影收编后一并定）。提案：schema 预留 `surface`，具体键随 #50.6 冻结。
4. **`id` 与插件 id 的关系**：提案惯例 = 插件短名，不强制校验（第三方可用任意唯一 id）。
5. **font 资产 vs 族名**：提案两种形式都收（资产路径 + 系统族名），渲染层 `getAssetPath` 统一解析——待确认是否需要只收一种。
