## 6. ESLint no-core-import-in-plugin 规则缺口核对（已收紧——E5.8#20-d）

规则：[eslint-local-rules.js](../../../../eslint-local-rules.js) `noCoreImportInPlugin`。**原两条豁免路径 = 为何 10 处全漏网**：

1. **测试文件整文件豁免**：`/__tests__|\.test\.|\.spec\./` 匹配 → 直接 `return {}`。理由：vitest 单进程与壳同 JS 堆，"多 WebView 静默失效"前提不成立。
2. **纯类型 import 豁免**：`importKind === "type"` → return。理由：类型擦除后零运行时耦合（E5.7#80）。

**E5.8#20-d 拍板收紧（#18 决策落执行）：**
- **纯类型 import 豁免取消**——type import 恰恰是插件依赖 @src/core 源码树的证据（插件作者拿不到独立契约文件才偷 core 源码类型，违反插件独立铁律）。契约文件通车后一律走 `@linkdesk/contracts`。
- **测试文件豁免取消**——vitest 单进程理由不成立，测试替身照常通过 `vi.mock("@src/core/...")`（CallExpression，非 ImportDeclaration，规则不拦——这是规则边界，非漏洞）。
- **唯一白名单例外**：`ContextKeyService`（测试运行时），登记于 `PLUGIN_IMPORT_WHITELIST`。
