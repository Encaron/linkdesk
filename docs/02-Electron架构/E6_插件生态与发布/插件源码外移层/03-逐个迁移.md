# 7.2 逐个迁移——搬一个、闭环一个

> **任务号：** E6#99 · **前置：** 7.1（出口打通——搬过去必须能构建） · **产物：** 每只发货插件一个独立 GitHub 仓；壳仓 `plugins/` 下只剩夹具
> **🔴 铁律：** **搬一只 → 构建验证一只 → 上架一只（7.3 轮）→ 壳仓那份删净一只。** 不许「全搬完再全上架」——中间态会长时间存在**双真相源**，而且**没有任何门禁能发现分叉**（内容指纹门禁只管 zip，不管源码）。

## 〇、本轮的物理动作只有三步

```
① 从壳仓历史里抽出该插件的子树 → 变成独立仓（保历史）
② 推到 GitHub + 在插件仓重建 zip（本轮手工，7.4 轮之后改由 sync:bundled 自动）
③ 壳仓同笔删源码 + 拆掉挂在它身上的壳侧绑定
```

难的不是 `mv`，是**第 ③ 步的「拆绑定」**（[总档案 §1.4](00-整理档案.md) 实测 17 处）。

## 二、抽子树保历史（照 L0.15 的先例做，**先试点**）

**先例：** [仓库结构上移/00-迁移档案.md](../仓库结构上移/00-迁移档案.md) 那次全仓上移用的就是 `filter-repo`，**3119 commit 全保、仅 hash 变**。本轮的形态更简单（只抽一个子树）。

### 2.1 红线与前置

- 🔴 **迁移期一律不许改任何插件的目录名**——插件身份今天靠**目录名兜底**，改目录名 = 改插件 id ⇒ **换了一个插件**（老用户安装目录并存两份、墓碑对不上、catalog 两个 id、更新链静默断、插件数据看似丢失；**五条后果全不报错**）。**展开与解法 = [09-命名规范.md §六](09-命名规范.md)**，前置动作 = 7.1 §七 身份显式化（`E6#98g`）。
- 🔴 **绝不在壳仓的工作副本上直接跑 `filter-repo`**——它是**破坏性改写**（会重写整份历史）。做法：**先 `git clone --mirror` 备份**，再在**临时克隆**上做抽取。
  ```
  git clone --mirror E:/linkdesk E:/linkdesk-l7-backup.git   # 备份（先做，且 fsck 校验）
  git clone E:/linkdesk <临时目录>                            # 在临时克隆上抽子树
  ```
- 🔴 **壳仓自身的历史不做 filter-repo**——即：壳仓的过去里**仍然留着** `plugins/<id>/` 的旧历史，这是**可接受且有意保留的**（重跑一次全仓 filter-repo 的风险远大于收益，而且会让所有已有 commit hash 再变一遍）。**本层只做「从今往后不再改它」**，见 §四。
- ⚠️ **实测教训可直接复用**（L0.15 记下的）：「**纯 `--path` 不移前缀**」⇒ 抽子树必须配 `--path-rename` 才能把 `plugins/<id>/` 变成仓库根：

  ```bash
  cd <临时克隆>
  git filter-repo --path plugins/<id> --path-rename plugins/<id>/:
  ```

  ⚠️ **本轮仍要在一个插件上先试点**（验证命令形态 + `git log --follow` 连续 + 文件树顶层正确），**试点通过再批量**——这是 L0.15 已经立过的规矩，别因为「看着简单」跳过。

### 2.2 试点验收（照 L0.15 的机械四验）

- `git log --oneline | wc -l` = 壳仓里该插件子树的 commit 数
- 顶层即插件工程（`plugin.json` / `src/` 直接可见，无 `plugins/<id>/` 套娃）
- `git log --follow src/index.tsx` 历史连续
- 抽出的工作树与壳仓现行 `plugins/<id>/` **逐字节一致**（`diff -r`，排除 `node_modules` / `dist`）

## 三、建仓与推送

### 3.1 建仓

> 🔴 **红线：`git push` 必须等用户本人点头**（memory `push-wait-for-user`）。本轮的「建仓」「推送」两步**都停在「命令已备好、等用户发话」**——AI **不许**自行推送。

- 仓库名（D5：**完全自由**）。建议惯例（**非强制**）：`linkdesk-plugin-<id>` 或裸 `<id>` 二选一，**全批统一**（`hello-linkdesk` / `first-run-setup` 是裸名先例，跟它们或另立新惯都可以，但**要在 7.0 轮落笔那一节里写死选了哪个**）。
- 本地落位：容器目录（D6）——`E:\linkdesk-plugins\official\<id>\`；**容器与容器内任何父级都不建仓**。

### 3.2 重建 zip（本轮手工；7.4 轮之后自动化）

```
cd <插件仓> && npm ci && npm run build      # 产出 <id>.linkdesk-plugin
copy <id>.linkdesk-plugin <壳仓>/bundled-plugins/
```

⚠️ **本轮是过渡态**：zip 手工复制进壳仓。7.4 轮落成 `sync:bundled` 后，**这段手工步骤被命令取代**（届时壳仓侧应只剩 lock 文件 + zip，不再需要人工搬运）。**过渡期不许把这一步写进常规流程文档**，否则会固化下来。

### 3.3 版本号处置

抽出来的插件仓 `plugin.json.version` **保持原值**（1.0.6 / 1.0.28 / …）——搬迁**不是内容变更**，不 bump。但**内容指纹门禁会在壳仓侧要求**：zip 换了 ⇒ `plugin.json.version` 要么不变而内容一致，要么 bump。**实测判断**：若插件仓重建出的 zip 与壳仓现存的**指纹相同**（同样的源码、同样的 SDK 版本、同样的 EOL 归一与固定时间戳）⇒ **`version-bumped`/`identical` 两者皆可过**；若指纹变了 ⇒ **必须 bump**（否则门禁红）。**这一步先跑再判，别猜。**

## 八、🔴 本轮最重的三条账（新发现，且都不是「搬完就好」）

### 8.1 i18n 审计的字典源随插件搬走了（已修，但性质要记住）

`audit-i18n.mjs` 要回答「**源码里的中文串有没有译名**」，而**译名大半住在插件里**——应用级字典 = `lang-defaults` 插件，另有 `marketplace` 等插件的 `i18n/en.json` 也一并注册进同一张资源表。**实测证据**：壳自身的 `src/hooks/usePoolSync/notif.ts` 里「下载中 {{percent}}%」这类 install 进度串，**译名就住在 marketplace 插件的字典里**。

源码一搬走，照旧读文件 ⇒ `translated` 几乎为空 ⇒ **满屏假「缺翻译」**（假红比门禁失效更糟：它会让真红失效）。**处置 = 改读随包种子 zip 里的字典**（`bundled-plugins/*.linkdesk-plugin` 的 `en.json` / `i18n/en.json`）——种子不是「第二份真相源」，而是壳仓里**真实存在的那一份**，语义还更准（被审计的就是用户实际会拿到的字典）。种子缺失 ⇒ **响亮红灯**，决不退化成「查了个空还说 ✓」。修后实测：**359 串全有译名、0 缺翻译**（887 key / 9 个字典条目）。

### 8.2 两份已封存档案…不，是 9 份——断链 109 处的处置

`check-doc-links` 当场红 109 处，**9 份全是已收官层的任务档案**（`03-插件市场/{08,13,14,16,18}`、`插件规范化层/{00,02,03}`、`E3.5-串口监视器UI整改/01`），目标全是 `plugins/{marketplace,editor,file-tree,settings,lang-defaults}/…` 的源码路径。

**处置 = 逐档进 `doc-links-exclude.txt` 挂账**（不是回填）：这些档案记的是**当时那一刻文件在哪**，「把它改写成插件仓路径」不是回填、是**篡改历史记录**（与 E5.5 那条排除同款理由）。⚠️ **口子只对这 9 份开**——活文档里出现指向 `plugins/<已外移 id>/…` 的链接，门禁**照旧红**。

### 8.3 两处「壳侧测试读插件源码」的真耦合（已修，保住了断言）

| 测试 | 原来 | 现在 |
|:--|:--|:--|
| `ThemeEngine/integration.test.ts` | 读 `plugins/theme-*/…` 真实 recipe 做引擎端到端裁决（7 例） | 改读**随包种子里同一个条目**（`readPluginText`：仓内优先、缺则回落种子）。JSZip 异步 ⇒ helper 变 `async`、7 个调用点加 `await`。**断言一条没减** |
