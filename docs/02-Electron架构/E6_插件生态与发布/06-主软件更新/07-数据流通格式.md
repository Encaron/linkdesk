# 07-数据流通格式——IPC 通道 / 消息类型 / TS 类型 / 状态映射

> 对应清单：**E6#57**。本档回答用户要求「细到数据流通格式」——更新能力在主进程↔壳渲染之间怎么传数据，逐通道逐类型写死。

## 一、通道总览（channels.ts 新增 `update.*` 命名空间）

```
主进程（UpdateService）                                   壳渲染进程（useUpdateState）
   │                                                          ▲
   │  ◄── ipcMain.handle（命令，invoke 请求-响应）──           │
   │       update.checkForUpdates    (boolean context)         │
   │       update.downloadUpdate     ()                        │
   │       update.quitAndInstall     ()                        │
   │       update.getState           () → UpdateState          │
   │       update.getReleaseNotes    (version?) → ReleaseNotes │
   │                                                           │
   │  ── broadcast（事件，壳→池 推送）────────────────────►     │
   │       IPC.update.stateChanged   (UpdateState)              │
   │                                                           │
   │  ── broadcast（事件）─────────────────────────────────►    │
   │       IPC.update.progress       (DownloadProgress)         │
```

- **命令通道**（壳渲染 → 主进程，`ipcMain.handle`/`ipcRenderer.invoke`）：请求型，一问一答。
- **事件通道**（主进程 → 壳渲染，`broadcast`）：推送型，状态变更即广播（对标 `theme:changed`/`config:changed`）。
- 池内插件代理：`PROXY_CHANNELS` 白名单可加 `update.getState`（只读状态查询，供第三方「关于」类插件读版本号）——**写命令不进白名单**（更新是壳私事，第三方不得触发下载/重启）。🔴 **`update.getReleaseNotes` 默认也不进白名单**（2026-09-11 定）——发行说明是壳自己的面，第三方没有读它的理由；将来要开放再单独过白名单评审。⇒ **白名单里有且只有一个 `update.*` 通道**。
- **ContextKey 推送**：壳推两个动态 context key——`updateActionable`（显隐门控）+ `updateButtonLabel`（三态文字：下载更新/更新中/重新启动）→ TitleBar 更新按钮 `when` 门控 + `label` 解析（03 §4.2，全文字 + 主题按钮色）。
- **产品信息通道（独立域，非 `update.*`）**：壳渲染 → 主进程 `app:getProductInfo` 一次拉全量 `{product, runtime}`——关于标签页 8 字段（版本/提交/日期/Electron/Chromium/Node/V8/OS，06 §4.2）唯一来源。数据源 = `electron/product.ts`（product.json 三件套 + `process.versions` 动态增强，主进程单例一次读取缓存，02 §2.2）。**与 `update.*` 不同**：产品身份是静态事实，不是更新状态机；`UpdateInfo` 只含「本次更新」字段，不含身份——两路不混。

## 二、通道常量（channels.ts 新增，命名对齐现有风格）

```typescript
export const IPC = {
  ...existing,
  update: {
    getState: 'update:getState',           // 命令：读当前状态
    checkForUpdates: 'update:checkForUpdates', // 命令：手动检查（context: boolean = 是否来自用户主动）
    downloadUpdate: 'update:downloadUpdate',   // 命令：开始下载
    quitAndInstall: 'update:quitAndInstall',   // 命令：重启安装
    getReleaseNotes: 'update:getReleaseNotes', // 命令：拉发行说明（主进程出网 + 落 {userData} 缓存，见 05 §2.4 / 清单 E6#57.8e）
    stateChanged: 'update:stateChanged',       // 事件：状态机变更广播（壳→池）
    progress: 'update:progress',               // 事件：下载进度广播
  },
  app: {
    getProductInfo: 'app:getProductInfo',     // 命令：读产品身份全量（关于页 8 字段）
  },
} as const;
```

> 命名对齐现有 22 命名空间驼峰风格（`filesystemChanged` 工厂等）；`stateChanged`/`progress` 是纯事件名（无 factory），对标 `theme:changed` 常量用法。

## 三、消息类型（TS，主进程 + 壳共用）

```typescript
// —— 共享类型：electron/ipc/types.ts 或 contracts（主进程与壳同源） ——

export interface UpdateInfo {
  version: string;          // 新版本（SemVer，无 v 前缀）
  currentVersion: string;   // 当前版本
  publishedAt: string;      // ISO 发布日期（Release published_at）
  releaseNotesUrl: string;  // 发行说明页 URL（GitHub release）
  downloadUrl?: string;     // 安装器直链（available 之后才有）
  checksum?: string;        // sha256（release asset 元数据）
  size?: number;            // 字节（release asset size）
}

export interface DownloadProgress {
  transferred: number;      // 已下载字节
  total: number;            // 总字节
  percent: number;          // 0-100（整数）
}

export interface UpdateError {
  code: UpdateErrorCode;
  message: string;          // 人类可读（i18n key）
}

// 🔴 2026-09-11 与 01 §2.3/§2.4 对齐——**归因不许压缩成「未知错误」**。
// 检查腿六类（01 §2.3 表）+ 下载腿四类（01 §2.4）：
export type UpdateErrorCode =
  // —— 检查腿（六类，文案必须互不相同） ——
  | 'network'              // 不可达/超时/代理未生效（本腿必走 main-fetch.ts，E6#76）
  | 'rate-limited'         // GitHub 403/429（x-ratelimit-remaining: 0）→ 「稍后自动重试」
  | 'not-found'            // 仓库不存在 / 无 Release（404）
  | 'invalid-response'     // JSON 结构非法 / 缺 tag_name、published_at
  | 'asset-missing'        // 🔴 Release 到手但匹配不到 asset（命名漂移）——不许报成 network
  | 'version-unparsable'   // 🔴 tag_name 非合法 SemVer——与「无更新」分开报，不许静默忽略
  // —— 下载腿（四类） ——
  | 'checksum-mismatch'    // sha256 不符 → 删文件 + 报错
  | 'checksum-unavailable' // 🔴 Release 未附 checksum → 记一笔 + 降级放行（不拦更新，01 §2.4）
  | 'write-error'          // 落盘失败（磁盘满/无权限）
  | 'interrupted'          // 🔴 进程中途退出留下的下载 → 重启后归 `Idle + interrupted`，**不复活 `downloading`**（01 §2.4 / 清单 #57.6f）
  | 'canceled';            // 用户/系统取消

export interface ReleaseNotes {
  version: string;          // 版本号（SemVer，无 v 前缀）；不传 = 最近一版
  publishedAt: string;      // ISO
  body: string;             // Release body（GFM 原文，渲染侧过 MarkdownView + sanitize）
  htmlUrl: string;          // 「在 GitHub 上查看」链接
  historical: ReleaseNotesSummary[]; // 左窄栏版本历史（倒序，最多 30 条，05 §2.4）
}
export interface ReleaseNotesSummary { version: string; publishedAt: string; }

// —— 状态机判别联合（对应 01 §2.1） ——
export type UpdateState =
  | { type: 'uninitialized' }
  | { type: 'disabled'; reason: string }
  | { type: 'idle'; update?: UpdateInfo; lastError?: UpdateError }
  | { type: 'checking' }
  | { type: 'available'; update: UpdateInfo }
  | { type: 'downloading'; update: UpdateInfo; progress: DownloadProgress }
  | { type: 'downloaded'; update: UpdateInfo }
  | { type: 'updating'; update: UpdateInfo }
  | { type: 'ready'; update: UpdateInfo };

// —— 产品身份（关于页数据，来源 electron/product.ts——02 §2.2） ——
export interface Product {
  nameLong: string;      // 产品全名（LinkDesk）
  nameShort: string;     // 品牌短名（LinkDesk）
  version: string;       // 0.1.0（= package.json，product.json 自证）
  commit: string;        // 91e6aa36…（发布时构建注入）
  date: string;          // ISO 发布日（2026-08-30T00:00:00Z）
  quality: 'stable' | 'preview'; // 更新通道（第一版只 stable）
  updateUrl: string;     // 更新源（GitHub releases）
}
export interface ProductRuntime {
  electron: string;      // process.versions.electron
  chromium: string;      // process.versions.chrome
  node: string;          // process.versions.node
  v8: string;            // process.versions.v8
  os: string;            // os.version() / os.release()（win32 读注册表显示名）
}
export interface ProductInfo { product: Product; runtime: ProductRuntime; }
```

## 四、逐通道协议（命令 + 事件 + payload 逐字段）

### 4.1 命令（ipcMain.handle）

| 通道 | 入参 | 返回 | 错误语义 |
|:--|:--|:--|:--|
| `update:getState` | — | `UpdateState` | 永不抛（服务必然有态） |
| `update:checkForUpdates` | `context: boolean`（true=用户主动，false=后台周期） | `UpdateState`（检查触发后的新态） | 网络错 → 态内 `lastError`，不抛 |
| `update:downloadUpdate` | — | `UpdateState`（`downloading` 或 `idle`+error） | 同上 |
| `update:quitAndInstall` | — | `void` | 抛错（无安装器/校验失败） |
| 🔴 `update:getReleaseNotes` | `version?: string`（不传 = 最近一版） | `ReleaseNotes` | 失败 → 缓存兜底；**无缓存才抛**（壳渲染转空态 + `[重试]`，05 §2.4 三态）｜🆕 2026-09-11 补，清单 E6#57.8e |
| `app:getProductInfo` | — | `ProductInfo` | 永不抛（product.ts 单例必有；dev 无 product.json → commit/date 降级 `—`，不崩，06 §4.4） |

> **命令层不新增 `update:openUpdateFlow`**——它是壳命令（`coreCommands` 注册），内部按当前状态分支后调上面三个 IPC 命令。TitleBar 按钮 / 命令面板都走这个命令（03 §2.2）。

### 4.2 事件（broadcast 推送）

**`update:stateChanged`** payload = `UpdateState` 全量（每次状态机迁移广播一次）。

**`update:progress`** payload = `DownloadProgress`（下载中，节流 ≤ 500ms 一次；避免高频刷广播——对标串口数据流节流先例）。

### 4.3 状态机迁移 → 广播时序（完整一局）

```
[后台/手动触发 checkForUpdates]
  handle checkForUpdates(context)
    → state: checking               → broadcast stateChanged {type:'checking'}
    → fetch GitHub latest（经 main-fetch.ts）
       ├ 失败（六类之一）            → broadcast stateChanged {type:'idle', lastError}
       │                               → 手动时：通知面条目 = 该类的**专属文案** + [重试]（04 §五，不许塌成「未知错误」）
       ├ 无更新                      → broadcast stateChanged {type:'idle'}（手动时通知面「当前已是最新版本」）
       └ 有更新                      → broadcast stateChanged {type:'available', update}
                                        → 壳推 context key updateActionable=true + updateButtonLabel=「下载更新」
                                          → TitleBar「下载更新」按钮出现（03 §4.2，全文字 + 主题按钮色）
[壳渲染收到 available]
  → 发现更新通知面条目（04 §二）——[查看更新内容] [立即更新]
  → 用户点条目「立即更新」 / TitleBar 按钮（openUpdateFlow）
    → handle downloadUpdate()
    → state: downloading             → broadcast stateChanged {type:'downloading'} + 每≤500ms progress
                                        → 通知面 updateToast 循环改文字（04 §三；4px 真条）
                                        → TitleBar 按钮变「更新中」（03 §4.3）
    → 下载完成 + sha256 校验
       ├ 校验失败                    → broadcast stateChanged {type:'idle', lastError:'checksum-mismatch'} + 通知面错误 + [重试]
       │                               → context key updateActionable=false → 按钮消失
       └ 校验通过（或缺 checksum 降级放行，记 checksum-unavailable）
                                     → broadcast stateChanged {type:'downloaded'}
                                        → 通知面「更新已下载，重启后生效」[稍后][重启并更新]（04 §四）
                                        → TitleBar 按钮变「重新启动」（03 §4.3 三态：下载更新 → 更新中 → 重新启动）
[downloaded]
  → 用户点条目「重启并更新」 / TitleBar 按钮（openUpdateFlow → quitAndInstall）
    → handle quitAndInstall()
    → state: updating                → broadcast stateChanged {type:'updating'}
    → ⚠️ `updating` 必须**先持久化再退出**（Windows 文件锁：旧进程没退干净时 NSIS 覆盖不了 LinkDesk.exe，01 §2.5 / 清单 #57.7a）
    → app.relaunch + app.quit()      → 进程退出（重启后首启自动弹发行说明）
[任一点用户点「稍后」]
  → 壳只关该条目；state 回 idle（保留 update 信息）
  → broadcast stateChanged {type:'idle', update} + context key updateActionable=false
    → 按钮消失，手动检查更新仍可再触发
[发行说明腿（与状态机无关，按需触发）]
  → 打开发行说明标签页 / 点「查看更新内容」
    → invoke(update:getReleaseNotes, version?)
      ├ 缓存命中（24h 内）        → 直接返回（**不经加载态**，05 §2.4）
      └ 未命中                    → 壳先渲**骨架屏**（mockup 03 Frame 3）→ 主进程出网（main-fetch.ts）
                                     ├ 成功 → 写 {userData}/updates/releases-cache.json → 渲染（Frame 1）
                                     └ 失败 → 缓存兜底；无缓存 → 空态 + [重试] + GitHub 链接（Frame 2）
```

### 4.4 首启状态（壳挂载订阅）

1. 壳渲染 `useUpdateState` mount → `invoke(IPC.update.getState)` 拉初值（不依赖事件是否先到——硬约束 20 缓冲/回放惯例，preload 顶层注册 + onReady 回放）。
2. 此后 `on(IPC.update.stateChanged)` 增量更新。
3. 竞态：事件可能在 mount 前到达 → preload `_buffer` 回放（对标现有 IPC 订阅模式，E5#11l Bug 4 教训）。

## 五、壳渲染消费（useUpdateState hook）

```typescript
// src/App/hooks/useUpdateState.ts（对标 usePoolSync 只监听关心 key 铁律）
export function useUpdateState(): UpdateState {
  const [state, setState] = useState<UpdateState>({ type: 'uninitialized' });
  useEffect(() => {
    // mount 拉初值 + 订阅 stateChanged；unmount 清理（引用计数，无模块级监听）
    const disposer = subscribeUpdateState(setState);
    return disposer;
  }, []);
  return state;
}
```

消费方（全部壳组件，无需插件在场）：

| 消费方 | 订阅 | 渲染 |
|:--|:--|:--|
| 更新通知面（铃铛宽面板） | `useUpdateState` | 发现/进度/完成/失败/手动结果全进**唯一通知面**（04）；🔴 多窗口下**条目只出在主窗口**（副窗口铃铛零未读，01 §2.2 / 18 档案 §八㉚） |
| 发行说明标签页 | 按需 `invoke(update:getReleaseNotes)`（**不订阅状态机**——发行说明与「有没有更新」无关，离线也该能看历史） | 三态：骨架屏 → 左窄栏历史 + 右主区 body → 空态 + `[重试]`（05 §2.4 / mockup 03 Frame 1/2/3） |
| TitleBar 更新按钮 | 动态 context key `updateActionable`（显隐）+ `updateButtonLabel`（三态文字） | 三态显隐 + 文字 + 点击走 `update.openUpdateFlow`（03 §4.3：下载更新 → 更新中 → 重新启动，主题按钮色） |
| 检查更新/关于入口 | 命令注册（恒显，无状态订阅） | 帮助/齿轮菜单项（03 §二/§三） |
| 关于标签页 | mount 时 `invoke(app:getProductInfo)` 拉一次（静态事实无事件，不订阅）；「检查更新…」按需 `invoke(update:checkForUpdates)`（06 §4.3） | 8 字段 key:value 表 + 「检查更新…」「复制」两动作按钮（06 §四） |

> **说明**：TitleBar 按钮走 `when: "updateActionable"` context key 门控 + `label: "updateButtonLabel"` 文字解析（声明制插槽），**不是**直接订阅 state——它不知道具体状态，只知「有无可处理更新」+ 当前应显示什么文字；具体行为由 `openUpdateFlow` 命令按态分支。命令源唯一，入口声明多处。**按钮 = 全文字 + 主题按钮色**——复用壳共享 Button 组件，`label` 字段为一次通用扩展（03 §4.4）。

## 六、数据流一句话总结

> **主进程 UpdateService 是唯一状态源**；`handle` 命令让壳渲染发起动作；`broadcast stateChanged/progress` 让壳渲染跟随状态；context key `updateActionable` + `updateButtonLabel` 让声明式按钮门控显隐 + 三态文字（全文字 + 主题按钮色）；壳渲染只管画（通知面条目/按钮/菜单），永远不自己算状态。**第三方插件读版本号走 `update:getState`（只读，白名单，且是 `update.*` 里唯一进白名单的），写命令不开放，`update.getReleaseNotes` 也不开放。**
> **关于页身份数据**另走一条独立通道：主进程 `product.ts` 单例 → `app:getProductInfo` → AboutView 一次 invoke 全量拉取（静态事实，无事件订阅）——与更新状态机两路不混。
