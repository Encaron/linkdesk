一、两档能力（为什么用 allowAlpha 而不是“永远 RGBA”）

同一个 ColorPicker，按配置键声明决定是否开放 alpha——不是两套组件。

allowAlpha: false（默认）

alpha 滑杆隐藏；输入接受 hex/rgb/hsl 但强制 alpha=1；输出恒为 hex。
用于：强调色、按钮色、任何参与对比度的颜色。

#A6771B

allowAlpha: true（显式开）

alpha 滑杆显示；输入/输出支持 rgba/hsla；alpha=1 时仍输出 hex（旧值零变化），<1 输出 rgba。

rgba(255,247,230,0.62)

点左侧两行切换：玻璃叠加色出现 alpha 条（allowAlpha=true），强调色不出现（allowAlpha=false）——同一个组件，按声明分档。

三、边界情况

点一条把值送进调色器，看它怎么处理。
  • alpha 越界：输入 1.2 / -1 ⇒ 钳到 0..1，并提示。
  • var()/color-mix()：只读展示，弹层内禁用编辑（不改用户变量）。
  • 小视口：面板宽 232→300 自适应，右/下放不下翻左/上，恒在视口内。
  • 键盘：Tab 到 SV/滑杆/输入；Esc 取消；Enter 应用；滑块带 aria-valuetext。
  • 首选减少动效：过渡 150ms → 0。

四、AI 操作面（死规定：每个 GUI 动作都有命令）

右栏是实时命令日志——你在这页做的每个动作都会落一条结构化命令（命令名是设计提案，实现时注册；真正落盘仍是 configuration.set）。
GUI 动作命令 / API载荷
打开调色器 / 读当前值appearance.colorPicker.open{ key, allowAlpha } → 返回 { value, format }
拖动 SV 面板appearance.colorPicker.setHsv{ key, h, s, v }
拖色相appearance.colorPicker.setHue{ key, h }
拖 alphaappearance.colorPicker.setAlpha{ key, a }

点预设appearance.colorPicker.applyPreset{ key, index, value }
应用 / 取消 / 复位appearance.colorPicker.apply · .cancel · .reset{ key }

五、工程结构（归一化 / 无硬编码 / 无死代码）

共享件三层，消费方零复制：
  • @linkdesk/ui/color：parseColor / formatColor / hsv↔rgb——唯一实现，调色器/色块/校验共用。
  • @linkdesk/ui/color-picker：SV + 色相 + alpha + 输入 + 预设；只认 value / onChange / allowAlpha / presets。
  • @linkdesk/ui/color-field：色块（棋盘格）+ 文本；不弹层、不认识配置键。
  • 设置插件：注入 allowAlpha / 锚点 / 开合；不重画调色器。

颜色全走 var(--…)；无新 token；无死键（allowAlpha 默认 false，旧调用零变化）；目录按角色分夹、不平铺。
