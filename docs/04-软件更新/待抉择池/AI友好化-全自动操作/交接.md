**裁决（本棒的判断题，五条）**：
1. 🔴 **原「二次启动 → 立刻 relaunch」是错的（本棒抓到的真缺陷，打包态 5/5 复现）**：第二次启动那个进程**自己就绑着请求的新端口**（开关在它 argv 里、Chromium 在它 init 时绑上，它随后才因单实例锁退场）⇒ 立刻 relaunch 出来的并集进程 **bind 失败**，而 **CDP 端口绑不上不会重试** ⇒ 得到一个「**App 跑着、但没有调试口**」的实例。**修法** = relaunch 前先等：**请求里的那个端口**空闲 **且**过 `settleMs`（**0.9s** = 第二次启动进程实测寿命上界 777–801ms），超时 **8s** 照旧重启并出声（⛔ 不把用户晾住）。⚠️ 等的是**请求里的**端口、**不是合并结果里的**——合并结果的端口若来自现状（本进程自己绑着的）会**死等**。
2. **探针太弱 = 假绿的来源（方法论，值得记住）**：原验只查「有个进程在服务新端口」⇒ 上面那个坏行为**看着是绿的**（新端口确实通，只是**由即将退场的第二次启动进程**在服务）。加固成 **并集标记 ＋ 幸存者身份 ＋ 端口真通**三条一起查才现形 ⇒ **凡「谁在服务」类判据，必须同时查身份与并集，别只查存在性**。
3. **`AI#19` 只记读数、不勾格**：「② 更新重启后 AI 连接不丢」**打包态已验毕**，但那是 `--dir` 产物、**不是真安装版**；①「CLI/MCP 装插件 → 开 → 操作」**归 M4**。**真机 nsis 整跳今天走不了**（本机安装版 = 仓内同版本 `0.2.21`，`build/installer.nsh` 的 `customInit` **拒绝静默同版/旧版安装** exit 1602；且红线 = 软件本体不发版）⇒ 验收配方写进台账 `AI#19` 段（工具就用 `accept.mjs` 的 P2 段，改 `EXE` 指向安装目录）。
