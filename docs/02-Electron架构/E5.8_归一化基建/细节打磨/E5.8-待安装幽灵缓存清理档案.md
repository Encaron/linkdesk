## 一、现状与实机证据

- 用户机器 `C:\Users\fengy\AppData\Roaming\linkdesk\plugins\.disabled\` **已空**（8-20 创建、8-26 清空；源码树 plugins/.disabled 同空，win-unpacked 无 .disabled）。

## 二、根因（file:line + 机制）——缓存只增不删，待安装读缓存不扫目录

**链条**：
1. 卸载 → 移 `.disabled/` + `cachePluginMetadata(pluginId, manifest, "uninstalled")`（[lifecycle-ops.ts:160](../../../../src/pluginLoader/lifecycle-ops.ts#L160)）——**只增不删**
2. 「待安装」读取 = `getUninstalledPluginInfo()` **从缓存扫**（[lifecycle-ops.ts:424-434](../../../../src/pluginLoader/lifecycle-ops.ts#L424)，不扫 `.disabled/` 目录）
3. 僵尸清理只删 `status === "installed"` 且未加载的条目（[loader.ts:186-194](../../../../src/pluginLoader/loader.ts#L186)）——**`status="uninstalled"` 永不清理**

→ `.disabled/` 目录清空后，缓存里 9 条 uninstalled 残留 → 幽灵待安装。

**git 溯源（非 E5.8 Phase 2 新增）**：卸载→`.disabled`+缓存 uninstalled = **E5.6#16.7k**（fea91f0d 引入）；缓存清理（只认 installed）= E5.6 时代（b0a32ceb，07-26）；E5.8#0d.10（374b29d6a）仅拆文件纯移动零逻辑变更。

## 三、修复设计（用户拍板：差集清理）

改 [loader.ts](../../../../src/pluginLoader/loader.ts) 启动第 7 步（当前扫 `.disabled/` 只增不删，:202-220）——**扫完后差集清理**：

```
pruneUninstalledCache(disabledDirs):            // 抽纯函数，便于单测
  对缓存里每条 status === "uninstalled" 的条目：
    若 pluginId ∉ disabledDirs → 删条目
  有删除 → setPluginStateValue 持久化
```

**语义**：「待安装」= 当前 `.disabled/` 里**真可重装**的插件（目录为准），缓存只做显示名兜底。目录清空 → 残留即时消失。

**顺序**：第 3 步（glob 有 fs 无 → 写 uninstalled，:128-131）先跑、第 7 步后跑 → 差集清理天然在最后生效。

**零新 API / 配置 / 贡献点**——纯 loader 启动逻辑 + 纯函数。

## 四、可执行性（§五 修前三件事）

| # | 原因 | 改法 | 验证路径 |
|---|---|---|---|
| #156 | 卸载写缓存 uninstalled（lifecycle-ops.ts:160）+ 待安装读缓存不扫目录（:424-434）+ 清理只认 installed（loader.ts:186-194）→ `.disabled` 清空后残留不消 | loader.ts 第 7 步扫 `.disabled` 后差集清理（缓存 uninstalled ∉ 目录 → 删 + 持久化；抽纯函数 pruneUninstalledCache 单测） | `npm run check` + 单测（差集删/目录仍存在保留/空目录全清）+ CDP 清空 `.disabled` 重启待安装空 |

**单测三态**：
- `.disabled` 空 + 缓存有 uninstalled → 全删
- `.disabled` 有目录 + 缓存对应 → 保留
- `.disabled` 有目录 + 缓存不匹配（新移入）→ 保留（第 7 步扫描正常写缓存）

## 五、与 E6 关系

E6#11e 退役 `.disabled`（卸载=真删除，E6-执行清单）。**本修复是 E6#11e 的前置卫生**：E6 真删除后卸载流程仍写缓存 uninstalled（lifecycle-ops.ts:160 代码不变）→ 无本修复则待安装出现**永远更死**的死条目（目录不存在，reinstall 必失败）；有本修复则真删除后下次启动差集清理即时清除 → 待安装永不出现死条目。
