## 一、案由（2026-10-06 · 用户两个问题）

用户在实机使用中连着点出两处「说法不一样」（原话）：

> ①「为什么顶部菜单栏，比如我给命令面板的快捷键是 ctrl 加 shift 加 P，为什么顶部菜单栏是大写，软件左下角齿轮的快捷键显示是小写」→ 见 [01](01-快捷键文案三把尺子.md)

> ②「我按 ctrl k 加 ctrl t，弹出的这个选择主题的界面，我选择了某一个主题前面是打的对勾。我按 ctrl k 加 ctrl l，弹出命令院长〔原文如此，即语言〕的选择菜单界面，在这个界面上我选择了哪个语言后面显示的是『当前』……对于同一种确定的当前的这个样子的东西它这个规定权不一样，是不是不归一？」→ 见 [02](02-当前项标记不归一.md)

**两问的共性**：⛔ 都不是「功能坏了」，而是**同一个语义被写了两遍**——①是**同一条命令的键位显示串**被三种写法格式化；②是**同一个「当前项」语义**被两种标记表达。用户拍板：**合成一个任务处理**（同批交付、同批验收）。

## 四、归一化判定尺子（以后新问题按这条判）

1. **是不是归一化缺口**：同一个语义在软件里有 **≥2 处**表达／实现 ⇒ 是（不是「风格偏好」，是**迟早漂移**的结构问题）。
2. **哪边是正典**（优先级从高到低）：① 契约／字段自述语义 ② 多数派既有形态 ③ 全产品惯例 ④ VS Code 对标。
3. **收口方向**：永远让**少数派接上正典**——⛔ 不选「把正典改成少数派」，除非正典本身站错了（那要单独立档说清为什么）。
4. **每件必配**：一条**机械锁**（防复发）＋ 一组 **dev 验收判据**（可目视、逐条可勾）。
