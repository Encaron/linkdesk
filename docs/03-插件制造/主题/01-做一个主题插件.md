# 做一个主题插件——从零到装上

> **一句话：做主题不用写代码。** 一个主题插件 = **一个 JSON 配方** ＋ **一条声明**。改配色就是改那个 JSON。
>
> **本页是动线**（我要做一个主题，从头走一遍）；**配方字段的深度参考**在 [11-主题制作](../11-主题制作.md)（目录规范 / 满配示例 / 避坑表），**字段与变量的索引**在 [02-主题字段速查](02-主题字段速查.md)。

## 一、先建立三个心智模型

| 概念 | 一句话 |
|:--|:--|
| **主题 = 插件** | 主题走和其它插件完全一样的路：`plugin.json` 声明 → 打包 → 安装 → 市场。**只是它没有组件**（纯数据插件） |
| **配方（Recipe）** | 一个主题文件 = 一份完整外观配方。它有两个正交的轴：**风格**（`appearance`）和**配色**（`colorways[]`） |
| **稀疏覆盖** | **你只写你想改的，其余继承壳默认。** 写得越少越稳——壳以后调整默认值，你的主题自动跟着受益 |

**风格 vs 配色分离**（这是整套设计里最重要的一条）：想要"1 个风格基座 + N 个配色"，就在**一个配方**里放 `colorways[]` ——换配色只动数组项，风格（圆角/玻璃/字体/背景）不用重抄。

## 二、从零走一遍（五步）

### 第 1 步：生成工程骨架

```bash
npm create linkdesk-plugin theme-myglass    # 名字 kebab-case
cd theme-myglass
npm install
```

生成物里已经有 `plugin.json` 和 `src/index.tsx`。**主题插件用不到那个组件文件**——留着不影响（它是一个空的最小视图）。

### 第 2 步：建立目录（别平铺在根目录）

```
theme-myglass/
├── plugin.json              # 声明（contributes.themes）
├── themes/                  # ← 配方 json 唯一住处
│   └── myglass.json
├── assets/                  # 可选：字体（woff2/ttf）+ 背景图（png/jpeg/webp）
└── resources/               # 插件图标等元数据资产
```

> 🔴 **配方 json 一律放 `themes/`**，禁止平铺在插件根目录。理由很实际：主题会越做越深（per-surface 精调、i18n、README…），先把三个槽立好，以后加东西不用搬。
> **最小主题只要 `themes/` 一个目录**——纯配色主题连 `assets/` 都不需要。

### 第 3 步：声明（`plugin.json`）

```jsonc
{
  "pluginId": "theme-myglass",
  "name": "我的玻璃主题",
  "version": "0.1.0",
  "contributes": {
    "themes": [
      { "id": "myglass", "label": "My Glass", "uiTheme": "dark", "path": "themes/myglass.json" }
    ]
  }
}
```

| 字段 | 含义 |
|:--|:--|
| `id` | 主题 id（配方文件里的 `id` 要**与它一致**） |
| `label` | 主题选择器里显示的名字 |
| `uiTheme` | `"dark"` 或 `"light"`——决定使用深浅底那一套基线 |
| `path` | 配方 json 相对插件根目录的路径 |

> 一个插件**可以带多个配方**（`contributes.themes` 里写多条，各指一个 json）。但**同一个风格多个配色**推荐合成一个配方（`colorways[]`），这样主题选择器里是**一张卡片多个配色**，比一排卡片清爽。

### 第 4 步：写配方（最小可用版）

```jsonc
// themes/myglass.json
{
  "id": "myglass",
  "name": "My Glass",
  "type": "dark",
  "appearance": {
    "radius": { "md": 10, "lg": 16 },
    "glass": { "blur": 16, "saturate": 1.3, "tint": "rgba(255,255,255,0.06)", "opacity": 0.9 }
  },
  "colorways": [
    { "id": "violet",  "name": "紫罗兰", "colors": { "bg-window": "#0E0B16", "accent": "#8B5CF6" } },
    { "id": "emerald", "name": "翡翠",   "colors": { "bg-window": "#0A1410", "accent": "#34D399" } }
  ]
}
```

**三个必须记住的点：**

1. **`colors` 的键 = CSS 变量名去掉 `--` 前缀**（`--bg-window` → `"bg-window"`）——你写的就是变量，不用记第二套名字。
2. **`colorways` 一定是数组**——单配色也写成 1 项数组（**没有第二种写法**）。
3. 顶层**不要**再写 `colors`——那是旧格式，引擎只读 `colorways[]`。

> 想拿编辑器的自动补全与报错，可以在配方开头加一行 `$schema` 指向 SDK 包内 schema：
> `"$schema": "./node_modules/@linkdesk/plugin-sdk/schemas/theme.schema.json"`（相对**你自己工程的根**，只有这一种写法）。

### 第 5 步：看见它

主题是纯数据插件，**没有"浏览器预览宿主页"**——它的效果只能在真壳里看：

```bash
npm run dev:real     # 真机环：装进你已安装的 LinkDesk，改码即刷新
```

装进 LinkDesk 后：**设置 → 外观/主题** 里能看到你的主题卡片；选中后整个界面颜色/圆角/玻璃一起变。

发布给别人（打包 → 上架两步）走和其它插件**完全一样**的流程——见 [13-插件开发指南](../13-插件开发指南.md) 第 8、9 步。

## 三、常见坑

| 坑 | 说明 |
|:--|:--|
| 配方 json 平铺在插件根目录 | 一律放 `themes/`（第 2 步） |
| 写顶层 `colors`（无 `colorways`） | 旧格式已弃——引擎只读 `colorways[]` |
| 资产写绝对路径 | 打包后 `file://` 全炸——**一律相对路径**（`assets/...`），壳统一解析 |
| 把能改的全抄一遍 | 稀疏覆盖才好维护——只写差异键，未写的继承默认 |
| 改了主题却只在自己插件里生效 | 主题是**全局**的（壳级 CSS 变量）；局部覆盖用插件自己的 CSS，别用主题域 |

## 四、我还能拿到什么（主题作者的额外能力）

- **混搭自动出现**：按你贡献的域，你的主题会自动出现在设置页的"混搭来源"里——**作者零额外工作**。
- **数据与事件**：`window.linkdesk.theme.listRecipes()` 拿配方列表（含预览色）；`theme:changed` 事件做实时联动。
- **应用主题**：`setRecipe` / `setColorway`，或直接写 `app.theme` 配置。

方法签名与载荷 → [01-插件API契约](../01-插件API契约.md)。
