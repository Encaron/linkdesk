# 通用交互范式——侧栏 = 管理面板

> 2026-07-21。从 [终端侧栏两次进化](V3-Phase5.5-终端侧栏两次进化.md) §六 提炼。
> 在讨论终端侧栏改名方案时发现：**这个名字不应该通过标签栏 F2/双击/右键来改——应该在侧栏里改。** 侧栏是插件管理自己资源的操作面板。终端会话、卡片、文件、数据库表——任何插件有"可管理的条目列表"时，侧栏就是它的管理面板。
>
> **这不是终端专属模式——这是 LinkDesk 的通用交互范式。**

> 🔥 **硬约束——终端不是特殊插件。** LinkDesk 是通用调试容器，不是串口调试器。终端是第一个被插件化的视图，碰巧也是目前最复杂的视图——但它在框架眼里和文件树、卡片工作台、未来任何第三方视图**完全平等**。终端用 `viewRole: "sidebarPrimary"`，和所有其他 sidebarPrimary 插件走相同的代码路径。没有"因为这是终端所以特殊处理"的 if 分支——没有，永远不会有。如果终端需要某个能力（如 COM 口状态隔离），框架提供通用机制（如 tabId 隔离），终端消费它——和文件树消费 FileService 一模一样。**写死终端特殊逻辑 = V2.6 惨剧重演。**

---

## 一、模式定义

```
标签栏 = 导航（快速切换当前在看什么）
侧栏   = 管理（增删改查插件自己的资源）
主区   = 内容（渲染/交互/编辑）
```

**改名不走标签栏——走侧栏。** 对标 VS Code：你不会在编辑器标签页上 F2 改文件名——你在 Explorer 侧栏里改。标签页标题只是"当前在看什么"的标签，不是管理入口。

```

## 三、卡片工作台沿用同一模式

> **侧栏管的是工作台布局，不是单个卡片。** 每个工作台布局是一个可命名的卡片排列方案（如"PID 调参"布局里有波形图卡 + 滑杆卡 + 仪表卡）。布局 = 一组卡片的排列，卡片是布局内部的元素。导入/导出是导出整个工作台布局，下次导入直接用——或者让 AI 帮你布局好，直接导入。

```
侧栏                          标签栏                    主区
┌──────────────────┐  ┌─────────────────────────┐  ┌──────────────┐
│ ▼ 工作台布局 (4)  │  │ [📊 PID调参]  [📊 电机测试] │  │ ┌──┐ ┌────┐ │
│   📊 PID调参  [✎] │  │                         │  │ │波│ │滑杆│ │
│   📊 电机测试  [✕] │  │  ↑ 标签页标题 = 布局名    │  │ │形│ │    │ │
│   📊 传感器面板     │  │  侧栏改名 → 标签同步      │  │ │图│ ├────┤ │
│   📊 调试总览       │  │                         │  │ │  │ │仪表│ │
│   [+ 新建工作台]   │  │                         │  │ └──┘ └────┘ │
│                   │  │                         │  │ ┌──┐ ┌────┐ │
│ ▶ 导入/导出布局    │  └─────────────────────────┘  │ │开│ │数字│ │
│                   │                              │ │关│ │显示│ │
│                   │                              │ └──┘ └────┘ │
└──────────────────┘                              └──────────────┘
```

**交互流程：**

```
侧栏点 [+ 新建工作台]
  → 输入布局名: "PID 调参"
  → 主区开空白工作台标签页
  → 用户从卡片库拖入卡片（波形图/滑杆/仪表…）→ react-grid-layout 自由排列
  → 关闭标签页时自动保存布局 → workspace.json

侧栏点 "PID调参"
  → 主区打开/聚焦该工作台标签页 → 恢复所有卡片位置和状态

侧栏右键 → 导出
  → 打包 workspace.json + 卡片配置 → .linkdesk-workspace 文件
  → 发给别人或给 AI

侧栏 → 导入
  → 选 .linkdesk-workspace 文件 → 侧栏出现新布局 → 点 → 开标签页
```

```
侧栏                          标签栏                    主区
┌──────────────────┐  ┌─────────────────────────┐  ┌──────────┐
│ ▼ stm32-project   │  │ [📄 main.c] [📄 timer.h] │  │ Monaco   │
│   📄 main.c   [✎] │  │                         │  │ 编辑器    │
│   📄 timer.h  [✕] │  │  ↑ 在侧栏改名 → 标签同步  │  │          │

VS Code 的 Explorer 侧栏就是一模一样的模式——文件名在侧栏改，不在标签栏改。

## 六、模式总结

| 插件 | 侧栏管理什么 | 操作 |
|------|-----------|------|
| 终端 | 会话列表 | 新建/改名/删除/切换 |
| 卡片工作台 | 工作台布局列表 | 新建/改名/删除/切换/导入/导出 |
| 文件树 | 文件/文件夹 | 新建/重命名/删除/移动 |
| 数据库浏览器 | 表列表/查询历史 | 打开/重命名/删除/收藏 |
| Git | 更改列表/分支 | stage/unstage/commit/switch |
| 任何"有列表"的插件 | 列表 | CRUD |

**`<SidebarSection>` 是渲染组件，`CRUD` 操作是每个插件自己的逻辑，但"改名在侧栏不在标签栏"是统一的交互规则。**

### 侧栏改名 → 标签标题联动规则

对标 VS Code Explorer 重命名：文件在侧栏改文件名 → 对应该文件的编辑器标签页标题自动更新。LinkDesk 所有"侧栏管理列表项 + 主区开对应标签页"的插件都遵循此规则：

```
侧栏改名 "COM3 PID调试" → reduceUpdateTabLabel(tabId, "COM3 PID调试")
侧栏删除会话       → closeTab(tabId)
侧栏新建会话       → createTab(tabId)

标签页标题来源于侧栏，不独立编辑。
标签栏本身不接受 F2 双击改名——F2 在侧栏内触发。
```

---

## 七、为什么好

1. **一致性——** 不管什么插件，用户知道"改名字去侧栏"
2. **标签栏纯粹——** 标签栏只管导航（切换/关闭/拖拽），不管管理（改名/删除）
3. **对标 VS Code——** Explorer 改名 / Extensions 管理 / Git 操作——全在侧栏
4. **AI 友好——** 新 AI 写插件时，文档一句话："有列表要管理？放侧栏，用 `<SidebarSection>`，改名走侧栏不走标签栏"
