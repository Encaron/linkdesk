## G. 阶段 0 实测回填（2026-10-05 · 第 1 波 AI-1 · 只读勘察）

> 照档头规矩「开工日先用阶段 0 勘察核对现行为，与清单冲突的以实测为准回填」。下列读数为**源码实测**（file:line 为当日读数），与上文各条并读；**冲突处以本段为准**。本段只回填勘察，⛔ 不含实施。

### G.1 getPluginFor 现行口径（E9/E10 不回归）

- 归一化只在 `FileAssociationService.normalizeExtension`（`src/core/services/files/FileAssociationService.ts:131-136`）：`trim()` → `toLowerCase()` → 去**一个**前导点；注册与查询**同吃此函数** ⇒ 大小写不敏感**双向**成立（`.PDF` 与 `pdf` 同键）。
- 双扩展名：三个入口一律**取最后一个点**——file-tree `extension()`（`E:\linkdesk-plugins\official\file-tree\src\utils\pathUtils.ts:69-72`，`idx > 0` 守卫）、intake（`src/hooks/useOpenPathIntake.ts:64-65`，`dot > 0` 守卫）、FileSearcher（`src/core/services/files/FileSearcher.ts:152`，裸 `slice(lastIndexOf("."))` **无守卫**）。`.tar.gz` → `gz`。
- ⇒ **E9「取最后一段」、E10「归一小写」现行即如此，不回归。**
- 点开头文件（`.gitignore`，`lastIndexOf(".")===0`）与无扩展名（`Makefile`）⇒ 打开链三入口**一律不查表**（`>0` 守卫拦下）：file-tree/intake 传空串落兜底、SearchView 直接 `return`。**FileSearcher 是唯一例外**，但它只用于 `BINARY_EXTS` 跳过、**不参与打开**。⇒ **E33 的「点开头＝无扩展名」在打开链上三处一致**，差异是 FileSearcher 的非打开用途（[§G.2](#g2-searchview-openmatch-静默行为e-分叉修的基线) 同源）。

### G.2 SearchView openMatch 静默行为（E 分叉修的基线）

- `E:\linkdesk-plugins\official\file-tree\src\views\SearchView\openMatch.ts:11-21`：`const ext = extension(...); if (!ext) return;` → `const pluginId = await getPluginFor(ext); if (!pluginId) return;` —— **无 handler 时纯静默 no-op**（不建标签、不提示）。
- 对照 FoldersView：`doOpenFile` 无 handler 时 `tabs.create("")` → 壳 `DEFAULT_TAB_TYPE` 兜底 → 开 editor 标签（`E:\linkdesk-plugins\official\file-tree\src\views\FoldersView.tsx:120-131`）。
- ⇒ **分叉属实**（一个静默、一个兜底），第 3 波 F3 归一的基线即此。

### G.3 拖拽是否走 useOpenPathIntake 同链（E18）

- **不是。** `useOpenPathIntake` 全仓唯一消费方 = 壳 `src/App.tsx:192`，喂它的是 `shell.onOpenPath`（主进程 `routeLaunchItems` ← argv／OS「打开方式」／文件关联），见 `src/hooks/useOpenPathIntake.ts:74-79`。
- 窗口级**没有**「拖入文件 → 打开」链路（壳 `src/` 无 window/body 级 drop handler；`src/pool/**` 的 drop 全是标签/视图拖拽协议）。
- 文件树内部拖入（`E:\linkdesk-plugins\official\file-tree\src\services\FileTreeDnD\useFileTreeDnD.ts:100-119`）= **复制/移动进目标目录**（`executeSafeDrop`），另有可选 `file-tree.autoOpenDroppedFile` 走 `onAutoOpenDroppedFile` 回调——**不是** intake 链。
- ⇒ **E18 原文「已同链路」前提不成立**（本波改判）：拖拽**不在**归一范围。第 3 波 F3 归一的三入口应钉死为 **FoldersView／SearchView／useOpenPathIntake**，拖拽不在内；若将来要「拖入即按解析结果打开」，是新增能力、另立案。

### G.4 files IPC 面落点：`isBinary` 的 additive 方式
