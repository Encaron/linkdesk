## 〇、定位：为什么市场是第一站

「万物皆插件」对用户的第一眼，就是打开软件看到什么。市场不是「管理插件的工具页」，是**「这个世界有什么可玩」的橱窗**。三条设计原则：

1. **探索优先**——未装插件也能看详情、看截图、看 README，看完再决定装不装。
2. **状态一眼即知**——安装/更新/禁用，按钮随状态自动切换，不让用户猜。
3. **作者就是门面**——图标/README/截图全由作者提供，壳只做容器，提供什么显示什么。

## 二、信息架构（IA）

侧栏（🧩）= 市场。主区 = 详情页。

```
侧栏（marketplace 插件 4 组）:
  ├── 探索插件   ← 目录浏览（marketplace.json 全量）——第一站
  │               · 未装 → 绿色「安装」按钮
  │               · 已装 → 状态徽标（已安装 / 可更新）
  │               · 有更新 → 升级入口
  ├── 已安装     ← 管理（禁用/卸载/更新/版本/自动更新勾选）
  ├── 内置       ← 核心插件（不可卸载）
  └── 已禁用     ← 管理（启用/卸载）

主区:
  ├── 市场欢迎页（现状——「已安装 N 个插件」引导）
  └── 插件详情页（三态 action + README + 截图 + 元数据侧栏）

搜索 → vscode式单一结果列表（E6#32a——四组合并平铺）
```

**语义变化：「待安装」→「探索插件」。** 旧「待安装」= `getUninstalled()`（E5.8 卸载缓存，残留概念）。新「探索插件」= market catalog 目录浏览——市场时代真正的橱窗。

## 三、插件状态机（三态 + 更新第三维）

```
                     ┌────────────────────┐
                     │   未安装（catalog）  │
                     └─────────┬──────────┘
                   安装(绿)     │  卸载
                     ┌─────────▼──────────┐
                     │  已安装 · 启用       │◄── 更新可用 → 升级入口 + 版本下拉
                     │  [禁用] [卸载]       │
                     └─────────┬──────────┘
                       禁用    │   启用
                     ┌─────────▼──────────┐
                     │  已安装 · 禁用       │
                     │  [启用] [卸载]       │
                     └────────────────────┘
```

- 按钮随状态**自动切换**（订阅 `plugin-lifecycle:changed`，安装完成自动变「禁用/卸载」，卸载完成变「安装」）。
- 更新可用 = **第三维**（不改变三态，在「禁用/卸载」旁叠加升级入口）。
- **挂起 · 缺依赖 = 第四维**（依赖引擎引入，E5.8#14/#15 已实现）：已装插件因依赖被卸载而挂起 / 市场安装时缺依赖被拦 → 详情页 action bar「🚫 安装不可用（缺依赖）」+ 侧栏「等待依赖」琥珀徽标；依赖补齐自动解除挂起。**视觉 + 交互 = mockups/02 帧 7（实机可复现，实现阶段逐帧对照验收）**。

## 三·五、反馈分工三通道（事件 / 状态 / 一望即知）

> 从 mockups/02 全状态详解逐帧提炼。**「什么信息走什么通道」是市场交互第一规则**——顶部横幅禁用（用户拍板：把整个 UI 往下推 + 影响性能），一切事件反馈走 toast。
> **验收契约：HTML 展示的每个状态/交互，最后必须实机逐帧可复现（实现阶段对照 mockups/02 验收）。**

| 通道 | 服务信息 | 形态 | 实机状态 |
|:--|:--|:--|:--|
| 右下角 toast（**事件型**） | 安装进度 / 成功 / 失败 / 禁用 / 卸载 / 缺依赖被拦——一次性事件，触发即示 | 市场插件**自调** `window.linkdesk.notifications.show`（四方法 show/update/finish/cancel，E3j#76 已实现，零新 API） | ✅ 已实现（lifecycle onDidInstall/onDidUninstall toast 先例）；市场具体文案 = E6 实现阶段 |
| 详情页内嵌条（**状态型**） | 已装插件因依赖被卸载而挂起——持续期间一直在 | pd-pending-notice（E5.8#15.5，详情页 header 下内嵌，只推详情页一行，不推整个 UI） | ✅ 已实现 |
| 侧栏徽标（**一望即知**） | 已安装 / 可更新 / 等待依赖 / 已禁用——列表扫一眼 | ms-item-badge 系列（marketplace 侧栏，waiting 琥珀「等待依赖」已实机） | ✅ 已实现 |

**逻辑闭环保证**：每个状态转换必有反馈落点——①点安装缺依赖 → toast（事件）+ 侧栏「等待依赖」（状态）+ 按钮「🚫 不可用」；②依赖补齐 → 挂起解除自动加载；③安装成功 → 按钮自动切「禁用/卸载」（lifecycle:changed 订阅）。无「画了状态但逻辑到不了」的孤儿帧。

## 四、marketplace.json 格式扩展

> **纯增量**——旧插件不填新字段不崩（对标 VS Code contributes 从 1.0 加几十个扩展点，旧扩展不升级不崩）。权威字段定义 → [01-GitHub-Releases方案.md](01-GitHub-Releases方案.md) §三，本档只列新增。

| 新字段 | 用途 | 需求点 |
|:--|:--|:--|
| `versions[]` `{ version, downloadUrl, publishedAt, changelog? }` | 版本历史（最新在前）——版本下拉数据源 | 点 4 |
| `readmeUrl` | 作者仓库 raw README——未装插件详情页数据源 | 点 6 |
| `screenshots[]` | 截图画廊 | 点 6 |
| `license` | 许可证标识（详情页侧栏） | 点 6 |
| `categories[]` | 多分类（E6#32b 分类源，替代单 `category`） | 点 6 |
| `icon` 的 url 形态 | 作者自制彩色图标（SVG/PNG 直接 `<img>`） | 点 5 |

**配套打包**：`.linkdesk-plugin` 包内带 `README.md`（E6#4a 打包结构补「原样复制」）——已装插件的详情页 README 数据源。

**下载数不在 marketplace.json**——来自 GitHub Releases API（GitHub 统计、我们只读），见 [08-信任与安全.md](08-信任与安全.md) §二。
