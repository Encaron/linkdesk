# 插件通信合规审计——E5.5#0a

> 📖 **铁律来源：** [[plugin-communication-standard]]——插件只认 `window.linkdesk.*`，禁止 `import @src/core`。
> [[multi-webview-root-cause]]——任何 import/变量共享/同步调用在多 WebView 下静默失效（不报错，只是不工作）。

## 为什么必须做

多 WebView 下每个插件 = 独立 WebContentsView = 独立 JS 堆。

```typescript
// ❌ 插件里写这个：
import { registerMenuItems } from "@src/core/registry/MenuRegistry";
registerMenuItems(MenuId.EditorContext, [...]);
// → 插件进程的 _menus Map 注册了菜单项
// → 壳进程的 _menus Map 没有这条
// → 壳的 ContextMenu 读壳的 _menus → 空
// → 菜单静默空白。不报错。不崩溃。
```

**E3a 教训：** `import` 核心模块有副作用的调用，在多 WebView 下 100% 静默失效。没有 error，没有 warning。用户看到的只是"菜单没出来""配置没生效""命令没注册"。

## 审计范围

### 第一步：全量扫描

```bash
grep -rn "from.*@src/core" plugins/
grep -rn "from.*\.\./\.\./src/core" plugins/
grep -rn "from.*\.\./\.\./\.\./src/core" plugins/
```

### 第二步：逐条分类

| 类别 | 判据 | 多 WebView 下行为 | 处理 |
|:--|:--|:--|:--|
| 类型定义 | `import type { ... }` | ✅ 编译时擦除，无运行时影响 | **白名单放行（唯一例外）** |
| 枚举/常量 | 纯值，不依赖运行时状态 | ✅ 安全但——切 `linkdesk.menu.MenuId` 或插件本地副本 | 切 API |
| 纯工具函数 | 无副作用，不依赖 DOM/React Context/模块变量 | ⚠️ 安全但在多 WebView 下 ESLint 拦截 | 切 `linkdesk.data.*` API（E5.5#23i） |
| 有副作用的服务 | Registry 操作、配置读写、文件操作 | 🔴 静默失效——操作的是插件进程的副本 | **必须切 linkdesk.\* API** |

> 🔥 **去掉向后兼容后的铁律：不存在"记录例外"。** 任何运行时 `import @src/core`——无论工具函数、UI 组件、枚举常量——全部消灭。仅 `import type` 白名单放行（编译擦除，零运行时影响）。

### 第三步：ESLint error 全量清理

当前 `no-core-import-in-plugin` ~37 处。E5.5 完成后：
- **error**（不是 warn）——新增插件 import `@src/core` → 直接报错
- 白名单仅限 `import type`（8 种类型：`FileEntry`, `FileDecoration`, `WorkspaceFolder`, `ViewPluginEntry`, `FileSearchResult`, `SearchMatch`, `SendContext`, `SendCallbacks`）
- `__tests__/` 目录放行（vitest 跑在 node，不经过 WebView），但测试内运行时 import 也切 `linkdesk.*` API
