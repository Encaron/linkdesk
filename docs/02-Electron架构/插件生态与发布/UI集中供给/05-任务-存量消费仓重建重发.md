### 四、执行序两个真教训（下批同类活直接照抄）

1. 🔴 **先 bump 版本，再 build**——`linkdesk-plugin-sdk publish` 发的是**工作区里现成的那只 `.linkdesk-plugin`**，它不会替你重 build。`file-tree` 踩到：先 build 后 bump ⇒ 发出去的 zip 里 `plugin.json` 还是 `1.0.11`、`CHANGELOG.md` 还是旧段（市场详情「更改日志」会空）。**处置**：`gh release delete v1.0.12 --yes --cleanup-tag` 删掉重发（asset 66,744 → 67,189 与本地一致）。后三仓已改为「bump → build → verify → publish」，一次过。
2. 🔴 **`publish` 会在远端写一笔**——它把 `marketplace.json` 更新**直接提交到该仓远端 main**（不是本地工作区）⇒ 发布后本地落后一提交，`git pull --rebase origin main` 才能对齐（file-tree 的 `784a43d` / serial-monitor 的 `3de04ea` / marketplace 的 `aedcb96` / settings 的 `3a05ff9` 都是这笔）。**不 pull 就做第二次 publish ⇒ 前置断言「本地 HEAD 已推送」会红**。
