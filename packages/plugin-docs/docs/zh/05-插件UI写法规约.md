# 插件 UI 写法规约

> **一句话：核心已提供标准组件和注册表——不要手写轮子。手写 = 风格不一致 + 以后归一化时要拆。**
> 写插件前扫一眼，避免同类返工。
> **2026-09-06 与实现对齐核对**（对账）：塌平单根（无 plugins/{builtin,user}）· 共享控件走 @linkdesk/ui · 分发 = .linkdesk-plugin zip。本页对应机制引用已清。

## 1. 右键菜单 → `<ContextMenu>` + MenuRegistry

**❌ 禁止：** 手写 `<div className="my-menu">` + `useState` + click-outside listener。

**✅ 正确：**
```json
// ① 声明菜单项——plugin.json contributes.menus（首选，声明式）
{
  "contributes": {
    "menus": {
      "editorContext": [
        { "command": "myPlugin.copy", "group": "navigation" },
        { "command": "myPlugin.clear", "group": "edit" }
      ]
    }
  }
}
```

```tsx
// 运行时动态注册（等价）——window.linkdesk.menu.registerItems(menuId, pluginId, items)
window.linkdesk.menu.registerItems("editorContext", "myPlugin", [
  { command: "myPlugin.copy", group: "navigation" },
  { command: "myPlugin.clear", group: "edit" },
]);

// ② 使用统一组件——MenuId 是开放 string，直接写字符串字面量
<ContextMenu menuId="editorContext" />
```

**理由：** `<ContextMenu>` 自带 backdrop + 四种失焦（Escape / click backdrop / window blur / 选项 click）+ 键盘导航 + when 条件过滤。手写做不到这四种失焦。

**MenuId 是开放 string（`src/core/registry/commands/MenuRegistry.ts` `export type MenuId = string`）——插件声明任意字符串即契约，无需壳加代码。** 壳内置注册点（MENU_SLOTS 常量表）：

| MenuId（字符串字面量） | 场景 |
|---|---|
| `commandPalette` | Ctrl+Shift+P 命令面板 |
| `tabContext` | 标签栏标签右键 |
| `panelViewContext` | 面板标签栏右键（位置/对齐子菜单 + 视图显隐列表） |
| `editorContext` | 标签页主内容区右键 |
| `extensionGear` | 底部齿轮菜单（设置/命令面板/主题选择器） |
| `marketplaceItemGear` | 插件市场条目齿轮（启用/禁用/卸载） |
| `menuBar` | ☰ 汉堡菜单栏 |
| `panel` | 菜单栏「面板」菜单 |
| `fileContext` | 文件树右键 |
| `cardContext` | 卡片右键 |
| `quickSendContext` | 快捷发送药丸右键 |
| `iconBar` | 图标栏右键 |
| `settingItemGear` | 设置项齿轮（Settings Editor 行 hover） |
| `viewTitleContext` | 侧栏视图 title 右键（折叠/重置位置/视图同组） |

新增右键场景 → MenuId 开放 string 直接声明即可（如 `"myMenu"`）：`contributes.menus.myMenu` 声明 + `<ContextMenu menuId="myMenu" />` 消费——**零壳改动**（插件独立铁律）。壳若要在此场景提供统一渲染点才需在 MENU_SLOTS 加条目。

## 2. 浮层 / 弹窗 → `createPortal`

**❌ 禁止：** 弹窗嵌在组件树的深层 div 里。

**✅ 正确：**
```tsx
import { createPortal } from "react-dom";

return createPortal(
  <div className="my-dialog">{/* ... */}</div>,
  document.body  // ← 关键：渲染到 body
);
```

**理由：** keep-alive 架构下非活跃标签页 `display: none`，子元素用 `position: fixed` 也看不见。render 到 `document.body` 才能突破组件树限制。

## 3. 持久化 → `window.linkdesk.configuration`（plugin.json contributes.configuration 声明）

**❌ 禁止：** `localStorage.setItem()` / `PreferenceService.loadPrefs()` / 手写文件读写 / `import ... from "@src/core/..."`。

**✅ 正确——走 `window.linkdesk.configuration`（插件通信铁律：只走 window.linkdesk.*，禁止 import @src/core）：**
```tsx
// 读配置（Promise——值运行时动态）
useEffect(() => {
  window.linkdesk.configuration.get<boolean>("myPlugin.showLineNumbers").then((v) => {
    setShowLineNumbers(v);
  });
}, []);

// 写配置
await window.linkdesk.configuration.set("myPlugin.showLineNumbers", true);

// 订阅变更——返回 unsubscribe，unmount 调用
useEffect(() => {
  return window.linkdesk.configuration.onChange<boolean>("myPlugin.showLineNumbers", (v) => {
    setShowLineNumbers(v);
  });
}, []);
```

**plugin.json 声明配置项：**
```json
{
  "contributes": {
    "configuration": {
      "title": "My Plugin",
      "properties": {
        "myPlugin.showLineNumbers": {
          "type": "boolean",
          "default": true,
          "description": "显示行号"
        }
      }
    }
  }
}
```

**理由：** 壳自动持久化 + 重启恢复 + Settings Editor 自动渲染。手写 localStorage → 丢掉 Settings Editor 集成 + 下一个持久化 bug。

## 4. 快捷键 → 两轨道：声明式（非文本键）+ 池侧自处理（文本键/焦点绑定键）

快捷键有**两条轨道**，选哪条取决于键的性质。**选错轨道 = 键死或劫持全池**（教训）。

### 4.1 轨道一：`contributes.keybindings`（设置面板可见）——**仅限非文本键**

**❌ 禁止：** 把 `ctrl+c` / `ctrl+v` / `ctrl+x` / `ctrl+a` / `f2` 等**文本编辑键**写进 `contributes.keybindings`。

**✅ 正确：**（非文本键——如 `ctrl+k` / `ctrl+shift+e` / `f5`）
```json
{
  "contributes": {
    "keybindings": [
      {
        "key": "ctrl+k",
        "command": "myPlugin.clear",
        "when": "activeEditor == 'myPlugin'"
      }
    ]
  }
}
```

**理由（为什么文本键是雷）：** 声明/注册的键会同步进主进程 keyCache → `before-input-event` 命中即**无条件吞键**（不认 when、不认可编辑状态、不认 handler 是否存在）。壳注册一个 `ctrl+c` 就吞掉全池所有输入框/Monaco 的原生 `ctrl+c`。文本键正解 = 轨道二。

### 4.2 轨道二：池侧自处理（容器 onKeyDown）——文本键 + 焦点绑定键正解

**✅ 正确：** 组件自己的键盘交互在自己的**容器 `onKeyDown`** 里处理：

```tsx
<div
  tabIndex={0}          // 让容器可聚焦——点击子项时浏览器把焦点给最近可聚焦祖先
  onKeyDown={(e) => {
    if (e.key === "F2") { e.preventDefault(); startRename(); }
  }}
>
  {items}
</div>
```

**为什么是正解：** 池内所有插件共用一个 document——**DOM 焦点天然分区**。容器聚焦才收键，Monaco 聚焦收不到，多插件各干各的 `ctrl+c` 互不打扰。不需要 when、不需要冲突检测。文件树剪贴板键 = 共享 `useClipboardKeys` hook + 命令链同款。剪贴板相关键可复用 `src/pool/hooks/useClipboardKeys`（`onCopy`/`onCut`/`onPaste` 声明式回调，机制一处实现一处修）。

**❌ 反模式（红字）：** `document.addEventListener("keydown", ...)` / `window.addEventListener("keydown", ...)` = **全局劫持**——绕过分区前提，插件有活动会话时劫持全池同键（串口 F2 曾劫持文件树 F2）。**`tabIndex` + 容器 `onKeyDown` 才是焦点分区正解**；非焦点元素不触发，可加 `tabIndex={0}` 承接。

🔴 **这条反模式有腿了（2026-09-20，SDK 0.1.46 起）**：`linkdesk-plugin-sdk lint` 的 `linkdesk/no-global-key-listener` 腿机械拦截 window/document 的 keydown/keyup **字面量**监听，报错文案直接给正解与豁免写法。确需全局抓键的正当形态（如快捷键录制器要 capture 抓原始键）走标准 disable 注释＋理由——判据本身无白名单。

**注意：** 轨道二键**不进快捷键设置面板**——面板只显示 KeybindingRegistry 绑定（轨道一）。这是设计取舍（注册即吞池，见 4.1），不是 bug。

### 4.3 剪贴板三选一通道表

| 你想复制的 | 通道 | 例子 |
|---|---|---|
| 可编辑元素内文本（input/textarea/Monaco） | **浏览器原生**——什么都不用写 | 输入框内 Ctrl+C/V |
| 任意文本 | `window.linkdesk.clipboard.writeText` | 复制选中文本到系统剪贴板 |
| 文件/路径列表 | `window.linkdesk.clipboard.writeFileList` | 文件树复制 → 资源管理器可粘贴（CF_HDROP） |

**注意：** 可编辑元素走浏览器原生，**不要**声明快捷键也不要拦截——Electron/Chromium 自动接系统剪贴板。

## 7. 侧栏列表选中条目 → `onMouseDown`（不是 `onClick`）

**❌ 禁止：** 侧栏垂直列表中选中条目用 `onClick`。

**✅ 正确：**
```tsx
<div
  className={`my-list-item${isActive ? " active" : ""}`}
  onMouseDown={() => onSelect(item.id)}
>
  <span>{item.label}</span>
</div>
```

**理由：** 侧栏条目垂直紧邻——快速点击时 mousedown 在条目 A、mouseup 滑到条目 B。浏览器 `click` 事件规范：mousedown 和 mouseup 落在不同元素 → click 投递到两者的共同祖先 → React 在祖先上找不到 handler → 静默丢失。`onMouseDown` 只关注按下位置，不要求释放在同一元素——消除快速点击丢事件。

**对标 VS Code：** Explorer 文件树选文件用 `onMouseDown`，不是 `onClick`。这是经过千万用户验证的模式，不要自己设计。

**适用场景：** 侧栏中任何垂直排列、条目间距小的可点击列表——会话列表、文件树、数据库连接、MQTT 主题、设备列表等。

**子元素的处理：** 条目内的操作按钮/输入框需要加 `onMouseDown={(e) => e.stopPropagation()}` 防止误触父条目的选中：
```tsx
<button
  onMouseDown={(e) => e.stopPropagation()}
  onClick={(e) => { e.stopPropagation(); handleDelete(); }}
>
  ✕
</button>
```

## 8. 插件自有数据模型 → `Emitter` 响应式模式

**❌ 禁止：** command handler 里改 model 后手动调 `rerender()` / `setVersion()` / 传 `treeVersion` prop。

**✅ 正确——Web 标准 `EventTarget`（零核心 import，插件自有类直接继承）：**
```typescript
class MyModel extends EventTarget {
  private _items: Item[] = [];

  add(item: Item): void {
    this._items.push(item);
    this.dispatchEvent(new CustomEvent("change"));  // ← 每个改状态的方法末尾 dispatch
  }

  remove(id: string): void {
    this._items = this._items.filter(i => i.id !== id);
    this.dispatchEvent(new CustomEvent("change"));
  }
}
```

```tsx
// 组件 mount 时订阅，unmount 清理
function MyView({ model }: { model: MyModel }) {
  const [version, setVersion] = useState(0);

  useEffect(() => {
    const onChange = () => setVersion(v => v + 1);
    model.addEventListener("change", onChange);
    return () => model.removeEventListener("change", onChange);  // unmount 自动注销
  }, [model]);

  const items = useMemo(() => computeItems(model), [model, version]);
  // ...
}
```

**理由：** 三次时序 bug（badge 0 / when 失效 / 刷新不更新树）根因都是 module 级 command handler 改了 mutable model，React 感知不到。model 自己通知变更（`EventTarget`/`CustomEvent` 是 Web 标准，不需要壳的 `Emitter`）——handler 只改 model，不碰 React。

**适用场景：** 插件有 module 级 command handler 需要改数据后触发 UI 刷新。

**⚠️ 插件禁止 `import { Emitter } from "@src/core/CoreEvents"`——那是壳内部实现（插件通信铁律 + ESLint `noCoreImportInPlugin` error 级拦截）。插件自有 model 用 Web 标准 `EventTarget`；插件与插件/壳之间的事件走 `window.linkdesk.events`（见 `07-插件间通信.md`）。**

## 9. 系统 UI 浮层 → linkdesk API（quickPick / notifications / dialog）

**❌ 禁止：** 手写选择器弹层 / `window.alert()` / `window.confirm()` / `import ... from "@src/core/..."`。

**✅ 正确：**
```tsx
// 选择器——window.linkdesk.quickPick.show({ items, placeholder, prefix })
const picked = await window.linkdesk.quickPick.show({
  placeholder: "选择目标会话",
  items: [
    { label: "会话 A", description: "/dev/ttyUSB0" },
    { label: "会话 B", description: "/dev/ttyUSB1" },
  ],
});

// 通知——window.linkdesk.notifications.show(message, { type })
await window.linkdesk.notifications.show("已连接", { type: "info" });
await window.linkdesk.notifications.show("校验失败", { type: "error" });

// 确认 / 提示 / 文件选择——window.linkdesk.dialog
const ok = await window.linkdesk.dialog.confirm("确定删除该会话？");
await window.linkdesk.dialog.alert("版本冲突，已跳过");
const file = await window.linkdesk.dialog.openFile({
  filters: [{ name: "DXF 文件", extensions: ["dxf"] }],
});
```

**理由：** 三者都是池内宿主统一渲染（QuickPickHost / **铃铛宽通知面板** / DialogHost）——样式与壳一致、随主题与字号缩放走。手写浮层 = 风格不一致 + keep-alive 下 `position: fixed` 失效。完整签名见 `contracts/linkdesk.d.ts`。

> ⚠️ **通知不是「自动消失的浮卡」**（通知面归一 +更正）：右下角窄 toast 链路已整删，**唯一通知面 = 状态栏铃铛宽面板**。作者要知道的三件事：
> 1. **通知不弹卡、不抢焦点、不挡操作**——它进铃铛（未读计数 +1），用户点开才看见。别把通知当「必须被看见」的通道：要用户当场决定 → 用 `dialog.confirm`（模态、抢焦点）。
> 2. **同来源常驻有配额**——按 `options.source` 分组，每组常驻最多 5 条，超出顶掉同来源最老的。刷屏不会堆成墙，但**也别指望靠通知留长期记录**。
> 3. **键盘可达是「面板可达」，不是「通知可达」**——铃铛可用键盘聚焦打开、面板内可 Tab 走遍、`Esc` 关；但面板**没有焦点陷阱**（非模态，焦点可自由离开）。**别写「按 Tab 就能到我的通知按钮」这种假设**——用户可能根本不开面板。

**通知主动作按钮（`notifications.show` 的 `actions`）：** 失败 / 需要用户行动的通知可带 `actions` 按钮数组——点击走**命令系统**执行（对标 VS Code `showErrorMessage(msg, { title, command })` 动作）。命令 handler 由插件自注册（`commands.registerCommand`）：

```tsx
// 失败 toast + [重试]/[查看依赖]——command = 插件自注册命令
await window.linkdesk.notifications.show("安装失败：无法连接源", {
  type: "error", // error 类 toast 停留 8s（够读诊断）；info/warning 停留 6s
  actions: [
    { id: "retry", label: "重试", isPrimary: true, command: "myplugin.retryInstall" },
    { id: "deps", label: "查看依赖", command: "myplugin.openDeps" },
  ],
});
// 命令可带参——点击执行 command(...args)
await window.linkdesk.notifications.show("保存冲突", {
  type: "warning",
  actions: [{ label: "强制保存", command: "myplugin.saveForce", args: [filePath] }],
});
```

按钮文案 = 最终显示文本（壳不二次翻译）；`isPrimary: true` = 主按钮（accent），不设 = 次级文本按钮。**不传 `actions` = 现状无按钮，零行为变化**。完整类型见 `contracts/linkdesk.d.ts`（`notifications.show` options 的 `actions`）。

**进度通知 + 长驻通知 + 来源身份：** `show` **一律返回句柄**（不是只有进度条才有）。三条最容易踩空的写法：

```tsx
// ① 进度通知——句柄驱动同一条通知（不会刷出 N 条）
const h = await window.linkdesk.notifications.show("正在下载…", {
  progress: true,          // 开真进度条；不传 percent = 不定态动画
  source: "myplugin",      // 见 ③
});
await h.update("正在下载…", 42);   // 0-100；只传 message = 保持不定态
await h.finish("下载完成");        // 关闭进度条，可选补一条完成通知
// 或 await h.cancel();            // 直接关掉，不补完成通知

// ② 长驻通知——不自动消失，等用户点 ×（错误诊断类用）
await window.linkdesk.notifications.show("端口被占用，请关闭其他程序", {
  type: "error",
  persistent: true,
});

// ③ 来源身份——面板按它分组，每组常驻各 5 条配额
await window.linkdesk.notifications.show("同步失败", { source: "myplugin" });
```

**三个必须知道的点：**

1. **句柄是唯一钥匙**：一条通知**只能被创建它的那个句柄**更新/删除。别处 `show` 同文案 = 另一条通知，撤不掉对方。撤长驻通知（如失败的 `persistent`）就用它自己的句柄或让用户点 ×。
2. **`source` 必须自己报**：池是单进程共享 realm，所有插件共用同一个 `window.linkdesk`，preload **无法**知道这次 `show` 是哪个插件发的 ⇒ 只能作者显式传。**不传 → 全落「其他」组**；插件传自己的插件 id，壳自身域用 `app.<域>`。
3. **`persistent` 有配额**：每组（按 `source`）常驻最多 5 条，超出顶掉同来源最老的并给汇总提示。**长驻 ≠ 无限留档**——要留档写自己的文件。

> 完整的**行为契约**（不是签名，签名看 `contracts/linkdesk.d.ts`）在 [`01-插件API契约.md`](01-插件API契约.md) §3.2 的 `notifications` 行——本节只给写法，语义以那里为准。

**富内容确认框（`dialog.confirmContent`）：** 要确认框里放**不止一行字**（表单 / 列表 / 截图 / 自定义排版）时用这条——**对话框是壳（居中、遮罩、Esc、焦点锁、点遮罩取消），内容由你的视图自画**（对标 VS Code「对话框是壳、内容插件定」）：

```tsx
// 1) plugin.json 先声明这个内容的视图（contributes.views 的任意容器均可）
// 2) 代码里按「声明 id」寻址打开它
const ok = await window.linkdesk.dialog.confirmContent({
  pluginId: "myplugin",      // 内容归属插件（壳据此复合寻址）
  viewId: "myplugin.confirmImport", // 内容视图声明 id
  title: "导入确认",          // 兜底标题——content 视图解析失败时壳回落纯文字确认
  message: "将覆盖 3 个条目",  // 兜底正文
  payload: { files: ["a.ts", "b.ts"] }, // 不透明载荷：壳不解释，你的视图自己读
});
if (ok) { /* 用户确认 */ }   // false = 取消 / 关闭
```

内容视图那一半（**同一份代码里的另一个视图**，读载荷 + 表态）：

```tsx
// 你的内容视图组件里——挂载即打开，读一次够（每次开新弹窗都是全新挂载）
function MyConfirmContent() {
  const data = window.linkdesk.dialogHost.current();
  if (!data || data.open !== true) return null;        // 防御：不白屏
  const payload = data.content?.payload as MyPayload;
  return (
    <div>
      {/* 正文排版、按钮全归你画 */}
      <button onClick={() => window.linkdesk.dialogHost.cancel()}>取消</button>
      <button onClick={() => window.linkdesk.dialogHost.confirm()}>确定</button>
    </div>

}
```

**兜底是硬的**：`viewId` 解析不出来（视图没声明 / 声明插件没装）→ 壳**回落成纯文字确认框**（用 `title`/`message`），弹窗照样出、**不会静默死**。所以 `title`/`message` 别省。载荷经结构化克隆过 IPC，只能放可克隆的数据（不能放函数/React 元素）。结算只有 `dialogHost.confirm()` / `dialogHost.cancel()` 两条路——**别自己 `setState` 关弹窗**，壳不认。

## 10. 字号 → `--font-size-*` token + `--ui-scale`（度量体系归一化）

**❌ 禁止：** 插件文本字号写裸 `px`（`font-size: 14px`）——`check-font-scale-audit` 门禁（`npm run check`）机械拦截。

**✅ 正确：** 字号消费 `var(--font-size-*)`；行高 unitless（`1.5`）或 `calc(... * var(--ui-scale))`；固定上界（输入框/按钮/状态栏高）写 `calc(Npx * var(--ui-scale))` 随全局缩放。统一全局字号缩放（设置 `app.uiFontScale` 85–150%，恒显恒生效）。

**档位表**（100% 渲染 = `--ui-scale: 1`；引擎按缩放系数算好最终 px）：

| 档 | 基准 px | 语义 |
|---|---|---|
| `--font-size-2xs` | 11 | 徽章/路径 |
| `--font-size-xs` | 12 | 次要文本/按钮/统计 |
| `--font-size-sm` | 13 | UI 主文本（对齐 VS Code 13px） |
| `--font-size-md` | 14 | 菜单/tab/文件树 name |
| `--font-size-lg` | 16 | 图标字形/内容图标（配 14px 文字） |
| `--font-size-xl` | 18 | 区标题 |
| `--font-size-2xl` | 22 | 行图标/大字 |
| `--font-size-3xl` | 28 | pd-name |
| `--font-size-4xl` | 30 | welcome-title |

**铁律 + 边界（对标档案 §五 图标裁决 / §六.2 monaco 孤岛拍板）：**
- **独立显示图标不随字号比例**（装饰/品牌语义，与文本不直接相邻）——`.icon-btn .plugin-icon--codicon` 24 / `.plugin-icon--emoji` 24 / `.hamburger-btn` 20 / hero-icon 48 / 行图标 20 等，白名单豁免见 `scripts/check-font-scale-audit.mjs`。
- **内容级字号走 `contributes.configuration`**（如 `editor.fontSize`）——大文本区/编辑器内容由插件自有配置控制，不随 `--ui-scale`。
- **monaco 内容孤岛先例**：编辑器内容读 `editor.fontSize`，chrome（状态栏/面包屑）随全局——两轴正交，各管各的。
- **对齐规则**：现有 `NNpx` 迁移到档位按「+1 档」——`12→sm / 13→md / 11→xs / 10→2xs / 14→lg / 18→xl`（100% 即放大到新默认基线，对标 VS Code）。

## 11. token 契约——六域矩阵 + 诚实边界 + 数据纪律（.5）

> **一句话：** 写 UI 前先查 11.1 六域矩阵——用 `var(--*)` 的表单/控件/表面**自动跟随主题 + 玻璃 + 全局缩放**，零插件感知。做对靠推荐、做错靠门禁显红但 WARN、绕过靠标准 eslint-disable 知情声明（内容/品牌死色合法豁免，见 11.2）。
> 门禁 = `linkdesk-plugin-sdk lint`（`@linkdesk/plugin-sdk` 内置）：eslint 规则腿 + 三 check 扫描腿双轨，15 项**全 WARN 永不 fail build/上传**——是建议不是封锁。作者项目根跑一次，违规即红 + 自解释修复文案。

### 11.1 token 六域矩阵——作者知道有哪些变量，才写得出「自动跟随」

| 域 | var() 键（完整清单永远以 `src/index.css` 为准） | 作者写法 | 门禁覆盖 |
|---|---|---|---|
| **颜色** | `--text-primary/--text-secondary/--text-muted`（文字色来源由 fontTone 控）+ `--bg-window/--bg-side-panel/--bg-card/--bg-input/--bg-selection` + `--accent/--accent-hover` | `color: var(--text-primary)` | `linkdesk/no-hardcoded-hex` |
| **表面** | `--bg-*` 表面填充 + `--surface-radius`（跟壳全局圆角滑杆） | `background: var(--bg-card)` | `linkdesk/no-hardcoded-hex` |
| **圆角** | `--radius-xs/sm/md/lg/xl/2xl` + `--surface-radius` | `border-radius: var(--radius-md)` | `linkdesk/no-hardcoded-radius`（border-radius 裸 px 即红） |
| **玻璃** | `--glass-blur/--glass-saturate/--glass-tint/--glass-morph/--glass-specular…`（`src/index.css` 全组） | `backdrop-filter: blur(var(--glass-blur)) …` | 契约引导——组合形态，逐条门禁管不住 |
| **字号** | `--font-size-2xs … 4xl` + `--ui-scale`（`app.uiFontScale` 缩放轴，档位表见 §10） | `font-size: var(--font-size-md)` / em/rem | `check-font-scale`（check 腿——字号裸 px 即红） |
| **字体族** | `--font-ui` / `--font-mono` | `font-family: var(--font-ui)` | 契约引导（作者合法自选字体） |

`var(--*)` = 换主题/玻璃/全局缩放自动跟随，零插件感知——**这正是 @linkdesk/ui 控件层「零思考跟随」的底层原因**——控件全部写在 token 上，插件 `npm i @linkdesk/ui` 消费即跟随。控件复用统一从 `@linkdesk/ui` import（见 §速查），不手写轮子。

### 11.2 诚实边界 / 知情绕行——内容与品牌色可以有自己天空

**门禁三档（07 §六）：** 推荐（照抄即对）/ 警告（15 项自解释，红但 **WARN 永不 fail**）/ 知情绕行（标准 eslint-disable 声明带理由）。**任何生态都管不住作者硬写死颜色**——VS Code 也有不跟随主题的扩展。门禁做的是把「做对」变默认、「做错」变显式红但可**知情绕行**：注释带理由 = 浏览器危险站点「仍要访问」的知情确认，不是静默关灯。

**合法豁免类别：** var() 回退 hex（`color: var(--x, #fff)` = 合规形态，不拦）/ 取色器色板 / canvas 绘图 / 引擎区 / **内容画布视图级豁免**。

**内容 vs chrome 边界（愤怒的小鸟考核实证）：** 游戏 / 数据可视化 / canvas 主区 = **内容世界，不是 UI chrome**——UI chrome 跟主题走（var()/t()/@linkdesk/ui），内容可以有自己天空（草地/血条红/天空蓝不必跟主题）。作者**视图级一次声明豁免**，门禁对内容区不逐条亮灯（一个游戏 5-10 处硬编码逐条 disable 太吵）：

```tsx
/* eslint-disable linkdesk/no-hardcoded-hex, linkdesk/no-hardcoded-radius -- 内容画布：游戏主区自绘 */
export function GameBoard() {
  return <canvas /* 画蓝天草地血条红——内容世界，不是 UI chrome */ />;
}
```

```tsx
// 行级知情绕行（品牌死色徽标——只豁免本行，其他行照样拦）
// eslint-disable-next-line linkdesk/no-hardcoded-hex -- 品牌固定色徽标
const PRO_BADGE = <span style={{ color: "#ff6b00" }}>PRO</span>;
```

```css
/* css 里同款格式（check 脚本认）——取色器色板固定值，本行豁免 */
/* eslint-disable-next-line linkdesk/no-hardcoded-hex -- 取色器色板 */
.swatch--brand { background: #ffd700; }
```

**语义：** 命中豁免的行**整体静默**不亮灯（对齐 eslint 原生 suppress——disable 声明后不逐条报）；**无声明 = 未处理偏离**，`linkdesk-plugin-sdk lint` 报告正常亮 WARN。**不是新语法**——与壳现有 `no-hardcoded-hex` 报错建议格式同款。**背景不被玻璃化是机制层天然成立**——backdrop-filter 只刷壳表面元素，不套插件视图根节点，作者画的内容本就不被玻璃化。

### 11.3 非 CSS 引擎适配——翻译桥（引擎自渲染不走 CSS 变量）

monaco 式引擎自渲染（canvas / WebGL / 富文本引擎同理）不消费 CSS 变量——要跟随主题走**翻译桥**：订阅主题变更 → 翻译成引擎自己的 theme API。先例：`src/services/theme-sync.ts`（住在 **editor 插件自己的仓** `Encaron/linkdesk-plugin-editor`——起发货插件源码不在壳仓）：

// 订阅主题变更（事件可能先于 mount → 顶层注册或 active 守卫，见 11.5）
const off = window.linkdesk.events.on("theme:changed", () => {
  engine.updateTheme(translateTheme()); // 把你的 token → 引擎 theme 对象

### 11.4 插件私有数据通道——自建设置界面 / 自管存档时选通道

作者自建设置 UI / 自管存档（不走壳设置页声明）时，数据落地按语义选：

## 12. CSS 类名——自己的元素用自有前缀，宿主保留名不要「借用」

**先记住一件事：插件视图的样式表不是你自己独占的。** 同一个窗口里同时加载着宿主的样式、共享组件
（`@linkdesk/ui`）的样式、以及**所有已加载插件**的样式——**类名是全局标识符**。你写下一个类名，
就等于占用了这个名字；别人也用这个名字，两边的样式就会落到同一个元素上。

🔴 **引用侧也有腿了（2026-09-20，SDK 0.1.46 起）**：TSX `className` **字面量**里引用的本插件前缀类名，必须能在本仓 CSS（含 scoped 规则）里找到定义——`linkdesk/no-reserved-class-name` 家族新判据机械把关。头号根因 = CSS 块注释里写 `--text-*/` 这类文本：`*/` 把注释**提前闭合**，残渣黏住下一条规则把它整条吞掉（生态首例，样式静默丢失零报错）；文案列三种常见根因（拼错／漏 import／注释吞规则）。动态拼接（模板插值 / clsx / 变量）跳过并计数。

**三条纪律：**

1. **给自己的元素起的类名，必须以 `pluginId` 加连字符开头**——`settings-*`、`editor-*`、`file-tree-*`……
   `pluginId` 就是你 `plugin.json` 里声明的那个 id（官方插件统统这么做）。**别用缩写**：`ms-`、
   `mpd-` 这类简写写法**已经废弃**——缩写不保证唯一，两个插件各自缩写成 `ms-` 就撞在一起了；
   而 `pluginId` 的唯一性由发布流程保证（发布后不可变），拿它当前缀是免费的防撞。
2. **`@keyframes` 的名字一样要带前缀**（`file-tree-fadeIn`），并且**改名字时同笔改 `animation:` 的引用**——
   关键帧名与类名一样是全局标识符，重名时后加载的那份会把前一份的动画顶掉。
3. **下面这些名字属于宿主保留名，不要拿来给自己的元素命名**（用了就会被宿主的样式命中）：

| 来源 | 保留名 | 说明 |
|---|---|---|
| 宿主**给你的**输入框工具类 | `.ldk-input` | 输入框工具类——**直接用即可**（它本来就是给你的输入框用的）。⚠️ 它是整个 `ldk-` 家族里**唯一**鼓励你**消费**的一个（其余的 `ldk-` 名是「别碰」，它是「拿去用」） |
| 共享组件类名 ＋ 宿主容器类名 | **整个 `ldk-` 命名空间**——今天有 `ldk-badge`、`ldk-button`、`ldk-combobox`、`ldk-mdv`、`ldk-selectbox`、`ldk-sle`、`ldk-slider`、`ldk-toggle`、`ldk-hint-card`（2026-09-19 起，悬停说明卡）等（共享组件），另含宿主自己的容器类（如 `ldk-titlebar`、`ldk-input`、`ldk-setting-group`） | 分别是 `@linkdesk/ui` 里徽标 / 按钮 / 组合输入 / Markdown 容器 / 下拉 / 数组编辑器 / 滑杆 / 开关的类名。**你不用记这些名字**——记一条就够：**凡 `ldk-` 开头都是宿主自己的（共享组件 ＋ 宿主界面容器），不要拿给自己的元素用**（唯一的例外是上一行的 `.ldk-input`：那个是**给你用的**） |

**`@keyframes` 的名字同理**——宿主自己也用着下面这些动画名，给你的动画起名时避开它们。重名的后果和类名一样（后加载的那份顶掉先加载的），而且同样是**静默**的：你的动画或宿主的动画有一个不播了，控制台没有任何报错。

| 保留的关键帧名 | 说明 |
|---|---|
| `ldk-selectbox-in` | 共享组件下拉框的入场动画 |
| `ldk-drop-zone-in` | 拖放区的入场动画（宿主的自有动画一律带 `ldk-` 前缀） |
| `ldk-dropdown-card-in` | 下拉卡片的入场动画 |
| `ldk-floating-panel-in` | 浮动面板的入场动画 |
| `ldk-group-tab-enter` | 分组标签的入场动画 |
| `ldk-group-tab-exit` | 分组标签的退场动画 |
| `ldk-notif-icon-spin` | 通知图标的旋转 |
| `ldk-notif-progress-scan` | 通知的进度扫描 |
| `ldk-rn-spin` | 发行说明页刷新图标的旋转 |

**引用的名字必须在架子上**——纪律 2 说的是「改名时同笔改引用」；这条是它的另一半，而且**机器会查**：
你 `animation` / `animation-name` 里写的名字，要么是**本仓 CSS 里 `@keyframes` 定义过的**，要么是
**上面那张保留表里的**（引用宿主的动画是**合法消费**，不会判你）。引一个**谁都没定义**的名字，
动画**不报错、不警告，只是不动**——症状是「我的动画怎么没生效」，而控制台一片安静（同一个窗口里
还有别的插件和宿主在跑，你很难一眼看出是这一条）。`@linkdesk/plugin-sdk` **≥ 0.1.37** 起，插件的
lint 会把这种**悬空引用**逐条报出来（**文件名 ＋ 行号 ＋ 名字**）；确需引用一个门禁看不见的名字
（例如动画由运行时注入），用标准 `eslint-disable` 注释写明理由。

> 🔧 **维护者注（作者可跳过）**：上面两张表的「**保留名**」「**保留的关键帧名**」两列都是**机器读的**——`npm run check` 里的门禁
> （`scripts/check-reserved-names-doc-sync.mjs`）把它们与登记表
> `packages/plugin-sdk/schemas/reserved-class-names.json` **双向核对**：登记表里的名字必须在这里出现，
> 这里出现的名字必须在登记表里登记（裸名）、或在宿主源码里真实存在（`ldk-` 名）；关键帧表与登记表的
> `keyframes` 段同样**双向**。
> ⇒ **改这两列 = 改公共面**：加/删一个名字要**同笔改三处**——登记表 ＋ 中英两棵树的这两张表。
> 两列**只放名字**，解释写「说明」列。

**还有一条跟命名空间有关的**：你的 `pluginId` **不得以 `ldk-` 开头**——整个 `ldk-` 命名空间是宿主的，
一个叫 `ldk-tools` 的插件用纪律 1 派生出来的前缀（`ldk-tools-*`）会**由构造落进宿主空间**，纪律 1
也就跟着失效了。这条约束写在 `plugin.json` 的 schema 里，编辑器会当场提示。

**要它们的样子，就用它们的组件**——`import { Button } from "@linkdesk/ui"`，不要手写它的类名
（手写等于绕过组件，组件升级你就掉队）。

**状态类一律复合使用**：`.你的类.active`、`.你的类.on`（不要裸写 `.active {}`、`.on {}`——那会把
宿主和其他插件里带同名状态类的元素一起改掉）。

**反例（真实踩过）**：把宿主保留名当成「随手可用的样式名」套到自己的元素上，结果底色和文字被涂成
同一个颜色、文字被背景吞掉，界面上看着就是「一块纯色」——**不报错**，只是长得不对，很难查。

**删组件时，同笔删它的 CSS 规则**——被壳的共享组件（`SidePanel` / `SidebarSection`）接管了的节点，
插件侧**不要留孤儿规则**：规则还在、节点没了，它就成了一个**静默吃掉样式**的挂载点——谁哪天往那个
类上挂样式（比如一个本地 token），都会**静默失效**（1.24 真实事故：官方 `serial-monitor` 的侧栏状态点
颜色被静默丢掉，v1.0.17 当场修正）。拿不准有没有孤儿规则，跑壳仓的
`npm run audit:plugin-dead-css`——它把「定义了、源码没人用」的自有前缀类逐条列出来（只报不拦）。

### 12.1 从旧版 `@linkdesk/ui` 升上来——一件要你自己改的事

共享组件的类名带上了 `ldk-` 前缀（`@linkdesk/ui` **0.2.0** 起）。这件事**只影响一种写法**：
你写在**插件自己 CSS 里**、用后代选择器去微调共享组件外观的那些规则。**升级前不用动，升级时改一处前缀即可。**

- **什么时候受影响**：把 `@linkdesk/ui` 升到 **0.2.0 之后**——**不是立刻**。旧版本里这些组件的类名是
  `.badge` 这样的裸名，包里带的 CSS 与组件自洽，**你不升级就不会坏**。（依赖写 `^0.1.x` 时不会自动
  跨到 `0.2.0`，所以只有你主动升级的那一下才需要动。）
- **什么会受影响**：你**插件自己 CSS** 里的这类后代选择器——
  `.control-bar .combobox { … }`、`.settings-slider-control .slider { … }`、`.changelog .mdv { … }`
  等等。**组件自己的样式不受影响，你自己的类名也不用改。**
- **怎么改**：把选择器里**指向共享组件的那一段**加上 `ldk-` 前缀——`.combobox` → `.ldk-combobox`、
  `.slider` → `.ldk-slider`、`.mdv` → `.ldk-mdv`、`.badge` → `.ldk-badge`、`.selectbox-trigger` →
  `.ldk-selectbox-trigger`、`.combobox-field` → `.ldk-combobox-field`——**族里的名字（`-trigger` / `-field` /
  `-input` 这类后缀）一样带前缀**。你自己的前缀（`.control-bar`、`.settings-*`）照旧。
  **升级后拿这八个旧基名 `.badge`、`.button`、`.combobox`、`.mdv`、`.selectbox`、`.sle`、`.slider`、`.toggle`
  grep 一遍自己的 CSS**：在调共享组件的就加上前缀，其余别动。
- **为什么不自动兼容**：这类失配**不报错**——选择器匹配不上，只是那几条规则悄悄不再生效，界面看着
  「大致还对、就是不太对」。正因为它是静默的，我们才把名字收进 `ldk-` 前缀，并把这段写进文档。

### 12.2 前缀规则（§12 纪律 1/2）上线——既有代码要不要动

**一句话：不改也照常跑，但下次动那个文件就是该改的时候。**

- **官方插件已经按新规则清过账**——本次改名涉及四只：`file-tree`（v1.0.9）、`settings`（v1.0.11）、
  `serial-monitor`（v1.0.12）、`marketplace`（v1.0.33），裸类名与关键帧名都补上了 `<pluginId>-` 前缀；
  其余官方插件仓本来就没有裸定义（它们的类名不是自带前缀，就是根本没定义类名）。以官方插件清单为口径
  的审计读数是 **18/18 合规**。
- **第三方作者没有仓要改**：这条规则只管**你自己写的类名与关键帧名**——不动仓库结构、不动 `pluginId`、
  也不影响别人的代码。你既有插件**不用为它单独发版**。
- **旧的无前缀类名不会报错、也不会失效**——今天照常工作。代价是**撞名的风险仍然在**：另一个插件写了
  同名类名，两边样式就会落到同一个元素上（不报错，只是长得不对，很难查）。
- **合规由工程自带的检查判**：脚手架建出来的工程带着一条严格检查腿（`npm run verify`），它扫你自己 CSS
  里**给自有元素裸定义**的类名和 `@keyframes` 名，不带 `<pluginId>-` 前缀就判红。所以真正的动作是
  **下一次动那个文件时顺手把名字改掉**：`.panel {}` → `.myplugin-panel {}`，CSS 与用到它的 JSX 两侧一起改
  （只改标识符，不动样式值）。

> 现在就想看看自己的工程有没有裸名？在工程根跑 `npm run verify`。

### 12.3 宿主的输入框工具类改名了：`.input` → `.ldk-input`（2026-09-16）

**一句话：如果你的插件写过 `className="input"`，改成 `className="ldk-input"` 就行——样式一模一样，只是名字换了。**

- **改了什么**：宿主原来把一个输入框工具类叫 **`.input`**（不带前缀，是唯一一个不带 `ldk-` 的宿主公共名）。它和本条纪律 1「跨方的名字都带命名空间」冲突 ⇒ 现在统一叫 **`.ldk-input`**。同时宿主的**设置分组卡片** `.setting-group` 也改名为 **`.ldk-setting-group`**。
- **谁受影响**：**在你自己插件的 JSX/TSX 里写过 `className="input"` 的插件**——官方插件里 `settings` 与 `serial-monitor` 两家用过，已在同一批发版改好。**改法就一处**：`className="input"` → `className="ldk-input"`；拼接写法同理（`"input my-input"` → `"ldk-input my-input"`）。**样式零变化**——同一条规则、同一批 CSS 变量，只换了名字。
- **不改会怎样**：输入框**不报错**，只是**失去宿主给的外观**（底色 / 边框 / 圆角 / 内边距），看起来像浏览器原生输入框。
- **什么时候必须改**：在**新壳**上跑就要改。新壳的版本号是 **`0.2.0`**，官方两只插件都已在 `plugin.json` 里声明 `minAppVersion: "0.2.0"`——你也给自己的插件声明同一个值，旧壳上的用户就会收到一句清楚的「需要应用版本 ≥0.2.0」提示，而不是看到一个没样式的输入框（`minAppVersion` 的语义见 [04-插件分发格式 §minAppVersion](04-插件分发格式.md)）。

### 12.4 共享组件剩下的类名也带 `ldk-` 了（2026-09-16）

**一句话：和 12.1 同一件事，只是把当时没覆盖到的组件补上——你若在自己 CSS 里用后代选择器微调过这些组件，升级时加一个 `ldk-` 前缀即可。**

- **改了什么**：§12.1 覆盖的是 `@linkdesk/ui` 的八个基名（`badge` / `button` / `combobox` / `mdv` / `selectbox` / `sle` / `slider` / `toggle`，**0.2.0** 起）。其余组件的类名——外加一个 `@keyframes` 名——现在也带上了前缀（**2026-09-16 那轮起**；版本线怎么读见 [19-组件速查 §2.1](19-组件速查.md)）：

  | 旧族 | 新族 |
  |---|---|
  | `.colorpicker-*` | `.ldk-colorpicker-*` |
  | `.ctx-*` | `.ldk-ctx-*` |
  | `.form-row` | `.ldk-form-row` |
  | `.inline-input`、`.inline-input--compact/--normal` | `.ldk-inline-input`、`.ldk-inline-input--compact/--normal` |
  | `.number-input*` | `.ldk-number-input*` |
  | `.segmented-radio`、`.segmented-radio__option/__label` | `.ldk-segmented-radio`、`.ldk-segmented-radio__option/__label` |
  | `.sidebar-section*`、`.sidebar-pane-view`、`.sidebar-pane-sash` | `.ldk-sidebar-section*`、`.ldk-sidebar-section-pane-view`、`.ldk-sidebar-section-pane-sash` |
  | `.theme-picker*`、`.theme-card`、`.theme-preview` | `.ldk-theme-picker*`、`.ldk-theme-picker-card`、`.ldk-theme-picker-preview` |
  | `.tbadge` / `.tname` / `.pv-bar` / `.pv-dot`（主题卡片内部） | `.ldk-theme-picker-badge` / `.ldk-theme-picker-name` / `.ldk-theme-picker-preview-bar` / `.ldk-theme-picker-preview-dot` |
  | `@keyframes selectbox-in` | `@keyframes ldk-selectbox-in` |

- **谁受影响**：还是**只有你自己 CSS 里**指向这些组件的后代选择器（例如 `.settings-row:has(.theme-picker)`）。**组件自己的样式不受影响，你自己的类名也不用改。** 这件事的意义是共享组件的名字现在全在 `ldk-` 命名空间里——而那条纪律你已经知道：**凡 `ldk-` 开头都是宿主的，别拿给自己的元素用**（唯一例外是 `.ldk-input`，那个是**给你用的**工具类）。
- **不改会怎样**：与 12.1 完全相同——选择器匹配不上，那几条规则悄悄不再生效。**不报错。**
- 🔴 **宿主以后改共享名 / 改样式，你这边不必改代码、也不必改 CSS**——组件与样式**由壳池统一供给**（L9 集中供给，见 [19-组件速查 §二](19-组件速查.md)）：壳升级后同一份实现跟着壳走，界面自然一致。你唯一要维持的是 `@linkdesk/ui` 依赖**别掉出当前版本线**（它决定你本地 dev 与类型解析到的那一份）。
- ⛔ **组件样式同样不从你的源码里来**：源码里出现 `import "@linkdesk/ui/index.css"`（或其 dist / `@import` 形态）会被 SDK 的 lint 腿 `linkdesk/no-ui-css-import` 判红——**没有豁免出口**。把样式烤进插件，等于「壳改样式、全生态跟随」对你失效。
- **什么时候必须改**：当你要支持的壳升到含这次改名的版本时（版本线怎么读见 [19-组件速查 §2.1](19-组件速查.md)——ui 版本 = 壳版本，一条线）。升级后**拿上表里的旧族名 grep 一遍自己的 CSS**：官方插件里只有 `settings` 有 1 处，已在同一批发版改好。
- **这把尺子你也有**（`@linkdesk/plugin-sdk` 0.1.40 起）：你仓里的 lint 自带「悬空名」判据——宿主改了共享名、你没跟上时，**你自己的 CI 会替你喊**（用法与修法见 [16-命名规范 §7.6](16-命名规范.md)）。

### 12.5 自定义属性的**作用域**——`--x:` 写在 `:root` 里就等于写给整个软件

类名那三条纪律管的是**名字**，这一节管**地盘**。自定义属性（`--xxx`）的规矩只有一句：

> **作用域才是命名空间。** 名字随你起，**它住在哪棵子树里**才是它属于谁。

**① 文档级的作用域只有宿主能用。** `:root` / `html` / `body` / `[data-theme="…"]` / `*` 上的定义
**对整个文档可见**——那不是你的地盘：

```css
/* ❌ 这条定义全文档可见 */
:root { --my-panel-gap: 8px; }

/* ✅ 挂在你自己的根类之下，作用域 = 你的子树 */
.my-plugin-root { --my-panel-gap: 8px; }
```

**② 其余定义一律挂在自己的类之下。** 写 `.你的类 { --xxx: … }` 就好——**这里的名字不需要任何前缀**：
`:root` 上的 `--gap` 会跟别人撞，`.my-plugin-root` 下的 `--gap` 不会（作用域已经把地盘划开了）。

**③ `--ldk-*` 自定义属性谁都不许定义**（和类名、关键帧同一条规矩——整个 `ldk-` 命名空间是宿主的）。

**为什么这条比类名还凶**：宿主大部分颜色 / 圆角 / 层级**不是由程序写上去的、而是靠样式表提供的**。
你在 `:root` 里写一个宿主的契约名（比如 `--bg-card`），**你会赢**——整个软件的卡片底色跟着变；
而且**换个主题可能又变回来**（主题会覆盖其中一部分名字）⇒ 症状是「**时好时坏**」，最难查的一类。

**一条自检**（写完 CSS 顺手看一眼）：**「我的 `--x:` 是不是写在 `:root` 里？」** 是 ⇒ 搬进你自己的根类。

**迁移**——已经在 `:root` 里写过自定义属性的插件：

| 情形 | 判级 | 怎么办 |
|---|---|---|
| 名字**带**你自己的前缀（`--my-plugin-gap`） | 🟡 建议改 | 搬进自己的根类。名字是你的、没人跟你抢，但「写在 `:root`」本身没有理由——改完作用域从整个文档缩回你自己的子树 |
| 名字**不带**前缀（`--gap`、`--bg-card`…） | 🔴 必须改 | 它此刻在全文档生效、可能正覆盖着宿主或别的插件的值 ⇒ 把它搬进自己的根类（名字可以照旧保留，**换的是作用域**） |
| 名字以 `ldk-` 开头 | 🔴 必须改 | 换成你自己的名字——`ldk-` 是宿主命名空间 |
| 写在**自己的根类**之下 | ✅ 合规 | 不用动。`.你的根类 .ldk-x { --y: … }` 这类**微调**同样合规（选择器里有你自己的类就行） |

**它怎么被机械守住**：在插件工程根跑 `npm run lint`（或 CI 里的 `npm run verify`）会逐条报出来
——🔴 会让 CI 红，🟡 只提示不拦。「我的插件本地好好的、CI 却红」时先看这一段。

> `docs/02-Electron架构/E6_插件生态与发布/01-插件独立构建/样式命名空间归一化/` 下；宿主侧由

### 12.6 选择器本身也要有「落点」——**禁写无锚选择器**（2026-09-16）

前五节管的是**名字**（类名 / 关键帧 / 自定义属性）。这一节管**选择器的形态**——一条更容易忽略的规矩：

> **类名和 id 是「名字锚」；元素 / 通配 / 属性 / 伪类 / 伪元素不是。**
> 后者**不需要与任何人同名**就能命中别人的元素。

```css
/* ❌ 一条规则改掉「这个文档里所有」的按钮——宿主和其他插件的按钮全在内 */
button { border: none; }
* { box-sizing: border-box; }
#some-id { display: none; }   /* id 也是全局的、可猜的，优先级还高于类 */
:root { outline: none; }      /* `:root` 同样是无锚选择器 */

/* ✅ 挂在自己的根类之下——同一个意图，落点只有你自己的子树 */
.my-plugin-root button { border: none; }
```

**两条规则**（都在插件工程根 `npm run lint` ／ CI `npm run verify` 里**机械判红**）：

| 规则 | 判定 | 为什么 |
|---|---|---|
| **禁无锚选择器** | 选择器**没有**任何 `.类` 或 `#id` 主体（元素 / 通配 / 属性 / 伪类 / 伪元素；**顶层或限定一律禁，`@media` 内也算**）⇒ 🔴 | 它命中「该文档里所有那一类元素」，与谁渲染无关 |
| **跨方命中必须自带自有锚** | 选择器里出现 `ldk-*` 类（**含 `:has(…)` 内的提及**）却**不带** `.<你的 pluginId>-*` 类 ⇒ 🔴 | `ldk-` 是宿主命名空间；**调优必须发生在自己的地盘里** |

⚠️ **第二条不影响「改共享组件外观」这件事本身**——那是**合法特性**（scoped 调优）。它只要求你**带着自家前缀作锚**：

```css
/* ❌ 改的是宿主/共享组件的元素，自己却一点落点都没有 ⇒ 判红 */
.ldk-toggle { transform: scale(1.1); }

/* ✅ 同一个意图，写在自己的地盘里 ⇒ 合规 */
.my-plugin-root .ldk-toggle { transform: scale(1.1); }
```

**为什么值得专门记住**：宿主自己就有 **17 处**这样的「无锚选择器」（`*` 重置 ／ `html`·`body` ／
`[data-theme]` ／ `*:focus-visible` ／ 滚动条一族 ／ `input[type="number"]`·`select`）——它们**是有意的
共享基线**，插件一直在依赖它们（也可以覆写）。正因为它们存在，**你的无锚选择器一定会命中它们**：
你写 `button { }`，宿主的按钮、其他插件的按钮，全都会跟着变。

**迁移**：**今天 0 存量**——官方 18 只插件 ＋ 壳内夹具全量复核（`npm run audit:plugin-prefix -- --all`
的「无锚 S2 ／ 跨方 S3」两列）都是 **0** ⇒ **你不需要改任何东西**；这条规矩是**预防性**的。
