## 一、新增腿 `check-ai-policy.mjs`

| # | 判据 | 级别 | 怎么查 | 负控样本 |
|:--|:--|:--|:--|:--|
| P1 | **OPS 全覆盖**：`whitelist.ts` 的每个 op 在 `OP_RISK` 有登记 | error | 静态解析两张表做差集 | 删一条 `OP_RISK` ⇒ 红 |
| P2 | **风险表无死条目**：`COMMAND_RISK` 的每个 id 在当前命令面存在 | warn | 运行期 `describe` 快照比对（允许视图态 `pending`） | 塞一条假 id ⇒ 黄 |
| P3 | **`userOnly` 不可被 AI 调**：`runShellCommand` 对 `userOnly` 一律 `EPROTECTED` | error | 单测：注册一条 `userOnly` 假命令，经 `exec` 调用 ⇒ 断言 `EPROTECTED` | 去掉判定 ⇒ 测试红 |
| P4 | **档位写入单一入口**：`setConfigurationValue("ai.policy.*")` 只许出现在 `policy/policyState.ts` | error | grep（排除测试） | 在 `aiPolicyCommands.ts` 直接写 ⇒ 红 |
| P5 | **策略键不散落**：`"ai.policy.mode"` 字面量只许出现在 `src/App/config/aiBridge.ts` 与 `policy/` | error | grep | 在 settings 插件里出现 ⇒ 红 |
| P6 | **插件不持策略语义**：插件仓源码不得出现 `ai.policy.` / 档位字符串常量 | error（官方）/ warn（第三方） | 跨仓 grep | 在设置插件里写 `if (mode==="auto")` ⇒ 红 |
| P7 | **回执/确认文案单源**：插件里不得手写「AI 请求」「允许一次」等话术 | warn | 词表 grep | 在插件里手拼 ⇒ 黄 |
| P8 | **状态订阅单源**：池侧读档位只许经 `services/aiPolicy`，不得读 `settings.json`/配置 IPC 直读 | error | import/字符串扫描 | 直接订阅 `ai.policy.mode` ⇒ 红 |

## 三、自测与历史回放

- `--self-test` 至少覆盖：
  1. 4×4 判定矩阵（16 格，纯函数直打）；
  2. 未登记命令兜底（R1）与 `kind:"write"` 兜底（R2）；
  3. `userOnly` 拒调（正控/负控各一）；
  4. `full` 档 R3 放行、`auto` 档 R3 必问；
  5. 配置损坏 ⇒ 按 `ask`（fail-closed）。
- **历史回放**：本档是新能力，无旧账可回放；用**合成样本**证明会红（照 06 §六 的口径，如实记「无历史样本」）。

## 四、门禁之外的评审判据（人审）

| 判据 | 问句 |
|:--|:--|
| 新 op 是否只「请求」不「批准」 | 这个 op 能不能改变自己的权限？能 ⇒ 不进 AI 面 |
| 新命令是否可能被用来改门 | 命令是否写 `ai.*`、是否起进程、是否改白名单？是 ⇒ `userOnly` |
| 新 UI 是否第二套 | 是否复用 `DialogHost` / 通知面板 / `AiPolicyPicker`？ |
| 新文案是否第二份 | 是否来自风险表 / `receipt.ts`？ |
| 第三方命令风险谁声明 | manifest `contributes.commands[].risk` 是否补（见 04） |
