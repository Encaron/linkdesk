## 〇、用户固定话语（全程有效，优先级最高）

1. **⛔ 软件本体（壳）不打包发行**——打包上传时间太慢。壳侧改动一律 `npm run electron:dev` dev 版先测（秒级热更新），落仓后进**攒批**等统一发版。
2. **✅ npm 包与插件侧：授权打包发行**——`@linkdesk/*` 各包、settings 等插件仓、主题仓，做完即可 bump ＋ CHANGELOG ＋ 发版；含 `git push`（**推必带代理 `127.0.0.1:7890`**）。⛔ 撤版、改写已发布 tag 仍归用户。
3. **最终测试无误后，用户会授权把任务夹 `git mv` 进 `已落地/`**——归档动作等用户点头，⛔ 不自作主张归档、不自作主张划销池表。
4. **任务期间可能有并行 AI**：**git 提交只 add 你自己任务的文件**（⛔ `git add -A`／`git add .`；提交前 `git status` 逐行核对暂存清单，别人的半成品一个不加）；commit message 带任务夹标识（例 `fix(滑杆件): …`）。
5. **热点文件纪律**：同一时刻一个热点文件只归一个 AI（§三 表）。发现你也要改的文件别人在改 → **挂起等信号**，在 §六 打点表留言，先去做你夹里不冲突的格子。
6. **打勾语义**：任务单里 `[x]` 只在「实现 ＋ 验证通过」后打；**收工必打点**（§六：日期＋推进到哪格＋给下一棒的留言）。
7. **设计图硬门**：壳共享 UI 改动必须过 `/impeccable` ＋ `/ui ux pro max` ＋ `html-blueprint`（整页拟真、完整软件轮廓、控件比例量壳源码）。已出稿的夹直接用，⛔ 不重画。
8. 规矩没写的情况：**问用户**。⛔ 不自作主张扩大范围；**已拍板的夹才动工** —— 池表（§一）里还没拍的行等拍板。
