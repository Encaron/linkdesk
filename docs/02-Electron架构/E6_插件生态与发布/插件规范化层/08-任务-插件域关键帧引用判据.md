### 8.7 补发 `0.1.38` 的由来（诚实记录 · 一条教训）

`0.1.37` 发出去**之后**，本格才做**轮次记法订正**（把源码注释里的 `1.50` 改成 `E6#112 · 2026-09-18`——`1.50` 是非样式命名空间轴（`E6#111l`）的收官轮号，清单 `:160` 明写 `E6#112`／`E6#113` **不许塞进 1.50**）。改动落在 `packages/plugin-sdk/src/eslint/**` 的**注释**上，但注释**在发货面里**（包内含 `sourcesContent` 源映射）⇒ 收尾 `npm run release:mark` **被机器拦下**：

```
⛔ [npm-release] 拒绝记基线——@linkdesk/plugin-sdk: 作者面内容变了，但版本号仍 0.1.37（= 基线版本）
   ⇒ 升版本 + npm publish    ／    确认这次就是不发？→ npm run release:mark -- --allow-drift
```

**修法**：`0.1.37` → **`0.1.38`**（只动注释，判据行为逐字未变）＋ `npm publish --registry=https://registry.npmjs.org`（shasum `c3b7a9f1e0173b3cd42173a6accdad4ea5793bc1`，172 files）＋ 等货架复制（本机实测 **约 4 分钟**才从 `0.1.37` 翻到 `0.1.38`）＋ `npm run release:mark` ⇒ 基线记 `@linkdesk/plugin-sdk@0.1.38`（52 文件）＋ `@linkdesk/plugin-docs@0.1.18`（48 文件），`check:npm-release` **✔ 无黄灯**。

**教训**：**注释也是发货面**——「先发版、后改字」会造出「内容跑在版本号前面」的漂移，机器拦得对。凡在 `packages/*/src/**` 里动字（含注释），**要么发版前改完，要么按规矩补一版**；⛔ 不许用 `--allow-drift` 把漂移记账成基线。**作者面「≥ 0.1.37」的说法不受影响**（判据自 `0.1.37` 起提供，`0.1.38` 只订正注释）——正因如此，`docs/03-*` 两棵树**本格不再动**（动了就又要发一版 docs），这与 §8.1 发版行里「作者面两棵树 ＋ 产物重生成要一次改完」是同一条教训。
