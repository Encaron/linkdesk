# 02 · 壳侧新目录（非平铺）

> 判据：宿主语义按域分子夹；⛔ 不在 `electron/services/` 根上平铺 `appearancePick.ts` / `appearancePath.ts`。
> 目标：换掉任何 UI 插件，这些能力照旧存在。

---

## 一、目录树


## 二、动作契约（一个动作一个入口）

| 动作 | 入口 | 参数 | 返回 | 风险 |
|:--|:--|:--|:--|:--|
| 选背景图 | `appearance.pickImage`（命令）／`window.linkdesk.appearance.pickImage()` | `{ domain:"background", target:"app"|"zone" }` | `{ picked:true, url:"linkdesk-userdata://...", name }` 或 `{picked:false}` | R1（用户在场，弹系统框） |
| 导入已选路径 | `appearance.importImage(path)`（既有） | 路径 | 受控 URL | R1 |
| 打开资产目录 | `appearance.openDirectory()`（既有） | — | — | R1 |

- **起始目录由壳决定**：`defaults.ts` 一处（`userData/appearance`），插件⛔ 不传目录/不传域名字符串。
- `pickImage` 只在主进程弹系统框；AI 调它时用户必须在场选文件——天然符合 A 判据（不是「AI 偷偷读盘」）。

## 三、声明（让第三方 UI 也做对）

`src/App/config/appearance.ts` 两个背景键补：

```ts
"app.backgroundImage": {
  // ...
  assetDomain: "appearance",
  pickTarget: "app",
},
"app.zoneBackgroundImage": {
  // ...
  assetDomain: "appearance",
  pickTarget: "zone",
},
```

- 通用渲染器（设置插件）只读 `uiHint:"image"` + `assetDomain/pickTarget`，调 `appearance.pickImage`。
- 第三方设置 UI 拿同一份 schema（`workbench.action.listConfigurations` / 配置读取面）即得同行为。
- `assetDomain` 是**宿主声明字段**，不是插件常量；新增域 = 壳加一条注册，插件零改动。

## 四、迁移与删除

| 旧 | 新 | 处置 |
|:--|:--|:--|
| 设置插件 `sharedAdapters.tsx` 的 `defaultPathKind:"appearance"` | 调 `appearance.pickImage({domain,target})` | 同笔删字面量 |
| `dialog-handlers.ts:41` 的 `defaultPathKind === 'appearance'` 映射 | `hostAssets/appearance/defaults.ts` | 同笔迁移；旧字段保留一个兼容期（见下） |
| 设置插件 `renderControl` 里的 `case "image"` 分支 | 仍可保留（渲染分支），但语义归共享件/宿主 | 不留第二份路径知识 |

**老壳兼容**：设置插件独立发版，旧壳可能没有 `appearance.pickImage`。插件侧写 `window.linkdesk?.appearance?.pickImage ? 新路 : 旧路`，并在注释标「minAppVersion 到位后删旧路」；旧路保留期必须有到期条件（照 R6 例外先例）。

## 六、为什么不是「把设置插件整个搬进壳」

- 设置页是**可整套替换的普通插件**（`factoryRole:"settings"`）；搬进壳会毁掉「万物皆可插件」的前提。
- 本档只搬**语义**：路径/默认值/域/动作；**表单长什么样**仍归插件。

## 七、盘点后新增的壳 API 缺口（四仓实读的产物）

| # | 缺口 | 现状（插件绕行） | 壳补什么 | 落点 |
|:--|:--|:--|:--|:--|
| **A1** | 设置文件路径 | settings 自拼 `appDataDir()+settings.json`（`SettingsView.tsx:216`） | `storage.getFilePath("settings")` | `electron/preload-shell.ts` + `contracts/linkdesk.d.ts`（实现已有 `StorageService.ts:245`） |
| **A2** | 插件资产 URL | marketplace 自拼 `linkdesk://`（`useDetailPackage.ts:41`） | `pluginAssets.getUrl(pluginId, dir)` | `electron/preload-pool/namespaces-plugin.ts` + 契约（`getPluginAssetPath` 已在 `:3375`） |
| **A3** | 最近目录读取 | file-tree 跨属主读 `app.recentFolders`（`useRecentFolders.ts:59`） | `workspace.getRecentFolders()` ＋ `onChange` | `electron/preload-shell.ts` + 壳 `recentList.ts` 暴露只读面 |
| **A4** | 保存对话框 | serial 用 `showSaveFilePicker`/`<a download>`（`useReceiveExport.ts:22-45`） | `dialog.save({title,filters,defaultName})` | 同 `dialog-handlers.ts`，主进程 `showSaveDialog` |
| **A5** | UI 度量（行高） | file-tree 读 `app.uiFontScale` 自行算 `26×scale`（`useTreeConfig.ts:21`） | 优先只吃 CSS `--ui-scale`；确需数值 ⇒ `ui.getMetrics()` | `src/pool` 侧共享；⛔ 不在插件里读外观键 |
| **A6** | 文件关联覆盖表 | settings 直用 `workbench.fileAssociations` 键（`managerHint.ts:31`） | `fileAssociations.getOverrides()/setOverrides()` | 壳 `FileAssociationService` 已有数据，补公共读写 |

> 这些 API 全部是**加性**；旧壳 fallback 由插件侧保留并标到期条件（照尺寸 token 先例）。
> 目录上：A2 落 `electron/services/pluginAssets/`（新子夹）；A3 落 `src/core/services/recentFolders/`；A4 归 `dialog-handlers.ts`；A5 归池共享件。
