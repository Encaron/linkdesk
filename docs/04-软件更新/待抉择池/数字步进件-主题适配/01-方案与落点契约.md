# 01 · 方案与落点契约

> 本文件回答五件事：**改成什么结构**（DOM）· **样式归谁管**（CSS）· **滑杆拉到底会怎样**（圆角行为）· **尺寸与单位怎么定** · **五态与可达性**。
> 一句话方案：**把「三个各自为政的盒子」收成「一个盒子装三段」**——边框、圆角、高度各只有一处来源。

---

## 一、DOM 契约（改后）

```html
<div class="ldk-number-input">                       <!-- 唯一容器：唯一边框 / 唯一圆角 / 唯一高度 -->
  <button class="ldk-number-input-btn" data-dir="down" tabindex="-1" aria-label="减少">−</button>
  <div class="ldk-number-input-cell">                <!-- 值单元格：值与单位同格，整组居中 -->
    <input class="ldk-number-input-field" type="text" inputmode="numeric" aria-label="数值">
    <span class="ldk-number-input-unit">％</span>      <!-- 只有 unit 有值时才渲 -->
  </div>
  <button class="ldk-number-input-btn" data-dir="up" tabindex="-1" aria-label="增加">+</button>
</div>
```

与今天的三处**结构差异**：

| | 今天 | 改后 |
|:--|:--|:--|
| 单位的位置 | 第 4 个 flex 兄弟，夹在字段与 `+` 之间 | **进「值单元格」**，与值同一个盒子、同一条居中轴 |
| 中间那格 | `<input class="ldk-input …">`——**借用**全仓输入框的类，于是它的 `border-radius` 归 `.ldk-input` 管 | 换掉 `.ldk-input`，只挂 `ldk-number-input-field` ⇒ **不再有第二条圆角规则来抢** |
| 圆角/边框 | 三段各写各的（按钮写 `first-child`/`last-child`，字段靠 `.ldk-input`） | **只写在外框上**，内部三段零圆角零边框 |

> 🔴 中间那格**必须摘掉 `.ldk-input`**——这是症状②的根，光把 CSS 改好看没用：只要还借 `.ldk-input`，就永远有第二条单类名规则可能后加载取胜（[00-README §三②](00-README.md) 的死代码实证）。

## 二、CSS 契约（数值即实现口径，可直接抄）

```css
.ldk-number-input {
  display: inline-flex;
  align-items: stretch;                       /* 关键：不是 center——三段等高由 stretch 保证 */
  height: calc(26px * var(--ui-scale));       /* 唯一高度来源（D2 定 24 / 26 / 28） */
  border: 1px solid var(--border);            /* 唯一边框 */
  border-radius: var(--radius-sm);            /* 唯一圆角——跟全局滑杆 */
  background: var(--bg-input);
  overflow: hidden;                           /* 内部永不越出圆角 */
  transition: border-color 150ms;
}

.ldk-number-input-btn {
  position: relative;
  display: flex; align-items: center; justify-content: center;
  width: calc(22px * var(--ui-scale));
  padding: 0;
  border: 0; background: transparent;         /* 内部零边框零底色 */
  color: var(--text-primary);
  font-size: var(--font-size-lg);
  line-height: 1; cursor: pointer; user-select: none;
  transition: background 150ms, color 150ms;
}
/* 分隔线：内缩 1px 竖线——容器 overflow:hidden ⇒ 胶囊档也不会切到弧线上 */
.ldk-number-input-btn::after {
  content: ""; position: absolute; top: 4px; bottom: 4px; width: 1px; background: var(--border);
}
.ldk-number-input-btn[data-dir="down"]::after { right: 0; }
.ldk-number-input-btn[data-dir="up"]::after   { left: 0; }

.ldk-number-input-cell {
  display: flex; align-items: center; justify-content: center; gap: 2px;
  min-width: calc(46px * var(--ui-scale)); padding: 0 calc(6px * var(--ui-scale));
}

.ldk-number-input-field {
  width: calc(34px * var(--ui-scale));
  padding: 0; border: 0; background: transparent; outline: none;
  text-align: center;
  color: var(--text-primary); font-size: var(--font-size-sm);
}
.ldk-number-input-unit { color: var(--text-muted); font-size: var(--font-size-sm); line-height: 1; user-select: none; }

/* 分态 */
.ldk-number-input-btn:hover:not(:disabled)  { background: var(--tab-hover-bg); }
.ldk-number-input-btn:active:not(:disabled) { background: var(--accent); color: var(--text-on-accent); }
.ldk-number-input-btn:disabled              { opacity: .3; cursor: default; }
.ldk-number-input:focus-within {             /* 整组一个环——不再只亮中间那格 */
  border-color: var(--accent);
  box-shadow: inset 0 0 0 1px var(--accent);
}
```

**三条硬纪律**：

1. **圆角/边框/高度只许在外框写一次**——内部任何一段再出现 `border-radius` 或 `border` 就是回归（[06 边缘 E1/E2](02-边缘情况清单.md)）。
2. **颜色全走 token**（硬约束 1）：`--border` / `--bg-input` / `--text-primary` / `--text-muted` / `--tab-hover-bg` / `--accent` / `--text-on-accent`。⛔ 不出现 hex。
3. **尺寸全乘 `--ui-scale`**（E5.8 Phase 12 度量体系）：宽、高、内边距、单元格外距一律 `calc(Npx * var(--ui-scale))`；字号走 `--font-size-*` token（引擎已按比例算好）。⛔ 不写死的 px。

## 三、圆角行为（症状① 与 ② 的正面回答）

`app.surfaceRadius` 是**绝对 px 滑杆 0–32**，引擎把 `--radius-xs…2xl` **六档平铺成同一个值**，`--radius-pill` 也跟着走（[tokens.ts:252-258](../../../../src/core/services/ui/ThemeEngine/tokens.ts)）。

| 滑杆 | `--radius-sm` | 改后应该看到的样子 | 今天的样子 |
|:--:|:--|:--|:--|
| **0** | `0px` | 一整块方角；三条内部竖线是唯一分界 | 三段硬拼，直角处接缝全露（症状①） |
| 4 | `4px` | 外框四角各 4px，内部仍是直的 | 字段四角 4px ＋ 按钮外侧 4px，已经开始不同步 |
| 8 | `8px` | 同上，更圆 | 差异拉大 |
| 16 | `16px` | 同上 | 按钮外侧被钳成半圆、字段被钳成胶囊（症状②） |
| **32** | `32px` | 浏览器按**半高**钳 ⇒ 整组一个胶囊，内部三段仍是**同一胶囊里的三条窄段** | 半个圆 + 半个圆 + 一个胶囊，三个形状 |

**判据（实现完照着读一次）**：从 0 拉到 32 的整条过程中，**控件的外轮廓应当是一个连续、单调变圆的形状**；内部只应看到「被 `overflow:hidden` 沿外轮廓裁出来的窄段＋内缩竖线」，**不应出现任何独立成形的第二、第三个圆角块**。

> ⚠️ **不钳制滑杆值**：滑杆 32 ≫ 高度 26/2，浏览器自己会把 `border-radius` 钳到半高。这是**想要**的效果（用户拉满＝要最圆），不是缺陷；⛔ 不要在组件里写 `min(var(--radius-sm), 13px)` 之类自作主张的钳制——那会让「滑杆拉满」在这一件上静默失效。

## 四、尺寸与单位

| 项 | 定 | 理由 |
|:--|:--|:--|
| 容器高度 | `calc(H * var(--ui-scale))`，H 取 **26**（D2 待拍） | 今天按钮写死 24、字段实际约 26 ⇒ 取其中较大值最省视觉变化；**必须只有一个来源** |
| 按钮宽 | `calc(22px * var(--ui-scale))`（沿用） | 与今天一致，不改手感 |
| 值单元格最小宽 | `calc(46px * var(--ui-scale))` ＋ `padding: 0 6px×scale` | 要装得下 `150％`（`app.uiFontScale` 的最长值＋单位）；窄了会挤，宽了浪费 |
| 输入框宽 | `calc(34px * var(--ui-scale))`，`text-align: center` | 装得下 3 位数字；值本身居中，与单位构成一个居中词 |
| 单位 | **在值单元格内**，紧贴值右侧（`gap: 2px`），`--text-muted` ＋ `--font-size-sm` | 症状③的正解：它属于「值」这一格，不参与容器分栏 |
| 无单位时 | 不渲 `<span>`，单元格只剩输入框 | `window.zoomLevel` 走这条路，外观与今天一致（宽度略变，见 D3） |

> **为什么单位不做「输入框内右侧绝对定位」**：值居中时，绝对定位的单位会在三位数字下与值撞车；而同格 flex 居中让「值＋单位」作为一个词一起居中，任意位数都端正。

## 五、五态与可达性（a11y）

| 态 | 表达 | 不许 |
|:--|:--|:--|
| 默认 | 外框 `--border`，三段同底 `--bg-input` | —— |
| 悬停（按钮） | 该段底 `--tab-hover-bg` | ⛔ 不改形状、不改外框圆角 |
| 按下（按钮） | 该段底 `--accent` ＋ 字 `--text-on-accent` | ⛔ 不做位移/缩放动画（设置页要稳） |
| 禁用（到极值） | 该按钮 `opacity: .3` ＋ `cursor: default` | ⛔ 不整件变灰（另一端仍可用） |
| 聚焦 | `:focus-within` ⇒ **整组**外框 `--accent` ＋ `inset 0 0 0 1px` 环 | ⛔ 不用 `outline`（会画出矩形直角、盖住圆角） |

**可达性四条**：

1. 两个按钮保持 `tabindex="-1"`（键盘用户用 ↑/↓ 或直接改数）——**与今天一致**，改的是「聚焦时形状裂开」，不是键盘模型。
2. `aria-label` 走 `t()`（`减少` / `增加`，硬约束 2）；输入框补 `aria-label`（今天**没有**——顺手补上，见 [02 E9](02-边缘情况清单.md)）。
3. 输入框加 `inputmode="numeric"`：触屏 / 软键盘出数字键盘（桌面端零影响）。
4. 对比度：`--text-muted` 的 `％` 是**辅助信息**（值才是主信息），按 ≥3:1 要求；⛔ 不要为「看清楚」把它提成 `--text-primary`（会与值抢权重）。

---

## 六、焦点与外部一致性

- 设置页的行高、控件右对齐、齿轮按钮**一概不动**——本件只换控件内部。
- `.ldk-input` 本身（其余输入框）**一个字不改**——本件是「中间那格不再借它」，不是「改它」。
- 已扫 `src/components/shared/**`：**无第二件**用拼装圆角（判据见 [03 §五](03-实现交接.md)）⇒ 不做全仓普查。

---

## 七、⛔ 不许（踩了就是返工）

- ⛔ 中间那格继续挂 `.ldk-input`（症状②的根，见 §一）。
- ⛔ 内部任一段写自己的 `border-radius` / `border`（症状①的根）。
- ⛔ 把高度分别写在按钮和字段上（症状①的第二个根——两套来源必然漂移）。
- ⛔ 单位再放到容器直接子级里当 flex 兄弟（症状③的根）。
- ⛔ 硬编码 hex 或裸 px（硬约束 1 ＋ E5.8 度量体系）。
- ⛔ 在组件里钳制 `--radius-sm`（见 §三 注）。
- ⛔ 改 `--radius-*` 引擎算法或六档平铺规则（本件只做消费侧）。
- ⛔ 为「保险」把 `.ldk-number-input-field` 的 `border-radius: 0` 再写一遍就交差——那是**在赌加载顺序**，正是今天坏掉的原因。
