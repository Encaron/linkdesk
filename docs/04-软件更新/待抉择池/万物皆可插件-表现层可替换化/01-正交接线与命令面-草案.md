# 01 · 正交接线与命令面（草案 —— 拍板前底稿）

> ⚠️ **状态：草案**，体例照范本 [已落地/兜底打开链与二进制文本选项/01](../../已落地/兜底打开链与二进制文本选项/01-方案与落点契约.md)。
> 本档 = 与姊妹档 [内置件独立更新与文档国际化分型](../内置件独立更新与文档国际化分型/00-提案.md) 的**合流案**：回答「两档如何正交互握、命令点如何供给、第三方 UI 如何接入、四化如何机械兜底」。链路 A（内容物一生）与链路 C（防遗忘）的细则住姊妹档 01，本档管 **A×B 握手**。
> **愿想（北极星）**：用户通过 LPM 管理内置内容物，同时通过第三方插件替换任何 GUI——**皮是第三方的，内容是官方的；更新不碰皮，替换不碰内容**。

---

## 一、端到端链路（三条，合起来 = 愿想）

**链路 A · 内容物的一生**（细则＝姊妹档 01）：
官方制作（manifest＋资源）→ 官方目录收录（channel=content，复用鉴权链）→ LPM 列表（扫描 manifest＋目录查询缓存）→ `lpm.updateItem`（下载→校验→原子落盘覆盖层）→ 消费方经 `content.read` 读序取数（覆盖层→基线）→ 失败回滚 = 删覆盖层。

**链路 B · 第三方 UI 接管**（本档主体）：
manifest 声明槽位（factoryRole / renderers / titleBar…）→ 装入 → 角色仲裁（一槽多候选，用户切换持久化）→ 替换体渲染时**只调数据命令**取数 → 用户动作**只调动作命令** → 崩溃走逃生舱命令回官方。

**链路 C · 防遗忘**（细则＝姊妹档 01 §五）：
新内容物必须建 manifest（孤儿门禁）→ 必填 dataCommand（门禁验在册）→ 呈现页面型即声明 factoryRole → R8 词表兜「以后再说」句式 → 想硬编码过不了 `npm run check`。

## 二、正交矩阵（两轴四象限全合法）

| | 内容 = 随包基线 | 内容 = LPM 已更新 |
|---|---|---|
| **画法 = 官方内置** | 出厂默认态 | 官方皮＋新内容（最常见） |
| **画法 = 第三方接管** | 第三方皮＋旧内容 | 第三方皮＋新内容（**愿想终态**） |

**关键不变式：皮不存内容、内容不带皮**——

- 替换体调 `content.read` / `lpm.listItems` 拿到的永远是「当前 active 版本」的数据；
- LPM 更新只动覆盖层，⛔ 触碰任何渲染体；
- 替换体 ⛔ 内嵌内容副本（否则矩阵右下角破碎——数据同源铁律的内容轴实例）；
- 四象限互不设前置：装第三方皮不需要先更新内容，更新内容不需要先换皮。

## 三、命令点供给制度（「如何提供命令点」的正面回答）

**三类命令，命名规范 `<域>.<动作>`**：

| 类 | 例 | 谁消费 |
|---|---|---|
| 数据命令 | `app.getWelcomeData` / `update.getReleaseNotes` / `content.read` | 任何渲染体（含第三方替换体） |
| 动作命令 | `lpm.updateItem` / `factoryRole.setActive` / 槽位重置 | 任何 UI 面（含第三方替换体）＋ AI/CLI |
| 状态命令 | `lpm.listItems` / `commands.getCommands` | LPM 列表 / 命令面板 / AI 自省 |

**槽位三命令标准件**（每个可替换槽位同笔配备——候选门禁腿判据「有槽位必有三命令＋数据命令」）：

- `slot.listProviders <slotId>` · `slot.setActive <slotId, providerId>` · `slot.resetToBuiltin <slotId>`
- ⚠️ **归一取舍**：factoryRole 已有查询/切换 API 面（FactorySlots）——⭐ 建议**不另立 `slot.*` 同义族，推广 factory-slots 命令族为唯一仲裁面**（多一套同义命令 = 违反归一）；renderers 槽位若最终独立于 factoryRole，届时并入还是并列 → 决策点。

**制度性要求**：meta 必带 `description`＋`params`（硬约束 26②）；新命令同笔进 AI 手册 02 章（`manual:build`）；ai-bridge/linkdeskctl/MCP 自动可达（ai-bridge 白名单维护为实施项）；UI 动作与命令**最后指向同一通路**（用户第 21 点铁律）。

## 四、第三方提供 UI 的统一接入六步（作者视角）

1. manifest 声明槽位（`factoryRole:"welcome"` / `contributes.renderers:"contextMenu"` / …）；
2. 插件仓独立构建（R7 自足，零壳依赖）；
3. 发布＋官方目录收录（市场两步，⛔ 无绕行）；
4. 用户装入 → 角色仲裁：同槽多候选 → 后装提示（00 §七-3 ⭐）→ 用户切换持久化；
5. 替换体内：**数据只走数据命令、动作只走动作命令**（⛔ import 壳内部、⛔ 自建数据副本——R2/R6/G1 照守）；
6. 崩溃 = 自动回退内置＋一条通知；用户可随时重置回官方（逃生舱命令在册，settingsCommands 先例）。

## 五、四化兜底总表（散落机制收拢一表）

| 设计元素 | 归一化 | AI 友好 | 无硬编码 | 无死代码 |
|---|---|---|---|---|
| 槽位仲裁 | factoryRole 唯一仲裁面 | 列举/切换/重置命令化 | 壳零 providerId 字面量（R1/R5） | — |
| 页面替换 | 欢迎页等走 factoryRole | 数据命令同笔 | 官方页转内置插件（吃狗粮） | 不保第二套实现（R4） |
| 部件皮 | renderers 槽位注册表 | 三命令＋数据命令 | 槽位 id 表数据化（host-menu-slots 同法） | v1 只收首批槽位 |
| 内容物 | LPM 唯一呈现＋管道一份 | `lpm.*`/`content.*` | 零 itemId 字面量 | manifest 缺失 = 红 |
| 启动期 | splash 白名单唯一口子 | 进度事件命令化 | 超时红线数据化 | — |
| AI 面 | 手册随 `manual:build` | audit 判据 | — | — |

（「候选腿」= 待新写：`check-content-ledger`、槽位三命令 audit——挂姊妹档 01 §五与本档 00 §3.8。）
