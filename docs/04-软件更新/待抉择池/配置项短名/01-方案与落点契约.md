# 01 · 方案与落点契约（逐层：现状 → 改法 → 判据）

> 每层四段：**现状**（file:line 取证）→ **改法** → **判据**（验收口径）→ **连锁**（发版/文档/门禁）。执行 AI 照层推进；本档与 [03 普查表](03-配置项普查与短名底稿.md)、[04 任务清单](04-任务清单.md) 三档互指。

## 层 1 · SDK ＋ 契约：加 `title` 字段（T1）

**现状**
- `packages/plugin-sdk/schemas/plugin.schema.json:354` 起 = `contributes.configuration` 节：`required: ["title","properties"]`（组名已有）；`properties.*` 的 required = `["type","default","description"]`，**无 title**。
- 契约命名类型住壳 `src/core/api/linkdesk-api/types.ts`（`LinkDeskConfigurationContribution`）→ `npm run contracts:gen`（`scripts/generate-contract.mjs`）生成 `@linkdesk/contracts` 的 `linkdesk.d.ts`，`contracts:check` 门禁盯漂移。
- schema 有多份拷贝（plugin-docs 内 `packages/plugin-docs/docs/zh/plugin.schema.json` 等），`check-plugin-schema-sync` 门禁管同步。

**改法**
- `properties.*` 加 `title: { type: "string", description: "…" }`（**optional**，D2；description 写清：行名短名、值域=中文原文＝i18n key、缺省时设置页回退显配置键）。
- 契约类型同步补 `title?: string` → `npm run contracts:gen` 重生（⛔ 不手改 d.ts）。
- schema 各拷贝同笔重生（`check-plugin-schema-sync` 红了就按其自述同步，四份字节一致）。
- SDK `own-dict-coverage.test.ts` 的声明字符串覆盖名单补 `properties.*.title` 值（该测试今天已列 `configuration.subtitle`／`properties.*.group`／`enumDescriptions` 值等族，title 是新族）。
- 发版：`plugin-sdk`、`@linkdesk/contracts`（、`plugin-docs` 若文档链重生出差异）——**作者轴自主发**（00 §四授权）；🚫 additive 改动，`check-api-surface-additive` 应绿。

**判据**：schema 校验接受带 `title` 的声明、拒绝类型错误；不带 `title` 的存量声明校验照旧通过（向后兼容实测一条）；contracts:check／schema-sync 全绿；npm 发完市场/工程内可装到新版。

## 层 2 · 设置插件：行名渲染（T2）

**现状**：`SettingRow.tsx:76` 行名渲染 `{configKey}`；`:70` 描述 `t(description ?? prop.description)`；prop 来自 `loadSettingsData.ts` 的 `allProps`（`getSchema()` 合并各仓 properties——声明加了 title 即随流到达，零壳新 API）。搜索 `filterGroups.ts` 只匹配 `key / description / 组title`。

**改法**
- `types.ts` 的 `ConfigProperty` 补 `title?: string`。
- 行名改 `{prop?.title ? t(prop.title) : configKey}`（D4：只显短名，ID 走齿轮；fallback 显 key 保第三方）。
- `filterGroups.ts` 匹配串加 `prop?.title ?? ""`（toLowerCase 同现行口径）——搜「自动保存」命中 `editor.autoSave`。
- 设置插件自身 `settings.openForm` 一条也补 `title`（本仓声明本仓补）。

**判据**：dev 版全行短名、搜索命中、无 title 声明回退 key（造一条临时声明验）；`npm run check`（插件侧腿在 SDK CI）全绿；仓发版＋目录收录。

## 层 3 · 市场插件：功能页同笔消费（T3）

**现状**：`features-groups.tsx` `ConfigGroup` 上行 `{desc?.description || key}` 下行 `{key}`；**两处都没走 `t()`**——描述是中文原文 key，英文界面原样中文。数据源 = `contribs.ts` `parseContribs`（`ConfigItem = [key, { description? }]`，读 `list().manifest.contributes`，已装启用分支才有）。

**改法**
- `contribs.ts` `ConfigItem` 值类型补 `title?: string`。
- `ConfigGroup` 上行改 `t(desc?.title) || t(desc?.description) || key`（短名优先，无 title 回退描述，再回退 key）；描述若仍展示（现有布局上行即描述位）同笔包 `t()`——**英文界面中文裸奔就此断根**。
- 下行 key 原样保留（D3）。

**判据**：已装插件的配置行显示「短名＋key」；英文界面整页无中文裸奔（对一只已译仓实测）；未装/禁用插件功能页空态分档照旧（E5）。

## 层 4 · 五台官方插件仓：声明补名＋译名（T4，48 条）

**现状**：editor 26／file-tree 18／serial-monitor 2／marketplace 1／settings 1 条，全无 `title`；枚举显示名缺口 = editor 8 组、file-tree 2 组、settings 1 组（`enumDescriptions` 缺，见 [03 表](03-配置项普查与短名底稿.md)「枚举显示名」列）。各仓 i18n/en.json 已给**描述**供英译（editor 54 键即范本），title 照此办理。

**改法（逐仓循环）**
1. `plugin.json` 逐条加 `"title": "<中文短名>"`（命名规则见 03 档头：≤12 字、名词短语、去插件前缀、动词行另说）。
2. 该仓 `i18n/en.json` 补两族映射：短名（中文原文 → English）＋ 新补的枚举显示名。
3. `renderHint:"action"` 行（如 `ai.guide.copyCliLine`）短名按**按钮语义**起名（「复制 CLI 接入行」），不是名词。
4. 每仓 bump＋CHANGELOG＋build＋publish＋**官方目录收录确认**（硬约束 24：收录了用户才点得到）。
5. ⚠️ 先 SDK 后仓（T1 未发时仓内 CI 的 schema 校验可能不认新字段——按层序走）。

**判据**：03 表「短名底稿」列全填实并回填读数；每仓市场可点升级；抽查三仓英文界面无中文裸奔。

## 层 5 · 壳：声明补名 ＋ 齿轮「复制设置名称」（T5，41 条＋一项）

**现状**
- 壳声明四文件：`src/App/config/appearance.ts`（主题组 24 条）·`aiBridge.ts`（AI接入 14）·`update.ts`（2）·`storage.ts`（1）；组 title 已 `t()` 包裹（`title: t("主题")`），property 无 title。
- `audit-i18n --strict` 按**属性名**排除 `description:` 的值，**不排 `title:`** ⇒ 壳侧 title 必须 `t()` 包裹，否则红（硬约束 2 例外不适用）。
- 齿轮槽 `MENU_SLOTS.SettingItemGear` 菜单项全在壳 `coreCommands.ts`（`:347` 复制设置 ID ·`:364` 复制为 JSON ·跟随主题 ·重置此设置，均带 when 条件）；settings 仓 `gearMenu.ts` 开齿轮前设 context key（`settingKey`/`settingModified`/`settingFollowTheme`/`settingResetsToDefault`）。

**改法**
- 四文件 41 条逐条加 `title: t("<中文短名>")`（t 注入模式照现文件头注释——语言切换重跑）。
- settings 仓 `gearMenu.ts` 开齿轮时增设 `settingHasTitle = !!prop?.title`（清理分支同步复位）。
- 壳 `coreCommands.ts` 新命令（id 建议 `core.copySettingName`，与同族命名对齐）＋菜单项「复制设置名称」：`menuId: SettingItemGear`、`when: "settingHasTitle"`；handler 按 context key `settingKey` 反查 `getConfigurationContributions()` 取该 property 的 `title`，`i18n.t()` 出**当前语言显示名**写剪贴板，toast「已复制：」同族样式；meta 带 `description`＋`params`（硬约束 26②）。
- context key 新键进 host-reserved context key 账（写权限 = 设置插件，消费 = 壳菜单）——照「文件打开方式」案 T5 的公共 context key 纪律；SDK context-ownership 自测补例。
- `npm run manual:build`（新命令进 AI 手册 02 章；⛔ 手改生成区）。
- 软件侧变更：提交前 version-bump skill 判类别＋同笔 CHANGELOG 段；**dev 测、攒批不发版**（00 §四）。

**判据**：dev 版设置页壳 41 条全显短名；有 title 行齿轮出「复制设置名称」、无 title 行不出（D5 when 实测）；复制内容 = 当前界面语言短名；`audit-i18n --strict`／`manual:build` 门禁绿。

## 层 6 · 市场跳设置复测＋二分（T6）

**现状**：链路六环齐全（00 §二取证 ⑥），静态逐环核过应当能跳；用户实机反馈「点了不跳类别」。两个已知嫌疑：
- **嫌疑 A · 首开时序**：`useSettingsEvents.ts` scrollTo 双通道 A（mount 消费 pending）在 `groupsRaw` 还是空数组时跑循环 ⇒ 查不到组；200ms 后 `getElementById` 行还没渲染 ⇒ **滚动丢**（但类别切换由 M1 通道 A 兜底，理论上仍应切到目标组）。
- **嫌疑 B · reveal 失败**：`core.openSettings` 的面板 reveal 链（`settingsCommands.ts:224-230`）若 `fpViewId` 解析失败即静默 no-op——请求已 fire 进空处，用户看到「什么都没发生」，下次手动开设置时 pending 才被莫名消费。

**改法**：先复测定性，再对症——
1. dev 版三场景实测：① 设置从未开过 → 市场详情点配置项；② 设置已开在别的类别；③ 设置已开在目标类别。记录每场景「开没开面板／切没切类别／滚没滚到行」三读数。
2. 全通 → 本格闭合，如实记读数（可能用户实测的是旧插件版本）。
3. 不通 → 按硬约束 15 `git checkout` 逐 commit 二分；修复落点大概率在 settings 仓双通道消费时序（嫌疑 A：scroll 重试到行渲染为止／`consumeScrollToSetting` 延后到数据加载完成）或壳 reveal 链（嫌疑 B：失败要**出声**——toast 或回退，⛔ 静默吞请求）。
4. 修复同笔补回归单测（能 jsdom 测的测时序回调，测不了的写 CDP/dev-driver 读数进本档）。

**判据**：三场景读数齐；不通的修到通；留下「复现 → 二分 commit → 修法」三段记录。

## §八 · 工程纪律对账（用户点名六条，逐条落点）

| 纪律 | 在本案的落法 |
|:--|:--|
| 无硬编码 | 短名是**声明数据**进各仓 plugin.json／壳 config，渲染侧零查找表；⛔ 任何插件 id 出现进壳代码；新命令按 context key 取数，不认插件名 |
| 无死代码 | 「复制设置名称」when=`settingHasTitle` 挡住无 title 行（不留永假菜单项）；fallback 分支（无 title 显 key）有真实消费方＝第三方存量 |
| 高内聚低耦合 | 声明（各仓）与消费（两台插件）分离；市场只读 manifest、零新壳 API；设置渲染只吃 allProps、不知道声明来自谁 |
| 插件独立／万物皆插件 | 第三方不声明 title 完全不受影响；渲染改动全在 settings/marketplace 两仓（可整体被第三方替换，壳不动结构）；新能力 = schema 开放字段，非壳特权 |
| AI 友好性 | 新命令带 meta（硬约束 26）；手册刷新；搜索索引扩 title；结构化验收（T6 读数可由 dev-driver 采集） |
| 文件目录管理／归一化 | 本案档案五份住本夹；普查尺进 `scripts/`（audit 家族命名）；schema 拷贝走既有同步门禁，⛔ 手抄副本 |

## §九 · i18n 译名模型（D6/D7 的机制底座）

- key = 中文原文（硬约束 2 惯例）；**谁声明谁供译**：插件 title 译名进各仓 `i18n/en.json`，壳 title 译名进外仓 `lang-defaults`（壳侧译名唯一住点——硬约束 2 备注同源）。
- 共享合并已就绪：`src/pluginLoader/contributions/i18nResources.ts:90-91` 把插件译文同时灌进 `pluginId` 命名空间与共享 `translation` 命名空间 ⇒ 设置页/市场跨仓 `t()` 均可解析（取证 ⑧）。
- 缺译回退 = 显示中文原文（i18next 缺键回退 key 本身），不算错但普查尺要报（D6）。
