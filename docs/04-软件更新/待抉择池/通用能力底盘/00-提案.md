# 通用能力底盘 —— 待决策提案

> **状态：待决策**（2026-11-12 立案；用户已拍板"两个大任务分开"，本档为**能力侧**；未排期）。
> **一句话**：壳只补四类**谁都用得上**的底层能力——**受控进程 · 高频数据流 · 连接/端点登记 · 能力声明与授权**——并给壳画一条**止损线**，防止它被任何单一行业（尤其硬件调试）带着长歪。
> **落点说明**：用户指示「大型任务分主题放在待决策区」；与 [AI 门面可信化](../../已落地/AI门外契约面补齐/00-提案.md) 正交——**本档管"能动手"，那档管"能确认"**。
> **🔴 用户定调（2026-11-12 原话要点）**：
> - 「我的软件核心是**万物皆可插件**；壳提供的始终是**有限的、通用的**，真正能力体现在**插件侧**。」
> - 「我害怕你把这个软件当成一个**串口监视器类型的、或者说调试硬件端的软件**而去不停使用它。」
> - 能做的东西不限于硬件：图片/代码/PDF 阅读器、地球浏览、打卡、学习记录、小说阅读、**PLC 上位机**……
> **证据时效**：2026-11-12。

## 〇、为什么需要这一档（一句话）

外部 AI 想做"全自动调试"，但**插件没有能力碰外部世界**：不能启动编译器、不能调调试器、不能收高频流、不能认"同一块板子换了 COM 号"。要补——但补的必须是**通用管子**，不是硬件功能。

## 二、四个轴 ＋ 一条止损线

### 轴一 · 受控进程（最高杠杆，最高风险）

- **通用性证明**：flasher 要调编译器/烧录器；git 插件要调 git；文档插件要调 pandoc；媒体插件要调 ffmpeg——**四个互不相干的领域**。
- **最小面**：`exec({ cmd, args: string[], cwd?, timeoutMs?, env? })` → `{ ok, exitCode, stdout, stderr, tookMs }`；**只收 argv 数组**，⛔ 不收 shell 字符串（杜绝拼接注入）。
- **授权**：由 [插件权限系统](../插件权限系统/00-提案.md) 统一管——插件在清单声明 `process.exec` ＋ 允许清单，装时展示、用户可取消；**授予后不再逐次询问**（用户 2026-11-12 定调：不做"每任务确认"）；全程记账。⛔ 本档不另造一套授权。
- **⛔ 不做**：不做交互式 shell、不做常驻守护进程、不做管道/重定向语法（要用的人在自己插件里拼 argv）。
- **风险**：这是**唯一一条"执行任意代码"的能力**——信任模型必须先定（见 §五）。

### 轴二 · 高频数据流

- **通用性证明**：串口高速、摄像头/视频、音频、传感器采样——同样是多个领域。
- **最小面**：插件**声明帧格式**（长度前缀 / 分隔符 / 定长），壳按帧回推；命令面只暴露 `open / close / status / stats`。
- **形态**：**插件类型扩容**（第七类 `stream`），而不是往命令面塞二进制（JSON 序列化会拖垮）。
- 🔴 **接口现在就定，不等需求出现**（硬约束 28「一次到位」：第二个使用者＝必然——摄像头、音频、RTT、逻辑分析仪、传感器，任何一个想接高速数据的作者都必须能用）；实现波次可以排在进程之后，但**契约不能挂着**。
- **⛔ 不做**：不做协议解码（那是插件的事）、不做录制/回放（先用插件自己做）。
- **风险**：内存与背压；必须定义"消费者慢"时的丢弃策略（丢最旧 + 计数如实回报）。

### 轴三 · 连接/端点登记（不是"设备注册表"）

- **通用性证明**：一块板子、一个数据库连接、一台远程主机、一个挂载点——都是"有身份、会在生命周期里变化的外部对象"。
- **🔴 命名纪律**：⛔ 不叫 `Devices` / `deviceId`（那是硬件词，会把壳拉成调试软件）。叫 **`connections` / `connectionId`**，`kind` 由**插件自定义字符串**，**壳不认识 kind 的含义**（核心无知）。
- **最小面**：`register({ kind, id?, label, meta? })` → `connectionId`；`list(kind?)`；`onDidChange`；`release`。
- 🔴 **身份怎么认（2026-11-12 用户追问的核心）**：**COM 号只是门牌号，会变；身份必须由设备自报**。三层：① **USB 描述符**（VID/PID/序列号——**壳现在只透出 `{name, description}`，这是要补的缺口**；廉价 CH340 常无序列号）；② **设备握手**（插件问"你是谁"，固件回唯一 ID——最可靠）；③ **人工命名绑定**（把名字绑到序列号）。系统只能看到「COM3 消失、COM5 出现」，**不能自动断定是同一块**——只有②能给答案。
- **不承诺**：壳不解析能力位、不猜"这块板子支持什么"——那全是插件的 `meta`。
- **⛔ 不做**：不做自动发现（谁发现谁登记）、不做跨插件强绑定（插件各自登记，命令以 `connectionId` 为参数）。

### 轴四 · 能力声明与授权

- 插件清单增 `capabilities: string[]`（`process.exec` / `stream` / `connections` …）；**默认拒绝**，未声明即无。
- 授权口径：装插件时列清楚"它要什么"；高危动作每次确认；账本可查。
- 机械兜底：能力清单与运行时对账（用了未声明的面 ⇒ 红灯）；清单本身作为 host 保留名同步（照 `host-reserved.json` 先例）。

### 轴五 · 止损线（不是能力，是纪律）

> **任何新增壳能力，必须能说出两个不同领域的消费者；说不出来 ⇒ 一律回插件。**

- 第二个作者＝必然（万物皆可插件）⇒ 判据是「**现在就说得出两个消费者**」，决定当场作，不推到将来。
- 反例清单（**明确不进壳**）：调试器/SWD/JTAG · 烧录 · 帧缓冲抓屏 · 内存/寄存器语义 · 故障解码 · PLC 协议 · Modbus/CAN · 任意厂商工具链。
- 机械形态：新增一条门禁腿——壳能力清单里出现**单一领域名词**即红（与 R8 落位禁忌句式同族）。

## 六、批次与验收

- **批次**：轴四（声明与授权）**先落**——它是另外三轴的前置闸门；然后轴一（进程）→ 轴三（连接）→ 轴二（流）。
- **一次验证**（每个轴都必须过）：
  1. **两个不同领域**各有一个真实消费者跑通（例：进程 → flasher ＋ git；流 → 串口高速 ＋ 摄像头）；
  2. 卸载消费者插件后，**壳功能不受影响、无残留代码路径**；
  3. 未声明能力的插件调用即拒，且拒绝可判读（有码、有 hint）。
- **出货**：随攒批，不发单版。
