# 02 — 插件生命周期

> 2026-07-24。**插件从存在到消失的完整状态机。** 注册→激活→运行→卸载。每个阶段的壳行为和插件责任。

---

## 一、状态机

```
  安装/放入目录
      │
      ▼
 [1] 注册（Registration）
      │  loader 扫描 plugin.json → 解析声明
      │  → 注册到 viewRegistry / CommandRegistry / CardRegistry / ...
      │  → 图标栏出现图标
      │
      ▼
 [2] 等待激活（Idle）
      │  插件已注册，但 JS 未加载。图标栏可见。
      │  激活时机由 activationEvents 决定。
      │
      ▼
 [3] 激活（Activation）
      │  首次触发 activationEvent → import() 插件 JS
      │  → 创建 WebContentsView（E3a）
      │  → React 组件 mount
      │  → 插件收到 { isActive: true/false }
      │
      ▼
 [4] 运行（Running）
      │  插件渲染到标签页/侧栏/卡片网格
      │
      ▼
 [5] 卸载（Uninstall）
      │  → 清理注册表（commands/keybindings/menus/configs/cards/...）
      │  → 销毁 WebContentsView
      │  → 移动文件到 .disabled
```

---

## 二、阶段详解

### 阶段 1：注册——Loader 扫描 plugin.json

**触发：** LinkDesk 启动时，`loader.ts` 扫描 `plugins/*/plugin.json`

**壳行为：**
1. 读 `plugin.json` → 校验 JSON Schema
2. 读 `entry` 字段 → 注册到 `viewRegistry`（图标栏出现图标）
3. 读 `sidebar` 字段 → 注册侧栏组件
4. 读 `statusBar` 字段 → 注册状态栏条目
5. 读 `contributes` → 解析并注册：
   - `commands` → `CommandRegistry`
   - `menus` → `MenuRegistry`
   - `keybindings` → `KeybindingRegistry`
   - `configuration` → `ConfigurationRegistry`
   - `themes` → `ThemeEngine`
   - `languages` → `i18next`
   - `fileAssociations` → `FileAssociationService`（E3 后）

**此阶段 JS 尚未加载。** 壳只读了 plugin.json 的声明，没有 import 插件代码。

**插件 config 默认值例外：** `contributes.configuration` 的 `default` 值在此阶段写入 `ConfigurationService`——不激活插件 JS 就能读到默认设置。

### 阶段 2：等待激活——按需加载

**activationEvents 决定插件 JS 何时加载：**

| activationEvent | 触发条件 | 例子 |
|------|------|------|
| `*` | 启动时立即加载 | 欢迎页、设置页 |
| `onCommand:<commandId>` | 用户执行命令（命令面板/快捷键/菜单） | `onCommand:cad.importDxf` |
| `onFileOpen:<extension>` | 用户双击文件 | `onFileOpen:.dxf` |
| `onPortOpen` | 串口连接建立 | `onPortOpen` |
| `onLanguage:<langId>` | 打开特定语言的文件 | `onLanguage:cpp` |
| `onView:<viewId>` | 用户展开特定视图容器 | `onView:explorer` |

**声明方式：**
```json
{
  "activationEvents": [
    "onFileOpen:.dxf",
    "onCommand:cad.importDxf"
  ]
}
```

不声明 `activationEvents` = 等同于 `"*"` = 启动时立即加载。

**对标 VS Code：** `package.json` 的 `activationEvents` 字段。VS Code 的完整事件集：`onLanguage` / `onCommand` / `onView` / `onStartupFinished` / `onFileSystem` / `workspaceContains` / `*`。LinkDesk 按需实现——`onCommand` / `onFileOpen` / `onPortOpen` / `onLanguage` 覆盖了当前需要的触发场景。

### 阶段 3：激活——首次 import + 创建 WebView

**壳行为：**
1. `import(entry)` → 加载插件 JS
2. （E3a）`WindowManager.createPluginView(pluginId)` → 创建独立 WebContentsView
3. 插件 preload 注入 `window.linkdesk.*`（插件版——比壳窄）
4. 插件 React 组件 mount
5. 插件执行初始化逻辑——注册命令 handler、订阅事件、读配置

**插件责任：**
```typescript
// 入口文件 index.tsx
export default function MyPlugin({ isActive }: { isActive: boolean }) {
  useEffect(() => {
    // 激活时——注册命令 handler
    window.linkdesk.commands.register("myPlugin.doSomething", async () => {
      // ...
    });

    // 订阅配置变化——切语言/切主题时自动响应
    window.linkdesk.config.onChange("myPlugin.someSetting", (val) => {
      // ...
    });

    // 订阅壳事件
    window.linkdesk.events.on("theme:changed", ({ themeId }) => {
      // 如果插件有自己的主题变量，在这里响应
    });
  }, []);

  return <div>...</div>;
}
```

### 阶段 4：运行

**`isActive` prop 约定：**

| 场景 | `isActive` |
|------|:--:|
| 标签页在前台 + 所在分屏面板活跃 | `true` |
| 标签页被其他标签页遮住 | `false` |
| 标签页所在面板不活跃（分屏时另一个面板活跃） | `false` |

**keep-alive 机制：** 所有标签页内容始终挂载，用 CSS `display` 切换。不要用 `{isActive && <View/>}` 条件渲染——会销毁 Canvas/Monaco 状态。

```typescript
// ✅ 正确
useEffect(() => {
  if (!isActive) return;
  editorRef.current?.layout();  // Monaco 重新布局
}, [isActive]);

// ❌ 错误——销毁组件状态
if (!isActive) return null;
```

### 阶段 5：卸载——清理链

**触发：** 用户在插件市场点"卸载" / 齿轮菜单卸载

**壳行为（`performUninstall()` 单入口）：**
1. 触发 `onWillUninstall` Emitter → 插件执行自定义清理
2. 注销所有注册表条目（按卸载顺序——先清注册表再清文件）：
   - `CommandRegistry` → 注销所有 `contributes.commands`
   - `KeybindingRegistry` → 注销所有快捷键
   - `MenuRegistry` → 注销所有菜单项
   - `ConfigurationRegistry` → 注销所有配置项
   - `CardRegistry` → 注销所有卡片
   - `ProtocolRegistry` → 注销所有协议
   - `viewRegistry` → 注销视图（图标栏图标消失）
3. （E3a）销毁插件 WebContentsView
4. 移动文件到 `plugins/.disabled/<pluginId>/`
5. 清理持久化状态——插件在 PluginStateService 中的条目

**插件的自定义清理：** 如果插件打开了串口、启动了定时器、监听了文件——在 `onWillUninstall` 的订阅中清理。壳在步骤 1 触发此事件。

## 三、多实例 vs 单例

| tabBehavior | 行为 |
|------|------|
| 默认（无声明） | 每次点击图标 → 创建新标签页 |
| `singleton: true` | 全局只一个实例。重复点击 → 聚焦已有标签页 |
| `isFallback: true` | 场上无标签页时自动创建。不可关闭。只有欢迎页声明 |

```json
{
  "tabBehavior": {
    "singleton": true,
    "confirmOnClose": "确定关闭设置页？"
  }
}
```

## 四、错误处理

| 错误 | 壳行为 | 插件责任 |
|------|------|------|
| plugin.json 格式错误 | 跳过该插件，toast 通知用户 | 校验格式 |
| entry 文件找不到 | 跳过，toast | 确保文件存在 |
| React 组件 throw Error | ErrorBoundary 捕获 → 显示 "「插件名」已崩溃 [重试]" | 不写不崩的代码 |
| `while(true){}` 死循环 | E3a 后——只死该插件 WebView。心跳检测弹"应用无响应" | 不写 |
| IPC 超时 (5s) | throw Error | try/catch |
