# 浮层归一化设计

> 极简Pool 下所有浮层（ContextMenu / QuickPick / Toast / Dialog / Tooltip）统一在 FloatingLayerHost 内用 CSS `position: fixed` + `z-index` 实现。不再需要 OverlayWindow。

---

## 1. 为什么不需要 OverlayWindow

E5.6 双Pool 架构中，SidebarPool 和 MainPool 是平级 WebContentsView。任何超出自身 bounds 的浮层被另一个 WCV 裁剪。OverlayWindow（透明置顶 BrowserWindow）是唯一解法。

极简Pool = 1 个 WCV 覆盖整个窗口。所有 UI 在单一 DOM → 同一个 CSS 层叠上下文 → `position: fixed; z-index: N` 可以浮在任何内容上面。

> 🔴 2026-08-13 审计：当前 E5.6 代码里 OverlayWindow 是空壳——overlay-main.tsx 四个浮层全占位符、壳侧 overlay.push 零调用、主进程只铺了中继管道。真浮层在壳 DOM（components/shared/ContextMenu 等）。本设计的迁移源是壳 DOM 浮层，不是 src/overlay/。

**消除的复杂度：**
- OverlayWindow BrowserWindow 生命周期
- `setIgnoreMouseEvents(true/false)` 二元切换
- 屏幕坐标转换（OverlayWindow 独立窗口 → 需要 `screenX/screenY` → 窗口 offset 转换）
- 跨进程浮层 IPC（OverlayWindow renderer ↔ 主进程 ↔ 调用方 Pool）

## 2. FloatingLayerHost——浮层容器

**文件：** `src/pool/zones/FloatingLayerHost.tsx`

```tsx
function FloatingLayerHost() {
  return (
    <div style={{
      position: 'fixed',
      inset: 0,
      zIndex: 2000,
      pointerEvents: 'none',  // ← 默认穿透——不阻挡正常交互
    }}>
      {/* Toast——始终在此，按需显示（例外：直挂容器，CSS 自设 none/auto） */}
      <ToastHost />

      {/* ContextMenu portal */}
      <div id="context-menu-root" style={{ pointerEvents: 'auto' }} />

      {/* QuickPick / CommandPalette portal */}
      <div id="quick-pick-root" style={{ pointerEvents: 'auto' }} />

      {/* Dialog / Modal portal */}
      <div id="dialog-root" style={{ pointerEvents: 'auto' }} />

      {/* Tooltip portal（如需要） */}
      <div id="tooltip-root" style={{ pointerEvents: 'auto' }} />
    </div>
  );
}
```

**设计原则：**

| 原则 | 说明 |
|:--|:--|
| 默认穿透 | `pointer-events: none` on 容器——不阻挡正常交互 |
| 根级 opt-in | 4 个 portal root 统一 `pointer-events: auto`（本文件一处）——浮层内容默认可交互。hosts 关闭时 `return null` 零 DOM → root 零 hit area → 穿透不受影响。（#14/#17 补丁 2026-08-14：原"浮层显示时各自设 auto"模式——`pointer-events` 是继承属性，ContextMenu 菜单本体 / DialogHost 漏设 → 池侧点不动 + 无 hover，壳侧 portal 回退 body 掩盖了 bug。已废弃"各自设"） |
| 自分层 | 每个浮层类型独立 `z-index`——不互相压 |
| portal 渲染 | `ReactDOM.createPortal`——浮层逻辑和调用方解耦 |
| 单宿主 | 一个 FloatingLayerHost——不分散到多个组件 |

## 3. z-index 层级

在 `src/constants.ts` 统一定义：

```typescript
export const Z_INDEX = {
  splitHandle: 100,          // 分屏分隔线拖拽手柄
  panelResizeHandle: 200,    // 面板拖拽尺寸手柄
  dragPreview: 500,          // 标签页拖拽预览
  dropZone: 1000,            // 分屏拖拽预览（Glassmorphism 内发光）
  toast: 2000,               // Toast 通知
  contextMenu: 3000,         // 右键菜单
  quickPick: 4000,           // 命令面板 / QuickPick
  dialog: 5000,              // 对话框 / Modal
  tooltip: 6000,             // 工具提示
} as const;
```

全部代码用 `Z_INDEX.xxx` 常量引用，禁止裸数字。

## 4. ContextMenu

### 4.1 渲染方式

ContextMenu 通过 portal 渲染到 `#context-menu-root`：

```tsx
// ContextMenuHost——在 FloatingLayerHost 内部
function ContextMenuHost() {
  const [state, setState] = useState<ContextMenuState | null>(null);

  useEvent('context-menu:show', ({ items, position, context }) => {
    setState({ items, position, context });
  });

  if (!state) return null;

  return ReactDOM.createPortal(
    <div style={{
      position: 'fixed',
      left: state.position.x,
      top: state.position.y,
      zIndex: Z_INDEX.contextMenu,
      // pointerEvents 由 #context-menu-root 根级提供（§2 根级 opt-in）——不在此写
    }}>
      <ContextMenuRenderer items={state.items} context={state.context} />
    </div>,
    document.getElementById('context-menu-root')!
  );
}
```

### 4.2 消失机制

和 OverlayWindow 版相同逻辑：

- **点击 backdrop**（透明覆盖层 `inset: 0`，`z-index: Z_INDEX.contextMenu - 1`）→ 关闭菜单
- **Escape 键** → 关闭菜单
- **点击菜单项** → 执行命令 → 关闭菜单
- **键盘导航**（🔴 防 E5.6 focusable:false 键盘回归）：菜单打开后聚焦菜单容器，↑↓ 移动高亮 + Enter 选择 + Escape 关闭

### 4.3 定位计算

```
ContextMenu 定位：
  anchor: { x: clientX, y: clientY }  ← client 坐标（同窗口）
  不是 screen 坐标——极简Pool 只有一个窗口

  边界检测：
    if (x + menuWidth > window.innerWidth)  → x = window.innerWidth - menuWidth - 4
    if (y + menuHeight > window.innerHeight) → y = window.innerHeight - menuHeight - 4
    🔴 拖拽区钳制（硬约束 18）：menuTop = max(30, y)——TitleBarZone 是 -webkit-app-region: drag，
       菜单顶部进入 30px 拖拽区 → OS 截鼠标事件 → 顶部菜单项点不动
       （E5.6 OverlayWindow 是独立 BrowserWindow，无此问题——E5.7 新生风险）
```

和 OverlayWindow 版的区别：OverlayWindow 需要用 `screenX/screenY` 减去主窗口 `getBounds()` 偏移——极简Pool 用 `clientX/clientY` 直接定位。

### 4.4 聪慧→哑数据流（继承 E5.6#23.7 设计）

```
调用方（Pool 内任意 Zone）
  → window.linkdesk.menu.show(menuId, { x: clientX, y: clientY }, context)
    → IPC → 主进程 → 转发壳渲染进程
      → resolveMenuItems(menuId, context)  // 壳侧一次性全解析（CommandRegistry/MenuRegistry 在壳）
      → 回传主进程 → webContents.send('context-menu:show', { items, position, context })

FloatingLayerHost 收到 context-menu:show
  → ContextMenuHost setState
  → ContextMenuRenderer 渲染
  → 用户点击项
    → window.linkdesk.menu.select(commandId, context)
      → IPC → 主进程 → 转发壳渲染进程 → executeCommand(commandId, context)
```

**三个阶段分属三个层：**
1. 菜单项解析 → 壳渲染进程（CommandRegistry/MenuRegistry 所在——有权访问所有注册表）
2. 菜单渲染 → Pool renderer（哑——只渲染 `ResolvedMenuItem[]`）
3. 命令执行 → 壳渲染进程（executeCommand）

**哑渲染器不自己 getItems/executeCommand/resolveChildren。** 它只收 `items` + 回传 `commandId`。

**E5.7 简化：** 单 Pool 后 `originPool` 追踪不需要——调用方永远是唯一 Pool。

🔴 主题/语言机制拆开写（2026-08-13 审计修正——语言不能靠 CSS 继承）：
- **主题**：菜单渲染在 Pool 文档内，自动继承 Pool 文档的 CSS 变量——壳→Pool 的 theme:changed 广播保留（preload-pool 注入），只是不再单独推给 OverlayWindow
- **语言**：显示文本铁律——标签在壳侧 t() 解析后作为字符串推送，池哑渲染、不初始化 i18n

## 5. QuickPick / CommandPalette

### 5.1 渲染方式

```tsx
function QuickPickHost() {
  const [state, setState] = useState<QuickPickState | null>(null);

  // Backdrop 覆盖全窗口
  // 居中面板——400px 宽，max 60vh 高
  // 顶部 input——自动聚焦
  // 中间列表——虚拟滚动
  // 防抖 150ms（输入过滤）

  return state && ReactDOM.createPortal(
    <>
      {/* Backdrop */}
      <div style={{
        position: 'fixed', inset: 0,
        zIndex: Z_INDEX.quickPick - 1,
        background: 'rgba(0,0,0,0.3)',
        pointerEvents: 'auto',
      }} onClick={close} />
      {/* Panel */}
      <div style={{
        position: 'fixed',
        top: '15vh', left: '50%', transform: 'translateX(-50%)',
        width: 400, maxHeight: '60vh',
        zIndex: Z_INDEX.quickPick,
        pointerEvents: 'auto',
      }}>
        <QuickPickInput ref={inputRef} onChange={handleFilter} />
        <QuickPickList items={filteredItems} onSelect={handleSelect} />
      </div>
    </>,
    document.getElementById('quick-pick-root')!
  );
}
```

### 5.2 数据流

```
用户 Ctrl+Shift+P
  → window.linkdesk.quickPick.show()
    → IPC → 主进程 → 转发壳渲染进程（🔴 2026-08-13 审计修正：CommandRegistry 在壳，Phase 11 主进程化后再改主进程直读）
      → QuickPickService 解析 items → 回传主进程
    → webContents.send('quick-pick:show', { items })

用户输入过滤
  → 本地 filter（不 IPC——items 已在 Pool 侧）
  → 或 IPC → 壳 filter（如果列表很大）→ 防抖 150ms

用户选择
  → window.linkdesk.quickPick.select(itemId)
    → IPC → 主进程 → 转发壳渲染进程 → executeCommand(itemId)
```

## 6. Toast

### 6.1 渲染方式

```tsx
function ToastHost() {
  const [toasts, setToasts] = useState<Toast[]>([]);

  useEvent('toast:show', (toast) => {
    setToasts(prev => [toast, ...prev]);  // 新的在下面（栈底）
    setTimeout(() => removeToast(toast.id), toast.duration || 5000);
  });

  return (
    <div style={{
      position: 'fixed',
      bottom: 30,          // 状态栏 22px + 8px gap（现网实测——回归矩阵场景 5）
      right: 6,
      zIndex: Z_INDEX.toast,
      pointerEvents: 'none',  // Toast 不阻挡交互
      display: 'flex',
      flexDirection: 'column-reverse',  // ← 新的在下面
      gap: 4,              // VS Code: margin 4px around each toast（现网实测）
    }}>
      {toasts.map(toast => (
        <ToastItem key={toast.id} toast={toast} onDismiss={removeToast} />
      ))}
    </div>
  );
}
```

### 6.2 定位——对标 VS Code

VS Code 的 Toast 锚定 `.monaco-workbench` 窗口底部：

```css
.monaco-workbench > .notifications-toasts {
    position: absolute;
    bottom: 25px;  /* 22px 状态栏 + 3px gap */
    right: 12px;
}
```

极简Pool 等效：`position: fixed; bottom: 30px; right: 6px` — 锚定窗口底部（E5.7#16 执行时按现网实测修正——回归矩阵场景 5 已订正：状态栏 22px + 8px gap，见 ToastContainer.css 现网值；本页旧草图值 25px/12px 作废）。PanelZone 打开/关闭 → 编辑器缩小/扩大，Toast 位置不变。

### 6.3 动画

CSS transition + 入场/退场类名（E5.7#16 执行时按现网实测修正——迁移零视觉变化）：

```css
.toast-item { opacity: 0; transform: translateY(8px); transition: transform 300ms ease-out, opacity 300ms ease-out; }
.toast-fade-in { opacity: 1; transform: translateY(0); }
.toast-exiting { transition-duration: 200ms; }  /* 反向滑出，exit faster than enter */
```

## 7. Dialog / Modal

### 7.1 渲染方式

```tsx
function DialogHost() {
  const [dialog, setDialog] = useState<DialogState | null>(null);

  useEvent('dialog:show', (d) => setDialog(d));
  useEvent('dialog:close', () => setDialog(null));

  if (!dialog) return null;

  return ReactDOM.createPortal(
    <>
      {/* Backdrop */}
      <div style={{
        position: 'fixed', inset: 0,
        zIndex: Z_INDEX.dialog - 1,
        background: 'rgba(0,0,0,0.5)',
        pointerEvents: 'auto',
      }} />
      {/* Modal */}
      <div style={{
        position: 'fixed',
        top: '50%', left: '50%', transform: 'translate(-50%, -50%)',
        minWidth: 300, maxWidth: '80vw', maxHeight: '80vh',
        zIndex: Z_INDEX.dialog,
        pointerEvents: 'auto',
      }}>
        <DialogRenderer {...dialog} onClose={close} />
      </div>
    </>,
    document.getElementById('dialog-root')!
  );
}
```

### 7.2 焦点陷阱

```
Dialog 打开时：
  - Tab 键在 Dialog 内循环（第一个可聚焦元素 → 最后一个 → 第一个）
  - Escape → 关闭（如果 dialog.closable !== false）
  - 外部点击 → 关闭（如果 dialog.backdropDismiss !== false）
  - 禁用 Dialog 后方的交互（backdrop 挡板 + pointer-events: auto）
```

## 8. 与 E5.6 OverlayWindow 的对比

| 维度 | E5.6 OverlayWindow | E5.7 FloatingLayerHost |
|:--|:--|:--|
| 进程 | 独立 BrowserWindow + renderer | 同 Pool renderer |
| 定位坐标 | screenX/screenY（需窗口偏移） | clientX/clientY（直接） |
| 鼠标穿透 | setIgnoreMouseEvents(true/false) | CSS pointer-events: none/auto |
| z-index | BrowserWindow 层级 | CSS z-index 数字 |
| 渲染方式 | overlay-main.tsx 分发 | ReactDOM.createPortal |
| 通信 | IPC ×3（壳→Overlay→调用方） | IPC ×1（调用方→主进程→Pool） |
| 主题同步 | 壳 pushTheme → OverlayWindow（独立窗口需单独推） | 菜单在 Pool 文档内，继承 Pool 已注入的 CSS 变量（壳→Pool theme:changed 广播保留） |
| 语言 | 壳推送语言到 OverlayWindow | 壳侧 t() 解析后字符串推送（池哑渲染，不初始化 i18n） |
| 代码量 | ~400 行（OverlayWindow 类） + overlay-main.tsx | FloatingLayerHost ~50 行 |
