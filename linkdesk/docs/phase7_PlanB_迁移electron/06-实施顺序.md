## 一、前置条件——迁移的唯一门槛

**满足以下全部条件后，下一个 commit 就是迁移。**

| # | 前置 | 内容 | 理由 |
|:--:|------|------|------|
| 1 | Phase 5.5 剩余 bug | 步 15 + G 类关键 bug 全部修完 | 迁移前代码必须稳定——带着已知 bug 迁移 = 新框架上旧 bug 叠加新 bug |
| 2 | `tsc --noEmit` + `vitest run` | 零错误 + 全测试通过 | 迁移前基线——确保迁移过程中能区分"原来就是坏的"vs"迁移搞坏的" |
| 3 | 旧 Phase 6（原计划底层加固）**尚未开始** | 一行旧 Phase 6 代码都没写 | 此时 Rust 投资最小（751 行）、插件最少（4 个）、无 add_child 代码、无 Rust 插件化代码。延迟一天，Tauri 耦合只增不减 |

**为什么不等旧 Phase 6 做完再迁移：** 旧 Phase 6a-c 会改 `StorageService.ts`、`useSendData.ts` 等文件——里面全是 `invoke()` 调用。先做旧 6a-c 再迁移 = 改了这些文件 → 迁移时每个 `invoke()` 再改一遍 `window.linkdesk.*` = 同一批文件碰两次。**先迁移再做 = `invoke` → `window.linkdesk` 在 Phase 6 一次性改完 → 然后 Phase 7 的新代码直接在正确的 API 上写，只碰一次。**

## 三、迁移 7 步——详细见 04 文档

| 步 | 内容 | 工时 | 验证标准 |
|:--:|------|:--:|------|
| 1 | Electron 壳初始化 | 1h | 壳 UI 正常渲染 |
| 2 | 串口服务（serialport npm） | 2h | 串口枚举 + 收发 |
| 3 | 文件/配置/插件管理服务 | 3h | 插件安装/卸载、配置读写 |
| 4 | 接前端 API | 3h | tsc 零错 + vitest 全过 + 功能完整 |
| 5 | linkdesk:// + WebContentsView 架构 | 4h | protocol 工作 + WebView 创建 |
| 6 | 清理 + 测试 | 2h | 端到端验证全部功能 |
| 7 | Electron 打包 | 1h | 生成安装包 |
| **合计** | | **~16h** | |

**步 5 备注：** 这一步只建架构骨架——4 个现有插件仍然在壳 WebView 里渲染（向后兼容）。Phase 7 期间逐步迁移每个插件到独立 WebContentsView。这是为了把"中"难度拆成可独立验证的小步。

## 四、原 Phase 6（底层加固）→ 新 Phase 7a-c

| 原计划（旧编号） | 迁移后（新编号） | 变化 |
|------|------|:--:|
| 6a: ErrorBoundary 增强 | → **7a**——纯 TS/React，框架无关 | 无 |
| 6b: 终端归一化 | → **7b**——纯 TS，框架无关。`serialport` npm 替代 Rust `serialport-rs` | 实现工具变了，目标不变 |
| 6c: FileService 等 | → **7c**——纯 TS，框架无关。`window.linkdesk.filesystem` 替代 `@tauri-apps/plugin-fs` | 底层变了，逻辑不变 |
| **6d: Rust 命令插件化** | → **删除** | **目标自动达成——Node.js `serialport` 天然独立，不需要"插件化"包装** |

原 6d 的目标是"`serialport` 从核心 `Cargo.toml` 消失"。迁移到 Electron 后 Rust 后端整个消失——目标自动达成。不需要走"先 Rust 插件化 → 再迁移"的路径——一步到位在 Node.js 上实现等价的模块隔离。

| 7b: 文件树 + Monaco 编辑器 | → **7e**——纯 UI 插件，框架无关 | 不受迁移影响 |
| 7c: 主题/语言引擎插件化 | → **7f**——纯 TS，框架无关 | 不受迁移影响 |
| 7d: Profile + 壳完善 | → **7g**——纯 TS/React，框架无关 | 不受迁移影响 |

[Phase7 原始设计文档](../phase7_多WebView与编辑能力/) 里的分析——七个坑（CSS 同步、IPC 竞态、内存、调试、开发体验、视觉接缝、安全）——**全部在 Electron 上同样适用，一份分析不浪费。** 变的只是 `add_child` → `WebContentsView`。

## 六、Phase 8 不受影响

Phase 8 是纯消费者插件——卡片工作台 + OLED。**不管在 Tauri 还是 Electron 上，代码完全一样。** 不受迁移影响。

## 七、回退策略

**如果迁移后发现 Electron 不可行（概率低）：**

1. `git checkout phase6-tauri`——回到完整 Tauri 工程
2. 丢失的：Electron 迁移以来的新代码
3. 保留的：Phase 1-5 全部基础设施 + Phase 6a-c 成果（这些是同一份 TS/React 代码）
4. 两分支上相同的：全部 React 组件、Registry、Hooks、插件、测试——不存在"白干"
