# 03 · 按任务操作（配方）

> 找「我要做某件事」的**具体走法**。每条配方是同一形状：**怎么做（代码）→ 读数验收（怎么证明成了）→ 坑**。
> 命令 id 与参数口径见 [02-命令与API索引](02-命令与API索引.md)；调命令的 `undefined` 位见 [01 章 §三](01-操作路径总览.md)。
> 代码一律按 `window.linkdesk` 前缀书写（池侧内容；`linkdesk` 是它的惯用别名）。

## 0. 先学会「问软件」

**配方 R0（所有配方的入口）**：不知道某插件能不能做某事、参数叫什么 —— 直接问：

```js
const all = await linkdesk.commands.getCommands();
// ① 按插件筛（命令 id 前缀 ≈ 插件归属；准确归属用 getCommands() 的 pluginId 字段）
const serial = all.filter((c) => c.id.startsWith("serial"));
// ② 每条命令自带 description（人话说明）与 params（参数名/类型/必填/说明）
console.log(serial.map((c) => [c.id, c.title, c.description, c.params]));
```

- 这是**运行时真源**，比本手册的索引新（索引是它的快照）。
- `params` 的**顺序 = 调用实参的顺序**（`params[0]` 就是第 3 个实参）。
- ⛔ 查不到 = 真的没有，别猜 id（[01 章 §七](01-操作路径总览.md) 第 3 条）。

## 1. 标签页（开 · 聚焦 · 关 · 批量 · 固定 · 挪位）

```js
// 开一个插件标签页（例 6 的核心）
await linkdesk.tabs.create("serial-monitor");     // 每次都新开一条
await linkdesk.tabs.openOrFocus("serial-monitor"); // 已有则聚焦，没有才开——**优先用它**（避免开一堆重复）

// 开文件标签页
await linkdesk.tabs.create("editor", { filePath: "D:/work/a.json" });

// 聚焦 / 关闭（按 tabId）
await linkdesk.tabs.focus("tab-7");
await linkdesk.tabs.close("tab-7");

// 按插件的**业务键**关（不加窗也能命中：sourceId 是插件绑数据的功能键）
await linkdesk.tabs.closeBySourceId("serial-monitor-49");
```

**例 6：一次开五个插件的标签页**（逐条 `create`，任一失败不牵连后续）：

```js
for (const id of ["serial-monitor", "modbus", "oscilloscope", "json-viewer", "notes"]) {
  await linkdesk.tabs.openOrFocus(id);   // 已开则聚焦（幂等）；要严格新开用 create
}
```

命令面的等价物（适合从菜单/面板那侧来）：
`core.closeTab {tabId}` · `core.closeOtherTabs {tabId}` · `core.closeRightTabs {tabId}` ·
`core.closeAllTabs {groupId}` · `core.closeAllEditors` · `core.duplicateTab {tabId}` ·
`core.togglePin {tabId}` · `workbench.action.focusNthTab {n}` · `workbench.action.nextTab {shift?}` ·
`workbench.action.reopenClosedEditor`（撤销关闭）。

**读数验收**：`(await linkdesk.tabs.list()).windows[0].groups` —— 数出每组 `tabs.length` 与 `activeTabId`。
**坑**：`tabs.create` 的**第一个参数是插件 id**（不是类型，虽然文件标签写 `"editor"`）；
`openOrFocus` 才是「用户语义」（不重复开）——AI 批量操作优先用它。

## 2. 分屏与嵌套分屏（例 11）

**方向口径**（⚠️ 与直觉相反的一半在这里）：

| 写法 | 屏幕上 | 等价命令 |
|:--|:--|:--|
| `direction: "horizontal"` | 左 **\|** 右 **并排**（沿 x 切） | `core.splitRight {tabId}` |
| `direction: "vertical"` | 上 **/** 下 **堆叠**（沿 y 切） | `core.splitDown {tabId}` |

```js
// 第一层：拿 tab-1 向右分屏（新组在右）
await linkdesk.pool.tabAction({ action: "splitTab", tabId: "tab-1", direction: "horizontal" });

// 第二层：把新组里的 tab-3 再上下分（嵌套 = 再发一次 splitTab，作用在**该组内**的 tabId 上）
await linkdesk.pool.tabAction({ action: "splitTab", tabId: "tab-3", direction: "vertical" });

// 指定落在哪个组（跨组分裂；不给则用 tabId 所在组）
await linkdesk.pool.tabAction({ action: "splitTab", tabId: "tab-5", direction: "horizontal", targetGroupId: "g-2" });

// 调分屏比例（百分比，两值之和无需为 100——渲染时按比例归一）
await linkdesk.pool.tabAction({ action: "updateSplitSizes", anchorGroupId: "g-2", sizes: [30, 70] });
```

嵌套的**正解是逐层发**：每层 `splitTab` 只把一个组一分为二。看 `pool.getLayout().root` 确认树形
（`branch` 套 `branch`）。**上限 = 深度 4**（`MAX_TREE_DEPTH`）——超了会被拒（[01 章 §七](01-操作路径总览.md)：先读树再动手）。

命令面的单层分屏：`core.splitRight {tabId}` / `core.splitDown {tabId}` / `workbench.action.toggleSplit`（当前组分屏↔合并）
/ `core.openInNewWindow {tabId}`（脱出为新窗）/ `core.mergeBackToMain {tabId}`（并回主窗）。

**读数验收**：
```js
const { root } = await linkdesk.pool.getLayout();  // branch/leaf 树：children[0]=左或上，children[1]=右或下
```
**坑**：`splitTab` 的 `direction` **不是**「分割条的方向」，是「排列方向」——写错就得反着理解一次。
`zone` 字段是拖拽落区归一化产物（`left/right/up/down/center`），**不是**你要传的方向；手写调用**只用 `direction`**。

## 3. 空间定位问答（例 12：「串口监视器在最右下角那一块」）

读取面：`tabs.list()`（全窗清单）＋ `pool.getLayout()`（本窗完整布局：`root` 树 + `groups` + `titleBar` + `sidebar` + `panel`）。
**软件外（门③）同一份数据**：`tabs` 操作（`windows[].root`/`groups`）——那份壳数据不分门。
⚠️ **别拿 `workbench.action.getLayout` 当分屏树**：它读的是**窗口/侧栏/面板几何**（宽高/贴边/显隐），
**不含**分屏结构（同名不同物，门外最容易踩的一脚）。

**「最右下角那块是谁」的算法**（与渲染器同规矩，见 `MainZone/layout.ts`）：
`children[0]` 在左/上，`children[1]` 在右/下 ⇒ 递归时**优先走 `children[1]`**，遇到 `branch` 就按
「右优先、无右则下」继续；到 `leaf` 拿 `groupId` → 去 `groups` 找该组的活跃标签 → 报它的 `title`。

```js
const layout = await linkdesk.pool.getLayout();
function bottomRight(node) {                    // 最右下角的 groupId
  while (node.type === "branch") node = node.children[1];
  return node.groupId;
}
const gid = bottomRight(layout.root);
const g = layout.groups.find((x) => x.id === gid);
console.log(g.id, g.activeTabId, g.tabs.map((t) => t.title), g.tabs.length);
```

**回答「X 面板在哪」**（反查）：`groups.find(g => g.tabs.some(t => t.title.includes("串口")))` 拿到 `groupId`，
再用 `root` 反推它落在哪个方位——说明「在哪一组、是左还是右、是上还是下」。
**多窗口**：`tabs.list().windows[]` 一次给全（每窗 `windowId` / `mode` / `activeGroupId` / `root` / `groups`）；
「当前窗」**没有**真相源（壳侧不存在这个概念）——要哪一窗自己按 `windowId` 筛（[02 章](02-命令与API索引.md) §三 `tabs.list` 说明）。
**坑**：`tabs.list()` 是**池侧独有**（壳不需要绕 IPC 问自己）；`title` 是可显示标题，`hint` 只在文件标签上有（完整路径）。

## 4. 通知：读懂它，并点掉它

```js
const nl = await linkdesk.notifications.list();   // NotifLayout：unread + 分组 + 每条 actions
const item = nl.groups.flatMap((g) => g.items)[0];

// ① 答「弹了什么/为什么弹」：message + sourceLabel + **wake**（是否允许把面板弹出来）
console.log(item.message, item.timeLabel, item.sourceLabel, item.wake);

// ② 点它上面的按钮 = 走同一条命令路径（读到什么就执行什么）
const a = item.actions.find((x) => x.isPrimary) ?? item.actions[0];
if (a?.command) await linkdesk.commands.executeCommand(a.command, undefined, ...(a.args ?? []));
```

**各字段能答什么**（`NotifItem`）：`message` 正文 · `iconClass` 严重级 · `timeLabel`「几分钟前」·
`sourceLabel`「来源: X」· `actions[].label/isPrimary/command/args` 按钮与它会跑的命令 ·
`wake` **是否允许弹面板**（恒在；`false` 也有信息量 = 它就是「这条没弹」的答案）·
`ttl` 自动消失毫秒数（`0` = 不消失）· `persistent` 长驻 · `progress`/`percent` 进度类通知的旗标与百分比。
**安装类任务**看 `sections`（`running` / `queued` 两段 + `NotifJobRow`，带 `cancellable`/`cancelLabel`）。
**坑**：`args` 可能与 `command` 成对出现；`command` 缺省 = 该按钮点击只关闭通知（没有命令可执行）。
⛔ 别去点通知的坐标——`actions[]` 就是它的结构化替身。

## 5. 面板 · 侧栏 · 悬浮面板

```js
// 例 4：左侧面板移到右侧
await linkdesk.commands.executeCommand("workbench.action.toggleSidebarPosition", undefined);

// 例 5：底部面板里隐藏某个插件的视图
await linkdesk.commands.executeCommand("workbench.action.togglePanelViewVisibility", undefined,
  "panel-container-id", "serial-monitor.view");   // 两个参数平铺（见 02 章该行「调用实参」列）
// 等价写法：一个具名对象（键名 = 那两个参数的名字；≥2 个参数时壳侧按声明顺序展开）
await linkdesk.commands.executeCommand("workbench.action.togglePanelViewVisibility", undefined,
  { containerId: "panel-container-id", viewId: "serial-monitor.view" });

// 其它：面板显隐/停靠/对齐/折叠
await linkdesk.commands.executeCommand("workbench.action.togglePanel", undefined);
await linkdesk.commands.executeCommand("workbench.action.positionPanelRight", undefined);
await linkdesk.commands.executeCommand("workbench.action.toggleViewVisibility", undefined, { viewId: "x" });
await linkdesk.commands.executeCommand("workbench.action.toggleContainerCollapse", undefined, { containerId: "c1" });
await linkdesk.commands.executeCommand("workbench.action.resetContainerPosition", undefined, { containerId: "c1" });

// 悬浮面板打开某视图（已开同名则关闭——注意这层幂等语义）
await linkdesk.commands.executeCommand("workbench.action.revealFloatingPanel", undefined, "viewId", "pluginId");
```

**参数形态**：`ctx: {...}` 是**一个对象**（平铺一个实参）；`containerId: string` / `viewId: string` 之类是**逐个平铺**——
也可合并成**一个具名对象**（如 `{ containerId, viewId }`，键名照参数名；≥2 个参数时壳侧按声明顺序展开）。
只有 1 个参数的命令不展开——那个对象本身就是实参。
以 [02 章](02-命令与API索引.md) §二「参数（调用实参）」列为准——那列就是「你该传几个实参」。
**读数验收**：侧栏左右看不出读数？用 `pool.getLayout()` 的 `sidebar`/`rightSidebar` 字段（谁在谁是权威）；
面板视图可见性读 `viewContainer.getViews()`。

## 6. 设置 · 主题 · 语言

```js
// 读（含「被改过没/是谁改的」）
const v = await linkdesk.configuration.get("editor.fontSize");
// 写
await linkdesk.configuration.set("editor.fontSize", 14);

// 设置行的三个配套命令（右键菜单那套）
await linkdesk.commands.executeCommand("workbench.action.copySettingId", undefined, { settingKey: "editor.fontSize" });
await linkdesk.commands.executeCommand("workbench.action.resetSetting", undefined, { settingKey: "editor.fontSize" }); // 会弹确认框
await linkdesk.commands.executeCommand("workbench.action.followTheme", undefined, { settingKey: "app.backgroundImage" });

// 主题/语言
await linkdesk.commands.executeCommand("theme.pick", undefined);                     // 弹选择器（要用户选）
await linkdesk.commands.executeCommand("theme.pick", undefined, { pluginId: "my-theme" }); // 只列该插件主题
await linkdesk.theme.apply("my-theme.dark");                                          // 直接生效（不弹窗）
await linkdesk.commands.executeCommand("workbench.action.selectLanguage", undefined);
```

**打开设置页**：`core.openSettings`（`ctx?: {pluginId, scrollTo}` 可定位到某插件分组并滚到某项）。
**坑**：`resetSetting` 会弹确认框（要用户点）——**无人值守时别用**，直接 `configuration.set(key, defaultValue)`。
**读数验收**：`configuration.get(key)` 复读；要「来源」用 `inspectConfiguration`。

**软件外（门③）读写设置**——门外没有 `window.linkdesk`，走这对命令：

```bash
linkdeskctl exec workbench.action.listConfigurations --json                            # 有哪些键（类型/默认/枚举）
linkdeskctl exec workbench.action.getConfiguration '{"key":"app.theme"}' --json        # 读（含 defaultValue/userValue/effectiveValue 分层）
linkdeskctl exec workbench.action.setConfiguration '{"key":"app.theme","value":"dark"}' --json   # 写（用户层）
```

- **写入回执**：`{key, applied, persisted, previousUserValue, userValue, effectiveValue}`——`previousUserValue` 是**写之前**那份，
  `userValue`/`effectiveValue` 是**写完重新读回来**的（⛔ 不是「我打算写的那个」）；`applied:false` 时带 `reason` 与 `error`，照它改。
  实参两种写法等价：具名 `{"key":"…","value":…}` 或逐位 `("键名", 值)`。
- **拒因一律出在回执里**（⛔ 不抛异常、不静默）：`undeclared`（键名不在注册面——**先 `listConfigurations` 对名字**）／
  `blocked`（**禁写名单**：`ai.*` 一律拒——AI 接入族（门锁／调试端口／账本开关）只由用户在设置页点，防 AI 自改自己的门）／
  `display-only`（该项是**显示槽**：`renderHint` 为 `readonly`/`action`，看状态或按钮，不是可写的值）／
  `bad-type`·`enum`·`below-minimum`·`above-maximum`（值要与 schema 的类型/枚举/上下限对得上）。
- **只写用户层**：`persisted:false` = 值进了内存但**落盘失败**（本次会话生效、重启会丢，如实报）；
  想「还原」就把 `value` 写成 `getConfiguration` 里的 `defaultValue`。

  口径见 [01-任务-命令id归属评估.md §10.2.2](../02-Electron架构/E6_插件生态与发布/01-插件独立构建/非样式命名空间归一化/01-任务-命令id归属评估.md)）。

## 8. 串口（例 10：发东西 + AI 自己转编码）

```js
const ports = await linkdesk.serial.listPorts();                 // [{ path, ... }]
const status = await linkdesk.serial.getStatus();
await linkdesk.serial.openPort("COM3", { baudRate: 115200 });    // 参数以 getStatus/listPorts 的返回与命令元数据为准

// 发文本并指定编码（编码由你决定——这就是「AI 自己转」）
await linkdesk.serial.sendText("测\r\n", "GBK", "COM3");         // (text, enc, portName?)
await linkdesk.serial.sendData([0x01, 0x03, 0x00, 0x00], "COM3"); // 裸字节

// 编码三件套（收：先探测再解码；发：先编码）
const enc = await linkdesk.encoding.detect(bytes);
const s = await linkdesk.encoding.decode(bytes, enc);
const out = await linkdesk.encoding.encode("测\r\n", "GBK");

// 收：订阅
const off = linkdesk.serial.onData((chunk) => { /* chunk 按编码解 */ });
```

**读数验收**：`serial.getStatus()`（是否已开、哪个口）；回显/收发计数从 `onStats` 订阅读。
**坑**：`sendText` 的第二参**必须**给编码（想「跟界面当前编码一致」也要自己先读出来再传，别留空）。

**怎么把回声读回来**（闭环：发一条 → 读回声 → 据此算下一组参数 → 再发）。串口虽是**流**，但软件**外部**的调用方（门③）没有订阅通道——读回声走串口插件的**拉取式命令**，⛔ 别想着「订一个事件」：

```bash
# 门③（软件外）：linkdeskctl exec <commandId> [args…]，实参两种写法等价（逐位平铺 / 一个具名对象）
linkdeskctl exec serial-monitor.listPorts --json                                       # ① 先看这台机器上有哪些口（挑 portName）
linkdeskctl exec serial-monitor.listSessions --json                                    # ② 看有哪几条会话、谁是活跃（挑 sessionId）
linkdeskctl exec serial-monitor.openPort  '{"portName":"COM3","baudRate":115200}' --json
linkdeskctl exec serial-monitor.send      '{"sendMode":"text","data":"AT\r\n"}' --json
linkdeskctl exec serial-monitor.readSince '{"since":0}' --json
linkdeskctl exec serial-monitor.readSince '{"since":<上一次回执里的 cursor>}' --json   # 下一轮带上回的游标续读
```

```js
// 门②（池侧）同一个命令：
const r = await linkdesk.commands.executeCommand("serial-monitor.readSince", undefined, { since: 0 });
// → { ok, items: [{ seq, portName, text, hex, ts }], cursor, count, lost }
```

- **多串口 = 多条会话并立**（每条一个口、一套设置、一个标签页）。**改设置类命令要点名会话**：
  `serial-monitor.toggle*` / `setSendCoding` / `closeSession` 都可带 `{"sessionId":"…"}`——缺省才是「活跃会话」。
  🔴 点名了却找不到那条会话 ⇒ **如实拒**（`{ok:false,noop:true,reason:"bad-session"}` 并列出**现有哪几条**），
  ⛔ **不会静默落到活跃会话上**（那种「账面无错、其实改了别的会话」正是多串口下最难查的错）。
- **开关类命令的回执自带读数**：`{ok, sessionId, name, field, value, previous}`——`field` 恒为被翻的字段名，
  `value` 是**改完读回来的**当前值 ⇒ 状态直接读回执，**别从命令面板标题反推**（标题是给人看的）。
- **`listSessions` 的两条读数别误读**：`viewMounted` = 该会话此刻**有没有挂载标签页**（视图态命令要靠它）；
  `paused` 没挂载时**如实回 `null`**（⛔ 不是 `false`——「没开标签页」与「不是暂停态」是两件事）。
- **`listPorts` 回 `{portName, description, open, sessionId}`**：`open` 取插件自己的权威态（与侧栏灯同一份），
  `sessionId` 是这个口**绑在哪条会话**上（没绑则 `null`）——挑完口直接拿它去寻址，一步接上。
  一个口都没有 ⇒ 如实回 `{ok:true,count:0,ports:[]}`（**不是报错**）；读口失败 ⇒ `reason:"read-failed"`
  （「问不出来」与「没有口」处置相反，别混）。
- **回执三态**：有新数据 `{ok:true, items, cursor, count, lost}` ／ 没有新的 `{ok:true, noop:true, reason:"no-new-data"}` ／ 调用不成立 `{ok:false, noop:true, reason:"bad-since"|"bad-limit"|"bad-port"|"cursor-ahead"}`。参数错**照常返回、不抛**——照 `reason` 改参数重发。
- **`lost` 与水位**：`lost > 0` = 有数据滚出缓冲、**已经读不到**了（你落后了，循环要更勤或 `limit` 更大）；拿不准就先问水位 `exec serial-monitor.receiveStatus` → `{cursor, first, count, capacity, ports:[{portName,count,open}]}`——它替你分清「**口没开**」与「**开了但设备没说话**」。
- 口仍由**软件**持有（Windows 串口独占）：⛔ 不绕过软件自己开串口抢口，⛔ 不用剪贴板绕。
- 插件的命令 id / `description` / `params` **现查现用**：`linkdeskctl describe`（或门② `linkdesk.commands.getCommands()`）——插件命令不在本手册的固定索引表里，声明面属于插件自己。

**读数验收**：`exec serial-monitor.receiveStatus` 里 `ports[].open === true` 且 `count` 随收发增长；`readSince` 回的 `cursor` 单调不减。
「发送」与「编码切换」**已命令化**（`serial-monitor.send` / `serial-monitor.setSendCoding`，例 10 的 00 章状态行）。
界面里的个别动作（复制/清屏/搜索这类**视图态**动作）命令化程度仍取决于插件——
拿不准就 `serial-monitor.listSessions` 看 `viewMounted`，或 `describe` 的 `commandsPending`。

## 9. 插件：装 · 启 · 停（含例 3：添加市场源）

```js
const list = await linkdesk.pluginManager.list();
await linkdesk.pluginManager.install("D:/pkg/plugin.zip");   // 或 installWithProgress / reinstall
await linkdesk.pluginManager.disable("some-plugin");
await linkdesk.pluginManager.enable("some-plugin");
const uninstalled = await linkdesk.pluginManager.getUninstalled();
```

**例 3（添加第三方市场源）——命令面已就位**（需装 **marketplace** 插件；官方内置）：

```bash
linkdeskctl exec marketplace.addSource '{"url":"https://github.com/作者/仓库"}' --json
```

- 参数 `url`：作者**仓库主页**或 `marketplace.json` 的 **HEAD 直链**都行（保持原样落盘，不归一）。
- **回执三态**：加上了 `{ok:true, added}` ／ 没变化 `{ok:true, noop:true, reason:"official"|"duplicate"}` ／
  调用不成立 `{ok:false, noop:true, reason:"empty"|"bad-url"}`。
- 落盘后配置变更**自动重拉目录**；**回读**用 `workbench.action.getConfiguration '{"key":"marketplace.marketplaceSources"}'`。

**读数验收**：`pluginManager.list()` / `isDisabled(id)`；安装过程看通知（§4 的 `sections`）；
加了源之后目录里应出现该源的条目（回读上面那个配置键 ＋ 市场视图里的清单）。

## 10. 与人协作：要用户拿主意时

```js
const ok = await linkdesk.dialog.confirm({ title: "确认", message: "要覆盖 a.json 吗？" });
const picked = await linkdesk.dialog.openFile({ /* 过滤器等 */ });   // 让用户挑文件（AI 碰不到系统对话框 ⇒ 这是唯一的门）
await linkdesk.dialog.alert({ message: "已完成" });
```

**纪律**：破坏性操作（覆盖/删除/发布）**先问**——用 `dialog.confirm` 把决定权交回用户，
并在报告里说明「已征询」。⛔ 不要为了少一次交互而默默覆盖。
