# 02 · 边缘情况清单

> 14 条（E1–E3 双轨与契约 · E4–E8 轮询与哨兵 · E9–E12 徽标与搬移 · E13–E14 逃生舱与类型收窄）。判据与方案见 [01](01-方案与落点契约.md)。

## 双轨与契约

- **E1 · 设置插件发版早于壳（双轨期）**：宿主「解好语义」面（`{ source, effective }`）随壳攒批发版，而设置仓 1.0.27 先发 ⇒ 插件上线时新面不存在。**处置**：插件保留本地判定作 fallback（共享 `formatEffectiveValue` 照用），宿主面可用则优先；壳发版后删 fallback（一次小改，随下一次插件发版走）。**验收**：插件发版后在**现装壳**上零回归（fallback 生效）。
- **E2 · 无 `uiHint` ≠ 未知 `uiHint`**：按 `type` 渲染是大多数键的正常路径（分发器第二层 switch），降级契约**只**约束「声明了 hint 但渲染器不认识」。⛔ 不许把正常路径改成只读——否则全设置页大面积回归。
- **E3 · 降级要可见**：未知 hint 降级为只读后，作者必须能发现「我声明的 hint 没生效」——只读值带 title 说明（「此设置项声明了设置页不认识的控件形态，以只读显示」）。作者面 schema description 同笔改写（三处字节拷贝），否则作者面还在承诺「falls back to the default rendering」。

## 轮询与哨兵

- **E4 · 哨兵收敛后的同步门禁（落点按 1.1 对账改正）**：`__none__` 的正典**不在 contracts**（那是纯类型生成包，写不出运行时值，见 [01 §0.1](01-方案与落点契约.md)）⇒ 正典 = `@linkdesk/ui` 的 `settings-hints/settingsHints.ts`，壳 core 由 `ThemeEngine/constants.ts` **re-export** 转出。必须防字面量再复制回来——新增门禁判据「`"__none__"` 字面量在 `src/` 业务代码里出现即红（**唯一豁免 = 正典定义件本身**；注释/文档不判）」；设置仓旧字面量同笔改成 `import { CONFIG_NONE_SENTINEL } from "@linkdesk/ui"`（跨仓那半边由该仓 CI 管，壳 check 够不着）。
- **E4b · 正典件认领的是「值」不是「层」**：`CONFIG_NONE_SENTINEL` 从壳 core 私有常量变成**共享层正典**后，`src/core/services/ui/ThemeEngine/constants.ts` 会出现一条 **core → `@src/components/shared/*`** 的 import（方向反转）。这是判据 A 的直接后果（消费它的 `FontFamilySelect` 住在共享层、插件也要拿），⛔ 不是失误；但**只许这一条**——正典件必须是**纯 TS、零 React、零 DOM**（不许顺带把组件带进 core 的依赖图）。
- **E4c · `MIX_FOLLOW_THEME_SENTINEL`（`followTheme`）同笔收编**：它与 `__none__` 是同一族跨边界字符串契约（设置仓 `deriveSourceBadge.ts:24` 与壳 `startup.ts`/ThemeEngine 各自写字面量）。本次一并进正典件、两边改 import——⛔ 不新开第二个「正典件」（一处一个正典）。
- **E4d · `renderHint` 正典是**三**值不是两值**（1.1 对账实录）：壳 `appearance.ts` 有 `renderHint:"color"` 两处（`app.accentColor`/`app.glassTint`），`renderControl` 的 type-switch 也认它。原稿写两值（`readonly`/`action`）⇒ **收窄即当场红**；定稿 `"readonly" | "action" | "color"`。
- **E5 · poller registry 生命周期**：去重 registry 按 `commandId` 引用计数，最后一个实例卸载才真停 `setInterval`；registry 是模块级 ⇒ 每 renderer 进程一份（主窗/脱出窗天然隔离，无需跨窗协调）。⛔ 泄漏形态＝实例卸载没减计数 ⇒ fake timers 测试盖「挂载 N→卸载 N→再挂载仍轮询」。
- **E6 · 隐藏暂停是行为变更，要明示**：今天的 ReadOnlyStatus 在页签隐藏时照轮；升级后隐藏暂停、回可见立即刷一次。ai 组验收判据相应写成「**可见时**节奏 3s 不变；隐藏暂停＋回可见立即刷」——⛔ 不许悄悄改，验收逐格对。
- **E7 · `statusCommand` 返回非字符串/抛错**：照抄今天——抛错静默保持现值、非字符串按 `String()` 处理与否以现实现为准（原样平移，不顺手"改进"）；共享件契约文档写明「命令返回字符串，空串/null ⇒ 不占位」。
- **E8 · 多行同命令不同 `intervalMs`**：registry 以 `commandId` 为键，间隔取首个挂载实例的声明；作者文档写「同一 `statusCommand` 建议全仓同间隔」。不做按实例多定时器（那等于没去重）。

## 徽标与搬移

- **E9 · 第三方键声明 `effectiveToken` 但 token 解析不出** ⇒ 无徽标（优雅降级）；双轨期 fallback 同样只对解析得出的 token 显。⛔ 不显示空徽标占位。
- **E10 · mix（混搭）态语义平移不变**：`deriveSourceBadge` 的 theme/user/mix 判定**原样**平移宿主（含 `__none__` 显式无、`appearanceMode` 分支、baseline 比对全部边界）——⛔ 平移时"顺手简化"＝验收四态必炸。验收＝默认/覆盖/混搭/跟随逐格截图比对。
- **E11 · 生效徽标与滑杆值标签同屏（E1 交界）**：滑杆案落地后滑杆键可能同屏「值标签（配置值）＋生效徽标（生效值）」——宽度与取舍按[滑杆案 00 §四·4.3](../../已落地/滑杆件-Slider能力扩展/00-README.md)＋[设置行案 00 §四·补](../../待抉择池/设置行-控制只读同行/00-README.md)；本案只保证生效徽标本体收编，**不给滑杆键隐藏徽标的特判**（那是设置行案 D2 的事）。
- **E12 · `BackgroundImagePicker` 的能力注入面**：选图对话框/拷贝入库/`reveal` 都是宿主 API，共享件只收 `Promise` 型回调 props；设置仓接线时保持现有「选图→入库→受控路径」语义逐格不变（含 `__none__`/`""`/路径三态）。⛔ 共享件里不得出现 `window.linkdesk` 直接调用。

## 逃生舱与类型收窄

- **E13 · 逃生舱与 `settingsSlotFilled` 门控的关系**：`core.openSettings` 对坏套的处理（`settingsCommands.ts:208-209` return）不动；逃生舱是**独立命令**（激活套回退），齿轮菜单兜底项的 `when` 条件＝「激活套存在且非内置」；回退后是否 toast 提示由实施定，判据＝用户不重启即可再开设置页。
- **E14 · `uiHint` 收联合类型的第一次实战**：appearance.ts 现有声明值全量对表——若出现表外值，**先修声明或扩正典**再合（编译期红即是盘点成果）；`renderHint` 同理（`readonly`/`action` 两个值，设置行案将来扩「伴生共存」不动此类型）。
