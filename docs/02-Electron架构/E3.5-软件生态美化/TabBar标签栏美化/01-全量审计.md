# 01-全量审计——TabBar 标签栏现状

> 2026-07-29。逐项对照 VS Code 标签栏，标出差距。

## 一、骨架——几乎完美

TabBar 是 E3.5 专题中**功能最完整的组件**——拖拽重排、进出动画、溢出滚动、右键菜单、[+]菜单、dirty 标记、preview 斜体全部对标 VS Code。

| 维度 | 实现 | 评价 |
|------|------|------|
| 进出动画 | `tab-enter` 150ms + `tab-exit` 120ms（max-width+opacity） | ✅ |
| 拖拽重排 | `useDragReorder` hook + 插入指示器脉冲动画 | ✅ |
| 拖拽分屏 | `computeSplitZone` + 6 区检测 | ✅ |
| 拖拽预览 | `createPortal` → body，opacity 0.85 + scale 1.03 | ✅ |
| 溢出滚动 | `ResizeObserver` + 左右箭头 + 滚轮横向滚动 | ✅ |
| 关闭按钮 | hover/active 显示，opacity transition 100ms | ✅ |
| 右键菜单 | `ContextMenu` + `MenuId.TabContext` | ✅ |
| [+] 菜单 | 从 viewRegistry 动态生成列表 | ✅ |
| dirty 标记 | `●` 圆点 + `var(--dirty-dot)` 颜色 | ✅ |
| preview 斜体 | `.tab-item.preview .tab-label { font-style: italic }` | ✅ |

## 二、小瑕疵

### 2.1 关闭按钮 `×` 文本字符 🟡

```tsx
<button className="tab-close">×</button>
```

和状态栏 `│` 同样的问题——Unicode 字符 `×` 跨平台渲染不一致。改 `codicon codicon-close`。

### 2.2 dirty 圆点 `●` 文本字符 🟡

```tsx
{tab.dirty && <span className="tab-dirty-dot">●</span>}
```

同样是文本字符。但 `●` 作为单个圆形字符，渲染比 `×` 稳定得多（所有字体都有实心圆）。**可改可不改**——用 CSS 画圆（`width:8px; height:8px; border-radius:50%; background:var(--dirty-dot)`）更可靠。

### 2.3 [+] 菜单样式未跟 ContextMenu 统一 🟢

```css
.tab-plus-menu {
  border-radius: 6px;
  box-shadow: var(--context-menu-shadow);
}
```

ContextMenu 刚改成 `border-radius: 8px` + 双层 `box-shadow`。[+] 菜单的视觉效果和右键菜单不一致——用户能感觉到"这两不是同一个设计系统"。

### 2.4 滚动箭头 `‹` `›` 文本字符 🟢

和关闭按钮同理，但优先级更低——这俩是单字符箭头，渲染稳定的多。用 `codicon-chevron-left/right` 统一。

## 三、好的部分——不动

| 项目 | 评价 |
|------|------|
| 进出动画 | 对标 VS Code，max-width+opacity 方案成熟 |
| 拖拽系统 | 功能完整——重排+分屏+预览+脉冲指示器 |
| 布局 flex 值 | 对标 VS Code（flex 120 / min 80 / max 200） |
| active 融入 | border-bottom transparent——对标 VS Code，正确 |
| 隐藏滚动条 | scrollbar-width:none——正确 |

## 四、总结

**TabBar 是最不需要大改的组件——功能层 100% 对标，视觉层仅 3 个文本字符换 codicon。**

| 优先级 | 项目 | 改动量 |
|:--:|------|:--:|
| 🟡 | `×` → codicon-close | ~2 行 TSX |
| 🟡 | `●` → CSS 圆 | ~5 行 TSX+CSS |
| 🟢 | [+] 菜单样式对齐 ContextMenu | ~3 行 CSS |
| 🟢 | `‹` `›` → codicon-chevron | ~2 行 TSX |

**总计 ~12 行。**
