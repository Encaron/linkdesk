## 二、worker 打包——本棒最大坑（?url 是陷阱）

1. **第一版用 `?url`**（`import workerUrl from "pdfjs-dist/build/pdf.worker.min.mjs?url"` ＋ `GlobalWorkerOptions.workerSrc`）——`npm run build` 全绿**但包里没有 worker 文件**：vite 在 lib 模式把 1.3 MB 的 worker **内联成了 `data:text/javascript;base64` URL** 塞进主 bundle。data: worker 在池沙箱 CSP 下大概率被拦，且这个失败是静默的（构建期零警告、包体读数也看不出）。
2. **正解 = `?worker` 构造器路线**（editor 仓 monaco worker 同款）：`import PdfWorkerCtor from "pdfjs-dist/build/pdf.worker.min.mjs?worker"` → vite 出**独立 chunk** 进包 `assets/`。用 `new PDFWorker({ port })` 显式接管：pdf.js 对外部 port 的 worker **不代管 terminate**——`destroy()` 里 `loadingTask.destroy()` 之后由本模块自己 `rawWorker.terminate()`，一文档一 worker，不留常驻线程。
3. ⚠️ 验 worker 必须实机开文档看 numPages/渲染——「build 绿」不证明 worker 打包对。

## 三、cmaps／标准字体随包——public/ 通道

- SDK packager 静态清单是**白名单**（icon/i18n/README/LICENSE…），不收任意子目录；官方各仓也无人写 vite.config.ts（SDK exports 也不吐 `defineLinkdeskPluginConfig`——deep import 才有）。
- 找到的原生通道 = **vite publicDir**：内层 build（`buildSurfaces`）没关 publicDir，`public/` 整树随 outDir(=pkgDir) 进包。
- 落法：`scripts/sync-pdfjs-assets.mjs` 挂 npm **`prebuild`** 钩子，幂等同步 `node_modules/pdfjs-dist/{cmaps,standard_fonts}` → `public/pdfjs/`；`public/` 进 .gitignore（产物不是源码）。运行时 URL 用 `new URL("pdfjs/cmaps/", import.meta.url)` 自锚定（SDK base "./" 机制），dev/分发两轨皆准。
- 取用侧 `useWorkerFetch: false`——cmap/字体在池域（主线程）fetch，不进 worker 沙箱。**实机验证**：池域 `fetch("linkdesk://pdf-reader/pdfjs/…")` 全 200。

## 五、过程教训（给后续棒）

1. **harness 每次 Bash 后重置 cwd 到壳仓**——`npm install`／`npm run` 不带 `cd` 前缀会落到壳仓。本棒实翻车：pdfjs-dist 装进了壳仓 package.json（已 `git checkout -- package.json package-lock.json` 还原＋删误装 node_modules，壳仓零 diff 判据保住）。
2. **identityField=filePath 的空源开法**：`open-tab pdf-reader` 不带 sourceId ⇒ 无 filePath ⇒ 无法归一 ⇒ 每次都开新标签（`pdf-reader-2`、`pdf-reader-3`…）。测试时要带 `--opts {"sourceId":...}`；这不是插件 bug，是声明口径本义（editor 同款）。
3. 卸载重装后**必须硬 reload 池页**再开新标签，否则动态 import 按 URL 命中旧模块——「装了新版还是旧行为」的又一形。
