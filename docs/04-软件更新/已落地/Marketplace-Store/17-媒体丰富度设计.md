## 〇·AI 接手须知（30 秒版）

- **唯一媒体入口**：市场仓 `Art`（选帧抽成 `mediaOf` 纯函数）；hero / mega / duo / wall 只是 variant，⛔ 新建第二套 `MediaStage`。

## 〇、用户原话与判据（验收尺子）

下面不是转述摘要，而是**用户口头原话里的判断标准**。后面每一节都要能对回这里。

1. **「人家首屏图片的丰富度比较多」「咱们硕大的图片中间只有一张图标，非常单调」**
   ⇒ hero 必须被媒体占满；没有图时也不能是「纯渐变＋一枚图标」。
2. **「图片怎么放？作者没放图怎么办？图片用谁的？」**
   ⇒ 图用作者的 `screenshots/cover`；没图走生成式封面；⛔ 不替作者画图塞 git。
3. **「大卡可以放好几张，hover 的时候在它单独卡片里面来回播放预设好的那几张」**
   ⇒ 轮播只在**卡内**、只轮**静帧**、只在 hover 时；⛔ 自动播放。
4. **「小卡（靶场横滚那种长条形）只显示图标就可以了」**
   ⇒ small / rank-row 保持纯图标，不加图。
5. **「主题页每一个都有图，咱们主题卡本来就大，适合放图」**
   ⇒ THEMES 变成图墙；mega 卡的封面必须是图，不是图标。
6. **「首屏叙事：人第一眼往哪带？图片是个非常好的地方」**
   ⇒ hero 的媒体是首视觉，文案压在 scrim 上，不抢图。
7. **「板块节奏大小卡交替是作者的事，除非你把 API 揉碎了喂到嘴里」**
   ⇒ 我们只做「一个板块声明就能喂图」的 API/渲染；⛔ 替作者编排板块。
8. **「策展/编辑精选/榜单叙事：用现有素材设计，那我觉得不必了」**
   ⇒ 不新建编辑系统；现有素材能复用的才复用。
9. **「归一化、无硬编码、无死代码、高内聚低耦合——我强调太多次了」**
   ⇒ 见 §六 四问自检；任何一条不达标即返工。
10. **「以后能放个动态视频，都可以显示」**
    ⇒ 先支持**封面视频**（作者直链、controls）；⛔ autoplay、⛔ 托管/转码。
11. **「未装的人也得能看到图」**
    ⇒ 所有媒体绝对 URL（publish 自动 URL 化）；包内相对路径在未装处 404。
12. **「设计语言就是 MS Store 那种：hover 浮空放大、周围泛光」**
    ⇒ 新媒体沿用既有 transform／opacity／辉光；⛔ 另起一套动效语言。

## 一、结构诊断：为什么现在单调

**结论：不缺 API，缺「展示层的最后一段」＋作者确实没喂图。**

实读市场仓（`official/marketplace`，2026-11-22）：

| 事实 | 位置 | 含义 |
|---|---|---|
| `CatalogEntry.screenshots?: (string \| {type:"video",url,poster?})[]`、`cover?: string` 已存在 | `src/services/marketCatalog/types.ts` | **不需要新增字段/接口** |
| `Art` 已经按 `cover → screenshots[0] → 渐变＋图标` 选图 | `src/views/store/cards/cardParts.tsx:145` | 媒体链路**已通**，但只取**第 0 张**、无视频 |
| Hero / Mega / Duo 都已经调用 `<Art … className="is-hero/is-mega/is-duo" />` | `Hero.tsx` / `CardMega.tsx` / `CardDuo.tsx` | **一个原语已经在用**——本轮是扩展它，不是新建 |
| 无图时 `Art` 回落为「hue 渐变＋大图标」 | `cardParts.tsx:159-163` | 这就是用户看到的「绿色空块＋图标」 |
| 详情页已有截图画廊 | `DetailOverviewTab.tsx` | 可复用，不新建第二套画廊 |
| THEMES 分类页走通用 `CardGrid` | `CategoryView.tsx` + `OrderedCards.tsx` | 主题卡没有「封面在上」的图墙形态 |

因此三件事同时成立：
1. **数据缺**：多数作者没声明 `screenshots`（官方存量也基本没有）→ 回落路径被高频命中，显得单调。
2. **展示缺**：`Art` 只取首图、不播视频、不轮播；hero 仍是左右分栏的「文字 + 色块」，图没有成为首视觉。
3. **形态缺**：THEMES 没有专用图墙；小卡本来就是图标（这是对的，不动）。

⇒ **本轮只改展示层 + 补齐数据口径**；⛔ 不新增媒体字段，⛔ 不建第二套画廊，⛔ 不把图塞进壳仓。

## 三、媒体原语（唯一入口）

### 3.1 数据形状（复用，不改 schema）

```ts
// 市场仓既有字段——本轮一个字都不加
screenshots?: Array<string | { type: "video"; url: string; poster?: string }>;
cover?: string;
```

规则（解析期已有，展示层只消费结果）：
- `string` ＝ 图片绝对 URL；
- 视频对象**至多 1 段，且必须排第一**（越位/多段由解析期丢弃并记声明警告）；
- `cover` 与首图同权，用于合集/板块封面。

### 3.2 选帧（视图模型，纯函数）

```
frames = unique([ video.poster, cover, ...stills ]).slice(0, MEDIA_MAX_FRAMES)   // 默认 3
kind   = video ? "video" : frames.length ? "image" : "generated"
```

- **封面帧优先级**：视频海报 → `cover` → 第一张静帧；
- 轮播上限 `MEDIA_MAX_FRAMES = 3`（token，不是具体图片列表）；
- ⛔ 不按插件 id 挑图，⛔ 不替作者挑「最好看的那张」。

### 3.3 渲染原语

**一个 stage，四个变体**（HTML6 里叫 `.m-stage`，真机映射见 §六）：

| 变体 | 用在哪 | 媒体框比例 | 轮播 |
|---|---|---|---|
| `hero` | 首屏轮播 | `--media-hero: 2/1`（用户口径 3:2 或 2:1） | 手动箭头/圆点；视频自带 controls |
| `mega` | 主题专区超大卡 | 200px 高（≈3:2） | hover 卡内 2~3 帧 |
| `duo` | 双大卡 | 半幅（≈4:3） | hover 卡内 2~3 帧 |
| `wall` | THEMES 图墙 | `--media-card: 3/2` | hover 卡内 2~3 帧 |

比例、轮播上限、帧间时长全部走 CSS 变量/token：`--media-hero`、`--media-card`、`--media-fade`、`--media-cycle`。

### 3.4 无图：生成式封面（不是空渐变）

同一份 `m-gen` 层**永远垫在帧下面**（图 404/未加载时自动露出）：

- **色场**：`entryHue` 三向渐变（亮角 + 暗角 + 底色）；
- **纹理**：30px 细网格（径向遮罩，不糊满）；
- **图标**：`marketIcon` 放在半透明圆角砖里，带 hue 外发光；
- **文字**：插件名大号水印（8% 白）＋分类 · LinkDesk 小字；
- 小卡/行卡**不启用**生成式封面（仍只显示图标——用户明确要求）。

⛔ 不做插画风、⛔ 不按分类画一套固定图（那会变成第二套素材系统）。

### 3.5 五态（HTML6 §「媒体原语 · 状态陈列」可逐一看）

| 态 | 触发 | 表现 |
|---|---|---|
| 有图 | `screenshots` 有静帧/cover | 封面帧 + hover 轮播 |
| 封面视频 | 第一项是视频对象 | 卡内只给海报＋「含视频」；hero/详情给 `<video controls>` |
| 无图 | 两者皆空 | 生成式封面 |
| 加载中 | 帧请求未回 | 骨架占位 + 底纹兜底；**几何先占好**，图到不跳动 |
| 图挂了 | 404/未装相对路径 | `onerror` 拆帧 → 同一张生成式封面兜底 |

> ⚠️ **HTML6 的「状态陈列」是评审展板，不是产品 UI。** 真机没有这一排；五态分别长在 hero / mega / duo / wall / 详情里。
> 展板瓦片是 `.md-tile`（不是 `.card`）——没有 hover 放大、没有动作层，只用来一次看全状态。

### 3.6 轮播只有一套机制

| 位置 | 触发 | 用到的部分 |
|---|---|---|
| hero | 箭头 / 圆点 / 滚轮 | 同一份帧序列；视频走 `<video controls>` |
| mega / split / duo / wall | hover + 移出复位 | 同一段 `@keyframes`（2 帧、3 帧各一套＝帧数差异，不是卡型差异） |
| small / row / rank | 不轮播 | 无媒体 |

- 选帧、去重、上限 `MEDIA_MAX_FRAMES=3` 全在 `mediaOf()` 一处；
- 帧时长/淡入在 `--media-cycle / --media-fade` 两个 token；
- ⛔ 每种卡各写一个 JS 定时器；⛔ 每种卡各抄一份 `screenshots` 读取。

## 四、分卡型规格

**先对齐名字**（用户问过「MEGA 卡是谁」）：

| 代号 | 位置 | 长相 |
|---|---|---|
| **hero** | 首屏 | 整幅图/视频，文案压左侧暗角 |
| **split** | 「编辑精选」 | **整行、与 hero 同尺寸**：左文右图，无满幅/无 scrim |
| **mega** | 「主题专区」那一排 | 312px 宽：上封面 200px＋下灰条 60px；hover 灰条上滑（半透明玻璃） |
| **duo** | 作者声明 `duo` 合集 / 「付费插件」 | **两枚一排**（50% 宽）；左文右图，图内嵌 |
| **small** | 「装机必备」2×N 横滚 | 236×84，只图标 |
| **wall** | THEMES 页图墙 | 封面在上（3:2）、名字/下载/状态在下 |
| **grid / row / rank** | 分类、搜索、榜单、详情行 | 图标，不加图 |

> ⚠️ 最上面「编辑器」是 **hero**，「编辑器 Pro Pack」是 **duo**——同一份 `screenshots`、同一个 `Art` 原语、不同 `variant`；⛔ 不是两套 API。

**为什么 THEMES 单独用 `wall`（用户 2026-11-22 提问）**：

- 现状：THEMES 和其他分类一样走通用 `CardGrid`（图标＋文字），所以主题页看不到封面。
- 新媒体下，主题的封面**就是内容本身**；grid 卡会把图压成图标位，违背「主题页每卡都有图」。
- `wall` 只是 `Art` 的一个**版式变体**：封面在上（3:2）、名字/下载/状态在下（46px 脚区）、单角标。
  数据仍是 `screenshots/cover`，状态仍是 `statusTag`，媒体仍是同一个 `Art`，面仍是同一套卡片 token。
  ⇒ ⛔ 不是第二套卡片系统、⛔ 第二套数据、⛔ 第二套角标。
- **其他分类仍用 grid（图标）**：保持 300px 密度与加载性能，不把每个分类都变成图墙。
- 如果不想新增版式，替代方案只有「THEMES 用 mega 卡横排」——但那是横滚，不是图墙；本稿推荐 `wall`。

| 卡型 | 有图？ | 轮播 | 说明 |
|---|---|---|---|
| **hero** | 是（满幅 2:1；文案列 56%） | 手动翻页；视频 controls | 文案压左 scrim；图占视觉主体 |
| **split（分栏大卡）** | 是（内嵌半幅） | hover 2~3 帧 | 整行 270px（与 hero 同尺寸）；左文右图；⛔ 无满幅/无 scrim |
| **mega（主题专区）** | 是（200px 封面） | hover 2~3 帧 | 脚区与 hover 条保留；hover 条半透明玻璃，图仍可见 |
| **duo（双大卡）** | 是（内嵌画面） | hover 2~3 帧 | 两枚一排、50% 宽（真实形态）；左文案右媒体 |
| **wall（THEMES 图墙）** | 是（3:2 封面） | hover 2~3 帧 | 封面在上、名/下载/状态在下；hover **快捷层**：作者/价格/安装购买/更多 |
| **small（横滚 2×N）** | **否** | — | 只插件图标（用户口径） |
| **grid（分类/搜索）** | 否（本轮） | — | 保持图标；避免 300px 普查被图挤爆 |
| **row / rank** | **否** | — | 只图标 |
| **详情画廊** | 是 | 否（横滚） | 复用同一份 `screenshots`；无图时用同一 stage，⛔ 不另画线框画廊 |

**封面占比（用户点名要想清楚）**：
- hero：媒体铺满整幅（≈100%），文案列 56%——**第一眼落在图，第二眼落在标题**，CTA 与标题同列；不把按钮压在图上抢焦点。
- split：整行；左右 **1:1**，媒体占半边且内嵌 12px——与 hero 的分界是「只占半边＋无 scrim」。
- duo：两枚一排（各 50% 宽）；媒体占卡宽约 55% 且内嵌，文字列约 45%。
- mega：媒体 200px / 卡高 260px ≈ **77%**；duo：媒体占**半幅**（≈45%）；wall：媒体占卡高 ≈**75%**（3:2 + 46px 脚区）。
- small / row / rank：媒体占比 **0**（只图标）。

**动作优先级**：
1. 整卡＝进详情（唯一主语义，封面本身不吃第二次点击）；
2. 安装/更新/购买等主动作只在 **hover 层与详情页**出现，⛔ 不在封面上压按钮；
3. 状态位（已装/更新/价格）沿既有单角标，不因加图而新增第二套角标。

> **「进详情」不是唯一路径（用户 2026-11-22 追问）**：所有卡型 hover 都必须给出快捷动作——安装/更新/购买/获取许可，
> 用的是**同一套** `actionBtn` + `statusTag` + `moreMenu`。主题墙卡（wall）v6 已补上：作者、价格、主按钮、更多。
> ⛔ 任何新卡型漏掉 hover 动作层都算未完成。

## 五、交互、可访问性与边界

- **hover 轮播**：仅 `:hover` 期间运行；移出即复位封面帧；2 帧/3 帧两套 keyframes；`prefers-reduced-motion` 下停用（始终封面帧）。
- **视频**：`controls` 强制、`preload="metadata"`、⛔ `autoplay`、⛔ `loop`；只播作者直链，不托管/不转码。卡内**不出 `<video>`**——卡内只轮静帧，点卡进详情/hero 播。
- **不挡指针**：hero 的 scrim 是 `pointer-events:none`；视频 `onclick` 阻断冒泡，避免点播放跳详情。
- **机械守则不变**：新动效只用 `transform / opacity / 遮罩`；媒体在 `overflow:hidden` 容器内缩放，不参与布局几何。
- **未装态**：所有图/视频绝对 URL；`Art` 的 `src` 直接来自目录（publish 已 URL 化）。
- **降级**：`onerror` 拆帧露底纹；骨架只占位不伪造内容；加载失败不重试风暴。
- **归属**：卡片长相/编排留在市场插件；壳只提供播放/浮层/主题能力（2026-11-21 共享边界）。

## 十一、媒体资源从哪来、怎么更新（2026-11-22 用户问）

### 11.1 只有一个来源：作者声明的绝对 URL

- 字段就是 `marketplace.json` 里的 `screenshots[]` / `cover`（与既有 `icon` / `marketIcon` 同一套）。
- 目录拉取链：`sourceUrl.ts` → `https://raw.githubusercontent.com/<owner>/<repo>/HEAD/marketplace.json` → `parse.ts` 归一 → `Art` 渲染。
- 资源可以放在：插件仓的 `resources/`（raw URL）· 作者自己的 CDN/COS · 任意公网 HTTPS。
- **壳与市场都不托管、不转码、不代画**；未装用户必须能直接访问 ⇒ 绝对 URL，包内相对路径必 404。

### 11.2 三种「换内容」的成本

| 想改什么 | 改哪里 | 要发插件新版本吗 | 为什么 |
|---|---|---|---|
| **谁上 hero / mega / 小卡 / duo** | 目录的 `collections[]`（`layout` + `items`） | ⛔ **不用** | 槽位是目录声明，插件只是被按 id 引用 |
| **某插件的截图 / 封面** | 该插件仓 `marketplace.json` 的 `screenshots` / `cover` | ⛔ **通常不用**（见 11.3） | 媒体是目录元数据，不是插件包内容 |
| **促销图 / 价格** | 同上（`pricing` 也在目录条目） | ⛔ **不用** | 刷新目录即生效 |
| **图放在插件包内（相对路径）** | 只能发新版本 | ✅ **必须** | 包内容不可变；未装用户还看不到 |

> 结论：**换图、换价格、换哪个插件上大屏，都不需要动插件本体**——改目录声明（GitHub 上的 `marketplace.json` / `collections/*.json`），商店刷新后生效。
> 唯一例外：图被打进插件包，或用「版本钉死」的 URL（见 11.3）。

### 11.3 一个必须遵守的 URL 纪律（否则还是得发版）

现有官方 `icon` 是**版本钉死**的：`https://raw.githubusercontent.com/…/v1.0.26/resources/icon.svg`。
版本 tag 是不可变内容——换图 ＝ 新 tag ＝ 发版。

截图/封面若要「随时换、不发版」，必须指向**稳定路径**：

1. 插件仓的稳定分支（如 `…/HEAD/resources/shots/hero.png` 或专用 `media` 分支），或
2. 作者 CDN/COS 的固定 key。

替换时**改 URL**（加 `?v=20261111` 或内容哈希）以绕过 Chromium / raw.githubusercontent 缓存。
推荐：截图放独立 `media/` 目录或 CDN，`marketplace.json` 只存 URL；⛔ 插件包不装图。

### 11.4 刷新链路（双十一大促怎么做）

1. 作者/官方在目录仓提交新的 `screenshots` / `pricing`（或在 CDN 换图并改 URL 的 `?v=`）。
2. 用户打开商店或点「刷新内容」→ 重新拉 `marketplace.json` → 新声明生效。
3. 图片由 `<img>` 直连 URL，按浏览器缓存；改 URL 即换图。
4. 插件版本、已安装状态、包体**都不动**。

### 11.5 一个实读提醒

官方目录当前 `collections` 为 **0**（`linkdesk-marketplace/marketplace.json` 实读），而 `HomeView` 完全按 `collections` 渲染 hero/合集、`主题专区` 则是按分类硬渲染。
⇒ 实现批次若要「改声明就能换 hero/mega/小卡」，需要先确认/补齐官方目录的 `collections[]` 声明；否则槽位没有数据源。

## 十二、设计稿与最终实现的差异边界（2026-11-22 用户问「最后一定和这个一样吗」）

**能保证（设计与验收的合同）**：

- 结构：hero 满幅／split 整行分栏／duo 两枚一排／mega 封面＋灰条／wall 图墙／small 只图标。
- 比例：hero 2:1、wall 3:2、mega 200px、split 270px、duo 50%×192——按 token 落地。
- 交互：hover 卡内轮播 2~3 帧、移出复位；视频 controls、⛔ autoplay；整卡进详情＋hover 快捷动作。
- 视觉语言：同一套卡片面、辉光、磨砂、角标、按钮；⛔ 第二套。

**会变（不是偏差，是环境差异）**：

1. **token 化**：稿里写的 px/色值会换成壳/主题的 `--font-size-*`、`--surface-*`、`--marketplace-hue`——主题缩放或换主题时会跟着变。
2. **真实数据**：作者图的实际比例、长标题、无图条目都会让画面与占位图不同；无图多时生成式封面出现得更频繁。
3. **卡片壳**：实现复用现有 `.marketplace-store-card` 壳与 hover 展开层，个别间距会按既有 token 对齐，允许 ±几 px。
4. **平台渲染**：Electron/Chromium 的字体渲染与 Windows 缩放，会让字宽/行高与截图略有差异。
5. **视频**：只在作者真的提供视频时有；没有就是图片或生成式封面。

**不会进产品（仅设计稿）**：

- 「媒体原语 · 状态陈列」展板、演示提示条、picsum 占位图、示例里的第 4 张「无图回落演示」hero。
- 稿里的示例插件/合集顺序；真机以目录声明为准。

**验收方式（避免「感觉差不多」）**：

- 同视口（1440 / 900 / 300）＋同数据，改造前后截图并排；结构/比例/交互逐项对，允许的差异只限上列 5 条。
- 300px 普查不回归；`prefers-reduced-motion` 下轮播静止。
- 任何「多一套按钮/角标/模糊/辉光」直接判不通过。
