§二 新设计：ldk-fallback 降级脸家族 🟩 五段结构 · 三变体 · 三尺度 · 全 token

五段：图标（codicon，随变体换形换色）→ 标题（一句话事实）→ 说明（一句下一步建议）→ 动作区（primary ＋ 次级 ＋ 详情披露）→ 诊断详情（<details> 默认收起）。三尺度＝full（主区 tab / 底部面板等横宽容器）· panel（侧栏窄栏）· micro（状态栏/工具槽极窄档）——通用功能：一张脸管九个挂载点，新 zone 挂上加载链即自动继承。落地建议 src/pool/shared/fallback/。

B6 · 衔接万物皆可插件＝回退链终点站母案 §四-4 · §四-7
将来：插件贡献 contributes.renderers 替换体接管某张脸（emptyStage 槽位族）—— 替换体崩溃 → 自动回退本内置脸 ＋ 一条 toast 通知（母案 §四-7 回退链机械化）。

所以这张内置脸必须先做到验收级：它是所有未来替换体的兜底终点。数据五段同构（插件 id / 变体 / 消息 / 时间 / 建议）⇒ 替换体照走同一契约，换皮零迁移；「列出候选 / 切换 / 回退默认」命令化随槽位落地同笔做（铁律 B），本档只留位不抢跑。

命令面＝跨皮稳定契约：皮被替换后同一批命令与参数照常工作（用户口述：未来即便换成通用 UI 的形式，底层命令不变）——AI 与用户的操作面永不因换皮重写。且每张脸都可被命令主动调出（建议 app.previewFallbackFace，variant / scale / name 参数化）——哪怕没有真实崩溃，AI 也能把崩溃脸调出来（演示 / 验收 / AI 验证共用同一入口）。
机制不抢跑：本档只定型「皮」＋预留「骨」的接口（数据命令 / 动作命令位）；槽位总线的拍板与实施在母案，两边互不阻塞。

§三 怎么读本图（断言清单）

  1. 真源逐值：token 表照抄 src/index.css（含亮色 --error:#B3261E）；现状区 .crash-legacy-* 每条声明＝ErrorBoundary.tsx:70-98 的 inline style 逐条转写，值零改动；.plugin-missing-view 真源零规则 ⇒ 本图刻意零声明。
  2. 新设计零手填（产品件）：字号一律 var(--font-size-*)、尺寸一律 calc(Npx * var(--ui-scale))、圆角一律 var(--radius-*)、色一律 var(--xxx)；类名 ldk-fallback-* 为落地建议名（ldk- 族段，硬约束 23 纪律）。
  3. 语义对齐既有裁决：missing＝中性（「没有」≠「坏了」，E6#162）；crash 图标点 --error；empty 为可选统一件（E5.6#11g 插件自判在先）；加载态不并入（ViewSkeleton 已是验收件，语义「内容在路上」不同于「结果不是内容」）。加载与三脸由 React 状态机互斥区分：import pending→骨架 / rejected→crash / null→missing / resolve→内容——永不错位互串；⏳ 边界：import 永久 pending 无超时兜底（骨架永转，慢与挂不可辨），是否立 --timeout 第四变体 → 提案 §六-5 开放问题。
  4. 双主题真切换：右上按钮改 data-theme，与实机同机制；两主题均过对比度（error on window、primary 白字 on accent）。
  5. AI 友好化＝命令直取，不读屏（硬约束 26③）：详情四行＝结构化命令返回值的 GUI 渲染，AI 经 ai-bridge / linkdeskctl / MCP 直接拿同一份 JSON（⛔ 截图→视觉理解→猜坐标）；动作指向命令位（GUI 点击与 AI 调用同源）；aria/role 是视障用户读屏软件的无障碍面，与 AI 无关；panel/micro 尺度砍视觉不砍通路（说明与详情可以不渲染，命令照返回）。命令 id 为建议值，注册随槽位落地同笔做。
  6. 交互为真，不是摆设：图内所有按钮真实可点——重试 → 轻 toast「正在重试…」；查看详情 → 页内原位展开（再点收起）；打开插件市场 / 清空条件 → 轻 toast 反馈；现状区（🟥）按钮同样接了演示反馈（真源行为＝state 重置重渲染，此处用轻 toast 演示反馈形态）。
  7. 反馈通路三分工（B7）：轻 toast＝路过反馈 · 页内详情＝就地深读 · 右下铃铛面板＝常驻待办（不在本档范围）——⛔ 互相客串。
  8. 变体判定零新增机制：crash＝ErrorBoundary catch（既有）；missing＝loader 存在性闸 null（E6#162 既有）；empty＝when 空态 / 插件自判（E5.6#11g 既有）——全部是既有出口换脸，判定逻辑不新增。
  9. 全脸可命令调出＋命令跨皮不变（AI 友好化终极判据，用户 2026-11-21 口述）：所见 AI 能见、所操作 AI 能操作、指哪打哪——三张脸不依赖真实故障即可被命令调出（建议 app.previewFallbackFace，演示/验收/AI 验证共用）；未来皮被通用 UI 替换，底层命令与参数不变——操作面永不重写。反面判据（LabVIEW 式软件）：模拟鼠标点击/拖动不是通路——每一条能力以结构化命令可达为唯一合格线（「远没有直接写 C 代码方便快捷」）。
  10. 文案规格：说明区两行（行1 事实 · 行2 出路）；禁口语化（「通常」「试试」类词）。
  11. 通用功能＝一张脸管九个挂载点（B3 全家福）：主区 tab / 侧栏视图 / 侧栏 section / 底部面板 / 悬浮面板 / 对话框 / 状态栏组件 / 工具槽 / 壳保底页全走同一条加载链；三尺度由容器 props 决定、与挂载点解耦——新 zone 挂上即自动继承，零新增代码；底部面板＝full 原样复用（横宽不改尺度），状态栏/工具槽＝micro 横排。
  12. 图标＝真 codicon：error / puzzle / files / debug-restart / refresh 与产品同一支字体；缺 node_modules 时字形退化为空框，跑 npm i 即可。
  13. 范围边界：状态栏通知面板失败行（ldk-notif-*）不在本档（有自己的三段结构），仅对齐动作语义；EmptyStage 品牌空场不并入（装饰件语义不同）。
