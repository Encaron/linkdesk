### 1.2 为什么「手工验过一次」不够（本件的核心论点）

`check-css-hardcode` 与 `check-theme-schema` 在**立项提交里各做过一次负测试**（注入违规 ⇒ 观察红 ⇒ 还原）。**那证明的是「那一刻它能红」**，不证明：
- 后来有人改了它的解析逻辑，**它现在还能红**；
- 它的射程**仍然覆盖**它声称覆盖的面（例：`#128` 的 hex-only grep **漏掉 `rgba`**，是机械门禁后来才抓到的）；
- 它的负控样例**恰恰是旧启发式漏掉的那一类**（`includes("-")` 的教训：负控若塞的是**不带连字符**的裸名，就永远测不出「带连字符也漏」）。

⇒ **只有「可复跑的自测 ＋ 接进链」才能持续证明**。这是本件要落成制度的东西。

for f in scripts/check-*.mjs; do grep -q "self-test\|selfTest" "$f" || echo "无自测: $f"; done

# ② 通读 check 链：每道「有自测」的是不是都带了 --self-test 那一步

  const has = /self-test|selfTest/.test(fs.readFileSync('scripts/'+f,'utf8'));
  const wired = p.includes(f+' --self-test');
  console.log((has?'有自测':'无自测'), (wired?'已接线':'未接线'), f);
}"

# ④ 死判据标本（minAppVersion）

grep -rn "minAppVersion" E:/linkdesk-plugins/official --include=*.json | grep -v node_modules | head
