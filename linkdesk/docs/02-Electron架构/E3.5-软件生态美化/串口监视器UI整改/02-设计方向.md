# 02 — 设计方向与决策

> 本文档列出需要 Encaron 确认的设计决策，以及整改的视觉方向。

---

## 需要确认的决策

### 决策 A：Emoji → Codicon 替换

**现状**：串口监视器 15+ 处使用 Emoji/文本字符作为图标（⏸ ▶ 📡 🔍 ✎ ✕ ✓ ● ▲ ▼）。

**方案**：全部替换为 `codicon` 字体图标。LinkDesk 已内置 codicon 系统。

**影响**：纯 UI 改动，零操作逻辑变更。每处 ~2 行改动。

> ✅ **确认即可执行。**

### 决策 B：工具栏"命令面板"按钮去留

**现状**：工具栏有一个 `▸ 命令面板` 按钮，点击打开全局面板。

**方案 A（推荐）**：移除。命令面板入口已有 `Ctrl+Shift+P` 快捷键 + 标题栏 ☰ 菜单。工具栏按钮是冗余入口，占用横向空间。
**方案 B**：保留但改为 codicon `list-flat`，无文字标签，节省空间。

> ❓ **需确认。**

### 决策 C：去除 `transform: scale()` 动效

**现状**：7 处 hover/active 使用 `scale()`——工具栏按钮、快捷发送 pill、发送按钮、回到底部按钮。

**问题**：`scale()` 在 flex 容器内会推动相邻元素；没有 `prefers-reduced-motion` 适配。

**方案 A（推荐）**：全部移除 `scale()`，仅用 `background` / `color` / `box-shadow` 做 hover 反馈。
**方案 B**：保留但包裹在 `@media (prefers-reduced-motion: no-preference)` 内。

> ❓ **需确认。**

### 决策 D：发送区前缀 `>` 是否改为 `→`

**现状**：Monaco 编辑器左侧有一个 accent 色的 `>` 符号。

**问题**：`>` 终端提示符语义（"输入命令"）在串口发送场景不完全准确。`→` 表示"发送方向"更准确。

**方案 A**：保持 `>` 不变（对标终端提示符）。
**方案 B（推荐）**：改为 `→` 或 `▶` codicon。

> ❓ **需确认。**

### 决策 E：侧栏设置组加分区标题

**现状**：12 个设置项分 3 组（显示 / 发送行为 / 编码），但组间仅用 `border-top` 分隔，无文字标题。

**方案 A（推荐）**：每组加 `<div className="setting-group-label">` 小标题——`显示`、`发送行为`、`编码`。
**方案 B**：保持现状（对标 VS Code 终端设置，无分区标题）。

> ❓ **需确认。**

## 视觉方向参考

### 对标 VS Code 终端面板

串口监视器对标 VS Code 的终端面板（Terminal panel），不是编辑器区。关键特征：

- **紧凑命令条** — 36px 一行控制栏（对标 shell 选择器）
- **等宽字体** — Sarasa Mono SC 用于数据和输入
- **系统字体** — Inter 用于 UI 标签和按钮
- **深色为主** — OLED 友好，暗色背景减少眼部疲劳
- **少用边框** — 用颜色和透明度区分层级
- **hover 揭示** — 次要操作仅在 hover 时显示（齿轮、改名等）
- **Accent 色强调** — 仅用于主要操作（发送按钮、连接状态、活跃指示器）

### 颜色 Token 补全

当前 CSS 变量体系缺少的 token：

```css
:root {
  /* 新增——警告色 */
  --warning-text: #E8AB3E;
  --warning-bg: rgba(255, 200, 0, 0.12);

  /* 新增——accent 上的文字色 */
  --text-on-accent: #ffffff;

  /* 新增——危险色 */
  --danger: #EF4444;

  /* 已有——连接状态 */
  --serial-monitor-ok: #22C55E;
}
```
