# 侧栏 ↔ 主区状态同步验证——E5.5#7

> 📖 **来源：** [[e5-multi-webview-abandoned]] Bug 3 & Bug 4——sidebar 和 main content 在不同 WebView，状态不同步。
> E5#85 已经部分解决了这个问题。E5.5#7 是重新验证。

## 背景

E5#85（ContextKey 和 Command 系统归一化）解决了以下同步问题：

| 问题 | E5#85 解法 | E5.5#7 验证 |
|:--|:--|:--|
| 侧栏点击文件→主区不更新 | `contextKey:set('activeFile', path)` + `contextKey:changed` 广播 | 多 WebView 下重新验证 |
| 侧栏焦点变化→快捷键不响应 | CommandRegistry IPC——命令注册统一到壳 | 多 WebView 下重新验证 |
| 主区关闭文件→侧栏不高亮 | EditorService IPC 反馈到壳 | 多 WebView 下重新验证 |

E5#85 修复了在**单 WebView** 下的问题——所有插件共享同一个 ContextKey `_store`。

**多 WebView 下：** 侧栏插件和主区插件在不同 WebView，各自的 ContextKey `_store` 是独立副本。E5#85 的 IPC 通道（`contextKey:set` + `contextKey:changed`）本应解决这个问题——E5#85 的设计就是为多 WebView 准备的。

**需要验证：** 多 WebView 恢复后，这些 IPC 通道是否真的在跨 WebView 同步。

## 验证场景

### 场景 1：侧栏点击 → 主区打开文件

```
前提：文件树插件 WebView + 编辑器插件 WebView + 壳 WebView（三个独立进程）

操作：
  1. 文件树中点击 "readme.md"
  
预期链路：
  1. 文件树 WebView → window.linkdesk.editor.open('readme.md')
  2. IpcBridge → 主进程 → 壳 WebView → editor IPC handler
  3. 编辑器 WebView 切换到 readme.md
  4. 壳 contextKey:set('activeFile', 'readme.md')
  5. IpcBridge.contextKey:changed 广播到所有 WebView
  6. 文件树 WebView 收到广播 → 高亮 readme.md ✅
  
验证点：
  - [ ] 编辑器确实切换到新文件
  - [ ] 文件树高亮同步更新
  - [ ] path bar 显示正确路径
  - [ ] 无额外 requestAnimationFrame 延迟
```

### 场景 2：主区关闭文件 → 侧栏取消高亮

```
操作：
  1. 编辑器标签页上点击关闭 "readme.md"
  
预期链路：
  1. EditorService 通知 contextKey 变化
  2. IpcBridge.contextKey:changed 广播
  3. 文件树 WebView 收到广播 → 取消高亮

验证点：
  - [ ] 文件树无任何文件高亮（或回退到激活文件的父目录）
```

### 场景 3：快捷键 Ctrl+S 保存

```
操作：
  1. 焦点在编辑器 WebView → Ctrl+S
  2. 快捷键注册在壳 WebView（壳的 KeybindingService）
  3. 壳 → IpcBridge → 发给编辑器 WebView

验证点：
  - [ ] 文件正确保存
  - [ ] 侧栏不闪烁（无重新渲染）
  - [ ] 状态栏更新（未保存标记消失）
```

### 场景 4：多个插件并发同步

```
操作：
  1. 快速在文件树中切换文件（点 A → B → C → D，间隔 100ms）
  
验证点：
  - [ ] 编辑器最终停在 D（不是 A/B/C）
  - [ ] 文件树高亮最终在 D（没有残留 A 高亮）
  - [ ] contextKey:changed 广播无积压（最后一条之后 500ms 无新广播）
  - [ ] IpcBridge 无 push 队列 overflow
```

## 调试工具

```typescript
// 在 DevTools (壳 WebView) 中
> window.linkdesk.contextKey.get('activeFile')  // 壳的当前值
> window.linkdesk.debug.getBroadcastLog()        // IpcBridge 最近 50 条广播

// 在 DevTools (文件树 WebView) 中——需要先把 DevTools 切换到文件树的 WebContentsView
> window.linkdesk.contextKey.get('activeFile')  // 文件树看到的 activeFile

// 值应该一致。不一致 → 同步断连。
```

## 回退机制

如果同步失效，IpcBridge 的 `lastBroadcasts` 机制提供回退：

```typescript
// IpcBridge.broadcast() 调用后，将消息存入 lastBroadcasts Map
// 新 WebView 连接时自动回放最近 50 条广播
// → 插件重新打开标签页时能恢复到正确状态
```

**验证：**
- [ ] 关闭后重新打开文件树标签页 → 高亮恢复
- [ ] 刷新插件 WebView（reload）→ 高亮恢复
