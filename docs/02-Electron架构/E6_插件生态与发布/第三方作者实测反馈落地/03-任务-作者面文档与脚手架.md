## §一 `E6#138` 17 号组合行为矩阵 ＋ 00 号动线指针（三图模型）

### 前因

第三方作者全程只读了 **00-readme + 17-region-map 两篇**就动手。结果是：

1. **三图模型没进他的视野**——icon（图标栏 Type-1 剪影）/ marketIcon（Type-2 彩色身份图）/ cover（README 场景封面）这套模型，他是从 file-tree 的 SVG 注释和 schema 字段描述里**反推**出来的。事实上 [06-plugin-json-spec.md:382–399](../../../03-plugin-authoring/06-plugin-json-spec.md) 有完整专节（含「the icon bar force-tints it, so a coloured image turns into a blob」这句关键行为），[12-readme-media-contract.md](../../../03-plugin-authoring/12-readme-media-contract.md) 管场景封面——**文档是全的，动线断了**：他读的 17 号对 marketIcon 只字未提，也没人告诉他去 06 号。
2. **图标栏点击行为无明文**——「`entry` + `appearsIn: { iconBar, tabBar }` = 图标栏图标 + 点击直达标签页」这个结论，17 号只给到 70 行一句「An icon plus openable-as-a-tab (the classic shape)」的暗示。

### 修哪里

- `docs/03-plugin-authoring/17-region-map.md`（矩阵 ＋ 三图模型指针）。
- `docs/03-plugin-authoring/00-readme.md`（阅读动线指针）。
- 中文维护者面对应文件同笔（双语门禁）。

### 怎么修

1. **17 号加「声明组合 → 用户点击后的行为」矩阵**（放 ⑤⑥ 区域行之后或 entryless 节附近）。至少覆盖四行：

   | 声明 | 用户点击图标栏图标后 | 备注 |
   |:--|:--|:--|
   | `entry` ＋ `appearsIn: { iconBar }` ＋ `tabBar: true` | **直接开标签页**（经典形态，无需额外声明） | 现行 70 行那句升级成表 |
   | `entry` ＋ `appearsIn: { iconBar }`（无 tabBar） | 按表实际行为写（动手前实测，⛔ 不凭记忆） | — |
   | 无 `entry` ＋ 侧栏容器 + `iconBar` | 切换侧栏容器（entryless，永不进标签页） | 73 行已有明文，进表 |
   | `sidePanel` / `statusBar` | 各自行为一句话 | 照 17 号已有区域行收拢 |

   ⚠️ 表格每一格的**行为以实测定**（起 dev 或读壳源码确认），不确定的格子宁可留「见 08 号文档」指针也不许编。
2. **17 号加三图模型小节（或指针块）**：五行讲清 icon（图标栏强制单色染色）/ marketIcon（市场彩色身份图）/ cover（README 场景封面）各管哪、谁会 force-tint；指向 [06 号 §marketIcon](../../../03-plugin-authoring/06-plugin-json-spec.md) 与 [12 号媒体契约](../../../03-plugin-authoring/12-readme-media-contract.md) 看完整规则。**不复制 06 号正文**——单一真相源，指针即动线。
3. **00 号阅读动线加指针**：在 00 号的推荐阅读顺序里，把「图标身份（icon / marketIcon）→ 06 号」「README 媒体 → 12 号」两根指针钉进去（照 00 号现有指路句的格式）。
4. 中文维护者面同笔（`docs/03-插件制造/` 下对应篇——以双语对齐门禁的报错为准找齐）。

## §二 `E6#139` 脚手架四件套

### 前因

第三方作者指出脚手架「只搭了必选件」里的最疼一块：**单图标心智模型**。他原话：「脚手架资源区只有一个 icon.svg 占位图，注释写的是『图标栏 / 标签页 / 市场里显示的就是它』——这是单图标心智模型，和 file-tree 实际采用的三件套不一致，是整个脚手架里我认为最该补的一块」。核对实锤：[template/plugin.json](../../../../packages/create-linkdesk-plugin/template/plugin.json) 的 icon 注释与 [plugin.schema.json](../../../../packages/plugin-sdk/schemas/plugin.schema.json) 自身的三图描述**自相矛盾**。另有两个实锤：README 过时句（说测试工具要自装，实际 vitest/jsdom/testing-library 全预装）；contributes 只有 viewsContainers 注释示例，commands/keybindings/statusBar/titleBar 零指引。

### 修哪里（全部在 `packages/create-linkdesk-plugin/template/` ＋ 壳仓 `scripts/check-scaffold.mjs`）

### 怎么修

1. **① plugin.json icon 注释升级三图模型**：把「图标——图标栏 / 标签页 / 市场里显示的就是它」改为与 schema 一致的三图描述（图标栏 = Type-1 单色剪影会被强制染色；市场彩色身份图 = marketIcon），并**预置注释掉的 marketIcon 行**：`// "marketIcon": "resources/icon.svg", // 市场彩色身份图（可选；缺省回落 icon）`。注意保持 JSONC 注释风格与现有行宽。
2. **② resources/ 预置带注释模板**：新增 `icon-bar.svg`（Type-1 线稿剪影示例——照 file-tree 的 icon-bar.svg 形态画个简单占位，SVG 内注释写「图标栏会用单色滤镜染色，别放彩色图」）与 `cover.svg`（README 场景封面示例，内注释写「这张只住 README，不进市场展示位」）。⛔ 不动现有 icon.svg 占位本体（只可改其内注释对三图的指向）。
3. **③ contributes 全家福注释速查**：plugin.json 的 contributes 节加一段**每键一行**的注释速查——`commands` / `keybindings`（含 when 旗子）/ `statusBar`（顶层 `statusBar[]`，非 contributes.statusBar——这个坑要写）/ `titleBar` / `viewsContainers`/`views`（保留现有示例）。每行格式：「键名 —— 一句话干什么 ＋ 详见 03/17 号文档哪篇」。⛔ 速查只指路不展开——**不做第二份 03 号文档**。
4. **④ README 修过时句**：删/改「run `npm i -D vitest` yourself — the scaffold does not preinstall test tooling」为如实描述（工具已预装，`npm run test` 直接跑）；顺笔把资源区说明补三图一句（与 ①② 呼应）。
5. **check-scaffold 同步**：跑 `node scripts/check-scaffold.mjs`——若它断言模板内容（字段/文件清单），同笔更新断言与 `--self-test`；**script 改动不进包不发版**。`generate-plugin-docs.mjs --check` 也跑一遍自证（它管的是作者面文档产物，理论上与模板无关，跑一下确证）。

### 验收

- `npx create-linkdesk-plugin` 产物（或直接 node index.js 生成临时工程）目视：三图注释到位、marketIcon 行在、速查注释齐、README 无过时句；`npm run check` 全绿（check-scaffold 过）。
