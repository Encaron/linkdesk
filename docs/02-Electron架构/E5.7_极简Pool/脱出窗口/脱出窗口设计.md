## 1. 脱出窗口的定义

| 特性 | 说明 |
|:--|:--|
| 触发 | 用户拖拽标签页超出主窗口边界 |
| 窗口 | 独立 BrowserWindow（无边框，跟随鼠标） |
| 内容 | 同一个 pool.html，pushLayout 只包含脱出的 tab |
| 生命周期 | 临时——关闭 = 销毁 BrowserWindow + WCV，tab 回归主窗口 |
| 代码 | 同一个 PoolZoneShell + MainRenderer——同代码、不同 layout |

## 2. 架构

```
主窗口                             脱出窗口
┌──────────────────┐             ┌──────────────────┐
│ BrowserWindow    │             │ BrowserWindow    │
│ ┌──────────────┐ │             │ ┌──────────────┐ │
│ │ WCV 100%     │ │             │ │ WCV 100%     │ │
│ │              │ │             │ │              │ │
│ │ PoolZoneShell│ │             │ │ PoolZoneShell│ │
│ │  所有 Zone   │ │             │ │ 只渲染:      │ │
│ │  含剩余 tabs │ │             │ │  - MainZone│ │
│ │              │ │             │ │  (含 TabBar) │ │
│ └──────────────┘ │             │ │  (1 个 tab)  │ │
└──────────────────┘             │ └──────────────┘ │
                                 └──────────────────┘

同一个文件:
  pool.html → pool-main.tsx → PoolZoneShell
  preload-pool.ts（同一个——window.linkdesk.* 一致）

区别:
  pushLayout 的内容不同
  主窗口 layout: 所有 groups
  脱出窗口 layout: 只有 { groups: [detachedGroup] }
```

## 3. 主进程 API

### 3.1 创建脱出窗口

```typescript
// electron/detached-window.ts

interface DetachedWindow {
  browserWindow: BrowserWindow;
  wcv: WebContentsView;
  tabId: string;
}

function createDetachedWindow(tab: PoolTab, position: { x: number; y: number }): DetachedWindow {
  // 1. 创建 BrowserWindow（无边框，跟随鼠标位置）
  const win = new BrowserWindow({
    x: position.x - 50,  // 居中于鼠标
    y: position.y - 15,
    width: 800,
    height: 600,
    frame: false,          // 🔄 E5.8#42 拍板 7：无边框 + 自绘标题栏（复用 PoolZoneShell titleBar 区，视觉一致）
    title: tab.title,      // 初始标题——随窗口内活动 tab 变（I9-12）
    show: false,           // 等 ready 后显示
    webPreferences: {
      preload: path.join(__dirname, 'preload-pool.js'),  // ← 同一个 preload
      nodeIntegration: false,
      contextIsolation: true,
      sandbox: true,
    },
  });

  // 2. 创建 WCV（100%×100%）
  const wcv = new WebContentsView({
    webPreferences: {
      preload: path.join(__dirname, 'preload-pool.js'),
      nodeIntegration: false,
      contextIsolation: true,
      sandbox: true,
    },
  });
  win.contentView.addChildView(wcv);
  wcv.setBounds({ x: 0, y: 0, width: 800, height: 600 });

  // 3. 加载同一个 pool.html
  wcv.webContents.loadURL(
    process.env.NODE_ENV === 'development'
      ? 'http://localhost:1420/pool.html'
      : `file://${path.join(__dirname, '../renderer/pool.html')}`
  );

  // 4. 等 pool:ready → 通知壳为「本窗口 sender」推布局（审计 2 / I9-20：主进程不 buildLayout/操作 tabState）
  //    主进程只转达「窗口就绪」事件 + sender 身份；壳 = tabState 唯一真相源——
  //    壳从 tabState 取脱出的 tab 组，对【两个窗口】各 pushLayout：
  //      主窗口 layout = 减掉脱出的 tab；脱出窗口 layout = 只含该组（iconBar 空 / sidebar hidden / statusBar 空）。
  ipcMain.once('pool:ready', (event) => {
    if (event.sender === wcv.webContents) {
      windowManager.notifyWindowReady(wcv);   // 壳据此 senderId 识别新窗口并推布局（多窗口路由见 §8）
      win.show();
    }
  });

  // 5. 窗口大小变化 → WCV setBounds
  win.on('resize', () => {
    const [w, h] = win.getContentSize();
    wcv.setBounds({ x: 0, y: 0, width: w, height: h });
  });

  return { browserWindow: win, wcv, tabId: tab.id };
}
```

> 🔄 **E5.8#42 决策落盘（2026-08-22）**：本段已按拍板修正——① `frame:false` + 自绘标题栏（拍板 7 / I9-11，窗口内 ×/最小化/最大化 = 自绘标题栏三按钮）；② 布局由**壳 pushLayout**（审计 2，主进程不 buildLayout）；③ 脱出窗口只渲染 MainZone（含 TabBar），无菜单栏/图标栏/侧栏/状态栏——纯工作区窗口（拍板 7 / I9-11）。
>
> **⑦ 外观玻璃态继承（#50.5 联注）**：脱出窗口是**新 document**——窗口创建后壳对其 document 执行 ThemeEngine applyTheme + BackgroundLayer 渲染（图片层 per-window，`cover` 相对**该窗口**视口；图片源 = `getAssetPath` 解析后绝对路径，新窗口可解析）。**Phase 9 立案即带此约束**——否则拖出窗口白底死色视觉断裂。

### 3.2 关闭脱出窗口 → tab 回归

```typescript
function closeDetachedWindow(detached: DetachedWindow): void {
  const { browserWindow, wcv } = detached;

  // 1. 主进程只通知壳「关窗」→ 壳关闭窗口内全部标签页（I9-9：关窗 × = 关闭，非回归——VS Code 行为）
  //    —— 审计 2 / I9-20：主进程不操作 tabState / 不 buildLayout，壳是唯一真相源
  windowManager.notifyShellWindowClosed(wcv);   // 壳收到 → 关闭窗口内全部 tab（tabState 移除 + 持久化）
  //    主窗口 layout 不变（这些 tab 本就不在主窗口——无需 pushLayout 主窗口）

  // 2. 销毁脱出窗口（WCV 先于 BrowserWindow）
  browserWindow.removeChildView(wcv);
  wcv.webContents.close();
  browserWindow.close();
}

// 监听脱出窗口关闭事件
detached.browserWindow.on('closed', () => {
  closeDetachedWindow(detached);
});
```

## 4. 拖拽检测——useDragDetach（释放时判断）

> 🔄 **E5.8#42 决策落盘（审计 3 / I9-1）**：**释放时判断**——所有窗口 dragover 置标志，dragend 时标志 false = 释放在窗口外才脱出；释放在当前聚焦窗口 bounds 内 = 拒绝（防误触发）；拖出再拖回 = 完全取消。旧稿「过线 30px 立即 detach」已废。

```typescript
// src/pool/hooks/useDragDetach.ts

function useDragDetach(
  tabId: string,
  dragRef: RefObject<HTMLDivElement>
) {
  // 1. 拖拽期只跟踪状态，不立即脱出
  const onMouseMove = useCallback((e: MouseEvent) => {
    dragState.lastScreen = { x: e.screenX, y: e.screenY };
    // 只更新视觉反馈（如「拖出可脱窗」提示），不触发任何 IPC
  }, []);

  // 2. 释放时判断（照抄 VS Code onGroupDragEnd）
  const onMouseUp = useCallback((e: MouseEvent) => {
    // 是否释放在【其他窗口】上方——各窗口 dragover 时自置 isWindowDraggedOver()
    const overOtherWindow = window.linkdesk.window.isWindowDraggedOver();

    if (overOtherWindow) {
      // 释放在其他窗口上方 = 拖入该窗口（按 I9-9 归并/按 tab 吸附），不是脱出
      cleanup();
      return;
    }

    // 释放在【当前聚焦窗口 bounds 内】= 拒绝（防误触发，I9-1）
    if (isInsideCurrentWindow(e.screenX, e.screenY)) {
      cleanup();  // 拖出再拖回 = 完全取消，什么都不做
      return;
    }

    // 释放在所有窗口外 = 真脱出
    window.linkdesk.window.detachTab(tabId, dragState.lastScreen);
    cleanup();
  }, [tabId]);

  // mousedown → 开始监听 → mouseup → 停止
  // ...
}
```

> 说明：
> - `isWindowDraggedOver()` = 主进程维护的全局标志——任一窗口 dragover 置 true，dragend 后清零。脱出窗口自身也注册该 handler（拖出后继续拖 = 可再拖回/拖入其他窗口）。
> - `isInsideCurrentWindow` 用 `e.screenX/screenY` 对当前窗口 bounds 判断（手写 mouse capture 下可用，审计 3）。

## 5. 脱出窗口 vs 新窗口

| 场景 | 触发 | 实现 |
|:--|:--|:--|
| 脱出窗口 | 拖标签页出主窗口 | `detachTab()` — 同一 tab 移动 |
| 新窗口 | 插件调用 API / 命令 | `window.linkdesk.window.open(layout)` — 创建新 tab |

**两种场景共享同一个 `createDetachedWindow` 逻辑。** 区别是 pushLayout 的内容——脱出的是现有 tab，新窗口是新 tab。

## 8. 多窗口连带（审计 5——E5.8#42 新增）

> 脱出窗口 = 第 2 个 BrowserWindow。单窗口期正确的硬编码到多窗口期必须改——本段是"多窗口路由"全套改动点。**改动点全部在壳侧/主进程侧；插件无感知**（同 preload，`window.linkdesk.*` 一致）。

### 8.1 window:* IPC 按 sender 路由

`main.ts` 现在硬编码 `mainWindow`（单窗口期正确）。多窗口期改 **sender 路由表**：

```typescript
// 主进程：senderId → window 映射（主窗口 + 每个脱出窗口）
const windowBySender = new Map<number, DetachedWindow | 'main'>();
// 注册：createDetachedWindow 时 windowBySender.set(wcv.webContents.id, detached)
//       主窗口启动时 windowBySender.set(mainWcv.webContents.id, 'main')

// 任何 window:* 命令一律按 event.sender 路由，禁止硬编码 mainWindow
ipcMain.handle('window:open', (event, args) => {
  const senderWin = windowBySender.get(event.sender.id) ?? 'main';
  // 脱出窗口里插件调 window.open → 创建新窗口 = 锚在发送者所在窗口
  openWindow(args, { from: senderWin });
});

// 反向：壳推布局也要知道目标窗口 —— 壳侧 pushLayout 时按"当前事件 sender"定位
//（壳 = 唯一真相源，tabState 里每组记录所属 windowId；pushLayout 对【该组所在窗口】推送）
```

### 8.2 preload `window.open`

E5.7#5 已留位。多窗口期接上：`window.linkdesk.window.open(layout)` → 主进程创建新窗口（第 5 节"新窗口"场景），同样走 §8.1 路由（锚定发送者所在窗口）。

### 8.3 broadcast 按窗口路由

壳广播（`ipcRenderer.send('shell:broadcast', ...)`）默认只发**主窗口**。需要脱出窗口也收到的广播（如主题切换、全局命令、插件状态变更）→ 遍历 `windowBySender` 全窗口发送；窗口本地事件（tab 激活等）→ 只发本窗口。按事件类型声明范围，不默认全发。

### 8.4 keyboard-router 按窗口路由

主进程键盘拦截（`before-input-event`）绑定在 mainWindow 上——多窗口期每个窗口各自注册。窗口切换 = 焦点事件自然切换（各窗口有自己的 WCV → 各自拦截器生效）。

### 8.5 崩溃恢复覆盖脱出窗口（I9-16）

主窗口崩溃恢复已实现；脱出窗口崩 → **[待拍：A 主进程弹 reload 提示（推荐——VS Code 同款，崩了可重载该窗口，tab 数据由插件持久化兜底）/ B 直接关窗销毁全部 tab]**（关窗语义见 I9-9）。主进程监听每个脱出窗口 `render-process-gone` 触发上述分支。主窗口崩 → 脱出窗口作为兜底宿主（I9-16：崩溃恢复 + 多窗口数据完整）。
