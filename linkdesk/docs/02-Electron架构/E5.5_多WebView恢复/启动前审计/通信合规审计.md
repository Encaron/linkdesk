# 插件通信合规审计——E5.5#0a

> 📖 **铁律来源：** [[plugin-communication-standard]]——插件只认 `window.linkdesk.*`，禁止 `import @src/core`。
> [[multi-webview-root-cause]]——任何 import/变量共享/同步调用在多 WebView 下静默失效（不报错，只是不工作）。

## 为什么必须做

多 WebView 下每个插件 = 独立 WebContentsView = 独立 JS 堆。

```typescript
// ❌ 插件里写这个：
import { registerMenuItems } from "@src/core/registry/MenuRegistry";
registerMenuItems(MenuId.EditorContext, [...]);
// → 插件进程的 _menus Map 注册了菜单项
// → 壳进程的 _menus Map 没有这条
// → 壳的 ContextMenu 读壳的 _menus → 空
// → 菜单静默空白。不报错。不崩溃。
```

**E3a 教训：** `import` 核心模块有副作用的调用，在多 WebView 下 100% 静默失效。没有 error，没有 warning。用户看到的只是"菜单没出来""配置没生效""命令没注册"。

## 审计范围

### 第一步：全量扫描

```bash
grep -rn "from.*@src/core" plugins/
grep -rn "from.*\.\./\.\./src/core" plugins/
grep -rn "from.*\.\./\.\./\.\./src/core" plugins/
```

### 第二步：逐条分类

| 类别 | 判据 | 多 WebView 下行为 | 处理 |
|:--|:--|:--|:--|
| 纯工具函数 | 无副作用，不依赖 DOM/React Context/模块变量 | ✅ 安全——每个 WebView 自己 import 一份 | 放行 |
| 类型定义 | `import type { ... }` | ✅ 编译时擦除，无运行时影响 | 放行 |
| 枚举/常量 | 纯值，不依赖运行时状态 | ✅ 安全 | 放行 |
| UI 组件 | React 组件，渲染 DOM | 🔴 多 WebView 下组件在插件进程渲染，不是壳进程 | 记录例外 |
| 有副作用的服务 | Registry 操作、配置读写、文件操作 | 🔴 静默失效——操作的是插件进程的副本 | **必须切 linkdesk.\* API** |

### 第三步：ESLint warn 分批复核

当前 `no-core-import-in-plugin` 37 处 warn。分三组：

1. **可切 linkdesk.\* API**——已有对应 API，直接替换。例：`import { getConfigurationValue }` → `window.linkdesk.configuration.get()`
2. **记录例外**——UI 组件（ContextMenu/InineInput 等）在当前阶段必须复用壳组件，无法切 API。记录到 [[plugin-import-exceptions]]，注明多 WebView 替代方案。
3. **白名单补漏**——ESLint 规则误报。例：`import type` 编译时擦除的。

## 验证

- [ ] `grep "from.*@src/core" plugins/` → 仅工具函数 + 类型 + 已记录例外
- [ ] 所有有副作用的 import → 已切 `window.linkdesk.*` API 或记录例外
- [ ] ESLint warn 从 37 处降到可接受范围（仅例外+白名单）
